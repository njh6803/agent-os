# 04: 런타임이 규칙 파일을 도구 호출마다 집행한다 — 막고, 묻고, 그냥 부른다

**What to build:** 운영자가 `rules.toml`에 적은 규칙이 실행마다 도구 호출 하나하나에 집행된다. 운영자의 deny에 맞는 도구는 모델의 도구 목록에서 빠지고, 모델이나 에이전트가 그 이름으로 부르면 도구를 부르지 않고 `운영자가 거부했다: <서버>:<도구>`로 거부되며 실행은 계속된다. 모델은 거부를 알고 이어 가고(스토리 16), 직접 부른 에이전트는 같은 문구의 `ToolError`를 받는다(스토리 13). 저자의 `requires_approval`, 운영자의 ask, 적힌 규칙 없음은 `run_paused`로 멈추고, 운영자의 allow는 묻지 않고 부른다. 저자의 승인 요구는 운영자의 allow보다 먼저라 풀리지 않는다(스토리 12). 연결에 없는 이름은 묻지 않고 `도구가 없다: <이름>`으로 거부된다(스토리 14). 트레이스의 `tool_called.rule`과 `run_paused.rule`이 그 호출을 정한 규칙을, `run_paused.server`가 멈춘 도구의 서버를 든다(스토리 7). 재개도 지금 디스크의 규칙을 다시 읽어 집행하므로, 운영자가 고친 규칙이 다음 실행과 다음 재개부터 듣고(스토리 3), 멈춘 사이 deny가 된 도구는 승인자가 승인해도 불리지 않는다(스토리 9). 규칙 파일이 깨졌으면 실행이 시작되지 않고 운영자 면은 원문의 500, 최종 사용자 면은 고정 문구의 500을 받는다(스토리 4·17). 기본이 묻는다가 되므로 저장소의 calc와 시험·e2e는 allow 규칙을 함께 두어 지금처럼 돈다(스토리 19).

04는 02와 03 뒤이고 05와 06을 막는다. 05와 06은 이 티켓 뒤에 나란히 돈다. 명세의 묶음 C 가운데 호출마다의 집행이 이 티켓이고, 실행 전·연결 직후·재개의 검사 셋은 05다. 명세의 묶음 D가 들던 것 가운데 기존 시험이 기대는 것(저장소 규칙 파일, README 트리 줄, 저장소 상태 시험, `-m llm` 도우미, 위젯 e2e 꾸러미, `gatedcalc` 둘의 규칙 파일)을 이 티켓이 같은 티켓에서 둔다(명세 검토가 셈을 넘기지 않고 C로 올렸다).

**병합 뒤에 틈이 셋 있다(to-tickets에서 사용자가 분할을 골랐다). 05가 셋을 닫는다.** 첫째, 마스킹할 인자(`secret_args`)가 있는 도구가 ask나 적힌 규칙 없음에 걸리면 실행 전에 거부되지 않고 멈추며, 승인 뒤 `마스킹된 인자를 실제 도구에 보낼 수 없다`로 실패한다. to-tickets 시점(main `83a66cdc`)에 저장소의 플러그인과 e2e 꾸러미에는 그런 도구가 없다(Grep으로 봤다). 둘째, 에이전트 표에 적은 줄을 연결과 대 보지 않아 deny의 오타가 조용히 효과가 없다. 셋째, 재개는 멈춘 호출의 서버를 대 보지 않아 멈춘 사이 같은 이름의 도구가 다른 서버에서 오면 승인이 그 도구에 적용된다(지금 코드가 이름과 인자만 대 본다는 것을 읽었다). 이 티켓이 쓰는 문장(독스트링, 주석, rules)은 틈 동안에도 참이어야 한다. 셋 가운데 하나를 이미 막는다고 읽히는 문장을 쓰지 않는다.

근거는 `.scratch/approval-rules/spec.md`의 "자리와 읽는 때", "집행의 차례와 게이트의 자리", "모델의 도구 목록", "거부 문구", "적용 규칙 칸의 이름과 값", "결정이 적용된 호출의 적용 규칙", "모두 deny인 재개", "예시 규칙 파일과 시험 자리의 규칙 파일", "고칠 자리의 묶음"의 C·D 줄과 그 2026-11-06 명세 검토 주석들, Testing Decisions 전체다. 앞선 결정은 ADR 0044의 "자리와 읽는 때"·"집행의 차례"·"기록"·"재개"·Consequences "치르는 값", ADR 0009의 2026-11-05 이력(운영자의 deny가 재개의 결정을 이긴다), ADR 0042 묶음 ①이다.

**Blocked by:** 02 (규칙 파일 읽기 — 운영자의 `rules.toml`이 core의 규칙 값이 된다), 03 (도구가 서버 이름을 들고, 같은 이름의 도구는 연결 직후 실패한다). 02의 `read_rules`와 적용 규칙 함수, 03의 `ToolSpec.server`와 가짜 연결의 기본 서버를 쓴다

**Status:** ready-for-agent

### 준비 — 실행과 재개마다 규칙 파일을 읽는다

- [ ] **실행과 재개를 준비할 때마다 `read_rules()`를 한 번 부르고 캐시하지 않는다.** 자리는 준비 순서의 깨짐 묶음 가운데 "운영자 파일의 손상"이고, 규칙 파일을 먼저 읽은 뒤 꺼진 집합을 읽는다(명세 "자리와 읽는 때"의 주석). 깨졌으면 실행 식별자가 생기기 전의 `PluginError`라 트레이스가 없고, 재개는 결정 이벤트를 쓰기 전에 끝나 일시정지 그대로다. 꺼진 집합의 읽기와 판정을 가르는 것은 05다
- [ ] **가짜 플러그인 소스가 `Rules`를 들고 읽은 횟수를 센다.** 공개 속성의 선례는 `tests/core/test_run.py`의 `FakePlugins.disabled`다. 실행 한 번에 한 번 읽는 것, 멈춘 사이 규칙을 바꾸면 재개가 새 규칙으로 집행하는 것을 본다. 지금의 `FakePlugins.corrupt`는 `read_disabled`에만 걸리므로(명세 검토가 읽었다) 규칙 파일의 손상을 심는 길을 더한다
- [ ] **두 운영자 파일이 모두 깨졌으면 규칙 파일의 문구가 나오는 것을 두 결함을 함께 심어 본다.** 선례는 `test_준비의_순서는_부재_깨짐_꺼짐_진입점_모델_만들기다`다
- [ ] **HTTP 두 면을 기존 시험 자리에 얇게 둔다.** 깨진 규칙 파일이면 운영자 채널은 500 봉투의 `message`에 그 `PluginError`의 원문을, 최종 사용자 면은 고정 문구의 500을 낸다(스토리 4·17). 선례는 `tests/channel/http/test_router.py`의 `test_실행_전_구성_오류는_500_봉투이고_message_가_그_PluginError_의_문구다`와 `tests/channel/http/test_end_user.py`의 `test_없는_모델은_운영자_면은_500_원문이고_최종_사용자_면은_고정_문구의_500이다`다. 채널 시험의 가짜 플러그인 소스에도 규칙 파일의 손상을 심는 길이 필요하다

### 모델의 도구 목록

- [ ] **컨텍스트가 모델에 도구 목록을 붙이는 자리(`_Context.llm`, `ctx.llm()` 한 번마다 연결의 목록을 한 번 읽는다)에서 운영자의 deny에 맞는 도구를 빼고 붙인다.** 공통 표와 에이전트 표를 합쳐 본다. 저자의 승인 요구와 ask에 맞는 도구는 그대로 붙는다. 목록이 비면 지금처럼 도구 없는 모델을 부른다(`core/loop.py`의 `_bind`). 저자의 승인 요구가 가리키는 도구가 실재하는지 보는 검사(`_reject_unknown_declarations`)는 거르기 전의 전체 목록에 대 본다(ADR 0044). 거르기와 게이트는 같은 적용 규칙 함수로 낸다(명세의 거부한 안: 두 자리에 두면 다른 판단을 할 수 있다)
- [ ] **`ToolAwareFakeModel`이 받은 도구 목록을 기록하도록 넓히거나 새 가짜를 둔다.** 지금 그 가짜의 `bind_tools`는 `binds`만 세고 `tools`를 버린다(명세 검토가 읽었다). 일부만 deny면 그 도구만 빠진 목록을 받는 것, 모두 deny면 `binds`가 0인 것을 본다

### 게이트의 차례

- [ ] **컨텍스트가 도구를 부르는 한 자리(`core/run.py`의 `_Context._call`)를 다음 차례로 만든다.** 루프의 호출과 에이전트의 직접 호출이 같이 지난다(ADR 0009, `.claude/rules/core.md`).
  1. 멈춘 실행이면 더 가지 않는다. 인자를 마스킹한다. 재생 구간이면 기록을 돌려준다(그대로다)
  2. 결정이 있으면 멈춘 호출과 같은 도구 이름, 같은 마스킹된 인자인지 본다. 다르면 결정을 적용하지 않고 `run_resumed` 없이 `run_failed`(원인 `resume_mismatch`)다(그대로다. 서버의 대조는 05가 더한다)
  3. **연결 목록에 없는 이름이면 게이트에 들지 않고 거부한다.** 결과는 `tool_called(ok=false)`, 내용은 어댑터의 문구 그대로 `도구가 없다: <이름>`(예외 타입의 접두 없이), `rule`은 없음이다. 루프에서는 모델에 돌아가고 직접 부른 에이전트는 `ToolError`다. 결정이 있었으면 지금처럼 `run_resumed` 기록과 함께 2 바로 뒤에 소비되어 버려지고, 이 거부와 5의 거부는 그 뒤에 온다(`_take_verdict`와 `_resume`의 차례). to-tickets 시점에 옛 문구 `LookupError: 도구가 없다:`를 단언하는 시험은 없다(Grep으로 봤다)
  4. 적용 규칙을 낸다(02의 함수, 공통 표와 에이전트 표의 합집합)
  5. `deny`면 도구를 부르지 않고 `tool_called(ok=false, rule="deny")`에 `운영자가 거부했다: <서버>:<도구>`를 담아 기록하고 실행은 계속된다. 결정이 있어도 같다
  6. `requires_approval`·`ask`·`default`면 결정이 없을 때 `run_paused(rule=<그 값>, server=<그 도구의 서버>)`로 멈춘다. 결정이 있으면 승인은 부르고 거부는 `tool_called(ok=false)`에 `승인자가 거부했다: <사유>`를 담는다(그대로다)
  7. `allow`면 결정이 없을 때 그냥 부르고 `tool_called.rule`은 `allow`다. 결정이 있으면(멈춘 사이 ask가 allow로 바뀐 재개) 6과 같이 적용한다
  8. 마스킹된 인자가 실제 도구에 가려는 것을 막는 검사와 호출과 기록은 그대로다
- [ ] **결정이 적용된 호출의 `tool_called.rule`은 그 호출을 멈춘 `run_paused.rule`과 같다.** 승인되어 불린 호출도, 승인자가 거부한 호출도 같다. 이 기능 전에 멈춘 실행(`run_paused`에 `rule`이 없다)에 결정을 적용한 호출은 `requires_approval`이다(명세 검토 주석. 그때 멈추는 까닭은 저자의 승인 요구 하나뿐이었다). 예외는 재개 때 운영자의 deny에 맞는 것 하나이고 결정이 무엇이든 `deny`다
- [ ] **갈래마다 core 시험을 둔다.** 선례는 `tests/core/test_run.py`의 "거부", "재개", "결정은 멈춘 호출에 묶인다" 절이다.
  - deny는 루프 호출(모델이 거부 문구를 받고 이어 간다)과 직접 호출(`ToolError`와 문구) 둘 다 본다
  - 저자의 승인 요구에 든 도구가 운영자의 allow에도 맞으면 `requires_approval`로 멈춘다
  - ask와 적힌 규칙 없음은 `run_paused.rule`이 각각 `ask`·`default`이고 `server`가 그 도구의 서버다
  - 연결에 없는 이름은 멈추지 않고 `rule` 없는 거부이고, 결정이 있는 재개에서는 결정이 소비된 뒤 거부된다
  - 운영자의 deny가 결정을 이기는 것은 승인과 거부 두 결정에서 모두 `tool_called(ok=false, rule="deny")`인 것을 보고, 양성 대조로 deny가 아닌 변화(ask → allow)에서는 승인이 불리는 것을 본다
  - 칸 없는 옛 멈춤 기록을 재개하면 승인과 거부 모두에서 `rule`이 `requires_approval`이다
  - 재생 구간의 기록은 다시 쓰지 않아 옛 줄의 없음이 새 값으로 채워지지 않는다

### 가짜의 기본 규칙

- [ ] **core·router·end_user의 세 가짜 플러그인 소스의 기본 규칙은 공통 표의 allow에 자기 서버 전부와 가짜 연결의 기본 서버(03)의 `<서버>:*`를 둔다.** 에이전트 표에 두지 않는다. 05의 에이전트 표 검사가 매니페스트 `mcp`에 없는 서버를 거부하는데, 채널 시험에는 `mcp` 없이 도구를 부르는 에이전트가 있다(`tests/channel/http/test_router.py`의 `ASKING`, 명세 검토가 읽었다). 게이트를 재는 사례만 규칙을 명시한다
- [ ] **이 기본 규칙이 지키는 자리를 빨강으로 대 본다.** 명세 검토가 코드를 읽어 셌다(어림이고, 채널 시험은 "적어도"다). `tests/core/test_run.py`는 서버 없는 가짜 플러그인 소스로 도구를 부르는 시험 열둘(임시 스크립트로 손으로 봤다)과, 서버 `srv`를 주지만 가짜 연결의 도구에 서버가 없는 `_gated_plugins`의 시험 마흔아홉이다. 마흔아홉은 명세 검토의 셈이고 기준이 보고에 남지 않았다. 셀프 리뷰의 두 축은 `_gated_plugins`를 직접 부르는 최상위 시험을 AST로 세어 예순일곱을 냈다(손으로 봤다). 그 가운데 승인 요구가 든 도구만 불러 지금도 멈추는 시험은 기본 규칙 없이도 빨개지지 않는다(차례에서 저자의 승인 요구가 적힌 규칙 없음보다 먼저라는 데서 낸 어림. 시험을 하나씩 읽지 않았다). 이 문장은 기본 규칙 때문에 나는 빨강만 말한다. 두 칸을 채워서 나는 빨강은 아래 불릿이다. `tests/channel/http/test_router.py`는 `asking`·`adding`·`careful`을 쓰는 넷, `tests/channel/http/test_end_user.py`는 `working`·`looping`을 쓰는 셋이다. 기본 규칙을 넣기 전의 빨강이 이 셈과 크게 다르면 PR 본문에 적는다

### 저장소와 e2e의 규칙 파일

- [ ] **저장소의 `plugins/rules.toml`을 둔다.** `schema_version = "1"`과 에이전트 표 하나 `[agents.calc] allow = ["everything:*"]`이고 공통 표는 두지 않는다(예시가 배치 전체를 여는 모양을 보이지 않기 위해서다). 파일 머리의 주석이 세 꼴과 차례를 한 줄씩 적는다. `README.md`의 플러그인 루트 트리에 `rules.toml` 줄을 `disabled.toml` 줄 옆에 둔다

- [ ] **`-m llm` 도우미 `_copy_repo_plugins`(`tests/test_main.py`)가 `rules.toml`도 복사한다.** 지금은 calc와 그것이 쓰는 플러그인 폴더 넷만 복사해 루트의 규칙 파일이 따라가지 않는다

- [ ] **이 규칙 파일들이 지키는 시험을 확인한다.** 명세 검토의 코드 읽기로, 규칙 파일 없이 이 티켓만 서면 멈추는 것은 `-m llm`의 calc 시험 셋(`plugins/`를 통째 복사하는 모델 이름 시험, 저장소 루트에서 도는 calc 이어 가기, `_copy_repo_plugins`로 네 폴더만 복사하는 요약 시험)과, 위젯 e2e의 `tools` 에이전트를 쓰는 사례들(`?agent=tools`)과 `-m llm_widget`의 calc다. 관리 화면 e2e의 결정 흐름 에이전트 둘과 `-m llm`이 아닌 `tests/test_main.py`의 도구 에이전트는 승인 요구가 든 `add`만 부르므로 그대로다(코드를 읽었다)
