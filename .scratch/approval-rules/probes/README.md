# approval-rules 프로브

명세(`../spec.md`)가 근거로 드는 측정이다. 규약은 `docs/agents/issue-tracker.md`의 프로브와 근거 절과 `.claude/rules/probes.md`.

## 돌리는 법

워크트리에서 돈다. `.env`는 저장소 루트의 것이고 읽지 않고 넘긴다(`docs/constitution/operations.md` LLM 테스트).

```bash
uv run --env-file ../../../.env python .scratch/approval-rules/probes/all_deny_resume_call.py
```

종료 코드 0은 측정이 아닌 회차가 없었다는 뜻이고 결론은 출력의 `결과:` 줄과 회차 줄로 읽는다(`tools/probe_kit.py`의 `Rounds`).

## 결과

### `all_deny_resume_call.py` — 도구 호출 블록이 든 대화를 도구 정의 없이 보내면 API가 받는가

2026-11-05, 모델 플러그인 `claude-opus-5`(응답의 `model` 칸도 `claude-opus-5`), langchain-anthropic 1.7.2, anthropic 1.7.0. 멈춘 호출을 운영자 deny로 거부한 직후의 메시지 열(사람 메시지 → `add(a=2, b=3)` 도구 호출 → `운영자 규칙이 거부했다: add` 도구 결과)을 `run_loop`의 모양대로 손으로 지어, 세 갈래로 두 회차씩 보냈다. 측정 6회차, 측정 아님 0회차, 종료 코드 0.

| 갈래 | 붙인 도구 정의 | 회차 | 결과 | 입력 토큰 |
|---|---|---|---|---|
| 도구없음(재려는 길) | 없음(`_bind`가 맨 모델을 돌려준다) | 2 | 2회 모두 수락, 도구 호출 없음 | 123 |
| 도구있음(양성 대조) | `add` | 2 | 2회 모두 수락, 도구 호출 없음 | 492 |
| 선택없음 | `add`와 `tool_choice` `{"type": "none"}` | 2 | 2회 모두 수락, 도구 호출 없음 | 492 |

해석. **도구 호출 블록이 든 대화를 도구 정의 없이 보내도 이 모델의 API는 받는다.** ADR 0044 Consequences "치르는 값"의 어림("API가 그런 요청을 거부하면 원인 `model_call`의 `run_failed`다")은 이 측정에서 서지 않았다. 사전에 적은 판정대로 명세는 모두 deny인 재개에 처리를 따로 두지 않는다. 블록이 모델에 실제로 갔다는 것은 두 관찰로 읽는다. 도구없음 갈래의 둘째 회차 응답이 도구 결과에만 있는 문구(`운영자 규칙이 거부했다`)와 호출(`add(a=2, b=3)`)을 되울렸고(출력을 봤다), 도구없음 갈래의 입력 토큰(123)이 도구 정의를 붙인 두 갈래(492)보다 작되 사람 메시지 한 줄의 크기(어림 20 안팎)보다는 훨씬 크다. 둘째 관찰은 결과를 본 뒤 더한 어림이다.

갈래가 가른 것. 도구있음이 수락이라 도구없음의 결과를 대화의 모양 탓으로 돌릴 수 없고, 도구없음이 수락이라 "도구 정의가 없어 거부된다"는 해석이 섰을 때의 처리 후보(선택없음)는 쓰이지 않는다. 선택없음 갈래가 수락인 것은 `tool_choice` `{"type": "none"}`을 이 API가 받는다는 것까지이고 명세는 그것을 쓰지 않는다.

재지 않은 것. 실제 재개 길(재생 뒤 게이트의 거부 기록 뒤의 모델 호출)은 지나지 않았다. 그 길은 구현 티켓의 `-m llm` 시험이 잰다(명세 "실제 모델 시험 하나"). 역사에 `add` 블록이 있는데 다른 도구(`mul`)만 붙인 갈래(일부 deny의 재개)는 돌리지 않았다. 도구 정의가 하나도 없어도 받으므로 다른 정의가 있어도 받을 것이라는 어림이다. 다른 모델과 다른 날의 API, 그리고 회차 둘이 잡지 못하는 드문 흔들림도 재지 않았다. 프로브가 도구 결과에 쓴 거부 문구 `운영자 규칙이 거부했다: add`는 명세가 뒤에 정한 `운영자가 거부했다: <서버>:<도구>`와 다르다(명세 전에 돌렸다). 재는 것은 요청의 모양(도구 호출 블록이 있고 도구 정의가 없다)이고 도구 결과의 글은 내용이라 수락 여부에 들지 않는다고 보지만, 명세의 문구로 다시 돌리지는 않았다(어림).

측정 뒤 고친 것. PR 직전 버그·성능 리뷰가 짚어, 400 응답을 본문에 도구 문구(`tool`)가 있을 때만 거부로 세고 다른 400(잘못된 파라미터 등)은 측정 아님으로 세게 판정을 좁혔다(`.claude/rules/probes.md` 첫 항목. 어떤 400이든 거부로 세던 첫 판은 다른 까닭의 400을 도구 정의 없음의 거부로 읽을 수 있었다). 기록된 여섯 회차에 400은 없어 위 결과는 그대로이고, 다시 돌리지 않았다.

LLM 토큰 합계: 입력 2214 출력 920(여섯 회차의 `usage_metadata`를 더했다).
