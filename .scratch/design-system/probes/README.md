# design-system 프로브

명세·ADR·코드 주석이 근거로 드는 측정 스크립트다. 규약은 `docs/agents/issue-tracker.md`의 "프로브와 근거".

`font_shadow/`는 페이지 안 위젯 번들(Shadow DOM 커스텀 요소, ADR 0024)에 한글 웹폰트를 싣는 길을 고르는 측정이다. 글꼴은 npm 패키지 `pretendard`를 저장소 밖 작업 폴더에 받아 풀고 그 `package/`를 인자로 준다. 받은 글꼴과 결과 JSON은 저장소에 두지 않는다. 저장소 루트에서 돈다.

```sh
npm pack pretendard@1.3.9 --pack-destination <작업 폴더>
tar -xzf <작업 폴더>/pretendard-1.3.9.tgz -C <작업 폴더>
node .scratch/design-system/probes/font_shadow/sizes.mjs <작업 폴더>/package --out <작업 폴더>/sizes.json
node .scratch/design-system/probes/font_shadow/measure.mjs <작업 폴더>/package --out <작업 폴더>/measure.json
node .scratch/design-system/probes/font_shadow/measure.mjs <작업 폴더>/package --playwright <playwright-core 폴더> --out <작업 폴더>/measure-other.json
```

넷째 줄은 `web/apps/admin`에 깔린 Playwright로 돈다. 다섯째 줄은 그 판의 Firefox·WebKit 빌드가 없을 때 이미 깔린 빌드에 맞는 다른 판의 playwright-core 폴더를 준다.

`storybook/`은 디자인 시스템 패키지(`packages/ui`)에 Storybook을 들이는 조합이 워크스페이스 판정자를 우회 없이 지나는지 재는 측정이다. `.scratch/web-widget/probes/widget_stack/`처럼 저장소 `web/`을 저장소 밖 사본으로 복사하고 `ui/`를 덮어써 실제로 설치한다. 저장소 루트에서 차례로 친다(첫 줄이 npm 레지스트리에 닿는다).

```sh
node .scratch/design-system/probes/storybook/setup.mjs <작업 루트>
node .scratch/design-system/probes/storybook/verify.mjs <작업 루트>/storybook
node .scratch/design-system/probes/storybook/cases.mjs <작업 루트>/storybook
node .scratch/design-system/probes/storybook/style.mjs <작업 루트>/storybook
node .scratch/design-system/probes/storybook/build.mjs <작업 루트>/storybook
node .scratch/design-system/probes/storybook/deps.mjs <작업 루트>/storybook
```

`visual_docker/`는 시각 회귀의 정답 사진을 판을 고정한 Playwright Linux Docker 이미지 안에서만 찍는 결정이 서는지 재는 측정이다. 같은 이미지에서 컨테이너를 따로 두 번 띄워 같은 표본(`visual_docker/site/index.html`)을 찍은 사진이 픽셀까지 같은지, 그 사진이 Windows 호스트 chromium의 사진과 얼마나 다른지 본다. 글꼴은 `font_shadow/`와 같은 Pretendard `package/`를 인자로 준다. 사진과 결과 JSON은 저장소 밖 작업 폴더에만 쓴다. 저장소 루트에서 돈다(`--pull`이 레지스트리에서 이미지를 받고, 받은 이미지는 지우지 않는다).

```sh
node .scratch/design-system/probes/visual_docker/run.mjs <작업 폴더>/package --work <작업 폴더>/visual_docker --pull
```

`tokens/`는 명세가 탐색 결과(`../design/`의 v3)를 받아 ADR 0026이 첫 티켓에 넘긴 측정을 재는 자리다. `design.mjs`가 커밋한 디자인 파일의 스크립트를 돌려 디자인 토큰을 뽑고, `setup.mjs`가 `storybook/`의 작업 루트 위에 두 층 디자인 토큰 CSS, 테마 글꼴, 판정 함수와 스토리(`ui/`)를 얹고 글꼴 패키지와 관리 화면의 Tailwind를 설치한다. `measure.mjs`가 스토리 테스트, Storybook 정적 빌드, 정적 빌드 위의 전환·상태 색·움직임과 글꼴, 관리 화면의 `next build`·`next start`를 재고, `visual.mjs`가 정적 빌드를 Playwright Linux 이미지에서 찍고 같은 이미지 안에서 Linux 빌드도 지어 찍는다. 마지막 두 줄은 표본을 얹은 사본이 판정자를 지나는지 보는 것이고, 정적 빌드를 지운 뒤 돈다. 저장소 루트에서 차례로 친다(`storybook/setup.mjs`, `tokens/setup.mjs`, `visual.mjs`의 Linux 빌드가 npm 레지스트리에 닿는다).

```sh
node .scratch/design-system/probes/tokens/design.mjs
node .scratch/design-system/probes/storybook/setup.mjs <작업 루트>
node .scratch/design-system/probes/tokens/setup.mjs <작업 루트>
node .scratch/design-system/probes/tokens/measure.mjs <작업 루트>/storybook
node .scratch/design-system/probes/tokens/visual.mjs <작업 루트>/storybook --work <작업 폴더>/visual_tokens
rm -rf <작업 루트>/storybook/web/packages/ui/storybook-static
pnpm -C <작업 루트>/storybook/web verify
```

`tokens/libmode.mjs`는 명세 검토(2026-10-06)가 짚은 것을 재는 자리다. 디자인 토큰 CSS와 글꼴 CSS를 Vite 라이브러리 모드(페이지 안 위젯 번들의 빌드, ADR 0024)와 Tailwind CLI(패키지의 `build`)가 어떻게 내는지 본다. `tokens/setup.mjs`를 마친 작업 루트에서 저장소 루트로부터 친다. 아무것도 설치하지 않고 레지스트리에 닿지 않는다.

```sh
node .scratch/design-system/probes/tokens/libmode.mjs <작업 루트>/storybook
```

## 2026-10-06 결과 — font_shadow

- shadow 안의 `@font-face`: Chromium 153·145와 Firefox 146은 `<style>`에 두든 `adoptedStyleSheets`에 두든 쓰지 않았다. 규칙은 `CSSFontFaceRule`로 시트에 남지만 글꼴 요청이 0건이고 `document.fonts`가 비었으며, 위젯 글자 폭은 대체 글꼴(monospace)의 폭이었다(Chromium CDP는 GulimChe로 그렸다고 답했다). WebKit 26.0은 두 자리 모두 적용했는데, 그 글꼴이 `document.fonts`에 들고 같은 family를 쓰는 사이트 글자에도 적용됐다.
- 문서에 선언하면(`<style>`, FontFace API 둘 다) 세 브라우저 모두 shadow 안 글자에 적용됐다. 요청 1건, 765,892바이트, `loaded`.
- 다른 출처 글꼴: 글꼴 출처가 CORS 머리글 없이 내면 Chromium·Firefox는 요청이 나가 서버가 파일을 다 냈는데도 CORS로 막아 `error`, 대체 글꼴로 그렸다. `Access-Control-Allow-Origin: *`를 붙이면 `<style>`과 FontFace API 모두 적용됐다. WebKit 빌드는 글꼴을 `Sec-Fetch-Mode: no-cors`로 받아 머리글 없이도 적용했다.
- 상속: 사이트 `body { font-family: serif }`는 shadow 안으로 상속됐고 `:host { font-family }`가 막았다. 사이트가 `* { font-family }`나 호스트 태그 선택자로 호스트 요소를 직접 겨냥하면 세 브라우저 모두 사이트가 `:host`를 이겼다(호스트 계산값도, 안쪽 글자도 serif). `:host`에 `!important`를 붙이면 사이트의 보통 선언과 `!important` 선언을 모두 이겼다. shadow 안의 감싼 요소에 `font-family`를 두면 사이트 `*`가 닿지 않아 위젯 글꼴이 됐다(호스트 계산값은 serif로 남는다).
- 같은 이름으로 문서에 선언하면 사이트에 샌다. 사이트가 `@font-face` 없이 `font-family: "Pretendard"`를 쓰면(이 기계에 로컬 설치 없음) 위젯의 선언으로 사이트 글자가 대체 글꼴에서 위젯 파일로 바뀌었다(세 브라우저, `<style>`과 API 둘 다). 사이트가 자기 `@font-face`(Black 파일)를 가졌을 때 위젯이 뒤에 `<style>`로 같은 이름을 선언하면 세 브라우저 모두 사이트 글자도 위젯 파일로 바뀌고 사이트의 Black은 받지도 않았다(`unloaded`). API로 더하면 Chromium·Firefox는 위젯 파일이, WebKit은 사이트의 Black이 이겼다. 위젯이 같은 이름을 shadow에만 선언하면 Chromium·Firefox는 위젯 글자를 사이트의 Black으로 그렸고, WebKit은 사이트 글자까지 위젯 파일로 바꿨다.
- 고유한 이름(`agent-os-sans`)으로 문서에 선언하면 사이트 글자 폭은 위젯이 없을 때와 같았다(세 브라우저). 사이트에서 보이는 것은 `document.fonts`의 항목 하나와, `<style>` 길일 때 `document.styleSheets`가 0에서 1로 는 것이다. API 길은 시트 수가 늘지 않았다.
- Pretendard 1.3.9, `OFL-1.1`. 저작권 줄이 `with Reserved Font Name Pretendard`다.
- 크기(바이트): Regular 전체 765,892, 9 굵기 합 6,901,476, 가변 하나 2,057,688, 고정 서브셋 Regular 267,096(`subset_glyphs.txt` 3,720자, 한글 음절 2,780자, 문장을 덮는다). 동적 서브셋은 굵기마다 92조각이고(정적 9 굵기 828파일), Regular 92조각 합 1,162,108(조각 3,992~19,780), 가변 92조각 합 2,957,724(8,252~43,920). 조각의 범위가 덮는 한글 음절은 11,172자 전부다.
