# design-system: 위젯과 관리 화면이 함께 쓰는 디자인 토큰과 기본 컴포넌트, 화면 사진 비교 검사를 만든다.

위젯과 관리 화면이 나누는 디자인 시스템 하나. 원천은 코드이고 Claude Design은 탐색과 화면을 맡는다(ADR 0025). 설계 인터뷰(일지 2026-10-06-05, ADR 0026), Claude Design 탐색(`.scratch/design-system/design/`의 v3, 기본 테마 먹), 명세(`.scratch/design-system/spec.md`, 일지 2026-10-06-13, ADR 0026의 넷째 2026-10-06 이력)가 2026-10-06에 끝났다. 무엇을 짓는지와 판정의 자리는 그 명세가 원천이다. 티켓은 넷이다(`.scratch/design-system/issues/`, 2026-10-06, 일지 2026-10-06-14). 01 디자인 토큰·스토리 테스트 이음매·아이콘·버튼·아이콘 버튼 → 02 사진 비교 게이트(01 뒤) → 03 상태 배지·진행 표시·카드와 04 글 입력·스위치·알림(01·02 뒤, 나란히). 03과 04 가운데 마지막에 병합되는 쪽이 닫는다. 명세 검토(2026-10-06)는 blocker 1·should-fix 13·nit 12였고 명세의 주석과 티켓으로 닫았다. to-tickets에서 사용자가 고른 것: 글꼴 CSS를 디자인 토큰 CSS와 나눠 `./fonts.css`로 낸다(페이지 안 번들이 글꼴 약 18MB를 data URL로 박았다, `probes/tokens/libmode.mjs`), 판정 함수를 `./testing`으로 내보내고 앱 스토리의 자리는 01이 ADR 0026 이력 초안으로 정한다(추천과 달랐다), 패키지 `build`의 글꼴은 첫 `/design-sync`에서 본다. `web/packages/ui` 하나에 디자인 토큰, 테마 다섯의 글꼴, atoms·molecules 아홉, Storybook을 두고, 스토리 테스트 하나와 사진 비교 게이트로 판정한다(게이트가 열둘이 된다). 승인을 묻는 화면의 버튼 글자는 "승인"과 "거부"다(사용자 결정, 일지 2026-10-06-12). 코드를 만든 뒤 사용자가 시작하는 `/design-sync`로 Claude Design의 디자인 시스템 프로젝트에 올린다. 티켓 02(2026-10-07, PR #158)가 사진 비교 게이트를 들였다(`pnpm -C web visual`, CI `visual` 잡, 게이트 열둘). GitHub 러너의 사진은 그 PR의 CI에서 로컬 컨테이너가 만든 정답과 같았다. 03·04는 01·02 뒤에 나란히 돌았다. 재지 못한 그 밖의 것은 `.scratch/design-system/probes/README.md`의 "재지 못한 것"이다.
