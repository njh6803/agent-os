# 인터럽트: 사람 승인으로 실행을 멈추고 재생해 재개한다

Status: ready-for-agent

슬라이스 2(`interrupts`). 근거는 `docs/adr/0009`(이 기능의 결정 전부), `docs/adr/0001`의 2026-09-21 재측정 이력, `docs/adr/0008`과 그 이력, `docs/PRD.md`, `docs/constitution/`, 그리고 2026-09-21 설계 인터뷰(일지). 용어는 `CONTEXT.md`의 `## 인터럽트` 절을 따른다. 새 결정을 만들지 않는다. 결정이 필요해지면 멈추고 ADR을 제안한다.

## Problem Statement

지금 실행은 시작하면 끝까지 간다. 에이전트가 메일을 보내든 이슈를 닫든 파일을 지우든, 사람이 그 앞에 끼어들 자리가 없다. `requires_approval` 같은 개념이 없으므로 위험한 도구와 안전한 도구가 런타임에게 똑같아 보인다.

PRD가 지목한 문제가 이것이다. "빌더는 PoC에는 좋지만 프로덕션에서 필요한 **상태 제어, 예외 처리**가 안 된다." 운영자는 "어떤 에이전트, 도구, 모델이 등록돼 돌아가는지 한 곳에서 보고 켜고 끄고" 싶은데, 지금 켜고 끌 수 있는 단위가 MCP 서버 전체뿐이라 "이 도구만 사람이 보고 나서"가 표현되지 않는다.

에이전트 저자가 스스로 조심하게 만드는 길도 있지만 그것은 가드레일이 아니다. 에이전트는 플러그인이고 신뢰 경계 밖이며, 저자가 잊거나 모델이 예상 밖으로 도구를 엮으면 그대로 실행된다. 가드레일은 런타임이 걸어야 하고, 운영자가 코드를 고치지 않고 바꿀 수 있어야 한다.

그리고 사람의 승인은 사람의 속도로 온다. 실행이 승인을 기다리며 프로세스를 붙들고 있으면 그것은 승인 게이트가 아니라 확인 프롬프트다. CLI 창을 닫으면 사라지고, 하루 뒤에 답하는 것이 불가능하고, 나중에 HTTP 채널이 붙어도 요청 하나가 서버 워커를 하루 점유한다.

## Solution

에이전트 매니페스트에 `requires_approval`로 승인이 필요한 도구 이름을 적어 둔다. 런타임이 그 도구를 부르기 직전에 **실행을 끝낸다**. 실행은 실패한 것도 끝난 것도 아닌 **일시정지** 상태로 트레이스에 남고, 프로세스는 죽어도 된다.

사람이 CLI로 승인하거나 거부하면 런타임이 그 결정을 트레이스에 쓰고, 에이전트를 **처음부터 다시** 돌린다. 이미 한 모델 호출과 도구 호출은 실제로 다시 부르지 않고 트레이스에 기록된 값으로 **재생**해 멈췄던 자리까지 되돌아간 뒤, 거기서부터 진짜로 이어 간다. 재개는 새 실행이 아니라 **같은 실행**이고 `run_id`도 트레이스 파일도 하나다.

사용자가 보는 것은 넷이다. 멈출 때 표준 출력에 찍히는 `run_id`와 "무엇을 승인해 달라는지", `run_failed`와 구분되는 전용 종료 코드, `agent-os resume <run_id> --approve | --deny` 명령, 그리고 한 파일에 이어 쌓이는 트레이스.

`requires_approval`이 없거나 비어 있으면 지금과 똑같이 동작한다. 이 기능은 선택이고, 켜지 않은 에이전트는 아무 비용도 치르지 않는다.

## User Stories

### 에이전트를 만드는 개발자

1. 에이전트 개발자로서, 승인이 필요한 도구를 매니페스트 한 줄로 선언하고 싶다. 에이전트 코드를 고치지 않고 가드레일을 걸기 위해서다.
2. 에이전트 개발자로서, 에이전트 코드가 인터럽트의 존재를 몰라도 되기를 바란다. 승인 정책이 바뀌어도 에이전트를 다시 쓰지 않기 위해서다.
3. 에이전트 개발자로서, `requires_approval`을 비워 두면 지금과 똑같이 동작하기를 바란다. 이 기능을 안 쓰는 에이전트가 비용을 치르지 않게 하기 위해서다.
4. 에이전트 개발자로서, 모델이 부르든 내가 컨텍스트로 직접 부르든 같은 정책이 걸리기를 바란다. 경로를 바꿔 빠져나갈 수 있는 가드레일을 믿을 수 없기 때문이다.
5. 에이전트 개발자로서, 직접 부른 도구가 거부당하면 이름으로 잡을 수 있는 예외를 받고 싶다. 그 자리에서 다른 길을 고를 수 있게 하기 위해서다.
6. 에이전트 개발자로서, 거부 예외에 사람이 적은 사유가 담기기를 바란다. 사용자에게 왜 안 됐는지 전할 수 있게 하기 위해서다.
7. 에이전트 개발자로서, 매니페스트에 적은 도구 이름이 실재하지 않으면 실행이 실패하기를 바란다. 오타 하나가 가드레일을 조용히 끄지 않게 하기 위해서다.
8. 에이전트 개발자로서, 프롬프트에 날짜를 넣는 평범한 에이전트도 재개될 수 있기를 바란다. 시각 때문에 재개 불가가 되는 것은 내 잘못이 아니기 때문이다.
9. 에이전트 개발자로서, 재개가 모델을 다시 부르지 않기를 바란다. 승인 한 번에 토큰 값을 두 번 내지 않기 위해서다.
10. 에이전트 개발자로서, 승인을 기다리는 사이 에이전트를 고쳤다면 재개가 조용히 성공하지 않기를 바란다. 옛 실행의 기록을 새 코드에 먹이는 것은 성공이 아니기 때문이다.
11. 에이전트 개발자로서, 재개가 실패했을 때 무엇이 어긋났는지 트레이스에서 보고 싶다. 고칠 곳을 찾기 위해서다.
12. 에이전트 개발자로서, 에이전트가 낸 이벤트가 재개 뒤 트레이스에 두 번 쌓이지 않기를 바란다. 실행의 기록을 세거나 되짚을 때 중복을 걸러내지 않아도 되게 하기 위해서다.

### 승인자

13. 승인자로서, 에이전트가 무슨 도구를 무슨 인자로 부르려는지 보고 싶다. 무엇을 허락하는지 모르고 허락하지 않기 위해서다.
14. 승인자로서, 프로세스를 켜 둔 채 기다리지 않아도 되기를 바란다. 내 답이 몇 시간 뒤에 올 수도 있기 때문이다.
15. 승인자로서, 승인할 때 실행 식별자 하나만 있으면 되기를 바란다. 멈춘 실행을 다시 찾아가는 일이 쉬워야 하기 때문이다.
16. 승인자로서, 거부에 사유를 달 수 있기를 바란다. 에이전트가 왜 안 되는지 알고 다르게 시도할 수 있게 하기 위해서다.
17. 승인자로서, 거부가 실행을 죽이지 않기를 바란다. 그때까지 한 일과 에이전트가 상황을 설명할 기회를 버리지 않기 위해서다.
18. 승인자로서, 내가 승인했다는 사실이 기록에 남기를 바란다. 나중에 누가 허락했는지 물을 때 답이 있어야 하기 때문이다.
19. 승인자로서, 지금은 내가 요청하고 내가 승인해도 되기를 바란다. 혼자 쓰는 동안 기능을 못 쓰게 되지 않기 위해서다.
20. 승인자로서, 답이 늦어도 일시정지가 만료되지 않기를 바란다. 사라진 실행을 다시 처음부터 돌리는 것이 더 비싸기 때문이다.
21. 승인자로서, 한 번에 한 가지만 판단하고 싶다. 여러 도구를 한꺼번에 보여 주고 부분 승인을 요구하면 실수하기 쉽기 때문이다.
22. 승인자로서, 이미 끝난 실행이나 일시정지가 아닌 실행을 승인하려 하면 분명한 오류를 받고 싶다. 아무 일도 안 일어난 것과 구분하기 위해서다.

### 운영자

23. 운영자로서, 어떤 도구가 승인 대상인지 한 곳에서 보고 싶다. 가드레일의 범위를 코드를 읽지 않고 알기 위해서다.
24. 운영자로서, 승인 정책을 에이전트마다 다르게 두고 싶다. 같은 도구가 에이전트에 따라 다른 위험도를 갖기 때문이다.
25. 운영자로서, 비밀로 선언한 인자가 트레이스에 남지 않기를 바란다. 트레이스를 나중에 공유하거나 관리 화면에 띄울 것이기 때문이다.
26. 운영자로서, 사람이 거부한 일을 모델이 다른 도구로 돌아가 해내지 못하게 하고 싶다. 우회할 수 있는 가드레일은 가드레일이 아니기 때문이다.
27. 운영자로서, 멈추고 재개하기를 반복해 실행이 무한히 도는 일이 없기를 바란다. 비용이 무한정 늘지 않게 하기 위해서다.
28. 운영자로서, 승인자 없는 승인이 애초에 불가능하기를 바란다. 지금 비용이 0일 때 필수로 만들지 않으면 나중에 기본값이 fail-open으로 굳기 때문이다.
29. 운영자로서, 일시정지가 실패와 다르게 보이기를 바란다. 스크립트가 둘을 같게 다루면 멈춘 실행을 잃어버리기 때문이다.
30. 운영자로서, 실패한 재개도 트레이스를 남기기를 바란다. 실패야말로 되짚어야 하는 것이기 때문이다.
31. 운영자로서, 트레이스 파일 하나가 실행 하나의 전모를 담기를 바란다. 재개가 여러 번 끼어도 조각을 모으지 않기 위해서다.
32. 운영자로서, 트레이스 형식이 바뀌었을 때 옛 파일이 조용히 다르게 해석되지 않기를 바란다. 형식 버전이 그 일을 하라고 있기 때문이다.
33. 운영자로서, 승인 정책이 있는 실행과 없는 실행의 트레이스를 같은 도구로 읽고 싶다. 형식이 갈라지면 읽는 쪽이 두 배가 되기 때문이다.

### 최종 사용자

34. 최종 사용자로서, 에이전트가 되돌리기 어려운 일을 하기 전에 나에게 묻기를 바란다. 에이전트의 판단을 전적으로 믿지는 않기 때문이다.
35. 최종 사용자로서, 내가 거부했을 때 에이전트가 왜 못 했는지 말해 주기를 바란다. 조용히 실패한 것과 구분하기 위해서다.

### 런타임 기여자

36. 런타임 기여자로서, 이 기능이 포트를 늘리지 않기를 바란다. 포트 목록이 닫혀 있다는 규칙의 값이 거기서 나오기 때문이다.
37. 런타임 기여자로서, 체크포인터라는 별도 부품이 생기지 않기를 바란다. 같은 사실이 두 곳에 남으면 언젠가 어긋나기 때문이다.
38. 런타임 기여자로서, 재개가 core의 함수 하나이기를 바란다. 나중에 HTTP 채널이 같은 것을 부르게 하기 위해서다.
39. 런타임 기여자로서, 재개의 시그니처가 거짓말을 하지 않기를 바란다. 받지도 않을 인자를 받는 모양이면 읽는 사람이 속기 때문이다.
40. 런타임 기여자로서, 이벤트의 열만 단언하는 기존 주 이음매가 이 기능도 덮기를 바란다. 이음매가 늘면 어디를 밀어야 하는지 세야 하기 때문이다.
41. 런타임 기여자로서, 가짜 어댑터가 포트를 상속하지 않고 시그니처로 만족하기를 바란다. 포트가 바뀌면 타입 검사가 가짜를 깨뜨려 알려 주게 하기 위해서다.
42. 런타임 기여자로서, 기본 테스트 스위트가 네트워크 없이 돌기를 바란다. 커밋마다 훅이 돌아도 비용과 시간이 들지 않게 하기 위해서다.
43. 런타임 기여자로서, 프로세스가 실제로 죽었다 살아나는 것을 증명하는 테스트가 하나 있기를 바란다. 가짜 포트로는 증명할 수 없는 유일한 주장이기 때문이다.
44. 런타임 기여자로서, 비결정적인 값이 컨텍스트를 지나야 한다는 제약이 문서로 남기를 바란다. 다음 사람이 컨텍스트를 우회하면 재생이 조용히 깨지기 때문이다.
45. 런타임 기여자로서, 마스킹이 재생을 깨뜨릴 수 있는 조합이 실행 전에 거부되기를 바란다. 실행 도중에 발견하면 이미 승인을 받은 뒤이기 때문이다.
46. 런타임 기여자로서, 원칙 III를 지키며 이 기능을 만들 수 있기를 바란다. 타입 우회를 한 번 허용하면 그것이 선례가 되기 때문이다.

## Implementation Decisions

전부 ADR 0009가 결정한 것이다. 여기서는 구현이 닿는 자리로 옮겨 적는다. 새 결정은 없다.

### 이음매

테스트가 미는 지점은 다섯이고 **전부 기존 이음매다. 새 이음매를 만들지 않는다.**

가장 높은 곳은 `core`의 주 이음매다. 포트를 가짜로 주입하고 이벤트의 열만 단언하는 그 지점이 이 기능의 행동을 거의 전부 판정한다. 인터럽트가 곧 이벤트의 열이 바뀌는 기능이기 때문에 그 이음매의 모양이 그대로 맞는다. 나머지 넷(`sdk` 이벤트, `sdk` 매니페스트, 트레이스 어댑터, CLI 표면)은 계약과 디스크 형식과 표면을 각각 얇게 엇번다.

### sdk 계약 — 이벤트

- 이벤트 종류 넷이 는다. **`RunPaused`**(승인을 기다리며 멈췄다. 어떤 도구를 어떤 인자로 부르려 했는지 담는다), **`ApprovalGranted`**(승인자), **`ApprovalDenied`**(승인자, 사유), **`RunResumed`**(재생 구간이 끝나고 실제 실행이 다시 시작된다).
- 승인과 거부를 하나의 `approved: bool`로 합치지 않는다. 거부만 사유를 갖는 비대칭이 실제로 있고, `sdk`가 이미 "종류별 클래스와 판별 유니온, 타입 검사가 지켜 주는 쪽"을 골랐다. `RunFinished`와 `RunFailed`를 쪼개 둔 것과 같은 결이다.
- 기존 이벤트 둘이 두꺼워진다. **`LlmCalled`** 가 모델이 낸 텍스트와 도구 호출을, **`ToolCalled`** 가 인자와 결과 내용을 담는다. 관찰에만 쓰이던 트레이스가 재개의 입력이 되기 때문이다.
- `BaseEvent`의 `run_id`와 `ts`는 새 이벤트 넷에도 그대로 필수다. 원칙 V.
- 이벤트 형식마다 버전을 붙이지 않는다. 트레이스 파일 첫 줄 헤더가 그 역할을 한다(ADR 0008).

### sdk 계약 — 매니페스트

- 에이전트 매니페스트에 **`requires_approval`**: 승인 없이는 부를 수 없는 도구 이름들. 선택 필드이고 기본은 비어 있다.
- mcp 매니페스트의 서버 절에 **`secret_args`**: 트레이스에 마스킹해 쓸 인자 이름들. 선택 필드이고 기본은 비어 있다.
- **`schema_version`은 `"1"` 그대로다.** 둘 다 선택 필드라 옛 매니페스트가 다르게 해석될 여지가 없다. 버전을 올리는 것은 기존 필드의 뜻이나 필수 여부가 바뀔 때다(ADR 0008 이력).
- **금지 규칙**: `secret_args`를 가진 도구는 `requires_approval`에 들어갈 수 없다. 마스킹된 인자는 복원할 수 없어, 승인받아 실제로 실행되는 그 호출이 마스킹된 값을 보내게 된다. 둘 다 매니페스트에 적히므로 매니페스트를 읽는 단계에서 정적으로 판정하고 거부한다. 실행 식별자가 생기기 전이므로 구성 오류로 끝나고 트레이스가 없다.
- **실재 검사**: `requires_approval`이 가리키는 도구가 실제로 있는지는 매니페스트만으로 알 수 없다. 도구 목록은 MCP 서버에 붙어야 나온다. 그래서 이것만은 도구 연결 직후에 검사하고, 어긋나면 실행 안의 실패로 끝난다. 트레이스가 남는다.

### 트레이스 형식

- 첫 줄 헤더의 형식 버전을 **2**로 올린다.
- 버전 1 파일은 **재개를 거부한다**. 읽기 자체를 막지는 않는다. 관리가 옛 트레이스를 보여 줄 수 있어야 하고, 재개만 성립하지 않기 때문이다.
- 재개는 같은 트레이스 파일에 이어 쓴다. 실행 하나에 파일 하나라는 대응이 유지된다.

### core — 포트

- `TraceSink`가 **`TraceStore`** 가 된다. `read(run_id)`가 는다.
- **포트는 다섯 그대로다.** 닿는 바깥 지점은 "트레이스 저장소" 하나이지 새 지점이 아니다. 쓰는 곳과 읽는 곳이 항상 같다는 사실을 타입이 강제한다.
- `Sink`라는 이름이 쓰기 전용을 뜻하므로 개명이 필요하다. 포트 표가 있는 규칙 문서를 코드와 같은 티켓에서 고친다.
- 같은 필요가 `admin-api`의 트레이스 조회에서도 곧 생긴다. 그 기능이 이 포트를 재사용한다.

### core — 재개 진입점

- **`resume(run_id, decision, approver, *, 포트들)`** 이 `run()` 옆에 선다. 반환은 `run()`과 같은 이벤트의 async iterator다.
- `run()`의 인자로 넣지 않는다. 입력이 실제로 다르기 때문이다. 재개는 에이전트 이름, 요청, 주체를 받지 않고 트레이스의 `run_started`에서 읽는다. 하나로 합치면 "재개일 때는 이 인자 셋이 무시된다"는, 타입으로 막을 수 없는 규칙을 문서로 적어야 한다.
- 내부는 `run()`과 공유한다. 갈리는 것은 "이벤트를 어디서 얻나"(재생이냐 실제 호출이냐)와 "무엇을 트레이스에 쓰나"뿐이다.
- 재개 대상이 일시정지 상태가 아니면(이미 끝났거나, 실패했거나, 애초에 멈춘 적이 없거나) 구성 오류로 거부한다.

### core — 재생 규칙

- 재개는 에이전트를 **처음부터 다시** 돌린다. 파이썬 제너레이터의 스택을 직렬화할 수 없기 때문이다.
- 재생 구간에서 모델 호출과 도구 호출은 실제로 일어나지 않고 트레이스의 기록된 값을 돌려준다.
- **대응은 순서로, 검증은 대조로.** N번째 호출에 N번째 기록을 쓰되, 쓰기 전에 지금 보내려던 것이 기록과 같은지 본다. 대조 대상은 모델 호출의 입력 메시지와 도구 호출의 이름·인자이고, 마스킹된 필드는 뺀다.
- 어긋나면 **실행이 실패로 끝나고 그 실행은 재개 불가가 된다.** 사용자는 에이전트가 바뀌었음을 알고 새로 실행하면 된다. 조용히 다른 실행의 기록을 먹이는 것보다 시끄럽게 죽는 쪽이다. 원칙 II와 같은 판단이다.
- **`ctx.now()`는 재생 구간에서 실행의 시작 시각을, `RunResumed` 뒤로는 실제 시각을 돌려준다.** 시계 읽기를 따로 기록하지 않고도 결정적이다. 이 규칙을 `sdk`의 컨텍스트 문서에 명시한다. 재생이 성립하려면 비결정적인 값이 전부 컨텍스트를 지나야 한다는 제약도 함께 적는다. (2026-09-22 티켓 04: 처음 실행에도 같은 값을 줘야 첫 재개의 대조가 성립한다. 처음 실행 전체가 나중에 재생될 구간이기 때문이다. 그래서 구현은 "재개 이벤트 전까지 시작 시각"이다. 재개가 두 번 이상일 때 이 규칙이 스스로를 깨뜨리는 것은 ADR 0009 이력의 열린 문제다.)
- **재생된 사실은 트레이스에 다시 쓰지 않는다.** 이미 거기 있기 때문이다. 에이전트가 낸 것도 마찬가지다. 기준은 "재생 구간인가"가 아니라 **"이미 트레이스에 있는가"** 다. 그래서 재생 구간에서 처음 생긴 사실은 쓴다 — 대조 불일치로 인한 실패가 그것이고, 그 실행은 `RunResumed` 없이 끝나지만 트레이스에는 남는다(사용자 스토리 30). 사실이 한 번씩만 남는다. (2026-09-22 티켓 04: 에이전트가 낸 이벤트도 재생 기록 열에서 함께 소비하고 대조한다. 트레이스에는 누가 낸 이벤트인지 표시가 없어서, 소비하지 않으면 에이전트가 낸 `tool_called` 하나가 기록을 밀어 그 뒤 대조가 전부 어긋난다.)
- `run_started`는 재개할 때 다시 내지 않는다. 실행 하나에 한 번이다.
- 루프 상한은 **실행 전체 기준이고 재생된 턴도 센다.** 상한의 목적이 비용을 묶는 것인데 재개로 리셋되면 멈추고-재개를 반복해 무한히 돌 수 있다.

### core — 승인 게이트

- 게이트는 **루프와 컨텍스트의 직접 도구 호출 둘 다** 덮는다. 정책은 도구에 붙는 것이지 경로에 붙는 것이 아니다.
- 한 모델 턴에 승인 대상이 여럿이면 **첫 것에서 멈춘다.** `RunPaused`가 도구 하나만 담아 승인과 실행이 1:1이 된다. 사람을 여러 번 찾는 대가를 치른다.
- **거부는 실행을 끝내지 않는다.** 루프에서는 도구 결과를 실패로 만들어 사유를 모델에 되돌리고 루프가 계속한다. 이미 있는 도구 실패 경로 그대로다. 직접 호출에서는 사유를 담은 예외가 에이전트에게 간다.
- 모델이 다른 도구로 우회하는 위험은 거부가 아니라 **정책이** 막는다. 같은 일을 할 수 있는 도구는 전부 `requires_approval`에 들어가야 한다. 이 사실을 매니페스트 문서에 적는다.
- 승인자는 필수로 기록한다. 자기 승인은 허용한다. 지금 채널이 CLI 하나이고 사용자가 혼자라 금지하면 기능 자체를 쓸 수 없다.

### core — 마스킹

- 마스킹은 **`core`에서, 이벤트를 만들 때** 한다. 어댑터가 아니다. 원칙 V가 금하는 것은 "이벤트에 비밀을 싣는 것"이지 파일이 아니고, `secret_args`를 아는 것도 `core`다.
- 마스킹된 필드는 대조 검증에서 뺀다.
- 재생 구간에서 도구 인자는 쓰이지 않고 결과만 필요하므로 마스킹이 재생을 깨지 않는다. 깨질 수 있는 유일한 조합은 위의 금지 규칙이 매니페스트 단계에서 막는다. (2026-09-22 티켓 04: 조합이 하나 더 있다. 한 모델 턴에 승인 대상 뒤로 마스킹된 도구가 오면 그 호출은 재생 경계를 넘어 실제로 실행되고 인자는 재생된 모델 응답에서 온 마스킹된 값이다. 금지 규칙은 승인 대상 도구만 보므로 막지 못한다. 실제 호출 직전에 인자가 마스킹 표지인지 보고 실패로 끝낸다. ADR 0009 이력.)
- **범위는 인자뿐이다. 열린 문제 둘이 남는다**(2026-09-21 티켓 01의 PR 직전 리뷰). (2026-09-22 티켓 04의 PR 리뷰: 셋이 됐다. `llm_called.prompt`도 마스킹을 지나지 않아, 에이전트가 이전 도구 결과를 프롬프트에 엮으면 그 값이 트레이스에 남는다. `text`와 같은 성격이고 같은 이유로 결정을 미룬다. ADR 0009 이력.)
  - **도구 결과와 예외 문자열은 가리지 않는다.** 실패한 호출은 예외 문자열이 그대로 `tool_called.content`가 되는데, MCP 도구는 신뢰 경계 밖이라 예외에 인자를 에코할 수 있다(`Invalid api_key: sk-...`). 그 경로로 비밀이 트레이스와 CLI 진행 표시 양쪽에 남는다. 가리려면 진단 정보를 버리거나(사용자 스토리 11과 충돌) 값 기반 치환을 해야 하고 둘 다 새 결정이다. **결정할 때 ADR 0009의 이력에 쌓는다.**
  - **`secret_args`가 가리키는 도구와 인자의 실재를 검사하지 않는다.** 오타나 중첩 프로퍼티는 조용히 마스킹을 끈다. `requires_approval`이 막으려 한 fail-open과 같은 종류이고 같은 자리에서 고친다 — 도구 목록은 MCP에 붙어야 나오므로 도구 연결 직후 검사이고 **티켓 03이 소유한다.**

### channel/cli

- **`agent-os resume <run_id> --approve | --deny --reason <사유>`**. 승인과 거부 중 하나를 반드시 골라야 한다. **거부에는 사유가 필수다.** `ApprovalDenied.reason`이 필수 필드이고, 선택으로 두면 CLI 가 빈 문자열을 지어내 사유 없는 거부가 기본값으로 굳는다. 승인자를 필수로 만든 논증과 같다(2026-09-21 리뷰).
- 실행이 멈추면 표준 출력에 `run_id`와 무엇을 승인해 달라는지(도구 이름과 인자)를 찍는다. 마스킹된 인자는 마스킹된 채로 보인다. (2026-09-21 티켓 03: 일시정지 이벤트도 같은 마스킹을 지나지만, 위의 금지 규칙이 마스킹된 도구를 승인 대상에서 빼므로 실제로 마스킹된 일시정지는 만들 수 없다. 테스트가 아니라 구성으로 성립하는 불변식이다.)
- 일시정지는 **실패와 다른 전용 종료 코드**로 끝난다. 성공도 실패도 아니라는 것을 스크립트가 알 수 있어야 한다.
- 멈춘 실행의 **목록** 조회는 만들지 않는다. 채널은 실행을 일으키는 면이고 관찰은 관리의 일이다. `admin-api`가 병렬 프론티어다.
- 조립은 지금과 같다. 어댑터 넷을 만들어 `core`에 넘기고, 주체는 시스템 사용자다. 승인자도 같은 출처에서 온다.

### 실패 정책 갱신

기존 넷(MCP 서버 시작 실패, 도구 에러, 루프 상한, LLM API 에러)에 더해:

- `secret_args`와 `requires_approval`이 겹치는 매니페스트 → 실행 전 구성 오류. 트레이스 없음.
- `requires_approval`이 없는 도구를 가리킴 → 도구 연결 직후 실행 실패. 트레이스 있음.
- `secret_args`가 없는 도구나 인자를 가리킴 → 같은 자리에서 실행 실패. 트레이스 있음.
- 재생 대조 불일치 → 실행 실패. 그 실행은 재개 불가.
- 버전 1 트레이스를 재개 시도 → 구성 오류로 거부.
- 일시정지가 아닌 실행을 재개 시도 → 구성 오류로 거부.

## Testing Decisions

좋은 테스트는 **바깥 행동만** 본다. 이 기능에서 바깥 행동은 **이벤트의 열**과 **트레이스 파일의 내용**과 **CLI의 출력·종료 코드**다. 재생기가 내부적으로 어떤 자료구조를 쓰는지, 대조를 어떻게 구현했는지는 단언하지 않는다. 테스트 이름은 행동 명세로 쓴다. 첫 슬라이스의 셀프 리뷰가 "이름과 단언이 모순"인 결함을 잡아낸 것이 그 규칙의 값이었다.

원칙 II대로 구현 전에 실패하는 테스트를 쓴다. 테스트가 실패하면 테스트를 고치지 않고 멈춰 보고한다.

### 주 이음매 — `core`의 실행과 재개

프리어 아트가 그대로 맞다. 지금 있는 주 이음매 테스트가 포트 다섯을 가짜로 주입하고(상속하지 않고 시그니처로 만족한다) 이벤트의 열만 단언한다. 가짜 트레이스 포트에 `read`가 붙는 것 말고 구조가 바뀌지 않는다. 네트워크가 없다.

여기서 판정하는 것:

- 승인 대상 도구를 만나면 `RunPaused`로 끝나고 그 도구가 실행되지 않는다
- 승인 뒤 재개하면 `ApprovalGranted` → (재생, 트레이스에 안 쌓임) → `RunResumed` → 도구 실제 실행 → `RunFinished`
- 거부 뒤 재개하면 `ApprovalDenied` → 도구 결과가 실패로 모델에 돌아가고 루프가 계속해 `RunFinished`
- 재생 구간의 모델 호출과 도구 호출이 가짜 포트에 **도달하지 않는다**(호출 횟수로 본다)
- 재생 구간에서 생긴 이벤트가 트레이스에 두 번 쌓이지 않는다. 에이전트가 낸 것도 마찬가지다
- 에이전트를 바꿔 끼우면 대조가 어긋나 실행이 실패하고, 실패 내용이 무엇이 어긋났는지 말한다
- `ctx.now()`가 재생 구간에서 시작 시각을, `RunResumed` 뒤로는 가짜 시계의 현재 시각을 돌려준다
- 컨텍스트로 직접 부른 도구도 멈추고, 거부하면 에이전트가 이름으로 잡을 수 있는 예외를 받는다
- 한 턴에 승인 대상이 둘이면 첫 것에서 멈추고, 재개하면 둘째에서 다시 멈춘다
- 루프 상한이 재생된 턴을 포함해 센다
- `requires_approval`이 없는 도구를 가리키면 도구 연결 직후 실패한다
- 비밀로 선언된 인자가 이벤트에 마스킹돼 담기고, 대조 검증이 그 필드를 뺀다
- 일시정지가 아닌 실행이나 끝난 실행을 재개하면 거부된다

### `sdk` 계약

- 새 이벤트 넷이 판별 유니온으로 왕복한다. 모르는 종류는 지금처럼 알 수 없는 이벤트로 떨어진다
- 두꺼워진 두 이벤트가 도구 호출과 결과를 담고 왕복한다
- `requires_approval`과 `secret_args`가 파싱되고 기본값이 빈 것이다
- 둘이 겹치는 매니페스트가 거부되고, 거부 내용이 어느 도구인지 말한다

### 트레이스 어댑터

- 헤더 버전 2로 쓰고 읽는다
- 버전 1 파일을 읽을 수는 있고 재개 대상으로는 거부한다
- 한 실행의 이벤트를 순서대로 돌려준다

### CLI 표면

프리어 아트가 있다. 지금 CLI 테스트가 임시 디렉터리에 쓴 픽스처 에이전트로 진입점을 부르고 표준 출력·표준 에러·종료 코드·트레이스 파일을 본다. 모델은 쓰지 않는다. 도구는 일시정지 테스트에서만 진짜 stdio 서버(`tests/adapters/mcp_fixture_server.py`)를 임시 디렉터리의 mcp 플러그인으로 등록해 붙인다. 실재 검사가 도구 목록을 요구하기 때문이고, 게이트가 도구 앞에서 멈추므로 서버는 붙기만 하고 불리지 않는다(2026-09-21 티켓 03).

- 멈추면 `run_id`와 승인 요청 내용이 표준 출력에 찍히고 전용 종료 코드로 끝난다
- `resume --approve`와 `--deny`가 각각 실행을 끝낸다
- 승인과 거부를 둘 다 안 주거나 둘 다 주면 진단이 나온다
- 없는 실행 식별자에 진단이 나온다

### 바깥 이음매 (`-m llm`, 기본 스위트에서 빠진다)

하나 더한다. 실제 CLI **프로세스**를 띄워 승인 대상 도구에서 멈추고, **그 프로세스가 끝난 뒤** 다른 프로세스로 재개해 끝까지 간다. 트레이스 한 파일에 `run_paused`, `approval_granted`, `run_resumed`가 순서대로 남는 것을 본다.

이 테스트가 증명하는 것은 가짜 포트로 증명할 수 없는 단 하나다. **일시정지가 프로세스보다 오래 산다.** 이 기능의 존재 이유가 그것이므로 그것만은 실물로 잰다.

키가 없으면 건너뛰지 않고 실패한다. 환경 부재로 skip된 테스트는 초록이 아니다(원칙 II).

## Out of Scope

- **HTTP로 승인받기.** 승인 표면은 CLI 하나다. `resume`이 core 함수라 `http-channel`이 나중에 같은 것을 부른다.
- **멈춘 실행 목록 조회.** 관찰은 관리의 일이고 `admin-api`가 병렬 프론티어다. 이번에는 멈출 때 식별자를 찍는 것으로 끝낸다.
- **일시정지의 만료.** 트레이스 파일이 있는 한 유효하다. 만료 정책은 관리가 생긴 뒤에 다룬다.
- **자기 승인 금지와 4-eyes.** 지금 사용자가 혼자다. 정책으로 나중에 더한다.
- **부분 승인.** 한 턴에 여럿이면 첫 것에서 멈추므로 "이건 되고 저건 안 돼"라는 입력이 없다.
- **에이전트가 스스로 부르는 인터럽트.** 용어집이 인터럽트를 상위 개념으로 정의해 자리를 비워 뒀지만, 이번에 만드는 종류는 승인 하나다. 필요가 증명되면 ADR로 더한다.
- **되감기.** 일시정지한 지점으로 되돌아가는 것과 임의의 과거 지점으로 되감는 것은 다른 기능이다.
- **재개 시 에이전트 코드 변경 수용.** 대조가 어긋나면 실패한다. 마이그레이션이나 버전 허용은 만들지 않는다.
- **트레이스 형식 1의 재개.** 읽기만 되고 재개는 안 된다.
- **승인 알림.** 사람에게 "승인해 달라"고 알리는 채널(메일, Slack)은 없다. 사람이 CLI 출력을 본다.
- **여러 모델·스킬 플러그인.** 이번 슬라이스가 건드리지 않는다.

## Further Notes

- **계약 티켓이 첫 티켓이고 다른 티켓을 막는다.** `sdk`의 이벤트와 매니페스트, 트레이스 형식 버전이 거기 들어간다. 계획 문서의 규약이다.
- **포트 개명은 코드와 규칙 문서를 같은 티켓에서 고친다.** 규칙 문서의 포트 표가 지금 옛 이름이다. 코드만 고치고 규칙을 남겨 두면 다음 실행이 틀린 것을 읽는다.
- **엔진은 직접 만든다.** ADR 0001이 예약한 재측정을 2026-09-21에 했고 결과가 같았다. langgraph는 1.2.11 그대로이고 인터럽트·체크포인터 경로가 `pyright: ignore` 없이 통과하지 않는다. 더 나쁜 것은 반환 타입의 누출이 표준 pyright에서 진단조차 나지 않는다는 점이다. 기록은 ADR 0001 이력.
- **이 기능은 첫 슬라이스가 남긴 제약 위에 선다.** 컨텍스트가 시각과 실행 식별자를 주는 것, 컨텍스트가 JSON 직렬화 가능한 것만 다루는 것, 실행이 이벤트의 열인 것. 첫 슬라이스 명세의 사용자 스토리 40번이 예고한 이음매가 실제로 그 자리였다.
- **측정할 때의 함정.** pyright의 명령행 파이썬 경로 지정은 프로젝트 설정의 가상환경 지정에 덮여 무시된다. 재측정 첫 시도가 그래서 거짓 실패를 냈다. 이 저장소가 두 번 겪은 "검사 범위 밖에서 받은 거짓 성공"의 반대 방향이고 교훈은 같다. 검사가 실제로 돌았는지를 분석된 파일 수로 먼저 확인한다.
- **환경 규약은 그대로다.** 파이썬 명령 앞에 UTF-8 강제, Git Bash에서는 `uv run python`, pyright 프로브는 테스트 디렉터리 아래.
