# 01: 계약 — 새 이벤트 넷과 매니페스트 필드 둘

**What to build:** `sdk`가 인터럽트의 어휘를 갖고, 트레이스가 재개에 필요한 내용을 담기 시작한다. 이 티켓이 끝나면 에이전트를 평소대로 실행해도 트레이스에 모델이 낸 텍스트와 도구 호출, 도구 인자와 결과가 남는다. 아직 아무것도 멈추지 않는다.

이 기능의 계약 티켓이고 나머지 전부를 막는다. 마스킹은 원래 03이었으나 2026-09-21 리뷰에서 01로 당겼다. 인자 기록을 켜는 것이 이 티켓이라, 나뉘면 01~02만 병합된 main 에서 `secret_args` 선언이 조용히 무효가 된다. 원칙 V 는 티켓 경계보다 위다. 디스크 형식을 바꾸는 유일한 자리이므로 리뷰의 질문은 "동작하나"가 아니라 "이 필드 이름과 모양으로 오래 살 수 있나"다. 근거는 `.scratch/interrupts/spec.md`와 ADR 0009, ADR 0008의 2026-09-21 이력.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 새 이벤트 넷(`RunPaused`, `ApprovalGranted`, `ApprovalDenied`, `RunResumed`)이 판별 유니온의 일원으로 왕복한다. 실행 식별자와 시각이 넷 모두에 필수다
- [x] `RunPaused`가 어떤 도구를 어떤 인자로 부르려 했는지 담는다
- [x] 승인과 거부가 별도 종류다. 둘 다 승인자를 필수로 담고, 거부만 사유를 담는다
- [x] `LlmCalled`가 모델이 낸 텍스트와 도구 호출을 담고, `ToolCalled`가 인자와 결과 내용을 담는다
- [x] 실행을 한 번 돌리면 그 내용이 실제로 트레이스 파일에 남는다. 두꺼워진 필드를 채우는 것은 `core`다
- [x] 에이전트 매니페스트가 `requires_approval`을, mcp 매니페스트의 서버 절이 `secret_args`를 읽는다. 둘 다 선택 필드이고 기본은 빈 것이다
- [x] `secret_args`로 선언된 인자가 마스킹된 채 이벤트에 담기고, 실제 도구 호출에는 진짜 값이 간다. 마스킹은 이벤트를 만드는 `core`가 하고 트레이스 어댑터는 받은 것을 쓴다
- [x] `secret_args`를 가진 도구를 `requires_approval`에 적은 매니페스트가 거부되고, 거부 내용이 어느 도구인지 말한다. 실행 식별자가 생기기 전이라 트레이스가 없다
- [x] `schema_version`은 `"1"` 그대로다. 옛 매니페스트가 그대로 읽힌다
- [x] 모르는 이벤트 종류가 지금처럼 알 수 없는 이벤트로 떨어진다
- [x] 이벤트마다 형식 버전을 붙이지 않는다. 트레이스 파일 첫 줄 헤더가 그 역할을 한다
- [x] **그 헤더의 형식 버전이 2로 올라간다.** 이벤트가 두꺼워지는 것과 버전이 올라가는 것은 반드시 한 커밋에 있다. 나뉘면 두꺼워진 이벤트가 버전 1을 달고 디스크에 쌓여, ADR 0008이 경고한 "형식이 바뀐 뒤 옛 파일이 조용히 다르게 해석되는" 상황이 된다
- [x] 검사 넷이 초록이다
