# 02: 트레이스를 읽는다

**What to build:** 재개가 설 바닥. `core`가 한 실행의 트레이스를 이벤트의 열로 읽을 수 있게 된다. 디스크 형식 버전을 올리는 것은 01이 하고, 여기서는 그것을 읽어 구별할 뿐이다. 사용자에게 보이는 새 동작은 없고, 04가 필요로 하기 전에 미리 까는 프리팩터다.

포트를 늘리지 않는다. 닿는 바깥 지점은 "트레이스 저장소" 하나이지 새 지점이 아니다. 쓰기 전용을 뜻하는 지금 이름이 맞지 않게 되므로 개명한다. 같은 필요가 `admin-api`의 트레이스 조회에서도 곧 생긴다.

**Blocked by:** 01 (이벤트 형식이 정해져야 읽어서 무엇으로 돌려줄지가 정해진다)

**Status:** done

- [x] 트레이스 포트가 쓰기와 읽기를 함께 갖고, 이름이 저장소를 뜻하게 바뀐다
- [x] 한 실행의 이벤트를 쓴 순서 그대로 돌려준다
- [x] 버전 1 파일을 **읽을 수는 있다**. 관리가 옛 트레이스를 보여 줄 수 있어야 한다
- [x] 읽은 결과로 그 트레이스가 버전 1인지 2인지 알 수 있다. 버전 1을 재개 대상으로 **거부하는 것은 04**다. 재개 진입점이 거기서 생기므로 이 티켓에서는 판정할 수 없다
- [x] 규칙 문서의 포트 표가 같은 티켓에서 새 이름으로 간다. 포트는 여전히 다섯이다. 코드만 고치고 규칙을 남겨 두면 다음 실행이 틀린 것을 읽는다
- [x] 가짜 트레이스 포트가 상속 없이 시그니처로 만족한다
- [x] 저장소 전체에서 옛 포트 이름의 잔존이 0이다
- [x] 검사 넷이 초록이다

## Comments

- 2026-09-21: 읽기 결과 타입 `Trace`(실행 식별자, 형식 버전, 이벤트 열)와 `UnknownEvent`를 `core/ports.py`로 옮겼다. 포트의 반환 타입은 포트를 선언하는 쪽이 소유해야 어댑터가 import할 수 있다(원칙 IV). 헤더(`TraceHeader`)는 디스크 형식이라 어댑터에 남는다. 부재는 `PluginSource.read_manifest`와 같이 `None`.

- 2026-09-21: 옛 이름 잔존은 코드·규칙·README·CONTEXT에서 0이다. 남긴 것은 개명 결정 자체를 적은 ADR 0009와 이 기능 명세, 지난 일지들, 닫힌 첫 슬라이스 명세다. 기록을 고치면 이력이 거짓이 된다.
