# 04: 승인하고 재개한다

**What to build:** 멈춘 실행을 승인하면 끝까지 간다. `agent-os resume <run_id> --approve`를 치면 런타임이 승인을 기록하고 에이전트를 처음부터 다시 돌리되, 이미 한 모델 호출과 도구 호출은 실제로 부르지 않고 트레이스의 기록된 값으로 재생해 멈췄던 자리까지 되돌아간 뒤, 거기서부터 진짜로 이어 간다. 트레이스 한 파일에 실행의 전모가 남는다.

기능의 심장이고 가장 큰 티켓이다. 재생이 성립하는 이유는 ADR 0008이 시각과 실행 식별자를 컨텍스트로 밀어 넣어 `run()`을 재실행 가능하게 만들어 뒀기 때문이다.

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] `core`에 재개 진입점이 생긴다. 실행 식별자와 결정과 승인자를 받고, 에이전트 이름·요청·주체는 받지 않고 트레이스의 시작 이벤트에서 읽는다
- [ ] 승인이 트레이스에 먼저 기록된 뒤 재생이 시작된다
- [ ] 재생 구간의 모델 호출과 도구 호출이 실제 포트에 **도달하지 않는다**(가짜 포트의 호출 횟수로 확인한다)
- [ ] N번째 호출에 N번째 기록이 대응된다
- [ ] 쓰기 전에 대조한다. 모델 호출의 입력 메시지와 도구 호출의 이름·인자가 기록과 다르면 실행이 실패로 끝난다. 마스킹된 필드는 대조에서 뺀다
- [ ] 대조 실패의 내용이 무엇이 어긋났는지 말한다. 그 실행은 재개 불가가 되고 사용자는 새로 실행하면 된다
- [ ] 재생 구간이 끝나는 자리에 재개 이벤트가 남는다
- [ ] 재생된 사실은 트레이스에 다시 쓰이지 않는다. 에이전트가 낸 것도 마찬가지다. 기준은 "재생 구간인가"가 아니라 "이미 트레이스에 있는가"다
- [ ] 재생 구간에서 **처음 생긴** 사실은 쓰인다. 대조 불일치로 끝나는 실행은 재개 이벤트 없이도 실패가 트레이스에 남는다
- [ ] 시작 이벤트는 재개 시 다시 나지 않는다. 실행 하나에 한 번이고 트레이스는 한 파일에 이어진다
- [ ] `ctx.now()`가 재생 구간에서 실행의 시작 시각을, 재개 이벤트 뒤로는 실제 시각을 돌려준다
- [ ] 그 규칙과 "비결정적인 값은 전부 컨텍스트를 지나야 한다"는 제약이 `sdk`의 컨텍스트 문서에 적힌다
- [ ] 루프 상한이 재생된 턴을 포함해 센다. 멈추고-재개를 반복해 무한히 돌 수 없다
- [ ] 한 턴에 승인 대상이 둘이었다면, 첫 것을 승인해 재개한 뒤 **둘째에서 다시 멈춘다.** 승인과 실행의 1:1 대응이 여기서 닫힌다(03이 연 것의 나머지 절반이다)
- [ ] 요청한 주체와 승인자가 같아도 통과한다. 자기 승인 금지는 이번 범위가 아니다
- [ ] 일시정지가 아닌 실행, 이미 끝난 실행, 이미 실패한 실행을 재개하려 하면 거부된다
- [ ] 형식 버전이 1인 트레이스를 재개하려 하면 거부된다
- [ ] CLI의 `resume --approve`가 동작한다
- [ ] 검사 넷이 초록이다
