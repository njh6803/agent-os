# named-query: 운영자가 적어 둔 조회문을 모델이 값만 넘겨 불러, 데이터베이스의 숫자를 그 사람이 볼 수 있는 데이터로만 답한다.
**슬라이스:** 15
**Blocked by:** principal-propagation, user-memory
**설계:** ADR 0055

정해 둔 조회(ADR 0055). "지난달 재고가 몇 개야?"처럼 숫자가 바뀌고 합계를 내야 하는 질문에 데이터베이스를 조회해 답한다. 운영자가 조회문을 미리 적어 두고 모델은 값만 넘겨 부른다. 조회는 런타임 밖의 MCP 서버(조회 서버)가 맡고 런타임은 그 서버를 모른다. 내는 것은 조회 서버를 가리키는 연결 플러그인, 스킬, 규칙 파일의 본보기 표(조회 도구를 allow로 적는다. 실행 전에 묻지 않는다), 안내 문서다. 기본 에이전트 `assistant`에는 붙이지 않고 커스텀 에이전트가 골라 붙인다. 사람마다 볼 수 있는 데이터가 다른 조회에서는 조회 서버가 지금 묻는 주체를 조회의 값으로 채우고, 모델은 그 값을 넘기지 않으며 넘겨도 쓰이지 않는다. 이 행이 조회 서버의 뼈대(주체를 받는 길, 데이터베이스 권한, 줄 수와 실행 시간의 상한)를 세우고 text-to-sql이 그 위에 얹힌다. 묶음(슬라이스 15)의 뜻과 시작하는 때와 차례는 ADR 0046의 2026-11-10 이력 "제품 1.0에 지식베이스 고르기가 들고 커스텀 에이전트의 부품 다섯이 새 묶음으로 선다"가 원천이다. Blocked by의 principal-propagation은 기술적 의존이다(조회 서버가 묻는 사람을 런타임이 넘긴 주체로만 받는다). user-memory는 기술적 의존이 아니라 사용자가 고른 차례다(기억, 정해 둔 조회와 사내 시스템 조회, 조회문 직접 작성, 계획표). 명세가 먼저 할 것: 조회 서버를 만들지 가져다 쓸지를 다시 조사해 정하고, 만들기로 하면 둘 저장소(이 저장소, rag-engine, 새 저장소)도 그때 정한다. 조건은 ADR 0055의 "조회 서버의 조건 여섯"이다. 다른 저장소에 두기로 하면 저장소를 나누는 결정이라 ADR이 먼저이고(ADR 0048이 문서 검색 서버를 나눈 선례다), rag-engine에 두려면 그 저장소의 PRD가 Text-to-SQL을 만들지 않는다고 적은 줄의 개정도 먼저다. 2026-11-10의 조사에서 MCP Toolbox for Databases는 매개변수가 있는 SQL을 도구로 정의하지만 인증된 사용자의 값으로 매개변수를 채우는 기능이 MCP로는 지원되지 않는다고 적었다(웹 요약이다. 일지 2026-11-10-1845의 "조사" 절). 명세가 정할 것: 먼저 지원할 데이터베이스, 정해 둔 조회를 적는 파일의 모양과 자리, 조회 하나가 도구 하나인지, 상한의 값, 조회 서버의 신뢰 수준(조회 결과에 사람이 쓴 글이 섞이면 그 글 속의 지시가 문서 속 지시와 같은 위험이 된다), 답에 계산 방식(기간, 조건)을 문장으로 밝히게 하는 스킬의 본문, 평가(정답 조회문의 결과와 견준다). 안내 문서에 적을 것: 조회 권한만 가진 전용 데이터베이스 계정을 쓰고, 그 계정에는 보여도 되는 표만 열며, 결과의 줄 수와 실행 시간에 상한을 둔다. 조회문과 결과는 트레이스에 남는다. 범위 밖: 데이터베이스에 쓰는 조회문, 웹 검색. 수락: 시험용 데이터베이스와 정해 둔 조회 둘(누구에게나 같은 것 하나, 사람별인 것 하나)을 둔 커스텀 에이전트에서, 숫자를 묻는 질문에 조회 결과로 답하고, 사람별 조회는 주체가 다르면 다른 결과를 내며 모델이 다른 사람의 값을 넘겨도 쓰이지 않고, 익명 주체의 사람별 조회는 거부되며, 상한을 넘는 조회는 끊기는 테스트가 통과한다
