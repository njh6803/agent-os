# mutation-table-test-filter-stale-after-rename: 시험 이름을 바꾸자 끝난 기능의 변이 표 여섯 곳에서 시험을 고르는 조건(pytest `-k`)이 옛 이름을 가리키게 됐는데 `tools/mutate.py --staged`가 "문제 0"으로 지났다

**상태:** 열림
**어디로:** 다섯 번째에 `tools/mutate.py`의 `--check`와 `--staged`: 러너의 사례 거르기 인자(vitest `-t`, pytest `-k`)의 이름 조각이 그 `tests` 파일 원문에 있는지 본다. pytest `-k`는 `or`·`and`·`not`으로 이은 식이라 조각마다 본다(vitest의 `-t`는 `describe`와 사례 이름을 이은 이름에 맞아, 조각이 둘에 걸치면 원문에 글자 그대로 없을 수 있다)
**승인:** 자체 승인 2026-11-17, 3회차(0491의 3회차. 0491은 2회차로 만료됐다), 일지 2026-11-17-2031-plain-words-in-written-artifacts.md. ADR 불필요

용어집의 이름을 바꾸며 시험 이름과 매개변수 id가 함께 바뀌었다. 끝난 기능의 변이 표는 기록이라 고치지 않았고, 조건 여섯이 옛 이름을 가리킨 채 남았다(자리는 그 일지의 "변이 표" 문단). `pytest --collect-only`로 대 보니 다섯은 고르는 시험이 하나도 없어 표를 다시 돌리면 기준선에서 멈춘다. 나머지 하나는 `or`로 이은 두 이름 가운데 하나만 옛 이름이라 시험 하나를 여전히 골라, 알림 없이 옛 시험 하나가 빠진 채 돈다. 0491의 처방(조건의 이름 조각이 시험 파일 원문에 있는지 본다)에 조각마다 보기를 더한 것은 이 `or` 꼴 때문이다.
