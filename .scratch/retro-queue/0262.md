# 0262: **`gh pr merge`와 `git push origin --delete <브랜치>`를 한 번에 나란히 보내, 병합이 base보다 뒤처져 실패했는데도 원격 브랜치가 지워져 PR이 닫혔다.** `next-session`의 "워크트리에서 병합할 때"가 병합 뒤 정리를 순서로 적지만 지침이라 지나갔다

**상태:** 닫힘 (`chore/hooks-journal-number-and-guards`, 2026-10-16, 새 막는 훅 `tools/hook_push_delete_open_pr.py`(Bash·PowerShell)가 `--delete`·`-d`·`:<브랜치>` 꼴의 지우는 `git push`를 git이 읽는 그대로(옵션 줄임, 묶음, `--dry-run`) 읽고, 그 브랜치를 머리로 둔 열린 PR이 `gh api`의 REST(쓰지 못하면 `ls-remote`의 merge ref)에 있으면 막는다. 일지 2026-10-16-21)
**어디로:** 막는 훅: `git push origin --delete <브랜치>`(와 `:<브랜치>` 꼴)에서 그 브랜치를 머리로 둔 열린 PR이 `gh`에 있으면 막는다. `tools/hook_payloads.toml`에 발동·비발동 페이로드
**승인:** 자체 승인 2026-10-15, 1회차, 일지 2026-10-15-01. ADR 불필요
