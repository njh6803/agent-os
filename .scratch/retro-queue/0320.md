# 0320: **PR 직전 `bug-perf-review` 가 워크트리 가드에 `uv run python -c` 를 거부당해 훅 함수를 부르지 못하고 코드를 읽어 판정했다**(주장 검증의 "코드의 동작" 항목이 비었다. 같은 세션의 셀프 리뷰 표준 축은 함수를 불렀다)

**상태:** 닫힘 (`chore/bug-perf-review-batch`, 2026-10-19, 트리아지 단계에 함수를 부르는 길 둘을 차례로 적었다. 저장소 루트의 `uv run python -c`, 그리고 heredoc으로 저장소 밖 `/tmp/bug-perf-review/`에 쓴 시험 파일을 `uv run python -m pytest`로 돌리는 길이다. 앞 길이 가드에 거부되면 한 번만 바꾸고, 둘 다 거부되면 그 지적의 근거에 적고 `보류`로 둔다. 2단계 밀 주장의 "코드의 동작" 항목도 이 길을 가리킨다. 거부가 아닌 실패는 길을 바꾸지 않고 한 번 고쳐 다시 치고, 시험 폴더는 브랜치마다 가르며, 예산 40에 닿은 뒤에는 함수를 새로 부르지 않는다. 가드를 먼저 잰 결과로는 거부되는 꼴을 고를 수 없었다. 2026-10-16에 그 서브에이전트가 거부당한 넷은 모두 코드나 heredoc 본문에 git 명령 글이 든 명령이었다(그 기록을 손으로 봤다). 이 워크트리에서 띄운 그 서브에이전트에게 명령을 치게 하자 git 글이 없는 다섯과 git 글이 든 짧은 `-c`·heredoc 시험 파일까지 일곱이 모두 지나갔고, 10-16에 거부된 짧은 `-c` 하나는 본 세션에서 글자 그대로 다시 쳐도 거부됐다(손으로 봤다). 이 PR의 PR 직전 리뷰에서는 git 글이 없는 heredoc 시험 파일이 거부되고 `uv run python -c`로 쓴 시험 파일의 `-m pytest`는 지나갔다(그 리뷰의 보고). "어디로" 칸의 맨 `uv run pytest <경로>`는 거부되지 않았지만 저장소 루트가 import 경로에 없어 `ModuleNotFoundError: No module named 'tools'`로 수집에서 멈춰, 정의에는 `python -m pytest`를 적고 맨 꼴이 멈추는 까닭도 적었다. 카나리아 `bug_perf_review_report_line_and_call_paths.toml` 통과 4, 일지 2026-10-28-08)
