# feature-paragraph-checked-against-plan-not-spec: 기능 단락의 동작 문장을 기능 계획의 값에만 대고 명세의 동작 문장과 대지 않았다

**상태:** 열림
**어디로:** `docs/constitution/operations.md`의 "릴리스 노트 원고" 기능 단락 항목에 한 문장(다섯 번째 반복에서 retro가 더할 때): 기능 단락이 적는 동작(주기, 멈추는 때, 눌러야 하는 때)은 기능 계획의 값이 아니라 명세의 그 동작을 정한 문장에 맞대어 쓴다. 검사로 옮기지 못한다(글이 명세와 맞는지는 낱말로 가를 수 없다)
**승인:** 자체 승인 2026-11-25, 1회차, 일지 2026-11-25-1159-connection-check-feature-paragraph-visible-tab.md. ADR 불필요

접속 확인 기능의 기능 단락을 PR #634에서 쓸 때 배포 안내의 소절 이름과 기능 계획의 간격(30초)에만 대어 "화면이 열려 있는 동안 30초마다"로 적었다. 명세 `.scratch/connection-check/spec.md`의 "간격과 보이지 않는 탭"은 보이지 않는 탭에서 멈춘다고 정했고, 이 단락은 출시 때 릴리스 노트에 글자 그대로 실린다. PR #634의 CodeRabbit 둘째 회차가 짚었고(#issuecomment-7139012640), 사용자가 출시 PR 전에 문구부터 고치기를 골라 별도 PR로 고쳤다. 기능 단락의 문구가 명세와 어긋난 사건은 열린 대기열 항목에서 같은 일을 다룬 것을 찾지 못해 이것이 처음이다(닫힌 항목은 검색에 잡히지 않아 보지 못했다).
