# 0578: **`coderabbit-review` 정의 1단계가 `coderabbit auth status`의 `Seat: not assigned`만 보고 `coderabbit review`를 돌리지 않고 종료해 CLI 축이 빈 것으로 보고했는데, 같은 `Seat: not assigned`(`Plan: Free`, CLI 0.7.5)에서 본 세션이 `coderabbit review --agent --committed --base origin/main`을 직접 치자 종료 코드 0, 출력의 `complete` 줄이 `review_completed`·`findings: 0`·검토한 파일 19개로 끝났다**(approval-rules 02의 PR 직전, 명령 출력을 손으로 봤다. 557과 같은 꼴이다: `auth status`의 문구로 CLI 축이 비었다고 단정하면 실제 실행과 갈린다)

**상태:** 닫힘 (.scratch/harness/issues/coderabbit-review-seat-not-assigned.md, 2026-11-08, `coderabbit-review` 정의 1단계가 `Seat: not assigned`에서 종료하지 않고 3으로 가게 하고 3에 150개 한도의 `--dir` 길을 더했다. `operations.md` 리뷰 파이프라인 2의 좌석 서술과 PR 템플릿의 "좌석은 PR마다", `KICKOFF.md`의 "좌석이 있을 때만", `kickoff/`의 두 표와 훅 독스트링의 같은 서술을 같이 맞췄다)
**어디로:** `.claude/agents/coderabbit-review.md` 1단계(고침): `Seat: not assigned`여도 종료하지 않고 3으로 가서 리뷰가 실제로 findings를 내는지로 판정하고, 보고에는 `Seat:` 줄을 그대로 적는다. `docs/constitution/operations.md` 리뷰 파이프라인 2의 좌석 서술(2026-09-23의 `Seat: not assigned`와 즉시 끝남)과 570의 "좌석 없이 비어 있다"를 같이 맞춘다(`Seat: not assigned`를 grep해 두 곳 이상을 함께 본다)
