# 0031: **헌법 파일이 바뀌면 헌법 버전도 바뀌었는지 기계가 본다.** 거버넌스에 semver 문장이 있는데도 PR 열하나(#19~#50)가 버전을 올리지 않았다.

**상태:** 닫힘 (`chore/pre-commit-batch`, 2026-10-19, 자리 후보 (1)을 골랐다. `tools/check_constitution_version.py`가 pre-commit(`files: ^docs/constitution/[^/]+\.md$`)에서 커밋에 들 판(색인)을 보고, 이 가지가 고친 헌법 파일(merge-base와도 `origin/main`과도 다른 것)이 있는데 판 줄이 `origin/main`이나 merge-base의 것과 같으면 막는다. main이 이 가지 몫으로 비워 둔 판(대기열 279)은 `tools/sibling_overlap.py`의 `reserved_version`으로 센다. pre-commit에만 두고 CI에 넣지 않아 게이트가 늘지 않으므로 ADR 없이 했다(이 행의 "ADR이 먼저다"는 게이트가 는다는 전제였다). 고친 커밋과 판을 올린 커밋을 나누면 앞 커밋이 막히는 것은 독스트링의 못 보는 것에 적고 시험으로 고정했다. 일지 2026-10-19-13)
**어디로:** `tools/` + `.pre-commit-config.yaml`·`ci.yml` + `operations.md` + ADR
**승인:** 사용자 승인 2026-09-25, 일지 2026-09-25-01. 대기열 224가 `tools/sibling_overlap.py`의 알림(종료 1)으로 같은 판정을 들였다(2026-10-13, 일지 2026-10-13-30). 이 행은 기계적으로 막는 게이트의 길로 남는다

지침을 어긴 것이 세 번을 넘었으므로 검사 차례다. 조건: `principles.md`·`tech.md`·`operations.md` 중 하나가 바뀌었는데 `docs/constitution/README.md`가 안 바뀌면 실패. 거버넌스상 오타 수정도 patch라 PR 단위로는 규칙상 거짓 양성이 없다. 자리 후보가 둘이다. (1) pre-commit 로컬 훅(`files: ^docs/constitution/`, 넘어온 파일 이름으로 판정). 판정 단위가 커밋이라 헌법을 고친 커밋과 버전을 올린 커밋을 나누면 PR 전체로는 맞아도 앞 커밋이 빨강이다. CI는 pre-commit이 아니라 도구를 직접 부르므로 CI에서는 돌지 않는다. (2) CI의 merge-base diff(PR 단위). `actions/checkout@v4`가 얕은 복제라 `fetch-depth`를 바꿔야 하고, `ci.yml`을 건드리면 Claude Code Review가 건너뛸 수 있다(`operations.md`, PR #3 실측, 반례 PR #43, 조건 미상. 2026-09-28 정정: 액션이 건너뛰는 것은 `claude-code-review.yml` 자신을 바꾼 PR뿐이다(`operations.md` 리뷰 파이프라인). 코멘트 0개 가드도 그 파일을 바꾼 PR에서만 코멘트를 세지 않는다(대기열 50·158, 2026-10-07)). 게이트가 느는 것이라 `operations.md` 가드레일 문장과 ADR이 먼저다
