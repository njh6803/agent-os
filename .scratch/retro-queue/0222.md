# 0222: **커밋 메시지 제목 길이(72자)를 pre-commit 검사(약 8분, 484초) 뒤의 commit-msg 단계에서야 검사해, 제목 하나 때문에 게이트를 한 번 더 돌았다**

**상태:** 닫힘 (`chore/bash-hooks-commit-msg-and-cd`, 2026-10-13, `tools/hook_bash_commit_msg.py`. 판정은 옮겨 적지 않고 커밋하는 저장소의 `tools/check_commit_msg.py`를 자식으로 띄워 받는다. "알린다"가 아니라 막는다(deny). PreToolUse의 additionalContext는 도구 결과 옆에 들어가 모델이 게이트가 끝난 뒤에야 본다(공식 hooks 문서). 거짓 양성을 막으려고 그 파일이 그대로 메시지가 되고 commit-msg 판정이 돌 커밋만 본다(셀프 리뷰가 반례 여섯을 찾았다. 여러 `-F`, `--squash`, 같은 명령에서 쓰는 파일, `-e`, commit-msg 판정이 없는 저장소, `SKIP=commit-msg`). 일지 2026-10-13-47)
**어디로:** `tools/`의 PreToolUse 훅(Bash `git commit -F <파일>`): 메시지 파일의 제목을 commit-msg 훅과 같은 판정으로 먼저 대 보고 알린다. 새 훅의 넷(`.claude/rules/tools.md`)
**승인:** 자체 승인 2026-10-13, 3회차, 일지 2026-10-13-06·2026-10-13-12·2026-10-13-30. ADR 불필요
