# 0293: **커밋의 pre-commit이 도는 동안 작업 트리를 고쳐 그 커밋이 실패했다**(pytest가 줄을 감다 만 순간의 파일을 읽었고, 인용 검사가 그 사이 바뀐 파일을 자기가 고친 것으로 셌다. 커밋을 한 번 더 돌렸다)

**상태:** 닫힘 (`chore/hooks-push-help-and-commit-lock`, 2026-10-16, 일지 2026-10-16-52): PostToolUse 계기 훅 `tools/hook_edit_during_commit.py`. 탐침(`.scratch/harness/probes/commit_lock/probe.py`, git 2.32)이 `git add` 뒤의 보통 커밋은 두 훅이 도는 동안 `index.lock`이 없다고 내(`-a`·경로 커밋에만 있다) 신호를 도는 `git commit` 프로세스로 바꿨다. 윈도는 Toolhelp와 PEB, 리눅스는 `/proc`에서 읽고, 자식 git을 띄운 git(윈도 런처 `cmd\git.exe`)은 세지 않고 나머지 git의 작업 디렉터리의 체크아웃이 고친 파일의 체크아웃과 같으면 알린다. 워크트리의 git 디렉터리 자리(`<주 체크아웃>/.git/worktrees/<이름>/`)도 그 탐침이 쟀다. 막는 훅으로 올리는 것은 알린 뒤에도 어겨질 때다. 3회차(일지 2026-10-16-35)는 이 훅이 서기 전의 일이라 알린 뒤 어긴 회차로 세지 않았다
**어디로:** `tools/`의 새 계기 훅(Edit·Write·NotebookEdit)과 `.claude/settings.json`, `tools/hook_payloads.toml`: 고치는 파일이 든 체크아웃에 커밋이 도는 중이면(그 git 디렉터리의 `index.lock`) 이 편집이 도는 커밋의 검사와 겹친다고 알린다. pre-commit이 도는 동안 `index.lock`이 있는지와 워크트리의 git 디렉터리 자리를 탐침으로 먼저 잰다. 알린 뒤에도 어겨지면 막는 훅(`.claude/rules/tools.md`의 계기·막는 훅 가름)
**승인:** 자체 승인 2026-10-16, 3회차, 일지 2026-10-06-09·2026-10-16-21·2026-10-16-35. ADR 불필요
