# 0368: **`hook_edit_during_commit`이 부하 pytest가 임시 저장소에 친 커밋을 이 체크아웃의 커밋으로 두 번 알렸다**(그 세션은 커밋을 띄우지 않았고 브랜치 머리와 편집이 그대로였다. 원인은 어림이다. 자식 git을 띄우기 전의 윈도 런처 `cmd\git.exe`가 띄운 폴더(pytest의 작업 디렉터리)를 작업 디렉터리로 쥔 채 `-C <임시> commit`을 든 순간을 훑었다고 본다)

**상태:** 닫힘 (`chore/choice-facts-batch`, 2026-10-22, `tools/hook_edit_during_commit.py`가 전역 옵션의 `-C`·`--work-tree`를 풀고 런처를 실행 파일 자리로 알아본다(`commit_directory`, `is_launcher`). 재현과 원인은 `.scratch/harness/probes/edit_during_commit_launcher.py`이고, 남은 실제 git의 상대 경로는 독스트링의 못 보는 것과 그 시험. 일지 2026-10-22-11-choice-facts-batch.md)
**어디로:** `tools/hook_edit_during_commit.py`: 먼저 `git -C <임시> commit`을 되풀이하는 부하 아래에서 편집해 거짓 알림을 재현하고 원인을 가른다. 런처 경합이면 런처를 실행 파일 자리로 알아보고 런처에만 `-C`를 얹거나, 그 길을 독스트링의 못 보는 것에 적는다. 그 시험. 이 훅을 막는 훅으로 바꾸는 412보다 먼저 한다
**승인:** 자체 승인 2026-10-19, 2회차, 일지 2026-10-19-25-mutate-ctrl-c-under-load.md·2026-10-20-08-timing-tests-under-load.md. ADR 불필요
