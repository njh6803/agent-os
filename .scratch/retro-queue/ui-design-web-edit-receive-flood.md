# ui-design-web-edit-receive-flood: **화면의 웹 편집 확인에서 `read`로 받는 화면 파일 열네 개(합계 139,155바이트)가 결과로 대화에 그대로 실려, 본 세션이 받기와 맞대기를 서브에이전트에 맡겨야 했다**(일지 2026-11-16-0013, widget-login-state 화면 세션)

**상태:** 열림
**어디로:** `.claude/skills/ui-design/SKILL.md`의 "웹 편집 확인" 첫 항목: 받을 파일이 많아 결과가 대화에 크게 실리면 받기와 sha256 맞대기를 서브에이전트에 맡기고 보고만 받는다. 본 세션은 서브에이전트가 남긴 두 폴더(받은 것, HEAD 사본)를 `sha256sum`으로 다시 맞댄다. 같은 파일의 `ui-design-web-edit-read-path-prefix`(읽는 경로)와 함께 묶는다
**승인:** 자체 승인 2026-11-16, 1회차, 일지 2026-11-16-0013-widget-login-state-screens-2.md. ADR 불필요

(받은 내용이 대화에 실리는 것은 `read`의 동작이라 도구로 막을 수 없고, 서브에이전트에 맡겨 본 세션의 컨텍스트는 아꼈다. 손상은 없고 화면이 많은 기능을 다시 들어올 때마다 같은 판단을 새로 한 값이 든다)
