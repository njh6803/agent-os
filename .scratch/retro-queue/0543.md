# 0543: **65의 4회차. 관리 화면 e2e 준비(`web/apps/admin/e2e/stack.ts`)의 뒷정리 `rmSync(work, { recursive: true, force: true })`가 `EPERM`으로 끝나, 시험 여덟이 다 돈 뒤에도 실행이 "1 error was not a part of any test"로 1이었고 임시 폴더(`%TEMP%\agent-os-e2e-…`)가 남았다. 같은 종류의 결함이 사례마다 다른 자리에서 나오는 행이다**

**상태:** 닫힘 (.scratch/harness/issues/037-rmsync-maxretries-lint-rule.md, 2026-11-01, `RESTRICTED_SYNTAX`에 `recursive: true`인 `rmSync` 호출이 `maxRetries`를 주지 않거나 0이면 잡는 selector를 더하고 걸리는 사례 일곱·지나는 사례 넷을 붙였다. 켜기 전 위반은 열세 곳(재귀 `rmSync` 열다섯 곳에서 `maxRetries`가 이미 있던 둘을 뺀 수를 기준 커밋에서 `git grep`으로 손으로 셌다. 린트는 그중 열둘을 냈고 하나는 린트 전에 먼저 고쳤다)이었고 판정에서 뺀 자리 없이 모두 `maxRetries: 5`를 주었다. 공용 도우미는 새 직접 호출을 막지 못해 고르지 않았다. 이 재시도는 일시 잠김만 넘기고 다른 프로세스가 폴더를 작업 폴더로 쥔 경우는 못 푼다. 관리 화면 e2e의 같은 EPERM이 재시도 뒤에도 나는지는 일지에 적었고, 다시 나면 새 행을 쓴다)
**어디로:** 종류 전체를 없애는 고침 하나: `web/eslint.config.mjs`에 `recursive: true`인 `rmSync`가 `maxRetries`를 주지 않으면 잡는 규칙(`no-restricted-syntax`)과 `web/eslint.config.test.ts`의 사례, 또는 모든 자리가 부르는 공용 도우미. 이 종류를 받아들이기로 하면 일지에 그렇게 적고 닫는다
**승인:** 자체 승인 2026-10-30, 2회차(65의 5회차. 65는 1회차, 379는 3회차로 닫혔다), 일지 2026-10-30-07-admin-run-list.md, 2026-10-30-11-admin-settings-theme.md(2회차: 같은 `stack.ts:64`의 `EPERM`이 변이 표의 e2e 기준선을 오류로 끝내 변이를 넣지 못하게 했고, e2e 파일 하나를 다시 돌린 실행에서도 시험 밖 오류로 났다). ADR 불필요

(65는 판정자 시험의 `afterAll`, 379는 판정자 임시 트리였다. web의 재귀 `rmSync` 열두 자리 가운데 `maxRetries`를 준 곳은 `web/tools/judge-trees.ts` 하나다, Grep으로 봤다)
