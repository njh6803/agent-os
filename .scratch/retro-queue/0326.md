# 0326: **인계로 연 새 세션의 `EnterWorktree(path)`가 앞 세션의 워크트리를 `belongs to another running Claude Code session`으로 거부했다**(앞 세션은 제목을 `(인계함)`으로 바꿨지만 앱이 연 세션은 턴을 끝내도 프로세스가 남아 잠금의 pid가 살아 있었다. 새 세션이 ADR 0032의 제목 판정에 기대 `git worktree unlock`으로 풀고 들어갔고, `path`로 들어간 뒤에는 다시 잠기지 않았다)

**상태:** 닫힘 (`chore/next-session-handoff-batch`, 2026-10-18. `next-session` "인계할 때" 4에 잠금 풀기 단계를 더했고(슬래시로 쓴 절대 경로를 따옴표 없이 준 한 줄이 워크트리 가드를 지났다), `operations.md` 브랜치와 병합의 `locked` 문장 곁에 거부 사실을 적었다. 명세의 넘기기 전 차례도 맞췄다. 일지 2026-10-18-02)
**어디로:** `.claude/skills/next-session/SKILL.md` "인계할 때" 4: 대기 멈추기와 열기 사이에, 워크트리 세션이면 `git worktree unlock <자기 워크트리 절대 경로>`로 자기 잠금을 푸는 단계를 더한다(그 명령이 워크트리 가드를 지나는지 먼저 본다). `docs/constitution/operations.md` 브랜치와 병합의 `locked` 문장 곁에, `EnterWorktree`가 살아 있는 다른 세션의 pid로 잠긴 워크트리를 거부한다는 사실을 적는다
