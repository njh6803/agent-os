# 0408: **PR 연 뒤의 계기 훅 둘이 PR 열기를 실제와 다르게 알아본다. `gh api repos/<owner>/<repo>/pulls --method POST`(대기열 382가 처방한 길)로 연 PR에는 `hook_pr_next_session`과 `hook_handoff`가 모두 침묵했고, `hook_pr_next_session`은 PR을 열지 않는 `gh pr create --help`를 PR 열기로 잡았다**

**상태:** 닫힘 (`chore/choice-facts-batch`, 2026-10-22, 두 훅이 `opens_pr_by_api`로 `gh api …/pulls`의 POST를 PR 열기로 보고, `hook_pr_next_session`도 `--dry-run`·`--help`·`-h`를 거른다. `--input`만 준 꼴은 POST로 쟀다(`.scratch/harness/probes/gh_api_method.py`). 시험 표는 `tests/tools/gh_api_cases.py`. 일지 2026-10-22-11-choice-facts-batch.md)
**어디로:** `tools/hook_pr_next_session.py`·`tools/hook_handoff.py`: 명령 위치의 `gh api`가 `…/pulls`로 POST하는 꼴(메서드를 주거나, 필드(`-f`·`-F`)를 실어 기본 메서드가 POST가 되는 꼴. 그 규칙은 `gh api --help`이고, `--input`만 준 꼴의 메서드는 그 글이 말하지 않는다)을 PR 열기로 보고, `hook_pr_next_session`도 `--dry-run`·`--help`·`-h`를 거른다. `tools/hook_payloads.toml`의 발동·침묵 사례와 그 시험. 382가 그 길을 들이기 전에 반영한다
**승인:** 자체 승인 2026-10-21, 1회차(고침), 일지 2026-10-21-07-ticket-for-every-pr-to-tickets.md. ADR 불필요

(앞의 것은 명세 PR #336을 연 세션이 계기 없이 인계 규약의 취지대로 넘겼다, 일지 2026-10-21-05 "인계(PR 연 뒤)". 뒤의 것은 티켓 세션이 PR을 열 길을 보려고 친 `--help`에 계기가 왔고 따르지 않았다, 일지 2026-10-21-07 "이어받은 세션". `hook_handoff`는 `_NOT_RUNNING`으로 `--dry-run`·`--help`·`-h`를 이미 거른다)
