# 03: 런타임 — 실행을 준비할 때마다 고른 스킬을 읽어 컨텍스트로 넘긴다

**What to build:** 런타임이 실행을 준비할 때마다 에이전트의 `skills`에 적힌 이름마다 매니페스트와 스킬 문서를 읽어, 이름·설명·본문을 매니페스트 순서 그대로 `ctx.skills`로 넘긴다. 그래서 운영자가 스킬 문서를 고치면 서버를 다시 띄우지 않아도 다음 실행부터 듣는다. 관리 화면에서 스킬을 끄면 그 스킬을 쓰는 다음 실행은 409다. 운영자 면은 `꺼진 플러그인이다: skill <이름> (에이전트 <이름> 이 쓴다)`이고 최종 사용자 면은 종류와 이름 없는 고정 문구다. 고른 스킬의 폴더나 스킬 문서가 없거나 깨졌으면 실행 전 실패 500이고 트레이스가 남지 않는다. 운영자 면은 원문, 최종 사용자 면은 고정 문구이고 위젯이 저장한 대화를 지우지 않는다. 재개와 이어 가기도 같은 준비를 지나 지금 디스크의 문서를 쓴다. `ctx.llm()`과 트레이스는 바뀌지 않는다. 에이전트 코드가 엮지 않으면 효과가 없다.

01과 02가 연 틈을 닫는다. **03과 04 사이에는 틈이 있다(to-tickets에서 사용자가 분할을 골랐다).** 켜고 끄기가 실제로 듣는데 관리 화면의 스킬 행은 아직 "로더가 생기기 전에는 효과가 없다"고 말하고, 결정 칸은 꺼진 스킬을 미리 알리지 않아 누른 뒤의 409가 말한다. 화면이 효과를 낮춰 말하는 쪽이다. 이 티켓이 쓰는 문장은 그 틈 동안에도 참이어야 한다. 저장소의 매니페스트는 05까지 `skills`를 적지 않으므로 실제 모델이 받는 글은 이 티켓에서 바뀌지 않는다.

근거는 `.scratch/skill-plugin/spec.md`의 "실행 준비의 순서와 없음의 문구", "포트 `read_skill`…", "컨텍스트 멤버…", "고칠 자리의 묶음"의 B와 그 2026-11-04 명세 검토 주석, Testing Decisions의 "이음매"(사용자가 골랐다)·"좋은 시험"·"core 준비"와 그 주석·"HTTP 두 면"이다. 앞선 결정은 ADR 0041의 "준비 단계에 스킬 판정이 는다"와 "트레이스는 바뀌지 않는다", ADR 0017과 그 2026-10-03 이력(최종 사용자 면의 고정 문구), ADR 0014(재개의 첫 걸음), ADR 0012의 2026-11-03 둘째 이력이다.

**Blocked by:** 01(에이전트의 `skills` 칸), 02(`read_skill`, `Skill`, `AgentContext.skills`)

**Status:** ready-for-agent

### 준비의 순서와 문구

- [ ] **준비의 순서는 부재 → 깨짐(mcp 없음 → 마스킹과 승인의 충돌 → 모델 없음·읽히지 않음 → 스킬) → 운영자 파일의 손상 → 꺼짐(에이전트 → mcp → 모델 → 스킬) → 진입점 import → 모델 만들기다.** 스킬의 깨짐은 적힌 순서대로 이름마다 매니페스트 없음·읽히지 않음 → 스킬 문서 없음·읽히지 않음·이름 어긋남이고, 한 이름을 끝낸 뒤 다음 이름이다. 시험은 결함 둘을 함께 심어 어느 오류가 먼저 나오는지로 잰다. 선례는 `tests/core/test_run.py`의 "꺼진 플러그인" 절과 `test_준비의_순서는_부재_깨짐_꺼짐_진입점_모델_만들기다`이고, 그 시험에 스킬 자리를 더한다
- [ ] **없음의 문구는 `에이전트 <이름> 이 지정한 skill 플러그인이 없다: <스킬>`과 `에이전트 <이름> 이 지정한 skill 플러그인에 SKILL.md 가 없다: <스킬>`이다**(스토리 6). 읽히지 않음은 어댑터의 `PluginError` 그대로다. 시험이 문구를 단언한다. 선례는 `test_없는_모델은_실행_전에_PluginError_이고_트레이스가_없다`다
- [ ] **꺼진 스킬은 `Disabled`이고 운영자 면의 문구는 `꺼진 플러그인이다: skill <이름> (에이전트 <이름> 이 쓴다)`다**(스토리 10·11). 선례는 `test_꺼진_모델을_쓰는_실행은_실행_전에_Disabled_이고_메시지에_모델과_에이전트가_있다`다
- [ ] **스킬 매니페스트와 스킬 문서는 준비 한 번에 이름마다 한 번 읽고, 꺼진 집합도 지금처럼 한 번 읽어 넷을 본다.** 가짜 플러그인 소스의 읽기 횟수로 잰다

### 컨텍스트에 실제 값을 싣는다

- [ ] **core 시험의 가짜 플러그인 소스(`tests/core/test_run.py`의 `FakePlugins`)가 스킬 매니페스트의 이름 집합과 스킬 문서를 이름별로 따로 들고 읽은 횟수를 센다.** 그래야 "매니페스트는 있는데 스킬 문서가 없다"를 흉내 낸다. 읽히지 않음은 `read_skill`이 `PluginError`를 던지게 해서 잰다
- [ ] **`ctx.skills`가 매니페스트 순서를 지킨 값의 열이다.** 판정 에이전트가 값을 출력에 옮겨 이름 순과 다른 순서로 적은 매니페스트에서 본다(스토리 2)
- [ ] **`read_skill`에 넘기는 이름은 플러그인 이름 패턴을 지난 값이고, 런타임은 `ValidationError`가 아닌 어댑터의 `PluginError`만 받는다**(02의 PR 직전 리뷰가 넘긴 것). 어댑터의 `read_skill`은 이름을 스스로 검증하지 않고(`read_manifest`와 같은 규약) 호출부가 거른 값만 넘긴다. 이름이 에이전트 매니페스트의 `skills` 칸에서 와 읽는 단계에서 패턴을 지났는지 코드로 확인하고, 아니면 `is_plugin_name`으로 거른다. 새 호출부가 `parse_skill`을 직접 부르게 되면 `ValidationError`의 `str(error)`를 쓰지 않는다(그 문구는 틀린 값을 싣는다)
- [ ] **두 `run()` 사이에 가짜의 본문을 바꾸면 둘째가 바뀐 본문을 받는다**(스토리 9의 core 몫). 선례는 `FakePlugins`의 공개 속성 `model_manifests`를 실행 사이에 바꾸는 시험이다
- [ ] **스킬을 고르고 엮지 않는 에이전트의 프롬프트는 받은 글 그대로이고, 모델이 받은 글(`ToolAwareFakeModel.received`)과 `llm_called.prompt`가 같다**(스토리 4). 런타임이 아무것도 붙이지 않는다는 바깥 증거다
- [ ] **트레이스는 형식 3 그대로이고 스킬 이름을 이벤트에 적지 않는다.** 시험이 스킬을 고른 실행의 시작 이벤트 키와 형식을 본다

### 재개와 이어 가기

- [ ] **재개는 기록된 에이전트의 매니페스트를 지금 디스크에서 읽어 같은 순서를 지난다.** 스토리 19다. 두 갈래를 모두 고정한다. 첫 모델 호출 뒤에 멈춘 실행의 본문을 바꾸고 프롬프트에 본문을 엮는 에이전트로 재개하면 원인 `resume_mismatch`의 `run_failed`이고(선례 `test_재생_구간에서_기록과_어긋나면_원인은_재개_대조다`), 모델보다 먼저 승인 대상 도구를 부른 실행에서는 바뀐 본문이 재개 뒤 첫 `llm_called.prompt`에 그대로 남는다(ADR 0041이 받아들인 한계)
- [ ] **재개의 동시 결정 시험이 초록이다.** `read_skill`이 동기라 첫 걸음에 `await`가 없다는 불변식이 그대로다(`.claude/rules/core.md`의 재개 항목). 선례는 `test_이어_간_실행에_동시에_온_결정_둘은_하나만_받아들여져_도구가_한_번_불린다`다
- [ ] **이어 가기도 같은 준비를 지난다.** 스킬을 고른 에이전트가 이어 간 실행에서 `ctx.skills`와 `ctx.conversation`을 함께 받는다

### HTTP 두 면

- [ ] **운영자 채널에서 없는 스킬·없는 스킬 문서는 원문의 500, 꺼진 스킬은 종류·이름·에이전트를 든 409다.** 최종 사용자 면에서는 고정 문구의 500과 409이고 라우트도 표도 바뀌지 않는다(스토리 11·17·18). 시험의 자리는 실제 라우트와 준비를 지나는 `tests/channel/http/test_end_user.py`이고, 선례는 `test_꺼진_모델은_운영자_면은_이름을_들고_최종_사용자_면은_고정_문구의_409다`·`test_없는_모델은_운영자_면은_500_원문이고_최종_사용자_면은_고정_문구의_500이다`다. 두 면을 한 시험에서 본다. 명세가 함께 든 `tests/test_server.py`의 `test_core_의_구성_오류는_500이고_code_가_internal_error_다`·`test_core_의_꺼짐은_409이고_code_가_conflict_다`는 `_route_that_raises`로 예외를 상태 코드로 옮기는 표만 밀어 구현과 무관하게 초록이므로 이 시험의 선례가 아니다
- [ ] **`tests/channel/http/test_end_user.py`의 `FakePlugins`를 넓힌다.** 지금은 mcp와 모델만 종류로 가르고 나머지를 에이전트 표에서 찾아, 스킬 매니페스트와 스킬 문서를 따로 들 자리가 없다. 02는 이 가짜를 최소한으로 두었다. 이름별로 따로 들어 "매니페스트는 있는데 스킬 문서가 없다"를 흉내 낸다

### 옛 셈과 규칙

- [ ] **옛 셈("mcp와 모델")을 적은 자리를 모두 고친다.** `core/run.py`의 모듈 독스트링 두 문장과 `_prepare`와 `_reject_disabled`, `core/ports.py`의 `Disabled`와 `read_disabled`, `channel/cli/main.py`의 재개 명령, `channel/http/router.py`의 둘, `channel/http/end_user.py`의 둘, `tests/core/test_run.py`의 절 머리 주석이다. 명세의 목록은 셋이었고 명세 검토가 grep과 코드 읽기로 늘렸다. 위 목록은 to-tickets 시점의 것이라 시작할 때 다시 grep한다
- [ ] **`.claude/rules/core.md`의 준비 순서 문장과 `Disabled` 문장(35행), `.claude/rules/http.md` 28행의 최종 사용자 500 목록에 스킬을 더한다.** `.claude/rules/sdk.md`에 런타임이 실행을 준비할 때마다 고른 스킬을 읽는다는 말을 더한다(01·02가 넘겼다). 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다(`.claude/rules/agent-docs.md`)
- [ ] **`README.md`의 트리(`각각 <name>/plugin.toml`. 스킬에는 `SKILL.md`도 있다)와 `disabled.toml` 줄 "skill은 로더가 생길 때 그 로더가 켜짐을 본다"를 고친다**
- [ ] **원문에 준비 호출을 든 변이 표 둘을 맞춘다.** `uv run python tools/mutate.py --check .scratch/model-plugin/probes/prepare_mutations.toml .scratch/conversation/probes/continuation_mutations.toml`은 to-tickets 시점에 두 표의 변이 3개와 30개가 모두 원문을 찾는다고 냈다. 바꾼 뒤 같은 명령이 다시 모두 찾는지 본다
- [ ] **옛 표현을 저장소 전체에서 grep해 살아 있는 문서에 잔존이 0인지 본다**(`CLAUDE.md` 작업 규약 4). 위 자리들과 "에이전트와 그 mcp와 모델까지"처럼 스킬이 빠진 셈이다. ADR 본문 문장이 거짓이 되면 `.claude/rules/adr.md`를 따른다

### 검증

- [ ] **빨강을 먼저 본다**(헌법 원칙 II). 첫 빨강은 가짜의 스킬 문서 읽기가 한 번도 불리지 않는 것이다
- [ ] **검증 명령이 모두 초록이다.** 손으로 치는 다섯, `-m llm`, `-m llm_widget`, 위젯 e2e(`pnpm -C web/apps/widget exec playwright test`)를 친다. 최종 사용자 경로의 실행 준비가 바뀌어 `CLAUDE.md`의 검증 명령이 뒤의 둘을 요구한다. 저장소의 매니페스트가 아직 `skills`를 적지 않아 이 두 시험은 스킬 경로를 지나지 않고, 옛 경로가 깨지지 않았는지를 본다. 스킬 경로를 실제 모델로 지나는 것은 05다
