# skill-plugin: 스킬을 플러그인으로 읽어, 에이전트가 고른 스킬의 이름과 설명과 본문을 받아 쓴다.
**슬라이스:** 6
**Blocked by:** 없음
**끝:** 2026-11-05

스킬을 플러그인으로 읽는다. `plugins/skills/<이름>/`에 공통 넷만 적은 `plugin.toml`과 Agent Skills 표준의 `SKILL.md`를 함께 두고, 에이전트 매니페스트의 선택 칸 `skills`(플러그인 이름 목록)로 고른 스킬의 매니페스트와 `SKILL.md`를 실행을 준비할 때마다 읽어 이름·설명·본문을 컨텍스트의 읽기 전용 멤버로 넘긴다. 프롬프트에 엮는 것은 에이전트의 몫이고 런타임은 `llm()`에 아무것도 붙이지 않는다. 그래서 스킬 파일을 고치거나 켜고 끈 것이 서버를 다시 띄우지 않아도 다음 실행부터 듣는다. 머리말은 PyYAML로 전체를 읽고 `name`·`description`만 보며 나머지 키는 무시한다(PyYAML이 직접 의존성에 든다). 준비 순서의 깨짐과 꺼짐 끝에 스킬이 선다. 트레이스는 바뀌지 않고, 관리 화면은 스킬 행의 안내 줄을 걷고 결정 칸이 에이전트가 고른 꺼진 스킬을 미리 알린다. 저장소가 예시 스킬 하나를 두고 calc 가 고른다. 첫 티켓 둘이 나란히 돈다: 매니페스트의 `skills` 칸과 `openapi.json`(01), sdk 의 스킬 값과 컨텍스트 멤버와 플러그인 포트의 읽기 메서드(02)(ADR 0041과 그 2026-11-04 이력). 설계는 일지 2026-11-03-02. 명세는 `.scratch/skill-plugin/spec.md`(2026-11-03, 일지 2026-11-03-03)이고 측정은 `.scratch/skill-plugin/probes/`다. 사용자가 고른 둘(core의 `run()`·`resume()`에 가짜 플러그인 소스를 꽂는 이음매, 예시 스킬 `answer-format`)과 명세가 정한 열셋(줄 단위 `---` 가르기, strict pydantic 두 칸, sdk의 불변 값 `Skill`과 `parse_skill`, `parse_skill`이 YAML 읽기의 모든 예외를 `ValueError`로 바꾸고 어댑터가 매니페스트와 같은 집합으로 `PluginError`를 만듦, `read_skill(name: PluginName)`이 `Skill`을 돌려주고 스킬 문서가 없으면 `None`, 읽지 못한 문구와 이름 어긋남 문구, `skills`의 중복 거부, 준비 순서와 없음의 문구, `AgentContext.skills`가 `tuple[Skill, ...]`, calc의 `지침 <이름>:` 블록, sdk 밖의 `yaml` import를 막는 계약, 고칠 자리의 묶음 넷(A 계약과 읽기 → B 런타임 → C 관리 화면과 D 예시. 명세 검토가 C를 B 뒤로 옮겼다), 실제 모델 호출은 calc 시험의 단언 하나). 명세의 PR이 ADR 0041 이력과 ADR 0012 둘째 이력을 올렸다. 범위 밖 셋은 claude-code-compat 행에 넘겼다. 2026-11-04 명세 검토를 거쳐 티켓 다섯으로 쪼갰다(`.scratch/skill-plugin/issues/`, 일지 2026-11-04-02). 01(매니페스트의 칸과 계약, PR #462)과 02(스킬 문서 읽기, PR #461)가 병합되어 기능이 `in-progress`가 됐다. 03(런타임이 실행마다 고른 스킬을 준비한다)이 PR #463으로(일지 2026-11-05-01), 05(calc가 예시 스킬 `answer-format`을 쓴다)가 PR #464로(일지 2026-11-05-02) 병합됐다. 04는 관리 화면의 스킬 행에서 안내 줄을 걷고 결정 칸이 에이전트가 고른 꺼진 스킬로 막힌 재개를 미리 알려 기능을 닫았다(PR #465, ADR 0019 이력, 일지 2026-11-05-03)
