# multi-instance: 서버 인스턴스를 여럿 띄워도 동시 실행 상한과 실시간 구독이 하나의 서버처럼 동작하게 한다.
**슬라이스:** 14
**Blocked by:** admin-crud

다중 인스턴스(후보 5). 도는 실행인가는 임대가 답하고, 상한의 셈은 Redis의 원자 연산으로 옮기며 값은 배치 전체의 합이다. 인스턴스는 이벤트를 트레이스에 쓴 뒤 Redis 채널(run_id)에 내고 구독은 트레이스의 나머지 뒤 그 채널을 받는다. 플러그인 디렉터리와 운영자 파일은 공유 볼륨이 전제다(ADR 0042 묶음 ⑤). postgres-foundation의 설계가 넘긴 것(2026-11-17, ADR 0066 결정 "표를 올리는 때"): 단독 compose에서는 한 번 돌고 끝나는 `migrate` 서비스 하나가 `serve` 앞에서 표를 올린다. `agent-os migrate` 둘이 같은 데이터베이스에 함께 도는 경우를 alembic이 막는지는 재지 않았다(어림). 서버를 여럿 띄우는 배치에서 표를 올리는 자리를 하나로 둘지는 이 행의 설계가 정하고, 둘이 함께 도는 경우도 그때 잰다
