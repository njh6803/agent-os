# step-up-login: 익명으로 질문하다가 로그인한 사람만 쓰는 도구에 닿으면 로그인을 안내하고, 로그인한 뒤 같은 대화에 이어 답한다.
**슬라이스:** 9
**Blocked by:** portal-login
**설계:** ADR 0060

질문 도중의 로그인 요구와 대화 넘겨받기(`CONTEXT.md`의 로그인 요구, 로그인 확인 표시, 대화 넘겨받기). portal-login의 설계 인터뷰(일지 2026-11-12-1937)에서 사용자가 둘 다 사이트의 동작에 "질문 도중 로그인 요구도 추가"를, 로그인한 뒤의 대화에 "로그인 전 대화를 넘겨받아 이어 가기"를 골랐고, 계획표의 줄을 portal-login과 나누기로 골라 선 행이다. 0.1 판의 행이라 pilot-release가 이 행을 기다린다(ADR 0046 이력 2026-11-12). portal-login을 기다리는 까닭은 로그인 흐름과 로그인 상태가 그 행의 것이기 때문이다. 정한 것은 ADR 0060이 원천이고 여기에 다시 적지 않는다. 그 ADR이 정한 갈래의 이름만 든다: 계기(운영자가 규칙 파일에 적는다), 로그인 확인 표시, 집행의 차례, 닿았을 때의 실패 원인, 재개, 위젯의 안내와 로그인 통로, 같은 질문 다시 보내기, 대화 넘겨받기, 관리 화면의 표시. 이 행은 계약을 다섯 자리에서 바꾼다(규칙 파일, 이벤트, 사이트 토큰의 선택 주장, 위젯의 공개 표면과 저장 형식, `openapi.json`. ADR 0060 Consequences "계약이 바뀌는 자리 다섯"). 그 계약을 고치는 티켓이 이 행의 첫 티켓이고 다른 티켓을 막는다. 이 행의 범위가 아닌 것: 저자가 매니페스트에 적는 로그인 요구는 author-login-requirement가, 도구 서버의 응답이 일으키는 로그인 요구는 server-login-requirement가 맡는다. 명세 전에 `/ui-design step-up-login`으로 화면(위젯의 로그인 안내와 단추, 단추 없는 안내, 관리 화면의 넘겨받았다는 한 줄)을 그린다. 명세가 먼저 잴 것: 위젯이 탭 저장소에 둔 대화와 다시 보낼 질문의 표시가 로그인 서버에 다녀온 뒤에도 남는지(portal-login의 e2e가 먼저 재면 그 값을 쓴다). 명세가 짓는 것은 ADR 0060 Consequences "명세가 짓는 것"에 있다. 수락: 둘 다 사이트에서 익명으로 calc 예시에 질문하다가 로그인 요구가 걸린 도구에 닿으면 로그인 안내가 뜨고, 로그인한 뒤 같은 대화에 이어 답이 나오며, 트레이스에 넘겨받은 사실이 남는다
