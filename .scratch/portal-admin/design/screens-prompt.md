# portal-admin 화면 프롬프트

위젯 관리 화면(사이트의 목록, 사이트 하나의 위젯 설정과 위젯 테스트 페이지 설정을 고치는 화면과 양식 옆의 미리보기, "테스트" 메뉴, 로그인하지 않았거나 로그인 시간이 끝났을 때의 화면)과 위젯 테스트 페이지의 들어오는 문을 그릴 때 그리는 쪽에 주는 시작 프롬프트다. 디자인 시스템 아티팩트에 올린 디자인 시스템으로 완성 화면을 그린다(ADR 0025와 그 2026-10-16·2026-10-20 이력). ADR 0064 Consequences "화면", ADR 0065 Consequences "화면", 기능 계획 `.scratch/portal-admin/plan.md`가 이 화면을 명세 전에 그려 사용자에게 확인받기로 했고, 확정한 화면은 명세의 근거가 된다.

프롬프트에 든 것은 세 가지다. **결정**은 ADR 0064(결정 "위젯 관리 화면", "주소", "로그인", "고칠 수 있는 계정", "주소의 검사", "0.1 판에서 등록하는 것"과 그 이력 2026-11-16, "밝기 스위치 숨기기", "위젯 미리보기 페이지 설정", "시작 검사가 가는 자리", "'테스트' 메뉴와 공개 주소", "값을 옮기는 길은 짓지 않는다", "고지의 고정 문장", "바꾼 기록"), ADR 0065(결정 "미리보기", "위젯 테스트 페이지", "익명 모드는 남는다", "이름"), ADR 0061(결정 "0.1 판에서 등록하는 것", "고지", "다크 모드 스위치", "로그아웃", "URL 방식", "위젯 설정"), ADR 0062(결정 "로그인 상태"의 쿠키가 `https`와 `localhost`에서만 저장된다는 것), 위젯 화면 작업이 그린 모양 셋(`.scratch/widget-login-state/design/README.md`의 갈래 2·3·4), 이 화면 작업에서 사람이 고른 것(일지 2026-11-16-0025의 "사용자에게 물은 것", "방향", "위젯 미리보기 페이지를 다시 묻기", "후속 질문 둘", "승인")이 정한 것이다. ADR 0064의 결정 제목에 남은 옛 이름 "위젯 미리보기 페이지"는 ADR 0065가 위젯 테스트 페이지로 바꿨다. 화면 문구의 말은 `CONTEXT.md`(위젯 관리 화면, 위젯 설정, 위젯 테스트 페이지, 위젯 테스트 페이지 설정, 미리보기, 사이트, 발급자, 보증 모드, 고지, 고지 확인, 운영자 계정, 로그인 서버 항목, 최종 사용자)와 `.claude/rules/web-design.md`에서 왔다. **이 프롬프트의 제안**은 그리는 데 필요해서 더한 것이고 명세가 다시 정한다. 화면마다 그릴 상태, 칸의 묶음과 차례, 도움말과 오류 문구, 저장과 되돌리기의 자리, 미리보기의 상태 고르기, 계정 자리의 메뉴, 사이트 지우기의 자리, 들어오는 문의 문구가 여기 든다. **탐색용 가정**은 결정도 제안도 아닌 그리기 위한 값이고 각 차례 끝의 "탐색용 가정"에 모았다.

이 화면 작업에서 사람이 고른 것은 다섯 갈래다. 첫째, 위젯 화면 작업이 위젯 설정에서 고르게 하자고 넘긴 화면 모양 둘(로그인 모드 사이트의 로그인 전 모양, 고지 전문을 보이는 법)을 0.1 판의 위젯 관리 화면에 넣는다. 그래서 위젯 설정의 화면 모양 칸은 만료 알림의 모양까지 셋이고, 칸마다 세 모양 가운데 하나를 고른다(ADR 0064 이력 2026-11-16). 둘째, 겉모습은 이미 확정한 Agent OS 관리 화면을 기준으로 삼고, 관리 화면에 없는 긴 설정 양식만 상담 위젯 제품의 설정 화면을 조사해 고른다(아래 "참고 디자인"). 셋째, 사이트 하나의 양식은 두 짜임(한 페이지와 저장 단추 하나, 탭과 저장 단추 하나)을 모두 그려 고르고, 화면 모양 칸은 작은 그림이 든 고르기다. 넷째, 양식 옆에 저장하지 않은 값으로 그린 위젯(미리보기)을 두고, "테스트"는 저장한 설정으로 실제로 질문해 보는 위젯 테스트 페이지로 간다(ADR 0065 결정 "미리보기"). 다섯째, 위젯 테스트 페이지는 로그인해야 열리고, 운영자 계정과 회사 로그인 두 문으로 들어온다(ADR 0065 결정 "위젯 테스트 페이지").

위젯 관리 화면은 관리 화면과 다른 앱이지만 디자인 시스템과 관리 화면이 쓰는 방식을 그대로 쓴다(ADR 0064 결정 "위젯 관리 화면"). 그래서 틀(왼쪽 옆 탐색과 좁은 폭의 위 막대, 화면 머리, 표, 알림)과 겉모습은 `.scratch/admin-style/design/`의 확정 화면과 같은 모양으로 그린다. 옆 탐색 맨 아래의 계정 자리와 좁은 폭의 두 줄 위 막대, 탐색이 없는 가운데 칸 틀은 관리 화면의 로그인 화면 작업(`.scratch/admin-login/design/`)이 확정한 모양을 따른다. 탐색 항목과 계정 메뉴의 내용만 이 앱의 것이다. 미리보기 안의 위젯은 위젯 화면 작업(`.scratch/widget-login-state/design/`)이 확정한 위젯 그대로이고, 위젯 테스트 페이지의 틀은 pilot-portal이 확정한 화면(`.scratch/pilot-portal/design/`)의 위쪽 띠와 가운데 한 열이다.

## 하는 법

`/ui-design portal-admin`으로 한다. 그 스킬이 순서의 원천이고, 이 파일은 그 스킬의 3단계가 쓰는 시작 프롬프트다.

1. **디자인 시스템을 맞춘다(스킬 2단계).** 2026-11-16에 이 화면 작업의 처음 세션과 이어받은 세션이 한 번씩 웹 편집을 확인했고 둘 다 `clean`이었다. 올리기는 두 번 모두 보낼 것이 없어 맞출 것 없이 끝났다(일지 2026-11-16-0025 "ui-design 1·2"와 "ui-design 2(이어받은 세션)").
2. **첫 차례를 그린다(스킬 5단계).** 아래 "1. 고를 갈래와 정해진 화면"이 그릴 것이다. 와이어프레임 차례는 두지 않는다. 디자인 시스템의 부품으로 그린 와이어프레임은 완성 화면과 색 말고는 거의 같아서, 고를 갈래도 완성 화면으로 그린다(`docs/agents/issue-tracker.md` 화면 디자인 절). 아티팩트 하나에 두 차례를 함께 두고 쪽(`pages`)으로 가른다.
3. **안을 고르고 정해진 화면을 확정한다(스킬 6단계).** 갈래마다 사람이 안 하나를 고르고, 같은 차례의 정해진 화면 전체를 그대로 확정할지 답한다. 고른 안과 확정은 캔버스 메모에도 적는다.
4. **둘째 차례를 그린다(스킬 5단계).** 같은 아티팩트의 다음 쪽에 "2. 고른 사이트 화면과 들어오는 문의 완성 화면"을 그리고, 사람이 그 차례 전체를 확정한다.
5. **저장소로 옮긴다(스킬 7단계).** 아래 "고른 뒤"가 이 기능의 표 칸이다.

## 참고 디자인

`kickoff/prompting.md`의 "참고 디자인 조사"대로 했다. 기준 화면은 확정한 Agent OS 관리 화면이고 색·글꼴·간격과 틀은 그대로 두며, 참고는 관리 화면에 없는 긴 설정 양식의 배치와 문구에만 쓴다. 사람은 "관리 화면 + 위젯 설정 사례 조사 (추천)"를 골랐고 따로 준 참고는 없다(일지 2026-11-16-0025 "사용자에게 물은 것"). 세션이 맡긴 서브에이전트가 다섯 제품(채널톡, Intercom, Crisp, Zendesk messaging Web Widget, Chatbase)의 공개 문서를 내려받아 읽었다. 화면 사진은 한 장도 보지 않았고, 글이 든 수치는 그 글의 값이지 잰 값이 아니다. 출처와 읽은 정도의 목록은 일지 2026-11-16-0025 "조사: 위젯 설정 화면 사례"다.

뽑은 규칙(같은 절):

1. 묶음 차례는 글 → 모양 → 동작 → 로그인·보안 → 설치가 흔하다(Zendesk, Intercom, Chatbase).
2. 양식은 한 페이지에 묶음 제목을 달아 늘어놓는다(Zendesk, 채널톡). 탭은 큰 갈래를 가를 때만 쓴다(채널톡, Chatbase).
3. 저장은 명시적인 단추가 다수다(Zendesk, Intercom). 자동 저장은 Crisp의 모양 설정뿐이다.
4. 저장하지 않은 바뀜의 표시는 Chatbase만 문서에 있다(반영 단추에 점과 남은 바뀜의 수). 떠날 때 묻는지는 다섯 문서 모두 말하지 않는다.
5. 저장 전 미리보기는 셋이 둔다(Intercom은 설정 오른쪽, Crisp는 실제 챗박스, Chatbase는 Playground).
6. 시험하는 길은 관리 화면 안의 시험 위젯과 새 탭의 공개 페이지 둘이다.
7. 입력 형식 규칙은 칸 설명에 적지만(Chatbase, Intercom), 오류를 언제 어디에 보이는지는 다섯 문서 모두 말하지 않는다.
8. 밝기는 라이트·다크·시스템 셋이 흔하다(Intercom, 채널톡). Chatbase는 테마 전환 켜고 끄기와 기본 테마를 따로 두어, 처음 밝기와 밝기 스위치 숨기기의 짝과 같다.

사람이 고른 방향(일지 2026-11-16-0025 "방향", "위젯 미리보기 페이지를 다시 묻기", "후속 질문 둘"):

1. **양식 짜임.** 사람이 'Other'에 "한 페이지와 저장 단추 하나 (추천)이랑 탭으로 나누고 저장 하나 둘 다 보여줘"라고 답했다. 한 페이지 짜임은 묶음을 차례로 늘어놓고 화면 아래에 붙은 띠에 바뀐 칸의 수와 "되돌리기", "저장"을 둔다(규칙 3·4). 목차를 어떻게 둘지(목차 없음, 왼쪽 목차, 묶음 제목을 왼쪽에 둔 두 열)는 세 안으로 그린다. 탭 짜임은 묶음마다 탭이고 저장 단추는 화면에 하나다. 그래서 갈래 1은 네 안이다.
2. **화면 모양 칸.** 사람이 "작은 그림이 든 고르기 (추천)"를 골랐다. 모양마다 위젯 상자를 줄인 회색 도식 그림과 이름, 한 줄 설명을 담은 고르기 칸 셋을 나란히 둔다. 화면 모양을 그림으로 고르는 예는 조사한 문서에서 찾지 못했다.
3. **미리보기.** 사람이 'Other'에 "양식 옆에 저장 전 위젯 그림 두기로 하고 이걸 미리보기 페이지로 하자. 테스트는 말 그대로 테스트 해보는 곳으로."라고 답했다(규칙 5). 미리보기는 질문을 보내지 않고, 실제로 답이 오는지는 위젯 테스트 페이지에서 본다(ADR 0065 결정 "미리보기").
4. **위젯 테스트 페이지.** 사람이 "테스트 페이지에 회사 로그인 문도 둠 (추천)"을 골랐다. 운영자는 운영자 계정으로 들어와 모든 사이트를 시험하고, 직원은 회사 로그인으로 들어와 로그인 모드 사이트에서 질문한다(규칙 6의 새 탭 쪽).

가져오지 않을 것: 참고 제품의 로고, 브랜드 색과 글꼴, 화면 구성의 복제, 자동 저장(Crisp의 모양 설정), 관리 화면 안에서 실제로 질문하는 시험 위젯(Zendesk의 "Test AI agent", Chatbase Playground. 미리보기는 질문을 보내지 않는다), 런처 위치 고르기와 모서리 슬라이더와 자유 색 칸(hex 입력과 색 견본)과 그림 올리기(그림 올리기와 자유 색은 0.1 판 뒤의 widget-appearance, ADR 0061), 설치 코드 묶음과 보안 묶음(위젯 설정에 없는 값이다. 허용 출처와 요청 글자 수 상한은 0.1 판 뒤의 site-limits-admin, ADR 0064), 데스크톱과 모바일 웹을 가르는 탭. 이 목록은 사람에게 따로 묻지 않았다. 화면 디자인 절이 든 넷(로고, 브랜드 색, 화면 구성의 복제, 그 화면에 없는 기능)을 이 기능의 결정에 비춰 세션이 풀어 적은 것이다.

참고와 저장소 규칙이 부딪친 자리 하나: Zendesk는 모서리를 슬라이더로, 색을 hex 입력과 색 견본으로 고른다(규칙 8). 이 화면은 색 테마 넷 가운데 하나만 고르고 디자인 시스템이 명암비를 판정하는 여덟 벌 밖의 색을 받지 않으므로(`.claude/rules/web-design.md`), 색 테마는 그 테마의 쓰임새 토큰으로 칠한 견본을 단 라디오로 그린다.

## 1. 고를 갈래와 정해진 화면

```text
Agent OS의 위젯 관리 화면과 위젯 테스트 페이지의 들어오는 문을 그려 줘. 위젯 관리 화면은 운영자가 위젯을 붙이는 사이트마다 위젯 설정(위젯의 이름과 글, 색과 밝기, 로그인과 로그아웃 주소, 고지, 위젯의 화면 모양)과 위젯 테스트 페이지 설정(위젯 테스트 페이지에 그 사이트를 담을지, 발급자, 보증 모드, 보고서 링크)을 등록하는 웹 앱이다. Agent OS 관리 화면과 다른 앱이고 같은 호스트의 다른 포트에 서지만, 운영자는 관리 화면에 로그인한 운영자 계정 그대로 들어온다. 로그인 화면은 관리 화면의 것 하나뿐이라 이 앱에는 계정 이름과 비밀번호 칸이 없다. 위젯 테스트 페이지는 저장한 위젯 설정으로 그린 위젯에 실제로 질문해 보는 페이지이고, 로그인해야 열린다. 디자인 시스템의 기본 테마(녹청)의 라이트 모드로 그린다. 모든 결과는 대화의 답이 아니라 디자인 파일 안의 쪽으로 넣어 줘.

틀(정해졌다): 관리 화면의 확정된 틀을 그대로 쓴다. 폭 768px 이상은 왼쪽 옆 탐색(폭 256px, 항목 높이 36px, 아이콘과 글자를 함께 둔 항목)과 본문을 바탕 한 단계(옆 탐색은 올라온 바탕)와 테두리로 가르고, 고른 탐색 항목은 옅은 회색으로 칠한다. 옆 탐색 맨 위 글자는 "위젯 관리 화면"이다. 탐색 항목은 둘이다. "사이트"(아이콘 list. 사이트 목록과 사이트 하나 화면)와 "테스트"다. "테스트"는 이 앱의 화면이 아니라 위젯 테스트 페이지(https://agent.example.com/portal/)를 새 탭으로 여는 링크라 고른 상태가 되지 않는다. 그 아이콘 자리에 새 탭으로 연다는 아이콘(Lucide external-link)을 두고, 화면 읽기 프로그램에는 "(새 탭에서 열림)"을 함께 읽힌다. 옆 탐색 맨 아래에 지금 로그인한 운영자 계정의 자리를 둔다. 계정 이름(고정폭)과 그 아래 흐린 "Agent OS 운영자 계정"이고 누르는 버튼이며, 누르면 위로 열리는 메뉴에 흐린 안내 "로그아웃은 관리 화면에서 한다. 관리 화면에서 로그아웃하면 이 화면에서도 나간다."와 링크 "관리 화면 열기"(새 탭)가 든다. 폭 768px 미만은 두 줄 위 막대다. 첫 줄에 "위젯 관리 화면"과 오른쪽 끝의 계정 이름 버튼, 둘째 줄에 탐색 항목 둘이 선다(메뉴 단추나 서랍은 두지 않는다). 본문은 화면 머리(제목, 개수, 흐린 설명 한 줄, 오른쪽 위의 동작)와 그 아래 내용이다. 로그인이 필요한 화면에는 탐색이 없다. 그 화면은 옆 탐색 없이 "위젯 관리 화면" 글자와 그 아래 한 칸이 최대 폭 440px로 가운데 서고 위 여백이 넉넉한 틀이다(관리 화면의 로그인 화면과 같은 틀).

배치와 밀도(정해졌다): 운영자가 사이트를 등록하거나 글 하나를 고치러 가끔 여는 도구 화면이라 조용하고 촘촘하게 둔다. 디자인 시스템의 밀도는 폭 768px 이상에서 촘촘(버튼과 입력 32px, 표의 행 36px, 본문 14px), 미만에서 보통(40px, 44px, 15px)이고 그대로 따른다. 표는 칸에 세로줄이 없고 행 사이는 아주 옅은 가로줄이며, 사이트 이름, 에이전트 이름, 발급자, 주소, 계정 이름, 시각은 고정폭이다. 묶음은 경계선보다 여백으로 나누고 위계는 화면 제목만 크게 두고 나머지는 글자 굵기로 짓는다.

지켜 줄 것(정해졌다):
- 색은 디자인 시스템의 쓰임새 토큰만 쓴다. 다크 전용 색이나 테마 전용 색을 따로 두지 않는다. 한 영역만 다른 테마나 모드로 그리려면 그 요소에 data-theme, data-mode, data-density를 달고 바탕을 var(--bg)와 var(--text)로 칠한다.
- 컴포넌트에 className과 style을 주지 않는다. 배치는 디자인 시스템 README의 유틸리티 클래스와 인라인 CSS 변수로 짓는다.
- 그림자는 떠 있는 것(계정 메뉴, 미리보기 안의 위젯 창, 확인 창)에만 쓴다. 카드, 표, 알림, 양식의 묶음은 그림자 없이 바탕과 테두리로 선다.
- 상태를 색만으로 보이지 않는다. 아이콘 모양이나 글자를 함께 쓴다. 상태 배지는 실행의 상태 넷에만 쓰고 꼬리표를 배지로 만들지 않는다.
- 스위치(Switch)는 누르는 즉시 적용되는 설정에만 쓴다. 이 양식은 저장 단추를 눌러야 적용되므로 켜고 끄는 값은 체크박스다.
- 버튼이 둘이면 보조가 먼저이고 주가 나중이다. 한 영역에 주 버튼은 하나다. 되돌릴 수 없는 일(사이트 지우기)에만 위험 버튼을 쓴다.
- 아이콘은 Lucide 모양, 선은 화면 1.5px, 크기는 14·16·20px이다. 디자인 시스템의 이름 열일곱 밖의 아이콘(external-link 등)은 쓴 자리를 그림 옆 메모로 적는다.
- 화면 문구는 한국어이고 용어집의 말을 쓴다. "위젯 관리 화면"을 "관리 화면"으로 줄여 쓰지 않는다(그 말은 Agent OS의 웹 앱이다). "테스트"는 탐색 항목의 글자에만 쓰고, 본문에서는 "위젯 테스트 페이지"라고 쓴다.
- 포인터로 누르는 목표는 가로세로 24px 이상이다. 폭 375px에서 가로 스크롤이 없다.

그릴 화면: 아래에서 "1280"은 데스크톱 1280px, "375"는 모바일 375px이다. 상태가 여럿인 화면은 아트보드 하나에 폭 360px 남짓한 칸을 나란히 두고 칸마다 위에 흐린 설명 한 줄을 달아도 된다.
```

## 2. 고른 사이트 화면과 들어오는 문의 완성 화면

하는 법 3에서 고른 안과 확정을 캔버스 메모에 적은 뒤 넣는 글이다. 첫 차례의 답(갈래 1은 "탭과 저장 단추 하나", 갈래 2는 "한 칸에 두 문을 위아래로", 일지 2026-11-16-0025의 "ui-design 6: 고르기(첫 차례)")으로 고른 안의 이름을 넣고, 한 페이지 짜임을 전제로 쓴 문장(1의 고른 탭, 3의 오류로 옮겨 가는 자리, 5의 짜임, 8의 한 열, 포커스 순서)을 탭 짜임에 맞게 고쳤다.

```text
앞에서 고른 안대로 사이트 하나 화면(탭과 저장 단추 하나)과 위젯 테스트 페이지의 들어오는 문(한 칸에 두 문을 위아래로)의 나머지 상태, 좁은 폭, 다크를 그려 줘. 틀, 밀도, 지켜 줄 것, 사이트와 칸의 값, 작은 그림 고르기, 미리보기, 저장 띠는 앞 차례와 같다. 모든 결과는 디자인 파일 안의 다음 쪽으로 넣어 줘.

그릴 화면(1280은 데스크톱 1280px, 375는 모바일 375px):
1. 사이트 하나, 1280, 바뀐 칸이 없을 때: 앞 차례의 help-center를 저장한 직후다. 저장 띠가 없고, 화면 머리의 흐린 줄의 바꾼 때가 "마지막으로 바꾼 때 2026-11-16 11:05 ops-lead"로 바뀌었으며, 머리 아래에 흐린 한 줄 "저장했다. 다음에 위젯을 여는 사람부터 바뀐다."가 다음 바뀜까지 남는다(제안). 고른 탭은 저장할 때의 "로그인과 로그아웃" 그대로이고, 탭 이름 뒤의 바뀐 칸의 수가 사라진다. 미리보기의 보는 상태는 "첫 화면"이다.
2. 미리보기의 상태, 칸 다섯을 나란히(미리보기 칸만, 폭 360px): (가) 대화가 한 번 오간 뒤(질문 "주문한 상품은 언제 오나요?", 도구 줄, 출력 "주문 번호를 알려 주시면 배송 상태를 찾아 드릴게요."), (나) 고지 확인 전(위젯 화면 작업이 확정한 고지 확인 덮개), (다) 고지 전문을 연 뒤(고지 전문을 보이는 법의 기본 "고지 줄 안에서 펼침"), (라) 로그인 시간이 끝남(만료 알림의 기본 "대화 안의 카드"), (마) 밝기 "어둡게"를 누른 첫 화면(위젯 창에 data-mode="dark"). 보는 상태 셀렉트의 값이 칸마다 그 상태다.
3. 저장하지 못했을 때, 1280: 두 칸이 거절되었다. 로그아웃 주소에 javascript:alert(1)을 넣어 칸을 떠난 순간 칸 오류 "https://로 시작하는 완전한 주소를 넣는다. 자기 PC에서 시험할 때는 http://localhost 주소도 된다."가 선다(형식은 브라우저에서 바로 본다, 제안). 발급자는 저장을 누른 뒤 위젯 관리 서버가 거절해 칸 오류 "이 발급자는 사이트 intranet이 이미 쓴다. 발급자는 사이트마다 달라야 한다."가 선다. 저장 띠는 위험 알림의 아이콘(circle-x)과 "저장하지 못했다. 칸 2개를 고친다."로 바뀌고 버튼은 그대로다. 오류가 든 탭 둘("로그인과 로그아웃", "위젯 테스트 페이지")의 이름 뒤에는 바뀐 칸의 수 대신 위험 글자색의 circle-x 아이콘과 오류 칸의 수가 서고(색만으로 보이지 않게), 첫 오류가 든 탭 "로그인과 로그아웃"이 골라져 첫 오류 칸에 포커스가 간다(제안). 그림은 그 탭이 골라진 화면이다.
4. 저장하지 않고 떠나려 할 때, 1280: 바뀐 칸이 3개인 채로 옆 탐색의 "사이트"를 눌렀다. 화면 가운데 확인 창(떠 있는 것이라 그림자, 뒤를 옅게 덮는다): 제목 "저장하지 않은 바뀜이 있다", 본문 "바뀐 칸 3개를 저장하지 않았다. 떠나면 바뀜이 사라진다.", 보조 버튼 "머무르기"와 위험 버튼 "버리고 떠나기"(제안. 조사한 다섯 문서는 떠날 때 묻는지 말하지 않는다).
5. 사이트 등록, 1280: 주소 /sites/new. 화면 머리는 돌아가기 링크 "사이트 목록", 제목 "사이트 등록", 흐린 한 줄 "사이트 이름은 등록한 뒤에 바꾸지 못한다." 양식은 같은 탭 짜임이고 첫 탭 "기본"이 골라져 있으며 칸이 비어 있다. 사이트 이름 칸이 쓸 수 있는 칸이고 도움말은 "영문 소문자, 숫자, 하이픈만 쓴다. 위젯의 임베드 속성에 적는 이름이다." 그리지 않는 다른 탭의 처음 값으로, "위젯 테스트 페이지에 담는다"는 켜져 있고, 고지 전문에는 위젯 테스트 페이지에 담는 사이트의 처음 값(익명 식별자와 계정 기록의 두 문장)이 들어 있다(ADR 0064 결정 "고지의 고정 문장"). 저장 띠는 "새 사이트"와 보조 버튼 "취소", 주 버튼 "등록"이다. 미리보기는 비운 칸마다 위젯의 기본값으로 그린다.
6. 사이트 지우기, 1280: 화면 머리의 더 보기 메뉴(떠 있는 것)가 열려 위험한 일 "사이트 지우기"(danger 글자색)가 보이는 칸과, 그것을 누른 뒤의 확인 창 칸을 나란히. 확인 창: 제목 "사이트 help-center를 지울까"(사이트 이름 고정폭), 본문 "이 사이트의 위젯 설정과 위젯 테스트 페이지 설정이 지워진다. 이 사이트 이름을 적은 위젯은 위젯 설정을 받지 못하고, 위젯 테스트 페이지에서도 빠진다. 되돌릴 수 없다.", 보조 버튼 "취소"와 위험 버튼 "지우기"(제안).
7. 열리지 않는 사이트, 1280: partner-trial의 사이트 하나 화면. 화면 머리 아래 경고 알림 "위젯 테스트 페이지가 이 사이트를 열지 않는다" / "발급자 https://partner.example이 사이트 파일에 없다. 사이트 파일에 그 발급자를 더하고 위젯 테스트 페이지를 다시 띄우거나, 아래 발급자를 고친다. 위젯 설정은 그대로 쓰인다." 화면 머리의 "위젯 테스트 페이지에서 열기"는 서지 않는다(제안).
8. 사이트 하나, 375: 두 줄 위 막대 아래 화면 머리, 탭 줄(넘치는 탭은 옆으로 밀어 본다, 제안), 고른 탭 "로그인과 로그아웃"의 칸이 한 열로 서고, 미리보기 칸은 없다. 화면 머리 오른쪽 위의 동작은 보조 버튼 "미리보기"와 더 보기 아이콘 버튼이고, 저장 띠는 화면 아래에 붙어 버튼 둘이 오른쪽에 나란히 선다. 그리고 "미리보기"를 누른 뒤의 화면: 미리보기가 화면 전체를 덮고(제목 줄의 "미리보기"와 닫기 아이콘 버튼 x, 보는 상태 셀렉트와 밝기 단추, 그 아래 위젯 창이 폭을 채운다) 아트보드 둘을 나란히 둔다(제안).
9. 사이트 하나, 1280 다크: 1의 화면을 다크 모드로(문서 뿌리에 data-mode="dark"). 미리보기 안의 위젯은 자기 밝기 단추를 따라 "밝게" 그대로다.
10. 위젯 테스트 페이지의 들어오는 문, 375: 고른 안의 좁은 폭(앞 차례 아트보드의 375 칸을 완성 화면으로 다듬는다).
11. 들어오는 문의 상태, 칸 셋을 나란히(1280의 가운데 칸만): (가) 회사 로그인을 설정하지 않은 배포: 로그인 서버 항목이 하나도 없어 운영자 계정 문만 선다. (나) 로그인 시간이 끝남: 문 위에 정보 알림 "로그인이 끝났다" / "다시 로그인하면 이어서 쓸 수 있다." (다) Agent OS 서버가 답하지 않음: 운영자 문 자리에 경고 알림 "운영자 로그인을 확인하지 못했다" / "위젯 테스트 페이지는 운영자 로그인을 Agent OS 서버에 물어 확인하는데 그 서버가 답하지 않는다." 회사 계정 문은 그대로 쓸 수 있다.
12. 운영자로 들어온 뒤, 1280: 위젯 테스트 페이지의 사이트 화면은 pilot-portal이 확정한 그대로다(위쪽 띠의 사이트 셀렉트, 가운데 위젯 자리 폭 400px·높이 560px, 위젯 아래 짧은 고지 한 줄과 보고서 링크). 바뀌는 것은 띠의 오른쪽 끝에 흐린 글자로 "운영자 ops-lead"(계정 이름 고정폭)가 서는 것뿐이다(제안). 셀렉트에는 위젯 테스트 페이지에 담은 사이트 넷 가운데 열리지 않는 partner-trial을 뺀 셋(help-center, demo, intranet)이 든다. 고른 사이트는 help-center이고, 위젯에는 저장한 설정(군청 테마, 소개 "주문, 배송, 환불을 물어보세요. 밤에도 답합니다.")이 그려진다.

키보드와 화면 읽기 프로그램을 그림 옆 메모로 적는다. 사이트 하나 화면의 포커스 순서(돌아가기 링크, 머리의 동작, 탭 줄, 고른 탭의 칸들, 미리보기의 보는 상태와 밝기 단추, 저장 띠의 버튼), 탭 줄은 고른 탭 하나로만 들어가고 좌우 화살표 키로 탭을 옮긴다는 것(제안), 작은 그림 고르기는 라디오 묶음이라 화살표 키로 고르고 묶음 이름이 칸의 라벨이라는 것, 미리보기 안의 위젯은 보기만 하는 그림이라 포커스를 받지 않고 화면 읽기 프로그램에는 "미리보기, 저장하지 않은 값으로 그린 위젯" 한 줄로 읽힌다는 것(제안), 저장 띠가 나타날 때 포커스를 옮기지 않는다는 것, 확인 창이 열리면 포커스가 창의 보조 버튼에 가고 Esc로 닫힌다는 것.

탐색용 가정(결정이 아니니 바꿔도 된다): 저장한 뒤의 흐린 한 줄, 형식 오류를 칸을 떠날 때 보이는 것, 떠날 때의 확인 창, 사이트 이름의 글자 규칙, 사이트 지우기와 그 확인 창의 문구, 375의 미리보기 덮개, 운영자로 들어온 뒤 띠의 계정 표시, 탭 이름 뒤의 오류 표시, 375에서 넘치는 탭을 옆으로 밀어 보는 것은 이 프롬프트의 제안이고 명세가 정한다. 사이트를 지우는 일과 지운 사이트 이름을 적은 위젯의 동작은 ADR이 정하지 않았다(위젯 관리 서버가 등록되지 않은 사이트의 이름에 무엇을 답하는지는 widget-admin-server의 명세가 정한다, ADR 0064 결정 "위젯 설정을 받아 가는 주소"). 다른 운영자가 그사이 같은 사이트를 저장한 경우는 그리지 않는다. 다크에서 미리보기의 위젯이 자기 밝기 단추를 따르는 것도 제안이다.
```
