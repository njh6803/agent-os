# portal-admin 화면

위젯 관리 화면(사이트 목록, 사이트 하나의 위젯 설정과 위젯 테스트 페이지 설정을 고치는 화면과 양식 옆의 미리보기, "테스트" 메뉴, 로그인이 필요한 화면)과 위젯 테스트 페이지의 들어오는 문을 그린 완성 화면이다. `/ui-design portal-admin`이 Design 아티팩트에 그리고 사람이 확정한 것을 그 스킬의 7단계가 옮겼다(일지 2026-11-16-0025). 규약은 `docs/agents/issue-tracker.md`의 화면 디자인 절이고, 그린 순서와 화면은 시작 프롬프트 `screens-prompt.md`다. 그리며 `frontend-design`과 저장소 규칙이 부딪친 자리는 `.scratch/design-system/design/frontend-design-conflicts.md`의 2026-11-16 행이다.

아티팩트에는 쪽이 둘이다. "1. 고를 갈래와 정해진 화면"(정해진 화면 여섯, 갈래 1인 사이트 하나 화면의 양식 짜임 네 안, 갈래 2인 들어오는 문 세 안)과 "2. 고른 사이트 화면과 들어오는 문의 완성 화면"(완성 화면 열두 장)이다. 여기 옮긴 것은 정해진 화면 여섯, 고른 안 둘(`ch-form-4.dc.html`, `ch-door-1.dc.html`), 둘째 쪽 열두 장, 캔버스 색인 `canvas.json`이다. 고르지 않은 안 다섯은 아티팩트에만 남겼다. 갈래 1의 안 1(`ch-form-1.dc.html`, 한 페이지에 목차 없음), 안 2(`ch-form-2.dc.html`, 한 페이지에 왼쪽 목차), 안 3(`ch-form-3.dc.html`, 묶음 제목을 왼쪽에 둔 두 열)과 갈래 2의 안 2(`ch-door-2.dc.html`, 나란한 카드 둘), 안 3(`ch-door-3.dc.html`, 회사 로그인을 주로)이다. 그래서 `canvas.json`의 `boards`와 `order`는 여기 없는 그 다섯 파일도 가리키고, 그 안들을 다시 보려면 아티팩트를 연다. 고름과 확정은 캔버스 메모(`fixed-decided`, `form-decided`, `door-decided`, `mk-decided`)와 일지에 함께 적었다. 화면 파일은 디자인 시스템을 `ds/agent-os/` 아래에서 불러오고 그 폴더는 옮기지 않았다(스킬 7단계가 `project/ds/`를 뺀다). 저장소에서 브라우저로 그려지는지는 보지 않았다. 그리는 쪽에서도 렌더하거나 찍어 보지 않았고, 아트보드 높이는 어림이다.

사람이 고르고 확정한 것은 셋이다(일지 "ui-design 6: 고르기(첫 차례)"와 "ui-design 6: 고르기(둘째 차례)").

- 갈래 1에서 추천(안 1, 목차 없음) 대신 안 4(탭과 저장 단추 하나)를 골랐다. 탭 일곱(기본, 글, 모양, 로그인과 로그아웃, 고지, 창으로 열 때, 위젯 테스트 페이지) 가운데 고른 탭의 칸만 보이고, 바뀐 칸이 든 탭 이름 뒤에 흐린 수가 서며, 저장 띠는 탭과 상관없이 화면에 하나다. 둘째 쪽의 사이트 하나 화면은 모두 이 짜임으로 그렸다. 옮긴 사이트 하나 화면은 "로그인과 로그아웃" 탭을 연 그림이고, 열리지 않는 사이트(`mk-site-broken.dc.html`)만 "위젯 테스트 페이지" 탭을, 사이트 등록(`mk-site-new.dc.html`)만 "기본" 탭을 열었다. 그래서 나머지 탭의 칸 가운데 예시 질문, 문의 링크, 고지 전문을 보이는 법은 옮긴 파일에 없고, 아티팩트에만 남긴 `ch-form-1.dc.html`~`ch-form-3.dc.html`에 그렸다.
- 갈래 2에서 추천대로 안 1(한 칸에 두 문을 위아래로)을 골랐다. 둘째 쪽의 들어오는 문은 이 안으로 그렸다.
- 정해진 화면 여섯과 둘째 쪽 열두 장은 고치지 않고 확정했다.

그림이 시작 프롬프트나 ADR과 다른 자리는 아래와 같다. 시작 프롬프트 "고른 뒤" 2가 명세 전에 사람에게 묻게 한 종류(없는 데이터, 금지한 말, 새 아이콘)다.

- 운영자로 들어온 뒤의 화면(`mk-tester.dc.html`)은 시작 프롬프트와 두 군데가 다르다. ADR 0061 결정 "위젯 미리보기 페이지"가 "띠의 다크 모드 스위치, 고지 확인 덮개와 짧은 고지 줄, 로그인 단추 줄은 그리지 않고 위젯이 그린다"고 정해서, 위젯 아래에는 보고서 링크만 두고 짧은 고지 줄은 위젯 안에 그렸으며 띠에 다크 모드 스위치가 없다. 시작 프롬프트는 pilot-portal이 확정한 그대로(위젯 아래 짧은 고지 한 줄과 보고서 링크)라고 적었다. 사람은 둘째 차례의 확정 질문에서 이 차이를 듣고 확정했다.
- 들어오는 문(`ch-door-1.dc.html`, `mk-door-m.dc.html`)에는 위젯이 없어 띠의 다크 모드 스위치를 남겼다. 운영자로 들어온 뒤의 띠와 다르니 명세가 정한다. 들어오는 문의 상태 셋(`mk-door-states.dc.html`)은 띠 없이 문의 칸만 그렸다.
- 디자인 시스템의 아이콘 이름 열일곱 밖의 아이콘 셋을 같은 크기와 선의 Lucide 모양 SVG로 직접 그렸다. external-link(새 탭으로 연다. 탐색의 "테스트", "관리 화면에서 로그인", "관리 화면 열기", "위젯 테스트 페이지에서 열기", 운영자로 들어온 뒤의 보고서 링크 "이 에이전트의 평가 보고서"), chevrons-up-down(옆 탐색 맨 아래의 계정 자리와 375px 위 막대의 계정 버튼), chevron-down(운영자로 들어온 뒤의 사이트 셀렉트. pilot-portal의 확정 화면 `.scratch/pilot-portal/design/pp-page.dc.html`에 있던 모양을 옮겼다)이다.
- 시작 프롬프트에 없던 작은 더함과 뺌이 셋이다. 들어오는 문의 상태 (다)(`mk-door-states.dc.html`)에 보조 버튼 "다시 확인"을 두었다. 경고 알림만 두면 다시 물을 길이 없기 때문이다. 375px 사이트 하나(`mk-site-m.dc.html`)의 저장 띠는 "바뀐 칸 3개"만 두고 흐린 문장 "저장하면 다음에 위젯을 여는 사람부터 바뀐다."를 뺐다. 사이트 등록(`mk-site-new.dc.html`)의 미리보기는 위젯의 이름(`heading`)이 비면 에이전트 값인데(`web/apps/widget/EMBED.md`의 속성 표) 에이전트도 비어 있어, 위젯 머리에 칸 이름 "위젯의 이름"을 흐리게 두었다. 둘째 차례의 확정 질문은 앞의 둘을 들었고, 셋째는 캔버스 메모 `mk-assume`에 제안으로만 적었다.

이 화면을 그린 뒤에 병합된 widget-login-state의 둘째 화면 작업(PR 583, `.scratch/widget-login-state/design/README.md`의 "위젯 설정이 더한 화면")과 다른 자리도 있다. 이 화면은 그 작업을 기다리지 않고 그렸다(시작 프롬프트 첫 차례의 탐색용 가정). 명세가 그 작업의 확정에 맞추거나 사람에게 다시 묻는다.

- 예시 질문의 모양. 그 작업은 세 모양(첫 화면 안내 아래 세로 목록, 감기는 알약, 입력창 위 띠)을 모두 위젯 설정에서 고르는 값으로 두고 기본을 세로 목록으로 정했다. 이 화면의 양식에는 그 고르는 칸이 없고, 미리보기와 운영자로 들어온 뒤의 위젯(`mk-tester.dc.html`)은 예시 질문을 첫 화면 안내 아래에 가운데 정렬로 줄을 바꿔 감기는 보조 버튼 줄로 그렸다. 그 칸을 0.1 판에 넣을지는 이 기능의 명세 전에 사람에게 묻는다(`.scratch/portal-admin/plan.md`).
- 로그인 모드 사이트의 로그인 전. 그 작업은 이때 예시 질문을 보이지 않는다고 제안했다(입력창이 막혀 누를 수 없는 단추가 되기 때문이다). 이 화면의 미리보기 "로그인 전"(`ch-form-4.dc.html`, `mk-site-m.dc.html`)은 예시 질문 셋을 보인다.
- 문의 링크. 그 작업은 문의 링크를 입력창 아래 줄의 오른쪽 끝에 보이는 글 "문의하기"로 고정해 그렸고, 운영자가 그 글을 바꿀 수 있게 할지와 그 주소를 로그인 주소처럼 검사할지를 명세에 넘겼다. 시작 프롬프트의 탐색용 가정은 링크 글과 주소 두 칸이고, 그 칸은 옮긴 파일에 없고 아티팩트에만 남긴 `ch-form-1.dc.html`~`ch-form-3.dc.html`에 그렸다. 미리보기에는 문의 링크를 그리지 않았다.

아래는 그리며 둔 탐색용 가정과 제안이다. 결정이 아니고 명세가 결정으로 바꾸거나 다시 묻는다(시작 프롬프트 "고른 뒤" 2). 같은 말이 캔버스 메모 `fixed-how`, `form-how`, `door-how`(첫 쪽), `mk-how`, `mk-assume`, `mk-door-how`(둘째 쪽)와 시작 프롬프트(차례마다 끝의 "탐색용 가정", 그리고 "(제안)"을 단 문장)에 나뉘어 적혀 있다.

- 사이트 다섯(help-center, partner-trial, demo, intranet, shop), 계정 이름(ops-lead, kim.dev), 시각, 주소(agent.example.com, help.example.com, partner.example)는 그리기 위한 값이다. 사이트 화면의 주소는 `/sites/help-center`, 사이트 등록은 `/sites/new`로 보았다.
- 묶음 일곱과 칸의 차례, 도움말과 오류 문구, 예시 질문의 개수 상한(넷), 문의 링크를 글과 주소 두 칸으로 받는 것, 묶음 이름 "창으로 열 때"는 시작 프롬프트가 정한 제안이다.
- 저장한 뒤의 흐린 한 줄, 형식 오류를 칸을 떠날 때 보이는 것, 탭 이름 뒤의 오류 표시와 첫 오류 탭으로 옮겨 가는 것, 떠날 때의 확인 창, 사이트 이름의 글자 규칙, 사이트 지우기와 그 확인 창의 문구, 375px의 미리보기 덮개, 375px에서 넘치는 탭을 옆으로 밀어 보는 것, 375px 머리의 "위젯 테스트 페이지에서 열기"를 더 보기 메뉴로 옮긴다고 본 것(그리지 않음), 운영자로 들어온 뒤 띠의 "운영자 ops-lead" 표시는 제안이다.
- 미리보기의 보는 상태 일곱과 밝기 단추, 다크에서 미리보기의 위젯이 자기 밝기 단추를 따르는 것은 제안이다. 미리보기의 대화와 이름(김하늘)은 보기 위한 견본이다. 첫 화면, 대화, 고지, 만료는 help-center가 위젯 테스트 페이지에서 "둘 다"인 것에 맞춰 둘 다인 사이트의 모양(상태 줄의 "로그인하고 질문하기")으로 그렸고, 보는 상태 "로그인 전"만 로그인 모드의 모양(입력창 자리를 단추로)이다. 위젯 설정에 로그인 모드를 둘지는 명세가 정한다.
- 예시 질문 단추와 문의 링크는 ADR 0064가 위젯에 더했지만 그릴 때는 위젯 화면 작업이 아직 그리지 않아, 미리보기 안에서는 첫 화면 안내 아래 보조 버튼 줄(예시 질문)로만 그리고 문의 링크는 그리지 않았다. 그 뒤 병합된 그 작업과 다른 자리는 위 목록에 있다.
- 고지 전문의 처음 값은 `web/apps/portal/server/notice.ts`의 첫 문단에서 "이 페이지"를 "이 위젯"으로 바꾼 문장, `cookie-policy.ts`의 30일을 적은 쿠키 문장, ADR 0059가 넣기로 정한 뜻을 시작 프롬프트가 글로 지은 계정 기록의 문장이다.
- 회사 계정 문은 로그인 서버 항목이 하나일 때의 그림이다. 여럿일 때 무엇을 둘지와 단추 글에 항목 이름을 넣을지는 명세가 정한다(ADR 0065 결정 "위젯 테스트 페이지").
- 다른 운영자가 그사이 같은 사이트를 저장한 경우는 그리지 않았다. 사이트를 지우는 일과 지운 사이트 이름을 적은 위젯의 동작은 ADR이 정하지 않았다.
- 키보드와 화면 읽기 프로그램의 동작(포커스 순서, 탭 줄의 화살표 키, 미리보기 안의 위젯이 포커스를 받지 않는 것, 확인 창의 첫 포커스와 Esc)은 캔버스 메모 `mk-how`에 적은 제안이다.
- 탭 줄, 계정 메뉴와 더 보기 메뉴, 확인 창, 셀렉트와 라디오와 체크박스, 작은 그림 고르기는 디자인 시스템에 없는 부품이라 브라우저 기본 요소에 쓰임새 토큰을 칠했다. 새 탭으로 여는 버튼 모양의 링크는 디자인 시스템의 Button이 글자 뒤 아이콘을 받지 않아, a 요소에 버튼과 같은 쓰임새 토큰을 칠했다.

기준 커밋은 그릴 때 읽은 근거 문서의 커밋이다. 이 브랜치는 `d80690da`(PR 580의 병합)에서 땄고, 이어받은 세션이 `origin/dev`를 `6cc67844`(PR 578의 병합)까지 합친 작업 트리에서 근거 문서를 읽고 이 화면을 그렸다(일지 "tidy-checkouts"와 "이어받기 (새 세션)"). 옮긴 뒤 커밋 전에 `59536371`까지 다시 합쳤고, 그사이 든 PR 583이 위의 다른 자리 셋을 낳았다. 그런데 ADR 0065와 ADR 0064 이력 2026-11-16, 그리고 근거 문서 칸의 `.scratch/portal-admin/plan.md` 고침과 `screens-prompt.md`는 그 커밋에 없고 화면과 같은 PR에 든다. 그래서 칸에 "(어림)"을 붙였다. 동기화한 커밋은 디자인 시스템 아티팩트 색인 `lastChange`의 `via`다. 그리기 직전의 올리기가 두 번 모두 보낼 것이 없어 그대로였다(일지 2026-11-16-0025 "ui-design 1·2"와 "ui-design 2(이어받은 세션)"). 둘째 쪽에서 옮긴 사이트 하나 화면의 줄은 모두 고른 안 4로, 들어오는 문의 줄은 모두 고른 안 1로 그린 것이다.
