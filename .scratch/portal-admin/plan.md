# portal-admin: 운영자가 위젯 관리 화면에 Agent OS의 운영자 계정으로 들어와 사이트마다의 위젯 설정과 위젯 미리보기 페이지 설정을 등록해, 파일을 열지 않고 위젯이 보일 것을 바꾼다.
**슬라이스:** 9
**Blocked by:** widget-admin-server, admin-login, widget-login-state
**설계:** ADR 0064

위젯 관리 화면. 운영자가 사이트마다의 위젯 설정과 위젯 미리보기 페이지 설정(둘 다 `CONTEXT.md`)을 등록하는 위젯 쪽의 화면이고, `CONTEXT.md`의 관리 화면(Agent OS의 웹 앱)과 다른 앱이라 "관리 화면"으로 줄여 쓰지 않는다. 행의 이름은 세울 때의 것이다. 이 행은 사용자가 pilot-portal 설계 인터뷰에서 다시 꺼낸 요구(사이트마다 위젯을 설정하는 관리 화면이 있어야 한다, 일지 2026-11-09-1410의 "사용자가 앞서 말한 요구를 다시 꺼냄")에서, pilot-portal이 "설정은 파일로, 미리보기까지 지금"으로 범위를 자르며 선 것이다(ADR 0050 Consequences "다른 행"). 그때는 위젯 미리보기 페이지 설정 파일을 고치는 화면이었고 제품 1.0 묶음(슬라이스 10)이었다. 2026-11-14의 설계 인터뷰(일지 2026-11-13-1813)가 이 행을 고쳐 세웠다. 사용자가 로그인 주소와 고지의 글 같은 달라지지 않는 값을 "위젯 관리자 페이지에서 위젯 설정으로 등록"하자고 했고, 그 값을 드는 자리를 묻는 질문에 "위젯 서버의 데이터베이스"라고 답했으며, 짓는 때를 묻는 질문에 "0.1 판에 넣기"를 골랐다. 그래서 이 행은 0.1 판의 행이 됐고(ADR 0046 이력 2026-11-14) pilot-release가 이 행을 기다린다. 2026-11-15의 설계 인터뷰(일지 2026-11-15-1312)가 그 일을 행 다섯으로 나눴다. 사용자가 "저장과 읽기를 먼저 떼어 넷으로"를 골랐고 0.1 판 뒤의 행 하나가 더 있다. 위젯 관리 서버의 뼈대와 데이터베이스와 위젯이 위젯 설정을 받아 가는 주소는 widget-admin-server가, 위젯이 사이트 파일의 두 값을 뜰 때 받는 일은 widget-runtime-values가, 회사 로그인 서버 항목을 화면에서 고치는 일은 portal-login-admin이, 허용 출처와 요청 글자 수 상한을 화면에서 고치는 일은 site-limits-admin(0.1 판 뒤)이 맡고, 이 행에는 화면이 남았다. widget-login-state는 이 행이 아니라 widget-admin-server를 기다리게 바뀌었다.

정한 것은 ADR 0064가 원천이고 여기에 다시 적지 않는다. 그 ADR이 정한 갈래의 이름만 든다: 위젯 관리 서버, 데이터베이스, 위젯 관리 화면, 주소, 로그인, 고칠 수 있는 계정, 주소의 검사, 0.1 판에서 등록하는 것, 밝기 스위치 숨기기, 위젯 미리보기 페이지 설정, 시작 검사가 가는 자리, "테스트" 메뉴와 공개 주소, 값을 옮기는 길은 짓지 않는다, 고지의 고정 문장, 바꾼 기록, 위젯 설정을 받아 가는 주소, 허용 출처와 요청 글자 수 상한, 배포에 느는 것, 회사 로그인 서버 항목, 이름, 기능 행. 이 행이 맡는 것은 아래다.

- 위젯 관리 화면. `web/` 워크스페이스의 새 Next 앱이고 관리 화면과 같은 이름(호스트)의 다른 포트에 선다. 사이트의 목록, 사이트 하나의 위젯 설정과 위젯 미리보기 페이지 설정을 고치는 화면, 위젯 미리보기 페이지로 가는 "테스트" 메뉴, 로그인하지 않았거나 로그인 시간이 끝났을 때의 화면을 짓는다.
- 로그인 확인. 위젯 관리 서버가 브라우저가 보낸 운영자의 로그인 쿠키를 Agent OS 서버의 "지금 누구인지"와 "갱신" 경로에 그대로 전한다. 부르는 경로는 그 둘뿐이고 쿠키를 저장하거나 기록하지 않는다.
- 저장 경로. 위젯 관리 화면의 포트에만 서고, 다른 사이트에서 온 요청을 거절하며, 로그인 주소와 로그아웃 주소의 형식을 검사한다. 사이트의 이름이나 발급자가 다른 사이트와 겹치면 저장을 거절한다(ADR 0064 결정 "시작 검사가 가는 자리"의 첫째). 저장할 때마다 바꾼 기록을 한 줄 남긴다.
- 위젯 미리보기 페이지 설정을 데이터베이스로. 그 페이지가 담는 사이트의 목록, 사이트마다의 발급자와 보증 모드와 보고서 링크를 위젯 관리 서버가 들고, 위젯 미리보기 페이지의 서버(Node)는 그 값을 위젯 관리 서버에서 받아 온다. 받아 올 때 사이트 파일과 자기 키로 볼 수 있는 것(발급자, 공개 출처, 키의 짝, 로그인 서버 항목)을 사이트마다 보고, 어긋난 사이트만 닫는다(같은 결정의 둘째). 그 페이지의 설정 파일에는 시작에 필요한 값만 남고, 뜰 때는 그 값만 본다(같은 결정의 셋째).
- 고지 전문의 처음 값. 위젯 미리보기 페이지가 담는 사이트를 처음 등록할 때, 화면이 고지 전문에 익명 식별자를 둔다는 문장과 질문이 로그인한 계정과 함께 기록된다는 문장을 처음 값으로 넣어 둔다.

세 행을 기다리는 까닭은 이렇다. widget-admin-server는 서버의 뼈대와 데이터베이스와 위젯 설정의 표를 세운다. admin-login은 운영자 계정과 "지금 누구인지"·"갱신" 경로를 들인다(ADR 0062). widget-login-state는 위젯이 위젯 설정으로 그리게 하고, 위젯 미리보기 페이지 설정 파일에서 에이전트와 모양과 고지 칸을 뺀다. 그 칸이 파일에 남아 있으면 임베드 속성이 위젯 설정보다 앞서 화면에서 고친 값이 그 페이지의 위젯에 닿지 않는다(ADR 0064 결정 "위젯 미리보기 페이지 설정").

이 행은 위젯 관리 서버의 계약 파일에 저장 경로를 더한다. 그 계약을 고치는 티켓이 이 행의 첫 티켓이고 다른 티켓을 막는다. Agent OS의 계약(`sdk`, `openapi.json`, 사이트 파일의 형식, 사이트 토큰의 주장)은 바꾸지 않는다. 단독 compose와 배포 파일 묶음에는 위젯 관리 화면의 컨테이너와 그 포트를 더한다(위젯 관리 서버와 위젯 쪽 PostgreSQL의 컨테이너는 widget-admin-server가 더한다). 명세 전에 `/ui-design portal-admin`으로 화면을 그려 사용자에게 확인받는다.

명세가 먼저 확인하는 것은 ADR 0064 Consequences "재지 않은 것"에 있다. 운영자의 로그인 쿠키가 다른 포트의 화면에 실려 오고 위젯 관리 서버가 그것을 두 경로에 전해 로그인을 이어 주는 흐름(갱신 때 Agent OS가 내는 새 쿠키를 브라우저에 되돌려 주는 것까지), 그리고 위젯 미리보기 페이지의 서버가 요청 때 위젯 관리 서버에 물어도 응답이 느려지지 않는지다. 확인해서 어긋나면 그 ADR의 그 대목을 이력으로 다시 본다. 명세가 짓는 것은 같은 ADR Consequences "명세가 짓는 것"에 있다. 그 가운데 하나는 순서에 달려 있다. portal-login이 이 행보다 먼저 끝났으면 위젯 미리보기 페이지 설정의 사이트는 자기가 쓰는 로그인 서버 항목의 이름을 가리키고 있으므로(ADR 0059 결정 "로그인 서버 항목"), 사이트의 목록을 데이터베이스로 옮길 때 그 이름을 어디에 두는지를 명세가 정한다. 로그인 서버 항목 자체는 portal-login-admin이 끝날 때까지 파일에 남는다. 순서에 달린 것이 하나 더 있다. 위젯 미리보기 페이지가 담는 사이트의 로그인 주소와 로그아웃 주소는 그 페이지의 끝점이라(ADR 0059), 운영자가 위젯 설정에 그 주소를 손으로 등록하는지 위젯 관리 화면이 처음 값으로 채워 주는지를 portal-login과 이 행 가운데 뒤에 끝나는 행의 명세가 정한다. 이 행이 고쳐 서기 전의 계획이 설계 인터뷰에 넘긴 물음이고 인터뷰에서 다루지 않았다. PR 직전 리뷰가 낸 빈 자리 넷도 그 목록에 있다. 로그인 주소와 로그아웃 주소의 사용자 정보 자리(`user:pw@`)와 쿼리에 든 값을 받을지, `http://localhost` 예외를 호스트 이름 전체로 견주는 시험, 쿠키를 되돌릴 때 속성을 바꾸지 않는지의 확인, 운영자가 고지의 글을 고친 뒤 이미 확인한 브라우저에 다시 확인을 받을지다.

이 행이 넘겨받았던 넷은 이렇게 갈렸다(ADR 0061 Consequences "다른 행"이 0.1 판에 넣을지를 이 행의 설계 인터뷰에 맡겼다).

- 위젯 미리보기 페이지 설정을 화면에서 고치는 일. 사용자가 "모두 0.1 판에"를 골랐다. 사이트의 목록과 보증 모드와 보고서 링크는 이 행이, 로그인 서버 항목은 portal-login-admin이 맡는다.
- 사이트 파일의 허용 출처와 요청 글자 수 상한을 화면에서 바꾸는 일(release-image의 설계 인터뷰에서 사용자가 더한 요구, 일지 2026-11-11-1532 "위젯 질문에 사용자가 되물었다"). 사용자가 "위젯이 실행 중에 받게만"을 골랐다. 위젯이 두 값을 뜰 때 받는 일은 widget-runtime-values가 0.1 판에, 화면에서 고치는 일은 site-limits-admin이 0.1 판 뒤에 설계부터 한다.
- 로그인 방식을 화면에서 고르는 일(portal-login의 설계가 넘겼다, 일지 2026-11-12-1937 라운드 2). portal-login-admin이 맡고 설계 인터뷰를 따로 한다. 클라이언트 비밀 같은 비밀 값을 화면이 받을지는 그 인터뷰가 정한다.
- release-image 명세가 넘긴 것(2026-11-13, `.scratch/release-image/spec.md`의 Out of Scope. 위젯 이미지가 뜰 때마다 하는 빌드를 없애며 함께 고칠 것). widget-runtime-values가 맡는다.

수락: 시험 환경에서 관리 화면에 로그인한 운영자가 다른 포트의 위젯 관리 화면을 열어 사이트 하나를 등록하고 위젯의 이름과 고지의 글을 저장하면, 아무것도 다시 띄우지 않고 위젯 미리보기 페이지의 그 사이트 위젯이 그 값으로 그려지며, 바꾼 기록에 계정 이름과 이전 값과 새 값이 남는다. 로그인하지 않은 브라우저의 저장 요청과 `javascript:`로 시작하는 로그인 주소의 저장은 거절된다
