# deploy-package: agent-os와 문서 검색 서버를 Docker Compose로 한 번에 띄우는 참조 배포를 준다.
**슬라이스:** 9
**Blocked by:** local-model, doc-qa-agent, release-image, ops-backup-upgrade, diag-bundle, rag-engine:release-image, rag-engine:backup-upgrade, rag-engine:diag-bundle

참조 배포. Docker Compose로 agent-os의 이미지(`serve`, 관리 화면, 위젯, pilot-portal)와 판을 고정한 문서 검색 서버 이미지(검색 서버와 관리자 페이지)를 doc-qa 플러그인과 함께 띄운다. 모델 서버는 배포 환경의 것을 가리키거나 선택 서비스로 둔다. 데이터베이스는 서비스마다 따로 띄우고, 각 서비스는 연결 문자열 하나만 받는다(ADR 0048). 배포 환경에 이미 PostgreSQL이 있으면 연결 문자열만 바꿔 그쪽에 붙인다. 밖으로 여는 포트는 TLS를 끝내는 리버스 프록시의 443 하나이고, 나머지 컨테이너는 내부 네트워크에서만 통신하며 호스트에 포트를 내놓지 않는다(ADR 0048). 프록시와 루프백 규칙을 잇는 방법은 release-image가 정한 바인딩을 따른다. 위젯처럼 정적 파일로 낼 수 있는 것은 프록시가 바로 내준다. 원격 MCP 서버(문서 검색 서버)의 수명은 배포가 관리하므로(PRD 전제) 재시작 정책과 상태 확인을 두고, `serve`와 문서 검색 서버 사이의 토큰은 환경 변수로 넣는다. 검색 도구를 허락하는 규칙 파일을 함께 낸다(ADR 0046). 운영자를 위해 켜기, 끄기, 상태 보기, 백업(ops-backup-upgrade와 문서 검색 서버의 백업), 진단(diag-bundle과 문서 검색 서버의 진단)을 묶은 관리 명령 하나를 두어, Docker를 모르는 운영자도 이 명령으로 켜고 끄고 상태를 본다. 폐쇄망 배포를 위해 이미지와 모델 파일을 파일로 옮기는 절차와 해시 확인을 함께 낸다. 트레이스는 지금 형식(JSONL) 그대로다. 배포 안내 문서 하나와 대상 사양(CPU, 메모리, GPU 유무, 디스크)을 함께 내고, GPU 등급은 클라우드 GPU에서 vLLM으로 잰 값을 근거로 한다(일지 2026-11-06-02의 "설계 인터뷰 입력" 절, GPU 환경의 권하는 조합 4). GPU 서버가 없는 배포 환경의 구성과, API를 쓰는 구성에서도 검색된 문서 조각이 밖으로 나간다는 사실은 일지 2026-11-06-02의 "설계 인터뷰 입력" 절(모델 배치 구성)대로 안내 문서에 적는다. 함께 배포하는 LLM, 임베딩, 리랭커 모델은 상용 이용과 재배포 조건을 확인해 안내 문서에 적는다. 안내 문서는 무거운 서버를 원격 MCP 서버(상주)로 두는 것을 기본으로 안내하고, stdio는 가벼운 도구와 바깥에서 받아 온 공개 서버에 쓴다고 적는다(ADR 0046). 관리 화면을 SSH 포워딩으로 열지, 사내망의 정해진 주소로만 열지는 설계 인터뷰가 정한다. 설계 인터뷰가 먼저 볼 것: 배포 환경의 반입 조건(컨테이너 런타임, 운영체제, 바깥 이미지의 반입)을 release-image와 함께 본다. 수락: 깨끗한 리눅스 VM에서 안내 문서만 보고 1시간 안에 배포해 질문하고 출처가 붙은 답을 받는 과정을 사람이 재서 프로브로 남기고, 그 VM에서 밖으로 열린 포트가 배포가 여는 443과 VM을 관리하는 SSH뿐임을 확인한다. 열린 포트는 들어오는 연결만 보므로, 바깥으로 나가는 연결을 막은 VM에서 같은 과정을 한 번 더 돌려 답에 쓰인 모델이 배포 환경 안의 모델임을 확인한다
