# deploy-package: agent-os와 문서 검색 서버를 Docker Compose로 한 번에 띄우는 참조 배포를 준다.
**슬라이스:** 9
**Blocked by:** local-model, portal-login, base-agent, release-image, ops-backup-upgrade, diag-bundle, mcp-http, rag-engine:release-image, rag-engine:admin, rag-engine:backup-upgrade, rag-engine:diag-bundle

참조 배포. public-demo의 배치(리버스 프록시 하나, 내부 네트워크, 밖에 내놓지 않는 관리 경로)를 출발점으로 삼는다. 질문 페이지는 사내 로그인 모드(portal-login)로 띄운다. Docker Compose로 agent-os의 이미지(`serve`, 관리 화면, 위젯, pilot-portal)와 판을 고정한 문서 검색 서버 이미지(검색 서버와 관리자 페이지)를 기본 에이전트의 플러그인(에이전트 `assistant`, 스킬 `cite-sources`, 연결 `doc-search`. ADR 0051)과 함께 띄운다. 특별한 요구가 없는 배포는 기본 에이전트를 그대로 쓰므로, 참조 배포의 예시 설정(사이트 파일의 열 에이전트, 질문 페이지 설정의 에이전트)은 `assistant`를 가리킨다. 요구가 있는 배포는 그 폴더를 복사해 커스텀 에이전트를 만들고(base-agent가 내는 안내 문서), 예시 설정이 그 이름을 가리키게 고친다. 모델 서버는 배포 환경의 것을 가리키거나 선택 서비스로 둔다. 데이터베이스는 서비스마다 따로 띄우고, 각 서비스는 연결 문자열 하나만 받는다(ADR 0048). 배포 환경에 이미 PostgreSQL이 있으면 연결 문자열만 바꿔 그쪽에 붙인다. 밖으로 여는 포트는 TLS를 끝내는 리버스 프록시의 443 하나이고, 나머지 컨테이너는 내부 네트워크에서만 통신하며 호스트에 포트를 내놓지 않는다(ADR 0048). 프록시와 루프백 규칙을 잇는 방법은 release-image가 정한 바인딩을 따른다. 위젯처럼 정적 파일로 낼 수 있는 것은 프록시가 바로 내준다. 원격 MCP 서버(문서 검색 서버)의 수명은 배포가 관리하므로(PRD 전제) 재시작 정책과 상태 확인을 두고, `serve`와 문서 검색 서버 사이의 토큰은 환경 변수로 넣는다. 기본 에이전트의 규칙 파일(검색은 허락, 문서 전문 읽기는 묻는다, 지식베이스 목록은 막는다)을 함께 낸다(ADR 0046, ADR 0051 "도구 셋의 규칙"). 운영자를 위해 켜기, 끄기, 상태 보기, 백업(ops-backup-upgrade와 문서 검색 서버의 백업), 진단(diag-bundle과 문서 검색 서버의 진단)을 묶은 관리 명령 하나를 두어, Docker를 모르는 운영자도 이 명령으로 켜고 끄고 상태를 본다. 폐쇄망 배포를 위해 이미지와 모델 파일을 파일로 옮기는 절차와 해시 확인을 함께 낸다. 트레이스는 지금 형식(JSONL) 그대로다. 배포 안내 문서 하나와 대상 사양(CPU, 메모리, GPU 유무, 디스크)을 함께 내고, GPU 등급은 클라우드 GPU에서 vLLM으로 잰 값을 근거로 한다(일지 2026-11-06-02의 "설계 인터뷰 입력" 절, GPU 환경의 권하는 조합 4). GPU 서버가 없는 배포 환경의 구성과, API를 쓰는 구성에서도 검색된 문서 조각이 밖으로 나간다는 사실은 일지 2026-11-06-02의 "설계 인터뷰 입력" 절(모델 배치 구성)대로 안내 문서에 적는다. 공개 데모가 그 표의 셋째 구성(상용 클라우드 API)으로 먼저 섰다는 것은 일지 2026-11-07-2053의 같은 이름의 절에 있다. 함께 배포하는 LLM, 임베딩, 리랭커 모델은 상용 이용과 재배포 조건을 확인해 안내 문서에 적는다. 안내 문서는 무거운 서버를 원격 MCP 서버(상주)로 두는 것을 기본으로 안내하고, stdio는 가벼운 도구와 바깥에서 받아 온 공개 서버에 쓴다고 적는다(ADR 0046). 관리 화면을 SSH 포워딩으로 열지, 사내망의 정해진 주소로만 열지는 설계 인터뷰가 정한다. 설계 인터뷰가 먼저 볼 것: 배포 환경의 반입 조건(컨테이너 런타임, 운영체제, 바깥 이미지의 반입)을 release-image와 함께 본다. 대상 사양의 GPU 등급이 기댈 vLLM 측정을 이 행에서 할지, pilot-release의 평가 보고서(local-model의 오픈 모델로 다시 돌린 answer-eval)로 뒤에 확인할지 정한다. 수락: 깨끗한 리눅스 VM에서 안내 문서만 보고 1시간 안에 배포해 질문하고 출처가 붙은 답을 받는 과정을 사람이 재서 프로브로 남기고, 그 VM에서 밖으로 열린 포트가 배포가 여는 443과 VM을 관리하는 SSH뿐임을 확인한다. 열린 포트는 들어오는 연결만 보므로, 바깥으로 나가는 연결을 막은 VM에서 같은 과정을 한 번 더 돌려 답에 쓰인 모델이 배포 환경 안의 모델임을 확인한다. ADR 0049(mcp-http)가 배포 안내에 넘긴 것: http 주소에서는 헤더 값(토큰)이 평문으로 가므로 http 주소는 신뢰하는 내부 네트워크(compose 서비스 이름 주소)에서만 쓰고 인터넷을 지나는 주소는 https로 적는다. 프록시 뒤에서는 내부 주소를 `NO_PROXY`에 적는다. 빠뜨리면 내부 서버 요청이 프록시로 가 접속 실패로 보이고 헤더 값(토큰)이 그 프록시에 남는다(ADR 0049 Consequences "배포가 알아야 할 것 넷"). mcp-http 명세(2026-11-09, `.scratch/mcp-http/spec.md`의 "로그"와 Out of Scope)가 배포 안내에 넘긴 것: mcp와 httpx2의 로거는 원격 MCP 서버의 주소를 쿼리 문자열까지 통째로 찍는다(`mcp.client.streamable_http`가 DEBUG로 접속 주소를, `httpx2`가 INFO로 요청마다 주소를. 기본 WARNING에서는 나오지 않는다. 프로브 `.scratch/mcp-http/probes/README.md`). 원격 MCP 서버 주소의 쿼리 문자열에 비밀을 두지 않도록 안내한다. 접속 실패 문구는 주소를 쿼리 문자열까지 그대로 실어 트레이스에 남고(ADR 0049 결정 "주소", 명세 "실패 문구"), 로그 수준을 INFO나 DEBUG로 낮추면 위 로거에도 찍힌다. 런타임은 매니페스트 단계에서 그것을 막지 않는다(ADR 0049의 알려진 한계). base-agent 명세가 넘긴 것(2026-11-10, `.scratch/base-agent/spec.md`의 "연결 플러그인 `doc-search`"): 그 플러그인이 커밋한 주소는 `http://rag-engine:8000/mcp`이고(서비스 이름 `rag-engine`, 포트는 문서 검색 서버 `serve`의 `--port` 기본값 8000. 그 저장소의 `src/rag_engine/main.py`와 `README.md`에서 읽었다) `Authorization` 헤더의 값을 환경 변수 `DOC_SEARCH_AUTHORIZATION`에서 읽는다. 값은 `Bearer <토큰>` 전체이고 토큰의 역할은 MCP와 `/health`만 여는 `reader`면 된다. 참조 배포는 `serve`에 그 변수를 주고, 문서 검색 서버의 `RAG_ALLOWED_HOSTS`에 서비스 이름 `rag-engine`을 넣는다. 그 서버는 적힌 값마다 그대로와 `값:*`의 두 꼴로 등록하므로 포트가 붙은 Host `rag-engine:8000`이 맞고, 어긋나면 `/mcp`가 421을 낸다(rag-engine의 `.scratch/core/spec.md`와 `docs/adr/0014-tokens-in-database-and-required-allowed-hosts.md`를 2026-11-10에 읽었다. 그 저장소는 명세 단계라 서버가 그렇게 도는 것을 본 것은 아니다). 서비스 이름이나 포트를 달리 두면 배포의 플러그인 디렉터리에서 그 매니페스트의 주소를 고친다(ADR 0051). 변수가 없으면 `assistant`의 실행이 원인 `tool_connection`으로 끝난다. local-model의 설계가 넘긴 것(2026-11-11): 모델 서버에 붙는 구성의 모델 파일을 쓰는 법은 ADR 0057의 결정 "모델 파일"과 "키"를 따른다. 배포 안내는 ADR 0057 Consequences "배포가 알아야 할 것"의 여섯(서버 옵션, 평문, 프록시, 상한, 기다림, 주소의 쿼리)을 적는다. 모델 서버를 띄우는 옵션의 예시에는 로컬 모델 시험이 남기는 서버의 판과 옵션의 기록(ADR 0058 "언제 돌리고 무엇을 남기는가")을 쓸 수 있다
