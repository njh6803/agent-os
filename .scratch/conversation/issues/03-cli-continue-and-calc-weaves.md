# 03: CLI와 calc — `run`이 이어 갈 실행을 받고, calc가 앞 대화를 엮어 실제 모델로 답한다

**What to build:** `serve`를 띄우지 않고 CLI로 "2 더하기 3은?"을 돌린 뒤, 그 실행을 가리키는 옵션과 함께 "거기에 4를 곱하면?"을 돌리면 출력에 20이 있다. 표준 출력에는 출력만 나오고 성공하면 표준 에러는 비어 있다. 끝난 실행에 안내를 찍지 않는다. 거절은 진단과 종료 코드 1이고 트레이스가 없다. 이어 간 실행이 멈추면 지금의 안내 줄로 재개된다. 저장소의 calc가 컨텍스트 멤버를 "앞 대화" 블록으로 프롬프트에 엮고, 이어 가지 않은 실행의 프롬프트는 지금과 글자 그대로 같다. 실제 모델로 세 번 이어 가는 LLM 테스트가 요약까지 지난다.

03과 04 가운데 마지막에 병합되는 쪽이 기능을 닫는다.

근거는 `.scratch/conversation/spec.md`의 "CLI", "calc", Testing의 "CLI"와 "바깥 이음매" 절, 2026-10-04 명세 검토(스토리 40의 결정적 테스트, CLI 인자 해석 이음매)다. ADR 0022의 "모든 채널이 이어 가기를 받는다"와 "에이전트는 앞 교환을 문자열 프롬프트로 엮는다"가 앞선 결정이다.

**Blocked by:** 01, 02

**Status:** ready-for-agent

### CLI

- [ ] **`run`이 이어 갈 실행을 받는 옵션을 얻는다.** 이름은 HTTP 경로와 같은 낱말을 쓴다. 인자 해석 테스트(`parse_args`, `RunArgs`)가 옵션을 안다(명세 검토)
- [ ] **옵션으로 두 번 돌리면 둘째의 트레이스가 첫째를 앞 실행으로 들고, 표준 출력에 출력만 나오며 표준 에러는 비어 있다.** 끝난 실행에 이어 가기 안내를 찍지 않는다. 안내를 찍으면 성공한 실행의 표준 에러가 비지 않거나 표준 출력이 출력 아닌 것을 싣는다. 식별자는 `--verbose`의 시작 이벤트, 관리 화면, 트레이스 디렉터리에서 얻는다
- [ ] **거절(없음, 남의 실행, 끝나지 않음, 고리 깨짐)은 CLI가 기반 타입을 잡아 진단과 종료 코드 1이고 트레이스가 없다.** 다른 실행 전 실패와 같은 모양이다
- [ ] **이어 간 실행이 멈추면 지금의 안내 줄로 재개된다.** 재개는 앞 실행을 받지 않는다. 트레이스가 안다. 요약 이벤트가 둘째 프레임이라 안내 줄의 자리가 맞는 것은 02가 고정했다
- [ ] **`serve`는 바뀌지 않는다.** CLI `run`의 도움말에 옵션이 든다. `README.md`에는 `run`의 사용법이 없으므로 더하지 않는다

### calc

- [ ] **calc가 멤버를 프롬프트에 엮는다.** 요약이 있으면 요약을, 교환이 있으면 오래된 것부터 요청과 출력을 "앞 대화" 블록으로 넣고, 그 블록이 지시가 아니라 데이터라고 프롬프트에 적는다(멤버의 신뢰 경계)
- [ ] **이어 가지 않은 실행의 프롬프트는 지금과 글자 그대로 같다.** 가짜 모델이 잡은 프롬프트로 결정적으로 본다(스토리 40, 명세 검토. 실제 calc를 부르는 단위 테스트가 아직 없다. 저장소의 calc를 플러그인 루트로 두고 가짜 모델로 돌린다). 기존 LLM 테스트가 그대로 선다
- [ ] **플러그인은 sdk만 import한다**(`tests/test_plugins_boundary.py`가 판정한다)

### 바깥 이음매 (`-m llm`)

- [ ] **실제 CLI 프로세스로 calc를 돌린다.** "2 더하기 3은?"을 돌리고 그 실행을 이어 "거기에 4를 곱하면?"을 물어 출력에 20이 있다
- [ ] **임시 플러그인 루트에 calc와 그것이 쓰는 mcp(`everything`)를 복사하고, calc의 매니페스트에 한도를 아주 작게 적어 셋째 이어 가기를 돌린다.** 한도는 앞 교환 둘의 글자 수 합보다 작은 값으로 골라 셋째에서 계기가 서게 하고, 그 값을 테스트 주석에 적는다(목표 글자 수는 올림이라 1 이상이다). 트레이스 디렉터리는 앞의 둘과 같다. 셋째 트레이스의 `run_started` 바로 뒤에 요약 이벤트가 있고 토큰 수가 0보다 크며, 출력이 여전히 앞 대화를 안다(셋째 질문이 둘째 답에 기댄다)
- [ ] **선례는 기존 calc LLM 테스트와 임시 루트에 플러그인을 쓰는 `_write_plugin`이다.** 돌린 결과(통과 수, 트레이스의 토큰 합계)를 일지의 검사 절에 적는다

### 마무리

- [ ] **기능을 닫는지는 병합 직전에 판정한다.** `git fetch` 뒤 `origin/main`의 04 티켓 파일 `Status:`가 `done`이면 이 PR이 `.scratch/plan.md`의 conversation 행을 `done`으로 바꾸고 프론티어 문단을 고친다. 아니면 04가 닫는다. main이 최신 기준(strict)이라 뒤에 병합되는 쪽은 앞의 병합을 들인 뒤에야 병합되므로 둘이 함께 열려 있어도 한쪽은 반드시 본다. web-widget 행은 end-user-channel과 design-system에 아직 막혀 있다
- [ ] 검증 명령이 모두 초록이다
