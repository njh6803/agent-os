# conversation: 끝난 실행을 이어 가며 대화를 나눌 수 있고, 대화가 길어지면 런타임이 앞부분을 요약한다.
**슬라이스:** 4
**Blocked by:** http-channel, web-admin
**끝:** 2026-10-05

대화. 새 실행이 같은 주체의 끝난 실행을 가리켜 이어 가고, 고리의 실행마다 에이전트가 다를 수 있다. 에이전트는 자기 교환(요청과 출력)과 자기 대화 요약만 `AgentContext`의 읽기 전용 멤버로 받는다. 그 에이전트의 마지막 요약 뒤 교환의 글자 수가 한도(에이전트 매니페스트의 선택 필드, 없으면 기본값)를 넘으면 런타임이 그 실행의 모델과 고정 프롬프트로 요약해 새 실행의 트레이스에 남긴다. 트레이스 형식 3. 이어 가는 쪽의 주체는 core가 판정한다(ADR 0009 이력). CLI와 `/runs`가 이어 가기를 받고(`/runs`는 앞 실행을 경로에 든 새 경로이고 본문은 `POST /runs`와 같다), 최종 사용자 경로의 이어 가기는 web-widget이 더한다(2026-10-15 설계 인터뷰가 end-user-continuation으로 옮겼다). 관리 화면이 새 이벤트 종류를 그린다. 첫 티켓은 계약: sdk 멤버, `run_started`의 선택 필드, 요약 이벤트, 형식 3, `/runs`의 이어 가기 경로, 매니페스트의 선택 필드, core의 하위 타입 둘(다른 주체, 이어 갈 수 없음). 같은 티켓이 `.claude/rules/sdk.md`·`adapters.md`·`core.md`·`channel.md`·`http.md`를 고치고, 관리 화면의 결정 자리 조건(형식 2만 허락하던 것을 형식 1이 아닌 것으로), api-client의 채널 경로 목록, 생성 타입을 단 테스트 픽스처를 함께 고친다. 명세가 정한 것: 원문은 한도의 절반까지 남기고, 요약은 문장마다 출처를 밝히며, 기본 한도는 20,000자, 요약 실패는 다시 시도 없이 `run_failed`, 재개는 요약을 다시 판정하지 않고, 요약 이벤트는 런타임만 낸다. 긴 고리가 `serve`의 이벤트 루프를 막던 한계는 end-user-continuation 티켓 04가 묶었다(이어 가기의 거슬러 읽기는 스레드로 보내고, 루프 위에 남는 재개의 거슬러 읽기는 읽는 실행 수의 상한이 묶는다). 대화는 거슬러 읽는 범위의 트레이스가 남아 있어야 이어진다. 명세는 `.scratch/conversation/spec.md`, 측정은 `.scratch/conversation/probes/`(거슬러 읽기는 트레이스 하나에 0.3~1.3ms). 설계는 ADR 0022와 ADR 0008·0014 이력, 일지 2026-10-03-03. 티켓은 넷이다(`.scratch/conversation/issues/`, 2026-10-04). 01 계약 → 02 요약 → 03 CLI·calc(01·02 뒤), 04 관리 화면 링크(01 뒤, 02·03과 나란히). 03과 04 가운데 뒤에 병합된 04가 2026-10-05에 닫았다. PR #130의 리뷰가 낸 값 기반 마스킹(런타임이 아는 비밀 값을 `llm_called.text`·`prompt`·`tool_called.content`·요약 글 같은 자유 형식 글에서 걸러 내는 안)은 ADR 0009·0022의 이력 초안으로 따로 본다(사용자 결정 2026-10-04). 02보다 먼저 서면 02가 따른다
