# conversation 프로브

명세·ADR·코드 주석이 근거로 드는 측정 스크립트다. 규약은 `docs/agents/issue-tracker.md`의 "프로브와 근거".

둘 다 저장소 루트에서 돈다.

```sh
PYTHONUTF8=1 uv run python .scratch/conversation/probes/chain_walk.py
PYTHONUTF8=1 uv run --env-file .env python .scratch/conversation/probes/token_ratio.py
```

| 파일 | 재는 것 | 근거로 드는 자리 | 다시 돌 때 | 잰 판 |
|---|---|---|---|---|
| `chain_walk.py` | 대화의 고리를 끝에서 처음까지 거슬러 읽는 비용. 실제 `JsonlTrace`로 끝난 실행 N개(10, 100, 1000)의 트레이스를 임시 디렉터리에 쓰고, 포트의 `read`로 하나씩 읽는 시간을 프롬프트 길이(한글 2,000자, 20,000자, 60,000자)마다 잰다. 포트에 없는 대조군 둘을 함께 잰다. ## 2026-10-04 결과

`chain_walk.py`. 파일 하나의 크기는 한글이 UTF-8로 3바이트라 프롬프트 글자 수의 약 세 배다. 처음 판의 대조군은 프롬프트가 든 셋째 줄까지 파싱해서 원인을 가르지 못했고(셀프 리뷰가 잡았다), 둘로 나눠 다시 쟀다. 아래가 다시 잰 값이다.

|---|---|---|---|---|---|---|

| 10 | 20,000 | 61.4 | 6.0 | 0.60 | 1.9 | 1.2 |

| 100 | 60,000 | 178.6 | 127.6 | 1.28 | 29.3 | 12.5 |

- 비용은 지나는 실행의 수에 비례하고, `read`는 트레이스 하나에 0.3~1.3ms다.
- 머리만 읽어도 트레이스 하나에 약 0.12ms가 들고 파일 크기와 무관하다(파일을 열고 두 줄을 파싱하는 몫).
- 머리와 끝과 머리만의 차이(끝까지 흘려 읽는 몫)는 파일 크기를 따라 실행 1000개에 31~79ms다.
- `read`와 머리와 끝의 차이(가운데 줄을 파싱하는 몫)가 가장 크고, 프롬프트가 클수록 커진다. 머리와 끝은 `read`보다 1.8~4.4배, 머리만은 2.3~10.2배 짧았다(표의 합계로 나눈 값). 어느 쪽이든 실행 수에 비례하는 것은 그대로다.

`continuation_mutations.toml`(2026-10-04, 티켓 01의 셀프 리뷰 전). 변이 12 모두 기대대로 빨갰다. pytest 변이 열은 각 1~3 failed, vitest 변이는 `형식 3` 사례 하나가 failed, tsc 변이는 `stream.ts(42,3)`의 TS1360과 `stream.test-d.ts(8,56)`의 TS2344 둘이었다. 셀프 리뷰 뒤 `_walk`의 순환 검사를 멈춤 조건 앞으로 옮기고 라우터의 중복을 걷었다. `--check`가 덮는 끝 변이의 원문이 옮겨 간 것을 잡아 새 모양으로 고치고 그 변이만 다시 돌려 빨강을 봤다. PR 리뷰 뒤 `_walk`를 `_next_link`로 나누고 `_output_of`를 지우자 덮는 끝 변이와 다른 에이전트의 교환 변이의 원문이 다시 옮겨 가, 같은 길로 고치고 둘을 다시 돌려 빨강을 봤다. 나머지는 원문이 그대로다.

`continuation_mutations.toml`(2026-10-04, 티켓 02). 거슬러 읽기가 `core/continuation.py`로 옮겨 가 01의 변이 여섯의 원문이 사라진 것을 `--check`가 잡아 새 자리로 고쳤다. 02의 변이 열하나를 더해 옮긴 여섯과 함께 열일곱을 돌렸고 모두 기대대로 빨갰다(각 1~2 failed). vitest·tsc 변이 둘은 원문이 그대로라 돌리지 않았다. 02의 테스트 열아홉 가운데 구현 전에 빨강을 보지 못한 넷(기본 한도 20,000과 긴 마지막 교환은 `-k 요약`에 걸리지 않아 돌지 않았고, 요약 글을 세지 않음과 재개가 다시 판정하지 않음은 구현 전부터 초록인 가드다)이 이 변이로 빨강을 봤다.

`continuation_mutations.toml`(2026-10-05, 티켓 03). `_read_paused`가 멤버까지 읽게 되고 요약 자리가 `SUMMARY_INDEX`가 되어 02의 변이 둘("요약 이벤트의 자리를 보지 않는다", "재개가 요약할지를 다시 판정한다")의 원문이 옮겨 간 것을 `--check`가 잡아 새 자리로 고쳤다. 03의 변이 다섯을 더해, 옮긴 둘과 옮긴 코드 가까이의 둘("재개가 자기 요약의 자리를 보지 않는다", "재생 기록 열에 요약 이벤트를 둔다")과 함께 아홉을 돌렸고 모두 기대대로 빨갰다(각 1~5 failed). 03의 테스트 열하나 가운데 구현 전부터 초록이던 둘(이어 가지 않은 실행의 프롬프트 리터럴, 재개와 serve의 옵션 거절)이 이 변이로 빨강을 봤다. 나머지 열아홉은 원문이 그대로라 돌리지 않았다.
