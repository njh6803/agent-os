# 03: `widget-admin serve`와 `widget-admin migrate`가 서고, 데이터베이스가 준비되지 않으면 서버가 이유를 한 줄로 찍고 멈춘다

**What to build:** 명령 `widget-admin`이 선다. 개발자가 README의 세 명령(테스트 컨테이너에 `widget_admin` 데이터베이스 만들기, `widget-admin migrate`, `widget-admin serve`)을 치면 `127.0.0.1:8100`에 위젯 관리 서버가 뜨고(사용자 이야기 36, 45), `widget-admin migrate`는 위젯 쪽 표를 마지막 판까지 올린다. 표의 판은 alembic(표를 만들고 올리는 도구)이 판 기록 표 `alembic_version`에 적는 마이그레이션의 번호다. 표가 뒤처진 채(그 번호가 코드가 아는 마지막 번호보다 앞인 채) `serve`를 띄우면 "`widget-admin migrate` 를 먼저 돌리십시오"가 든 글과 종료 코드 3으로 멈추고(14), 표가 더 새로우면 `migrate`도 표를 건드리지 않고 백업을 복원하라고 알린다(15). 데이터베이스가 아직 뜨지 않았으면 30초까지 다시 시도하며 기다렸다 붙고(16), 비밀번호가 틀렸으면 기다리지 않고 바로 이유를 찍으며(17), 어떤 글에도 비밀번호가 없다(18). `--host 0.0.0.0`은 이미지의 표지 파일(우리 이미지 안에서 돈다는 것을 알아보게 이미지에 굽는 파일)과 `AGENT_OS_CONTAINER_NETWORK=1`이 함께 있을 때만 받는다(21). 이것이 루프백 규칙이다. 서버는 이 컴퓨터 안에서만 닿는 주소(`127.0.0.1`, `::1`)에만 열리고, 컨테이너 안에서만 그 예외가 켜진다. 지금 네 프로세스(`serve`, 관리 화면, 위젯, 위젯 미리보기 페이지)가 같은 규칙의 사본을 따로 들고 있고(`tests/fixtures/container_network/README.md`), 이 티켓이 다섯째 사본을 더해 같은 판정 표로 시험한다(43).

이 티켓은 01 뒤에 따로 든다. 01이 앱을 짓고 시험이 진짜 데이터베이스로 경로를 부르므로, 시작 검사는 그 앱의 가장 바깥에 더하면 된다(명세 "티켓을 나눌 때 함께 둘 것"의 셋째). 04는 이 티켓을 기다린다. 시작 검사가 없는 서버를 compose에 띄우면 표가 없을 때 멈추지 않고 떠서 모든 요청에 500을 낸다.

근거는 명세 `.scratch/widget-admin-server/spec.md`의 "설치 묶음과 패키지와 명령"의 명령 항목, "연결 문자열과 시작", "멈출 때의 글", "루프백 규칙", "개발 PC에서 붙는 데이터베이스", "문서와 하네스"에서 시작 검사의 변경이 싣는 것, Testing Decisions 첫째 이음매의 "시작"과 "루프백"과 머리 문단의 닫기 사례다. 그 절들이 원천으로 가리키는 postgres-foundation 명세 `.scratch/postgres-foundation/spec.md`의 "연결 문자열과 비밀번호의 변수", "비밀번호에 드는 글자", "뜰 때의 확인과 다시 시도", "데이터베이스 포트와 조립"의 미들웨어, "멈출 때의 글", "표의 판을 견주는 자리", Testing Decisions의 첫째·둘째·셋째도 근거다. 결정은 ADR 0064, ADR 0066, ADR 0056 결정 "루프백 규칙의 예외"다. 이 티켓의 "명세 검토"와 그 번호(S3, S4 같은 것)는 일지 `docs/journal/2026-11-24-2305-widget-admin-server-tickets.md`의 "명세 검토" 절을 가리킨다.

**Blocked by:** 01(위젯 관리 서버가 둘째 설치 묶음으로 서고, 표에 넣은 위젯 설정이 `/widget-settings/<사이트 이름>`에서 토큰 없이 읽힌다). 02와 나란히 돌 수 있다. 두 티켓이 함께 고치는 파일은 루트 `README.md`뿐이고 절이 다르다(파일 목록으로 판단한 것이고 돌려 보지는 않았다).

**Status:** done

### 명령과 루프백 규칙

- [x] 멤버 `pyproject.toml`의 명령 `widget-admin`이 패키지의 `main`을 부른다. `widget-admin serve [--host <주소>] [--port <번호>]`의 기본 주소는 `127.0.0.1:8100`이고, `widget-admin migrate`는 인자가 없다. 둘 다 `python -m widget_admin.main`으로도 돈다(명세 "설치 묶음과 패키지와 명령")
- [x] `--host`가 명세 "루프백 규칙"대로다. 루프백 둘은 늘 받고, `0.0.0.0`은 표지 파일 `/etc/agent-os/image`가 있고 `AGENT_OS_CONTAINER_NETWORK`가 `1`일 때만 받는다. 판정은 Agent OS의 `serve`와 같은 사본이다. 진단의 글은 `serve`의 것에서 까닭의 줄 하나만 명세 "루프백 규칙"이 정한 글자로 바꾸고 나머지 줄은 같다
- [x] uvicorn에 `lifespan="on"`을 넘기고, 멈출 때 연결이 남은 응답을 기다리는 상한은 Agent OS와 같은 5초다(명세 "연결 문자열과 시작")
- [x] `tests/fixtures/container_network/README.md`의 읽는 시험 목록에 위젯 관리 서버의 시험을 더하고 "네 프로세스"를 다섯으로 고친다

### 연결 문자열과 뜰 때의 확인

- [x] `serve`와 `migrate`는 연결 문자열을 `WIDGET_ADMIN_DATABASE_URL` 하나로만 받고, 그 밖의 환경 변수와 파일을 읽지 않는다. 꼴은 `postgresql://계정:비밀번호@호스트:포트/데이터베이스`만 받고, 드라이버가 붙은 꼴, 질의 문자열, `@`가 둘 이상인 주소는 "읽지 못했다" 글과 1이며 값을 되울리지 않는다
- [x] 01의 데이터베이스 객체에 확인을 더한다. 실패의 갈래 다섯, 다시 시도 30초와 시도 사이 1초, 시도 하나(연결을 얻는 것부터 판을 다 읽는 것까지)를 통째로 감싸는 5초, 첫 실패 뒤 알림 한 줄이다. 다시 시도 시간과 시도 하나의 제한 시간은 인자로 받고 기본값은 그 30초와 5초다(명세 "연결 문자열과 시작", 명세 검토 S3). 시도 하나의 제한 시간을 드라이버의 접속 인자로만 걸지 않는다
- [x] 표의 판 견줌이 postgres-foundation 명세 "표의 판을 견주는 자리"대로다(뒤처짐, 맞음, 더 새로움)
- [x] 수명 확인 미들웨어를 앱의 가장 바깥에 둔다. 수명(lifespan)은 uvicorn이 앱에 보내는 뜨기·내리기 신호이고, 수명 확인 미들웨어는 그 신호를 가장 먼저 받아 뜨기 전에 데이터베이스를 확인하는 층이다. 수명이 열리는 첫 메시지에서 앱의 시작 단계보다 먼저 확인하고, 글이 오면 `lifespan.startup.failed`에 실어 보내며, 확인이 예외를 던져도 같은 길로 멈추고, 수명이 끝날 때는 연결 묶음을 닫은 뒤에 완료를 넘긴다(명세 "응답 머리"의 미들웨어 차례)
- [x] `migrate`는 닿을 때까지 기다리고, 판을 견주고, 마지막 판까지 올린다. 표가 더 새로우면 표를 건드리지 않고 1이다

### 멈출 때의 글

- [x] 찍는 글은 명세 "멈출 때의 글"의 표와 같다. 글자가 다른 셋(변수가 없거나 비었다, 읽지 못했다, 표가 뒤처졌다)은 그 표의 글자이고, 나머지는 postgres-foundation 명세 "멈출 때의 글"의 줄과 글자 그대로 같다. 시험이 글자까지 단언한다
- [x] 글에 ADR 번호 같은 저장소 안의 말을 싣지 않는다. 배포 안내가 이 글을 그대로 옮기기 때문이다(명세 "멈출 때의 글"의 표 아래 줄)
- [x] 글을 짓는 자리는 자리 표시(`<자리>`, `<까닭>`, `<판>`)를 넣어 부를 수 있는 함수나 상수로 두고, 기본 다시 시도 시간과 실패·판 견줌의 갈래도 시험이 읽게 낸다. Agent OS 쪽이 `retry_notice`, `unreached_text`, `misaligned_text`, `DEFAULT_RETRY_SECONDS`로 낸 꼴이다(`src/agent_os/adapters/postgres/database.py`). 04가 배포 안내 13절의 표를 그 글과 견주는 시험을 더한다(명세 "노트 검사와 저장소 상태 시험"의 "배포 안내 13절의 표")
- [x] 그 줄들이 가리키는 배포 안내의 절("데이터베이스 비밀번호 바꾸기", "띄우기가 끊겼을 때")은 04가 위젯 쪽 절차를 더한다. 이 티켓에서는 그 절이 아직 Agent OS 쪽만 적는다는 것을 알고 글을 그대로 쓴다
