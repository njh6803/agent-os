# 05: Claude Design에 올릴 것과 마무리 — 보여 주기용 스토리, 기초 카드, 목록 타일, 사용 규약

**What to build:** 사용자가 Claude Design에서 디자인 시스템 "Agent OS 디자인 시스템"을 열면, 컴포넌트마다 실제 쓰임(승인 묻기의 버튼 쌍, 실행 목록의 배지 넷, 플러그인 줄의 스위치 등)을 보이는 카드와, 색(원색과 쓰임새, 테마 넷)·글자 단계·간격과 모서리·밀도 두 벌을 소개하는 기초 카드를 본다. 변형과 상태를 빠짐없이 늘어놓는 변형 스토리는 카드에서 빠진다. 프로젝트 목록의 타일은 녹청의 색이다. 디자인 에이전트가 읽는 사용 규약은 테마 넷과 밀도, 새 클래스와 변수를 안내한다. 저장소의 살아 있는 문서와 코드에 옛 테마·글꼴·디자인 토큰의 말이 남지 않는다. 이 PR이 병합된 뒤 사람이 `/design-sync`를 시작해 올린다.

04 뒤에 돈다. 이 기능의 마지막 티켓이다.

근거는 `.scratch/design-refresh/spec.md`의 "`/design-sync`에 올릴 것", "문서와 설정"(화면 프롬프트와 잔존 grep), Testing Decisions의 "보여 주기용 스토리"와 그 2026-10-12 명세 검토·to-tickets 주석이다. 동기화의 절차는 `docs/agents/issue-tracker.md`의 화면 디자인 절이고, 배경과 다시 볼 위험은 `.design-sync/NOTES.md`다. 결정은 ADR 0025·0026(스토리 한 벌이 갤러리, 실제 브라우저 테스트, Claude Design의 원천을 함께 맡는다)이다.

### 보여 주기용 스토리

- [x] **컴포넌트 아홉마다 실제 쓰임을 보이는 스토리 몇을 패키지의 Storybook에 더한다**(사용자가 골랐다). 예는 승인 묻기의 버튼 쌍("거부"(보조)가 먼저, "승인"(주)이 나중), 실행 목록의 배지 넷, 플러그인 줄의 스위치, 실행 실패 알림, 카드 안의 실행 요약이다. 패턴과 화면(organisms 이상)을 패키지에 짓지 않는다. 보여 주기용 스토리는 컴포넌트를 엮어 보일 뿐이다
- [x] **보여 주기용 스토리에 태그를 단다.** `judgment`는 달지 않는다. 달면 사진에서 빠진다. 보여 주기용 스토리도 스토리 테스트(afterEach의 클래스 판정, axe)와 사진 비교(녹청의 라이트·다크 × 밀도 둘)를 지난다. 단언은 두지 않아도 된다. 정답 사진을 컨테이너에서 만들어 커밋한다

### 카드에서 변형 스토리를 뺀다

- [x] **동기화 설정의 컴포넌트별 `overrides.<Name>.skip`에 변형 스토리를 든다.** 변환기는 그 목록의 스토리를 카드에서 뺀다(명세가 2.1.286 판의 변환기 `package-build.mjs`와 `emit.mjs`를 읽었다. 이 세션의 변환기 판이 다르면 다시 읽는다). 이 명세가 처음에 "판정용 스토리"라 부른 것을 이제 "변형 스토리"라 부른다(명세 검토). 설정의 `titleMap`은 제목("진입점", "판정", "판정의음성사례")으로 판정 스토리 파일만 뺀다. 컴포넌트 스토리 파일 안의 `judgment` 스토리(기본 테마가 아닌 테마에서 재는 것 등)는 `titleMap`으로 빠지지 않으므로 그것도 빼는 목록에 든다
- [x] **빼는 목록이 어긋나지 않게 검사한다**(명세 검토). 빼는 목록은 스토리 id라, 스토리를 더하거나 이름을 바꾸면 조용히 어긋난다. 보여 주기용 태그가 없는 컴포넌트 스토리가 모두 빼는 목록에 있는지, 목록의 id가 모두 지금 있는 스토리인지 보는 검사를 동기화 때 도는 사용 규약 검사기(`.design-sync/check-conventions.mjs`)에 둔다. CI에 두지 않는 것은 명세 이음매 절의 "더하지 않는 것"(새 이음매) 때문이다. admin-style이 `IconName`을 더해 스토리가 바뀌어도, 그 기능이 그리기 전에 돌리는 동기화에서 이 검사가 잡는다. 규칙은 `.design-sync/NOTES.md`에 적는다
- [x] 빼는 목록을 채점(Storybook과 카드의 비교)도 따르는지는 처음 동기화가 본다(명세의 재지 못한 것) (2026-10-14: 따른다. compare가 보여 주기용 11개만 캡처했다)

### 기초 카드와 목록 타일

- [x] **기초 카드 넷.** 색(원색과 쓰임새, 테마 넷), 글자 단계, 간격과 모서리, 밀도 두 벌이다. 첫 줄이 `<!-- @dsCard group="…" -->`인 HTML이고, 변환기의 자체 검사가 폴더마다 첫 `@dsCard` HTML 하나를 고르므로 카드마다 폴더를 따로 둔다. 자리는 `.design-sync/` 아래이고 목록 타일처럼 빌드 뒤 `ds-bundle/`에 복사해 올린다
- [x] **값은 글자로 적지 않고 올린 CSS의 변수(`var(--gray-50)` 등)로만 읽는다.** ADR 0026의 "디자인 토큰의 값은 코드에만 둔다"를 지키기 위해서다. 사용 규약의 검사기가 기초 카드의 `var(--이름)`도 빌드 CSS의 선언과 맞댄다(명세 검토). 이름이 바뀌면 `var()`가 풀리지 않아 조용히 빈 칸이 되기 때문이다. 빌드 CSS의 hex는 짧은 꼴일 수 있어 6·8자리를 가정하지 않는다(`tailwind.mjs`)
- [x] 컴포넌트 폴더 밖의 `@dsCard` 카드가 실제로 모이는지는 처음 동기화가 본다 (2026-10-14: 모인다. 그룹 넷 아래에 하나씩 오르고 이름은 파일 이름을 따라 `index`다)
- [x] **목록 타일.** `.design-sync/thumbnail.html`을 녹청의 색으로 다시 그린다

### 사용 규약, 변환기 포크, NOTES

- [x] **사용 규약 `.design-sync/conventions.md`.** 테마 키 넷과 기본 녹청, 밀도와 그 변수(인라인 `style`에는 원천인 `--body-size` 등을 쓴다), 이미 있는 클래스와 변수의 목록, 예시를 새 결정으로 고친다. 검사기 `.design-sync/check-conventions.mjs`가 읽는 문장 모양을 바꾸면 검사기도 고친다 (04 메모: 지금 규약은 이미 걷힌 이름을 든다. 04가 걷은 것은 `text-heading`, `text-caption`, `text-code`, `control-m`, `row-touch`, `field-multi`이고, `shadow-1`~`3`, `font-strong` 등은 02·03이 걷었다. 04가 더한 이름은 글자 `text-badge`·`text-table`·`text-mono`, 높이 `h-control`·`size-control`·`h-row`, 틀 `w-nav`·`h-nav-item`·`h-top-bar`, 부품 치수(`switch-knob`, `switch-inset`, `badge`, `badge-start`), 그림자 `shadow-float`이다. `size-control-s`는 값이 32px에서 28px로 바뀌었다. 밀도를 따르는 다섯과 그림자는 `@theme inline`이라, CSS가 `var()`로 읽지 않는 한 CSS 변수로 나오지 않는다. 규약의 변수 목록에는 원천인 밀도 변수 일곱을 든다)
- [x] **변환기 포크.** 기본 테마(`muk`)를 녹청으로 바꾸고, 스토리의 밀도 globals를 테마·모드처럼 감싸는 요소로 옮긴다. 포크를 고치면 다음 동기화가 모든 컴포넌트를 다시 채점한다(`.design-sync/NOTES.md`의 Re-sync risks). 설정의 `libOverrides` 설명 문장도 고친다
- [x] **NOTES.** 옛 테마와 글꼴의 문장, 빼는 목록의 규칙, 기초 카드의 자리를 고친다

### 이 티켓이 정할 것

1. 보여 주기용 스토리의 목록과 이름, 그리고 그 태그의 이름
2. 검사기가 스토리의 목록과 태그를 읽는 방법(빌드한 Storybook의 색인 등)
3. 기초 카드 넷의 폴더 이름과 그룹 이름

정한 것(2026-10-13 구현):

1. 태그는 `showcase`, 이름은 `쓰임: …`, 내보내기 이름은 `Showcase…`다. 열하나다. Button 둘(승인 묻기의 버튼 쌍, 새로 고침과 토큰 지우기), IconButton 하나(위젯 대화 입력 끝의 보내기), Icon 하나(탐색 항목 앞의 아이콘), StatusBadge 하나(실행 목록의 배지 넷), Progress 하나(단계를 아는 진행과 응답 기다리기), Card 하나(카드 안의 실행 요약), Switch 하나(플러그인 줄의 스위치), TextField 하나(거부 사유와 채널 토큰), Alert 둘(실행 실패 알림, 경고와 정보 알림). 자리와 문구는 관리 화면과 위젯에 있는 동작(승인·거부와 거부 사유, 새로 고침, 토큰 지우기, 플러그인 켜고 끄기, 보내기)에서만 골랐다. 셀프 리뷰가 처음 판의 없는 기능(다시 실행, 실행 지우기, 플러그인 더하기)을 짚어 바꿨다.
2. 동기화가 짓는 참조 Storybook 의 색인 `cfg.storybookStatic`/`index.json`(`.design-sync/sb-reference/index.json`)이다. 항목에 태그가 실리고, 변환기도 같은 파일에서 스토리 id 와 컴포넌트를 모은다. 판정이 빨개지는 것은 `probes/checker_mutations.mjs`, 보여 주기용 스토리가 판정을 지나는 것은 `probes/showcase_mutations.toml` 이 잰다.
3. `.design-sync/foundations/{colors,type,spacing,density}/index.html` 이고 그룹은 `Colors`, `Type`, `Spacing`, `Density` 다(앞의 셋은 `DesignSync` 도구 설명이 드는 기초 라벨). 올리는 자리는 `ds-bundle/foundations/<폴더>/index.html` 이다.
