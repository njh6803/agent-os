# doc-qa-agent: 문서 검색 서버를 불러 근거를 찾고 출처를 달아 답하는 참조 질의응답 에이전트를 준다.
**슬라이스:** 8
**Blocked by:** mcp-http, approval-rules

참조 에이전트 `doc-qa`, 스킬 `cite-sources`, 문서 검색 서버를 주소로 가리키는 MCP 플러그인(원격 MCP 서버). `plugins/agents/calc`가 `plugins/mcp/everything`을 쓰는 것과 같은 모양이고, 런타임은 calc를 모르듯 이 플러그인들도 모른다(ADR 0048). 에이전트는 매니페스트의 `mcp`로 문서 검색 서버를 고르고, 그 검색 도구(형식은 ADR 0048의 계약)로 근거를 모아 답한다. 스킬은 답의 문장마다 근거 문서와 위치를 적게 하고, 근거가 없으면 모른다고 답하게 한다. 출처에는 문서의 갱신일도 함께 적는다. 나중에 답을 되짚을 때 어떤 판의 문서로 답했는지가 남아야 하기 때문이다. 출처를 출력 글 안에 적으면 계약이 바뀌지 않는다. `run_finished`에 구조화한 출처 칸을 더하면 sdk와 `openapi.json`의 가산 변경이 첫 티켓이고, 위젯의 출처 표시가 마지막 티켓이다. 둘 가운데 무엇인지, 그리고 이 플러그인들을 기본 플러그인 루트(`plugins/`)에 둘지 참조 배포 전용 루트에 둘지는 설계 인터뷰가 정한다. 규칙 파일에 적지 않은 도구는 묻는 것이 기본이라(ADR 0044), 검색 도구를 허락하는 규칙 파일을 함께 낸다(ADR 0046). 그래서 approval-rules에 막힌다. 검색 결과는 문서 내용이므로 최종 사용자 입력과 같은 신뢰 수준의 데이터로 프롬프트에 엮고, 문서 속의 지시를 따르지 않는다(mcp-trust 전까지 런타임이 감싸 주지 않는다, ADR 0046). 실행 하나의 모델 호출 수에 끝을 두고(예: 검색 두 번과 답 한 번), 검색할 조각 수도 정해 둔다. 토큰 합 상한(token-limit)이 오기 전에는 이 끝과 모델 매니페스트의 `max_tokens`, 사이트 파일의 요청 글자 수 상한이 실행 하나의 토큰을 묶기 때문이다(public-demo가 이것으로 시간당 비용의 최댓값을 셈한다). 시험은 ADR 0043의 CI 분담을 따른다: 빠른 검사는 검색 도구 형식을 흉내 내는 가짜 MCP 서버(테스트 픽스처)로 돌고, 실제 이미지의 compose e2e는 판을 고정한 실제 문서 검색 서버 이미지로 돈다(ADR 0048). 설계 인터뷰가 먼저 볼 것: 빠른 검사가 가짜 서버로 도므로, 문서 검색 서버가 형식을 바꾸면 빠른 검사는 초록인데 실제 이미지의 e2e에서 깨질 수 있다. 가짜 서버가 따르는 형식의 판을 한 곳에 적고(ADR 0048), 실제 이미지의 e2e를 반드시 돌린다. 출처의 갱신일이 문서의 판을 가르는지도 본다. 갱신일이 날짜 단위면 같은 날 바뀐 두 판의 출처가 같아지므로, 갱신일의 단위나 판을 가르는 값을 검색 도구 형식의 계약(ADR 0048)과 함께 정한다. 수락: 가짜 검색 서버에 표본 조각을 두고 위젯에서 질문하면 출처와 갱신일이 붙은 답이 나오고, 근거가 없는 질문에는 모른다고 답하며, 지시가 섞인 표본 조각이 와도 그 지시를 따르지 않는 테스트가 통과한다
