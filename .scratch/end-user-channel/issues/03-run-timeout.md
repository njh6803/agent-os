# 03: 실행 타임아웃 — 결말이 나지 않는 실행을 런타임이 시간 안에 `run_failed`로 끝낸다

**What to build:** 시작 이벤트(재개에서는 결정 이벤트)를 쓴 뒤 그 시간 안에 결말이 나지 않으면 런타임이 실행을 `run_failed`로 끝낸다. 메시지는 "실행이 N초 안에 끝나지 않았다"이고 트레이스에 결말로 남아 결말 없음과 갈린다. 부르던 도구는 취소된다. 기본 600초이고 `serve` 인자로 바꾸며 CLI `run`·`resume`에도 걸린다. 재개마다 다시 세어 멈춰 있는 시간은 세지 않는다. 최종 사용자는 실패 항목을 받고 다시 물을 수 있다.

ADR 0014가 범위 밖에 두었던 것을 사용자가 들였다(ADR 0014의 2026-10-05 이력). 01의 틈 하나(실행에 타임아웃이 없다)를 닫는다. 02를 막는다 — 걸린 실행이 동시 실행 칸을 붙잡는 열린 문제의 답이고, 타임아웃 뒤 칸이 돌아오는 02의 사례가 여기 기댄다.

근거는 `.scratch/end-user-channel/spec.md`의 "실행 타임아웃", "CLI와 `serve`"(타임아웃 인자), Testing의 "타임아웃" 절과 그 2026-10-05 명세 검토·to-tickets 주석, 측정 `run_timeout.py`다.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] **`run()`과 `resume()`이 선택 인자 하나를 더 받는다: 타임아웃(초).** 없음은 core의 기본값 600초다(루프 상한·목록 상한·기본 대화 한도와 같은 자리). 이름은 이 티켓이 짓는다
- [ ] **자리는 core의 진입점 둘이고 범위는 시작 이벤트(재개에서는 결정 이벤트)를 쓴 뒤부터 결말까지다.** 요약 호출은 진입점이 몸통을 부르기 전에 하므로 진입점이 `anyio.fail_after`를 열어 요약과 몸통을 함께 감싼다. 시간이 지나면 취소가 안쪽 `await`에 들어가 범위를 나오며 `TimeoutError`가 되고 진입점이 그것을 `run_failed`로 바꿔 쓴다. 요약 중이었어도 같은 메시지다(취소는 `BaseException`이라 요약의 실패 경로를 지나친다). **몸통의 `except Exception`이 이것을 먼저 잡는 경우는 없다** — anyio는 범위 안에서는 취소로 전달하고 범위를 나올 때만 `TimeoutError`로 바꾼다(명세 검토 nit. 어림이고 재지 않았다 — 측정 `run_timeout.py`는 범위를 몸통 안에 둔 모양이다. 명세의 "하나만 쓰이게 한다(티켓의 몫)"는 그 어림이 맞으면 일어나지 않는 경우다). 그래서 이 티켓의 core 테스트가 진입점 모양에서 `run_failed`가 하나뿐이고 태스크 그룹이 깨지지 않는 것을 실제 가짜 도구 연결로 고정한다. 어림이 틀리면(몸통이 먼저 잡는 경우가 있으면) 멈춰 보고한다
- [ ] **재개마다 다시 센다.** 멈춰 있는 시간은 세지 않는다(일시정지에 만료 시간을 두지 않는 ADR 0009 그대로)
- [ ] **타임아웃으로 실패한 실행은 다른 실패와 같다.** 재개할 수 없고 이어 갈 수 없으며 등록부에서 빠진다. 도구 연결은 취소되어 닫힌다
- [ ] **`serve`가 인자로 받아 `create_app`에 넘기고 채널이 `run()`·`resume()`에 넘긴다.** `serve` 인자의 기본은 없음이고 600은 core 한 곳만 든다(명세 검토 nit). 0 이하는 구성 오류. CLI `run`·`resume`은 플래그 없이 기본값을 쓴다. 인자 이름은 이 티켓이 짓는다
- [ ] **core 테스트.** 가짜 모델이 타임아웃보다 오래 자면 `run_started` → `run_failed`이고 메시지가 타임아웃을 든다. 요약 호출(이어 가기에서 한도를 넘긴 가짜 모델이 잔다)에서 걸려도 같은 메시지의 `run_failed` 하나이고 요약 이벤트는 없다. 재개도 같다(결정 이벤트 뒤 `run_failed`). 멈춘 뒤 시계를 타임아웃 넘게 돌려도 재개가 선다. 타임아웃 안에 끝나면 그대로다. 가짜 도구 포트의 연결이 닫힌다(`servers`와 닫힘 기록). 둘째 구동자에서 타임아웃 뒤 실행이 등록부에서 빠지는 것
- [ ] **`serve` 테스트.** 새 인자가 `create_app`에 닿는다. 0 이하 → 종료 코드 1과 진단
- [ ] **`core.md`에 타임아웃의 자리와 실패 정책을, `channel.md`에 넘기는 것을 적는다.** 잔존 `취소와 타임아웃`을 저장소 전체에서 grep한다(기록 제외. ADR 0014 본문의 그 문장은 이력 포인터가 이미 있다)
- [ ] 검증 명령이 모두 초록이다. `core/run.py`와 `main.py`를 건드리므로 기존 `-m llm`을 한 번 돌려 일지의 검사 절에 적는다

### 이 티켓이 정할 것

1. `run()`·`resume()`의 타임아웃 인자 이름과 core 기본값 상수의 이름
2. `serve`의 타임아웃 인자 이름
