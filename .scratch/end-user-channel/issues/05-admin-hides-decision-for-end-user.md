# 05: 관리 화면 — 최종 사용자의 멈춘 실행에는 결정 자리가 서지 않고 한 줄로 이유가 보인다

**What to build:** 관리 화면의 실행 상세에서 트레이스 시작 이벤트의 주체에 `|`가 들면 결정 자리(허가·거부)가 서지 않고 최종 사용자의 실행이라 결정은 그 사람만 낸다는 뜻의 한 줄이 보인다(문구는 이 티켓이 짓는다). 지금 조건 셋(채널 토큰, 일시정지, 형식 1 아님)에 넷째가 든다. 서버에 묻지 않는다. 목록과 상세는 바뀌지 않고 주체는 글자로 그려진다.

TS만이라 01과 나란히 돌 수 있다(막는 것 없음). 01보다 먼저 병합되어도 거짓이 되는 문장은 없다 — `|`가 든 주체가 최종 사용자의 것이라는 규칙은 accepted ADR 0023의 것이고, 그때까지 그런 실행은 없을 뿐이다. 01이 먼저 병합되면 그 사이 결정 자리가 서고 누르면 409 봉투가 보인다(명세 검토가 거짓이 되는 계약이 없다고 확인했다).

근거는 `.scratch/end-user-channel/spec.md`의 "관리 화면", "주체"(관리 화면 항목), Testing의 "관리 화면" 절, 스토리 48·49·62와 그 2026-10-05 명세 검토·to-tickets 주석이다. ADR 0023이 앞선 결정이다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] **결정 자리의 조건에 넷째가 든다.** 시작 이벤트(`events[0]`가 `run_started`)의 주체에 `|`가 들면 자리가 서지 않는다(`RunDecision`). 자리에 한 줄을 둔다. 문구는 이 티켓이 짓되 ADR 0023의 결정(실행의 주체만 결정하고 이어 간다)에 기댄다
- [ ] **서버에 묻지 않는다.** 눌러 보면 서버가 409로 막는 것은 그대로다(core)
- [ ] **목록과 상세는 바뀌지 않는다.** 주체는 글자로 그려지고 `|`는 글자다(web-admin 스토리 32)
- [ ] **페이지 테스트.** 주체에 `|`가 든 멈춘 실행(채널 토큰 있음, 형식 3)에 결정 자리가 없고 한 줄이 보인다. `|`가 없는 같은 트레이스에는 자리가 있다(기존). 픽스처의 주체는 지금 `operator`라 새 사례에 `발급자|sub` 모양 하나를 더한다
- [ ] **`web-admin.md`에 넷째 조건과, 그 조건이 주체 이름의 구분자 `|`에 기댄다는 것을 적는다.** sdk 계약 밖의 결합이라 구분자를 바꾸는 결정은 이 조건을 함께 바꾼다(PR #135의 claude-review 2회차). 결정 컴포넌트의 독스트링(조건 셋 → 넷)을 고친다
- [ ] **e2e는 늘리지 않는다**
- [ ] 이 기능의 첫 병합이면 `.scratch/plan.md`의 end-user-channel 행을 `in-progress`로 바꾼다(01이 먼저 병합됐으면 이미 바뀌어 있다)
- [ ] **기능을 닫는지는 병합 직전에 판정한다.** `git fetch` 뒤 `origin/main`의 02 티켓 파일 `Status:`가 `done`이면 이 PR이 `.scratch/plan.md`의 end-user-channel 행을 `done`으로 바꾸고 프론티어 문단을 고친다(02가 `done`이면 01·03·04도 `done`이다). 아니면 02가 닫는다. main이 최신 기준(strict)이라 뒤에 병합되는 쪽은 앞의 병합을 들인 뒤에야 병합되므로 둘이 함께 열려 있어도 한쪽은 반드시 본다
- [ ] 검증 명령이 모두 초록이다. 파이썬은 바뀌지 않으므로 `-m llm`은 돌리지 않는다
