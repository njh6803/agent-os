# 05: 관리 화면 — 최종 사용자의 멈춘 실행에는 결정 자리가 서지 않고 한 줄로 이유가 보인다

**What to build:** 관리 화면의 실행 상세에서 트레이스 시작 이벤트의 주체에 `|`가 들면 결정 자리(허가·거부)가 서지 않고 최종 사용자의 실행이라 결정은 그 사람만 낸다는 뜻의 한 줄이 보인다(문구는 이 티켓이 짓는다). 지금 조건 셋(채널 토큰, 일시정지, 형식 1 아님)에 넷째가 든다. 서버에 묻지 않는다. 목록과 상세는 바뀌지 않고 주체는 글자로 그려진다.

01 뒤이고 03·04와 나란히 돈다. 01이 OS 사용자 이름의 `|` 가드를 세우기 전에는 `serve`가 `getpass.getuser()`를 검사 없이 주체로 넘기므로, `|`가 든 OS 사용자 이름의 실행에서도 이 가림이 걸려 운영자의 결정 자리가 숨는다(PR #136의 CodeRabbit이 코드를 읽어 짚었다. 처음 초안은 막는 것 없음이었다). 01 뒤에는 `|`가 든 주체가 언제나 최종 사용자다. 01이 먼저 병합된 사이 결정 자리가 서고 누르면 409 봉투가 보인다(명세 검토가 결정 컴포넌트의 실패 안내 코드를 읽어 그 사이 거짓이 되는 계약이 없다고 봤다).

근거는 `.scratch/end-user-channel/spec.md`의 "관리 화면", "주체"(관리 화면 항목), Testing의 "관리 화면" 절, 스토리 48·49·62와 그 2026-10-05 명세 검토·to-tickets 주석이다. ADR 0023이 앞선 결정이다.

- [x] **결정 자리의 조건에 넷째가 든다.** 시작 이벤트(`events[0]`가 `run_started`)의 주체에 `|`가 들면 자리가 서지 않는다(`RunDecision`). 자리에 한 줄을 둔다. 문구는 이 티켓이 짓되 ADR 0023의 결정(실행의 주체만 결정하고 이어 간다)에 기댄다
- [x] **서버에 묻지 않는다.** 눌러 보면 서버가 409로 막는 것은 그대로다(core)
- [x] **목록과 상세는 바뀌지 않는다.** 주체는 글자로 그려지고 `|`는 글자다(web-admin 스토리 32)
- [x] **페이지 테스트.** 주체에 `|`가 든 멈춘 실행(채널 토큰 있음, 형식 3)에 결정 자리가 없고 한 줄이 보인다. `|`가 없는 같은 트레이스에는 자리가 있다(기존). 픽스처의 주체는 지금 `operator`라 새 사례에 `발급자|sub` 모양 하나를 더한다
- [x] **`web-admin.md`에 넷째 조건과, 그 조건이 주체 이름의 구분자 `|`에 기댄다는 것을 적는다.** sdk 계약 밖의 결합이라 구분자를 바꾸는 결정은 이 조건을 함께 바꾼다(PR #135의 claude-review 2회차). 결정 컴포넌트의 독스트링(조건 셋 → 넷)을 고친다
- [x] **e2e는 늘리지 않는다**
