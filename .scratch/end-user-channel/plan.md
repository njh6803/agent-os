# end-user-channel: 사이트가 서명한 토큰을 가진 최종 사용자가 실행을 시작하고 결과를 받는 별도 경로를 연다.
**슬라이스:** 4
**Blocked by:** http-channel, web-admin
**끝:** 2026-10-06

최종 사용자 경로. `/runs`와 다른 새 접두사 아래에 시작, 결정, 구독이 선다. 사이트가 RS256으로 서명한 JWT만 받고(PyJWT, 허용 알고리즘 하나), 주체는 발급자와 `sub`를 묶은 이름이다. `serve`가 시작 때 읽는 사이트 파일(TOML, 없으면 받아들일 사이트 없음)이 발급자, 공개 키, 대상, 허용 출처, 열 에이전트, 상한 값을 든다. 스트림은 최종 사용자 항목 유니온이고 프레임의 SSE `id`가 트레이스 인덱스다. 실행의 주체만 그 실행에 결정·구독·이어 가기를 하고 판정은 core가 한다(CLI도 막힌다, ADR 0009 이력). 면마다 응답이 다르다(최종 사용자 404, 운영자 409, CLI 진단). 구독은 앱이 든 도는 실행의 등록부로 도는 실행을 알아보고, 등록부에 없고 결말도 없으면 끝내지 못했다는 항목으로 닫는다. 사이트 파일은 발급자가 겹치면 구성 오류이고, 검증 전에 발급자로 항목 하나를 고른다. 인자를 줬는데 파일이 없으면 구성 오류다. 열 에이전트 목록은 결정·구독·이어 가기에서도 본다. CORS는 새 접두사에만이고 에러 응답에도 붙으며 `Retry-After`를 노출한다. 상한(요청 크기, 주체별·사이트별·전역의 동시 실행과 시간당 실행 수, 주체별 구독, 결정도 동시 실행 셈에 듦, 셈은 프로세스 메모리)은 요청 크기 초과가 기존 422이고 나머지는 429와 새 에러 코드다. 연결마다 백로그 상한, 넘치면 그 연결만 닫는다. 관리 화면은 최종 사용자의 실행에서 결정 버튼을 막는다. 층: JWT와 CORS는 `agent_os.http`, 사이트 파일은 `main.py`, 투영·구독·등록부·셈은 채널이고 포트는 늘지 않는다. 첫 티켓은 계약. conversation에서 넘어온 것: conversation이 2026-10-05에 먼저 닫혀 다른 주체의 core 하위 타입은 그 티켓 01이 지은 `DifferentPrincipal`을 그대로 쓴다(공용 표의 409 줄, core 테스트의 하위 타입 목록, rules 둘, 409의 정의 문장과 공유 설명도 그쪽이 고쳤다). 최종 사용자 투영이 만나는 대화 요약 이벤트는 건너뛴다. 손상이 주체보다 앞이라 남의 손상된 트레이스가 500으로 존재를 드러내는 것은 최종 사용자 면에서 실행을 가리키는 경로의 500을 404로 덮어 닫았다(아래. end-user-continuation 티켓 05가 덮는 것을 주인을 확인하기 전의 손상으로 좁혔다). 명세가 정한 것(2026-10-05)은 `.scratch/end-user-channel/spec.md` 서두의 목록이고 측정은 `.scratch/end-user-channel/probes/`다 — 사용자가 고른 여덟(이음매, 토큰 규칙, 주체 이름 `발급자|sub`, 재개의 판정 순서, 상한 기본값, 실행 타임아웃, 요약 이벤트 건너뜀, 손상 500→404)과 명세가 정한 스물다섯. 열린 문제는 남지 않았다. 설계는 ADR 0023과 ADR 0009·0010·0011·0014·0015·0017 이력, 일지 2026-10-03-03. 명세의 PR이 ADR 0014 이력 둘과 ADR 0023 이력 하나를 올렸다. 이것으로 닫힌 넘겨받은 것: http-channel의 최종 사용자 인증, CORS, 재접속, 에러 문구 노출(PR #68 CWE-209는 원격 면에서 닫고 운영자 `/runs`는 그대로), 느린 수신자의 백로그와 요청 크기. plugin-toggle의 꺼진 에이전트 404/409. web-admin의 (1) 토큰 배치를 물려받지 않음과 (6) 결정의 자리. 명세 검토(2026-10-05)는 blocker 1·should-fix 8·nit 8이었고 명세의 주석으로 닫았다. 티켓은 다섯이다(`.scratch/end-user-channel/issues/`, 2026-10-05). 01 계약(토큰·사이트 파일·경로 셋·투영·등록부·구독·판정) → 03 타임아웃·04 CORS·05 관리 화면(01 뒤, 나란히) → 02 상한·백로그(01·03·04 뒤). 02와 05 가운데 마지막에 병합되는 쪽이 닫는다 — 02가 마지막이라 2026-10-06에 닫았다. to-tickets에서 사용자가 고른 것은 명세 서두의 주석이다
