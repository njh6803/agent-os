# 02: 채널 토큰 — `/runs` 아래는 채널 토큰만 연다

**What to build:** 운영자가 `agent-os serve`를 띄우려면 토큰이 둘 필요하다. 관리 토큰(`AGENT_OS_ADMIN_TOKEN`)과 채널 토큰(`AGENT_OS_CHANNEL_TOKEN`)이 모두 있고 서로 달라야 서버가 서며, 어긋나면 구성 오류가 모여 한 번에 나온다. 서버가 서면 `/runs` 접두사 아래는 채널 토큰만, 그 밖은 관리 토큰만 통과한다. 채널 라우트는 아직 없다 — 이 티켓이 만드는 것은 **그 뒤로 붙는 채널 라우트가 처음부터 자기 토큰 뒤에 서는 자리**다.

라우트보다 먼저인 것이 이 티켓의 존재 이유다. `/runs` 라우트가 먼저 병합되면 미들웨어의 기본값이 관리 토큰이라 그 사이의 main에서 관리 토큰이 실행을 일으키고, 지금의 전수 테스트(`test_allowlist_밖의_모든_경로가_토큰_없이_401이다`)는 그 상태에서도 초록이다(명세 검토). 관리 API가 인증을 라우트보다 먼저 둔 것(admin-api 티켓 02)과 같은 논증이다. 반대로 이 티켓 뒤의 main은 아직 없는 채널을 위해 토큰을 요구하는 더 엄한 상태이고, 그것은 시끄러운 쪽이다.

근거는 ADR 0015, ADR 0011과 그 2026-09-24 이력 "미들웨어가 접두사로 토큰을 가르고 채널은 자기 토큰을 쓴다", ADR 0016.

**Blocked by:** 01

**Status:** done

- [x] 인증 미들웨어가 접두사→토큰 표를 받는 일반형이 되고 표는 `server`가 넘긴다. 미들웨어는 여전히 앱 전체에 걸리고 라우트가 보호를 opt-in하지 않는다. 표에 없는 경로의 기본값은 관리 토큰이다 — 새 채널 경로를 `/runs` 밖에 두는 실수는 틀린 토큰으로 막힐 뿐 열리지 않는다
- [x] **접두사 비교는 경로 조각 단위다.** `/runs`와 `/runs/…`는 채널이고 `/runsx`는 아니다. `/runsx`는 채널 토큰으로 401이고 관리 토큰으로는 401이 아니다(라우트가 없으니 404). 이 대조가 판정한다
- [x] `/runs` 아래의 **영구히 라우트가 없는 경로**가 관리 토큰으로 401, 채널 토큰으로 404다. 03·04가 붙일 `/runs`와 `/runs/{run_id}/approval`을 쓰지 않는 이유는, 라우트가 붙는 순간 이 테스트가 빨개져 원칙 II에 따라 그 티켓이 멈추기 때문이다(명세 검토). 지금의 서버 테스트가 대조에 문서에 없는 `/unrouted`를 쓰는 것과 같은 이유다. 관리 경로 전부(`app.openapi()`가 아는 것)가 채널 토큰으로 401이다. **열거가 비어 있으면 실패한다** — 지금의 전수 테스트가 두는 가드와 같다. 채널 쪽 전수 열거는 채널 라우트가 생기는 03이 같은 가드와 함께 더한다
- [x] `PUBLIC_PATHS`는 `/health` 하나 그대로이고 그것을 고정하는 테스트가 그대로 초록이다. 채널이 붙었다고 allowlist가 자라지 않는다
- [x] 채널 토큰의 비교도 값에 따라 시간이 달라지지 않는다. 두 토큰의 비교는 같은 코드 한 곳을 지난다. 상수 시간 비교 자체는 바깥 행동이 아니라 테스트로 단언하지 않고 리뷰가 확인한다
- [x] `create_app`이 채널 토큰을 받는다. 빈 채널 토큰과 같은 두 토큰을 거부한다 — 지금 빈 관리 토큰을 거부하는 그 자리에서. 진단과 종료 코드로 운영자에게 말하는 것은 `serve`의 몫이고, 여기서는 그런 앱이 만들어지지 않는다는 것까지다
- [x] `serve`가 채널 토큰을 환경변수로만 받는다(ADR 0011의 규칙을 그대로 적용). 없거나 공백뿐이면, 두 토큰이 같으면 진단을 내고 실패 종료 코드로 끝나며 서버가 뜨지 않는다. 공백만 있는 토큰을 없는 것으로 보는 규칙과 통과한 토큰을 다듬지 않고 넘기는 규칙은 관리 토큰과 같다
- [x] **구성 오류는 모아서 한 번에 나온다.** 관리 토큰 없음, 채널 토큰 없음, 루프백 아님이 한 실행에 함께 나온다. 두 토큰의 값은 어느 진단에도 없고, "두 토큰이 같다"는 진단도 값을 싣지 않는다(원칙 V)
- [x] 통과하면 `create_app`이 두 토큰을 받는다. 구성 오류와 `create_app`에 넘긴 것을 재는 조립 테스트가 선례다
- [x] `.env.example`에 채널 토큰 줄이 는다. 없으면 예시 파일대로 채운 운영자의 `serve`가 이 티켓 뒤로 뜨지 않는다(명세 검토)
- [x] 토큰은 이벤트에도, 서버 기록 한 줄에도, 에러 봉투에도 실리지 않는다
- [x] 인증 모듈 독스트링의 "`http-channel` 은 이 결정을 물려받지 않는다"로 시작하는 문단이 이제 결정된 것(ADR 0015)을 말한다. HTTP 층 rules 파일의 인증 문장이 두 토큰과 접두사 표를 안다. 옛 표현의 잔존을 grep해 0인지 본다
- [x] 검사 넷이 초록이다
