# 05: 실제 `serve`로 멈추고 HTTP로 승인해 끝까지 간다

**What to build:** 실제 `agent-os serve` 프로세스에 실제 모델과 실제 stdio 도구 서버를 붙인다. 그 위에서 세 단계를 한 번에 본다. HTTP로 일으킨 실행이 승인 대상에서 멈추고, HTTP로 보낸 승인으로 재개되고, 올바른 답으로 끝난다. 이 테스트는 가짜로 증명할 수 없는 것만 잰다. `main.py`의 조립, uvicorn이 실제 소켓으로 SSE를 흘리는 것, 실제 모델이 채널을 지나는 것, 멈춘 실행이 요청을 건너 트레이스로 재개되는 것이다.

interrupts 티켓 06(멈춘 실행이 프로세스를 넘어 산다)과 같은 자리의 티켓이다. 01~04는 가짜 포트로 닫히고, 이 티켓이 그 위에 실제 경로 하나를 긋는다.

근거는 명세의 "바깥 이음매 — 실제 `serve`와 실제 모델" 절과 `docs/constitution/operations.md`의 LLM 테스트 규약.

- [x] 트레이스는 실행 하나에 파일 하나다. 결정, `run_resumed`, 도구 호출이 그 순서로 있다
- [x] 프레임을 가를 때 keepalive 주석은 건너뛴다. 모델 호출이 keepalive 간격을 넘는 날에도 테스트가 흔들리지 않는다(명세 검토)

- [x] 프리어 아트는 조립 테스트 파일에 있는 `-m llm` 테스트 둘이다. 하나는 실제 프로세스를 띄우고, 다른 하나는 멈춘 실행을 다른 프로세스가 재개한다. 서버가 설 때까지 기다리는 방식은 이 티켓이 정한다
- [x] 검사 넷과 `uv run --env-file .env pytest -m llm`이 초록이다

## Comments

- 2026-09-26(구현): 서버가 설 때까지 기다리는 방식. `--port 0`으로 띄우고 uvicorn의 기동 줄(`Uvicorn running on …`)에서 고른 포트를 읽는다. 그 줄은 앱의 수명이 열리고 소켓이 듣기 시작한 뒤에 찍혀서 헬스 체크를 되풀이하지 않고, 미리 고른 포트를 남이 가져갈 틈도 없다. 대가는 uvicorn의 기동 문구에 기대는 것이고 문구가 바뀌면 "서지 않았다"는 실패가 된다. 출력은 파이프가 아니라 파일로 받고, 나갈 때 표준 에러로 옮겨 실패한 테스트의 캡처에 서버 쪽 원인이 실린다.
- 2026-09-26(구현): 정리는 `terminate` → `wait` → `kill`이다. Windows에서 venv의 `python.exe`는 실제 인터프리터를 자식으로 띄우는 런처인데, 런처를 거두면 자식도 함께 끝났다. 변이 셋으로 쟀다 — 서버가 선 뒤 실패(남은 프로세스 0), 도구 서버가 `ListToolsRequest`를 처리한 뒤 모델 호출 도중 실패(도구 서버까지 0), 정리를 뺀 대조군(런처와 인터프리터가 남음).
- 2026-09-26(구현): 초록으로 시작한 테스트라 반증으로 이빨을 쟀다(interrupts 06과 같은 자리). `main.py`가 트레이스 디렉터리를 엉뚱한 곳으로 넘기면 빨강이다. keepalive 건너뛰기는 실제 모델로 부를 수 없어 기본 스위트의 테스트 하나가 FastAPI의 `KEEPALIVE_COMMENT` 바이트로 잰다.
