# 05: 실제 `serve`로 멈추고 HTTP로 승인해 끝까지 간다

**What to build:** 실제 `agent-os serve` 프로세스에 실제 모델과 실제 stdio 도구 서버를 붙인다. 그 위에서 세 단계를 한 번에 본다. HTTP로 일으킨 실행이 승인 대상에서 멈추고, HTTP로 보낸 승인으로 재개되고, 올바른 답으로 끝난다. 이 테스트는 가짜로 증명할 수 없는 것만 잰다. `main.py`의 조립, uvicorn이 실제 소켓으로 SSE를 흘리는 것, 실제 모델이 채널을 지나는 것, 멈춘 실행이 요청을 건너 트레이스로 재개되는 것이다.

interrupts 티켓 06(멈춘 실행이 프로세스를 넘어 산다)과 같은 자리의 티켓이다. 01~04는 가짜 포트로 닫히고, 이 티켓이 그 위에 실제 경로 하나를 긋는다.

근거는 명세의 "바깥 이음매 — 실제 `serve`와 실제 모델" 절과 `docs/constitution/operations.md`의 LLM 테스트 규약.

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] `-m llm` 테스트 하나다. 실제 `agent-os serve`를 서브프로세스로 빈 포트에 띄운다. 임시 플러그인 루트에는 승인 대상을 가진 계산 에이전트(`gatedcalc`)와 실제 stdio 도구 서버를 둔다. 두 토큰은 테스트가 지은 서로 다른 값을 환경변수로 준다
- [ ] `POST /runs`의 스트림이 `run_paused`로 끝나면, 그 실행 식별자로 승인을 보낸다. 재개 스트림은 올바른 답을 담은 `run_finished`로 끝난다
- [ ] 트레이스는 실행 하나에 파일 하나다. 결정, `run_resumed`, 도구 호출이 그 순서로 있다
- [ ] 프레임을 가를 때 keepalive 주석은 건너뛴다. 모델 호출이 keepalive 간격을 넘는 날에도 테스트가 흔들리지 않는다(명세 검토)
- [ ] 키가 없으면 skip이 아니라 실패한다. 기본 실행에서는 빠진다. 테스트가 실패해도 서버 프로세스가 남지 않게 정리한다
- [ ] 프리어 아트는 조립 테스트 파일에 있는 `-m llm` 테스트 둘이다. 하나는 실제 프로세스를 띄우고, 다른 하나는 멈춘 실행을 다른 프로세스가 재개한다. 서버가 설 때까지 기다리는 방식은 이 티켓이 정한다
- [ ] 검사 넷과 `uv run --env-file .env pytest -m llm`이 초록이다
