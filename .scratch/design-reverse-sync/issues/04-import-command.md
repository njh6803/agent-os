# 04: 들이기 명령 — 웹·기준본·코드를 셋으로 맞대 값과 설명은 디자인 토큰 CSS의 그 줄로 옮기고, 명암비에 걸리면 가장 가까운 통과 값을 낸다

**What to build:** 스크립트의 들이기 명령이 웹의 `tokens.json`, 기준본(입력 파일), 지금 디자인 토큰 CSS를 받아 토큰·벌마다 셋으로 맞댄다. 웹만 바뀐 값 바꾸기(원색, 반투명, 글자 크기·줄 높이·굵기, 간격, 모서리)와 설명 고침은 디자인 토큰 CSS의 그 줄로 옮기고, 나머지는 사람에게 물을 목록으로 낸다. 옮긴 뒤의 여덟 벌로 짝 표를 판정하고, 걸리면 걸린 짝, 실제 명암비, 통과하는 가장 가까운 값을 보고에 낸다. 사람이 고른 답(웹 값, 코드 값, 제안 값)을 입력 파일로 다시 주면 그 값으로 옮긴다. 보고 JSON은 무엇을 어느 벌에서 무엇으로 옮겼는지와 hex로 바꾼 값을 든다(스토리 6·7·8). 대응 바꾸기, 일부 벌만 바꾼 값, 코드와 웹이 함께 바꾼 값은 옮기지 않고 묻는다(스토리 9·10·11).

근거는 `.scratch/design-reverse-sync/spec.md`의 "거꾸로 동기화"(티켓과 티켓의 절은 07)와 그 2026-10-22 주석(색 변환), "겹침" "병합됐으면"의 2026-10-22 주석의 셋째(이어받는 들이기의 기준본), Testing Decisions의 "왕복"·"옮기기와 묻기"·"판정과 제안"이다. 결정은 ADR 0025의 2026-10-21 이력("옮기는 규칙")이다.

01(명암비 모듈)과 02(스크립트의 뼈대, 짓기, 맞대기)를 쓴다. 05와 나란히 돌고, 겹치는 곳은 진입 파일의 명령 표 한 줄이다. 뒤에 병합하는 쪽이 main을 합쳐 그 줄을 푼다. 이 티켓은 07을 막는다.

**Blocked by:** 01, 02

**Status:** ready-for-agent

### 셋 맞대기와 옮기기

- [ ] **기준본은 입력 파일로 받는다.** 보통은 기록의 기준본이고, 병합된 `claim`을 이어받는 들이기에서는 이어받는 `claim`에 든 기준본(지금 웹의 `tokens.json`에서 확인이 더 고친 몫으로 낸 토큰·벌만 앞 `claim`의 사본 값으로 바꾼 것, 06의 확인 명령이 낸다)이다. 고르는 것은 07의 스킬이고, 명령은 어디서 온 기준본인지 모른다
- [ ] **토큰·벌마다 네 갈래로 가른다.** 웹만 바뀌었으면 웹 편집, 코드만 바뀌었으면 들일 것이 없음, 둘 다 같은 값으로 바뀌었으면 이미 들인 것, 둘 다 다르게 바뀌었으면 묻는 목록("웹 값", "코드 값", "웹에서 다시 고친다")이다
- [ ] **한 값을 나누는 벌은 모두 같은 값으로 바뀌었을 때만 옮긴다.** 원색은 같은 테마의 라이트·다크, 반투명은 여덟 벌 모두다. 일부만 바뀌었으면 묻는다
- [ ] **설명 고침은 그 줄의 주석으로 옮기고, 보고에 전과 후를 낸다.** `*/`나 줄바꿈이 든 설명은 그 토큰만 묻는다
- [ ] **hex가 아닌 값.** `rgb()`·`rgba()`·`hsl()`·`hsla()`·`oklch()`·`oklab()`은 sRGB 안이면 hex(투명도가 1이 아니면 8자리)로 바꿔 옮기고 바꾼 값을 보고에 적는다. 3·4자리 hex는 6·8자리로 펴서 옮긴다. sRGB 밖, `lab()`·`lch()`·`color()`, 별칭으로 바뀐 원색과 반투명은 묻는다
- [ ] **색 변환은 의존성을 더하지 않고 스크립트 안에서 계산한다**(명세 "가장 가까운 값"의 2026-10-22 주석). 알려진 값의 변환과 hex 왕복을 시험으로 본다
- [ ] **크기 값.** px, 단위 없는 수(px로 읽는다), `0`만 옮기고, `rem`·`em`·`%`, 단위 없는 줄 높이, 굵기 범위는 묻는다
- [ ] **묻는 것.** 쓰임새 토큰의 대응 바꾸기(별칭이 아닌 값으로 바꾼 것 포함), 토큰 더하기·지우기·이름 바꾸기(이름 바꾸기일 수 있다고 함께 적는다), 글자 스타일의 다른 칸, 새 계열, 계열 설명은 옮기지 않고 묻는 목록에 낸다. 사람이 들이기로 고른 묻는 것은 스크립트가 아니라 들이기 세션이 고친다(07의 스킬)
- [ ] **고친 디자인 토큰 CSS가 Prettier의 포맷 검사를 지난다**(`pnpm -C web verify`의 `format`)

### 판정과 제안

- [ ] **옮긴 뒤의 여덟 벌을 01의 모듈로 판정한다.** 짝 표와 공식을 다시 쓰지 않는다
- [ ] **걸린 짝마다 실제 명암비와, 그 짝에 든 바뀐 원색 하나마다 가장 가까운 통과 값을 낸다.** 다른 바뀐 값은 들인 채로 OKLCH 밝기만 0.001씩 양쪽으로 옮겨 sRGB 안의 첫 hex 가운데 그 원색이 드는 여덟 벌의 모든 짝을 통과하는 것이다. 밝기 차이가 같으면 밝은 쪽이다. 반투명은 투명도를 1/255씩 옮긴다. 없으면 "통과하는 값이 없다"다
- [ ] **사람이 고른 답 파일을 받아 다시 돌면 그 값으로 옮긴다.** 제안 값을 고른 토큰은 제안 값, 코드 값을 고른 토큰은 그대로다. 같은 입력과 답에는 같은 결과다

### 시험과 검증

- [ ] **지금 디자인 토큰 CSS의 여덟 벌을 판정하면 걸린 짝이 없다.** 01이 합성 값으로만 본 판정을 실제 값으로 잇는다
- [ ] **왕복**: 지은 `tokens.json`을 그대로 들이면 바뀌는 것이 없다. 값 하나를 바꿔 들인 디자인 토큰 CSS로 다시 지으면 웹 값과 같다
- [ ] **옮기기와 묻기의 사례**(명세 Testing Decisions): 원색 한 벌, 원색의 라이트·다크 함께, 반투명 첫 테마만, 반투명 일부 벌, 크기 px와 rem, `oklch()`, sRGB 밖의 값, 별칭, 대응 바꾸기, 더하기, 지우기, 셋 맞대기의 네 갈래, 설명 고침, `*/`가 든 설명. 각 사례가 옮겼는지와 묻는 종류를 보고와 출력 파일로 본다
- [ ] **이어받는 기준본의 사례**: 앞 들이기에서 사람이 "코드 값"을 고른 토큰은, 이어받는 기준본을 주면 코드만 바뀐 것으로 보여 다시 들어오지 않는다. 더 고친 몫이 아닌 토큰(열린 PR 때 "덮어쓴다"가 옛 코드로 되돌린 토큰 포함)은 웹과 기준본이 같아 들어오지 않는다. 더 고친 몫은 들어온다(명세 "병합됐으면"의 2026-10-22 주석)
- [ ] **판정과 제안의 사례**: 녹청 다크의 글자 원색을 바탕에 가깝게 바꾸면 보고가 걸린 짝과 제안 값을 낸다. 제안 값으로 다시 들이면 걸린 짝이 없고, 제안 값에서 밝기를 0.001 덜 옮긴 값은 걸린다. 통과하는 값이 없는 사례도 둔다
- [ ] **원칙 III를 지킨다**
- [ ] 검증 명령이 모두 초록이다
- [ ] **기능을 닫지 않는다**
