# 02: `tokens.json` 짓기와 값으로 맞대기 — 디자인 토큰 CSS에서 여덟 벌의 `tokens.json`을 짓고, 페이지가 다시 쓴 꼴도 같은 값으로 읽는다

**What to build:** `web/tools`의 TypeScript 스크립트 하나가 서고, 그 첫 명령(짓기)이 디자인 토큰 CSS(`web/packages/ui/src/styles/theme.css`)에서 Design System 형식의 `tokens.json`을 짓는다. 테마 넷 × 모드 둘의 여덟 벌, 색·글자 크기·간격·모서리 112개이고, 설명은 그 토큰을 선언한 줄 끝의 주석이다. 같은 입력에는 바이트까지 같은 결과가 나온다. 같은 스크립트의 공용 모듈이 `tokens.json` 두 벌을 맞대는 몫(토큰·벌마다의 값과 설명, 글자 스타일의 모든 칸, 계열 설명, 계열과 토큰의 목록)으로 맞대 차이 목록을 낸다. 페이지가 저장하며 꼴만 다시 쓴 `tokens.json`(문자열 색 값을 첫 테마의 객체로, 빈 설명 칸, 소문자)은 차이가 없다. 또 이 티켓은 편집을 켠 임시 디자인 시스템 아티팩트에서 페이지가 실제로 저장한 `tokens.json`을 받아 시험 사례로 두고, `force` 없이 보낸 낡은 판의 `publish`가 거부되는지 손으로 본다(사용자가 추천을 골랐다).

근거는 `.scratch/design-reverse-sync/spec.md`의 "이음매"와 그 2026-10-22 주석(명령마다 모듈), "tokens.json", "토큰 설명의 자리"(자리만. 주석 112개는 03), "기록"의 2026-10-22 주석의 넷째(맞대는 값 함수의 `tokens.json` 몫), "편집 켜기와 사람의 확인"의 2026-10-22 주석(임시 아티팩트에서 손으로 보기), "겹침" 첫 항목의 2026-10-22 주석(`baseVersion` 거부), Testing Decisions의 "스크립트"·"짓기"·"왕복"의 셋째 문장이다. 결정은 ADR 0025의 2026-10-21 이력이다.

01과 파일이 겹치지 않아 나란히 돈다. 그래서 이 티켓은 `web/package.json`을 고치지 않는다(01이 의존 한 줄을 더한다). 스크립트를 부르는 `web/package.json`의 스크립트 줄이 필요하면 07이 스킬과 함께 더한다. 이 티켓은 03·04·05를 막는다.

**Blocked by:** None (can start immediately)

**Status:** done

### 스크립트의 뼈대

- [x] **진입 파일 하나가 명령 표로 명령을 고르고, 명령마다 모듈 하나를 둔다.** 디자인 토큰 CSS를 푸는 것, `tokens.json`의 모델, 두 벌의 차이는 공용 모듈이다. 04(들이기)와 05(기록과 확인)가 나란히 돌며 각자 모듈 하나와 명령 표의 한 줄만 더하게 하려는 것이다(명세 "이음매"의 2026-10-22 주석)
- [x] **명령의 입력과 출력은 파일이고, 보고는 기계가 읽는 JSON 하나다.** 실패는 0이 아닌 종료 코드와 그 JSON의 오류 칸이다

### 짓기

- [x] **형식의 문법을 원문에서 읽고 짓는다.** 형식 설명(`artifact-type/reference/format.md`, 명세가 대 본 사본은 아티팩트 판 `1792564314-af13`, sha256 `0b8f13f4…`)의 "tokens.json grammar"와 caps 줄이다. 테마의 표시 이름 칸은 형식 설명에서 보지 못했으므로 페이지 스크립트(`app.js`)에서 칸 이름을 보고, 받으면 `CONTEXT.md`의 한국어 이름(녹청 라이트 등)을 단다. (구현 메모: 판 `1792564314-af13`의 `app.js`는 `color.themes[]`의 `name`을 표시 이름으로 읽어 120자에서 자르고, 받은 저장본도 그 칸을 지켰다. `CONTEXT.md`에는 테마의 한국어 이름이 없어, 패키지의 테마 목록 `web/packages/ui/src/themes.ts`의 이름을 `build.ts`에 옮겼다)
- [x] **테마 여덟의 id는 `<테마>-<모드>`이고 첫째가 `nokcheong-light`, 그다음 녹청 다크, 군청·자초·쪽빛의 라이트·다크 순이다**
- [x] **원색 68개는 여덟 벌의 값을 모두 적고, 반투명 7개는 문자열 하나, 쓰임새 토큰 23개는 벌마다 그 벌의 대응(군청·자초의 주 버튼 덮기 포함)이 가리키는 원색이나 반투명을 `{이름}`으로 적는다.** hex는 소문자다
- [x] **글자 크기는 `type` 묶음 하나에 스타일 셋(`text-title`, `text-small`, `text-badge`)이다.** 스타일마다 크기·줄 높이·굵기를 디자인 토큰 CSS의 값 그대로 내고 설명은 `usage` 칸에 낸다. 글꼴 묶음(`type.families`)에는 `--sans` 값 하나를 `sans` 키로 내고 묶음이 그것을 가리킨다. `type.fonts`는 내지 않는다
- [x] **간격 7개와 모서리 4개를 이름과 px 값 그대로 내고 계열 설명(`note`)은 비운다.** 밀도와 이름 있는 치수는 내지 않는다
- [x] **한도(테마 8, 색 600, 다른 계열 60)를 넘는 입력은 오류다**
- [x] **설명은 명세 "토큰 설명의 자리"의 줄 끝 주석에서 읽는다.** 지금 디자인 토큰 CSS에는 그 주석이 대부분 없어 설명이 빈 칸으로 나온다. 주석을 다는 것은 03이다

### 값으로 맞대기

- [x] **`tokens.json` 두 벌을 맞대는 몫으로 맞대 차이 목록을 내는 공용 함수를 둔다.** 맞대는 몫은 토큰·벌마다의 값과 설명, 글자 스타일의 모든 칸, 계열 설명(`note`), 계열과 토큰의 목록이다(명세 "맞대는 것"의 2026-10-22 주석). 차이마다 어느 토큰·벌이나 계열인지, 종류(값, 설명, 글자 스타일의 다른 칸, 계열 설명, 더한 것, 지운 것), 전과 후를 낸다. 04와 05가 이것을 쓴다
- [x] **`tokens.json`의 맞대는 값(위 맞대는 몫을 정규 꼴로 적은 것의 sha256)을 내는 함수를 둔다.** 기록·`pending`·`claim`·확인이 모두 이 함수를 쓴다(명세 "기록"의 2026-10-22 주석의 넷째). README와 바이트 파일의 몫은 05가 더한다
- [x] **페이지가 꼴만 다시 쓴 같은 내용은 차이가 없고 맞대는 값도 같다**

### 임시 아티팩트에서 재기

바깥 상태를 만드는 일이라, 아티팩트를 만들기 전에 사람에게 무엇을 만들고 무엇을 해 달라고 할지 보이고 승인을 받는다. 결과는 `.scratch/design-reverse-sync/probes/README.md`에 "스크립트로 다시 낼 수 없는 도구와 브라우저 조작"으로 손으로 본 것을 적는다(선례 `.scratch/design-artifacts/probes/README.md`).

- [x] **`claude auth status`로 Claude Code의 계정을 보고, 그 계정에서 Design System 형식으로 비공개 임시 아티팩트를 만든다.** 형식 목록에 그 형식이 없으면 멈추고 사람에게 묻는다(이 계정에서 만들 수 있는지는 대 보지 않았다). 사람이 웹에서 고칠 수 있는 계정(주인이거나 편집자로 수락한 계정)도 함께 정한다
- [x] **편집을 켠 채 이 티켓이 지은 `tokens.json`을 올리고, 사람이 페이지에서 녹청 라이트 원색 하나의 값과 설명 하나를 고쳐 저장한다.** 받은 `tokens.json`을 이 기능의 시험 자료로 커밋하고, 맞대기의 차이가 사람이 고친 둘뿐인지 시험으로 본다. 모양이 명세의 문법 읽기와 다르면 다른 점을 명세 Testing Decisions "확인"의 사례로 더할 것으로 05에 넘긴다(받는 05의 Blocked by에 02가 있다)
- [x] **사람 몫만 든 README 하나를 함께 올리고, 저장 뒤 받은 README에 페이지가 생성 몫을 붙였는지 본다.** 붙였으면 받은 파일을 05의 시험 자료로 커밋한다(명세 "맞대는 것"의 2026-10-22 주석의 구분선과 생성 머리). 붙이지 않았으면 그렇게 적고, 05는 페이지 스크립트의 함수로 지은 사례를 쓴다
- [x] **고치지 않고 페이지를 여는 것만으로 저장되는지 본다.** 열기 전후의 판 id와 `tokens.json`의 sha256을 맞댄다
- [x] **`force` 없이 보낸 낡은 판의 `publish`가 거부되는지 본다.** 세션이 읽은 뒤 사람이 페이지에서 저장하고, 세션이 앞서 읽은 판을 기준으로 다른 파일 하나를 `publish`한다. 거부되면 그 문구와 건네받은 판을, 거부되지 않으면 그대로 적는다. 거부되지 않으면 명세 "겹침"의 다시 읽기가 유일한 방어라는 것을 06·07에 넘긴다(받는 둘의 Blocked by에 02가 이어져 있다)
- [x] **끝나면 임시 아티팩트를 지운다.** 지우기는 사람이 확인한다

### 시험과 검증
