# 05: 기록과 확인 명령 — 올린 뒤의 기록을 짓고, 아티팩트에서 받은 파일을 기록과 맞대 웹 편집이 있는지 가른다

**What to build:** 스크립트의 기록 명령이 올리기가 보낸 것과 지운 것을 앞 기록에 합쳐 아티팩트의 기록(`project/sync-record.json`)을 짓는다. 여러 호출로 나뉜 올리기의 첫 호출에는 `pending`이 든 기록을, 마지막 호출에는 `pending` 없는 기록을 낸다. 확인 명령은 아티팩트에서 받은 폴더(`tokens.json`, 색인, 기록, 마크다운, `pending`이 든 경로)와 지금 코드에서 지은 `tokens.json`을 받아 결과 다섯 가운데 하나를 낸다. 웹 편집 없음, 웹 편집 있음(토큰과 토큰 밖을 가른 목록), 들이는 중(06이 채운다), 기록 전, 판단할 수 없음(까닭)이다. 첫 올리기 뒤에 기록이 없어졌거나 읽히지 않으면 판단할 수 없음이라 올리기가 덮어쓰지 않고 멈춘다(스토리 32). 중간에 멈춘 올리기가 보낸 파일과 아직 보내지 않은 파일은 웹 편집으로 보이지 않는다(스토리 30). 같은 명령의 공용 함수가 이번 올리기가 보낼 파일·지울 경로와 빌드가 필요한지를 낸다(스토리 31).

근거는 `.scratch/design-reverse-sync/spec.md`의 "기록"과 그 2026-10-22 주석 둘(넷을 더한 것, 크기), "확인"과 그 2026-10-22 주석 둘(생성 절, 편집이 꺼진 색인), "올리기"의 빌드가 필요한 올리기·필요 없는 올리기·첫 올리기와 그 2026-10-22 주석, Testing Decisions의 "확인"과 "기록"(`claim`의 사례는 06)이다. 결정은 ADR 0025의 2026-10-21 이력 "명세가 정할 것 (1)·(4)"다.

02의 뼈대와 맞대기를 쓴다. 04와 나란히 돌고, 겹치는 곳은 진입 파일의 명령 표 한 줄이다. 이 티켓은 06을 막는다. 02가 임시 아티팩트에서 손으로 본 결과가 저장 꼴의 다른 점이나 `publish` 거부의 결과를 넘겼으면 이 티켓이 받는다.

**Blocked by:** 02

**Status:** ready-for-agent

### 맞대는 값

- [ ] **파일 종류마다 맞대는 값을 내는 함수 하나를 기록·`pending`·확인이 함께 쓴다.** `tokens.json`은 02의 함수, README는 페이지가 사람 몫과 생성 몫을 가르는 함수(판 `1792564314-af13`의 페이지 스크립트)를 옮겨 구분선 앞의 사람 몫만 잰 sha256, 나머지는 바이트의 sha256이다(명세 "기록"의 2026-10-22 주석의 넷째와 "맞대는 것"의 2026-10-22 주석). "## Consuming"부터만 떼면 구분선이 남아 생성 몫만 붙은 README가 웹 편집으로 보인다. 옮긴 함수의 주석에 옮겨 온 판 id를 남겨, 페이지가 생성 머리를 바꿔 모든 README가 웹 편집으로 보이는 날 어디서 왔는지 찾게 한다. `claim`의 해시(06)도 이 함수를 쓴다

### 기록 명령

- [ ] **기록이 드는 것은 명세대로다.** 꼴 판 `v`(1), 올린 main 커밋과 시각, `project/` 아래 파일마다의 맞대는 값과 바이트 수, 기준본(마지막으로 올린 `tokens.json`의 내용 그대로), 색인의 그림과 문서 목록(`assetGroups`, `blobs`, `docs`, `sections`), `pending`, `claim`이다. 이 티켓은 `claim` 칸을 받은 그대로 지킨다. 넣고 비우는 것은 06이다
- [ ] **빼는 것.** 기록 자신, 페이지가 저장할 때 다시 짓는 파일(`tokens.css`, `api/*.md`, `manifest.json`)은 해시하지 않고, 색인은 목록만 적는다
- [ ] **앞 기록에 이번에 보낸 것과 지운 것을 합친다.** 해시는 보낸 파일의 로컬 바이트로 잰다
- [ ] **여러 호출의 첫 기록.** `pending`에 이번에 보낼 파일의 목표 해시, 지울 경로, 색인 목록의 목표를 넣고 파일 해시와 기준본은 앞 기록 그대로 둔다. 마지막 기록은 `pending`을 비운다. 다시 한 올리기가 목표와 같아 보내지 않은 파일도 새 `pending`과 마지막 기록에 목표 해시로 넣는다
- [ ] **들여쓰기 없는 JSON으로 쓰고, 512 KB를 넘는 기록은 쓰지 않고 오류로 멈춘다.** 형식 설명이 KB의 단위를 밝히지 않으면 작은 쪽(512,000바이트)으로 보고, 시험이 그 경계를 바이트로 못 박는다

### 확인 명령

- [ ] **결과 다섯을 낸다.** 들이는 중은 06이 채우고, 이 티켓에서 `claim`이 든 기록은 06이 들어올 때까지 판단할 수 없음(까닭: `claim`을 가르지 못한다)으로 낸다. 편집이 꺼진 동안은 `claim`이 쓰이지 않는다
- [ ] **색인이 `editing: "off"`를 들면, 기록도 `tokens.json`도 없을 때는 기록 전이고 그 밖(기록이 있거나, 기록만 없거나 읽히지 않는 것)은 웹 편집 없음이다.** 기록이 없거나 읽히지 않으면 보낼 것은 아래 함수가 아티팩트의 sha256과 맞대 고른다
- [ ] **편집이 켜진 뒤 기록이 없거나, JSON으로 풀리지 않거나, 꼴 판을 모르면 판단할 수 없음이다**
- [ ] **읽기 실패는 스킬이 넘긴 까닭으로 가른다.** 확인 명령은 경로마다 "없다는 까닭으로 읽지 못했다"와 "다른 까닭으로 읽지 못했다"를 입력 파일로 받는다. 앞의 것만 그 파일이 없다는 뜻이고, 뒤의 것은 판단할 수 없음이다
- [ ] **`tokens.json`은 기준본과 02의 맞대는 몫(토큰·벌마다의 값과 설명, 글자 스타일의 모든 칸, 계열 설명, 계열과 토큰의 목록)으로, 마크다운은 맞대는 값으로, 색인은 그림과 문서 목록으로 맞댄다**
- [ ] **`pending`이 있으면 파일마다 목표 해시, 앞 해시 차례로 맞대고 어디와도 다르면 웹 편집이다.** `pending`의 지울 경로가 웹에 없으면 그 올리기가 지운 것이다. 색인 목록은 `pending`의 목표와도 맞댄다. `tokens.json`이 목표와도 기준본과도 다르면 기준본과 맞댄 목록을 내고 멈춘 올리기가 보낸 값이 섞일 수 있다는 표시를 단다
- [ ] **스킬이 받을 경로를 낸다.** 첫 받기(`tokens.json`, 색인, 기록)의 뒤에 받을 경로(기록에 든 마크다운 가운데 `api/` 밖, 색인의 `docs`, 컴포넌트마다의 README, `pending`이 든 경로)를 확인 명령이나 그 공용 함수가 낸다. 스킬이 그 목록을 손으로 짓지 않는다

### 보낼 것과 빌드

- [ ] **보낼 파일과 지울 경로를 내는 함수를 둔다.** 입력은 기록, 이번 산출의 로컬 파일, 코드의 판으로 되돌릴 파일과 웹에서 더한 경로(사람이 "덮어쓴다"를 고른 확인이 찾은 것. 병합된 `claim`이 든 것은 06이 더한다)다. 맞대는 값이 기록과 다른 파일과 되돌릴 파일을 보내고, 지난 산출에 있었고 이번 산출에 없는 경로와 웹에서 더한 경로를 지운다(명세 "찾았을 때"의 "덮어쓴다"). 기록이 없으면 아티팩트에서 받은 sha256과 맞대 고른다(첫 올리기와 편집이 꺼진 동안 기록을 잃은 때)
- [ ] **빌드가 필요한지 가르는 함수를 둔다.** 입력은 기록의 커밋 뒤에 바뀐 경로(스킬이 `git diff --name-only`로 넘긴다)와 되돌릴 파일이다. `web/packages/ui` 아래나 빌린 빌드의 설정(`.design-sync` 아래의 설정과 포크 파일. `foundations/`와 `NOTES.md`는 뺀다)이 바뀌었거나, 되돌릴 파일 가운데 빌드가 짓는 파일이 있으면 빌드가 필요하다. `tokens.json`, 기록, 원본을 그대로 옮기는 다섯(`foundations/`의 기초 카드 넷과 `web-design.md`)만 바뀌면 필요 없다

### 시험과 검증

- [ ] **확인의 사례**(명세 Testing Decisions "확인"과 그 2026-10-22 주석에서 `claim`이 든 것을 뺀 것): 웹 편집 없음, 토큰 웹 편집, README에 페이지가 구분선과 생성 몫("## Consuming" 머리와 "## Quick start" 머리 각각)만 붙인 것(02가 받은 실제 꼴이 있으면 그것), 마크다운 편집, 색인의 그림 목록 변화, `pending`이 있고 목표 해시와 같은 파일, 앞 해시와 같아 아직 보내지 않은 파일, 둘 다와 다른 파일이 섞인 것, `pending`의 지울 경로가 지워진 것과 아직 있는 것, 편집이 꺼진 색인에 기록이 있는 것(앞 해시가 없는 첫 올리기의 멈춤 포함), 편집이 꺼진 색인에 기록은 없고 `tokens.json`은 있는 것, 페이지가 꼴만 다시 쓴 아직 보내지 않은 `tokens.json`, 보낸 뒤 더 고친 `tokens.json`, 목표 해시와 앞 해시가 같은 파일, 생성 절이 든 README의 기록 해시, 기록 전, 기록이 없는 편집 켜진 상태, 풀리지 않는 기록, 모르는 꼴 판, 없다는 까닭이 아닌 읽기 실패, 02가 임시 아티팩트에서 받은 저장 꼴
- [ ] **기록의 사례**: 앞 기록에 보낸 것과 지운 것을 합치는 것, 빼는 파일과 색인 목록, `pending`이 마지막 기록에서 비는 것, 목표와 같아 보내지 않은 파일이 새 `pending`과 마지막 기록에 목표 해시로 드는 것, 1,024개 파일, 기준본, `pending`, `tokens.json` 사본과 이어받은 기준본 크기의 `claim`(`tokens.json` 세 벌)을 든 합성 기록이 512 KB 이하인 것
- [ ] **보낼 것과 빌드의 사례**: 바뀐 파일만 보내는 것, 되돌릴 파일을 코드가 그대로여도 보내는 것, 지울 경로, "덮어쓴다"의 웹에서 더한 경로를 지우는 것, 기록 없이 아티팩트의 sha256과 맞대 고르는 것, 빌드가 필요한 바뀐 경로·필요 없는 바뀐 경로·빌드가 짓는 되돌릴 파일
