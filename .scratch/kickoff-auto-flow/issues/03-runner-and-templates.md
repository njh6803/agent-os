# 03: 진행 규율과 두 템플릿, 첫 시작의 진입점

**What to build:** 새 프로젝트 폴더에서 연 세션에 사람이 `/kickoff` 하나를 치면(처음 쓰는 기계면 런북 머리의 한 줄을 붙여 넣으면), 세션이 런북 clone의 진행 규율을 읽어 준비부터 8단계까지 차례로 진행한다. 02가 넣은 사람 몫 줄에서 멈춰 결정은 추천을 맨 앞에 둔 선택 화면으로, 허락은 무엇을 어디에 하는지 보인 선택 화면으로, 사람만 일은 확인 명령으로 대 본다. 진행은 새 프로젝트의 진행 파일에 남아, 세션이 끊기거나 압축된 뒤에도 첫 미완 단계부터 잇는다. 이 티켓은 진행 규율, 사용자 레벨 스킬의 원문, 진행 파일의 템플릿과 런북의 진입점을 넣는다. 실제로 돌려 보는 것은 04다.

진행 규율이 02보다 먼저 들어가면 멈출 줄이 없는 런북을 읽어, 8단계의 저장소 만들기와 보호와 PR이 허락 화면 없이 지나간다. ADR 0028의 허락 기준이 조용히 무효가 된다(명세 검토의 지적, 일지 2026-10-13-01). 그래서 02에 막힌다.

근거는 `.scratch/kickoff-auto-flow/spec.md`의 Solution, "파일과 자리", "첫 시작", "진행 규율이 정하는 것", "진행 파일의 모양", "8단계와 첫 PR", 변경 표의 행들(아래 "런북" 절이 든다), 스토리 1~3·15~32·34·35다. ADR 0028 "배치와 진행"과 두 2026-10-12 이력이 앞선 결정이다. 명세 검토 뒤 사용자가 고른 것(킥오프 동안 새 프로젝트의 스킬은 Skill 도구로 부르지 않고 Read로 읽어 따른다)이 진행 규율의 슬래시 명령 항목에 든다(일지 2026-10-13-01).

**Blocked by:** 02

**Status:** ready-for-agent

### 새 파일 셋

- [ ] **`kickoff/runner.md`(진행 규율).** 순서, 멈출 자리, 선택 화면, 진행 기록만 갖고 단계의 내용은 적지 않는다(ADR 0028). 명세 "진행 규율이 정하는 것"의 항목마다 대응하는 문단이 있다
  - 시작의 확인 셋. 사용자 레벨 스킬(아래 "첫 시작"), 런북 clone의 상태(경로, 브랜치, `HEAD`, `git -C <clone> --no-optional-locks status --porcelain`, `fetch` 뒤 `rev-list --left-right --count origin/main...HEAD`, `fetch`가 실패하면 지난 `origin/main`으로 센다고 보인다, main이 아니거나 뒤처지거나 앞서거나 고치다 만 파일이 있으면 결정. 그 답은 진행 파일 머리에 적고, 진행 파일이 있고 기록한 런북 커밋이 지금 `HEAD`와 같으면 상태를 보이기만 하고 다시 묻지 않는다), 작업 폴더(진행 파일이 없는데 커밋이 있는 저장소이거나 런북 clone 자신이면 시작하지 않는다)다. 진행 규율은 clone의 파일과 브랜치를 바꾸지 않는다
  - 진행 파일 찾기, 런북 판의 대조(이어 갈 때와 단계를 시작할 때마다. 같으면 묻지 않고, 다르면 `KICKOFF.md`와 `kickoff/`를 바꾼 커밋이 있을 때만 그 목록을 보이고 묻고, 기록한 커밋이 clone에 없으면 비교할 수 없다고 묻는다)
  - 단계를 읽는 법. 펜스 밖의 `^## ` 머리의 줄 번호를 찾아 지금 단계의 절만 Read의 `offset`·`limit`로 읽는다
  - 사람 몫의 처리. 멈추기 전에 진행 파일에 "대기"를 적는다. 결정, 허락, 사람만의 처리와 확인을 먼저 돌리는 것, 확인이 "없음"인 줄은 사람의 답을 적는 것이다. 확인이 "세션이 대화에 들어온 출력을 읽어 일지에 적는다"인 줄(`/context`)에서 출력이 대화에 들어오지 않으면 사람에게 값을 묻는다(명세 "단계마다의 사람 몫" 표 아래)
  - 런북이 사람에게 치라고 적은 슬래시 명령. 새 프로젝트의 스킬(2단계가 설치하고 7단계가 복사한 것)은 Skill 도구로 부르지 않고 그 `SKILL.md`를 Read로 읽어 따른다. 그 스킬이 다른 스킬을 부르라고 하거나 훅의 계기가 스킬을 부르라고 해도 Read로 읽는다. 압축 뒤 지금 단계를 다시 읽을 때 그 스킬 파일도 다시 읽는다. 사용자 레벨 스킬과 `/init`은 Skill 도구로 부른다(`init`이 목록에 없으면 `kickoff/claude-md-template.md`에서 쓴다). 어느 스킬이든 글로 물으라고 해도 결정은 선택 화면으로 올린다(스토리 20). 대화형 화면과 내장 명령은 사람만이다
  - 결정과 조사의 가름(조사는 서브에이전트, 선택 화면은 본 세션), 사람 몫이 아닌 멈춤(실패는 "막힘"과 결정, 같은 실패 두 번이면 원인 보고, 런북 어긋남은 진행 파일의 그 절과 결정, 런북 저장소는 고치지 않는다, 끊긴 단계는 처음부터 읽고 된 일은 확인해 건너뛴다)
  - 일지. 준비가 진행 파일과 함께 만들고, 고른 선택지는 질문과 고른 설명을 `> 사용자:` 인용으로 적는다. 커밋되는 billing 값의 규칙(02가 런북 준비 절에 적은 것)을 따른다. 킥오프 동안 `## 다음`은 8단계 끝에만 쓴다
  - 끝. 아래 "8단계와 첫 PR"의 4~6이다. `retro`와 `next-session`은 새 프로젝트의 스킬 파일을 Read로 읽어 따르고, `hook_journal_retro`의 계기에 기대지 않는다. 모든 단계가 끝남이나 건너뜀인데 첫 PR이 병합되지 않았으면(`gh pr view chore/kickoff --json state`) 6부터 잇는다
- [ ] **첫 시작**(명세 "첫 시작"). 시작할 때 `~/.claude/skills/kickoff/SKILL.md`가 있고 이 clone을 가리키는지 본다. 없으면 허락을 받아 원문에서 만들고, `~/.claude/skills`를 새로 만들었으면 `/reload-skills`를 먼저, 그다음 같은 세션에서 `/kickoff`를 치게 하고 멈춘다. 다른 clone을 가리키면 결정으로 묻는다. 진행 파일이 없을 때만, 붙여 넣은 한 줄로 시작했고 스킬이 이 clone을 가리키면 `/kickoff`를 치게 하고 멈춘다. `/kickoff`가 인식되지 않으면 `/reload-skills`, 그래도 안 되면 같은 폴더의 새 세션이다. 시작 확인의 허락은 준비가 진행 파일을 만든 직후 사람 몫 표에 단계 `시작`의 행으로 옮겨 적는다
- [ ] **`kickoff/skill-template.md`.** 명세 "파일과 자리"의 원문 그대로다(`name: kickoff`, `disable-model-invocation: true`, 본문은 `<clone>/kickoff/runner.md`를 Read로 읽고 따르라는 한 줄). 자리표시자는 `<clone>` 하나이고, 진행 규율이 자기 파일의 자리(`kickoff/`의 부모)에서 정한 clone의 절대 경로(슬래시)로 바꾼다
- [ ] **`kickoff/progress-template.md`.** 명세 "진행 파일의 모양"이다. 머리(clone의 경로·커밋·브랜치, 시작 확인에서 clone 상태에 답한 것, 새 프로젝트의 경로, 시작한 날), 준비에서 정한 것(billing은 `sku`마다 합계만), 단계 표(준비와 0~8단계, 상태 여섯), 사람 몫 표(단계 `시작`의 행 포함), 런북 어긋남이다. 표의 칸에 파이프 문자를 넣지 않는다
- [ ] 두 템플릿은 스킬로 취급되지 않는다. 지침 검사(`tools/check_instructions.py`)가 초록인지 본다

### 런북 (명세 변경 표의 나머지 행)

- [ ] **머리.** 첫 문단 뒤에 첫 시작의 한 줄을 둔다. 처음 쓰는 기계면 런북 저장소를 clone한다, 새 프로젝트 폴더에서 연 세션에 `<clone>/kickoff/runner.md`를 Read로 읽고 그대로 따르라는 한 줄을 붙여 넣는다, 그 뒤로는 `/kickoff`로 시작하고 잇는다. 문구는 이 티켓이 정한다
- [ ] **준비 절.** 첫 일로 진행 파일 만들기를 일지 만들기 앞에 더한다
- [ ] **0단계.** 사용자 레벨 진행 스킬 항목을 더한다. 사람 몫 줄이 아니다. 시작 확인이 허락을 받아 만들고 0단계는 그 결과를 진행 파일에 옮긴다
- [ ] **8단계.** 첫 PR의 차례(명세 "8단계와 첫 PR"의 1~6, `chore/kickoff` 브랜치에 그때까지의 진행 파일과 일지)를 넣는다. 02가 8단계 산문 자리에 둔 사람 몫 줄을 이 차례에 맞춰 옮기고, 사람 몫 검사가 여전히 초록인지 본다. 02가 남긴 둘을 완성한다. 첫 PR 열기 줄에 `chore/kickoff` 브랜치를 넣고, "건너뛴 사람 몫을 지금 할지"의 결정 줄(건너뛴 것이 있을 때만)을 더해 명세 표의 8단계 열 줄을 채운다(02에서 받는 것)
- [ ] **"어디에 무엇이 사는가"의 전역 스킬 행**에 `kickoff`(런북 clone의 진행 규율을 가리키는 짧은 스킬)를 적는다. **7단계의 `skillOverrides` 문장**에 `kickoff`는 끄지 않는다고 더한다
- [ ] **첫날 종료 체크리스트**의 0단계 항목에 사용자 레벨 진행 스킬을 더한다. **부록 목록**에 새 파일 셋을 더한다. **마지막 절**의 "아직 구현 전이고, 이 런북의 단계는 지금도 사람이 하나씩 시켜 진행한다"를 지운다
- [ ] **`kickoff/facts.md`에 스킬 폴더 감시 행**을 더한다. 세션 시작 때 없던 최상위 스킬 폴더는 `/reload-skills` 뒤에만 실리고, 그래서 킥오프는 새 프로젝트의 스킬을 Read로 읽는다. 확인일 2026-10-12, 근거는 명세의 프로브 `skill_live`와 공식 skills 문서다

### 마감

- [ ] 진행 규율의 문단을 명세 "진행 규율이 정하는 것"과 "첫 시작"의 항목과 하나씩 대조한 표를 일지에 남긴다. 진행 규율에는 자동 이음매가 없고(명세 Testing Decisions) 실행은 04가 본다
- [ ] 사람 몫 검사, 지침 검사, 마크다운 표 검사가 초록이다. `CLAUDE.md`의 검증 명령이 모두 초록이다
- [ ] 옛 표현을 grep한다. "아직 구현 전", "사람이 하나씩 시켜"다. 기록, 바뀔 것을 적은 이 기능의 명세와 티켓(`.scratch/kickoff-auto-flow/`)과 ADR 0028 본문, `.claude/worktrees/`는 제외한다

### 이 티켓이 정할 것

결정과 근거는 일지에 적고, 여기 "이 티켓이 정한 것" 절을 더한다.

1. 런북 머리의 첫 시작 한 줄의 문구
2. 진행 규율 안의 절 구성과 문구(명세가 내용을 정했다)
