# portal-login-admin: 회사 로그인 서버 항목과 사이트가 쓰는 항목을 위젯 관리 화면에서 고쳐, 설정 파일을 열지 않고 사이트의 로그인을 바꾼다.
**슬라이스:** 9
**Blocked by:** portal-login, portal-admin

로그인 서버 항목(`CONTEXT.md`)을 위젯 관리 화면에서 고치는 일. portal-login의 설계 인터뷰에서 사용자가 로그인 방식을 화면에서 고르기를 물었고, 0.1 판은 설정 파일로 정하되 화면에서 고르는 일은 portal-admin 행이 맡기로 했다(일지 2026-11-12-1937 라운드 2). portal-admin의 설계 인터뷰(일지 2026-11-15-1312)에서 사용자가 위젯 미리보기 페이지 설정에 남는 값과 로그인 서버 항목을 "모두 0.1 판에" 화면에서 고치기로 골랐고, 일을 나누며 이 행이 섰다(ADR 0064 결정 "회사 로그인 서버 항목"과 "기능 행"). 0.1 판의 행이다(ADR 0046 이력 2026-11-15). portal-login을 기다리는 까닭은 로그인 서버 항목이 그 행에서 처음 코드에 들기 때문이고, portal-admin을 기다리는 까닭은 위젯 관리 화면과 그 로그인과 저장 경로가 그 행의 것이기 때문이다.

이 행에는 아직 설계가 없다. 화면이 고칠 것은 로그인 서버 항목(방식, 주소, 식별자로 쓸 주장, 유지 시간의 기준, 로그아웃 방식. ADR 0059 결정 "로그인 서버 항목")과 사이트가 쓰는 항목이다. 설계 인터뷰가 먼저 볼 것은 아래다.

- 클라이언트 비밀 같은 비밀 값을 화면이 받을지. portal-admin의 인터뷰에서 추천은 "화면은 비밀 값을 받지 않기"였고 사용자가 "그 화면을 짓는 행의 설계에서 정하기"를 골랐다. 지금은 설정이 파일 경로로 가리키는 값이다(ADR 0059). ADR 0064는 이 인터뷰가 정할 때까지 위젯 관리 서버의 데이터베이스에 비밀 값을 두지 않는다는 것까지만 정했다. 화면이 받는다면 그 값을 어디에 어떻게 두는지, 데이터베이스의 백업이 비밀이 되는지, 바꾼 기록에 값을 남기지 않는 방법을 함께 정한다. 받지 않는다면 운영자가 파일을 두는 절차와 화면의 안내를 정한다.
- 위젯 미리보기 페이지의 서버가 로그인 서버 항목을 받아 오는 길과 때. 사이트의 목록과 보증 모드는 portal-admin이 위젯 관리 서버에서 받아 오게 바꾼다(ADR 0064 결정 "위젯 미리보기 페이지 설정"). 로그인 서버 항목이 바뀐 순간에 진행 중이던 로그인과 이미 로그인한 사람의 상태가 어떻게 되는지를 본다.
- 로그인 서버에 등록해 둔 돌아오는 주소는 항목마다 하나다(ADR 0059). 화면에서 항목의 이름을 바꾸거나 지울 때의 규칙과, 사이트가 쓰고 있는 항목을 지울 때의 규칙을 정한다.
- 보증 모드를 바꿀 때 남는 익명 토큰(ADR 0059 결정 "보증 모드를 바꿀 때")을 화면이 어떻게 알리는지.
- portal-ldap-login(0.1 판 뒤)이 방식의 칸에 값을 하나 더하므로, 화면이 방식을 고르는 모양을 그 행이 넓힐 수 있게 둔다.
- 화면. 명세 전에 `/ui-design portal-login-admin`으로 그려 사용자에게 확인받는다.

수락: 사내 로그인 하나를 흉내 낸 시험 환경에서 운영자가 위젯 관리 화면에서 로그인 서버 항목 하나를 등록하고 사이트 하나가 그 항목을 쓰게 하면, 설정 파일을 고치지 않고도 위젯 미리보기 페이지의 그 사이트에서 그 로그인 서버로 로그인한 사람만 calc 예시에 질문할 수 있다
