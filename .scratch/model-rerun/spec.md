Status: ready-for-agent

하네스 기능(`model-rerun`)이다. `.scratch/plan.md`에는 제품 기능만 두므로 이 기능의 행이 없고, 티켓이 모두 done이면 끝난다(`docs/agents/issue-tracker.md` 전체 계획, ADR 0037). 근거는 사용자가 승인한 설계 `.scratch/model-rerun/design.md`(아래 "설계"), 같은 승인을 받은 `docs/adr/0029-session-model-is-picked-before-send.md`의 이력 2026-10-20, 설계 일지 `docs/journal/2026-10-22-08-model-rerun-design.md`, 이 명세의 일지 `docs/journal/2026-10-22-16-model-rerun-spec.md`다.

**넘겨받은 것은 아래 "넘겨받은 것" 표의 열여섯 행이다.** 열다섯은 설계에서 왔고(그 가운데 한 행은 7~9절과 11절의 사용자 결정 셋을 묶었다), 하나는 ADR 0029 이력 2026-10-20에서 왔다.

**사용자가 고른 것은 둘이고 본문에 `(사용자가 골랐다)`로 표시한다.** 시험의 자리(회차 고리까지 저장소 시험으로 고정하고 도구를 `tools/`에 둔다)와 숨은 시험의 범위(파이썬 시험만)다. 이 명세 세션에서 추천을 맨 앞에 둔 선택 화면 하나로 물었고 둘 다 추천을 골랐다(이 명세의 일지).

**ADR 이력은 없다.** ADR 0029 이력 2026-10-20은 측정의 절차(정의를 본 측정 전에 프로브 README의 사전 등록 절에 고정하고, 판정 뒤 이력 초안으로 칸을 바꾼다)를 정했다. 명세가 고친 것은 설계의 실행 조건과 도구의 자리이고 그 절차의 문장을 바꾸지 않는다. 설계 6절 머리는 사전 등록 전의 고침을 실행 조건의 고침으로 보았다. **거부한 안은 넷이고 끝의 "거부한 안" 절에 있다.**

## Problem Statement

`next-session` 결정표는 구현 세션을 `Opus 5.5 / xhigh`로 연다. 그 칸이 이 저장소의 작업에 맞는지는 잰 적이 없다. 사용자가 붙여 넣은 다른 AI의 답은 더 싼 모델이나 낮은 레벨로도 같은 결과가 난다고 했고, 사용자는 그 주장을 실제 작업으로 재 보고 싶다고 했다(설계 1절). 소급 측정은 기록의 66%가 같은 칸이라 효과를 가르지 못하고, 레벨 스윕은 몇 주가 든다(설계 2절).

설계는 승인됐지만 돌릴 도구가 없다. 도구에는 덩어리가 여럿이고 서로 막는다. 과제를 고르고 숨은 시험을 가려야 회차를 돌 수 있고, 회차 기록이 있어야 판정할 수 있다. 회차 하나가 $15~40을 쓰고(설계 7절 어림) 예산은 $900이라, 러너의 결함을 실제 회차에서 찾으면 그만큼 예산이 샌다. 다시 푸는 세션은 사람 없이 돌기 때문에, 막지 않으면 사람의 앱에 세션을 열거나 GitHub에서 병합된 풀이를 읽는다. 원격 저장소는 공개 저장소라(`gh api repos/njh6803/agent-os --jq .visibility`가 `public`이었다, 손으로 봤다) 웹에 닿는 길은 모두 답이 새는 길이다.

설계가 `claude -p`의 동작으로 가정한 것 가운데 하나는 틀렸다. `--resume`으로 이어 부른 세션의 결과 이벤트는 비용을 세션 누적으로 싣는다. 그래서 설계대로 결과 이벤트마다 비용을 더하면 이어 부른 몫을 두 번 센다(`probes/README.md`).

## Solution

`tools/`의 세 명령으로 측정을 돈다(사용자가 골랐다).

1. **과제 고르기.** main의 병합 기록에서 후보를 찾고, 후보마다 숨은 시험을 가리고, 과제의 조건을 대 보고, 층으로 나눠 파일럿 셋과 본 측정 여덟을 고른다. 결과는 과제 목록 파일과 후보 표(후보마다 남았거나 빠진 이유)다. 회차의 결과는 읽지 않는다.
2. **회차 돌리기.** 과제 목록의 과제와 갈래마다 새 클론을 짓고, 지시문을 첫 메시지로 넣어 `claude -p`를 띄우고, 이어 가기를 판정하며 세션을 잇는다. 상한·한도·오염·모델을 보고, 끝나면 결과 커밋에서 게이트와 숨은 시험을 돈다. 회차마다 회차 기록 파일 하나를 남긴다. 과제 차례, 동시에 둘, 예산 $900 안에서 멈추기를 지킨다.
3. **판정.** 과제 목록, 회차 기록, 프로브 README의 사전 등록 절을 읽어 갈래마다의 수와 결론(새 칸, 칸을 둠, 결론 없음)을 낸다. 사전 등록 절의 해시가 다르면 판정하지 않는다.

세 명령은 시험으로 고정된다. 회차 하나는 진짜 `claude` 대신 정해 둔 출력을 내는 가짜 실행 파일과 임시 저장소로 이어 가기·예산·한도·끄기 갈래를 돈다(사용자가 골랐다). 진짜 `claude`의 동작은 이 명세의 프로브가 쟀고, 전용 설정 폴더와 Opus에서의 동작은 파일럿이 본다.

마지막 티켓이 파일럿을 돈다. 사람이 전용 설정 폴더에 njh6803으로 로그인한 뒤, 작은 과제 셋으로 실행 조건을 고치고, 본 측정의 과제를 고르고, 정의를 사전 등록 절로 옮겨 해시로 고정한다. 본 측정은 그 PR이 병합된 직후에 돈다(설계 11절 사용자 결정).

## User Stories

1. As 측정을 맡은 세션, I want 병합된 feature 티켓 가운데 조건을 맞는 것을 도구가 찾아 주기를, so that 과제를 손으로 고르며 결과를 미리 보는 일이 없다
2. As 측정을 맡은 세션, I want 후보마다 남았거나 빠진 이유가 표로 남기를, so that 사람이 과제 목록을 사전 등록 전에 검토할 수 있다
3. As 측정을 맡은 세션, I want 숨은 시험이 M에서 두 번 통과한 것만 남기를, so that 흔들리는 시험이 갈래를 떨어뜨리지 않는다
4. As 측정을 맡은 세션, I want B에 덮었을 때 단언에서 실패하는 시험만 남기를, so that PR이 새로 지은 이름을 부르기만 하는 시험이 다르게 지은 풀이를 떨어뜨리지 않는다
5. As 측정을 맡은 세션, I want 본문이 PR이 처음 지은 이름에 기대는 시험이 빠지기를, so that 티켓이 정하지 않은 이름을 맞혀야만 통과하는 시험이 품질 값이 되지 않는다
6. As 측정을 맡은 세션, I want 숨은 시험이 셋보다 적은 티켓이 후보에서 빠지기를, so that 시험 하나의 우연이 회차의 성패를 정하지 않는다
7. As 측정을 맡은 세션, I want 수용 기준이 LLM 시험·e2e·사진 비교·Claude Design·사람의 확인을 요구하는 티켓이 빠지기를, so that 사람 없는 회차가 끝낼 수 없는 과제가 들지 않는다
8. As 측정을 맡은 세션, I want 원래 세션의 PR 앞 비용이 $70을 넘는 티켓이 빠지기를, so that 한 과제가 예산을 먹어 치우지 않는다
9. As 측정을 맡은 세션, I want 후보를 크기 지표로 세 층에 나눠 층마다 정해 둔 씨앗으로 고르기를, so that 큰 티켓을 빼지 않고 고른 사람의 손이 타지 않는다
10. As 측정을 맡은 세션, I want 후보가 모자라면 병합 시각을 거슬러 채우기를, so that 층마다 고를 수가 찬다
11. As 측정을 맡은 세션, I want 본 측정의 과제가 층을 엇갈린 차례로 돌기를, so that 예산이 중간에 다해도 한 층이 통째로 빠지지 않는다
12. As 측정을 맡은 세션, I want 회차마다 B까지의 이력만 든 새 클론을 받기를, so that 다시 푸는 세션이 `git log`로 병합된 풀이를 읽지 못한다
13. As 측정을 맡은 세션, I want 클론의 `origin`이 로컬 bare 저장소이기를, so that 푸시가 GitHub에도 주 저장소에도 닿지 않는다
14. As 측정을 맡은 세션, I want 회차마다 클론의 경로가 다르기를, so that 세션 기록 폴더와 자동 메모리가 회차 사이에 섞이지 않는다
15. As 측정을 맡은 세션, I want 세션 전에 `uv sync`, `pnpm install`, `pre-commit install`이 돌기를, so that 회차가 실제 지시문 세션처럼 커밋 훅을 지나고 준비 시간이 비용에 들지 않는다
16. As 사용자, I want 다시 풀기가 전용 설정 폴더의 njh6803 계정으로만 돌기를, so that 내 기본 계정의 한도와 기록이 섞이지 않는다

## Implementation Decisions

### 자리와 모듈

- 도구는 `tools/`의 새 모듈 셋(과제 고르기, 회차, 판정)과 그 명령 줄 입구다. 셋 다 `tests/tools/`의 시험을 갖고 pyright strict, 타입 우회 검사(`tools/check_type_escapes.py`), 리눅스 CI를 지난다. 설계 9절 2의 "도구를 짓는다(`.scratch/model-rerun/probes/`)"를 이렇게 고친다(사용자가 골랐다). 프로브 폴더에는 README(사전 등록 절, 결과), 과제 목록, 후보 표, 회차 기록, 이 명세의 프로브가 남는다.
- 모듈 사이의 계약은 파일 둘이다. 과제 목록(고르기 → 회차·판정)과 회차 기록(회차 → 판정)이고, 칸은 아래 두 절이 정한다. 두 파일은 JSON이다(명세가 정했다). (2026-10-22 명세 검토: 아래 칸은 우리말 설명이라, 고르기·회차·판정 티켓이 나란히 지으면 각자의 픽스처로 초록이면서 서로 맞지 않을 수 있다. 그래서 두 파일의 꼴(키 이름, 형, 맨 위 모양, 꼴 판, 읽고 쓰는 함수, `records/`의 파일 이름)을 첫 티켓이 넷째 모듈 하나에 짓고, 세 모듈은 그 꼴을 import한다. 판정이 회차 모듈의 바깥 몫(하위 프로세스)을 끌어오지 않게 하려는 것이다. 그래서 위의 "새 모듈 셋"은 이 꼴 모듈까지 넷이 된다. 파일럿 목록과 본 측정 목록은 따로 두 파일이다. to-tickets가 정했다)
- 판정하는 함수(숨은 시험 가르기, 이어 가기의 갈래, 오염 검사, 모델 확인, 판정)는 git·pytest·claude를 부르지 않고 값만 받는다. 바깥을 부르는 몫은 얇은 층에 모은다(명세가 정했다). 하위 프로세스 호출마다 시간 제한을 둔다(`.claude/rules/tools.md`의 시간 제한 항목, `tools/check_instructions.py`의 `calls_without_timeout`).
- 회차 폴더와 임시 작업 트리를 지우는 길은 `.claude/rules/tools.md`의 지우는 도구 항목을 따른다. 러너는 사람이 명령 줄로 준 절대 경로의 뿌리 아래에 자기가 만든 폴더만 지운다. 그 폴더는 만든 직후 표지 파일을 심고, 지울 때 표지를 본다. 링크는 따라가지 않고 링크만 끊는다(선례 `tools/canary.py`의 `_cut_links`, `tools/tidy_checkouts.py`의 `delete_path`). 커밋 전에 임시 저장소에서 판정을 깨려는 입력(링크, 커밋하지 않은 파일, 윈도 경로 정규화가 바꾸는 이름)으로 반박한다.
- bare 저장소, 클론, 임시 작업 트리에 git을 띄우는 자리와 그 시험은 `tools.run_hooks.REPO_LOCATION_VARS`를 자식 환경에서 벗긴다. 워크트리에서 커밋할 때 pre-commit 아래에서 돌면 git이 내보낸 `GIT_DIR`과 `GIT_INDEX_FILE`이 이 저장소를 가리킨다(`.claude/rules/tools.md`의 pre-commit 항목).
- 하위 프로세스의 출력을 이어 읽는 자리는 `.claude/rules/probes.md`의 읽기 항목(daemon 스레드와 큐, 풀지 못한 줄은 이벤트가 아닌 줄, 읽지 않는 stderr는 버림, EOF 표시를 되돌림, 배출에도 시간 제한)을 첫 판부터 따른다. 프로세스를 끄기 전에는 그 pid의 명령 줄에 그 호출의 세션 id가 있는지 본다(같은 파일의 끄기 항목, 아래 "상한과 끄기").

### 러너가 기대는 `claude -p`의 동작

`probes/README.md` 2026-10-22 결과에서 왔고, 아래 결정은 그 결과에서 나온다(명세가 정했다).

- **비용은 세션마다 마지막 결과 이벤트의 `total_cost_usd`다.** `--resume`의 결과 이벤트는 비용과 `modelUsage`를 세션 누적으로 싣는다. 회차의 비용은 세션 id마다 마지막 결과 이벤트의 값을 더한 것이다. 설계 6절의 "회차의 세션마다 결과 이벤트의 `total_cost_usd`를 더한다"를 고친다.
- **`--max-budget-usd`는 그 호출의 몫을 세고 구독 로그인에서 멈춘다.** 그래서 설계 5절대로 호출마다 회차의 상한에서 앞선 호출들이 쓴 것을 뺀 값을 넘긴다. 예산은 응답이 끝난 뒤에 재므로, 넘긴 응답 하나만큼 상한을 넘을 수 있고 그 응답의 도구 호출은 돌지 않는다. 결과 `subtype`이 `error_max_budget_usd`인 호출은 "상한으로 끊김(예산)"이다. 설계 5절의 "멈추지 않으면 러너가 기록의 사용량을 보며 끈다"는 지을 일이 없다.
- **결과 글은 글이 빈 것을 뺀 마지막 결과 이벤트의 `result`다.** 서브에이전트가 백그라운드로 뜨면 한 호출에 결과 이벤트가 여럿 나오고 마지막 것의 글이 빌 수 있다(`서브-2.jsonl`). 이어 가기의 지시문 찾기와 "물으며 끝남"은 이 글을 읽는다.
- **노력과 모델은 세션 기록 파일에서 읽는다.** stream-json에는 노력이 없다. 본 세션은 `<설정 폴더>/projects/<작업 폴더 slug>/<세션 id>.jsonl`, 서브에이전트는 `<세션 id>/subagents/*.jsonl`의 assistant 줄이다. (2026-10-22 명세 검토: 러너는 작업 폴더 slug를 셈하지 않고 `<설정 폴더>/projects/*/<세션 id>.jsonl`처럼 세션 id로 기록 파일을 찾는다. 프로브도 그렇게 찾았다(`headless_flags.py`의 `transcript_effort`). 러너와 가짜 `claude`가 같은 slug 셈을 쓰면 시험이 순환한다. to-tickets가 정했다) 모델이 `<synthetic>`이고 노력이 없는 줄은 뺀다. 프로브에서는 예산에 끊긴 세션을 이어 부른 기록에만 하나 있었고, 무엇이 그 줄을 만드는지는 가르지 않았다. `modelUsage`의 모델 목록은 판정에 쓰지 않는다. 갈래 밖의 모델(Haiku)이 서브에이전트 없이도 실렸다.
- **막는 규칙은 클론의 `.claude/settings.local.json`에 둔다.** auto 모드의 분류기는 `gh`, `git push`, 스크립트 실행, 바깥 파일 읽기, 스킬, WebFetch를 스스로 막지 않았고 규칙이 막았다.
- **막는 규칙을 둔 세션에는 PowerShell 도구가 없다.** 실제 지시문 세션과의 차이다. 회차 기록에 init의 도구 목록을 남기고, 파일럿의 시작 컨텍스트 대조(설계 8절 8)에 넣는다.
- **`-p`에는 `AskUserQuestion`이 없다.** 사람에게 묻고 싶은 세션은 글로 묻고 차례를 끝낸다. 이것은 이어 가기의 2(물으며 끝남)나 3(개입)으로 간다. 설계 6절 탐색의 "`AskUserQuestion`을 부른 수"는 늘 0이라 "물으며 끝남"의 수로 대신한다. 설계 8절 7의 확인은 기본 설정 폴더의 Sonnet low에서 했고, 파일럿은 전용 설정 폴더에서 같은지만 본다(아래 "파일럿과 사전 등록").
- **한도 이벤트에 사용률이 있다.** 회차 기록에 회차의 첫과 끝의 `utilization`(창마다)을 남긴다(설계 6절 탐색의 마지막 줄).

### 명령과 막는 규칙

- 명령은 설계 5절의 것에 첫 호출의 `--session-id <러너가 지은 uuid>`(세션 기록 파일을 찾으려고), 이어 가기 3의 `--resume <세션 id>`, 호출마다의 `--max-budget-usd <남은 값>`을 붙인다.
- 클론의 `.claude/settings.local.json`의 막는 규칙(`permissions.deny`)은 아래다. 앞의 넷은 설계 5절에서 왔고, 꼴은 프로브가 막는 것을 본 꼴(`Bash(<접두>:*)`, `Bash(*<글>*)`, `Read(//<드라이브>/<경로>/**)`, `Skill(<이름>)`)을 따른다.
  - `Bash(gh:*)`, `Bash(git push:*)`
  - 주 체크아웃과 사용자의 `~/.claude`의 `Read`·`Edit`·`Write`. 설계는 읽기만 들었고, 쓰기도 막는다(명세가 정했다)
  - `Skill(open-session)`, `Bash(*open_session.ps1*)`, `Bash(*claude://*)`
  - 웹 도구 `WebFetch`·`WebSearch` 전부. 설계는 GitHub 주소의 WebFetch만 들었다. 저장소가 공개라 검색과 다른 주소(`raw.githubusercontent.com`, 미러)로도 병합된 풀이를 읽을 수 있어 통째로 막는다. 모든 갈래가 같이 웹을 쓰지 못하므로 짝 비교는 흐려지지 않는다(명세가 정했다)
  - 바깥 상태를 바꾸는 도구 `SendMessage`, `ListAgents`, `RemoteTrigger`, `PushNotification`, `DesignSync`, `CronCreate`, `ScheduleWakeup`. 프로브의 init 도구 목록에 있었고, 사람의 다른 세션에 메시지를 보내거나 사람의 기기에 알림을 보내거나 Claude Design에 올리거나 예약을 남긴다(명세가 정했다)
- 도구 이름만 쓴 규칙(`WebSearch`)과 쓰기·편집 규칙은 프로브가 재지 않은 꼴이다. 파일럿이 그 꼴이 막는지 보고, 오염 검사가 받친다.

### 지시문과 첫 메시지

- **첫 메시지는 첫 줄, 빈 줄, 지시문이다.** 첫 줄은 `tools/open_session.ps1`의 `Convert-StartLine`이 `/implement <티켓 경로>`를 옮긴 꼴이다. 스킬 파일을 읽어 따르라는 문장이고, 연 저장소는 클론의 경로, 인자는 티켓 경로다. 러너는 그 문장을 파이썬으로 짓는다. 시험이 `open_session.ps1`에서 그 문장의 틀을 읽어 러너의 틀과 같은지 본다. 두 곳의 문장이 갈리면 실제 세션과 다른 길로 스킬이 실린다(명세가 정했다).
- **지시문의 틀**(명세가 정했다). `next-session`의 지시문 형식을 따른다. 갈래 사이에는 `모델:` 줄만 다르다.

  ```
  다음 작업: <티켓 경로>. <티켓 파일의 첫 제목 줄에서 `# NN:`·`# ` 머리를 뗀 글>
  다음 단계: 구현
  어디서: 새 세션
  시작 프롬프트: /implement <티켓 경로>
  브랜치: <원래 PR의 머리 브랜치>
  모델: <Opus 5.5 또는 Sonnet 5.5> / <xhigh·high·medium>
  읽을 것: 없음
  이어받을 상태: 없음
  확인할 선행 조건: 없음
  이번 요청 범위: 구현·리뷰·커밋까지
  ```

- 워크트리 문장은 넣지 않는다. 클론은 main에 깨끗하게 체크아웃되고 묶음이 아니다(설계 5절).

### 이어 가기와 끝

- **지시문을 알아보는 함수는 첫 턴 훅의 것을 그대로 쓴다.** 러너는 `tools/hook_prompt_directive.py`의 `_directive_branch`(줄 머리가 `어디서: 새 세션`인 줄이 있으면 줄 머리 `브랜치:`의 값)를 공개 이름으로 바꿔 import한다. pyright strict는 다른 모듈의 밑줄 이름을 쓰면 막는다. 두 곳의 규칙이 갈리지 않게 하려는 것이다. 훅끼리는 서로 import하지 않지만(`.claude/rules/tools.md`), 훅 밖에서 훅의 함수를 쓰는 선례는 프로브에 있다(`.scratch/harness/probes/webfetch_payload/transcripts.py`의 `context_for`)(명세가 정했다).

### 모델 확인

설계 5절을 아래 자리에서 본다(명세가 정했다).

- 본 세션의 기록 파일에서 `<synthetic>`을 뺀 assistant 줄이 모두 갈래의 모델(`claude-opus-5-5`·`claude-sonnet-5-5`)과 갈래의 노력이다.
- 서브에이전트 기록의 assistant 줄은 모델만 본다. 허용하는 모델은 셋의 합이다. 갈래의 모델, 하네스가 정한 모델(클론의 `.claude/agents/*.md`의 `model` 값과 `code-review` 스킬이 표준 축에 주는 `sonnet`), 그 세션이 Agent 도구 입력의 `model`로 직접 고른 모델이다. 별칭은 전체 이름으로 바꾼다(`sonnet` → `claude-sonnet-5-5`, `haiku` → `claude-haiku-5-5`, `opus` → `claude-opus-5-5`, `inherit`과 빈 값은 갈래의 모델). 세션이 직접 고른 모델은 설정 실수가 아니라 갈래의 행동이라 허용한다. 내장 에이전트(Explore 등)가 모델을 주지 않았을 때 무엇으로 도는지는 재지 않았다. 파일럿이 서브에이전트 기록의 모델을 모두 적고, 허용 모임은 사전 등록 절이 고정한다. 서브에이전트의 노력은 판정에 쓰지 않고 수만 기록에 남긴다. 하네스가 노력을 정한 자리(`code-review`가 표준 축에 주는 `effort: high`)와 정하지 않은 서브에이전트의 노력이 기록에 무엇으로 실리는지를 재지 않았다. 프로브에서 노력을 주지 않은 서브에이전트의 기록에는 본 세션과 같은 `low`가 실렸지만, 물려받은 것인지 기본값인지는 가르지 않았다. 파일럿이 서브에이전트 기록의 노력을 모두 적는다. 설계 5절이 서브에이전트에 허용한 모델(하네스가 정한 모델이나 갈래의 모델)을 고친다. 허용 모임에 세션이 Agent 입력으로 고른 모델을 더했다.
- 다르면 "측정 아님(모델)"이다. 회차마다 `claude --version`을 적고, 과제 하나의 갈래 사이에 판이 다르면 판정이 그 과제를 T(판정에 쓰는 과제의 모임, 아래 "판정")에서 뺀다(설계 6절). (2026-10-22 명세 검토: `claude` 실행 파일은 사람의 다른 세션과 같이 쓰는 파일이다(`~/.local/share/claude/versions/`에 판 이름의 실행 파일 2.1.299·2.1.300·2.1.302가 있었다, 검토 서브에이전트와 셀프 리뷰 표준 축이 손으로 봤다). 러너 환경의 `DISABLE_AUTOUPDATER=1`은 사람의 세션이 판을 올리는 것을 막지 못한다. 그래서 러너는 띄울 `claude`의 경로를 명령 줄로 받는다. 판 이름의 실행 파일을 바로 띄워 판을 고정할 수 있는지와, 측정 기간에 사람이 자동 업데이트를 끄는 것은 파일럿 티켓이 사람과 정한다. to-tickets가 정했다)

### 게이트와 숨은 시험

- 결과 커밋을 클론에서 새 작업 트리(`git worktree add`)로 꺼내 준비한 뒤 게이트 셋을 돈다. `uv run ruff check .`, `uv run ruff format --check .`, `uv run python tools/run_checks.py`이고, 셋 다 종료 0이면 게이트가 초록이다. 세션이 일한 클론의 작업 폴더는 쓰지 않는다. 커밋하지 않은 변경과 세션이 남긴 파일이 판정에 들지 않게 하려는 것이다(명세가 정했다).
- 같은 작업 트리에 M의 숨은 시험 파일과 시험 지원 파일을 덮고, 숨은 시험의 노드 ID만 pytest로 돌려 junit xml로 센다. 모두 통과하면 숨은 시험이 통과다. (2026-10-23 티켓 07: 숨은 시험은 게이트 셋이 모두 0으로 끝난 회차에서만 돈다. 판정의 "풀었다"(`tools/rerun_judge.py`의 `solved`)가 게이트 초록을 먼저 요구해, 게이트가 초록이 아닌 회차의 숨은 시험은 판정과 되풀이에 쓰이지 않는다. 노드 ID로 돌린 pytest는 한 파일을 모으지 못하면 `--continue-on-collection-errors`를 줘도 실행 전체를 종료 4로 멈춰, 다른 파일의 노드도 결과가 없어 실패로 센다. 모두 통과인지는 같고 통과 수만 낮게 나온다. 덮을 자리가 결과 작업 트리의 링크를 지나거나(작업 트리 자리 자체가 링크로 바뀐 때 포함) 쓰지 못하면 덮지 않고 모든 노드가 실패다. 결과 커밋을 꺼내지 못하거나 원본에서 M의 파일을 읽지 못하면 게이트 도구는 판정하지 않고 오류로 올리고, 러너(10)가 그 회차를 어떻게 적을지 정한다)

### 회차 기록

회차마다 JSON 한 파일이고 프로브 폴더의 `records/` 아래에 쌓아 커밋한다. 원본 stream-json, 세션 기록 파일, 결과 글, 게이트 출력은 회차 폴더(저장소 밖)에 둔다. 커밋하는 기록에는 모델이 쓴 글과 도구 입력을 옮기지 않고, 정해진 칸의 수·식별자·참거짓만 남긴다. 지우지 않는 저장소에 입력에서 고른 값을 남길 때는 알아볼 수 있는 꼴만 남긴다는 규칙(`.claude/rules/tools.md`의 허용 목록 항목)을 따른 것이다. 칸은 아래다(명세가 정했다).

- 식별: 과제 id, 갈래, 회차 번호(같은 과제·갈래의 몇째), 조건 판(러너의 정수 상수. 실행 조건을 고칠 때마다 올린다), 파일럿인지, 회차 폴더 경로 (2026-10-23 티켓 01의 PR 봇 회차: 경로가 아니라 뿌리를 뺀 회차 폴더 이름만 적는다. 뿌리는 사람이 명령 줄로 준 경로라 커밋하는 기록에 남기지 않는다(`.claude/rules/tools.md`의 허용 목록 항목). 회차 번호와 다시 뜬 러너가 찾는 회차 폴더는 기록 파일 이름과 뿌리 아래 폴더 이름에서 나오므로 이 칸은 그 셈에 쓰이지 않는다. 대가로 커밋된 기록만으로는 원본(stream-json 등)의 자리를 알 수 없고, 그 회차를 띄운 뿌리를 아는 사람만 이름으로 찾는다)
- 환경: `claude --version`, 계정 이름, 넘긴 환경 변수의 이름, init의 도구 목록
- 세션마다: 세션 id, 호출마다의 종류(첫·인계·개입)와 넘긴 예산과 종료 코드와 결과 이벤트(`subtype`, `terminal_reason`, `num_turns`, `result_index`, 결과 글이 지시문을 담았는지와 물음표로 끝났는지), 세션의 비용(마지막 `total_cost_usd`)과 마지막 `modelUsage`, 기록 파일의 모델·노력 수와 서브에이전트 기록의 모델·노력 수
- 이어 가기: 인계 수, 개입 수, 물으며 끝남
- 끝: `끝남`, `상한으로 끊김`(개입·세션·예산·시간), `측정 아님`(한도·오염·모델·설정) 가운데 하나와 그 이유 글. 한도면 `resetsAt` (2026-10-23 티켓 01: 끝은 종류와 하위 이유 두 칸이고, 이유 글은 하위 이유 칸 하나다. 러너가 지은 글이어도 자유 글 칸은 커밋하는 기록의 허용 목록 밖이라 두지 않는다. 다른 글 칸도 칸마다 그 값이 나오는 꼴만 받는다. 게이트와 준비의 명령은 명세가 정한 세 명령의 상수와 같아야 하고, 게이트는 셋이 그 차례로 든다. 회차 폴더는 그 회차의 폴더 이름이어야 한다. 끝남인 회차에는 결과 커밋이 있다(위 "이어 가기와 끝"의 갈래 2). 계정 불일치는 회차를 열지 않아 기록이 없으므로 하위 이유에 없다. 아래 "차례, 동시성, 예산"의 2026-10-23 주석이 든 계정은 러너가 멈추는 까닭이다. 두 파일의 키 이름과 형, 칸 사이의 맞음(끝남이 아닌 회차에는 게이트와 숨은 시험이 없다, 결과 커밋과 고른 규칙의 짝 등)은 `tools/rerun_files.py`가 원천이다)

- (2026-10-22 명세 검토: 러너는 멈추거나 죽은 뒤 같은 명령으로 다시 띄워 잇는다. 과제마다 그 과제의 기록에서 가장 큰 조건 판을 V, 러너의 조건 판을 C라 한다. 회차는 측정 아님이 아닌 기록이 있으면 끝난 것이고, 측정 아님인 기록을 다루는 법은 아래 2026-10-23 주석이 사유마다 정한다. 그 판에서 오염으로 뺀 과제는 끝난 과제다. 가장 늦은 한도 기록의 `resetsAt`이 아직 오지 않았으면 그때까지 새 회차를 열지 않는다. 그 위에서 셋을 가른다. V에서 갈래 계획을 다 마친 과제는 다시 돌지 않는다(아래 "판정"이 과제마다 가장 큰 조건 판을 쓴다). 사람이 명령 줄로 과제 id를 준 과제는 C에서 갈래 계획을 돌고 C에서 끝난 회차는 건너뛴다. 설계 5절이 인계 뒤 조건을 고치면 그 과제의 다섯 갈래를 모두 다시 돌게 하므로, 조건을 고친 사람은 C를 올리고 그 과제 id를 준다. 같은 명령을 다시 쳐도 C에서 끝난 회차는 다시 돌지 않고, C를 올리지 않고(C = V) id만 주면 같은 판의 회차가 늘지 않는다. V에서 갈래 계획을 다 마치지 못한 과제는 V = C이면 남은 회차를 돌고, V < C인데 그 id가 명령 줄에 없으면 러너가 회차를 열지 않고 멈춰 그 id를 낸다. 판이 섞인 과제가 판정에서 말없이 빠지지 않게 하려는 것이다. 다시 뜬 러너는 뿌리 아래에서 표지는 있는데 `records/`에 기록이 없는 회차 폴더(죽은 러너가 돌리던 회차)를 찾아 아래 2026-10-23 주석대로 다룬다. 회차 번호는 러너가 회차를 열 때 `records/`의 기록과 뿌리 아래 회차 폴더의 이름에서 그 과제·갈래의 가장 큰 번호 다음으로 잡고, 곧바로 그 폴더를 만든다. 그래서 동시에 도는 두 회차와 죽은 러너가 남긴 회차가 같은 번호를 받지 않는다. to-tickets가 정했다)
- (2026-10-23 PR 직전 리뷰: 위 주석을 셋 넓힌다. 첫째, 측정 아님인 기록을 사유마다 다룬다. 한도는 `resetsAt` 뒤에(비었으면 사람이 다시 띄운 때, 위 "한도"의 주석) 다시 돈다. 오염은 같은 과제·갈래·조건 판의 기록에서 둘째이면 그 과제를 그 판에서 빼고 첫째면 다시 돈다. 설정·준비·계정·호출·모델은 처음 났을 때 러너가 멈추고, 사람이 푼 뒤 다시 띄우면 그 회차를 다시 돈다. 모델도 설정처럼 멈추는 것은, 허용 모임 밖의 서브에이전트 모델이 대개 하네스나 설정 폴더의 잘못이라 다른 회차도 같이 걸리기 때문이다. 멈추지 않고 넘어가면 그 갈래가 비어 판정이 그 과제를 T에서 말없이 뺀다. 같은 까닭으로 다시 멈추면 그 과제를 어떻게 할지는 사람이 정한다. 사람이 id를 준 과제는 V에서 다 마쳤거나 그 판에서 오염으로 뺀 과제여도 C에서 돈다(id가 앞선다). 둘째, 다시 뜬 러너가 이미 시작한 과제(그 판의 회차 기록이나 회차 폴더가 있다)를 이어 돌 때 예산의 어림은 남은 회차의 갈래 비율만 더한 배수로 낸다. 쓴 것에 끝난 회차의 비용이 이미 들어 있어, 전체 배수를 곱하면 같은 몫을 두 번 센다. 셋째, 죽은 러너가 남긴 회차는 다시 뜬 러너가 "측정 아님(중단)"으로 `records/`에 쓴 뒤 다시 돈다. 비용은 세션마다 원본 stream-json의 마지막 `total_cost_usd`이고, 결과 이벤트가 없는 세션(죽을 때 돌던 호출)은 끈 호출처럼(위 "상한과 끄기"의 주석) 그 세션의 기록 파일로 셈한 공식 단가를 대신 넣고 표시한다. 그래서 그 비용이 커밋하는 기록에 남아 쓴 것에 들고, 사람이 회차 폴더를 지워도 줄지 않는다. 지우기 명령은 기록이 없는 회차 폴더를 지우지 않는다. 세션 id는 러너가 지은 uuid라 띄우기 전에 회차 폴더에 적어 두고, 다시 뜬 러너는 그것으로 init 전에 죽은 호출까지 찾는다. 그 세션 id가 명령 줄에 든 프로세스가 돌거나, 이름이 띄운 `claude` 실행 파일과 같은데 명령 줄을 읽지 못한 프로세스가 있으면 새 회차를 열지 않고 멈춰 사람에게 넘긴다. 끄기(위 "상한과 끄기")는 모르는 프로세스를 끄지 않는 쪽이 안전하고, 여기는 돌고 있을지 모르는 회차 위에 새 회차를 얹지 않는 쪽이 안전해 방향이 반대다. 위 "회차 기록"의 끝의 `측정 아님`에는 중단도 든다. to-tickets가 정했다)

### 판정

- 입력은 과제 목록, `records/`의 회차 기록, 프로브 README의 사전 등록 절과 판정 도구의 해시 상수다. 사전 등록 절은 `<!-- 사전 등록 시작 -->`·`<!-- 사전 등록 끝 -->` 사이이고 내용의 SHA-256을 상수와 대 본다(선례 `.scratch/harness/probes/model_sweep/README.md`와 `tools/model_sweep.py`의 `prereg_section`).
- 본 측정의 회차만 쓴다(파일럿 표시가 없는 것). 과제마다 그 과제의 회차 가운데 가장 큰 조건 판의 회차만 쓰고, 그 판에 측정인 회차가 없는 갈래가 있으면 그 과제를 T에서 뺀다. 설계 5절이 인계가 지시문대로 돌지 않으면 조건을 고치고 그 과제의 다섯 갈래를 모두 다시 돌게 해서, 측정인 회차가 한 갈래에 둘 생기는 것은 그때뿐이다. 고친 뒤의 회차를 써야 하고, 다시 돌기가 중간에 끊겨 고치기 전과 뒤의 회차가 한 과제에 섞이면 그 과제는 짝 비교가 되지 않는다. 같은 조건 판 안에서 과제와 갈래마다 측정인 회차가 둘 이상이면 회차 번호가 가장 작은 것을 쓴다(명세가 정했다).
- T(다섯 갈래가 모두 측정인 과제의 모임), S_k(갈래 k가 푼 과제 수), C_k(갈래 k의 T 위 비용 합), U_k(푼 과제 하나의 비용 C_k / S_k), R_k(비용 비 U_k / U_A), 후보 조건 셋, 후보 가운데 U_k가 가장 작은 갈래, 후보가 없으면 칸을 둔다, 결론 없음 조건, 판이 다른 과제 빼기는 설계 6절 그대로다. 부트스트랩은 2,000회, `random.Random(0)`, 회마다 과제를 한 번 다시 뽑아 두 갈래에 함께 쓰고, 90% 구간은 `tools/model_sweep_judge.py`의 `percentile_ci`와 같은 정의다. 다시 뽑은 표본에서 S가 0인 것은 세지 않고, 그런 표본이 5%를 넘으면 그 갈래의 구간은 "셀 수 없음"이다. (2026-10-22 명세 검토: "S가 0인 표본"은 그 표본에서 S_k나 S_A가 0인 것이다. 어느 쪽이 0이어도 R_k가 정의되지 않는다. `random.Random(0)`은 갈래 k의 구간을 낼 때마다 새로 만든다(선례 `tools/model_sweep_judge.py`도 호출마다 새로 만든다). 그래서 모든 갈래의 구간이 같은 2,000개 다시 뽑기에서 나오고, 갈래를 도는 차례가 수를 바꾸지 않는다. 구간이 "셀 수 없음"인 갈래는 위 끝을 모르므로 후보 조건 3(위 끝이 1보다 작다)을 맞지 못한다. to-tickets가 정했다)
- **되풀이 둘.** 하나는 공식 단가의 셈으로 낸 판정이다. 설계 6절은 "Sonnet 5.5의 캐시 읽기를 공식 가격표($0.10)로 셈한 비용"이라 했는데, 2.1.302의 Sonnet 기록은 이미 그 단가였다. 그래서 모든 모델을 공식 단가로 다시 셈한 값으로 넓힌다. 판에 따라 Claude Code의 셈이 바뀌어도 이 되풀이가 그 차이를 잡는다(명세가 정했다). 다른 하나는 숨은 시험 없이 끝남과 게이트만으로 센 "풀었다"다. 되풀이로 고른 갈래가 달라지면 "<단가 / 숨은 시험>에 따라 갈린다"를 붙인다.
- **탐색.** 설계 6절의 줄 그대로이고, "`AskUserQuestion`을 부른 수"만 "물으며 끝남의 수"로 바꾼다.
- 출력은 표(갈래마다 S, C, U, R과 구간, 개입이 A보다 많은 과제 수, 물으며 끝남, 상한으로 끊김)와 결론 한 줄이다. 결론은 ADR 0029 이력 초안의 재료이고, 초안과 승인은 이 기능 밖이다.

## Testing Decisions

- 좋은 시험은 세 자리의 바깥 동작만 본다. 함수 안의 차례나 중간 값이 아니라, 입력 파일과 가짜 실행 파일이 낸 것에서 나온 과제 목록, 회차 기록, 판정 출력을 단언한다(사용자가 골랐다).
- **과제 고르기와 숨은 시험 가르기.** 값만 받는 함수를 지은 입력으로 시험한다. 작은 시험 소스 두 판(B와 M)에서 바뀐 시험 함수를 찾는 것, junit xml 조각(통과, 단언 실패, `AttributeError` 실패, 모음 `error`, 건너뜀, 매개변수화한 경우)에서 남는 노드, 이름과 문자열의 M·B 유무에서 조건 3, 바뀐 티켓 파일과 B·M의 Status 값에서 푼 티켓 찾기(여럿 가운데 하나만 `done`으로 바뀐 것, `done`에서 `done`, `in-progress`로 바뀐 것, B에 없는 티켓 파일), 후보 행에서 바깥 검증 낱말·날짜·비용 문턱·브랜치 접두, 층 자르기와 씨앗 고르기의 결정성, 후보가 열둘보다 적을 때 거슬러 채우기, 엇갈린 실행 차례를 본다.
- **회차 하나.** 가짜 `claude` 실행 파일(정해 둔 각본대로 stream-json 줄을 내고, 설정 폴더 아래에 세션 기록 파일을 쓰고, 멈추거나 정해 둔 코드로 끝나는 파이썬 스크립트)과 임시 저장소(B와 M이 있는 주 저장소)로 회차를 돈다. 가짜는 받은 인자, 표준 입력, 환경 변수의 이름을 파일에 적는다. 각본의 이벤트 꼴은 커밋한 프로브 요약에서 옮긴다(누적 비용, 결과 이벤트 여럿과 빈 마지막 글, `error_max_budget_usd`, `status: rejected`, `<synthetic>` 줄, 서브에이전트 기록). 시험은 아래를 본다.
  - 끝남과 결과 커밋을 고르는 세 규칙, 같은 브랜치 지시문의 새 세션(갈래 1), 개입 한 줄과 `--resume`(갈래 3), 개입·세션의 상한, 물으며 끝남
  - 호출마다 넘긴 `--max-budget-usd`가 상한에서 그 호출 전까지 회차가 쓴 것(이어 부를 세션을 포함해 세션마다 마지막 비용의 합)을 뺀 값이고, `--resume` 호출에서도 그 세션이 이미 쓴 몫이 빠지며, 남은 값이 $1 미만이면 세션을 열지 않는 것. 세션 비용이 결과 이벤트의 합이 아니라 마지막 값인 것
  - 한도 표지에서 측정 아님과 `resetsAt`, 그 시각 뒤까지 새 회차를 열지 않고 그 회차를 새 클론으로 처음부터 다시 도는 것(시험에서는 가짜 시계를 준다)
  - 오염: 셸 명령의 낱말 `gh`(`xargs gh`, `["gh", "api"]`는 걸리고 `high `는 걸리지 않음), Write 내용의 주소(`.py`는 걸리고 `.md`와 `tests/` 아래는 걸리지 않음), 거부된 호출을 오염으로 세지 않는 것, 한 번 걸리면 다시 돌고 두 번 걸리면 그 과제를 모든 갈래에서 빼는 것
  - 모델·노력 불일치와 하네스가 정한 서브에이전트 모델의 통과
  - 계정 확인(`claude auth status --json`의 `loggedIn`·`email`·`configDirectory`가 하나라도 다르면 회차를 열지 않음)과 설정 확인(설정 폴더의 `env` 키, init의 `mcp_servers`·`plugins`가 다르면 측정 아님(설정)으로 적고 멈춤). 가짜가 `auth status`와 init을 각본대로 낸다
  - 본 측정에서 갈래 1(인계)이 처음 난 회차가 끝나면 새 회차를 열지 않고 멈추고, 확인 인자를 주면 잇는 것
  - 다음 과제를 시작하기 전에 쓴 것과 그 과제의 어림의 합이 명령 줄의 상한을 넘으면 멈추는 것(파일럿과 측정 아님의 비용도 쓴 것에 든다)
  - 벽시계 제한(시험에서는 짧게 준다)에 걸린 가짜를 명령 줄의 세션 id를 본 뒤 끄는 것(첫 호출과 `--resume` 호출 둘 다)과, 그 세션 id가 없는 pid를 끄지 않는 것
  - 넘긴 환경이 허용 목록과 `GH_CONFIG_DIR`뿐이고, 부모 환경에 넣은 가짜 `GH_TOKEN`이 넘어가지 않는 것
  - 첫 메시지의 첫 줄이 `open_session.ps1`의 틀과 같고 지시문이 갈래마다 모델 줄만 다른 것
  - 클론에 B 뒤 커밋과 다른 ref가 없는 것, 회차 폴더 지우기가 표지 없는 폴더와 링크를 건드리지 않는 것
  - 게이트와 숨은 시험의 명령은 회차 함수의 인자로 받아, 시험에서는 임시 저장소 안의 작은 명령과 작은 pytest 시험으로 돈다. 실제 게이트 목록은 상수로 따로 단언한다
- 가짜는 리눅스 CI에서도 돈다(`sys.executable`로 띄운다). 진짜 `claude`는 시험하지 않는다. 그 몫은 이 명세의 프로브와 파일럿이다.
- **판정.** 지은 회차 기록과 사전 등록 절로 시험한다. 후보가 고르는 갈래, 후보 없음, 결론 없음 셋(T < 6, S_A < T/2, 해시 불일치), 판이 다른 과제 빼기, 파일럿 회차를 쓰지 않음, 조건 판이 둘인 과제(가장 큰 판의 회차를 쓰고, 그 판에 갈래가 빠지면 과제를 뺀다), 같은 조건 판에서 측정 회차가 둘인 과제, "셀 수 없음", 되풀이가 다른 갈래를 고를 때의 문구를 본다.
- 선례: `tests/tools/test_model_sweep_judge.py`(사전 등록 해시와 부트스트랩 판정), `tests/tools/test_canary.py`(한도 표지, 러너를 시험에서 갈아 끼움), `tests/tools/test_tidy_checkouts.py`(임시 저장소로 지우는 길을 반박), `tests/tools/test_hook_prompt_directive.py`(지시문 알아보기), `tests/tools/test_open_session.py`.
- 판정과 숨은 시험 가르기의 갈림(후보 조건 셋, 결론 없음 셋, 조건 2의 실패 종류)을 시험보다 먼저 지은 자리가 있으면 `tools/mutate.py`로 그 시험의 빨강을 본다(`.claude/rules/probes.md` 첫 항목의 표지).

## Out of Scope

- 본 측정을 돌고 판정하는 일, ADR 0029 이력 초안과 승인, 그 이력의 "함께 고치는 것"(`tools/model_sweep.py`의 `SWEPT`에서 구현을 빼는 것 등). 마지막 티켓이 병합된 직후 `next-session`이 본 측정의 지시문을 낸다(설계 9절 7·8, 11절).
- 2차(계획과 실행 나누기, 서브에이전트의 모델). 설계 10절이고 1차 판정 뒤에 연다.
- web(Vitest) 숨은 시험(사용자가 골랐다). 넣으려면 실패 종류와 TypeScript 이름 뽑기를 새로 정해야 한다.
- 하네스 칸과 데스크톱 앱 세션의 재현(설계 11절 한계).
- Claude Code가 Sonnet 5.5의 캐시 읽기를 셈하는 단가가 `docs/model-selection.md` 3절과 사용량 장부의 단가표(`tools/token_report.py`)가 적은 것($0.20)과 달랐던 일. 이 명세는 그 단가에 기대지 않게 공식 단가의 셈을 함께 남기는 것까지다. 지표 문서와 장부 단가표를 판마다 다시 맞추는 일은 받는 쪽이 정해지지 않아 이 명세의 일지 "다음"에 남긴다.

## Further Notes

- 설계 문서는 승인받은 판의 문장을 그대로 두고, 머리에 이 명세가 몇 자리를 고쳤다고 가리키는 문단 하나만 더했다. 고친 자리는 이 명세 본문이 설계의 절을 들어 적었고(대개 "설계 N절의 …를 고친다" 꼴이고, 설계의 일이 없어진 자리는 "지을 일이 없다"처럼 적었다), 고친 내용의 원천은 이 명세다.
- 8f8c54f8까지 커밋 시각이 2026-10-12 이후인 `feat` 병합 커밋은 26개이고, 그 가운데 `done`으로 바뀐 티켓 파일이 정확히 하나인 것은 25개였다(`git log 8f8c54f8 --since=2026-10-12 --grep=^feat --format=%h%x09%s --name-only -G "^\*\*Status:\*\* done" -- ".scratch/*/issues/*.md"`가 커밋마다 파일 하나씩 25개를 낸다. 손으로 봤다. `-G`는 그 줄이 더해지거나 빠진 파일을 내므로, 25개 모두 B에서 `done`이 아니었던 것은 B와 M의 Status 줄을 세션 스크래치 스크립트로 찍어 따로 봤다). 날짜는 M의 커밋 시각이고 후보 조건(B의 시각)과 하루 안에서 다를 수 있다. 숨은 시험·바깥 검증·비용 조건으로 빠지는 것을 생각하면 열둘을 채우려고 2026-10-12 앞으로 거슬러 채울 가능성이 크다(어림). 그 25개 가운데 `tests/` 아래 `.py`를 바꾼 것은 17개다(`git log 8f8c54f8 --since=2026-10-12 --grep=^feat --format=%h -- "tests/*.py"`가 17개를 내고 모두 25개 안이다. 손으로 봤다).
- 설계 8절의 파일럿 확인 가운데 이 명세가 잰 것은 기본 설정 폴더와 Sonnet low에서다. 전용 설정 폴더, njh6803, Opus와 다른 노력의 동작은 재지 않았다. 잰 계정의 주간 사용률이 0.97이라 이 세션에서 더 띄우지 않았다. 프로브는 `--setting-sources project,local`로 돌아 사람의 사용자 설정을 뺐고, 러너는 설계 5절대로 `user,project,local`이다. 러너의 `user`는 전용 설정 폴더의 설정이고, 그 차이는 파일럿이 본다(`probes/README.md` 못 본 것).
- 서브에이전트가 백그라운드로 뜨는 때는 네 번 가운데 한 번이었고 무엇이 갈랐는지 보지 않았다. 결과 글을 읽는 규칙이 두 경우를 모두 받는다.

## 거부한 안

1. **도구를 `.scratch/model-rerun/probes/`에만 두고 계산만 시험한다.** 설계 9절 2의 문장 그대로다. 러너의 이어 가기·예산·한도·끄기 결함이 파일럿(어림 $65~115)에서야 드러나고, 고치면 그 회차를 다시 돈다. 사용자가 회차 고리까지 시험하는 안을 골랐다(사용자가 골랐다).
2. **web(Vitest) 시험도 숨은 시험으로 쓴다.** 실패 종류와 TypeScript 이름 뽑기를 새로 짓고 파일럿에서 판정을 정해야 하는데, 2026-10-12 뒤 web 시험을 바꾼 feat 커밋은 둘이라 과제가 많아야 둘 는다(사용자가 골랐다).
3. **러너가 기록의 사용량을 보며 회차를 끈다.** 설계 5절이 예산 플래그가 멈추지 않을 때를 위해 둔 길이다. 프로브에서 플래그가 구독 로그인에서 멈췄고 호출의 몫을 셌다. 남은 값을 넘기는 것으로 충분하고, 사용량을 셈해 끄는 길은 끄는 순간의 경합과 pid 확인을 더할 뿐이다(명세가 정했다).
4. **GitHub 주소의 WebFetch만 막는다.** 설계 5절의 범위다. 저장소가 공개라 검색과 다른 주소로도 병합된 풀이를 읽을 수 있고, 주소마다 막으면 리뷰가 새 주소를 찾을 때마다 한 줄씩 는다(`.claude/rules/tools.md`의 허용 목록 항목과 같은 까닭). 웹 도구를 통째로 막는다(명세가 정했다).
