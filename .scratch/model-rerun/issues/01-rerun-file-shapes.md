# 01: 두 계약 파일의 꼴 — 과제 목록과 회차 기록의 키·형·판을 한 모듈에 짓고, 세 도구가 그것으로 읽고 쓴다

**What to build:** 과제 고르기, 회차, 판정의 세 도구가 주고받는 파일 둘(과제 목록, 회차 기록)의 꼴을 `tools/`의 넷째 모듈 하나에 짓는다. 키 이름, 형, 맨 위 모양, 꼴 판, 읽고 쓰는 함수, `records/`의 파일 이름을 이 모듈이 정한다. 뒤의 티켓(고르기 05, 회차 04·06~10, 판정 03)은 각자의 픽스처 꼴을 짓지 않고 이 모듈의 함수로 파일을 짓고 읽는다. 그래서 그 티켓들이 나란히 돌아도, 각자 초록이면서 파일럿에서 처음 서로 맞지 않는 일이 없다(스토리 38). 이 모듈은 하위 프로세스를 부르지 않는다. 판정이 이 모듈만 import해도 회차 도구의 바깥 몫을 끌어오지 않는다.

근거는 `.scratch/model-rerun/spec.md`의 "자리와 모듈"과 그 2026-10-22 주석, "과제 목록의 칸"과 그 주석(갈래 계획, 파일럿의 층 값, 숨은 시험 파일), "씨앗"의 주석(갈래 계획을 고르기가 적는다), "회차 기록"의 칸과 그 주석(판정이 읽는 칸, 대신 셈한 모델, 끝에 더한 준비와 호출), "준비"의 주석(측정 아님(준비)), "이어 가기와 끝"의 갈래 셋 주석(측정 아님(호출)), "게이트와 숨은 시험"의 주석(결과 작업 트리의 준비 실패), "상한과 끄기"의 주석(끈 호출의 비용을 대신 넣은 표시), "차례, 동시성, 예산"의 다시 띄우기 주석(회차 번호를 잡는 자리)과 2026-10-23 주석(측정 아님(중단)), "한도"의 2026-10-23 주석(풀리는 시각을 모르는 한도)이다. 명세 검토의 blocker C2가 이 티켓이 되었다(일지 2026-10-22-25). 갈래 다섯의 모델과 노력은 설계(`.scratch/model-rerun/design.md`) 4절이다.

이 티켓은 계약이라 02·03·04를 막는다(`CLAUDE.md` 작업 규약 2). 칸을 이 티켓에서 더하거나 바꾸면 명세의 그 절도 같이 고친다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 공통

- [ ] **갈래 다섯의 이름(A~E)과 모델·노력이 이 모듈의 상수다.** A `claude-opus-5-5`/`xhigh`, B Opus/`high`, C Opus/`medium`, D `claude-sonnet-5-5`/`high`, E Sonnet/`medium`이다(설계 4절). 지시문의 `모델:` 줄에 쓰는 사람의 이름(`Opus 5.5 / xhigh` 꼴)도 이 상수에서 낸다
- [ ] **두 파일 모두 꼴 판(정수)을 맨 위에 든다.** 읽는 함수는 모르는 판, 빠진 키, 형이 다른 값, 모르는 키를 오류로 거부한다. JSON을 타입 우회 없이 형 있는 값으로 푸는 길은 원칙 III를 따른다(`Any`·`cast` 없이 값마다 형을 확인한다)
- [ ] **쓰는 함수는 읽는 함수가 받는 꼴만 낸다.** 지은 값을 쓰고 다시 읽으면 같은 값이 나오는 것을 시험이 두 파일 모두에서 본다

### 과제 목록

- [ ] **목록 하나는 머리와 과제의 열이다.** 머리에 꼴 판과 목록의 종류(파일럿, 본 측정)가 든다. 파일럿 목록과 본 측정 목록은 따로 두 파일이고, 한 목록의 과제가 그 목록의 종류와 다른 `파일럿인지` 값을 가지면 읽기가 거부한다
- [ ] **과제마다 명세 "과제 목록의 칸"의 칸과 주석이 더한 갈래 계획이 든다.** 과제 id(`<slug>-<NN>`), 티켓 경로, B와 M(40자 커밋 해시), 원래 브랜치, 층(작은·중간·큰·파일럿), 크기 지표, 실행 차례, 파일럿인지, PR 앞 비용, 회차 상한, 숨은 시험 ID 목록, 시험 지원 파일 목록, 원래 세션의 모델과 레벨, 갈래 계획(갈래 이름의 차례 있는 목록. 같은 갈래가 두 번 들 수 있다)이다
- [ ] **숨은 시험 파일 목록은 칸으로 두지 않는다.** 숨은 시험 ID의 `::` 앞에서 꺼내는 함수 하나가 내고, 게이트(07)와 고르기(05)가 그 함수를 쓴다
- [ ] **한 목록 안에서 과제 id와 실행 차례가 겹치면 읽기가 거부한다**

### 회차 기록

- [ ] **회차 하나가 JSON 한 파일이고, 명세 "회차 기록"의 칸이 모두 든다.** 식별, 환경, 세션마다(호출마다의 종류·넘긴 예산·종료 코드·결과 이벤트 칸), 이어 가기, 끝, 결과, 비용과 탐색이다. 주석이 더한 칸(공식 단가 셈에서 `modelUsage`로 대신 셈한 모델과 그 토큰)도 든다. 커밋하는 기록에는 모델이 쓴 글과 도구 입력을 담을 칸이 없다. 수, 식별자, 참거짓, 정해진 이름(오염 꼴의 이름, 도구 이름, 넘긴 환경 변수의 이름)만 담는다(`.claude/rules/tools.md`의 허용 목록 항목)
- [ ] **돌지 않은 몫의 칸은 비어 있을 수 있다.** 결과 커밋이 없거나 측정 아님으로 끝난 회차에는 결과 커밋, 게이트 셋의 종료 코드, 숨은 시험의 수가 없다. 빈 값과 0을 가른다(게이트가 돌지 않은 것과 종료 0은 다르다)
- [ ] **뒤 티켓이 적는 칸이 처음부터 든다.** 게이트마다 종료 코드나 시간 넘김(07), 결과 작업 트리의 준비가 실패했으면 그 명령과 종료 코드(07, 명세 "게이트와 숨은 시험"의 주석), 끄지 않고 기록한 호출(명령 줄에 세션 id가 없었다, 08), 세션마다 러너가 끈 호출이 있었는지(08), 끈 호출이나 결과 이벤트 없이 끝난 호출이 든 세션의 비용을 공식 단가 셈으로 대신 넣었다는 표시(10, 명세 "상한과 끄기"의 주석과 "차례, 동시성, 예산"의 2026-10-23 주석)다
- [ ] **끝은 종류와 하위 이유 두 칸이다.** 종류는 `끝남`, `상한으로 끊김`, `측정 아님` 셋이다. 하위 이유는 상한이면 개입·세션·예산·시간, 측정 아님이면 한도·오염·모델·설정·준비·호출·중단이고, 끝남이면 비어 있다. 중단은 죽은 러너가 남긴 회차를 다시 뜬 러너가 적는 것이다(명세 "차례, 동시성, 예산"의 2026-10-23 주석). 값의 모임은 이 모듈의 상수이고, 종류와 맞지 않는 하위 이유는 읽기가 거부한다. 한도면 `resetsAt`이 들고, 풀리는 시각을 모르는 한도는 그 칸을 비워 적는다(명세 "한도"의 2026-10-23 주석). 빈 값과 시각을 가른다
- [ ] **`records/`의 파일 이름은 이 모듈의 함수가 과제 id, 갈래, 회차 번호에서 낸다.** 회차 번호는 같은 과제·갈래 안에서 조건 판을 넘어 이어 세므로 파일 이름이 겹치지 않는다. 쓰기는 이미 있는 파일을 덮지 않고 오류로 멈춘다
- [ ] **회차 폴더의 이름(`<과제 id>-<갈래>-<회차 번호>-<짧은 난수>`)을 짓고 푸는 함수와, 다음 회차 번호를 내는 함수를 여기 둔다.** 다음 번호는 `records/`의 기록과 뿌리 아래 회차 폴더의 이름을 함께 받아 그 과제·갈래의 가장 큰 번호 다음이다. 기록은 회차가 끝날 때 쓰므로 `records/`만 보면 동시에 도는 두 회차(같은 갈래가 두 번 든 파일럿 과제)와 죽은 러너가 남긴 회차가 같은 번호를 받고, 둘째 기록 쓰기가 돈을 쓴 뒤에 오류로 멈춘다(명세 "차례, 동시성, 예산"의 주석). 번호를 잡고 폴더를 만드는 차례는 10이 지킨다
- [ ] **판정이 읽는 칸을 모은 읽기 함수가 있다.** 명세 "회차 기록"의 판정이 읽는 칸(끝, 게이트, 숨은 시험, 비용 둘, 개입, 물으며 끝남, 판, 조건 판)과 주석이 더한 식별·탐색 칸이다. 판정(03)은 이 함수로 읽는다

### 시험과 검증

- [ ] **꼴의 사례**: 두 파일의 쓰고 다시 읽기, 모르는 판, 빠진 키, 형이 다른 값, 모르는 키, 종류와 맞지 않는 끝의 하위 이유, 하위 이유 중단, `resetsAt`이 빈 한도 기록, 파일럿 목록에 든 본 측정 과제, 겹친 과제 id와 실행 차례, 이미 있는 기록 파일 덮어쓰기 거부, 다음 회차 번호가 조건 판을 넘어 이어지는 것과 기록이 없는 회차 폴더의 번호를 비켜 가는 것, 회차 폴더 이름을 짓고 푸는 것(과제 id에 `-`가 든 이름), 노드 ID에서 숨은 시험 파일을 꺼내는 것(매개변수화한 노드 ID 포함)
- [ ] **이 모듈이 하위 프로세스를 부르는 모듈을 import하지 않는다**를 시험으로 본다. 판정이 회차 도구의 바깥 몫을 끌어오지 않게 하려는 것이다
- [ ] **원칙 III를 지킨다**
- [ ] 검증 명령이 모두 초록이다
- [ ] **기능을 닫지 않는다**
