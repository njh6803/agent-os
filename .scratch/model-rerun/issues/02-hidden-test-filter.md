# 02: 숨은 시험 가르기 — 후보 하나의 원래 PR 시험 가운데, 흔들리지 않고 B에서 단언으로 실패하며 새 이름에 기대지 않는 노드만 남긴다

**What to build:** 후보 하나(B와 M)를 받아 숨은 시험 ID 목록, 시험 지원 파일 목록, 노드마다 빠진 이유를 낸다. M이 바꾼 파이썬 시험 함수를 찾고, 세 조건으로 거른다. M에서 두 번 다 통과한 노드만 남고(스토리 3), B에 덮어 돌렸을 때 단언에서 실패하는 노드만 남으며(스토리 4), 본문이 PR이 처음 지은 이름에 기대는 함수의 노드는 빠진다(스토리 5). 가르는 함수는 값만 받고, 작업 트리를 꺼내고 pytest와 `git grep`을 부르는 몫은 얇은 바깥 층이다. 05(과제 고르기)가 후보마다 이것을 부른다.

근거는 `.scratch/model-rerun/spec.md`의 "숨은 시험 가르기" 전체와 조건 3의 2026-10-22 주석(본문만 보는 한계), "자리와 모듈"의 셋째·넷째 항목(값만 받는 함수, 시간 제한), Testing Decisions의 "과제 고르기와 숨은 시험 가르기"와 마지막 항목(`tools/mutate.py`)이다. 설계 3절의 조건을 명세가 고친 자리(web 시험을 쓰지 않는다, 조건 3의 찾는 자리)는 명세가 원천이다.

01의 꼴(노드 ID에서 시험 파일을 꺼내는 함수)을 쓴다. 이 티켓은 05를 막는다. web(Vitest) 시험은 다루지 않는다(명세 Out of Scope).

### 바뀐 시험과 단위

- [x] **바뀐 시험은 M과 B의 `tests/` 아래 시험 파일에서 AST로 견준 시험 함수다.** 모듈 수준의 `test_*`와 `Test*` 클래스의 `test_*` 메서드 가운데 M에 새로 생겼거나 함수 정의(데코레이터 포함)의 AST 덤프가 다른 것이다
- [x] **시험의 단위는 pytest의 노드 ID다.** 매개변수화한 시험은 경우마다 따로 세고, 조건 3은 함수 본문으로 보므로 같은 함수의 경우들이 함께 남거나 빠진다
- [x] **시험 지원 파일은 M이 바꾼 `conftest.py`와 `tests/` 아래 `test_`로 시작하지 않는 `.py`다.** 조건 2의 덮기와 게이트(07)의 덮기가 이 목록을 쓴다

### 세 조건 (값만 받는 함수)

- [x] **가르는 함수는 git·pytest를 부르지 않는다.** 입력은 노드마다의 M 두 번 결과, B에 덮은 결과와 실패의 `message` 머리, 함수 본문의 이름과 문자열, 이름과 문자열마다 M과 B에 있는지다. 출력은 남은 노드 ID와 빠진 노드마다의 이유(어느 조건, 어떤 실패 종류, 어떤 이름)다
- [x] **조건 1.** 두 번 다 통과한 노드만 남는다. 한 번이라도 실패하거나 건너뛰면 빠진다
- [x] **조건 2.** junit xml로 가른다. `error` 요소(모음과 준비의 실패)인 노드, `failure`의 `message`가 `AttributeError`·`NameError`·`TypeError`로 시작하는 노드, 통과하거나 건너뛴 노드는 빠지고, 그 밖의 `failure`(단언 실패와 다른 예외)는 남는다. 모음 오류로 파일이 통째로 실패하면 그 파일의 노드가 모두 빠진다
- [x] **조건 3.** 함수 본문의 AST에서 이름(`Name`의 id, `Attribute`의 attr)과 길이가 둘 이상인 문자열 상수를 모은다. 하나라도 M의 `tests/` 밖 추적 파일에 있고 B의 추적 파일 어디에도 없으면 그 함수의 노드가 모두 빠진다. 본문이 부르는 모듈 수준 상수와 도우미 안의 이름은 보지 않는다(명세 주석의 한계). 이 한계를 독스트링의 못 보는 것에 적는다(`.claude/rules/tools.md`의 못 보는 것 항목)

### 바깥 층

- [x] **B와 M을 꺼낸 작업 트리에서 pytest를 돌린다.** M에서는 바뀐 시험을 두 번, B에서는 M의 시험 파일과 지원 파일을 덮고 한 번이다. 이름은 낱말 경계로(`git grep -w -F`), 문자열은 고정 문자열로(`git grep -F`) 찾는다. pytest를 띄우는 명령은 함수의 인자로 받고, 실제 명령은 상수로 따로 단언한다
- [x] **pytest는 그 작업 트리의 파이썬 환경으로 돈다.** 작업 트리마다 `uv sync`를 돌고 그 작업 트리를 작업 폴더로 `uv run pytest`를 띄운다. 러너 체크아웃의 `.venv`는 `agent_os`를 편집 설치로 러너의 `src/`에 묶어, 그 파이썬으로 돌면 B에 덮은 시험이 B가 아니라 러너의 새 코드로 돌아 통과하고 조건 2가 `src/`를 고친 후보의 시험을 모두 뺀다(명세 "숨은 시험 가르기"의 2026-10-23 주석). 준비 명령도 함수의 인자로 받고, 실제 명령은 상수로 따로 단언한다. 시험은 두 명령이 그 작업 트리를 작업 폴더로 도는 것을 본다. 05의 실제 후보 표에서 `src/`를 고친 후보의 숨은 시험이 모두 0이면 이 자리부터 본다
- [x] **`git grep`에는 이름과 문자열을 `-e`로 넘긴다.** `-`로 시작하는 문자열(시험의 인자 `--resume` 같은 것)을 패턴 자리에 그대로 두면 git이 옵션으로 읽어 종료 129로 끝난다. 종료 0은 있음, 1은 없음이고, 그 밖은 그 후보의 실패 갈래로 센다. `git grep`은 줄바꿈이 든 패턴을 줄마다 따로 찾아 한 줄만 있어도 있다고 답하므로, 줄바꿈이 든 문자열 상수는 줄마다 나눠 길이가 둘 이상인 줄 하나를 문자열 하나로 센다(git 2.32에서 손으로 봤다, 명세 같은 주석)
- [x] **하위 프로세스 호출마다 시간 제한을 두고, 넘김은 그 후보의 실패 갈래로 센다**(`.claude/rules/tools.md`의 시간 제한 항목, `tools/check_instructions.py`의 `calls_without_timeout`)
- [x] **git을 띄우는 자리와 그 시험은 `tools.run_hooks.REPO_LOCATION_VARS`를 자식 환경에서 벗긴다**(`.claude/rules/tools.md`의 pre-commit 항목)
- [x] **꺼낸 작업 트리는 성공·실패·시간 넘김 어느 길에서도 걷고, 걷은 뒤 그 저장소의 등록 목록이 부르기 전과 같다.** 걷는 길은 지우는 도구 항목을 따른다. 링크는 따라가지 않고 링크만 끊는다(선례 `tools/canary.py`의 `_cut_links`). 커밋 전에 임시 저장소에서 그 판정을 깨려는 입력(작업 트리 안의 링크, 커밋하지 않은 파일)으로 반박한다

### 메모(구현 세션)

- 가르기는 새 모듈 `tools/rerun_hidden.py`에 두었다. 05의 고르기 모듈이 `sort_candidate`를 import한다. 명세 "자리와 모듈"은 바깥 층을 고르기 도구의 몫이라 했고, 고르기 모듈이 아직 없어 그 몫을 따로 둔 모듈로 지었다.
- pytest에는 바뀐 시험의 노드 ID가 아니라 그 시험이 든 파일을 넘기고, junit에서 바뀐 시험의 노드만 읽는다. 모으지 못한 파일의 노드 ID를 받은 pytest는 `--continue-on-collection-errors`가 있어도 `found no collectors`로 실행 전체를 멈춰, B의 모음 오류 하나가 모든 노드를 "결과 없음"으로 만들었다(이 모듈의 끝까지 시험이 재현하고, 변이 표가 그 되돌림을 잡는다).
- 01의 봇이 보류한 경로 칸은 허용 목록으로 좁혔다(`tools/rerun_files.py`의 `is_test_file`·`is_support_file`). 바깥 층은 그 꼴에 드는 경로만 시험 파일과 지원 파일로 고른다.
- 셀프 리뷰에서 고친 것: M에서 돌지 않은 바뀐 시험(마커로 빠졌거나 M에서 모으지 못했다)이 결과에서 까닭 없이 사라지던 것을 조건 1의 "결과 없음"으로 빼게 했다(`node_facts`). B의 작업 트리에 덮지 못한 `OSError`가 `Failure`가 아닌 예외로 새던 것을 실패 갈래로 바꿨다. 변이 표지 셋이 시험 소스의 조각이던 것을 고른 단언이 실패할 때만 나오는 줄로 바꿨다.
- PR 봇 첫 회차에서 정한 것: M에서 풀리지 않는 시험 파일(구문 오류, NUL)은 그 후보의 실패 갈래(`CandidateError`가 `Failure`로)이고, B에서 풀리지 않는 파일은 그 파일의 시험을 모두 새것으로 센다. 명세와 이 티켓은 풀리지 않는 파일을 정하지 않았고, M을 풀지 못하면 바뀐 시험을 하나도 알 수 없어 빈 `Hidden`을 성공처럼 돌려줄 수 없다.
