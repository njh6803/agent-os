# 02: 숨은 시험 가르기 — 후보 하나의 원래 PR 시험 가운데, 흔들리지 않고 B에서 단언으로 실패하며 새 이름에 기대지 않는 노드만 남긴다

**What to build:** 후보 하나(B와 M)를 받아 숨은 시험 ID 목록, 시험 지원 파일 목록, 노드마다 빠진 이유를 낸다. M이 바꾼 파이썬 시험 함수를 찾고, 세 조건으로 거른다. M에서 두 번 다 통과한 노드만 남고(스토리 3), B에 덮어 돌렸을 때 단언에서 실패하는 노드만 남으며(스토리 4), 본문이 PR이 처음 지은 이름에 기대는 함수의 노드는 빠진다(스토리 5). 가르는 함수는 값만 받고, 작업 트리를 꺼내고 pytest와 `git grep`을 부르는 몫은 얇은 바깥 층이다. 05(과제 고르기)가 후보마다 이것을 부른다.

근거는 `.scratch/model-rerun/spec.md`의 "숨은 시험 가르기" 전체와 조건 3의 2026-10-22 주석(본문만 보는 한계), "자리와 모듈"의 셋째·넷째 항목(값만 받는 함수, 시간 제한), Testing Decisions의 "과제 고르기와 숨은 시험 가르기"와 마지막 항목(`tools/mutate.py`)이다. 설계 3절의 조건을 명세가 고친 자리(web 시험을 쓰지 않는다, 조건 3의 찾는 자리)는 명세가 원천이다.

01의 꼴(노드 ID에서 시험 파일을 꺼내는 함수)을 쓴다. 이 티켓은 05를 막는다. web(Vitest) 시험은 다루지 않는다(명세 Out of Scope).

**Blocked by:** 01

**Status:** ready-for-agent

### 바뀐 시험과 단위

- [ ] **바뀐 시험은 M과 B의 `tests/` 아래 시험 파일에서 AST로 견준 시험 함수다.** 모듈 수준의 `test_*`와 `Test*` 클래스의 `test_*` 메서드 가운데 M에 새로 생겼거나 함수 정의(데코레이터 포함)의 AST 덤프가 다른 것이다
- [ ] **시험의 단위는 pytest의 노드 ID다.** 매개변수화한 시험은 경우마다 따로 세고, 조건 3은 함수 본문으로 보므로 같은 함수의 경우들이 함께 남거나 빠진다
- [ ] **시험 지원 파일은 M이 바꾼 `conftest.py`와 `tests/` 아래 `test_`로 시작하지 않는 `.py`다.** 조건 2의 덮기와 게이트(07)의 덮기가 이 목록을 쓴다

### 세 조건 (값만 받는 함수)

- [ ] **가르는 함수는 git·pytest를 부르지 않는다.** 입력은 노드마다의 M 두 번 결과, B에 덮은 결과와 실패의 `message` 머리, 함수 본문의 이름과 문자열, 이름과 문자열마다 M과 B에 있는지다. 출력은 남은 노드 ID와 빠진 노드마다의 이유(어느 조건, 어떤 실패 종류, 어떤 이름)다
- [ ] **조건 1.** 두 번 다 통과한 노드만 남는다. 한 번이라도 실패하거나 건너뛰면 빠진다
- [ ] **조건 2.** junit xml로 가른다. `error` 요소(모음과 준비의 실패)인 노드, `failure`의 `message`가 `AttributeError`·`NameError`·`TypeError`로 시작하는 노드, 통과하거나 건너뛴 노드는 빠지고, 그 밖의 `failure`(단언 실패와 다른 예외)는 남는다. 모음 오류로 파일이 통째로 실패하면 그 파일의 노드가 모두 빠진다
- [ ] **조건 3.** 함수 본문의 AST에서 이름(`Name`의 id, `Attribute`의 attr)과 길이가 둘 이상인 문자열 상수를 모은다. 하나라도 M의 `tests/` 밖 추적 파일에 있고 B의 추적 파일 어디에도 없으면 그 함수의 노드가 모두 빠진다. 본문이 부르는 모듈 수준 상수와 도우미 안의 이름은 보지 않는다(명세 주석의 한계). 이 한계를 독스트링의 못 보는 것에 적는다(`.claude/rules/tools.md`의 못 보는 것 항목)

### 바깥 층

- [ ] **B와 M을 꺼낸 작업 트리에서 pytest를 돌린다.** M에서는 바뀐 시험을 두 번, B에서는 M의 시험 파일과 지원 파일을 덮고 한 번이다. 이름은 낱말 경계로(`git grep -w -F`), 문자열은 고정 문자열로(`git grep -F`) 찾는다. pytest를 띄우는 명령은 함수의 인자로 받고, 실제 명령은 상수로 따로 단언한다
- [ ] **하위 프로세스 호출마다 시간 제한을 두고, 넘김은 그 후보의 실패 갈래로 센다**(`.claude/rules/tools.md`의 시간 제한 항목, `tools/check_instructions.py`의 `calls_without_timeout`)
- [ ] **git을 띄우는 자리와 그 시험은 `tools.run_hooks.REPO_LOCATION_VARS`를 자식 환경에서 벗긴다**(`.claude/rules/tools.md`의 pre-commit 항목)
- [ ] **꺼낸 작업 트리는 성공·실패·시간 넘김 어느 길에서도 걷고, 걷은 뒤 그 저장소의 등록 목록이 부르기 전과 같다.** 걷는 길은 지우는 도구 항목을 따른다. 링크는 따라가지 않고 링크만 끊는다(선례 `tools/canary.py`의 `_cut_links`). 커밋 전에 임시 저장소에서 그 판정을 깨려는 입력(작업 트리 안의 링크, 커밋하지 않은 파일)으로 반박한다

### 시험과 검증

- [ ] **가르는 함수의 사례**(명세 Testing Decisions): 작은 시험 소스 두 판(B와 M)에서 바뀐 시험 함수 찾기(새 함수, 데코레이터만 바뀐 함수, 바뀌지 않은 함수, `Test*` 클래스의 메서드), junit xml 조각(통과, 단언 실패, `AttributeError` 실패, 모음 `error`, 건너뜀, 매개변수화한 경우), 조건 1에서 두 번 가운데 한 번 실패한 노드, 이름과 문자열의 M·B 유무에서 조건 3(이름은 낱말 경계, 문자열은 고정 문자열, 한 글자 문자열은 보지 않음)
- [ ] **바깥 층의 사례**: B와 M 커밋이 있는 임시 저장소와 작은 pytest 시험으로 숨은 시험 ID와 빠진 이유가 끝까지 나오는 것, 시간 넘김이 실패 갈래가 되는 것, 그 뒤 등록된 작업 트리가 남지 않는 것
- [ ] **갈림을 시험보다 먼저 지은 자리가 있으면 `tools/mutate.py`로 그 시험의 빨강을 본다.** 조건 2의 실패 종류 셋과 조건 3의 B 유무가 대상이다. 표지는 고른 단언이 실패할 때만 나오는 문구로 고른다(`.claude/rules/probes.md` 첫 항목)
- [ ] **원칙 III를 지킨다**
- [ ] 검증 명령이 모두 초록이다
- [ ] **기능을 닫지 않는다**
