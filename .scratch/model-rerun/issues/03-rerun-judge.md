# 03: 다시 풀기 판정 — 본 측정의 회차 기록에서 갈래마다 푼 수와 비용 비를 내고, 사전 등록의 해시가 맞을 때만 결론을 낸다

**What to build:** 판정 명령이 본 측정의 과제 목록, `records/`의 회차 기록, 프로브 README의 사전 등록 절을 읽어 갈래마다의 표(S, C, U, R과 그 구간, 개입이 A보다 많은 과제 수, 물으며 끝남, 상한으로 끊김)와 결론 한 줄(새 칸, 칸을 둠, 결론 없음)을 낸다. 사전 등록 절의 해시가 판정 도구의 상수와 다르면 결론을 내지 않는다(스토리 40). 후보 조건 셋과 결론 없음 조건은 설계 6절 그대로다(스토리 41). 공식 단가로 셈한 되풀이와 숨은 시험 없이 센 되풀이를 함께 내고(스토리 42), 과제 하나의 갈래 사이에 Claude Code 판이 다르면 그 과제를 뺀다(스토리 43). 결론은 ADR 0029 이력 초안의 재료이고, 초안과 승인은 이 기능 밖이다.

근거는 `.scratch/model-rerun/spec.md`의 "판정" 전체와 부트스트랩의 2026-10-22 주석, "회차 기록"의 판정이 읽는 칸과 그 주석(식별·탐색 칸, 대신 셈한 회차 수), Testing Decisions의 "판정"과 마지막 항목(`tools/mutate.py`)이다. 정의의 원천은 설계(`.scratch/model-rerun/design.md`) 6절이고 명세가 고친 자리(비용은 세션마다 마지막 값, 되풀이의 공식 단가, 탐색의 물으며 끝남)는 명세가 원천이다. 선례는 `tools/model_sweep_judge.py`(부트스트랩과 `percentile_ci`)와 `tools/model_sweep.py`의 `prereg_section`, 그 시험 `tests/tools/test_model_sweep_judge.py`다.

01의 꼴로 두 파일을 읽는다. 회차 도구(04·06~10)와 나란히 돌고, 회차 도구의 모듈을 import하지 않는다. 사전 등록 절과 그 해시 상수의 실제 값은 11이 넣는다. 그때까지 상수는 어떤 절과도 맞지 않는 값이라 명령 줄의 판정은 늘 결론 없음이다(README에 절이 없는 동안은 표지가, 절만 넣고 상수를 두면 해시가 맞지 않는다). 그래서 판정 함수는 기대 해시를 인자로 받고, 명령 줄 입구만 상수를 넘긴다. 시험은 지은 README 글의 해시를 넘겨 후보 사례를 본다. 러너(10)는 이 티켓의 절 꺼내기와 해시 상수를 import해 본 측정 목록을 열기 전에 대 보므로, 이 티켓은 10과 11을 막는다.

### 쓰는 회차

- [x] **본 측정의 회차만 쓴다.** 파일럿 표시가 있는 기록은 읽되 셈에 넣지 않는다
- [x] **과제마다 가장 큰 조건 판의 회차만 쓴다.** 그 판에 측정인 회차가 없는 갈래가 있으면 그 과제를 T에서 뺀다. 같은 조건 판 안에서 과제와 갈래마다 측정인 회차가 둘 이상이면 회차 번호가 가장 작은 것을 쓴다
- [x] **과제 하나의 쓰는 회차 사이에 `claude --version`이 다르면 그 과제를 T에서 뺀다**
- [x] **풀었다는 끝남이고, 게이트 셋이 모두 종료 0이고, 숨은 시험이 모두 통과한 것이다**(설계 6절 회차마다)

### 수와 후보

- [x] **T, S_k, C_k, U_k = C_k / S_k, R_k = U_k / U_A를 설계 6절대로 낸다.** 비용은 회차 기록의 비용(Claude Code의 셈)이다
- [x] **R_k의 90% 구간은 부트스트랩 2,000회다.** 회마다 T의 과제를 한 번 다시 뽑아 갈래 k와 A에 함께 쓰고, 구간의 정의는 `percentile_ci`와 같다. `random.Random(0)`은 갈래 k의 구간을 낼 때마다 새로 만들어, 모든 갈래가 같은 다시 뽑기 위에서 셈하고 갈래를 도는 차례가 수를 바꾸지 않는다. 다시 뽑은 표본에서 S_k나 S_A가 0이면 세지 않고, 그런 표본이 5%를 넘으면 그 갈래의 구간은 "셀 수 없음"이다(명세 주석)
- [x] **후보 조건 셋**(S_k ≥ S_A − 1, 개입 수가 A보다 많은 과제가 둘 이하, R_k의 구간 위 끝이 1 미만)을 모두 맞는 갈래가 후보다. "셀 수 없음"인 갈래는 셋째 조건을 맞지 못한다. 후보 가운데 U_k가 가장 작은 갈래가 새 칸이고, 후보가 없으면 칸을 `Opus 5.5 / xhigh`로 둔다
- [x] **결론 없음 셋**: T가 여섯보다 적다, S_A가 T의 절반보다 적다, 사전 등록 절의 해시가 다르다. 해시는 README의 `<!-- 사전 등록 시작 -->`·`<!-- 사전 등록 끝 -->` 사이 내용의 SHA-256을 상수와 대 본다. 표지가 없거나 하나뿐이어도 결론 없음이다(2026-10-23 셀프 리뷰: 둘 이상이어도 결론 없음이다. 다른 글에 적은 표지 사이를 절로 읽지 않게 한다)
- [x] **사전 등록 절을 꺼내는 함수와 기대 해시 상수는 공개 이름이다.** 러너(10)가 import한다. pyright strict는 다른 모듈의 밑줄 이름을 막는다(명세 "이어 가기와 끝"이 `_directive_branch`를 공개 이름으로 바꾸는 것과 같은 까닭)

### 되풀이와 탐색

- [x] **되풀이 둘**: 회차 기록의 공식 단가 셈으로 낸 판정과, 숨은 시험 없이 끝남과 게이트만으로 센 "풀었다"로 낸 판정이다. 되풀이로 고른 갈래가 본 판정과 달라지면 결론 줄에 "<단가 / 숨은 시험>에 따라 갈린다"를 붙인다
- [x] **공식 단가 셈에 `modelUsage`로 대신 셈한 몫이 든 회차 수를 출력에 적는다**(명세 "회차 기록"의 주석. Haiku의 단가 갈림을 가르지 못하는 몫이다)
- [x] **끈 호출의 비용을 공식 단가 셈으로 대신 넣은 회차 수와, 결과 작업 트리의 준비가 실패해 풀지 못한 회차 수를 갈래마다 출력에 적는다**(명세 "상한과 끄기"와 "게이트와 숨은 시험"의 주석). 앞의 것은 C_k에 두 셈이 섞인 몫이고, 뒤의 것은 일시 실패가 갈래의 실패로 셈해졌을 수 있는 몫이다
- [x] **탐색은 설계 6절의 줄 그대로이고, "`AskUserQuestion`을 부른 수"만 "물으며 끝남의 수"로 바꾼다.** 원래 세션과 A를 견주는 줄은 과제 목록의 원래 세션 모델과 레벨이 `xhigh`인 과제로만 낸다
