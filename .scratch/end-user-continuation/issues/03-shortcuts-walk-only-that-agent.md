# 03: 바로가기 — 시작 이벤트에 에이전트별 바로가기를 쓰고, 이어 가기와 재개는 그 에이전트의 실행만 따라간다

**What to build:** 새 대화의 첫 실행은 시작 이벤트에 빈 바로가기(지도)를 쓰고, 이어 간 실행은 앞 실행의 지도에 앞 실행 자신(그 에이전트 → 앞 실행)을 덮어 쓴 지도를 쓴다. 이어 가기는 지금 에이전트 A의 교환을 모을 때 지도에서 A의 실행으로 곧장 가고, 그 실행의 지도에서 A의 앞 실행으로 가기를 되풀이한다. 다른 에이전트의 실행은 읽지 않는다. A로 한 번, B로 k번 이어 간 뒤 A로 돌아와도 읽는 실행은 앞 실행과 A의 실행뿐이고 k와 무관하다. 앞 실행에 지도가 없는 옛 대화는 지도 없음이 이어지고 지금처럼 하나씩 따라간다. 지도가 가리킨 실행이 기록과 어긋나면 깨진 고리처럼 `PluginError`이고 메시지가 그 실행과 이유를 든다. 지도가 있는 이어 간 실행이 멈췄다가 재개되면 자기 지도로 같은 실행들을 다시 읽어 같은 멤버를 받는다. 운영자 채널, CLI, 최종 사용자 경로가 모두 core 한 자리에서 같은 지도를 쓴다.

01의 틈 가운데 바로가기를 닫는다. 01이 세운 `run_started`의 필드에 동작이 붙는다. 04를 막는다 — 교환 수와 상한과 스레드가 바로가기를 따라가는 읽기를 고치고, "상한에 닿는 것은 옛 대화뿐"이 이 티켓 뒤에야 참이다.

근거는 `.scratch/end-user-continuation/spec.md`의 "바로가기", "재개" 절, Testing Decisions의 core "바로가기 쓰기"·"바로가기 따라가기"·"바로가기 검증"·"재개" 항목과 바깥 이음매 절, 그리고 그 2026-10-16 명세 검토·to-tickets 주석이다. ADR 0022의 둘째 2026-10-15 이력이 앞선 결정이다.

### 쓰기

- [x] **새 대화(앞 실행 없음)는 빈 지도다.** 이어 가기는 앞 실행의 지도에 앞 실행 자신을 덮어 쓴 지도다. 고리는 끝난 실행만으로 이어지므로 지도의 실행은 모두 끝난 실행이다. 지도에는 이 실행보다 앞선 고리에 실행이 있는 에이전트마다 그 에이전트의 가장 최근 실행이 들고 크기는 대화에 나온 에이전트 수다
- [x] **옛 대화는 바로가기 없음이 이어진다.** 앞 실행의 시작 이벤트에 지도가 없으면(이 기능 전이나 01과 이 티켓 사이에 쓰인 실행) 새 실행도 없음을 쓴다. 그래서 지도가 있는 실행은 대화의 처음부터 모두 지도가 있는 실행이고 지도는 언제나 온전하다. 표지를 따로 두지 않고 없음이 그 표시다. 옛 대화를 지도로 옮기지 않는다(명세가 거부했다)
- [x] **운영자 채널, CLI, 최종 사용자 경로가 모두 core 한 자리에서 쓴다**

### 따라가기

- [x] **지금 에이전트 A의 교환은 새 실행의 지도에서 A의 실행으로 가고, 그 실행의 지도에서 A의 앞 실행으로 가기를 되풀이해 모은다.** 다른 에이전트의 실행은 읽지 않는다. 멈추는 자리는 지금 규칙 그대로다 — 가장 가까운 A의 요약을 만나면 그 덮는 끝에서 멈추고(덮는 끝은 읽지 않는다), 지도에 A가 없으면(A의 처음) 멈춘다
- [x] **에이전트가 받는 값은 지금과 같다.** A는 A의 교환만, B는 B의 교환만이다. `AgentContext.conversation`의 모양은 바뀌지 않는다
- [x] **판정 순서는 그대로다.** 앞 실행(없음 → 손상 → 다른 주체 → 끝나지 않음) → 고리(이제 바로가기를 따라가는 읽기) → 준비. 바로가기의 검증은 고리 덩어리에 든다. 거절된 이어 가기는 트레이스를 남기지 않는다
- [x] **옛 대화의 거슬러 읽기는 지금처럼 앞 실행을 하나씩 따라간다.** 상한은 04다

### 검증

- [x] **바로가기는 요청이 아니라 서버의 기록이 가리킨 것이라 어긋나면 깨진 고리처럼 `PluginError`이고 메시지가 그 실행과 이유를 든다.** 따라간 실행마다 본다 — 트레이스가 있다, 손상이 아니다(`link_of`와 기록 규칙), 주체가 대화의 주체와 같다, 에이전트가 지도의 키와 같다, `run_finished`로 끝났다, 그 실행의 지도가 있다(지도가 가리킨 실행은 같은 대화의 지도 있는 실행이어야 한다), 지나온 실행이 아니다(순환). 요약을 만났는데 덮는 끝을 만나지 못한 채 A의 처음에 닿아도 깨진 것이다(지금 규칙)
- [x] **기록 규칙(`check_record_rules`)이 지도의 키(플러그인 이름 패턴)와 값(실행 식별자 패턴)을 본다.** `RunStarted.previous_run`과 같은 규칙이고 모델에는 패턴을 걸지 않는다(01). 앞 실행 자신의 기록 규칙은 앞 실행의 에이전트가 A가 아니어서 따라가지 않을 때도 본다 — 새 실행의 지도가 앞 실행의 지도를 이어받아 거기 든 손상이 다음 실행들로 번지기 때문이다. 그 자리는 지금처럼 고리 덩어리(주체·끝남 뒤)다
- [x] **기록 규칙이 앞 실행을 따로 읽지 않고 볼 수 있는 일관성 둘을 더 본다**(명세 검토). 지도가 있는 실행에서, 앞 실행이 없으면 지도가 비어 있고, 앞 실행이 있으면 지도의 값 가운데 그 앞 실행이 있다. 이어 가지 않은 실행에 대화 요약 이벤트가 있으면 손상으로 보는 기록 규칙과 같은 모양이다. 지도의 키(그 앞 실행의 에이전트)는 앞 실행을 따로 읽어야 대므로 보지 않는다. 손으로 키 하나를 지운 지도는 이것으로도 잡히지 않고 받아들인다
- [x] **core 테스트.** 가리킨 실행이 없음, 손상, 다른 주체, 다른 에이전트, 끝나지 않음, 지도 없음, 순환, 패턴을 어긴 키나 값, 덮는 끝을 못 만남, 그리고 위 일관성 둘이 `PluginError`이고 메시지가 그 실행과 이유를 든다. 하위 타입이 아니다 — 따라간 실행의 손상도 기반 타입이고, 05의 새 하위 타입(주인을 확인하기 전의 손상)은 요청이 가리킨 실행에만 선다. 깨진 것을 단언하는 기존 모양(`not isinstance(…, _SUBTYPES)`)을 따르고, 05가 먼저 병합됐으면 05가 넓힌 모양(새 하위 타입도 아님)을 따른다

### 재개

- [x] **바로가기가 있는 실행의 재개는 자기 지도로 다시 읽는다.** 멈춘 실행의 시작 이벤트 지도에서 그 에이전트의 실행부터 따라간다. 앞 실행을 따로 읽지 않는다. 처음과 같은 실행을 같은 규칙으로 읽어 같은 멤버를 주므로 재생 대조가 통과한다
- [x] **자기 요약의 규칙은 그대로다.** 멈춘 실행의 트레이스에 요약 이벤트가 있으면 이미 만난 요약이고 그 덮는 끝에서 멈춘다. 덮는 끝이 지도의 그 에이전트 칸이면(가장 최근 교환까지 접혔다) 아무것도 읽지 않는다 — 지금 "덮는 끝이 앞 실행 자신이면"의 일반화다
- [x] **옛 대화의 재개는 지금처럼 앞 실행에서 하나씩 따라간다.** 주체의 비교 대상은 멈춘 실행의 `run_started` 주체다(지금 그대로)
- [x] **재개의 첫 걸음에 `await`가 없다는 불변식은 그대로다**(ADR 0014). 재개의 거슬러 읽기는 이벤트 루프 위에 남는다

### 테스트 (core, 가짜 포트)

- [x] **쓰기.** 새 대화는 빈 지도, A → B → A의 셋째 시작 이벤트는 두 에이전트의 칸을 든다, 같은 에이전트로 셋을 이으면 그 칸이 바로 앞 실행이다, 옛 실행(필드 없음)을 이어 가면 없음이다
- [x] **따라가기.** A로 한 번, B로 k번 이어 간 뒤 A로 돌아오면 가짜 트레이스가 읽힌 실행이 앞 실행과 A의 실행뿐이고 k와 무관하다. 에이전트가 받는 값은 지금 테스트와 같다. 기존 고리 사례의 트레이스를 지도 없이 지으면 그것이 옛 대화 사례다
- [x] **재개.** 바로가기가 있는 이어 간 실행이 멈췄다가 재개되면 같은 멤버를 받아 재생이 통과하고 앞 실행을 읽지 않는다. 자기 요약의 덮는 끝이 지도의 그 에이전트 칸이면 아무것도 읽지 않는다
- [x] **선례.** "이어 가기"의 "거슬러 읽기가 멈추는 자리" 절, "대화 요약"의 "계기와 원문 범위" 절

### HTTP (`create_app()` + `ASGITransport`)

- [x] **01이 더한 최종 사용자 경로의 이어 가기 사례에서 트레이스의 `run_started`가 앞 실행과 함께 지도(그 에이전트 → 앞 실행)를 든다.** 명세 Testing Decisions의 "트레이스의 `run_started`가 앞 실행과 지도를 든다"의 지도 몫이다(셀프 리뷰 명세 축). 운영자 채널 `/runs`의 이어 가기도 같은 지도를 쓴다

### 바깥 이음매 (`-m llm`, 사용자가 골랐다)

- [x] **01이 붙인 최종 사용자 경로의 이어 가기 LLM 테스트에 지도 단언을 더한다.** 이어 간 실행의 `run_started`가 지도(그 에이전트 → 첫 실행)를 들고, 첫 실행의 `run_started`는 빈 지도를 든다. 바로가기가 실제 디스크에 쓰이는 것을 재는 자리다
