# 06: 관리 화면 — 실행 상세가 실패 원인을 글자로, 바로가기를 그 실행으로 가는 링크로 그린다

**What to build:** 운영자가 관리 화면의 실행 상세를 열면 `run_failed`에 "실패 원인"이 계약의 값 그대로 글자로 보인다. `run_started`의 "바로가기"는 에이전트마다 에이전트 이름이 글자로, 그 실행 식별자가 그 실행의 상세로 가는 링크로 보여 운영자가 그 에이전트의 앞 대화로 곧장 간다. 링크의 주소와 가드는 앞 실행·덮는 끝과 같다. 바로가기가 없는 옛 실행은 다른 필드처럼 글자 `null`, 새 대화의 첫 실행(빈 지도)은 글자 `{}`이고 링크가 없다. 지도가 아닌 값은 지금의 글자 그리기로 내려간다.

01이 필드 이름 표의 두 줄을 더해 두 필드가 이미 글자로 보인다. 이 티켓은 바로가기를 링크로 바꾸고 그리기를 테스트로 고정한다. 막는 티켓은 없다(잎). 이어 가기 단추와 대화 단위 화면은 두지 않는다(conversation 명세 그대로).

근거는 `.scratch/end-user-continuation/spec.md`의 "관리 화면" 절과 Testing Decisions의 "관리 화면" 항목, 그리고 그 2026-10-16 명세 검토·to-tickets 주석이다. 원인마다 문구를 짓는 것은 위젯의 몫이고 관리 화면은 계약의 값을 보인다(ADR 0031).

**Blocked by:** 01

**Status:** ready-for-agent

### 그리기

- [x] **새 필드 둘은 다른 필드처럼 이벤트 하나를 그리는 부품(`EventItem`)을 지난다.** 필드 이름과 용어집의 말(01이 표에 더한 "실패 원인", "바로가기")이 함께 보인다
- [x] **실패 원인의 값은 계약의 값 그대로 글자다.** 원인마다 문구를 짓지 않는다
- [x] **바로가기는 에이전트마다 그 실행의 상세로 가는 링크다.** 앞 실행·덮는 끝과 같은 주소(`/runs/` 뒤에 `encodeURIComponent`로 감싼 식별자)와 같은 가드(`.`과 `..`은 링크가 아니라 글자)다. 에이전트 이름은 글자다. 링크 하나에 에이전트 하나다
- [x] **값이 없으면(옛 실행) 다른 필드처럼 글자 `null`이다.** 빈 지도(`{}`)는 지금의 글자 그리기(`asText`) 그대로 글자 `{}`이고 링크가 없다 — 새 대화의 첫 실행마다 생기는 가장 흔한 값이고 옛 실행의 `null`과 글자로 갈린다(to-tickets가 정했다. 명세 검토)
- [x] **지도가 아닌 값(문자열, 배열, 문자열이 아닌 값을 든 객체)이 오면 지금의 글자 그리기로 내려간다.** 트레이스는 바깥에서 온 텍스트라 믿지 않는다. 좁히는 자리는 타입 단언 없이 술어로 좁힌다(원칙 III)

### 테스트 (관리 화면 vitest)

- [x] **실행 상세 페이지 테스트.** 실패 원인의 필드 이름과 값이 보인다. 바로가기의 실행마다 `/runs/<인코딩한 식별자>`로 가는 링크이고 에이전트 이름이 글자로 보인다. 바로가기가 없으면(`null`) 링크가 없고 글자 `null`이다. 빈 지도는 링크가 없고 글자 `{}`다. `.`·`..`인 값은 링크가 아니다. 지도가 아닌 값은 글자다
- [x] **TS 테스트의 이름은 행동을 말하는 한국어 문장이다**(`.claude/rules/web-workspace.md`)

### 지침과 검증

- [x] **실행 식별자 필드를 링크로 그리는 자리의 독스트링(앞 실행·덮는 끝)에 바로가기를 더한다.** 바로가기는 값 하나가 아니라 지도라 그리는 갈래가 따로다
- [ ] 검증 명령이 모두 초록이다(`pnpm -C web verify`). 중계·시작 래퍼·api-client·서버 라우트를 건드리지 않으면 e2e는 CI에 맡긴다. `packages/ui`를 건드리지 않으면 사진 비교도 CI에 맡긴다(`CLAUDE.md` 검증 명령)

- [ ] **기능을 닫는지는 병합 직전에 판정한다.** `git fetch` 뒤 `origin/main`의 나머지 잎(02·04·05) 티켓 파일 `Status:`가 모두 `done`이면 이 PR이 `.scratch/plan.md`의 end-user-continuation 행을 `done`으로 바꾸고 프론티어 문단을 고친다. 아니면 뒤에 병합되는 잎이 닫는다. main이 최신 기준(strict)이라 뒤에 병합되는 쪽은 앞의 병합을 들인 뒤에야 병합되므로 마지막 잎은 반드시 본다(01은 이 티켓이 막혀 있던 것이라 이미 `done`이다. end-user-channel 티켓 02의 선례)
