# 05: 404 덮기 — 최종 사용자 면이 404로 덮는 것은 주인을 확인하기 전의 손상뿐이고, 운영자의 구성 실수는 500이다

**What to build:** 최종 사용자 면에서 요청이 가리킨 실행(결정과 구독의 실행, 이어 가기의 앞 실행)의 기록을 그 실행의 주체와 견주기 전에 읽다 만난 손상만 없는 실행과 같은 404다. 남의 실행, 남의 손상된 실행, 자기 실행의 손상(주체 앞), 없는 실행은 여전히 모두 같은 404 고정 문구다. 주체를 확인한 뒤의 고장 — 깨진 고리와 깨진 바로가기, 기록이 가리키는 에이전트의 부재, 요청한 에이전트와 그것이 쓰는 mcp와 진입점의 구성 오류 — 은 최종 사용자 면 어디서나 500 고정 문구이고, 원인은 서버 기록에 `request_id`와 함께 남는다. 그래서 운영자가 에이전트 설정을 망가뜨려도 위젯은 404가 아니라 500을 받아 저장한 대화를 지우지 않는다. 운영자 면은 새 하위 타입도 다른 `PluginError`처럼 500과 원문이다.

01의 틈 가운데 이어 가기 경로의 구성 오류도 404인 것을 닫는다. 결정의 기존 동작(구성 오류, 깨진 고리, 기록의 에이전트 부재가 404)도 500으로 바뀐다. 막는 티켓은 없다(잎).

근거는 `.scratch/end-user-continuation/spec.md`의 "최종 사용자 면의 404 덮기" 절, Testing Decisions의 core "주인을 확인하기 전의 손상" 항목과 HTTP "에러"·"덮기의 바뀐 동작" 항목, 그리고 그 2026-10-16 명세 검토 주석이다. ADR 0023의 2026-10-16 이력 "최종 사용자 면이 404로 덮는 것은 주인을 확인하기 전의 손상뿐이다"(사용자가 골랐다)와 ADR 0014의 2026-09-26 이력(하위 타입의 기준 "깨졌나")이 앞선 결정이다.

**Blocked by:** 01

**Status:** ready-for-agent

### core — 새 하위 타입

- [ ] **core가 주인을 확인하기 전의 손상을 `PluginError`의 하위 타입 하나로 던진다.** 이름은 계약을 바꾸지 않아 이 티켓이 짓는다(용어집의 "주체"와 "트레이스"에 기댄다). 깨진 것의 하위 타입이라 4xx 하위 타입 목록에 들지 않는다
- [ ] **던지는 자리는 요청이 가리킨 실행을 읽는 두 곳뿐이다.** 이어 가기의 앞 실행 읽기(`gather_continued`의 첫 읽기)와 자기 실행 읽기(`_own_link` — 결정의 재개와 구독이 지난다). 여기 드는 것은 단건 읽기의 손상(어댑터가 `PluginError`로 감싸 올리는 실패 전부. JSONL 어댑터는 파일을 여는 `OSError`도 감싼다), `link_of`의 손상, 그리고 자기 실행 읽기에서 주체 앞에 서는 기록 규칙이다
- [ ] **같은 읽기 함수가 고리를 따라갈 때와 재개가 멈춘 실행의 앞 실행을 읽을 때는 기반 타입 그대로다.** 주체를 확인한 뒤의 고장이기 때문이다. 이어 가기에서 앞 실행 자신의 기록 규칙도 지금처럼 주체·끝남 뒤라 기반 타입이다
- [ ] **대가.** 주인을 확인하기 전에는 그 실행이 누구의 것인지 모르므로 일시적인 읽기 오류도 404다. 최종 사용자의 자기 앞 실행을 읽다 일시적인 읽기 오류가 나면 위젯이 대화를 지울 수 있고, 404에 곧바로 지울지 한 번 더 시도한 뒤 지울지는 web-widget이 정한다(`plan.md`의 그 행). 이 티켓은 읽기 오류만 500으로 빼지 않는다 — 그러면 그 식별자의 남의 파일이 있다는 것이 드러난다

### 표와 면

- [ ] **표(`failure_for`)에 새 하위 타입의 갈래가 기반 `PluginError` 갈래보다 앞에 선다.** 운영자 면은 500과 원문, 최종 사용자 면은 404 고정 문구다. 상태 코드는 여전히 표가 정하고 라우트는 정하지 않는다
- [ ] **최종 사용자 면에서 하위 타입이 아닌 `PluginError`는 500 고정 문구(`INTERNAL_MESSAGE`)다.** 결정, 구독, 시작, 이어 가기 모두다
- [ ] **면의 열거는 운영자와 최종 사용자 둘로 준다.** 시작 경로와 실행을 가리키는 경로를 가르던 것은 하위 타입이 아닌 `PluginError` 하나였는데 이제 둘 다 500이고 새 하위 타입은 실행을 읽는 경로에서만 난다. 조립이 넘기는 시작 경로(`EndUserPaths.start`, `END_USER_START_PATH`)도 지운다. 열거를 그대로 두면 같은 번역을 하는 갈래 둘이 남는다
- [ ] **덮어 상태 코드가 바뀐 기록 한 줄의 모양(`원래 상태 500 PluginError: …`)은 그대로다**

### 테스트

- [ ] **core — 주인을 확인하기 전의 손상.** 결정·구독의 실행과 이어 가기의 앞 실행이 손상이면 새 하위 타입이고, 고리·바로가기·준비의 `PluginError`는 기반 타입이다. 하위 타입이 서로 겹치지 않음을 보는 기존 사례를 넓힌다
- [ ] **core — 어댑터가 감싼 손상**(명세 검토). 지금 가짜 트레이스는 손상을 모두 모르는 종류의 줄로 만들어 `read()`가 `PluginError`를 던지는 가짜가 없다. 그런 가짜로 앞 실행과 자기 실행의 읽기 실패가 새 하위 타입으로 옮는지 본다 — 감싸기를 빠뜨리면 남의 읽히지 않는 파일이 500으로 드러나는데 지금 사례로는 초록이다
- [ ] **core — 깨진 것의 단언을 넓힌다**(명세 검토). 깨진 것을 단언하는 기존의 `not isinstance(caught.value, _SUBTYPES)` 열두 자리는 새 하위 타입을 걸러 내지 못해, 고리나 바로가기의 깨짐이 새 하위 타입을 잘못 던져도 초록이다. 그 단언이 새 하위 타입도 아님을 보게 한다. `_SUBTYPES`의 주석("하위 타입 다섯. 깨진 것(하위 타입이 아닌 PluginError)을 단언할 때 이것을 뺀다.")과 뜻이 갈리지 않게 모양은 이 티켓이 정한다. 03이 먼저 병합됐으면 그 검증 사례도 같은 모양으로 넓힌다
- [ ] **HTTP — 덮기의 바뀐 동작**(`create_app()` + `ASGITransport`. 그 사례는 지금 없어 새로 더한다, 명세 검토). 결정에서 진입점을 불러올 수 없는 에이전트, 없는 mcp, 기록이 가리키는 에이전트의 부재, 깨진 고리가 500 고정 문구이고 원인이 서버 기록에 `request_id`와 함께 남는다. 이어 가기에서 요청한 에이전트의 구성 오류와 깨진 고리가 500 고정 문구다. 남의 손상된 실행과 자기 실행의 손상은 그대로 404다. 모두 JSON 봉투이고 CORS 헤더가 붙는다. 구독은 자기 실행 읽기만 불러 주체 뒤에 나는 `PluginError`가 없으므로 바뀌는 것이 없다
- [ ] **HTTP — 운영자 면.** 새 하위 타입이 `/runs`의 이어 가기와 결정에서 500 원문이다

### 지침과 잔존

- [ ] **`.claude/rules/http.md`를 고친다.** 표의 면은 둘이고, 최종 사용자 면에서 404로 덮는 `PluginError`는 새 하위 타입뿐이며, 그 밖의 `PluginError`는 면 어디서나 500 고정 문구다. ADR 0023의 2026-10-16 이력을 가리킨다. 01이 "실행을 가리키는 경로"의 열거에 이어 가기를 더한 문장도 이것으로 다시 쓴다
- [ ] **`.claude/rules/core.md`를 고친다.** 새 하위 타입과 그 자리를 적고, 기준 "깨졌나"를 풀어 쓴 말("하위 타입을 뺀 뒤 남는 것이 서버의 구성이나 기록이 깨진 것")은 4xx 하위 타입 다섯을 뺀 뒤로 좁힌다 — 새 하위 타입은 깨진 것이라 ADR 0014의 기준은 그대로다
- [ ] **독스트링과 주석을 고친다.** core 포트 모듈의 `PluginError` 계열, HTTP 층의 `Surface`·`EndUserPaths`·`failure_for`, 최종 사용자 면 모듈의 독스트링과 결정 라우트의 404 주석("구성 오류까지 404"), 조립(`server.py`)이 시작 경로를 넘기던 자리
- [ ] **잔존이 0이다.** `구성 오류까지 404`, `구성 오류도 404`, `END_USER_START`, `END_USER_RUN`, `실행을 가리키는 경로`, `하위 타입 다섯`, `하위 타입을 뺀 뒤`, `남는 것이 서버의 구성이나 기록이 깨진 것`을 저장소 전체에서 찾는다. 제외 범위는 명세 잔존 grep이다(ADR 0023의 지난 이력은 기록이다). 글자 grep은 같은 뜻의 다른 말을 놓치므로 걸린 것 둘레도 읽는다
- [ ] **01이 덮기를 가리켜 `05`·`틈`으로 쓴 문장을 다시 읽어 지금 동작과 맞게 다듬는다**
- [ ] **원칙 III를 지킨다**
- [ ] 검증 명령이 모두 초록이다. core 포트·실행 모듈과 채널을 건드리므로 기존 `-m llm`을 돌려 일지의 검사 절에 적는다. 서버 라우트의 조립을 건드리므로 e2e도 로컬에서 친다(`CLAUDE.md` 검증 명령)
- [ ] **기능을 닫는지는 병합 직전에 판정한다.** `git fetch` 뒤 `origin/main`의 나머지 잎(02·04·06) 티켓 파일 `Status:`가 모두 `done`이면 이 PR이 `.scratch/plan.md`의 end-user-continuation 행을 `done`으로 바꾸고 프론티어 문단을 고친다. 아니면 뒤에 병합되는 잎이 닫는다. main이 최신 기준(strict)이라 뒤에 병합되는 쪽은 앞의 병합을 들인 뒤에야 병합되므로 마지막 잎은 반드시 본다(01은 이 티켓이 막혀 있던 것이라 이미 `done`이다. end-user-channel 티켓 02의 선례)
