# 02: 계정 표와 시스템 관리자 명령(마이그레이션, 느낌표)

**What to build:** 운영자가 서버에서 `agent-os operator system-admin <계정 이름>`을 치면 명령이 비밀번호를 두 번 묻고(글자는 보이지 않는다), 그 이름의 시스템 관리자 계정을 데이터베이스에 만든다. 같은 이름으로 다시 치면 비밀번호를 다시 정하고 잠금을 풀고 그 계정의 로그인을 모두 끊는다. 다른 이름의 시스템 관리자가 이미 있거나 그 이름의 관리자 단계 계정이 있으면 바꾸지 않고 종료 코드 1로 멈춘다. 비밀번호가 규칙(8자 이상 128자 이하, 대문자, 숫자, 특수문자)에 맞지 않으면 규칙을 적은 문구와 함께 1로 멈춘다. 파이프로 넣으면 첫 줄 하나를 받는다. 판을 올린 데이터베이스에는 `migrate`가 새 표 여섯(운영자 계정, 로그인 한 건(한 번 로그인해 유지 시간 동안 이어지는 로그인 상태 하나), 갱신용 번호, 비밀번호 링크, 서명 키, 로그인 기록)을 만든다. 아직 로그인할 길은 없다. 로그인은 03이 들인다.

이 티켓은 PR 제목에 느낌표(`feat!:`처럼 붙이는 `!`. 판을 올리는 사람이 손으로 할 일이 있다는 표지)를 붙인다. 판을 올리는 운영자가 올리기 전에 데이터베이스를 백업해야 하기 때문이다.

계정 저장소의 포트(바깥 저장소에 닿는 자리를 타입으로 적은 약속)를 `agent_os.http`의 `Database` 포트 옆에 처음 선언하고, PostgreSQL 구현을 `agent_os.adapters`에 둔다. 포트의 메서드는 이 티켓의 명령이 쓰는 것만 짓고, 뒤 티켓이 자기가 쓰는 메서드를 더한다. 표 여섯은 이 티켓이 한꺼번에 만든다. 마이그레이션은 `0002` 하나로 두기로 명세가 정했고(명세 "표와 마이그레이션"), 이미 dev에 든 마이그레이션 파일은 고치지 않기 때문이다.

근거는 명세 `.scratch/admin-login/spec.md`의 "계정 이름과 비밀번호", "계정 저장소의 포트", "표와 마이그레이션", "로그인 기록"(이 티켓은 "명령으로 시스템 관리자를 정함" 한 종류), "서버 명령"의 `system-admin`, Testing Decisions의 "서버 명령", "마이그레이션", "계정 어댑터"다. 측정은 `.scratch/admin-login/probes/port_shape_async/`, `hash_load/`, `password_hash/`이고 다시 돌리지 않는다. 결정은 ADR 0062 결정 "첫 계정", "비밀번호 규칙", "비밀번호 저장", "경로와 층", "저장"이다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-25-1007-admin-login-tickets.md`의 "명세 검토(spec-reviewer)" 절을 가리킨다.

### 표와 마이그레이션

- [x] `0002`가 명세 "표와 마이그레이션"의 표 여섯과 시스템 관리자에만 거는 유일 색인(시스템 관리자인 줄에만 걸어, 시스템 관리자가 둘 생기지 못하게 데이터베이스가 막는 색인)을 만든다. postgres-foundation 명세의 "마이그레이션 파일"을 따라 손으로 쓰고 `upgrade`만 둔다. 칸의 이름과 타입은 이 티켓이 정한다
- [x] 시각을 담는 칸에 기본값(`server_default`)이나 `now()`를 두지 않는다. 시각은 `http`가 주입된 시계에서 읽어 넘긴다(명세 "계정 저장소의 포트"의 "한 트랜잭션에 묶을 일". 일지의 "지적마다 한 일" 표 S4의 "데이터베이스의 시각")
- [x] `0002`는 표와 색인을 만들기만 하고 줄을 넣거나 바꾸거나 형을 바꾸지 않는다. 앞으로 이 표들의 해시와 키 칸을 건드리는 마이그레이션도 같은 규칙을 지킨다는 한 줄을 `0002`의 독스트링에 적는다. 첫 마이그레이션 파일은 고치지 않는다. 그 독스트링이 "이미 dev 에 들어간 파일은 고치지 않고 새 파일을 더한다"고 적기 때문이다

### 계정 이름과 비밀번호의 규칙

- [x] 이름 규칙(영문 소문자, 숫자, `.`, `_`, `-`로 3~32자, 영문자나 숫자로 시작)과 들어온 이름의 영문 대문자만 소문자로 바꾸는 것을 `http`의 함수로 둔다. 뒤 티켓의 로그인과 계정 경로가 같은 함수를 쓴다
- [x] 비밀번호 규칙을 명세 "계정 이름과 비밀번호"의 여섯(NFKC 정규화(모양이 다르게 적힌 같은 글자를 한 모양으로 맞추는 유니코드 규칙), 코드 포인트(유니코드 글자 하나에 붙은 번호)로 센 글자 수, ASCII로 읽는 글자 종류, 제어 문자와 짝 없는 서로게이트(둘이 짝을 지어야 글자 하나가 되는 반쪽 코드 포인트가 홀로 든 것)의 거절, 몸통의 상한 1024자는 뒤 티켓의 경로 몫)대로 짓는다
- [x] 해시는 `argon2-cffi`의 Argon2id(비밀번호를 일부러 느리고 메모리를 많이 쓰게 해시해 저장하는 방식)이고 매개변수 m=19456, t=2, p=1을 코드에 고정한다. 의존성을 더할 때 `docs/constitution/tech.md`를 읽고 그 규약대로 적는다(ADR 0062 결정 "비밀번호 저장")

### 계정 저장소의 포트와 어댑터

- [x] 포트는 `agent_os.http`의 `Database` 포트 옆에 비동기 Protocol로 선언한다. 어댑터는 `agent_os.http`를 가져오지 않고 시그니처로 만족한다. 줄은 `http`가 읽기 전용 Protocol로 적고, 여러 줄은 `Sequence`로 적는다(명세 "계정 저장소의 포트"의 처음 세 항목)
- [x] 계정을 넣는 메서드는 넣은 계정의 줄이나 글자 값 `"taken"`을 돌려준다. 어댑터는 유일 제약 위반을 옮길 때와 그 밖의 데이터베이스 예외를 포트 밖으로 낼 때 원래 예외를 원인으로 잇지 않는다(같은 절의 "이름 충돌은 돌려주는 값으로 가른다", "어댑터는 원인을 잇지 않는다")
- [x] `main`은 데이터베이스 어댑터의 메서드 `accounts()`로 같은 엔진을 쥔 계정 어댑터를 받는다(같은 절의 "조립"). `tests/test_main.py`의 가짜 데이터베이스가 그 메서드를 어떻게 내는지도 이 티켓이 정한다
- [x] 어댑터는 SQLAlchemy의 표 정의로 짓고 칸마다 타입을 붙이며, 비어 있을 수 있는 칸은 타입 인자에 `None`을 함께 적는다. 트랜잭션을 여는 메서드는 작업 객체를 비동기 문맥 관리자로 내고, 반환은 `AsyncGenerator`로 적는다(같은 절의 "표를 적는 법", "한 트랜잭션에 묶을 일")
- [x] 포트 타입을 적은 시험 픽스처는 작업 객체도 그 포트 타입에 한 번 적는다(같은 절)
- [x] `.claude/rules/core.md`의 "포트는 다섯이고 닫힌 목록이다"와 "도메인별 포트는 두지 않는다"를 core의 포트를 말하는 줄로 남기고 core 밖의 이 포트를 적는다. `.claude/rules/adapters.md`에 계정 어댑터의 항목(원인을 잇지 않는 것, 표 정의로 짓는 것, 시각을 받아 적는 것)을 더한다(같은 절의 "규칙 문서"). 규칙 파일을 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다(`.claude/rules/agent-docs.md`)

### 서버 명령

- [x] `agent-os operator system-admin <계정 이름>`을 명세 "서버 명령"의 갈래대로 짓는다. 만들기, 같은 이름의 시스템 관리자면 다시 정하기(잠금과 틀린 횟수를 지우고 로그인을 모두 끊는다), 다른 이름의 시스템 관리자가 있으면 그 이름을 적은 문구와 종료 1, 그 이름의 관리자 단계 계정이 있으면 종료 1이다
- [x] 비밀번호는 표준 입력이 터미널이면 보이지 않게 두 번 받고 둘이 다르면 종료 1, 터미널이 아니면 첫 줄 하나를 받는다(줄 끝의 개행만 뗀다). 명령의 인자로 받지 않는다
- [x] `serve`와 같은 `AGENT_OS_DATABASE_URL`로 닿고, 표의 판이 맞지 않으면 `serve`와 같은 진단으로 멈춘다. 문구는 데이터베이스 진단과 같은 높임말이다
- [x] 로그인 기록에 "명령으로 시스템 관리자를 정함" 한 줄을 남긴다. 비밀번호와 해시는 어느 줄에도 남기지 않는다(원칙 V)

### 시험

- [x] 마이그레이션: `0002`가 빈 데이터베이스에 표 여섯을 만들고, 보낸 문장이 표와 색인을 만드는 것뿐인지 본다. 서명 키의 표를 같은 이름으로 먼저 만든 뒤 `migrate`가 1로 끝나고 출력에 "already exists"가 있으며 판이 `0001` 그대로이고 `0002`의 다른 표가 하나도 남지 않는지 본다(명세 "표와 마이그레이션"의 "값을 싣는 실패를 시험으로 막는 법"). 문장을 모으는 길은 이 티켓이 고른다
- [x] 계정 어댑터: 포트 타입을 적은 픽스처로 진짜 데이터베이스(`tests/database.py`의 픽스처, 선례 `tests/adapters/test_postgres_database.py`)에 대고 넣기, 읽기, 쓰기, 이름 충돌을 본다. 이름 충돌의 결과와 서버 기록과 역추적에 카나리아(기록에서 찾아낼 수 있게 일부러 심은 글자)로 심은 이름이 실리지 않는지 본다
- [x] 서버 명령: 파이프로 비밀번호를 넣어 돌리고 종료 코드와 문구와 데이터베이스의 결과를 본다. 출력에 비밀번호가 실리지 않는 것도 본다. 선례는 `tests/test_migrate_command.py`다
