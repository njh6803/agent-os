# 12: 계정 화면, 내 비밀번호 바꾸기 화면, 링크로 비밀번호 정하기 화면

**What to build:** 시스템 관리자가 탐색의 "계정"을 누르면 `/accounts`에 운영자 계정 목록이 선다. 상태는 배지(활성, 비활성, 비밀번호 미설정)이고 잠긴 계정에는 잠김 배지와 "15:42까지" 같은 풀리는 시각이 붙는다. "계정 만들기"로 이름을 넣으면 곧바로 비밀번호 링크 창이 열리고, 운영자는 그 링크를 복사해 새 운영자에게 직접 전한다. 링크를 연 사람은 `/set-password`에서 새 비밀번호를 두 번 넣고, 정하면 로그인 화면에 "비밀번호를 정했다. 그 비밀번호로 로그인한다"가 선다. 줄 끝의 메뉴로 링크를 다시 만들고, 잠금을 풀고, 비활성으로 바꾸거나 되돌린다. 관리자에게는 탐색의 "계정"이 보이지 않고, 주소로 열면 "이 계정으로는 볼 수 없다" 한 줄만 보인다. 누구나 계정 메뉴의 "내 비밀번호 바꾸기"로 `/password`에서 자기 비밀번호를 바꾼다.

근거는 명세 `.scratch/admin-login/spec.md`의 "계정 화면과 내 비밀번호", "비밀번호 링크"의 "링크의 주소"와 "비밀번호를 정하는 화면", "계정 이름과 비밀번호"의 "화면", "관리 화면의 페이지와 주소"(표의 `/accounts`, `/password`, `/set-password#<토큰>`, "탐색"), "로그인을 끊는 일"의 "ADR 0062가 넘긴 둘", Testing Decisions의 "화면의 페이지 시험", "관리 화면 e2e", "사진 비교"다. 그린 화면은 `.scratch/admin-login/design/mk-accounts.dc.html`과 그 창 셋, `mk-set-password-states.dc.html`이다. 결정은 ADR 0062 결정 "비밀번호 링크", "두 단계와 권한 표"다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-25-1007-admin-login-tickets.md`의 "명세 검토(spec-reviewer)" 절을 가리킨다.

### 계정 화면

- [x] 탐색에 "계정"(아이콘 `users`)을 더하고 시스템 관리자에게만 보인다. 관리자가 `/accounts`를 주소로 열면 "이 계정으로는 볼 수 없다" 한 줄만 보인다
- [x] 목록의 열은 계정 이름, 단계, 상태, 만든 시각, 동작이다. 로그인한 계정의 줄에는 "지금 계정"이 붙는다. 상태는 08의 계정 상태 배지이고 잠김의 풀리는 시각은 브라우저 시간대다. 비활성 계정은 기본으로 숨기고 "비활성 계정도 보기"를 켜면 보인다. 폭 768px 미만에서는 계정마다 카드다
- [x] 줄 끝의 메뉴는 명세 "계정 화면과 내 비밀번호"의 "줄 끝의 메뉴" 규칙대로다. 비활성 계정에는 "활성으로 바꾸기"만, 시스템 관리자의 줄에는 메뉴가 없고 잠겼을 때만 "잠금 풀기"가 선다
- [x] 계정 만들기 창, 비밀번호 링크 창(링크 `<관리 화면의 출처>/set-password#<토큰>`, "복사"(아이콘 `copy`), 네 줄), 비활성으로 바꾸기 창(네 줄. 첫 줄은 "이 계정의 로그인은 길어야 N분 안에 모두 끊긴다. 도는 실행은 끝까지 간다"이고 N은 `token_minutes`, 이야기 33)을 명세대로 짓는다. 409면 칸 아래에 "이 이름의 계정이 있다(비활성 계정 포함)"를 보인다. 창을 닫으면 링크는 화면에서도 사라진다
- [x] 메뉴, 확인 창, 고르는 칸은 관리 화면 앱이 짓는다. 디자인 시스템의 부품으로 올리지 않고 헤드리스 라이브러리(모양 없이 동작만 주는 부품 라이브러리)를 들이지 않는다

### 내 비밀번호 바꾸기

- [x] 계정 메뉴에 "내 비밀번호 바꾸기"를 더한다. `/password`는 지금 비밀번호 칸, 새 비밀번호 칸, 처음부터 보이는 규칙 목록(맞으면 "맞음")이다. 규칙은 `normalize("NFKC")`와 코드 포인트 셈으로 미리 보이고, 입력 칸의 `maxlength`로 128자를 막지 않는다
- [x] 422의 칸(`body.current_password`, `body.new_password`)마다 그 칸 아래에 알린다. 409면 "계정이 잠겼다. 잠시 뒤에 다시 한다"를 보인다. 성공하면 "비밀번호를 바꿨다. 다른 곳의 로그인은 길어야 N분 안에 끊긴다"를 보인다

### 링크로 비밀번호 정하기

- [x] `/set-password`는 주소의 `#` 뒤를 읽은 즉시 방문 기록의 주소를 바꿔 주소창에서 지운다. 토큰으로 무엇을 읽어 오지 않고 계정 이름을 보이지 않는다. 로그인 없이 열리고 갱신 규칙을 지나지 않는다(09가 `api/session/rule.ts`의 `OUTSIDE_RULE`에 `/auth/set-password`를 이미 넣었으니 그 목록은 고치지 않고 규칙 밖에서 서는지만 시험으로 본다)
- [x] 새 비밀번호 칸 둘과 처음부터 보이는 규칙 목록이다. 두 칸이 다르면 보내지 않고 알린다. 128자를 넘으면 규칙 목록 위에 알린다. 404면 "이 링크는 더 쓸 수 없다. 관리하는 사람에게 새 링크를 받는다"를 보이고 입력 칸을 막는다. 204면 `/login?notice=password-set`으로 보낸다

### 시험

- [x] 페이지 시험: 계정 화면의 메뉴 규칙(시스템 관리자의 줄, 비활성 계정의 줄, 잠긴 줄), 관리자에게 탐색의 "계정"이 없고 주소로 열면 한 줄인 것, 비밀번호 정하기 화면이 주소의 `#` 뒤를 지우는 것, 규칙 목록의 셈(자모로 적힌 한글, 그림 문자 128자), 404와 409의 문구, 비활성으로 바꾸기 창의 네 줄
- [x] 관리 화면 e2e: 시스템 관리자가 계정을 만들고 링크를 받아, 그 링크로 비밀번호를 정한 뒤 새 계정으로 로그인하는 길 하나
- [x] 사진 비교(화면을 찍어 정답 사진과 견주는 시험): 계정 목록과 창 셋, 내 비밀번호, 비밀번호 정하기(입력, 404)를 관리 화면의 사진 정답에 더한다

### 결과 기록

- 화면 셋(`/accounts`, `/password`, `/set-password#<토큰>`)과 창 셋(계정 만들기, 비밀번호 링크, 비활성으로 바꾸기)을 관리 화면 앱에 지었다. 창은 `components/molecules/Dialog`(포털, 포커스 가두기, Esc)이고 헤드리스 라이브러리는 들이지 않았다. 계정 메뉴와 줄 끝 메뉴는 `hooks/usePopupMenu`를 함께 쓴다.
- 09에서 보류한 둘을 함께 했다. 계정 메뉴의 키보드 흐름(열릴 때 첫 항목에 포커스, Esc로 닫으면 단추로 복귀)과 로그아웃 중의 `aria-busy`, 루프백이 아닌 http 주소의 로그인에서 주 버튼만 끄기(`LoginForm`의 `state` 묶음으로 `LogInAttempt`와의 Data Clumps도 묶었다). 알림 값 표의 중복은 그대로 두었다.
- 128자를 넘는 입력의 알림은 규칙 목록 위, 새 비밀번호 칸 바로 아래에 둔다("128자 이하로 줄인다").
- 사진 정답은 새 92장과 바뀐 16장이다(계정 목록·창·내 비밀번호·비밀번호 정하기와 탐색의 "계정", 계정 메뉴, http 로그인 안내).
