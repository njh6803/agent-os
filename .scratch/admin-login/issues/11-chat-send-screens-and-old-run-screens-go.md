# 11: 대화에서 보내고 결정하기, 옛 실행 화면 걷기

**What to build:** 운영자가 `/chat/new`에서 켜진 에이전트를 고르고 요청을 보내면, 답이 흐르는 대로 대화에 그려지고 주소가 `/chat/<그 실행>`으로 바뀐다. 뒤로 가기를 누르면 빈 새 대화가 아니라 대화 목록으로 간다. 끝난 대화의 입력 칸에 다음 요청을 적어 보내면 같은 에이전트로 이어 간다. 도구 호출이 승인을 기다리면 그 자리에 "거부"와 "승인"이 서고, 누르면 그 결정이 실행을 잇는다. 실패한 실행에는 "다시 보내기"가 서서 같은 요청을 실패 전의 실행에서 다시 보낸다. 최종 사용자의 대화는 볼 수만 있다. 옛 주소 `/runs`와 `/runs/<실행>`은 대화 화면으로 옮겨 가고, 옛 실행 목록과 실행 상세 화면은 사라진다.

근거는 명세 `.scratch/admin-login/spec.md`의 "대화 화면"(새 대화, 이어 가기, 결말 없음, 실패, 일시정지, 최종 사용자의 대화, 진행 표시, 좁은 화면, 스트림이 끊기면), "관리 화면의 페이지와 주소"의 "옛 주소", "화면이 갱신을 부르는 규칙"의 "스트림이 열린 동안의 갱신"과 "스트림 도중 갱신이 실패하면", "도는 실행을 이어 보기"의 "주기 읽기를 입력 칸과 떼어 둔다", "실행 패널"의 "결정 자리는 없다", "디자인 시스템에 더하는 것"의 "규칙 문서의 예", Testing Decisions의 "화면의 페이지 시험", "관리 화면 e2e", "사진 비교", "수락 조건을 덮는 자리"다. 측정은 `.scratch/admin-login/probes/swr_poll/` 결과 1c다. 그린 화면은 `.scratch/admin-login/design/ch-a.dc.html`과 그 둘째 쪽 화면들, `ch-running.dc.html`, `ch-m.dc.html`이다. 결정은 ADR 0063 결정 "대화 화면", "도는 실행을 이어 보기"다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-25-1007-admin-login-tickets.md`의 "명세 검토(spec-reviewer)" 절을 가리킨다.

### 보내기

- [x] `/chat/new`는 켜진 에이전트를 고르는 칸과 입력 칸이다. 켜진 에이전트가 없으면 "켜진 에이전트가 없다"와 플러그인 화면으로 가는 링크를 보인다. 첫 요청을 보내면 채널의 시작 경로를 부르고, 시작 이벤트가 오는 순간 `history.replaceState`(방문 기록을 늘리지 않고 주소만 바꾸는 브라우저 기능)로 주소를 `/chat/<그 실행>`으로 바꾼다
- [x] 끝 실행이 끝남이면 입력 칸이 열리고, 보내면 끝 실행에서 이어 간다. 새 실행의 시작 이벤트가 오면 주소를 그 실행으로 바꾼다(같은 바꾸기). 에이전트는 대화 안에서 바꾸지 않는다
- [x] 끝 실행이 결말 없음이면 입력 칸이 막힌다. 실패면 실패 알림과 "다시 보내기"를 보이고, 실패한 실행의 앞 실행에서 그 요청을 이어 보낸다. 앞 실행이 없으면 같은 에이전트로 새 대화를 시작한다. 입력 칸에 새 요청을 적어 보내도 같은 앞 실행에서 잇는다
- [x] 일시정지의 승인 묻기는 "거부"(보조)가 먼저, "승인"(주)이 나중이고, 거부하면 사유 칸이 열린다. 누르면 채널의 결정 경로를 그 일시정지의 자리(`pause_index`. 결정이 답하는 `run_paused`가 트레이스의 이벤트 열에서 서는, 0부터 센 자리)와 함께 부르고 응답 스트림을 받는 대로 그린다. 지금 실행 상세 화면의 결정 자리와 그 꺼짐 미리 알림을 이 자리로 옮긴다
- [x] 첫 실행의 주체(실행을 요청한 신원)에 `|`가 들었으면 입력 칸과 버튼 대신 "최종 사용자의 대화라 이어 가거나 결정할 수 없다"를 보인다
- [x] 실행이 도는 동안 진행 표시가 지금 단계("모델을 부르는 중", "도구를 부르는 중")를 보이고 보내기가 막힌다. 단계는 마지막으로 받은 이벤트의 다음 일로 짐작한다(명세 "대화 화면"의 "진행 표시", 이야기 48)
- [x] 휴대전화 폭(375px)에서도 승인 묻기에 답한다(명세 "대화 화면"의 "좁은 화면", 이야기 61)

### 스트림

- [x] 응답의 이벤트 스트림이 열린 동안에는 다른 요청이 없어 401이 나지 않으므로, 짧은 JWT(5분짜리 출입증 쿠키) 수명의 80%마다(`token_minutes`에서) 갱신을 부른다. 그 갱신이 실패하면 `/login?next=<지금 대화의 주소>&notice=expired`로 보낸다
- [x] 응답 스트림이 결말 전에 끊기면 그 실행의 트레이스를 읽어 다시 그리고 도는 실행 이어 보기로 넘어간다
- [x] 주기 읽기를 거는 부품을 입력 칸의 상태와 떼어, 글을 쳐도 그 부품이 다시 그려지지 않게 한다

### 옛 화면

- [x] `/runs`는 `/chat`으로, `/runs/<실행>`은 `/chat/<실행>?run=<실행>`으로 옮긴다. 옮겨 간 화면은 그 실행까지의 대화를 그리고 패널에 그 실행을 연다
- [x] 옛 실행 목록과 실행 상세 화면과 탐색의 "실행" 항목을 걷는다
- [x] `.claude/rules/web-design.md`가 보여 주기용 스토리의 자리로 드는 "실행 목록의 배지"를 "대화 목록의 배지"로 고친다. `.claude/rules/web-admin.md`의 결정 자리 줄을 대화 화면의 승인 묻기를 말하게 고친다. 옛 이름(`RunDecision`, 실행 목록 화면)을 살아 있는 문서에서 grep해 잔존이 0인지 본다. 규칙 파일을 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다

### 시험

- [x] 페이지 시험: 결말 없는 대화에서 입력 칸에 3초 넘게 글을 치는 동안에도 3초마다 다시 읽는 것, 스트림이 열린 동안 짧은 JWT 수명의 80%마다 갱신하는 것(가짜 시계의 선례는 `HomePage.connection.test.tsx`), 스트림 도중 갱신이 실패하면 로그인 화면으로 가는 것, 옛 주소 `/runs`의 이동, 최종 사용자의 대화에 입력 칸이 없는 것, 다시 보내기가 고르는 앞 실행, 진행 표시의 단계(시작 뒤, 모델 호출 뒤, 도구 호출 뒤)
- [x] 관리 화면 e2e: 로그인한 운영자가 새 대화에서 모델 없는 에이전트에 요청을 보내 답을 받고, 이어 가기를 한 번 보내 대화 목록에 그 줄이 서는 것을 본다. 승인을 묻는 에이전트가 있으면 승인 한 번도 지난다
- [x] 사진 비교(화면을 찍어 정답 사진과 견주는 시험): 새 대화, 실행이 도는 중, 일시정지의 승인 묻기(폭 375px 포함), 실패와 다시 보내기를 관리 화면의 사진 정답에 더한다
