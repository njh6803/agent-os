# 03: 로그인, 로그아웃, 지금 누구인지, 첫 계정 확인(공유 토큰과 함께 받기)

**What to build:** 프로그램(curl이나 시험)이 `POST /auth/login`에 계정 이름과 비밀번호를 보내면 204와 쿠키 둘을 받는다. `__Host-aos_at`은 짧은 JWT(계정 이름과 단계를 서버가 서명해 담은, 기본 5분짜리 출입증)이고 `__Host-aos_rt`는 갱신용 번호(짧은 JWT가 끝났을 때 새것을 받는 데 쓰는 난수, 기본 30분 쉬면 끝난다)다. 그 뒤 그 쿠키로 관리 API와 운영자 채널(`/runs`)을 부를 수 있다. 틀린 비밀번호를 연속 다섯 번 넣으면 그 계정이 1분 잠기고, 잠긴 동안에는 맞는 비밀번호도 401이다. 없는 계정, 틀린 비밀번호, 잠긴 계정이 모두 같은 401과 같은 문구 "로그인하지 못했다"이고, 어느 갈래든 해시와 한 번 견주어 걸린 시간을 맞춘다(명세 "견줌 시간". 함수 길에서는 갈리지 않았다고 쟀고, HTTP 길에서는 판정하지 못했다). `GET /auth/me`는 `{name, tier, token_minutes, run_timeout_seconds}`를 답하고, `POST /auth/logout`은 그 로그인을 끊고 쿠키를 지운다. `GET /auth/setup`은 운영자 계정이 하나도 없을 때만 `{needs_first_account: true}`를 답한다. 유지 시간의 세 환경 변수가 범위를 벗어나면 `serve`가 문구를 찍고 종료 코드 2로 끝난다.

이 티켓부터 13까지 `serve`는 운영자 경로(최종 사용자 경로와 `/health`를 뺀, 운영자가 부르는 관리 API와 `/runs`)에서 공유 토큰(지금 `.env`의 `AGENT_OS_ADMIN_TOKEN`과 `AGENT_OS_CHANNEL_TOKEN`으로 모두가 함께 쓰는 비밀 글)과 로그인 쿠키를 함께 받는다(명세 "공유 토큰과 쿠키를 함께 받는 기간"). 그래서 관리 화면과 지금의 시험과 e2e 하네스는 공유 토큰 그대로 돌고, 이 티켓이 더한 경로는 쿠키로 시험한다. 갱신(`POST /auth/refresh`)은 04가 들인다. 그래서 이 티켓에서는 짧은 JWT가 만료되면 다시 로그인해야 한다.

이 티켓은 경로 넷(`log_in`, `log_out`, `get_me`, `get_setup`)을 계약에 더하므로 그것을 부르는 화면 티켓(09)을 막는다(명세 "경로"의 첫 문단).

근거는 명세 `.scratch/admin-login/spec.md`의 "경로"(표의 넷, `token_minutes`와 `run_timeout_seconds`, 401의 머리, 지우는 줄, 계약에 박히는 것), "로그인 없이 열리는 경로", "로그인", "쿠키 둘과 갱신"의 "쿠키", "짧은 JWT", "지금 누구인지", "로그아웃", "유지 시간", "서명 키"의 "만들기"와 "알아채는 길", "계정 이름과 비밀번호"의 "저장", "뜰 때 만드는 것과 시험", "스레드와 동시에 도는 해시", "견줌 시간", "로그인 기록", "공유 토큰과 쿠키를 함께 받는 기간", "로그인하지 않은 요청의 응답", Testing Decisions의 "HTTP 시험", "진짜 데이터베이스가 보는 경합", "전수 검사", "쿠키와 유지 시간", "로그인 기록", "요청 출처 검사의 사례 표"다. 측정은 `.scratch/admin-login/probes/hash_load/`, `password_hash/`, `port_shape_async/`이고 다시 돌리지 않는다. 결정은 ADR 0062 결정 "자격", "로그인 상태", "잠금과 실패 문구", "서명 키", "로그인 기록"이다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-25-1007-admin-login-tickets.md`의 "명세 검토(spec-reviewer)" 절을 가리킨다.

### 계약

- [x] 경로 넷을 명세 "경로"의 표대로 계약에 더한다. 오류 문서는 `log_in` 401·403·422, `log_out` 401·403, `get_me` 401·403, `get_setup` 403이다. 쿠키를 심거나 지우는 응답은 `Set-Cookie` 머리를 응답 문서에 적는다
- [x] `get_me`의 `run_timeout_seconds`는 `create_app`이 받은 실행 제한 시간이고, 주지 않았으면 core의 `DEFAULT_RUN_TIMEOUT_SECONDS`를 읽어 채운다. `server`와 관리 층에 600을 따로 적지 않는다. `tier`는 `system_admin`과 `admin` 둘인 닫힌 열거다
- [x] `openapi.json`과 생성 TS 타입이 같은 커밋에 실린다

### 자격과 함께 받는 기간

- [x] 공개 경로 목록(로그인 없이 열리는 경로의 목록. 목록 밖은 모두 401로 닫힌다)에 로그인과 첫 계정 확인을 더한다(`/health`와 함께 셋. 04가 갱신을, 06이 링크로 비밀번호 정하기를 더해 다섯이 된다)
- [x] 짧은 JWT는 HS256(서버 혼자 아는 키 하나로 서명하고 확인하는 방식) 하나로 서명하고 칸 다섯(`sub`, `sid`, `tier`, `iat`, `exp`)이 다 있어야 하며 만료에 여유를 두지 않는다. 시각은 `create_app`이 받는 시계를 거쳐 읽는다. 검증에 데이터베이스를 읽지 않는다. 사이트가 서명한 토큰(RS256 하나. 사이트의 비밀 키로 서명하고 공개 키로 확인하는 방식)과 알고리즘 목록이 달라 한쪽의 토큰이 다른 쪽을 지나지 않는 것을 시험으로 본다
- [x] 운영자 경로는 이 기간 동안 공유 토큰과 짧은 JWT를 함께 받는다. 관리 토큰은 `/runs` 밖을, 채널 토큰은 `/runs` 아래를 지금처럼 열고, 짧은 JWT는 둘 다 연다. 요청에 둘이 함께 오면 하나라도 맞으면 지난다. 최종 사용자 경로는 서명 토큰만 받는다(명세 "공유 토큰과 쿠키를 함께 받는 기간"의 처음 항목)
- [x] `log_out`과 `get_me`는 짧은 JWT로만 연다. 공유 토큰으로 오면 401이다
- [x] 401의 `WWW-Authenticate: Bearer`는 이 기간에 지금 그대로 싣는다(13이 뺀다)
- [x] `.claude/rules/http.md`의 자격 표와 미들웨어 항목에 이 기간의 규칙을 적는다. 13이 그 줄을 걷는다. 규칙 파일을 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다

### 서명 키

- [x] `serve`가 뜰 때 서명 키의 줄이 없으면 "없으면 넣는다" 한 문장으로 하나 넣는다. `serve` 둘이 함께 떠도 키가 하나로 모인다
- [x] 키를 메모리에 두고 마지막으로 읽은 뒤 10초가 지난 다음 쓸 때 다시 읽는다. 10초는 `create_app`이 받는 `Clock`(`src/agent_os/core/ports.py`)으로 센다. 키를 바꾸는 명령과 그 시험은 04가 한다

### 로그인

- [x] 본문 `{name, password}`의 형식(`name` 1~32자, `password` 정규화 전 1~1024자)을 어기면 422다. 그 안의 모든 실패는 401과 문구 하나다
- [x] 판정을 명세 "로그인"의 차례 1~6대로 짓는다. 횟수를 견주기 전에 짧은 트랜잭션(데이터베이스에 함께 적히거나 함께 취소되는 일 한 묶음)에서 줄을 잠가 세고, 견줌과 다시 해시는 연결을 쥐지 않은 채 트랜잭션 밖에서 하며, 맞으면 둘째 트랜잭션에서 줄을 다시 잠가 해시가 그대로이고 계정이 활성인지 본 뒤 횟수와 잠금을 지우고 로그인 한 건(한 번 로그인해 유지 시간 동안 이어지는 로그인 상태 하나)을 연다. 이때 그 계정의 끝난 로그인을 지운다
- [x] 잠그는 시간은 다섯째에 1분이고 하나 늘 때마다 두 배이며 1시간에서 멈춘다. 잠긴 동안의 시도는 횟수에 들지 않는다. 판정의 규칙(잠그는 시간, 만료)은 `http`의 함수가 갖고, 어댑터는 줄을 잠그고 읽고 적는 일만 한다
- [x] 어댑터가 적는 시각은 모두 `http`가 주입된 시계에서 읽어 넘긴 값이다
- [x] 가짜 해시(없는 계정의 로그인도 같은 시간이 걸리게 견주는, 아무 계정에도 속하지 않은 해시)는 저장과 같은 매개변수로 만든다. 해시와 견줌은 해시 전용 스레드 넷으로 넘기고 서버가 멈출 때 닫는다. 기본 일꾼 스레드 묶음으로 넘기지 않는다
- [x] 가짜 해시와 해시 전용 스레드와 서명 키의 줄을 만드는 자리와, HTTP 시험(`ASGITransport`는 서버가 뜨고 멈출 때 도는 수명 주기(lifespan)를 돌리지 않는다)이 그 자리를 지나는 길을 정하고 시험으로 고정한다(명세 "계정 이름과 비밀번호"의 "뜰 때 만드는 것과 시험")
- [x] 쿠키 둘을 명세 "쿠키 둘과 갱신"의 "쿠키"대로 심는다. `__Host-aos_at`에는 `Max-Age`가 없고, `__Host-aos_rt`의 `Max-Age`는 쉬는 시간과 총 시간의 남은 몫 가운데 짧은 것이다. 갱신용 번호는 32바이트 난수이고 서버에는 SHA-256 해시만 둔다
