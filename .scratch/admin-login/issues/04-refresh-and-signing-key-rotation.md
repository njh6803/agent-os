# 04: 갱신과 서명 키 바꾸기

**What to build:** 짧은 JWT(로그인할 때 받는 5분짜리 출입증 쿠키)가 만료된 뒤 프로그램이 `POST /auth/refresh`를 부르면, 갱신용 번호 쿠키(새 출입증을 받는 데 쓰는 난수) 하나로 새 쿠키 둘을 받아 로그인이 이어진다. 갱신할 때마다 갱신용 번호도 새것으로 바뀌고 앞의 번호는 쓴 것으로 적힌다. 탭 둘이 같은 번호로 거의 같은 때에 갱신해도 둘 다 204이고, 어느 응답의 번호가 남아도 다음 갱신이 통한다. 쓴 지 10초가 지난 번호가 다시 오면 401과 지우는 줄(쿠키를 지우는 `Set-Cookie` 줄)을 받고 그 로그인이 끊기며 로그인 기록에 "번호를 다시 씀"이 남는다. 쉬는 시간(기본 30분)이나 총 시간(기본 480분)이 지났거나 계정이 비활성이거나 잠겼으면 갱신이 401이다. 서버에서 `agent-os operator rotate-key`를 치면 "도는 `serve`는 10초 안에 새 키를 씁니다"를 찍고, 10초 뒤 옛 키의 짧은 JWT는 401이 되지만 갱신으로 로그인이 이어진다.

이 티켓은 경로 `refresh_login`을 계약에 더하므로 화면의 갱신 규칙을 짓는 09를 막는다.

근거는 명세 `.scratch/admin-login/spec.md`의 "경로"(표의 `refresh_login`, 지우는 줄), "쿠키 둘과 갱신"의 "갱신용 번호"와 "갱신의 판정", "탭 둘이 함께 갱신할 때의 유예", "유지 시간", "서명 키", "로그인을 끊는 일", "계정 저장소의 포트"의 "한 트랜잭션에 묶을 일", "로그인 기록"(이 티켓은 "번호를 다시 씀"과 "서명 키 바꿈"), "서버 명령"의 `rotate-key`, Testing Decisions의 "진짜 데이터베이스가 보는 경합", "쿠키와 유지 시간", "서버 명령"이다. 측정은 `.scratch/admin-login/probes/port_shape_async/`의 트랜잭션 갈래이고 다시 돌리지 않는다. 결정은 ADR 0062 결정 "로그인 상태", "서명 키"다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-25-1007-admin-login-tickets.md`의 "명세 검토(spec-reviewer)" 절을 가리킨다.

**Blocked by:** 03

**Status:** ready-for-agent

### 계약

- [ ] `POST /auth/refresh`(`refresh_login`)를 명세 "경로"의 표대로 계약에 더한다. 성공은 204와 새 쿠키 둘, 오류 문서는 401(지우는 줄 둘과 함께)과 403이다. `Set-Cookie` 머리를 응답 문서에 적는다
- [ ] 공개 경로 목록에 갱신을 더한다(넷)
- [ ] 05와 나란히 돌 수 있다. 늦게 병합하는 쪽이 권한 표(05가 들인다)에 `refresh_login`(로그인 없이 연다) 줄을 더한다. 먼저 병합된 쪽을 기준 브랜치에서 합친 뒤 05의 전수 검사가 초록인지 본다
- [ ] `openapi.json`과 생성 TS 타입이 같은 커밋에 실린다

### 갱신

- [ ] 쿠키 `__Host-aos_rt`만 보고 짧은 JWT는 보지 않는다. 명세 "갱신의 판정"의 여덟 갈래 가운데 하나라도 맞으면 401과 지우는 줄 둘을 내고, 계정이 비활성인 것부터의 셋(비활성, 잠김, 10초 지난 재사용)은 그 로그인 한 건(한 번 로그인해 유지 시간 동안 이어지는 로그인 상태 하나)도 끊는다
- [ ] 번호와 로그인 한 건의 줄을 잠가 판정하고 새 번호를 적는 일은 한 트랜잭션이다. 같은 번호로 동시에 온 둘은 차례로 판정되어 먼저 온 것이 번호를 쓴 것으로 적고 뒤에 온 것은 유예로 받는다
- [ ] 유예는 10초다. 쓴 지 10초가 안 된 번호가 다시 오면 끊지 않고 새 번호를 하나 더 낸다. 아직 쓰지 않은 번호는 그 로그인 한 건이 끝날 때까지 통한다
- [ ] 새 `__Host-aos_rt`의 `Max-Age`는 그때의 쉬는 시간과 총 시간의 남은 몫 가운데 짧은 것이다. 새 짧은 JWT의 `tier`는 그때 계정에서 읽은 값이다
- [ ] 판정의 규칙(유예, 쉬는 시간, 총 시간)은 `http`의 함수가 갖고 시각은 주입된 시계에서 온다

### 서명 키 바꾸기

- [ ] `agent-os operator rotate-key`가 새 난수로 키의 줄을 바꾸고 로그인 기록에 "서명 키 바꿈"을 남긴 뒤 "도는 `serve`는 10초 안에 새 키를 씁니다"를 찍고 0으로 끝난다. 옛 키는 남기지 않는다. 데이터베이스 진단은 `system-admin`과 같다

### 로그인 기록

- [ ] "번호를 다시 씀"(쓴 지 10초가 지난 번호가 다시 왔다)과 "서명 키 바꿈"을 명세 "로그인 기록"의 표대로 남긴다. 번호 값은 남기지 않는다

### 시험

- [ ] 경합: 같은 번호로 동시에 온 갱신 둘이 모두 204이고, 그 뒤 두 응답이 낸 번호 어느 것으로도 다음 갱신이 204다. 줄 잠금이 있는지는 이 결과로 가르지 못하므로 단언하지 않는다(명세 "탭 둘이 함께 갱신할 때의 유예"의 "동시에 온 둘")
- [ ] 같은 번호가 가짜 시계로 10초 뒤에 다시 오면 401이고 지우는 줄 둘이 실리며, 그 로그인의 다른 번호도 더는 통하지 않고, 로그인 기록에 한 줄이 남는다
- [ ] 쉬는 시간과 총 시간이 지난 갱신이 401이다. 비활성 계정과 잠긴 계정의 갱신은 401이고 그 로그인이 끊긴다. 비활성은 06 전이라 경로가 없으므로 데이터베이스에 상태를 직접 넣어 만든다
- [ ] `__Host-aos_rt`의 `Max-Age`가 남은 몫을 따른다(쉬는 시간이 짧은 때와 총 시간이 짧은 때)
- [ ] `rotate-key` 뒤 갱신으로 로그인이 이어지고, 옛 키의 짧은 JWT가 가짜 시계로 10초를 지난 뒤 401이다. 명령의 종료 코드와 문구와 기록을 본다(선례 `tests/test_migrate_command.py`)

### 검증

- [ ] `CLAUDE.md`의 검증 명령이 모두 초록이다
- [ ] 서버 라우트와 api-client를 고치므로 관리 화면 e2e(`pnpm -C web/apps/admin exec playwright test`)를 로컬에서 친다
- [ ] `adapters/`와 `channel/`을 고치므로 LLM 시험의 병합 조건 범위에 든다. `-m llm`을 치고, 로컬 모델 시험은 `--yes` 없이 쳐 예상 비용을 사용자에게 보이고 확인받은 뒤 돌린다
