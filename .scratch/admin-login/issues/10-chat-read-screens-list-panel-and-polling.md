# 10: 대화 목록과 대화를 읽는 화면, 실행 패널, 도는 실행 이어 보기

**What to build:** 운영자가 관리 화면의 탐색에서 "대화"를 누르면 `/chat`에 대화 목록이 선다. 열은 첫 요청, 요청한 계정, 에이전트, 상태, 실행 수, 마지막이다. 줄을 누르면 `/chat/<끝 실행>`에서 그 대화의 요청과 출력이 말풍선으로 이어지고, 실행마다 "자세히"를 누르면 오른쪽에 폭 480px의 실행 패널이 열려 지금 실행 상세 화면이 보이는 기록(이벤트의 열, 요청한 계정과 결정한 계정)이 선다. 끝 실행(그 대화에서 아직 아무도 이어 가지 않은 마지막 실행)이 아직 도는 대화를 열어 두면 3초마다 그 실행을 다시 읽어 새 이벤트를 그리고, 마지막 이벤트 뒤 실행 제한 시간이 지나도 결말이 없으면 "끝맺지 못한 것으로 보입니다"를 보이고 멈춘다. 이 티켓의 대화 화면은 읽기만 한다. 보내기와 이어 가기와 승인 버튼은 11이 더하고, 그동안 옛 실행 화면(`/runs`)도 남는다.

근거는 명세 `.scratch/admin-login/spec.md`의 "대화 목록", "관리 화면의 페이지와 주소"(표의 `/chat`과 `/chat/<끝 실행>?run=<실행>`, "탐색"), "대화 화면"(보이는 것과 진행 표시, 시각, 도구 호출, 최종 사용자의 대화를 가르는 것, 좁은 화면), "대화를 다시 그리는 읽기", "도는 실행을 이어 보기", "실행 패널", Testing Decisions의 "화면의 페이지 시험", "관리 화면 e2e", "사진 비교", "수락 조건을 덮는 자리"의 둘째 행이다. 측정은 `.scratch/admin-login/probes/swr_poll/`이고 다시 돌리지 않는다. 그린 화면은 `.scratch/admin-login/design/ch-a.dc.html`과 그 둘째 쪽 화면들, `ch-run.dc.html`, `ch-list.dc.html`, `ch-list-m.dc.html`이다. 결정은 ADR 0063 결정 "대화 화면", "도는 실행을 이어 보기", "주기 읽기의 예외"다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-25-1007-admin-login-tickets.md`의 "명세 검토(spec-reviewer)" 절을 가리킨다.

### 대화 목록

- [x] `/chat`이 `GET /conversations`를 읽어 줄을 그린다. 첫 요청은 열 폭에 맞춰 줄이고, `complete`가 거짓이면 첫 요청 옆에 "앞부분을 읽지 못함"을 보인다. 상태로 거르고 쪽을 넘긴다. 저절로 다시 읽지 않는다
- [x] 요청한 계정이 비면 그 칸에 흐린 글자로 주체(실행을 요청한 신원)를 보이고, 최종 사용자의 대화는 그 앞에 "최종 사용자"를 붙인다. "명령줄"은 붙이지 않는다(명세 "대화 목록"의 표, 이야기 65). 폭 768px 미만에서는 대화마다 카드다
- [x] 표지 줄(읽히지 않는 트레이스를 대화 줄과 따로 알리는 `{run_id, reason}` 줄)은 그 이유를 보이고, 누르면 `/chat/<run_id>`로 가서 단건 읽기의 실패를 보인다
- [x] 탐색에 "대화"(아이콘 `message-square`)를 더한다. 옛 "실행" 항목은 11이 걷는다

### 대화를 읽는 화면

- [x] `/chat/<끝 실행>`은 그 실행의 트레이스를 읽고 시작 이벤트의 앞 실행을 따라 하나씩 거슬러 읽은 뒤, 첫 실행부터 한 번에 그린다. 거슬러 읽는 실행은 끝 실행을 빼고 많아야 100개이고, 닿으면 맨 위에 "더 앞의 대화는 이 화면에 보이지 않는다"를 둔다. 앞 실행이 404거나 읽히지 않으면 읽은 데까지 그리고 맨 위에 "앞부분을 읽지 못했다"를 둔다
- [x] 실행마다 요청, "도구 N개를 불렀다"로 접힌 도구 호출 묶음, 승인 묻기와 지난 결정("<결정한 계정>가 <시각>에 승인했다: <도구>"나 "거부했다". 결정한 계정이 비면 주체 이름), 출력(디자인 시스템의 마크다운 부품)이나 실패를 보인다. 대화 요약 이벤트는 대화에 보이지 않는다. 대화의 시각은 브라우저의 시간대다
- [x] 진행 표시는 "대화를 불러오는 중"과 "다시 확인하는 중"이다
- [x] 휴대전화 폭(375px)에서도 대화를 읽는다(명세 "대화 화면"의 "좁은 화면")
- [x] 패널과 주기 읽기는 같은 실행을 같은 열쇠로 읽어 SWR의 같은 값을 쓴다

### 도는 실행 이어 보기

- [x] 끝 실행이 결말 없음(트레이스의 마지막 이벤트가 끝남, 실패, 일시정지가 아닌 실행 상태. 실행 상태는 마지막 이벤트 하나로 파생한다. 그래서 승인으로 다시 도는 실행은 앞의 일시정지 이벤트가 트레이스에 남아 있어도 마지막 이벤트가 아니므로 결말 없음이고 주기 읽기 대상이다)일 때 그 실행의 트레이스 하나만 다시 읽는다. 간격은 SWR(관리 화면이 서버 데이터를 읽고 들고 있는 라이브러리)의 `refreshInterval`에 그릴 때마다 새로 만드는 함수(인라인 꼴. 한 번 만든 함수를 그대로 쓰는 꼴은 데이터가 오기 전에 0을 내면 시작하지 않았고 멈춘 뒤 새로 고쳐도 다시 돌지 않았다, `swr_poll` 결과 1a·1b)로 주고, 데이터가 없으면 3000, 결말이 있거나 멈출 때가 지났으면 0, 그 밖은 3000이다
- [x] 멈출 때는 마지막 이벤트의 시각에 `run_timeout_seconds`(`useMe().data`에 실려 있는 값. 09는 읽을 자리만 열었고 이 티켓이 pages에서 읽어 넘긴다)를 더한 때다. 알림을 그리는 부품은 SWR의 `isValidating`(지금 다시 읽는 중인지)을 함께 읽는다. 데이터만 읽는 부품은 같은 트레이스가 다시 오면 다시 그려지지 않아 알림이 서지 않았다(`swr_poll` 결과 4c)
- [x] 401이 아닌 실패는 읽기 골격(관리 화면이 서버를 읽는 화면마다 쓰는 불러오는 중·실패·빈 목록의 틀, `.claude/rules/web-admin.md`)의 규칙대로 실패와 "다시 읽기"를 보인다. 창이 가려진 동안 읽지 않고 돌아오면 읽는 앱의 지금 정책은 바꾸지 않는다
- [x] `.claude/rules/web-admin.md`의 주기 읽기 줄에 이 예외의 범위(결말 없는 실행 하나, 창이 보이는 동안, 멈출 때까지)를 적는다. 규칙 파일을 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다

### 실행 패널

- [x] "자세히"를 누르면 열리고 주소에 `?run=<실행>`이 붙는다. 닫기 버튼과 Esc로 닫고 질의가 빠진다. 덮개가 없고, 열린 채 다른 실행의 "자세히"를 누르면 내용만 바뀐다. 폭 768px 미만에서는 화면 전체를 덮는다
- [x] 패널의 시각은 트레이스의 UTC 값 그대로다. 결정 자리를 두지 않는다. 머리의 "새로 고침"은 그 실행을 다시 읽고, 패널은 주기 읽기를 따로 걸지 않는다

### 시험

- [x] 페이지 시험: 거슬러 읽기의 상한과 끊긴 고리의 알림, 멈출 때가 지나면 알림이 서는 것, 결말이 오면 다시 읽기가 멈추는 것, 패널의 여닫기와 주소, 표지 줄, 요청한 계정이 빈 줄의 주체와 "최종 사용자"
- [x] 관리 화면 e2e: API로 대화(이어 가기를 한 번 한 실행 둘)를 만든 뒤 `/chat`에 그 줄이 서고, 누르면 두 실행의 요청과 출력이 차례로 서는 것을 본다
- [x] 사진 비교(화면을 찍어 정답 사진과 견주는 시험): 대화 목록(폭 375px의 카드 포함), 대화, 실행 패널을 관리 화면의 사진 정답에 더한다
