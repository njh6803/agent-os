# admin-login 화면

관리 화면에 운영자 계정 로그인과 대화 화면을 더하는 완성 화면이다. `/ui-design admin-login`이 Design 아티팩트에 그리고 사람이 확정한 것을 그 스킬의 7단계가 옮겼다(일지 2026-11-15-1755). 규약은 `docs/agents/issue-tracker.md`의 화면 디자인 절이고, 그린 순서와 화면은 시작 프롬프트 `screens-prompt.md`다. 그리며 `frontend-design`과 저장소 규칙이 부딪친 자리는 `.scratch/design-system/design/frontend-design-conflicts.md`의 2026-11-15 행이다.

아티팩트에는 쪽이 둘이다. "1. 대화 화면 네 안과 정해진 화면"(정해진 화면 열다섯과 대화 화면의 네 안 A·B·C·D)과 "2. 고른 대화 화면의 완성 화면"(아트보드 열넷)이다. 여기 옮긴 것은 정해진 화면 열다섯, 고른 안 A, 둘째 쪽 열넷, 캔버스 색인 `canvas.json`이다. 고르지 않은 B(`ch-b.dc.html`, 플레이그라운드형), C(`ch-c.dc.html`, 입력 칸 위 승인 패널), D(`ch-d.dc.html`, 작업 기록형)는 아티팩트에만 남겼다. 그래서 `canvas.json`의 `boards`와 `order`는 여기 없는 그 세 파일도 가리키고, 그 안들을 다시 보려면 아티팩트를 연다. 고름과 확정은 캔버스 메모(`fixed-decided`, `chat-decided`, `mock-round2`)와 일지에 함께 적었다. 화면 파일은 디자인 시스템을 `ds/agent-os/` 아래에서 불러오고 그 폴더는 옮기지 않았다(스킬 7단계가 `project/ds/`를 뺀다). 저장소에서 브라우저로 그려지는지는 보지 않았다.

대화 화면은 네 안을 그려 A(위젯과 같은 결, 가운데 한 열)를 골랐다. 고르며 사람이 정한 것이 확정된 관리 화면(admin-style)과 ADR 0063을 바꾼다.

- 실행과 대화를 탐색의 "대화" 메뉴 하나로 합쳤다. 탐색은 플러그인, 대화, 계정, 설정 넷이고, 이미 확정한 정해진 화면 여섯(`mk-accounts`, `mk-accounts-m`, `mk-account-menu`, `mk-account-menu-m`, `mk-my-password`, `mk-settings`)과 A의 탐색에서 "실행"을 뺐다. 대화 목록(`ch-list`)이 admin-style의 실행 목록 화면(`mk-runs`) 자리에 선다.
- 실행 하나는 따로 된 페이지가 아니라 대화 화면 위 오른쪽에 뜨는 패널(`ch-run`)이다. admin-style의 실행 하나 화면(`mk-run`)의 내용을 패널로 옮겼다.
- 이 둘이 ADR 0063의 결정 문장과 기능 계획의 수락 문장을 바꾼다. 그래서 명세 전에 ADR 0063의 개정과 서버 계약의 경로(대화 목록, 대화 주소)를 사람이 승인해야 한다. 바뀌는 문장은 아래와 같다.
  - 결정 "대화의 주소"의 "새 대화는 `/chat`이고"와 "대화의 목록을 주는 경로는 만들지 않는다". 목업은 `/chat`을 대화 목록으로, 새 대화를 `/chat/new`로 두었다.
  - 결정 "쓰는 경로"의 "서버의 경로와 본문은 이 화면 때문에 바뀌지 않는다". 대화 목록을 그리려면 서버가 대화를 묶어 줄 경로가 는다.
  - 따로 된 실행 상세 화면을 전제한 문장 셋. 결정 "대화 화면"의 "대화의 실행마다 실행 상세로 가는 '자세히'를 둔다", 결정 "대화의 주소"의 "실행 상세에 '이 대화 열기'를 두어", 결정 "도는 실행을 이어 보기"의 "실행 상세 화면에도 같은 규칙을 쓴다"이다. 목업에서 "자세히"는 패널을 열고, 패널에는 "이 대화 열기"가 없다.
  - 기능 계획 `.scratch/admin-login/plan.md`의 수락 문장 "플러그인 목록과 실행 목록을 보고". 실행 목록 자리에 대화 목록이 선다.

사람이 고른 문구도 하나 있다. 대화를 처음 열어 아직 아무것도 그리지 못한 동안은 진행 표시 "대화를 불러오는 중", 보인 대화를 남긴 채 다시 읽는 동안은 "다시 확인하는 중"이다(일지 "ui-design 6: 둘째 차례 확정 질문"). 그림은 "다시 확인하는 중"의 2-8(`ch-polling`)만 있다.

아래는 그리며 둔 탐색용 가정과 제안이다. 결정이 아니고 명세가 결정으로 바꾸거나 다시 묻는다(시작 프롬프트 "고른 뒤" 2). 같은 말이 캔버스 메모 `fixed-how`(정해진 화면)·`mock-how`(둘째 쪽)와 시작 프롬프트(탐색용 가정 문단, "지켜 줄 것", 틀과 화면 설명)에 나뉘어 적혀 있다.

- 주소는 `/chat`(대화 목록), `/chat/new`(새 대화), `/chat/<마지막 실행>`(대화 하나)이고, 패널이 열린 상태는 질의 `?run=<실행>`에 남는다. 대화 목록의 열(첫 요청, 요청한 계정, 실행 수)과 끝 실행의 상태로 거르기는 서버가 대화를 묶어 줄 경로를 전제한다.
- 실패한 실행과 결말 없는 실행은 이어 가지 못한다(`src/agent_os/core/continuation.py`의 `gather_continued`가 `run_finished`로 끝난 실행만 받는다). 그래서 실패 뒤의 다음 요청과 "다시 보내기"는 그 앞의 끝난 실행에서 잇고, 결말 없는 실행 뒤에는 입력 칸이 막힌다. 그러면 대화가 갈라져 끝마다 한 행이 된다.
- 요청한 계정(`requested_by`)과 결정한 계정(`decided_by`)의 필드 이름은 자리표시이고 명세가 정한다. 승인자 칸은 ADR 0063대로 주체와 같은 `operator`로 맞췄다(admin-style 확정 화면에는 주체와 다른 `ops`가 적혀 있었다).
- 패널은 대화를 막지 않아 덮개가 없고, 닫기 버튼과 Esc로 닫으며, 가려지지 않은 쪽의 다른 실행의 "자세히"를 누르면 내용만 바뀐다. 375px에서는 화면 전체를 덮는다(그리지 않았다). 패널의 시각은 트레이스의 UTC 값이고 대화의 시각은 브라우저 시간대다.
- 계정의 상태(쓰는 중, 쓰지 않음, 비밀번호를 정하기 전)와 잠김은 상태 배지 대신 글자와 아이콘으로 보인다. 시작 프롬프트가 상태 배지를 실행의 상태 넷에만 쓰기로 했기 때문이다("지켜 줄 것"). 사람이 고른 설명은 "한 줄이 계정 하나(이름, 단계, 상태 배지, 잠김 배지)"였으므로(일지 "방향 (첫 선택 화면)") 명세 전에 다시 묻는다. 사람은 이 모양으로 그린 정해진 화면 열다섯을 그대로 확정했다.
- 폭 768px 미만의 위 막대는 두 줄이다. 첫 줄에 "Agent OS"와 계정 버튼, 둘째 줄에 탐색 항목이 선다(시작 프롬프트의 틀 문단).
- 비밀번호를 정하는 화면은 계정 이름을 보이지 않는다. 링크를 읽는 경로가 계약의 경로 목록에 없기 때문이다.
- 디자인 시스템의 아이콘 집합에 없는 아이콘 일곱(message-square, users, chevrons-up-down, log-out, copy, lock, circle)을 같은 크기와 선의 Lucide 모양 SVG로 직접 그렸다. 시작 프롬프트 "고른 뒤" 2의 새 아이콘이라 명세 전에 사람에게 묻는다.
- 메뉴와 확인 창, 에이전트 고르는 칸은 디자인 시스템에 없는 부품이라 브라우저 기본 요소에 쓰임새 토큰을 칠했다. 첫 계정 명령 `agent-os operator create-system-admin`은 자리표시다.

기준 커밋은 그릴 때 읽은 근거 문서의 커밋이다. 이 워크트리를 딴 `origin/dev`의 머리이고 ADR 0062·0063을 남긴 설계 PR의 병합 커밋이라, 어림이 아니어서 "(어림)"을 붙이지 않았다. 다만 근거 문서 칸의 `screens-prompt.md`는 그 커밋에 없다. 이 폴더에서 그리는 동안 고쳤고(일지 "ui-design 4~5"와 "ui-design 5"의 두 절), 화면과 함께 이 폴더에 커밋한 판이 마지막으로 그린 때의 것이다. 동기화한 커밋은 디자인 시스템 아티팩트 색인 `lastChange`의 `via`다. 그리기 직전의 올리기가 보낼 것이 없어 그대로였다(일지 2026-11-15-1755 "ui-design 1~2"). 둘째 쪽에서 옮긴 대화 줄은 모두 고른 안 A로 그린 것이다.
