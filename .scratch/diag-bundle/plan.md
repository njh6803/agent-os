# diag-bundle: 문제를 살필 때 판과 구성과 최근 실패 원인을 비밀 값 없이 파일 하나로 묶는 명령을 준다.
**슬라이스:** 9
**Blocked by:** release-image, mcp-http

agent-os의 진단 묶음 명령. 판, 구성(매니페스트와 운영자 파일. 값은 지금의 `_describe` 규칙처럼 되울리지 않는다, `adapters/filesystem.py`), 원격 MCP 서버마다의 접속 확인 결과, 최근 실패 실행의 원인(`cause`)과 이벤트 종류와 시각을 한 파일로 묶는다. 트레이스에는 최종 사용자의 글(PRD의 알아 둘 사실)과 검색된 문서 조각이 그대로 있으므로 기본으로 싣지 않고, 운영자가 실행을 골라 명시할 때만 싣는다. 비밀 값은 싣지 않는다(원칙 V). 문서 검색 서버 쪽 진단(색인 상태, 수집 실패)은 그 저장소의 diag-bundle이 맡고, 참조 배포의 관리 명령이 두 진단을 한 묶음으로 합친다(ADR 0048). mcp-http 명세(2026-11-09, `.scratch/mcp-http/spec.md`)가 넘긴 것: 원격 MCP 서버의 접속 확인은 어댑터가 서버 하나를 여는 함수의 경계를 다시 쓴다(ADR 0049 Consequences "뒤 기능이 기대는 것"). 그 실패 문구는 서버가 돌려준 오류 응답의 상태를 원인 끝에 `(HTTP 401 Unauthorized)`처럼 들므로, 토큰 불일치는 꺼진 서버(`ConnectError`)와 문구에서 갈린다(명세 "실패 문구"). 수락: 일부러 깨뜨린 배포(모델 서버 꺼짐, MCP 서버 꺼짐, 토큰 불일치)에서 묶음만 보고 원인을 가를 수 있다. release-image 명세가 넘긴 것(2026-11-13, `.scratch/release-image/spec.md`의 Out of Scope): 묶음이 적을 판은 이미지의 OCI 라벨 셋(`org.opencontainers.image.version`, `.revision`, `.source`)과 이미지 안의 `agent-os --version`으로 읽힌다(그 명세 "이미지의 이름과 태그", "이미지의 구성"의 판 번호). 단독 배포의 컨테이너는 다섯(프록시와 `serve`, 관리 화면, 위젯, 위젯 미리보기 페이지)이고 프록시를 뺀 넷에 상태 확인이 있다(같은 명세 "이미지의 구성"의 상태 확인). 위젯은 뜰 때마다 사이트 파일로 빌드하므로 사이트 파일이 없거나 깨졌거나 읽히지 않으면 빌드 전에 까닭을 적은 진단과 함께 종료 1로 끝난다(같은 명세 "이미지의 구성"의 위젯). 관리 화면 상류 검사의 실패는 시작 기록에 `Ready` 줄이 찍힌 뒤에 나므로, 떴는지는 기록의 줄이 아니라 종료 코드와 상태 확인으로 본다(같은 명세 "관리 화면의 상류")
