# 09: 설정 화면에서 테마를 고르면 바로 바뀌고, 새로 고쳐도 첫 그림부터 그 테마다

**What to build:** 운영자가 설정 화면에서 테마 카드 넷을 그 테마로 칠한 표본으로 나란히 견주고 하나를 누르면, 저장 버튼 없이 그 자리에서 화면 전체가 그 테마로 바뀐다. 고른 테마는 이 브라우저의 localStorage에 남아, 새로 고치거나 다른 화면으로 가도 첫 그림부터 그 테마이고 깜빡이지 않는다. 같은 브라우저의 다른 탭에서 고른 테마가 이 탭에도 따라온다. 모드(라이트·다크)는 시스템 설정을 따른다는 안내가 카드 아래에 있다. 토큰은 그대로 탭마다 sessionStorage이고 localStorage에 남지 않는다.

근거는 `.scratch/admin-style/spec.md`의 "설정 화면과 테마"에서 테마 카드, 고르면 즉시 적용, 저장, 그리기 전 스크립트, 하이드레이션, 하이드레이션이 실패하면 되살린다, 다른 탭, 테마 키 두 벌의 어긋남, 토큰 저장소의 머리 주석이다. Testing Decisions "동작"의 테마 줄(2026-10-27 주석의 afterEach와 설정 밖 화면의 `storage` 이벤트)과 localStorage 단언 줄, "모양"의 테마 카드 스토리 주석과 갈래의 단언, "첫 그림의 테마" 전부(2026-10-27 주석의 시험 파일 자리), "검증과 문서" 주석의 `tech.md` 문장도 근거다. ADR 0026의 첫째 2026-10-12 이력 "관리 화면의 테마는 설정 화면에서 고르고 그 브라우저의 localStorage에 둔다"가 앞선 결정이고, ADR 0019(토큰은 sessionStorage)가 그대로다. 그림은 `mk-settings.dc.html`, `mk-settings-m.dc.html`이다. 측정은 `.scratch/admin-style/probes/`의 `card_theme.mjs`, `prepaint_theme.mjs`이고 그 `THEME_SCRIPT`가 그리기 전 스크립트의 선례다. 설정 화면과 채널 토큰·토큰 지우기는 04가 지었다.

**Blocked by:** 04

**Status:** ready-for-agent

### 시작 전

- [ ] `/ui-design`의 "웹 편집 확인"을 위 그림 둘과 옮긴 `canvas.json`에 먼저 한다. 지금 계정이 화면 Design 아티팩트를 읽지 못하면 03처럼 멈추고 사람에게 넘긴다. 다르면 멈추고 사람에게 묻는다

### 테마 카드

- [ ] **`fieldset` "테마"(`legend`) 안에 테마마다 라디오 하나를 품은 카드다.** 목록은 패키지의 `THEMES`에서 읽고 이름은 그 `name`이다. 고른 카드는 라디오의 체크와 테두리로 드러난다
- [ ] 카드 안의 표본은 `inert`이고 `data-theme`을 단 요소에 주 버튼 "승인", 상태 배지 하나(끝남), 고정폭 "payments.refund"다. 표본 요소는 `data-mode`를 달지 않는다
- [ ] 본문 칸이 `split` 이상이면 한 줄에 넷, 그 미만이면 두 줄에 둘씩이다. 카드 아래에 "모드(라이트·다크)는 시스템 설정을 따른다."다

### 고르기와 저장

- [ ] **고르면 즉시 적용한다.** 라디오가 바뀌는 순간 `html`의 `data-theme`을 그 키로 바꾸고 localStorage에 적는다. 고른 카드는 `html`의 지금 테마를 따른다
- [ ] 키는 `agent-os-admin-theme`, 값은 테마 키의 글자 그대로다. 기본(녹청)을 골라도 그 키를 적는다. 토큰을 지워도 테마는 지우지 않는다
- [ ] **다른 탭.** 같은 브라우저의 다른 탭이 저장 값을 바꾸면 `storage` 이벤트로 이 탭의 `html`과 테마 카드가 따른다. 키가 테마 키인 이벤트만 받고, 목록에 없는 값이 오거나 그 키가 지워지면 속성을 걷어 기본으로 그린다. 저장소 전체가 비워진 이벤트(키가 없는 것)도 지워진 것으로 받는다. 이 듣기는 설정 화면만이 아니라 모든 화면에서 돈다

### 첫 그림

- [ ] **그리기 전 스크립트.** `public/`의 스크립트 파일 하나를 뿌리 레이아웃 `<head>`의 막는(`async`·`defer` 없는) `<script src>`로 싣는다. 스크립트는 저장 값을 읽어 테마 키 목록에 있으면 `html`의 `data-theme`에 달고, 목록에 없거나 저장소를 읽다 예외가 나면 아무것도 달지 않는다. 타입 표기 없는 평범한 JS다(`public/`의 `.js`는 JS 파서가 읽어 타입 표기가 파싱 오류다)
- [ ] 뿌리 레이아웃의 `<html>`에 `suppressHydrationWarning`을 단다
- [ ] **하이드레이션이 실패하면 되살린다.** 모든 화면이 지나는 pages 층의 공통 컴포넌트가 마운트될 때 저장 값을 다시 읽어, 저장 값이 테마 키 목록에 있고 `html`의 `data-theme`이 그것과 다르면 다시 단다. 목록에 없는 값이나 저장소 예외에서는 아무것도 바꾸지 않는다. 평소에는 아무것도 바꾸지 않는다

### 토큰과 문서

- [ ] 토큰 저장소의 머리 주석이 localStorage를 (디스크에 평문으로 남고 모든 탭이 나눠 가져서) 쓰지 않는다고 적은 것을, 토큰을 localStorage에 두지 않는다는 뜻으로 좁혀 고친다
- [ ] `docs/constitution/tech.md` 웹 줄의 "운영자가 고른 테마는 그 브라우저의 localStorage에 두기로 했다(admin-style이 들인다, ADR 0026의 첫째 2026-10-12 이력)"를 들인 모양으로 고친다. 옛 표현을 저장소 전체에서 grep해 살아 있는 문서에 잔존이 0인지 본다

### 시험

- [ ] **페이지 시험.** 설정에서 카드를 누르면 `html`의 `data-theme`과 저장 값이 그 키다. 테스트가 만들어 보낸 `storage` 이벤트에 따르고, 목록에 없는 값과 지워진 키와 키 없는 이벤트에서 속성을 걷으며, 다른 키의 이벤트는 무시한다. `storage` 이벤트 시험 하나는 설정이 아닌 화면에서 `html`이 따르는지 본다
- [ ] **마운트 때 다시 단다.** 저장 값이 목록에 있고 `html`과 다르면 공통 컴포넌트가 마운트되며 다시 단다. 그 시험은 그리기 전에 `html`에 `data-theme`이 없다고 먼저 단언하고, 테스트 셋업(`web/apps/admin/testing/setup.ts`)의 afterEach가 localStorage와 함께 `html`의 `data-theme`도 걷는다. 앞 시험이 단 속성이 남아 초록이 되는 길을 막는다. 실제 하이드레이션 실패 뒤에 되살아나는지는 프로브가 잰 것이고 이 시험은 마운트 때의 행동만 본다
- [ ] **localStorage 단언을 좁힌다.** `HomePage.test.tsx`의 저장 시험과 `admin-token.e2e.ts`가 localStorage에 항목이 하나도 없다고 단언하던 것을, 저장소의 어느 값에도 넣은 토큰 글자가 없고 키는 테마 키만 있을 수 있다는 단언으로 바꾼다
- [ ] **스크립트 단위 시험.** 뿌리 `vitest.config.ts`의 `node` 프로젝트가 `public/`의 스크립트 파일을 읽어 node `vm`의 맥락에서 돌린다. 맥락의 `document.documentElement.dataset`과 `localStorage`는 시험이 만든다. `THEMES`의 키마다 그 키가 달리는지, 목록에 없는 값과 빈 저장소에서 아무것도 달리지 않는지, `getItem`과 `localStorage` 접근자가 던질 때 예외 없이 아무것도 달리지 않는지 본다. 저장 키는 설정 화면이 쓰는 키와 같은 상수에서 읽어 맞댄다. 그래서 `THEMES`에 테마를 더하거나 저장 키를 바꾸고 스크립트를 고치지 않으면 빨개진다. 시험 파일은 `public/` 밖에 둔다(`public/`의 파일은 그대로 공개된다)
- [ ] **첫 그림 e2e 한 편.** `admin-token.e2e.ts`의 흐름 뒤에 설정에서 쪽빛을 고르고 새로 고친다. 초기화 스크립트가 매 프레임의 `data-theme`을 기록하고, 첫 그림(`first-paint`의 `paintTime`)보다 앞선 마지막 프레임의 속성이 쪽빛인지 본다. 하이드레이션이 끝난 뒤와 다른 화면으로 옮긴 뒤에도 쪽빛인지 본다. `startTime`은 거칠게 잘려 쓰지 않는다. 이 판정이 `useEffect`로 단 갈래를 빨갛게 가른다는 것은 프로브의 양성 대조가 보였다
- [ ] **테마 카드의 스토리는 둘로 가른다.** 카드의 표본이 그 카드 테마의 쓰임새 토큰 값인지 계산값으로 재는 판정 스토리(`judgment`, 사진에서 빠진다)와, 네 카드를 보이는 스토리(사진에 든다)다. 뒤의 것은 문서 뿌리가 기본 테마이고 카드 안의 표본만 다른 테마로 칠해진다. 넓은 프로젝트에서 한 줄에 넷, 좁은 프로젝트에서 두 줄에 둘씩인지 위치로 본다
- [ ] `pnpm -C web visual:admin:update`로 새 스토리의 정답을 만들고, 바뀐 사진을 사람이 보고 PR 본문에 적는다. 사진 비교가 globals 밖의 `data-theme`(카드 안의 표본)을 막지 않는지는 재지 않았으니, 막으면 멈추고 그 까닭을 사람에게 알린다
