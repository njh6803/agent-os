# 04: 관리 화면의 틀과 공통 상태가 서고, 채널 토큰 넣기와 토큰 지우기가 설정 화면으로 옮긴다

**What to build:** 관리 토큰을 넣은 운영자가 화면 폭 768px 이상에서는 왼쪽 옆 탐색의 "Agent OS"와 플러그인·실행·설정(아이콘과 글자)으로, 768px 미만에서는 위 막대의 글자 탐색 셋으로 화면을 옮긴다. 지금 화면의 탐색 항목이 옅게 칠해진다. 화면마다 머리에 그 화면의 제목(`h1`)과 흐린 설명 한 줄이 있고, 읽는 화면이면 "새로 고침"이 있다. 처음 불러오는 동안 0.3초가 지나면 진행 표시가, 다시 확인하는 동안 머리 아래 진행 표시가, 읽다 실패하면 무엇을 읽지 못했는지와 서버의 메시지·추적 식별자가 디자인 시스템의 모양으로 선다. 머리에 있던 채널 토큰 입력과 "토큰 지우기"는 새 설정 화면(`/settings`)으로 옮긴다. 설정 화면은 "채널 토큰"과 "토큰 지우기"를 그림대로 그리고, 테마 카드는 09가 더한다.

화면마다의 본문(플러그인 줄, 실행 표, 이벤트 카드, 결정 칸)은 05~08이 다시 그린다. 이 티켓은 둘 이상의 화면이 함께 쓰는 것을 짓는다. 틀, 화면 머리, 읽기의 공통 상태, 링크·탐색 항목·코드 칸·빈 줄, 본문 칸의 컨테이너와 Storybook 데코레이터, 화면마다 `h1`이 되는 제목 수준이다.

근거는 `.scratch/admin-style/spec.md`의 "틀과 탐색"(2026-10-27 주석의 하이드레이션 전 틀), "화면 머리와 공통 상태" 전부(실패 알림 표의 읽기 넷, 처음 불러오는 중의 주석), "앱 부품"의 링크·탐색 항목·코드 칸, "설정 화면과 테마"의 머리·"채널 토큰"·"토큰 지우기"(2026-10-27 주석의 최대 폭 `content`), "접근성과 폭", Testing Decisions "동작"의 제목 수준·채널 토큰·실패 알림 줄과 "모양"의 데코레이터·갈래·틀과 부품의 단언, Further Notes의 티켓 나눔 주석 둘(설정 경로와 시험 도우미, 공통인 것)이다. 하이드레이션 전에는 틀만 그리는 것을 사용자가 2026-10-27에 골랐다(일지 2026-10-27-09). 화면 머리의 768px은 화면 중단점 `wide:`이고, ADR 0026의 2026-10-26 이력이 `wide:`에 남긴 "틀(옆 탐색과 위 막대)과 밀도" 안이다.

### 시작 전

- [x] `/ui-design`의 "웹 편집 확인"을 화면 파일 열일곱 전부와 옮긴 `canvas.json`에 먼저 한다. 틀은 모든 화면 그림에 있고, 설정 화면은 `mk-settings`·`mk-settings-m`이다. 지금 계정이 화면 Design 아티팩트를 읽지 못하면 03처럼 멈추고 사람에게 넘긴다. 다르면 멈추고 사람에게 묻는다

### 틀과 탐색

- [x] `wide:` 이상에서 왼쪽 옆 탐색(폭 `nav`)과 본문을 바탕 한 단계로 가른다. 옆 탐색 맨 위에 "Agent OS", 그 아래 탐색 항목 셋이다. `wide:` 미만에서는 위 막대(높이 `top-bar`)에 "Agent OS"와 글자만의 탐색 셋이다. 서랍이나 메뉴 단추는 두지 않는다
- [x] 탐색의 차례는 플러그인(`plug`), 실행(`list`), 설정(`settings`)이다. 탐색 항목은 아이콘 16과 글자, 높이 `nav-item`이고, 지금 화면의 항목은 `aria-current="page"`와 `bg-selected`다
- [x] "Agent OS"는 제목 요소가 아니고, 탐색의 `aria-label`은 "관리 화면"이다. 지금 틀의 `<h1>관리 화면</h1>`과 탐색 이름 "화면"은 사라진다
- [x] 하이드레이션 전, 곧 이 탭에 관리 토큰이 있는지 화면이 아직 모르는 동안에는 틀만 그리고 본문은 비운다. 관리 토큰을 넣기 전에는 틀 없이 관리 토큰 넣기 화면만 선다(03)
- [x] **본문 칸은 틀(template)이 이름 없는 컨테이너(`@container`)로 선언한다.** 틀 없이 그리는 organisms의 스토리는 미리보기의 데코레이터가 같은 컨테이너를 둘러 그린다. 조상에 컨테이너가 없으면 `split`의 갈래가 서지 않는다

### 화면 머리와 공통 상태

- [x] **화면 머리.** `h1`, 그 아래 흐린 설명 한 줄, 읽는 화면(플러그인 목록, 플러그인 하나, 실행 목록, 실행 하나)이면 오른쪽에 보조 버튼 "새로 고침"이다. `wide:` 미만에서는 버튼이 제목 아래로 내려간다. 화면마다의 제목과 설명 글자는 그 화면 티켓(05~08)이 그림대로 넣는다. 이 티켓은 지금 제목 글자를 `h1`로 올린다
- [x] **제목 수준.** 화면마다 `h1`이 그 화면의 제목이고 그 아래가 `h2`, `h3`이다. 페이지 시험의 `h2`/`h3`/`h4` 단언이 한 단계씩 올라간다
- [x] **다시 확인하는 중.** 이미 보인 것이 있는 동안 다시 읽으면 "새로 고침"이 불러오는 중(`loading`)이 되고 머리 아래에 진행 표시(`Progress`, `label` "다시 확인하는 중")가 선다. 보인 것은 지우지 않는다
- [x] **처음 불러오는 중.** 머리 아래 진행 표시 하나이고 `label`은 "플러그인 목록을 불러오는 중", "플러그인을 불러오는 중", "실행 목록을 불러오는 중", "트레이스를 불러오는 중"이다. 0.3초를 넘길 때만 보인다. **페이지 시험이 가짜 시계로 0.3초 전에는 진행 표시가 없고 그 뒤에 서는 것을 본다.** 지금 단언(`findByRole("status")`)은 지연이 있든 없든 초록이라 그대로 두면 지연을 지키지 못한다. 관리 화면 페이지 시험에 가짜 시계 선례가 있다(`HomePage.test.tsx`, `RunsPage.test.tsx`). 실행 목록의 넓은 갈래(표 머리와 뼈대 행)는 06이다
- [x] **실패 알림.** 패키지 `Alert`의 위험이다. 제목은 읽기 넷("플러그인 목록을 읽지 못했다", "플러그인을 읽지 못했다", "실행 목록을 읽지 못했다", "실행을 읽지 못했다")이고, 본문은 지금의 메시지(봉투의 `message`, 봉투가 아니면 "서버에 닿지 못했다")와 그 아래 고정폭의 "추적 식별자: <값>"(있을 때)이다. 다시 읽다 실패하면 보인 것이 지워지는 행동은 읽기 골격 한 자리에 그대로 있고, 지금의 단언이 그것을 지킨다. 켜고 끄기의 실패는 05, 결정의 실패는 08이다

### 설정 화면과 토큰

- [x] **새 경로 `/settings`가 설정 화면이다.** 다른 화면처럼 관리 토큰을 넣은 뒤에 열리고, 관리 토큰이 없으면 관리 토큰 넣기 화면이 선다. 서버의 경로와 계약(`openapi.json`)은 바뀌지 않는다
- [x] `h1` "설정"과 설명 "테마는 이 브라우저에, 토큰은 이 탭에만 남는다. 서버의 구성은 바꾸지 않는다."이고, 본문은 최대 폭 `content`다
- [x] **채널 토큰.** `h2` "채널 토큰", 설명 "일시정지한 실행에 결정을 낼 때 쓴다. agent-os serve 를 띄울 때 AGENT_OS_CHANNEL_TOKEN 에 준 값이다.", 카드 안에 가린 한 줄 입력("채널 토큰")과 주 버튼 "채널 토큰 넣기"다. 넣었으면 `circle-check` 16과 "채널 토큰을 넣었다"다
- [x] **토큰 지우기.** `h2` "토큰 지우기", "관리 토큰과 채널 토큰을 이 탭에서 모두 지운다."와 보조 버튼 "토큰 지우기"다. 누르면 지금처럼 두 토큰이 지워지고 관리 토큰 넣기 화면으로 돌아간다
- [x] 채널 토큰 입력과 "토큰 지우기"는 다른 화면의 머리에 없다. 토큰은 그대로 sessionStorage다(ADR 0019)
- [x] 다만 관리 토큰 넣기 화면 카드 아래의 "토큰 지우기"(03)는 머리에서 뺀 것이 아니라 그 화면의 것이라 그대로 둔다. 관리 토큰이 거부돼도 채널 토큰은 이 탭에 남고, 관리 토큰이 없으면 `/settings`가 열리지 않아 설정 화면의 "토큰 지우기"에 닿지 못하기 때문이다(지금 `AdminScreen`이 이 상태에서 버튼을 그린다)
- [x] 머리를 전제한 시험 도우미(`web/apps/admin/e2e/screen.ts`, `web/apps/admin/testing/token.ts`)가 설정 화면을 지나 채널 토큰을 넣고 지우게 옮긴다. 그 도우미를 쓰는 페이지 시험과 e2e가 초록이다

### 시험

- [x] 페이지 시험이 탐색 항목마다 그 화면으로 가고 지금 화면의 항목에 `aria-current="page"`가 있는지, 설정 화면이 관리 토큰 없이 관리 토큰 넣기 화면인지, 채널 토큰이 머리에 없고 설정에서 넣고 지워지는지 본다. 또 관리 토큰이 없고 채널 토큰이 남은 상태에서 관리 토큰 넣기 화면의 "토큰 지우기"가 채널 토큰을 지우는지 본다. jsdom은 Tailwind의 CSS를 싣지 않으므로, 옆 탐색과 위 막대를 둘 다 그리고 CSS로 하나를 숨기면 jsdom에는 이름이 같은 탐색이 둘 보인다. 페이지 시험이 그것을 어떻게 다루는지를 이 티켓이 정해 "이 티켓이 정한 것"에 적는다. 06의 표와 카드도 같은 물음을 받는다
- [x] 스토리가 틀(두 폭에서 옆 탐색과 위 막대), 화면 머리의 다시 확인하는 중과 실패, 빈 줄, 설정의 채널 토큰을 넣은 상태를 그리고 두 프로젝트에서 클래스 판정과 axe, 가로 스크롤 없음을 지난다
- [x] 링크와 탐색 항목의 포커스 링은 play가 포커스를 옮겨 계산값으로 본다(`.claude/rules/web-design.md`)

### 이 티켓이 정한 것

- **jsdom에서 탐색이 둘 보이는 물음.** 옆 탐색과 위 막대를 두 벌로 그리지 않고 `nav` 하나의 배치만 `wide:`로 바꾼다(`templates/AdminFrame`). 그래서 페이지 시험은 탐색을 이름 "관리 화면"으로 하나만 찾고, 지금 항목은 `findAllByRole("link", { current: "page" })`가 하나인지로 본다(`pages/SettingsPage.test.tsx`). 06의 표와 카드는 DOM의 모양이 달라 같은 길로 풀리지 않을 수 있다.
- **설정 화면의 구역에는 이름이 없다.** 구역 제목 "채널 토큰"이 입력의 라벨 "채널 토큰"과 같아, 구역에 `aria-labelledby`를 달면 `queryAllByLabelText("채널 토큰")`이 구역(`SECTION`)과 입력(`INPUT`)을 함께 찾는다. 이름 없는 구역에서는 입력 하나다(셀프 리뷰 뒤 패키지의 `TextField`를 두 구역에 넣은 임시 페이지 시험을 `vitest run --project pages`로 돌려 손으로 봤다). 그림(mk-settings, mk-settings-m)의 `section`에도 이름이 없다.
- **시험 도우미가 설정을 지나는 길.** 페이지 시험의 도우미(`testing/token.ts`)는 설정 화면을 따로 그려 넣고 지운 뒤 걷는다. 토큰은 토큰 스토어(zustand)를 거쳐 그리던 화면에 닿는다. e2e 도우미(`e2e/screen.ts`)는 탐색의 "설정"으로 가서 넣고, 넣었다는 줄을 본 뒤 브라우저의 뒤로 가기로 돌아온다. 지우기는 `clearTokens`로 설정의 "토큰 지우기"를 누른다.
- **탐색 목록과 설정 본문은 organisms다.** `organisms/AdminNav`(탐색 항목 셋)와 `organisms/Settings`(설정 본문)를 떼어, 페이지(`AdminScreen`, `SettingsPage`)와 틀의 스토리(`templates/AdminFrame.stories.tsx`)가 같은 부품을 그린다. 스토리가 화면 구성을 손으로 다시 적으면 화면이 바뀌어도 사진이 옛 모양을 찍는다.
- **패키지에서 둘을 내보낸다.** 포커스 링을 계산값으로 재는 도우미(`src/storybook/expect.ts`)를 `@agent-os/ui/storybook/expect`로 내보내 관리 화면의 스토리가 쓴다. 메모(03 PR의 claude-review)의 a11y 사본도 이 티켓에서 걷었다. 본체가 `A11Y_PARAMETERS`를 내보내고 본체의 `storyPreview`와 관리 화면의 미리보기가 그것을 쓴다. 패키지를 고쳐 사진 비교 셋을 모두 쳤다.
- **앱 부품 셋은 지었지만 화면에 넣지 않았다.** 글자 링크(`atoms/TextLink`), 코드 칸(`atoms/CodeBlock`과 `formatJson`), 빈 줄(`molecules/EmptyLine`)은 스토리만 그린다. 화면의 본문은 05~08이 다시 그리며 그때 쓴다. 실패 알림(`molecules/FailureAlert`)은 읽기 골격의 실패만 쓴다. 옛 `molecules/FailureNotice`를 쓰는 자리는 그 자리를 다시 그리는 티켓이 `FailureAlert`로 옮기고, 쓰는 곳이 남지 않으면 그 티켓이 `FailureNoticeProps`를 옮긴 뒤 옛 것을 지운다. 지금 쓰는 자리는 여섯이다(`grep FailureNotice`로 봤다). 켜고 끄기의 실패(`PluginList`, 05), `PluginPage`의 주소를 풀지 못한 실패와 플러그인의 종류가 아닌 주소(05), `RunPage`의 주소를 풀지 못한 실패(07), `RunDecision`의 결정을 보내지 못한 알림과 422의 거부 사유 위반(08)이다. 05·07·08의 메모가 저마다의 자리를 든다.
- **실행 화면의 채널 토큰 단언.** `RunPage.decision.test.tsx`의 "채널 토큰이 없으면 … 채널 토큰을 넣는 자리가 있다"는 실행 화면에 넣는 자리가 없다는 단언으로 바꿨다. 설정으로 이끄는 안내 줄과 "설정 열기"는 08이 든다.
- **하이드레이션 전의 틀은 서버의 첫 그림으로 본다.** jsdom에서 `render`로 그리면 `useHydrated`가 곧 참이라 그 분기를 지나지 않는다. 그래서 페이지 시험(`SettingsPage.test.tsx`)이 `react-dom/server`의 `renderToString`으로 서버 스냅숏의 그림을 그려, 탐색은 서고 본문(`main`)은 비었으며 관리 토큰 넣기 화면도 없는지 본다.
- **명세와 그림이 갈린 두 자리는 명세를 따랐다.** 다시 확인하는 중의 진행 표시는 화면 머리 아래에 서고, `wide:` 미만에서 "새로 고침"은 제목 아래로 내려간다.
