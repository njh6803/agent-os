# 06: 실행 목록이 데스크톱에서는 표, 휴대폰에서는 카드로 서고, 시각을 이 브라우저의 시간대로 적는다

**What to build:** 운영자가 데스크톱에서 실행을 상태·실행·에이전트·주체·시작·마지막 열의 표로, 휴대폰에서 실행마다 카드로 본다. 상태는 아이콘과 글자로 된 배지이고, 시작과 마지막은 "2026-10-12 14:03:22"처럼 이 브라우저의 시간대로 적히며 그 시간대 이름이 머리 설명에 한 번 적힌다. 상태로 거른 목록이 비면 그 상태의 아이콘과 한 줄을, 처음 불러오는 동안 넓은 폭에서는 표 머리와 움직이지 않는 뼈대 행을, 읽을 수 없는 트레이스의 행에서는 이유와 그 실행으로 가는 링크를 본다. 아래의 "더 보기"로 다음 쪽을 잇는다.

근거는 `.scratch/admin-style/spec.md`의 "실행 목록" 전부, "앱 부품"의 표, "화면 머리와 공통 상태"의 처음 불러오는 중(뼈대 행과 그 2026-10-27 주석), Testing Decisions "동작"의 시각(2026-10-27 주석의 America/New_York)과 빈 목록 줄, "모양"의 갈래의 단언과 표본 값, "e2e"의 Playwright 시간대다. 개수를 그리지 않는 것, 시간대를 머리 설명에 밝히는 것, 빈 목록의 "전부 보기"를 빼는 것은 사용자가 골랐다(일지 2026-10-26-16). 그림은 `mk-runs.dc.html`, `mk-runs-dark.dc.html`, `mk-runs-m.dc.html`, `mk-runs-empty.dc.html`, `mk-runs-loading.dc.html`이다. 컨테이너 기준 폭 `split`은 01, 본문 칸의 컨테이너와 데코레이터, 진행 표시와 0.3초, 빈 줄은 04가 지었다.

**Blocked by:** 04

### 시작 전

- [ ] `/ui-design`의 "웹 편집 확인"을 위 그림 다섯과 옮긴 `canvas.json`에 먼저 한다. 지금 계정이 화면 Design 아티팩트를 읽지 못하면 03처럼 멈추고 사람에게 넘긴다. 다르면 멈추고 사람에게 묻는다

### 머리와 거르기

- [ ] `h1`은 "실행"이고 개수를 붙이지 않는다. 설명은 "트레이스로 남은 실행이다. 새로 시작한 것이 위에 온다. 시각은 이 브라우저의 시간대(<시간대 이름>)로 적었다."이고 시간대 이름은 브라우저의 `Intl`이 고른 IANA 이름이다
- [ ] 거르기는 지금처럼 `fieldset` "상태"의 라디오 다섯(전부, 일시정지, 끝남, 실패, 결말 없음)이다

### 표와 카드

- [ ] **본문 칸이 `split` 이상이면 표다.** 열은 상태(상태 배지), 실행(고정폭 실행 식별자, 실행 하나로 가는 링크), 에이전트, 주체, 시작, 마지막(시작과 마지막은 고정폭)이다. 칸에 세로줄 없이 행 사이에 옅은 가로줄, 행 높이 `h-row`와 글자 `text-table`, 행에 올리면 `bg-hover`이고 열 머리는 `<th scope="col">`이다. 표는 내용으로 열 폭을 정하고 그림의 열 폭 px는 옮기지 않는다
- [ ] **그 미만이면 실행마다 카드다.** 첫 줄에 상태 배지와 시작 시각, 그 아래에 실행 식별자 링크, 에이전트, 주체, 마지막이다
- [ ] 실행 상태는 배지의 상태로 잇는다. 일시정지는 `paused`, 끝남은 `done`, 실패는 `failed`, 결말 없음은 `no-outcome`이고 배지의 글자는 용어집의 말이다. 일시정지만 `<strong>`으로 두드러지게 한 지금 모양은 배지가 대신한다
- [ ] **시각은 `started_at`과 `last_at`을 브라우저의 시간대로 바꾼 24시간 "YYYY-MM-DD HH:mm:ss"다.** 브라우저의 `Intl`로 바꾼다. 실행 하나 화면의 이벤트 시각은 트레이스의 글자 그대로라 이 티켓이 건드리지 않는다
- [ ] 읽을 수 없는 트레이스의 행은 상태 칸에 `triangle-alert` 16, 실행 칸에 실행 식별자 링크(계약의 `UnreadableTrace`가 `run_id`를 든다), 나머지 칸을 합쳐 "읽을 수 없는 트레이스: <이유>"다. 카드에서는 첫 줄이 아이콘과 그 글이고 그 아래가 링크다
- [ ] 실행 식별자 링크의 포인터 목표는 24px 이상이다. 긴 실행 식별자와 주체는 폭 320에서 줄을 바꿔 흐른다
- [ ] 다음 쪽이 있으면 목록 아래에 보조 버튼 "더 보기"다(지금 행동)

### 빈 목록과 불러오는 중

- [ ] 빈 목록은 거른 상태의 배지 아이콘(20)과 한 줄이다. 전부는 `list`와 "실행이 없다", 일시정지는 `circle-pause`와 "일시정지한 실행이 없다", 끝남은 `circle-check`와 "끝난 실행이 없다", 실패는 `circle-x`와 "실패한 실행이 없다", 결말 없음은 `circle-minus`와 "결말 없는 실행이 없다"다. "전부 보기"는 없고, 거르기는 그대로 남는다
- [ ] 본문 칸이 `split` 이상이면 처음 불러오는 동안 표 머리를 두고 행 자리에 진짜 행과 같은 높이의 막대(뼈대 행) 넷을 그린다. 막대는 움직이지 않고 0.3초를 넘길 때만 보인다. 막대 길이는 그림의 px를 옮기지 않는다. 그 미만에서는 04의 진행 표시 하나다
- [ ] **페이지 시험이 가짜 시계로 0.3초 전에는 뼈대 행이 없고 그 뒤에 서는 것을 본다.** 04의 진행 표시 시험과 같은 꼴이고, 명세의 "0.3초는 둘 다다"를 뼈대 행 쪽에서 지킨다. jsdom에서 두 갈래가 함께 보이면 04가 정한 다루는 법을 따른다

### 시험

- [ ] **페이지 시험의 시간대는 `pages` 프로젝트에서 America/New_York으로 고정한다.** 이 PC의 시간대가 Asia/Seoul이라 고정이 듣지 않아도 Asia/Seoul로는 같은 값이 나오고, 시간대를 Asia/Seoul로 박은 구현도 초록이기 때문이다. 기대는 `2026-09-30T09:00:00+00:00`이 "2026-09-30 05:00:00"이고 머리 설명에 "America/New_York"이 드는 것이다. 그 머리 단언이 고정이 들었다는 단언을 겸한다. 같은 프로세스에서 `process.env.TZ`를 넣으면 `Date`와 `Intl`이 따랐고 `worker_threads` 안에서는 따르지 않았으므로(명세 검토가 손으로 봤다), 고정은 시험 파일이 도는 프로세스에 닿는 길로 넣는다
- [ ] 페이지 시험(`RunsPage.test.tsx`)이 배지의 글자, 시각, 거른 상태마다 빈 줄과 "전부 보기" 없음, 읽을 수 없는 행, "더 보기"를 본다. jsdom은 Tailwind의 CSS를 싣지 않아 컨테이너 질의를 풀지 않으니 표와 카드의 갈래는 스토리가 본다. 두 갈래를 모두 그리고 CSS로 하나를 숨기면 jsdom에는 둘 다 보여 같은 링크가 두 번 찾아진다. 페이지 시험이 그것을 어떻게 다루는지(한 갈래 안에서 찾기 등)를 이 티켓이 정해 "이 티켓이 정한 것"에 적는다
- [ ] **스토리가 갈래를 위치와 역할로 본다.** 넓은 프로젝트에서 실행 목록은 표(`table` 역할)이고, 좁은 프로젝트에서는 카드다. 사진만 보면 처음 정답을 만들 때 넓은 폭에서 좁은 갈래가 그려져도 그대로 정답이 된다
- [ ] 스토리가 목록, 빈 목록(거른 상태 하나 이상), 처음 불러오는 중(뼈대 행), 읽을 수 없는 행, 다음 쪽이 있는 목록을 그리고, 두 프로젝트에서 클래스 판정과 axe, 가로 스크롤 없음을 지난다. 표본 값은 그림의 것이고 첫 행의 주체는 실행 하나 화면과 같은 operator다. 스토리 테스트의 브라우저 시간대는 고정되지 않으므로 play는 시각 글자를 단언하지 않는다. 사진은 Asia/Seoul로 찍힌다
- [ ] 관리 화면 e2e의 Playwright 설정(`web/apps/admin/playwright.config.ts`)에 `timezoneId` Asia/Seoul과 `locale` ko-KR을 더하고, `runs.e2e.ts`의 문구와 조회가 새 화면에 맞는다. `runs.e2e.ts`가 머리 설명에 "Asia/Seoul"이 드는 것을 한 번 본다. 페이지 시험만으로는 시간대를 America/New_York으로 박은 구현이 초록이기 때문이다(명세 주석)
- [ ] `pnpm -C web visual:admin:update`로 새 스토리의 정답을 만들고, 바뀐 사진을 사람이 보고 PR 본문에 적는다

메모(04에서): 04가 지은 공통 부품의 이름이다. 화면 머리는 `molecules/ScreenHeader`, 읽기 골격은 `organisms/ReadSection`(머리 아래 자리 `above`, 처음 불러오는 중의 `loadingLabel`, 실패 제목 `failureTitle`), 실패 알림은 `molecules/FailureAlert`(제목, 메시지, 추적 식별자), 글자 링크는 `atoms/TextLink`, 코드 칸은 `atoms/CodeBlock`과 JSON을 두 칸 들여 쓰는 `formatJson`, 빈 줄은 `molecules/EmptyLine`(아이콘 16·20)이다. 04는 부품을 짓고 스토리만 그렸고 화면에는 넣지 않았다. jsdom에서 같은 것이 둘 보이는 물음을 04는 탐색을 두 벌로 그리지 않고 `nav` 하나의 배치만 `wide:`로 바꿔 풀었다(04의 "이 티켓이 정한 것"). 표와 카드는 DOM의 모양이 달라 같은 길로 풀리지 않을 수 있다. 0.3초 지연은 `atoms/AfterDelay`이고, 그 가짜 시계 시험의 선례는 `HomePage.test.tsx`의 "처음 불러오는 표시는 0.3초가 지나야 선다"다.
