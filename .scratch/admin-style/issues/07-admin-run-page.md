# 07: 실행 하나 화면에서 이벤트가 카드로 서고, 결정 칸이 데스크톱에서는 옆에 붙고 휴대폰에서는 아래로 내려간다

**What to build:** 운영자가 실행 하나 화면의 제목에서 실행 식별자를, 그 아래에서 에이전트와 주체를 본다. 이벤트는 종류와 시각을 머리로 한 카드로 차례로 서고, 필드는 지금처럼 "용어집의 말 + 계약 이름"과 트레이스의 값 그대로다. 마지막 이벤트가 일시정지이면 결정 칸이 본문 칸이 넓을 때는 오른쪽 옆 칸에 붙어 스크롤해도 보이고, 좁을 때는 이벤트 아래, 재개 스트림 위에 선다. 결정한 뒤 재개한 이벤트는 "재개 스트림" 아래에 같은 카드로 붙고, 스트림이 끊기면 실행은 서버에서 계속된다는 정보 알림이 화면 머리 아래에 선다. 결정 칸 안의 모양(세 갈래, 결정 자리, 버튼 차례, 경고, 결정 실패)은 08이 다시 그리고, 이 티켓은 지금의 결정 자리를 새 자리에 놓는다.

근거는 `.scratch/admin-style/spec.md`의 "실행 하나와 결정 자리"에서 머리, 이벤트 카드(2026-10-27 주석의 최대 폭 `content`), 결정 칸이 서는 조건과 자리, 재개 스트림, 끊긴 재개 스트림, 결정 뒤 넓어지는 이벤트 칸이다. Testing Decisions "모양"의 갈래의 단언(결정 칸의 위치)과 틀과 부품의 단언(옆 칸의 `sticky`는 사진만)도 근거다. 머리의 상태 배지를 그리지 않는 것은 사용자가 골랐다(일지 2026-10-26-16). 그림은 `mk-run.dc.html`, `mk-run-resumed.dc.html`, `mk-run-m.dc.html`이다. `split`과 `content`는 01, 화면 머리와 본문 칸의 컨테이너, 코드 칸, 빈 줄은 04가 지었다.

**Blocked by:** 04

**Status:** ready-for-agent

### 시작 전

- [ ] `/ui-design`의 "웹 편집 확인"을 위 그림 셋과 옮긴 `canvas.json`에 먼저 한다. 지금 계정이 화면 Design 아티팩트를 읽지 못하면 03처럼 멈추고 사람에게 넘긴다. 다르면 멈추고 사람에게 묻는다

### 머리

- [ ] 링크 "실행 목록"(돌아가기), `h1` 실행 식별자(고정폭), 그 아래 "에이전트 <이름> 주체 <주체>"(시작 이벤트에서 읽고, 시작 이벤트가 없으면 이 줄이 없다), "새로 고침"이다. 머리의 상태 배지는 그리지 않는다
- [ ] 형식 1 트레이스면 머리 아래에 `circle-minus` 16의 흐린 줄 "형식 1 트레이스라 읽을 수 있지만 재개할 수 없다"만 서고 결정 칸은 서지 않는다(지금 문구)

### 이벤트

- [ ] `h2` "이벤트 <개수>" 아래에 이벤트마다 카드(`Card`, 안쪽 3)이고, 카드 머리는 패키지 `Card`의 `children`으로 지은 `h3` "<종류> <시각>"(시각은 트레이스의 글자 그대로, 고정폭)이다. 필드는 지금처럼 모두 펼친 채이고 모르는 종류는 원문 그대로다
- [ ] 이벤트 칸은 넓어도 최대 폭 `content`를 넘지 않는다. 결정 칸이 옆에 선 상태도 같다. 그 그림(`mk-run.dc.html` 38줄)은 이벤트 칸을 `minmax(0, 1fr)`로 적어 상한이 없지만, 명세의 문장("넓어도 880px을 넘지 않는다")은 상태를 가리지 않는다. 긴 값은 폭 320에서 줄을 바꿔 흐른다

### 결정 칸의 자리

- [ ] **마지막 이벤트가 일시정지이고 형식 1이 아니면 결정 칸이 선다.** 본문 칸이 `split` 이상이면 오른쪽 옆 칸(360px)이고 스크롤해도 머물며(`sticky`), 그 미만이면 이벤트 칸 아래, 재개 스트림 위다. 결정 칸 안은 지금의 결정 자리 그대로다(08)
- [ ] 결정 뒤에 다시 읽은 트레이스가 일시정지가 아니면 결정 칸이 걷히고 이벤트 칸이 넓어진다(지금 행동)

### 재개 스트림

- [ ] 이벤트 칸 아래의 `h2` "재개 스트림"이다. 결정 자리가 섰거나 받은 조각이 있으면 선다. 조각이 없으면 `circle-minus` 16과 "결정을 내면 재개한 이벤트가 여기에 차례로 붙는다."(빈 줄)이고, 받은 이벤트는 이벤트 칸과 같은 카드다. 읽지 못한 조각은 `h3` "읽지 못한 프레임"과 원문 카드다
- [ ] 스트림이 끝나면(결말이든 끊김이든) 트레이스를 다시 읽고 이 절은 걷히며, 기록의 원천은 다시 읽은 트레이스다(지금 행동)
- [ ] **끊긴 재개 스트림.** 스트림이 결말 없이 끝나면 화면 머리 바로 아래(이벤트 칸 위)에 `Alert` 정보로 제목 "재개 스트림이 끊겼다. 실행은 서버에서 계속된다"와 본문 "창을 닫거나 떠나도 실행은 끝까지 간다. 돌아오면 트레이스로 이어 본다."가 선다. 지금은 이벤트 아래 결정 자리 뒤에 선다. 08의 결정 실패 알림이 같은 자리를 나눠 쓴다

### 시험

- [ ] 페이지 시험(`RunPage.test.tsx`)이 머리의 `h1`과 에이전트·주체 줄(시작 이벤트가 없으면 없음), 이벤트 카드의 `h3`, 형식 1 줄, 재개 스트림의 빈 줄과 읽지 못한 프레임, 끊긴 스트림 알림의 제목과 본문을 본다. 결정 칸 안의 단언은 08이 고친다
- [ ] **스토리가 결정 칸의 위치를 본다.** 넓은 프로젝트에서 결정 칸은 이벤트 칸의 오른쪽이고, 좁은 프로젝트에서는 이벤트 칸 아래다. 옆 칸의 `sticky`는 사진만 본다
- [ ] 스토리가 이벤트만 있는 실행, 결정 칸이 선 실행, 재개 스트림에 조각이 붙은 실행, 읽지 못한 프레임, 끊긴 재개 스트림, 형식 1을 그리고, 두 프로젝트에서 클래스 판정과 axe, 가로 스크롤 없음을 지난다. 표본 값(에이전트, 주체 operator, 실행 식별자)은 그림의 것이다
- [ ] e2e의 결정 자리 도우미가 새 자리에서 결정 자리를 찾는지 보고, 관리 화면 e2e가 초록이다
