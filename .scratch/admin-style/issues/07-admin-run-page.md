# 07: 실행 하나 화면에서 이벤트가 카드로 서고, 결정 칸이 데스크톱에서는 옆에 붙고 휴대폰에서는 아래로 내려간다

**What to build:** 운영자가 실행 하나 화면의 제목에서 실행 식별자를, 그 아래에서 에이전트와 주체를 본다. 이벤트는 종류와 시각을 머리로 한 카드로 차례로 서고, 필드는 지금처럼 "용어집의 말 + 계약 이름"과 트레이스의 값 그대로다. 마지막 이벤트가 일시정지이면 결정 칸이 본문 칸이 넓을 때는 오른쪽 옆 칸에 붙어 스크롤해도 보이고, 좁을 때는 이벤트 아래, 재개 스트림 위에 선다. 결정한 뒤 재개한 이벤트는 "재개 스트림" 아래에 같은 카드로 붙고, 스트림이 끊기면 실행은 서버에서 계속된다는 정보 알림이 화면 머리 아래에 선다. 결정 칸 안의 모양(세 갈래, 결정 자리, 버튼 차례, 경고, 결정 실패)은 08이 다시 그리고, 이 티켓은 지금의 결정 자리를 새 자리에 놓는다.

근거는 `.scratch/admin-style/spec.md`의 "실행 하나와 결정 자리"에서 머리, 이벤트 카드(2026-10-27 주석의 최대 폭 `content`), 결정 칸이 서는 조건과 자리, 재개 스트림, 끊긴 재개 스트림, 결정 뒤 넓어지는 이벤트 칸이다. Testing Decisions "모양"의 갈래의 단언(결정 칸의 위치)과 틀과 부품의 단언(옆 칸의 `sticky`는 사진만)도 근거다. 머리의 상태 배지를 그리지 않는 것은 사용자가 골랐다(일지 2026-10-26-16). 그림은 `mk-run.dc.html`, `mk-run-resumed.dc.html`, `mk-run-m.dc.html`이다. `split`과 `content`는 01, 화면 머리와 본문 칸의 컨테이너, 코드 칸, 빈 줄은 04가 지었다.

### 이 티켓이 정한 것

- **두 배치를 임의값 없이 짓는다.** 그림 mk-run의 열 정의(`minmax(0, 1fr) 360px`)는 임의값이라 미리보기의 클래스 판정에 걸린다. 그래서 `organisms/RunDecision`의 지역 부품 `RunColumns`가 표준 유틸리티로 짓는다. 본문 칸이 `split` 이상이면 flex 행으로 왼쪽 칸(이벤트와 재개 스트림, 최대 폭 `content`)과 결정 칸(`w-wide`, `sticky`, `top-8`)이 나란히 서고, 그 미만이면 왼쪽 칸을 `contents`로 풀어 세 칸을 한 열의 형제로 두고 `order`로 결정 칸을 이벤트 칸과 재개 스트림 사이에 놓는다. 그래서 좁은 폭에서는 보이는 차례(이벤트, 결정, 재개 스트림)와 문서의 차례(이벤트, 재개 스트림, 결정)가 다르고, 화면 읽기 프로그램은 늘 문서의 차례로 읽는다. 재개 스트림에서 포커스를 받는 것은 받은 이벤트의 실행 링크뿐이라, 탭 차례가 보이는 차례와 어긋나는 것은 그 링크가 있을 때뿐이다. 그림과 달리 왼쪽 칸이 최대 폭에 닿으면 결정 칸은 본문 칸의 오른쪽 끝이 아니라 왼쪽 칸 바로 옆에 붙는다.
- **결정 칸은 내용이 있을 때만 선다.** 지금 결정 칸에 서는 것은 결정 자리와 최종 사용자의 실행 한 줄 둘이다. 채널 토큰이 없는 운영자의 실행에는 아직 그릴 것이 없어(안내 줄과 "설정 열기"는 08) 결정 칸이 서지 않고 이벤트 칸이 넓어진다. 08이 그 줄을 더하면 이 조건(`panel`이 null인지)이 그대로 결정 칸을 세운다.
- **재개 스트림이 서는 조건.** "결정 자리가 섰거나 받은 조각이 있으면"의 결정 자리는 `decisionPlaceStands`(채널 토큰, 일시정지, 형식 1이 아님, 최종 사용자의 실행이 아님)다. 최종 사용자의 실행 한 줄만 선 결정 칸에는 재개 스트림이 서지 않는다. 결정 화면에서 떠났다 돌아온 시험은 이제 재개 스트림이 빈 줄로 서고 조각이 붙지 않은 것을 본다.
- **결정 뒤의 실패 알림도 머리 아래로 옮겼다.** 끊긴 재개 스트림의 정보 알림과 함께, 결정을 보내지 못한 알림(옛 `FailureNotice`)도 이벤트 칸 위에 선다. 401로 채널 토큰을 내려놓으면 이 티켓에서는 결정 칸이 걷혀, 그 알림을 결정 칸 안에 두면 보일 자리가 없다(08이 채널 토큰 안내 줄을 더하면 결정 칸은 남는다). 모양은 08이 `FailureAlert`로 다시 그린다.
- **필드는 넓은 폭에서도 이름 아래 값이다.** 그림 mk-run의 두 칸(이름 168px)은 디자인 시스템의 크기 단계에 없는 폭이다. 값 칸은 도구 이름이 고정폭 `font-medium`, 시각과 글자가 아닌 JSON 값이 고정폭, 나머지 글자가 표의 글자다. 그림 mk-run·mk-run-m의 `<pre>`는 둘 다 결정 구역 안(mk-run 108줄, mk-run-m 102줄)에만 있고, 그림의 이벤트 카드는 JSON 값도 한 줄의 고정폭 `dd`다. 그래서 `CodeBlock`의 카드 안 갈래(바탕 `bg`, 안쪽 3)는 08의 결정 카드가 든다. 이벤트 카드의 JSON 값은 그림의 한 줄과 달리 지금처럼 두 칸 들여 쓴 글자로 둔다. 아래 04의 메모가 그 `<pre>`를 이벤트 카드의 몫으로 적은 것은 이 대조로 바로잡는다.
- **주소를 풀지 못한 실패는 옮기지 않았다.** `RunPage`의 `AddressFailure`는 옛 `FailureNotice` 그대로다. 같은 뼈대의 `PluginPage` 사본을 05가 나란히 고치고 있어, 한 부품으로 합치면 두 브랜치가 같은 파일을 다툰다. 합칠지는 둘 가운데 뒤에 병합하는 쪽이 정한다.
- **다른 실행으로 가는 링크는 `TextLink`다.** 이벤트의 앞 실행, 요약이 덮는 끝, 바로가기의 실행 식별자가 포인터 목표 24px을 갖는다.
