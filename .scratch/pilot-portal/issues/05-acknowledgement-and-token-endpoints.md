# 05: 사이트마다 고지 확인 끝점이 익명 식별자 쿠키를 주고, 토큰 끝점이 그 쿠키로 120초짜리 사이트 토큰을 낸다

**What to build:** 질문 페이지가 사이트마다 `/portal/sites/<이름>/` 아래 끝점 셋을 낸다. `GET …/acknowledgement`는 그 사이트의 고지 확인 여부를 `{"acknowledged":true}` 또는 `{"acknowledged":false}`로 답한다. `POST …/acknowledgement`는 `Origin`이 공개 출처와 같을 때만 204와 함께 익명 식별자 쿠키 `portal_anon`(소문자 UUID v4, `HttpOnly; SameSite=Strict; Path=/portal/sites/<이름>; Max-Age=2592000`, 공개 출처가 https일 때만 `Secure`)을 주고, `Origin`이 없거나 다르면 쿠키 없이 403이다. `POST …/token`은 꼴이 맞는 쿠키가 있으면 RS256 사이트 토큰 하나를 `text/plain`으로 내며 쿠키의 만료를 다시 적고, 없으면 401 "고지 확인이 필요합니다."다. 토큰의 `sub`가 `anon-<쿠키 UUID의 해시>`라 운영자는 트레이스와 관리 화면에서 익명 주체를 바로 알아본다(스토리 1, 2, 12). 보증 모드가 `login`인 사이트의 세 끝점은 메서드와 쿠키와 상관없이 403 "이 사이트는 로그인이 필요합니다. 로그인은 아직 제공하지 않습니다."다(스토리 6).

05는 04 뒤이고 06을 막는다. 04가 만든 순수 HTTP 요청 처리기에 경로를 더한다.

**병합 뒤에 틈이 있다(to-tickets에서 사용자가 아홉 장 분할을 골랐다).** 이 티켓만 병합된 main에서는 끝점이 서지만 그것을 부르는 페이지(`/portal/`)가 아직 404다(06이 짓는다). 아직 이 앱을 띄우는 배포가 없으므로 바깥에 보이는 것은 바뀌지 않는다.

근거는 `.scratch/pilot-portal/spec.md`의 "경로와 끝점"(표, 로그인 사이트, 캐시 헤더, 토큰 끝점이 `Origin`을 보지 않는 까닭), "익명 식별자 쿠키", "토큰", "HTTP 요청 처리기와 서버", Testing Decisions의 "Vitest"와 그 주석이다. 앞선 결정은 ADR 0050의 결정 "익명 식별자 쿠키"·"토큰"·"기록"과 Consequences(쿠키 꼴 검사만 두고 서명을 두지 않는다, 형제 도메인의 한계), ADR 0023(사이트 토큰), ADR 0024(최종 사용자 경로의 주체)다.

**Blocked by:** 04 (질문 페이지 서버가 설정과 사이트 파일을 대 본 뒤에야 뜬다). 04의 순수 HTTP 요청 처리기, 설정 모델(사이트마다 `issuer`·`assurance`, 공통 `public_origin`·`kid`), 시작 때 읽은 개인 키와 사이트 파일의 `audience`를 쓴다

**04가 넘긴 메모.** 04의 순수 처리기는 `handle(request)`이고 요청은 메서드, 경로, 헤더, 쿠키(실린 차례의 `{name, value}` 열)를 든다. 시계와 UUID 만들기를 인자로 받는 자리는 04에 쓰는 끝점이 없어 두지 않았다(안 쓰는 인자는 린트의 `no-unused-vars`에 걸린다. `web/eslint.config.mjs`가 켠 `strictTypeChecked`의 규칙이고 설정을 읽은 것이다). 이 티켓이 `handle`의 인자로 더한다. 시작 검사를 지난 결과 `loadPortal`은 `{config, privateKey, siteFile}`을 낸다(`server/load.ts`). 토큰의 서명 키는 `privateKey`이고 `audience`는 `siteFile.sites`에서 `issuer`로 찾는다. 진단과 시험의 `sites[<i>]`는 사이트 파일과 설정 모두 0부터다. 쿠키 수명 일수는 `server/cookie-policy.ts`의 `COOKIE_LIFETIME_DAYS`이고 `Max-Age=2592000`은 그 값에서 그린다.

**Status:** ready-for-agent

### 끝점

- [ ] **명세 "경로와 끝점" 표의 세 끝점을 그대로 낸다.** 모르는 사이트 이름은 404, 아는 경로의 다른 메서드는 405와 `Allow`다. 끝점 응답에는 `Cache-Control: no-store`를 단다. 확인 끝점은 요청 본문을 읽지 않는다
- [ ] **보증 모드가 `login`인 사이트의 세 끝점은 403 `text/plain; charset=utf-8` "이 사이트는 로그인이 필요합니다. 로그인은 아직 제공하지 않습니다."다.** `both`는 `anonymous`와 같다
- [ ] **토큰 끝점은 `Origin`을 보지 않는다**(명세 "경로와 끝점". 쿠키가 `SameSite=Strict`라 다른 사이트에서 일으킨 요청에는 실리지 않는다)

### 익명 식별자 쿠키

- [ ] **쿠키 이름은 사이트와 상관없이 `portal_anon` 하나이고, 값이 소문자 UUID v4(36자)가 아니면 없는 것으로 본다.** 같은 이름이 둘 이상 실리면 첫 것을 쓴다(명세 "익명 식별자 쿠키"). `__Host-`·`__Secure-` 접두를 쓰지 않는다
- [ ] **확인 끝점은 쿠키가 없거나 꼴이 틀리면 새 UUID를, 꼴이 맞으면 같은 값으로 만료만 다시 적는다.** 토큰 끝점의 200도 받은 쿠키와 같은 값으로 `Max-Age=2592000`의 `Set-Cookie`를 다시 낸다
- [ ] **`Secure`는 `public_origin`이 `https`일 때만 붙는다**

### 토큰

- [ ] **헤더는 `{"alg":"RS256","typ":"JWT","kid":<설정의 kid>}`, 본문은 `iss`(그 사이트의 발급자), `sub`(`anon-<해시 32자>`. 쿠키 값 글자 36자의 SHA-256을 소문자 16진으로 쓴 앞 32자이고 소금은 없다. 시험이 같은 해시를 스스로 계산해 대조하고 토큰 본문에 쿠키 값 원문이 없는 것도 본다), `aud`(사이트 파일의 그 사이트 `audience`), `iat`, `exp`(`iat`+120)의 다섯이다.** `nbf`는 넣지 않는다. 서명은 `node:crypto`의 RSA-SHA256이고 키 하나로 모든 사이트에 서명한다. 선례는 위젯 e2e의 `token.ts`다. 05는 02에 막히지 않으므로, 02가 먼저 병합됐으면 `@agent-os/e2e-stack`에서, 아니면 `web/apps/widget/e2e/`에서 읽는다. 서버는 그것을 import하지 않는다(`@agent-os/e2e-stack`은 앱의 devDependency다)
- [ ] **응답은 `text/plain; charset=utf-8`의 토큰 글 하나다**(명세 "토큰"의 거부한 안: JSON 봉투)
- [ ] **어떤 출력에도 쿠키 값과 토큰을 싣지 않는다**(ADR 0050 결정 "기록")

### Vitest

- [ ] **node 프로젝트에서 순수 함수를 부르는 사례를 명세 "Vitest"와 그 주석 가운데 이 티켓의 몫으로 둔다.** 토큰이 공개 키로 검증되고 클레임 다섯이 기대와 같으며 `exp - iat`가 120이고 헤더에 `kid`가 실린다. 쿠키 판정은 `Origin` 없음·다른 출처·같은 출처, 꼴이 맞는 쿠키는 같은 값으로 만료만 다시, 꼴이 틀린 쿠키는 새 값, 같은 이름 둘이면 첫 것, `https` 공개 출처에서만 `Secure`다. 상태 끝점의 두 답, 로그인 사이트 세 끝점의 403, 미확인 토큰의 401과 그 본문, 토큰 200의 쿠키 재설정, 모르는 사이트 이름의 404와 다른 메서드의 405, 끝점의 `no-store`다
- [ ] **시계와 UUID 만들기는 시험이 고정한다**(명세 "HTTP 요청 처리기와 서버")
