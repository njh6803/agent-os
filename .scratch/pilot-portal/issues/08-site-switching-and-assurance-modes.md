# 08: 셀렉트로 사이트를 바꾸고, 보증 모드와 다크 모드와 보고서 링크가 화면에 보인다

**What to build:** 사이트가 여럿인 질문 페이지에서 최종 사용자는 위쪽 띠의 라벨 "사이트"와 셀렉트로 사이트를 고른다. 바꾸면 페이지를 떠나지 않고 위젯이 그 사이트의 설정으로 다시 그려지며, 정보 글 "사이트를 바꿔 새 대화로 시작합니다."가 한 번 읽히고 앞 대화는 보이지 않는다. 확인하지 않은 사이트로 바꾸면 덮개가 다시 뜬다. 로그인이 필요한 사이트는 위젯 대신 "이 사이트는 로그인이 필요합니다." / "로그인은 아직 제공하지 않습니다." 알림을 보인다. 둘 다 사이트는 위젯 바로 위에 누를 수 없는 "로그인하고 질문하기" 단추와 "로그인은 아직 제공하지 않습니다. 지금은 로그인 없이 질문할 수 있습니다." 글 한 줄을 보인다. 띠의 "다크 모드" 스위치는 페이지와 위젯을 함께 어둡게 바꾼다. 사이트가 `report_url`을 적었으면 위젯 아래에 "이 에이전트의 평가 보고서" 링크가 새 탭으로 열린다. 사이트를 하나만 적은 설정으로 띄운 질문 페이지에서는 셀렉트와 라벨이 없다(스토리 4, 5, 6, 7, 8의 사이트 바꾸기 부분, 13).

08은 07 뒤이고 09와 나란히 돈다. 07의 확인 흐름(사이트를 고를 때마다 상태를 묻는 것)과 페이지 부품 위에 사이트 바꾸기와 보증 모드별 모습을 얹는다. 09와 둘 다 질문 페이지 e2e의 준비를 고칠 수 있으니, 나중에 병합하는 쪽이 main을 받아 그 파일을 맞춘다. 명세 묶음 C의 나머지와 묶음 E의 사례다.

근거는 `.scratch/pilot-portal/spec.md`의 "페이지"(화면의 뼈대, 사이트 고르기, 보증 모드별 모습, 다크 모드 스위치, 포커스 차례), "모양"과 그 2026-11-10 명세 검토 주석 둘째(부품을 HTML로 옮기는 것, 아이콘 다섯)와 셋째(넓은 창 대 보기), Testing Decisions의 "Playwright e2e"의 사례(사이트 바꾸기, 로그인과 둘 다, 다크 모드, 사이트 하나의 둘째 인스턴스)와 그 주석이다. 화면은 `.scratch/pilot-portal/design/`(표는 그 `README.md`)이다. 앞선 결정은 ADR 0050의 결정 "경로"(사이트가 하나면 셀렉트를 숨긴다), "페이지"와 그 2026-11-09 이력 "둘 다 사이트의 비활성 로그인 단추 곁은 알림이 아니라 글 한 줄이다", Consequences(같은 에이전트의 두 사이트 사이를 바꿔도 대화를 지운다), ADR 0024(발급자나 `sub`가 바뀌면 위젯이 저장한 대화를 지운다)다. 다크 모드 스위치는 화면 작업에서 사람이 들였다(일지 2026-11-09-1839).

**Blocked by:** 07 (처음 온 최종 사용자가 고지 덮개에서 확인한 뒤 질문한다). 07의 확인 흐름, 덮개, 짧은 고지, 옮긴 Alert·Button의 HTML과 아이콘을 쓴다

**Status:** ready-for-agent

### 사이트 바꾸기

- [ ] **위쪽 띠에 라벨 "사이트"와 셀렉트를 둔다. 사이트가 하나면 둘 다 숨긴다.** 셀렉트는 브라우저 기본 `<select>`를 토큰으로 칠한 것(높이 `--control-h`, 경계 `--border-control`, 모서리 `--radius-m`, 오른쪽 꺾쇠 `chevron-down`)이다(명세 "모양")
- [ ] **사이트를 바꾸는 동안 늦게 온 앞 사이트의 상태 답이 지금 화면을 덮지 못하게 가린다.** 07의 `browser/portal.ts`는 사이트를 한 번만 고르므로 이 가림을 두지 않았다(셀프 리뷰가 시험 없는 도달 불가 코드로 걷어 냈다). 사이트를 바꾸는 길이 서면 `ask`와 확인 단추의 응답 처리에 사이트를 고를 때마다 하나 늘어나는 번호를 두고, 늦게 온 답을 그 번호로 가리는 e2e 사례를 함께 쓴다
- [ ] **셀렉트로 바꾸면 06의 고르기와 같은 일을 하고 07의 상태 묻기를 다시 하며, 정보 글 "사이트를 바꿔 새 대화로 시작합니다."(`role="status"`, 아이콘 `info`)를 보인다.** 그 글은 다음에 사이트를 바꾸거나 `tokenProvider`가 다음에 불릴 때 거둔다(명세 "페이지")

### 보증 모드별 모습

- [ ] **`login`은 위젯 요소를 두지 않고 위젯 자리와 같은 크기의 상자에 정보 알림(제목 "이 사이트는 로그인이 필요합니다.", 본문 "로그인은 아직 제공하지 않습니다.")을 두며, 짧은 고지는 없다**
- [ ] **`both`는 익명 흐름에 더해 위젯 자리 바로 위 한 줄에 `disabled`인 보조 버튼 "로그인하고 질문하기"와 글 한 줄 "로그인은 아직 제공하지 않습니다. 지금은 로그인 없이 질문할 수 있습니다."를 둔다.** 단추는 포커스를 받지 않고 글이 읽는 차례에서 단추 바로 뒤에 온다
- [ ] **정보 알림과 보조 버튼은 디자인 시스템 Alert·Button의 마크업과 ARIA를 옮긴 HTML과 페이지 CSS로 그린다**(명세 "모양"의 주석 둘째)

### 다크 모드 스위치와 보고서 링크

- [ ] **"다크 모드" 스위치는 디자인 시스템 Switch의 마크업과 ARIA(`<input type="checkbox" role="switch">`와 상태 글)를 옮긴 HTML이다.** 켜고 끄면 뿌리의 `data-mode`와 위젯의 `mode` 속성을 함께 `dark`·`light`로 바꾼다. 처음 값과 사이트를 바꾼 뒤의 값은 그 사이트의 `mode`(없으면 시스템 설정)이고 저장하지 않는다(명세 "페이지")
- [ ] **`reportUrl`이 있는 사이트는 위젯 아래에 "이 에이전트의 평가 보고서" 링크(새 탭, `rel="noopener"`)를 그리고, 없는 사이트는 그리지 않는다.** 바깥 링크 아이콘(`external-link`)은 꾸밈이라 숨긴다
- [ ] **포커스 차례는 셀렉트, 다크 모드 스위치, 위젯 요소 또는 덮개의 단추, "고지 전문" 단추, 보고서 링크다**(명세 "페이지")

### 질문 페이지 e2e 사례

- [ ] **확인한 사이트에서 같은 에이전트의 다른 사이트로 바꾸면 앞 대화가 없고 정보 글이 보이며, 미확인 사이트로 바꾸면 덮개가 보인다**
- [ ] **사이트를 바꾼 뒤의 정보 글이 `role="status"`이고, 다음 사이트 바꾸기와 첫 요청을 보낼 때 거둬진다**(명세 "Playwright e2e"의 주석)
- [ ] **로그인 사이트는 위젯 없이 알림을 보이고, 둘 다 사이트는 `disabled` 단추와 그 바로 뒤의 글을 보인다**
- [ ] **다크 모드 스위치가 뿌리와 위젯의 모드를 함께 바꾼다**
- [ ] **`reportUrl`이 있는 사이트는 링크가 있고 없는 사이트는 없다.** 06의 준비가 사이트 넷 가운데 하나에 `report_url`을 적지 않았으면 이 티켓이 적는다
- [ ] **사이트 하나의 모습은 설정에 사이트 하나만 적은 둘째 질문 페이지 프로세스를 제 루프백 주소로 열어 셀렉트와 라벨이 없는 것만 본다.** 위젯 번들은 그 출처에 없어 그리지 않는다(명세 "Playwright e2e"). 그 출처는 06의 준비가 사이트 파일의 허용 출처에 이미 넣었다

### 넓은 창 대 보기

- [ ] **1280px과 375px에서 기본·덮개·로그인·둘 다 화면을 Playwright로 찍어 PR 본문에 디자인 그림과 나란히 싣는다.** 디자인의 넓은 창 그림은 바깥이 촘촘으로 그려졌으므로 치수가 아니라 배치를 대 본다. 찍은 그림은 사진 비교의 정답으로 커밋하지 않는다(명세 "모양"과 그 주석 셋째)
