# 03: 위젯 입력창을 "질문"으로 부르고 디자인 시스템 TextField에 화면에서만 숨기는 이름표를 더한다

**What to build:** 위젯을 넣은 모든 사이트에서 최종 사용자가 보는 입력창이 바뀐다. 입력창 위의 이름표 "요청"이 화면에서 사라지고, 화면 읽기 프로그램은 그 입력창을 "질문"으로 읽는다. 입력창 안내는 "무엇을 도와드릴까요?", 첫 화면 안내는 "아래 입력창에 적어 보내 주세요.", 앞 요청이 422로 돌아왔을 때의 오류 글은 "질문을 보낼 수 없습니다. 질문을 고쳐 다시 보내 주세요."다. 디자인 시스템의 TextField에는 이름표를 화면에서만 숨기는 선택 속성이 생기고, `<label for>`는 그대로라 접근 이름은 이름표에서 나온다. 개념어는 그대로 "요청"이다(`CONTEXT.md`의 요청 항목 단서는 명세와 같은 커밋에서 이미 달았다).

03은 02 뒤이고 07을 막는다. 위젯 미리보기 페이지와는 독립이지만, 이름표 "요청"으로 입력창을 찾는 위젯 e2e 파일을 02가 옮기거나 고치므로 02 뒤에 선다. 07의 위젯 미리보기 페이지 e2e는 입력창을 이름 "질문"으로 찾으므로 이 티켓 뒤에 선다.

근거는 `.scratch/pilot-portal/spec.md`의 "위젯 문구와 TextField"와 그 2026-11-10 명세 검토 주석, "고칠 자리의 묶음"의 D 줄과 그 주석이다. 문구는 화면 작업에서 사람이 골랐다(일지 2026-11-09-1839, 캔버스 메모 `mk-how`). 디자인 시스템의 규칙은 `.claude/rules/web-design.md`다.

**Blocked by:** 02 (위젯 e2e의 준비를 `@agent-os/e2e-stack`으로 뽑는다). 02가 옮기거나 고친 위젯 e2e 파일 위에서 문구를 바꾼다

**Status:** done

### 디자인 시스템 TextField

- [x] **디자인 시스템의 TextField에 이름표를 화면에서만 숨기는 선택 속성을 더한다.** `<label for>`는 그대로 두어 접근 이름이 이름표에서 나온다(명세 "위젯 문구와 TextField"의 거부한 안: 이름표를 없애고 `aria-label`만 둔다). TextField의 타입 테스트에 그 속성의 사례를 더한다
- [x] **TextField의 스토리와 그 `.md`에 그 변형을 더한다.** 스토리의 play 함수가 그 변형에서 이름표가 화면에 보이지 않고 입력창의 접근 이름이 이름표의 글인 것을 본다

### 위젯 문구

- [x] **위젯의 입력창이 그 속성으로 이름표 "질문"을 숨기고, 입력창 안내·첫 화면 안내·422 오류 글을 위 글로 바꾼다**
- [x] **옛 글 넷의 grep 잔존이 위젯의 소스·시험·스토리·e2e에서 0이다.** 이름표 `"요청"`(입력창을 찾는 `{ name: "요청" }` 포함), "요청을 적어 주세요", "아래에 요청을 적어 보내 주세요.", "요청을 보낼 수 없습니다. 요청을 고쳐 다시 보내 주세요."다. 명세 검토가 grep으로 센 자리는 14파일 36줄이다(명세 주석). 수용 기준은 줄 수가 아니라 잔존 0이다. 개념어 "요청"이 든 코드 이름과 주석은 바꾸지 않는다

### 사진 비교

- [x] **사진 비교의 정답을 다시 만든다.** `packages/ui`와 `apps/widget`을 건드리므로 `pnpm -C web visual:update`와 `pnpm -C web visual:widget:update`를 Docker로 친다. 관리 화면은 TextField를 쓰므로 `pnpm -C web visual:admin`도 쳐서 정답이 바뀌지 않는 것을 본다(바뀌면 그 까닭을 PR 본문에 적는다)
