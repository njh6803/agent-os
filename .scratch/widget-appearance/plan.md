# widget-appearance: 그림 올리기와 자유 색, 레이아웃 같은 새 모양 값을 위젯 설정에 더해, 사이트마다 위젯의 생김새를 더 넓게 고른다.
**슬라이스:** 10
**Blocked by:** portal-admin, widget-login-state, pilot-release

위젯이 지금 받는 모양 값은 속성 다섯(`agent`, `heading`, `intro`, `theme`, `mode`. `web/apps/widget/EMBED.md`의 속성 표)이다. 사용자가 pilot-portal 설계 인터뷰에서 다시 꺼낸 요구(사이트마다 레이아웃·모양·아이콘을 적용할 수 있어야 한다, 일지 2026-11-09-1410의 "사용자가 앞서 말한 요구를 다시 꺼냄")에서, pilot-portal이 지금 있는 다섯 값만 위젯 미리보기 페이지 설정으로 받기로 하며 새 행으로 세운 것이다(ADR 0050 Consequences "다른 행"). 슬라이스 10은 ADR 0050 승인 화면에서 사용자가 골랐다(제품 1.0 묶음. 0.1 판에는 들지 않는다).

2026-11-14의 설계 인터뷰(일지 2026-11-13-1813, ADR 0061)가 이 행의 자리와 범위를 고쳤다. 새 모양 값은 위젯의 임베드 속성과 위젯 미리보기 페이지 설정이 아니라 위젯 설정(`CONTEXT.md`)에 더한다. 위젯 설정은 위젯 쪽 서버가 데이터베이스에 들고 운영자가 위젯 설정 관리 화면에서 등록하며(portal-admin. `CONTEXT.md`의 관리 화면과 다른 위젯 쪽의 화면이다), 위젯이 그것을 받아 와 그린다(widget-login-state). 그래서 이 행은 그 두 행을 기다린다. 그 인터뷰에서 사용자가 맞춤을 넓혀 달라고 했고("챗봇 이름, 챗봇 아이콘 업로드, url은 파비콘 업로드, 배경 이미지 업로드 또는 배경색 변경할 수 있는 컬러팔레트, 인풋창 플레이스홀더 문구, 고지 문구 등"), 0.1 판의 범위를 묻는 화면에서 "글과 고르는 값 먼저"를 골랐다. 글과 고르는 값은 portal-admin이 0.1 판에 넣고, 이 행은 그 나머지를 0.1 판 뒤에 맡는다(ADR 0061 결정 "0.1 판에서 등록하는 것"). 그림 올리기(위젯 아이콘, URL 방식 창의 파비콘, 배경 이미지)와 자유 색(배경색을 고르는 팔레트)이다. 0.1 판 뒤로 미룬 까닭은 둘이다. 그림 올리기는 파일을 저장하고 검사하는 일(형식, 크기, 그림 파일에 숨은 스크립트)이 따로 든다(어림, 재지 않았다). 자유 색과 배경 이미지는 디자인 시스템이 스토리 테스트로 판정하는 명암비(테마 넷과 모드 둘의 여덟 벌, `.claude/rules/web-design.md`)를 벗어나 따로 설계가 필요하다.

위젯의 외형은 위젯과 사이트가 가진다는 ADR 0047의 자리는 그대로다. 설계 인터뷰가 먼저 볼 것: 어떤 값을 더할지(그림과 자유 색 말고도 레이아웃, 자리, 크기 등)와 디자인 시스템의 토큰(ADR 0025·0026)과의 관계, 사이트가 고른 색에서 글자의 명암비를 어떻게 지키는지, 아이콘을 사이트가 올린 그림으로만 받을지 lucide 아이콘 이름으로도 받을지, 올린 그림을 어디에 두고 무엇을 검사하는지, 새 값을 임베드 속성으로도 받을지(임베드 속성에 적은 값이 위젯 설정보다 앞선다, ADR 0061 결정 "위젯 설정"). 수락: 시험 환경에서 운영자가 위젯 설정 관리 화면에서 사이트 하나의 위젯 설정에 새 모양 값 하나를 등록하면, 위젯 미리보기 페이지의 그 사이트 위젯과 사이트 페이지에 붙인 위젯이 같은 모양으로 그려지는 테스트가 통과한다
