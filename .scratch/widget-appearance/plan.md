# widget-appearance: 레이아웃과 아이콘 같은 새 모양 칸을 위젯의 임베드 속성과 위젯 미리보기 페이지 설정에 더해, 사이트마다 위젯의 생김새를 더 넓게 고른다.
**슬라이스:** 10
**Blocked by:** pilot-portal

위젯이 지금 받는 모양 값은 속성 다섯(`agent`, `heading`, `intro`, `theme`, `mode`. `web/apps/widget/EMBED.md`의 속성 표)이다. 사용자가 pilot-portal 설계 인터뷰에서 다시 꺼낸 요구(사이트마다 레이아웃·모양·아이콘을 적용할 수 있어야 한다, 일지 2026-11-09-1410의 "사용자가 앞서 말한 요구를 다시 꺼냄")에서, pilot-portal이 지금 있는 다섯 값만 위젯 미리보기 페이지 설정으로 받기로 하며 새 행으로 세운 것이다(ADR 0050 Consequences "다른 행"). 새 모양 칸은 위젯의 임베드 속성(EMBED.md의 속성 표)과 위젯 미리보기 페이지 설정의 사이트 칸에 함께 는다. 위젯의 외형은 위젯과 사이트가 가진다는 ADR 0047의 자리는 그대로다. 슬라이스 10은 ADR 0050 승인 화면에서 사용자가 골랐다(제품 1.0 묶음. 0.1 판에는 들지 않는다). 설계 인터뷰가 먼저 볼 것: 어떤 칸을 더할지(레이아웃, 아이콘, 자리, 크기 등)와 디자인 시스템의 토큰(ADR 0025·0026)과의 관계, 아이콘을 사이트가 주는 그림으로 받을지 lucide 아이콘 이름으로 받을지, EMBED.md의 속성 표와 위젯 미리보기 페이지 설정의 모양을 바꾸는 범위(지금 모양 칸은 `heading`·`intro`·`theme`·`mode`이고 위젯의 속성 이름과 같다, pilot-portal 명세 "위젯 미리보기 페이지 설정"), 새 칸을 더할 때 위젯 미리보기 페이지 설정의 `schema_version`을 올리는지(위젯 미리보기 페이지는 모르는 칸을 거부한다. 같은 명세 절의 2026-11-10 주석이 이 기능의 명세에 넘겼다). 수락: 시험 환경에서 사이트의 위젯 미리보기 페이지 설정에 새 모양 칸 하나를 적으면, 위젯 미리보기 페이지의 그 사이트 위젯과 사이트 페이지에 붙인 위젯이 같은 모양으로 그려지는 테스트가 통과한다
