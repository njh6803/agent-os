# 04: 사이트 파일 — 위젯 빌드와 서버가 같은 파일에서 같은 허용 출처와 글자 수 상한을 읽는다

**What to build:** 운영자가 사이트 파일 하나를 주면 서버(`serve --site-file`)와 위젯 빌드가 같은 값을 쓴다. 위젯 빌드는 시작 래퍼를 지나 환경 변수 `AGENT_OS_SITE_FILE`이 가리키는 파일을 읽어, 모든 사이트의 허용 출처를 합친 목록을 iframe 페이지의 `frame-ancestors`와 postMessage의 출처 거르기 목록에, 모든 사이트의 요청 글자 수 상한 가운데 가장 작은 값을 입력창의 상한에 넣는다. 허용 출처의 표기는 브라우저가 `Origin` 헤더에 싣는 직렬화 그대로여야 하고, 그와 다른 표기는 서버가 뜨지 못하고 빌드가 실패한다. 파이썬과 Node가 같은 픽스처로 같은 판정을 낸다.

이 티켓이 픽스처 둘과 두 언어의 판정을 함께 들인다. 갈라 들이면 먼저 들어온 쪽의 판정을 다른 언어가 고정하지 않는 사이가 생긴다(명세 Testing Decisions 5).

근거는 `.scratch/web-widget/spec.md`의 "위젯 앱의 배치와 빌드" 절(빌드의 입력, 허용 출처의 표기 검사, 사이트 파일의 판)과 Testing Decisions의 "서버의 계약"(표기 픽스처, TOML 사이트 파일 픽스처)·5다. ADR 0024(fail-closed, 표기를 두 언어가 같은 픽스처로 판정)와 ADR 0023(사이트 파일)이 앞선 결정이다.

**Blocked by:** 03 (위젯 앱의 뼈대)

**Status:** done

### 빌드의 입력

- [x] **빌드는 `AGENT_OS_SITE_FILE`이 가리키는 사이트 파일을 읽는다.** 시작 래퍼가 그 변수를 넘긴다(래퍼의 자리는 03이 정했다)
- [x] **합친 허용 출처.** iframe 페이지의 `frame-ancestors`와, 05가 쓸 postMessage의 출처 거르기 목록이 그것을 쓴다. 합친 목록이 비면 `frame-ancestors 'none'`이고 postMessage도 모두 버린다
- [x] **가장 작은 요청 글자 수 상한.** 사이트가 값을 적지 않았으면 서버의 기본값 20,000이다. 05의 입력창이 그것을 쓴다
- [x] **변수가 없으면 `'none'`과 20,000으로 빌드한다. 변수가 경로를 줬는데 그 파일이 없거나 읽지 못하면 빌드가 실패한다.** 읽지 못하는 것은 둘이다. 파일의 모양이 서버의 규칙과 어긋난 것(TOML이 깨짐, 판 `schema_version`이 `"1"`이 아님, 모르는 키, 필수 키 빠짐(사이트 항목의 `issuer`·`audience`·`public_keys`·`allowed_origins`·`agents`), 엄격한 타입과 다른 값)과, 빌드가 읽는 두 값이 서버가 거절할 값인 것(아래 표기 밖의 허용 출처, 1보다 작은 요청 글자 수 상한)이다. 서버만 읽는 값의 뜻(발급자, 공개 키의 PEM과 `kid`, 열 에이전트의 이름)은 빌드가 다시 판정하지 않는다. 그 값이 틀린 파일로는 serve가 뜨지 못한다
- [x] **Node의 TOML 파서와 그 판을 이 티켓이 정한다**(ADR 0024가 넘긴 셋째)

### 허용 출처의 표기

- [x] **규칙.** 스킴은 `http`나 `https`이고, 호스트는 소문자 ASCII(국제화 도메인은 퓨니코드)다. 기본 포트(`http`의 80, `https`의 443)는 적지 않는다. IPv4 호스트는 앞에 0이 없는 십진수 넷을 점으로 잇는다. IPv6 호스트는 대괄호 안에 브라우저가 적는 꼴이다. RFC 5952 압축형이되 IPv4를 품은 주소도 16진수로 적는다(파이썬의 `compressed`는 판에 따라 IPv4 매핑 주소(`::ffff:0:0/96`)를 점으로 적어 기준으로 쓰지 않는다. 픽스처 README의 `ipv6`). 포트는 앞에 0이 없는 65535 이하의 십진수다. 경로, 끝 슬래시, 질의, 조각, 사용자 정보, `*`, `null`은 없다
- [x] **커밋한 JSON 픽스처 하나**에 지나는 사례와 막히는 사례를 둔다. 막히는 사례에는 명세가 든 다섯(`http://127.1`, `http://0x7f.0.0.1`, `http://127.000.000.001`, `https://[0:0:0:0:0:0:0:1]`, `https://example.com:0443`)이 든다. 이 다섯은 Node 24.19.0의 `new URL(v).origin`이 다른 값으로 바꾼 표기다(`node -e`로 손으로 봤다). `null`과 http(s)가 아닌 스킴(`capacitor://localhost`)도 막히는 사례다. `https://example.com:65536`(Node의 `new URL`이 `ERR_INVALID_URL`로 거절한다)과 `http://[::ffff:1.2.3.4]`(Node의 `new URL(v).origin`이 `[::ffff:102:304]`로 바꾼다)도 막히는 사례다
- [x] **파이썬은 사이트 파일을 읽을 때 그 픽스처로 판정한다.** 지금은 `"*"` 하나만 거절한다. 막히면 serve가 뜨지 못하고, 구성 오류 문구가 어긋난 항목과 어긴 규칙을 말한다
- [x] **Node는 위젯 빌드에서 같은 픽스처로 판정한다.** 막히면 빌드가 실패한다
- [x] **사이트 파일의 판은 `"1"` 그대로다.** 조여서 막히는 표기 가운데 대문자·기본 포트·경로·정규형이 아닌 IP 같은 것은 전에도 어떤 `Origin`과도 맞지 않던 항목이다. `null`과 http(s)가 아닌 스킴은 전에 맞던 항목이고, 이 티켓이 의도해서 막는 비호환이다(명세의 "사이트 파일의 판은 `"1"` 그대로다" 항목이 까닭을 든다). 그런 항목이 든 파일로는 serve가 구성 오류로 멈추고 문구가 항목과 규칙을 말한다

### 시험

- [x] **파이썬**(`tests/test_main.py`의 사이트 파일 절이 선례). 표기 픽스처의 사례마다 사이트 파일 읽기가 지나거나 막히고, 막히면 문구가 그 항목을 말한다
- [x] **TOML 사이트 파일 픽스처 하나**(사이트 둘, 그 가운데 하나만 기본값보다 작은 `request_chars`를 적는다)를 파이썬의 사이트 파일 읽기와 Node의 빌드 설정 시험이 함께 읽는다. 합친 허용 출처와 가장 작은 글자 수 상한의 기대값을 하나의 JSON에서 읽어 두 언어가 같은 값을 끌어낸다는 것을 고정한다. Node 파서가 키 경로를 잘못 읽으면 위젯은 조용히 20,000을 쓰고 서버는 422를 낸다
- [x] **빌드 설정의 시험**(선례 `next.config.test.ts`). 변수가 없을 때 `frame-ancestors 'none'`과 20,000, 준 파일이 없거나 위 "읽지 못하는 것"의 갈래마다(깨진 TOML, 다른 판, 모르는 키, 빠진 `allowed_origins`·`agents`, 글자로 적은 수, 표기 밖의 출처, 0인 상한) 빌드가 실패하는 것, TOML 픽스처에서 끌어낸 두 값이 `frame-ancestors`와 상한에 드는 것
- [x] 각 시험은 고친 판정을 되돌리면 빨개지는 것을 먼저 본다(원칙 II)

### 이 티켓이 정한 것

근거와 고른 까닭은 일지 2026-10-24-05이다.

1. **Node의 TOML 파서는 smol-toml 1.9.1이다**(ADR 0024가 넘긴 셋째). 위젯 앱의 `dependencies`에 판을 고정해 든다(Next·React와 같은 선언). 의존성이 없어 잠금 파일에 그 하나만 들고, BSD-3-Clause이며, 1.9.1은 2026-10-09에 나왔다(`pnpm view`). 정수를 bigint로 읽는 옵션(`integersAsBigInt`)이 있어 정수와 실수를 가른다. 파이썬의 엄격한 정수가 실수를 받지 않기 때문이다. 파일 머리의 BOM은 smol-toml이 받고 파이썬의 tomllib이 거절해, Node 쪽이 따로 막는다. 파일은 UTF-8로 엄격하게 푼다.
2. **빌드 값은 `next.config.ts`의 `env`로 번들에 싣는다.** `AGENT_OS_WIDGET_ORIGINS`(공백으로 이은 합친 허용 출처)와 `AGENT_OS_WIDGET_REQUEST_CHARS`(십진수 글)다. 05가 읽는 법은 05의 머리에 적었다.
3. **상대 경로의 `AGENT_OS_SITE_FILE`은 시작 래퍼가 부른 자리에서 풀어 넘긴다.** 래퍼가 next를 부르기 전에 작업 폴더를 앱으로 옮기기 때문이다. 빈 글은 변수를 준 것으로 보아 빌드가 실패한다. 사이트 없음으로 빌드하려면 변수를 주지 않는다.
4. **호스트의 규칙은 명세의 "소문자 ASCII"를 브라우저의 직렬화로 푼 것이다.** 비지 않았고 WHATWG URL의 금지된 도메인 글자가 없으면 지난다. 밑줄·`$`·빈 라벨·끝 점이 든 호스트는 브라우저가 그대로 실어 지난다. 그 가운데 CSP의 문법 밖인 호스트(밑줄, `$`, 빈 라벨)와 IP 호스트의 출처는 `frame-ancestors`에서 맞지 않을 수 있어, 호스트 이름을 쓰라는 안내를 06·10에 넘겼다(`tests/fixtures/site_file/README.md`). 첫 판은 CSP의 `host-char`로 밑줄과 빈 라벨을 막았다. 명세의 규칙 목록 밖이고 서버의 CORS에서는 맞던 항목을 serve가 거절하게 되어, 셀프 리뷰 명세 축의 지적으로 되돌렸다.
5. **진단은 어긴 자리와 규칙을 말하되 값을 싣지 않는다.** 사용자 정보에 비밀번호가 들 수 있다.
6. **Node가 서버와 같게 보는 모양은 타입·필수 키·모르는 키·판, 1 이상의 `request_chars`, 허용 출처의 표기다.** 공개 키의 수, 다른 상한의 범위, 서버만 읽는 값의 뜻은 보지 않는다. 그 값이 틀린 파일로는 빌드가 지나도 serve가 뜨지 못한다. smol-toml은 TOML 1.1을 따라 파이썬의 tomllib(TOML 1.0)이 거절하는 문법도 받으므로, 그런 파일도 같다.
