# 08: 승인 묻기 — 에이전트가 승인을 물으면 최종 사용자가 도구와 인자의 원문을 보고 승인하거나 사유를 적어 거부한다

**What to build:** 에이전트가 승인 대상 도구에서 멈추면 대화 안에 테두리 카드가 서서, 도구 이름과 인자를 고치거나 줄이지 않은 고정폭 원문으로 보인다. 최종 사용자는 "승인"을 누르거나 사유를 적고 "거부"를 누른다. 사유가 비면 "거부"가 막힌다. 결정하면 카드의 버튼과 사유 칸이 걷히고 "승인했습니다" 또는 "거부했습니다: <사유>" 한 줄이 남으며, 결정 응답의 스트림으로 실행을 이어 받는다. 기다리는 동안 입력창은 막히고 그 위 띠가 "승인이나 거부를 먼저 골라 주세요."를 보인다. 결정을 보냈는데 거절되면 카드가 다시 결정을 받는 상태로 돌아오거나, 결정할 수 없게 된 까닭을 보인다.

05가 남긴 틈(`paused`가 오면 진행 표시를 걷고 입력창을 막아 두기만 한 것)을 이 티켓이 닫는다. 새로 고친 뒤 멈춘 실행에 다시 붙어 카드가 다시 서는 것은 09가 더한다.

근거는 `.scratch/web-widget/spec.md`의 "승인 묻기", "요청이 거절될 때"(경로가 "결정"인 행과 "넷 모두"의 결정 몫), "상한", "접근성" 절과 Testing Decisions 1·3이다. ADR 0023(결정 경로)이 앞선 결정이다. 화면은 `.scratch/web-widget/design/`의 `mk-approval`이고 입력창은 고른 A다.

**Blocked by:** 07 (실패와 거절 — 입력창 위의 띠 부품과 거절 알림)

**Status:** ready-for-agent

### 카드

- [ ] **`paused` 항목이 오면 진행 표시를 걷고 카드를 세운다.** 도구 이름은 고정폭 `font-medium`이다
- [ ] **인자는 `JSON.stringify(args, null, 2)`의 글**(받은 키 차례, 두 칸 들여쓰기, 한글을 이스케이프하지 않는다)을 고정폭으로, 줄바꿈을 지키고 긴 값은 아무 자리에서나 꺾어 그린다. 고치거나 줄이지 않는다
- [ ] **사유를 다듬어 비면 "거부"가 막힌다.** 다듬는 글자는 서버와 같이 파이썬 `str.strip()`이 지우는 글자(`str.isspace()`가 참인 글자)다. JS의 `trim()`은 U+001C~U+001F와 U+0085를 지우지 않고 U+FEFF를 지워 서버와 갈리므로 쓰지 않는다
- [ ] **결정의 `pause_index`는 `paused` 프레임의 `id`다**(01의 읽기가 낸다)
- [ ] **보내는 동안 두 버튼과 사유 칸이 막힌다.** `decided` 항목이 오면 버튼과 칸이 걷히고 "승인했습니다" 또는 "거부했습니다: <사유>" 한 줄이 남는다. 결정 응답은 결정 항목부터 실행을 이어 받으므로 그 뒤는 대화의 흐름과 같다

### 입력창과 새 대화

- [ ] **결정을 기다리는 동안 입력창은 막힌 채 남고, 그 위 띠가 "승인이나 거부를 먼저 골라 주세요."를 보인다.** 띠는 07의 부품이고 차례는 재접속, 상한 다음이다
- [ ] **멈춘 실행을 기다릴 때 "새 대화"는 열려 있다.** 누르면 묻지 않고 화면과 기억을 비운다. 멈춘 실행은 서버에 남고 위젯은 그것을 잊는다

### 결정의 거절

- [ ] **401, 또는 토큰을 받지 못함.** 위험 알림 "로그인 정보를 받지 못했습니다. 페이지를 새로 고쳐 주세요."가 카드 아래에 서고 카드의 버튼이 다시 열린다
- [ ] **404.** 1초 뒤 한 번 더. 또 404면 카드의 버튼과 사유 칸을 걷고 그 아래 정보 알림 "이 승인 묻기는 더 이상 받을 수 없습니다."를 남긴다. 다시 붙을 실행을 비우고 입력창을 연다
- [ ] **409.** `Last-Event-ID`를 일시정지 프레임의 `id`로 두고 그 실행을 다시 구독한다. 새 항목이 오면 그것을 따라간다(다른 탭이 결정했다). 아무것도 없이 닫히면 카드 아래 위험 알림 "결정을 보내지 못했습니다. 잠시 뒤 다시 골라 주세요."를 보이고 버튼을 다시 연다. 같은 탭을 복제한 탭이 이미 결정한 경우가 이 길이다
- [ ] **422는 500과 같다**
- [ ] **429.** 띠가 상한의 문구를 "다시 고를 수 있습니다"로 끝맺어 보이고 그동안 결정 버튼을 막는다. 시간이 다 되면 버튼을 다시 연다. 저절로 다시 보내지 않는다
- [ ] **500, 표 밖의 상태, 응답 전의 네트워크 실패, `decided` 항목 전에 끝난 스트림.** 카드 아래 위험 알림 "요청을 처리하지 못했습니다. 잠시 뒤 다시 보내 주세요."를 보이고 버튼을 다시 연다. 결정이 이미 서버에 닿았으면 다시 고른 결정이 409를 받아 위 409 행대로 그 결정을 따라간다

### 접근성

- [ ] **승인 묻기가 서면 포커스가 카드의 제목으로 가고, 결정한 뒤에는 결과 줄로 간다.** 입력창이 다시 열려도 포커스를 옮기지 않는다
- [ ] **숨긴 `role="status"` 영역이 "승인이 필요합니다: payments.refund"처럼 승인 묻기를 한 번 읽는다**(05의 읽기 차례에 더한다)
- [ ] **포커스 차례**에 승인 카드가 대화 안의 버튼으로 든다

### 시험

- [ ] **화면 동작 테스트(`widget-pages`, MSW).** 인자의 글(키 차례, 들여쓰기, 한글), `pause_index`, 사유를 다듬는 글자(U+001C~U+001F와 U+0085만 든 사유는 "거부"가 막히고, U+FEFF만 든 사유는 막히지 않는다. 스토리 18), 보내는 동안 막힘, 결정 뒤의 한 줄(스토리 19), 결정의 거절 행마다(409의 다시 구독과 따라가기, 아무것도 없이 닫힘 포함. 스토리 21·22), 포커스의 옮김, 읽기 영역의 차례(스토리 38), 기다리는 동안의 띠와 새 대화
- [ ] **05의 틈 동안 쓴 시험**(`paused`에서 입력창을 막아 두기만 한 것)을 이 티켓의 규칙으로 바꾼다
- [ ] **위젯 스토리(`widget-storybook`).** 승인 묻기 organism을 폭 320px과 400px에서 긴 인자와 함께 그려 분류 판정, 접근성, 사진을 본다. 긴 인자가 가로 스크롤 없이 다시 흐른다(스토리 41)
