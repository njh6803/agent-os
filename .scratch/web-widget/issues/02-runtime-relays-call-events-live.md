# 02: core — 런타임이 모델·도구 호출의 이벤트를 기록하는 자리에서 곧바로 흘린다

**What to build:** 실행 도중에 모델·도구 호출의 이벤트가 소비자에게 바로 닿는다. 에이전트 코드를 바꾸지 않아도, 루프가 `ctx.llm()` 한 번인 에이전트(저장소의 계산 에이전트)에서도 모델이 도구를 요청한 순간 최종 사용자 스트림에 `calling` 항목이, 도구가 끝날 때마다 도구 항목이 온다. 운영자 `/runs`와 CLI도 실행 도중에 `llm_called`와 `tool_called`를 받는다. 함께 부른 도구(`asyncio.gather`)는 지금처럼 겹쳐 돈다. 트레이스 쓰기가 실패하면 그 뒤의 도구는 불리지 않는다.

구조는 ADR 0039이고 명세가 시제품으로 재서 정했다(`.scratch/web-widget/probes/live_relay.patch`와 `live_relay.py`, 그 README의 2026-10-23 결과). 시제품은 커밋 `934f8dfa`에 대한 패치다. 이 티켓을 시작할 때 main의 `src/agent_os/core`와 `tests/core`가 그 커밋에서 바뀌었으면 같은 diff를 다시 본다.

근거는 `.scratch/web-widget/spec.md`의 "core — 실시간 중계(ADR 0039)" 절과 Testing Decisions의 "core"·"서버의 계약"이다. ADR 0039가 앞선 결정이고, 대가는 그 Consequences다.

**Blocked by:** 01 (계약 — `calling` 항목과 429의 상한 종류). 최종 사용자 스트림의 실시간 시험이 `calling` 항목과 실시간 중계가 둘 다 있어야 초록이라, 그 시험을 드는 이 티켓이 계약 뒤에 온다(명세 Further Notes)

**Status:** done

### 구조(ADR 0039)

- [x] **에이전트는 몸통이 연 anyio 태스크 그룹의 자식 태스크에서 돈다.** 에이전트 태스크가 에이전트의 제너레이터를 순회하고 닫는다(`_closing` 그대로). 몸통은 태스크 사이로 오는 신호를 기다렸다가, 신호가 오면 컨텍스트의 줄에 쌓인 이벤트를 모두 꺼내 내보내고 그 신호에 답한다
- [x] **컨텍스트는 이벤트를 기록하는 자리마다 몸통에 신호를 보내고 답을 기다린다(맞물림).** 자리는 다섯이다. 모델을 부르기 직전과 모델 호출을 기록한 뒤, 도구를 부르기 직전(게이트를 지난 뒤)과 도구 호출을 기록한 뒤, 거부를 기록한 뒤다. 부르기 직전의 신호는 그 앞에 쌓인 런타임 이벤트(재개의 `run_resumed` 따위)를 먼저 흘린다. 에이전트가 낸 이벤트도 줄에 넣고 같은 신호를 보낸다. 줄이 비었으면 기다리지 않는다. 재생 구간에서 되살린 호출은 흘릴 것이 없다
- [x] **신호는 다음을 청하는 `anyio.Event` 하나이고 크기 0의 메모리 흐름으로 건넌다. 이벤트 자체는 흐름에 싣지 않는다.** 몸통이 끝날 때 남은 것을 꺼내는 지금의 정리(`_attend`의 `finally`)가 그대로 받는다(ADR 0039의 거부한 안 넷째)
- [x] **에이전트 태스크는 취소가 아닌 예외를 모두 그 객체 그대로 몸통에 넘기고, 신호의 보내는 쪽을 닫아 몸통의 기다림을 끝낸다.** 몸통은 받은 예외를 태스크 그룹 밖에서 다시 던진다. 일시정지 신호도 이 길로 닿는다. 취소는 붙잡지 않고 다시 던진다
- [x] **몸통 자신의 예외(트레이스 쓰기 실패, 소비자가 스트림을 닫음)는 태스크 그룹 안에서 붙잡아 그룹을 취소한 뒤 그룹 밖에서 다시 던진다.** anyio 4.15.1의 태스크 그룹이 그룹 밖으로 나가는 취소 아닌 예외를 `BaseExceptionGroup`으로 감싸기 때문이다(`.scratch/web-widget/probes/anyio_facts.py`)
- [x] **에이전트 태스크의 예외를 몸통에 돌려주는 길을 출력 인자 없이 짓는다.** 명세에 옮긴 시제품 조각의 `outcome`은 지름길이고 `CODING_STANDARDS.md`의 "출력 인자를 쓰지 않는다"에 걸린다. 이름과 자리는 이 티켓이 정한다
- [x] **두 진입점(`run()`, `resume()`)이 몸통을 공유하므로 모든 면이 함께 바뀐다**(ADR 0039 Consequences)

### core 시험(`tests/core/test_run.py`, 선례는 `ClosingAgent`의 시험들)

- [x] 모델 호출이 도구 호출을 들었을 때, 그 도구가 불리는 순간 소비자는 이미 그 `llm_called`를 받았다. 가짜 도구가 불릴 때 소비자가 받은 이벤트의 목록을 남겨 본다. 도구 호출의 `tool_called`도 다음 모델 호출 전에 소비자에게 닿는다
- [x] `llm_called`를 트레이스에 쓰다 실패하면 그 도구는 불리지 않는다(가짜 도구가 불린 수가 0이다)
- [x] `asyncio.gather`로 함께 부른 도구 둘은 둘 다 시작한 뒤에야 끝난다. 둘이 서로를 기다리는 악수가 제한 시간 안에 풀리는지로 본다
- [x] 정리 코드의 태스크를 단언한 시험 `test_런타임이_멈춘_에이전트의_정리_코드는_실행이_끝나기_전에_같은_태스크에서_돈다`(매개변수 세 사례)는 "에이전트를 돌린 태스크에서 돈다"로 바뀌고 이름도 그 뜻으로 바뀐다
- [x] `.scratch/end-user-continuation/probes/contract_mutations.toml`의 변이 "에이전트의 제너레이터를 닫지 않는다"가 바뀐 세 사례에서도 빨개지는지 다시 보고, 표지(`expect_output`)가 맞지 않으면 고친다
- [x] 소비자가 실행 도중 스트림을 닫으면 에이전트의 태스크가 취소되고 정리 코드가 돌며 실행이 제한 시간 안에 끝난다
- [x] 런타임이 에이전트 자리에서 던진 실패는 같은 객체로 몸통에 닿는다. 지금의 `_Thrown` 시험이 그대로 초록이다
- [x] 시점은 잠이 아니라 이벤트로 맞추고, 기다리는 시험마다 시간 제한을 둔다(`.claude/rules/tests.md`의 시간 단언)

### 서버 층의 실시간 시험

- [x] **최종 사용자 경로.** 실제 앱을 지나는 시작의 스트림에서, 가짜 도구는 시험이 HTTP로 `calling` 프레임을 받은 뒤에야 끝난다. 에이전트는 `ctx.llm()` 한 번의 루프가 그 도구를 부르는 모양이다. 시험은 스트림을 둘째 구동자(`tests/channel/http/test_end_user.py`의 "둘째 구동자" 절)로 읽어 그 프레임을 본 뒤 도구를 풀고, 실행이 제한 시간 안에 결말에 닿는지로 본다. 지금 core에서는 제한 시간에 걸려 빨개진다
- [x] **운영자 `/runs`.** 같은 모양으로, 가짜 도구가 시험이 `llm_called` 프레임을 받은 뒤에야 끝난다(운영자 채널 시험이 선례다)
- [x] 차례만 보는 시험은 지금 core에서도 초록이라 실시간 중계를 가르지 못한다. 위 둘은 지금 core에서 빨개지는 것을 먼저 본다(원칙 II)

### 함께 고치는 문서

- [x] **`.claude/rules/core.md`의 두 문장.** "에이전트의 `finally`가 `run()`이 끝나기 전에 같은 태스크에서 돈다"를 "에이전트를 돌린 태스크에서 돈다"로 바꾸고, "범위가 yield를 건너므로 부르는 쪽은 이벤트 사이에 await 하지 않는다"의 까닭에 몸통의 태스크 그룹을 더한다
- [x] **`.claude/rules/channel.md`의 "실행을 모는 루프는 이벤트와 이벤트 사이에 await 하지 않는다"의 까닭**(core가 취소 범위 안에서 yield한다)에 몸통의 태스크 그룹을 더한다
- [x] **sdk `BaseAgent.run`의 독스트링에 셋을 적는다**(ADR 0039 Consequences). 정리 코드는 에이전트를 돌린 태스크에서 돌고, 에이전트가 바꾼 컨텍스트 변수는 부른 쪽에 보이지 않으며, 버려진 실행에서는 정리 코드의 await가 취소된다
