# 06: 위젯 e2e — 실제 serve·Next 앞의 같은 출처 중계 뒤에서 iframe 위젯이 요청 하나를 끝까지 보낸다

**What to build:** e2e가 사이트 파일과 RS256 키를 준 실제 `serve`, 그 사이트 파일로 빌드한 실제 Next, 둘을 한 출처 아래에 모으는 시험 안의 작은 중계를 띄우고, 다른 출처의 사이트 페이지에 iframe 위젯을 넣어 요청 하나를 결말까지 보낸다. 실행 도중 도구 줄이 결말 전에 서는 것도 본다. CI에는 잡 `e2e-widget`이 생기고 필수 검사 `verify`에 든다.

이 티켓이 위젯 e2e의 준비(키, 임시 플러그인 루트, 중계, 사이트 페이지)를 세우고, 뒤의 티켓(09, 10, 11)이 그 위에 사례를 더한다. 페이지 안 방식(커스텀 요소)의 사례는 10, 새로 고친 뒤 다시 붙는 사례는 09, 실제 모델은 11이다. 07과 08은 사례를 더하지 않고 이 e2e로 회귀를 본다.

근거는 `.scratch/web-widget/spec.md`의 "nginx와 배포" 절과 Testing Decisions 4다. 처음에는 nginx 틀(`deploy/nginx/`)과 실제 nginx(TLS) 뒤의 e2e를 함께 세우는 티켓이었는데, 구현 중에 사용자가 nginx를 이 기능의 범위에서 빼고 같은 출처를 시험 안의 중계로 만들기로 했다(일지 2026-10-24-10, ADR 0024 이력 2026-10-24). 파일 이름은 브랜치 이름과 맞추느라 그대로 둔다.

**Blocked by:** 02 (core — 실시간 중계. 실제 서버에서 도구 줄이 결말 전에 서려면 있어야 한다), 05 (대화)

**Status:** done

### e2e의 준비(선례 `web/apps/admin/e2e/stack.ts`)

- [x] **실제 `serve`**를 사이트 파일과 RS256 공개 키로 띄우고, **실제 Next**를 같은 사이트 파일(`AGENT_OS_SITE_FILE`)로 빌드해 띄운다. serve의 환경에는 부모의 환경을 펼친다(관리 화면 e2e의 준비가 그렇다. 11이 `.env`의 키를 serve까지 넘기는 길이다)
- [x] **같은 출처의 중계.** 준비가 node로 띄우는 작은 중계가 `/end-user/` 아래는 serve로, `= /widget`과 `/widget/` 아래는 Next로 넘기고, 나머지는 404로 답한다. 응답은 모으지 않고 받는 대로 넘긴다. nginx의 경로 정규화와 버퍼링은 흉내 내지 않는다(ADR 0024 이력 2026-10-24)
- [x] **키와 토큰은 `node:crypto`가 짓는다.** TLS는 두지 않는다
- [x] **에이전트는 임시 플러그인 루트에 짓는, 모델 없이 도는 것들이다.** 이 티켓의 사례가 쓰는 것은 도구를 직접 부르는 것과 출력에 HTML 조각을 내는 것이다. 승인 대상에서 멈추는 것과 새로 고치는 동안 끝나지 않는 것은 그것을 쓰는 티켓이 더한다
- [x] **사이트 페이지는 위젯과 다른 출처**에서 서빙한다. 허용 출처의 페이지 하나와 허용 밖 출처의 페이지 하나다
- [x] **출처는 호스트 이름으로 둔다**(`*.localhost`). 표기 규칙(04)은 IP 호스트의 출처와 CSP의 문법 밖인 호스트(밑줄, `$`, 빈 라벨이 든 것)의 출처도 지나보낸다. 그런데 CSP3(2026-09-16 Working Draft)의 문법은 호스트 글자를 영문자·숫자·하이픈으로 두고, host-part 대조는 host가 domain이 아니면 맞지 않는다고 적는다. 그래서 그런 출처는 `frame-ancestors`에서 맞지 않을 수 있다(04가 원문을 내려받아 읽었다. 브라우저에서는 재지 않았다, `tests/fixtures/site_file/README.md`). 위젯 빌드의 `AGENT_OS_SITE_FILE`이 상대 경로면 시작 래퍼를 부른 자리에서 푼다(04)

### e2e의 사례

- [x] **iframe 위젯이 요청 하나를 결말까지 보낸다.** 허용 출처의 사이트 페이지가 postMessage로 토큰을 넘기고, 위젯이 도구를 직접 부르는 에이전트를 돌려 도구 줄과 출력을 그린다. 위젯의 요청은 위젯 출처 아래 `/end-user`로 가고, 같은 출처라 CORS 사전 요청이 없다
- [x] **도구 줄이 결말 전에 선다.** 도구를 직접 부르는 에이전트가 첫 도구를 부른 뒤 다음 도구에서 기다리는 동안, 첫 도구 줄이 이미 화면에 서 있다. 02의 실시간 중계와 중계가 응답을 모으지 않는 것이 함께 있어야 초록이다
- [x] **iframe 산출물의 CSS가 선다.** iframe 페이지의 위젯 요소에 디자인 토큰의 값이 계산된 스타일로 든다(명세 "테스트 프로젝트"의 "두 산출물의 빌드에서 서는지는 e2e가 본다"의 iframe 몫. 페이지 안 방식의 몫은 10이 본다)
- [x] **postMessage 거르기.** 부모가 아니거나 허용 밖 출처에서 온 토큰 메시지는 버려진다. e2e는 부모가 아닌 프레임 둘(같은 허용 출처의 형제, 허용 밖 출처)을 본다. 부모이면서 허용 밖 출처인 보낸 쪽은 `frame-ancestors`가 먼저 막아 e2e에서 만들 수 없고, 그 갈래는 위젯의 페이지 시험(jsdom)이 본다
- [x] **`frame-ancestors`.** 허용 출처의 페이지는 iframe을 품고, 허용 밖 출처의 페이지는 품지 못한다
- [x] **출력의 HTML 조각이 실행되지 않는다**
- [x] **글자 수 상한.** 입력창의 상한이 서버의 기본값과 같다. 서버에 직접 보낸 20,000자는 받고 20,001자는 422다
- [x] **각 사례는 판정을 되돌리면 빨개지는 것을 먼저 본다**(원칙 II). 예: `frame-ancestors`를 `*`로 바꾸면 허용 밖 사례가 빨개진다

### CI와 지침

- [x] **CI 잡 `e2e-widget`.** 관리 화면의 `e2e` 잡과 같은 모양이다. 필수 검사 `verify`의 `needs`에 더하고, 워크플로 첫머리 주석의 잡 목록도 고친다. 워크플로 감사(zizmor)가 초록이다
- [x] **로컬 명령을 정한다.** 관리 화면 e2e(`pnpm -C web/apps/admin exec playwright test`)의 모양을 따른다
- [x] **`CLAUDE.md` 검증 명령 절의 셋을 고친다.** web 줄의 괄호에 위젯 e2e의 명령과 치는 때(위젯, api-client의 위젯 몫, 서버의 최종 사용자 경로를 건드렸을 때)를 더하고, "게이트는 열다섯"을 열여섯으로, "남은 둘인 e2e와 사진 비교는 CI만 돈다"를 위젯 e2e까지 셋으로 바꾼다. 하네스 문서이므로 새 세션에서 실려 읽히는 것을 확인한다(`CLAUDE.md` 작업 규약 3)
- [x] **새 잡이 거짓으로 만드는 닫힌 문장을 고친다.** CI 잡의 수, 매 푸시에서 도는 e2e의 수, 실제 `serve`를 띄우는 구동자의 수를 세어 닫은 문장과, 실제 uvicorn·사이트 파일·서명 토큰의 조립을 지나는 자리를 "유일한"으로 닫은 문장이다. 그런 말(잡의 수, "e2e 하나", "구동자", "유일한 자리")로 저장소를 grep해 살아 있는 문서의 잔존이 0인지 본다(`CLAUDE.md` 작업 규약 4). 지금 아는 자리는 `docs/constitution/tech.md` 원격·CI 행의 "잡 다섯", `.claude/rules/http.md`의 "실제 `serve`의 둘째 구동자인 관리 화면의 e2e"와 "매 푸시에서 도는 것은 e2e 하나다", `tests/test_main.py` 최종 사용자 경로 LLM 시험 독스트링의 "실제 실행으로 보는 유일한 자리다", 같은 파일 serve 판정 시험 독스트링의 "매 푸시에서 도는 관리 화면의 e2e(실제 serve 의 둘째 구동자)", `web/apps/admin/e2e/stack.ts` 머리 주석의 "e2e 는 실제 `serve` 의 둘째 구동자이고"다. "구동자"는 같은 앱을 ASGI로 직접 부르는 시험의 이름이기도 하다(`docs/constitution/tech.md`의 같은 절, `tests/channel/http/test_end_user.py` 머리). 그 뜻의 일치는 고치지 않고, 위젯 e2e를 부를 이름이 그 이름과 겹치지 않게 한다. `tech.md`는 헌법 문서이므로 `docs/constitution/README.md`의 판을 patch로 올린다(`tools/check_constitution_version.py`가 본다). 바꾼 rules도 새 세션에서 실려 읽히는 것을 확인한다
