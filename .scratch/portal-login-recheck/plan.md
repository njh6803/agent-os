# portal-login-recheck: 위젯 미리보기 페이지가 refresh token으로 로그인 상태를 주기적으로 다시 확인해, 정지된 계정이 유지 시간보다 빨리 막히게 한다.
**슬라이스:** 10
**Blocked by:** portal-login, pilot-release

로그인 상태의 재확인. portal-login은 로그인 상태를 서명된 쿠키에 두므로, 로그인 서버에서 계정을 정지해도 유지 시간(기본 8시간)이 끝날 때까지는 질문할 수 있다(ADR 0059 Consequences "한계"). 설계 인터뷰에서 사용자가 refresh token을 설정 옵션으로 둘 수 있는지 물었고, "유지 시간 기준은 설정으로 선택, refresh token은 뒤 판"을 골라 제품 1.0 묶음의 새 행이 됐다(일지 2026-11-12-1937 "유지 시간의 기준과 refresh token(다시 올림)", ADR 0059 Considered Options). 그때까지는 유지 시간을 짧게 잡거나 ID 토큰의 만료를 따르는 기준으로 보완한다. 인터뷰가 어림한 일의 크기는 다음이고 재지 않았다. refresh token을 쿠키에 두려면 암호화가 필요하고, 쿠키 크기 한도(약 4KB)를 봐야 하며, 한 브라우저의 요청 여럿이 동시에 갱신할 때의 충돌을 다뤄야 하고(조사한 oauth2-proxy는 쿠키 저장이 잠글 수 없어 충돌하면 다시 로그인하게 된다고 적었다. 서브에이전트가 원문을 받아 읽었고 다시 대 보지 않았다), 시험용 가짜 로그인 서버에 갱신 기능을 더해야 한다. `openid-client` 6.8.9의 타입 선언에 `refreshTokenGrant`가 있다(읽었고 실행해 보지 않았다). 설계 인터뷰가 먼저 볼 것: 다시 확인하는 수단(refresh token, 로그인 서버에 조용히 다녀오는 재확인, 로그인 서버가 알리는 로그아웃)을 견주고, 위젯 미리보기 페이지의 무상태(ADR 0050)를 지킬지, 기본을 끔으로 둘지, 다시 확인이 실패했을 때의 화면을 정한다. 수락: 시험 환경에서 가짜 로그인 서버가 계정을 정지하면 유지 시간이 남아 있어도 정한 간격 안에 그 사람의 다음 질문이 로그인 안내로 막힌다
