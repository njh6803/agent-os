# 06: `/traces/{run_id}` — 한 실행의 이벤트 전부

**What to build:** 무엇이 어긋났는지 되짚는 자리가 생긴다. 한 실행의 이벤트가 쓴 순서 그대로 나오고, 승인자는 "무엇을 승인해 달라는지"를 목록이 아니라 여기서 본다. 이 런타임이 모르는 종류의 이벤트도 원문을 든 채 나온다 — 빼면 화면이 실행에 대해 거짓말을 하고, 모르는 이벤트가 하나라도 있으면 재개가 거부되므로 화면이 보지 못한 그 줄이 곧 재개 불가의 원인이 된다.

경계 밖으로 마스킹되지 않은 도구 결과와 프롬프트가 나가는 자리가 여기다. 그것이 성립하는 전제는 02가 세운 인증이고(ADR 0011과 ADR 0009의 2026-09-22 이력은 짝이라 둘 중 하나가 바뀌면 다른 하나를 다시 본다), 마스킹 범위는 이 기능이 건드리지 않는다. 그 전제가 기댄 사실을 불변식으로 바꾸는 테스트가 이 티켓에 함께 있다.

**Blocked by:** 02 (실행 식별자의 패턴은 01이 정하고, 02가 이미 01에 막혀 있다)

**Status:** ready-for-agent

- [ ] `GET /traces/{run_id}`가 한 실행의 이벤트를 쓴 순서 그대로 돌려준다
- [ ] **모르는 종류의 이벤트가 판별자를 달고 원문과 함께 실린다**(ADR 0010의 2026-09-22 이력). 판별자 값이 실제 이벤트 종류와 충돌하지 않는다. 디스크 형식은 바뀌지 않는다 — 모르는 이벤트는 쓰이는 타입이 아니라 읽기 결과다
- [ ] 부재는 404다. 내 오타와 서버의 문제가 갈린다
- [ ] 읽을 수 없는 트레이스 파일은 500이고 에러 봉투다. 4xx면 운영자가 잘못 요청했다고 믿고 깨진 파일을 못 찾는다. **명세의 상태 코드 표는 `PluginError`를 매니페스트로만 적었지만 ADR 0012의 2026-09-22 이력이 트레이스로 넓혔다** — 표를 보고 되돌리지 않는다
- [ ] **`{run_id}`에 `..`나 경로 구분자나 절대 경로가 들어오면 422이고 포트가 아예 불리지 않는다.** 가짜 포트의 호출 횟수로 본다. 절대 경로는 `pathlib`의 `/`가 왼쪽을 버려 루트를 통째로 무력화하고, 404와 500이 갈리는 것은 임의 경로의 파일 존재 오라클이 된다
- [ ] 경로에 거는 패턴이 01이 정한 그것이고 경로 파라미터 스키마로 `openapi.json`에 박힌다. `RunId`는 제약 없는 `NewType`이라 런타임 검증이 0이고, CLI에서는 argv라 신뢰 경계 안이었던 값을 HTTP가 원격 입력으로 바꾼다
- [ ] **저장소의 매니페스트 중 `secret_args`를 선언한 것이 없다는 것을 테스트가 판정한다**(ADR 0009의 2026-09-22 이력). 이 라우트가 마스킹되지 않은 이벤트를 내보내므로, 처음 선언하는 날 그 테스트가 빨개지고 그 순간이 곧 열린 문제 셋을 닫을지 정해야 하는 순간이다. 테스트가 막는 것은 선언 자체가 아니라 결정 없이 지나가는 것이다
- [ ] `openapi.json`이 이 라우트를 알고 최신성 테스트가 초록이다
- [ ] 검사 넷이 초록이다
