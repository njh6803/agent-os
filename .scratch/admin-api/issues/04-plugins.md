# 04: `/plugins` — 등록된 것을 한 곳에서 본다

**What to build:** 운영자가 요청 한 번으로 무엇이 실려 있는지 본다. 에이전트·MCP·스킬·모델이 한 목록에 나오고 각 항목이 자기 종류를 든다. 어떤 도구가 승인 대상인지가 거기서 보인다 — `interrupts`가 `requires_approval`이라는 필드로 닫고 읽는 면은 만들지 않은 운영자 스토리가 여기서 닫힌다. 깨진 매니페스트 하나가 나머지를 가리지 않고, 깨졌다는 사실도 목록에 보인다.

표지가 `/plugins`와 같은 티켓인 것이 중요하다. 표지 없이 목록이 먼저 병합되면 그 구간의 목록은 읽히지 않는 것을 조용히 빼거나 전체를 500으로 만들고, 그 사이에 커밋되는 `openapi.json`은 나중에 파괴적으로 바뀐다. `interrupts` 01이 마스킹을 당겨 온 것과 같은 모양이다. 경로 파라미터 검증도 같은 이유로 여기다 — 검증이 늦으면 그 구간 main에 경로 순회가 실재하고, 명세가 그 구멍을 아는 상태로 적었으므로 나누는 순간 "아는 구멍을 열어 둔 것"이 된다. 패턴 자체는 01이 정했고 이 티켓은 그것을 경로에 건다.

**Blocked by:** 02 (포트의 `list_manifests`와 이름 패턴은 01이 정하고, 02가 이미 01에 막혀 있다)

**Status:** ready-for-agent

- [ ] `GET /plugins`가 종류 넷의 매니페스트를 한 평평한 목록으로 돌려주고 각 항목이 자기 종류를 든다. 클라이언트가 종류로 가른다
- [ ] 목록의 각 항목이 매니페스트 그대로라 `requires_approval`이 거기서 보인다. 가드레일의 범위를 코드를 읽지 않고 안다
- [ ] 깨진 매니페스트가 있어도 나머지가 돌아오고, 깨진 것은 항목으로 남아 종류·이름·이유를 든다. 조용히 빠지면 등록했다고 믿는 것과 실제가 어긋난다
- [ ] `GET /plugins/{kind}/{name}`이 매니페스트 하나를 통째로 돌려준다. 부재는 404, 깨진 파일은 500이다. 목록과 단건의 비대칭이 의도라는 것을 테스트가 고정한다
- [ ] **응답 타입이 `sdk`의 매니페스트 그대로인지 API 쪽 별도 타입인지를 이 티켓이 정한다.** 그대로면 매니페스트의 `schema_version`이 `openapi.json`에 박히고, `plugin-toggle`이 매니페스트 계약을 바꾸는 날 계약 파일이 함께 바뀐다
- [ ] 없는 `kind`는 422다. 내 오타와 서버의 문제가 갈린다
- [ ] **`{name}`에 `..`나 경로 구분자(윈도가 주 환경이라 역슬래시도 구분자다)나 절대 경로가 들어오면 422이고 포트가 아예 불리지 않는다.** 가짜 포트의 호출 횟수로 본다. 검증이 파일시스템에 닿기 전에 끝난다는 것이 이 단언의 내용이다
- [ ] 경로에 거는 패턴이 01이 정한 그것이고 `openapi.json`에 박힌다. `sdk`가 매니페스트의 이름에 이미 거는 것이라 새 규칙이 아니라 있는 계약을 조회 쪽에도 거는 것이다
- [ ] 매니페스트를 통째로 내보내는 것이 **mcp 매니페스트의 `command`·`args`도 내보낸다는 뜻**임을 알고 구현한다(ADR 0009의 2026-09-22 이력, 네 번째 열린 문제). 가리지 않는 것이 결정이고 경계는 인증이다. 여기서 새로 닫지 않는다
- [ ] 목록이 MCP 서버를 띄우지 않는다. 조회 하나가 외부 프로세스 여럿을 띄우면 서버 하나가 죽어 있을 때 목록이 통째로 실패한다
- [ ] `openapi.json`이 이 라우트 둘을 알고 최신성 테스트가 초록이다
- [ ] 검사 넷이 초록이다
