# 01: 계약 — 포트 둘에 목록이 늘고 실행 요약이 생긴다

**What to build:** 이름을 모르는 채 묻는 것이 가능해진다. 플러그인 디렉터리의 매니페스트를 종류별로 전부 받을 수 있고, 트레이스 디렉터리의 실행들을 최근 순으로 상태와 함께 받을 수 있다. 사람에게 보이는 새 동작은 없다 — HTTP는 아직 없고, 이 티켓이 끝나면 어댑터 둘이 진짜 디렉터리에서 목록을 만들어 낸다.

이 기능의 계약 티켓이고 나머지 전부를 막는다. 포트는 다섯 그대로다(ADR 0012). 어댑터 구현을 다음 티켓으로 미룰 수 없다 — `main.py`가 어댑터를 포트 타입 파라미터에 넘기므로 Protocol만 넓히면 pyright strict가 그 자리에서 깨진다. 식별자 둘의 문자 집합도 여기서 정한다. 라우트가 각자 정하면 목록을 만드는 이 티켓과 목록을 내보내는 05가 패턴을 모르는 채 먼저 병합되고, 05가 커밋하는 `openapi.json`이 패턴 없는 식별자를 계약으로 박는다. 리뷰의 질문은 "동작하나"가 아니라 "이 시그니처와 필드 이름으로 오래 살 수 있나"다.

근거는 `.scratch/admin-api/spec.md`, ADR 0012와 그 2026-09-22 이력 셋, ADR 0010, ADR 0003.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] `PluginSource.list_manifests(kind)`가 종류 하나의 매니페스트를 전부 돌려준다. 빈 디렉터리와 없는 디렉터리가 빈 목록이다
- [x] 깨진 매니페스트가 섞여도 읽히는 것은 전부 돌아오고, 깨진 것은 종류·이름·읽을 수 없는 이유를 든 표지로 나온다. 같은 파일에 단건 읽기는 그대로 `PluginError`다. **이 비대칭이 의도라는 것을 테스트가 고정한다** — 문서에만 두면 다음 사람이 일관성 결함으로 보고 고친다
- [x] **표지 둘**(매니페스트, 트레이스)의 이름이 `CONTEXT.md`에 자리를 얻는다. API와 화면과 테스트 이름에서 실제로 불릴 말이므로 작명은 domain-modeling 스킬이 한다
- [x] `TraceStore.list(*, status, limit, after)`가 트레이스 전체가 아니라 **실행 요약**을 돌려준다. 키워드 전용이고 셋 다 선택이다
- [x] 실행 요약의 필드는 일곱이다. 실행 식별자, 실행 상태, 트레이스 형식 버전, 시작 시각, 마지막 시각, 에이전트 이름, 주체. 프롬프트·토큰 수·출력·이벤트는 없다
- [x] 실행 상태는 값 넷이고 어디에도 저장하지 않는다. 마지막 이벤트가 `run_paused`·`run_finished`·`run_failed`이면 각각이고 그 밖은 결말 없음이다. **마지막 이벤트가 모르는 종류여도 결말 없음이다.** 와이어 값 넷은 ADR 0012가 정했다
- [x] 상태 파생 규칙과 요약 타입이 `core`에 한 곳으로 산다. 관리와 채널과 CLI가 각자 다시 구현할 자리를 만들지 않는다
- [x] 목록이 시작 시각 역순이고 동률은 실행 식별자로 갈린다. `after`가 그 정렬 키 그대로의 커서이고 오프셋이 아니다
- [x] `status`가 그 상태의 실행만 남기고 `limit`이 개수를 자른다. **`limit`의 기본값과 상한 숫자를 이 티켓이 정한다.** 상한이 있어야 하는 이유는 첫 어댑터가 디렉터리를 훑어 전부 만든 뒤 자르기 때문이다
- [x] **목록 하나가 모든 실행의 모든 이벤트를 메모리에 올리지 않는다.** 요약의 상태와 마지막 시각이 마지막 이벤트에서 오므로 단건 읽기를 그대로 재사용하면 파일마다 전부 파싱하게 되고, `limit`은 그 뒤에 자르므로 도움이 되지 않는다. 명세가 받아들인 것은 "전부 만든 뒤 자른다"이지 "전부 파싱한다"가 아니다(PR 직전 보안·성능 축)
- [x] **플러그인 이름과 실행 식별자의 문자 집합을 이 티켓이 정한다.** 이름은 `sdk`가 매니페스트에 이미 거는 패턴 그대로이고, 실행 식별자는 `Clock`이 내는 형식을 담는 같은 성격의 안전한 집합이다. 라우트가 아니라 여기서 정하는 이유는 04·06이 경로 파라미터로 걸기 전에 **이 티켓과 05가 이미 그 식별자를 내보내기** 때문이다. 나중에 조이는 것은 파괴적 변경이다
- [x] 목록과 표지가 내는 실행 식별자가 그 패턴을 만족한다. **그 패턴을 만족하지 않는 이름의 파일을 목록이 어떻게 다루는지도 이 티켓이 정한다** — 런타임이 만들 수 없는 이름이므로 표지로 낼지 목록에서 뺄지가 갈린다
- [x] 형식 1로 쓰인 트레이스도 목록에 나오고 요약이 형식 버전 1을 싣는다. 읽기는 되고 재개만 안 된다
- [x] **읽을 수 없는 트레이스 파일이 실행 식별자와 이유를 든 표지로 목록에 남는다**(ADR 0012의 2026-09-22 이력). 헤더가 깨진 것, 줄이 잘린 것, 빈 파일이 `/traces` 전체를 죽이지 않는다
- [x] **같은 손상 파일을 단건으로 읽으면 `PluginError`다.** 지금은 pydantic 검증 오류가 그대로 올라와 채널의 `except PluginError`를 지나친다. `.claude/rules/core.md`가 이미 "재개할 수 없는 트레이스(없음, 형식 1, 일시정지 아님, 손상)도 같은 자리의 `PluginError`"라고 적었으므로 규칙의 문언을 코드에 맞추는 일을 겸한다
- [x] `.claude/rules/core.md`의 포트 표와 `adapters.md`의 어댑터 목록이 **같은 티켓에서** 목록 메서드를 알게 된다. 포트는 여전히 다섯이다. 코드만 고치고 규칙을 남겨 두면 다음 실행이 틀린 것을 읽는다
- [x] `pyproject.toml`이 `tech.md` 스택 표에 맞는다. 런타임에 `fastapi`·`uvicorn`, dev에 `httpx`. 런타임 의존성이 넷에서 여섯이 된다. 전이 의존에 기댄 테스트는 그 경로가 바뀌는 날 조용히 깨진다
- [x] **의존성 셋이 들어와도 원칙 III를 지킨다.** `Any`·`cast`·`ignore`는 pyright strict도 지금의 ruff select도 잡지 않으므로 그 판정은 검사 넷이 아니라 리뷰다. 타입 우회가 필요해 보이면 고치지 말고 멈춰 보고한다
- [x] 가짜 포트가 상속 없이 시그니처로 만족하고 픽스처가 포트 타입으로 annotate한다. 그 한 줄이 포트 적합성이 검증되는 자리다
- [x] 검사 넷이 초록이다
