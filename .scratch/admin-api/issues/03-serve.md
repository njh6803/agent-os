# 03: `agent-os serve` — 한 명령으로 띄운다

**What to build:** 운영자가 `agent-os serve`를 치면 관리 API가 루프백에 선다. 배포 스크립트도 별도 진입점도 먼저 배우지 않는다. 토큰을 안 넣었으면 401을 보는 것이 아니라 **서버가 아예 뜨지 않고** 진단을 받는다. 루프백이 아닌 주소를 주어도 뜨지 않는다. 플러그인 디렉터리와 트레이스 디렉터리를 명령줄로 지정해 작업 디렉터리에 묶이지 않는다.

구성 오류를 요청 시점이 아니라 시작 자리에서 끝내는 것이 이 티켓의 내용이다(ADR 0011). 실행 식별자가 생기기 전이라 트레이스가 없는 `PluginError` 계열과 같은 성격이다. 실제로 uvicorn이 포트를 여는 것은 이 스위트가 증명하지 않는다 — 가짜로 증명할 수 없는 주장이 조립 세 줄과 서드파티의 동작뿐이고, `interrupts`가 바깥 이음매를 둔 이유("일시정지가 프로세스보다 오래 산다"는 그 기능의 존재 이유였다)가 여기에는 없다. 필요가 증명되면 그때 티켓 하나로 더한다.

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] `serve`가 `--host`·`--port`·`--traces`·`--plugins-root`를 받고 `--host`의 기본이 `127.0.0.1`이다. 비밀만 환경변수다
- [ ] `AGENT_OS_ADMIN_TOKEN`이 없거나 빈 문자열이면 진단을 내고 실패 종료 코드로 끝난다. 서버가 뜨지 않는다. 운영자가 토큰 없는 서버를 띄워 놓고 401만 보게 되는 것을 막는다
- [ ] 루프백(`127.0.0.1`, `::1`)이 아닌 `--host`는 진단을 내고 실패 종료 코드로 끝난다. 그때까지 원격 접근의 답이 SSH 포트 포워딩이라는 것이 진단이나 문서에 있다
- [ ] 구성 오류 테스트들이 포트를 열지 않는다. 서버가 서기 전에 끝나기 때문이다
- [ ] 진단에 토큰이 실리지 않는다
- [ ] `--plugins-root`가 생기면서 `main.py`에 하드코딩된 `PLUGINS_ROOT`가 `run`·`resume`에서도 풀린다. 셋이 같은 인자를 받는다
- [ ] 설정 파일(`agent-os.toml`)을 만들지 않는다. 새 디스크 형식이라 `schema_version`과 ADR이 또 필요한데 지금 값이 넷뿐이다
- [ ] 검사 넷이 초록이다
