# 05: `/traces` — 지나간 실행과 멈춘 실행의 목록

**What to build:** 무엇이 돌았는지 기억과 스크롤백에 의존하지 않게 된다. 최근 실행이 먼저 오고, 행마다 어떤 에이전트의 것이고 누가 요청했고 언제 시작해 언제 마지막으로 움직였는지가 보인다. 승인자에게는 `?status=paused`가 곧 멈춘 실행 목록이다 — `interrupts` 명세가 Out of Scope로 두고 여기로 넘긴 "멈춘 실행 목록 조회"가 이 질의 하나로 닫힌다. 거기서 얻은 실행 식별자를 그대로 `agent-os resume`에 넘긴다.

멈춘 실행에 별도 경로를 만들지 않는다. 상태는 요약의 한 필드이지 다른 자원이 아니고, `/traces/paused`를 두면 `/traces/{run_id}`와 경로가 겹쳐 `paused`라는 실행 식별자가 생길 수 없게 되며 상태가 늘 때마다 경로가 는다. 페이지네이션이 처음부터 계약에 있는 이유는 나중에 더하는 것이 파괴적 변경이고 슬라이스 3의 클라이언트가 `openapi.json`에서 생성되기 때문이다.

**Blocked by:** 02 (포트의 `list`와 식별자 패턴은 01이 정하고, 02가 이미 01에 막혀 있다)

**Status:** done

- [x] `GET /traces`가 실행 요약의 목록과 다음 커서를 돌려준다. 요약의 필드는 일곱이고 프롬프트도 토큰 수도 없다. 목록은 개요를 보는 자리이지 내용을 읽는 자리가 아니다
- [x] 최근 실행이 먼저 온다. 일시정지·끝남·실패·결말 없음이 목록에서 갈린다. 스크립트가 셋을 같게 다루면 멈춘 실행을 잃어버린다
- [x] 끝 이벤트가 없는 실행을 "진행 중"이라 부르지 않는다. 지금 돌고 있는 실행과 프로세스가 죽어 사라진 실행이 파일 위에서 똑같이 보이기 때문이다
- [x] 오래 멈춰 있는 실행을 마지막 시각으로 알아본다. 만료가 없으므로 방치를 알아볼 길이 그것뿐이다
- [x] 형식 1 실행도 목록에 나오고 요약이 형식 버전을 실어 화면이 "이 실행은 재개할 수 없다"를 말할 수 있다
- [x] 읽을 수 없는 트레이스가 있어도 나머지가 돌아오고 그것은 표지로 나온다
- [x] `status`·`limit`·`after`가 포트에 그대로 전달된다. 셋 다 선택이고 `status`가 없으면 전부다
- [x] `?status=paused`가 멈춘 실행만 돌려준다. `/traces/paused` 같은 경로는 없다
- [x] 잘못된 `status`, 음수이거나 상한을 넘는 `limit`이 422다. 상한의 숫자는 01이 정했다
- [x] **다음 커서 문자열의 모양을 이 티켓이 정한다.** `openapi.json`에 박힌다
- [x] **형식에 맞지 않는 `after`는 422다.** 포트에 닿기 전에 끝난다. 04·06이 경로 파라미터에 거는 것과 같은 종류의 검증이고, 없으면 조작된 커서가 처리되지 않은 500이 된다(PR 직전 보안·성능 축)
- [x] **커서가 잡지 못하는 경우 하나를 이 티켓이 확인한다.** 정렬 키가 `started_at` 이므로, 이미 지나간 페이지의 시각 범위에 속하는 실행의 파일이 그 뒤에 디스크에 나타나면 `after` 필터에 걸리지 않고 영구히 누락된다. 오프셋 드리프트와 다른 종류이고 쓰기 순서가 아니라 시작 시각으로 정렬하는 결정(ADR 0012)의 결과다. 단일 프로세스 전제에서 실제로 일어나는지 보고, 일어난다면 알려진 한계로 ADR 0012 이력에 쌓을지 정한다(티켓 01의 PR 직전 성능 축이 보류로 올렸다)
- [x] 커서가 오프셋이 아니다. **페이지 사이에 새 실행이 생겨도** 같은 항목이 두 번 오거나 건너뛰이지 않는다. 오프셋과 커서를 가르는 성질이 그것이므로 정적 디렉터리만으로는 재지 못한다
- [x] 응답의 실행 식별자가 01이 정한 패턴을 만족한다. 그래서 그대로 `agent-os resume`에도 `/traces/{run_id}`에도 넘길 수 있다. 관리와 채널이 같은 실행을 가리킨다
- [x] `openapi.json`이 이 라우트를 알고 최신성 테스트가 초록이다
- [x] 검사 넷이 초록이다
