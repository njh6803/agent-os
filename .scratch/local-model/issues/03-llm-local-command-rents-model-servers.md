# 03: 모델 서버를 띄우는 명령 — `tools/llm_local.py run`이 비용을 확인받고 Runpod에 모델 서버 둘을 띄워 시험을 돌린 뒤 지운다

**What to build:** 이 저장소를 고치는 세션이 워크트리에서 `uv run --env-file ../../../.env python tools/llm_local.py run`을 치면 GPU 후보마다 예상 비용(어림 30분과 타이머까지 간 최악 90분)만 찍고 아무것도 띄우지 않은 채 끝난다. 세션이 그 출력을 사용자에게 보여 확인을 받고 `--yes`를 붙여 다시 치면, 명령이 서버 키를 만들고, Terraform으로 Runpod에 모델 서버 둘(A.X 4.0 Light와 gpt-oss-20b)을 90분 뒤 스스로 지워지게 걸린 채로 띄우고, 두 서버가 준비되기를 기다리고, `--` 뒤의 명령(기본 `uv run pytest -m llm_local`)을 두 서버의 주소와 모델 이름과 키를 환경 변수 여섯에 채워 자식 프로세스로 돌리고, 시험이 어떻게 끝났든 Ctrl-C로 끊겼든 서버를 지운 뒤, PR 코멘트와 일지에 옮길 기록 묶음을 찍는다. 종료 코드는 시험 통과(0), 시험 실패(1), 무효 회차(2), 지우기 실패(3), 아무것도 띄우지 않고 끝남(4)으로 갈린다. `sweep`은 앞 세션과 버려진 브랜치가 남긴 서버와 상태 파일을 치운다. 요금을 내는 사용자는 띄우기 전에 비용을 확인하고(스토리 21), 명령이나 세션이 죽어도 서버가 계속 요금을 내지 않으며(스토리 22), 나란히 도는 세션이 서로의 서버를 지우지 않는다(스토리 23). 서버 키와 `RUNPOD_API_KEY`의 값은 화면, 로그, 기록 묶음, 저장소 어디에도 찍히지 않고 세션도 보지 않는다.

이 기능의 시험 인프라 티켓이다. 계약에 기대지 않고 `tools/`의 새 파일에 서서 01·02·04와 나란히 돈다. 05가 이 명령으로 로컬 모델 시험을 두 모델로 통과해야 병합하므로 이 티켓이 05를 막는다. 이 티켓만 병합된 개발 브랜치에는 마커 `llm_local`과 로컬 모델 시험이 아직 없다(05가 더한다). 그래서 이 티켓이 실제로 띄워 확인할 때는 `--` 뒤에 도구 호출을 확인하는 프로브를 넣는다. 이 티켓의 PR에는 로컬 모델 시험의 조건이 붙지 않는다. 돌릴 시험이 아직 없기 때문이다(ADR 0058 결정 "첫 적용").

명세의 이 절은 문서의 원문과 이 PC에서 본 것으로 정했고 클라우드에서 돌려 보지 않았다. 실제로 띄워 확인하는 것은 이 티켓의 일이다(ADR 0058 Consequences "서버를 띄우는 파일을 들이는 티켓이 띄워 확인하는 것"). 미리 적은 구성이 모두 서지 않으면 멈춰 사용자에게 다시 묻는다.

근거는 `.scratch/local-model/spec.md`의 "모델 서버를 띄우는 명령"과 그 2026-11-12 주석, "로컬 모델 시험"의 환경 변수 항목과 그 주석, "규약 문서"의 주석 둘째, "고칠 자리의 묶음"의 C 줄과 그 주석, Testing Decisions의 "모델 서버를 띄우는 명령(C)"과 그 주석, Further Notes 셋이다. 측정은 `.scratch/local-model/probes/outside_worktree.py`(워크트리 밖 쓰기와 `.env`를 넘기는 명령)와 그 `README.md`이고 다시 돌리지 않는다. 앞선 결정은 ADR 0058의 결정 "시험은 두 층이다"부터 "띄우지 못할 때"까지와 "명세로 넘기는 것", Consequences "비밀"·"서버를 띄우는 파일을 들이는 티켓이 띄워 확인하는 것"이다. 프로세스 번호의 판정은 `.claude/rules/probes.md`의 프로세스를 끄는 탐침 항목과 `tools/proc_command_line.py`가 선례이고, 지우는 도구의 반박과 외부 명령의 시간 제한은 `.claude/rules/tools.md`다. 사용자의 준비를 먼저 보고 모자라면 멈추는 선례는 base-agent 07의 첫 수락이다(`.scratch/base-agent/issues/07-real-rag-engine-image-once.md`).

### 자리와 하위 명령

- [ ] 스크립트는 `tools/llm_local.py`이고 Terraform 구성은 그 옆 폴더 `tools/llm_local_server/`다. 둘 다 로컬 모델 시험 자신으로 세어 병합 조건의 범위에 든다(ADR 0058 결정 "병합 조건의 범위")
- [ ] 하위 명령은 `run`과 `sweep`이다. `run`은 `--yes` 없이 치면 예상 비용만 찍고 끝나고, `--` 뒤에 서버가 떠 있는 동안 돌릴 명령을 받으며 기본은 `uv run pytest -m llm_local`이다
- [ ] 로컬 모델 시험이 받는 환경 변수 여섯(`AGENT_OS_LLM_LOCAL_<n>_BASE_URL`, `AGENT_OS_LLM_LOCAL_<n>_MODEL_ID`, `AGENT_OS_LLM_LOCAL_<n>_API_KEY`, `<n>`은 1과 2)의 이름은 이 스크립트의 상수 한 자리에 둔다. 05의 로컬 모델 시험이 그 상수를 import해 읽는다(선례 `tests/conftest.py`의 `from tools import llm_tokens, run_hooks`)

### 구성, 서버 옵션, 타이머

- [ ] 구성은 차례로 셋이고 첫째가 기본이다. 첫째는 모델마다 파드 하나씩을 한 번의 `terraform apply`로 나란히 띄우는 것이고 GPU 후보는 RTX A5000, RTX 3090, A40(48GB)의 차례다(재고가 없으면 다음 후보). 둘째는 A40 한 장의 파드 하나에 서버 둘을 `--gpu-memory-utilization`으로 반씩 띄우는 것, 셋째는 파드 하나에 모델을 차례로 올리는 것이다. 이미지는 vLLM 공식 이미지 0.33.0 판이고, 프로바이더 `runpod/runpod`의 판(2.0.0)은 구성에 글자 그대로 묶는다
- [ ] 이 티켓은 첫째와 둘째 구성만 짓는다. 셋째는 파드 하나가 모델 하나만 올리므로 준비를 기다리고, 시험하고, 지우는 것이 모델마다 한 번씩이다. 그러면 걸음 9가 환경 변수 여섯을 한 자식 프로세스에 함께 넘기는 것, 05의 환경 검사가 두 모델의 필수 변수를 모두 요구하는 것, 06이 두 모델을 pytest 한 번으로 돌리는 것이 모두 맞지 않는다. 그 셋을 어떻게 바꿀지는 명세가 정하지 않았다. 그래서 첫째와 둘째가 모두 서지 않아 셋째로 가야 하면 띄우지 않고 멈춰 사용자에게 시험을 어떻게 나눌지 묻는다
- [ ] 파드는 포트 `8000/http` 하나만 열고 영구 볼륨 없이 컨테이너 디스크만 쓴다. 주소는 Runpod의 프록시 주소 `https://<파드 ID>-8000.proxy.runpod.net/v1`의 꼴이다
- [ ] 두 서버 모두 `--api-key`(명령이 만든 서버 키)와 `--enable-auto-tool-choice`를 받고, 파서는 A.X 4.0 Light(`skt/A.X-4.0-Light`)가 `--tool-call-parser hermes`, gpt-oss-20b(`openai/gpt-oss-20b`)가 `--tool-call-parser openai`다. 서버에 준 옵션은 키를 뺀 글자 그대로 기록 묶음에 남는다
- [ ] 파드는 서버를 띄우기 전에 건 타이머와 함께 뜨고, 타이머는 90분 뒤 그 파드를 멈추지 않고 지운다. 거는 방법은 차례로 둘이다. 공식 이미지의 시작 명령을 셸로 바꿔 지우는 명령을 백그라운드로 거는 것(`runpodctl`이 없으면 REST의 `DELETE /v2/pods/<파드 ID>`), 셸로 시작하는 Runpod의 기본 이미지에 같은 판의 vLLM을 설치하는 것이다. 둘 다 서지 않으면 띄우지 않고 멈춰 사용자에게 묻는다. 스스로 지워지게 걸리지 않은 구성으로는 띄우지 않는다
- [ ] 타이머가 지우는 호출의 자격은 Runpod가 파드에 주입하는 키다(명세 "모델 서버를 띄우는 명령"의 타이머 문단, "파드에 주입된 키로 부른다"). 명령이 쥔 계정 키 `RUNPOD_API_KEY`는 파드의 시작 명령에도 환경에도 넣지 않는다. 넣으면 그 값이 상태 파일에 평문으로 남고(아래 항목) 파드 안의 서버 프로세스도 본다. 주입된 키로 그 파드가 지워지는지는 아래 "띄워 확인하는 것"에서 본다. 지워지지 않으면 스스로 지워지게 걸리지 않은 구성이므로 띄우지 않고 멈춰 사용자에게 묻는다
- [ ] 서버 키를 받는 Terraform 변수는 `sensitive = true`로 둔다. `sensitive`는 화면의 출력만 가리고, 그 값을 받은 자원의 칸(파드의 시작 명령)은 상태 파일에 평문으로 남는다(Terraform 문서 "Sensitive data in state"의 웹 요약, `https://developer.hashicorp.com/terraform/language/state/sensitive-data`). 그래서 상태 폴더는 저장소 밖에 두고(걸음 1~4) 세션은 그 안의 상태 파일을 읽지 않는다. 지우기가 성공한 회차는 상태 폴더에 서버 키 값이 든 파일이 남지 않게 한다. 지운 뒤의 상태에는 자원이 없지만, 상태 파일의 백업은 지우기 전의 상태를 담으므로 지운다. 지우기가 실패한 회차의 상태는 `sweep`이 지울 때까지 그대로 둔다

### `run`의 걸음

- [ ] 걸음 1~4. 환경(`RUNPOD_API_KEY`의 이름, Terraform 1.6 이상, 분리 HEAD가 아닌 브랜치)을 보고 없는 것을 이름으로 들어 끝난다. 상태 폴더는 사용자 홈 아래 `.agent-os/llm-local/<브랜치 이름>/`이고(브랜치 이름의 `/`는 폴더 이름에 쓸 수 있는 글자로 바꾼다) Terraform의 상태 파일과 작업 폴더(`TF_DATA_DIR`)가 그 안에 선다. 잠금 파일은 상태 폴더 밖, 같은 뿌리 바로 아래의 `<폴더 이름>.lock`이다(`sweep`이 폴더를 지우는 동안에도 잠금이 남게 하려는 것이다). 그 파일은 그 폴더를 쓰는 `run`의 프로세스 번호와 시작 시각을 들고, 번호의 프로세스가 살아 있고 그 명령줄이 이 스크립트의 `run`일 때만 산 잠금이다(번호만 보지 않는다). 산 잠금이면 아무것도 건드리지 않고 끝난다. 잠금은 배타적 생성(`os.open`의 `O_CREAT | O_EXCL`)으로 얻어, 같은 폴더에서 두 `run`이 동시에 시작해도 하나만 얻고 다른 하나는 산 잠금을 만난 것으로 끝난다. 죽은 잠금의 판정과 제거와 새로 얻기는 `<폴더 이름>.guard` 파일에 건 OS의 배타적 파일 잠금(윈도 `msvcrt.locking`, 리눅스 `fcntl.flock`) 안에서 한다. 이 파일은 지우지 않고, 프로세스가 끝나면 OS가 풀어 주므로 죽은 것인지 판정할 필요가 없다. 그 안에서 잠금 파일을 다시 읽어 판정한 뒤에만 지우고 새로 얻으므로, 먼저 판정한 쪽이 앞선 판정을 근거로 다른 프로세스가 새로 얻은 산 잠금을 지우지 않는다. 이 파일 잠금이 이미 잡혀 있으면 기다리지 않고 산 잠금을 만난 것으로 끝난다. 죽은 잠금 아래 상태 파일에 자원이 남아 있으면 비용 확인을 기다리지 않고 `terraform destroy`로 먼저 지운다
- [ ] 걸음 5~8. GPU 후보마다 단가, 파드 수, 30분과 90분의 값을 찍고 단가 표에 옮긴 날짜를 적는다. `--yes`가 없으면 여기서 끝난다. 서버 키는 무작위 값이고 Terraform에는 `TF_VAR_…`로, 시험에는 `AGENT_OS_LLM_LOCAL_<n>_API_KEY`로 넘기며 화면에도 로그에도 파일에도 찍지 않는다. 재고가 없어 실패하면 다음 GPU 후보로 가고, 띄운 뒤 Terraform이 돌려준 시간당 값(`cost`)의 합이 예상에 쓴 단가의 합보다 크면 지우고 끝난다. 준비는 두 서버의 `GET <주소>/models`(키 헤더를 싣는다)가 200으로 그 모델을 낼 때까지 기다리고 상한은 30분이다
- [ ] 걸음 9. 시험을 자식 프로세스로 돌리며 환경 변수 여섯을 채워 넘긴다. 자식의 환경에서는 `RUNPOD_API_KEY`를 뺀다. 시험은 그 키를 쓰지 않고, 세션이 `--` 뒤에 넣는 명령에 클라우드 계정의 키를 넘길 까닭이 없다. 자식의 환경에 `PYTEST_ADDOPTS`로 `--junitxml=<상태 폴더 안의 파일>`과 `--basetemp=<상태 폴더 안의 폴더>`를 넣는다. 자식이 pytest면 통과 수는 그 JUnit XML에서, 토큰 합계는 그 basetemp를 `tools/llm_tokens.py`의 `count`로 세어 얻는다. 자식이 pytest가 아니어서 XML이 없으면 통과 수와 토큰 합계는 "없음"이고 판정은 자식의 종료 코드다
- [ ] 걸음 10~12. 시험이 실패했으면 지우기 전에 두 서버의 모델 목록을 한 번 더 본다. 시험이 어떻게 끝났든 Ctrl-C로 끊겨도 지우고, 지우기가 실패하면 상태 폴더의 경로와 함께 크게 알린다. 기록 묶음은 시험한 커밋, 두 모델의 이름, 서빙 엔진의 판과 서버 옵션, GPU의 종류, 통과 수와 토큰 합계, 걸린 시간, 실제 단가, Terraform 출력에서 가린 것이 있었는지(참·거짓)다. 서버 키와 주소는 넣지 않는다. 기록 묶음은 찍는 것과 함께 상태 폴더에 회차마다 파일 하나로도 남기고, 그 파일에는 종료 코드와 무효 회차의 까닭도 든다. `sweep`이 그 폴더를 지우기 전까지 남아, 비용을 내고 돌린 뒤 일지와 PR 코멘트에 옮기기 전에 끊긴 세션을 이어받은 세션이 다시 빌리지 않고 기록을 읽으며, 연달은 무효 회차도 그 파일들로 센다
- [ ] Terraform의 표준 출력과 표준 오류(plan, apply, destroy, 오류 글)는 받아 두었다가 세션에 옮기기 전에 서버 키 값을 글자 그대로 찾아 `***`로 바꾸고, 받은 그대로를 파일에 쓰지 않는다
- [ ] 종료 코드는 0(통과), 1(서버가 살아 있던 회차의 시험 실패), 2(무효 회차. 시험이 실패했는데 걸음 10의 확인에서 서버가 살아 있지 않은 회차, 띄운 뒤 끊긴 회차, GPU 후보 셋 모두 재고 없음), 3(지우기 실패, 걸음 4의 지우기 실패), 4(띄우기를 시작하기 전에 끝남)이고 겹치면 3, 2, 1의 차례다. 시간 제한에 걸린 시험은 실패한 시험으로 보고 걸음 10의 확인을 거친다. 띄우기를 시작한 뒤 끊긴 회차는 지운 뒤 2이고, 그 전에 끊긴 회차는 4다. `sweep`은 0(남은 것이 없다)과 3(지우지 못한 것이 있다)을 낸다. 세부는 명세의 "종료 코드는 다섯으로 가른다" 문단 그대로다
- [ ] 걸음마다 부르는 외부 명령(terraform, git, 시험)에는 시간 제한을 둔다(`.claude/rules/tools.md`, `tools/check_instructions.py`가 시간 제한 없는 호출을 잡는다)

### 청소

- [ ] `sweep`은 `.agent-os/llm-local/` 바로 아래를 훑어 죽은 잠금의 폴더마다 남은 자원을 `terraform destroy`로 지우고, 자원이 없음을 확인한 폴더를 지운다. 살아 있는 잠금의 폴더는 건드리지 않고, 이 스크립트가 심은 표지 파일이 있는 폴더만 지우며, 링크는 따라가지 않는다. 죽은 잠금이라고 판정한 폴더는 걸음 1~4와 같은 방법(`.guard` 안에서 다시 판정하고 배타적 생성으로 잠금을 얻는다)으로 그 잠금을 얻은 뒤에만 지운다. 판정한 뒤 지우기 전에 `run`이 잠금을 얻었으면 그 폴더는 건드리지 않는다. 잠금 파일은 폴더 밖이라 `sweep`이 폴더를 지우는 동안에도 쥐고 있고, 폴더를 다 지운 뒤 마지막에 지운다. 그 사이에 `run`이 같은 폴더에서 잠금을 얻으려 하면 산 잠금을 만나 끝난다
- [ ] 타이머가 이미 지운 파드를 `terraform destroy`가 넘기지 못하면 `terraform apply -refresh-only`로 상태를 실제와 맞춘 뒤 다시 지우고, 그래도 남으면 사람에게 넘긴다

### 시험 (클라우드 없이)

- [ ] 시험은 `tests/tools/`에 선다. 외부 명령(terraform, git, 시험)은 스크립트의 한 함수를 지나고 시험이 그 함수를 가짜로 바꿔 끼운다. CI의 리눅스에서도 돌므로 윈도에만 있는 것에 기대지 않는다(`.claude/rules/tests.md`)
- [ ] 명세 Testing Decisions의 "모델 서버를 띄우는 명령(C)" 사례를 모두 덮는다. 모자란 환경(이름만 들고 4), `--yes` 없는 `run`이 `terraform apply`를 부르지 않고 예상 비용을 찍고 4로 끝나는 것, 예상 비용의 셈, 상태 폴더 이름(브랜치 이름의 `/`), 잠금의 판정(산 프로세스와 그 명령줄, 죽은 번호, 다른 프로세스가 받은 번호), 죽은 잠금 아래 자원을 띄우기 전에 destroy하는 것, 시험이 실패하든 Ctrl-C로 끊기든 destroy를 부르는 것, 무효 회차의 가름과 종료 코드, 겹칠 때의 차례(시험 실패와 지우기 실패는 3, GPU 후보 셋 모두 재고 없음은 2), 죽은 잠금 아래 자원을 지운 뒤 `--yes` 없이 끝난 4, 실패하거나 시간 제한에 걸린 시험이 걸음 10의 확인으로 1이나 2로 갈리는 것, 띄운 뒤 끊긴 2와 띄우기 전에 끊긴 4, 기록 묶음에 서버 키와 주소가 없는 것, 같은 폴더에서 두 `run`이 동시에 시작하면 하나만 잠금을 얻고 다른 하나는 4로 끝나는 것, `sweep`이 죽은 잠금을 판정한 뒤 `run`이 잠금을 얻으면 `sweep`이 그 폴더를 건드리지 않는 것, 두 프로세스가 같은 죽은 잠금을 판정했을 때 한쪽이 치우고 새로 얻은 뒤 다른 쪽이 앞선 판정으로 지우려 해도 산 잠금이 남는 것(`.guard` 안에서 다시 판정), `sweep`이 폴더를 지우는 동안 `run`이 그 폴더에서 잠금을 얻지 못하는 것이다
- [ ] 명세 검토와 셀프 리뷰가 더한 것을 덮는다. 자식 프로세스에 넘긴 환경에 이름 여섯과 서버 키가 들었고 `RUNPOD_API_KEY`는 없다. 기록 묶음에 위 칸이 모두 있고(스토리 24), 상태 폴더의 회차 파일에 같은 묶음과 종료 코드가 남으며 서버 키와 주소가 없다. 가짜 terraform이 받은 키를 표준 출력과 표준 오류에 되울려도 `run`의 전체 출력과 기록 묶음에 그 값이 없고, 가린 것이 있었다는 칸이 참이다. 가짜 terraform이 받은 키를 상태 파일과 그 백업에 써도, 지우기가 성공한 회차가 끝나면 상태 폴더의 어느 파일에도 그 값이 없다. Terraform 구성을 읽어, 파드 자원의 시작 명령과 환경에 계정 키를 싣는 변수가 없는 것을 본다
- [ ] 실제 pytest 자식 하나를 `PYTEST_ADDOPTS`를 넣어 돌려 JUnit XML과 basetemp가 상태 폴더 안의 두 자리에 생기고, 거기서 통과 수와 토큰 합계를 얻는 것을 본다. pytest가 그 변수를 명령줄 앞에 붙여 읽는다는 것은 명세의 일반 지식이고 재지 않았다
- [ ] `sweep`이 지우는 길을 판정을 깨려는 입력(표지 없는 폴더, 뿌리 밖을 가리키는 링크, 살아 있는 잠금)으로 반박하는 사례를 두고, 커밋 전에 임시 폴더에서 손으로도 반박해 본다(`.claude/rules/tools.md`)

### 띄워 확인하는 것

- [ ] 띄울 때마다 `--yes` 없이 친 출력을 사용자에게 보여 비용 확인을 받는다. 확인 없이 `--yes`를 치지 않는다
- [ ] 명세 "띄워 확인하는 것"과 ADR 0058 "돌려 보지 않은 것"에서 남은 것을 실제로 띄워 본다. 구성 1이 서는지(파드 둘, 두 모델이 뜬다), 타이머의 두 방법 가운데 어느 것이 서는지와 타이머가 실제로 파드를 지우는지(Runpod가 주입한 키로 지워지는지), 타이머가 지운 뒤의 `terraform destroy`, 지우기가 성공한 뒤 상태 폴더에서 서버 키 값이 든 파일의 수(값은 찍지 않고 수만 센다)가 0인지, 두 모델이 도구가 든 요청에 `tool_calls`로 답하는지, 띄우기부터 준비까지의 시간, 프록시 주소의 꼴, Terraform이 돌려준 `cost`와 가격 페이지의 단가가 같은지, 응답의 모델 이름, 실제 apply·destroy 출력에서 가린 것이 있었는지다
- [ ] 도구 호출의 확인은 `--` 뒤에 넣는 프로브로 재고 `.scratch/local-model/probes/`에 커밋한다. 결과는 그 `README.md`에 날짜 절로 적는다
- [ ] 결과가 명세의 구성이나 값과 다르면 명세의 그 절에 날짜를 단 주석으로 적는다. 준비 상한 30분은 잰 준비 시간으로 다시 맞춘다. 도구 호출이 되지 않는 모델은 같은 기준의 다음 후보(A.X 3.1 Light, Ministral 3 8B)로 바꾸고 까닭을 일지에 적는다. ADR 0058 본문의 문장을 거짓으로 만들면 그 ADR의 이력 초안을 쓰고 셀프 리뷰를 반영한 뒤 사용자의 승인을 받는다(작업 규약 5)
- [ ] 띄운 회차의 기록 묶음과 무효 회차의 까닭을 명령이 끝난 그 턴에 일지에 옮기고 PR 코멘트에도 옮긴다. 옮기기 전에 끊겼으면 이어받은 세션이 상태 폴더의 회차 파일에서 옮긴다
