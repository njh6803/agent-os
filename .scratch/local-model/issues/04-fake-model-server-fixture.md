# 04: 가짜 모델 서버 — 시험이 루프백에 Chat Completions를 흉내 내는 서버를 띄우고 받은 요청과 연결의 수를 읽는다

**What to build:** 시험이 실제 모델 서버 없이 시험 프로세스 안의 스레드로 루프백의 빈 포트에 가짜 모델 서버를 띄우고, 띄운 쪽이 쥔 핸들로 끈다. 서버는 받은 요청마다 메서드, 경로, 헤더, 본문을 차례로 적고, 시험이 차례로 정한 응답을 돌려주며, 받은 연결과 처리를 마친 연결의 수를 센다. 흉내 내는 것은 Chat Completions 하나다. 시험은 응답을 상태 코드와 본문(JSON이거나 JSON이 아닌 날 글자)으로 정하고, 받은 요청을 보고 응답을 짓는 함수와 답하기 전에 기다릴 시간도 정할 수 있다. 같은 프로세스의 시험도, 시험이 자식 프로세스로 띄운 CLI도 그 주소로 붙는다.

01과 나란히 돈다. 계약에도 어댑터에도 기대지 않고 `tests/adapters/`의 새 파일에 선다. 쓰는 곳은 05에서 생긴다. 05의 어댑터 시험(요청, 응답, 실패, 수명과 취소, 로그)과 CLI 시험(calc의 평소 시험, 인자가 깨진 도구 호출)이 이 픽스처에 붙는다. 이 티켓에는 `langchain-openai`가 아직 없어(05가 들인다) 픽스처 자신의 시험은 보통의 HTTP 클라이언트로 민다. 명세는 이 픽스처를 묶음 D에 두었는데 to-tickets에서 사용자가 여섯 장 분할을 골라 따로 뗐다. 그래서 05의 사례가 기대는 이음매를 이 티켓이 미리 갖춘다. 명세 Testing Decisions의 어댑터(D)·CLI(D) 사례가 픽스처에 바라는 능력을 이 티켓이 모두 갖춘다. 짓는 세션은 그 사례를 하나씩 읽어 각 사례가 픽스처에 무엇을 바라는지 대 본다. 아래는 그 예이고 전부가 아니다. 받은 키를 되울리는 401(응답이 받은 요청에 달린다), 요청을 받은 뒤 환경의 키 값을 바꾸고 옛 키를 되울리는 401(응답을 짓는 함수가 그 자리에서 돈다), 기한에 끊기는 호출(답하기 전에 기다린다), JSON이 아닌 200 본문(날 글자), 환경에 심은 `OPENAI_BASE_URL`이 요청을 바꾸지 않는 사례의 "다른 서버가 받은 요청 0건"(서버 둘을 함께 띄우고 저마다 받은 요청을 따로 읽는다. 프로브는 미끼 서버를 하나 더 띄웠다, `cases_request.py`), 기한에 끊긴 호출의 연결 셈(끊긴 요청의 처리는 기다릴 시간이 끝난 뒤에야 마치므로 그 연결은 그 뒤에야 처리를 마친 것으로 세어진다. 프로브는 1초에 그 지연을 더해 기다렸다, `cases_lifetime.py`)이다. 연결의 수로 "놓인 모델과 실패한 호출의 연결이 남지 않는 것"(명세 "HTTP 클라이언트")을 보려면 서버가 응답마다 연결을 닫지 않아야 한다. 서버가 닫으면 셈이 어느 클라이언트에서나 "모두 닫혔다"가 되어 05의 수명 사례가 퇴행을 가르지 못한다. 그래서 서버는 HTTP/1.1로 답하고, 연결을 닫을지는 클라이언트가 정한다.

근거는 `.scratch/local-model/spec.md`의 Testing Decisions "가짜 모델 서버"와 "사례"의 어댑터(D)·CLI(D) 사례와 그 2026-11-12 주석, "고칠 자리의 묶음"의 주석(04 줄)이다. 선례는 프로브의 가짜 서버 `.scratch/local-model/probes/fake_server.py`이고 옮기지 않고 새로 짓는다. 그 프로브가 무엇을 쟀는지는 `.scratch/local-model/probes/README.md`다. 같은 모양의 시험 픽스처 선례는 원격 MCP 서버 픽스처 `tests/mcp_http.py`와 가짜 문서 검색 서버(`.scratch/base-agent/issues/02-fake-doc-search-server-fixture.md`)다.

### 서버

- [x] 표준 라이브러리의 스레드 서버(`http.server.ThreadingHTTPServer`)로 짓고, 시험 프로세스 안의 스레드로 루프백의 빈 포트에 뜬다. 시험은 그 주소를 모델 파일의 `base_url`(경로 `/v1`까지)로 쓸 수 있다
- [x] 띄운 쪽이 쥔 핸들로 끈다. 끈 뒤에는 그 포트가 닫혀, 05의 "꺼진 서버" 사례가 그 주소를 쓸 수 있다
- [x] 받은 요청마다 메서드, 경로, 헤더, 본문을 받은 차례로 적고 시험이 읽는다
- [x] 응답은 시험이 차례로 정한다. 상태 코드와 본문이고 본문은 JSON이거나 JSON이 아닌 날 글자다. 받은 요청을 보고 응답을 짓는 함수와 답하기 전에 기다릴 시간도 정할 수 있다. Chat Completions의 응답 모양(글, 도구 호출, `usage`, `model`)과 오류 본문을 짓는 도우미를 둔다
- [x] HTTP/1.1로 답해 연결을 닫을지를 클라이언트가 정한다. 받은 연결과 처리를 마친 연결의 수를 센다. 기다릴 시간을 준 응답의 연결은 클라이언트가 먼저 끊어도 그 시간이 끝난 뒤에 처리를 마친 것으로 세어진다는 것을 독스트링에 적는다(05의 기한 사례가 그만큼 더 기다린다)
- [x] 한 시험에서 서버 둘 이상을 함께 띄울 수 있고, 받은 요청과 연결의 셈은 서버마다 따로다
- [x] HTTP 흉내 라이브러리를 시험 의존으로 들이지 않는다. `respx` 같은 HTTP 흉내 라이브러리는 `httpx`를 겨냥하고 openai 3.49.0은 `httpx2`로 보내므로 명세가 거부했다

### 시험

- [x] 이 픽스처를 보통의 HTTP 클라이언트로 띄워 본다. 받은 요청의 메서드·경로·헤더·본문이 적힌 대로이고, 정한 응답이 차례대로 오며, 응답을 짓는 함수가 받은 요청으로 응답을 짓고, 기다릴 시간을 준 응답이 늦게 오고, 날 글자 본문이 그대로 온다
- [x] 연결의 셈을 양쪽으로 본다. 연결을 쥔 채 두 번 부른 클라이언트는 연결 하나로 두 요청을 보내고 닫기 전에는 처리를 마친 연결이 0이며, 그 클라이언트를 닫은 뒤에는 받은 연결과 처리를 마친 연결이 같다. 셈을 단언하기 전에 짧게 기다리되 한 번만 견주지 않고 기한까지 거듭 견준다(`.claude/rules/tests.md`)
- [x] 기다릴 시간을 준 응답을 클라이언트가 그 시간 전에 끊으면, 처리를 마친 연결의 수는 그 시간이 끝난 뒤에 는다
- [x] 서버 둘을 함께 띄워 한쪽에만 요청을 보내면 다른 쪽이 받은 요청은 0건이다
- [x] 띄운 쪽이 핸들로 끈 뒤 그 포트에 붙으면 연결이 거부된다
- [x] 자식 프로세스에서도 그 주소로 요청이 닿는다(05의 CLI 시험이 기대는 모양)
