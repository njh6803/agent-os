# local-model: 바깥 API를 쓸 수 없는 환경에서도 OpenAI 호환 모델 서버로 에이전트를 돌릴 수 있게 한다.
**슬라이스:** 7
**Blocked by:** 없음

모델 공급자에 OpenAI 호환 엔드포인트를 더한다. 바깥 API를 쓸 수 없는 폐쇄망 배포 환경에서는 그 환경의 모델 서버(vLLM처럼 OpenAI 호환 API를 내는 서버)로 실행이 돌아야 한다. 같은 어댑터가 OpenAI 호환 API를 내는 클라우드 엔드포인트와 NPU 서빙 소프트웨어에도 붙는다. 그래서 이 기능은 vLLM 하나에 붙는 일이 아니라, 서빙 엔진과 모델을 같은 자리에서 바꿔 끼우는 경계로 정의한다. GPU 서버가 없는 배포 환경의 구성도 이 경계 위에 선다(일지 2026-11-06-02의 "설계 인터뷰 입력" 절, 모델 배치 구성). 첫 티켓은 계약이다: 닫힌 열거 `ModelProvider`(`sdk/manifest.py`)에 값 하나를 더하는 가산 변경이다(ADR 0040의 Consequences "이번 범위 밖"이 둘째 제공사를 그렇게 적었다). 엔드포인트 주소를 모델 매니페스트의 선택 칸으로 둘지 환경 변수로 둘지는 설계 인터뷰가 정해 ADR 0040의 이력에 적는다. 키는 매니페스트에 두지 않고 환경에서만 읽는다(원칙 V). 새 의존성은 `tech.md`와 ADR을 거친다. 로컬 모델 서버가 필요한 테스트의 표지(예: `-m llm_local`)와 CI에서의 취급도 같은 인터뷰가 정한다. 개발 중에는 시간 단위로 빌린 클라우드 GPU의 vLLM을 시험 엔드포인트로 쓴다(같은 일지 절, GPU 환경). 공개 데모(public-demo)는 Anthropic API를 쓰므로, 막는 기능이 없어도 이 행은 공개 데모 뒤에 한다(ADR 0046의 2026-11-06 이력). 설계 인터뷰가 먼저 볼 것: OpenAI 호환 API라도 도구 호출을 해석하는 방식은 서빙 엔진과 모델 계열마다 다르고, 모델이 도구 호출 형식을 지키지 않으면 실행이 실패한다. 특정 서빙 엔진에만 있는 확장에 얼마나 기대지 않을지와, 그런 실패를 어느 원인(`cause`)으로 보일지를 함께 정한다. 수락에 계열이 다른 모델 둘을 넣은 것은 이 차이를 드러내기 위해서다. base-agent의 설계가 넘긴 것: 기본 에이전트 `assistant`는 모델이 검색 도구를 스스로 불러야 답이 나오므로(ADR 0051 Consequences "모델이 도구 호출 형식을 지켜야 답이 나온다"), 수락의 calc 예시에 더해 기본 에이전트의 실제 모델 시험도 그 모델로 돌릴지를 설계 인터뷰가 정한다. base-agent가 먼저 닫혀 있어야 돌릴 수 있다. 고를 한국어 오픈 모델과 NPU 서빙의 확인은 같은 일지 절의 남은 확인이다. 수락: 상용 모델 API 없이 클라우드 GPU의 vLLM 엔드포인트로 calc 예시가 MCP 도구를 써서 답하고 트레이스가 남는 테스트가 통과하며, 계열이 다른 모델 둘(예: 상용 이용이 가능한 한국어 오픈 모델 하나와 해외 오픈 모델 하나)로 모델 매니페스트만 바꿔 같은 테스트가 통과한다(ADR 0046)
