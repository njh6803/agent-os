# local-model 명세: 모델 파일에 적은 주소의 모델 서버에 붙어 실행을 돌리고, 로컬 모델 시험의 모델 서버를 명령 하나로 띄웠다 지운다

Status: ready-for-agent

슬라이스 7(`local-model`). 설계는 설계 인터뷰(일지 2026-11-11-1534)와 ADR 0057·0058이 정했고, 이 명세는 그 결정 안에서 자리와 문구와 시험을 채운다. 결정을 바꾼 둘은 아래 "이력"이다. 이 명세는 `/to-spec`으로 새 세션에서 썼고 설계 인터뷰를 다시 열지 않았다(일지 2026-11-12-0248). 용어는 `CONTEXT.md`의 모델, 모델 서버, 서빙 엔진, 실행, 이벤트, 트레이스, 어댑터, 포트, 운영자, 실패 원인(모델 호출 `model_call`)을 따른다. ADR 0057·0058의 "호환 서버"와 기능 계획의 "OpenAI 호환 엔드포인트"는 용어집의 모델 서버이고, 이 명세가 새로 짓는 이름(가짜 모델 서버, 모듈, 시험 이름)도 그 말을 쓴다. 이미 승인된 이름인 제공사 값 `openai-compatible`, 마커 `llm_local`, "로컬 모델 시험"은 그대로 쓴다(사용자가 골랐다, 일지 2026-11-12-0248 "사용자에게 물은 것 셋"의 첫째). "코드를 읽었다"는 명세를 쓸 때의 커밋 `c475168d9`(ADR 0057·0058을 들인 origin/main)의 코드다. 그 뒤 이 브랜치를 개발 브랜치의 끝 `fba36f78a`(origin/dev)로 올렸고, 셀프 리뷰가 명세가 근거로 든 자리(루프의 `_ask`·`_describe`·`model_caller`, 종류에 맞지 않는 칸의 목록 넷, `main.py`의 조립 자리 셋, 관리 화면의 `temperature` 줄 수)를 그 커밋에서 다시 대 봐 달라진 것이 없었다(일지 2026-11-12-0248 "셀프 리뷰"). 라이브러리의 판은 프로브가 저장소 락 위에 얹어 깐 langchain-openai 1.6.2, openai 3.49.0(그 아래 httpx2·httpcore2 2.13.0), langchain-core 1.6.3, pydantic 2.13.5이고, pyright는 1.1.414, Python은 3.12.10이다.

**넘겨받은 것은 스물여섯이다.** ADR 0057에서 열일곱이다. (1) 새 제공사 값은 `openai-compatible` 하나이고 `schema_version`은 `"1"` 그대로다(결정 "제공사"). (2) 그 값의 모델 파일은 `base_url`을 글자 그대로 반드시 적고 `http`·`https`만 받으며 사용자 정보가 든 주소를 거부한다. `api_key_env`는 선택이고 이름의 꼴은 명세가 정하며 출발점은 ADR 0049의 헤더 변수 이름 규칙이다. 종류와 제공사에 맞지 않는 칸은 읽는 단계에서 거부하고, `max_tokens`와 `temperature`는 없으면 요청에 싣지 않는다(결정 "모델 파일"). (3) 주소는 비밀이 아니어서 관리 API와 실패 문구에 실리고, 쿼리 문자열은 막지 않는다(결정 "주소는 비밀이 아닌 것으로 본다". 뒤의 것은 이 명세가 바꾼다, 아래 "이력"). (4) 키 값은 어댑터가 호출 때 환경에서 읽고 언제나 직접 넘기며, `api_key_env`가 없으면 자리 채움 글자를 넘긴다. 변수가 없으면 첫 모델 호출에서 원인 `model_call`로 실패하고 실패 내용은 변수의 이름만 든다. 키를 읽는 함수가 실패할 때의 예외 모양은 구현 티켓이 확인한다(결정 "키". 이 명세의 프로브가 먼저 쟀다, 아래 "키"). (5) 모델 서버가 되울린 키를 실패 문구에서 가리고, 어댑터가 모델 호출과 core 사이에 설 수 있는지는 명세의 프로브가 먼저 보고 자리를 정한다(결정 "되울린 키"). 라이브러리의 예외 타입과 문구를 어디서 감싸 core에 내보낼지도 같은 자리다(설계 일지 "다음"의 봇 회차 첫째). (6) 요청은 Chat Completions 하나로 고정하고, 싣는 것은 모델 이름, 대화, 도구 목록, 모델 파일에 있을 때의 상한과 온도다. `tool_choice`와 서빙 엔진의 확장 칸은 싣지 않고 사고 글은 읽지 않으며, 타임아웃과 재시도의 칸을 두지 않는다(결정 "요청"). (7) 도구 호출 파서와 형식 강제는 모델 서버를 띄우는 쪽이 맞추고, 글로 샌 도구 호출은 답으로 보인다(결정 "서빙 엔진마다 다른 설정은 서버를 띄우는 쪽이 맞춘다", "글로 샌 도구 호출"). (8) 인자가 깨진 도구 호출은 원인 `model_call`의 실패이고, 확인하는 자리는 명세가 정하며 출발점은 `reply_from`이다. 실패 내용은 도구 이름을 들고 깨진 글을 싣지 않는다(결정 "인자가 깨진 도구 호출"). (9) 포트는 `ModelSource` 그대로이고, 제공사로 가르는 자리와 모듈의 이름은 명세가 정한다(결정 "포트와 어댑터"). (10) `langchain-openai`를 런타임 의존으로 들이고, 어댑터가 openai SDK를 직접 import하면 그것도 직접 선언하며, import-linter의 금지 목록 둘에 둘을 더한다(결정 "의존"). `docs/constitution/tech.md`의 의존 행은 들이는 티켓이 고친다(설계 일지 "다음"의 봇 회차 셋째). (11) 평소의 시험은 루프백의 가짜 모델 서버로 돌고 무엇을 보는지(결정 "평소의 시험"). (12) 범위 밖 여덟(결정 "범위 밖"). (13) 계약 변경이 첫 티켓이고 다른 티켓을 막는다(Consequences "계약 변경이 첫 티켓이다"). (14) 구현 티켓이 함께 고칠 자리이고, `.claude/rules/`의 "제공사는 `anthropic` 하나" 문장을 고치는 일을 수락에 건다(Consequences "구현 티켓이 함께 고칠 자리", 설계 일지 "다음"의 봇 회차 둘째). (15) 배포가 알아야 할 것 여섯은 deploy-package의 배포 안내가 받는다(Consequences "배포가 알아야 할 것"). (16) 구현 티켓의 수락에 "키가 있는 모델로 부르며 루트 로거를 DEBUG로 켠 시험에서 키 값이 로그에 나타나지 않는다"를 넣는다(Consequences "로그"). (17) 모델 파일을 쓰는 사람이 운영자의 환경 변수를 제 주소로 보내게 적는 것을 막는 승인은 두지 않는다(Consequences "모델 파일을 쓰는 사람"). ADR 0058에서 아홉이다. (18) 시험은 두 층이고 로컬 모델 시험은 `-m llm_local`로만 돌며 환경이 없으면 skip이 아니라 실패한다(결정 "시험은 두 층이다"). (19) 트레이스에 도구 호출이 남아야 통과한다(결정 "로컬 모델 시험이 보는 것"). (20) 두 모델과 다음 후보(결정 "두 모델"). (21) 병합 조건의 범위, 두 모델 모두, 한 번 실패하면 실패, 언제 돌리고 무엇을 남기는가, 첫 적용, 지키게 하는 수단(결정 여섯). (22) 모델 서버는 세션이 Terraform으로 띄웠다 지우고, 명령 하나가 서버 키를 만들어 넘기며, 서버는 스스로 꺼지게 걸린 채로 뜨고, 띄울 때마다 비용을 확인받고, 상태 파일은 워크트리 밖에 브랜치마다 두며, 띄우지 못하면 다른 곳의 서버로 돌린다(결정 "모델 서버는 세션이 띄웠다 지운다"부터 "띄우지 못할 때"까지). (23) 사용자가 한 번 준비하는 것 넷(결정 "사용자가 한 번 준비하는 것"). (24) 기본 에이전트의 사례를 두 모델로 기록하는 티켓이 마지막이다(결정 "기본 에이전트의 사례"). (25) 명세로 넘기는 일곱. GPU의 종류와 올리는 방식, 타이머의 값과 삭제까지 가는지, 스크립트와 Terraform 파일의 자리, 시험이 받는 환경 변수의 이름, 시작할 때 남은 서버를 먼저 지우는지와 앞 세션의 서버를 가르는 법, 남은 파드와 상태 파일을 누가 언제 지우는지, 서버 쪽 사정의 회차를 실패로 셀지다(결정 "명세로 넘기는 것"). (26) 실제로 띄워 확인하는 것은 서버를 띄우는 파일을 들이는 티켓이 하고, 규약 문서는 어댑터와 로컬 모델 시험을 넣는 PR이 고친다(Consequences "서버를 띄우는 파일을 들이는 티켓이 띄워 확인하는 것", "규약이 서는 때").

**셋은 사용자가 이 명세를 쓰기 전에 골랐다.** 명세와 새 이름이 쓰는 말은 용어집의 모델 서버다(위 첫 문단). 모델 서버를 실제로 띄워 구성을 확인하는 것은 명세가 아니라 그 파일을 들이는 티켓이 한다("모델 서버를 띄우는 명령"). 평소의 시험은 실제 CLI를 띄우고 모델 자리에만 가짜 모델 서버를 끼운다("사례"의 calc 평소 시험). 질문과 고른 설명의 원문은 일지 2026-11-12-0248의 "사용자에게 물은 것 셋"이다.

**스물다섯은 명세가 넘겨받은 것 안에서 스스로 정했고 각 절 제목의 괄호에 "명세가 정했다"로 표시한다.** 키 변수 이름의 꼴, 주소 검사의 수단과 거부 문구, 주소의 조각과 경로, 계약 묶음만 병합된 개발 브랜치의 임시 거부, 관리 화면 시험 하나, 모듈의 나눔, 모델을 만들다 거부되는 주소의 처리, 요청을 고정하는 인자, 모델마다의 HTTP 클라이언트, 키를 읽는 함수의 검사와 문구, 실패 문구의 모양과 감싸는 자리, 검증 예외가 싣는 것, 깨진 도구 호출을 확인하는 자리와 문구, 로그 시험의 모양, 로컬 모델 시험의 환경 변수, 그 시험의 모양, 명령의 자리, 구성, 타이머, 걸음, 잠금, 청소, 무효 회차, 가짜 모델 서버와 사례, 고칠 자리의 묶음이다. 설계가 묻지 않은 자리를 이 명세가 재어 찾은 것은 다섯이다. 셋은 위 스물다섯에 든다. 라이브러리가 주소별로 나눠 쓰는 클라이언트는 한 프로세스의 둘째 이벤트 루프에서 실패한다(아래 "HTTP 클라이언트"). 도구 호출의 인자가 JSON이지만 객체가 아니면 라이브러리의 검증 예외가 그 인자를 글에 되울린다(아래 "실패 문구와 되울린 키"). 읽는 단계의 주소 검사를 지난 주소 가운데 라이브러리가 모델을 만드는 순간 거부하는 것이 있다(아래 "모델 소스와 모듈"). 나머지 둘은 아래 "이력"이 됐다. 쿼리가 든 주소는 라이브러리가 요청 줄을 깨뜨려 보낸다(아래 "매니페스트". 실제 모델 서버가 그 요청을 어떻게 답하는지는 보지 않았다). 모델 이름의 머리가 요청을 바꾼다(아래 "요청").

**이력은 둘이다.** ADR 0057의 2026-11-12 이력 "모델 파일의 주소에 쿼리 문자열이 있으면 읽는 단계에서 거부한다"와 "모델 이름의 머리에 따라 라이브러리가 요청을 바꾸는 것을 알려진 한계로 둔다"이다. 둘 다 이 명세와 같은 커밋에서 초안을 쓰고 셀프 리뷰를 반영한 뒤 사용자의 승인을 받았다(작업 규약 5, 일지 2026-11-12-0248 "ADR 0057 이력 둘의 승인"). 앞의 것은 결정 "주소는 비밀이 아닌 것으로 본다"의 쿼리 문장과 Consequences "주소의 쿼리"를 거짓으로 만들고, 뒤의 것은 결정 "요청"의 싣는 것 문장을 거짓으로 만들어 그 문장들에 포인터를 단다(`.claude/rules/adr.md`). 키를 읽는 함수의 예외 모양(결정 "키"), 어댑터가 설 자리(결정 "되울린 키"), 모델마다의 HTTP 클라이언트, 검증 예외의 처리는 ADR 본문에 사실을 더하거나 ADR이 명세에 넘긴 자리를 채우는 것이라 본문의 문장을 거짓으로 만들지 않아 이력을 쓰지 않는다.

**거부한 안은 서른넷이고 각 절의 "거부한 안:" 표시에 있다.**

측정은 `.scratch/local-model/probes/`이고 결과는 그 `README.md`다. 루프백의 가짜 모델 서버에 라이브러리와 후보 어댑터를 붙인 `openai_compat.py`(사례 108, `cases_*.py`와 `fake_server.py`·`support.py`·`adapter_candidate.py`가 한 프로브다), 후보의 타입 검사 `check_adapter_types.py`, 의존을 풀어 보는 `make_env.py`, 워크트리 밖 쓰기와 `.env`를 넘기는 `outside_worktree.py`다. 이 명세에서 "쟀다"는 그것을 가리키고 사례 이름을 함께 적는다. 코드를 읽은 것과 어림은 그렇게 적는다. 모두 Windows 10(이 PC)에서만 쟀다. 실제 모델 서버와 클라우드는 부르지 않았다(사용자가 골랐다, 일지 2026-11-12-0248 "사용자에게 물은 것 셋"의 둘째).

## Problem Statement

운영자 관점. 모델 제공사는 `anthropic` 하나다(`sdk/manifest.py`의 `ModelProvider`를 읽었다). 바깥 API를 쓸 수 없는 폐쇄망 배포 환경에서는 그 환경의 모델 서버로 실행이 돌아야 하는데, 모델 파일에 주소를 적을 칸이 없고 그 주소에 붙는 어댑터가 없다(기능 계획 `.scratch/local-model/plan.md`).

모델 파일을 쓰는 사람 관점. 키가 필요한 모델 서버에 붙으려면 키를 둘 자리가 있어야 한다. 모델 파일에 값을 적으면 관리 API의 매니페스트 응답에 그대로 실려 원칙 V에 어긋난다.

개발하는 세션 관점. 모델과 서빙 엔진의 조합이 도구 호출을 실제로 내는지는 가짜 모델 서버로 볼 수 없다. 도구 호출이 글로 샌 조합은 런타임에게 보통의 답과 같아(ADR 0057 결정 "글로 샌 도구 호출") 실제 모델 서버로 도는 시험만이 가른다. 그 시험에는 GPU가 필요한데 CI 러너에는 없고(ADR 0058의 어림), 세션이 모델 서버를 띄웠다 지우는 길이 저장소에 없다. 손으로 띄우면 끄기를 잊은 서버가 요금을 낸다.

라이브러리 관점(명세의 측정이 더했다). `ChatOpenAI`를 손대지 않고 쓰면 원칙 V와 실행의 모양에 닿는 것이 넷이다(쟀다). 401의 예외는 서버가 되울린 키를 글과 원인 사슬에 싣고(`fail_401_echo_string`), 키를 생성자에 주지 않으면 환경의 `OPENAI_API_KEY`가 모델 서버로 가며(`env_key_used_when_omitted`), 도구 호출의 인자가 JSON이지만 객체가 아니면 검증 예외가 그 인자를 글에 싣는다(`tool_args_not_object`). 그리고 같은 프로세스에서 이벤트 루프를 닫고 새로 열면 같은 주소의 둘째 호출이 `Event loop is closed`로 실패한다(`two_loops_same_url`). 그래서 어댑터는 라이브러리를 감싸야 한다.

## Solution

모델 플러그인의 `plugin.toml`에 `provider = "openai-compatible"`과 모델 서버의 주소 `base_url`을 적는다. 키가 필요한 서버면 `api_key_env`에 환경 변수의 이름을 적는다. 런타임은 지금처럼 실행을 준비할 때마다 그 파일로 모델을 만들고, 모델을 부를 때마다 그 주소에 Chat Completions 요청을 보낸다. 키 값은 호출 직전에 환경에서 읽어 요청에만 싣고 어디에도 기록하지 않는다. `anthropic` 모델 파일은 그대로 읽히고 그대로 돈다.

```toml
schema_version = "1"
kind = "model"
name = "ax-4-light"
version = "0.1.0"
provider = "openai-compatible"
model_id = "skt/A.X-4.0-Light"
base_url = "http://model-server:8000/v1"
api_key_env = "MODEL_SERVER_API_KEY"
```

시험은 두 층이다. 평소의 pytest와 CI는 시험이 이 PC 안에 띄운 가짜 모델 서버로 돌고, calc 예시가 그 서버를 모델로 삼아 MCP 도구를 써서 답하고 트레이스를 남기는 것까지 본다. 로컬 모델 시험(`-m llm_local`)은 같은 calc 예시를 실제 모델 둘로 돌린다. 그 시험의 모델 서버는 명령 하나가 Runpod에 띄우고, 준비를 기다리고, 시험을 돌리고, 지운다. 명령은 띄우기 전에 예상 비용을 보여 주고 확인 없이는 띄우지 않으며, 서버는 일정 시간 뒤 스스로 지워지게 걸린 채로 뜬다.

## User Stories

1. 운영자로서, 바깥 API를 쓸 수 없는 배포 환경에서 그 환경의 모델 서버로 에이전트를 돌리고 싶다. 그래야 폐쇄망에서도 실행이 돈다.
2. 운영자로서, 모델 파일에 `provider = "openai-compatible"`과 `base_url`만 적어 모델 서버를 가리키고 싶다. 그래야 서빙 엔진이나 모델을 바꿀 때 모델 파일만 고친다.
3. 운영자로서, 지금 있는 `anthropic` 모델 파일을 한 글자도 고치지 않고 그대로 쓰고 싶다. 그래야 이 기능이 들어와도 배포가 깨지지 않는다.
4. 운영자로서, 키 값을 모델 파일에 적지 않고 환경 변수의 이름만 적고 싶다. 그래야 비밀이 저장소와 관리 API 응답에 남지 않는다.
5. 운영자로서, 키 없이 붙는 내부 모델 서버에는 `api_key_env`를 적지 않고 붙고 싶다. 그래야 쓰지 않는 키를 지어내지 않는다.
6. 운영자로서, `serve`의 환경에 다른 용도의 `OPENAI_API_KEY`가 있어도 그 값이 모델 파일에 적힌 주소로 가지 않기를 바란다. 그래야 남의 서비스의 키가 모델 서버로 새지 않는다.
7. 운영자로서, 키 변수를 빠뜨렸을 때 어느 변수가 없는지를 실패 내용에서 이름으로 보고 싶다. 그래야 값이 아니라 이름만 보고 고친다.
8. 운영자로서, 모델 서버가 꺼졌을 때와 키가 틀렸을 때가 실패 내용만으로 갈리기를 바란다. 그래야 진단 묶음(diag-bundle)만 보고 원인을 가른다.
9. 운영자로서, 모델 서버가 받은 키를 오류 글에 되울려도 실패 내용과 트레이스에 키 값이 남지 않기를 바란다. 그래야 트레이스를 공유해도 비밀이 새지 않는다.
10. 운영자로서, 모델이 도구 호출의 인자를 깨진 JSON으로 냈을 때 실행이 빈 답으로 끝나지 않고 원인 `model_call`의 실패로 끝나며 어느 도구였는지 보이기를 바란다. 그래야 모델과 서버 옵션의 조합이 맞지 않는다는 것을 안다.
11. 운영자로서, 깨진 인자의 글이 트레이스에 남지 않기를 바란다. 그래야 `secret_args`로 가려야 하는 인자가 실패 내용으로 새지 않는다.
12. 운영자로서, `openai-compatible` 파일에 `base_url`을 빠뜨리거나 `anthropic` 파일에 `base_url`을 적으면 읽는 단계에서 어느 칸이 틀렸는지 듣고 싶다. 그래야 오타가 조용히 무시되지 않는다.
13. 운영자로서, 사용자 정보(`user:pass@`)나 쿼리 문자열이 든 주소, http·https가 아닌 주소는 읽는 단계에서 거부되기를 바란다. 그래야 비밀이 주소에 실린 채 관리 API에 나오지 않고, 붙지 않을 주소가 첫 호출까지 숨지 않는다.
14. 운영자로서, 관리 API와 관리 화면의 매니페스트에서 모델이 어느 주소의 모델 서버를 가리키고 키를 어느 변수에서 읽는지 보고 싶다. 그래야 배포가 어느 서버를 쓰는지 확인한다.
15. 운영자로서, `max_tokens`와 `temperature`를 적지 않으면 모델 서버의 기본값이 쓰이기를 바란다. 그래야 서버를 띄운 쪽이 정한 값을 모델 파일이 덮지 않는다.
16. 최종 사용자로서, 모델 서버의 실패를 지금과 같은 고정 문구로 보고 싶다. 그래야 모델 서버의 주소나 내부 사정이 최종 사용자 면에 새지 않는다.
17. 에이전트 저자로서, 에이전트 코드를 고치지 않고 모델 파일만 바꿔 같은 에이전트를 다른 모델로 돌리고 싶다. 그래야 모델이 플러그인이라는 약속(ADR 0040)이 제공사가 늘어도 선다.
18. 운영자로서, 루트 로거를 DEBUG로 켜도 키 값이 로그에 남지 않기를 바란다. 그래야 문제를 살피려 로그를 켜는 순간 비밀이 새지 않는다. 모델 서버가 응답 헤더로 키를 되울리는 경우는 받아들인 한계다(아래 "로그").
19. 이 저장소를 고치는 세션으로서, GPU 없이 도는 평소의 시험에서 calc 예시가 가짜 모델 서버를 모델로 삼아 도구를 쓰고 트레이스를 남기는 것을 보고 싶다. 그래야 CI가 이 길을 커밋마다 본다.
20. 이 저장소를 고치는 세션으로서, 실행 코드를 고친 변경을 병합하기 전에 명령 하나로 실제 모델 둘에 로컬 모델 시험을 돌리고 싶다. 그래야 한쪽 도구 호출 파서에서만 깨지는 변경이 개발 브랜치(핫픽스라면 운영 브랜치)에 들어오지 않는다.
21. 요금을 내는 사용자로서, 모델 서버를 띄우기 전에 예상 비용을 보고 확인하고 싶다. 그래야 확인하지 않은 과금이 생기지 않는다.
22. 요금을 내는 사용자로서, 명령이나 세션이 중간에 죽어도 모델 서버가 계속 돌며 요금을 내지 않기를 바란다. 그래야 잊은 서버가 잔액을 비우지 않는다.
23. 요금을 내는 사용자로서, 나란히 도는 두 세션이 서로의 모델 서버를 지우지 않고, 버려진 브랜치의 서버와 상태 파일이 남지 않기를 바란다. 그래야 여러 세션을 함께 돌려도 요금과 시험이 섞이지 않는다.
24. 리뷰어로서, 로컬 모델 시험의 기록(시험한 커밋, 두 모델, 모델 서버의 판과 옵션, 통과 수, 토큰 합계)을 PR 코멘트에서 보고 싶다. 그래야 병합 조건이 지켜졌는지 PR만 보고 안다.
25. 이 저장소를 고치는 세션으로서, 모델 서버 쪽 사정으로 시험이 끝까지 돌지 못한 회차가 코드의 실패로 세어지지 않기를 바란다. 그래야 고칠 코드가 없는 실패에 막히지 않는다.
26. 리뷰어로서, 계약 변경이 첫 티켓 하나에 모여 다른 티켓이 그 뒤에 서기를 바란다. 그래야 sdk·`openapi.json`·생성 TS 타입이 한 커밋에서 함께 바뀐다.
27. deploy-package의 저자로서, 배포 환경의 모델 서버를 이 값의 모델 파일로 가리키고 싶다. 그래야 그 기능이 모델 파일의 모양을 새로 정하지 않는다.
28. base-agent와 answer-eval의 저자로서, 기본 에이전트의 사례가 두 로컬 모델에서 어떻게 되는지의 기록을 받고 싶다. 그래야 스킬 문구와 모델 고르기의 입력이 생긴다.

## Implementation Decisions

### 매니페스트 (넘겨받았다. 키 변수 이름의 꼴, 주소 검사의 수단과 거부 문구, 주소의 조각과 경로는 명세가 정했다. 쿼리의 거부는 ADR 0057의 이력이다)

- `ModelProvider`에 값 `openai-compatible`을 더하고, 매니페스트에 선택 칸 둘 `base_url`과 `api_key_env`를 더한다. 둘 다 문자열이고 기본은 없음이다. 다른 모델 칸과 같이 기본값을 글자로 두지 않는다.
- `base_url`은 글자 그대로 보관한다(`AnyHttpUrl`을 쓰지 않는다. 쓰면 관리 API 응답이 파일에 적은 글자와 달라진다). 검사는 원격 MCP 서버의 `url`과 같은 규칙 넷이고 문구도 칸 이름만 다른 같은 모양이다. 주소 모양이 아니다, `http`나 `https` 주소가 아니다, 사용자 정보가 들었다, 호스트가 없다. 문구는 적은 값을 되울리지 않는다(`sdk/manifest.py`의 `HttpServer` 검증자를 읽었다. 같은 규칙을 두 자리에 따로 적지 않고 나눠 쓴다).
- `base_url`에는 규칙이 하나 더 있다. 조각(`#` 뒤)을 뗀 주소에 `?`가 있으면 거부하고 문구는 `base_url 에 쿼리 문자열을 적을 수 없다`다. 빈 쿼리(`…/v1?`)도 든다. 까닭은 둘이다. 라이브러리는 쿼리가 든 주소의 쿼리 뒤에 경로를 붙여, 가짜 모델 서버가 받은 요청 줄이 `POST /v1/?probe_token=query-secret-4b9dchat/completions`였다(쟀다, `path_with_query`). 경로는 `/v1/`이고 `chat/completions`는 쿼리 값의 꼬리가 되어 Chat Completions의 경로(`/v1/chat/completions`)를 가리키지 않는다. 실제 모델 서버가 그 요청에 무엇을 답하는지는 보지 않았다. 그런 주소로 Chat Completions에 붙는 서버는 없을 것으로 본다(어림). 그리고 그 주소는 401의 원인 예외 글과 `httpx2` 로거의 INFO 줄에 쿼리째 실린다(쟀다, `query_url_401`, `logs_401_query_url`). 붙지 않을 주소를 받아 두면 쿼리에 적은 비밀이 관리 API, 실패 문구, 원인 예외, 로그로 나가기만 한다. 그래서 ADR 0057이 받아들인 "주소의 쿼리 문자열에 비밀을 적는 것은 막지 않고"를 이 칸에서는 거둔다(ADR 0057의 2026-11-12 이력 "모델 파일의 주소에 쿼리 문자열이 있으면 읽는 단계에서 거부한다"). 원격 MCP 서버의 `url`의 규칙은 바꾸지 않는다. 그 칸에서 쿼리가 요청을 깨는지는 재지 않았고 이 기능의 범위 밖이다. 빈 쿼리가 요청 경로를 어떻게 바꾸는지는 재지 않았다. 쓸모가 없는 글자라 함께 막는다. 거부한 안: 쿼리를 막지 않고 그대로 둔다(ADR 0057의 원래 결정이다. 첫 호출이 깨진 요청 줄로 가고, 쿼리는 관리 API와 실패 문구와 로그에 그대로 실린다). 거부한 안: 라이브러리에 넘기기 전에 어댑터가 쿼리를 떼어 경로를 고친다(파일에 적은 주소와 실제로 가는 주소가 달라지고, 쿼리로 인증하는 서버라면 조용히 인증이 빠진다).
- 조각은 막지 않는다. 라이브러리가 떼고 보내 요청은 `POST /v1/chat/completions`이고(쟀다, `path_with_fragment`) 조각은 네트워크로 나가지 않는다. 관리 API에는 파일에 적은 글자 그대로 실린다. 거부한 안: 조각도 거부한다(받아도 붙는 주소라 막을 까닭이 쿼리처럼 서지 않는다).
- `base_url`은 모델 서버의 API 뿌리까지 적는다. vLLM이면 `/v1`까지다. 라이브러리는 그 뒤에 `chat/completions`만 붙이고, 끝의 `/`는 있어도 없어도 같다(쟀다, `path_plain`, `path_trailing_slash`). `/v1` 없이 적으면 요청이 `POST /chat/completions`로 간다(쟀다, `path_without_v1`). 이 뜻은 sdk의 칸 설명(`openapi.json`에 실린다)과 Solution의 예시가 적는다. 거부한 안: 경로가 `/v1`로 끝나지 않으면 거부하거나 어댑터가 붙인다(API 뿌리가 다른 모델 서버와 게이트웨이를 막는다).
- `api_key_env`의 꼴은 `[server.headers]`의 환경 변수 이름과 같다. 글자·숫자·밑줄만이고 비지 않는다. 같은 타입 제약을 써서 패턴이 `openapi.json`에 실린다(ADR 0049의 선례. `sdk/manifest.py`의 `_EnvName`을 읽었다). 거부한 안: 숫자로 시작하는 이름을 막는다(두 칸의 규칙이 갈린다. 그런 이름은 환경에 없을 뿐이라 첫 호출의 "변수가 없다"로 드러난다).
- 종류와 제공사에 맞지 않는 칸은 읽는 단계에서 거부한다. 판정은 지금의 다른 칸과 같이 "적었는가"다.
  - `provider`가 `openai-compatible`인데 `base_url`이 없다. 문구는 `provider 가 openai-compatible 인 model 플러그인은 base_url 이 필요하다`.
  - `provider`가 `anthropic`인데 `base_url`이나 `api_key_env`를 적었다. 문구는 `provider 가 anthropic 인 model 플러그인은 <칸 이름> 을 갖지 않는다`.
  - 모델이 아닌 종류가 둘 가운데 하나를 적었다. 지금의 `<종류> 플러그인은 <칸 이름> 을 갖지 않는다`이고, 그 검사가 도는 네 칸의 목록에 둘을 더한다.
  문구가 싣는 것은 칸 이름과 닫힌 열거를 지난 제공사 값뿐이다.
- `model_id`는 모델 서버에 보내는 모델 이름이다. `max_tokens`와 `temperature`의 검사는 그대로이고 `temperature`의 상한 1도 그대로다. OpenAI의 API는 2까지 받지만(어림, 일반 지식) 칸의 뜻을 제공사마다 가르지 않는다.
- `schema_version`은 `"1"` 그대로다(ADR 0057 결정 "제공사").
- 직렬화 스키마에서 두 칸은 다른 선택 칸처럼 required이고 `null`을 허락한다. 그래서 모든 종류의 매니페스트 응답에 `base_url`과 `api_key_env`가 `null`로 실린다.

### 계약과 관리 화면 (넘겨받았다. 계약 묶음만 병합된 개발 브랜치의 임시 거부와 관리 화면 시험 하나는 명세가 정했다)

- `openapi.json`(`ModelProvider`의 값, 매니페스트의 두 칸과 키 변수 이름의 패턴)과 생성 TS 타입이 계약 묶음에서 함께 바뀐다.
- 매니페스트 값을 생성 타입으로 적은 테스트 픽스처와 스토리에 두 칸이 는다. `temperature`를 적은 줄로 세면 관리 화면의 테스트 파일 셋에 열 줄, 스토리 파일 셋에 다섯 줄이다(손으로 봤다, Grep `temperature`, `web/apps/admin`. 매니페스트 객체의 수를 어림하는 수다).
- 관리 화면은 매니페스트를 JSON 그대로 그리므로 줄이 둘 늘어 사진 정답이 바뀔 수 있다(ADR 0057 Consequences "계약 변경이 첫 티켓이다". 어느 사진인지는 계약 묶음이 `pnpm -C web visual:admin`으로 본다).
- 관리 화면의 플러그인 상세 시험에 사례 하나를 더한다. `openai-compatible` 모델의 매니페스트를 열면 주소와 키 변수 이름이 화면에 보인다(스토리 14). 새 스토리와 화면 변경은 두지 않는다.
- **계약 묶음만 병합된 개발 브랜치.** `ModelProvider`에 값이 늘면 모델 소스가 그 값을 다뤄야 pyright를 지난다(`adapters/anthropic.py`를 읽었다. 제공사로 가르는 `match`에 기본 갈래가 없다). 계약 묶음은 그 값의 갈래를 실행 전 구성 오류(`PluginError`)로 둔다. 문구는 `model 플러그인 <이름> 의 provider openai-compatible 에 붙는 어댑터가 아직 없다`이고 트레이스가 남지 않는다. 어댑터 묶음이 그 갈래를 실제 어댑터로 바꾸며 그 문구를 지운다. 선례는 mcp-http의 계약 묶음이 http 갈래에 둔 임시 실패다(`.scratch/mcp-http/spec.md` "고칠 자리의 묶음"의 주석).

### 모델 소스와 모듈 (명세가 정했다. 모듈의 나눔과, 모델을 만들다 거부되는 주소의 처리다)

- 포트는 `ModelSource` 그대로이고 구현은 어댑터 층의 모델 소스 하나다. 모델 소스가 `provider`로 갈라 제공사의 모듈에게 모델을 만들게 한다.
- 모듈은 셋으로 나눈다. 제공사를 모르는 모델 소스 모듈(`adapters/models.py`. 모델 소스와, 기본 모델의 이름을 정하는 `resolve_model_name`과 `AGENT_OS_MODEL`), Anthropic 모듈(`adapters/anthropic.py`. `ChatAnthropic`을 만드는 것과 상한 16000), 모델 서버 모듈(`adapters/openai_compatible.py`. 아래 "요청"부터 "로그"까지의 모델 객체)이다. 지금은 앞의 둘이 `adapters/anthropic.py` 한 파일에 있어, 갈래만 더하면 그 파일이 `langchain_openai`를 import하게 된다.
- 옮기며 바뀌는 자리는 `main.py`의 import 한 줄과 조립 자리 셋, `tests/adapters/test_anthropic.py`·`tests/test_main.py`·`tests/core/test_model.py`, `.claude/rules/adapters.md`의 모델 소스 문장이다(손으로 봤다, Grep `AnthropicModels|resolve_model_name|MODEL_ENV`. `src/`, `tests/`, `tools/`, `.claude/rules/`). 같은 grep에 걸리는 `channel/cli/main.py`의 독스트링은 함수 이름 `resolve_model_name`만 들어 그 이름을 지키면 그대로이고, `tools/hook_probe_citing_doc.py`의 독스트링은 지난 사례의 기록이라 고치지 않는다.
- 모델 만들기는 두 제공사 모두 키도 네트워크도 요구하지 않는다(포트의 전제, ADR 0040). 모델이 아닌 종류의 매니페스트와 공백뿐인 `model_id`의 거부는 제공사를 가르기 전에 있어 두 제공사에 같다.
- **모델을 만들다 거부되는 주소.** 읽는 단계의 주소 검사를 지난 주소 가운데 라이브러리가 모델을 만드는 순간 거부하는 것이 있다. 개행이 든 주소, 탭이 든 주소, 포트가 숫자가 아닌 주소, 경로가 7만 자인 주소가 `httpx2.InvalidURL`로 끝났다(쟀다, `build_rejects_address`. 꼴이 이상한 주소 열을 넣어 그 넷이 걸렸다. 거부되는 꼴의 전부가 아니다). 읽는 단계의 검사는 표준 라이브러리의 `urlsplit`으로 보는데, 그 검사는 이 넷을 지나게 둔다(같은 사례가 sdk의 `HttpServer`를 불러 봤다). 실행을 준비하는 길은 `PluginError`를 실행 전 구성 오류로 받아 트레이스 없이 진단만 적으므로(`channel/cli/main.py`를 읽었다), 라이브러리의 예외가 그대로 올라오면 그 길을 비켜 간다. 그 뒤 CLI와 `serve`가 어떻게 끝나는지는 돌려 보지 않았다. 그래서 모델 서버 모듈은 모델을 만드는 자리에서 난 예외를 종류를 가리지 않고 받아 `PluginError`로 바꾼다. 문구는 `model 플러그인 <이름> 의 base_url 로 모델을 만들 수 없다 (<예외 종류의 이름>)`이고, 다른 실행 전 구성 오류처럼 트레이스가 남지 않는다. 라이브러리의 글은 싣지 않는다. 그 글이 주소의 조각을 되울리는데(포트가 숫자가 아닌 주소의 글이 `Invalid port: 'odd-part-3c7e'`였다) 읽는 단계의 문구가 적은 값을 되울리지 않는 것과 맞춘다. 만드는 때에는 키를 읽지 않아(아래 "키") 이 예외에 키가 실릴 길이 없다. 만들어지기는 하는 주소가 호출에서 실패하는 것(포트가 99999인 주소가 만들어졌다)은 아래 "실패 문구와 되울린 키"의 길로 간다. 거부한 안: 읽는 단계의 검사에 규칙(제어 문자, 포트, 길이)을 더한다(무엇이 주소인지를 정하는 것은 라이브러리의 해석이고 sdk는 그 라이브러리를 import하지 않는다. 손으로 베낀 규칙은 라이브러리의 판이 바뀌면 어긋나고, 원격 MCP 서버의 `url`과 나눠 쓰는 규칙이라 그 칸의 계약도 함께 바뀐다). 거부한 안: 바꾸지 않고 둔다(실행 전 구성 오류를 받는 길을 비켜 간다).
- 거부한 안: `adapters/anthropic.py`의 `match`에 갈래만 더한다(파일의 이름과 독스트링이 거짓이 된다). 거부한 안: 제공사마다 모델 소스를 따로 두고 `main.py`가 고른다(포트의 구현이 둘이 되고 조립 자리 셋이 제공사를 알아야 한다).

### 요청 (넘겨받았다. 고정하는 인자는 명세가 정했다. 모델 이름 머리의 한계는 ADR 0057의 이력이다)

- 모델 서버 모듈은 `ChatOpenAI`의 하위 클래스(아래 "실패 문구와 되울린 키")로 모델을 만들고 생성자에 모두 이름으로 넘긴다. 매니페스트에서 오는 것은 `model`(`model_id`), `base_url`, `max_completion_tokens`(`max_tokens`. 없으면 없음), `temperature`(없으면 없음)다. 어댑터가 짓는 것은 `api_key`(아래 "키"의 함수)와 `http_async_client`(아래 "HTTP 클라이언트")다. 고정하는 것은 넷이다.
  - `use_responses_api=False`. 주지 않으면 이름이 `gpt-5-pro-local`·`my-codex-model`이거나 환경에 `LC_OUTPUT_VERSION=responses/v1`이 있을 때 요청이 `POST /v1/responses`로 간다(쟀다, `route_pro_name_auto`, `route_codex_name_auto`, `route_env_version_auto`). 주면 셋 다 `/v1/chat/completions`다(`route_pro_name_off`, `route_codex_name_off`, `route_env_version_off`, `route_candidate_env_version`).
  - `disable_streaming=True`. `astream`도 `_agenerate`를 지나 아래 감싸기를 비켜 가지 않는다(쟀다, `guard_paths`). 끄지 않으면 `astream`이 `_astream`으로 가서 감싸기를 비켜 가고 키가 샌다(`guard_stream_bypass_control`). 토큰 단위 스트리밍은 범위 밖이라(ADR 0014) 잃는 것이 없다. 스트리밍 콜백이 붙은 `ainvoke`가 같은 길이라는 것은 읽은 것이다(langchain-core 1.6.3의 `_agenerate_with_cache`).
  - `openai_proxy=None`. 환경의 `OPENAI_PROXY`가 요청을 키와 함께 그 프록시로 보내지 못하게 한다(쟀다, `env_openai_proxy`, `env_openai_proxy_candidate`). 표준 프록시 변수는 그대로 듣는다. `HTTP_PROXY`로 쟀고(`env_http_proxy_candidate`) `HTTPS_PROXY`와 `ALL_PROXY`는 넣어 보지 않았다. 그것은 배포가 다룰 일이다(ADR 0057 Consequences "프록시").
  - `output_version=None`. 환경의 `LC_OUTPUT_VERSION`이 이 칸을 채우지 못하게 한다(속성을 쟀다, `client_defaults`). 그 값이 응답 메시지의 꼴을 어떻게 바꾸는지는 재지 않았다.
- 요청의 모양(쟀다). `POST <base_url>/chat/completions`이고 본문의 키는 `messages`, `model`, `stream`(false), `tools` 넷이다. 도구 하나는 `{"type": "function", "function": {"name", "parameters", "description"}}`이고 `strict`가 없다. `tool_choice`, `parallel_tool_calls`, `max_tokens`, `max_completion_tokens`, `temperature`, `stream_options`, `n`은 실리지 않는다(`body_with_tools`). 도구가 없으면 `tools`도 없다(`body_without_tools`). 상한과 온도는 매니페스트에 있을 때만 `max_completion_tokens`와 `temperature`로 실린다(`guard_candidate_success`). 헤더에는 `authorization: Bearer <키>`, `user-agent: AsyncOpenAI/Python 3.49.0`, `x-stainless-*` 아홉이 간다(`authorization_header`). 실제 모델 서버가 이 이름과 헤더를 받는지는 C와 D가 실제 서버로 본다.
- 응답의 해석(쟀다). `usage`의 입력·출력 토큰이 `reply_from`의 두 수가 되고, 모델 이름은 서버가 응답에 실은 `model`이며 요청에 적은 `model_id`가 아니다. 서버가 `model`을 싣지 않으면 `unknown`이다(`response_usage_and_model`, `response_without_usage_and_model`). 사고 글 칸(`reasoning_content`, `reasoning`)은 버려진다(`response_reasoning_content`). 글 안에 `<think>`로 섞여 온 사고 글은 답에 남는다(어림. 넣어 보지 않았다).
- 타임아웃과 재시도는 라이브러리의 기본값 그대로다. SDK 클라이언트의 `max_retries`는 2, `timeout`은 없음이고(속성을 쟀다, `client_defaults`), 429·500·연결 실패는 세 번, 400·401·404는 한 번 보낸다(쟀다, `fail_*`). ADR 0057 Consequences "기다림" 그대로다.
- **알려진 한계, 모델 이름의 머리.** `use_responses_api=False`로도 라이브러리가 모델 이름을 보고 요청을 바꾼다. 이름이 `o1-local`·`o3-local`이면 시스템 메시지가 `role: developer`로 가고, `gpt-5-local`·`gpt-5-pro-local`이면 매니페스트의 `temperature=0.2`가 빠진다. `local-model`과 `my-codex-model`은 그대로다(쟀다, `model_name_quirks`. 이 여섯 이름만 넣었다). 조건은 읽었다(langchain-openai 1.6.2의 `chat_models/base.py`). 역할은 이름이 정규식 `^o\d`에 맞을 때(대소문자를 가린다) 바뀌고, 온도는 소문자로 바꾼 이름이 `gpt-5`로 시작하고 `chat`이 없으며 값이 1이 아닐 때 빠진다. 다만 `reasoning_effort`나 `reasoning.effort`가 `none`이면 빼지 않는데, 어댑터는 그 칸을 주지 않는다. 같은 검증자에는 `o1`로 시작하는 이름에서 생성자 인자에 `temperature`라는 키가 아예 없을 때 1을 채우는 갈래도 있다. 어댑터는 `temperature`를 없음이어도 언제나 이름으로 넘기므로 키가 있어 그 갈래가 서지 않는다(조건은 읽은 것이다). `o1-local`에 `temperature=None`을 이름으로 넘긴 요청의 본문에는 `temperature`가 없었다(쟀다, `model_name_quirks`의 그 행. 키를 아예 빼면 1이 실린다는 양성 대조는 넣지 않았다). 두 시험 모델의 이름 `skt/A.X-4.0-Light`와 `openai/gpt-oss-20b`는 두 조건에 걸리지 않는다(읽은 조건에 대 봤다). 그런 이름의 모델을 내는 모델 서버(OpenAI 모델을 중계하는 게이트웨이 등)에서는 모델 파일의 온도가 듣지 않거나 시스템 메시지가 `developer` 역할로 가고, 그 역할을 모르는 서버는 요청을 거절할 수 있다(어림). 이 명세는 그것을 막지 않는다. ADR 0057 결정 "요청"의 싣는 것 문장이 그런 이름에서는 거짓이 되므로 이력에 적는다(ADR 0057의 2026-11-12 이력 "모델 이름의 머리에 따라 라이브러리가 요청을 바꾸는 것을 알려진 한계로 둔다"). 거부한 안: 하위 클래스가 요청 본문을 만드는 메서드(`_get_request_payload`)를 재정의해 바뀐 것을 되돌린다(라이브러리의 안쪽 메서드에 기대어 판을 올릴 때마다 깨질 수 있고, 그 이름의 실제 OpenAI 모델에는 라이브러리의 처리가 맞다). 거부한 안: 그런 `model_id`를 읽는 단계에서 거부한다(sdk가 라이브러리의 이름 규칙을 알게 되고, 게이트웨이 뒤의 OpenAI 모델을 쓰지 못한다).
- **알려진 한계, 환경의 헤더 변수 넷.** 키와 주소를 명시해도 `OPENAI_ORG_ID`는 `openai-organization` 헤더로, `OPENAI_ORGANIZATION`은 `OPENAI_ORG_ID`가 없을 때 같은 헤더로, `OPENAI_PROJECT_ID`는 `openai-project` 헤더로, `OPENAI_CUSTOM_HEADERS`는 거기 적은 헤더로 모델 서버에 닿는다(쟀다, `env_identity_headers_candidate`, `env_legacy_org_alone`). 두 라이브러리 모두 값이 없으면 환경에서 채우고(읽었다, langchain-openai 1.6.2의 `chat_models/base.py`, openai 3.49.0의 `lib/_client_auth.py`) 막는 길은 찾지 못했으며 해 보지 않았다. `OPENAI_ADMIN_KEY`와 `OPENAI_WEBHOOK_SECRET`은 닿지 않았다(같은 사례). 넷은 `serve`의 환경을 정하는 운영자의 변수이고 모델 서버의 키가 아니어서 이 명세는 막지 않는다. 배포 안내에 넘긴다(아래 "다른 기능에 넘기는 것").

### HTTP 클라이언트 (명세가 정했다)

- 어댑터는 모델을 만들 때마다 그 모델만 쓰는 비동기 HTTP 클라이언트를 새로 만들어 넘긴다. `openai.DefaultAsyncHttpxClient`에 한도 `httpx2.Limits(max_connections=1000, max_keepalive_connections=0)`을 준 것이다. 연결 수 1000은 라이브러리의 기본값 그대로이고 쉬는 연결의 수만 100에서 0으로 바꾼다(읽었다, openai 3.49.0의 `_constants.py`의 `DEFAULT_CONNECTION_LIMITS`). 모델을 만드는 것은 지금처럼 네트워크에 닿지 않는다(클라이언트는 첫 요청에서 연결한다).
- 모델마다 주는 까닭. 손대지 않은 모델은 라이브러리가 주소별로 캐시한 클라이언트를 나눠 쓰고(읽었다, langchain-openai 1.6.2의 `chat_models/_client_utils.py`, `_cached_async_httpx_client`), 같은 프로세스에서 이벤트 루프를 닫고 새로 연 뒤 같은 주소를 부르면 `RuntimeError("Event loop is closed")`로 실패한다(쟀다, `two_loops_same_url`). 모델마다 클라이언트를 주면 둘째 루프도 된다(`two_loops_own_client`, `two_loops_candidate`). 시험마다 `asyncio.run`을 따로 도는 pytest와, 한 프로세스에서 루프를 다시 만드는 실행 경로가 그 실패에 걸린다.
- 쉬는 연결을 두지 않는 까닭. 모델마다 준 클라이언트를 닫는 자리가 없다. core는 실행마다 모델을 만들고 놓을 뿐 닫지 않고, 포트 `ModelSource`에는 닫기가 없다(`.claude/rules/core.md`). 라이브러리 기본값의 클라이언트를 주면 한 루프에서 모델 다섯을 만들어 한 번씩 부르고 놓은 뒤 서버 쪽 연결 5개 가운데 닫힌 것이 0개였다. 놓기 전에 클라이언트를 닫은 양성 대조는 5개가 모두 닫혔고, 쉬는 연결을 두지 않는 클라이언트는 닫지 않고 놓아도 5개가 모두 닫혔다(쟀다, `runs_in_one_loop`). 그래서 `serve`처럼 루프 하나가 오래 도는 프로세스에서 실행마다 쉬는 연결이 하나씩 남지 않는다(어림. `serve`의 루프로 돌리지 않았다). 루프가 닫힌 뒤에 놓아도 이 클라이언트는 `ResourceWarning`을 내지 않았다. 기본값의 클라이언트는 1건을 냈다(쟀다, `candidate_released_after_loop_closed`, `keepalive_released_after_loop_closed`).
- 치르는 값은 호출마다 연결을 새로 맺는 것이다. https 주소에서는 호출마다 TLS 악수가 드는데 그 시간은 재지 않았다(가짜 모델 서버는 평문 HTTP다). 모델 하나를 여러 번 부르는 실행은 호출 수만큼 연결을 맺는다. 네 번 부르니 연결이 4개였고 기본값 클라이언트의 대조는 1개를 다시 썼다(쟀다, `calls_on_one_model`). 호출의 수는 `ctx.llm()` 한 번마다 턴 상한(에이전트 매니페스트의 `max_turns`, 없으면 10. ADR 0052)까지이고, 에이전트가 `ctx.llm()`을 여러 번 부를 수 있어 실행 전체의 상한은 없다(`core/loop.py`의 `run_loop` 독스트링을 읽었다). 지연을 재는 answer-eval에 넘긴다(아래 "다른 기능에 넘기는 것").
- 실패하거나 취소된 호출도 연결을 남기지 않았다. 401로 끝난 호출, 재시도가 든 500, 200에 JSON이 아닌 본문, 기한에 끊긴 호출의 연결이 모두 닫혔고, 기본값 클라이언트를 준 대조의 401은 연결 3개 가운데 하나도 닫히지 않았다(쟀다, `candidate_connections_after_failures`. 넣은 갈래 넷에서 본 것이다). 모델 하나를 놓지 않고 네 번 불렀을 때도 넷째 호출이 끝나고 1초를 기다린 시점(모델을 아직 쥐고 있을 때)에 연결 4개가 모두 닫혀 있었다(쟀다, `calls_on_one_model`). 두 사례의 셈은 모두 호출이 끝난 뒤 1초 이상을 기다리고 읽은 값이고, 호출이 끝난 바로 그 순간의 값은 재지 않았다. 그래서 포트에 닫기를 두지 않는다.
- 재지 않은 것은 Linux의 이벤트 루프다(README 질문 10). 이 절의 값은 모두 Windows(이 PC)의 것이다. 쉬는 연결을 두지 않는 것은 연결 풀의 설정이라 루프의 종류에 덜 기댈 것으로 본다(어림). 그 자리는 D의 어댑터 시험이 메운다. 가짜 모델 서버의 연결 셈으로 놓인 모델과 실패한 호출의 연결이 남지 않는 것을 보고(아래 "사례"), 그 시험은 CI의 리눅스 러너에서도 돈다. 리눅스 측정을 이 명세가 따로 하지 않은 것은 그 결과가 결정을 바꿀 수 있는 자리가 D의 시험이 빨개지는 자리와 같아서다.
- 거부한 안: 라이브러리가 나눠 쓰는 클라이언트를 그대로 쓴다(둘째 루프에서 실패한다). 거부한 안: 기본값의 클라이언트를 모델마다 준다(놓인 모델의 연결이 쌓인다). 거부한 안: 포트에 닫기를 더하거나 core가 실행 끝에 모델을 닫는다(포트의 모양이 바뀌어 ADR이 필요하고, Anthropic 모델에는 닫을 것이 없다). 거부한 안: 어댑터가 이벤트 루프마다 클라이언트를 캐시한다(루프의 수명을 어댑터가 따라가야 하고 닫는 자리는 여전히 없다).

### 키 (넘겨받았다. 키를 읽는 함수의 검사와 문구는 명세가 정했다)

- 어댑터는 `api_key`에 키를 읽는 함수 객체를 넘긴다. 라이브러리는 모델을 만들 때 그것을 부르지 않고 요청마다 한 번 부른다(쟀다, `key_function_per_request`). 재시도가 든 호출에서는 시도마다 다시 부르는 것으로 본다. 실을 수 없는 키로 재시도한 두 사례에서 호출 한 번에 세 번 불렸고(쟀다, `bad_key_newline_function`, `bad_key_trailing_space_function`), 429·500의 재시도에 키 함수를 준 사례는 없다. 부르는 스레드는 이벤트 루프의 스레드가 아니라 실행기의 스레드다(같은 사례). 함수는 환경을 읽기만 한다.
- 함수가 돌려주거나 던지는 것은 셋이다. 문구가 싣는 것은 변수 이름뿐이고 그 이름은 sdk의 패턴을 지났다.
  - `api_key_env`가 없으면 자리 채움 글자 `no-key`를 돌려준다. 서버에는 `Authorization: Bearer no-key`가 간다(쟀다, `guard_candidate_no_key_variable`). 비밀이 아니다.
  - 변수가 없거나 값이 비었으면 `RuntimeError("모델 서버의 키를 읽을 환경 변수 <이름> 가 없다")`를 던진다. 거부한 안: 빈 값을 키 없음으로 보고 자리 채움 글자를 보낸다(변수를 적은 운영자는 키를 보내려 한 것이라, 조용히 키 없이 붙으면 실수가 401이나 인증 없는 접속으로 숨는다).
  - 값에 인증 헤더로 보낼 수 없는 글자가 있으면 `RuntimeError("환경 변수 <이름> 의 값에 인증 헤더로 보낼 수 없는 글자가 있다")`를 던진다. 받는 값은 보이는 ASCII이고 공백은 가운데에만 온다. 라이브러리에 그대로 넘기면 끝에 개행이나 공백이 든 값은 요청 0건으로 1.25~1.42초의 재시도 뒤 `Connection error.`로 끝나며 원인 사슬의 글에 키가 실리고, ASCII가 아닌 값은 `UnicodeEncodeError`의 `repr`에 키가 실린다(쟀다, `bad_key_newline_string`, `bad_key_trailing_space_string`, `bad_key_unicode_string`과 함수로 준 셋). 함수가 막으면 요청 0건, 값 없는 글, 재시도 없음이다(쟀다, `guard_candidate_bad_key_newline`, `guard_candidate_bad_key_unicode`, `guard_candidate_bad_key_trailing_space`). 거부한 안: 앞뒤 공백을 떼어 보낸다(보내는 값이 환경의 값과 달라져, 서버가 뗀 값을 되울리면 아래 가리기가 환경의 값으로 찾지 못한다).
- 감싼 메서드는 라이브러리를 부르기 전에 이 함수를 한 번 먼저 부른다. 그래서 위 두 실패는 요청을 만들기 전에 그 문구 그대로 core에 닿는다(쟀다, `guard_candidate_missing_key`. 요청 0건, 원인 사슬 없음). 라이브러리 안에서 함수가 던진 예외도 그 객체 그대로 올라오지만(쟀다, `key_function_raises`) 아래 감싸기가 받아 `호출이 실패했다 (RuntimeError): …`로 한 겹 더 싸므로, 먼저 불러 문구를 하나로 둔다.
- 호출 때 읽으므로 환경의 값을 바꾸면 다음 요청의 헤더가 바뀌고, 만든 뒤 변수를 지우면 다음 호출이 없음의 실패다(쟀다, `guard_candidate_key_rotation`).
- core는 이 실패를 원인 `model_call`의 `run_failed`로 쓰고 메시지는 `RuntimeError: 모델 서버의 키를 읽을 환경 변수 <이름> 가 없다`다(`core/run.py`의 `_ask`와 `_describe`를 읽었다). 이어 가기의 대화 요약에서 나면 원인은 대화 요약이고 메시지가 "대화 요약이 실패했다"로 시작한다(`.claude/rules/core.md`의 대화 요약 항목).
- 키를 언제나 이름으로 넘기므로 환경의 `OPENAI_API_KEY`는 헤더와 본문 어디에도 없고 요청은 명시한 서버로만 간다(쟀다, `env_explicit_wins`). LangSmith 게이트웨이의 변수도 같다(`env_gateway_explicit_wins`). 스토리 6이 이것이다.

### 실패 문구와 되울린 키 (넘겨받았다. 감싸는 자리, 문구의 모양, 검증 예외가 싣는 것은 명세가 정했다)

- **자리.** 모델 서버 모듈의 `ChatOpenAI` 하위 클래스가 `_agenerate`와 `_generate`를 재정의해 감싼다. core는 어댑터가 만든 모델 객체에 `bind_tools`와 `ainvoke`를 바로 부르고 예외는 그 객체에서 올라오므로(읽었다, `core/loop.py`의 `model_caller`, `core/run.py`의 `_ask`) 어댑터가 설 자리는 객체 안이다. 루프의 길(`bind_tools` 뒤 `ainvoke`)과 `astream`과 동기 `invoke`가 재정의를 지난다(쟀다, `guard_paths`, `guard_candidate_astream_401`, `guard_candidate_invoke_401`). 재정의는 `**kwargs: object`로 받아 `Any` 없이 pyright strict를 지나고 진단과 타입 우회가 0개였다(쟀다, `check_adapter_types.py`의 다섯 회차). 거부한 안: `BaseChatModel`을 새로 구현해 안에 `ChatOpenAI`를 들고 위임한다(`bind_tools`와 구조화 출력까지 위임할 것이 늘고, 하위 클래스로 선다).
- **받는 것.** `Exception` 전부를 받는다. `openai.OpenAIError`만 받으면 200 응답의 `error` 칸이 내는 내장 `ValueError`가 그대로 지나가 키가 글에 실린다(쟀다, `guard_first_plan_ok_error_body`). 취소(`CancelledError`)는 `Exception`이 아니라 받지 않아 실행 타임아웃이 그대로 듣는다(쟀다, `guard_candidate_cancelled`).
- **원인을 잇지 않는다.** 바꾼 예외는 `except` 블록 밖에서 던져 `__cause__`도 `__context__`도 없다. 안에서 `from None`으로 던지면 맨 위 글은 가려져도 `__context__`에 원래 예외가 남고 그 글·`body`·요청 헤더에 키가 있다(쟀다, `guard_first_plan_401`). MCP 어댑터가 되울린 헤더 값을 가린 문구에 원인을 남기지 않는 것과 같은 까닭이다(`.claude/rules/adapters.md`). 거부한 안: `openai.OpenAIError`만 받아 `except` 안에서 `from None`으로 던진다(이 명세가 프로브를 짓기 전에 세운 첫째 안의 꼴이다. 위 두 군데가 샌다).
- **문구 넷.** `<주소>`는 모델 파일의 `base_url`을 글자 그대로 실은 것이고 찍히지 않는 글자만 이스케이프한다. ADR 0057 결정 "주소는 비밀이 아닌 것으로 본다"가 주소는 실패 문구에 그대로 실린다고 정했고, MCP 어댑터가 원격 서버의 주소를 싣는 방식과 같다(`adapters/mcp.py`의 `_where`를 읽었다). 경로까지 실려 `/v1`을 빠뜨린 주소가 문구에서 보인다. 경로에 공백, 한글, 유니코드 줄 구분 문자(U+2028)가 든 주소는 글자 그대로 실리되 줄 구분 문자만 이스케이프한 꼴로 실렸다(쟀다, `guard_candidate_odd_url_401`). ASCII 제어 문자가 든 주소는 모델을 만들다 거부되어 여기까지 오지 않는다(위 "모델 소스와 모듈"). 거부한 안: 스킴과 호스트와 포트만 싣는다(셀프 리뷰 전의 안이다. ADR 0057의 그 결정과 어긋나고, 경로를 잃어 주소를 잘못 적은 것을 문구로 가르지 못한다. 그 안이 막으려던 사용자 정보와 쿼리는 읽는 단계가 거부한다). `<글>`은 원래 예외의 `str`에서 키 값을 글자 그대로 찾아 `***`로 바꾼 것이다. 찾는 값은 둘이다. 감싼 메서드가 라이브러리를 부르기 전에 먼저 읽어 둔 값(위 "키")과, 예외를 바꾸는 때의 환경 값이다(까닭은 아래 "되울린 키의 한계").
  - 상태 오류(`openai.APIStatusError`)는 `RuntimeError("모델 서버 <주소> 가 요청을 거절했다 (HTTP <코드>): <글>")`다. 쟀다: `모델 서버 http://127.0.0.1:<포트>/v1 가 요청을 거절했다 (HTTP 401): Error code: 401 - Incorrect API key provided: ***. 키를 확인하라.`(`guard_candidate_401`. 500은 코드만 다른 같은 꼴이다, `guard_candidate_500`).
  - 연결 오류(`openai.APIConnectionError`. 시간 초과 `APITimeoutError`는 그 하위다, 읽었다 openai 3.49.0의 `_exceptions.py`)는 `ConnectionError("모델 서버 <주소> 에 닿지 못했다: <글>")`다. 글은 `Connection error.`뿐이다(쟀다, `guard_candidate_closed_port`).
  - 검증 예외(`pydantic.ValidationError`)는 `RuntimeError("모델 서버 <주소> 의 응답을 읽지 못했다: <자리> 의 꼴이 틀렸다")`다. `<자리>`는 오류마다의 위치(`loc`)를 점으로 이은 것이고 여럿이면 쉼표로 잇는다. 원래 글은 틀린 값을 `input_value`로 되울려 도구 호출의 인자가 실린다(쟀다, `tool_args_not_object`, `tool_args_object_value`). 쟀다: 인자가 `["args-secret-6e1f", 2]`이면 `… 의 응답을 읽지 못했다: tool_calls.0.args 의 꼴이 틀렸다`이고, 글이 아닌 객체로 온 인자는 자리가 `invalid_tool_calls.0.args`이며 두 글에 그 인자의 글자가 없다(`guard_candidate_args_not_object`, `guard_candidate_args_object_value`). 도구 이름은 싣지 않는다. 입력 없이 종류와 자리만 싣는 선례는 `filesystem.py`와 `jsonl.py`의 `_describe`다(읽었다). 거부한 안: 검증 예외도 다른 예외처럼 글을 싣고 키만 가린다(가려야 할 인자는 키가 아니라 `secret_args`라 어댑터가 그 값을 모른다).
  - 그 밖은 `RuntimeError("모델 서버 <주소> 호출이 실패했다 (<원래 예외의 종류 이름>): <글>")`다. 200 응답의 `error` 칸(`ValueError`), JSON이 아닌 200 본문(`ValueError`, 본문이 글에 실린다), `choices`가 `null`인 본문(`TypeError`)이 여기 든다(쟀다, `guard_candidate_ok_error_body`, `guard_candidate_not_json`, `guard_candidate_null_choices`).
- **타입은 내장이다.** core는 원인을 예외의 타입이 아니라 `blamed("model_call")`의 자리로 정하므로(`.claude/rules/core.md`의 실패 정책) 타입은 `run_failed.error`의 머리(`_describe`의 `<종류>: `)에만 보인다. 그래서 꺼진 서버는 `ConnectionError: 모델 서버 http://… 에 닿지 못했다: Connection error.`이고 틀린 키는 `RuntimeError: 모델 서버 http://… 가 요청을 거절했다 (HTTP 401): …`라 실패 내용만으로 갈린다(스토리 8). 최종 사용자 면에는 지금의 `model_call` 고정 문구가 뜬다(ADR 0057 Consequences "최종 사용자에게 보이는 것").
- **연결 오류의 원인은 싣지 않는다.** 원인 사슬의 맨 안쪽(`ConnectionRefusedError([WinError 1225] …)` 등)을 싣지 않아 닿지 못한 까닭(거부, 이름 풀이, TLS)은 글에서 갈리지 않는다. 거부한 안: 원인 사슬의 맨 안쪽 글을 덧붙인다(실을 수 없는 키를 라이브러리에 넘긴 사례에서 그 사슬의 글이 키를 실었다, `bad_key_newline_string`. 지금은 그 값을 함수가 먼저 막지만, 사슬의 글이 무엇을 싣는지는 httpx2·httpcore2·h11의 판에 달린다).
- **되울린 키의 한계.** 가리는 것은 위 두 값을 글자 그대로 찾은 것뿐이다. 서버가 값을 잘라 내거나 인코딩해 되울리면 놓친다(ADR 0057 그대로. 사례는 없다). 값을 둘 찾는 까닭은 호출 도중에 환경의 값이 바뀌는 때다. 예외를 바꾸는 때의 값만 찾으면, 요청이 나간 뒤 환경의 값이 바뀐 호출에서 서버가 되울린 옛 값이 문구에 남는다. 도중에 한 번 바뀌면 보낸 값은 그 둘 가운데 하나이고, 한 호출 안에서 두 번 이상 바뀌면 가운데 값을 놓칠 수 있다. 이 갈래는 프로브로 재지 않았다. 후보(`adapter_candidate.py`의 `KeySource.masked`)가 그 모양이고 D의 어댑터 시험이 본다(아래 "사례"의 실패). 거부한 안: 예외를 바꾸는 때의 환경 값만 가린다(PR 직전 리뷰 전의 안이다. 위의 호출에서 옛 키가 `run_failed`의 문구로 트레이스에 남는다). 사용자 정보가 든 주소가 어댑터까지 오면 키 대신 Basic 인증이 가고, 그 주소의 암호 글자와 서버가 되울린 Basic 값이 둘 다 문구에 실린다(쟀다, `guard_candidate_userinfo_401`). 쿼리가 든 주소도 문구에 쿼리째 실린다(후보에 그런 주소를 넣은 `logs_401_query_url`의 예외 글을 저장한 출력에서 손으로 봤다, README 질문 7의 "후보의 한계"). 그 둘은 읽는 단계에서 거부되어 어댑터까지 오지 않는다(위 "매니페스트"). 주소를 글자 그대로 싣는 이 문구는 읽는 단계의 그 두 거부를 전제로 선다. 거부한 안: 서버의 글을 빼고 상태 코드만 남긴다(서버가 준 까닭, 예컨대 모델 이름이 틀렸다는 404의 글을 잃는다).

### 인자가 깨진 도구 호출 (넘겨받았다. 확인하는 자리와 문구는 명세가 정했다)

- 라이브러리는 인자가 올바른 JSON이 아닌 도구 호출을 예외 없이 `tool_calls`에서 빼 `invalid_tool_calls`에 넣고 글을 빈 문자열로 둔다(쟀다, `tool_args_broken`). 지금의 `reply_from`은 `tool_calls`만 읽어(`core/model.py`를 읽었다) 루프가 그 응답을 빈 최종 답으로 받는다.
- 확인하는 자리는 `core/model.py`의 `reply_from`이다. 메시지의 `invalid_tool_calls`가 비어 있지 않으면 `ValueError("모델이 낸 도구 호출의 인자가 올바른 JSON 이 아니다: <이름들>")`을 던진다. `<이름들>`은 깨진 호출의 도구 이름을 응답의 순서대로 쉼표로 이은 것이고, 이름이 비었으면 `(이름 없음)`이다(이름이 빈 깨진 호출은 쟀다, `tool_args_broken_empty_name`). 깨진 인자의 글과 라이브러리의 `error` 글은 싣지 않는다. 뒤의 것도 받은 글을 싣는다(쟀다, `tool_args_broken`). 그 모듈은 모델이 돌려준 것을 우리 타입으로 바꾸는 경계라(그 독스트링) 바꾸지 못하는 응답을 거기서 거절한다.
- 멀쩡한 호출과 깨진 호출이 섞인 응답도 실패다. 라이브러리는 앞의 것을 `tool_calls`에, 뒤의 것을 `invalid_tool_calls`에 나눠 넣는다(쟀다, `tool_args_mixed`). 거부한 안: 멀쩡한 것만 부른다(모델이 낸 호출의 일부만 실행되고 빠진 것이 트레이스에 남지 않는다).
- `_ask`가 `reply_from`을 `blamed("model_call")` 안에서 부르므로(`core/run.py`를 읽었다) 원인은 `model_call`이고 `run_failed.error`는 `ValueError: 모델이 낸 도구 호출의 인자가 올바른 JSON 이 아니다: add`다. 그 모델 호출의 `llm_called`는 남지 않는다(`_record_model_call`이 `reply_from`의 결과를 받는다). 도구도 불리지 않아 `tool_called`가 없다. 대화 요약도 `reply_from`을 부르지만(`core/continuation.py`를 읽었다) 도구를 붙이지 않아 깨진 호출이 나올 길이 없다(어림). 거부한 안: `llm_called`를 쓴 뒤 실패한다(그 이벤트가 도구 호출 없는 빈 답이라 최종 답처럼 읽히고, 기록 뒤에 확인을 따로 둬야 한다. 고른 안이 치르는 값은 그 호출의 토큰 수가 트레이스에 남지 않는 것이다). 거부한 안: 어댑터가 확인한다(제공사마다 같은 확인을 따로 두게 된다).
- 확인은 제공사를 가리지 않는다. `invalid_tool_calls`는 langchain-core `AIMessage`의 칸이라 Anthropic 모델의 응답에도 있다. `ChatAnthropic`이 비스트리밍 응답에서 그 칸을 채우는지는 보지 않았다.
- 이 확인 밖의 꼴은 셋이다. 인자가 빈 글이나 `null`이면 `args {}`인 멀쩡한 호출이다(쟀다, `tool_args_empty_string`, `tool_args_null`). 인자가 멀쩡하고 이름만 빈 호출은 `tool_calls`에 이름 `""`로 들고(쟀다, `tool_args_valid_empty_name`), 루프가 연결에 없는 이름으로 `tool_called(ok=false)`를 모델에 돌려준다(`.claude/rules/core.md`의 승인 게이트 항목). `id`가 없는 호출은 지금처럼 `""`로 읽힌다(쟀다, `tool_call_missing_id`).
- JSON이지만 객체가 아닌 인자와 글이 아닌 객체로 온 인자는 `reply_from`에 오기 전에 라이브러리의 검증 예외로 끝나 위 "실패 문구와 되울린 키"의 검증 예외 문구가 된다. 원인은 같은 `model_call`이고 도구 이름은 없다. ADR 0057 결정 "인자가 깨진 도구 호출"은 "인자가 올바른 JSON이 아니면"을 말하므로 이 둘에서 이름이 없는 것이 그 문장을 거짓으로 만들지 않는다.
- 계약과 웹 화면은 바뀌지 않는다(ADR 0057).

### 로그 (넘겨받았다. 시험의 모양은 명세가 정했다)

- 루트 로거를 DEBUG로 두고 모은 레코드에 키 값, `Bearer `라는 글자, 프롬프트가 없었다. 손대지 않은 모델과 후보, 성공과 401 모두다(쟀다, `logs_success_plain`, `logs_success_candidate`, `logs_401_plain`, `logs_401_candidate`). 찍히는 것은 `openai._base_client`의 요청 단계, `httpcore2`의 연결 단계와 응답 헤더의 값, `httpx2`의 INFO 요청 줄(주소 전체)이다. 요청 헤더의 값은 찍히지 않는다.
- 주소는 `httpx2`의 INFO 줄에 쿼리째 실렸다(쟀다, `logs_401_query_url`). 쿼리는 읽는 단계에서 거부되므로(위 "매니페스트") 그 길은 닫힌다.
- 수락 시험(D). 키를 적은 모델로 가짜 모델 서버를 부르며 루트 로거를 DEBUG로 켜고 모은 모든 레코드의 메시지와 인자에 키 값이 없다는 것을 본다. 갈래는 성공과 401(서버가 키를 되울린다) 둘이다. 표지 둘을 함께 단언한다. 가짜 모델 서버가 그 키를 받았다, 레코드에 `httpx2`의 요청 줄이 있다(로그를 실제로 모았다).
- 막는 장치(로그 필터)는 두지 않는다. 라이브러리의 판을 올리면 이 시험이 다시 본다. 거부한 안: 라이브러리 로거에 필터를 단다(키와 프롬프트는 지금 찍히지 않아 막을 것이 없는 코드가 되고, 다른 로거로 옮겨 찍히면 놓친다. 아래 응답 헤더의 값은 어느 것이 비밀인지 어댑터가 알지 못한다. MCP 어댑터가 `mcp.client.streamable_http`의 DEBUG 기록을 통째로 버리는 필터를 두는 것은 거기서는 도구 호출의 인자가 찍혀 막을 것이 있었기 때문이다(`adapters/mcp.py`를 읽었다). 여기서 `httpcore2`의 DEBUG 기록을 통째로 버리면 응답 헤더와 함께 접속 단계의 기록(위 첫 항목)도 사라져, 접속이 안 되는 까닭을 살피려 로그를 켠 운영자가 볼 것이 없어진다).
- 받아들인 한계는 응답 헤더다. `httpcore2`의 DEBUG 줄이 응답 헤더의 값을 찍으므로(위 첫 항목), 모델 서버나 그 앞의 게이트웨이가 응답 헤더에 비밀을 실으면 그 값이 DEBUG 로그에 남는다. 받은 키를 헤더로 되울리는 서버와 세션 쿠키를 `Set-Cookie`로 주는 게이트웨이가 그 꼴이다. 그런 서버로 재지는 않았고 위 측정에서 따라 나오는 것이다. 수락 시험의 갈래에는 넣지 않는다. 막는 장치가 없어 그 갈래는 통과할 수 없는 시험이 되기 때문이다. 루트 로거를 DEBUG로 켜는 것은 운영자의 선택이라 배포 안내가 알린다(아래 "다른 기능에 넘기는 것").

### 의존 (넘겨받았다)

- `langchain-openai`를 런타임 의존으로 선언한다. 어댑터가 `openai`의 예외 타입과 클라이언트(`DefaultAsyncHttpxClient`)를 직접 import하므로(위 "HTTP 클라이언트"와 "실패 문구와 되울린 키") `openai`도 직접 의존으로 선언한다(ADR 0057 결정 "의존"이 건 조건이다). 판의 묶음은 의존을 들이는 묶음이 `uv lock`으로 풀어 본 뒤 정한다. 저장소 락의 판을 제약으로 걸고 `langchain-openai==1.6.2`를 얹으면 새로 드는 패키지는 넷(`langchain-openai` 1.6.2, `openai` 3.49.0, `regex` 2026.11.9, `tiktoken` 0.14.0)이고 락에서 판이 바뀌는 패키지는 없었다(쟀다, `make_env.py`).
- 어댑터가 직접 쓰는 `httpx2`(클라이언트의 한도 `Limits`와 타입)와 `pydantic`(검증 예외)은 이미 런타임 직접 의존이다(`pyproject.toml`을 읽었다. `httpx2>=2.13,<3`은 ADR 0049가 들였다). openai 3.49.0도 HTTP를 `httpx2`로 보낸다(쟀다, 예외의 원인 사슬과 로거 이름).
- import-linter의 금지 목록 둘("core knows no provider", "sdk knows no engine")에 `langchain_openai`와 `openai`를 더한다.
- `docs/constitution/tech.md` 런타임 의존성 행의 "local-model의 구현 티켓이 선언하고 … 그때까지 `pyproject.toml`에는 없다"를 들인 사실로 고치고 헌법 판을 올린다(설계 일지 "다음"의 셋째).

### 로컬 모델 시험 (넘겨받았다. 환경 변수의 이름과 시험의 모양은 명세가 정했다)

- 마커는 `llm_local`이다. `pyproject.toml`의 마커 선언과 기본 실행의 제외(`addopts`)에 더하고, `tests/conftest.py`의 실제 모델 마커 목록에 더해 다른 실제 모델 시험과 같이 실행 끝에 토큰 합계가 찍히게 한다.
- 시험은 시험 파일 하나에 모은다. calc 예시를 CLI 프로세스로 돌리는 사례 하나를 두 모델로 매개변수화한 것이고, 선례는 `tests/test_main.py`의 `test_calc_에이전트가_실제_모델로_답하고_트레이스에_모델_호출이_남는다`다. 저장소의 플러그인을 임시 루트에 복사하고 거기에 `openai-compatible` 모델 파일 하나를 적어 넣은 뒤 `--model`로 그 이름을 준다. calc의 MCP 서버는 저장소의 `everything` 그대로다(`-m llm`과 같아 Node가 있어야 한다).
- 시험이 적는 모델 파일은 `base_url`과 `model_id`를 환경 변수에서 받고, `temperature = 0`을 적으며, `max_tokens`는 적지 않는다(모델 서버의 기본값을 쓴다). 키 변수가 환경에 있으면 `api_key_env`에 그 변수의 이름을 적고, 없으면 그 칸을 적지 않는다. 시험은 키 값을 읽지 않는다. 런타임이 그 이름으로 스스로 읽는다.
- 환경 변수는 모델마다 셋이고 `<n>`은 1과 2다. `AGENT_OS_LLM_LOCAL_<n>_BASE_URL`(필수), `AGENT_OS_LLM_LOCAL_<n>_MODEL_ID`(필수), `AGENT_OS_LLM_LOCAL_<n>_API_KEY`(선택). 필수 넷 가운데 하나라도 없으면 skip이 아니라 실패하고 문구가 없는 변수의 이름을 든다(원칙 II, ADR 0058 결정 "시험은 두 층이다"). 사용자가 다른 곳에 띄운 모델 서버로도 이 변수만 채워 같은 시험을 돌린다(ADR 0058 결정 "띄우지 못할 때"). 거부한 안: 키 변수를 두 모델이 함께 쓰는 하나로 둔다(따로 띄운 서버 둘의 키가 다를 수 있다).
- 단언은 `-m llm`의 calc 시험과 같고 두 군데만 다르다(그 시험의 단언을 읽었다, `tests/test_main.py`). 같은 것은 종료 코드 0, 출력에 계산 결과, 트레이스의 마지막이 `run_finished`, 도구 호출이 든 `llm_called`, 인자와 결과가 찬 `tool_called`, 저장소의 스킬 문서 본문이 첫 프롬프트에 있다는 것이다. 트레이스에 도구 호출이 남아야 통과하므로 도구 호출이 글로 샌 조합은 통과로 읽히지 않는다(ADR 0058 결정 "로컬 모델 시험이 보는 것"). 다른 것의 첫째는 `tool_called` 가운데 성공한 것(`ok`가 참)이 하나 이상 있어야 한다는 것이다. `-m llm`의 시험은 도구 호출이 있는지와 인자·결과가 찼는지만 본다. 둘째는 모델 이름이다. `-m llm`의 시험은 모든 `llm_called.model`이 매니페스트의 `model_id`와 같은지를 보는데, 여기서는 비어 있지 않고 `unknown`이 아닌지만 본다. 모델 서버가 응답에 싣는 모델 이름이 `model_id`와 글자 그대로 같은지는 서빙 엔진의 몫이라 단언하지 않고 기록에 남긴다(어림. vLLM이 무엇을 싣는지는 모델 서버를 띄워 확인하는 묶음이 본다).
- 시험 안에 다시 시도를 두지 않는다. 한 번 실패하면 실패다(ADR 0058). 모델 서버가 준비됐는지는 시험이 아니라 아래 명령이 본다.

### 모델 서버를 띄우는 명령 (넘겨받았다. 자리, 구성, 타이머, 걸음, 잠금, 청소, 무효 회차는 명세가 정했다. 돌려 보지 않았다)

이 절의 구성과 걸음은 문서의 원문과 이 PC에서 본 것으로 정했고 클라우드에서 돌려 보지 않았다. 실제로 띄워 확인하는 것은 이 명령을 들이는 묶음의 일이고(ADR 0058 Consequences "서버를 띄우는 파일을 들이는 티켓이 띄워 확인하는 것"), 사용자가 그 때를 골랐다(일지 2026-11-12-0248 "사용자에게 물은 것 셋"의 둘째). 미리 적은 구성이 모두 서지 않으면 그 묶음이 멈춰 사용자에게 다시 묻는다.

**자리.** 스크립트는 `tools/llm_local.py`이고 Terraform 구성은 그 옆 폴더 `tools/llm_local_server/`다. 둘 다 로컬 모델 시험 자신으로 세어 병합 조건의 범위에 든다(ADR 0058 결정 "병합 조건의 범위"). 워크트리에서는 `uv run --env-file ../../../.env python tools/llm_local.py run`으로 부른다. 주 체크아웃의 `.env`가 `RUNPOD_API_KEY`를 프로세스 환경으로 넘기고 세션은 그 값을 읽지 않는다. 워크트리 세션에서 같은 꼴의 명령(`uv run --env-file ../../../.env python <스크립트>`) 하나가 `.env` 읽기 훅과 데스크톱 앱의 가드를 지나 그 파일의 변수를 환경으로 넘긴 것은 쟀다(`outside_worktree.py`의 둘째 명령. 표지는 그 파일에 있는 `ANTHROPIC_API_KEY`가 환경에 있다는 것이고, `--env-file` 없이 친 첫째 명령의 환경에는 그 변수가 없었다). 가드는 같은 꼴의 명령에도 결과가 갈린 적이 있어(`CLAUDE.md` 환경 함정) 한 번 지난 것이 언제나 지난다는 뜻은 아니다.

**하위 명령.** `run`은 띄우기부터 지우기까지를 잇고, `sweep`은 남은 것만 치운다. `run`은 `--yes` 없이 치면 예상 비용만 찍고 아무것도 띄우지 않은 채 끝난다. 세션은 그 출력을 사용자에게 보여 확인을 받은 뒤 `--yes`를 붙여 다시 친다(ADR 0058 결정 "비용 확인"). `run`은 `--` 뒤에 모델 서버가 떠 있는 동안 돌릴 명령을 받고 기본은 `uv run pytest -m llm_local`이다. 모델 서버를 띄워 확인하는 묶음과 기본 에이전트의 사례를 기록하는 묶음이 그 자리에 다른 명령을 넣는다.

**구성.** 차례로 시도할 구성은 셋이고 첫째가 기본이다.

1. 모델마다 파드 하나씩을 한 번의 `terraform apply`로 나란히 띄운다. GPU는 24GB 이상이고 후보의 차례는 RTX A5000, RTX 3090, A40(48GB)이다. 재고가 없으면 다음 후보로 간다. 이미지는 vLLM의 공식 이미지 0.33.0 판이고 파드마다 서버 하나가 뜬다. 후보 셋은 모두 Ampere 세대다. gpt-oss의 vLLM 안내는 H100·H200·B200을 들고 "Ampere, Ada Lovelace, RTX 5090"은 작업 중이라고 적으면서, 같은 글의 A100 절은 Ampere 장치에서 기본으로 돈다고 적는다(설계 세션이 받아 둔 원문을 읽었다, 일지 2026-11-12-0248 "묻기 전에 원문에서 본 것"). 두 문장이 엇갈리므로 A100과 같은 세대인 이 셋에서 gpt-oss-20b가 도는지는 띄워 봐야 알고, Ada 세대(L4, RTX 4090)보다 앞에 둔 근거는 A100 절 하나다(어림). 두 모델의 가중치는 14.52GB와 13.76GB다(ADR 0058 "모델 후보").
2. A40 한 장의 파드 하나에 서버 둘을 띄운다(ADR 0058이 어림한 구성). 파드의 시작 명령을 셸로 바꿀 수 있어야 하고, 두 서버가 GPU 메모리를 반씩 쓰게 `--gpu-memory-utilization`을 준다.
3. 파드 하나에 모델을 차례로 올린다. 첫 모델로 시험하고 지운 뒤 둘째 모델로 다시 띄워 시험한다. 시간이 두 배 가까이 든다.

첫째를 기본으로 둔 까닭은 공식 이미지가 서버 하나를 띄우는 모양 그대로이고 두 모델이 함께 준비되기 때문이다. 요금은 A5000 둘이 시간당 $0.54, A40 하나가 $0.59다(Runpod 가격 페이지의 원문, 2026-11-11에 받았다. Community와 Secure 가운데 어느 값인지는 가르지 못했다). 거부한 안: 둘째를 기본으로 둔다(시작 명령을 셸로 바꾸는 것과 48GB에 둘이 오르는 것, 두 가지가 모두 서야 한다).

주소는 Runpod의 프록시 주소 `https://<파드 ID>-8000.proxy.runpod.net/v1`이다(문서의 꼴을 읽었다). 파드의 포트는 `8000/http` 하나만 연다. 영구 볼륨을 두지 않고 컨테이너 디스크만 쓴다. 그래서 가중치는 띄울 때마다 새로 받는다.

**서버 옵션.** 두 서버 모두 `--api-key`(아래의 서버 키)와 `--enable-auto-tool-choice`를 받고, 파서는 A.X 4.0 Light가 `--tool-call-parser hermes`, gpt-oss-20b가 `--tool-call-parser openai`다(모델 카드와 vLLM 안내의 원문). 도구 호출이 되지 않으면 같은 기준의 다음 후보(A.X 3.1 Light, Ministral 3 8B)로 바꾸고 까닭을 일지에 적는다(ADR 0058 결정 "두 모델"). 서버에 준 옵션은 키를 뺀 글자 그대로 기록 묶음에 남는다.

**타이머.** 파드는 시작 명령이 서버를 띄우기 전에 건 타이머와 함께 뜬다. 타이머는 90분 뒤 그 파드를 멈추지 않고 지운다. 멈춘 파드는 디스크 요금이 계속 나가기 때문이다(ADR 0058 결정 "서버를 막는 것"). 값 90분은 준비 상한 30분에 시험과 여유를 더한 것이고, 확인받는 예상 비용의 상한이 된다. 타이머를 거는 방법은 차례로 둘이다.

1. 공식 이미지에서 파드의 시작 명령을 셸로 바꿔 `sleep` 뒤 지우는 명령을 백그라운드로 걸고 서버를 띄운다. Terraform 프로바이더의 문서는 시작 명령을 `args`로 정한다고 적고 읽기 전용 칸 `docker_entrypoint`의 예로 `["/bin/bash", "-c"]`를 든다. Runpod 문서는 파드 안에서 `sleep 2h; runpodctl pod stop $RUNPOD_POD_ID &`로 멈춤을 예약하는 예시와 `runpodctl pod delete`를 싣는다(둘 다 원문을 읽었다). 공식 이미지에 `runpodctl`이 들어 있는지와 `args`가 이미지의 시작 명령을 실제로 바꾸는지는 모른다. `runpodctl`이 없으면 같은 문서의 REST 호출(`DELETE /v2/pods/<파드 ID>`)을 파드에 주입된 키로 부른다.
2. 셸로 시작하는 Runpod의 기본 이미지에서 같은 타이머를 걸고 같은 판의 vLLM을 설치해 띄운다. 준비 시간이 늘어난다.

둘 다 서지 않으면 모델 서버를 띄워 확인하는 묶음이 멈춰 사용자에게 묻는다. "스스로 꺼지게 걸린 채로 뜬다"(ADR 0058)를 지키지 못하는 구성으로는 띄우지 않는다.

**`run`의 걸음.**

1. 환경을 본다. `RUNPOD_API_KEY`가 환경에 있는지(이름만 본다), Terraform이 1.6 이상인지, 브랜치가 있는지(분리 HEAD면 거부한다). 없는 것을 이름으로 들고 끝난다.
2. 상태 폴더를 정한다. 사용자 홈 아래 `.agent-os/llm-local/<브랜치 이름>/`이고(브랜치 이름의 `/`는 폴더 이름에 쓸 수 있는 글자로 바꾼다) Terraform의 상태 파일과 작업 폴더(`TF_DATA_DIR`)가 그 안에 선다. 저장소와 워크트리 밖이라 워크트리가 지워져도 남고, 브랜치마다 따로라 나란히 도는 세션이 서로의 서버를 지우지 않는다(ADR 0058 결정 "상태 파일"). 워크트리 세션이 띄운 파이썬 프로세스가 사용자 홈 아래에 폴더를 만들어 파일을 쓰고 읽고 지운 것은 쟀다(`outside_worktree.py`의 "워크트리 밖 쓰기" 회차). Terraform이 같은 자리에 쓰는 것은 재지 않았다(같은 사용자의 프로세스라 같으리라는 어림이다).
3. 잠금을 본다. 상태 폴더의 잠금 파일은 그 폴더를 쓰는 `run`의 프로세스 번호와 시작 시각을 든다. 그 번호의 프로세스가 살아 있고 그 명령줄이 이 스크립트의 `run`이면 앞 세션의 명령이 아직 쓰고 있는 것이라, 아무것도 건드리지 않고 그렇게 말하고 끝난다. 번호가 죽었거나 다른 프로세스가 받은 번호면 죽은 잠금이다. 프로세스 번호만 보지 않는 까닭은 번호가 다시 쓰이기 때문이다(`.claude/rules/probes.md`의 프로세스를 끄는 탐침 항목과 같은 판정. `tools/proc_command_line.py`가 명령줄을 읽는 선례다).
4. 남은 것을 지운다. 죽은 잠금 아래 상태 파일에 자원이 남아 있으면 `terraform destroy`로 먼저 지운다(ADR 0058이 명세로 넘긴 "남은 서버를 먼저 지우는지"의 답이다).
5. 예상 비용을 찍는다. GPU 후보마다 단가와 파드 수, 어림 시간(30분)의 값과 타이머까지 간 최악(90분)의 값이다. 단가는 스크립트의 표가 들고 표에 옮긴 날짜를 적는다. `--yes`가 없으면 여기서 끝난다.
6. 서버 키를 만든다. 무작위 값이고 Terraform에는 환경 변수(`TF_VAR_…`)로, 시험에는 `AGENT_OS_LLM_LOCAL_<n>_API_KEY`로 넘긴다. 화면에도 로그에도 파일에도 찍지 않는다. Terraform의 상태 파일에는 평문으로 남을 수 있고 그 파일은 저장소 밖이며 키는 서버와 함께 죽는다(ADR 0058 Consequences "비밀").
7. 띄운다. 재고가 없어 실패하면 다음 GPU 후보로 간다. 띄운 뒤 Terraform이 돌려준 시간당 값(`cost`)의 합이 예상에 쓴 단가의 합보다 크면 지우고 끝난다. 확인받은 값보다 비싸게 돌리지 않는다.
8. 준비를 기다린다. 두 서버의 모델 목록(`GET <주소>/models`, 키 헤더를 싣는다)이 200으로 그 모델을 낼 때까지이고 상한은 30분이다. 넘으면 지우고 끝난다. 상한은 모델 서버를 띄워 확인하는 묶음이 잰 준비 시간으로 다시 맞춘다(10~20분은 ADR 0058의 어림이다).
9. 시험을 자식 프로세스로 돌린다. 환경 변수 여섯을 채워 넘긴다.
10. 시험이 실패했으면 지우기 전에 두 서버의 모델 목록을 한 번 더 본다(아래 "무효 회차").
11. 지운다. 시험이 어떻게 끝났든, 중간에 끊겨도(Ctrl-C) 지운다. 지우기가 실패하면 상태 폴더의 경로와 함께 크게 알린다. 그때는 타이머가 뒤를 받친다.
12. 기록 묶음을 찍는다. 시험한 커밋, 두 모델의 이름, 서빙 엔진의 판과 서버 옵션, GPU의 종류, 통과 수와 토큰 합계, 걸린 시간, 실제 단가다. 세션이 그것을 PR 코멘트와 일지에 옮긴다(ADR 0058 결정 "언제 돌리고 무엇을 남기는가"). 묶음에 서버 키와 주소는 넣지 않는다.

종료 코드는 다섯으로 가른다. 0은 시험 통과, 1은 시험 실패, 2는 무효 회차, 3은 지우기 실패, 4는 아무것도 띄우지 않고 끝난 것(걸음 1의 환경이 모자라다, 걸음 3의 앞 세션이 쓰고 있다, 걸음 5에서 `--yes`가 없어 예상 비용만 찍었다)이다. 4를 0과 가르는 것은 확인을 받으려 친 첫 호출이 시험 통과로 읽히지 않게 하려는 것이다. 겹칠 때의 차례는 3, 2, 1이다. 지우기 실패(3)가 다른 결과를 이기고, 그때 시험이 어떻게 끝났는지는 기록 묶음에 남는다. 걸음 4에서 앞 세션이 남긴 것을 지우지 못해도 3이고 그때는 새로 띄우지 않는다. 그다음이 무효 회차(2)이고, 걸음 7에서 GPU 후보 셋 모두 재고가 없을 때도 2다. 시험 실패(1)는 서버가 살아 있던 회차에만 낸다. 4는 띄우기를 시작하기 전에 끝난 때에만 낸다. 걸음 1·3·5에서 끝난 때와 걸음 7 전에 Ctrl-C로 끊긴 때다. 걸음 4가 앞 세션이 남긴 것을 지운 뒤 걸음 5에서 `--yes`가 없어 끝난 때도 4이고, 무엇을 지웠는지는 출력에 남긴다. 남은 것을 지우는 일은 요금을 줄이기만 하므로 비용 확인을 기다리지 않는다. 거부한 안: 걸음 4의 지우기를 `--yes` 뒤로 미룬다(확인을 기다리는 동안 남은 서버의 요금이 타이머가 지울 때까지 나간다). 걸음 9의 시험이 시간 제한에 걸리면 실패한 시험으로 보고 걸음 10의 확인을 거친다. 서버가 살아 있으면 1이고 아니면 2다. Ctrl-C로 끊긴 회차는 걸음 7에서 띄우기를 시작한 뒤면 걸음 11대로 지운 뒤 2이고(지우지 못하면 3), 그 전이면 4다(걸음 4의 지우기가 끊겨 남은 것이 있으면 위대로 3이다). 끊긴 회차는 시험이 판정을 내지 못한 회차라 실패로 세지 않는다(아래 "무효 회차"). `sweep`은 0(남은 것이 없다)과 3(지우지 못한 것이 있다)을 낸다. 걸음마다 부르는 외부 명령(terraform, git, 시험)에는 시간 제한을 둔다(`.claude/rules/tools.md`. `tools/check_instructions.py`가 `tools/`의 시간 제한 없는 `subprocess` 호출을 잡는다).

**무효 회차.** "한 번 실패하면 실패"(ADR 0058)는 시험이 모델 서버에 닿아 판정을 낸 회차에 건다. 무효 회차는 셋이다. 시험을 시작하기 전에 끝난 회차(띄우지 못했다, 준비 상한을 넘겼다, 값이 예상보다 커서 지웠다), 시험이 실패했는데 그 직후의 확인에서 모델 목록에 답하지 않는 서버가 있는 회차(타이머가 먼저 지웠다, 프록시가 끊겼다), 그리고 띄우기를 시작한 뒤 시험이 판정을 내기 전에 Ctrl-C로 끊긴 회차다. 무효 회차는 실패로 세지 않고 다시 띄워 돌릴 수 있으며, 까닭을 일지와 PR 코멘트에 적는다. 다시 띄울 때도 비용 확인을 받는다. 무효 회차가 연달아 둘이면 세션이 멈춰 보고한다. 서버가 살아 있는데 시험이 실패한 회차는 모델의 흔들림까지 포함해 실패다. 받아들인 틈은 둘이다. 시험 도중 잠깐 끊겼다 돌아온 서버는 확인을 지나 실패로 세어지고, 코드의 잘못으로 실패했는데 마침 서버도 죽은 회차는 무효로 세어진다. 뒤의 것은 다시 돌리면 같은 실패가 나므로 숨지 않는다. 거부한 안: 서버 쪽 사정의 회차도 실패로 센다(고칠 코드가 없어 "고친 뒤 처음부터 다시"가 성립하지 않는다). 거부한 안: 실패하면 한 번 더 돌려 가른다(ADR 0058이 거부한 "다시 돌려 통과하면 통과"와 같아진다).

**청소.** `sweep`은 상태 폴더의 뿌리(`.agent-os/llm-local/`) 아래를 훑어 죽은 잠금의 폴더마다 남은 자원을 `terraform destroy`로 지우고, 자원이 없음을 확인한 폴더를 지운다. 살아 있는 잠금의 폴더는 건드리지 않는다. `run`은 시작할 때 자기 브랜치의 폴더만 본다(위 걸음 4). 다른 브랜치의 것은 사람이나 세션이 `sweep`을 쳐서 치운다. 치는 때는 둘이다. 병합 절차가 로컬 모델 시험을 돌린 PR을 병합한 뒤와, 사용자가 남은 서버가 걱정될 때다. 타이머가 서버를 먼저 지우므로 `sweep`이 늦어도 요금은 타이머의 90분에서 멎고, `sweep`이 치우는 것은 주로 상태 파일이다. `sweep`이 지우는 폴더는 그 뿌리 바로 아래의 것으로, 이 스크립트가 심은 표지 파일이 있을 때만 지우고 링크는 따라가지 않는다. 지우는 도구라 커밋 전에 판정을 깨려는 입력(표지 없는 폴더, 뿌리 밖을 가리키는 링크, 살아 있는 잠금)으로 반박해 본다(`.claude/rules/tools.md`). 타이머가 이미 지운 파드를 `terraform destroy`가 깨끗이 넘기는지는 모른다. 넘기지 못하면 상태를 실제와 맞춘 뒤(`terraform apply -refresh-only`) 다시 지우고, 그래도 남으면 사람에게 넘긴다.

**띄워 확인하는 것.** 모델 서버를 띄워 확인하는 묶음이 ADR 0058 "돌려 보지 않은 것"에서 남은 것 전부와 이 절이 모른다고 적은 것을 띄워 본다. 구성 1이 서는지(파드 둘, 두 모델이 뜬다), 타이머의 두 방법 가운데 어느 것이 서는지와 타이머가 실제로 파드를 지우는지, 타이머가 지운 뒤의 `terraform destroy`, 두 모델이 도구가 든 요청에 `tool_calls`로 답하는지, 띄우기부터 준비까지의 시간, 프록시 주소의 꼴, Terraform이 돌려준 `cost`와 가격 페이지의 단가가 같은지, 응답의 모델 이름이다. 도구 호출의 확인은 프로브로 재고 `.scratch/local-model/probes/`에 커밋한다. 결과가 이 절의 구성이나 값과 다르면 그 묶음이 이 명세의 이 절에 날짜를 단 주석으로 적고, ADR 0058 본문의 문장을 거짓으로 만들면 그 ADR의 이력에 적는다(ADR 0058 Consequences의 같은 대목).

### 규약 문서 (넘겨받았다)

어댑터와 로컬 모델 시험을 넣는 PR(묶음 D)이 고친다(ADR 0058 Consequences "규약이 서는 때"). 그 PR이 가장 늦게 든 마커 `llm_portal`로 저장소를 grep해 자리를 다시 찾는다. 마지막 항목의 두 자리만 그보다 앞선 묶음 A와 B가 맡는다.

- `docs/constitution/operations.md`의 LLM 테스트 절(헌법 판을 올린다). `-m llm_local`의 뜻과 명령, 병합 조건의 범위, 두 모델 모두와 한 번 실패하면 실패, 무효 회차, 기록과 그 유효함의 판정, 워크트리에서 `.env`를 넘기는 꼴을 적는다. 조건이 붙는 PR도 적는다. 개발 브랜치로 가는 티켓 PR과 운영 브랜치로 바로 가는 핫픽스 PR이고, 운영 브랜치로 가는 PR의 CI가 돌리는 LLM 테스트에는 `llm_local`이 들지 않는다(ADR 0058 Consequences "브랜치 전략과의 관계"). 제품 판을 내기 전에도 한 번 돌린다는 것과, 그 절차는 pilot-release와 deploy-package가 정한다는 것도 적는다(ADR 0058 결정 "언제 돌리고 무엇을 남기는가").
- `CLAUDE.md`의 검증 명령, `.claude/rules/tests.md`, `.claude/rules/http.md`, `.github/PULL_REQUEST_TEMPLATE.md`의 체크리스트, `.github/workflows/ci.yml`의 주석, `.coderabbit.yaml`, `tools/llm_tokens.py`와 그 시험, `tools/hook_env_read.py`의 문구, `tools/mutate.py`의 독스트링, `tests/test_main.py`와 `tests/test_calc_plugin.py`의 독스트링, `tests/test_conftest.py`, `web/apps/portal/playwright.config.ts`와 `web/packages/e2e-stack/src/plugins.ts`의 주석.
- `.claude/skills/next-session/merge.md`의 "병합 전". 범위에 드는 변경이면 로컬 모델 시험과 비용 확인의 단계를 밟고, 기록이 유효한지를 시험한 커밋과 브랜치 끝 사이의 차이로 가르며, "병합할지는 사용자에게 묻지 않는다"에 과금 확인의 예외를 적고, 병합 뒤 `sweep`을 친다.
- ADR 0057이 든 자리. `.claude/rules/sdk.md`의 모델 항목("값은 `anthropic` 하나", 모델 칸의 목록)은 계약 묶음(A)이, `.claude/rules/core.md`의 실패 정책에 더하는 깨진 도구 호출 한 줄은 그 확인을 넣는 묶음(B)이 고친다. `.claude/rules/adapters.md`의 모델 소스 항목, `.claude/rules/core.md`의 모델 포트 행, `README.md`와 `.env.example`의 모델 설명은 어댑터 묶음(D)이 고친다(설계 일지 "다음"의 둘째).

### 다른 기능에 넘기는 것 (명세가 정한 것에서 나왔다)

이 명세와 같은 커밋이 받는 기능 계획의 본문 끝에 적고 `uv run python tools/plan_table.py`를 돌린다.

- `.scratch/deploy-package/plan.md`. 설계가 넘긴 여섯(서버 옵션, 평문, 프록시, 상한, 기다림, 주소의 쿼리) 가운데 주소의 쿼리는 이제 읽는 단계의 거부라 안내가 비밀을 적지 말라고 할 일이 아니라 거부 문구를 설명할 일이 된다. 더하는 것은 여섯이다. 환경의 `OPENAI_ORG_ID`·`OPENAI_ORGANIZATION`·`OPENAI_PROJECT_ID`·`OPENAI_CUSTOM_HEADERS`가 모델 서버로 가므로 `serve`의 환경에 두지 않는다(위 "요청"). 런타임은 `OPENAI_PROXY`를 듣지 않고 표준 프록시 변수를 듣는다(같은 절. `HTTP_PROXY`로 쟀다). 이름이 `o`와 숫자로 시작하거나 `gpt-5`로 시작하고 `chat`이 없는 모델은 라이브러리가 요청을 바꾼다(같은 절). `base_url`은 API 뿌리(vLLM이면 `/v1`)까지 적는다(위 "매니페스트"). 모델 호출마다 연결을 새로 맺어 https 모델 서버에서는 호출마다 TLS 악수가 든다(위 "HTTP 클라이언트"). 로그 수준을 DEBUG로 낮추면 모델 서버와 그 앞의 게이트웨이가 준 응답 헤더의 값이 로그에 찍히므로, 응답 헤더에 비밀을 싣는 서버 앞에서는 그 로그를 비밀로 다룬다(위 "로그"). 그 기능 계획의 `**Blocked by:**`에 local-model이 있다.
- `.scratch/answer-eval/plan.md`. 모델 호출마다 연결을 새로 맺어 https 모델 서버에서는 호출마다 TLS 악수가 지연에 든다(위 "HTTP 클라이언트"). 로컬 모델의 지연을 재면 그 몫을 갈라 적는다. 그 기능 계획의 `**Blocked by:**`에는 local-model이 없다. 그 기능의 첫 보고서는 Anthropic API의 모델로 내고, 오픈 모델의 지연은 local-model이 닫힌 뒤 다시 재서 pilot-release의 보고서로 내기 때문이다(그 기능 계획의 본문을 읽었다). 이 메모는 그 다시 재는 때에 쓰인다.

### 고칠 자리의 묶음 (넘겨받았다. 묶음은 명세가 정했다)

티켓은 to-tickets가 나누되 이 묶음을 밑그림으로 쓴다.

- A(계약. 다른 묶음을 막는다). sdk의 `ModelProvider`와 두 칸과 검증, 모델 소스의 임시 거부 갈래, `openapi.json`, 생성 TS 타입, 관리 화면의 픽스처와 스토리와 시험 하나와 사진 정답, `.claude/rules/sdk.md`의 모델 항목, sdk 매니페스트 시험.
- B(깨진 도구 호출). `reply_from`의 확인(위 "인자가 깨진 도구 호출")과 그 시험, `.claude/rules/core.md`의 실패 정책 한 줄이다. 어댑터 없이 선다(가짜 모델이 깨진 호출이 든 응답을 내면 된다). A와 나란히 돈다.
- C(모델 서버를 띄우는 명령). 스크립트와 Terraform 구성, 그 시험, 실제로 띄워 확인하는 것, `docs/constitution/tech.md`의 시험용 모델 서버 행이다. 사용자의 준비 넷(Further Notes)이 먼저 끝나 있어야 한다. A·B와 파일이 겹치지 않아 나란히 돈다.
- D(어댑터와 로컬 모델 시험). 모듈 나눔, 모델 서버 어댑터(위 "요청"부터 "로그"까지. 알려진 한계는 그 모듈 독스트링이 원천이다), 의존 선언과 import-linter, 가짜 모델 서버와 어댑터 시험, calc의 가짜 모델 서버 시험, DEBUG 로그 수락, 로컬 모델 시험과 마커, 위 규약 문서 가운데 A와 B가 맡은 두 자리를 뺀 전부다. 어댑터는 프로브의 `adapter_candidate.py`를 옮기지 않고 거기서 본 모양을 근거로 새로 짓는다. A·B·C에 막힌다. 어댑터와 로컬 모델 시험과 규약 문서는 PR 하나에 들고 그 PR이 로컬 모델 시험을 두 모델로 통과해야 병합한다(ADR 0058 결정 "첫 적용"). 티켓을 더 쪼개더라도 PR은 하나다.
- E(기본 에이전트의 사례 기록. 마지막 묶음). base-agent가 끝난 뒤 그 실제 모델 시험의 사례를 두 모델로 돌려 사례별 통과와 실패를 기록한다. 통과를 요구하지 않는다(ADR 0058 결정 "기본 에이전트의 사례"). 상시 시험을 더하지 않고 `run`의 `--` 뒤에 그 사례를 고르는 명령을 넣어 한 번 돌린다. D와 base-agent에 막힌다.

A·B·C의 PR에는 로컬 모델 시험의 조건이 붙지 않는다. 돌릴 시험이 아직 없기 때문이다(ADR 0058 결정 "첫 적용"). B가 고치는 `core/model.py`는 병합 조건의 범위에 들지만 같은 까닭으로 붙지 않고, D의 로컬 모델 시험이 그 변경까지 지난다. B는 `-m llm`을 돌린다.

## Testing Decisions

### 좋은 시험

바깥 행동만 본다. 매니페스트는 읽힌 값과 거부의 위치·종류를, 어댑터는 가짜 모델 서버가 받은 요청(경로, 헤더, 본문)과 돌려준 예외의 타입과 문구를, core는 이벤트의 열과 `run_failed`의 원인을, CLI는 종료 코드와 출력과 트레이스 파일을 본다. 모델 객체의 안쪽(어느 메서드를 감쌌는지)은 시험하지 않는다. 환경이 없어 skip되는 시험은 두지 않는다(원칙 II). 시간 단언은 홀로 돌린 시간의 넉넉한 배수로 둔다(`.claude/rules/tests.md`).

### 가짜 모델 서버 (명세가 정했다)

- 시험 픽스처이고 자리는 `tests/adapters/`다. 시험 프로세스 안의 스레드로 루프백의 빈 포트에 뜨는 HTTP 서버이고 표준 라이브러리의 스레드 서버(`http.server.ThreadingHTTPServer`)로 짓는다. 받은 요청마다 메서드, 경로, 헤더, 본문을 차례로 적고, 시험이 차례로 정한 응답(상태 코드와 본문)을 돌려주며, 받은 연결과 처리를 마친 연결의 수를 센다. 흉내 내는 것은 Chat Completions 하나다. 선례는 프로브의 `fake_server.py`이고 옮기지 않고 새로 짓는다.
- CLI 시험(calc)에서는 CLI가 자식 프로세스로 돌고 가짜 모델 서버는 시험 프로세스에 뜬다. 정한 응답은 차례로 둘이다. 첫째는 `add`의 도구 호출이고 둘째는 그 결과를 든 글의 답이다.
- 거부한 안: HTTP 흉내 라이브러리(`respx` 등)를 시험 의존으로 들인다(그 라이브러리들은 `httpx`를 겨냥하는데 openai 3.49.0은 `httpx2`로 보내고, 연결의 셈은 어차피 직접 지어야 한다).

### 사례 (명세가 정했다)

묶음마다 무엇을 보는지다. 사례 이름과 파일은 티켓이 정한다.

- **sdk(A).** `openai-compatible`에 `base_url`만 적은 파일과 `api_key_env`까지 적은 파일이 읽히고 값이 글자 그대로다. 거부와 그 위치·문구: `base_url` 없음, 주소 모양 아님, `http`·`https`가 아님, 사용자 정보, 호스트 없음, 쿼리(빈 쿼리 포함), `api_key_env`의 꼴, `anthropic` 파일의 두 칸, 모델이 아닌 종류의 두 칸. 조각이 든 주소는 읽힌다. 거부 문구에 적은 값이 없다. 직렬화 스키마의 두 칸이 required이고 `null`을 허락한다. 지금의 `anthropic` 파일이 그대로 읽힌다(스토리 3).
- **관리 화면(A).** 위 "계약과 관리 화면"의 사례 하나.
- **core(B).** 가짜 모델이 `invalid_tool_calls`가 든 응답을 내면 실행이 원인 `model_call`의 `run_failed`로 끝나고, 메시지가 도구 이름을 들며 깨진 인자의 글을 싣지 않고, 그 호출의 `llm_called`와 `tool_called`가 없다. 섞인 응답과 이름이 빈 깨진 호출도 같다. 가짜 모델은 지금 core 시험의 것을 쓴다(`tests/fake_models.py`의 `FakeModels`가 모델 소스다).
- **어댑터(D), 만들기.** 키 변수가 없어도, 가짜 모델 서버가 꺼져 있어도 모델이 만들어진다. 모델이 아닌 종류의 매니페스트와 공백뿐인 `model_id`는 두 제공사 모두 같은 `PluginError`다. `provider`로 갈라 `anthropic`은 지금의 모델을, `openai-compatible`은 모델 서버의 모델을 만든다. 같은 매니페스트로 부를 때마다 새 객체다. 읽는 단계는 지나지만 라이브러리가 받지 않는 주소(개행이 든 주소, 포트가 숫자가 아닌 주소)의 매니페스트는 `PluginError`로 끝나고, 문구가 플러그인 이름과 예외 종류의 이름을 들며 주소의 글자를 싣지 않는다(위 "모델 소스와 모듈").
- **어댑터(D), 요청.** 경로, 본문의 키 넷과 빠지는 키, 도구의 모양, 상한과 온도가 없을 때와 있을 때, 인증 헤더의 키, `api_key_env`가 없을 때의 자리 채움 글자, 환경에 심은 `OPENAI_API_KEY`·`OPENAI_BASE_URL`·`OPENAI_PROXY`·`LC_OUTPUT_VERSION`이 요청을 바꾸지 않는 것(다른 서버가 받은 요청 0건, 그 키가 헤더와 본문에 없음, 경로가 chat completions).
- **어댑터(D), 응답.** 글, 도구 호출, 토큰 수, 응답의 모델 이름, 모델 이름이 없을 때의 `unknown`. 인자가 깨진 JSON인 도구 호출은 어댑터에서 예외가 나지 않고 메시지의 `invalid_tool_calls`에 그 도구 이름으로 든다(B의 확인이 기대는 모양이다. 라이브러리의 판이 그 모양을 바꾸면 이 사례가 빨개진다).
- **어댑터(D), 실패.** 키 변수 없음과 빈 값과 실을 수 없는 값(요청 0건, 문구가 변수 이름만 든다), 401에 키를 되울린 응답(글에 키가 없고 `***`가 있다), 가짜 모델 서버가 요청을 받은 뒤 환경의 키 값을 바꾸고 받은 키를 되울린 401(글에 옛 키도 새 키도 없다), 꺼진 서버(`ConnectionError`와 문구), 500, 200의 `error` 칸, JSON이 아닌 200 본문, 객체가 아닌 도구 인자(문구가 자리만 들고 인자의 글자가 없다), 어느 실패든 `__cause__`와 `__context__`가 없고 내장 타입이다. 문구의 주소는 모델 파일에 적은 글자 그대로다(경로까지 실린다). 꺼진 서버와 500은 재시도로 몇 초가 걸리므로(쟀다, 닫힌 포트 7.3~7.5초) 사례 수를 줄여 둔다.
- **어댑터(D), 수명과 취소.** 환경의 키를 바꾸면 다음 요청의 헤더가 바뀐다. 한 프로세스에서 `asyncio.run`을 두 번 돌려 같은 주소를 불러도 된다. 한 루프에서 모델 다섯을 만들어 부르고 놓은 뒤 가짜 모델 서버의 연결이 모두 닫혀 있다(셈을 단언하기 전에 짧게 기다린다. 프로브는 1초를 기다렸다). 401로 끝난 호출과 기한에 끊긴 호출 뒤에도, 모델 하나를 여러 번 부른 뒤에도 연결이 모두 닫혀 있다. 이 연결 셈은 CI의 리눅스 러너에서도 돌아 프로브가 재지 않은 리눅스를 메운다(위 "HTTP 클라이언트"). 실행 기한(`anyio.move_on_after`)이 답을 기다리는 호출을 끊고 취소가 다른 예외로 바뀌지 않는다.
- **어댑터(D), 로그.** 위 "로그"의 수락 시험.
- **CLI(D), calc의 평소 시험.** `tests/test_main.py`의 실제 모델 calc 시험과 같은 모양으로 플러그인을 임시 루트에 복사하고, 거기에 가짜 모델 서버를 가리키는 `openai-compatible` 모델 파일을 적어 `--model`로 준다. calc의 MCP 서버는 Node가 필요한 `everything` 대신 같은 파일이 쓰는 stdio 픽스처(`tests/adapters/mcp_fixture_server.py`, 도구 `add`가 있다)로 바꾼다. http calc 시험이 `mcp`와 규칙 파일의 `allow`를 바꾸는 선례(`_replace_in`)를 따른다. 단언은 종료 코드 0, 출력의 계산 결과, 트레이스의 마지막 `run_finished`, `llm_called` 둘과 성공한 `tool_called`(인자와 결과), 가짜 모델 서버가 받은 첫 요청에 `tools`가 있다는 것이다. 기본 pytest와 CI에서 돈다(사용자가 골랐다, 일지 2026-11-12-0248 "사용자에게 물은 것 셋"의 셋째).
- **CLI(D), 인자가 깨진 도구 호출.** 위 calc의 평소 시험과 같은 모양에서 가짜 모델 서버의 첫 응답만 바꾼다. `add` 호출의 인자가 깨진 JSON이다. 단언은 종료 코드가 0이 아니고, 트레이스의 마지막이 원인 `model_call`의 `run_failed`이며, 그 메시지가 도구 이름 `add`를 들고 깨진 인자의 글자를 싣지 않고, `tool_called`가 없다는 것이다. ADR 0057 결정 "평소의 시험"이 가짜 모델 서버로 보라고 적은 인자가 깨진 도구 호출이 이 사례다. B의 core 시험은 가짜 모델이 지어낸 메시지로 확인을 보고, 이 사례는 그 메시지가 실제 라이브러리와 어댑터를 지나 만들어지는 길 전체를 본다.
- **로컬 모델 시험(D).** 위 "로컬 모델 시험"의 시험 하나. 환경 변수가 모자랄 때 skip이 아니라 실패하고 문구가 변수 이름을 드는 것은 기본 pytest의 사례로 본다(마커 없이, 그 시험의 환경 검사 함수를 부른다).
- **모델 서버를 띄우는 명령(C).** 클라우드 없이 도는 시험이 `tests/tools/`에 선다. 외부 명령(terraform, git, 시험)은 스크립트의 한 함수를 지나고 시험이 그 함수를 가짜로 바꿔 끼운다. 보는 것은 걸음 1의 모자란 환경(이름만 들고 4), `--yes` 없이 친 `run`이 `terraform apply`를 부르지 않고 예상 비용을 찍고 4로 끝나는 것(걸음 1의 판 확인과 걸음 4의 destroy는 그 전에 부를 수 있다), 예상 비용의 셈(단가 표와 파드 수, 30분과 90분), 상태 폴더 이름(브랜치 이름의 `/`), 잠금의 판정(산 프로세스와 그 명령줄, 죽은 번호, 다른 프로세스가 받은 번호), 죽은 잠금 아래 자원이 있으면 띄우기 전에 destroy를 부르는 것, 시험이 실패하든 Ctrl-C로 끊기든 destroy를 부르는 것, 무효 회차의 가름과 종료 코드, 종료 코드가 겹칠 때의 차례(시험이 실패하고 지우기도 실패하면 3, GPU 후보 셋 모두 재고가 없으면 2), 죽은 잠금 아래 자원을 지운 뒤 `--yes` 없이 끝난 `run`의 4, 시간 제한에 걸린 시험이 걸음 10의 확인을 거쳐 1이나 2로 갈리는 것, 띄운 뒤 끊긴 회차의 2와 띄우기 전에 끊긴 회차의 4, 기록 묶음에 서버 키와 주소가 없는 것이다. `sweep`이 지우는 길은 판정을 깨려는 입력(표지 없는 폴더, 뿌리 밖을 가리키는 링크, 살아 있는 잠금)으로 반박하는 사례를 둔다(`.claude/rules/tools.md`). 실제로 띄워 확인하는 것은 위 "띄워 확인하는 것"이다.

## Out of Scope

- ADR 0057이 범위 밖으로 둔 여덟. 토큰 단위 스트리밍, 서버로 그대로 넘기는 칸과 엔진의 확장, 깨진 도구 호출을 모델에 되돌려 다시 시키는 것, 새 실패 원인, 타임아웃과 재시도의 칸, 인증 헤더를 빼는 길, 자체 서명 인증서의 설정, 임베딩처럼 대화가 아닌 API.
- 배포 환경의 모델 서버를 띄우는 방법과 배포 안내(deploy-package. ADR 0057 Consequences "배포가 알아야 할 것"의 여섯은 설계가 그 기능 계획에 적었고 `**Blocked by:**`에 local-model이 있다. 이 명세가 다섯을 더했다, 위 "다른 기능에 넘기는 것").
- 로컬 모델의 지연과 정답률을 재는 것, 배포에 쓸 모델을 고르는 것(answer-eval). 호출마다 새 연결을 맺는 몫을 갈라 재는 것도 그 기능이 한다(같은 절).
- 환경의 헤더 변수 넷(`OPENAI_ORG_ID`, `OPENAI_ORGANIZATION`, `OPENAI_PROJECT_ID`, `OPENAI_CUSTOM_HEADERS`)이 모델 서버로 가는 것을 막는 것, 모델 이름의 머리가 요청을 바꾸는 것을 되돌리는 것(위 "요청"의 알려진 한계 둘).
- 모델마다 준 HTTP 클라이언트를 닫는 자리(포트의 닫기). 쉬는 연결을 두지 않아 닫을 것이 남지 않게 한다(위 "HTTP 클라이언트").
- vLLM이 아닌 서빙 엔진의 확인. 이 기능이 시험으로 확인하는 엔진은 vLLM 하나다(ADR 0057 결정 "제공사").
- CI에서 로컬 모델 시험을 돌리는 것과 병합을 자동으로 막는 검사(ADR 0058 결정 "지키게 하는 수단").
- Runpod이 아닌 클라우드에 띄우는 길. 사용자가 다른 곳에 띄운 모델 서버는 환경 변수로 받는다.
- `anthropic` 제공사의 예외를 감싸거나 문구를 바꾸는 것. 그 길은 지금 그대로다.
- 관리 화면에 모델 서버를 위한 새 화면이나 입력란을 두는 것. 매니페스트는 지금처럼 JSON으로 보인다.
- `plugins/models/`에 `openai-compatible` 모델의 예시를 두는 것. 저장소의 예시 모델은 지금의 하나이고, 배포마다 주소가 달라 예시가 가리킬 서버가 없다.

## Further Notes

- **사용자가 한 번 준비하는 것 넷**(ADR 0058 결정 "사용자가 한 번 준비하는 것"). Runpod 계정과 크레딧 충전, API 키를 주 체크아웃의 `.env`에 `RUNPOD_API_KEY`로 넣기, Terraform을 1.6 이상으로 올리기, 자동 충전(auto-pay)을 켜지 않기다. 2026-11-12에 주 체크아웃의 `.env`를 넘긴 환경에 `RUNPOD_API_KEY`는 없었고(쟀다, `outside_worktree.py`의 둘째 명령. 이름만 봤다) 이 PC의 Terraform은 1.5.5다(ADR 0058이 손으로 봤다). 묶음 C가 시작하기 전에 끝나 있어야 한다.
- 가격과 문서의 원문은 설계 세션이 2026-11-11에 받아 둔 것이고 저장소에 없다(설계 일지 "다음"의 "저장소로 알 수 없는 것"). 묶음 C가 단가 표를 적을 때 가격 페이지를 다시 받는다.
- Terraform 프로바이더 `runpod/runpod` 2.0.0은 2026-10-27에 나온 판이다(ADR 0058). 프로바이더의 판은 Terraform 구성에 글자 그대로 묶는다.
