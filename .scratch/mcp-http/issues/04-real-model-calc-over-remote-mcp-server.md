# 04: 실제 모델 시험 — calc 예시가 원격 MCP 서버의 도구를 쓰고 트레이스가 남는다

**What to build:** 실제 모델로 calc 예시를 CLI로 돌리되 calc가 고른 mcp 플러그인을 http 모양 하나로 바꾸면, calc가 시험이 띄운 원격 MCP 서버에 주소로 붙어 그 서버의 도구로 계산하고 답에 결과가 나오며 트레이스에 그 도구 호출이 남는다. 기능 계획 수락의 앞 절(시험용 원격 MCP 서버에 calc 예시가 주소로 붙어 도구를 쓰고 트레이스가 남는다. 뒤 절의 꺼진 서버는 02가 잰다)을 실제 CLI 프로세스와 실제 Anthropic 호출로 잰다(스토리 1·2). `plugins/mcp/`에 http 모양의 예시는 두지 않는다(ADR 0049 결정 "시험"). 매니페스트는 시험이 임시 루트에 적는다.

04는 02 뒤이고 03과 나란히 돈다. 접속(02)만 있으면 서고 닫는 길(03)과는 파일이 겹치지 않는다. 이 시험은 정상 종료만 지나므로 03이 바꾸는 닫는 길의 어느 쪽에서도 같은 결과다.

근거는 `.scratch/mcp-http/spec.md`의 "실제 모델 시험 하나"와 그 2026-11-09 to-tickets 주석, "고칠 자리의 묶음"의 주석의 C다. 앞선 결정은 ADR 0049의 결정 "시험"이다.

**Blocked by:** 02 (원격 MCP 서버에 매니페스트의 주소로 실행마다 붙는다). 02의 http 갈래와 HTTP 픽스처를 쓴다

**Status:** done

- [x] **`tests/test_main.py`에 `llm` 마커의 시험 하나를 둔다.** 선례는 같은 파일의 `test_calc_에이전트가_실제_모델로_답하고_트레이스에_모델_호출이_남는다`다. 저장소의 플러그인을 임시 루트(`tmp_path` 아래)에 복사한다. 선례의 두 복사 모양(플러그인 트리 전체를 복사하는 것과 `_copy_repo_plugins`) 모두 저장소의 규칙 파일 `plugins/rules.toml`을 함께 옮긴다
- [x] **시험이 02의 HTTP 픽스처를 별도 프로세스로 띄우고, 그 주소를 `url`로 적은 http 모양의 mcp 플러그인 하나를 임시 루트에 적는다.** 02가 두 시험이 함께 쓰는 자리에 둔 픽스처와 띄우는 도우미를 그대로 쓰고, 옮기거나 고치지 않는다(나란히 도는 03이 같은 픽스처에 인자를 더한다). 헤더는 적지 않아도 된다(헤더 값이 서버에 닿는 것은 02의 어댑터 시험이 잰다)
- [x] **임시 루트에서 calc의 매니페스트의 `mcp`를 그 플러그인의 이름 하나로 바꾸고, 규칙 파일의 `[agents.calc]` 줄도 그 이름으로 바꾼다.** 규칙 파일을 그대로 두면 에이전트 표의 줄(`everything:*`)이 연결에 없는 서버를 가리켜 실행이 연결 직후 원인 `tool_connection`의 `run_failed`로 끝난다(`.claude/rules/core.md` 실패 정책, 명세 "실제 모델 시험 하나"의 주석). 규칙 줄을 지우기만 하면 calc의 도구 호출이 어느 규칙에도 맞지 않아 묻는다로 멈춘다(`plugins/rules.toml` 머리 주석의 집행 차례, ADR 0044)
- [x] **CLI로 돌리고, 종료 코드가 0이며 답에 계산 결과가 있고, 트레이스에 `tool_called`가 남으며 마지막 이벤트가 `run_finished`다.** calc가 고른 mcp가 그 플러그인 하나뿐이므로 트레이스의 도구 호출은 그 서버의 것이다. 양성 대조로 픽스처의 기록 파일에 POST 요청이 있는지 본다(그 서버에 실제로 붙었다)
