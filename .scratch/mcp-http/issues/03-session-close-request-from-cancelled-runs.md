# 03: 실행 기한이나 serve 종료로 취소된 실행에서도 원격 MCP 서버에 세션 종료 요청을 보낸다

**What to build:** 원격 MCP 서버를 쓰는 실행이 실행 기한에 걸리거나 `serve`가 멈추며 취소되어도, 런타임이 그 서버에 세션 종료 요청(DELETE)을 2초 안에 보내고 클라이언트를 닫은 뒤 끝난다. 그래서 서버가 끝난 실행의 세션을 유휴 만료(mcp 2.3.0 서버의 기본 1800초, 코드를 읽었다)까지 쥐지 않는다(스토리 9·12). 기한에 걸린 실행의 결말은 지금처럼 원인 `timeout`의 `run_failed`이고(스토리 11), 서버가 종료 요청에 답하지 않아도 실행은 2초 안팎에 끝난다(스토리 10). 정상 종료도 같은 길을 지나며 늦어지지 않는다. 서버가 `/mcp`를 `/mcp/`로 돌려보내는 모양이어도 종료 요청은 같은 서버 안의 최종 주소에 닿고, 다른 출처로는 실려 가지 않는다.

03은 02 뒤이고 04와 나란히 돈다. 02가 남긴 틈(취소된 실행은 종료 요청을 보내지 않는다)을 닫는다. 라이브러리의 종료 요청을 끄는 것, 응답 훅이 세션 식별자를 받아 두는 것, 어댑터가 종료 요청을 보내는 것은 이 티켓에 함께 든다. 앞의 것만 먼저 들어오면 정상 닫기에서도 종료 요청이 나가지 않기 때문이다(명세 "접속"의 주석).

근거는 `.scratch/mcp-http/spec.md`의 "닫기"(결정, 까닭, 종료 요청의 모양, 2초, 걸리는 시간)와 그 2026-11-09 주석(리디렉션), "고칠 자리의 묶음"의 주석의 B2, Testing Decisions의 "시험 픽스처의 모양과 더한 사례"와 그 주석이다. 측정은 `.scratch/mcp-http/probes/http_close.py`(갈래 `normal`, `deadline_plain`, `deadline_shield_exit`, `deadline_shield_delete`, `deadline_shield_after`, `deadline_shield_finally`, `deadline_shield_finally_hang`, `normal_own_delete`)와 그 `README.md`이고 다시 돌리지 않는다. 앞선 결정은 ADR 0049의 결정 "닫기"와 Consequences "닫는 데 시간이 든다", 그 2026-11-09 이력 "닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다"다. 보호를 라이브러리 문맥을 닫는 호출에 두는 모양은 anyio가 중첩 위반(`RuntimeError: Attempted to exit a cancel scope that isn't the current tasks's current cancel scope`)으로 거부하고, 그 예외가 새면 기한의 결말이 예외로 바뀐다(`deadline_shield_exit`). 구현 중에 보호의 자리를 옮기고 싶으면 이 측정부터 다시 읽는다.

**Blocked by:** 02 (원격 MCP 서버에 매니페스트의 주소로 실행마다 붙는다). 02의 http 갈래, 클라이언트, 응답 훅, HTTP 픽스처를 쓴다

**Status:** ready-for-agent

### 닫는 길

- [ ] **라이브러리의 종료 요청을 끈다(`terminate_on_close=False`).** 02가 쓰던 기본값을 바꾼다
- [ ] **응답 훅이 세션 식별자(`Mcp-Session-Id` 응답 헤더)를 받아 둔다.** 02의 응답 훅에 더한다. 라이브러리 전송의 비공개 속성에서 읽지 않는다(명세 "닫기"의 거부한 안)
- [ ] **라이브러리 문맥(세션, 전송)을 보호 없이 닫고, 같은 `finally`에서 `CancelScope(shield=True)` 안에 어댑터가 자기 클라이언트로 종료 요청을 `move_on_after(2)` 유예 안에서 보낸다.** 유예가 지났어도 같은 보호 안에서 클라이언트를 닫는다. 유예는 종료 요청에만 걸린다. 한 유예에 둘을 함께 두면 종료 요청이 걸렸을 때 클라이언트 닫기가 건너뛰어진다. 정상 종료도 같은 길이다. 2초는 어댑터 안의 상수 하나이고 stdio 상류가 서버가 스스로 끝나기를 기다리는 유예와 같은 값이다(ADR 0034·0049)
- [ ] **종료 요청의 모양.** 매니페스트의 `url` 그대로(쿼리 문자열 포함)에 DELETE를 보내고, 헤더는 클라이언트의 기본 헤더에 `accept: application/json, text/event-stream`, `content-type: application/json`, `mcp-session-id`(응답 훅이 받아 둔 것), `mcp-protocol-version`(`initialize` 결과의 값)을 더한 것이다. 세션 식별자를 받지 못했으면(`initialize` 전에 실패했거나 서버가 주지 않았다) 보내지 않는다. 응답은 보지 않는다. `httpx2.HTTPError`(서버가 연결을 끊을 때의 `RemoteProtocolError` 포함)와 2초 초과는 삼키고 기록하지 않는다(어댑터는 로그를 쓰지 않는다)

### 리디렉션(사용자가 골랐다)

- [ ] **종료 요청은 `follow_redirects=False`로 보낸다.** 응답이 리디렉션이면 httpx2가 지어 둔 다음 요청(`Response.next_request`)이 세 조건을 모두 갖출 때만 그것을 보낸다. 같은 출처(scheme·호스트·포트가 같거나, 기본 포트를 쓰는 같은 호스트의 http에서 https로), 메서드가 DELETE 그대로(httpx2는 302·303에서 GET으로 바꾼다), 위치에 사용자 정보가 없음이다. 라이브러리가 자기 요청에 쓰는 조건과 같다
- [ ] **판정은 httpx2의 공개 API(`Response.next_request`, `URL`의 칸)로 짓는다.** 라이브러리의 비공개 모듈(`mcp.shared._httpx_utils`)은 import하지 않는다(명세가 정했다. 판이 바뀌면 조용히 깨진다)
- [ ] **어댑터가 따른 횟수를 세어 클라이언트의 `max_redirects`를 넘지 않게 한다.** httpx2의 횟수 상한은 한 번의 `send` 안에서만 센다. 2초 유예는 따르는 요청까지 모두 덮는다. 조건을 갖추지 못한 리디렉션은 따르지 않고 그 응답으로 끝낸다. 그래서 다른 출처로는 `Authorization` 밖의 인증 헤더도 세션 식별자도 실려 가지 않는다

### 시험 픽스처

- [ ] **02의 HTTP 픽스처에 선택 인자 셋을 더한다.** DELETE에 답하지 않고 잠드는 것, DELETE의 연결을 응답 없이 끊는 것, 리디렉션 모드에서 DELETE만 다른 출처(다른 포트)로 돌려보내는 것이다. 다른 출처에 닿은 요청이 없음을 볼 수 있게 그 출처에도 요청을 기록하는 자리를 둔다

### 어댑터 시험의 사례

선례는 `tests/adapters/test_mcp.py`의 `test_도구_호출_도중에_기한이_오면_감싼_프로세스_아래의_서버까지_내려간다`다. 어댑터 시험은 본문에서 `async with`로 연다(`.claude/rules/tests.md`).

- [ ] 정상 닫기에 종료 요청이 앞선 POST와 같은 세션 식별자로 서버에 닿는다(이제 어댑터가 보낸다)
- [ ] 도구 호출 도중에 기한이 오면 종료 요청이 같은 세션 식별자로 닿고, 기한의 표지(`cancelled_caught`)가 참이며, 예외가 새지 않는다
- [ ] 종료 요청에 답하지 않는 서버에서는 닫기가 2초 안팎에 돌아온다. 상한은 그 시험만 홀로 돌린 시간의 넉넉한 배수로 둔다(`.claude/rules/tests.md`의 시간 단언 항목). 하한도 단언해 유예가 실제로 걸렸는지 본다
- [ ] `initialize` 전에 실패하면(02의 401 사례 같은) 종료 요청을 보내지 않는다(기록 파일에 DELETE가 없다)
- [ ] 리디렉션 모드에서 정상 닫기와 취소된 실행의 종료 요청이 `/`를 붙인 최종 주소에 닿는다
- [ ] DELETE를 다른 출처로 돌려보내면 그 출처에는 요청이 닿지 않고 닫기가 예외 없이 돌아온다
- [ ] DELETE의 연결을 끊어도 닫기가 예외 없이 돌아온다

### core와 채널을 지나는 시험

- [ ] **도구 호출 도중에 실행 기한이 오면 결말은 원인 `timeout`의 `run_failed`이고 종료 요청이 서버에 닿는다**(스토리 11, 명세가 넘겨받은 것 (15)). `run()`은 도구 포트를 인자로 받으므로 실제 어댑터와 HTTP 픽스처를 넘겨 잰다. 선례는 `tests/core/test_run.py`의 `test_기한의_취소를_도구_연결의_닫기가_다른_예외로_바꿔도_원인은_시간_초과다`이고, 그 시험의 가짜 도구 포트 자리에 실제 어댑터가 선다. 다만 그 선례는 기한이 모델 호출(`SleepyModel`)에 떨어지므로, 이 시험은 모델이 픽스처의 잠드는 도구를 부르게 해 기한이 도구 호출 도중에 오게 한다. 가짜 플러그인 포트가 http 모양의 매니페스트를 내는 것은 02가 넓힌 것을 쓴다
- [ ] **앱의 수명을 닫아 도는 실행을 취소하면 종료 요청이 서버에 닿는다**(스토리 12). 선례는 `tests/channel/http/test_end_user.py`의 `test_앱이_멈추며_취소한_실행도_칸을_돌려준다`다. 그 파일의 앱 조립 도우미가 도구 포트를 인자로 받으므로 실제 어댑터를 넘긴다. 다만 그 파일의 가짜 플러그인 포트가 내는 mcp 매니페스트(`CALC_SERVER`)는 stdio 모양이고 선례가 쓰는 에이전트 `asking`은 mcp를 고르지 않아, 실제 어댑터를 넘겨도 서버를 열지 않는다. 그래서 http 모양의 매니페스트와 그것을 고른 에이전트를 시험이 더한다. 수명은 본문의 `async with`로 연다(`.claude/rules/channel.md`)

### 문서

- [ ] **어댑터의 모듈 독스트링에 http 전송의 닫는 길과 시간을 적는다.** 02가 적은 "라이브러리의 종료 요청"을 이 길로 바꾸고, 취소된 실행이 종료 요청만큼 최대 2초 늦게 끝나며 정상 종료는 늦지 않는다는 것을 적는다(측정은 명세 "닫기"의 걸리는 시간). `.claude/rules/channel.md`가 닫는 시간을 이 독스트링으로 가리킨다
- [ ] **`.claude/rules/adapters.md`의 MCP 어댑터 항목에서 "취소된 실행에서도 서버를 닫은 뒤 끝난다"를 http 전송까지 넓힌다.** 02가 그 문장을 stdio의 것으로 좁혀 두었다. 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다(`.claude/rules/agent-docs.md`)
- [ ] **옛 표현을 저장소 전체에서 grep해 살아 있는 문서에 잔존이 0인지 본다**(`CLAUDE.md` 작업 규약 4). http 전송의 취소된 실행이 종료 요청을 보내지 않는다고 읽히는 문장(02가 남긴 틈의 문장)이다

### 검증

- [ ] **빨강을 먼저 본다**(헌법 원칙 II). 기한 사례에서 종료 요청이 닿지 않는 것(02의 라이브러리 기본값 그대로)이 첫 빨강이다
- [ ] **검증 명령이 모두 초록이다.** 손으로 치는 다섯이다. 서버 라우트·api-client·위젯을 건드리지 않으면 e2e와 사진 비교는 닿지 않는다
