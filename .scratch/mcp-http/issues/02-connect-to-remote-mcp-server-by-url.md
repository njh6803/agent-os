# 02: 원격 MCP 서버에 매니페스트의 주소로 실행마다 붙는다

**What to build:** 운영자가 http 모양의 mcp 플러그인을 쓰는 에이전트를 돌리면, 런타임이 실행마다 매니페스트의 `url`에 streamable HTTP로 붙어 도구 목록을 읽고 도구를 부른 뒤 닫는다. 서버 프로세스를 새로 띄우지 않으므로 임베딩 모델과 색인을 올린 서버가 질문마다 시작 비용을 치르지 않는다(스토리 1). 헤더 값은 접속 직전에 `[server.headers]`의 환경 변수에서 읽어 요청에만 싣는다. 원격 서버의 도구도 stdio 서버의 도구처럼 `ToolSpec.server`에 플러그인 이름을 단다(스토리 13). 여는 동안 실패하면 실행은 원인 `tool_connection`의 `run_failed`로 끝나고, 문구 `MCP 서버 <이름>(<url>)에 붙지 못했다: <원인>`만 보고 꺼진 서버(`ConnectError: All connection attempts failed`), 틀린 토큰(`… (HTTP 401 Unauthorized)`), 빠진 환경 변수(`헤더 <헤더 이름>의 환경 변수 <변수 이름>이 없다`)가 갈린다(스토리 5·6·7). 서버가 받은 토큰을 오류 글에 되울려도 실패 문구와 트레이스에는 `[가림: 헤더 <헤더 이름>]`이 남는다(스토리 8). 루트 로거를 DEBUG로 켜도 `secret_args`의 값과 헤더 값이 로그에 남지 않는다(스토리 21).

02는 01 뒤이고 03과 04를 막는다. 01이 남긴 http 갈래의 임시 실패(`NotImplementedError`)를 실제 접속으로 바꾸고, 01이 둔 그 시험을 실제 접속의 시험으로 바꾼다.

**병합 뒤에 틈이 있다(to-tickets에서 사용자가 네 장 분할을 골랐다).** 이 티켓은 라이브러리의 종료 요청을 그대로 쓴다(`terminate_on_close`의 기본값 True). 정상 닫기에서는 라이브러리가 세션 종료 요청(DELETE)을 보내 서버에 닿지만(쟀다, `http_close.py`의 `normal`), 실행 기한으로 취소된 실행은 보내지 않아(쟀다, 같은 프로브의 `deadline_plain`) 서버가 그 세션을 유휴 만료까지 쥔다(mcp 2.3.0 `server/streamable_http_manager.py`의 `DEFAULT_SESSION_IDLE_TIMEOUT`이 `30 * 60`초다, 코드를 읽었다). `serve` 종료로 취소된 실행도 같은 취소라 보내지 않는다고 본다(어림. 프로브는 기한만 잰다). 03이 닫고, 03의 스토리 12 시험이 `serve` 종료 쪽을 잰다. 이 티켓이 쓰는 문장(어댑터의 모듈 독스트링, `.claude/rules/adapters.md`, `.claude/rules/core.md`)은 틈 동안에도 참이어야 한다. http 전송에 대해 "취소된 실행에서도 닫는다"를 약속하지 않는다.

근거는 `.scratch/mcp-http/spec.md`의 "접속"과 그 2026-11-09 명세 검토 주석, "실패 문구"와 그 주석 둘(응답 훅의 상태, 가리기), "로그"와 그 주석, "세션을 여는 자리와 두 전송의 공통", "고칠 자리의 묶음"의 B 줄과 그 주석의 B1, Testing Decisions의 "시험 픽스처의 모양과 더한 사례"와 그 주석이다. 측정은 `.scratch/mcp-http/probes/http_close.py`(픽스처 서버 `http_fixture_server.py`)와 그 `README.md`이고 다시 돌리지 않는다. 앞선 결정은 ADR 0049의 결정 "접속"·"실패"·"의존"·"시험"과 Consequences "구현 티켓이 함께 고칠 자리"·"문구에 실리는 것과 실리지 않는 것"·"로그"·"approval-rules와의 접점", 그 2026-11-09 이력 "오류 응답의 상태를 원인에 덧붙인다"와 "서버가 되울린 헤더 값을 실패 문구에서 가린다"다.

**Blocked by:** 01 (계약 — mcp 매니페스트의 `[server]`가 `transport`로 stdio와 http를 가른다). 01의 `HttpServer` 모델, 어댑터의 `transport` 갈래, 여는 문맥의 공통 자리를 쓴다

**Status:** ready-for-agent

### 접속

- [ ] **어댑터는 접속 직전에 `[server.headers]`의 환경 변수를 매니페스트에 적힌 순서로 읽는다.** 하나라도 없으면 붙지 않고 `ConnectionError`로 끝내며 원인은 `헤더 <헤더 이름>의 환경 변수 <변수 이름>이 없다`다. 여럿이 없으면 그 문장을 매니페스트 순서로 `; `로 잇는다. 빈 문자열도 있는 것으로 보고 그대로 싣는다. 값에 ASCII 인쇄 가능 글자(0x20~0x7e)와 탭이 아닌 글자가 들면 값을 라이브러리에 넘기지 않고 붙지 않으며, 원인은 `헤더 <헤더 이름>의 환경 변수 <변수 이름>의 값에 헤더 값으로 쓸 수 없는 글자가 있다`다(여럿이면 같은 규칙으로 잇는다). 어느 문장에도 값은 없다. 환경을 읽는 코드는 어댑터의 http 갈래에만 있다(`.claude/rules/adapters.md`)
- [ ] **클라이언트는 `httpx2.AsyncClient`다.** 기본 헤더가 그 값들이고, 기한은 mcp가 자기 클라이언트에 쓰는 값(접속·쓰기·풀 30초, 읽기 300초), `trust_env`와 `follow_redirects`는 기본값이다. 같은 출처의 리디렉션은 라이브러리가 자기 요청마다 스스로 따른다(명세 "닫기"의 주석). 그 클라이언트를 mcp의 `streamable_http_client`에 넘겨 세션을 열고 `initialize`하고 도구 목록을 읽는다(쪽 나눔의 상한은 stdio와 같다). 그 뒤의 호출은 stdio와 같은 연결이다
- [ ] **도구마다 `ToolSpec.server`에 플러그인 이름이 실린다.** 두 서버 가운데 하나가 http여도 서버 이름이 실리는 것을 시험으로 본다(ADR 0049 "approval-rules와의 접점". approval-rules는 2026-11-08에 끝났다)

### 실패 문구

- [ ] **문구는 `MCP 서버 <이름>(<url>)에 붙지 못했다: <원인>`이고 `<url>`은 매니페스트의 `url` 그대로다**(쿼리 문자열과 조각 포함, ADR 0049 결정 "주소"). `<원인>`은 지금의 규칙(예외 종류와 글, 예외 그룹은 펼친다)대로다
- [ ] **응답 훅(`event_hooks`의 `response`) 하나를 단다.** 훅은 POST 응답마다 받아 둔 상태(메서드·상태 코드·이유 구절)를 바꾸고, 2xx면 지우며, GET과 DELETE의 응답은 받아 두지 않는다. 여는 동안 실패했을 때 받아 둔 상태가 있으면 원인 끝에 ` (HTTP <상태 코드> <이유 구절>)`을 덧붙인다. 응답 본문은 읽지 않는다. 마지막 오류 응답 하나를 두는 옛 규칙은 라이브러리가 삼킨 GET 알림 흐름의 405나 라이브러리가 따른 307을 뒤의 다른 실패에 붙인다(명세 "실패 문구"의 첫 주석. httpx2의 응답 훅은 리디렉션 응답에서도 돈다)
- [ ] **서버가 되울린 헤더 값을 가린다(사용자가 골랐다).** 가릴 글은 헤더마다 환경에서 읽은 값 전체와, 값이 공백 하나로 나뉜 `<낱말> <나머지>` 꼴이면 그 나머지(`Bearer <토큰>`의 토큰)다. 8자보다 짧은 글은 가리지 않는다. 가리는 자리는 어댑터가 짓는 두 문구, 곧 여는 동안의 `ConnectionError` 문구와 도구 호출이 실패할 때의 `RuntimeError` 문구다. 긴 글부터 글자 그대로 찾아 `[가림: 헤더 <헤더 이름>]`으로 바꾼다. 가린 것이 하나라도 있으면 그 예외를 `from None`으로 던져 원인 체인의 글에 값이 남지 않게 한다. `except` 밖에서 던지는 모양(`.claude/rules/adapters.md`의 `read_skill` 항목)은 쓰지 않는다. core가 닫기의 정리 코드가 덮은 취소를 `__context__`로 찾기 때문이다(core의 `_cancellation_under`, 명세 "실패 문구"의 가리기 주석). 가린 것이 없으면 지금처럼 원인을 잇는다. 알려진 한계(바꿔 되울린 값, 8자보다 짧은 값, 도구가 오류로 돌려준 결과의 본문)는 어댑터의 모듈 독스트링에 적는다

### 의존과 경계

- [ ] **`httpx2`를 런타임 직접 의존으로 선언한다(`httpx2>=2.13,<3`).** `pyproject.toml`의 주석 둘을 함께 고친다. `[project]` 머리 주석의 mcp 대목 뒤에 httpx2가 직접 의존인 까닭을, `[dependency-groups]` 머리 주석의 "mcp 는 2 에서 httpx 대신 httpx2 를 쓴다" 대목에 httpx2가 직접 의존이 된 사실을 잇는다(ADR 0049 Consequences). `uv lock`을 돌려 잠금 파일의 차이를 PR 본문에 적는다. 명세 검토가 저장소 밖 사본에서 돌렸을 때는 84 packages로 풀렸고 차이는 agent-os 자신의 의존 두 줄이었다(일지 2026-11-09-2138, 손으로 봤다)
- [ ] **import-linter의 금지 목록 둘에 `httpx2`를 더한다.** `pyproject.toml`의 "core knows no provider"와 "sdk knows no engine"이다. `uv run lint-imports`가 판정한다
- [ ] **`docs/constitution/tech.md` 런타임 의존성 행의 `httpx2` 괄호를 선언한 사실로 고친다.** 지금 괄호는 "mcp-http의 접속 티켓(02)이 선언한다"와 락이 바뀌지 않는다는 어림이다(to-tickets PR이 "첫 티켓"을 그렇게 고쳤다). 같은 행의 pyjwt 문장처럼 이 티켓이 선언했다는 것과 `uv lock`의 결과로 바꾸고, 헌법 판을 patch로 올린다(`docs/constitution/README.md`. 올린 까닭은 일지에 적는다)

### 문서

- [ ] **어댑터의 모듈 독스트링에 http 전송을 더한다.** 접속, 헤더 값의 읽기와 판정, 실패 문구, 가리기와 그 한계, 응답 훅의 역할, 닫는 길(이 티켓에서는 라이브러리의 종료 요청)이다. `.claude/rules/channel.md`가 "닫는 시간은 `adapters/mcp.py`의 모듈 독스트링"이라 가리키므로 http 전송의 닫는 시간을 틈에 맞게 적는다
- [ ] **`.claude/rules/adapters.md`의 MCP 항목 셋과 예외 항목을 고친다.** 어댑터 목록의 "mcp 2의 stdio 클라이언트와 세션"(두 전송, 그리고 "취소된 실행에서도 서버를 닫은 뒤 끝난다"가 stdio의 것임), 런처 항목의 범위(stdio 모양에만 걸린다), 예외 항목의 `<명령>`(모양에 따라 명령이나 주소)과 "원래 예외가 `__cause__`다"(가린 것이 있으면 원인을 잇지 않는다)다. 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다(`.claude/rules/agent-docs.md`)
- [ ] **`.claude/rules/core.md`의 포트 표 `ToolSource` 행의 첫 어댑터 칸과 실패 정책의 "MCP 서버 시작 실패"를 두 전송에 맞게 고친다**(ADR 0049 Consequences)
- [ ] **옛 표현을 저장소 전체에서 grep해 살아 있는 문서에 잔존이 0인지 본다**(`CLAUDE.md` 작업 규약 4). MCP 서버가 stdio 프로세스뿐이라고 읽히는 문장, 그리고 01이 틈 동안 쓴 문장(http 모양은 읽히지만 아직 붙지 않는다. `.claude/rules/sdk.md`와 어댑터의 독스트링·주석)과 `아직 구현되지 않았다`이다. 기록은 고치지 않는다

### 시험 픽스처

- [ ] **HTTP 픽스처를 둔다.** 지금의 stdio 픽스처와 같은 `MCPServer`에 add 도구와 잠드는 도구를 두고, 요청마다 메서드·경로·쿼리 문자열·`Authorization`·`Mcp-Session-Id`를 기록 파일에 JSON 한 줄로 남기는 ASGI 미들웨어를 앞에 끼워 uvicorn으로 루프백의 빈 포트에 띄운 별도 프로세스다. 프로브의 `http_fixture_server.py`가 그 모양이고 시험 픽스처는 그것을 옮긴다. 시험은 포트가 열릴 때까지 TCP 접속으로 기다리고 프로세스는 쥔 핸들로만 끈다
- [ ] **픽스처 서버와 그것을 띄워 포트를 기다리는 도우미는 처음부터 04의 실제 모델 시험(`tests/test_main.py`)과 어댑터 시험이 함께 쓰는 자리에 둔다.** 02 뒤에 03과 04가 나란히 돌고 03은 같은 픽스처에 인자를 더하므로, 04가 픽스처를 옮기지 않아도 되게 하기 위해서다
- [ ] **이 티켓이 쓰는 픽스처의 선택 인자는 넷이다.** 기대한 `Authorization` 값과 다른 요청을 401로 막는 것, 되울림 모드(초기화나 지정한 도구의 호출에 401과, 받은 `Authorization` 값을 글에 담은 JSON-RPC 오류 본문을 돌려준다), 리디렉션 모드(경로 끝에 `/`가 없는 요청을 `/`를 붙인 경로로 307로 돌려보낸다), 도구 목록 요청(`tools/list`)에 HTTP 200과 JSON-RPC 오류 본문으로 답하는 것이다. DELETE를 잠재우거나 끊는 것과 DELETE만 다른 출처로 돌려보내는 것은 03이 더한다

### 어댑터 시험의 사례

- [ ] 도구 목록·호출·`ToolSpec.server`(두 서버 가운데 하나가 http)
- [ ] 헤더 변수가 있으면 그 값이 서버의 요청 헤더에 닿는다(기록 파일). 빈 값의 변수로도 붙고 그 헤더가 빈 값으로 닿는다
- [ ] 헤더 변수가 없으면 붙지 않고 문구가 헤더 이름과 변수 이름을 든다. 둘이 없으면 둘 다 든다. 끝에 개행이 붙은 값의 변수로는 붙지 않고 문구가 헤더 이름과 변수 이름을 들며, 값은 문구와 원인 체인 어디에도 없다
- [ ] 닫힌 포트에 쿼리 문자열이 든 주소로 붙으면 문구에 서버 이름과 매니페스트의 `url` 그대로의 주소(쿼리 문자열 포함)가 있고 토큰 값은 문구와 원인 체인에 없다. 같은 사례에서 루트 로거를 기본 수준(WARNING)으로 잡은 로그에 쿼리 문자열이 없다는 단언을 둔다. 지금의 구현으로는 빨개질 수 없는 회귀 단언이라 이 티켓의 수락으로 세지 않는다(명세 "로그")
- [ ] 401을 돌려주는 서버에 붙으면 원인에 `HTTP 401 Unauthorized`가 있다
- [ ] 되울림 모드에서 여는 동안의 실패와 도구 호출 실패의 문구에 값 전체도 `Bearer` 뒤의 토큰도 없고 `[가림: 헤더 Authorization]`이 있으며, 원인 체인(`__cause__`)에도 값이 없다
- [ ] 리디렉션 모드에서 초기화와 도구 호출이 선다(같은 출처의 307은 라이브러리가 따른다)
- [ ] 리디렉션 모드에 도구 목록 요청을 JSON-RPC 오류로 답하는 인자를 겹쳐 붙으면 여는 동안 실패하고, 원인 끝에 `HTTP 307`이 붙지 않는다. 마지막 POST가 307을 지나 2xx로 끝났으므로, 응답 훅이 POST의 2xx에서 받아 둔 상태를 지우는지를 가르는 사례다(옛 규칙 "2xx가 아닌 응답의 마지막 하나"면 지나간 307이 붙는다. 명세 "실패 문구"의 첫 주석). 상태를 덧붙이는 것은 여는 동안의 실패뿐이라 도구 호출이 실패하는 사례로는 이 규칙을 잴 수 없다
- [ ] 정상 닫기에 종료 요청(DELETE)이 서버에 닿는다(라이브러리가 보낸다. 기록 파일의 `Mcp-Session-Id`가 앞선 POST의 것과 같다)
- [ ] 선례는 `tests/adapters/test_mcp.py`의 서버 기동 실패·둘째 서버 실패 시험이다. 어댑터 시험은 본문에서 `async with`로 연다(`.claude/rules/tests.md`)

### core를 지나는 시험

`run()`은 도구 포트를 인자로 받으므로 실제 어댑터를 넘긴다. 서버의 모양은 플러그인 포트의 매니페스트에서 오는데, `tests/core/test_run.py`의 가짜 플러그인 포트(`FakePlugins`)가 내는 mcp 매니페스트(`_mcp_manifest`)는 지금 stdio 모양(`command = "fake-server"`)뿐이다. 그 포트가 http 모양의 매니페스트도 낼 수 있게 넓힌다. 03의 core 시험이 이것을 쓴다.

- [ ] **서버를 끈 채 돌린 실행은 원인 `tool_connection`으로 끝난다**(기능 계획의 수락)
- [ ] **`secret_args`가 있는 도구를 http 모양의 서버에 부르며 루트 로거를 DEBUG로 켜면 그 값과 헤더 값이 로그에 없다**(ADR 0049 Consequences "로그"의 구현 티켓 수락). mcp의 클라이언트 로거는 DEBUG로 보내는 메시지 전체를 찍으므로(`Sending client message: …`) 막는 자리를 이 티켓이 정하고 그 까닭을 어댑터의 독스트링에 적는다. 단언 전에 양성 대조로 그 값이 서버에 닿았는지(도구가 받은 인자, 기록 파일의 헤더)를 본다
