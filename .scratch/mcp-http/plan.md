# mcp-http: 원격 MCP 서버에 주소로 접속해, 실행마다 서버를 새로 띄우는 시작 비용을 없앤다.
**슬라이스:** 7
**Blocked by:** 없음

원격 MCP 서버에 접속한다(`[server]`의 http 모양). claude-code-compat 행에서 이 부분만 떼어 앞당겼다(ADR 0046, ADR 0042의 2026-11-06 이력). 공개 데모(public-demo)로 가는 행이라 pilot-portal과 함께 먼저 한다(ADR 0046의 2026-11-06 이력). 지금은 core가 실행마다 MCP 서버에 연결하고 stdio 서버는 그때마다 새 프로세스로 뜨므로(`core/run.py`의 `self._tools.connect`, `adapters/mcp.py`의 `stdio_client`), 임베딩 모델과 색인을 올리는 서버는 질문마다 시작 비용을 치른다. 원격 MCP 서버에는 실행마다 접속만 하고, 도구 목록은 지금처럼 실행마다 다시 읽는다. 첫 티켓은 계약이다: 모양은 ADR 0042 "원격 MCP" 줄에서 출발한다. 주소는 배포 환경마다 달라지므로, 그 모양을 바꿔야 하면(주소를 저자의 매니페스트가 아니라 mcp-trust가 계획한 운영자의 서버 파일에 두는 것 등) 설계 인터뷰가 mcp-trust 행과 맞춰 ADR 0042의 이력으로 바꾼다. 헤더의 값은 환경에서만 읽는다(원칙 V). 클라이언트는 고정한 mcp 2.3.0의 `streamable_http_client`인데, 이 함수에는 헤더 인자가 없어 토큰 헤더를 실으려면 `httpx2.AsyncClient`를 넘겨야 한다. httpx2는 잠금 파일에 이미 있지만, 직접 import하는 의존은 선언하는 관행이 있다(`pyproject.toml`의 `[dependency-groups]` 첫 주석, ADR 0023의 pyjwt). 접속 실패는 지금의 `ConnectionError`와 원인 `tool_connection` 그대로이고, 런처와 프로세스 그룹 정리(ADR 0034)는 이 경로에 걸리지 않는다. 도구별 `[server.secret_args]`는 두 모양에 똑같이 건다. stdio 모양은 지우지 않는다(두 모양의 역할 분담은 ADR 0046). approval-rules와 이 행이 둘 다 `adapters/mcp.py`를 고치므로, 나중에 병합하는 쪽이 충돌을 풀고 approval-rules가 도구마다 싣는 서버 이름이 원격 MCP 서버의 도구에도 실리는지를 시험으로 본다(ADR 0046). 설계 인터뷰가 먼저 볼 것: 서버가 꺼졌을 때 무엇이 보이는지(`tool_connection` 실패와 diag-bundle의 접속 확인). 수락: 시험용 원격 MCP 서버에 calc 예시가 주소로 붙어 도구를 쓰고 트레이스가 남으며, 서버를 끈 채 돌린 실행이 원인 `tool_connection`으로 끝나는 테스트가 통과한다
