# 04: 플러그인 화면의 행이 접속 확인의 결과를 보인다

**What to build:** 운영자가 관리 화면의 첫 페이지(플러그인 목록)를 열면, 켜 둔 원격 MCP 서버와 켜 둔 모델의 행이 바로 `확인하는 중`이 되었다가 `붙음`이나 `붙지 못함`으로 바뀐다. 붙지 못했으면 그 까닭의 글 전체가 함께 보인다. 화면을 열어 둔 동안 30초마다 다시 확인하므로, 서버가 꺼지면 30초쯤 뒤 그 행이 `붙지 못함`으로 바뀐다. 다른 탭을 보는 동안에는 확인이 멈추고, 돌아오면 바로 한 번 확인한다. 다시 확인하는 동안 앞선 결과가 지워지지 않는다. 확인 요청 자체가 실패하면 앞선 결과를 지우고 `확인하지 못함`을 보인다. 켜 둔 stdio MCP 서버의 행에는 '접속 확인' 버튼이 있고, 누르면 응답까지 버튼이 눌리지 않으며, 응답 뒤에는 결과와 확인한 시각이 보인다. 꺼 둔 행에는 결과가 보이지 않고 버튼도 누를 수 없다. 매니페스트를 읽지 못한 표지 행과 에이전트·스킬의 행에는 접속 확인이 없다. 관리 화면 e2e의 기존 장면은 실제 모델 제공사에 닿지 않고, 새로 생긴 행의 글자 때문에 깨지지 않는다.

02와 03 뒤다(to-tickets에서 사용자가 골랐다). 화면이 처음 붙는 dev에서 행마다 실제 확인의 결과가 보이게 하려는 것이다. 이 티켓이 병합되면 화면이 확인을 보내기 시작하므로, 기존 e2e 장면을 지키는 일도 이 티켓이 한다(명세 검토 S3).

근거는 명세 `.scratch/connection-check/spec.md`의 "간격과 보이지 않는 탭", "행에 보이는 것", "겹치는 확인과 잦은 확인"의 "화면이 줄인다", Testing Decisions의 셋째와 넷째 가운데 기존 장면의 몫, 사용자 이야기 1~3과 8~23이다. 결정은 ADR 0067의 결정 "화면이 스스로 하는 확인"·"자리"·"꺼 둔 플러그인"이고, 같은 읽기 정책의 다른 예외는 ADR 0063 결정 "주기 읽기의 예외"다. 화면의 규칙은 `.claude/rules/web-workspace.md`와 `.claude/rules/web-admin.md`다. 이 티켓의 "명세 검토"와 그 번호(S1, S2, S3)는 일지 `docs/journal/2026-11-22-0159-connection-check-tickets.md`의 "명세 검토" 절을 가리킨다.

### 코드를 쓰기 전

- [x] 화면 작업 전에 Skill 도구로 `sync-design-system`을 `확인`으로 부른다
- [x] 행마다 확인을 읽는 자리의 모양을 먼저 정한다. 관리 화면의 부품은 층으로 나뉜다(organisms는 여러 부품을 묶은 덩어리, templates는 배치, pages는 페이지 하나). organisms와 templates는 읽기 훅(서버의 값을 읽어 오는 함수)을 부르지 않고 pages가 읽어 넘긴다(`web/eslint.config.mjs`의 층 규칙). 지금 목록은 pages가 읽어 organism(`web/apps/admin/components/organisms/PluginList.tsx`)에 넘기고, 행은 그 organism 안에서 그려진다. 행마다 읽는 부품을 pages 쪽에 두고 organism에 넘길지, 여러 행을 한 훅으로 읽을지를 정해 일지에 적는다(명세 검토 S2)
- [x] 디자인 시스템의 기존 부품으로 행의 상태를 그릴 수 없으면, 코드보다 먼저 `/ui-design connection-check`로 그린다(명세 "행에 보이는 것"). 기존 부품으로 그리면 어느 부품인지 일지에 적는다

### 행에 보이는 것

- [x] 행마다 명세 "행에 보이는 것"의 표대로 보인다. 누른 확인의 요청이 실패한 stdio 행은 앞선 결과를 지우고 `확인하지 못함`과 그 실패의 글과 누른 시각을 보이며, 버튼이 다시 눌린다(명세 검토 S10이 더한 줄)
- [x] 상태는 색만이 아니라 글자로 읽힌다. 화면 읽기 도구에는 상태가 바뀔 때만 알리고, 30초마다 같은 결과를 다시 읽어 주지 않는다
- [x] 플러그인 상세 페이지에는 두지 않는다

### 간격과 읽기

- [x] 목록을 그리면 켜 둔 원격 MCP 서버와 켜 둔 모델의 행마다 바로 한 번 확인하고, 그 뒤 30초마다 다시 확인한다. 보이지 않는 동안에는 보내지 않고 돌아오면 바로 한 번 확인한다. 다른 페이지로 가거나 탭을 닫으면 멈춘다. 관리 토큰이 없으면 부르지 않는다
- [x] 목록을 다시 읽어 행이 꺼짐으로 바뀌면 그 행의 확인을 멈추고 결과를 지우며, 켜짐으로 바뀌면 바로 확인한다. 목록의 새로 고침 버튼을 누르면 스스로 하는 확인도 바로 한 번 다시 한다
- [x] 확인 요청이 실패하면 앞선 결과를 지우고 `확인하지 못함`과 그 실패의 글을 보인다(명세 "행에 보이는 것"의 표). 401이면 다른 관리 요청처럼 관리 토큰을 내려놓는다. 응답이 `disabled`나 `not_applicable`이면 그 행의 결과를 지우고 목록을 다시 읽는다
- [x] 스스로 하는 확인은 행마다 한 번에 하나만 보내고, '접속 확인' 버튼은 응답이 올 때까지 눌리지 않는다
- [x] 관리 화면의 읽기 훅은 SWR(서버의 값을 읽어 두고 때맞춰 다시 읽는 라이브러리)을 쓴다. SWR의 기본 동작으로는 되지 않는 셋을 되게 한다. `확인하지 못함`이 된 행도 30초 뒤 다시 확인을 보낸다. 확인이 날아가는 동안 목록의 새로 고침을 눌러도 그 행의 요청은 하나다. 껐다 다시 켠 행에는 옛 결과가 보이지 않고 확인이 바로 나간다(명세 Testing Decisions의 셋째, 명세 검토 S1)
- [x] stdio 서버의 결과는 화면에만 있다. 목록을 다시 읽어도 남고, 그 플러그인을 끄거나 페이지를 떠나면 사라진다
- [x] `.claude/rules/web-admin.md`에 읽기 정책의 예외(플러그인 화면에서만, 창이 보이는 동안만, 켜 둔 원격 MCP 서버와 모델의 행 수만큼)를 적고, 읽기 정책의 주석을 고친다. 규칙 파일을 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다(`.claude/rules/agent-docs.md`)

### 시험(명세 Testing Decisions의 셋째)

- [x] 브라우저 없이 화면 부품을 띄우고 가짜 응답과 가짜 시계로 본다(선례 `web/apps/admin/components/pages/HomePage.test.tsx`). 명세 Testing Decisions의 셋째가 든 사례 전부와, 위 SWR의 셋을 본다
- [x] 플러그인을 켜면 그 행의 확인이 바로 시작되고, 다시 켰을 때 옛 결과가 보이지 않는 것을 본다(이야기 21, 명세 검토 S9)
- [x] 생김새는 스토리(부품을 상태마다 따로 띄워 보는 견본)와 사진 정답(사진 비교가 견주는 기준 그림)으로 지킨다. 행의 상태마다 하나씩이다

### 기존 e2e를 지키기

- [x] 관리 화면 e2e의 준비(`web/apps/admin/e2e/stack.ts`)가 띄우는 `serve`가 접속 확인으로 실제 모델 제공사에 닿지 않게 한다. 그 준비는 `serve`에 자기 환경을 그대로 물려주고 켜 둔 모델 픽스처 둘의 제공사가 모두 `anthropic`이라, 셸에 키가 있는 로컬에서는 실제 제공사에 30초마다 요청이 두 건씩 갈 수 있다(명세 Testing Decisions의 넷째). 요청이 나가지 않는다는 것을 시험이나 손으로 본 기록으로 확인한다. 실제 모델을 쓰는 e2e(`-m llm_widget`, `-m llm_portal`)는 다른 준비(`web/packages/e2e-stack`)로 돌고 관리 화면을 열지 않으므로 그대로 둔다
- [x] 플러그인 화면을 여는 기존 장면이 모델 행의 새 글자에 깨지지 않는지, 키가 없는 CI와 키가 있는 로컬에서 모두 본다. 그때 기존 장면의 모델 행에 보인 글을 일지에 적는다(명세 Further Notes "재지 않은 것"의 마지막 항목). 단독 배포 e2e는 관리 화면을 브라우저로 열지 않으므로 이 티켓이 볼 것이 없다(명세 Testing Decisions의 넷째) _(키가 없는 셸과, 가짜 키를 `ANTHROPIC_API_KEY`에 넣은 셸에서 새 장면이 둘 다 통과했다. 진짜 키는 이 PC에 없어 쓰지 못했다. 기존 장면은 모델 행의 글을 단언하지 않아 거기 보인 글은 새 장면의 것으로 갈음했다. 일지 "기존 e2e를 지킨 것")_
- [x] 켜 둔 원격 MCP 서버와 모델의 행이 여럿일 때 느린 확인이 같은 화면의 다른 관리 요청을 늦추는지(브라우저가 주소 하나에 여는 연결의 상한) 보고 일지에 적는다(명세 검토가 확인하지 못한 것) _(재지 못했다. 어림과 05로 넘긴 까닭을 일지 "보지 못한 것"에 적었다)_
