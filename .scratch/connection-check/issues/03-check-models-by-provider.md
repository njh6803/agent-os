# 03: 모델의 접속 확인 — anthropic은 그 모델 하나를 묻고 openai-compatible은 목록에서 이름을 찾는다

**What to build:** 운영자가 켜 둔 모델을 `GET …/connection-check`로 확인하면 `serve`가 제공사마다 다른 요청 한 건을 보낸다. 제공사가 `anthropic`이면 `GET /v1/models/<model_id>`로 그 모델 하나를 묻고 200이면 `reached`다. `openai-compatible`이면 모델 서버의 `GET <base_url>/models`로 목록을 받아 `model_id`와 글자가 같은 `id`가 있으면 `reached`다. 두 요청 모두 답변을 만들지 않아 토큰을 쓰지 않는다. 붙지 못하면 `unreached`와 `serve`가 지은 글 `모델 <이름>(<주소>)에 붙지 못했다: <뒷부분>`이 오고, 뒷부분은 닫힌 아홉 갈래 가운데 하나다(꺼진 서버는 `서버에 닿지 못했다`, 틀린 키는 `키를 받아들이지 않았다(HTTP 401)`, 틀린 모델 이름은 그 이름의 모델이 없다는 글). 서버가 오류 본문에 적은 글과 되울린 키는 화면에 닿지 않는다. 확인은 실행과 같은 주소, 같은 키, 같은 프록시와 덧붙임 헤더로 묻고, 요청을 다시 보내지 않으며, 10초 기한에 닿으면 `<N>초 안에 답이 없었다`로 끝난다. `anthropic` 패키지가 직접 쓰는 의존성으로 선언된다. 01이 남긴 틈 가운데 모델의 몫이 닫힌다. 화면은 아직 이 경로를 부르지 않는다(04).

01 뒤에 02와 나란히 간다. 이 기능에서 헌법(`docs/constitution/tech.md`, `operations.md`)을 고치고 헌법의 판을 올리는 티켓은 이것 하나다. 작업 규약 2의 예외인 까닭은 명세 Further Notes의 "헌법을 고치는 티켓은 하나다"에 있다. 02와 함께 고치는 파일은 `.claude/rules/adapters.md`(서로 다른 항목)뿐일 것으로 본다(어림).

근거는 명세 `.scratch/connection-check/spec.md`의 "모델을 확인하는 법" 전체, "화면에 보이는 글과 비밀"의 모델 쪽과 아홉 갈래의 표, "기한"의 모델 행, "결과가 남는 자리"의 HTTP 라이브러리 로거 항목, "포트와 층"의 "결과 타입이 사는 층", Testing Decisions의 둘째 가운데 모델 몫과 다섯째·일곱째, Further Notes의 "헌법을 고치는 티켓은 하나다"·"구현 티켓이 함께 고칠 자리"다. 측정은 `.scratch/connection-check/probes/model_requests_live.py`와 `model_requests_loopback.py`이고, 설치한 `anthropic`·`openai`·`langchain-anthropic`의 판이 그 `README.md` 표의 판과 같으면 다시 돌리지 않는다. 결정은 ADR 0067의 결정 "모델을 확인하는 법"·"비밀"·"기한"과 이력 2026-11-21 "모델은 제공사마다 다른 요청으로 확인하고, anthropic 패키지를 직접 의존으로 선언한다"다. 프록시와 덧붙임 헤더를 따르는 것은 to-tickets에서 사용자가 골랐다(명세 위의 10). import 계약을 어디까지 둘지는 일지 `docs/journal/2026-11-21-0502-connection-check-spec.md`의 "다음"이 이 티켓에 넘겼다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-22-0159-connection-check-tickets.md`의 "명세 검토" 절을 가리킨다.

**Blocked by:** 01

**Status:** ready-for-agent

### 요청

- [ ] `anthropic`은 그 모델 하나를 묻는 `GET /v1/models/<model_id>` 한 건을 보내고, 응답이 200이면 돌아온 id가 물은 id와 달라도 `Reached`다(날짜를 뗀 이름을 적은 모델 파일, 이야기 7)
- [ ] `openai-compatible`은 `GET <base_url>/models` 한 건을 보내고, 응답이 200이고 첫 쪽의 목록에 `model_id`와 글자가 같은 `id`가 있으면 `Reached`다. 다음 쪽은 읽지 않는다
- [ ] 확인은 요청을 한 번만 보낸다. 라이브러리의 재시도를 끈다
- [ ] 기한은 어댑터를 만들 때 주는 값이고 기본이 10초다. 시험은 짧은 기한을 준다(명세 "값을 주는 자리")
- [ ] `anthropic`은 실행과 같은 인자로 만든 모델 객체가 정한 주소와 키, 프록시, 덧붙임 헤더를 받아 확인하는 클라이언트에 넘긴다. 접속 확인이 환경 변수를 따로 읽어 같은 규칙을 다시 짓지 않는다(명세 "실행과 같은 주소와 같은 키", 사용자가 고른 10)
- [ ] `openai-compatible`은 모델 파일의 `base_url`로 묻고, 키는 실행이 호출마다 키를 읽는 규칙 그대로 읽는다. `api_key_env` 칸이 없으면 실행처럼 자리 채움 글자(`no-key`)를 보낸다. 환경의 `OPENAI_API_KEY`를 싣지 않고 `OPENAI_PROXY`를 따르지 않는다
- [ ] 키가 없거나(`anthropic` 모델 객체의 키 칸이 비었다, 또는 `openai-compatible` 모델 파일에 `api_key_env` 칸이 있는데 그 변수가 없거나 비었다) `openai-compatible`의 그 변수 값에 인증 헤더로 보낼 수 없는 글자가 있으면 요청을 보내지 않고 `Unreached`로 가른다. 키 모양의 갈래는 `openai-compatible`에만 있다(명세 아홉 갈래의 표)
- [ ] 모델 종류가 아닌 매니페스트와 공백뿐인 `model_id`는 실행과 같은 구성 오류의 예외로 올린다(관리 경로가 500으로 답한다)
- [ ] 어댑터는 라이브러리의 예외나 응답 객체를 `Unreached.reason`의 `str` 밖으로 내보내지 않는다. 서드파티 타입이 포트의 반환값에 비치지 않는다(`CODING_STANDARDS.md`의 "서드파티는 경계에서 감싼다")

### 화면에 보일 글

- [ ] 까닭은 명세 "화면에 보이는 글과 비밀"의 아홉 갈래 가운데 위에서부터 먼저 맞는 것이다. 시간 초과는 닿지 못함보다 먼저 가른다(두 라이브러리 모두 시간 초과의 예외가 연결 오류 예외의 하위 종류다). 갈래는 예외의 종류가 아니라 서버가 준 응답 상태 번호로 가른다
- [ ] 앞머리는 `모델 <이름>(<주소>)에 붙지 못했다: `다. 주소는 요청을 보낸 API의 뿌리이고, `anthropic`에서 모델 객체의 주소 칸이 비었으면 클라이언트가 푼 값(기본 `https://api.anthropic.com`)이다. 사용자 정보 자리(`user:password@`)와 쿼리 문자열을 떼고, 인쇄할 수 없는 글자는 실행의 실패 글이 주소를 싣는 규칙과 같게 다룬다(명세 검토의 nit)
- [ ] 라이브러리 호출에서 난 예외는 종류를 가리지 않고 갈래의 `Unreached`로 바꾸고, 원래 예외를 올리지도 기록하지도 않는다(명세 "예외를 잇지 않는다")
- [ ] 환경 변수의 이름(`ANTHROPIC_API_KEY`, `api_key_env`에 적힌 글자)은 싣고 값은 어느 갈래에도 싣지 않는다

### 의존성과 층 경계

- [ ] `pyproject.toml`에 `anthropic`을 `>=1.7,<2`로 직접 의존으로 선언하고, 잠금 파일의 차이로 설치되는 판이 그대로인지 보아 일지에 적는다
- [ ] 층 경계 계약의 금지 모듈 목록 둘(core가 제공사를 모른다는 계약, sdk가 엔진을 모른다는 계약)에 `anthropic`을 `openai`와 나란히 더한다. 채널과 관리와 조립 층이 import하지 못하게 막는 계약까지 둘지는 이 티켓이 계약 파일을 보고 정하고, 그 판단과 까닭을 일지에 적는다(일지 2026-11-21-0502 "다음", PR 618 claude-review의 Nit)
- [ ] `docs/constitution/tech.md`의 의존성 줄("anthropic SDK는 `langchain-anthropic` 뒤에서 온다")과 `pyproject.toml`의 같은 뜻의 주석을 고친다. 헌법의 판(`docs/constitution/README.md`)을 이 티켓에서 한 번 올리고, `tools/sibling_overlap.py`가 알리는 형제의 가장 높은 판보다 높게 고른다

### 시험(명세 Testing Decisions의 둘째 가운데 모델 몫)

- [ ] 가짜 모델 서버(`tests/adapters/fake_model_server.py`)로 붙어 본다. 그 독스트링이 "Chat Completions 하나"라 적으므로 모델 하나를 묻는 경로와 목록 경로를 더하며 함께 고친다(명세 검토의 nit)
- [ ] 두 제공사마다 본다. 붙는 서버는 `Reached`, 닫힌 포트는 `서버에 닿지 못했다`, 401은 `키를 받아들이지 않았다(HTTP 401)`, 없는 모델은 제공사마다의 글, 답이 늦는 서버는 짧게 준 기한 뒤 시간 초과의 글이다
- [ ] 하나를 묻는 요청에 다른 id를 200으로 돌려줘도 `Reached`다(이야기 7, 명세 검토 S9)
- [ ] 서버가 오류 본문에 키를 되울리고 표지 문구를 적어도 `reason`에 둘 다 없다. 키 글자만 보면 예외의 글을 옮기고 키만 가리는 구현이 초록이기 때문이다(이야기 24·25, 명세 검토 S9)
- [ ] 500, 429, 529에 가짜 서버가 받은 요청이 한 건이다(재시도 없음, 명세 검토 S9). 받은 요청의 메서드와 경로와 키 헤더가 기대와 같다
- [ ] 주소 변수에 사용자 정보(`user:pass@`)와 쿼리 문자열(`?k=v`)을 심어도 `reason`에 둘 다 없다(명세 검토 S9)
- [ ] 주소 변수를 바꾼 환경에서 `anthropic` 확인이 그 주소로 간다. 환경의 `ANTHROPIC_PROXY`에 가짜 프록시를 두면 확인 요청이 그 프록시를 지난다. 모델 객체가 그 변수에서 프록시 칸을 읽으므로 포트로 부르는 시험으로 잴 수 있다(사용자가 고른 10)
- [ ] 덧붙임 헤더는 지금 제품이 모델 객체에 채우는 자리가 없다(`chat_anthropic`이 그 칸을 주지 않고 모델 매니페스트에 헤더 칸이 없다). 그래서 포트로 부르는 시험은 어떤 구현에서도 초록이다. 확인하는 클라이언트를 모델 객체에서 짓는 함수가 모델 객체를 인자로 받게 두고, 그 함수에 덧붙임 헤더를 든 모델 객체를 넘겨 헤더가 요청에 실리는지 본다. 그런 함수를 두지 않기로 했으면 이 사례를 잴 수 없다는 것과 그 까닭을 일지에 적는다(명세 "실행과 같은 주소와 같은 키", to-tickets의 이음매 확인)
- [ ] 기한을 재는 단언의 상한은 `.claude/rules/tests.md`의 시간 단언 항목을 따른다
- [ ] 키가 없는 `anthropic` 모델에서 요청이 0건이고, 그때 모델 객체의 키 칸의 값을 시험으로 고정한다(명세 "키가 없는 `anthropic` 모델". 명세 검토는 빈 `SecretStr`로 읽었다)
- [ ] `openai-compatible` 모델이 `api_key_env` 칸이 없으면 자리 채움 글자를 싣고, 칸이 있는데 변수가 없거나 값의 글자가 맞지 않으면 요청이 0건이며 `reason`에 변수의 값이 없다. 확인이 모델 파일의 주소로 가고 환경의 `OPENAI_API_KEY`를 싣지 않는다

### 실제 서버 시험

- [ ] 키가 있을 때만 도는 시험(`-m llm`)에 하나를 더한다. 실제 `serve`를 띄워 기본 모델의 접속 확인이 `reached`인지 보고, `serve`의 표준 오류에 HTTP 라이브러리의 요청 줄(`HTTP Request:`)이 없는지 본다. 모델을 부르지 않는다. 테스트 데이터베이스 컨테이너가 떠 있어야 돈다(명세 Testing Decisions의 다섯째, 선례 `tests/test_main.py`의 실제 `serve` 시험)
- [ ] 로컬 모델 시험(`-m llm_local`)에 하나를 더한다. 빌린 서버마다 `openai-compatible` 모델의 접속 확인을 한 번 불러 `Reached`인지 본다(명세 Testing Decisions의 일곱째)
- [ ] `docs/constitution/operations.md`의 LLM 테스트 절에 위 두 시험을 적는다. 실제 `serve`로 기본 모델의 접속 확인을 보는 `-m llm` 시험(명세 Testing Decisions의 다섯째)과, 로컬 모델 시험이 빌린 서버마다 접속 확인을 한 번 부르는 것(같은 곳의 일곱째)이다
