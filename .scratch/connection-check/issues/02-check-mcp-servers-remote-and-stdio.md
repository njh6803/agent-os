# 02: MCP 서버의 접속 확인 — 원격 서버는 스스로, stdio 서버는 눌러서 붙어 본다

**What to build:** 운영자가 켜 둔 원격 MCP 서버(주소로 붙는 서버)를 `GET …/connection-check`로 확인하면, `serve`가 실행이 서버 하나를 여는 것과 같은 단계(접속, 세션 열기, 초기화, 도구 목록 읽기)를 지난 뒤 닫고 `reached`로 답한다. 꺼진 서버는 `unreached`와 연결 오류의 글이고, 토큰이 틀리면 글 끝에 `(HTTP 401 Unauthorized)`가 붙어 꺼진 서버와 갈린다. 답이 없는 서버는 10초 뒤 `MCP 서버 <이름>(<주소>)에 붙지 못했다: 10초 안에 준비되지 않았다`로 끝난다. 켜 둔 stdio MCP 서버(명령으로 띄우는 서버)를 `POST …/connection-check`로 확인하면 `serve`가 그 서버의 프로세스를 하나 띄워 같은 단계를 지난 뒤 끈다. 명령을 찾지 못하면 실행과 같은 실패 글이고, 기한은 20초이며, 확인이 끝난 뒤에도 기한에 닿은 뒤에도 띄운 프로세스가 서버에 남지 않는다. 01이 남긴 틈 가운데 MCP 서버의 몫이 닫힌다. 화면은 아직 이 경로를 부르지 않는다(04).

01 뒤에 03과 나란히 간다. 03과 함께 고치는 파일은 `.claude/rules/adapters.md`(서로 다른 항목)뿐일 것으로 본다(어림). 늦게 병합하는 쪽이 기준 브랜치를 합칠 때 그 파일의 충돌을 푼다.

근거는 명세 `.scratch/connection-check/spec.md`의 "MCP 서버를 확인하는 법", "기한"의 원격 MCP 서버와 stdio MCP 서버 행과 그 아래 항목들("stdio의 20초", "기한 뒤의 정리", "값을 주는 자리", "실행의 기한은 바뀌지 않는다"), "화면에 보이는 글과 비밀"의 MCP 쪽, "결과가 남는 자리"의 HTTP 라이브러리 로거 항목, Testing Decisions의 둘째 가운데 MCP 몫이다. 결정은 ADR 0067의 결정 "MCP 서버를 확인하는 법"·"기한"과 Consequences "접속 확인이 보지 못하는 것", ADR 0049(서버 하나를 여는 함수, 실패 문구, 닫는 길, 이력 2026-11-09 "서버가 되울린 헤더 값을 실패 문구에서 가린다"), ADR 0034(stdio 서버를 띄우는 길과 정리 길)다. mcp-http 명세가 넘긴 것은 기능 계획 `.scratch/connection-check/plan.md` 본문에 있다. 이 티켓의 "명세 검토"는 일지 `docs/journal/2026-11-22-0159-connection-check-tickets.md`의 "명세 검토" 절을 가리킨다.

### 원격 서버(스스로 하는 확인)

- [x] 실행이 서버 하나를 여는 함수를 그대로 다시 쓴다(ADR 0049 Consequences "뒤 기능이 기대는 것"). 도구 목록을 읽을 때까지 예외 없이 지났으면 `Reached`이고, 도구가 하나도 없어도 `Reached`다
- [x] 여는 동안의 실패는 실행의 실패 글을 그대로 `Unreached`의 까닭으로 돌려준다. 꼴은 `MCP 서버 <이름>(<주소>)에 붙지 못했다: <원인>`이고, 서버가 오류 응답을 돌려줬으면 끝에 공백 하나와 `(HTTP <코드> <이유>)`가 붙는다. 서버가 되울린 헤더 값을 가리는 것도 실행과 같다
- [x] 기한은 어댑터를 만들 때 주는 값이고 기본이 10초다. 넘기면 확인을 끊고 연 것을 닫은 뒤 `MCP 서버 <이름>(<주소>)에 붙지 못했다: <N>초 안에 준비되지 않았다`를 돌려준다. 기한의 취소가 어댑터 안에서 연결 오류로 바뀌어 시간 초과 대신 연결 오류의 글이 나오지 않는지를 시험이 본다(명세 검토가 확인하지 못한 것)
- [x] 닫을 때는 ADR 0049의 닫는 길(세션 종료 요청을 2초 유예 안에서 보낸다)을 지나고, 기한에 닿아 끊긴 확인도 같은 길로 거둔다
- [x] 닫는 동안 난 예외처럼 여는 단계 밖에서 난 예외는 바꾸지 않고 그대로 올린다(관리 경로가 500으로 답한다)
- [x] 실행의 접속 기한 30초와 실행 기한은 바뀌지 않는다
- [x] 두 전송 모두, `Unreached.reason`은 비지 않은 글이다. 예외의 글(`str(error)`)이 빈 경우에도 어댑터가 예외의 종류 같은 글로 채운다. 응답 계약이 비지 않은 문자열을 요구해, 빈 글이 가면 관리가 응답을 만들지 못해 500이다(티켓 01의 셀프 리뷰에서 넘어온 것. 약속의 자리는 `core/ports.py`의 `Unreached` 독스트링)
- [x] 두 전송 모두, 어댑터는 mcp와 `httpx`의 예외나 응답 객체를 `Unreached.reason`의 `str` 밖으로 내보내지 않는다. 서드파티 타입이 포트의 반환값에 비치지 않는다(명세 "결과 타입이 사는 층", `CODING_STANDARDS.md`의 "서드파티는 경계에서 감싼다")

### stdio 서버(눌러서 하는 확인)

- [x] 실행과 같은 길로 띄우고(윈도우가 아닌 OS에서는 런처 뒤에, ADR 0034), 확인이 끝나면 닫아 프로세스를 끈다. 요청 하나가 서버 하나만 띄운다. 명령을 찾지 못한 것도 여는 단계 안의 실패라 같은 꼴의 글이 된다
- [x] 기한은 기본 20초다. 기한에 닿은 확인도 ADR 0034의 정리 길로 프로세스를 거둔 뒤 `Unreached`로 돌아온다

### 시험(명세 Testing Decisions의 둘째 가운데 MCP 몫)

- [x] 가짜 원격 MCP 서버와 실제로 띄우는 stdio 서버로 붙어 본다(선례 `tests/adapters/`의 MCP 시험). 붙는 서버는 `Reached`, 닫힌 포트는 연결 오류의 글, 401을 내는 서버는 글 끝의 `(HTTP 401 Unauthorized)`, 답이 늦는 서버는 짧게 준 기한 뒤 시간 초과의 글, 서버가 오류 본문에 헤더 값을 되울려도 `reason`에 그 글자가 없는 것, 명령을 찾지 못한 stdio 서버의 글, stdio 확인이 끝난 뒤와 기한에 닿은 뒤에 띄운 프로세스가 남지 않는 것이다
- [x] 프로세스와 기한을 재는 단언의 상한은 `.claude/rules/tests.md`의 시간 단언 항목을 따른다
- [x] 원격 MCP 서버가 확인 한 번에 받는 요청의 수를 가짜 서버로 세어 일지에 적는다. 화면이 30초마다 되풀이하므로 바깥 서버가 받는 몫이다(명세 "간격과 보이지 않는 탭"의 "요청의 수", "재지 않은 것")

- [x] 규칙 파일을 고치기 전에 Skill 도구로 `writing-for-agents`를 부른다(`.claude/rules/agent-docs.md`)
- [x] `.claude/rules/adapters.md`의 MCP 항목과 MCP 어댑터의 모듈 독스트링에 접속 확인의 동작(같은 여는 함수, 기한, 닫는 길)을 적고, 01이 적은 '아직 붙어 보지 않는다'는 문장을 지운다
