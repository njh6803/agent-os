# public-demo: 공개 정부 문서를 넣은 클라우드 VM 한 대를 공개 주소에 열어, 누구나 로그인 없이 묻고 출처가 붙은 답을 받게 한다.
**슬라이스:** 8
**Blocked by:** base-agent, release-image, answer-eval, answer-markdown, rag-engine:release-image, rag-engine:search-eval

공개 데모(`CONTEXT.md`). 클라우드 VM 한 대에 agent-os의 이미지와 판을 고정한 문서 검색 서버 이미지를 띄우고, 공개 주소에서 누구나 질문 페이지(pilot-portal의 익명 모드)로 기본 에이전트 `assistant`(base-agent, ADR 0051)에 묻게 한다. 기본 플러그인 루트에는 에이전트 calc와 MCP 서버 플러그인 everything이 함께 있으므로, 이 배포의 사이트 파일은 열 에이전트 목록에 `assistant`만 적고 calc를 뺀다. 위젯이 답을 마크다운으로 그리는 answer-markdown도 기다린다(ADR 0053). 폐쇄망 배포보다 먼저, 같은 구성 요소를 실제 최종 사용자의 질문 앞에서 끝까지 돌려 보기 위해서다(ADR 0046의 2026-11-06 이력). 제품 0.1의 조건이 아니므로 pilot-release를 막지 않는다. 넣을 문서는 저작권 보호를 받지 않는 공개 정부 문서(법령, 고시, 훈령 같은 것)이고, answer-eval과 문서 검색 서버의 search-eval이 쓰는 공개 문서 묶음과 같게 둔다. 그래서 두 보고서의 숫자가 이 데모를 그대로 설명한다. 문서는 문서 검색 서버의 관리 명령으로 한 번 넣고, 동기화는 쓰지 않는다. 답의 출처에 보이는 갱신일은 문서 검색 서버가 준 UTC 날짜 그대로라, 날짜만 아는 문서는 그 날짜의 UTC 0시로 넣는다(ADR 0051 Consequences "갱신일의 날짜"). 모델은 Anthropic API이고(local-model은 이 행 뒤에 온다), 임베딩은 VM의 CPU에서 돈다. 배치는 deploy-package의 원칙을 앞당겨 따른다. 밖으로 여는 포트는 TLS를 끝내는 리버스 프록시의 443 하나이고, 프록시는 질문 페이지, 위젯, 최종 사용자 경로만 내놓는다. agent-os의 관리 API와 관리 화면, 문서 검색 서버의 관리 API와 관리자 페이지는 내놓지 않고, 운영은 SSH 포워딩으로 한다. 프록시에는 접속 주소마다의 요청 빈도 제한도 둔다. 도구는 읽기 전용 검색 하나만 연다. 기본 에이전트가 내는 규칙 파일의 표는 검색을 허락하고 문서 전문 읽기(`get_document`)를 묻게 두지만(ADR 0051 "도구 셋의 규칙"), 이 배포의 규칙 파일은 전문 읽기도 deny로 막는다. 묻는 도구는 질문한 익명 최종 사용자가 스스로 승인할 수 있기 때문이다. 규칙 파일은 플러그인 루트마다 하나라 이 배포는 제 플러그인 루트의 규칙 파일을 바꿔 쓰고, 이미지에 든 파일을 덮는지 루트를 따로 두는지는 설계 인터뷰가 release-image의 이미지 구성을 보고 정한다(ADR 0051 "도구 셋의 규칙"의 공개 데모 항목). 그 밖의 도구도 deny로 막는다. deny가 allow보다 먼저 집행되어 맨 `*`는 검색 도구까지 막으므로(ADR 0044와 그 이력 2026-11-06 "도구 이름의 별표는 패턴이다"), 문서 검색 서버의 나머지 도구를 이름이나 접두 패턴으로 deny에 적는다. 적지 않은 도구는 묻는 것이 기본이라 질문한 최종 사용자가 스스로 승인할 수 있기 때문이다. 문서 검색 서버가 도구를 새로 더하면 그 도구는 묻는다로 열리므로, 판을 올릴 때마다 도구 목록과 deny를 다시 대 본다. 문서 검색 서버의 명세가 적은 도구는 지금 셋(`search`, `get_document`, `list_knowledge_bases`)이라 deny에 뒤의 둘이 들고, 그 밖에 무엇을 적을지는 설계 인터뷰가 그때의 도구 목록을 보고 정한다. 비용은 새 런타임 기능 없이 묶는다. `serve`가 다시 시작하지 않는 동안 시간당 비용의 최댓값은 사이트 파일의 사이트별 시간당 실행 수 상한과, 기본 에이전트의 구조(매니페스트의 턴의 끝과 도구 호출의 끝(ADR 0052), 모델 매니페스트의 `max_tokens`, 요청 글자 수 상한, 검색 조각 수)가 정하는 실행 하나의 토큰 최댓값을 곱한 값이다. 검색 조각 수는 모델이 넘기는 인자라 에이전트 쪽에 단단한 끝이 없으므로(ADR 0051 "검색 대상과 조각 수") 문서 검색 서버의 설정으로 그 끝을 낮춘다. 그 서버의 명세는 `top_k`의 최댓값을 설정 `RAG_SEARCH_MAX_TOP_K`(기본 50)로 둔다(rag-engine의 `.scratch/core/spec.md` 97줄과 186줄을 읽었다. 그 저장소는 명세 단계라 코드로 확인한 것이 아니다). 낮출 값은 설계 인터뷰가 정한다. 시간당 실행 수 상한에는 전역 범위가 없으므로(주체별과 사이트별뿐이다, `channel/http/limits.py`), 사이트 파일에는 사이트를 질문 페이지 하나만 둔다. 그 셈은 프로세스 메모리라 `serve`가 다시 시작하면 비워지므로(같은 모듈), 다시 시작한 시간에는 이 값을 넘을 수 있고 그 초과분은 뒤의 모델 API 계정의 사용 한도가 받는다. 이어 가기를 열면 앞 대화도 입력에 들어가므로, 공개 데모에서 이어 가기를 열지와 그때의 끝은 설계 인터뷰가 정한다. 열면 대화 요약의 모델 호출이 `max_turns`에 들지 않고 따로 일어나므로(ADR 0052) 그 호출의 입출력 토큰도 실행 하나의 최댓값에 넣어 센다. 모델 API 계정의 사용 한도를 마지막 방어선으로 함께 건다. mcp-trust와 io-guardrail이 아직 없으므로, 질문 페이지에 다음을 알린다. 질문과 답은 기록되고 정한 기간 뒤 지워진다(트레이스에 둘 다 남는다. 기본 고지도 "질문과 받은 출력"이라 적는다). 질문은 답을 만드는 모델 API(Anthropic)에도 보내지고, 그쪽에 남는 것은 이 배포의 정리 작업이 지우지 못해 그 제공자의 보존 조건을 따른다. 개인정보를 넣지 않는다. AI의 답은 참고용이고 원문을 확인해야 한다. 보존 기간은 배포의 정리 작업(끝난 실행의 트레이스 파일 `<run_id>.jsonl` 가운데 기한이 지난 것을 지우는 예약 작업)으로 지키고, retention-worker가 오면 그것으로 바꾼다. 질문 페이지에서 answer-eval과 search-eval의 보고서로 잇는다. 고지 글은 질문 페이지 설정의 사이트 칸 `notice`로, 보고서 링크는 `report_url`로 준다(pilot-portal 명세 "질문 페이지 설정"). 링크는 사이트마다 하나라 두 보고서를 함께 두는 페이지 하나를 가리킨다. 익명 식별자 쿠키 문장은 질문 페이지가 고지 전문 끝에 늘 붙이고, 위젯 곁의 짧은 고지 한 줄은 사이트가 바꾸지 못한다. 도메인, VM 사양, 상한 값, 보존 기간은 설계 인터뷰가 정한다. GPU를 쓰지 않는 구성, 모델 배치 구성에서 이 데모의 자리, 넣을 문서의 저작권 확인은 일지 2026-11-07-2053의 "설계 인터뷰 입력" 절에 있고, 그 절이 가리키는 모델 배치 구성의 표는 일지 2026-11-06-02의 같은 이름의 절에 있다. 설계 인터뷰가 먼저 볼 것: 공개 주소에는 자동화된 요청이 몰릴 수 있다. 익명 주체는 식별자를 새로 받아 주체별 상한을 피할 수 있으므로, 비용은 사이트별 상한과 기본 에이전트의 구조로 묶고, 접속 주소마다의 빈도 제한은 프록시가 맡는다. 최종 사용자가 넣은 글은 트레이스에 그대로 남으므로(PRD의 알아 둘 사실) 고지와 보존 기간을 먼저 정한다. 고지에 적을 모델 API 쪽의 보존 조건은 쓸 계정의 계약과 그 제공자의 공식 문서로 확인한다. 최종 사용자가 질문을 지시처럼 써도(프롬프트 주입) 이 배포에서 열린 도구가 읽기 전용 검색 하나뿐이라 피해가 답의 글에 그친다는 것을 시험으로 확인한다. `serve`가 실행 도중 다시 시작하면 그 실행의 트레이스에는 끝 이벤트가 붙지 않고 그런 실행을 닫는 orphan-recovery는 슬라이스 11이므로, 위의 정리 작업이 끝난 실행만 지우면 그 질문이 고지한 기간을 넘겨 남는다. 끝 이벤트 없이 남은 트레이스도 보존 기간 안에 지울 길을 정한다. 위의 시간당 최댓값에는 빈틈이 셋 있어 그 셈을 정한다. 모델 매니페스트의 `max_tokens`는 출력만 묶으므로 입력은 검색 조각 하나의 크기(문서 검색 서버가 정한다)까지 알아야 묶인다. 셈한 값은 토큰 수라 금액은 입력과 출력의 토큰에 요금을 따로 곱해야 한다. 상한은 실행을 시작 시각으로 세고 토큰은 응답 뒤에 쓰이므로, 수락의 프로브가 토큰을 어느 시각으로 묶을지 정한다. 수락: 공개 주소에서 질문하면 출처와 갱신일이 붙은 답이 나오고, 사이트별 시간당 실행 수 상한을 넘긴 요청이 거부되며, 밖에서 관리 경로에 닿을 수 없고 열린 포트가 443과 SSH뿐임을 확인한다. 한 주 동안 돌린 뒤 `serve`가 다시 시작하지 않은 시간마다 시간당 토큰 사용량이 계산한 최댓값 안에 있었음을, 다시 시작한 시각과 함께 프로브로 남긴다. base-agent 명세가 넘긴 것(2026-11-10, `.scratch/base-agent/spec.md`): 기본 에이전트 `assistant`의 매니페스트는 `max_turns = 6`, `max_tool_calls = 4`다(사용자가 골랐다). 그래서 실행 하나의 모델 호출은 많아야 6번이고(이어 가기의 대화 요약 호출은 따로다) 도구 호출은 많아야 4번이며, 전문 읽기를 deny로 막는 공개 데모에서는 그 넷이 모두 검색일 수 있다. 모델은 한 턴에 검색을 둘 내기도 한다(명세 전의 프로브에서 봤다. `.scratch/base-agent/probes/README.md`). 최대 비용의 셈은 검색 4번의 결과가 모두 입력에 쌓인 채 모델을 6번 부르는 것으로 잡는다. 검색 한 번이 돌려주는 조각 수는 모델이 넘기는 `top_k`가 정하므로 문서 검색 서버의 `RAG_SEARCH_MAX_TOP_K`를 낮춰 묶는다(ADR 0051). 검색했는데 근거가 없을 때의 답은 출처 목록 없이 "등록된 문서에서 관련 내용을 찾지 못했으니, 다른 표현이나 다른 질문으로 다시 물어봐 주세요." 한 문장이고, 문서와 관련 없는 질문에도 이 문장이 나온다. 연결 플러그인 `doc-search`가 커밋한 주소는 `http://rag-engine:8000/mcp`이고 `Authorization` 헤더의 값을 환경 변수 `DOC_SEARCH_AUTHORIZATION`에서 읽으므로(값은 `Bearer <토큰>` 전체다), 공개 데모의 배포가 `serve`에 그 변수를 주고 문서 검색 서버의 `RAG_ALLOWED_HOSTS`에 서비스 이름 `rag-engine`을 넣는다(그 서버가 `값:*`의 꼴도 함께 등록해 포트가 붙은 Host `rag-engine:8000`이 맞는다. rag-engine의 ADR 0014를 2026-11-10에 읽었다)
