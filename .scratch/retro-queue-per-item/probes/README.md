# retro-queue-per-item 프로브

ADR 0045의 까닭이 근거로 드는 측정이다. 규약은 `docs/agents/issue-tracker.md`의 프로브와 근거 절과 `.claude/rules/probes.md`.

## 돌리는 법

저장소 루트(워크트리도 된다)에서 돈다. LLM을 부르지 않고 git 기록만 읽는다.

```bash
uv run python .scratch/retro-queue-per-item/probes/plan_changes.py 19bbfa06 origin/main
```

종료 코드 0은 측정이 아닌 회차가 없었다는 뜻이고 결론은 출력의 집계 줄과 회차 줄로 읽는다(`tools/probe_kit.py`의 `Rounds`). 가지가 전진하면 커밋이 늘어 수가 커지므로, 아래 표와 같은 수를 보려면 `origin/main` 자리에 `83a66cdc`를 준다.

## 결과

### `plan_changes.py` — `.scratch/plan.md`를 고친 커밋은 표의 어느 칸을 고치는가

2026-11-06, origin/main 83a66cdc, 기준 커밋 19bbfa06(2026-10-22). 커밋 39개, 측정 39회차, 측정 아님 0회차, 종료 코드 0.

| 고친 것 | 커밋 |
|---|---|
| 내용 | 22 |
| Status + 내용 | 8 |
| 행 추가 | 3 |
| Status | 3 |
| 표 밖 | 3 |

해석. **`plan.md`를 고친 커밋 39개 가운데 Status만 고친 것은 3개이고, 내용 칸을 고친 것은 30개다**(위 표, 탐침이 찍은 집계). Status 칸을 생성으로 돌려도 내용 칸을 고치는 커밋 30개는 남는다(ADR 0045 Considered Options "Status 칸만 생성으로"를 거부한 근거. 표에서 읽은 셈이다). 이 프로브는 커밋마다 diff가 고친 칸을 셀 뿐이고 병합 충돌은 세지 않는다. 충돌이 어느 칸에서 났는지는 재지 않았다.

재지 않은 것. 표 밖 회차 셋은 diff가 비지 않았는데 바뀐 기능 행이 없는 것이라 따로 표지가 없고, 회차 줄의 커밋(`3ee0be4f`, `06a8f85b`, `f1ed4be7`)을 `git show`로 보면 프론티어 문단만 바뀌었다(손으로 봤다). 티켓 PR은 커밋 하나로 합쳐지므로(`CONTEXT.md` 티켓 PR) 한 PR 안에서 Status와 내용을 따로 고친 것은 하나로 센다.

측정 뒤 고친 것. 첫 판은 기점을 날짜(`git log --since=2026-10-22`)로 받아 커밋 44개(내용 25, Status + 내용 9, Status 4, 행 추가 3, 표 밖 3)를 냈다. 셀프 리뷰 표준 축이 git의 `--since`가 날짜만 주면 돌리는 시각의 시분을 붙여 같은 날에도 수가 달라진다고 짚어(이 PC의 git 2.32에서 `--since="2026-10-22 00:00"`은 44, `--since="2026-10-22 23:59"`는 39였다), 기준 커밋을 받아 `<BASE>..<REF>`로 세게 고쳤다. 위 표는 고친 판의 수다. 같은 리뷰 명세 축이 슬라이스 칸만 바뀐 행을 표 밖으로 세는 것을 짚어 `COLUMNS`에 슬라이스를 더했다. 위 표의 종류 다섯에 슬라이스가 없으므로 이 범위에는 슬라이스 칸을 고친 커밋이 없고, 더하기 전 판으로 돌려도 같은 수다(탐침 출력에서 읽은 셈이고, 더하기 전 판을 이 범위로 다시 돌리지는 않았다).
