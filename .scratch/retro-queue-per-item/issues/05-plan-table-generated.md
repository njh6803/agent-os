# 05: 전체 계획을 기능 계획과 티켓에서 도구가 만든다

**What to build:** 제품 기능마다 `.scratch/<slug>/plan.md`(기능 계획)가 생기고, 루트 `.scratch/plan.md`는 `uv run python tools/plan_table.py`가 손 파일(`.scratch/plan-head.md`)과 기능 계획과 티켓에서 만들어 커밋하는 생성 파일이 된다. 표의 내용 칸에는 한 줄 요약과 기능 계획으로 가는 링크만 들어 표가 한눈에 읽힌다. 기능의 상태는 손으로 바꾸지 않고 `끝` 줄과 티켓에서 나온다. 프론티어 문단은 도구가 계산하고, 다른 저장소(rag-engine)를 기다리는 기능은 따로 적힌다. 기능 계획이나 티켓을 고치고 도구를 잊으면 시험이 명령을 알려 주고, 이 파일의 병합 충돌은 도구를 다시 돌려 푼다. 기능의 마지막 티켓을 닫는 커밋이 기능 계획에 `**끝:** YYYY-MM-DD`를 적고, 빠뜨리면 저장소 상태 시험이 막는다. 설계 인터뷰를 마친 세션은 기능 계획에 `**설계:** ADR NNNN`을 적고, 설계 인터뷰의 계기는 명세도 설계 줄도 없는 기능이 된다.

근거는 `.scratch/retro-queue-per-item/spec.md`의 "전체 계획 생성", "끝 줄", "설계 줄과 설계 인터뷰의 계기", "이음매", "저장소 상태 시험의 실패 문장"의 전체 계획·끝 줄, "바뀌는 자리"의 전체 계획 생성, Testing Decisions의 "전체 계획 도구"·"커밋 검사"·"끝 줄 시험"·"저장소 상태 시험"·"훅"·"스킬과 규칙"·"변이 표", Further Notes의 "헌법 판을 올리는 티켓", 사용자 스토리 7~12·23~26·34·35·36이다. 결정은 ADR 0045 결정 3, 4, 10의 면제 몫(기능 계획, 손 파일)이다. 이 티켓이 병합되면 ADR 0045 이력 2026-11-06의 끝 줄·설계 줄·판 올리기가 선다. 시험 자리, 끝 줄을 막는 자리, 설계 표지, 표의 내용 칸은 사용자가 골랐다(명세 서두).

이 티켓은 크다(명세의 고칠 자리 목록에서 02 다음으로 크다). 한 세션에 다 못 하면 인계로 이어 간다.

**Blocked by:** 03 (리뷰 봇 경로 거르기), 04 (일지 이름)

**Status:** ready-for-agent

### 시작할 때

- [ ] 첫 편집으로 이 티켓의 `Status:`를 `in-progress`로 바꿔 첫 커밋에 싣는다
- [ ] 명세 "바뀌는 자리"의 전체 계획 생성 목록을 `git grep`으로 다시 대 본다. 이 티켓이 든 수는 명세가 센 것이고, 근거의 종류는 명세가 그 수를 적은 자리에 있다(따로 적지 않은 수는 6f205c0e에서 조사 서브에이전트가 읽고 센 것이다, 명세 서두). 명세의 수(표 51행, 폴더가 있는 기능 20과 없는 31, done 19, 행이 없는 폴더 여덟)는 6f205c0e의 것이라 그때의 수를 다시 센다. 목록 밖에서 찾은 자리는 PR 본문에 적는다

### 기능 계획과 손 파일

- [ ] **기능 계획의 모양.** 첫 줄 `# <slug>: <한 줄 요약>`(slug는 폴더 이름), 그 아래 `**슬라이스:** N`, `**Blocked by:** <slug>, …`(없으면 `없음`, 다른 저장소의 기능은 `rag-engine:<slug>`), 있을 때만 `**설계:** …`과 `**끝:** YYYY-MM-DD`, 빈 줄 뒤의 본문은 지금 표의 내용 칸이다. 하네스 기능의 기능 계획은 `**슬라이스:**` 줄이 없고 전체 계획에 들지 않는다. 지금 전체 계획에 행이 없는 폴더(하네스 폴더 일곱과 `agent-os-direction`)는 기능 계획을 만들지 않는다
- [ ] **손 파일.** 지금 `.scratch/plan.md`의 표 밖 글(제목, 머리말, 목표 배치, 첫 슬라이스의 범위)을 `.scratch/plan-head.md`로 옮기고, 도구가 그 뒤에 표와 프론티어 문단을 붙인다. 생성 파일의 첫 줄에 이 파일은 도구가 만들고 기능 계획이나 손 파일을 고쳐 도구를 돈다는 주석을 둔다

### 도구

- [ ] **쓰기와 확인.** 도구가 `.scratch/plan.md`를 쓴다. `--check`는 쓰지 않고, 디스크에서 만든 결과가 커밋할 파일과 다르면 1로 끝난다. 기능 계획의 줄이 빠졌거나, slug가 폴더 이름과 다르거나, Blocked by가 없는 기능을 가리키거나, 티켓의 상태 값을 모르면 그 경로와 까닭을 찍고 2로 끝난다. 생성 파일은 읽지 않으므로 병합 충돌 표지가 든 채로도 돈다. 아래 임시 폴더 시험이 그 폴더를 저장소 루트로 넘길 수 있어야 한다
- [ ] **표.** 칸은 `| 슬라이스 | 기능 | 내용 | Blocked by | Status |`이고, 기능 칸은 기능 계획으로 가는 링크, 내용 칸은 기능 계획 머리의 한 줄 요약이다. 요약의 `|`는 이스케이프한다. 행은 슬라이스 번호의 숫자 순, 그다음 slug 순이다. 첫 생성에서 지금 표와 행 순서가 달라지는 것은 이 규칙 탓이다
- [ ] **상태.** `끝` 줄이 있으면 done, 없고 그 폴더 `issues/`에 done 티켓이 있으면 in-progress, 아니면 todo다. 티켓의 상태는 줄 머리가 `Status:`이거나 `**Status:**`인 첫 줄의 첫 낱말로 읽고, 이 규칙 하나를 커밋 검사(`tools/check_ticket.py`)와 함께 쓴다
- [ ] **프론티어 문단.** done이 아니고, Blocked by가 비었거나 이 저장소의 막는 기능이 모두 done인 기능의 목록이다. Blocked by에 `rag-engine:<slug>`가 들면 프론티어에 넣지 않고 다른 저장소를 기다리는 기능 목록에 따로 적는다. 이 저장소의 막는 기능이 done이 아닌 기능은 다른 저장소의 기능이 함께 들어도 어느 목록에도 넣지 않는다
- [ ] **도는 때.** 기능 계획이나 손 파일을 고치거나 티켓의 상태를 바꾼 세션이 손으로 돌리고 결과를 같은 커밋에 싣는다. pre-commit 훅이 다시 쓰게 하지 않는다(명세의 거부한 안)

### 이행

- [ ] 지금 표의 행마다 기능 계획을 만든다. 폴더가 있는 기능은 그 폴더에, 없는 기능은 폴더와 기능 계획만 만든다. 한 줄 요약은 이 세션이 지금 내용 칸을 읽고 짓는다
- [ ] done 기능의 `끝` 날짜는 그 기능의 마지막 티켓을 병합한 커밋의 날짜를 git 기록에서 찾는다. 티켓이 없는 design-artifacts는 `.scratch/plan.md`에서 그 행이 done이 된 커밋의 날짜다. 지금 프론티어 문단이 적은 닫힌 날짜와 맞대고, 다르면 PR 본문에 적는다
- [ ] 지금 프론티어 문단의 서술(닫힌 슬라이스의 PR 번호와 날짜, 프론티어 문장의 역사)은 옮기지 않고 버린다
- [ ] **설계 줄.** 명세가 없고 설계를 마친 기능에 설계 줄을 적는다. 6f205c0e에는 그런 기능이 없었다. 그 뒤에 설계를 마치고 명세 전인 기능이 생겼는지 이 티켓을 시작할 때 다시 보고(폴더마다 `spec.md`, 기능마다 설계 일지와 ADR), 생겼으면 적는다
- [ ] 이 PR이 마지막으로 origin/main을 합친 뒤 그 main의 `.scratch/plan.md`와 행 집합과 내용 칸을 다시 맞댄다. 병합 충돌을 도구로 다시 만들어 풀면 main이 손으로 고친 행이 덮이는데, 저장소 대조 시험은 기능 계획에서 만들어 초록이기 때문이다. main이 고친 몫을 기능 계획으로 옮긴다

### 끝 줄

- [ ] **막는 자리.** 저장소 상태 시험이다. 기능 계획의 폴더 `issues/`에 든 티켓이 모두 닫혔고(done 또는 wontfix) done이 하나 이상인데 `**끝:**` 줄이 없으면 빨갛다. `**슬라이스:**` 줄이 없는 기능 계획(하네스 기능)과 기능 계획이 없는 폴더는 보지 않는다. 지금 `tests/test_plan_status.py`의 행 판정을 기능 계획의 `끝` 줄로 옮긴 것이다
- [ ] **적는 때.** 기능의 마지막 열린 티켓을 닫는 커밋(done이나 wontfix로 바꾸거나 그 티켓을 지우는 커밋)이, 닫은 뒤 그 기능의 done 티켓이 하나 이상이면(명세 "끝 줄"의 막는 자리) 같은 커밋에서 `끝` 줄을 적는다. 날짜는 그 커밋의 로컬 날짜다. 이 규칙을 `docs/agents/issue-tracker.md`의 전체 계획 절(실패 문장이 가리키는 원천)과 `implement` 스킬(지금 그 문장이 없다)에 적는다
- [ ] **나란히 돈 마지막 티켓 둘.** main 보호가 strict라 늦게 병합되는 PR이 main을 합친 뒤의 CI에서 막혀 그 PR이 적는다는 것을 같은 절에 적는다. 이 규칙은 ADR 0043의 개발 브랜치 전의 것이고, 그 전환을 맡는 harness 티켓이 다시 정한다(명세 Out of Scope)

### 시험

- [ ] **전체 계획 도구(임시 폴더).** 상태 규칙마다 사례 하나(`끝` 줄 → done, done 티켓만 → in-progress, 아무것도 없음 → todo, done 기능에 열린 고침 티켓 → done, 모두 닫혔는데 `끝` 줄 없음 → in-progress, 다른 저장소의 막는 기능), 순서(슬라이스 숫자, 그다음 slug), 프론티어(막는 기능이 모두 done, 다른 저장소의 기능, 이 저장소의 막는 기능이 done이 아닌데 다른 저장소의 기능도 든 기능), 요약의 `|` 이스케이프, 깨진 기능 계획의 종료 2와 그 경로, 병합 충돌 표지가 든 `.scratch/plan.md` 곁에서 같은 파일을 쓰는 것을 본다
- [ ] **끝 줄 시험(임시 폴더).** 마지막 티켓이 done이고 `끝` 줄이 없으면 빨강, 있으면 초록, 마지막 티켓을 wontfix로 닫아도 done이 하나 이상이면 빨강, done 기능에 열린 고침 티켓이 있어도 초록, 티켓이 모두 열린 기능은 초록, `**슬라이스:**` 줄이 없는 기능 계획은 보지 않는 것을 본다
- [ ] **커밋 검사.** 임시 저장소의 진짜 `git commit`과 `--ci`로 기능 계획과 손 파일의 면제, `.scratch/harness/plan.md` 같은 면제 밖 사례를 본다(`tests/tools/test_check_ticket.py`)
- [ ] **훅.** `tests/tools/test_hook_grill_design_check.py`가 `spec.md`와 설계 줄을 단언하도록 조이고, 실제 입력 표(`tools/hook_payloads.toml`)를 `tools/run_hooks.py`로 돌린다
- [ ] **빨강을 먼저 본다.** 바꾸기 전의 시험과 도구로 티켓이 모두 닫혔는데 `끝` 줄이 없는 기능 계획과 다른 저장소를 기다리는 기능의 사례가 빨간 것을 본다(원칙 II)
