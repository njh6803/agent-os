# 01: 번호 도구가 harness 티켓 번호를 내주고, 겹치면 알리고 옮긴다

**What to build:** 세션이 harness 티켓을 쓸 때 번호를 손으로 고르지 않는다. `uv run python tools/sibling_overlap.py`의 다음 빈 번호 줄에 `티켓 NNN`이 뜬다(harness 폴더에 티켓이 없으면 `001`, 지금 main에서는 `002`). 나란히 도는 형제(열린 PR, 형제 워크트리의 커밋하지 않은 파일)가 같은 번호로 다른 티켓 파일을 쓰면 일지 번호처럼 겹침으로 알리고 1로 끝난다. 겹치면 이 브랜치가 비켜 가되, 이 브랜치에 열린 PR이 있으면 옮기지 않고 상대가 옮긴다고 알린다. 상대가 이미 main에 병합된 티켓이면 열린 PR이 있어도 이 브랜치가 옮긴다. `--move`는 티켓 파일 이름과 인용을 옮기고, 브랜치·원격·세션 제목을 바꾸는 명령과 할 일을 찍는다.

근거는 `.scratch/ticket-for-every-pr/spec.md`의 "번호"(명세가 정했다)와 그 2026-10-21 명세 검토 주석, 사용자 스토리 20·22·29, Testing Decisions "번호 도구", Further Notes의 순서(이 티켓이 먼저다. 문서·스킬과 커밋 검사의 막는 글이 "번호는 번호 도구의 다음 빈 번호"라고 가리킨다)다. 결정은 ADR 0037의 "번호"다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 번호 도구

- [ ] **다섯째 번호를 본다.** 지금 보는 넷(일지 순번, ADR 번호, 대기열 행, 헌법 판)에 `.scratch/harness/issues/NNN-*.md`의 `NNN`을 더한다. 같은 번호에 다른 파일이면 겹침이다. 다음 빈 번호 줄에 세 자리 `티켓 NNN`이 든다
- [ ] **merge-base에서 다섯째 자리가 비어도 2로 끝나지 않는다.** #335 전에 딴 브랜치의 merge-base에는 harness 폴더가 없다. 나머지 넷은 지금처럼 merge-base에서 하나라도 비면 경로가 어긋난 것으로 보고 2로 끝난다(그 도구의 독스트링)
- [ ] **겹치면 누가 옮기나.** 이 브랜치가 비켜 간다. 이 브랜치에 열린 PR이 있으면 티켓 번호를 옮기지 않고 상대가 옮긴다고 알린다(브랜치 이름을 바꾸면 PR이 끊긴다). 둘 다 열린 PR이면 PR 번호가 큰 쪽이 옮기고, 도구는 새 이름의 브랜치로 PR을 다시 열라는 할 일만 낸다. 상대가 이미 main에 병합된 티켓이면 상대는 옮길 수 없으므로, 이 브랜치에 열린 PR이 있어도 이 브랜치가 옮기고 같은 할 일을 낸다(명세 "번호"의 2026-10-21 주석)
- [ ] **`--move`가 옮기는 것.** 티켓 파일 이름, 이 브랜치의 변경과 미추적 파일 안의 stem 인용(`NNN-<slug>`. slug까지 맞대어 다른 번호의 글과 섞이지 않는다)을 옮긴다. 인용 블록과 merge-base·main에 글자 그대로 있는 줄은 지금처럼 두고, 워크트리 이름은 그대로 둔다
- [ ] **`--move`가 찍는 것.** 지금 브랜치가 그 stem의 `chore/` 브랜치면 브랜치를 바꾸는 명령(`git branch -m`)과 세션 제목을 새 브랜치로 바꾸라는 할 일을 찍는다. 그 브랜치가 원격에도 있으면 새 이름으로 푸시하고 옛 원격 브랜치를 지우는 명령도 찍는다. 도구는 브랜치·인덱스·참조를 바꾸지 않는다
- [ ] **독스트링.** 다섯째 번호와 옮기는 길, 못 보는 것 둘(기능 폴더의 두 자리 티켓 번호, 지시문이 받아 두고 아직 파일이 없는 번호)을 적는다

### 시험

- [ ] `tests/tools/test_sibling_overlap.py`의 임시 git 저장소에 사례를 더한다. 형제 워크트리의 커밋하지 않은 harness 티켓과의 겹침, 열린 PR과의 겹침, 다음 빈 번호(`001`과 이어지는 번호), merge-base에 harness 폴더가 없을 때 2로 끝나지 않는 것, 열린 PR이 있는 이 브랜치가 옮기지 않는 것, 둘 다 열린 PR일 때(작은 번호의 PR은 그대로, 큰 쪽은 할 일만), 열린 PR이 있는 이 브랜치의 번호를 main이 이미 쓴 때(이 브랜치가 옮기고 할 일을 낸다), `--move`가 파일 이름과 stem 인용을 옮기고 인용 블록은 두는 것, 브랜치 명령과 원격 명령을 찍는 것
- [ ] **빨강을 먼저 본다.** 다섯째 번호를 더하기 전의 도구로 겹침·다음 번호 사례가 빨간 것을 본다
