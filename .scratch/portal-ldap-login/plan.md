# portal-ldap-login: 질문 페이지가 아이디와 비밀번호를 직접 받아 조직의 계정 디렉터리에 확인하는 로그인 방식을 더한다.
**슬라이스:** 10
**Blocked by:** portal-login, pilot-release

질문 페이지의 둘째 로그인 방식(LDAP). portal-login의 설계 인터뷰에서 사용자가 회사 로그인 서버로 보내는 방식과 아이디·비밀번호를 직접 받는 방식을 둘 다 두기를 물었고, "0.1은 하나, 구조는 열어 두기"를 골라 이 방식이 제품 1.0 묶음의 새 행이 됐다(일지 2026-11-12-1937 라운드 2, ADR 0059 Considered Options와 Consequences "다른 행"). 따로 둔 로그인 서버가 없는 조직을 위한 것이다. ADR 0059가 로그인 서버 항목에 방식의 이름 칸을 두었으므로 이 행은 그 칸에 값 하나를 더하고 설정의 모양은 바꾸지 않는다. 식별자, 로그인 상태(서명된 쿠키), 로그아웃, 고지 확인, 사이트 토큰은 ADR 0059의 것을 그대로 쓴다. 설계 인터뷰가 먼저 볼 것: 질문 페이지가 비밀번호를 직접 다루게 되므로 비밀번호가 로그와 기록에 새지 않게 하는 길과 반복 시도 차단을 어디에 두는지(질문 페이지는 무상태다, ADR 0050), 디렉터리와 통신하는 라이브러리와 시험용 가짜 디렉터리(인터뷰는 표준 라이브러리만으로 어렵다고 어림했고 재지 않았다), 로그인 화면을 질문 페이지가 직접 그리는 일, 디렉터리에 묶는 계정의 비밀 값을 두는 자리, 화면에서 방식을 고르는 portal-admin과의 차례. 수락: 시험용 가짜 디렉터리를 둔 시험 환경에서 아이디와 비밀번호로 로그인한 사람만 calc 예시에 질문할 수 있고, 틀린 비밀번호는 거절되며, 질문 페이지의 로그에 비밀번호가 없다
