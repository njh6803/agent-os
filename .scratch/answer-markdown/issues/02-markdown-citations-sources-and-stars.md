# 02: 마크다운 부품이 출력을 다듬는다 — 번호는 위첨자로, 출처는 작게, 곱셈의 별표는 글자로

**What to build:** 01의 부품이 기본 에이전트와 계산 에이전트의 출력을 읽기 좋게 다듬는다. 문장 끝의 `[숫자]`는 대괄호를 뗀 작은 위첨자로, 출력 끝의 "출처" 줄과 번호 목록은 선 아래 작은 흐린 글자로 그린다. 이어진 번호(`[1][2]`, `[1] [2]`)는 두 번호가 떨어져 보인다. 숫자 사이의 별표(`2*3*4 = 24`, `2*x*4`)와 밑줄로 두른 강조(`__init__.py`)는 글자 그대로 남고, 한국어에서 닫히지 않던 굵게(`**민법 제750조(불법행위)**는`)는 굵게로 보인다. 디자인 시스템의 카드와 단위 시험이 이 모양을 보인다. 위젯은 아직 부품을 쓰지 않는다.

근거는 `.scratch/answer-markdown/spec.md`의 "변환의 차례", "한국어에서 닫히지 않는 굵게", "글자로 두는 기호", "문장 끝 번호", "출처 덩이", "그리는 요소와 모양"의 표와 "놓인 자리에 따른 차이", "모양은 요소마다의 클래스로 낸다"(이어진 번호와 "표지의 길"), "패키지에 더하는 것", "고칠 자리의 묶음"의 2, Testing Decisions의 "부품의 단위 시험"과 "스토리와 사진 비교"다. 앞선 결정은 ADR 0053의 2026-11-10 이력(번호, 출처, 숫자 사이 별표와 밑줄)과 2026-11-11 이력의 마지막 문단(별표의 범위, 화면 그림에 맞추기)이다. 별표의 범위("글자가 낀 식까지 넓힘")는 사용자가 골랐다.

**Blocked by:** 01 (디자인 시스템에 마크다운 부품을 세운다). 부품, 변환의 차례 1·4·7·8, 단위 시험의 자리, 스토리가 01에 선다.

**Status:** done

### 변환

- [x] 명세 "변환의 차례"의 2(닫히지 않은 굵게와 기울임 되살리기), 3(글자로 두는 기호), 5(출처 덩이), 6(문장 끝 번호)을 01의 차례 사이에 끼워 1부터 8까지가 명세의 차례로 선다. 2가 3보다, 5가 6보다, 6이 7보다 먼저이고, 8은 5가 감싼 뒤의 형제를 본다
- [x] 닫히지 않은 굵게: 파서가 글자로 남긴 별표 묶음을 같은 부모 안에서 명세의 세 조건(여는 묶음 바로 뒤와 닫는 묶음 바로 앞이 공백이 아니다, 둘 사이가 비지 않는다, 두 묶음의 길이가 같다)으로 다시 짝짓는다. 역슬래시나 문자 참조로 쓴 별표가 든 글자 노드는 건너뛰고, 밑줄은 다시 짝짓지 않는다
- [x] 글자로 두는 기호: 밑줄로 쓴 강조는 언제나, 별표로 쓴 강조는 여는 묶음의 바로 앞 글자와 닫는 묶음의 바로 뒤 글자가 ASCII 숫자일 때 노드를 벗겨 기호와 안의 내용을 남긴다. 묶음은 이어진 같은 기호 전체다. 다른 변환이 만든 노드(위치가 없다)는 건드리지 않는다
- [x] 출처 덩이: 명세 "출처 덩이"의 표지 다섯 꼴과 목록 두 꼴로, 출력 최상위의 마지막 두 블록을 알아보고 `div` 하나로 감싼다. 안의 요소는 원문이 쓴 그대로이고, 알아보지 않는 꼴(같은 절의 목록)은 그대로 둔다
- [x] 문장 끝 번호: 명세 "문장 끝 번호"의 규칙(번호로 보는 것과 보지 않는 일곱)으로 알아보고, 대괄호와 번호 바로 앞의 공백을 떼어 숫자만 `sup`에 둔다. 번호 앞의 공백을 뗀 뒤 바로 앞 형제가 번호인 번호(`[1][2]`, `[1] [2]`의 둘째)에는 표지를 달리 단다. 번호는 링크가 아니다. 출처 덩이 안의 `[숫자]`는 위첨자가 되지 않는다
- [x] 번호 변환은 글자 노드마다 줄의 경계를 한 번만 훑어 번호의 수에 비례하는 시간에 돈다(명세 "문장 끝 번호"의 "구현에 넘기는 것"). PR 본문에, `가나 [1] `을 되풀이한 줄바꿈 없는 한 줄에서 번호 2,000개, 4,000개, 8,000개를 그리는 데 걸린 시간을 적는다(시제품은 0.3~0.4초, 0.5~0.6초, 1.5~3.5초였다). 기록이고 시험으로 단언하지 않는다

### 모양과 토큰

- [x] 위첨자는 작은 글자(`text-small`), 흐린 색(`text-muted`), 줄 높이 0, 왼쪽 틈 2px이고, 이어진 번호의 표지가 달린 것은 왼쪽 틈 4px이다. 출처 덩이는 위 선 1px(`border`)과 선 아래 12px, 작은 흐린 글자, 안의 블록 사이 4px, 항목 사이 0이고, 안의 요소는 글자 크기와 색을 덩이에서 물려받으며 제목은 굵기만 다르다
- [x] 디자인 토큰 CSS의 "부품 치수" 묶음에 `cite-start`(2px)를 간격 이름공간으로 더하고 묶음 머리 주석에 쓰임을 더한다. `.claude/rules/web-design.md` 컴포넌트 공통의 부품 치수 목록에 같은 커밋에서 더한다(`.claude/rules/agent-docs.md`). 짓기의 토큰 수 단언(`toHaveLength(112)`)이 그대로 지난다
- [x] `MarkdownText`는 위첨자 번호 앞에 공백을 둔다

### 단위 시험

- [x] 닫히지 않는 굵게 34가지(`CJK`. 받아들이는 한계 `n13`·`n34`는 지금의 결과를 그대로 적어 고정한다), 글자로 두는 기호 60가지(`LITERAL`), 변환의 차례 11가지(`INTERPLAY`), 문장 끝 번호 48가지(`CITE`), 출처 덩이 32가지(`SOURCES`), 합친 사례 17가지(`COMBINED`). 목표를 적어 둔 입력은 그 모양과 같은지를, 적지 않은 입력은 지금의 결과를 고정한다. 01의 모든 입력에 거는 규칙을 이 사례에도 건다
- [x] 사례 파일에 없는 번호의 경계 입력을 더한다. 굵게나 기울임의 첫 글자로 시작하는 번호(`근거는 **[1]** 이다`의 `[1]`은 글자로 남는다), `[1\]`(번호로 본다), `\[1]`(글자로 남는다), 차례 2나 3이 고친 문단의 `\[1\]`(`2*3*4 = 24 \[1\]`과 `**민법 제750조(불법행위)**는 \[1\] 이다`에서 위첨자가 된다), 할 일 표시를 되돌린 항목 `- [x] 한 일 \[1\]`(글자로 남는다), 대조 `근거는 [1] 이다`(위첨자)와 `값 \[1\] 이다`(글자). 손으로 본 결과는 일지 2026-11-11-1057의 "셀프 리뷰" 절에 있다
- [x] 01의 위험한 입력 52가지와 그 밖의 사례가 이 티켓의 변환을 더한 뒤에도 지난다. 병적인 입력 14가지(`STRESS_INPUTS`)도 그 가운데 하나로 이름을 들어 본다. 별표와 대괄호가 끝없이 이어지는 입력에 반응하는 변환(2, 3, 6)이 이 티켓에서 들어오므로, 두 갈래 모두 던지지 않고 그리거나 원문으로 물러서며 모든 입력에 거는 규칙에 걸리지 않는다(사용자 이야기 22)
- [x] `MarkdownText`: 위첨자 번호 앞에 공백이 있고, 출처 덩이의 글이 남는다
