# 03: 위젯이 모든 에이전트의 출력을 마크다운 부품으로 그린다

**What to build:** 최종 사용자가 위젯(iframe 방식, 페이지 안 방식, 질문 페이지가 담은 위젯)에서 받는 모든 에이전트의 출력이 01·02의 부품으로 그려진다. 제목, 목록, 표, 링크가 든 답이 기호 없이 보이고, 링크를 누르면 새 탭이 열리며 위젯이 든 페이지는 그대로이고, 이미지가 든 출력을 그려도 그 주소로 요청이 나가지 않는다. 계산 에이전트의 `2*3*4 = 24`는 별표까지 보이고, 기본 에이전트의 번호와 출처는 위첨자와 작은 글자로 보인다. 화면 읽기 프로그램에 새 출력을 알리는 숨긴 영역은 기호를 뗀 글을 읽는다. 최종 사용자의 질문, 실패 안내, 인사말, 승인 카드의 도구 인자는 지금처럼 글자 그대로다. 임베드 속성, 질문 페이지 설정, 서버의 계약(`openapi.json`), 이벤트, 트레이스는 바뀌지 않는다.

근거는 `.scratch/answer-markdown/spec.md`의 "출력의 틀", "읽기 영역은 글자만 내는 갈래로 읽는다", "바뀌지 않는 것", "다른 문서", "고칠 자리의 묶음"의 3, Testing Decisions의 "이음매", "스토리와 사진 비교", "위젯의 시험", "글자를 단언하는 시험의 고칠 자리", "실제 모델 시험의 비교 규칙"이다. 앞선 결정은 ADR 0053 결정 "위젯이 그리는 것"과 "시험", ADR 0024의 e2e 사례다. 기본 에이전트의 위젯 사례(`.scratch/base-agent/issues/06-widget-real-model-assistant-case.md`)와 감싸는 시험의 판정을 함께 건드리고, 둘은 서로 기다리지 않는다(아래 "실제 모델 e2e").

**Blocked by:** 01 (디자인 시스템에 마크다운 부품을 세운다), 02 (마크다운 부품이 출력을 다듬는다). 02 없이 적용하면 계산 에이전트의 `2*3*4 = 24`에서 별표가 사라지고, 한국어의 굵게가 별표로 남으며, 기본 에이전트의 번호와 출처가 본문 크기로 남는다.

**Status:** ready-for-agent

### 위젯

- [ ] 출력의 틀: 숨긴 "출력: "과 `Markdown`을 감싸는 요소(문단이 아니다) 하나에 나란히 둔다. 글자만 든 출력은 지금과 같은 자리에 같은 글자가 놓인다(출력 한 문단의 위아래 여백이 지금과 같다). 되돌린 이전 대화의 출력도 같은 부품으로 그리고, 저장 형식은 바뀌지 않는다
- [ ] 읽기 영역(`role="status"`): 알림 항목에 출력인지 아닌지의 종류를 두고, 출력인 항목만 `MarkdownText`로 문단 안에 그린다. 실패 안내와 상태 같은 다른 알림은 지금처럼 글자 그대로다. 알림은 저장하지 않는다
- [ ] 사용자의 질문, 실패 안내, 인사말, 승인 카드의 도구 인자는 고치지 않는다
- [ ] 위젯 대화 부품의 머리 주석("마크다운으로 그리지 않고 HTML 조각은 글자로 보인다(ADR 0024)")을 지금의 결정(ADR 0053)으로 고친다
- [ ] `web/apps/widget/EMBED.md`에, 출력이 마크다운으로 그려진다는 것, 그리지 않는 것(원시 HTML, 이미지), 링크가 새 탭으로 열리는 조건(`http`·`https`의 절대 주소이고 사용자 정보가 없을 때), 켜고 끄는 설정이 없다는 것을 사이트의 개발자가 읽는 말로 적는다

### 페이지 시험과 스토리

- [ ] 위젯 페이지 시험(`widget-pages`): 굵게가 든 출력에 `strong`이 있다, 숨긴 "출력: "이 그 앞에 그대로 있다, 읽기 영역에는 기호를 뗀 글이 문단으로 놓이고 요소(제목, 표, 링크)가 없다, 되돌린 이전 대화의 출력도 같은 모양이다, 질문·실패 안내·인사말·승인 카드의 도구 인자는 별표와 밑줄이 든 글을 넣어도 글자 그대로다(사용자 이야기 26, 27). 부품의 사례는 다시 적지 않고 "부품이 불렸다"를 보일 만큼만 둔다
- [ ] 출력 문단의 구조(문단 안의 숨긴 글)를 보는 페이지 시험의 사례 하나를 새 구조로 고친다. 도우미를 부르는 79곳은 새 구조에서 돌려 확인하고, 빨개지면 대화 영역 안의 "출력: 글"로 맞춘다
- [ ] 대화 부품 스토리의 긴 낱말 스토리가 출력 문단을 설명하는 주석을 새 틀에 맞춘다

### e2e

- [ ] 준비(`@agent-os/e2e-stack`)의 픽스처 에이전트에, 고정된 마크다운 출력을 내는 에이전트 하나를 더한다(HTML 조각을 내는 지금의 픽스처 에이전트와 같은 모양). 출력에는 제목, 굵게, 표, 링크, 이미지, 문장 끝 번호, 출처 덩이를 넣는다
- [ ] 위젯 e2e(Playwright)에 남기는 사례는 넷이다. (1) HTML 조각이 든 출력이 실행되지 않는다(ADR 0024의 사례 그대로). (2) 이미지가 든 출력을 그려도 그 주소로 요청이 나가지 않는다. 이미지 주소를 준비가 띄운 서버의 경로로 두고 그 경로에 닿은 요청이 0인 것을 보며, 양성 대조로 같은 페이지에서 그 경로를 직접 불러 요청이 세어지는 것을 먼저 본다. (3) 링크를 누르면 새 탭이 열리고 위젯이 든 페이지의 주소는 그대로다. (4) iframe 방식과 페이지 안 방식에서 같은 마크다운 출력의 제목, 표, 링크가 요소로 그려지고, 페이지 안 방식에서 e2e 사이트 페이지에 심은 표와 제목의 CSS가 그 모양을 바꾸지 않는다(표의 테두리나 제목의 글자 크기 같은 계산된 스타일을 하나씩 본다)
- [ ] 페이지 전체에서 출력의 글자를 exact로 찾는 위젯 e2e의 두 곳을 대화 영역 안으로 좁힌다
- [ ] 명세가 그대로 서리라 본 자리(대화 영역 안에서 "출력: 글"로 찾는 위젯 e2e의 네 곳과 페이지 안 방식 e2e의 도우미, 출력이 아직 없다는 것을 0으로 단언하는 두 곳, 질문 페이지 e2e에서 페이지 전체의 "출력: 글"로 찾는 두 곳)를 새 구조에서 실제로 돌려 확인한다. shadow DOM 안의 수는 재지 않은 어림이었다

### 실제 모델 e2e

- [ ] 위젯과 질문 페이지의 실제 모델 e2e 로케이터(`web/apps/widget/e2e/calc.llm.ts`, `web/apps/portal/e2e/calc.llm.ts`의 "문단 가운데 '출력: '이 든 것")를, 숨긴 "출력: "을 감싼 요소를 찾아 그 글을 싣게 고친다
- [ ] 두 파이썬 래퍼(`tests/test_widget_llm.py`, `tests/test_portal_llm.py`)의 비교 규칙을 명세 "실제 모델 시험의 비교 규칙"대로 바꾼다. 화면 글에서 머리의 "출력: "을 떼고 "(새 탭에서 열림)"과 "이미지"를 어디서든 글자 그대로 지운 뒤, 유니코드 글자와 숫자만 남긴 것이 트레이스 출력에서 같은 것만 남긴 것의 부분열이고 화면 글이 비지 않는다. 규칙은 함수 하나이고 두 래퍼가 함께 부른다. 지우는 말은 부품이 스스로 쓰는 문구와 같은 글자다
- [ ] 그 함수를 모델 없이 기본 실행에서 시험한다. 부분열인 짝, 부분열이 아닌 짝(화면 파일 입력의 화면 글을 서로 바꿔 넣은 것 같은 양성 대조), 빈 화면 글, 지우는 말이 든 화면 글을 둔다(명세의 `textcompare.mjs`가 같은 대조를 쟀다)
- [ ] 견주는 짝은 사례마다 하나다. 화면 글은 그 사례가 연 에이전트의 이름과 함께 싣고, 트레이스에서는 그 에이전트로 시작한 실행(`run_started`의 `agent`)의 출력을 고른다. 위젯 래퍼의 `len(outputs) != 1` 판정은 이 짝짓기로 바뀐다(명세 "위젯의 시험"). base-agent 06(`assistant` 사례)이 먼저 들어와 있으면 그 짝짓기를 그대로 쓰고, `assistant` 사례는 정해 둔 낱말만 보며 글자를 견주지 않는다
- [ ] `uv run --env-file <.env 경로> pytest -m llm_widget`과 `-m llm_portal`이 초록이다(워크트리의 `.env` 경로는 `docs/constitution/operations.md` LLM 테스트). base-agent 06이 먼저 들어와 있으면 `-m llm_widget`의 두 사례가 함께 돈다
