# 01: 디자인 시스템에 마크다운 부품을 세운다 — 위험한 글은 그리지 않고 기본 모양은 화면 그림대로

**What to build:** 디자인 시스템 패키지(`@agent-os/ui`)에 출력을 마크다운으로 그리는 부품 `Markdown`과, 같은 변환을 지나 글자만 내는 `MarkdownText`가 선다. 제목, 문단, 굵게, 기울임, 취소선, 목록, 인용, 줄 안 코드와 코드 블록, 표, 링크, 가로줄, 한 줄 바꿈이 좁은 칸에서 사람이 확정한 화면 그림(`.scratch/answer-markdown/design/`의 완성 화면 열)대로 보인다. 원시 HTML과 스크립트는 글자로만 보이고, 이미지는 "이미지: 대체 글"만 보이며, `http`·`https` 밖의 주소와 사용자 정보가 든 주소는 링크가 되지 않는다. 인용과 목록이 10겹 넘게 겹치거나 그리다 던지는 출력은 원문이 글자 그대로 보인다. 디자인 시스템의 카드(스토리)에서 이 모양을 보고, 단위 시험이 입력마다 무엇이 그려지는지 말해 준다. 위젯은 아직 이 부품을 쓰지 않는다.

근거는 `.scratch/answer-markdown/spec.md`의 "부품의 자리와 내보내는 것", "새 의존성", "그리는 요소와 모양", "모양은 요소마다의 클래스로 낸다", "패키지에 더하는 것", "변환의 차례", "한 줄 바꿈", "각주와 할 일 목록", "링크", "이미지 자리와 원시 HTML", "표와 코드 블록의 스크롤 칸", "실패를 받는 방법", "깊이 가드", "읽기 영역은 글자만 내는 갈래로 읽는다", "고칠 자리의 묶음"의 1, Testing Decisions의 "부품의 단위 시험"과 "스토리와 사진 비교"다. 앞선 결정은 ADR 0053과 그 2026-11-11·2026-11-12 이력이다. 규칙은 `.claude/rules/web-design.md`(컴포넌트 공통, 스토리, 판정하는 것)와 `.claude/rules/web-workspace.md`다. 시제품(`.scratch/answer-markdown/probes/markdown_render/apps/widget/`)은 옮기지 않고 명세와 사례 파일을 보고 시험부터 짓는다(원칙 II). 시제품에서 읽어도 되는 것은 규칙의 세부다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 의존성과 단위 시험의 자리

- [ ] `@agent-os/ui`의 `dependencies`에 react-markdown 10.1.0과 remark-gfm 4.0.1을 캐럿 없이 더한다. 판은 다시 고르지 않는다. rehype-raw, remark-breaks, remark-cjk-friendly는 들이지 않는다
- [ ] `docs/constitution/tech.md`의 웹 행에 두 패키지와 쓰임(디자인 시스템 패키지의 마크다운 부품, 판 고정, ADR 0053)을 적고 `docs/constitution/README.md`의 판을 patch로 올린다
- [ ] 패키지의 부품 시험을 jsdom으로 도는 Vitest 프로젝트 하나를 `web/vitest.config.ts`에 더하고, 그 파일들을 `node` 프로젝트에서 뺀다(선례는 위젯 앱의 `widget-pages`). Testing Library(`@testing-library/react`, `@testing-library/dom`)를 패키지의 개발 의존성에 위젯 앱과 같은 판으로 더한다
- [ ] 새 프로젝트는 시험마다 그린 것을 걷는 설정 파일을 쓴다(`cleanup()`을 `afterEach`에 건다. 선례 `web/apps/widget/testing/setup.ts`). 시험 파일은 패키지 tsconfig의 `include`(`src/**/*`) 안에 둔다
- [ ] 변환과 주소 판정처럼 DOM이 필요 없는 시험은 `node` 프로젝트에 둔다

### 부품

- [ ] `Markdown`과 `MarkdownText`는 패키지의 molecules에 두고 루트 진입점이 둘을 내보낸다. props는 둘 다 `text`(문자열) 하나이고, `className`·`style`과 허용 요소나 링크 규칙을 바꾸는 prop이 없다. 상태와 효과가 없다
- [ ] 변환(remark 플러그인 하나와 그 안의 처리들)과 주소 판정은 화면을 그리지 않는 모듈이라 컴포넌트 폴더 밖의 폴더 하나에 두고, 패키지 밖으로 내보내지 않는다
- [ ] 변환은 명세 "변환의 차례"의 1(깊이 가드), 4(각주와 할 일 목록), 7(한 줄 바꿈), 8(바로 앞 형제가 제목인 제목의 표지)을 그 차례로 돈다. 02가 2·3·5·6을 그 사이에 끼운다. 깊이를 세는 일과 나무를 고치는 일은 재귀 없이 돌고, 원문의 위치를 보는 처리는 BOM을 뗀 원문과 맞댄다
- [ ] 그리는 요소는 명세 "그리는 요소와 모양"의 표가 닫힌 목록이다. 라이브러리가 붙이는 클래스(`language-*`, `task-list-item`, `contains-task-list`)와 인라인 `style`은 요소에 넘기지 않고, 표 칸의 정렬은 라이브러리의 정렬 값을 읽어 정렬 유틸리티로 바꾼다
- [ ] 제목은 한 단계 낮춘다(`#`은 `h2`, `#####`와 `######`은 `h6`). 보이는 모양은 여섯 단계가 같다
- [ ] 링크: 브라우저와 Node가 함께 가진 URL 파서로 기준 주소 없이 풀어, 스킴이 `http:`·`https:`이고 사용자 이름과 비밀번호가 비었을 때만 링크로 그린다. `href`에는 파서가 정규화한 주소를 내고, 속성은 `href`·`target`·`rel`(`noopener noreferrer`)뿐이며, 링크 제목은 `title`로 넘기지 않는다. 링크 글 뒤에 화면 읽기 프로그램만 읽는 "(새 탭에서 열림)"을 두고 포커스 링을 그린다. 링크가 아닌 것은 링크 글만 글자로 남는다
- [ ] 이미지: `img`를 내지 않고 "이미지: "과 대체 글을 흐린 글자로 둔다. 대체 글이 비면 "이미지"만 남는다
- [ ] 원시 HTML은 쓴 글자 그대로 보인다. 각주의 `[^1]`과 정의, 할 일 목록의 `[ ]`·`[x]`·`[X]`는 원문 글자로 되돌린다(명세 "각주와 할 일 목록")
- [ ] 표는 `div`로 감싸고 그 `div`가 가로로 스크롤한다. `div`는 이름 "표"의 묶음(`role="group"`)이고 포커스를 받는다(`tabIndex` 0). 코드 블록은 `pre`가 가로로 스크롤하고 포커스를 받는다. 둘 다 포커스 링을 그리고, 넘치지 않을 때도 같은 속성이다
- [ ] 실패: 라이브러리의 컴포넌트를 요소로 두지 않고 함수로 직접 불러 try/catch로 감싸고, 던지면 원문 문단(본문 글자, 줄바꿈과 공백을 그대로, 긴 낱말은 어디서나 꺾는다)을 돌려준다. 인용과 목록의 깊이가 합쳐 10겹을 넘으면 원문으로 물러선다. `Markdown`과 `MarkdownText`는 따로 물러선다
- [ ] `MarkdownText`는 요소 없이 글자만 낸다. 번호 목록은 항목 앞에 번호와 점을 되살리고, 표는 칸 뒤에 공백을, 줄 뒤에 줄 끝 글자를 두며, 이미지 자리는 "이미지: 대체 글"이고, "(새 탭에서 열림)"을 내지 않는다
- [ ] 쓰임 문서 `Markdown.md`에 부품이 스스로 쓰는 화면 문구 셋("(새 탭에서 열림)", "이미지: ", "표")을 적는다

### 모양과 토큰

- [ ] 모양은 요소마다의 유틸리티 클래스로 낸다. 놓인 자리(뿌리, 인용, 목록 항목)는 React 컨텍스트로 알고, 바로 앞 형제가 제목인 제목은 변환이 단 표지로 안다. 표지는 DOM에 넘기지 않는다. 임의값 클래스와 규칙 없는 클래스는 쓰지 않는다(명세 "모양은 요소마다의 클래스로 낸다"의 치수를 내는 길)
- [ ] 글머리는 어디에 놓여도 검은 점이고 안쪽 목록은 들여쓰기 24px으로 단계가 갈린다(ADR 0053의 2026-11-12 이력). 인용 안의 블록 사이는 12px이다
- [ ] 디자인 토큰 CSS의 "부품 치수" 묶음에 `cell-min`(96px)과 `cell-max`(256px)를 간격 이름공간으로 더하고, 묶음 머리 주석에 두 토큰의 쓰임을 더한다. `.claude/rules/web-design.md` 컴포넌트 공통의 부품 치수 목록에 두 이름을 같은 커밋에서 더한다(`.claude/rules/agent-docs.md`)
- [ ] 짓기의 토큰 수 단언(`web/tools/sync-design-system/build.test.ts`의 `toHaveLength(112)`)이 그대로 지난다. 두 토큰은 `tokens.json`에 실리지 않는다

### 단위 시험

- [ ] 사례의 원천은 프로브의 사례 파일(`.scratch/answer-markdown/probes/markdown_render/probe/`의 `cases.mjs`, `shape-cases.mjs`)이다. 명세와 다른 자리(표 스크롤 칸의 역할, 표 칸의 정렬, `language-*` 클래스, 시제품의 클래스와 속성 이름, 가드를 늘 켜는 것)는 명세를 따른다. 옮기는 것은 요소의 종류와 차례, 글, 링크의 주소와 속성이다
- [ ] 위험한 입력 52가지에서 원시 HTML, 스크립트, 이벤트 속성, 위험한 주소가 요소나 속성으로 그려지지 않는다
- [ ] 모든 입력에 거는 규칙 하나(그려진 요소가 허용 목록 안이고, `href`는 `http`나 `https`의 절대 주소뿐이며, 링크의 속성은 `href`·`target`·`rel`뿐이고, `img`·`input`·`script`·`style`·`iframe`과 이벤트 속성과 인라인 `style`이 없다)를 이 티켓의 모든 사례에 건다. 양성 대조로, 라이브러리의 기본 설정으로 그린 대조가 이 규칙에 걸리는 입력 하나를 둔다
- [ ] 한 줄 바꿈 30가지(`BREAKS`), 제목·이미지·표·코드·각주·할 일 목록 21가지(`SHAPE`), 링크 17가지(`LINKS`). 목표를 적어 둔 입력은 그 모양과 같은지를, 적지 않은 입력은 지금의 결과를 고정한다. 셋에는 번호, 출처, 숫자 사이의 기호, 닫히지 않은 굵게가 없어 02의 변환이 결과를 바꾸지 않는다
- [ ] 주소 판정은 순수 함수의 시험으로 따로 둔다. 링크 17가지의 주소에 더해 공백과 제어 글자가 섞인 스킴, 대문자 스킴, 사용자 정보의 여러 꼴, 프로토콜 상대 주소(`//host`), 빈 주소를 넣는다
- [ ] 깊이 가드: 10겹(인용, 한 줄 목록, 들여쓴 목록, 섞인 것)은 그리고 11겹은 원문이며, 원문은 넣은 글자와 같다
- [ ] 실패하면 원문: 던지는 것이 정해진 길(가드의 11겹)로 보고 콘솔에 오류가 없다. 같은 부품 하나에 보통 글, 물러서는 글, 보통 글을 차례로 넣어 다시 그리면 마지막 그림이 그려지고 콘솔에 오류가 없다(라이브러리가 훅을 쓰는 판으로 바뀌면 다시 그릴 때 깨진다. 명세 "실패를 받는 방법")
- [ ] 병적인 입력 14가지(`inputs.mjs`의 `STRESS_INPUTS`)에서 두 갈래 모두 던지지 않고, 그리거나 원문으로 물러서며, 모든 입력에 거는 규칙에 걸리지 않는다. `>` 3,000겹과 들여쓴 목록 200겹은 원문이다. 걸린 시간은 단언하지 않는다(사용자 이야기 22)
- [ ] `MarkdownText`: 요소가 없다, 화면의 갈래와 낱말의 열이 같다, 번호 목록의 번호가 되살아난다, 표의 칸과 줄이 붙지 않는다, 이미지 자리가 "이미지: 대체 글"이다, "(새 탭에서 열림)"이 없다. 상황마다(표, 번호 목록, 다른 수에서 시작하는 번호, 안쪽 목록, 이미지, 줄바꿈, 코드 블록, 물러서는 입력) 하나 이상 둔다
- [ ] 그 밖: 머리의 BOM이 그려지지 않는다, 빈 글과 공백뿐인 글이 던지지 않는다, 링크에 숨긴 "(새 탭에서 열림)"과 `target`·`rel`이 있다, 제목이 든 링크(`[글](주소 "제목")`)에 `title`이 없다, 표의 스크롤 칸이 이름 "표"의 묶음이고 포커스를 받는다, 제목이 `h2`부터 `h6`으로 그려진다
- [ ] 시험은 바깥 행동만 본다. 안쪽 함수의 이름, 나무의 노드 모양, 클래스 이름의 글자는 단언하지 않는다. 시험 이름은 행동을 말하는 한국어 문장이다

### 스토리와 사진

- [ ] 변형 스토리: 기본 모양(`mk-all`의 입력), 그리지 않는 것(`mk-unsafe`), 넘치는 표와 코드 블록, 물러선 원문(`mk-fallback`). 다크 스토리 하나 이상, `"showcase"` 태그의 `쓰임: …` 스토리 하나(위젯의 출력 자리에 놓인 모양). 기본 모양과 그리지 않는 것의 입력은 사례 파일의 `SCREEN_INPUTS`(`mk-all`, `mk-unsafe`)이고, 넘치는 표와 코드 블록과 물러선 원문의 입력은 그 화면 파일(`ch-table-1`, `ch-code-1`, `mk-fallback-320`)의 출력 글을 옮긴다. `SCREEN_INPUTS`에는 그 셋이 없다
- [ ] 놓인 자리 스토리의 이 티켓 몫: 잇단 제목과 제목·문단·제목, 목록 항목 안의 제목, 번호 목록 안의 점 목록과 점 목록 안의 점 목록, 블록이 둘인 인용, 정렬을 적은 표 칸(왼쪽, 가운데, 오른쪽). play가 계산값으로 잰다. 제목 바로 뒤의 제목 사이와 문단 뒤 제목의 사이가 모두 16px이고(표지가 잘못 달리면 24px), 두 안쪽 목록의 글머리가 검은 점이다(명세 "모양은 요소마다의 클래스로 낸다"의 "표지의 길"). 계산값은 `.claude/rules/web-design.md`의 play 항목대로 클래스 글자가 아니라 계산된 값으로 잰다. 색은 `src/storybook/expect.ts`의 도우미로, 사이는 두 요소의 `getBoundingClientRect`로(선례 `Progress.stories.tsx`의 이름 자리), 글머리 모양은 `getComputedStyle`의 `listStyleType`으로 잰다. `expect.ts`에는 사이와 글머리를 재는 도우미가 없다
- [ ] 상호작용 목록(`INTERACTIONS`)에 부품을 더한다. 포커스를 받는 것은 링크, 표의 스크롤 칸, 코드 블록이다. 스토리 테스트가 포커스 링과 명암비(여덟 벌)와 afterEach의 클래스 판정을 지난다
- [ ] `pnpm -C web visual`로 새 스토리의 정답을 만든다. 사람이 보통 밀도의 사진을 화면 파일과 견준다(잇단 제목 사이, 번호 목록 안 점 목록의 검은 점, 넘치는 표와 코드). 인용 안의 블록 사이 12px과 점 목록 안 점 목록의 검은 점은 그림에 없어 명세의 값으로 본다(명세 Further Notes "화면 파일과 달라지는 자리"). 촘촘한 밀도의 사진은 화면 파일과 견주지 않는 기준선이다
