# answer-markdown 화면 프롬프트

위젯이 모델의 출력을 마크다운으로 그린 모습(제목, 목록, 표, 코드, 인용, 링크, 기본 에이전트의 출처 목록)을 그릴 때 그리는 쪽에 주는 시작 프롬프트다. 디자인 시스템 아티팩트에 올린 디자인 시스템으로 완성 화면을 그린다(ADR 0025와 그 2026-10-16·2026-10-20 이력). ADR 0053의 결정 "목업 먼저"가 이 화면을 명세 전에 그리기로 했고, 확정한 화면은 명세의 근거가 된다.

프롬프트에 든 것은 세 가지다. **결정**은 ADR 0053(결정 "부품의 자리", "위젯이 그리는 것", "그리는 요소는 허용 목록이다", "링크", "이미지를 그리지 않는 이유", "줄바꿈", "실패하면 원문", "받아들이는 부작용"), ADR 0051(결정 "답의 모양"의 출처 목록), ADR 0024(원시 HTML을 끈 렌더러만 쓴다), 기능 계획 `.scratch/answer-markdown/plan.md`, 위젯의 확정 화면 `.scratch/web-widget/design/`(위쪽 띠, 질문 상자, 접힌 도구 줄, 입력창)과 그 뒤 바뀐 위젯 문구(입력창 안내 "무엇을 도와드릴까요?", 이름표 없이 화면 읽기 프로그램만 읽는 이름 "질문", `web/apps/widget/components/organisms/Composer.tsx`)가 정한 것이다. 화면 문구의 말은 `CONTEXT.md`(요청은 사람에게 보이는 글에서 질문, 출력, 위젯, 최종 사용자)와 `.claude/rules/web-design.md`에서 왔다. **이 프롬프트의 제안**은 그리는 데 필요해서 더한 것이고 명세가 다시 정한다. 블록 사이 간격, 목록의 들여쓰기, 인용과 줄 안 코드의 모양, 이미지 대체 글의 표시, 새 탭 링크를 화면 읽기 프로그램에 알리는 글, 제목의 단계를 문서의 제목 단계에 옮기는 법이 여기 든다. **탐색용 가정**은 위쪽 띠의 이름, 예시 질문과 출력이고 두 프롬프트 끝의 "탐색용 가정"에 모았다.

위젯은 모델이 지은 출력 하나만 마크다운으로 그린다. 질문 상자, 실패 안내, 첫 화면 안내, 승인 카드의 도구 인자는 지금처럼 글자 그대로다(ADR 0053 결정 "위젯이 그리는 것"). 출처 목록과 문장 끝 번호는 모델이 쓴 평범한 글이다. 부품은 "출처" 줄을 알아보지 않고, 출처를 접거나 카드로 바꾸지 않는다(아래 "참고 디자인"에서 사람이 그렇게 골랐다). 그래서 이 프롬프트가 그리는 것은 위젯의 출력 칸 하나 안에서 마크다운의 요소마다 무엇이 보이는지다. 위젯의 나머지는 확정한 위젯 화면 그대로 그 둘레에 놓인다.

## 하는 법

`/ui-design answer-markdown`으로 한다. 그 스킬이 순서의 원천이고, 이 파일은 그 스킬의 3단계가 쓰는 시작 프롬프트다(참고와 방향은 이미 골랐으므로 그 단계는 다시 묻지 않는다).

1. **디자인 시스템을 맞춘다(스킬 2단계).** 디자인 시스템 아티팩트는 이미 `main@9bf65c75`에 맞아 있었다. 웹 편집이 없었고, `origin/main`(`3dc3f15e`)에서 지은 산출에 보낼 것이 없었다(일지 2026-11-10-1846).
2. **고를 갈래를 그린다(스킬 5단계).** 아래 "1. 고를 갈래"가 그릴 것이다. 와이어프레임 차례는 두지 않는다. 디자인 시스템의 부품으로 그린 와이어프레임은 완성 화면과 색 말고는 거의 같아서, 고를 갈래도 완성 화면으로 그린다(`docs/agents/issue-tracker.md` 화면 디자인 절). 아티팩트 하나에 두 차례를 함께 두고 쪽(`pages`)으로 가른다.
3. **안을 고른다(스킬 6단계).** 갈래마다 사람이 하나를 고른다. 고른 안은 캔버스 메모에도 적는다.
4. **완성 화면을 그린다(스킬 5단계).** 같은 아티팩트의 다음 쪽에 "2. 완성 화면"을 그리고, 사람이 그 차례 전체를 확정한다.
5. **저장소로 옮긴다(스킬 7단계).** 아래 "고른 뒤"가 이 기능의 표 칸이다.

그릴 화면의 나눔은 다음과 같다.
- **안을 고를 화면(갈래 넷).** 제목의 크기(세 안), 표가 넘칠 때(세 안), 코드 블록의 긴 줄(두 안), 문장 끝 번호(두 안)다. 참고 제품끼리 갈린 자리라서 사람이 그림을 보고 고른다. 코드 블록과 문장 끝 번호가 두 안인 것은 고른 방향("조용한 글")이 머리줄과 단추가 붙은 안과 번호를 알약이나 칠로 바꾸는 안을 뺐기 때문이다.
- **배치가 정해진 화면(한 안).** 모든 요소가 든 출력, 출처가 든 출력, 키보드 포커스, 그리지 않는 것, 받아들이는 부작용, 그리다 실패한 출력, 다크, 테마 넷이다. 배치는 고른 방향과 ADR 0053이 정했고, 고를 갈래에서 고른 안을 그대로 쓴다.

## 참고 디자인

`kickoff/prompting.md`의 "참고 디자인 조사"대로 했다. 기준 화면은 위젯이고(`.scratch/web-widget/design/`), 마크다운 출력은 같은 위젯의 출력 칸 안에 그리므로 색·글꼴·간격은 디자인 시스템 그대로 두고 블록의 모양과 위계만 참고에서 고른다. 사람은 줄 참고가 없다고 했고, 세션이 맡긴 서브에이전트가 네 제품의 소스를 GitHub에서 받아 읽었다. 화면은 열지 않았다. 글과 소스에 든 수치는 그 원문의 값이고 잰 값이 아니다.

- IBM Carbon AI Chat: [소스](https://github.com/carbon-design-system/carbon-ai-chat)(커밋 `9f26f485`. 떠 있는 창의 기본 폭 380px, 마크다운의 제목·목록·인용·간격, 줄 안 링크, 표, 코드 조각, 출처 껍데기)
- GOV.UK Chat: [소스](https://github.com/alphagov/govuk-chat)(커밋 `ef5b4a2d`. 출력을 그리는 도우미, 대화 말과 출처 목록의 스타일), [govuk_publishing_components](https://github.com/alphagov/govuk_publishing_components)(커밋 `03c5ac27`의 본문 서식과 표)
- Vercel: [chatbot](https://github.com/vercel/chatbot)(커밋 `a8989b52`의 말 부품), [streamdown](https://github.com/vercel/streamdown)(커밋 `072ce7ea`의 요소 부품, 표, 코드 블록, 한중일 글자 처리), [ai-elements](https://github.com/vercel/ai-elements)(커밋 `ca8be600`의 줄 안 인용과 출처)
- HuggingChat: [소스](https://github.com/huggingface/chat-ui)(커밋 `cdf3781e`의 본문 스타일, 말 부품, 마크다운 설정, 코드 블록. 원문이 덮어쓰지 않은 자리는 Tailwind typography 플러그인의 기본값)

뽑은 공통 규칙(셋 이상의 제품에서 본 것):

1. 작은 제목은 본문 크기에 굵게만 준다(Carbon의 넷째 단계 이하, GOV.UK, HuggingChat). 제목은 아래 블록에 붙여 둔다(Carbon, GOV.UK, Vercel).
2. 표는 넷 모두 표 안에서 가로로 스크롤하고 세로 칸선이 없다. 표를 카드로 바꾸는 제품은 없다.
3. 코드 블록은 가로로 스크롤하고 복사 단추를 둔다(Carbon, Vercel, HuggingChat). 줄 안 코드는 회색 바탕이다(GOV.UK, Vercel, HuggingChat).
4. 인용은 왼쪽 선이고 바탕이 없다(Carbon, Vercel, HuggingChat).
5. 바깥 링크 아이콘은 넷 다 없다.
6. 블록 사이는 16~20px이다(Carbon, GOV.UK, Vercel).

둘 이하에서 본 것: 목록 기호를 글 밖에 매단다(Carbon, GOV.UK), 표 칸 폭의 최소 96px·최대 256px(HuggingChat), 한 줄 바꿈을 줄바꿈으로 그린다(HuggingChat). 갈린 자리는 제목 크기(크게 벌리는 Vercel 30px와 Carbon 28px, 작게 두는 GOV.UK 21px와 HuggingChat 18px), 표를 테두리 칸으로 감싸는지(Vercel), 코드 블록의 머리줄(Carbon, Vercel), 문장 끝 번호의 모양(HuggingChat의 위첨자, Vercel의 알약, Carbon의 형광 칠)이다. 링크 밑줄은 Carbon만 마우스를 올릴 때 긋고 나머지는 늘 긋는다.

한국어에서 본 것(서브에이전트가 CommonMark 파서로 손으로 돌렸다): 강조가 문장부호로 끝나고 바로 조사가 붙으면(`**마감(3월)**까지`, `**"인용"**은`) 굵게 되지 않고 별표가 그대로 보인다. `**마감(3월)** 까지`처럼 띄우면 굵게 된다. ADR 0053이 적은 현상과 같고, 보완은 명세가 프로브로 정한다. 한국어 글꼴에는 기울인 글자가 없어 기울임은 브라우저가 눕혀 그린다(GOV.UK는 기울임을 바로 세운다).

고른 방향은 **조용한 글**이다(GOV.UK Chat, HuggingChat에 가깝다). 출력은 위젯 바탕 위의 글이고, 표와 코드도 단추나 머리줄 없이 얇은 칸으로만 선다. 출처는 출력 끝에 펼친 번호 목록으로 보인다. 위젯이 이미 고른 "조용한 기록형"과 이어진다. 고르지 않은 것은 "도구가 붙은 블록"(Vercel, Carbon처럼 표와 코드 블록이 테두리 카드로 서고 머리줄에 언어 이름과 복사 단추가 붙는 것)이다.

가져오지 않을 것(사람이 추천 목록대로 골랐다): 각 제품의 로고, 브랜드 색과 글꼴, 말풍선 배치의 복제, 표의 필터·쪽 나눔·내려받기·전체 화면, 코드 접기와 실행 단추, 링크를 열기 전의 확인 창, 출처 카드와 출처 접기(접으려면 부품이 "출처" 줄을 알아보는 특수 처리가 필요하다), 수식과 다이어그램, 표가 옆으로 더 있음을 알리는 양끝 그림자(디자인 시스템은 그림자를 떠 있는 것에만 쓴다). 고른 방향을 따라 코드 블록의 복사 단추와 언어 이름도 그리지 않는다.

## 1. 고를 갈래

```text
위젯이 모델의 출력을 마크다운으로 그린 모습의 갈래 넷을 완성 화면으로 그려 줘. 갈래 1·2는 세 안, 갈래 3·4는 두 안이고, 안마다 아트보드 하나다. 디자인 시스템의 기본 테마(녹청)의 라이트 모드, 밀도 보통(위젯 뿌리에 data-density="regular")이다. 위젯 자리의 폭은 320px이다(가장 좁은 폭이라 갈래가 가장 크게 갈린다). 갈래와 안의 이름, 메모까지 모든 결과는 대화의 답이 아니라 디자인 파일 안의 "1. 고를 갈래" 쪽에 넣어 줘. 그 파일을 내보내 쓴다.

위젯(정해졌다): 확정한 위젯 화면대로 그린다. 위젯 창은 떠 있는 바탕(bg-raised)에 그림자(shadow-float), 모서리 radius-l이다. 위쪽 띠에 위젯의 제목과 "새 대화" 글자 버튼, 가운데 대화, 아래 입력창(안내 글 "무엇을 도와드릴까요?"와 보내기 버튼)이고, 셋은 경계선 한 줄로 가른다. 대화의 안쪽 여백은 16px이고 말 사이도 16px이다. 질문은 오른쪽에 붙은 옅게 칠한 상자(bg-selected, radius-l, 안쪽 좌우 12px·위아래 8px, 최대 폭 5/6)이고 글자 그대로다. 출력은 그 아래 바탕 위의 글이고, 출력 바로 위에 접힌 도구 줄(wrench 아이콘 14px, text-small, text-muted) "도구 N개를 불렀습니다"가 있다. 출력이 위젯 높이를 넘으면 대화가 스크롤하지만, 고를 갈래의 그림은 비교할 부분이 보이게 위젯 틀의 높이를 출력에 맞춰 늘려 그린다.

출력 칸 안(정해졌다, 고른 방향 "조용한 글"):
- 본문은 text-body(15px/22px), 글자색 text다. 블록(문단, 제목, 목록, 표, 코드 블록, 인용, 가로줄) 사이는 12px이다. 한 줄 바꿈은 문단 안에서 줄바꿈으로 보인다(빈 줄은 문단을 가른다).
- 굵게는 font-semibold, 기울임은 기울인 글자(한국어 글꼴에는 기울인 모양이 없어 브라우저가 눕혀 그린다), 취소선은 줄을 긋는다.
- 목록: 기호와 번호를 글 밖에 매달아, 꺾인 둘째 줄이 첫 글자에 맞춰 선다. 왼쪽 들여쓰기 24px, 겹친 목록은 24px 더. 항목 사이 4px. 기호는 첫 단계 채운 점, 둘째 단계 빈 점, 번호는 "1.".
- 인용: 왼쪽 선 2px(border-control), 선과 글 사이 12px, 바탕 없음, 글자색 text, 기울이지 않는다.
- 줄 안 코드: 고정폭 글꼴, text-mono(14px), 바탕 bg, radius-s, 좌우 4px.
- 링크: 강조색(accent) 글자에 늘 밑줄. 새 탭에서 열린다. 바깥 링크 아이콘은 두지 않는다.
- 가로줄: 경계선(border) 한 줄.

출력의 예(갈래 1~3이 함께 쓴다). 질문 "육아휴직 신청 절차를 정리해 주세요.", 도구 줄 "도구 2개를 불렀습니다", 출력은 아래 마크다운이다.

  ```bash
  curl -X POST https://hr.example.com/api/v1/leave-requests -H "Content-Type: application/json" -d '{"type":"parental","start":"2026-12-01","end":"2027-11-30"}'
  ```

갈래 1. 제목의 크기. 위 출력의 처음부터 "필요한 서류" 표 머리까지를 그린다(제목 세 단계가 다 보인다).
- 안 1(추천): 모든 제목 단계가 본문 크기(15px/22px)에 font-semibold다. 단계 차이는 두지 않는다. 제목 위는 앞 블록과 16px, 아래 블록과는 4px로 붙인다. 출력의 첫 블록이 제목이면 위 여백이 없다.
- 안 2: 첫째 단계(#)만 제목 글자(text-title 24px/32px, font-semibold)이고, 둘째 단계 이하는 본문 크기에 font-semibold다. 여백은 안 1과 같다.
- 안 3: 첫째·둘째 단계는 본문 크기에 font-semibold이고 그 아래에 경계선(border) 한 줄을 긋는다(글과 선 사이 4px). 셋째 단계 이하는 본문 크기에 font-semibold다. 여백은 안 1과 같다.

갈래 2. 표가 넘칠 때. 위 출력의 "필요한 서류" 제목부터 인용까지를 그린다. 출력 칸의 폭은 288px(위젯 320px에서 좌우 16px)이라 네 칸이 다 들어가지 않는다. 표 글자는 text-table(14px/20px)이고 머리 행은 font-semibold다. 세로 칸선은 긋지 않는다.
- 안 1(추천): 테두리 없는 표. 머리 행 아래와 행 사이에 가로선(border) 한 줄. 칸의 안쪽은 위아래 8px, 좌우 12px이고 첫 칸의 왼쪽은 0이다. 칸 폭은 최소 96px, 최대 256px이고 칸 안에서 줄을 바꾼다. 그래도 표가 넘치면 표 칸이 가로로 스크롤한다(위젯 전체는 스크롤하지 않는다). 처음 모습은 왼쪽 끝이고, 넷째 칸이 오른쪽 끝에서 잘려 더 있음이 보인다. 스크롤 막대는 브라우저 기본이다.
- 안 2: 안 1의 표를 테두리 칸(border, radius-m) 안에 넣고, 머리 행을 바탕(bg)으로 칠한다. 첫 칸의 왼쪽도 12px이다. 넘치면 테두리 칸 안에서 가로로 스크롤한다.
- 안 3: 가로 스크롤 없이 칸 폭을 나눠 네 칸이 출력 칸 폭 안에 다 들어온다. 칸 안에서 줄을 바꾸고 긴 낱말은 아무 데서나 꺾는다. 가로선과 칸 안쪽은 안 1과 같다.

갈래 3. 코드 블록의 긴 줄. 위 출력의 가로줄부터 끝까지를 그린다. 코드 블록은 위젯의 승인 묻기 인자 칸과 같은 칸이다(바탕 bg, 테두리 border, radius-s, 안쪽 12px, 고정폭 글꼴 text-mono 14px, 줄 높이 20px). 언어 이름과 복사 단추는 두지 않는다.
- 안 1(추천): 긴 줄은 칸 안에서 가로로 스크롤한다. 줄은 꺾지 않는다. 처음 모습은 왼쪽 끝이고, 줄이 오른쪽 끝에서 잘려 더 있음이 보인다.
- 안 2: 긴 줄은 칸 안에서 줄을 바꾼다(아무 데서나 꺾는다. 승인 묻기 인자 칸과 같다). 가로 스크롤은 없다.

갈래 4. 문장 끝 번호. 기본 에이전트의 출처가 든 출력을 그린다. 질문 "육아휴직은 얼마나 쓸 수 있어요?", 도구 줄 "도구 1개를 불렀습니다", 출력은 아래 마크다운이다. 첫 두 줄은 빈 줄 없이 줄만 바꿨으므로 한 문단 안의 두 줄로 보인다. "출처"는 문단이고 그 아래가 번호 목록이다. 위젯 높이는 560px 그대로다.
  육아휴직은 자녀 1명당 최대 1년까지 쓸 수 있습니다. [1]
  신청서는 휴직 시작 30일 전까지 내야 합니다. [2]

  출처
  1. 육아휴직 업무편람, 12쪽 (갱신일 2026-10-01)
  2. 인사 규정, 제3장 제14조 (갱신일 2026-08-15)
- 안 1(추천): 문장 끝의 [1]을 글자 그대로(본문 글자, text) 둔다. 출처 목록도 마크다운 그대로다.
- 안 2: 문장 끝의 [숫자]를 작은 위첨자(text-small 12px, text-muted)로 그리고 대괄호를 뗀다. 출처 목록은 안 1과 같다. 그림 옆 메모에 "모든 에이전트의 출력에 걸리는 처리라 a[1] 같은 글도 위첨자가 될 수 있다"를 적는다.

지켜 줄 것:
- 상태는 색만으로 보이지 않는다. 링크는 색과 함께 늘 밑줄을 긋는다.
- 위젯 전체에는 가로 스크롤이 없다. 가로 스크롤은 표와 코드 블록의 칸 안에서만 생긴다.
- 색은 쓰임새 토큰만 쓴다. 강조색은 포커스, 링크, 주 버튼에만 쓴다.
```

## 2. 완성 화면

하는 법 3에서 고른 안을 디자인 파일에 적게 한 뒤 넣는 글이다.

```text
앞에서 고른 안대로 위젯 출력의 완성 화면을 그려 줘. 디자인 시스템의 기본 테마(녹청)의 라이트 모드, 밀도 보통(위젯 뿌리에 data-density="regular")으로 그린다. 위젯과 출력 칸의 정해진 모양, 출력의 예는 "1. 고를 갈래"와 같고, 제목·표·코드 블록·문장 끝 번호는 고른 안을 쓴다. 모든 결과는 디자인 파일 안의 "2. 완성 화면" 쪽에 넣어 줘.

그릴 화면:
1. 모든 요소: "1. 고를 갈래"의 육아휴직 신청 절차 출력을 처음부터 끝까지, 위젯 자리 폭 320px과 400px으로. 출력 전체가 보이게 위젯 틀의 높이를 출력에 맞춰 늘려 그린다(실제로는 대화가 스크롤한다). 400px에서도 표나 코드가 넘치는지 그대로 보인다.
2. 출처가 든 출력: 갈래 4의 출력을 고른 번호 안으로, 위젯 자리 320px과 400px, 높이 560px으로.
3. 키보드 포커스(320px): 출력 안의 링크에 포커스가 있는 모습과, (고른 표·코드 안이 스크롤하면) 그 스크롤 칸에 포커스가 있는 모습. 포커스 링은 디자인 시스템의 포커스 링 토큰(outline 2px, focus-ring, 간격 2px)이다. 스크롤하는 칸은 키보드로 스크롤할 수 있게 포커스를 받는다.
4. 그리지 않는 것(320px): 질문 "영수증과 환불 안내를 보여 주세요.", 출력은 아래 마크다운이다. 원시 HTML은 글자 그대로 보이고 실행되지 않는다. 이미지는 그리지 않고 대체 글만 흐린 글자(text-muted)로 "이미지: 영수증 사진"처럼 보인다(대체 글이 비면 "이미지"만). http·https가 아닌 주소의 링크는 링크가 되지 않고 링크의 글만 평범한 글자로 남는다. 주소에 사용자 정보(@ 앞의 이름)가 든 주소는 링크가 되지 않고 글자 그대로다. 앞의 정상 링크 하나와 나란히 두어 다름이 보이게 한다.
     요청하신 영수증입니다.
     ![영수증 사진](https://tracker.example/r.png?id=184)
     <b>배송 지연</b> 보상은 <script>alert(1)</script> 결제한 수단으로 돌아갑니다.
     [환불 안내](javascript:alert(1))를 확인해 주세요.
     정상 주소는 [주문 내역](https://shop.example.com/orders)입니다.
     https://shop.example.com@phish.example/refund 는 링크가 되지 않습니다.
5. 받아들이는 부작용(320px): 마크다운을 쓰지 않는 에이전트의 출력이 바뀌어 보이는 모습 둘. 그리는 모양은 지금 정한 렌더러(react-markdown과 remark-gfm)가 내는 대로다.
   - 계산 도우미: 질문 "2 곱하기 3 곱하기 4는?", 출력 "2*3*4 = 24입니다." 가운데 3이 기울임이 되고 별표 둘이 사라져 "234 = 24입니다."로 보인다(3만 기울어짐).
   - 글이 든 출력: 아래 마크다운. 첫 줄은 닫는 별표 앞이 괄호이고 뒤가 조사라 굵게 되지 않고 별표가 그대로 보인다. 둘째 줄은 #으로 시작해 첫째 단계 제목이 된다. 셋째 줄의 __init__.py는 굵은 "init" 뒤에 ".py"가 붙어 보인다.
     **민법 제750조(불법행위)**는 고의나 과실로 남에게 손해를 입힌 사람이 갚아야 한다고 정합니다.
     # 1번 항목은 다음 쪽에 있습니다.
     설정 파일은 __init__.py 옆에 둡니다.
   그림 옆 메모에 "사용자가 '모든 답을 항상'을 고르며 받아들인 부작용이다(ADR 0053). 한국어 굵게의 보완은 명세가 정한다."를 적는다.
6. 그리다 실패한 출력(320px): 부품이 그리다 실패하면 원문이 글자 그대로 보인다. 지금의 위젯과 같은 모양이다(본문 글자, 줄바꿈을 지키고 긴 낱말은 줄 끝에서 꺾는다). 예는 >를 아주 깊게 겹친 인용이다. 원문의 앞 몇 줄(>가 가득한 줄들)과 "…"로 줄인 모습을 그리고, 그림 옆 메모에 "원문은 >를 3,000겹 겹친 인용이고, 그리는 쪽이 예외를 던져 원문을 보인다"를 적는다. 실패를 알리는 안내 글은 두지 않는다.
7. 다크: 1번의 출력을 320px 다크 모드로 한 번 더.
8. 테마 넷: 군청, 녹청, 자초, 쪽빛의 라이트 320px에 짧은 출력 하나(링크, 줄 안 코드, 고른 안의 표 두 행, 인용 한 줄)를 나란히. 테마는 색만 바꾸므로 글꼴과 크기는 넷이 같다.

키보드와 화면 읽기 프로그램을 그림 옆 메모로 적는다. 포커스 순서(위쪽 띠의 "새 대화", 대화 영역, 출력 안의 링크와 스크롤하는 칸, 대화 안의 버튼, 입력창, 보내기), 새 탭에서 열리는 링크를 화면 읽기 프로그램에 알리는 법(링크의 글 뒤에 화면 읽기 프로그램만 읽는 "(새 탭에서 열림)"), 표의 스크롤 칸이 이름 "표"의 영역인지, 출력의 제목 단계를 문서의 제목 단계로 어떻게 옮길지(위젯의 위쪽 띠 제목보다 낮은 단계로 내리는 제안), 그리다 실패한 출력을 화면 읽기 프로그램이 어떻게 읽는지(지금처럼 "출력:" 뒤에 원문).

지켜 줄 것:
- 화면 문구는 한국어이고 최종 사용자에게 하는 말이라 "~습니다"로 맺는다. 위젯이 스스로 쓰는 새 문구는 이미지의 "이미지:"와 화면 읽기 프로그램만 읽는 "(새 탭에서 열림)"뿐이다. 이 말을 쓴다: 질문, 출력, 대화, 새 대화, 도구. "답변", "응답", "채팅", "챗봇", "메시지", "세션", "프롬프트"는 쓰지 않는다. 출력 안의 글은 모델이 쓴 것이라 이 규칙의 대상이 아니다.
- 컴포넌트는 디자인 시스템의 모양을 쓰고, 색은 쓰임새 토큰만 쓴다. 다크 전용 색이나 테마 전용 색을 따로 두지 않는다. 길이는 디자인 시스템의 크기 단계와 px만 쓴다(rem은 사이트를 따라가므로 쓰지 않는다).
- 포커스는 모든 상호작용 부품에서 포커스 링 토큰으로 보인다. 상호작용 부품은 브라우저 기본 요소(a, button, textarea)로 짓는다.
- 아이콘은 디자인 시스템의 아이콘 집합(Lucide 모양, 크기 14·16·20px, 선은 크기와 상관없이 1.5px)에서 쓴다. 출력 칸 안에는 새 아이콘을 두지 않는다.
- 위젯 전체에는 폭 320px에서도 가로 스크롤이 없고, 포인터로 누르는 목표는 24px 이상이다. 출력 안의 링크는 글자 줄 높이(22px)라 24px에 못 미치지만, 문장 속 링크는 WCAG 2.5.8의 예외다.

시각 방향: 조용한 글. GOV.UK Chat과 HuggingChat의 출력처럼 평평하고 조용하게, 출력은 위젯 바탕 위의 글이다.
- 떠 있는 것은 위젯 창 하나다. 출력 안의 표, 코드 블록, 인용은 그림자 없이 선과 바탕으로만 선다.
- 강조색은 링크와 포커스에만 쓴다. 성공·경고·위험의 색은 출력 안에 쓰지 않는다.
- 움직임은 없다. 글이 흘러나오는 효과, 입력 중 표시, 그라데이션, 반투명 유리 효과, 표 끝의 그림자는 쓰지 않는다.
- 참고 제품의 로고, 브랜드 색, 글꼴, 화면 구성을 복제하지 않는다. 코드의 복사 단추와 언어 이름, 표의 도구(필터, 쪽 나눔, 내려받기, 전체 화면), 출처 카드와 출처 접기, 링크를 열기 전의 확인 창, 수식과 다이어그램은 그리지 않는다.

탐색용 가정(결정이 아니니 바꿔도 된다): 위쪽 띠의 위젯 제목 "사내 규정 도우미"(5번의 계산 도우미 출력만 "계산 도우미"). 예시 질문과 출력, 문서 이름과 갱신일, 인사 시스템의 주소와 API는 지어낸 것이다. 출처의 모양은 ADR 0051의 "답의 모양"에서 사용자가 고른 미리보기를 옮겼다.
```

2. **명세를 쓴다.** to-spec 스킬의 차례대로 쓰고, 명세가 완성 화면을 가리킨다(ADR 0025). 그림이 이 프롬프트나 위의 근거 문서와 다르면(위젯이 받지 않는 자료를 그렸거나, 금지한 말을 썼거나, 새 아이콘과 새 부품을 썼으면) 명세 전에 사람에게 묻는다. 이 프롬프트의 제안(블록 사이 간격, 목록의 들여쓰기, 인용과 줄 안 코드의 모양, 이미지 대체 글의 표시, 새 탭 링크를 알리는 글, 제목 단계를 옮기는 법)과 탐색용 가정은 명세가 결정으로 바꾸거나 다시 묻는다.

## 완성 화면 확인에서 바뀐 것

위의 본문은 그린 때의 프롬프트이고 고치지 않았다. 완성 화면을 확인하며 사람이 셋을 바꿨고, 아티팩트의 그림과 캔버스 메모, 옮긴 화면은 바뀐 대로다(일지 2026-11-10-1846 "완성 화면"). 명세는 본문과 이 절이 다르면 이 절을 따른다. 결정은 ADR 0053의 2026-11-10 이력이고, 기본 에이전트가 쓰는 글의 모양(ADR 0051 "답의 모양")은 그대로다.

1. **갈래 5 "출처의 구분"을 더했다**(`ch-src-1`, `ch-src-2`). 사람이 출처를 본문과 구분해 달라고 청했다. 고른 안 2는 부품이 출력 끝의 "출처" 줄과 그 뒤 번호 목록을 알아보아, 위에 경계선을 긋고 작은 흐린 글자(`text-small` 12px/16px, `text-muted`)로 그린다. 그래서 첫머리(7행)의 부품이 "출처" 줄을 알아보지 않는다는 문장과, "가져오지 않을 것"이 출처 접기를 뺀 까닭(부품이 "출처" 줄을 알아보는 특수 처리가 필요하다)은 이제 맞지 않는다. 출처를 접거나 카드로 바꾸지 않는 것은 그대로다.
2. **갈래 4는 안 2다.** 처음에는 추천 안 1(글자 그대로)을 골랐다가 완성 화면을 보고 바꿨다. 문장 끝의 `[숫자]`를 대괄호를 뗀 작은 위첨자로 그린다.
3. **완성 5는 보완한 뒤의 목표 모양이다.** 본문 "2. 완성 화면"의 5는 지금 렌더러가 내는 대로 그리라고 했지만, 사람이 숫자 사이의 별표와 밑줄로 두른 강조를 위젯이 글자로 두는 길을 골라 `2*3*4 = 24입니다.`와 `__init__.py`를 글자 그대로, 한국어 굵게는 닫힌 모양으로 그렸다. `#`으로 시작하는 줄이 제목이 되는 것은 남는다. 그림 옆 메모도 본문이 적으라고 한 문장 대신 이 내용이다. 막는 방법은 명세가 프로브로 정한다.
