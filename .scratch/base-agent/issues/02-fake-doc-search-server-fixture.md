# 02: 가짜 문서 검색 서버 — 시험이 실제 서버의 모양으로 답하는 별도 프로세스 픽스처를 띄운다

**What to build:** 시험이 실제 문서 검색 서버(rag-engine) 없이 그 서버와 같은 모양으로 답하는 가짜 검색 서버를 별도 프로세스로 띄우고, 띄운 쪽이 쥔 핸들로 끈다. 서버는 도구 셋(`search`, `get_document`, `list_knowledge_bases`)을 그 서버의 칸, 칸 설명, 도구 설명 글, 입력 스키마, 입력 검증의 차례 그대로 연다. 조각의 위치는 형식마다 실제처럼 오고(PDF는 쪽, DOCX·HWPX는 절 경로 배열), 전문은 블록 경계에서 자른 창으로 오며, 오류는 Problem Details 모양의 실패 결과다. 시험은 띄울 때 실패 모드(검색 실패, 끝 넘음 흉내, 빈 색인)와 창의 상한을 고를 수 있고, 서버가 받은 요청의 헤더와 도구 호출(이름과 인자)을 읽을 수 있다. 흉내 내는 검색 도구 형식의 판 `1.0.0`은 이 서버 모듈의 상수 한 곳에만 있다.

01과 나란히 돌 수 있다. 이 티켓이 끝나면 03(플러그인 꾸러미 시험)이 이 픽스처에 붙고, 03이 프로브(`.scratch/base-agent/probes/skill_follow.py`)도 이 픽스처를 띄우게 고친다.

근거는 `.scratch/base-agent/spec.md`의 Implementation Decisions "가짜 검색 서버"와 Further Notes "스킬을 고칠 때", "형식의 판을 아는 자리", "검색 결과가 비어 오는 때"다. 옮길 원본은 프로브의 가짜 서버 `.scratch/base-agent/probes/fake_doc_search.py`이고, 그 독스트링이 rag-engine main `68aa7e0`에서 무엇을 옮기고 무엇을 다르게 두었는지의 원천이다. 그 프로브의 결과는 `.scratch/base-agent/probes/README.md`의 2026-11-11 절들이다. 선례 픽스처는 원격 MCP 서버 픽스처 `tests/mcp_http.py`(띄우는 쪽)와 `tests/mcp_http_server.py`(서버)다. 앞선 결정은 ADR 0048(판을 한 곳에 적는다, 의존은 플러그인에서 서버로만 간다)과 ADR 0051(가짜 서버로 빠른 검사를 돈다)이다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 띄우기와 판

- [ ] 선례 `tests/mcp_http.py`처럼 별도 프로세스로 띄우고 띄운 쪽이 쥔 핸들로만 끈다. 루프백의 빈 포트에 듣는다
- [ ] 판 `1.0.0`은 서버 모듈의 상수 한 곳에만 적고, 시험은 그 상수를 읽는다(ADR 0048)

### 도구 셋

- [ ] 도구 셋의 칸과 칸 설명, 도구 설명 글, 입력 스키마, 입력 검증의 차례가 프로브의 가짜 서버와 같다(그 서버가 rag-engine main `68aa7e0`에서 옮긴 것이다). 문서 식별자는 UUID이고, 결과 글은 띄어쓰기 없는 JSON이며, 성공 결과에 구조화한 내용과 출력 스키마가 실린다
- [ ] `search`는 질문이 무엇이든 가까운 조각을 `top_k`개(기본 10) 돌려준다. 무관한 질문에도 점수가 낮은 조각이 온다
- [ ] PDF 문서의 조각은 `page`가 있고 `section`이 빈 배열이다. DOCX·HWPX 문서의 조각은 `page`가 null이고 `section`이 절 경로(바깥에서 안쪽)다
- [ ] `get_document`는 `include_text`가 참일 때만 전문의 창을 돌려주고, `text_length`는 그와 상관없이 낸다. 창은 블록 경계에서 잘리고 `next_offset`을 준다. 제목 블록은 `#`을 수준만큼 붙인 한 줄이다
- [ ] 전문의 모양은 문서마다 넷이다. `#` 제목 줄이 든 DOCX·HWPX의 전문, 제목 줄이 없는 PDF의 전문, 비어 오는 전문(`text_length`, `text`, `next_offset`이 모두 null), 한 창보다 긴 전문이다. 글이 없는 문서(스캔본)의 모양은 두지 않는다(명세가 적은 까닭)
- [ ] 창의 상한은 기본 20000자이고 띄울 때 작게 줄 수 있다. 도구 설명 글의 수도 그 값을 따른다

### 오류와 실패 모드

- [ ] 오류는 `isError` 결과에 Problem Details 모양의 JSON을 싣는다. 코드는 다섯이다(`knowledge_base_not_found`, `document_not_found`, `invalid_argument`, `search_unavailable`, `internal_error`). 실패 결과는 도구 함수가 직접 돌려준다. `ToolError`를 던지면 mcp 2.3.0이 글 앞에 머리말을 붙여 결과 글이 JSON으로 시작하지 않는다(명세가 읽은 자리)
- [ ] 띄울 때 켜는 실패 모드는 셋이다. 검색이 `search_unavailable`로 실패하는 모드, 런타임의 끝 넘음 문구(`도구 호출 횟수를 넘었다: 이 실행은 도구를 <N>번까지 부른다`)로 실패하는 모드, 현재 색인 판이 없을 때처럼 검색이 빈 `results`를 내는 모드다

### 헤더와 기록

- [ ] `Authorization` 헤더가 기대한 값이 아니면 401로 막는다
- [ ] 받은 요청의 헤더와 도구 호출(이름과 인자)을 시험이 읽을 수 있게 기록한다(선례 픽스처의 `headers_of`). 헤더가 서버에 닿았다는 것과 `include_text`가 참으로 갔다는 것을 서버 쪽 기록으로 본다

### 표본

- [ ] 표본은 프로브의 것을 옮긴다. 문서 넷과 조각 일곱이다. DOCX 육아휴직 업무편람(조각 셋 가운데 하나가 도우미에게 내리는 지시를 섞은 조각, 전문에 `#` 제목 줄, 복직 절차의 "7일"은 전문에만), PDF 연차휴가 운영지침(조각 둘, 비어 오는 전문), PDF 출장비 지급규정(조각 하나, 제목 줄 없는 전문, 해외 일비 "60달러"는 전문에만), HWPX 법인차량 운영 규정(조각 하나, 785자 전문, 창 상한 320에서 "최대 4일"은 첫 창에만, "35만원"은 셋째 창에만)이다
- [ ] 실제 모델 시험(05)의 단언이 표본의 글자에 기댄다는 것을 서버 모듈의 독스트링에 적는다. 표본을 고치면 그 단언과 프로브를 함께 고친다
- [ ] 프로브의 가짜 서버 독스트링이 적은 것(rag-engine의 어느 커밋에서 무엇을 옮겼고 무엇을 다르게 두었는지)을 서버 모듈의 독스트링으로 옮긴다. 프로브의 서버에 없던 헤더 확인처럼 픽스처에서 달라진 것은 고쳐 적는다. 03이 프로브의 가짜 서버를 지운 뒤에는 이 독스트링이 그 원천이다

### 시험

- [ ] 이 픽스처를 실제 MCP 클라이언트로 띄워 본다. 도구 셋과 그 출력 스키마, 형식마다의 위치, 창(블록 경계, `next_offset`, 마지막 창의 null), 전문의 네 모양, 입력과 실패 모드로 낼 수 있는 오류 넷, 실패 모드 셋, 틀린 헤더의 401, 헤더와 도구 호출의 기록이 위대로다
- [ ] `internal_error`는 도구가 예상하지 못한 예외에서만 나서 MCP 클라이언트의 입력으로는 낼 길이 없다. 그래서 도구 함수가 쓰는, 예외를 실패 결과로 바꾸는 자리를 프로세스 안에서 예외를 던지는 호출로 불러 Problem Details의 코드가 `internal_error`인지 본다
- [ ] 띄운 쪽이 핸들로 끈 뒤 포트가 닫힌다
- [ ] 검증 명령이 모두 초록이다
