# base-agent: 기본 에이전트 assistant와 문서 검색 스킬·연결·규칙을 함께 내, 요구가 없으면 그대로 쓰고 요구가 있으면 복사해 커스텀 에이전트를 만들게 한다.
**슬라이스:** 8
**Blocked by:** mcp-http, approval-rules
**설계:** ADR 0051, ADR 0052

기본 에이전트 `assistant`(`CONTEXT.md`), 스킬 `cite-sources`, 문서 검색 서버를 주소로 가리키는 연결 플러그인 `doc-search`(원격 MCP 서버, ADR 0049), 규칙 파일의 에이전트 표를 기본 플러그인 루트 `plugins/`에 calc와 함께 둔다. 옛 이름은 doc-qa-agent이고, 설계 인터뷰에서 사용자가 이름과 뜻을 바꿨다(일지 2026-11-10-1345). 에이전트의 코드는 일에 묶이지 않고, 문서 검색에만 해당하는 것은 스킬과 연결과 규칙 파일에 있으며, 모델이 검색 도구를 스스로 부른다. 도구 셋의 규칙, 답의 모양, 커스텀 에이전트를 만드는 길은 ADR 0051이 정했다. 런타임은 calc를 모르듯 이 플러그인들도 모른다(ADR 0048). 첫 티켓은 에이전트 매니페스트의 선택 칸 둘(턴의 끝, 도구 호출의 끝)을 더하는 계약 변경이고 다른 티켓을 막는다(ADR 0052). 그 뒤가 플러그인 셋과 규칙 파일의 표, 가짜 검색 서버 픽스처, 커스텀 에이전트를 만드는 안내 문서와 이름만 바꾼 사본의 시험, 실제 모델 시험, 위젯의 실제 모델 e2e 사례다. 마지막 티켓은 실제 문서 검색 서버 이미지로 한 번 돌리는 것이고, 그 이미지(`rag-engine:release-image`)가 나올 때까지 이 기능을 닫지 않는다(사용자가 골랐다). Blocked by에 그 행을 적지 않은 것은 앞의 티켓들이 그 이미지 없이 가짜 서버로 돌기 때문이다. 시험은 ADR 0043의 CI 분담을 따른다. 빠른 검사는 검색 도구 형식의 판을 흉내 내는 가짜 검색 서버로 돌고, 그 판은 픽스처 파일 한 곳에 적는다(ADR 0048). 규칙 파일에 적지 않은 도구는 묻는 것이 기본이라(ADR 0044) approval-rules에 막힌다. 위젯이 답을 마크다운으로 그리는 것은 answer-markdown이고 이 기능과 서로 기다리지 않는다(ADR 0053). 명세가 정할 것: 매니페스트에 적을 두 끝의 값, 근거가 없을 때 답하는 문장의 문구, 안내 문서의 자리, 승인 사례 둘을 둘 시험 층, 그리고 ADR 0052의 "명세가 정할 것"(무엇을 한 번으로 세는지, 셈과 승인의 차례, 끝을 넘은 호출의 기록 모양, 10을 넘는 값을 보는 층). 명세가 먼저 확인할 것: 문서 전문 읽기(`get_document`)가 돌려주는 글의 크기에 끝이 있는지를 rag-engine의 명세에서 보고, 없으면 그 저장소의 계획에 넘긴다. 그 도구는 `include_text`를 참으로 넘길 때만 전문을 돌려주므로(ADR 0051 "도구 셋의 규칙") 스킬이 그 인자를 적고, 승인 사례의 가짜 검색 서버도 그 인자를 본다. 위젯 e2e의 픽스처가 규칙 파일을 덮어쓰므로 `assistant`의 표를 그 픽스처에 더한다(둘 다 ADR 0051 Consequences). 수락: 매니페스트에 적은 턴의 끝을 넘긴 실행은 원인 `loop_limit`으로 끝나고, 도구 호출의 끝을 넘은 호출은 불리지 않고 실패 결과로 모델에 돌아가 실행이 이어지며, 두 칸을 적지 않은 에이전트는 지금과 같이 도는 테스트가 통과한다(ADR 0052). 가짜 검색 서버에 표본 조각을 두고 위젯에서 `assistant`에게 질문하면 출처와 갱신일이 붙은 답이 나오고, 근거가 없는 질문에는 모른다고 답하며, 지시가 섞인 표본 조각이 와도 그 지시를 따르지 않고, 문서 전문 읽기는 승인하면 읽고 답하고 거부하면 조각만으로 답하며, 이름만 바꾼 사본이 원본과 같은 시험을 지나는 테스트가 통과한다. 실제 문서 검색 서버 이미지로 한 번 돌린 결과도 남긴다
