# 08: 저장소 밖 설정 적용 — 자동 압축 창, 사용자 범위 Playwright, 작업 스케줄러

**What to build:** 이 PC의 저장소 밖 설정 셋을 바꾼다. 첫째, 사용자 설정에 `autoCompactWindow` 400,000을 둬서 인계보다 먼저 40만에 닿은 세션이 자동으로 압축된다. 둘째, 사용자 범위 MCP 서버 `playwright`를 지워 Playwright MCP가 플러그인판 하나만 실린다. 셋째, Windows 작업 스케줄러가 매일 08:00에(처음에는 05:00이었고 등록 명령을 보였을 때 사용자가 바꿨다) `tools/token_report.py daily`를 불러 사용량 장부와 보고서를 쌓는다. 셋 다 저장소의 검사와 리뷰를 받지 않으므로, 무엇을 어디에 하는지 그대로 붙여 넣을 수 있는 명령으로 보이고 사람의 허락을 받은 뒤 적용하고, 적용 뒤 확인 명령의 결과를 일지에 적는다.

이 티켓의 세션이 적용하고 확인한다. 저장소에 남는 것은 레벨 스윕 README의 줄과 일지다.

근거는 `.scratch/token-usage/spec.md`의 "자동 압축 창", "시작 컨텍스트"의 Playwright, "작업 스케줄러", "적용 뒤 확인"(맡는 티켓이 적용 티켓인 행), "레벨 스윕 기록"이다. 결정은 ADR 0033 본문과 Consequences "바뀌는 자리"다.

**Blocked by:** 03(작업 스케줄러가 쌓는 장부는 지우지 않으므로, 행의 모양이 다 선 뒤에 쌓기 시작한다)

**Status:** done

1. 작업 스케줄러의 작업 이름과 출력을 남길 자리(실패를 사람이 볼 수 있게)

     `.scratch/token-report/scheduler.log`에 덮어써 남긴다. 그 폴더는 무시되고(`.gitignore`) `report`는 보고서 폴더

     `uv.exe`를 바로 띄우면 작업 스케줄러가 표준 출력을 어디에도 남기지 않아, 실패는 `LastTaskResult`의 숫자로만
     남는다고 어림했다(재지 않았다). 실행 제한은 1시간이다
