# 09: 처음 일어난 실제 인계와 첫 보고서를 사람과 확인한다

**What to build:** 모든 티켓이 병합되고 저장소 밖 설정이 적용된 뒤, 실제로 처음 일어난 인계 하나와 첫 일간 보고서, 새 요약 뒤 첫 세션의 요약을 보고 명세대로 돌았는지 확인한다. 인계가 실제로 절감을 남기는지도 잰다(아래 "인계의 비용"). 명세의 지표가 이것을 재지 못해 이 티켓이 맡는다. 명세의 "적용 뒤 확인" 표에서 이 티켓이 맡은 행도 마친다. 스킬과 저장소 밖 설정에는 시험 이음매가 없어 이것이 그 확인이다(명세 "이음매" ③).

이 티켓은 이 티켓의 세션이 직접 인계하지 않는다. 이 티켓의 세션은 다른 세션이 남긴 일지·지시문·장부·보고서를 읽어 결과를 이 티켓의 일지에 적고, 사람이 해야 하는 것(계정 바꾸기)은 차례를 안내한다.

근거는 `.scratch/token-usage/spec.md`의 Testing Decisions "사람 확인 티켓"과 "적용 뒤 확인"(맡는 티켓이 사람 확인 티켓인 행)이다. 이음매는 사용자가 골랐다(일지 2026-10-16-13).

### 처음 일어난 실제 인계

- [ ] 장부의 세션 행(인계로 열렸는지)이나 일지에서 처음 일어난 인계를 찾는다. 그 인계가 어느 경계였고 스윕 브랜치였는지 적는다
- [ ] 넘긴 세션이 일지를 적고, 백그라운드 대기를 멈추고, 제목을 `<브랜치> (인계함)`으로 바꾸고, `open-session` 뒤 다른 도구 없이 턴을 끝냈는지 본다
- [ ] 새 세션이 워크트리 확인을 지났는지, 지시문의 다음 단계·모델·이어받을 상태(`인계: <경계>`와 경계마다의 문장)가 결정표대로였는지, 일지를 이어 쓰고 커밋했는지 본다
- [ ] 넘긴 세션이 턴 끝 알림을 사람에게 한 번 보였는지, 인계한 턴에는 그 알림이 없었는지 본다
- [ ] 실제 인계 하나가 보지 못한 경계와 갈래(다른 경계, 스윕 갈래, 같은 경계의 재계기, 범위가 끝나는 경계, PR 직후의 두 계기)는 05의 카나리아가 받았다. 그 카나리아의 결과 줄이 최신인지 본다

#### 인계의 비용

이 확인은 명세에 없다. 사용자가 인계로 연 세션이 다시 읽는 값이 절감을 얼마나 깎는지 재야 하지 않느냐고 물어 더했다(일지 2026-10-16-72). ADR 0033 "근거"는 인계 뒤를 따로 셈하지 않았고, "인계를 고른 까닭"에서 새 세션이 시작 컨텍스트(중앙값 3만)에서 다시 시작한다고만 적었다. 같은 절의 절감 어림(읽는 세션 컨텍스트가 압축 지점 20만에서 60%, 40만에서 41% 준다)은 압축 뒤 세션 컨텍스트를 시작 컨텍스트에 요약 2만과 다시 읽기 3만을 더한 값으로 두고, 지난 72시간에 시작한 메인 세션 522개로 셈한 압축의 시뮬레이션이다. 인계로 연 세션이 실제로 얼마나 다시 읽고 얼마나 커지는지는 ADR도 명세도 재지 않았다. 일간 보고서도 이것을 내지 않는다. 10절은 브랜치별 비용, 세션 수, 인계 횟수, PR 앞뒤 몫만 내고, 12절의 다시 읽기 후보는 같은 세션 안의 것만 본다(명세 "사용량 장부와 보고서 도구"의 지표).

- [ ] 인계 한 쌍(앞 세션과 그 세션이 연 인계 세션)마다 아래 셋을 잰다. 인계가 이어지면(일지 2026-10-16-70처럼 넘겨받은 세션이 다시 넘기면) 쌍마다 따로 잰다. 인계 세션의 일이 끝난 쌍만 잰다. 끝났다는 것은 그 브랜치의 PR이 병합되거나 닫혔거나, 인계 세션이 다시 넘긴 것이다. 재는 때까지 이 셋에 들지 않는 쌍(아직 도는 세션, PR 없이 멈춘 세션)은 재지 않고 그 수만 따로 적는다. 인계 시점은 앞 세션이 넘긴 계기의 경계를 일으킨 도구 호출을 낸 응답이다. 인계 훅이 세션 컨텍스트를 읽은 응답과 대개 같지만, 병렬 호출의 앞쪽에서는 그 응답이 아직 기록되지 않아 훅이 그 앞 응답을 읽을 수 있다(명세 "인계 훅"의 세션 컨텍스트 읽기). 그 뒤 앞 세션이 인계 절차(스킬 파일 읽기, 일지, 지시문, 제목, 대기 멈추기, `open-session`)에 쓴 호출은 인계의 비용이다. 그 응답을 기록에서 어떻게 찾는지(계기 문장이 기록에 남는지)는 도구를 지을 때 원본 기록으로 본다(`.claude/rules/probes.md`의 둘째 항목)
  - (가) 세션 컨텍스트: 인계 세션의 메인 세션 호출을 시각순으로 세어 30번째 호출의 세션 컨텍스트와 최대 세션 컨텍스트를 내고, 둘마다 인계 시점의 세션 컨텍스트로 나눈 비를 함께 적는다. 30번째 호출이 없으면 그 칸은 "해당 없음"이고 다른 호출로 대신하지 않는다. 인계 세션이 압축됐으면 압축의 수를 함께 적고, 30번째 호출이 압축 뒤이면 그렇게 표시한다. 30번째는 이 항목을 시킨 세션이 고른 수다. 시작 컨텍스트에 지시문·일지 읽기와 다시 읽기가 얹힌 뒤를 보려는 것이고, 그때까지 몇 호출이 걸리는지는 재지 않았다
  - (나) 인계가 만든 다시 읽기: 인계 세션이 Read한 파일 가운데, 앞 세션이 이미 읽었고 그 뒤 바뀌지 않은 것의 글자 수다. 판정은 장부 12절의 다시 읽기 후보(`tools/token_report.py` 독스트링의 12절)와 같게 하고, 보는 세션만 둘로 넓힌다. 같은 파일(`file_key_of`)을 같은 offset·limit로 읽었거나 앞 세션이 전체를 읽었고, 그 사이에 두 세션 어느 쪽에서도 그 파일을 Edit·Write·NotebookEdit·MultiEdit로 고치지 않았고, 압축이 없었고, 작업 트리를 바꾸는 git 명령(`GIT_MUTATION`)이 돌지 않았을 때 센다. 앞 세션이 압축된 뒤 넘겼으면 압축 전에 읽은 것은 세지 않는다. 인계 시점의 앞 세션 컨텍스트에 없던 것이라 인계가 만든 다시 읽기가 아니고, (다)에서는 새 일로 보고 두 쪽에서 뺀다. 장부의 `reads`에는 고친 기록이 없어 이 판정을 하지 못하므로, 도구는 두 세션의 기록을 직접 읽는다. 글자는 토큰으로 바꾸지 않는다(대기열 273). 인계 세션이 Read한 글자 가운데 그 몫과 가장 많이 다시 읽은 파일을 함께 적는다
  - (다) 비용의 차: 앞 세션이 계속했다면 쓸 비용의 어림에서 인계가 실제로 쓴 비용을 뺀 값이다. 일이 새로 만드는 입력(그 캐시 쓰기와, 뒤 호출이 그것을 캐시에서 읽는 값)과 출력, 서브에이전트 호출은 두 쪽이 같다고 보고 두 쪽에서 뺀다. 앞 세션이 계속했어도 같은 일로 같은 만큼 자라 같은 몫을 읽었을 것이기 때문이다. 그래서 어림은 남은 호출 수(인계 세션의 메인 세션 호출 수)에 인계 시점의 세션 컨텍스트를 곱해 앞 세션 모델의 캐시 읽기 단가로 셈하고, 실제에는 인계로만 생긴 것을 모두 넣는다. 인계 세션의 호출마다 캐시에서 읽은 것 가운데 앞 세션에 이미 있던 몫(시작 컨텍스트, 지시문, 일지, (나)의 다시 읽기)의 읽기, 그 몫을 캐시에 새로 쓴 값, 앞 세션의 인계 절차 호출, 인계 세션이 일을 마칠 때까지 앞 세션이 깨어나 한 호출이다. 마지막 것은 명세 "`next-session`의 인계"의 "넘긴 뒤"가 못 보는 것으로 둔 값이다. 호출마다 읽고 쓴 것 가운데 어디까지가 앞 세션에 이미 있던 몫인지(그 Read 결과가 실린 다음 호출의 캐시 쓰기와, 그 뒤 호출들이 그것을 읽은 값 등)는 읽기와 쓰기에 같은 가름으로 도구가 정해 독스트링에 적는다. 가르지 못한 몫은 새 일로 보고 두 쪽에서 빼며, 실제를 그만큼 낮게 잡았다고 적는다. 단가표는 장부와 같은 것(`tools/token_report.py`)이다. Opus 5.5와 Sonnet 5.5는 캐시 읽기 단가가 같아, 두 세션의 모델이 그 둘이면 모델이 달라도 어림은 같고 실제의 쓰기 단가만 다르다. 두 세션의 모델을 함께 적는다. 환산 비용은 청구액이 아니다(ADR 0033 "못 보는 것")
  - 차가 못 보는 것: 앞 세션이 계속했다면 새 일로 자랐을 몫은 위에서 두 쪽에서 뺐다. 그 밖에 이 항목을 쓰며 본 쏠림은 셋이다. 앞 세션이 계속했다면 그 사이에 자동 압축(창을 적용한 뒤에는 40만)이 왔을 것과, 인계 세션이 지시문과 일지를 읽느라 더 한 호출이 남은 호출 수에 드는 것은 어림을 높인다. 가르지 못한 몫을 새 일로 본 것은 실제를 낮춘다. 셋 다 차를 키우는 쪽이고, 얼마나 키우는지는 재지 않았다
- [ ] 인계 세션은 첫 사람 메시지(지시문)의 "이어받을 상태"가 `인계: `로 시작하는 세션으로 알아본다(명세 "인계 훅"의 경계의 이름과 "`next-session`의 인계"의 시작 프롬프트 칸. 장부 세션 행의 `handoff`와 같은 판정이다). 앞 세션은 그 "이어받을 상태"가 가리키는 일지 파일을 인계 세션이 열리기 전에 Write·Edit로 마지막으로 쓴 같은 브랜치의 메인 세션이다. 그런 세션이 없으면(Bash로 썼다 등) 그 쌍은 아래의 표지가 없는 쌍이다. 인계는 일지를 쓰는 단계(`next-session` 1단계의 4)를 건너뛰지 않는다(명세 "1단계를 건너뛴다")
- [ ] 재는 도구는 이 티켓의 세션이 `.scratch/token-usage/probes/`에 커밋하는 프로브로 짓고, 그 README 표에 한 줄을 둔다. `.claude/rules/probes.md`를 따른다. 곧 재려는 상황의 표지(인계 세션의 `인계: ` 줄, 앞 세션이 하나로 정해졌다는 것, 인계 시점의 세션 컨텍스트가 인계 문턱 20만을 넘는다는 것)를 단언하고, 표지가 없는 쌍은 측정으로 세지 않고 따로 적으며, 그런 쌍이 하나라도 있으면 종료 코드를 0으로 두지 않는다. 이 항목을 더한 세션은 범위가 이 티켓 파일 하나라 도구를 짓지 않았다. 표지를 처음 세워 볼 실제 기록은 main의 일지 2026-10-16-70에 있는 인계 둘이다(브랜치 `chore/precommit-xdist-runner`, `커밋 뒤` 10:45:44Z와 `PR 연 뒤` 11:11:58Z). 그 일지가 인계 계기의 문장에서 옮긴 값으로는, 약 42.7만에서 넘겨받은 세션이 반영 커밋에서 약 28.4만, PR을 연 뒤 약 31.2만이었다. PR 직전 리뷰 둘을 돌린 뒤의 경계 값이라 (가)의 30번째 호출 값은 아니다
- [ ] 재는 때는 인계가 하루 이틀 쌓인 뒤다. 20만을 넘는 메인 세션이 하루 열 개 남짓이고(위 전제), 그 가운데 명세 "인계하지 않는 때"에 들지 않는 세션이 인계한다. 쌓인 수는 장부 세션 행의 `handoff`로 센다. 일간 보고서 10절의 인계 횟수는 비용 상위 열 브랜치만 내서(`TOP_BRANCHES`) 덜 센다. 일지 2026-10-16-70의 두 쌍도 재되, 두 인계 세션 모두 자동 압축 창을 적용한 때(2026-10-16 11:41 UTC, 레벨 스윕 README의 조건 변경)보다 먼저 열렸다고 표시한다. 그 창은 적용 뒤 새로 연 세션부터 선다고 어림했고(같은 README), 둘째 쌍의 인계 세션은 병합까지 맡았고(그 지시문의 요청 범위), PR #281은 그 시각 뒤인 11:59:54Z에 병합됐다(병합 커밋 `df1238cf`의 커밋 시각). 쌓인 쌍을 모두 재어 셋마다 중앙값과 최대, 쌍의 수를 적고, ADR의 가정(인계 세션은 시작 컨텍스트 3만에서 다시 시작한다)과 나란히 일지에 적는다(아래 마감)
- [ ] 판단 기준(제안): 아래 수는 사용자가 정하지 않았다. 이 항목을 시킨 세션과 더한 세션이 고른 것이고, 사용자가 바꿀 수 있다. ADR 0033의 결정(20만 인계, 40만 압축, 경계 셋)은 이 티켓이 바꾸지 않고, 바꿀 까닭이 서면 멈추고 ADR 이력을 제안한다(아래 "어긋났을 때")
  1. 멈추는 기준: (다)의 중앙값이 0 이하다. 위 "차가 못 보는 것"의 쏠림은 셋 다 차를 키우는 쪽이라, 차가 0 이하면 인계가 절감을 남기지 못한 것으로 본다. 멈추고 사용자에게 알린다. 차가 0보다 크면 절감이 남았다고 단정하지 않고, 그 쏠림과 함께 값으로 적는다. 손익은 이 기준만 판정한다
  2. 알리는 기준: (가)의 30번째 호출 비의 중앙값이 0.5를 넘는다. 멈추지 않고, (나)와 함께 보고에 따로 적어 사용자에게 알린다. ADR은 인계 세션이 시작 컨텍스트 3만에서 다시 시작한다고 두었고, 그것은 인계 시점 20만의 15%, 40만의 7.5%다. 0.5는 그 가정의 세 배가 넘어, 인계 세션이 ADR의 가정보다 훨씬 빨리 커진다는 신호다. 다시 읽기 때문인지 새 일 때문인지는 (나)로 가른다. 손익분기는 아니다. 30번째 호출의 값에는 새 일로 자란 몫도 들고, 비가 0.5여도 남은 호출이 많으면 절감이 남는다(셈은 일지 2026-10-16-72)
  3. 판정하는 쌍의 수: 기준마다 그 값이 있는 쌍을 센다(2는 30번째 호출이 있는 쌍만 센다). 다섯 쌍보다 적은 기준은 판정하지 않고 값만 적는다. 중앙값이 한두 쌍에 끌려가지 않게 고른 수다. 하루 이틀 뒤에도 다섯 쌍이 모이지 않으면 있는 쌍의 값을 적고, 판정하지 못했다고 일지의 "다음"에 남긴다
