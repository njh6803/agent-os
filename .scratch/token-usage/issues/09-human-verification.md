# 09: 처음 일어난 실제 인계와 첫 보고서를 사람과 확인한다

**What to build:** 모든 티켓이 병합되고 저장소 밖 설정이 적용된 뒤, 실제로 처음 일어난 인계 하나와 첫 일간 보고서, 새 요약 뒤 첫 세션의 요약을 보고 명세대로 돌았는지 확인한다. 명세의 "적용 뒤 확인" 표에서 이 티켓이 맡은 행도 마친다. 스킬과 저장소 밖 설정에는 시험 이음매가 없어 이것이 그 확인이다(명세 "이음매" ③).

이 티켓은 이 티켓의 세션이 직접 인계하지 않는다. 이 티켓의 세션은 다른 세션이 남긴 일지·지시문·장부·보고서를 읽어 결과를 이 티켓의 일지에 적고, 사람이 해야 하는 것(계정 바꾸기)은 차례를 안내한다.

근거는 `.scratch/token-usage/spec.md`의 Testing Decisions "사람 확인 티켓"과 "적용 뒤 확인"(맡는 티켓이 사람 확인 티켓인 행)이다. 이음매는 사용자가 골랐다(일지 2026-10-16-13).

**Blocked by:** 01, 02, 03, 04, 05, 06, 07, 08

**Status:** ready-for-agent

### 전제

- [ ] 01~08이 main에 병합되고 주 체크아웃이 당겨져 있다. 새 세션의 훅과 스킬이 주 체크아웃의 판으로 돈다(`.claude/rules/tools.md`의 `CLAUDE_PROJECT_DIR`)
- [ ] 지난 7일 기록으로 20만을 넘는 메인 세션은 하루 열 개 남짓이다(명세 "이음매" ③). 하루가 지나도 인계가 없으면 보고서 7·10절과 장부에서 까닭을 찾아 적는다

### 처음 일어난 실제 인계

- [ ] 장부의 세션 행(인계로 열렸는지)이나 일지에서 처음 일어난 인계를 찾는다. 그 인계가 어느 경계였고 스윕 브랜치였는지 적는다
- [ ] 넘긴 세션이 일지를 적고, 백그라운드 대기를 멈추고, 제목을 `<브랜치> (인계함)`으로 바꾸고, `open-session` 뒤 다른 도구 없이 턴을 끝냈는지 본다
- [ ] 새 세션이 워크트리 확인을 지났는지, 지시문의 다음 단계·모델·이어받을 상태(`인계: <경계>`와 경계마다의 문장)가 결정표대로였는지, 일지를 이어 쓰고 커밋했는지 본다
- [ ] 넘긴 세션이 턴 끝 알림을 사람에게 한 번 보였는지, 인계한 턴에는 그 알림이 없었는지 본다
- [ ] 실제 인계 하나가 보지 못한 경계와 갈래(다른 경계, 스윕 갈래, 같은 경계의 재계기, 범위가 끝나는 경계, PR 직후의 두 계기)는 05의 카나리아가 받았다. 그 카나리아의 결과 줄이 최신인지 본다

### 첫 보고서와 요약

- [ ] 작업 스케줄러가 만든 첫 일간 보고서를 열어 지표 열둘과 경보가 있는지 본다. 리뷰 서브에이전트가 Sonnet 5.5 `high`로 돈 것이 4절에 보이는지 본다(07)
- [ ] 새 요약 뒤 처음 연 세션에 요약이 사람에게만 한 번 보였는지, 같은 보고서로는 다음 세션에 보이지 않았는지 본다
- [ ] 그 세션이 데스크톱 앱의 세션이었는지 적는다. 데스크톱 세션의 훅이 `CLAUDE_CODE_SESSION_ATTENDED`를 `1`로 받는지는 04가 코드와 셸 값으로 셈만 했다(04 "정한 것" 1). 데스크톱 세션에서 요약이 한 번도 보이지 않으면 그 셈이 틀린 것이다. 요약을 가져간 세션이 사람이 연 세션이 아니라 `open-session`이 연 세션이었으면(04 훅의 못 보는 것) 그렇게 적고, 사람이 그 세션에서 요약을 봤는지 묻는다

### 레벨 스윕 기록

- [ ] 레벨 스윕 README의 조건 변경 절에서 병합으로 든 줄(05, 06, 07)마다 `gh pr view <번호> --json mergedAt`으로 병합 시각을 채운다(명세 "레벨 스윕 기록"). ADR 0033 본문의 "들인 시각을 … 결과 절에 적는다"가 이것으로 참이 된다. `sweep.py prereg`가 0으로 끝난다

### 적용 뒤 확인(이 티켓이 맡은 행)

- [ ] 자동 압축 창: 적용 뒤 며칠의 보고서 7절에서 자동 압축 직전의 세션 컨텍스트가 40만 안쪽에 모이고 40만을 넘은 세션이 없는지 본다. 그 지점이 40만과 얼마나 다른지 적는다
- [ ] 플러그인 끄기: 새 세션 뒤의 보고서 9절에서 넷의 스킬 목록이 0자인지 본다
- [ ] 계정 바꾸기: 사람이 계정을 바꾼 뒤 새 세션을 열면 계정 기록의 마지막 줄이 새 계정인지 본다. 사람이 바꾸지 않았으면 확인하지 못했다고 적는다
- [ ] 세션 시작 훅의 `systemMessage`: 요약이 보인 세션에서 모델에게 그 경보 줄을 옮겨 보라고 한다. 옮기지 못하면 세션 컨텍스트에 들지 않은 것이다
