# 02: 사용량 장부와 일간 보고서

**What to build:** 사람이 `tools/token_report.py daily`를 치면, 이 PC의 세션 기록(`~/.claude/projects/`)을 읽어 주 체크아웃의 `.scratch/token-report/ledger/`에 달마다 하나인 사용량 장부를 쌓는다. 그리고 장부에서 일간 보고서(`daily/<날짜>.md`)와 요약 파일(`summary.txt`)을 만든다. 이 티켓의 보고서는 명세 지표 1~6을 낸다. 경보, 합계와 계정별 환산 비용, 메인 세션과 서브에이전트, 모델·노력, 서브에이전트 유형, 상위 세션 다섯이다. 경보는 비용 급증과 단가표 밖·읽지 못한 줄의 둘이다. 같은 기록을 두 번 읽어도, 폴더 둘에 겹친 기록이 있어도 수가 같고, 기록 파일이 지워져도 장부는 남는다. 나머지 지표(7~12), 경보 둘, 주간·4주 보고서, 대기열 273을 닫는 것은 03이다. 매일 부르는 작업 스케줄러는 08이다.

근거는 `.scratch/token-usage/spec.md`의 "사용량 장부와 보고서 도구"(도구, 자리, 장부의 행, 증분과 멱등, 계정 기록의 줄, 계정, 단가표, 지표 1~6, 경보, 보고서 파일과 보관, 요약 파일), "대기열 273과 보류 지적"의 측정의 기본 길, Testing Decisions의 보고서 도구 항목이다. 이음매는 명령 하나다(사용자가 골랐다, 일지 2026-10-16-13).

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 도구와 장부

- [ ] `tools/token_report.py`에 명령 셋(`ingest`, `report`, `daily`)이 있고, 인자 넷(세션 기록 폴더, 출력 폴더, `+09:00` 같은 고정 오프셋의 지역 시간대, `--today`)을 받는다. 기본값은 명세대로이고, 주 체크아웃은 git 공용 디렉터리의 부모로 찾는다
- [ ] 표준 라이브러리만 쓴다. `uv run --no-project python tools/token_report.py --help`가 돈다(작업 스케줄러가 가상 환경 없이 부른다)
- [ ] 장부의 모든 행에 형식 판 칸 `v`(1)가 있다. 호출 행은 명세의 칸을 모두 든다(응답 ID, 시각, 세션 ID, 메인 세션·서브에이전트와 그 유형, 프로젝트 폴더, 브랜치, 모델, 노력, 토큰 다섯, 세션 컨텍스트, 직전 호출과의 간격). 환산 비용은 행에 적지 않는다. 세션 행은 이 티켓에서 세션 ID와 시작 시각을 들고, 나머지 칸은 03이 더한다
- [ ] 증분과 멱등은 명세대로다. 지난 실행의 한 시간 전보다 뒤에 바뀐 파일만 다시 읽고 그 세션의 행을 갈아 끼운다. 겹친 사본은 응답 ID와 세션 ID로 한 번만 세고 가장 긴 사본을 읽는다. 줄바꿈 없이 잘린 마지막 줄은 경보 없이 넘긴다
- [ ] 계정 기록(`ledger/accounts.jsonl`)을 명세 "계정 기록의 줄"의 모양 그대로 읽는다. 쓰는 쪽은 04다. 세션의 계정은 `account_uuid`가 `null`이 아닌 마지막 줄이고, 서브에이전트는 부모의 계정이며, 기록이 없으면 "계정 모름"이다. 모르는 키는 무시한다
- [ ] 단가표를 `.scratch/harness/probes/session_cost/costs.py`에서 도구로 옮기고 출처와 날짜를 적는다. 프로브는 그대로 둔다
- [ ] 대기열 273에서 이 티켓의 몫을 옮기며 고친다. `.scratch/harness/probes/token_usage/measure.py`의 호출 모으기(응답 ID마다 출력 토큰이 가장 큰 usage), 비용 가르기(`split`), 서브에이전트 유형 잇기다. 이 PC 경로에 묶인 `REPO_PREFIX`를 없애고 기록 폴더 이름을 주 체크아웃 경로에서 만든다. `dict` 매개변수 대신 기록과 행의 모양을 타입으로 둔다. 대기열 273은 닫지 않는다(03)

### 보고서

- [ ] 지표 1~6을 명세대로 낸다. 경보는 이 티켓에서 둘이다. 하루 환산 비용이 지난 7일 일간 비용 중앙값의 1.5배를 넘는다(호출이 있던 날만 세고 넷보다 적으면 비교하지 않고 그렇다고 적는다). 단가표에 없는 모델의 호출이나 읽지 못한 기록 줄이 있다
- [ ] 일간 보고서는 `--today`의 전날이고, 마지막 일간 보고서 뒤로 빠진 날을 모두 만든다(보관 수 안에서). 일간은 최근 7개만 남는다
- [ ] 보관 수를 넘은 보고서를 지우는 길은 출력 폴더의 그 이름 모양 파일만 지운다. 이름이 다른 파일과 링크를 넣은 시험으로 반박해 본다(`.claude/rules/tools.md`의 지우거나 덮어쓰는 도구)
- [ ] `summary.txt`는 최근 일간 보고서의 날짜, 합계와 계정별 비용 한 줄, 경보 줄 모두, 보고서 경로로 여덟 줄 이하다. 첫 줄은 글자 그대로 `보고서 날짜: YYYY-MM-DD`(지역 날짜)다. 세션 시작 훅(04)이 이 줄에서 보고서 날짜를 읽고 파일을 그대로 보인다(명세 "요약 파일")
- [ ] 하루치 기록, 세션 하나뿐일 때도 셈(중앙값 등)이 끝난다

### 문서와 설정

- [ ] `.gitignore`에 `/.scratch/token-report/`를 더한다
- [ ] 도구의 독스트링에 토큰·비용을 재는 기본 길(장부, 단가표, 겹침 거르기)과 근사 가중치로 세지 않는다는 것, 못 보는 것을 적는다
- [ ] `CLAUDE.md` 지도 표에 한 행을 더한다. 문서 칸은 `tools/token_report.py` 독스트링과 `.scratch/token-report/`, 읽는 때는 토큰·비용·한도를 묻거나 잴 때, 쓰는 때는 지표를 바꿀 때다. `CLAUDE.md`는 `writing-for-agents` 스킬을 따라 고치고 지침 검사가 초록인지 본다

### 시험과 검증

- [ ] 명세 Testing Decisions의 보고서 도구 항목 가운데 이 티켓 몫을 시험으로 고정한다. 장부 항목 가운데 Bash 대상 밖 모두(큰 도구 결과는 03의 세션 행 칸이다), 계정 항목 모두, 날짜 항목의 일간 몫(시간대, 빠진 날, 일간 보관, 보고서 폴더를 지운 뒤 다시 만들기), 지표 항목의 2~6절, 경보 둘, 요약 여덟 줄이다. 모든 시험은 `--today`를 준다. 선례는 `tests/tools/test_check_adr_pointers.py`와 `tests/tools/test_sibling_overlap.py`다
- [ ] 이 PC의 실제 기록 폴더로 한 번 돌려, 보고서의 합계가 같은 기간을 잰 프로브(`.scratch/harness/probes/token_usage/measure.py split`)와 어느 정도 맞는지 일지에 적는다. 출력 폴더는 임시 폴더로 준다
- [ ] `tools/mutate.py`로 겹침 거르기, 증분, 계정 고르기를 바꾸면 시험이 빨개지는지 본다
