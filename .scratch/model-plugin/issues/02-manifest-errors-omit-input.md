# 02: 매니페스트를 읽지 못한 문구가 잘못 적은 값을 되울리지 않는다

**What to build:** 운영자가 플러그인 파일에 칸을 잘못 적어도(모델 파일에 `api_key = "sk-ant-…"`) 그 값이 어디에도 다시 나오지 않는다. 관리 API 목록의 표지 행 `reason`, 단건 상세의 500 봉투, 그 매니페스트를 읽는 실행의 실행 전 실패 500, 그 실패의 서버 기록 한 줄에는 파일 경로와 칸의 위치(`api_key`)와 오류 종류(`extra_forbidden`)만 남는다. 모든 종류의 매니페스트에 걸린다. 운영자는 여전히 어느 파일의 어느 칸이 왜 틀렸는지 안다.

지금도 있는 동작이다. 매니페스트를 읽는 어댑터가 pydantic 검증 오류의 전문을 문구에 담고, 그 전문이 입력값(`input_value`)을 든다. 명세 검토 서브에이전트가 임시 스크립트로 모델 파일에 심은 값이 단건 문구와 목록 `reason`에 그대로 나오는 것을 손으로 봤다고 보고했다(커밋한 프로브가 아니다). 이 기능이 같은 문구를 내는 출구를 둘 더한다. 05의 `serve` 시작 진단과 CLI 시작 확인이 그 문구를 표준 에러에 내고, 04부터 모든 실행이 모델 파일을 읽는다. 모델 파일은 API 키를 잘못 적을 가능성이 가장 큰 파일이고 스토리 10이 "비밀이 플러그인 파일과 관리 API 응답에 실리지 않는다"를 약속한다. 그래서 출구를 더하는 04보다 먼저 닫는다.

근거는 `.scratch/model-plugin/spec.md`의 "시작 때의 확인" 절 2026-10-31 명세 검토 주석과 스토리 10, 일지 2026-10-31-07의 "다음"(PR 직전 보안 리뷰가 기준 미달로 뺀 것), 일지 2026-10-31-08의 명세 검토다. 선례는 트레이스 쪽이 같은 까닭으로 입력값을 빼는 `adapters/jsonl.py`의 `_describe`와 그것을 적은 `.claude/rules/adapters.md`의 문장("pydantic 검증 문구의 `input_value`가 깨진 줄의 내용(도구 결과)을 싣기 때문이다")이다. 헌법 원칙 V(이벤트와 로그에 비밀을 싣지 않는다)가 앞선 결정이다.

01과 나란히 돈다. 둘 다 `tests/adapters/test_filesystem.py`를 고치므로 뒤에 병합되는 쪽이 앞의 것을 합친다. 이 티켓의 시험은 01이 없어도 선다. 모든 종류가 모르는 칸을 `extra_forbidden`으로 거부하므로 에이전트나 mcp 매니페스트에 값을 심으면 된다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 어댑터

- [ ] **매니페스트를 읽지 못한 `PluginError`의 문구가 pydantic 검증 오류를 입력값 없이 싣는다.** 고칠 자리는 파일시스템 어댑터의 매니페스트 파싱 한 곳(`adapters/filesystem.py`의 `_parse`)이고, 모양은 `jsonl.py`의 `_describe`처럼 오류마다 위치와 종류와 문구만 남기고 입력값·문맥·URL을 뺀다. 파일 경로는 지금처럼 문구에 든다. 이 한 곳을 고치면 목록 표지, 단건 상세, 실행 준비, 그리고 05가 더할 시작 진단의 출구가 함께 닫힌다
- [ ] **검증 오류가 아닌 실패(파일을 열지 못함, UTF-8이 아님, TOML 문법 오류)는 지금 문구 그대로다.** 그 문구가 파일 내용을 되울리는지는 이 티켓이 한 번 손으로 보고 결과를 PR 본문에 적는다. 되울리면 같은 모양으로 막는다
- [ ] **오류 종류(`type`)와 위치는 남는다.** 그래서 매니페스트 거부의 표지를 단언하는 기존 시험(종류별 칸 거부, 표지 행의 이유)이 그대로 서거나 표지 단언으로 옮겨 선다. 문구 전문을 글자 그대로 단언하던 시험이 있으면 표지 단언으로 바꾼다

### 시험

- [ ] **실제 폴더에 값을 심은 매니페스트를 두고, 단건 읽기의 `PluginError` 문구와 목록 표지 행의 `reason`에 그 값이 없고 `extra_forbidden`과 칸 이름은 있음을 본다.** 자리는 `tests/adapters/test_filesystem.py`이고 선례는 `test_깨진_매니페스트가_섞여도_읽히는_것은_전부_돌아오고_깨진_것은_표지다`와 `test_같은_깨진_파일을_단건으로_읽으면_PluginError다`다. 심는 값은 키처럼 생긴 글자(`sk-ant-` 머리)이고, 시험 이름이 무엇을 막는지 말한다
- [ ] **HTTP 면은 같은 문구를 그대로 내므로 어댑터 시험으로 덮는다.** 운영자 면의 500 봉투와 서버 기록 한 줄은 오류 문구 그대로이고 최종 사용자 면은 고정 문구다. 따로 시험을 더하지 않는 까닭을 시험 독스트링에 한 줄로 적는다

### 문서

- [ ] **`.claude/rules/adapters.md`에 매니페스트 쪽 문장을 더한다.** 트레이스의 `_describe` 문장 곁에, 매니페스트를 읽지 못한 문구도 경로와 위치와 오류 종류만 싣고 입력값을 되울리지 않는다는 것과 그 까닭(운영자가 칸을 잘못 적은 비밀이 목록·상세·시작 진단으로 나간다)을 적는다

### 검증

- [ ] **빨강을 먼저 본다.** 심은 값이 문구에 있다는 실패가 첫 빨강이다
- [ ] **검증 명령이 모두 초록이다.** 손으로 치는 다섯이다. 이 티켓은 서버 라우트·위젯·실제 모델 호출에 닿지 않는다
