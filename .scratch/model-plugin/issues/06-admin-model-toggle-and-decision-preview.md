# 06: 관리 화면 — 모델 켜고 끄기의 효과를 사실대로 말하고, 꺼진 모델 때문에 막힌 결정을 미리 알린다

**What to build:** 관리 화면 목록의 모델 행에서 "로더가 생기기 전에는 효과가 없다"가 사라진다(스토리 11). 스킬 행에는 그대로 남는다. 멈춘 실행을 열었을 때, 그 실행의 에이전트가 매니페스트의 `model`로 고른 모델이 꺼져 있으면 결정 칸이 에이전트나 mcp가 꺼졌을 때처럼 "꺼진 플러그인이 있어 재개할 수 없다"와 `모델 <이름>`을 보이고 사유 칸과 버튼 둘을 막는다. 에이전트가 `model`을 적지 않아 기본 모델을 쓰는 실행은 미리 알리지 않는다. 관리 API가 기본 모델의 이름을 내지 않아 화면이 모르기 때문이고, 그때는 누른 뒤의 409 봉투가 `꺼진 플러그인이다: model 이름 (에이전트 X 이 쓴다)`로 말한다. README의 `disabled.toml` 줄에서 model이 빠진다.

04가 켜고 끄기를 실제로 듣게 만든 뒤에 화면을 그 사실에 맞춘다. 04와 이 티켓 사이에는 화면이 효과를 낮춰 말하는 틈이 있었고, 사용자가 to-tickets에서 그 틈을 받아들이고 이 티켓을 따로 두는 쪽을 골랐다. 결정 칸의 미리 알림을 모델까지 넓히는 것도 to-tickets에서 사용자가 골랐다(명세 검토가 찾은 빈칸, ADR 0019).

근거는 `.scratch/model-plugin/spec.md`의 "계약" 둘째 불릿과 그 2026-10-31 명세 검토 주석, "꺼진 모델"의 2026-10-31 to-tickets 불릿, "저장소의 기본 모델 플러그인과 격리 루트"의 운영자 문서 불릿, Testing Decisions의 "관리 화면"과 그 주석이다. 앞선 결정은 ADR 0019의 "꺼진 에이전트나 그 mcp 때문에 재개할 수 없는 실행은 미리 알린다"와 ADR 0017(꺼짐)이다. 결정 칸의 규칙은 `.claude/rules/web-admin.md`(목록을 다시 읽다 실패하면 옛 목록을 믿지 않고 미리 알 수 없다고 말한다)다.

05와 나란히 돈다. 함께 고치는 파일은 `README.md` 하나이고 줄이 다르다(05는 `serve` 줄의 주석, 이 티켓은 `disabled.toml` 줄). 뒤에 병합되는 쪽이 앞의 것을 합친다.

**Blocked by:** 04(켜고 끄기가 실제로 듣고, 꺼진 모델의 409 문구가 선다)

**Status:** ready-for-agent

### 목록의 안내 줄

- [ ] **`PluginList.tsx`의 로더 없는 종류 집합에서 model을 뺀다.** 집합의 주석(로더가 아직 없어 끄고 켜도 런타임이 달라지지 않는 종류)도 지금 사실에 맞춘다. 스킬 행의 안내 줄은 그대로다
- [ ] **같은 줄을 단언하는 vitest를 고친다.** `components/pages/HomePage.test.tsx`의 "스킬과 모델 행에만 로더가 생기기 전에는 효과가 없다가 보인다"가 스킬 행에만 보이고 모델 행에는 없음을 단언하게 바뀐다
- [ ] **관리 화면 e2e(`web/apps/admin/e2e/admin-token.e2e.ts`)의 모델 행 단언이 그 줄이 없다는 단언으로 바뀐다.** 스킬 행의 단언은 그대로다
- [ ] **`PluginList` 스토리와 사진을 본다.** to-tickets 시점에 그 스토리의 목록에는 모델 행이 없다("모델은 등록된 것이 없다", 모델 0). 그래서 사진은 바뀌지 않을 것이다(코드를 읽은 어림). `pnpm -C web visual:admin`이 빨개지면 바뀐 사진을 보고 `visual:admin:update`로 정답을 다시 만들어 PR 본문에 적는다

### 결정 칸의 미리 알림

- [ ] **결정 칸의 꺼짐 미리 알림(`components/organisms/RunDecision`의 `disabledFor`)이 에이전트 매니페스트의 `model`을 본다.** 값이 있고 목록에 그 이름의 모델 행이 꺼져 있으면 `모델 <이름>`을 더한다. 에이전트·mcp의 표기(`에이전트 X`, `MCP X`)와 같은 꼴이다. 값이 없으면(기본 모델) 더하지 않는다. 목록이 없거나 에이전트 행이 표지이면 지금처럼 미리 알 수 없다(빈 것). 함수의 독스트링("실행의 에이전트와 그 매니페스트의 `mcp` 를 목록의 행과 잇는다")에 `model`과 기본 모델을 미리 알 수 없는 까닭을 더한다
- [ ] **시험은 `components/pages/RunPage.decision.test.tsx`의 "에이전트가 쓰는 MCP 가 꺼졌으면 결정 버튼이 막히고 꺼진 MCP 가 보인다"를 본뜬다.** 에이전트가 고른 모델이 꺼졌으면 버튼이 막히고 `모델 <이름>`이 보인다. 다른 모델이 꺼진 것은 막지 않는다. `model`을 적지 않은 에이전트는 꺼진 모델이 있어도 미리 막지 않는다. 시험의 에이전트 리터럴은 01이 더한 `model` 칸을 쓴다
- [ ] **결정 칸의 꺼짐 스토리를 본다.** 꺼진 사례는 `components/organisms/RunDetail.stories.tsx`의 `DisabledPlugins`(에이전트와 MCP가 꺼진 경고)다. 경고의 모양은 그대로라 모델 사례를 새 스토리로 더하지 않아도 된다(코드를 읽은 어림). 그 스토리의 목록에 꺼진 모델을 더하면 경고 문구와 사진이 함께 바뀌므로, 더할지는 시작할 때 고르고 바꾸면 `visual:admin:update`로 정답을 다시 만들어 PR 본문에 적는다
- [ ] **관리 화면 e2e의 꺼짐 흐름(`e2e/plugin-toggle.e2e.ts`)은 에이전트만 끈다.** 모델 사례를 e2e에 더하지 않고 vitest로 덮는다. 미리 알림은 화면 안의 계산이고 서버를 지나지 않기 때문이다

### ADR과 문서

- [ ] **ADR 0019에 이력 한 줄의 초안을 쓴다.** 미리 알림이 에이전트 매니페스트가 고른 모델까지 보고, 기본 모델은 관리 API가 이름을 내지 않아 409 봉투에 맡긴다는 것과 그 근거(model-plugin to-tickets에서 사용자가 골랐다, 일지 2026-10-31-08)다. `/code-review`의 셀프 리뷰를 반영한 뒤에 보여주고 승인을 받는다(`CLAUDE.md` 작업 규약 5). ADR 0019 본문의 그 문장에서 이력으로 가는 포인터가 필요한지는 `.claude/rules/adr.md`를 따른다
- [ ] **README의 `disabled.toml` 줄 "skill과 model은 로더가 생길 때 그 로더가 켜짐을 본다"에서 model을 뺀다**(ADR 0040의 "구현 티켓이 고칠 곳")
- [ ] **옛 표현을 저장소 전체에서 grep해 살아 있는 문서에 잔존이 0인지 본다.** 모델을 로더 없는 종류로 적은 문장, 미리 알림이 에이전트와 mcp만 본다고 적은 문장(`RunDecision`의 독스트링 따위)이다

### 검증

- [ ] **빨강을 먼저 본다.** 첫 빨강은 모델 행에 안내 줄이 없다는 vitest 단언과, 에이전트가 고른 모델이 꺼진 실행에서 버튼이 막힌다는 단언이다
- [ ] **검증 명령이 모두 초록이다.** `pnpm -C web verify`와 관리 화면 e2e(`pnpm -C web/apps/admin exec playwright test`)와 사진 비교 `pnpm -C web visual:admin`을 치고, 손으로 치는 나머지도 친다
