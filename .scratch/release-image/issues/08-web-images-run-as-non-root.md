# 08: 관리 화면·위젯·위젯 미리보기 페이지 이미지가 root가 아닌 사용자로 뜬다

**What to build:** `deploy/images/`에서 web 쪽 이미지 셋(`admin`, `widget`, `portal`)을 짓는다. 셋 모두 uid 10001의 `agentos` 사용자로 돌고(스토리 25) 첫 프로세스가 tini다. 관리 화면은 지을 때 상류를 `http://serve:8000`으로 넣어 같은 네트워크의 serve로 관리 API를 넘긴다. 위젯은 뜰 때 운영자의 사이트 파일로 빌드한 뒤 서비스를 시작하고, 사이트 파일이 없거나 깨졌으면 빌드 전에 까닭을 적고 끝난다. 위젯 미리보기 페이지는 node가 `.ts`를 빌드 없이 돈다. compose 파일과 자동 시험은 09가 더한다. 이 티켓은 이미지를 이 PC에서 지어 띄운 결과를 일지에 적는다.

web 셋의 측정은 `node:24-bookworm-slim`과 uid 1000에서 했고, 명세가 고른 꼴은 `node:24-trixie-slim`과 uid 10001이다(명세 "이미지의 구성"의 바탕과 사용자). 명세 검토가 그 차이를 짚었다(일지 2026-11-14-1748 "명세 검토"의 S9). 그래서 이 티켓이 프로브를 고른 꼴로 다시 잰다.

근거는 명세 "이미지의 이름과 태그"의 OCI 라벨, "이미지의 구성"의 바탕·사용자와 init·관리 화면·위젯·위젯 미리보기 페이지·상태 확인, "루프백 규칙의 예외", "관리 화면의 상류", "발행하는 포트와 지원하는 최소 판"의 컨테이너 안 포트, "배포 파일 묶음"의 사이트 파일과 위젯 미리보기 페이지 설정 폴더다. 측정은 `.scratch/release-image/probes/web_images/README.md`이고 이 티켓이 그 프로브를 고쳐 다시 돈다(아래 "프로브").

**Blocked by:** 03

**Status:** ready-for-agent

### 시작하기 전에

- [ ] portal-admin 기능이 위젯이 사이트 파일을 요청 때마다 읽게 바꿨는지 본다(명세 Out of Scope, `.scratch/portal-admin/plan.md`의 "release-image 명세가 넘긴 것"). 바꿨으면 위젯이 뜰 때 빌드하는 꼴이 달라지므로 위젯 이미지를 짓기 전에 멈추고 명세로 돌아간다

### 셋에 공통

- [ ] 바탕은 `node:24-trixie-slim`을 digest로 고정한다. uid·gid 10001의 `agentos` 사용자와 그 passwd 항목과 홈 폴더를 이미지가 만들고, 첫 프로세스는 tini다
- [ ] 의존성 설치는 pnpm의 저장소와 메타데이터 캐시를 빌드 캐시 마운트로 빼서 이미지에 남기지 않는다
- [ ] 03의 판정이 읽는 표지 파일 `/etc/agent-os/image`를 root 소유로 굽고, OCI 라벨 셋을 빌드 인자로 채운다
- [ ] 관리 화면과 위젯의 이미지에는 `NEXT_TELEMETRY_DISABLED=1`을 둔다

### 이미지마다

- [ ] 관리 화면: 운영 의존성과 이미지를 지을 때 만든 `.next`를 담고 시작 래퍼로 띄운다. 짓는 단계에 표지 파일과 루프백 예외의 환경 변수를 두어 상류 `http://serve:8000`이 빌드 때의 검사를 지나게 한다(03이 남긴 일). 읽기 전용 루트로 돈다
- [ ] 위젯: 워크스페이스 전체 의존성을 잠금 파일을 얼려 깔고, 지을 때 `next typegen`으로 `next-env.d.ts`와 `.next/types`를 미리 만들며, `.next`와 `public`을 앱 사용자 소유로 둔다. 시작은 사이트 파일의 자리를 컨테이너 안의 정해진 경로로 늘 넘긴다. 루트는 읽기 전용으로 두지 않는다
- [ ] 위젯 미리보기 페이지: 운영 의존성과 `apps/portal`, `packages/site-file`, `packages/ui`의 소스를 담는다. 읽기 전용 루트와 읽기 전용 설정 폴더로 돈다
- [ ] 사이트 파일의 경로와 위젯 미리보기 페이지 설정·개인 키의 경로는 서로 다른 폴더로 이 티켓이 정한다. 사이트 파일 폴더는 serve·위젯·위젯 미리보기 페이지에, 설정 폴더는 위젯 미리보기 페이지에만 얹힌다(명세 "배포 파일 묶음", 명세 검토 S3). 정한 경로를 일지에 적어 09의 compose와 10의 배포 안내가 쓰게 한다

### 이 PC에서 띄워 본다

본 명령과 결과를 일지에 적는다.

- [ ] 셋의 사용자가 uid 10001이고 root가 아닌지, `docker stop`이 143으로 끝나는지 본다. 빌드 중인 위젯도 멈춰 본다
- [ ] 관리 화면: 같은 Docker 네트워크에 serve(07의 이미지, 없으면 가짜 상류)를 별칭 `serve`로 두고 관리 API가 넘어가는지 본다. 루프백 예외의 환경 변수 없이 띄우면 상류 검사로 끝나는지 종료 코드로 본다(기록의 `Ready` 줄은 실패보다 먼저 찍힌다)
- [ ] 위젯: 네트워크 없이 사이트 파일로 빌드하고 서는지, 걸린 시간과 메모리 최고치를 본다. 사이트 파일이 없음·폴더·깨짐·읽지 못함일 때 빌드 전에 진단과 함께 종료 1로 끝나는지 본다. 사이트 파일을 바꾸고 같은 컨테이너를 다시 띄우면 바뀐 파일로 다시 빌드하는지 본다
- [ ] 위젯 미리보기 페이지: 네트워크 없이 서고, 앱 사용자가 읽지 못하는 개인 키로는 시작에서 끝나는지 본다. 페이지가 받는 토큰 CSS, 페이지 스크립트, 글꼴이 이미지에서 나오는지 한 번 본다(09 시험의 첫 사례가 같은 것을 단언한다)
- [ ] 셋 모두 시작 래퍼나 설정에 `0.0.0.0`을 주고 루프백 예외의 환경 변수를 주지 않으면 03의 진단과 함께 끝나는지 본다(스토리 26)
- [ ] node의 `fetch` 한 줄로 묻는 상태 확인(관리 화면 `/`, 위젯 `/widget`, 위젯 미리보기 페이지 `/portal/health`)이 정상에 0, 듣지 않는 포트에 1인지 본다
- [ ] 셋의 풀린 크기와 짓는 데 걸린 시간을 적는다

### 프로브

- [ ] PR 567 봇 첫 회차에서 보류한 `web_images/run.py`의 지적을 고친다. 자리는 "admin-upstream 기본 판은 다른 컨테이너에 닿지 않는다(대조)" 회차의 500 단언(기준 `c21a4fc3b`에서 912~916행)이다. 봇이 든 895행은 PR 567의 반영 커밋 전 판의 번호다. 500 응답이 기대한 원인(예외 없는 판이 상류를 거부한 것)에서 났다는 표지를 본다(`.claude/rules/probes.md`의 첫 항목. 원문은 일지 `docs/journal/2026-11-13-1843-release-image-spec.md`의 "봇 첫 회차")
- [ ] 시제품 Dockerfile의 바탕을 이 티켓이 고른 `node:24-trixie-slim`(같은 digest)으로, 앱 사용자를 uid 10001로 바꾼다. 03이 들인 예외 때문에 프로브가 이미지 안의 사본에 측정용 예외를 넣던 몫이 맞지 않으면 그 몫을 고친 코드에 맞게 바꾸고 README에 적는다
