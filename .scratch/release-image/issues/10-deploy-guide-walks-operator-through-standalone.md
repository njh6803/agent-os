# 10: 배포 안내가 운영자를 단독 배포의 채우기부터 확인까지 이끈다

**What to build:** 배포 파일 묶음에 드는 한국어 배포 안내 한 편이 `deploy/standalone/`에 선다. 운영자는 그 문서만 보고 인증서와 키, 사이트 파일, 위젯 미리보기 페이지 설정과 개인 키, 환경 변수 파일을 채워 띄우고, SSH 포트 포워딩으로 관리 화면에 닿는다. 시험 삼아 띄울 때 쓸 스스로 서명한 인증서의 명령(스토리 13), 인터넷이 막힌 곳으로 이미지를 옮기고 해시를 대조하는 명령(스토리 14), Docker Hub에서 받는 횟수 제한(스토리 15), 사이트 파일을 고친 뒤 다시 띄울 것(스토리 18), 지원하는 Docker Engine과 Compose의 최소 판(스토리 21), 발행 포트를 고치면 열리는 것(스토리 22), 도메인에 IPv4 주소만 등록하라는 것(스토리 30)이 그 안에 있다. 내 인증서와 키를 정해진 폴더에 두면 프록시가 읽는다(스토리 12).

안내에 적는 명령은 이 티켓이 실제로 돌려 본다. 명세가 "배포 안내를 쓰는 티켓이 실제로 돌려 본다"고 넘긴 명령이 넷이다(스스로 서명한 인증서, 바인드 마운트로 바꿀 때의 옮기기와 소유 넘기기, 위젯 미리보기 페이지 개인 키의 소유와 권한, 인터넷이 막힌 곳의 반입).

근거는 명세 "배포 안내"(적는 것의 목록과 위 절들이 넘긴 것), "배포 파일 묶음", "이미지의 구성"의 사용자와 init·serve·플러그인 루트와 트레이스 폴더를 붙이는 것·위젯, "발행하는 포트와 지원하는 최소 판", "프록시 설정"의 키 파일·설정을 고칠 때·IPv6, "프록시가 뒷단을 다시 찾는 길"이다. 측정은 `.scratch/release-image/probes/bridge_recover/README.md`이고 이 티켓이 다시 돈다(아래 "프로브"). 이 티켓의 "명세 검토"와 그 번호(S3, N4 같은 것)는 일지 `docs/journal/2026-11-14-1748-release-image-tickets.md`의 "명세 검토" 절을 가리킨다.

**Status:** ready-for-agent

### 안내

- [ ] 명세 "배포 안내"가 늘어놓은 항목을 모두 싣는다. 위 절들이 배포 안내에 넘긴 문장도 모두 싣는다. 쓰기 전에 명세에서 "배포 안내"를 grep해 걸린 문장을 하나씩 대 보고, 빠진 것이 없는지 일지에 적는다. 넘긴 것의 예는 Docker 문서의 두 문장을 옮긴 경고와 rootless 모드·firewalld·ufw에서는 재지 않았다는 말, 관리 화면이 떴는지는 기록의 `Ready` 줄이 아니라 종료 코드와 상태 확인으로 본다는 것, compose에 `user:`를 더하지 말 것, 인터넷이 막힌 곳에서 npx로 띄우는 MCP 서버가 서지 않는 것, 바인드 마운트로 바꿀 때의 명령, 키 파일의 소유와 권한, `nginx -t` 뒤 reload, `request_chars`를 크게 올리면 413이 먼저 답할 수 있는 것, 다시 만들거나 판을 올린 직후 약 10초, IPv4 주소만 등록할 것과 `0.0.0.0`을 지우면 생기는 일이다
- [ ] 채울 폴더는 09의 compose가 얹는 대로 적는다. 사이트 파일 폴더와 위젯 미리보기 페이지 설정·개인 키 폴더는 따로이고, 위젯 미리보기 페이지의 개인 키는 주인을 root로 두고 그룹 10001에 읽기만 연다(명세 "배포 파일 묶음", 명세 검토 S3). 환경 변수 파일은 비밀 값을 담으므로 운영자만 읽게 두라고 적는다
- [ ] 서버의 메모리(위젯이 뜰 때 1.6GiB 가까이 쓴다)와 판을 바꿀 때 먼저 노트의 "올릴 때 할 일"을 본다는 한 줄을 적는다. 판 올림의 절차 전체는 쓰지 않는다(ops-backup-upgrade의 것)
- [ ] 경로·ADR 번호·티켓 이름 같은 저장소 안의 말은 운영자가 쓰지 않으므로 싣지 않고, 화면에 무엇이 뜨는지와 운영자가 치는 명령으로 쓴다

### 돌려 보는 명령

본 명령과 결과를 일지에 적는다. 돌려 보지 못한 명령은 안내와 일지에 그렇다고 적는다.

- [ ] 스스로 서명한 인증서를 만드는 openssl 한 줄(bridge_edge README 5절의 시제품에서 시작한다)로 만든 인증서와 `root:101 0640`의 키로 프록시가 TLSv1.3으로 뜨는지 본다
- [ ] 위젯 미리보기 페이지의 개인 키를 안내의 소유와 권한으로 두면 그 컨테이너가 서는지 본다
- [ ] 플러그인 루트와 트레이스 폴더를 바인드 마운트로 바꾸는 명령(이미지의 플러그인을 호스트 폴더로 옮기고 두 폴더의 소유를 `10001:10001`로 넘긴다)을 치고, 플러그인 끄고 켜기가 204이고 실행이 트레이스를 쓰는지 본다
- [ ] 인터넷이 막힌 곳의 반입 명령(`docker save`로 파일로 저장, `docker load`로 불러오기, 해시 대조)을 이 PC에서 친다. 대조할 해시가 무엇인지(파일의 해시인지 이미지의 digest인지)를 안내에 적는다
- [ ] 사이트 파일을 고친 뒤 세 컨테이너를 다시 띄우면 바뀐 값이 듣고, 위젯이 다시 뜨는 동안 위젯이 응답하지 않는지 본다
- [ ] 안내를 처음부터 따라 이 PC에서 04의 도구로 지은 묶음을 띄우고, 위젯 미리보기 페이지에서 질문하고 답을 받는다. 안내에서 막힌 자리가 있으면 안내를 고친다
