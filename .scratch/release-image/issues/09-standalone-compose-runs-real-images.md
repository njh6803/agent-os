# 09: 단독 compose가 실제 이미지 넷과 프록시로 뜨고, 브라우저 시험이 그 배치를 잠근다

**What to build:** `deploy/standalone/`에 단독 배포의 원본(compose 파일, 프록시 설정 두 파일, 환경 변수 틀, 사이트 파일 틀, 위젯 미리보기 페이지 설정 틀)이 선다. 04의 도구로 그 원본을 배포 파일 묶음으로 지어 풀고 채울 것을 채운 뒤 `docker compose up`을 치면, 방문자는 프록시의 443으로 위젯 미리보기 페이지에 들어가 질문하고 답을 받는다(스토리 1, 27). 80은 443으로 넘기고(스토리 28), 토큰 끝점의 몰아치기는 429이며(스토리 29), 정해진 경로 밖은 404다(스토리 31). 밖으로 발행한 포트는 프록시의 `0.0.0.0:443`·`0.0.0.0:80`과 관리 화면의 `127.0.0.1:3000` 셋뿐이다(스토리 10, 11, 30).

새 워크스페이스 패키지 하나가 그 배치를 띄워 Playwright의 Chromium으로 위 사례를 단언하고(명세 Testing Decisions의 첫째 이음매), ci.yml의 새 잡이 main으로 가는 PR과 main 푸시에서 그 시험을 돈다(스토리 38). 시험 패키지와 CI 잡은 Dockerfile·compose 파일·프록시 설정이 모두 갖춰지는 이 변경에 함께 싣는다(명세 "티켓을 나눌 때 함께 둘 것"). dev로 가는 이 PR에서는 잡이 시험하지 않으므로 이 PC의 Docker로 돌린 결과를 일지에 적는다.

`merge.md`의 한 문장을 고치므로 하네스에도 닿는다(아래 "CI와 검증 명령").

근거는 명세 "이미지의 이름과 태그", "이미지의 구성"의 사용자와 init·serve·플러그인 루트와 트레이스 폴더를 붙이는 것·상태 확인, "루프백 규칙의 예외", "발행하는 포트와 지원하는 최소 판", "프록시 설정", "프록시가 뒷단을 다시 찾는 길", "배포 파일 묶음", Testing Decisions의 첫째, ADR 0043 Consequences "CI 분담"이다. 측정은 `.scratch/release-image/probes/`의 `proxy_config`, `bridge_edge`, `bridge_recover`다. 이 티켓이 `proxy_config`와 `bridge_edge`를 고쳐 다시 돈다(아래 "프로브"). `bridge_recover`는 10이 다시 돈다. 이 티켓의 "명세 검토"와 그 번호(S3, N4 같은 것)는 일지 `docs/journal/2026-11-14-1748-release-image-tickets.md`의 "명세 검토" 절을 가리킨다.

**Blocked by:** 04, 07, 08

**Status:** ready-for-agent

### compose 파일

- [ ] 서비스는 serve, 관리 화면, 위젯, 위젯 미리보기 페이지, 프록시 다섯이다. 이미지 넷의 이름공간과 판 번호는 환경 변수 틀의 값으로 고른다(명세 "배포 파일 묶음")
- [ ] 발행하는 포트는 프록시의 `"0.0.0.0:443:8443"`과 `"0.0.0.0:80:8080"`, 관리 화면의 `127.0.0.1:3000` 셋뿐이다. serve, 위젯, 위젯 미리보기 페이지는 발행하지 않고, 안쪽 네트워크에 IPv6를 켜지 않는다
- [ ] 다섯의 재시작 정책은 `unless-stopped`이고 `depends_on`은 두지 않는다
- [ ] 우리 이미지 넷에는 `user:`를 주지 않고 메모리 제한을 두지 않는다. 루프백 예외의 환경 변수 `AGENT_OS_CONTAINER_NETWORK=1`은 넷에 서비스마다 직접 주고, 듣는 주소 `0.0.0.0`은 serve의 `--host`, 관리 화면과 위젯 시작 래퍼의 `--hostname`, 위젯 미리보기 페이지 설정 틀의 `host`(포트 3000)로 준다. `HOSTNAME`으로는 주지 않는다
- [ ] serve는 읽기 전용 루트에 플러그인 루트와 트레이스 폴더를 이름 있는 볼륨 둘로 붙이고, 홈에 앱 사용자 소유의 tmpfs(`uid=10001,gid=10001,mode=0700`)를 준다. 관리 화면과 위젯 미리보기 페이지는 읽기 전용 루트이고, 위젯은 읽기 전용으로 두지 않는다
- [ ] 환경 변수 파일은 serve 하나에만 준다. 사이트 파일 폴더는 serve·위젯·위젯 미리보기 페이지에, 위젯 미리보기 페이지 설정과 개인 키의 폴더는 위젯 미리보기 페이지에만, 인증서와 키 폴더와 프록시 설정 폴더는 프록시에 읽기 전용으로 얹는다(명세 검토 S3). 컨테이너 안의 경로는 08이 정한 것을 쓴다
- [ ] 프록시는 공식 `nginx`의 안정판 alpine을 digest로 고정하고 `user: "101:101"`, 읽기 전용 루트, 모든 권한(capability) 빼기, `no-new-privileges`, `/tmp` tmpfs, `init: true`로 둔다. 상태 확인을 두지 않는다
- [ ] 우리 이미지 넷의 상태 확인은 07과 08이 본 명령이고, 첫 값은 간격 30초, 제한 시간 10초, 재시도 3, 시작 간격 2초, 시작 유예 위젯 300초와 나머지 30초다

### 프록시 설정과 틀

- [ ] 주 설정은 공식 이미지의 것을 바꿔 끼워 pid 파일과 임시 폴더를 `/tmp` 아래로 옮긴다. 사이트 설정은 명세 "프록시 설정"의 조각과 항목(포트와 TLS, HSTS, 허용 목록의 경로, 넘기는 머리, 본문 상한, 토큰 끝점의 빈도 제한, `upstream`의 `zone`과 `resolve`, `resolver 127.0.0.11 valid=5s ipv6=off`)을 담는다. 잰 설정 `.scratch/release-image/probes/proxy_config/nginx/proxy.conf`에서 `listen [::]:8443 ssl`과 `listen [::]:8080`을 뺀 꼴이다
- [ ] 환경 변수 틀은 판 번호, 이미지 이름공간, 관리 토큰, 그것과 다른 채널 토큰, 기본 모델의 이름, 모델 제공사의 API 키를 든다. 사이트 파일 틀과 위젯 미리보기 페이지 설정 틀은 서로 다른 폴더에 둔다. 판 번호와 이미지 이름공간을 채우는 자리는 04가 독스트링에 정한 표시를 쓴다

### 시험 패키지

- [ ] 새 워크스페이스 패키지 하나에 시험을 둔다. e2e-stack(`@agent-os/e2e-stack`)의 픽스처 플러그인과 토큰 서명을 다시 쓴다. 시험은 04의 도구로 배포 파일 묶음을 지어 임시 폴더에 풀고, 시험용 인증서·키·사이트 파일·설정을 채워 띄운다. 이미지의 이름공간과 태그는 환경 변수로 받는다(첫 판을 지켜보는 세션이 레지스트리에서 받은 이미지로 같은 시험을 돈다. 명세 Testing Decisions의 넷째)
- [ ] 픽스처 플러그인을 serve 컨테이너에 넣는 길(시험만 쓰는 compose 덧씌움 등)과 그 파일의 소유는 이 티켓이 정한다. 이름 있는 볼륨의 첫 채움(명세 "플러그인 루트와 트레이스 폴더를 붙이는 것")을 깨지 않는 길이어야 한다(명세 검토 S6)
- [ ] 사례는 명세 Testing Decisions 첫째의 것 모두다. 위젯 미리보기 페이지가 그려지고(토큰 CSS, 페이지 스크립트, 글꼴이 받아진다) 질문하고 답을 받는다. 토큰 끝점에 한도를 넘기면 429다. 관리 API의 경로, serve의 `/health`, 최종 사용자 접두사 밖으로 나가는 우회는 404다. 80은 443으로 넘기고 443의 응답에 HSTS가 있다. 관리 화면은 프록시로 닿지 않고 `127.0.0.1:3000`으로 닿는다. Docker에 물은 발행 포트가 셋뿐이다. 띄운 컨테이너의 사용자가 root가 아니고 `agent-os --version`이 넣은 번호다
- [ ] 명세 검토가 덮이지 않았다고 짚은 스토리를 사례로 더한다(S4). 관리 화면(`127.0.0.1:3000`)에서 플러그인을 끄고 켜면 204다(스토리 17). 뒷단 하나를 다시 만든 뒤 그 경로가 정해진 시간 안에 다시 200이다(스토리 20. 명세는 약 10초 동안 매달리거나 502일 수 있다고 적었으므로 문턱은 15초로 시작하고, 10이 `bridge_recover`를 다시 잰 결과로 맞춘다). 예시 MCP 서버가 네트워크 밖으로 나가지 않고 MCP 연결을 지난다(스토리 23. 어떤 요청으로 볼지는 이 티켓이 정한다. 07은 채널 실행이 모델 호출에서 끝나는 것으로 봤다). 이미지를 `docker run`으로 루프백 예외의 환경 변수 없이 `0.0.0.0`에 띄우면 0이 아닌 코드로 끝난다(스토리 26)
- [ ] 실제 모델 묶음은 환경 변수가 켜지고 API 키가 있을 때만 더한다. 위젯 미리보기 페이지 e2e(`web/apps/portal/playwright.config.ts`)의 방식을 따르고, 켜는 환경 변수의 이름을 이 티켓이 정해 시험 패키지와 `docs/constitution/operations.md`의 LLM 테스트 절에 적는다(명세 검토 S5. 헌법 판 올림은 마무리 항목). ci.yml의 새 잡은 그 묶음을 켜지 않는다. 이 PC에서 그 묶음을 한 번 켜고 돌려 결과를 일지에 적는다
- [ ] 띄운 배치는 시험이 끝나면 컨테이너·볼륨·네트워크를 지운다. 지우는 대상은 그 실행이 만든 것만 고른다(같은 이름의 다른 실행을 지우지 않는다)

### CI와 검증 명령

- [ ] ci.yml에 새 잡을 더한다. main으로 가는 PR과 main 푸시에서 이미지 넷을 지어 시험하고, 그 밖에서는 잡 안에서 곧바로 성공으로 끝난다(`if:`로 건너뛰지 않는다). 잡을 verify의 needs에 넣는다. 제한 시간은 어림으로 시작한다(ci.yml 머리 주석의 규약). 쓰는 액션은 커밋 해시로 고정하고 워크플로 감사(zizmor)를 지난다
- [ ] ci.yml 머리 주석의 "실제 이미지의 compose e2e 는 이 파일에 아직 없다" 문장을 고친다(명세 "병합 절차와 규약 문서")
- [ ] 잡을 verify의 needs에 넣으므로 검사 잡의 수(지금 일곱)를 적은 문장을 모두 고친다. 지금 그 수를 적은 자리는 ci.yml 머리 주석 두 곳, `merge.md` 출시 PR 절, `docs/constitution/tech.md`의 원격·CI 행, `docs/constitution/operations.md`의 자동 검사 문단(잡 이름 목록도 함께)이고, "일곱"과 "잡 일곱"을 하네스와 헌법 문서에서 grep해 이 목록 밖에 남은 자리가 없는지 본다
- [ ] `.claude/skills/next-session/merge.md` 출시 PR 절에서 그 주석을 들어 "main에서만 더 도는 검사는 아직 없다"고 적은 문장을, 출시 PR이 이 잡을 더 지난다는 것으로 고친다. 그 문장은 ci.yml 머리 주석이 llm 잡을 main에서만 더 도는 검사로 적은 뒤로 이미 맞지 않으므로, 고친 문장은 llm 잡과 이 잡을 함께 든다(명세 "병합 절차와 규약 문서"). 스킬을 고치는 일이라 이 티켓은 워크트리에서 하고, 고치기 전에 Skill 도구로 `writing-for-agents`를 부르며(`.claude/rules/agent-docs.md`), 고친 `merge.md`가 새 세션에서 실리는지 본다(작업 규약 3). "main에서만"과 "아직 없다"를 하네스 전체에서 grep해 같은 주장이 남은 자리가 없는지 본다
- [ ] 이 시험의 로컬 명령을 `CLAUDE.md` "검증 명령"의 web 괄호에 다른 e2e처럼 `deploy/`나 이 시험 패키지를 건드렸을 때 친다는 조건과 함께 더하고, 게이트의 수와 CI만 도는 목록을 고친다. 05도 게이트를 더하므로 먼저 병합된 쪽의 수에서 세고, 옛 수를 grep해 살아 있는 문서의 잔존이 0인지 본다
