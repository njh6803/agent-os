# 03: 네 프로세스가 이미지 안의 명시적 설정이 있을 때만 컨테이너 네트워크 쪽 주소에 묶인다

**What to build:** `serve`, 관리 화면, 위젯, 위젯 미리보기 페이지는 지금처럼 루프백 주소만 받는다. 예외는 둘이 함께 있을 때뿐이다. 하나는 이미지를 지을 때 root 소유로 굽는 표지 파일 `/etc/agent-os/image`이고, 다른 하나는 compose가 주는 환경 변수 `AGENT_OS_CONTAINER_NETWORK=1`이다. 그때 듣는 주소로 `0.0.0.0` 하나가 늘고, 관리 화면의 상류 호스트로 compose의 서비스 이름 `serve` 하나가 는다. 개발 PC에서 그 환경 변수를 내보내도 표지 파일이 없으므로 루프백 밖에 묶이지 않고, 이미지를 `docker run`으로 띄운 운영자도 환경 변수를 주지 않으면 묶이지 않는다(스토리 26). 네 곳이 같은 판정을 내는지는 사례 표 하나가 잠근다(스토리 39).

네 프로세스의 예외와 관리 화면 상류의 예외, 그리고 사례 표는 한 변경에 싣는다. 한 곳만 루프백 밖을 받는 상태가 기준 브랜치에 남지 않게 한다(명세 "티켓을 나눌 때 함께 둘 것"). 이미지 넷을 짓는 티켓(07, 08)이 이 티켓을 기다린다.

근거는 명세 "루프백 규칙의 예외", "관리 화면의 상류", Testing Decisions의 둘째, ADR 0056 결정 "루프백 규칙의 예외"와 Consequences "잃는 것"·"다른 ADR"이다. 측정은 `.scratch/release-image/probes/web_images/README.md` 3, 4절이고 이 티켓은 다시 돌리지 않는다(08이 web_images를 고쳐 다시 돈다).

**Blocked by:** 01

**Status:** ready-for-agent

### 판정

- [ ] 판정은 표지 파일의 유무를 인자로 받는 순수 함수로 둔다. 시험은 `/etc`에 파일을 만들지 않고 두 경우를 모두 넣는다. 표지 파일을 실제로 읽는 길은 07·08이 띄운 컨테이너와 09의 시험이 본다
- [ ] 켜지면 받는 주소는 `0.0.0.0` 하나가 늘 뿐이다. 다른 IPv4 주소, `::`, 이름은 여전히 거부한다
- [ ] 환경 변수가 없거나 빈 값이면 꺼진 것이고, `1`이 아닌 다른 값(`true`, `0` 등)은 구성 오류다
- [ ] 진단은 경우마다 다르다. 환경 변수는 있는데 표지 파일이 없으면 "이미지 밖에서는 켜지지 않는다"고 말하고, 표지 파일만 있고 환경 변수가 없는데 `0.0.0.0`을 받으면 지금의 루프백 진단에 그 환경 변수를 알리는 한 줄을 더한다
- [ ] 자리는 지금의 시작 인자와 설정 그대로다. `serve`의 `--host`, 관리 화면과 위젯 시작 래퍼의 `--hostname`, 위젯 미리보기 페이지 설정의 `portal.host`다. 환경 변수 `HOSTNAME`으로는 받지 않는다(명세가 든 까닭: Docker가 그 변수에 컨테이너 ID를 넣는다)
- [ ] 관리 화면의 상류는 예외가 켜지면 호스트로 `127.0.0.1` 밖에 `serve` 하나만 더 받는다. 상류 검사는 빌드 때와 시작 때 모두 돌므로 두 자리가 같은 판정을 쓴다. 이미지를 짓는 단계에 표지 파일과 환경 변수를 두는 것은 08의 일이다

### 사례 표

- [ ] 사례 표 하나를 파이썬과 TS 시험이 함께 읽는다(선례 `tests/fixtures/site_file/`와 그 README). 칸은 표지 파일의 유무 × 환경 변수가 없음·빈 값·`1`·다른 값 × 주소가 `127.0.0.1`·`::1`·`0.0.0.0`·그 밖의 IPv4·`::`·이름이고, 관리 화면 상류는 같은 표에 주소의 호스트 칸(`127.0.0.1`, `serve`, 다른 이름)을 더한다. 사례마다 기대하는 판정과 진단의 종류를 적는다
- [ ] 그 표를 읽는 시험을 네 프로세스의 시작 검사 시험에 더한다. 자리는 `tests/test_main.py`의 루프백 시험, `web/apps/admin/tools/loopback.test.ts`·`start.test.ts`·`start.spawn.test.ts`, `web/apps/widget/tools/start.test.ts`·`start.spawn.test.ts`, `web/apps/portal/server/config.test.ts`다. 실패하는 시험을 먼저 쓴다
- [ ] 한 곳의 판정만 바꾸면 표를 읽는 시험이 빨개지는지 손으로 한 번 본다(변이 하나로 충분하다). 본 명령과 결과를 일지에 적는다

### 마무리

- [ ] 루프백 규칙을 적은 문서(ADR 0010·0011·0015·0019·0024·0050이 ADR 0056을 가리키는 자리, `.claude/rules/`의 해당 규칙)를 grep해 "루프백만 받는다"는 문장이 예외 없이 남아 거짓이 된 곳이 없는지 본다(작업 규약 4). 고칠 곳이 ADR 본문이면 고치지 않고 이력이나 포인터로 둔다
