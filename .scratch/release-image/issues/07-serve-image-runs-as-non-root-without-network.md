# 07: serve 이미지가 넣은 판 번호를 글자 그대로 싣고 root가 아닌 사용자로 네트워크 없이 뜬다

**What to build:** `deploy/images/`에서 serve 이미지를 짓는다. 운영자가 그 이미지를 띄우면 `agent-os --version`, 설치된 패키지의 판, `/openapi.json`의 `info.version`이 지을 때 넣은 번호(`0.1.0-rc.1` 꼴)와 글자까지 같고(스토리 3), 프로세스는 uid 10001의 `agentos` 사용자로 돌며(스토리 25), 인터넷이 없어도 예시 MCP 서버가 뜬다(스토리 23). 플러그인 루트와 트레이스 폴더는 이미지 밖의 볼륨으로 붙일 수 있고, 붙인 볼륨에서 관리 화면의 플러그인 끄고 켜기가 된다(스토리 16, 17의 이미지 몫). compose 파일과 그것을 띄우는 자동 시험은 09가 더한다. 이 티켓은 이미지를 이 PC에서 지어 `docker run`으로 띄운 결과를 일지에 적는다.

근거는 명세 "저장소의 자리", "이미지의 이름과 태그"의 OCI 라벨, "이미지의 구성"의 바탕·사용자와 init·판 번호·serve·예시 MCP 서버·플러그인 루트와 트레이스 폴더를 붙이는 것·상태 확인, "루프백 규칙의 예외"의 표지 파일이다. 측정은 `.scratch/release-image/probes/serve_image/README.md` 1~8번이다. 이 티켓이 그 프로브를 고쳐 다시 돈다(아래 "프로브").

**Blocked by:** 02, 03

**Status:** ready-for-agent

### 이미지

- [ ] 바탕은 `python:3.12-slim-trixie`이고, `node:24-trixie-slim`의 `node` 실행 파일과 전역 npm 폴더를 복사하며, tini를 apt로 깐다. 두 바탕은 digest로 고정한다
- [ ] `@modelcontextprotocol/server-everything` 2.3.0을 전역에 깐다(02가 예시 매니페스트와 개발 PC·CI에 쓴 것과 같은 판)
- [ ] uid·gid 10001의 `agentos` 사용자와 그 passwd 항목과 홈 폴더 `/home/agentos`를 이미지가 만든다. 첫 프로세스는 tini다
- [ ] 판 번호는 빌드 인자로 받는다. 의존성은 잠금 검사와 함께(`uv sync --locked --no-install-project`) 깔고, 빌드 단계 안의 `pyproject.toml` 사본만 그 번호로 바꾼 뒤 프로젝트만 `--frozen`으로 깐다. 그 뒤 설치된 패키지의 판이 넘긴 번호와 다르면 빌드를 실패시킨다. 저장소 파일은 바꾸지 않는다. 번호를 넘기지 않고 지을 때 무엇이 되는지는 이 티켓이 정해 일지에 적는다
- [ ] 03의 판정이 읽는 표지 파일 `/etc/agent-os/image`를 root 소유로 굽는다
- [ ] OCI 라벨 셋(`org.opencontainers.image.version`, `org.opencontainers.image.revision`, `org.opencontainers.image.source`)을 빌드 인자로 채운다
- [ ] 플러그인 루트 `/app/plugins`에 저장소의 플러그인을 담고, 그 폴더와 트레이스 폴더 `/data/traces`를 uid 10001 소유로 둔다. 그 밖은 root 소유로 두어 읽기 전용 루트로 돌 수 있게 한다

### 이 PC에서 띄워 본다

본 명령과 결과를 일지에 적는다. 여기서 쓰는 띄우기 옵션은 09의 compose가 같은 뜻으로 옮긴다.

- [ ] 번호 `0.1.0-rc.1`을 넣어 짓고, `agent-os --version`, 설치된 패키지의 판, 띄운 serve의 `/openapi.json`의 `info.version`이 모두 그 글자인지 본다. 판을 넣는 줄이 아무것도 바꾸지 못했을 때 빌드가 실패하는지도 한 번 본다(빌드 단계의 판 대조가 잡는지)
- [ ] 컨테이너의 사용자가 uid 10001이고 root가 아닌지 본다
- [ ] 네트워크 없음, 읽기 전용 루트, 플러그인 루트와 트레이스 폴더에 이름 있는 볼륨 둘, 홈에 앱 사용자 소유의 tmpfs(`uid=10001,gid=10001,mode=0700`), 루프백 예외의 환경 변수와 `--host 0.0.0.0`으로 띄운다. 플러그인 끄고 켜기가 204이고, `calc` 예시의 채널 실행이 MCP 연결을 지나 모델 호출에서 끝나며(API 키를 주지 않는다), 서버 로그에 쓰기 오류가 없는지 본다
- [ ] 운영자가 npx로 띄우는 MCP 서버(스토리 24)도 같은 조건에 네트워크만 열어 띄우면, 홈의 tmpfs 덕에 MCP 연결을 지나 모델 호출에서 끝나는지 본다. 명세 "이미지의 구성"이 serve_image README 5번 (나)로 잰 길이다. 매니페스트는 지금 예시의 `npx -y` 꼴을 시험용으로 하나 둔다
- [ ] 루프백 예외의 환경 변수 없이 `--host 0.0.0.0`으로 띄우면 03의 진단(지금의 루프백 진단에 그 환경 변수를 알리는 한 줄)과 함께 0이 아닌 코드로 끝나는지 본다(스토리 26. 03이 남긴 "표지 파일을 실제로 읽는 길"이다)
- [ ] `docker stop`이 uvicorn의 정상 종료 기록을 내고 종료 코드 143으로 끝나는지 본다
- [ ] 상태 확인 명령(이미지의 python으로 `http://127.0.0.1:8000/health`를 4초 제한으로 열어 200이면 0, 아니면 1)이 정상인 serve에 0, 듣지 않는 포트에 1인지 보고, compose의 상태 확인과 같은 뜻의 `docker run` 옵션으로 달아 healthy와 unhealthy가 갈리는지 본다
- [ ] 이미지의 풀린 크기와 짓는 데 걸린 시간을 적는다(명세는 382MB, 19~21초로 적었다)
- [ ] Grype로 이미지의 고칠 수 있는 Critical 수를 한 번 보고 적는다. 0이 아니어도 멈추지 않는다(경고는 11의 판 내기가 노트에 싣는다)

### 프로브

- [ ] PR 567 봇 첫 회차에서 보류한 `serve_image/run.py`의 지적을 고친다. 자리는 SILENT 판정(`seen = not exited`, 기준 `c21a4fc3b`에서 848행)이다. 봇이 든 833행은 PR 567의 반영 커밋 전 판의 번호다. SILENT 판정이 EOF로 끝난 회차와 마감이 지난 회차를 가르게 한다(`.claude/rules/probes.md`의 첫 항목. 지적의 원문은 일지 `docs/journal/2026-11-13-1843-release-image-spec.md`의 "봇 첫 회차")
- [ ] 고친 판으로, README "PR 직전 리뷰가 좁힌 측정 조건(2026-11-14)" 절이 든 회차의 항목(2, 4, 5, 6, 7)을 다시 돈다. 명세가 기대는 자리는 "이미지의 구성"의 예시 MCP 서버(4번과 거부한 안의 `/tmp` 갈래), serve의 쓰는 자리(5번), 플러그인 볼륨의 첫 채움과 다음 판의 새 파일(6번), init과 끄기(7번)다. 측정 아님 회차가 있으면 원인을 고쳐 다시 돈다
- [ ] 다시 잰 결과를 README의 결과와 "잰 판"에 적고, 그 절에 다시 돌린 날짜와 결과를 더한다. 결과가 명세의 문장과 다르면 구현을 멈추고 명세와 ADR 0056 이력으로 돌아간다(명세 Further Notes "다시 잴 때")
