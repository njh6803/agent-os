# 01: 저장소의 판 번호가 0.0.0이 된다

**What to build:** 개발 PC에서 `uv run agent-os --version`이 `0.0.0`을 찍고, 저장소의 `openapi.json`과 띄운 serve의 `/openapi.json`의 `info.version`도 `0.0.0`이다. 판의 번호는 저장소 파일이 아니라 git 태그가 정하고 이미지를 지을 때만 넣는다(ADR 0056 결정 "저장소의 번호", 이력 2026-11-13 "이미지 안의 판 번호는 태그와 글자까지 같다"). 저장소의 `0.1.0`이 남아 있으면 첫 출시 후보(`0.1.0-rc.1`)를 내기 전부터 개발 PC가 정식 판 번호를 보이게 된다.

이 기능의 계약 티켓이다. `openapi.json`에 닿으므로 다른 모든 티켓을 막는다(작업 규약 2, 명세 "티켓을 나눌 때 함께 둘 것"의 첫 항목).

근거는 `.scratch/release-image/spec.md`의 "티켓을 나눌 때 함께 둘 것"과 "이미지의 구성"의 판 번호, ADR 0056 결정 "저장소의 번호"다.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] `pyproject.toml`의 `version`을 `0.0.0`으로 바꾸고, 같은 변경에서 `openapi.json`의 판 칸과 `uv.lock`의 자기 패키지 항목을 함께 바꾼다. `openapi.json`은 저장소가 그 파일을 만들고 대조하는 기존 길로 다시 만들고 손으로 고치지 않는다. 잠금 파일은 잠금 검사(`uv sync --locked` 꼴)를 지난다
- [x] `web/packages/api-client`의 생성물이 판 칸을 담으면 같은 변경에서 다시 만든다(`pnpm -C web verify`가 대조한다)
- [x] 저장소의 판을 단언하는 시험이 있으면 그것만 `0.0.0`으로 고친다. 플러그인 매니페스트의 `version`과 그것을 쓰는 시험 글은 저장소의 판이 아니므로 바꾸지 않는다(`tests/` 아래 파일 여럿이 `0.1.0`을 든다. 이 티켓을 쓸 때 파일 이름만 grep했고, 그것이 플러그인 매니페스트의 판인지 저장소의 판인지는 읽지 않았다)
- [x] 실패하는 시험을 먼저 쓴다. `agent-os --version`의 출력이 설치된 패키지의 판과 같다는 것과, 띄운 serve의 `/openapi.json`의 `info.version`이 그 판과 같다는 것을 판 번호를 글자로 박지 않고 단언한다(07이 이미지에 넣은 번호로 같은 성질을 본다)
- [x] 바뀐 결정을 가리키는 문서에 옛 번호(`0.1.0`이 저장소의 판이라는 문장)가 남지 않았는지 grep으로 본다(작업 규약 4)
- [x] 검증 명령이 모두 초록이다
