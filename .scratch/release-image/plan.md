# release-image: 판마다 서버와 관리 화면과 위젯과 질문 페이지의 컨테이너 이미지를 짓고 올리며 단독 배포 안내도 낸다.
**슬라이스:** 8
**Blocked by:** pilot-portal

판마다 컨테이너 이미지를 짓고 올린다. 대상은 `serve`, 관리 화면, 위젯, 질문 페이지(pilot-portal)다. 질문 페이지 이미지는 빌드 산출이 아니라 소스와 `node_modules`를 그대로 담는다. node가 `.ts`를 빌드 없이 바로 돌린다(ADR 0050). 질문 페이지는 토큰 CSS와 페이지 스크립트를 시작 때 짓고 글꼴을 디자인 시스템 패키지의 경로에서 바로 내므로, 이미지의 `node_modules`에는 Tailwind CLI와 글꼴 패키지가 그대로 들어야 한다(ADR 0050 이력 2026-11-09 "띄우기의 어림을 잰 값으로 바꾸고 토큰 CSS와 페이지 스크립트는 시작 때 짓는다"). 질문 페이지(`/portal/`)는 같은 출처의 위젯 번들(`/widget/element.js`)을 싣고(ADR 0050 결정 "페이지"), 위젯 번들과 최종 사용자 경로는 한 출처에 선다(ADR 0024). 그래서 셋은 한 공개 출처 아래에 서야 하고, 그것을 프록시가 어떻게 갖추는지는 이 행의 설계 인터뷰가 정한다(pilot-portal 명세 Out of Scope. PR 500의 코멘트가 넘겼다). 질문 페이지의 공개 출처는 믿을 수 없는 하위 도메인이 없는 도메인에 둔다(ADR 0050 Consequences "위젯은 바뀌지 않는다"). 여기서 도메인은 질문 페이지 호스트에 `Domain` 쿠키를 심을 수 있는 등록 도메인(공개 접미사 바로 아래. `portal.example.com`이면 `example.com`)이고, 그 아래 모든 호스트(형제 도메인 포함)를 같은 운영자가 믿을 수 있게 쥐어야 한다. 익명 식별자 쿠키는 `Domain` 없이 질문 페이지 호스트에 묶이지만, 등록 도메인 아래 어느 호스트든 `Domain=example.com`으로 심은 쿠키는 질문 페이지에도 실려 형제 도메인이 심는 쿠키까지 막지는 못한다. 질문 페이지 호스트의 아래에만 믿을 수 없는 하위 도메인이 없는 것으로는 모자란다. 그 도메인을 어떻게 고르고 갖추는지도 이 행의 설계 인터뷰가 정한다(pilot-portal 명세 Out of Scope). 익명 식별자 쿠키가 `__Secure-` 접두를 쓰지 않는 근거는 질문 페이지의 공개 출처 앞 프록시가 443을 TLS로만 듣고 HSTS를 내는 것이다(pilot-portal 명세 "익명 식별자 쿠키", ADR 0024의 프록시 규칙). 저장소의 어떤 시험도 HSTS를 보지 않으므로(ADR 0024), 이 행이 질문 페이지 앞의 프록시를 갖출 때 HSTS를 함께 둔다. agent-os만 띄우는 단독 compose와 그 배포 안내도 이 행이 낸다(배포와 운영은 데이터를 가진 저장소가 맡는다, ADR 0048). ADR 0043이 main으로 가는 PR의 실제 이미지 compose e2e를 위해 새로 짓기로 한 Dockerfile과 compose(잡 이름과 모양은 harness 티켓이 정한다)를 이 행이 함께 쓰고, 그 harness 티켓이 아직 닫히지 않았으면 이 행의 첫 티켓이 짓는다. 컨테이너의 첫 프로세스에는 init을 두고(README의 "컨테이너의 첫 프로세스로 띄우면 init을 둔다" 항목), 컨테이너는 root가 아닌 사용자로 돈다. 이미지를 올릴 레지스트리, 태그 규칙(판 태그와 커밋), 폐쇄망 배포를 위해 이미지를 파일로 내보내는 방법(`docker save`), 이미지마다 낼 취약점 점검 결과(SBOM과 CVE 스캔)도 설계 인터뷰가 정한다. 설계 인터뷰가 먼저 볼 것: `serve`와 두 Next 앱과 질문 페이지는 루프백에만 서는데(ADR 0011, ADR 0019, ADR 0050. 루프백 목록은 네 곳이 따로 든다, ADR 0047과 그 포인터), compose에서는 리버스 프록시가 다른 컨테이너에 있다. 규칙을 지키면서 네 프로세스에 프록시를 잇는 방법(같은 네트워크 이름공간, 같은 컨테이너의 프록시 등)을 이 행의 설계 인터뷰가 한꺼번에 고르고, 고르지 못하면 deploy-package가 막힌다(pilot-portal 설계 인터뷰 라운드 2가 넘겼다, 일지 2026-11-09-1410). 질문 페이지의 토큰 끝점은 서명 전에 프록시에서 요청 빈도를 제한해야 하고, 배포 환경의 프록시가 그것을 어떻게 갖출지도 이 설계 인터뷰가 정한다(질문 페이지는 직접 제한하지 않는다, ADR 0050 결정 "빈도 제한"). 배포 환경에 따라 컨테이너 런타임의 사용, 운영체제(RHEL 계열 등), 바깥 이미지의 반입이 제한될 수 있다. 수락: main에 판 태그를 달면 네 이미지가 그 태그로 올라가고, 깨끗한 리눅스 VM에서 그 이미지만 받아 단독 compose로 띄우면 `/health`가 정상이며 위젯과 질문 페이지(`/portal/`. 이미지가 시작 때 지은 토큰 CSS와 페이지 스크립트, 패키지의 글꼴이 받아진다)에서 calc 예시에 질문할 수 있고, 질문 페이지의 토큰 끝점에 프록시의 한도를 넘겨 요청하면 거부된다
