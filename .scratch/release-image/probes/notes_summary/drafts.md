# 후보 프롬프트로 받은 초안 넷

`prompt.md`의 프롬프트에 기능 이름과 티켓 PR 제목 목록을 채워 서브에이전트(모델 Sonnet, 새 컨텍스트)에 하나씩 주고 받은 답을 글자 그대로 옮겼다. 2026-11-13에 손으로 한 번씩 돌렸다. 실제 워크플로(`anthropics/claude-code-action`)로 돌린 것이 아니다. 제목 목록은 `git log --format=%s origin/dev -- .scratch/<slug>/issues`의 출력에서 `docs:`와 `chore:` 줄을 뺀 것이다(기준 커밋 `1117a170f`).

## pilot-portal

제목 아홉은 모두 `feat:`이고 느낌표가 없다.

> 이 판부터 위젯을 붙일 사이트나 토큰을 서명할 서버가 없어도 쓸 수 있는 위젯 미리보기 페이지가 새로 생긴다. 운영자가 설정 파일 하나에 사이트 목록을 적고 `serve`의 사이트 파일과 함께 띄우면, 처음 온 사람은 로그인 없이 고지를 한 번 확인한 뒤 고른 사이트의 위젯으로 calc 같은 예시 에이전트에 질문해 볼 수 있다. 사이트가 하나면 셀렉트 박스 없이, 여럿이면 셀렉트 박스로 사이트를 바꿔 가며 볼 수 있다. 사이트를 바꾸면 새 대화가 시작된다는 안내가 뜬다. 질문한 브라우저는 `anon-`으로 시작하는 익명 이름으로 트레이스와 관리 화면에 남아 로그인한 사람의 실행과 구별된다. 로그인이 필요한 사이트는 질문 대신 "아직 제공하지 않는다"는 알림이 뜨고, 설정 파일과 사이트 파일이 어긋나면 페이지가 뜨지 않고 시작 때 어느 칸이 틀렸는지 알려 준다. 비용은 사이트 파일의 요청 상한과 `serve`의 동시 실행 상한이 묶는다.
>
> 변경 목록에 느낌표가 붙은 제목이 없고 운영자가 반드시 고쳐야 하는 변경도 보이지 않아, 이 판을 올릴 때 손댈 것은 없다.

## mcp-http

제목 넷은 `feat:` 셋과 `test:` 하나이고 느낌표가 없다.

> 원격 MCP 서버를 주소로 붙일 수 있게 됐다. 플러그인의 `[server]` 칸에 `transport = "http"`와 `url`을 적으면, 실행마다 서버 프로세스를 새로 띄우는 대신 이미 떠 있는 서버에 접속한다. 임베딩 모델과 색인을 올리는 문서 검색 서버를 한 번만 띄워 두면 질문마다 시작 비용을 치르지 않는다. 토큰이 필요하면 `[server.headers]`에 헤더 이름과 환경 변수 이름만 적는다. 값은 접속할 때만 환경에서 읽고 어디에도 기록하지 않는다. 서버가 꺼졌거나 토큰이 틀리면 실행이 `tool_connection` 원인으로 끝나고, 실패 문구에 서버 이름과 주소가 보인다. 토큰이 틀린 경우에는 문구 끝에 `(HTTP 401 Unauthorized)` 같은 상태가 붙어 꺼진 서버와 구분된다. 실행 기한이 지나거나 `serve`를 끄느라 취소된 실행도 2초 안에 서버 쪽 세션 종료 요청을 보내므로, 서버가 유휴 만료까지 세션을 쥐고 있지 않는다. `transport`를 적지 않은 기존 매니페스트는 지금처럼 stdio로 읽혀 그대로 돈다.

## approval-rules

제목 여섯은 모두 `feat:`이고 느낌표가 없다.

> 운영자가 플러그인 루트에 `rules.toml`을 두면 도구 호출마다 막을지(deny), 승인을 요구할지(ask), 묻지 않고 돌릴지(allow)를 에이전트 매니페스트를 고치지 않고 정할 수 있습니다. 파일에는 모든 에이전트에 걸리는 공통 표 `[common]`과 에이전트별 표 `[agents.<에이전트 이름>]`을 두고, 규칙 줄은 `add`, `everything:*`, `everything:add` 꼴이며 도구 이름에는 `*`를 쓸 수 있습니다. 막은 도구는 모델의 도구 목록에서 빠지고 부르면 거부로 기록되며, 실행은 죽지 않고 모델이 거부를 알고 이어 갑니다. 저자가 매니페스트에 적은 승인 요구는 운영자의 allow로 풀 수 없습니다. 파일은 실행이나 재개를 준비할 때마다 다시 읽으니 서버를 다시 띄우지 않아도 고친 내용이 다음 실행부터 적용됩니다. 어느 규칙이 호출을 정했는지는 트레이스의 도구 호출과 멈춤 기록에 남고, 멈춘 기록에는 서버 이름도 함께 남습니다. 재개 때 도구가 다른 서버에서 오거나 그사이 deny로 바뀌었으면 승인이 있어도 불리지 않습니다. 파일이 깨졌으면 실행이 시작되지 않고 운영자 쪽 오류에 경로와 오류가 적힙니다. 한 에이전트가 고른 서버 둘이 같은 이름의 도구를 내거나 에이전트 표에 적은 도구나 서버가 연결에 없으면, 연결 직후 실행이 실패로 끝나며 원인을 알려 줍니다. 마스킹할 인자가 있는 도구를 묻게 둔 경우에는 실행 전에 오류를 받습니다.
>
> 경고(개발자에게): 제목 접두에 느낌표가 없어 "올릴 때 할 일" 목록을 쓰지 않았지만, 운영자가 손댈 것이 있어 보입니다. 재료에 따르면 이제 규칙 파일이 없거나 allow에 적히지 않은 도구 호출은 기본이 "묻는다"여서 승인 대기로 멈춥니다. 저장소가 예시 `plugins/rules.toml`에 calc의 allow 규칙을 함께 둔 것도 그 때문입니다. 판을 올리기 전에는 승인 없이 돌던 도구가 멈출 수 있으니, 운영자는 묻지 않고 돌릴 도구에 allow 규칙을 써야 합니다. 같은 이름의 도구를 내는 서버 둘을 한 에이전트에 고른 배치도 이제 연결 직후 실패합니다. 이 변경이 실제로 하위 호환을 깨는지 확인하고, 깬다면 접두에 느낌표를 붙이고 할 일 목록을 채워 주세요.

## admin-style (느낌표를 지어 넣은 갈래)

저장소의 이력에는 접두 뒤에 느낌표가 붙은 커밋이 없다(`git log --format='%h %s' origin/dev`의 출력을 PowerShell의 `Select-String`으로 걸러 손으로 봤고 0줄이었다). 그래서 "올릴 때 할 일" 갈래는 실제 제목 가운데 04번 하나의 접두를 `feat!:`으로 바꿔 넣어 봤다. 실제 제목은 `feat:`이다.

> 이번 판부터 관리 화면이 새 디자인으로 바뀌어 휴대폰 폭에서도 가로로 밀지 않고 읽을 수 있고, 설정 화면에서 테마 넷 가운데 하나를 골라 바로 바꿀 수 있습니다. 데스크톱에서는 왼쪽 옆 탐색으로, 휴대폰에서는 위 막대로 플러그인·실행·설정 사이를 옮깁니다. 플러그인 목록에서는 이름을 눌러 바로 켜고 끄고 매니페스트는 줄 끝의 "매니페스트" 링크로 봅니다. 실행 목록은 넓은 화면에서 표, 좁은 화면에서 카드로 서고 시각을 이 브라우저의 시간대로 적습니다. 실행 하나 화면은 이벤트를 카드로 보여 주고, 결정이 필요한 실행에는 "거부"와 "승인" 버튼이 서며 버튼 글자가 "허가"에서 "승인"으로 바뀝니다. 채널 토큰이 없으면 결정 자리에 설정으로 가는 안내 한 줄이 섭니다.
>
> 올릴 때 할 일:
> - 채널 토큰 넣기와 "토큰 지우기"가 모든 화면의 머리에서 설정 화면으로 옮겨 갑니다. 이 탭에서 멈춘 실행을 승인하거나 거부하려면 설정 화면에서 채널 토큰을 넣어야 하고, 자리를 뜰 때 토큰을 지우는 것도 설정 화면에서 합니다. 머리에서 이 입력을 찾는 안내나 절차가 있으면 새 위치에 맞게 고칩니다.
> - 화면에서 테마를 고르는 값은 이 브라우저에만 남고 서버 구성은 바뀌지 않으니, 서버 쪽에서 따로 손댈 것은 없습니다.
>
> 경고(개발자에게): `feat!:` 접두가 붙은 04번 제목은 채널 토큰 입력의 위치가 옮겨 가는 화면 변경만 말합니다. 재료에서 운영자가 설정 파일이나 환경 변수를 고쳐야 하는 변경은 찾지 못해, 위 목록은 위치 이동 안내로만 썼습니다. 접두가 옳은지 확인해 주세요.
