# 02: 꺼진 것을 부른 새 실행과 재개가 실행 전에 거부된다

**What to build:** 운영자가 끈 것이 실제로 멈춘다. 요청한 에이전트가 꺼졌거나 그 에이전트가 쓰는 mcp가 꺼졌으면 `POST /runs`가 409 `conflict`다. 메시지는 꺼진 플러그인의 종류와 이름을 들고, 트레이스는 생기지 않는다. 멈춘 실행의 에이전트를 끄면 그 실행에 보낸 결정이 409다. 트레이스는 일시정지 그대로 남고, 다시 켜면 같은 결정을 보내 이어 갈 수 있다. CLI의 `run`과 `resume`은 무엇이 꺼졌는지 적은 진단과 종료 코드 1로 끝난다. 꺼진 에이전트의 코드는 import되지 않고, 거부된 실행에서 MCP 서버가 뜨지 않는다. 도는 실행은 끝까지 간다.

01이 남긴 틈(스위치는 도는데 런타임이 거부하지 않는 기간)을 이 티켓이 닫는다. 이 티켓으로 기능이 닫힌다. 새 실행과 재개를 한 티켓에 두는 이유가 있다. 둘은 core의 준비 단계를 함께 쓴다. 가르면 재개만 허용되는 기간이 main에 생기는데, 그것은 ADR 0017이 거부한 드레인이다.

근거는 `.scratch/plugin-toggle/spec.md`의 "core — 준비 단계의 판정", "옛 기준 문구"의 core 판정 티켓 몫, "채널", "CLI", "Testing Decisions" 절과 그 2026-09-27 명세 검토 주석이다. ADR 0017의 "런타임은 준비 단계에서 꺼짐을 본다"와 ADR 0014의 2026-09-26 이력도 근거다.

**Blocked by:** 01

**Status:** ready-for-agent

### core — `run()`과 `resume()`

- [ ] **꺼짐은 깨짐을 다 본 뒤에 보되, 진입점 import보다는 앞에서 본다.** 새 실행의 순서는 이렇다
  1. 요청한 에이전트의 매니페스트(없으면 `Absent`, 깨졌으면 `PluginError`)
  2. 에이전트가 쓰는 mcp들(없거나 깨졌으면 `PluginError`)
  3. 마스킹과 승인의 충돌(`PluginError`)
  4. 운영자 파일(깨졌으면 `PluginError`)
  5. 에이전트의 꺼짐(`Disabled`)
  6. mcp의 꺼짐(`Disabled`). 매니페스트에 적힌 순서로 본다
  7. 진입점 import(`PluginError`)
  8. 실행 식별자
- [ ] **순서를 테스트가 고정한다**
  - **부재가 먼저다.** 꺼진 집합에 든 이름이라도 에이전트가 없으면 `Absent`다. 운영자 파일이 깨졌어도 없는 에이전트는 `Absent`다
  - **깨짐이 먼저다.** 에이전트가 꺼졌는데 그것이 쓰는 mcp가 없거나 깨졌으면 하위 타입이 아닌 `PluginError`다. 마스킹과 승인이 충돌해도 같다
  - 운영자 파일이 깨졌으면 하위 타입이 아닌 `PluginError`다
- [ ] **`Disabled`의 메시지는 꺼진 플러그인의 종류와 이름을 든다.** 켜진 에이전트가 꺼진 mcp 때문에 거부되면 그 mcp의 이름이다. 꺼진 mcp가 둘이면 매니페스트에 먼저 적힌 것이다
- [ ] **꺼진 에이전트는 import하지 않는다.** 진입점 로드가 한 번도 불리지 않는다. 진입점이 깨진 꺼진 에이전트는 `Disabled`다. import 실패를 판정하려면 플러그인 코드를 실행해야 하기 때문이고, 이것이 "깨짐이 먼저"의 유일한 예외다
- [ ] **거부된 실행에서는 도구 포트가 연결되지 않는다**(스토리 38). 새 실행과 재개 둘 다 본다. 가짜 도구 포트는 이미 연결을 기록하므로 그것으로 본다. 거부된 새 실행은 실행 식별자가 만들어지지 않고 트레이스가 없다. 거부된 재개의 트레이스는 아래 항목대로 바이트 그대로다
- [ ] **꺼진 집합은 준비 한 번에 한 번 읽는다.** 에이전트와 mcp들을 같은 순간의 상태로 판정한다. 캐시가 없어서 같은 포트에서 켜고 나면 다음 준비부터 효력이 난다. core 가짜 포트가 진입점 로드와 꺼진 집합 읽기를 센다. 지금은 카운터가 없어서 이 티켓이 새로 넓힌다
- [ ] **재개의 순서.** 트레이스 판정은 지금 순서 그대로다(없으면 `Absent`, 형식 1이면 `NotResumable`, 손상이면 `PluginError`, 일시정지가 아니면 `NotResumable`). 다음이 트레이스가 가리키는 에이전트의 매니페스트이고, 없으면 `PluginError`다. 그 뒤는 새 실행과 같다. 결정 이벤트 쓰기가 맨 끝이다
  - 일시정지가 아닌 실행은 에이전트가 꺼졌어도 `NotResumable`이다
  - 트레이스가 가리키는 에이전트가 없으면 꺼진 집합에 들어 있어도 `PluginError`다
- [ ] **거부된 재개는 트레이스에 아무것도 쓰지 않는다.** 에이전트가 꺼졌을 때, 그 에이전트가 쓰는 mcp가 꺼졌을 때, 운영자 파일이 깨졌을 때 모두 `Disabled`나 `PluginError`다. 트레이스는 바이트 그대로이고 마지막 이벤트가 `run_paused`다. 같은 포트에서 다시 켜면 같은 실행의 재개가 결정 이벤트로 시작한다
- [ ] **재개 첫 걸음에 `await`가 없다는 불변식이 그대로다.** 꺼진 집합 읽기가 첫 걸음 안에 들어와도 동기라서 동시 재개의 기존 테스트가 그대로 초록이다(ADR 0014)
- [ ] **도는 실행은 건드리지 않는다.** 판정은 준비 단계에만 있다. `run()`과 `resume()`의 시그니처와 이벤트는 바뀌지 않는다. 바뀌는 것은 실행 전에 던지는 예외의 종류가 하나 느는 것뿐이다
- [ ] 매개변수화된 "구성이나 기록이 깨진 것은 부재도 재개 불가도 아닌 `PluginError`다" 테스트에 운영자 파일의 손상이 한 경우로 든다

### HTTP — 가짜 포트와 주 이음매

- [ ] **꺼진 에이전트의 실행은 409다.** PUT으로 끈 에이전트의 `POST /runs`가 409 봉투를 받는다. `code`는 `conflict`이고 메시지에 종류와 이름이 있으며, 트레이스가 생기지 않는다. 그 에이전트가 쓰는 mcp를 끈 경우도 409이고, 메시지에 그 mcp의 이름이 있다
- [ ] **꺼진 에이전트의 재개도 409다.** 멈춘 실행의 에이전트를 끄면 `POST /runs/{run_id}/approval`이 409다. 트레이스는 바뀌지 않고 마지막 이벤트가 그대로 `run_paused`다. PUT으로 다시 켜면 같은 결정이 결정 이벤트로 시작하는 스트림을 준다
- [ ] **채널은 켜짐을 먼저 확인하지 않는다.** core가 던진 타입을 표가 옮긴다. 채널이 포트로 먼저 보면 판정 순서가 core 밖으로 샌다. `create_app`의 시그니처는 바뀌지 않는다

### 실제 어댑터 한 흐름 — `serve`가 세운 앱

- [ ] **실제 어댑터로 한 흐름을 민다.** `main(["serve", ...])`로 세운 앱을 받아 수명을 테스트 본문에서 연다. 이 흐름을 한 번만 재는 이유는 둘이다. 조립이 같은 어댑터를 두 라우터에 넘긴다는 것과 캐시가 없다는 것은 가짜로 증명할 수 없다. 프리어 아트는 조립 테스트의 "`serve`가 세운 앱으로 실행하면 주체가 OS 사용자이고 트레이스가 그 디렉터리에 남는다"다. 흐름은 넷이다
  1. 관리 토큰으로 PUT해 에이전트를 끄면 플러그인 루트에 `disabled.toml`이 생기고, `tomllib`으로 읽은 값에 그 이름이 있다
  2. 목록이 그 행을 꺼진 것으로 보인다
  3. 채널 토큰으로 `POST /runs`를 보내면 409이고 트레이스 디렉터리에 파일이 없다
  4. 파일을 손으로 고쳐 그 이름을 지우면, 서버를 다시 세우지 않아도 같은 앱이 다음 `POST /runs`를 `run_finished`까지 흘린다

### CLI

- [ ] **CLI 코드는 바뀌지 않는다.** `run`과 `resume`은 기반 타입을 잡으므로 `Disabled`도 진단과 종료 코드 1의 길로 간다. 손으로 쓴 운영자 파일로 셋을 본다
  - 에이전트를 끈 파일이 있으면 `agent-os run`이 종류와 이름을 적은 진단과 종료 코드 1로 끝나고 트레이스가 없다
  - 멈춘 실행의 에이전트를 손으로 끄면 `agent-os resume`이 같은 진단과 종료 코드 1로 끝나고 트레이스가 바이트 그대로다
  - 운영자 파일이 깨졌으면 진단이 파일 경로를 적는다

### 문서와 회귀

- [ ] **`run()`·`resume()`이 무엇을 던지는지 말하는 문장을 이 티켓이 고친다.** core가 `Disabled`를 실제로 던지는 티켓이라서다
  - core 실행 모듈의 모듈 독스트링: 하위 타입 열거와 실행 전 실패 열거. 지금은 꺼짐과 운영자 파일의 손상이 없다
  - `.claude/rules/core.md` 실패 정책: 하위 타입 열거와 판정 순서
  - 재개 라우트의 409를 재개 불가 둘로만 설명한 주석
  - `.claude/rules/channel.md`의 "부재와 재개 불가는 … 표가 옮긴다"와 채널 재개 경로 독스트링의 같은 문장(채널이 먼저 확인하지 않는 것에 꺼짐이 든다)
  - CLI `resume`의 독스트링 "(없음, 형식 1, 일시정지 아님, 손상)"
  - core 테스트의 "실행 전 실패의 두 갈래" 절 주석
- [ ] **하위 타입을 둘로 닫아 적은 문장이 남지 않았는지 grep한다.** 셋째 grep은 `재개 불가|NotResumable|재개할 수 없는`이다. 제외는 01의 잔존 grep과 같다(일지, ADR 본문과 이력, `.scratch/`의 명세·티켓·`retro-queue.md`, `.claude/worktrees/`). 걸린 것마다 닫힌 열거인지 본다
- [ ] **기존 `-m llm`을 한 번 돌린다**(`uv run --env-file .env pytest -m llm`). 새 LLM 테스트는 두지 않는다. 켜짐 판정은 모델 호출보다, 실행 식별자보다도 앞에서 끝나기 때문이다. 넷 가운데 조립 테스트의 셋이 실제 파일시스템 어댑터를 지난다. 그래서 운영자 파일이 없는 경로에서 준비 단계의 새 읽기가 켜진 실행을 바꾸지 않았다는 것을 실제 모델과 함께 본다. 결과는 이 티켓의 일지에 남긴다
- [ ] 기능이 닫히면 `.scratch/plan.md`의 plugin-toggle 행과 프론티어 문장을 고친다. web-admin이 이 기능에 막힌 간선이 풀린다
- [ ] **원칙 III를 지킨다.** 타입 우회가 필요해 보이면 고치지 말고 멈춰 보고한다
- [ ] 검사 넷이 초록이다
