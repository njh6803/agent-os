# 01: 계약 — 운영자가 관리 API로 플러그인을 켜고 끄고, 목록이 켜짐을 보인다

**What to build:** 운영자가 서버의 셸에 들어가지 않고 HTTP 요청 하나로 플러그인을 끄고 다시 켠다. `PUT /plugins/{kind}/{name}/enabled`에 `{"enabled": false}`를 보내면 204이고, 플러그인 루트에 `disabled.toml`이 생긴다. `GET /plugins`와 `GET /plugins/{kind}/{name}`의 행은 겉에 `kind`, `name`, `enabled`를 든다. 읽히는 행은 `manifest`에 매니페스트를 통째로 담고, 표지 행은 `reason`을 담는다. 파일을 손으로 고쳐도 다음 목록에 그대로 보인다. 매니페스트와 `sdk`는 바뀌지 않는다.

이 기능의 계약 티켓이고 02를 막는다. 계약은 `openapi.json`의 감싼 행·PUT 경로·`POST /runs`의 409, `PluginSource`의 메서드 둘, core의 `Disabled`와 표 한 줄, 하위 타입 기준의 옛 문구다. 이 목록이 끌고 오는 것이 둘이고 둘 다 도구가 강제한다. 하나는 **파일시스템 어댑터의 구현**이다. `main.py`가 어댑터를 포트 타입 자리에 넘기므로 Protocol만 넓히면 pyright strict가 깨진다(admin-api 티켓 01과 같은 구조). 다른 하나는 **관리 라우트의 구현**이다. 계약 파일은 앱에서 생성되므로 PUT 경로를 계약에 싣는 순간 라우트가 있어야 하고, 감싼 행은 포트의 꺼진 집합을 읽어야 채워진다. 리뷰의 질문은 "동작하나"가 아니라 "이 시그니처와 이름과 행의 모양으로 오래 살 수 있나"다. ADR이 승인한 것은 모양(겉 셋에 `manifest`나 `reason`, 메서드 둘)이고 이름은 이 PR에서 사용자가 본다.

**병합 뒤에 틈이 있다(사용자가 받아들였다).** 스위치와 목록의 `enabled`는 동작하지만, 런타임은 아직 꺼진 것을 거부하지 않는다. 계약 파일의 `POST /runs` 409도 그동안은 아직 나지 않는 응답을 적는다. 02가 바로 잇는다.

근거는 `.scratch/plugin-toggle/spec.md`의 "계약 티켓", "운영자 파일", "포트", "옛 기준 문구", "에러의 번역", "관리 API", "`openapi.json`", "문서 갱신" 절과 그 2026-09-27 명세 검토 주석이다. ADR 0017과 그 2026-09-27 이력 둘도 근거다. ADR 0010·0012·0014의 2026-09-26 이력이 앞선 결정이다.

**Blocked by:** None (can start immediately)

**Status:** done

### 운영자 파일 — 파일시스템 어댑터

- [x] **파일이 없으면 꺼진 것이 없다.** 모양은 `schema_version = "1"`(필수)과 종류 키 넷(`agent`, `mcp`, `skill`, `model`, `PluginKind`의 값과 같다)의 이름 배열이다. 빠진 키는 빈 목록이고, 한 배열 안의 중복은 하나로 합친다. 형식은 어댑터가 소유하고, `sdk`와 매니페스트는 바뀌지 않는다
- [x] **손상은 `PluginError`이고 메시지에 파일 경로와 이유가 있다.** 손상으로 보는 것은 아래 전부다. 매니페스트에서 여는 것부터 검증까지를 `PluginError`로 바꾸는 선례와 같다
  - 문법 오류
  - 형식 버전이 없음(빈 파일 포함)
  - 모르는 형식 버전
  - 모르는 키
  - `sdk`의 패턴을 어긴 이름
  - 값의 타입 오류(배열이 아닌 값, 문자열이 아닌 원소)
  - UTF-8로 읽지 못함
  - 열지 못함(`PermissionError`는 아래 재시도가 다한 뒤에)
- [x] **고아 항목은 손상이 아니다.** 디렉터리가 없는 이름은 읽을 때 꺼진 집합에 그대로 들고, 쓸 때도 지우지 않는다
- [x] **쓰기는 통째로 교체한다.** 종류 넷을 모두, 이름순으로, 중복 없이 같은 디렉터리의 임시 파일에 쓴 뒤 이름을 바꾼다. 손으로 쓴 비정규 파일(키 누락, 중복, 뒤섞인 순서, 주석)에 무언가를 바꾸는 쓰기를 하면 정규형이 되고 주석이 사라진다. 바뀌는 것이 없는 쓰기는 아래 항목대로 파일을 건드리지 않는다. 쓰기 코드는 직접 짜고 쓰기 의존성을 들이지 않는다
- [x] **왕복을 `tomllib`이 판정한다.** 여러 집합을 쓰고 `tomllib`으로 읽은 값이 그 집합과 같아야 한다. 집합은 빈 것, 종류마다 하나, 패턴의 경계 문자를 쓴 이름이다
- [x] **바뀌는 것이 없으면 쓰지 않는다.** 이미 꺼진 것을 끄거나 켜진 것을 켜면 파일을 건드리지 않고 성공한다. 주석이 든 파일은 바이트 그대로다. 파일이 없을 때 켜면 파일이 생기지 않는다. 마지막 꺼진 것을 켜면 파일은 남고 네 배열이 빈다
- [x] **부재 판정이 먼저다**(ADR 0017의 2026-09-27 둘째 이력)
  - `plugin.toml`이 없는 이름에 쓰면 부재를 값으로 돌려준다. 파일은 바이트 그대로이고, 없었으면 여전히 없다
  - 운영자 파일이 깨졌어도 없는 이름은 부재다
  - 매니페스트가 깨진 플러그인에는 쓸 수 있다. 판정 대상은 파일이 있느냐이지 읽히느냐가 아니다
- [x] **깨진 파일은 덮어쓰지 않는다.** 쓰기도 먼저 읽는다. 읽기가 손상이면 `PluginError`이고 파일이 바이트 그대로다. 바뀌는 것이 없는 쓰기도 같다. 손상 판정이 "바뀌는 것이 없다"는 판단보다 먼저다
- [x] **쓰기가 실패하면 `PluginError`이고 옛 파일은 그대로다.** 성공이든 실패든 플러그인 루트에 임시 파일이 남지 않는다
- [x] **윈도우의 경합은 짧게 동기로 다시 시도해서 넘긴다**(ADR 0017의 2026-09-27 첫 이력)
  - 파일을 열거나 교체하다 `PermissionError`를 받으면 수십 밀리초 상한 안에서 다시 시도한다. 상한을 넘기면 위의 규칙 그대로다
  - 다시 시도하는 것은 `PermissionError` 하나다
  - 재시도는 `await`가 아니다. `await`가 끼면 루프가 쓰기를 줄세운다는 전제와 재개 첫 걸음의 불변식이 깨진다
  - 주입으로 두 경우를 읽기와 쓰기 양쪽에서 고정한다. 몇 번 실패한 뒤 성공하는 경우와 끝까지 실패하는 경우다. 끝까지 실패하면 옛 파일이 바이트 그대로이고 임시 파일이 없다
  - 윈도우에서는 실제 핸들로 교체와 읽기가 재시도 안에서 성공하는지 잰다. 다른 스레드가 연 경우와 다른 프로세스가 연 경우 둘 다다. 윈도우가 아닌 러너에서는 그 테스트가 무엇을 재는지 말한다. skip은 초록이 아니다(원칙 II)
  - 상한의 숫자는 실제 어댑터로 다시 재서 정하고, 결과를 그 이력에 한 줄 더한다. 명세 검토의 프로브는 1·2·4·8·16ms(합 31ms)였다

### 포트와 `Disabled`

- [x] **`PluginSource`에 메서드 둘이 는다. 포트는 다섯 그대로다**(ADR 0012의 2026-09-26 이력)
  - 하나는 꺼진 (종류, 이름)의 집합을 한 번에 읽는다. 파일이 없으면 빈 집합이고, 손상이면 `PluginError`이며, 원소의 이름은 `PluginName`이다
  - 다른 하나는 (종류, 이름) 하나의 켜짐을 쓰고, 부재를 값으로 돌려준다
  - **둘 다 동기다.** 02가 읽기를 `resume()`의 첫 걸음 안에서 부르게 된다. 그 첫 걸음에 `await`가 없다는 것이 동시 재개의 불변식이다(ADR 0014)
  - 이름과 반환 타입은 이 티켓이 짓는다. 조건은 셋이다. HTTP의 어휘를 쓰지 않는다. 부재를 예외가 아니라 값으로 말한다. 원소 타입은 `ManifestRow`처럼 core의 포트 모듈에 산다
  - `.claude/rules/core.md` 포트 표의 `PluginSource` 행과 포트 클래스의 독스트링이 같은 티켓에서 두 메서드를 안다
- [x] **가짜 포트 셋과 스키마 전용 포트가 두 메서드를 얻는다.** 가짜 셋은 관리, 채널, core 테스트의 것이다(core의 나머지 가짜는 그것을 상속한다). 스키마 전용 포트는 계약 파일 생성기의 것이다. 가짜는 상속 없이 시그니처로 만족하고, 픽스처가 포트 타입으로 annotate한다. 관리 쪽 가짜는 꺼진 집합을 들고, 쓰기를 그 집합에 반영하며, 부른 횟수를 센다
- [x] **core의 `Disabled`는 `PluginError`의 하위 타입이다.** `Absent`, `NotResumable`과 같은 자리에 선다. **이 티켓에서는 아무도 던지지 않는다.** 던지는 것은 02다
  - 표가 409 `conflict`로 옮기고, 그 갈래가 `PluginError`(500)보다 먼저다. 뒤집히면 500이 되는 것을 테스트가 잡는다
  - 어휘는 다섯 그대로다. 어휘와 상태 코드가 1:1이라는 지금의 검사는 그대로 판정한다
  - 매개변수화된 "구성이나 기록이 깨진 것은 부재도 재개 불가도 아닌 `PluginError`다" 테스트가 제외하는 하위 타입에 `Disabled`가 는다

### 관리 API

- [x] **`GET /plugins`는 감싼 행의 목록이다**(ADR 0010의 2026-09-26 이력)
  - 겉은 `kind`, `name`, `enabled`다. 읽히는 행은 `manifest`에 `sdk`의 `PluginManifest`를 그대로 담고, 표지 행은 `reason`을 든다
  - 두 행은 required 필드(`manifest`와 `reason`)로 갈린다. 둘 다 추가 필드를 받지 않고 기본값이 없어 계약에서 전부 required다
  - 행 둘과 그 유니온이 이름 있는 컴포넌트다
  - **읽히는 행의 `name`은 `sdk`의 패턴을 스키마에 싣는다.** 목록에서 얻은 이름을 PUT 경로에 그대로 넘기게 하려는 것이다. 표지 행의 `name`은 `str` 그대로다
  - 꺼진 집합은 요청 하나에 한 번 읽는다
  - 표지 행도 꺼질 수 있다. 디렉터리 이름이 패턴을 어겨 표지가 된 행은 언제나 켜짐이다
  - 운영자 파일이 깨지면 목록 전체가 500 봉투다
- [x] **단건 GET이 읽히는 행을 돌려준다.** 판정 순서는 부재(404) → 깨진 매니페스트(500) → 운영자 파일의 손상(500)이다. 운영자 파일이 깨졌어도 없는 이름은 404다. 계약의 `summary`도 매니페스트가 아니라 행을 말하게 고친다
- [x] **`PUT /plugins/{kind}/{name}/enabled`의 성공**
  - 본문은 `{"enabled": bool}`이고, 답은 본문 없는 204다. 다음 목록에 반영된다. 이미 꺼진 것을 다시 꺼도 204다
  - 에러 문서는 401, 404, 422, 500이고 409는 없다. `operation_id`를 손으로 준다
  - 없는 이름은 404다. 운영자 파일이 깨졌어도 그렇다. 매니페스트가 깨진 플러그인은 204다
  - 있는 이름이라도 운영자 파일이 깨졌으면 500 봉투이고 파일은 바이트 그대로다. 쓰기가 실패해도 500이다
  - skill과 model의 PUT도 204이고 파일에 적힌다. 로더가 생긴 뒤에야 효과가 난다는 한 줄을 오퍼레이션 설명이나 `README.md`에 둔다(스토리 18)
- [x] **경로의 `{name}`은 `verbatim` 변환기와 `sdk`의 이름 패턴으로 받는다.** 단건 GET과 같은 규칙이다
  - `..`나 경로 구분자는 422이고 포트가 불리지 않는다. `violations`가 그 파라미터를 가리킨다. 테스트는 퍼센트 인코딩으로 민다
  - GET `.../calc/enabled`는 422이고, PUT `.../calc`는 405다
  - 명세 검토의 프로브에서 PUT `.../calc/enabled%0A`가 이름 `calc`로 맞아 204였다. 실제 변환기로 다시 재서 그 결과를 테스트로 고정한다. 포트에 닿는 이름이 패턴을 지나므로 경로가 플러그인 루트를 벗어나지 않는다는 것이 이 경우를 두는 근거다
- [x] **본문은 추가 필드를 받지 않고 기본값이 없으며, `enabled`는 엄격한 불린이다**
  - `enabled`가 없거나, 문자열 `"false"`나 숫자 `0`이거나, 추가 필드가 있으면 422다. `violations`가 그 필드를 가리키고 포트가 불리지 않는다
  - 계약의 스키마는 `boolean` 그대로다
  - 본문 모델의 이름은 기존 컴포넌트와 겹치지 않는다. 겹치면 컴포넌트가 `-Input`·`-Output`으로 갈라진다
- [x] **PUT 라우트는 `async def`이고 포트의 쓰기를 이벤트 루프에서 직접 부른다.** ADR 0017의 "이벤트 루프가 줄세운다"를 참으로 만드는 조건이다. 동기 `def`면 FastAPI가 워커 스레드에서 돌려 갱신 하나가 사라진다
  - **동시 PUT 둘이 둘 다 남는다.** 서로 다른 두 이름을 `asyncio.gather`로 끄면 목록에 둘 다 꺼져 있다
  - 가짜 포트의 쓰기는 읽고, 디스크 시간을 들인 뒤 쓴다. 채널 테스트의 `disk_seconds`가 선례다. 즉시 끝나는 가짜로는 동기 라우트도 스레드 타이밍에 따라 초록으로 지나간다
- [x] **인증은 바뀌지 않는다.** 새 경로는 미들웨어의 기본값인 관리 토큰 뒤에 선다. 앱이 아는 (메서드, 경로)를 전수로 도는 기존 테스트가 새 경로를 저절로 덮는다. 관리 라우터는 여전히 도구 포트를 받지 않는다
- [x] **이름은 이 티켓이 짓는다.** `operation_id`, 본문 모델, 행 모델 둘과 그 유니온이다. 기존 컴포넌트(`PluginManifest`, `UnreadableManifest`, `PluginRow`)와 겹치는지 보고 정한다. 표지 행이 `enabled`를 얻으면 용어집의 "읽을 수 없는 매니페스트"와 계약의 이름이 멀어지는지를 domain-modeling 스킬이 그 자리에서 본다
- [x] **감싼 행 때문에 기존 관리 테스트를 다시 쓴다.** HTTP 표지와 core 표지의 필드를 맞추는 대조 테스트는 core 표지의 필드에 `enabled`를 더한 것을 판정한다. 표지 행의 required 집합, `PluginRow` 유니온의 모양, "단건이 매니페스트 그대로"를 단언하는 테스트도 새 모양으로 바꾼다

### `openapi.json`과 409가 닿는 테스트

- [x] **`openapi.json`이 `create_app().openapi()`와 같다.** 최신성 테스트가 그대로 판정한다
  - 바뀌는 것: 감싼 행 둘과 그 유니온, 단건 GET의 응답 타입과 `summary`, 새 PUT 경로와 그 본문과 에러 문서, `POST /runs`의 409, 설명의 관리 문장. 설명은 관리가 읽기만 하는 것이 아니라 켜고 끄기도 한다고 말하게 고치고, 제목은 그대로다
  - 바뀌지 않는 것: 매니페스트 컴포넌트, 에러 어휘, 채널의 본문, 제목
- [x] **`POST /runs`에 409가 붙어 빨개지는 테스트와 거짓이 되는 문장을 이 티켓이 고친다**(명세 검토). 원칙 II 때문에 목록에 없으면 구현자가 그 자리에서 멈춘다
  - `POST /runs`의 에러 문서가 `{401, 404, 422, 500}`이라고 단언하는 채널 테스트와 그 독스트링
  - 409가 승인 라우트에만 있다고 단언하는 채널 테스트. "409는 채널 라우트에만 있다"로 바꿔 관리 쪽 감시를 남긴다
  - `conflict`를 "채널이 재개할 수 없는 실행에 내는 409"라고 적은 관리 테스트의 독스트링
  - 채널 라우터에서 `POST /runs`의 에러를 설명하며 409가 없다고 적은 주석

### 이 티켓이 정한 것 (2026-09-28, PR에서 사용자가 본다)

- **포트.** `read_disabled() -> frozenset[PluginKey]`와 `write_enabled(kind, name, enabled) -> WriteOutcome`. 원소 `PluginKey(kind, name)`와 결과 `WriteOutcome = Literal["applied", "absent"]`가 `core/ports.py`에 산다. `applied`는 요청한 켜짐이 지금 상태라는 뜻이지 파일을 건드렸다는 뜻이 아니다. TOML을 읽은 느슨한 값은 어댑터의 pydantic 모델 `_OperatorFile`이 좁힌다.
- **계약 이름.** 읽히는 행 `Plugin`, 표지 행 `PluginPlaceholder`, 유니온 `PluginRow`(기존 이름), 본문 `SetEnabled`, `operation_id` `set_plugin_enabled`. HTTP의 `UnreadableManifest`는 사라진다 — domain-modeling: 표지 행이 `enabled`를 얻으면 그 이름은 매니페스트가 켜짐을 가진다고 읽혀 용어집의 "읽을 수 없는 매니페스트"(종류·이름·이유)와 멀어진다. 용어집의 표지(Placeholder)로 이름 짓고, "깨진 플러그인"을 피하라는 항목 때문에 `UnreadablePlugin`은 쓰지 않았다. core의 `UnreadableManifest`와 용어집은 그대로다.
- **재시도 상한.** 1·2·4·8·16ms 그대로. 실제 어댑터 측정은 ADR 0017의 2026-09-27 첫 이력에 한 줄 더했다(읽기 9736번 실패 0, 쓰기 670번 실패 1, 재시도 없이는 각각 406/9643과 750/2147).
- **PUT `.../calc/enabled%0A`.** 실제 변환기로 재니 이름 `calc`로 맞아 204다. 테스트가 고정한다.
- **ADR 0014 이력의 "네 자리".** 여덟이었다는 한 줄을 그 이력에 더했다.
- **티켓 목록 밖에서 빨개진 테스트 하나.** 채널 테스트 `test_스트림_항목이_이름_있는_Event_이고_TraceEvent_와_같은_멤버를_가리킨다`가 계약 컴포넌트 이름의 전수 목록을 들고 있어 `UnreadableManifest`→`Plugin`·`PluginPlaceholder`·`SetEnabled`로 목록을 고쳤다. 계약 이름을 이 티켓이 짓는 것이 그 목록을 바꾸는 이유다.
