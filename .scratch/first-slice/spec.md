# 첫 슬라이스: CLI로 에이전트 하나를 실제로 실행한다

Status: ready-for-agent

슬라이스 1(`first-slice`). 근거는 `docs/PRD.md`, `docs/constitution/`, `docs/adr/0001`~`0003`, `docs/journal/2026-09-19-kickoff.md`의 9단계 인터뷰. 용어는 `CONTEXT.md`를 따른다.

## Problem Statement

에이전트를 만드는 개발자는 서비스마다 LLM 호출, 도구 연결, 트레이스를 다시 만든다. 이 저장소의 앞선 두 시도(`ai-agent-platform`, `agent-runtime-platform`)는 둘 다 문서와 관리 화면을 먼저 키우고 LLM 호출 코드 0줄에서 멈췄다. 지금 Agent OS에도 헌법, 용어집, ADR 일곱, 가드레일, 리뷰 파이프라인이 있고 실행 코드는 없다. `sdk`에 이벤트 타입과 `BaseAgent` 프로토콜이 있지만 그것을 실제로 호출하는 런타임이 없어서, 플러그인을 하나 써 봐도 돌려 볼 방법이 없다.

원칙 I이 이 문제에 붙인 기한은 2026-09-22다. 그때까지 LLM을 실제로 호출하는 테스트가 통과하지 않으면 헌법을 더 쌓는 대신 멈추고 원인을 ADR로 남긴다.

## Solution

`plugins/agents/` 아래에 에이전트 플러그인 하나를 놓고 CLI로 요청을 하나 던지면, 런타임이 그 플러그인을 로드하고 매니페스트가 지정한 MCP 서버를 띄워 도구를 붙인 뒤, 모델이 멈출 때까지 루프를 돌려 출력을 낸다. 실행 중 일어난 일은 이벤트의 열로 흐르고 그대로 JSONL 트레이스로 남는다.

사용자가 보는 것은 셋이다. 표준 출력의 출력 문자열, `--verbose`일 때 표준 에러로 흐르는 이벤트, 그리고 실행마다 하나씩 쌓이는 트레이스 파일.

첫 에이전트는 `calc`, 첫 MCP 서버는 `everything`이다. 에이전트는 모델도 도구도 직접 알지 못하고 런타임이 넘긴 컨텍스트로만 일한다. 플러그인이 보는 것은 `sdk` 하나뿐이고 엔진이 LangGraph라는 사실은 플러그인에 보이지 않는다.

## User Stories

### 에이전트 플러그인을 쓰는 개발자

1. 에이전트 개발자로서, 매니페스트 하나와 파이썬 파일 하나로 에이전트 플러그인을 만들고 싶다. 런타임에 등록 절차를 따로 밟지 않고 디렉터리에 놓는 것만으로 실행되게 하기 위해서다.
2. 에이전트 개발자로서, `sdk`만 import하고 싶다. 런타임의 엔진이 바뀌어도 내 플러그인이 깨지지 않게 하기 위해서다.
3. 에이전트 개발자로서, `run()`이 요청 문자열 하나를 받고 이벤트를 내는 async generator이기를 바란다. 출력이 다 만들어질 때까지 기다리지 않고 진행을 흘려보내기 위해서다.
4. 에이전트 개발자로서, 컨텍스트의 `llm()` 한 번으로 모델 호출과 도구 실행의 루프 전체를 돌리고 싶다. 루프를 내가 다시 짜지 않기 위해서다.
5. 에이전트 개발자로서, 컨텍스트의 `tool()`로 모델을 거치지 않고 도구를 직접 부르고 싶다. 모델에게 맡길 필요가 없는 결정을 코드로 쓰기 위해서다.
6. 에이전트 개발자로서, 실행 식별자와 현재 시각을 컨텍스트에서 받고 싶다. `run()`을 같은 입력으로 다시 돌렸을 때 같은 일이 일어나게 하기 위해서다.
7. 에이전트 개발자로서, 컨텍스트의 메서드가 JSON으로 직렬화 가능한 것만 주고받기를 바란다. 나중에 에이전트가 다른 프로세스나 원격에서 돌 때 계약이 그대로 유지되게 하기 위해서다.
8. 에이전트 개발자로서, 내 에이전트가 쓸 MCP 서버를 매니페스트에 적고 싶다. 모든 에이전트가 모든 도구를 갖는 기본값이 굳지 않게 하기 위해서다.
9. 에이전트 개발자로서, 매니페스트에 MCP 서버를 안 적으면 도구가 없는 채로 돌기를 바란다. 도구 없는 에이전트를 만들 때 빈 목록을 쓰는 것 말고 다른 절차가 필요 없게 하기 위해서다.
10. 에이전트 개발자로서, 내가 만든 마지막 이벤트 하나(`run_finished`)만 직접 내고 시작과 실패 이벤트는 런타임이 내기를 바란다. 모든 에이전트가 같은 뼈대 코드를 베끼지 않게 하기 위해서다.
11. 에이전트 개발자로서, 내가 낸 다른 이벤트도 스트림에 그대로 흐르기를 바란다. 에이전트만 아는 중간 상태를 기록에 남기기 위해서다.
12. 에이전트 개발자로서, 매니페스트 형식이 버전을 가지기를 바란다. 형식이 바뀌었을 때 내 플러그인이 조용히 다르게 해석되지 않고 거부되게 하기 위해서다.
13. 에이전트 개발자로서, 같은 파일명을 가진 플러그인을 여러 개 놓아도 서로 덮어쓰지 않기를 바란다. 플러그인마다 이름을 조심해서 짓지 않아도 되게 하기 위해서다.

### 운영자(지금은 CLI를 쓰는 사람)

14. 운영자로서, 명령 한 줄로 에이전트에 요청을 던지고 싶다. 서버를 띄우지 않고 에이전트가 동작하는지 확인하기 위해서다.
15. 운영자로서, 출력 문자열만 표준 출력으로 받고 싶다. 다른 명령으로 파이프해 쓰기 위해서다.
16. 운영자로서, `--verbose`를 줬을 때 진행 이벤트를 표준 에러로 보고 싶다. 출력 파이프를 더럽히지 않고 진행을 보기 위해서다.
17. 운영자로서, 실행이 성공하면 종료 코드 0, 실패하면 1을 받고 싶다. 스크립트에서 분기하기 위해서다.
18. 운영자로서, 실행마다 트레이스 파일이 실행 식별자 이름으로 하나씩 남기를 바란다. 나중에 무슨 일이 있었는지 되짚기 위해서다.
19. 운영자로서, 트레이스가 이벤트를 그대로 저장한 것이기를 바란다. 실행 중에 본 것과 파일에 남은 것이 다르지 않게 하기 위해서다.
20. 운영자로서, 트레이스 파일 첫 줄에서 형식 버전을 알고 싶다. 나중에 형식이 바뀌어도 옛 파일을 읽을 수 있게 하기 위해서다.
21. 운영자로서, 트레이스를 읽는 쪽이 모르는 이벤트 종류를 만나도 원문을 보존하기를 바란다. 새 런타임이 낸 트레이스를 옛 도구가 지우지 않게 하기 위해서다.
22. 운영자로서, 어떤 모델로 돌릴지 플래그나 환경변수로 정하고 싶다. 코드를 고치지 않고 모델을 바꾸기 위해서다.
23. 운영자로서, 지정한 모델이 안 되면 다른 모델로 몰래 넘어가지 않기를 바란다. 비용과 품질이 내가 모르는 사이에 바뀌지 않게 하기 위해서다.
24. 운영자로서, 모든 이벤트에 실행 식별자와 주체가 붙기를 바란다. 나중에 여러 사람이 쓸 때 누가 무엇을 돌렸는지 되짚을 수 있게 하기 위해서다.
25. 운영자로서, 트레이스가 쌓이는 디렉터리를 정하고 싶다. 저장소 작업 트리를 어지럽히지 않고 격리된 곳에 남기기 위해서다.
26. 운영자로서, 이벤트와 트레이스에 API 키나 토큰이 실리지 않기를 바란다. 기록을 공유해도 비밀이 새지 않게 하기 위해서다.

### 실패를 겪는 사람

27. 운영자로서, 없는 에이전트 이름을 줬을 때 무엇이 없는지 바로 알고 싶다. 오타인지 설치 문제인지 구분하기 위해서다.
28. 운영자로서, MCP 서버가 안 뜨면 실행이 거기서 실패하기를 바란다. 도구 없이 절반만 동작한 답을 받지 않기 위해서다.
29. 운영자로서, 도구 하나가 에러를 냈을 때 실행이 죽지 않고 모델이 그 사실을 알고 계속하기를 바란다. 모델이 다른 방법을 시도할 수 있게 하기 위해서다.
30. 운영자로서, 모델이 도구와 호출을 무한히 반복하지 않기를 바란다. 비용이 무한정 늘지 않게 하기 위해서다.
31. 운영자로서, LLM API 에러가 재시도 뒤에도 계속되면 실행이 실패로 끝나기를 바란다. 무엇이 잘못됐는지 트레이스에 남기기 위해서다.
32. 운영자로서, 실패한 실행도 트레이스를 남기기를 바란다. 실패야말로 되짚어야 하는 것이기 때문이다.
33. 운영자로서, 매니페스트가 잘못됐으면 실행 전에 거부되기를 바란다. 절반쯤 돌다가 죽는 것보다 시작하지 않는 편이 낫기 때문이다.

### 런타임을 고치는 사람

34. 런타임 기여자로서, core가 프로세스 밖과 닿는 지점이 포트 다섯으로 닫혀 있기를 바란다. 어디를 가짜로 바꿔야 테스트가 되는지 세지 않아도 되게 하기 위해서다.
35. 런타임 기여자로서, 기본 테스트 스위트가 네트워크 없이 돌기를 바란다. 커밋마다 훅이 돌아도 비용과 시간이 들지 않게 하기 위해서다.
36. 런타임 기여자로서, LLM을 실제로 호출하는 테스트가 마커로 분리되기를 바란다. 원칙 I의 판정을 따로 돌리기 위해서다.
37. 런타임 기여자로서, 키가 없을 때 LLM 테스트가 skip이 아니라 실패하기를 바란다. 초록 착시를 만들지 않기 위해서다.
38. 런타임 기여자로서, 프로바이더를 바꿀 때 core를 건드리지 않기를 바란다. 교체가 어댑터 한 개의 일로 끝나게 하기 위해서다.
39. 런타임 기여자로서, 가짜 어댑터가 포트를 상속하지 않고 시그니처로 만족하기를 바란다. 포트가 바뀌면 타입 검사가 가짜를 깨뜨려 알려 주게 하기 위해서다.
40. 런타임 기여자로서, 나중에 붙일 인터럽트와 체크포인터가 지금 설계를 다시 뜯지 않기를 바란다. `run()` 재실행 가능과 컨텍스트의 JSON 직렬화라는 두 제약이 그 이음매이기 때문이다.

## Implementation Decisions

### 이음매

테스트가 미는 지점은 둘이고, 둘 다 기존 계약 위에 있다. 새 이음매를 만들지 않는다.

- **주 이음매: core의 실행 함수 하나.** 에이전트 이름, 요청, 주체, 그리고 포트 다섯(TraceSink, PluginSource, ToolSource, ChatModel, Clock)을 받아 이벤트를 내는 async generator다. 이것은 첫 슬라이스가 끝난 상태의 시그니처다. 도구 원천은 마지막 티켓에서 붙으므로 그 전까지 이 함수가 받는 포트는 넷이다. 기본 스위트의 모든 테스트가 이 지점을 민다. 로더, 루프, 도구 연결, 트레이스 기록, 실패 정책이 전부 이 아래에 있어서 이음매 하나로 덮인다.
- **바깥 이음매: CLI 프로세스.** `llm` 마커가 붙은 end-to-end만 여기를 민다. 실제 Anthropic 호출과 실제 MCP 서버 기동을 포함하며 원칙 I의 판정이 이 테스트다.
- JSONL 트레이스 어댑터는 별도 이음매를 두지 않는다. 진짜 어댑터를 임시 디렉터리에 물려 주 이음매에서 같이 검증한다.
- `sdk`의 기존 테스트(이벤트 JSON 왕복, 매니페스트 거부)는 그대로 둔다. 디스크 형식의 계약이라 그 자리가 맞다.

### 계약 변경 (`sdk`) — 다른 티켓을 막는 첫 티켓

디스크에 남는 형식이라 여기부터 바꾸고 나머지가 뒤따른다.

- 매니페스트에 `schema_version`을 넣는다. 값은 `"1"` 하나이고 판별자와 같은 취급이라 `Literal`이다. 모르는 값은 거부한다.
- `PluginKind`에 `model`을 더하고 `StrEnum`으로 바꾼다. 근거는 슬라이스 3의 생성 클라이언트가 재사용하도록 OpenAPI가 이름 있는 정의로 내보내야 한다는 것이다. 판별자 `type`과 `schema_version`만 `Literal`로 남는다.
- 에이전트 매니페스트에 쓸 MCP 서버 목록을 더한다. 비어 있으면 도구가 없다(ADR 0002). 에이전트 종류에만 허용한다.
- mcp 매니페스트에 서버 실행 정보를 담는 표를 더한다. 실행 명령과 인자 목록이며 mcp 종류에만 허용한다.
- `run_started` 이벤트에 주체를 필수 필드로 더한다. 선택 필드로 미루면 멀티테넌시가 fail-open이 된다. CLI는 OS 사용자 이름을 넣는다.
- 컨텍스트 프로토콜에 실행 식별자와 현재 시각을 더한다. `run()`이 재실행 가능하려면 시각과 난수가 컨텍스트를 통해서만 들어와야 한다.
- 식별자는 `NewType`으로 감싼다(실행 식별자, 에이전트 이름, 플러그인 이름, 주체). 경계에서 한 번만 감싸고 JSON 형식은 문자열 그대로다.
- 이 변경으로 기존 `sdk` 테스트의 가짜 에이전트가 깨진다. 같은 티켓에서 고친다.

### 컨텍스트의 의미

지금 계약에서 가장 해석이 갈리는 지점이라 여기서 못 박는다.

- `llm()`은 프롬프트 한 번이 아니라 **루프 전체**를 돈다. 모델을 부르고, 모델이 도구를 부르면 실행해 결과를 되돌리고, 모델이 멈출 때까지 반복한 뒤 마지막 텍스트를 돌려준다. 루프는 런타임이 소유한다는 용어집 정의가 여기로 내려온 것이다.
- `tool()`은 모델을 거치지 않고 도구 하나를 부른다.
- 루프 안에서 생긴 이벤트(모델 호출, 도구 호출)는 런타임이 컨텍스트에 순서대로 쌓고, core의 스트림이 에이전트의 다음 이벤트보다 먼저 내보낸다. 순서 보장은 하나다. 어떤 컨텍스트 호출 안에서 생긴 이벤트는 그 호출이 돌아온 뒤 에이전트가 내는 이벤트보다 앞선다.

### 포트 다섯과 어댑터

포트는 닫힌 목록이고 늘리려면 ADR이 필요하다.

- **TraceSink**: 이벤트를 쓴다. 첫 어댑터는 JSONL 파일.
- **PluginSource**: 매니페스트를 읽고 에이전트 플러그인을 로드한다. 첫 어댑터는 파일시스템(ADR 0003).
- **ToolSource**: 서버 명세를 받아 도구 목록을 주고 도구를 호출한다. 시작과 종료의 수명이 있다. 첫 어댑터는 MCP.
- **ChatModel**: 모델 호출. 포트 자체는 langchain-core의 추상 클래스이고 첫 어댑터는 langchain-anthropic.
- **Clock**: 현재 시각(UTC)과 실행 식별자(uuid4).

어댑터는 포트를 상속하지 않고 시그니처로 만족한다. core는 프로바이더 패키지를 import하지 않고 조합은 진입점이 한다. import-linter가 판정한다.

### 실행의 흐름과 이벤트 주체

- 런타임이 실행 식별자를 만들고 `run_started`를 낸다. 에이전트는 마지막에 `run_finished` 하나를 낸다. 실패는 런타임이 `run_failed`로 낸다. 에이전트가 낸 다른 이벤트는 그대로 통과시킨다.
- core는 자기가 내는 모든 이벤트를 TraceSink에 쓴다(원칙 V). 채널은 표시만 결정한다.
- 도구는 에이전트 매니페스트가 지정한 MCP 서버의 것만 붙는다. 지정이 비면 도구 없이 돈다.

### 실행 전과 실행 중의 경계

무엇이 트레이스를 남기는 실패이고 무엇이 아닌지의 선을 긋는다.

- **실행 전(구성 오류)**: 없는 에이전트 이름, 매니페스트 파싱 실패, 모르는 `schema_version`, 지정한 MCP 서버 이름이 없음, 진입점 import 실패. 표준 에러에 무엇이 잘못됐는지 적고 종료 코드 1로 끝낸다. 실행 식별자를 만들지 않고 트레이스도 남기지 않는다. 실행이 시작되지 않았기 때문이다.
- **실행 중**: MCP 서버 기동 실패부터는 실행 안이다. `run_failed`로 끝나고 트레이스가 남는다.

### 실패 정책

- MCP 서버 기동 실패 → `run_failed`.
- 도구 에러 → `tool_called`에 실패로 기록하고 에러 내용을 도구 결과로 모델에 되돌려 루프를 계속한다.
- 루프 상한 10턴. 넘으면 `run_failed`.
- LLM API 에러 → 프로바이더 SDK의 재시도 뒤에도 실패하면 `run_failed`. 다른 모델로 넘어가지 않는다.

### CLI 표면

- `run` 하위 명령이 에이전트 이름과 요청을 위치 인자로 받는다. 옵션은 모델 지정, 진행 표시, 트레이스 디렉터리 지정 셋. 기존 버전 옵션은 그대로 둔다.
- 표준 출력은 출력 문자열만.
- 표준 에러는 두 가지를 싣고 규칙이 다르다. 실패 진단은 진행 표시와 무관하게 언제나 나간다. 진행 이벤트는 진행 표시를 켰을 때만 한 줄에 하나씩 JSON으로 나가고 트레이스와 같은 직렬화를 쓴다. 따라서 진행 표시를 끈 성공한 실행에서만 표준 에러가 비어 있다.
- 종료 코드는 성공 0, 실패 1.
- 주체는 OS 사용자 이름이고 플래그로 바꾸지 않는다.
- 모델 결정 순서는 플래그, 환경변수, 기본값(`claude-opus-5`)이다. 폴백은 없고 `max_tokens`는 16000이다.
- 트레이스는 기본적으로 작업 디렉터리 아래 `traces/<run_id>.jsonl`에 쌓는다. 이 디렉터리는 git에서 무시한다(지금 `.gitignore`에 없다).

### 트레이스 파일 형식

- 한 줄에 JSON 하나. 첫 줄은 헤더이고 형식 버전과 실행 식별자를 담는다. 둘째 줄부터 이벤트다.
- 읽는 쪽은 모르는 이벤트 종류를 만나면 원문을 보존한다. 형식을 바꾸면 ADR을 남긴다.
- 키와 토큰은 이벤트에 싣지 않는다(원칙 V).

### 첫 플러그인 둘

- 에이전트 `calc`. 계산 요청을 받아 도구를 써서 답한다. 매니페스트가 MCP 서버 `everything`을 지정한다.
- mcp 플러그인 `everything`. `npx -y @modelcontextprotocol/server-everything`으로 뜨는 stdio 서버다. 이 머신에 Node 24가 있는 것을 확인했다.
- 진입점은 플러그인 디렉터리 기준 파일이며 고유 모듈명(`agent_os_plugins.<name>.<module>`)으로 로드한다. `sys.path`를 건드리지 않는다.

### 의존성

- `pyproject.toml`을 `docs/constitution/tech.md`의 표에 맞춘다. core는 langgraph, langchain-core, pydantic. 어댑터는 langchain-anthropic, langchain-mcp-adapters. anthropic과 mcp는 직접 의존이 아니라 이들 뒤에서 온다. 근거는 ADR 0001이다.
- `langchain-mcp-adapters`가 mcp를 1.x로 고정해 지금 설치된 mcp 2.2.0이 1.x로 내려간다. 예상된 대가다.
- dev 의존성으로 `pytest-asyncio`를 더하고 `asyncio_mode = "auto"`로 둔다. 근거는 ADR 0007이다. 주 이음매가 수명 있는 포트를 주입받아서 async 픽스처가 필요하고, 지금의 `asyncio.run()` 방식으로는 async 픽스처를 만들 수 없다.
- pytest 설정에서 `RuntimeWarning`을 에러로 올린다. `await`를 빼먹은 코루틴이 경고만 내고 통과하는 것을 막는다. 경고 전부를 올리지는 않는다. 서드파티의 deprecation 경고가 우리 잘못이 아닌 이유로 스위트를 빨갛게 만들기 때문이다.
- 기존 `sdk` 에이전트 테스트의 `asyncio.run` 사용을 같은 티켓에서 바꾼다. 한 저장소에 두 방식을 두지 않는다.

### ADR 0001의 후퇴 체크포인트

ADR 0001은 pyright strict 마찰로 2026-09-21까지 LLM 테스트가 초록이 안 되면 프로바이더 SDK의 내장 루프로 후퇴하라고 적었다. **그 날짜가 오늘이고 원칙 I의 기한은 내일이다.** 그러므로 구현 순서는 LangGraph 경로의 타입 마찰을 가장 먼저 드러내는 순서여야 한다. 마찰이 하루 안에 풀리지 않으면 후퇴하고 그 사실을 ADR 0001에 덧붙인다. 후퇴해도 플러그인 계약과 포트 다섯은 그대로이고 바뀌는 것은 루프 구현 하나다. 이 이음매가 후퇴를 싸게 만든다.

## Testing Decisions

### 좋은 테스트의 정의

- 바깥으로 드러난 행동만 검증한다. 이 슬라이스에서 그것은 이벤트의 열, 출력 문자열, 종료 코드, 트레이스 파일의 내용, 실패했다는 사실이다. 내부 호출 순서나 private 이름을 단언하지 않는다.
- 나머지 테스트 규약은 여기서 다시 적지 않는다. 원천은 `.claude/rules/tests.md`이고 그 위에 원칙 II와 `CODING_STANDARDS.md`가 있다. skip이 초록이 아니라는 것, 실패한 테스트를 고치지 않는 것, 이름을 행동 명세로 쓰는 것이 거기 있다.

### 무엇을 어디서 테스트하나

**주 이음매(core의 실행 함수, 기본 스위트)** — 네트워크 없이 돈다.

- 도구 없는 에이전트의 이벤트 열이 시작과 종료로 끝난다.
- 도구를 쓰는 에이전트의 이벤트 열에 모델 호출과 도구 호출이 순서대로 들어간다.
- 컨텍스트 호출 안에서 생긴 이벤트가 그 호출 뒤 에이전트가 낸 이벤트보다 앞선다.
- 모든 이벤트에 같은 실행 식별자가 붙고 시작 이벤트에 주체가 있다.
- 매니페스트가 MCP 서버를 지정하지 않으면 도구 없이 끝난다.
- 매니페스트가 지정한 서버의 도구만 붙는다(다른 서버가 있어도 안 붙는다).
- MCP 서버 기동 실패가 실패 이벤트로 끝난다.
- 도구 에러가 실패로 기록되고 루프가 계속된다.
- 루프 상한을 넘으면 실패 이벤트로 끝난다.
- LLM 에러가 실패 이벤트로 끝난다.
- 진짜 JSONL 어댑터를 임시 디렉터리에 물렸을 때, 파일 첫 줄이 헤더이고 이후 줄이 흘러간 이벤트와 같다.
- 실패한 실행도 트레이스를 남긴다.
- 모르는 종류의 이벤트가 섞인 트레이스를 읽어도 원문이 보존된다.

**`sdk`(기존 자리 유지)** — 디스크 형식의 계약.

- 매니페스트의 새 필드가 종류별로 맞는 자리에만 허용된다.
- 모르는 `schema_version`이 거부된다.
- 주체 없는 시작 이벤트가 거부된다.

**CLI 표면(기본 스위트)** — 네트워크 없이 돈다. 모델도 도구도 쓰지 않는 테스트용 에이전트로 CLI를 불러서 검증한다.

- 표준 출력에 출력 문자열만 나온다.
- 진행 표시를 켜면 이벤트가 한 줄에 하나씩 표준 에러로 나온다. 끈 채로 성공하면 표준 에러가 비어 있다.
- 진행 표시를 끈 실패에서도 표준 에러에 원인이 남는다. 실패 진단과 진행 이벤트는 규칙이 다르다.
- 성공과 실패의 종료 코드가 다르다.
- 주체가 OS 사용자 이름으로 채워진다.
- 지정한 트레이스 디렉터리에 실행 식별자 이름의 파일이 생긴다.
- 없는 에이전트 이름, 매니페스트 파싱 실패, 모르는 형식 버전은 종료 코드 1이고 트레이스를 남기지 않는다.

**바깥 이음매(CLI, `llm` 마커)** — 실제 호출.

- `calc` 에이전트에 계산 요청을 던지면 종료 코드 0으로 끝나고 표준 출력에 답이 있으며, 트레이스에 모델 호출과 도구 호출이 모두 남는다.
- 그보다 앞서, 모델 어댑터가 실제로 답을 받는 테스트 하나가 따로 있다. 이 하나가 원칙 I의 판정이고 CLI보다 먼저 통과한다.

### 가짜를 만드는 방식

- 가짜는 포트 프로토콜을 상속하지 않고 시그니처로 만족한다. 픽스처에서 포트 타입으로 annotate하는 그 한 줄이 포트 적합성이 검증되는 유일한 지점이고, pyright가 테스트를 검사하는 이유다.
- 테스트는 `async def`로 쓴다. 데코레이터도 마커도 없고 `asyncio.run()`을 직접 부르지 않는다. 시작과 종료의 수명이 있는 ToolSource는 async 픽스처로 열고 닫는다. 그 수명 관리가 테스트 본문마다 반복되지 않는 것이 이 방식을 고른 이유다.
- 모델 가짜는 미리 정해진 응답을 순서대로 돌려준다. 도구 호출을 시키는 응답과 최종 텍스트를 섞을 수 있어야 루프를 검증할 수 있다.
- 도구 가짜는 이름별로 결과나 에러를 정해 둔다. 시계 가짜는 고정 시각과 고정 식별자를 준다.

### 기존 자산

- 비동기 이벤트 스트림을 모아 단언하는 방식은 기존 `sdk` 에이전트 테스트의 수집 헬퍼가 선례다. 수집하는 부분은 그대로 쓰고 이벤트 루프를 직접 돌리는 부분만 버린다.
- 디스크 형식의 JSON 왕복과 거부 케이스는 기존 이벤트·매니페스트 테스트가 선례다.
- 테스트 디렉터리는 소스를 미러링하고 import 모드가 importlib이라 같은 파일명이 여러 디렉터리에 공존한다.

## Out of Scope

첫 슬라이스가 끝나기 전에는 만들지 않는다.

- 선언적 그래프 정의, 빌더 UI.
- HTTP 채널, 관리 API, 관리 화면, 위젯. 슬라이스 2 이후다.
- 체크포인터와 되감기, 사람 승인 인터럽트. `thread_id`를 실행 식별자로 붙이는 것은 슬라이스 2다.
- 토큰 스트리밍, 취소와 타임아웃, 병렬 도구 호출.
- 스킬 로더와 모델 로더. 디렉터리와 종류 값만 예약한다.
- 원격·컨테이너·WASM 실행, 플러그인별 의존성 격리.
- 메모리, 대화 이력, RAG.
- 멀티테넌시. 주체 필드만 지금 넣는다.
- 트레이스 DB와 OTel, 비용 계량, 모델 라우팅, 멀티 프로바이더.
- 핫리로드와 레지스트리, 스케줄러와 웹훅 트리거, 헬스체크와 Docker.
- PII와 가드레일. 키를 이벤트에 싣지 않는 것만 지금 지킨다.

## Further Notes

- **일지와 규칙이 어긋나는 곳 하나.** 인터뷰 기록에는 "JSONL 구현은 channel"이라고 적혀 있지만, 이후 확장성 검토에서 HTTP 채널이 같은 구현을 쓰는 순간 채널끼리 import하게 된다는 이유로 철회되어 어댑터로 옮겨졌다. 현재 규칙 문서가 맞고 이 명세는 그쪽을 따른다.
- **`.gitignore`에 트레이스 디렉터리가 없다.** 첫 실행이 작업 트리를 더럽히므로 CLI 티켓에 포함한다.
- **티켓 순서는 기한이 정했다.** 제품 의도 문서가 성공의 정의를 둘로 나눠 두었고 내일 기한은 "LLM을 실제로 호출하는 테스트 하나"다. 모델 어댑터는 매니페스트도 이벤트 스키마도 쓰지 않으므로 계약 티켓을 기다릴 이유가 없다. 그래서 의존성, 모델 호출, 계약 순이다.
- **`sdk` 계약 티켓이 실행 함수와 디스크 어댑터를 막는다.** 디스크에 남는 형식을 바꾸기 때문이다. 모델 호출과는 겹치지 않아 나란히 갈 수 있다.
- **위험은 루프 티켓 하나에 모여 있다.** 그래프 엔진의 타입 마찰이 드러나는 유일한 조각이라 디스크 어댑터를 떼어 놓았다. 후퇴해도 다시 만드는 것은 그 하나다.
- **원칙 III가 이 슬라이스의 가장 큰 마찰이다.** LangGraph와 langchain 계열은 pyright strict에서 부분적으로 알려지지 않은 타입을 낸다. 원칙 III가 타입 우회를 금지하므로 경계에서 우리 타입으로 감싸는 것이 유일한 길이다. 감싸는 자리는 core의 포트다. 이 마찰이 하루 안에 풀리지 않으면 위의 후퇴 체크포인트를 실행한다.
- **원칙 I 기한이 내일(2026-09-22)이다.** 가장 짧은 초록 경로를 먼저 밟는다. 계약 티켓, 그다음 실제 호출이 닿는 가장 얇은 세로 조각, 그다음 나머지.
