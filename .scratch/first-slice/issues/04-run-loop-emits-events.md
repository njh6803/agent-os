# 04: 실행 함수가 루프를 돌고 이벤트를 낸다

**무엇을 만드나:** 에이전트에게 요청 하나를 주면 런타임이 모델 호출과 도구 실행의 루프를 대신 돌고, 그 과정이 이벤트의 열로 흐른다. 에이전트 개발자는 루프를 직접 짜지 않고 컨텍스트의 모델 호출 한 번으로 끝낸다. 아직 디스크에 닿지 않는다. 로더와 트레이스와 시계는 가짜이고 부르는 쪽은 테스트다.

이 티켓이 주 이음매를 만든다. 포트를 주입받아 이벤트를 내는 실행 함수 하나이고, 이후 모든 기본 스위트 테스트가 이 지점을 민다.

**위험이 여기 모여 있다.** 그래프 엔진의 strict 타입 마찰이 드러나는 유일한 조각이다. 하루 안에 풀리지 않으면 ADR 0001의 후퇴를 실행하고 그 사실을 그 ADR에 덧붙인다. 후퇴해도 플러그인 계약과 포트는 그대로이고 바뀌는 것은 이 티켓의 루프 구현 하나다. 디스크에 닿는 어댑터를 05로 떼어 놓은 이유가 이것이다.

**Blocked by:** 02, 03

**Status:** ready-for-agent

- [ ] core가 트레이스 싱크, 플러그인 원천, 시계 포트를 선언한다. 이 셋의 선언 주인이 이 티켓이고 05가 구현한다. 모델 포트는 02가 이미 선언했다
- [ ] 실행 함수가 에이전트 이름, 요청, 주체와 포트 넷을 받아 이벤트를 내는 비동기 스트림이다. 도구 원천은 아직 받지 않고 07이 다섯째로 더한다. 명세의 "포트 다섯"은 슬라이스가 끝난 상태를 가리킨다
- [ ] 런타임이 실행 식별자를 만들고 시작 이벤트를 낸다. 에이전트는 마지막에 종료 이벤트 하나를 낸다
- [ ] 에이전트가 낸 다른 이벤트도 스트림에 그대로 흐른다
- [ ] 모든 이벤트에 같은 실행 식별자가 붙고 시작 이벤트에 주체가 있다
- [ ] 컨텍스트의 모델 호출이 루프를 돈다. 도구가 없으면 한 바퀴로 끝나고 마지막 텍스트를 돌려준다
- [ ] 모델 호출마다 이벤트가 하나 나고 토큰 수가 담긴다
- [ ] 컨텍스트 호출 안에서 생긴 이벤트가 그 호출 뒤 에이전트가 내는 이벤트보다 앞선다
- [ ] 실행 함수가 자기가 내는 모든 이벤트를 트레이스 포트에 쓴다. 수집 층을 따로 두지 않는다
- [ ] 루프가 상한을 넘으면 실패 이벤트로 끝난다
- [ ] 모델 호출이 재시도 뒤에도 실패하면 실패 이벤트로 끝나고, 다른 모델로 넘어가지 않는다
- [ ] 실패한 실행도 트레이스 포트에 이벤트를 남긴다
- [ ] 엔진이 플러그인에 보이지 않는다. sdk와 플러그인은 엔진을 import하지 않는다
- [ ] 가짜는 포트를 상속하지 않고 시그니처로 만족한다. 픽스처가 포트 타입으로 annotate된다
- [ ] 기본 스위트가 네트워크 없이 돈다
- [ ] 검증 명령 넷이 초록이다
