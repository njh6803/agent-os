# 06: CLI로 에이전트를 실행한다

**무엇을 만드나:** 운영자가 명령 한 줄로 에이전트에 요청을 던진다. 출력은 표준 출력으로 나와 다른 명령에 파이프할 수 있고, 진행을 보고 싶으면 표준 에러로 이벤트를 흘려볼 수 있다. 성공과 실패가 종료 코드로 구분되고 실행마다 트레이스 파일이 하나 남는다. 첫 에이전트 플러그인이 저장소에 실재하게 된다.

여기서부터 데모가 된다. 사람이 명령을 쳐서 답을 본다. 앞의 조각들이 조합 층에서 처음으로 한데 묶인다.

**Blocked by:** 04, 05

**Status:** ready-for-agent

- [ ] 실행 하위 명령이 에이전트 이름과 요청을 위치 인자로 받는다
- [ ] 표준 출력에 출력 문자열만 나온다
- [ ] 진행 표시를 켜면 이벤트가 표준 에러로 한 줄에 하나씩 나온다. 트레이스와 같은 직렬화다
- [ ] 진행 표시를 끈 성공한 실행에서 표준 에러가 비어 있다
- [ ] 실패 진단은 진행 표시와 무관하게 언제나 표준 에러로 나간다. 진행 표시를 끈 실패에서도 원인을 읽을 수 있다
- [ ] 성공은 종료 코드 0, 실패는 1이다
- [ ] 주체가 OS 사용자 이름으로 채워진다
- [ ] 트레이스 디렉터리를 지정할 수 있고, 지정하지 않으면 기본 위치에 쌓인다
- [ ] 모델을 플래그로 지정할 수 있다. 플래그, 환경변수, 기본값 순이고 폴백은 없다
- [ ] 위 표면들이 기본 스위트에서 검증된다. 모델도 도구도 쓰지 않는 테스트용 에이전트로 부르면 네트워크가 필요 없다
- [ ] 없는 에이전트 이름은 무엇이 없는지 표준 에러에 적고 종료 코드 1로 끝난다. 실행 식별자를 만들지 않고 트레이스도 남기지 않는다
- [ ] 매니페스트 파싱 실패, 모르는 형식 버전, 진입점 import 실패도 같은 방식으로 실행 전에 끝난다
- [ ] 조합 층이 어댑터를 만들어 넘긴다. 채널이 어댑터를 직접 고르지 않는다
- [ ] 에이전트 플러그인 `calc`가 저장소에 있고 아직 MCP 서버를 지정하지 않는다. 모델만으로 답한다. 07이 같은 플러그인에 서버를 더하므로 셋째 에이전트를 만들지 않는다
- [ ] 위 표면 테스트가 쓰는 에이전트는 테스트 안의 픽스처이고 `plugins/`에 두지 않는다
- [ ] 마커를 단 end-to-end 테스트가 실제 호출로 답을 받고, 트레이스에 모델 호출이 남는 것을 확인한다
- [ ] 그 테스트가 저장소 작업 트리를 더럽히지 않는다
- [ ] 검증 명령 넷이 초록이다
