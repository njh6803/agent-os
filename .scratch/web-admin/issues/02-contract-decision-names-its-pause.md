# 02: 계약 — 결정은 그것이 답하는 일시정지의 자리를 든다

**What to build:** 승인자는 HTTP로 결정을 보내거나 CLI로 `resume`을 친다. 어느 쪽이든 결정은 자기가 본 일시정지의 자리를 필수로 든다. 자리는 `run_paused` 이벤트가 트레이스 상세 `events`에서 서는 0부터 센 인덱스다. 그 자리가 지금의 일시정지가 아니면 core가 결정을 쓰기 전에 거절한다. HTTP는 409 `conflict`이고 메시지가 두 자리를 든다. CLI는 진단을 내고 종료 코드 1로 끝난다. 거절된 결정은 트레이스를 바이트 그대로 두므로 맞는 자리로 다시 결정할 수 있다. CLI가 멈출 때 찍는 안내 줄 둘이 그 자리를 싣고, 그대로 복사해 치면 재개된다. 이렇게 틈 하나가 닫힌다. 지금은 오래된 화면이나 터미널에 남은 옛 줄의 결정이 200을 받고, 승인자가 본 적 없는 도구 호출을 실행한다(`probe_stale_decision.py`). 디스크 형식과 `sdk`는 바뀌지 않는다.

이 기능의 뿌리 둘 가운데 하나다. 01과 서로 막지 않고, 03과 03 뒤에 서는 web 티켓(05~08)을 막는다. 생성물이 옛 결정 본문으로 한 번 섰다가 다시 서는 일을 두지 않기 위해서다. 04는 생성물을 쓰지 않아 이 티켓에 막히지 않는다(사용자가 골랐다). **나누지 않는 짝이다.** 결정 본문의 필드, core의 판정, 채널의 전달, CLI의 인자와 안내 줄이 한 PR에 든다. 나누면 두 모양 가운데 하나가 main에 남는다. 계약은 자리를 요구하는데 core가 보지 않아 오래된 결정이 여전히 200인 상태, 또는 ADR 0014 이력이 거부한 "HTTP만 묶고 CLI는 마지막 일시정지"다. 리뷰의 질문은 명세대로 이 필드 이름과 판정 순서로 오래 살 수 있느냐다. 필드 이름은 이 PR에서 사용자가 본다.

근거는 `.scratch/web-admin/spec.md`의 "계약 티켓 — 결정의 자리"와 "파이썬 — 계약 티켓", "LLM 테스트" 절이다. ADR 0014의 2026-09-28 이력과 ADR 0009, `probe_stale_decision.py`, `probe_lax_index.py`도 근거다. 파이썬 서버가 바뀌는 곳은 이것 하나다(ADR 0010의 2026-09-28 이력).

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 계약의 필드

- [ ] **이름은 이 티켓이 짓는다.** 조건은 넷이다
  - `Approve`와 `Deny`에 같은 이름이다
  - 0 이상의 정수이고 기본값이 없다. 요청 본문은 검증 스키마로 실려, 기본값이 곧 계약의 "선택"이 된다(`.claude/rules/channel.md`)
  - 시각으로 읽히는 이름을 피한다
  - 계약의 설명이 "트레이스 상세 `events`의 인덱스"를 말한다. 필드에는 독스트링을 둘 자리가 없어 필드의 `description`에 둔다. `src/`에 아직 `Field(description=…)`가 없고, 가장 가까운 선례는 관리 라우트의 `Query(description=…)`다
- [ ] **자리는 엄격한 정수다.** 필드를 `strict=True`로 둔다. 채널 본문 모델은 지금 lax 검증이라 문자열 `"2"`, 실수 `2.0`, 불린 `true`가 모두 받아졌고 `true`는 1로 읽혔다(`probe_lax_index.py`). 스키마는 lax와 같다(`integer`, 최솟값 0). 선례는 관리 트레이스 목록 커서 모델 `_CursorWire`다
- [ ] **`openapi.json`.** `Approve`와 `Deny`에 required 필드 하나가 늘고 `minimum: 0`이다. 어휘, 경로, 스트림의 항목은 그대로다. 최신성 테스트가 그대로 판정한다. web 생성물은 아직 없다. 03이 이 티켓에 막혀 있기 때문이다

### core `resume()`

- [ ] **자리를 필수로 받는다. 기본값은 없다.** 선택으로 두면 기본값이 곧 "마지막 일시정지"라 fail-open이다. 별도 인자로 받을지 `Approve`·`Deny`의 필드로 받을지는 이 티켓이 정한다
- [ ] **판정 순서.** 먼저 트레이스를 판정한다. 없음, 형식 1, 손상, 일시정지 아님, 자리 어긋남 순이다. 그다음이 준비다. 매니페스트, mcp, 마스킹과 승인의 충돌, 운영자 파일, 꺼짐, 진입점 순이다. 결정 이벤트 쓰기가 맨 끝이다
- [ ] **어긋나면 `NotResumable`이다.** 메시지는 결정이 가리킨 자리와 지금 일시정지의 자리를 모두 든다
- [ ] **자리 판정도 첫 걸음 안이고 `await`가 없다.** 같은 자리를 든 결정 둘이 동시에 오면 둘째는 지금처럼 "일시정지 아님"이다(ADR 0014)
- [ ] 거절된 결정은 트레이스에 아무것도 쓰지 않는다
- [ ] **자리로 이벤트를 꺼내지 않는다.** 받은 값이 마지막 이벤트의 인덱스와 같은지만 본다. 파이썬의 음수 인덱스로 이벤트를 꺼내면 `-1`이 마지막 이벤트에 맞는다. 같은지만 보면 음수는 언제나 어긋남이다. core는 채널이 막았다고 믿지 않는다
- [ ] **테스트.** 프리어 아트는 `tests/core/test_run.py`의 `test_한_턴에_승인_대상이_둘이면_재개한_뒤_둘째에서_다시_멈춘다`다
  - 자리가 맞으면 지금과 같다
  - 한 턴에 승인 대상이 둘이면, 첫 일시정지의 자리로 둘째 일시정지에 결정할 때 `NotResumable`이다. 메시지가 두 자리를 든다. 트레이스의 이벤트 수와 마지막 이벤트가 그대로이고, 도구는 불리지 않는다
  - **같은 도구를 같은 인자로 두 번 멈춰도 자리가 가른다.** 도구와 인자로 묶는 안을 거부한 근거의 테스트다
  - 일시정지가 아니면 자리와 무관하게 "일시정지 아님"이다(순서)
  - 꺼진 에이전트여도 자리 어긋남이 먼저다(순서)
  - 음수 자리(`-1`)는 `NotResumable`이다
  - 동시 재개 불변식의 기존 테스트는 같은 자리를 든 둘로 그대로 초록이다

### 채널

- [ ] **본문의 필드를 core로 넘기기만 한다.** 채널은 자리를 먼저 확인하지 않는다. 꺼짐과 재개 불가를 먼저 보지 않는 것과 같은 이유다(`.claude/rules/channel.md`)
- [ ] **승인 경로의 409는 뜻이 넷이 된다.** 일시정지 아님, 형식 1, 꺼짐, 자리 어긋남이고 메시지가 가른다
- [ ] **테스트.** 프리어 아트는 `tests/channel/http/test_router.py`의 두 테스트다. `test_재개가_다시_멈추면_같은_경로로_둘째_결정을_내_끝까지_간다`와 `test_한_루프에서_동시에_온_결정_둘은_하나만_받아들여져_도구가_한_번_불린다`다
  - 422 사례: 자리가 없음, 음수, 추가 필드, 정수가 아닌 것. **정수가 아닌 것은 JSON 정수로 보이는 것까지 넷을 모두 고른다.** 문자열 `"2"`, 실수 `2.0`, 불린 `true`, 소수 `2.5`다. 앞의 셋을 고르지 않은 테스트는 lax로도 초록이다
  - 422이면 `violations`가 그 필드를 가리키고, 포트는 불리지 않는다
  - 자리가 어긋나면 409 봉투이고, 트레이스는 바뀌지 않는다
  - **스트림만 본 클라이언트도 센 수로 다음 결정을 낸다**(스토리 61). 본 프레임 총수에서 1을 뺀 것이 새 일시정지의 자리다. 예를 들어 첫 스트림이 셋이고 재개 스트림이 넷이면 자리는 6이다. 1을 빼지 않으면 409다
  - `openapi.json`이 `create_app().openapi()`와 같고, 두 결정 본문에 그 필드가 required이며 `minimum: 0`이다
  - 두 번 멈추는 기존 테스트 안의 결정 본문 둘은 자리를 싣게 고친다

### CLI

- [ ] **`resume`이 같은 값을 필수 인자로 받는다.** 빠뜨리거나 음수를 주면 인자 오류다. CLI가 마지막 일시정지로 짐작하면 거절의 뜻이 없어진다
- [ ] **멈출 때 찍는 안내 줄 둘(승인, 거부)이 그 값을 싣는다.** 안내한 명령은 그대로 복사해 쓸 수 있어야 한다(`_approval_request` 독스트링의 규칙)
- [ ] **안내 줄의 자리를 어디서 얻는지는 이 티켓이 정한다.** 재개 스트림에는 재생된 사실이 없어, 재개 스트림의 수만 세면 틀린다. 길은 둘이다
  - 트레이스 포트로 읽는다
  - 받은 자리에 재개 스트림의 프레임 수를 더한다. core가 결정 이벤트를 쓰고 나서 내보내고, 뒤의 이벤트도 쓰고 나서 내보내므로 성립한다. `run`의 안내 줄은 스트림 전부의 수로 센다
- [ ] 거절은 기반 타입(`PluginError`)의 길로 가서 진단과 종료 코드 1이다
- [ ] **테스트.** 프리어 아트는 `tests/test_main.py`의 셋이다. `test_안내된_재개_명령을_그대로_실행하면_재개된다`, `test_멈추면_거부_명령도_함께_안내된다`, `test_플러그인_루트를_지정했으면_안내된_재개_명령이_그것을_물려받는다`다
  - 안내 줄 둘이 자리를 싣고, 그대로 실행하면 재개된다
  - 재개가 다시 멈추면 새 안내 줄의 자리가 새 일시정지의 것이다. 재개 스트림만 세면 틀리는 자리다
  - 옛 안내 줄을 그대로 치면 진단과 종료 코드 1이고, 트레이스는 바이트 그대로다
  - 자리를 빼거나 음수를 주면 인자 오류다
