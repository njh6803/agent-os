# 05: 관리 토큰을 넣고 플러그인 목록을 본다 — 첫 e2e

**What to build:** 운영자가 관리 화면을 처음 열면 관리 토큰을 넣는 자리를 본다. 토큰을 넣으면 목록 요청 하나로 확인한다. 거부되면 "관리 토큰이 거부됐다"를 듣고, 토큰은 저장되지 않는다. 받아들여지면 그 탭의 sessionStorage에 남는다. 새로 고쳐도 다시 넣지 않고, 탭을 닫거나 지우기 버튼을 누르면 사라진다. 플러그인은 종류별로 묶여 켜짐과 함께 보인다. 표지 행은 이유를 글자로 보이고, 스킬·모델 행은 "로더가 생기기 전에는 효과가 없다"를 보인다. 운영자 파일이 깨졌으면 목록 대신 그 경로와 이유를 본다. 탭으로 돌아오거나 버튼을 누르면 다시 읽고, 주기 폴링은 없다. 이 흐름이 실제 `serve`와 실제 중계를 지나는 첫 e2e이고, CI의 필수 검사 안에서 돈다.

**나누지 않는 짝이다.** 첫 e2e 흐름과 `ci.yml`의 e2e 단계(브라우저 설치 포함)가 한 PR에 든다. 나뉘면 e2e가 필수 검사 밖에서 돈다. ADR 0021 이력이 거부한 모양이다. 이 티켓은 페이지 이음매(Vitest jsdom + Testing Library + MSW)를 처음 세운다. 이 기능의 첫 TS 페이지 테스트다. 뒤의 화면(06·07·08)은 여기서 세운 토큰·새로 고침·에러·문구의 규칙을 물려받는다.

근거는 `.scratch/web-admin/spec.md`의 여러 절이다. "관리 화면 — 토큰", "관리 화면 — 화면들"의 플러그인 목록, "새로 고침과 상태", "문구와 렌더링", "주 이음매 — 페이지", "e2e" 절이다. ADR 0015·0017·0019·0021도 근거다.

**Blocked by:** 03(생성 클라이언트), 04(래퍼와 중계. 토큰을 저장하고 싣는 화면은 그 뒤다)

**Status:** ready-for-agent

### 페이지 이음매

- [ ] **`components/pages/`의 클라이언트 컴포넌트를 Vitest(jsdom)에서 Testing Library로 그린다.** 생성 클라이언트는 그대로 두고, MSW가 HTTP를 받는다. 훅(SWR), 스토어(Zustand), organisms·molecules·atoms는 따로 이음매를 두지 않고 이것으로 덮는다. Testing Library는 dev 의존성이다(ADR 0021 이력)
- [ ] **MSW 핸들러의 응답 본문은 생성 타입(`components["schemas"]`)으로 적는다.** 계약이 바뀌면 핸들러가 컴파일에서 깨진다(스토리 81)
- [ ] **격리.**
  - 테스트마다 SWR 캐시를 새로 둔다(`provider`)
  - 스토어와 sessionStorage를 비운다
  - 처리하지 않은 요청은 에러다(`onUnhandledRequest: "error"`)
- [ ] 데이터는 SWR 훅이 가져온다. 컴포넌트는 `useSWR`이나 클라이언트를 직접 부르지 않는다. API는 organisms 이상만 부른다
- [ ] **01이 세운 web 규칙(씨앗 셋)이 이 티켓의 실제 파일을 Read 도구로 열 때 실리는지 본다(Bash로 읽거나 Write로 새로 만들 때는 원래 안 실린다).** pages, templates, 스토어, SWR 훅이 이 티켓에서 처음 생긴다. 실리지 않으면 그 규칙의 `paths`를 고친다

### 관리 토큰

- [ ] **관리 토큰이 없으면 입력 화면이다.** 넣은 토큰은 확인 요청의 `Authorization`에 실린다. 401이면 "관리 토큰이 거부됐다"를 보이고 저장하지 않는다
- [ ] **Zustand 스토어가 토큰을 들고 persist를 sessionStorage에 건다.** `partialize`로 토큰만 저장한다. sessionStorage에는 토큰만 있고 다른 상태는 없다. localStorage는 비어 있다(스토리 2). 새로 그려도 토큰이 남는다(스토리 3)
- [ ] **관리 요청이 401을 받으면 관리 토큰을 지우고 입력 화면으로 돌아간다.** 메시지는 "관리 토큰이 거부됐다"다(스토리 6)
- [ ] **토큰 지우기 버튼이 있다.** 채널 토큰까지 지우게 넓히는 것은 08이다
- [ ] **토큰이 URL, 화면의 글자, 콘솔 어디에도 없다**(스토리 9)
  - 위치의 경로와 질의, 문서의 글자를 본다
  - 콘솔 출력을 가로채 본다
  - 토큰 입력칸은 가린 입력이라 값이 글자로 보이지 않는다
  - 에러 표시에도 싣지 않는다
- [ ] 관리 요청의 헤더에 관리 토큰이 실리는 것을 핸들러가 본다. 채널 토큰과의 교차는 08이 본다

### 플러그인 목록 (`GET /plugins`)

- [ ] **행은 겉 셋(`kind`, `name`, `enabled`)에 `manifest`나 `reason` 하나다.** 종류(에이전트, MCP, 스킬, 모델)별로 묶인다. 켜짐이 보인다. 스위치로 바꾸는 것은 06이다
- [ ] 표지 행은 이유를 글자로 보인다(스토리 13)
- [ ] 스킬과 모델 행에는 "로더가 생기기 전에는 효과가 없다"가 보인다(스토리 21)
- [ ] 운영자 파일이 깨지면 목록 전체가 500 봉투다. 화면은 목록 대신 그 `message`와 `request_id`를 보인다(스토리 16, ADR 0017)
- [ ] **문구는 한국어이고 용어집의 말을 쓴다.** 각 항목의 _Avoid_(예: 콘솔, 대시보드, 비활성)를 쓰지 않는다

### 새로 고침과 에러

- [ ] **포커스, 버튼, 쓰기 직후만 다시 읽는다.**
  - 창 포커스에 목록을 다시 읽는다(스토리 33)
  - 시간이 흘러도 스스로 다시 읽지 않는다. 가짜 시계로 밀어 본다(스토리 35)
  - 새로 고침 버튼이 다시 읽는다(스토리 34)
- [ ] **처음 불러오는 중(`isLoading`)은 자리표시, 다시 확인하는 중(`isValidating`)은 작은 표시다.** 다시 확인하는 동안 이미 보인 행이 남는다(스토리 36)
- [ ] **에러는 봉투의 `message`와 `request_id`를 보인다.** 봉투가 아닌 실패는 "서버에 닿지 못했다"로 보인다(스토리 37). MSW의 네트워크 에러로 잰다. 네트워크 실패와 중계가 상류에 닿지 못한 것이 여기 든다

### 첫 e2e (짝)

- [ ] **Playwright로 실제 `serve`와 실제 중계를 지난다.**
  - e2e는 실제 `serve`의 둘째 구동자다. 모델을 부르지 않는다
  - `serve`의 포트를 빌드 전에 정하고, 시작 래퍼로 `build` 뒤 `start`를 띄운다. `dev`는 `rewrites`를 빌드 산출물이 아니라 설정에서 읽어 운영과 다른 길을 잰다
- [ ] **픽스처 플러그인 루트는 테스트 준비가 임시 디렉터리에 쓴다.** MCP 매니페스트가 그 기계의 파이썬 인터프리터 경로를 들어야 해서 커밋할 수 없다. `tests/test_main.py`가 `sys.executable`로 짓는 것과 같다. 목록에 종류별 행과 표지 행이 보이도록 채운다
- [ ] **토큰은 테스트만 아는 값이다.** 준비가 만들어 두 프로세스의 환경에 넘기고, 화면에는 테스트가 입력한다. 커밋하지 않는다
- [ ] **흐름: 토큰을 넣고 플러그인 목록을 본다.** 읽기 흐름의 나머지(실행 목록과 실행 하나)는 07이 잇는다
- [ ] **브라우저가 없어 건너뛰면 실패다.** 윈도우와 CI의 ubuntu에서 모두 돈다. 운영체제별 명령에 기대지 않는다
- [ ] **`ci.yml`의 `verify` 잡의 한 단계다.** 브라우저를 그 잡에서 설치한다. 브라우저 캐시와 잡 시간은 이 티켓이 본다. 이 PR도 `.github/workflows/`를 바꾼다. 대기열 50이 병합되지 않았으면 claude-review의 코멘트 0개 가드가 꺼진다. 그 경우 병합 전에 코멘트를 손으로 본다
- [ ] **`CLAUDE.md` 검증 명령 절에 e2e 명령을 괄호로 적는다.** LLM 테스트처럼 적는다. 로컬에서 칠 계기는 중계, 시작 래퍼, api-client, 서버 라우트를 건드렸을 때다(`operations.md` 머리의 "실제로 돌려 통과한 명령만 적는다")
- [ ] **게이트 훅이 이 티켓의 실제 e2e 명령을 파이프 뒤에서 경고한다.** 01은 스크립트 이름에 기대지 않는 모양으로 잡았다. 그 모양이 실제 명령을 잡는지 본다. `tools/hook_payloads.toml`에 그 명령의 발동할 입력과 발동하지 말아야 할 입력을 더해 `tools/run_hooks.py`로 확인한다

### 서버가 중계에 기대는 성질 — 파이썬 테스트 둘

둘 다 지금 테스트가 없다(명세 검토). 이음매는 새것이 아니다. 채널 테스트와 같은 `create_app()` + `ASGITransport`다. 이미 참인 성질을 고정하는 테스트라 처음부터 초록이다. 그래서 빨강은 `tools/mutate.py`로 본다. 예를 들어 미들웨어가 `OPTIONS`를 통과시키게 하거나, 간격을 30 이상으로 바꾼다.

- [ ] **다른 출처의 preflight는 토큰 없이 401이다**(스토리 65). `tests/test_server.py`에 관리 경로 하나와 채널 경로 하나의 토큰 없는 `OPTIONS`가 401이라는 테스트를 둔다. ADR 0011 이력은 "미들웨어는 메서드를 가르지 않는다"고 적었지만, 파이썬 테스트에 `OPTIONS`가 한 번도 없다
- [ ] **keepalive 간격이 중계의 침묵 한도(30초)보다 짧다**(스토리 67)
  - 기존 `test_모델이_조용한_동안_keepalive_주석이_나간다`는 `fastapi.routing`의 이름 하나를 줄여 쓴다. 그 이름을 읽어 30보다 작은지 단언한다
  - 이 명세의 "바깥 행동만"의 예외다. 행동으로 재려면 기본 스위트에서 15초 넘게 기다려야 한다. 예외라는 것을 독스트링에 적는다
  - 기존 테스트가 이미 같은 이름에 기대므로 새로 느는 결합은 없다. 이름이 사라지면 두 테스트가 함께 깨지고, 그것이 올림에서 다시 볼 신호다
- [ ] 이 둘은 `src/`를 바꾸지 않는다. 그래서 `-m llm`은 돌리지 않는다

### 문서

- [ ] **실제 `serve`를 띄우는 것이 하나라고 적은 문장 둘을 고친다.** `.claude/rules/http.md`와 `tests/test_main.py`의 `serve` 판정 테스트 독스트링이다. e2e가 서면 실제 `serve`를 띄우는 것이 둘이 되고, 그중 매 푸시에서 도는 것은 e2e 하나다. 이 저장소에서 "둘째 구동자"는 이미 같은 앱을 ASGI로 직접 부르는 것의 이름이다. 그래서 e2e는 "실제 `serve`의 둘째 구동자"라고 부른다
- [ ] `README.md`의 관리 화면을 띄우는 법에 관리 토큰을 넣는 줄을 더한다

### 01이 남긴 메모

- **게이트 훅의 모양.** 01은 `playwright test`가 명령 위치에 선 것을 게이트로 잡았다. 앞에 `pnpm exec`, `pnpm -C <디렉터리> exec`, `npx`가 와도 된다. e2e를 스크립트(예: `pnpm -C web e2e`)로 치게 하면 `tools/hook_bash_gate_pipe.py`의 `_GATE`와 그 테스트, 페이로드를 함께 넓힌다
- **CI의 자리.** 01의 `verify` 잡은 파이썬 단계 뒤에 Node 24(setup-node)와 pnpm(pnpm/action-setup, 락파일로 스토어 캐시)을 세우고 `pnpm -C web install --frozen-lockfile`과 `pnpm -C web verify`를 돈다. e2e 단계는 그 뒤에 선다
- **`operations.md` 가드레일 머리.** "자동 검사는 둘이고 내용은 같다"의 예외는 지금 둘(훅 러너, 인용 대조)이다. e2e가 CI에만 서면 셋째 예외가 되므로 그 문장과 검사 목록에 e2e를 더한다

### 03이 남긴 메모

- **앱은 생성 클라이언트를 워크스페이스 의존성으로 든다.** `"@agent-os/api-client": "workspace:*"`다. 패키지는 TS 원본을
  내보낸다(`exports`의 `.`이 `./src/index.ts`). Next가 그것을 번역하는지(`transpilePackages`가 필요한지) 실제 앱에서 본다.
- **관리 클라이언트는 `createAdminClient(관리 토큰)`이다.** `baseUrl`은 `location.origin`에서 만든 절대 주소라 jsdom의
  페이지 테스트가 제품과 같은 코드를 지난다. 관리 토큰만 실린다는 헤더 단언이 이 티켓의 몫이다.
- **atoms·molecules가 이 패키지를 import하면 판정자가 빨갛다.** 03은 임시 트리의 앱 자리에 실제 패키지로 가는 junction을
  두고 쟀다. 실제 앱의 링크에서도 같은 변이가 빨간지 본다.
- **응답의 배열은 가변 타입이다.** `--immutable`을 거뒀다(ADR 0021의 2026-09-29 이력). SWR이 든 값을 제자리에서 바꾸지
  않는 것은 타입이 막지 않는다.
- **판정자가 아직 막지 않는 HTTP 길이 셋 있다.** 03의 셀프 리뷰가 찾았다. 앱이 `openapi-fetch`를 직접 import해 클라이언트를
  만드는 것, `EventSource`나 `XMLHttpRequest`를 쓰는 것, 상대 경로로 `packages/api-client/src/*`를 import하는 것(로컬로
  분류되어 03의 모듈 이름 정책을 피한다)이다. 앱 코드가 처음 API를 부르는 이 티켓에서 막을지 정한다. 막으면 경로와
  무관하게 쓰고 `web/eslint.config.test.ts`에 사례를 붙인다(`.claude/rules/web-workspace.md`).

- [ ] `CLAUDE.md`의 검증 명령과 e2e가 모두 초록이다
