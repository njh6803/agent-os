# 08: 채널 토큰을 넣고, 멈춘 실행에 화면이 본 그 일시정지로 결정을 내린다

**What to build:** 운영자가 채널 토큰을 넣으면 멈춘 실행에 결정 자리가 선다. 채널 토큰은 선택이다. 넣지 않아도 관리 화면의 나머지를 모두 쓴다. 승인자는 무엇을 승인하는지, 곧 도구 이름과 인자를 보고 결정한다. 허가는 버튼 하나이고, 거부는 사유를 적어야 보낼 수 있다. 결정은 화면이 트레이스 상세에서 읽은 일시정지의 자리를 든다. 보내면 재개된 실행의 이벤트가 받는 대로 붙고, 스트림이 끝나면 트레이스를 다시 읽는다. 다시 멈췄으면 새 결정 자리가 선다. 다른 곳(CLI나 다른 탭)이 먼저 결정했으면 409 메시지를 보고 지금의 일시정지를 본다. 에이전트나 그것이 쓰는 MCP가 꺼졌으면 미리 알리고 버튼을 막는다. 스트림이 끊겨도 결정을 다시 보내지 않는다. 다시 보낸 결정은 다른 일시정지에 닿을 수 있기 때문이다.

이 기능의 마지막 티켓이다. 설계에서 사용자가 골랐다(일지 2026-09-28-06, R1 범위). 다른 티켓이 넘긴 것을 여기서 받는다. 받는 기준은 모두 아래 절에 있다.

- 03: 결정 요청의 헤더 행동, 술어를 지나지 못한 프레임을 글자로 보이는 것
- 04: `compress: false`의 회귀를 잡는 조각 스트림 e2e, `README.md`의 채널 토큰 줄
- 05: 토큰 지우기를 두 토큰으로 넓히는 것, 두 토큰이 맡지 않은 면에 실리지 않는지의 교차
- 06: 켜고 끄기 e2e에서 결정 버튼이 막히고 풀리는 부분
- 07: 결정 자리가 설 실행 하나의 화면

모델은 부르지 않는다. 결정의 자리는 모델 호출보다 앞, `resume()`의 첫 걸음에서 판정된다(02). 승인 뒤 모델을 부르는 경로는 기존 HTTP LLM 테스트가 잰다.

근거는 `.scratch/web-admin/spec.md`의 여러 절이다. "관리 화면 — 토큰"의 채널 토큰과 401, "관리 화면 — 화면들"의 "실행 하나" 첫 항목과 "결정", "주 이음매"의 결정, "e2e"의 결정 흐름 절이다. ADR 0014의 2026-09-28 이력, ADR 0015·0017·0019도 근거다.

**Blocked by:** 06(켜고 끄기, 그 e2e 흐름), 07(실행 하나)

**Status:** done

### 채널 토큰

- [x] **채널 토큰은 선택이다.** 넣지 않아도 관리 화면의 나머지를 모두 쓴다(스토리 4). 넣었을 때만 결정 자리가 보인다(스토리 5). 저장은 관리 토큰과 같은 스토어와 sessionStorage이고, `partialize`로 토큰 둘만 둔다
- [x] **확인할 채널의 읽기 경로가 없다**(ADR 0014가 거부했다). 그래서 틀린 채널 토큰은 첫 결정의 401로 드러난다
- [x] **결정이 401을 받으면 채널 토큰만 지운다.** 결정 자리에 "채널 토큰이 거부됐다"를 보이고, 관리 화면은 그대로 쓴다(스토리 7)
- [x] **관리 요청이 401을 받으면 관리 토큰만 지운다.** 05가 세운 처리다. 두 토큰이 함께 있는 것은 이 티켓이 처음이라 "만"을 여기서 잰다. 채널 토큰은 sessionStorage에 남는다
- [x] 토큰 지우기 버튼이 두 토큰을 모두 지운다(스토리 8)
- [x] **토큰은 자기가 맡은 면에만 실린다**(스토리 10). 관리 요청에는 채널 토큰이, 결정 요청에는 관리 토큰이 실리지 않는다. 핸들러가 헤더를 본다
- [x] 채널 토큰도 URL, 화면의 글자, 콘솔 어디에도 없다(스토리 9)
- [x] `README.md`의 관리 화면을 띄우는 법에 채널 토큰의 줄을 더한다

### 결정 자리

- [x] **보이는 조건은 셋이다.** 채널 토큰이 있고, 실행 상태가 일시정지이고, 형식 2 트레이스다. 형식 1이면 결정 자리를 두지 않고 이유를 보인다(스토리 52)
- [x] **상태는 트레이스에서 읽는다.** 상세의 응답에는 요약이 없기 때문이다
  - 에이전트는 첫 이벤트(`run_started`)의 `agent`다
  - 일시정지인지는 마지막 이벤트의 `type`이 `run_paused`인지로 본다
  - core `run_status()`의 이 한 갈래만 TS로 다시 쓴다. 상태의 이름을 보이는 것은 목록의 요약에 맡긴다
- [x] **무엇을 결정하는지는 마지막 이벤트(`run_paused`)의 도구와 인자다**(스토리 38)
- [x] **결정의 자리는 트레이스 상세에서 읽은 그 인덱스다**(ADR 0019 이력). 화면이 자리를 짐작하거나 스트림에서 세지 않는다. 결정 뒤에는 트레이스를 다시 읽기 때문이다
- [x] **허가는 버튼 하나다**(스토리 39). 본문에 판별자와 그 인덱스가 실린다
- [x] **거부는 사유를 적어야 보낼 수 있다**(스토리 40, 41). 다듬어 비면 보내지 않는다. 서버의 422(`body.deny.reason`)가 오면 `violations`를 사유 옆에 보인다
- [x] 결정의 승인자는 `serve`를 띄운 OS 사용자로 기록된다. 화면은 승인자를 고르지 않는다(스토리 53, ADR 0015). 운영자가 그것을 알 자리는 결정 자리의 문구나 `README.md`다. 명세의 구현 결정에 없는 것이라 이 티켓이 고른다

### 재개 스트림

- [x] **보내면 결정 버튼을 막는다.** 재개 스트림의 이벤트는 받는 대로 트레이스 아래에 붙인다(스토리 42). 스트림이 닫히기 전에 첫 이벤트가 화면에 있다
- [x] **스트림이 결말 이벤트로 끝나거나, 결말 없이 끊기면 트레이스를 다시 읽는다**(스토리 43)
- [x] **결정을 다시 보내지 않는다**(스토리 46, ADR 0019). 결정 요청은 정확히 한 번이다. 결말 없이 끊겼으면 두 가지를 보인다
  - 스트림이 끊겼고, 실행은 서버에서 계속된다
  - 창을 닫거나 떠나도 실행은 끝까지 가고, 돌아오면 트레이스로 이어 본다(스토리 45)
- [x] **다시 읽은 트레이스가 새 일시정지에서 끝나면, 새 자리로 결정 자리가 다시 선다**(스토리 44)
- [x] **술어를 지나지 못한 프레임은 원문 그대로 글자로 보인다.** 뒤의 프레임도 계속 붙는다. 기록의 원천은 스트림이 끝난 뒤 다시 읽는 트레이스다

### 409와 꺼짐

- [x] **409를 받으면 봉투의 메시지를 보이고, 트레이스와 `/plugins`를 다시 읽는다**(스토리 47, 48, 51)
  - 409의 뜻 넷은 모두 같은 처리다. 자리 어긋남, 일시정지 아님, 형식 1, 꺼짐이고, 가르는 것은 메시지다
  - `/plugins`도 다시 읽는 이유가 있다. 꺼짐의 409 뒤에는 버튼을 막는 미리 알림이 그 목록에 기댄다
- [x] **꺼짐을 미리 알린다**(스토리 50, ADR 0019)
  - 실행의 에이전트(`run_started`의 `agent`)와 그 매니페스트의 `mcp`를 `/plugins`의 행과 잇는다
  - 무엇이 꺼졌는지 보이고 버튼을 막는다
  - 에이전트 행이 표지이거나 없으면 미리 알 수 없다. 그 경우는 서버의 봉투가 말한다

### e2e — 결정 흐름

- [x] **픽스처 에이전트는 모델 없이 승인 대상 도구를 `ctx.tool()`로 직접 부른다.** 도구는 기존 MCP 픽스처 서버(`tests/adapters/mcp_fixture_server.py`)가 준다. 그래서 결정 뒤의 재개가 모델 없이 끝까지 간다
- [x] **멈춘 실행은 테스트 준비가 채널 토큰으로 `POST /runs`를 보내 만든다.** 화면 밖의 요청이다
- [x] **허가.** 멈춘 실행을 허가하면 재개 스트림이 화면에 붙고, 실행이 끝남으로 바뀐다. 도구가 실제로 불렸다는 것은 트레이스의 `tool_called`로 본다
- [x] **오래된 화면.**

  - 테스트 준비가 채널 토큰으로 그 실행의 첫 일시정지를 직접 허가한다. 실행은 둘째에서 다시 멈춘다
  - 그다음 화면에서 옛 일시정지를 허가한다. 409 메시지가 보이고, 새 일시정지가 보이고, 둘째 도구는 불리지 않았다
  - "다른 곳"은 둘째 탭이 아니라 준비의 요청이다. 탭을 바꾸면 포커스 재검증이 먼저 새 일시정지를 읽어 옛 자리를 보낼 기회가 사라질 수 있다
- [x] **재개 스트림이 조각으로 온다.** 첫 이벤트가 결말보다 먼저 화면에 있다. 04의 `compress: false`가 빠지면 여기서 빨개진다. `tools/mutate.py`로 그 설정을 되돌려 빨강을 본다
- [x] **06의 켜고 끄기 흐름에 더한다.** 스위치로 에이전트를 끄면 그 에이전트의 멈춘 실행에서 결정 버튼이 막힌다. 다시 켜면 풀린다

### 03이 남긴 메모

- **결정은 `Decision` 타입의 값으로 넘긴다.** `components["schemas"]["Decision"]`로 적은 값을 `body`에 주면
  `parseAs: "stream"`의 `data`가 `ReadableStream`이다. 인라인 객체 리터럴이면 openapi-fetch 0.17.0의 옵션 추론이 제약으로
  떨어져 `data`가 `unknown`이 되고, `readFrames(data)`에서 컴파일이 실패한다(`probes/immutable_readable.sh`).
- **`readFrames(data)`가 프레임을 준다.** `{ kind: "event", event }`는 이벤트이고, `{ kind: "raw", raw }`는 술어를 지나지
  못한 프레임의 `data` 원문이다. 원문을 글자로 보이는 것이 이 티켓이다. 스트림이 프레임 한가운데서 끝나면 남은 것을
  프레임 하나로 닫아 같은 길로 넘긴다(술어를 지나면 이벤트, 못 지나면 원문).
- **연결은 요청의 `signal`로 끊는다.** 화면이 떠날 때 `AbortController`를 끊으면 다음 조각을 기다리던 읽기가 그 에러로
  끝나고 `readFrames`가 그 에러를 던지며 잠금을 푼다. 반복자의 `return()`이나 `data.cancel()`로는 끊지 못한다. 기다리는
  동안 스트림이 잠겨 있다. 브라우저의 fetch가 본문 스트림을 끝내는 것은 03이 손으로 만든 스트림으로만 쟀다. MSW를 지나는
  페이지 테스트에서 끊김이 실제로 그 모양인지 본다.
- **채널 클라이언트는 결정 경로 하나만 안다.** `createChannelClient(채널 토큰)`이다. 채널 토큰만 실린다는 헤더 단언이 이
  티켓의 몫이다.
- **다시 내보낸 `Event`는 DOM 전역 `Event`와 이름이 같다.** `@agent-os/api-client`의 `index.ts`가 계약의 스키마 이름
  그대로 `type Event`를 내보낸다. 그것을 import한 파일에서는 DOM의 `Event`(예: 입력 핸들러의 인자)가 가려져
  `globalThis.Event`로 적어야 한다. import를 빠뜨린 파일에서는 `Event`가 DOM 전역으로 조용히 풀린다. `type`이 `string`이라
  `event.type === "run_finished"` 같은 비교도 컴파일된다. import할 때 `type Event as RunEvent`처럼 이름을 바꿔 쓰면 두
  쪽을 다 피한다. PR #101의 둘째 claude-review가 남겼다(Minor).

### 05가 남긴 메모

- **스토어는 `apps/admin/stores/tokens.ts`다.** 채널 토큰을 더하고 `partialize`에 넣는다. `clearTokens`가 두 토큰을 지우게
  넓힌다. 페이지 테스트 "받아들여진 관리 토큰은 sessionStorage 에만 남고…"는 저장된 잎이 토큰 하나라고 센다. 두 토큰으로
  넓힌다. 넣는 자리의 알림(`adminTokenNotice`)과 받아들인 횟수(`adminTokenGeneration`)는 저장하지 않는다. 채널 토큰의 알림도 같다.
- **hydration 가드(`hooks/useHydrated.ts`).** 서버의 그림과 hydration의 첫 그림은 토큰을 보지 않는다. 채널 토큰으로 갈리는
  결정 자리도 그 뒤에 선다. 가드가 막는 것은 서버가 미리 그린 HTML에 넣는 칸이 박혀 새로 고칠 때 번쩍이는 것이고, e2e가
  그 칸이 문서에 붙는지로 본다. 두 그림의 어긋남은 zustand가 막는다(`probes/admin_pages_mutations.mjs`).
- **e2e의 준비는 `apps/admin/e2e/stack.ts`다.** 채널 토큰을 만들어 `serve`에만 넘기고 워커에는 넘기지 않는다. 멈춘 실행을
  만드는 `POST /runs`와 오래된 화면의 "다른 곳"은 채널 토큰을 아는 준비에서 보낸다. 화면에 넣을 채널 토큰이 필요하면
  `e2e/env.ts`에 더한다.
- **e2e의 콘솔 단언은 401만 봐준다.** 브라우저는 실패한 응답을 콘솔 에러(`Failed to load resource`)로 찍는다. 409를 받는
  흐름은 그것도 봐줘야 한다.
- **Next가 페이지에 두는 경로 알림도 `role="alert"`다.** e2e에서 alert를 찾을 때 글자로 거른다.
- **아이콘은 아직 아무도 들이지 않았다.** 01의 메모(lucide-react의 서브패스 import와 그 타입)는 아이콘을 처음 들이는
  티켓의 몫이다.
- **MSW 3.0.0의 SSE.** `jsdom_sse.sh`는 msw 2.15.0으로 쟀다. 3.0.0에서 `ReadableStream` 응답이 조각마다 오는지는 재지 않았다.
  이 티켓의 첫 재개 스트림 테스트가 본다.

### 06이 남긴 메모
