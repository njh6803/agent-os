# 06: 플러그인 하나를 열어 보고, 스위치로 켜고 끈다

**What to build:** 운영자가 플러그인 하나를 열면 매니페스트를 통째로 본다. 승인 대상 도구와 쓰는 MCP 서버를 여기서 확인한다. 매니페스트가 깨졌으면 그 경로와 이유를 본다. 목록의 행마다 스위치가 있어 플러그인을 끄고 켠다. 누르면 서버에 보내고, 스위치는 서버에서 다시 읽은 값을 따른다. 화면이 값을 먼저 뒤집어 두지 않는다. 표지 행도 끌 수 있다. 끄면 플러그인 루트에 운영자 파일이 생긴다.

05가 세운 토큰, 새로 고침, 에러의 규칙을 그대로 물려받는다. 켜고 끄기는 이 기능의 쓰기 둘 가운데 하나다. 하나 더 있는 결정은 08이다. 에이전트를 끄면 그 에이전트의 멈춘 실행에서 결정 버튼이 막혀야 한다. 그 부분은 결정 자리가 서는 08이 이 티켓의 e2e 흐름에 더한다.

근거는 `.scratch/web-admin/spec.md`의 "관리 화면 — 화면들"에서 "플러그인 하나"와 "켜고 끄기", 그리고 "주 이음매"와 "e2e"의 켜고 끄기 절이다. plugin-toggle의 계약(ADR 0017)도 근거다.

**Status:** done

- [x] **깨진 매니페스트는 500 봉투의 `message`를 보인다.** 경로와 이유가 든다(스토리 15). `request_id`도 함께 보인다
- [x] 없는 이름은 404이고, 봉투의 메시지를 보인다

### 켜고 끄기 (`PUT /plugins/{kind}/{name}/enabled`)

- [x] **스위치를 누르면 PUT을 보내고, 204 뒤에 목록과 그 행을 다시 읽는다**(스토리 17, 18). 본문은 `{"enabled": false}` 모양이다. 화면이 값을 먼저 뒤집어 두지 않는다. "그 행"은 떠 있지 않은 플러그인 하나라 캐시를 버린다(아래 "이 티켓이 정한 것")
- [x] **누른 뒤 응답까지는 스위치를 막는다.** 응답 전의 두 번째 누름은 요청을 더 보내지 않는다. PUT은 멱등이라 두 번 가도 틀리지 않는다. 다만 두 응답이 엇갈려 목록을 두 번 다시 읽을 까닭이 없다(스토리 22). 막는 것은 목록을 다시 읽을 때까지로 넓혔다(아래)
- [x] **실패하면 메시지를 보이고, 스위치는 다시 읽은 값이다**(스토리 19). 메시지는 목록의 머리에 보인다(아래)
- [x] 표지 행도 끌 수 있다(스토리 20, plugin-toggle 스토리 6)
- [x] 쓰기 직후의 다시 읽기는 05의 새로 고침 규칙 가운데 "쓰기 직후"다

### 05가 남긴 메모

- **페이지 이음매의 자리는 `apps/admin/testing/`의 셋이다.** `network.ts`는 MSW 서버 `network`, 주소 `api(path)`, 봉투
  `envelope()`, 생성 타입 별칭을 든다. `render.tsx`의 `renderPage`는 그릴 때마다 SWR 캐시를 새로 둔다. `setup.ts`는
  Vitest `pages` 프로젝트의 준비다. 스토어와 브라우저 저장소를 비우고, 처리하지 않은 요청이 있으면 그 테스트를 빨갛게
  한다. 페이지 테스트는 `components/**/*.test.tsx`이고 jsdom에서 돈다(`web/vitest.config.ts`).
- **MSW 3.0.0의 옵션 이름은 `onUnhandledFrame`이다.** 명세의 `onUnhandledRequest`는 2의 이름이다. `"error"` 전략은 요청을
  네트워크 에러로 끝내고 콘솔에 찍기만 한다. 화면이 그것을 "서버에 닿지 못했다"로 보이면 테스트가 초록일 수 있어서
  `request:unhandled` 사건을 받아 적고 테스트 끝에 본다.
- **읽기 정책은 `hooks/queries/plugins`의 `READ`다.** 포커스 재검증만 켜고 주기·재연결·실패 뒤 재시도를 끈다. 플러그인
  하나의 훅도 같은 정책을 쓴다. 쓰기 직후의 다시 읽기는 SWR의 `mutate`다. 목록 키는 `pluginKeys.list(generation)`이다.
  토큰 대신 토큰을 받아들인 횟수(스토어의 `adminTokenGeneration`)를 싣는다. 토큰마다 캐시와 진행 중인 요청을 가르기
  위해서다. 플러그인 하나의 키도 그것을 싣는다. SWR 2.5는 마운트한 뒤 5초(`focusThrottleInterval`)와 요청 뒤 2초(`dedupingInterval`) 동안 포커스를 흘려보낸다.
  포커스 테스트는 가짜 시계(`shouldAdvanceTime`)로 그 너머로 민다.
- **실패의 표시.** 요청 함수는 데이터가 아니면 `RequestFailure`(`api/failure`)를 던진다. 화면은 `describeFailure()`와
  `FailureNotice`(molecule)로 봉투의 `message`·`request_id`를, 봉투가 아니면 "서버에 닿지 못했다"를 보인다. 관리 요청의
  401은 훅의 fetcher가 관리 토큰을 내려놓는다(`readPlugins`). 새 관리 훅도 같은 자리에서 한다. (06) `readPlugins`는
  없는 이름이었다. 그때의 자리는 `listOrReject`였고 06부터 `orRejectAdminToken`이다.
- **목록은 다시 읽다 실패하면 이미 보인 행을 지운다(스토리 16).** 켜고 끄기가 실패한 뒤 "다시 읽은 값이 스위치를 정한다"와
  만나는 자리다. 다시 읽기도 실패하면 스위치 대신 실패가 보인다.
- **e2e의 준비는 `apps/admin/e2e/stack.ts`다.** 플러그인 루트(에이전트 `echo`, 표지 `broken`, mcp `fixture`, 꺼진 스킬
  `summarize`, 모델 `sonnet`)를 임시 디렉터리에 쓴다. 켜고 끄기 흐름이 볼 루트 경로는 아직 테스트에 넘기지 않는다.
  `e2e/env.ts`에 더한다. 흐름들은 `serve` 하나를 함께 쓰고 차례로 돈다(`workers: 1`). 앞 흐름이 바꾼 켜짐이 뒤 흐름에 남는다.
- **Next가 페이지에 두는 경로 알림도 `role="alert"`다.** e2e에서 alert를 찾을 때 글자로 거른다. 페이지 테스트(jsdom)에는
  그것이 없다.
- **아이콘은 아직 아무도 들이지 않았다.** 01의 메모("lucide-react 1.48에는 `exports` 맵이 없다. 서브패스 import의 모양과
  그 타입이 서는지 본다")는 아이콘을 처음 들이는 티켓의 몫이다. 스위치에 아이콘을 쓰면 여기서 본다.

### 이 티켓이 정한 것 (2026-09-30, PR에서 사용자가 본다)

- **플러그인 하나는 주소가 있는 화면이다.** 동적 라우트 `app/plugins/[kind]/[name]/page.tsx`가 주소의 두 조각을 그대로
  `components/pages/PluginPage`에 넘긴다(라우팅만 한다, ADR 0021). 새로 고침과 뒤로 가기가 되고, 07의 실행 하나도 같은
  모양으로 설 수 있다. 목록 행의 이름이 링크이고 표지 행도 연다(스토리 15). 표지의 이름은 패턴 밖일 수 있어 링크에
  조각으로 적는다(`encodeURIComponent`).
- **주소의 종류는 페이지가 가린다.** 넷이 아니면 요청을 보내지 않고 "플러그인의 종류가 아니다"를 보인다. 생성 클라이언트의
  경로 파라미터가 종류의 유니온이라 좁혀야 부를 수 있다. 가리는 함수(`isPluginKind`)는 `api/plugins`에 있고 종류 넷을
  `Record<PluginKind, true>`로 적어 계약의 종류가 바뀌면 컴파일에서 깨진다. `app/`은 pages와 templates만 import해 거기서
  가리지 않는다.
- **토큰 문을 화면들이 함께 쓴다(`components/pages/AdminScreen`).** 05의 첫 화면에 있던 hydration 가드, 관리 토큰을 넣는
  자리, 토큰 지우기를 옮겼다. 첫 화면과 플러그인 하나가 이 문을 지나고, 07·08의 화면도 지난다. 라우트가 아니라서 `"use
  client"`는 라우트가 부르는 화면(HomePage, PluginPage)에만 둔다.
- **스위치는 목록의 행에만 있다.** 플러그인 하나는 켜짐을 글자로만 보인다(티켓의 "목록의 행마다 스위치").
- **"목록과 그 행을 다시 읽는다"의 "그 행"은 플러그인 하나다.** 204든 실패든 훅이 목록을 다시 읽고, 그 플러그인 하나는
  캐시의 값을 버리며 다시 읽는다(`mutate(key, undefined, { revalidate: true })`). 스위치가 있는 목록에는 플러그인 하나가
  떠 있지 않고, SWR의 `mutate`는 마운트되지 않은 키에 요청을 보내지 않는다. 값만 두면 전에 열어 본 플러그인을 다시 열 때
  옛 켜짐이 "다시 확인하는 중"과 함께 먼저 보였다(셀프 리뷰의 명세 축). 캐시를 버려 다음에 열 때는 자리표시 뒤에 새 값이
  선다. 페이지 테스트가 캐시 하나를 세 번의 그리기에 넘겨 화면을 옮겨 다니는 운영자를 잰다(`renderPage`의 `cache`).
- **화면을 열 때의 읽기는 다시 읽기의 계기가 아니라 그 화면의 첫 읽기다.** 명세의
  "포커스, 버튼, 쓰기 직후만 다시 읽는다"는 열린 화면이 스스로 다시 읽는 때를 말한다. 캐시가 있으면 SWR이 그것을 먼저
  보이고 "다시 확인하는 중"을 단다(`revalidateIfStale`의 기본값). 05의 목록도 같다.
- **스위치는 목록을 다시 읽을 때까지 막는다.** 명세는 "응답까지"다. PUT의 응답에서 풀면 다시 읽기 전의 옛 값인 스위치를
  한 번 더 눌러 같은 PUT이 다시 갈 수 있다. 막힘이 풀릴 때 스위치는 서버에서 다시 읽은 값이다. 스위치는 제어하는
  체크박스(`role="switch"`)라 누른 뒤 React가 목록의 값으로 되돌린다. 화면이 값을 먼저 뒤집지 않는 것은 그 기본 동작이다.
- **켜고 끄기의 실패는 목록의 머리에 보인다.** 봉투의 메시지와 추적 식별자, 그리고 어느 플러그인(`agent/calc`)인지다.
  처음에는 행이 들었는데, 그 사이 플러그인이 사라져 404이면 다시 읽은 목록에서 행이 빠지며 메시지도 사라졌다(셀프 리뷰의
  명세 축, 스토리 19). 다음 켜고 끄기가 시작될 때 걷힌다. 다시 읽기도 실패하면 목록 전체의 실패가 행과 스위치를 대신하고,
  켜고 끄기의 실패는 그 위에 남는다(05의 규칙). 요청 함수가 던지지 않는 예외는 결함이라 덮지 않고 다시 던진다.
- **켜고 끄기의 401은 관리 토큰을 내려놓고, 목록은 토큰과 함께 걷힌다.** 훅은 성공이든 실패든 `finally`에서 다시 읽기를
  청하고 `mutate`는 걷힌 키를 읽지 않아, 거부된 토큰으로 다시 읽지 않는다. 401을 따로 가르는 분기를 두었다가 그것을 뺀
  변이가 초록으로 지나가 걷었다. jsdom에서 401 뒤 `finally`에 닿을 때 스위치가 문서에 없는 것을 쟀다
  (`probes/switch_after_rejection.mjs`).
- **이름 패턴 밖의 표지는 열어도 켜고 꺼도 422다.** 계약의 경로가 이름을 `^[a-z][a-z0-9-]{1,62}$`로 받는다. 화면은 그
  패턴을 다시 두지 않고, 여는 화면과 목록의 머리에 422 봉투의 메시지를 보인다. "표지 행도 연다"(스토리 15)가 경로와 이유를
  보이는 것은 이름이 패턴 안인 표지(읽을 수 없는 매니페스트)다.
- **204는 응답의 상태로 가른다.** openapi-fetch 0.17은 본문 없는 성공에도 `data`를 비워 둔다(설치본 `index.mjs`). 목록과
  플러그인 하나처럼 `data`로 가르면 성공이 실패가 된다.
- **관리 요청의 401 처리를 한 자리로 모았다.** fetcher 둘과 쓰기 하나(`useSetPluginEnabled`)가 `orRejectAdminToken`을
  지난다. PR #103의 셋째
  claude-review Nit대로 `rejectIfStillHeld`를 `rejectAdminTokenIfStillHeld`로 바꿨다. 플러그인 하나의 키도 토큰을 받아들인
  횟수를 싣고, 05의 "지운 토큰의 늦은 401" 테스트를 플러그인 하나에도 두었다. 변이 목록을 짜다 그 키를 지키는 테스트가
  없다는 것을 알았다.
- **e2e는 새 파일 `e2e/plugin-toggle.e2e.ts`다.** 준비가 플러그인 루트를 `AGENT_OS_E2E_PLUGINS_ROOT`로 워커에 넘긴다.
  운영자 파일은 준비가 이미 써 둔다(꺼진 스킬). 그래서 "생긴다"는 그 파일의 `agent` 줄에 `echo`가 적히고 다시 켜면 빠지는
  것으로 잰다. 흐름은 꺼진 에이전트를 열어 매니페스트와 꺼짐도 본다. 목록의 링크와 동적 라우트를 실제 Next로 지나는 곳이
  여기뿐이다. 두 흐름이 함께 쓰는 화면 도우미는 `e2e/screen.ts`로 옮겼다.
- **아이콘은 들이지 않았다.** 스위치는 체크박스다. 01의 아이콘 메모는 07·08로 넘긴다.
- **변이는 `probes/plugin_toggle_mutations.mjs`다.** 페이지 테스트와 e2e가 무엇을 재는지 행동마다 본다. 셀프 리뷰 전의
  첫 실행에서 초록이던 둘이 테스트 공백 하나(204 뒤에 실패가 보이지 않는 것)와 관찰되지 않는 분기 하나(401)를 드러냈다.
  06이 요청 함수를 셋으로 늘려 05의 러너(`admin_pages_mutations.mjs`) 원문 하나가 세 번 나오게 됐고, 목록 요청으로 좁혔다.
