# 06: 플러그인 하나를 열어 보고, 스위치로 켜고 끈다

**What to build:** 운영자가 플러그인 하나를 열면 매니페스트를 통째로 본다. 승인 대상 도구와 쓰는 MCP 서버를 여기서 확인한다. 매니페스트가 깨졌으면 그 경로와 이유를 본다. 목록의 행마다 스위치가 있어 플러그인을 끄고 켠다. 누르면 서버에 보내고, 스위치는 서버에서 다시 읽은 값을 따른다. 화면이 값을 먼저 뒤집어 두지 않는다. 표지 행도 끌 수 있다. 끄면 플러그인 루트에 운영자 파일이 생긴다.

05가 세운 토큰, 새로 고침, 에러의 규칙을 그대로 물려받는다. 켜고 끄기는 이 기능의 쓰기 둘 가운데 하나다. 하나 더 있는 결정은 08이다. 에이전트를 끄면 그 에이전트의 멈춘 실행에서 결정 버튼이 막혀야 한다. 그 부분은 결정 자리가 서는 08이 이 티켓의 e2e 흐름에 더한다.

근거는 `.scratch/web-admin/spec.md`의 "관리 화면 — 화면들"에서 "플러그인 하나"와 "켜고 끄기", 그리고 "주 이음매"와 "e2e"의 켜고 끄기 절이다. plugin-toggle의 계약(ADR 0017)도 근거다.

**Blocked by:** 05

**Status:** ready-for-agent

### 플러그인 하나 (`GET /plugins/{kind}/{name}`)

- [ ] **읽히는 행의 매니페스트를 통째로 보인다**(스토리 14). JSON 값은 들여쓴 글자로 보인다. HTML이나 마크다운으로 그리지 않는다
- [ ] **깨진 매니페스트는 500 봉투의 `message`를 보인다.** 경로와 이유가 든다(스토리 15). `request_id`도 함께 보인다
- [ ] 없는 이름은 404이고, 봉투의 메시지를 보인다

### 켜고 끄기 (`PUT /plugins/{kind}/{name}/enabled`)

- [ ] **스위치를 누르면 PUT을 보내고, 204 뒤에 목록과 그 행을 다시 읽는다**(스토리 17, 18). 본문은 `{"enabled": false}` 모양이다. 화면이 값을 먼저 뒤집어 두지 않는다
- [ ] **누른 뒤 응답까지는 스위치를 막는다.** 응답 전의 두 번째 누름은 요청을 더 보내지 않는다. PUT은 멱등이라 두 번 가도 틀리지 않는다. 다만 두 응답이 엇갈려 목록을 두 번 다시 읽을 까닭이 없다(스토리 22)
- [ ] **실패하면 메시지를 보이고, 스위치는 다시 읽은 값이다**(스토리 19)
- [ ] 표지 행도 끌 수 있다(스토리 20, plugin-toggle 스토리 6)
- [ ] 쓰기 직후의 다시 읽기는 05의 새로 고침 규칙 가운데 "쓰기 직후"다

### e2e — 켜고 끄기 흐름

- [ ] 스위치로 에이전트를 끄면 플러그인 루트에 운영자 파일이 생기고, 목록이 꺼짐을 보인다
- [ ] 다시 켜면 목록이 켜짐을 보인다
- [ ] 멈춘 실행의 결정 버튼이 막히고 풀리는 부분은 08이 이 흐름에 더한다

### 확인

- [ ] 화면 문구는 한국어이고 용어집의 말을 쓴다(05의 규칙). 꺼진 플러그인, 표지 같은 말이다. 각 항목의 _Avoid_(예: 비활성 플러그인, 차단, 중지)를 쓰지 않는다
- [ ] TS 테스트의 이름은 행동을 말하는 한국어 문장이다
- [ ] `CLAUDE.md`의 검증 명령과 e2e가 모두 초록이다
