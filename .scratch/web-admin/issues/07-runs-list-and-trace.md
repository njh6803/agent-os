# 07: 실행 목록과 실행 하나를 본다 — 트레이스는 글자로만

**What to build:** 운영자가 실행을 최근 것부터 본다. 상태(일시정지, 끝남, 실패, 결말 없음)로 거르고, 한 쪽을 넘으면 이어서 더 본다. 멈춘 실행은 목록에서 바로 알아본다. 읽을 수 없는 트레이스도 실행 식별자와 이유로 보인다. 실행 하나를 열면 이벤트를 쓴 순서대로 전부, 들어온 모양 그대로 글자로 본다. 요청과 프롬프트, 도구의 인자와 결과, 출력과 에러가 모두 그렇다. 모르는 종류의 이벤트는 원문으로 보이고, 형식 1 트레이스는 "읽을 수 있지만 재개할 수 없다"를 보인다. 트레이스에 든 HTML이나 스크립트는 화면에서 실행되지 않는다.

트레이스는 바깥에서 온 텍스트를 싣는다. 도구 결과와 프롬프트다. 화면이 그것을 HTML로 그리면 XSS가 곧 토큰 유출이다(ADR 0019). 그래서 이 티켓의 가장 무거운 수용 기준은 "글자로만"이다. 결정 자리는 08이 이 화면 위에 세운다.

근거는 `.scratch/web-admin/spec.md`의 "관리 화면 — 화면들"에서 "실행 목록"과 "실행 하나", "문구와 렌더링", "주 이음매", "e2e"의 읽기 흐름 절이다. ADR 0010·0019·0021도 근거다.

### 실행 목록 (`GET /traces`)

- [x] **행은 서버가 준 순서 그대로다**(스토리 23). 화면이 다시 정렬하지 않는다
- [x] **상태 넷과 "전부"로 거른다.** 거르면 질의에 `status`가 실린다(스토리 24). 커서로 더 보면 `after`가 실린다(`next_cursor`, 스토리 25)
- [x] **상태의 이름은 용어집의 말이다.** 일시정지, 끝남, 실패, 결말 없음이다. "결말 없음"이 보이고 "실행 중"은 어디에도 없다(스토리 26, ADR 0021)
- [x] 행은 실행 요약이거나 읽을 수 없는 트레이스다. 읽을 수 없는 트레이스 행은 식별자와 이유를 보인다(스토리 27)
- [x] 멈춘 실행은 목록에서 바로 알아보게 한다
- [x] 새로 고침과 에러는 05의 규칙 그대로다

### 실행 하나 (`GET /traces/{run_id}`)

- [x] **상세의 응답에는 요약이 없다.** 필드는 `run_id`, `schema_version`, `events` 셋이다. 목록을 거치지 않고 상세로 곧장 들어온 화면도 선다(ADR 0010의 2026-09-24 이력)
- [x] **이벤트를 쓴 순서 그대로 전부 보인다**(스토리 28)
  - 종류별 필드를 글자로 보인다
  - 모르는 종류(`unknown`)는 원문 문자열을 그대로 보인다(스토리 29)
  - 인자와 도구 결과 같은 JSON 값은 들여쓴 글자로 보인다
  - 마스킹된 인자는 `***`로 보인다(스토리 31)
- [x] **형식 1이면 "읽을 수 있지만 재개할 수 없다"를 보인다**(스토리 30)
- [x] **트레이스 내용은 텍스트로만 그린다**(스토리 32)
  - React의 기본 이스케이프에 기댄다
  - `dangerouslySetInnerHTML`(ESLint가 판정한다)과 마크다운의 HTML 렌더를 쓰지 않는다. 마크다운 렌더러를 들이려면 ADR이 필요하다(`tech.md`)
  - 페이지 테스트: HTML이 든 도구 결과(`<img src=x onerror=…>`)가 글자 그대로 보인다. 문서에 그 요소가 없다
- [x] 없는 실행과 읽을 수 없는 파일은 봉투의 메시지와 `request_id`로 보인다

### e2e — 읽기 흐름을 잇는다

- [x] **읽기용 트레이스는 테스트 준비가 쓴다.** 끝남, 실패, 형식 1, 모르는 종류의 줄, 읽을 수 없는 파일이다
- [x] **05의 흐름(토큰, 플러그인 목록)에 잇는다.** 실행 목록을 보고, 실행 하나를 열어 모르는 종류의 원문과 형식 1의 표시를 본다
- [x] **트레이스의 HTML이 요소로 그려지지 않는 것을 실제 브라우저에서 한 번 더 본다**

### 이 티켓이 정한 것 (2026-09-30, PR에서 사용자가 본다)

- **실행 목록은 `/runs`, 실행 하나는 `/runs/[runId]`다.** 둘 다 `AdminScreen`을 지난다. 동적 라우트는 06의 플러그인 하나와
  같은 모양이다. 라우트가 조각을 그대로 넘기고 페이지가 푼다. 푸는 함수(`decodeSegment`)는 두 화면이 함께 쓰게
  `components/pages/segment.ts`로 옮겼다. 식별자가 패턴 안이면 인코딩이 드러나지 않아 페이지 테스트는 띄어쓰기로 잰다.
- **머리에 화면 사이 링크를 두었다.** 티켓에는 없다. 없으면 플러그인 목록에서 실행 목록으로 갈 길이 주소를 치는 것뿐이다.
  `AdminFrame`에 `nav` 슬롯을 더하고 `AdminScreen`이 토큰이 있을 때 "플러그인 목록"과 "실행 목록"을 채운다. e2e가 이
  링크로 실행 목록에 간다.
- **쪽 넘김은 SWR의 무한 목록(`swr/infinite`)이다.** 둘째 쪽부터의 키는 앞 쪽의 `next_cursor`다. 다시 읽을 때는 본 쪽을
  모두 차례로 다시 읽으며 다음 쪽의 키를 새로 읽은 앞 쪽의 커서로 다시 짓는다. 쪽마다 따로 `useSWR`를 두면 옛 커서로 읽어
  행이 겹치거나 빠진다. 새로 고침(`mutate()`)은 기본으로 그렇게 읽는다. 포커스와 더 보기도 그렇게 읽도록
  `revalidateAll`을 켰다. 기본값이면 포커스가 첫 쪽과 커서가 바뀐 쪽만 읽는다(설치본 2.5.1). 그러면 떠나 있던 사이
  둘째 쪽의 멈춘 실행이 끝나도 옛 일시정지가 남는다(스토리 33, 셀프 리뷰의 명세 축이 짚었다). 대가로 더 보기는 본 쪽을
  모두 다시 읽는다. 누른 때만이라 스토리 35의 비용(연 시간에 비례)은 아니다. 처음 고르는 상태는 첫 쪽부터다. 전에 본
  상태로 돌아오면 그때 본 쪽 수를 되살린다(`persistSize`의 기본값). 더 보기는 읽는 동안 막는다.
- **거르기는 라디오 다섯(전부와 상태 넷)이고 목록의 머리에 있다.** 읽기 골격의 `above` 자리라 목록이 실패해도 남아 다른
  상태로 옮겨 갈 수 있다. 고른 상태는 화면의 상태이고 주소에 싣지 않는다.
- **멈춘 실행은 상태를 `<strong>`으로 두드러지게 한다.** 아이콘은 들이지 않았다(01의 메모는 08로 넘긴다).
- **요약 행은 식별자(링크), 상태, 에이전트, 주체, 시작과 마지막 시각이다.** 시각은 서버가 준 ISO 문자열 그대로다. 형식
  버전은 어느 화면에도 수로 보이지 않는다. 실행 하나가 형식 1일 때만 재개할 수 없다는 한 줄로 말한다. 읽을 수 없는
  트레이스의 행도 링크다. 열면 서버의 500 봉투가 경로와 이유를 말한다. 행이 없으면 "실행이 없다"를 보인다.
- **실행 하나의 필드는 용어집의 말과 계약의 이름을 함께 보인다(`요청 request`).** 처음에는 계약의 이름만 보였다. 셀프
  리뷰의 명세 축이 "화면 문구는 한국어이고 용어집의 말을 쓴다"와도, 에이전트와 주체를 한국어로 적는 목록과도 어긋난다고 짚었다. 이름의 표는
  `Record<EventField, string>`이라 계약의 이벤트에 필드가 늘면 컴파일에서 깨진다. 빌드 뒤 서버에서 느는 필드는 계약의 이름만
  보인다. `type`은 이벤트의 제목이고 `run_id`는 화면의 제목이라 되풀이하지 않는다. 문자열은 그대로(`white-space:
  pre-wrap`), 그 밖의 JSON 값은 두 칸 들여 적는다. 모르는 종류의 제목은 "모르는 종류"다. 실행 하나에는 06의 "플러그인
  목록으로"와 같은 모양으로 "실행 목록으로" 링크를 두었다.
- **에이전트와 일시정지를 트레이스에서 읽는 두 줄은 08의 몫이다.** 명세의 "실행 하나"에 있지만 결정 자리를 세울지와 꺼짐
  미리 알림에만 쓰인다. 08의 "07이 남긴 메모"에 적었다.
- **읽기 골격을 뽑았다(06의 메모).** `organisms/ReadSection`이 제목, 새로 고침, 다시 확인하는 중, 실패·자리표시·값의
  갈래를 든다. 플러그인 목록과 플러그인 하나도 이것을 지난다. 실패를 보이려면 `api/failure`의 `describeFailure`를 불러야
  해서 molecule이 아니라 organism이다(atoms·molecules는 api를 import하지 않는다). 서버 데이터를 다시 읽다 실패하면 이미
  보인 것을 지우는 규칙이 이제 한 자리에 산다(`.claude/rules/web-admin.md`를 고쳤다). 그 규칙을 지키는 테스트는 화면마다
  있다.
- **`READ`와 401 처리를 `hooks/queries/admin`으로 옮겼다(05·06의 메모).** 플러그인과 실행 두 도메인이 barrel로 가져간다.
- **e2e는 새 파일 `e2e/runs.e2e.ts`다.** 05의 흐름에서 이어 토큰과 플러그인 목록을 거쳐 머리의 링크로 간다. 05의 파일은
  토큰의 저장과 지우기로 끝나 거기 이으면 한 흐름이 둘을 잰다. 읽기용 트레이스는 준비가 serve를 띄우기 전에
  `e2e/traces.ts`로 쓴다. 거르기의 단언은 행의 수를 세지 않는다. 뒤 티켓의 흐름이 serve 하나에 실행을 더한다.
- **글자로만은 네 자리에서 잰다.** 페이지 테스트는 요청의 `<script>`, 프롬프트의 `javascript:` 링크, 도구 결과의
  `<img onerror>`, 모르는 종류의 원문의 `<b>`가 글자로 보이고 문서에 그 요소가 없는 것을 본다. e2e는 실제 브라우저에서
  도구 결과의 `<img onerror>`가 요소가 되지 않고 전역 표시가 남지 않은 것을 본다.
