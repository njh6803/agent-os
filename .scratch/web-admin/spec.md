# 관리 화면: 운영자가 브라우저에서 플러그인과 실행을 보고, 켜고 끄고, 멈춘 실행에 결정을 내린다

Status: ready-for-agent

슬라이스 3(`web-admin`). 근거는 이 기능의 설계 전부다.

- ADR 0019(브라우저가 토큰을 들고 Next는 무상태 중계), 0020(원칙 III이 TypeScript에도 걸린다), 0021(web 워크스페이스의 스택)
- 그것들이 앞선 ADR에 남긴 이력 둘: ADR 0010의 2026-09-28 "계약의 첫 소비자가 생기고 계약 파일은 바뀌지 않는다", ADR 0011의 2026-09-28 "루프백 규칙이 관리 화면에도 걸린다"
- 이 명세를 쓰며 사용자가 승인한 이력 넷: ADR 0014의 2026-09-28 "결정은 그것이 답하는 일시정지를 트레이스 안의 자리로 가리킨다", ADR 0019의 2026-09-28 "열린 물음은 결정을 자리에 묶어 닫았다", ADR 0021의 2026-09-28 둘 "CI의 web 단계는 뼈대와 같은 PR에 들고, e2e도 `verify` 잡이 돈다"와 "화면을 그리는 테스트는 Testing Library로 쓰고 dev 의존성으로 선언한다"

그 밖의 근거는 다음과 같다.

- 재생과 재개의 ADR 0009, 원칙 III의 판정자인 ADR 0013, 채널 토큰의 ADR 0015, 켜짐의 ADR 0017
- `docs/PRD.md`, `docs/constitution/`
- 설계 인터뷰 일지 `docs/journal/2026-09-28-06-web-admin-design.md`
- 측정 `.scratch/web-admin/probes/`(파일과 근거의 짝은 그 README)

용어는 `CONTEXT.md`를 따른다.

- `## 구조`: 운영자, 관리, 관리 화면, 채널, 플러그인, 매니페스트, 표지, 읽을 수 없는 매니페스트, 꺼진 플러그인
- `## 실행`: 실행, 트레이스, 이벤트 스트림, 실행 상태, 실행 요약, 읽을 수 없는 트레이스
- `## 인터럽트`: 일시정지, 승인, 결정, 승인자, 재개

"일시정지의 자리"는 ADR 0014 이력이 쓰는 말이고 용어집의 항목이 아니다. 뜻은 `run_paused` 이벤트가 트레이스 상세 `events`에서 서는 0부터 센 인덱스다.

**이 명세가 정한 것은 두 갈래다.**

- **사용자가 이 명세를 쓰며 고른 것은 다섯이다.**
  - 테스트 이음매, 결정을 일시정지에 묶는 것과 그 식별자(HTTP와 CLI 모두), e2e를 도는 자리: 설계가 명세에 넘긴 물음이다.
  - `ci.yml`이 드는 PR: 설계가 정한 것("별도 PR로 먼저")을 그 전제가 좁았다는 사실로 뒤집었다.
  - 화면을 그리는 테스트 라이브러리: 이음매를 고르며 드러났다.
  - 이음매를 뺀 넷은 위의 ADR 이력으로 승인받았다.
- **명세가 ADR의 문장을 구현이 닿는 자리로 옮기다 스스로 정한 것.** 각 절에 "(이 명세가 정했다)"로 표시하고 PR에서 사용자가 본다.

결정이 더 필요해지면 멈추고 ADR의 이력을 제안한다.

**선행 조건은 코드와 프로브로 확인했다.** 설계는 오래된 결정이 다음 일시정지에 닿는다는 것을 계약에서 추론만 했다(일지 06). 이 명세를 쓰며 두 가지로 확인했다.

- 코드를 읽었다. core의 재개 진입점은 트레이스의 마지막 이벤트를 결정이 묶이는 일시정지로 쓴다.
- 스크립트로 쟀다(`probe_stale_decision.py`). 오래된 화면의 승인이 200이었고, 화면이 본 적 없는 호출을 실행했다.

## Problem Statement

PRD의 운영자는 "어떤 에이전트, 도구, 모델이 등록돼 돌아가는지 한 곳에서 보고 켜고 끄고 싶다." 슬라이스 2가 그 일을 할 HTTP 표면을 모두 세웠다.

- 관리의 GET 넷과 켜고 끄는 PUT 하나
- 채널의 결정 경로

그러나 화면이 없다. 운영자는 지금 이렇게 일한다.

- 베어러 토큰을 붙인 curl로 JSON을 읽는다.
- 트레이스는 이벤트 JSON의 배열로 읽는다.
- 멈춘 실행에 결정을 내리려면 CLI의 안내 줄을 찾거나, 결정 본문을 손으로 짓는다.

앞선 두 저장소는 관리 화면부터 만들고 실행 루프 없이 멈췄다(PRD "왜 지금"). 이번에는 실행과 API가 먼저 섰고, 그 위에 화면을 올린다.

**화면은 새 위험을 넷 들인다.**

- **토큰이 브라우저로 들어온다.** 누가 토큰을 드는지가 새 앱의 노출 경계를 정한다(ADR 0019).
- **트레이스는 바깥에서 온 텍스트를 싣는다.** 도구 결과와 프롬프트다(ADR 0009의 열린 문제). 화면이 그것을 HTML로 그리면 XSS가 곧 토큰 유출이다.
- **Next는 인자 없이 띄우면 `0.0.0.0`과 `[::]`에 선다.** LISTEN 소켓으로 쟀다(`next_measure.mjs`). 중계가 LAN에 서면 토큰이 평문으로 지난다(ADR 0011의 CWE-319).
- **원칙 III은 파이썬의 말로만 적혀 있어 TypeScript에 침묵한다.** TS의 `as` 하나가 생성 클라이언트의 계약을 조용히 덮는다(ADR 0020).

**그리고 화면은 계약의 틈 하나를 흔한 일로 만든다.** 결정 본문에는 어느 일시정지에 대한 것인지가 없다. 그래서 core는 결정을 트레이스의 마지막 일시정지에 묶는다. 화면이 도구 호출 X를 보여 주는 동안 다른 곳(CLI나 다른 탭)이 X를 결정하고, 실행이 Y에서 다시 멈출 수 있다. 그러면 화면에서 누른 결정은 409가 아니라 200이고, 운영자가 본 적 없는 Y가 실행된다. 같은 도구를 같은 인자로 두 번 부르면 도구와 인자로도 둘을 가르지 못한다(`probe_stale_decision.py`, 스크립트로 쟀다). CLI에서도 가능한 일이지만, 화면은 열어 둔 채 오래 두는 것이 기본이라 이 틈이 흔해진다. ADR 0009가 재생 없는 재개를 기각한 이유, "사람이 승인한 것과 실제로 실행되는 것이 달라진다"가 여기서 다시 열린다.

## Solution

**`web/`은 pnpm 워크스페이스이고 둘이 선다.**

- `packages/api-client`: `openapi.json`에서 openapi-typescript로 생성해 커밋한다.
- `apps/admin`: Next 16과 React 19의 관리 화면이다.

**화면은 이렇게 돈다.**

- 운영자가 관리 화면을 띄우면 루프백에만 선다. 다른 호스트를 주면 구성 오류로 끝난다.
- 브라우저에서 관리 토큰(필수)과 채널 토큰(선택)을 넣는다. 토큰은 그 탭의 sessionStorage에 있고, 탭이 닫히면 사라진다.
- 브라우저가 매 요청의 헤더에 토큰을 싣는다. 같은 출처의 `/api/*`는 Next의 `rewrites`가 파이썬 서버로 넘긴다. Next에는 비밀도, API를 부르는 서버 코드도 없다.

**운영자가 보는 것은 다섯이다.**

- **플러그인 목록.** 종류별로 보이고, 행마다 켜짐 스위치가 있다. 표지 행은 이유를 든다.
- **플러그인 하나.** 매니페스트를 통째로 보인다.
- **실행 목록.** 상태로 거르고, 커서로 더 본다.
- **실행 하나.** 트레이스를 쓴 순서 그대로, 텍스트로만 보인다.
- **결정.** 채널 토큰을 넣었을 때만 보인다. 허가, 또는 사유를 붙인 거부다.
  - 재개된 실행의 이벤트가 받는 대로 붙는다.
  - 에이전트나 그것이 쓰는 MCP가 꺼진 실행은 미리 알리고 버튼을 막는다.

새로 고침은 탭 포커스, 버튼, 쓰기 직후다. 주기 폴링은 없다.

**결정은 화면이 본 그 일시정지에만 닿는다.** 결정 본문과 CLI `resume`이 일시정지의 자리를 필수로 든다. 그 자리가 지금의 일시정지가 아니면 core가 결정을 쓰기 전에 거절하고 409다. 화면은 409를 받으면 트레이스를 다시 읽어 지금의 일시정지를 보인다. CLI는 멈출 때 찍는 안내 줄에 그 자리를 싣는다. 디스크 형식과 sdk는 바뀌지 않는다. 파이썬 서버가 바뀌는 것은 이것 하나다.

**원칙 III이 TypeScript에도 걸린다.**

- 판정자는 타입 기반 규칙까지 켠 typescript-eslint이고, 인라인 설정은 꺼진다.
- tsconfig의 `strict`를 끄는 것은 검사가 막는다.
- 검증 명령이 다섯이 된다. 다섯째는 `pnpm -C web verify`로, 린트·타입·단위 테스트·생성물 최신성을 본다.
- pre-commit과 CI의 `verify` 잡이 다섯째 명령을 돈다. CI의 `verify` 잡은 e2e도 돈다.

## User Stories

### 토큰을 넣는 운영자

1. 운영자로서, 관리 화면을 처음 열면 관리 토큰을 넣는 자리를 보고 싶다. 토큰 없이는 어떤 관리 요청도 401이기 때문이다.
2. 운영자로서, 넣은 토큰이 탭을 닫으면 사라지기를 바란다. 디스크에 평문으로 남거나 모든 탭이 공유하면 안 되기 때문이다(ADR 0019).
3. 운영자로서, 같은 탭에서 새로 고침해도 토큰을 다시 넣지 않기를 바란다. 메모리에만 두면 새로 고침마다 다시 넣게 되기 때문이다(ADR 0019).
4. 운영자로서, 채널 토큰을 넣지 않아도 관리 화면의 나머지를 전부 쓸 수 있기를 바란다. 결정은 내가 허락할 때만 쓰는 다른 권한이기 때문이다(ADR 0015, 0019).
5. 운영자로서, 채널 토큰을 넣었을 때만 결정 버튼이 보이기를 바란다. 누를 수 없는 버튼이 서 있으면 안 되기 때문이다.
6. 운영자로서, 관리 토큰이 거부되면 무엇이 거부됐는지 듣고 다시 넣는 자리로 가고 싶다. 빈 화면을 보며 서버가 비었다고 믿으면 안 되기 때문이다.
7. 운영자로서, 채널 토큰이 거부되면 결정 자리에서만 그렇다고 듣고 싶다. 관리 화면은 계속 써야 하기 때문이다.
8. 운영자로서, 탭을 닫지 않고도 토큰을 지울 수 있기를 바란다. 자리를 비울 때 권한을 내려놓기 위해서다.
9. 운영자로서, 토큰이 URL, 화면의 글자, 브라우저 콘솔 어디에도 드러나지 않기를 바란다. 기록이나 화면 공유로 새면 안 되기 때문이다.
10. 운영자로서, 관리 토큰이 채널 경로에, 채널 토큰이 관리 경로에 실리지 않기를 바란다. 한 토큰이 맡지 않은 면에 보내지는 것 자체가 노출이기 때문이다.

### 플러그인을 보는 운영자

11. 운영자로서, 등록된 플러그인을 종류(에이전트, MCP, 스킬, 모델)별로 한 화면에서 보고 싶다. PRD의 "한 곳에서"가 이것이다.
12. 운영자로서, 행마다 켜졌는지 보고 싶다.
13. 운영자로서, 매니페스트로 읽히지 않는 플러그인도 목록에서 이유와 함께 보고 싶다. 조용히 빠지면 등록했다고 믿는 것과 실제가 어긋나기 때문이다.
14. 운영자로서, 플러그인 하나를 열어 매니페스트를 통째로 보고 싶다. 승인 대상 도구와 쓰는 MCP 서버를 확인하기 위해서다.
15. 운영자로서, 매니페스트가 깨진 플러그인을 열면 그 경로와 이유를 보고 싶다. 무엇을 고칠지 알아야 하기 때문이다.
16. 운영자로서, 운영자 파일이 깨졌으면 목록 대신 그 파일의 경로와 이유를 보고 싶다. 무엇이 꺼져 있는지 모르는 채 목록을 믿으면 안 되기 때문이다(ADR 0017).

### 켜고 끄는 운영자

17. 운영자로서, 스위치 하나로 플러그인을 켜고 끄고 싶다.
18. 운영자로서, 누른 뒤 목록이 서버에서 다시 읽은 값을 보이기를 바란다. 화면이 스스로 뒤집은 값을 믿으면 서버와 어긋나도 모르기 때문이다.
19. 운영자로서, 끄기가 실패하면 에러 메시지를 보고 스위치가 서버의 값으로 돌아오기를 바란다.
20. 운영자로서, 표지 행도 끌 수 있기를 바란다. 깨진 것을 끈 채로 고치고 싶을 수 있기 때문이다(plugin-toggle 스토리 6).
21. 운영자로서, 스킬과 모델을 끄는 것은 로더가 생기기 전에는 효과가 없다는 것을 화면에서 알고 싶다. 끈 것이 아무것도 막지 않는데 믿으면 안 되기 때문이다.
22. 운영자로서, 스위치를 두 번 눌러도 에러가 나지 않기를 바란다. 켜고 끄기는 멱등이다.

### 실행을 관찰하는 운영자

23. 운영자로서, 실행 목록을 최근 것부터 보고 싶다.
24. 운영자로서, 실행 상태로 거르고 싶다. 무엇보다 멈춘 실행을 찾기 위해서다.
25. 운영자로서, 목록이 한 쪽을 넘으면 이어서 더 보고 싶다.
26. 운영자로서, 상태의 이름이 용어집의 말이기를 바란다. "결말 없음"을 "실행 중"으로 부르면, 끝내지 못하고 사라진 실행을 돌고 있다고 믿게 되기 때문이다.
27. 운영자로서, 읽을 수 없는 트레이스도 목록에서 실행 식별자와 이유와 함께 보고 싶다.
28. 운영자로서, 실행 하나를 열어 이벤트를 쓴 순서 그대로 전부 보고 싶다.
29. 운영자로서, 모르는 종류의 이벤트도 원문 그대로 보고 싶다. 화면이 보지 못한 그 줄이 곧 재개 불가의 원인일 수 있기 때문이다(ADR 0010 이력).
30. 운영자로서, 형식 1 트레이스는 읽을 수 있지만 재개할 수 없다는 것을 보고 싶다.
31. 운영자로서, 요청과 프롬프트, 도구의 인자와 결과, 출력과 에러가 들어온 모양 그대로 글자로 보이기를 바란다. 마스킹된 인자는 `***`로 보인다.
32. 운영자로서, 트레이스에 든 HTML이나 스크립트가 화면에서 실행되지 않기를 바란다. 트레이스는 바깥에서 온 텍스트를 싣고, 그것이 실행되면 내 토큰이 샌다(ADR 0019).
33. 운영자로서, 탭으로 돌아오면 목록이 새로 고쳐지기를 바란다. 떠나 있던 사이에 실행이 끝났을 수 있기 때문이다.
34. 운영자로서, 새로 고침 버튼이 있기를 바란다.
35. 운영자로서, 화면이 주기적으로 폴링하지 않기를 바란다. 서버와 트레이스 디렉터리를 훑는 비용이 화면을 열어 둔 시간에 비례하면 안 되기 때문이다.
36. 운영자로서, 처음 불러오는 중과 이미 보인 것을 다시 확인하는 중을 구분해 보고 싶다. 다시 확인할 때마다 목록이 사라졌다 나타나면 안 되기 때문이다.
37. 운영자로서, 에러가 나면 메시지와 추적 식별자(`request_id`)를 보고 싶다. 서버의 표준 에러에서 같은 줄을 찾기 위해서다(`.claude/rules/http.md`).

### 결정을 내리는 운영자

38. 승인자로서, 멈춘 실행에서 무엇을 승인하는지 보고 결정하고 싶다. 도구 이름과 인자다.
39. 승인자로서, 허가는 버튼 하나이기를 바란다.
40. 승인자로서, 거부는 사유를 적어야만 보낼 수 있기를 바란다. 사유 없는 거부가 기록되면 안 되기 때문이다(ADR 0009, 0014).
41. 승인자로서, 공백뿐인 사유는 보내기 전에 화면이 막기를 바란다. 서버가 422로 막더라도 먼저 아는 편이 낫다.
42. 승인자로서, 결정 뒤 재개된 실행의 이벤트가 받는 대로 화면에 붙기를 바란다. 모델 호출이 수십 초 걸려도 무엇이 진행 중인지 보기 위해서다.
43. 승인자로서, 재개 스트림이 끝나면 화면이 트레이스를 다시 읽어 기록과 맞추기를 바란다. 스트림과 트레이스는 같은 사실의 두 모습이다(ADR 0014).
44. 승인자로서, 재개가 다음 승인 대상에서 다시 멈추면 새 일시정지와 결정 버튼을 보고 싶다. 결정 하나는 도구 하나만 판정하기 때문이다.
45. 승인자로서, 창을 닫거나 떠나도 실행이 끝까지 간다는 것을 알고 싶다. 돌아오면 트레이스로 이어 본다(ADR 0014).
46. 승인자로서, 스트림이 끊겨도 화면이 결정을 다시 보내지 않기를 바란다. 다시 보낸 결정은 다른 일시정지에 닿을 수 있기 때문이다(ADR 0019).
47. 승인자로서, 내가 보는 일시정지를 다른 곳이 먼저 결정했으면 내 결정이 거절되기를 바란다. 다른 곳은 CLI나 다른 탭이다. 내가 보지 않은 도구 호출을 승인하면 안 되기 때문이다(ADR 0014 이력).
48. 승인자로서, 그렇게 거절되면 화면이 트레이스를 다시 읽어 지금의 일시정지를 보여 주기를 바란다.
49. 승인자로서, 같은 도구를 같은 인자로 다시 부른 일시정지가 앞의 것과 구분되기를 바란다. 둘은 사람이 따로 판단할 두 호출이기 때문이다.
50. 승인자로서, 에이전트나 그것이 쓰는 MCP가 꺼진 실행에는 결정 버튼이 막히고 무엇이 꺼졌는지 보이기를 바란다. 누르면 어차피 409이기 때문이다(ADR 0017, 0019).
51. 승인자로서, 화면을 연 뒤에 꺼진 것은 409 봉투의 메시지로 듣고 싶다.
52. 승인자로서, 형식 1인 멈춘 실행에는 결정 버튼이 없기를 바란다. 재개할 수 없는 실행이기 때문이다.
53. 승인자로서, 결정의 승인자가 `serve`를 띄운 OS 사용자로 기록된다는 것을 알고 싶다. 화면은 승인자를 고르지 않는다(ADR 0015).

### CLI로 결정하는 운영자

54. 운영자로서, 실행이 멈출 때 CLI가 찍는 안내 줄이 결정할 일시정지의 자리를 싣기를 바란다. 그 명령을 그대로 복사해 쓰면 재개된다.
55. 운영자로서, 터미널에 남은 오래된 안내 줄을 그대로 쳤을 때 그 사이 다른 곳이 결정했으면 거절되기를 바란다. 거절은 진단과 종료 코드 1이고, 트레이스는 바이트 그대로다.
56. 운영자로서, 자리를 빠뜨리면 인자 오류로 끝나기를 바란다. CLI가 마지막 일시정지로 짐작하면 거절의 뜻이 없어지기 때문이다.

### HTTP로 결정하는 클라이언트 개발자

57. 개발자로서, 결정 본문에 일시정지의 자리가 필수이기를 바란다. 빠지면 422다.
58. 개발자로서, 자리가 지금의 일시정지가 아니면 409 `conflict`를 받고 싶다. 메시지는 두 자리를 든다. 무엇이 어긋났는지 알아야 하기 때문이다.
59. 개발자로서, 음수처럼 형식이 틀린 자리는 422이고 `violations`가 그 필드를 가리키기를 바란다.
60. 개발자로서, 거절된 결정이 트레이스에 아무것도 쓰지 않기를 바란다. 그래야 실행이 일시정지 그대로이고, 맞는 자리로 다시 결정할 수 있다.
61. 개발자로서, 스트림만 본 클라이언트도 자리를 셀 수 있기를 바란다. 재개 스트림의 프레임은 트레이스에 새로 붙은 줄과 같다.
62. 개발자로서, 같은 자리를 든 결정 둘이 동시에 오면 하나만 받아들여지기를 바란다. ADR 0014의 불변식은 그대로다.

### 관리 화면을 띄우는 운영자

63. 운영자로서, 관리 화면이 루프백에만 서기를 바란다. 다른 호스트를 주면 구성 오류로 끝나고 SSH 포트 포워딩을 안내받는다. 중계가 LAN에 서면 토큰이 평문으로 지나기 때문이다(ADR 0011 이력).
64. 운영자로서, 중계가 넘기는 곳(상류)도 루프백이기를 바란다. 상류가 다른 호스트면 토큰이 거기까지 평문으로 가기 때문이다.
65. 운영자로서, 다른 출처의 페이지가 중계를 지나도 토큰 없이 401이기를 바란다. CORS가 없는 것이 곧 차단이다(ADR 0011 이력).
66. 운영자로서, 관리 화면의 서버 쪽이 비밀을 들지 않고 API를 부르지 않기를 바란다. 그런 코드가 있으면 토큰 없이 권한을 쓰는 뒷문이 되기 때문이다(ADR 0019).
67. 운영자로서, 모델이 조용한 동안에도 재개 스트림이 끊기지 않기를 바란다. keepalive 간격(15초)이 중계의 침묵 한도(30초)보다 짧다(ADR 0019).
68. 운영자로서, 재개 스트림이 끝에 한꺼번에 몰리지 않고 생기는 대로 오기를 바란다. 기본 압축이 SSE를 끝에 몰았다(ADR 0019).
69. 운영자로서, 관리 화면을 띄우는 명령과 파이썬 서버의 포트를 맞추는 법을 README에서 찾고 싶다.

### web 코드를 쓰는 개발자

70. 개발자로서, TypeScript에서도 `any`, 타입 단언(`as const`는 제외), 비null 단언 `!`, `@ts-ignore`, `@ts-nocheck`가 막히기를 바란다. 생성 클라이언트의 계약이 조용히 덮이면 안 되기 때문이다(ADR 0020).
71. 개발자로서, `@ts-expect-error`는 타입 테스트 파일에서만, 설명과 함께 쓸 수 있기를 바란다. 그것은 억제가 아니라 "이 코드는 컴파일되면 안 된다"는 단언이다.
72. 개발자로서, 인라인 설정 주석으로 규칙을 끌 수 없기를 바란다. 정당한 예외는 설정 파일에 경로와 함께 들어가 리뷰에 diff로 보인다.
73. 개발자로서, tsconfig의 `strict`나 그 계열 플래그를 끄는 것도 막히기를 바란다. 설정 한 줄이 파일 하나의 단언보다 세다(ADR 0020).
74. 개발자로서, 생성 클라이언트는 손으로 고치지 않고, 계약이 바뀌면 다시 생성해 커밋하기를 바란다. 최신성 검사가 어긋남을 잡는다.
75. 개발자로서, 파이썬 티켓이 `openapi.json`을 바꾸면 다섯째 명령이 빨개지기를 바란다. 그래야 생성물이 같은 PR에 담긴다(ADR 0021).
76. 개발자로서, 아토믹 층의 경계를 린터가 판정하기를 바란다. atoms와 molecules는 순수하고 API는 organisms 이상만 부른다. 경계는 사람이 기억할 것이 아니다.
77. 개발자로서, 한 명령으로 린트·타입·단위 테스트·생성물 최신성을 보기를 바란다. pre-commit과 CI가 같은 명령을 돈다.
78. 개발자로서, e2e가 실제 `serve`와 실제 중계를 지나고 CI가 그것을 필수 검사 안에서 돌기를 바란다. 중계의 SSE와 루프백 래퍼는 가짜로 증명할 수 없기 때문이다.
79. 개발자로서, `next dev`가 앱 폴더에 `AGENTS.md`와 `CLAUDE.md`를 만들지 않기를 바란다. 지침을 `.claude/rules/`에 둔다는 결정이 조용히 우회되기 때문이다(ADR 0021).
80. 개발자로서, web 지침이 web 경로의 파일을 열 때만 실리기를 바란다. 파이썬만 만지는 세션의 컨텍스트를 채우면 안 되기 때문이다(ADR 0004).
81. 개발자로서, 화면 테스트의 가짜 응답이 생성 타입으로 적히기를 바란다. 계약이 바뀌면 가짜도 컴파일에서 깨져야, 테스트가 옛 모양 위에서 초록이 되지 않는다.

### 런타임 기여자

82. 기여자로서, 파이썬 서버가 결정의 자리 하나 밖에서는 바뀌지 않기를 바란다(ADR 0010 이력).
83. 기여자로서, 자리 판정이 `resume()`의 첫 걸음 안에 있고 `await`가 없기를 바란다. 동시 재개 불변식이 거기에 기대기 때문이다(ADR 0014).
84. 기여자로서, 채널이 자리를 먼저 확인하지 않고 core가 던진 타입을 표가 옮기기를 바란다. 판정 순서가 core 밖으로 새면 안 되기 때문이다.
85. 기여자로서, 에러 어휘가 다섯 그대로이고 core가 상태 코드를 모르기를 바란다.
86. 기여자로서, 디스크 형식과 sdk가 바뀌지 않기를 바란다. 트레이스는 이미 순서이고, 이벤트 형식을 바꾸면 트레이스 형식 3이 든다.

## Implementation Decisions

위의 ADR과 이력이 결정한 것을 구현이 닿는 자리로 옮겨 적는다. 이 명세가 스스로 정한 것은 "(이 명세가 정했다)"로 표시한다.

### 이음매 (사용자가 골랐다)

**web의 주 이음매는 페이지다.**

- `components/pages/`의 클라이언트 컴포넌트를 Vitest(jsdom)에서 Testing Library로 그린다.
- 생성 클라이언트는 그대로 두고, MSW가 HTTP를 받는다.
- 훅(SWR), 스토어(Zustand), organisms·molecules·atoms는 따로 이음매를 두지 않고 이것으로 덮는다.
- 핸들러의 응답 본문은 생성 타입으로 적는다.

jsdom에서 MSW가 낸 SSE는 openapi-fetch의 `parseAs: "stream"`으로 조각마다 왔다(`jsdom_sse.sh`, 스크립트로 쟀다). 그래서 재개 스트림도 이 이음매에서 잰다.

**좁은 이음매는 순수 함수 넷과 판정자의 변이 테스트다.**

- 순수 함수: SSE 프레임 파서와 판별자 술어, 생성 스크립트의 `Json` 변환, 시작 래퍼와 상류의 루프백 판정, tsconfig 검사
- 판정자의 변이 테스트는 아래 "첫 티켓" 절

**e2e는 Playwright다.** 진짜 `serve`와 시작 래퍼로 띄운 Next를 지나 세 흐름을 본다. 읽기, 켜고 끄기, 결정이다. 픽스처 플러그인 루트와 트레이스 디렉터리를 쓴다.

**파이썬은 기존 이음매 셋을 넓힌다.** core `resume()`, `create_app()` + `ASGITransport`의 채널, CLI 표면이다. 새 이음매는 없다.

### 티켓의 순서

- **첫 티켓은 헌법과 하네스와 web 뼈대다.** 설계가 정했다(plan 행). 아래 절이다.
  - web 뼈대가 이 티켓에 드는 이유는 둘이다. 다섯째 검증 명령이 실제로 돌아야 명령 목록에 적을 수 있다(`operations.md` 머리: "실제로 돌려 통과한 명령만 적는다"). web 규칙의 `paths`는 가리키는 것이 있어야 지침 검사를 지난다(ADR 0021 이력).
- **계약 티켓은 결정의 자리다.** 파이썬과 계약 파일만 바꾸고 web을 모른다.
- **뿌리는 둘이다(이 명세가 정했다).** 헌법·하네스·web 뼈대 티켓과 계약 티켓이다. 둘은 서로를 막지 않는다.
  - `docs/agents/issue-tracker.md`는 계약을 바꾸는 티켓이 그 기능의 첫 티켓이며 다른 티켓을 막는다고 적었다. `CLAUDE.md` 작업 규약 2는 막는 것만 적었다. ADR 0019 본문도 "묶는다면 web-admin의 첫 티켓"이라고 적었다. 이 기능에는 계약을 바꾸는 티켓이 둘이라, 그 "첫"을 다른 티켓보다 앞에 서고 뒤의 것을 막는 뿌리로 읽는다. ADR 0019의 2026-09-28 이력이 이것을 적는다.
  - **계약 티켓은 생성 클라이언트 티켓과 그 뒤의 web 티켓 전부를 막는다.** 생성물이 옛 결정 본문으로 한 번 서고 다시 서는 일을 두지 않는다.
- **결정 화면이 마지막 티켓이다.** 설계에서 사용자가 골랐다(일지 06, R1 범위).
- **나누지 않는 짝(이 명세가 정했다).** 짝의 한쪽만 main에 병합되면 ADR의 약속이 그동안 빈다. 짝마다 한 티켓의 한 PR에 든다.
  - **계약 티켓 하나.** 결정 본문의 필드, core의 판정, 채널의 전달, CLI의 인자와 안내 줄이다. 나누면 계약은 자리를 요구하는데 core가 보지 않아 오래된 결정이 여전히 200인 상태가 된다. CLI만 미루면 ADR 0014 이력이 거부한 "HTTP만 묶고 CLI는 마지막 일시정지"가 그동안의 main이다. plugin-toggle은 계약과 core 판정을 갈라 틈을 따로 다뤄야 했다(plugin-toggle 명세의 "계약 티켓" 절).
  - **앱의 `dev`·`start` 스크립트, 시작 래퍼, `agentRules: false`.** 나뉘면 `next dev`가 `0.0.0.0`에 서고(ADR 0019), 앱 폴더에 `AGENTS.md`와 `CLAUDE.md`가 생긴다(ADR 0021).
  - **`rewrites`, `compress: false`, 상류의 루프백 판정.**
  - **토큰을 저장하고 싣는 화면은 래퍼와 중계보다 앞서 병합되지 않는다.**
  - **첫 e2e 흐름과 `ci.yml`의 e2e 단계(브라우저 설치 포함).** 나뉘면 e2e가 필수 검사 밖에서 돈다. ADR 0021 이력이 거부한 모양이다.
- 나머지를 가르는 것은 `/to-tickets`다.

### 판정자와 검사 (ADR 0020)

- **판정자는 typescript-eslint다.**
  - `strictTypeChecked`를 켠다. 여기에 타입 단언을 막는 설정(`as const`는 제외)을 더한다.
  - 비null 단언, `@ts-ignore`와 `@ts-nocheck`를 막는다. `@ts-expect-error`는 타입 테스트 파일(`*.test-d.ts`)에서만 설명과 함께 허용한다.
  - `linterOptions.noInlineConfig`를 켜고, `verify`의 린트는 `--max-warnings 0`으로 돈다(이 명세가 정했다). `noInlineConfig`가 켜진 파일의 인라인 설정 주석은 에러가 아니라 경고로 보고되고, ESLint CLI는 경고만 있으면 종료 코드가 0이다(명세 검토가 ESLint 9.39.5 설치본의 코드를 읽었다. 설계 프로브의 10.11.0은 읽지 않았다). 경고 0이 게이트여야 끄기 주석이 조용히 지나가지 않는다.
  - 대상 글롭은 `.ts`, `.tsx`, `.d.ts`와 생성물을 모두 든다. 생성물을 판정 범위에서 빼는 목록을 두지 않는다(ADR 0020).
  - **근거의 종류.** 설계 프로브(`ts7_lint.sh`)가 스크립트로 잰 것은 `JSON.parse`의 `any` 경로와 `as unknown as` 이중 단언이 다섯 건으로 잡히는 것까지다. 그 탐침 파일에는 그 둘만 들었다.
    - 코드를 읽은 것: 명세 검토가 typescript-eslint 8.33.1 설치본을 읽었다. `assertionStyle: "never"`는 `as const`를 면제하고, strict 설정의 `ban-ts-comment`는 설명이 붙은 `@ts-expect-error`를 어디서나 허용한다. 그래서 "타입 테스트 파일에서만"은 글롭별 설정이 필요하다.
    - 재지 않은 것: 비null 단언, `@ts-ignore`, `@ts-nocheck`, 꺾쇠 단언, `.d.ts`, 인라인 설정 주석, 아래 내장 규칙들. 첫 티켓의 변이 테스트가 잰다. ADR 0020이 정한 금지 목록을 확인하는 일이라 새 결정을 낳지 않는다. 어긋나면 설정을 고친다.
- **ESLint가 함께 판정하는 것.** 전부 ESLint 내장 규칙이나 이미 승인된 플러그인으로 하고, 새 플러그인을 들이지 않는다.
  - eslint-plugin-boundaries: 층 경계와 앱 사이의 import, barrel import, 아이콘 서브패스 import
  - TS `enum` 금지
  - `dangerouslySetInnerHTML` 금지(이 명세가 정했다)
  - **Next에서 API를 부르는 서버 코드 금지(이 명세가 정했다).** 대상은 셋이다.
    - Server Actions 지시문(`"use server"`)은 web 전체에서 막는다.
    - Next 서버가 돌리는 파일은 앱의 어느 자리에 두어도 막는다. 라우트 핸들러(`route`), `middleware`, `proxy`, `instrumentation`이다. 명세 검토가 Next 16.3.3 설치본의 파일 관례를 읽었다. 16.3.6은 앱을 세우는 티켓이 다시 본다.
    - 전역 `fetch`는 web 전체에서 막는다(`no-restricted-globals`). 생성 클라이언트 패키지도 `fetch`를 직접 부르지 않아(부르는 것은 openapi-fetch다) 예외를 두지 않는다(티켓 03이 거뒀다). 모든 HTTP가 생성 클라이언트를 지나게 되고, `app/**/page.tsx`가 import 없이 `fetch`를 부르는 길도 닫힌다.

  경로에 기대는 규칙은 뼈대의 가상 경로가 아니라 **경로와 무관하게** 쓴다. 규칙이 첫 티켓에 서고 앱은 뒤 티켓에 서기 때문이다. 앱이 다른 배치(예: `src/app/`)를 쓰면 가상 경로에 건 규칙은 아무것도 보지 않고, 변이 테스트는 초록이 된다. 앱을 세우는 티켓은 실제 배치에서 변이가 빨강인지 다시 본다.

  뒤의 둘(`dangerouslySetInnerHTML`, 서버 코드)은 ADR 0019가 적은 약속("HTML로 렌더하지 않는다", "API를 부르는 서버 코드를 두지 않는다")을 지침이 아니라 린터 층에 두는 것이다. 교정 루프의 "규칙은 강제력이 가장 높은 층에"다. `no-restricted-syntax`와 `no-restricted-globals` 같은 내장 규칙으로 되므로 의존성이 늘지 않는다. 서버 컴포넌트가 생성 클라이언트를 import해 부르는 길은 층 경계로 막는다. `app/`의 파일은 pages와 templates만 import한다(이 명세가 정했다). ADR 0021의 "`app/**/page.tsx`는 라우팅과 레이아웃만 한다"를 boundaries 규칙으로 옮긴 것이다.
- **tsconfig 검사의 자리(이 명세가 정했다, ADR 0020이 넘겼다).**
  - `pnpm -C web verify`의 한 단계로 돈다.
  - 검사할 tsconfig는 목록으로 적지 않고 `web/` 아래를 훑어 찾는다(`node_modules/` 제외). 목록이면 뒤 티켓의 tsconfig가 조용히 빠진다. ADR 0013이 경계한 "범위를 손으로 두 곳에"다.
  - 찾은 tsconfig마다 TypeScript 자신이 풀게 한다. `tsc --showConfig`는 `extends`를 풀어, 부모의 `strict: true`와 자식의 `strictNullChecks: false`를 함께 드러냈다(`tsc_showconfig.sh`, 스크립트로 쟀다).
  - `strict`가 참인지, 그리고 strict 계열의 개별 플래그 가운데 거짓으로 덮인 것이 없는지 본다. `strict: true`여도 `strictNullChecks: false` 한 줄이 그 계열을 끄기 때문이다.
  - ESLint 규칙이 아니라 설정을 읽는 검사라 판정자와 별개다(ADR 0020).
  - 파이썬 `tools/`에 두지 않는 이유는 둘이다. `extends`를 풀려면 TS 도구가 필요하다. 그리고 "판정자는 언어마다 하나"의 짝으로, 언어마다의 검사는 그 언어의 명령이 돈다.
- **생성물 최신성.** `pnpm -C web verify`의 한 단계다. 루트 `openapi.json`에서 다시 생성한 결과가 커밋된 생성물과 같은지 본다. 저장소는 `* text=auto eol=lf`라서 윈도우와 CI가 같은 바이트를 본다. 이 단계와 그 변이 테스트, 그리고 생성물이 판정 범위에 드는지 보는 테스트는 **생성 클라이언트 티켓**의 것이다. 생성물이 없는 첫 티켓에 서면 빈 것을 재고 초록이 된다.

### 계약 티켓 — 결정의 자리 (ADR 0014의 2026-09-28 이력)

리뷰의 질문은 이 필드 이름과 판정 순서로 오래 살 수 있느냐다. 필드 이름은 이 티켓이 짓는다. 조건은 넷이다.

- `Approve`와 `Deny`에 같은 이름이다.
- 0 이상의 정수이고 기본값이 없다. 요청 본문은 검증 스키마로 실려 기본값이 곧 계약의 "선택"이 된다(`.claude/rules/channel.md`).
- 시각으로 읽히는 이름을 피한다.
- 계약의 설명이 "트레이스 상세 `events`의 인덱스"를 말한다. 필드에는 독스트링을 둘 자리가 없으므로 필드의 `description`이다. `src/`에는 아직 `Field(description=…)`가 없고, 가장 가까운 선례는 관리 라우트의 `Query(description=…)`다.

**자리는 엄격한 정수다(이 명세가 정했다).** 채널의 본문 모델은 지금 기본(lax) 검증이다. 명세 검토가 프로브로 쟀다. 같은 모델 설정에 0 이상 제약만 붙인 정수 필드를 두면 문자열 `"2"`, 실수 `2.0`, 불린 `true`가 모두 받아졌다. `true`는 1로 읽혔다. 필드를 `strict=True`로 두면 셋 다 422였고, 두 스키마는 같았다(`integer`, 최솟값 0). 계약이 `integer`라고 적는데 문자열이 자리를 정하면 안 된다. plugin-toggle이 켜짐의 불린을 엄격하게 둔 것과 같은 이유다. `strict=True`의 선례는 관리의 트레이스 목록 커서 모델(`admin/traces.py`의 `_CursorWire`)이다. 그 프로브는 검토자의 스크래치패드에 있었고, 이 명세가 `.scratch/web-admin/probes/probe_lax_index.py`로 옮겼다.

**`openapi.json`.**

- `Approve`와 `Deny`에 필수 필드 하나가 는다. 어휘, 경로, 스트림의 항목은 그대로다.
- 최신성 테스트가 그대로 판정한다.
- web의 생성물이 이미 있다면 같은 PR에서 다시 생성한다(ADR 0021).

**core `resume()`.**

- 자리를 필수로 받는다. 기본값은 없다. 선택으로 두면 기본값이 곧 "마지막 일시정지"라 fail-open이다(ADR 0014 이력).
- 모양은 이 티켓이 정한다. 별도 인자로 받을 수도 있고, `Approve`·`Deny`의 필드로 받을 수도 있다.
- **판정은 트레이스 판정 바로 뒤에서 한다.** 순서는 없음 → 형식 1 → 손상 → 일시정지 아님 → 자리 어긋남이다. 그다음이 준비(매니페스트, mcp, 마스킹과 승인의 충돌, 운영자 파일, 꺼짐, 진입점)이고, 결정 이벤트 쓰기가 맨 끝이다.
- 어긋나면 `NotResumable`이다. 메시지는 결정이 가리킨 자리와 지금 일시정지의 자리를 모두 든다.
- 자리 판정도 첫 걸음 안이고 `await`가 없다. 같은 자리를 든 결정 둘이 동시에 오면 둘째는 지금처럼 "일시정지 아님"이다.
- 거절된 결정은 트레이스에 아무것도 쓰지 않는다.
- **자리를 인덱스로 쓰지 않는다.** 받은 값이 마지막 이벤트의 인덱스와 같은지만 본다. 파이썬의 음수 인덱스로 이벤트를 꺼내면 `-1`이 마지막 이벤트에 맞는다. 같은지만 보면 음수는 언제나 어긋남이다. HTTP와 CLI는 음수를 앞에서 형식 오류로 막는다. core는 채널이 막았다고 믿지 않는다.
- 트레이스에 모르는 종류의 이벤트가 있으면 이미 재개 전에 `PluginError`이므로, core가 세는 인덱스와 트레이스 상세의 인덱스는 재개할 수 있는 실행에서 언제나 같다. 코드를 읽었다. JSONL 어댑터는 머리 줄을 빼고 모든 줄을 이벤트로 읽는다. core는 모르는 종류가 있으면 재생 전에 거부한다. 관리의 트레이스 상세는 이벤트를 1:1로 옮긴다.

**채널.**

- 결정 본문의 필드를 core로 넘긴다. 채널은 자리를 먼저 확인하지 않는다. 꺼짐과 재개 불가를 먼저 보지 않는 것과 같은 이유다(`.claude/rules/channel.md`).
- 승인 경로의 409는 뜻이 넷이 된다. 일시정지 아님, 형식 1, 꺼짐, 자리 어긋남이고 메시지가 가른다.

**CLI.**

- `resume`이 같은 값을 필수 인자로 받는다.
- 멈출 때 찍는 안내 줄 둘(승인, 거부)이 그 값을 싣는다. 안내한 명령은 그대로 복사해 쓸 수 있어야 한다는 규칙이 그대로 선다(`_approval_request` 독스트링).
- 재개 스트림에는 재생된 사실이 없다. 그래서 CLI가 안내 줄의 자리를 재개 스트림의 수만으로 세면 틀린다. 어디서 얻는지는 티켓이 정한다. 길은 둘이다.
  - 트레이스 포트로 읽는다.
  - 받은 자리에 재개 스트림의 프레임 수를 더한다. core가 결정 이벤트를 쓰고 나서 내보내고, 뒤의 이벤트도 쓰고 나서 내보내므로 성립한다(명세 검토가 core 실행 모듈을 읽었다). `run`의 안내 줄은 스트림 전부의 수로 센다.
- 거절은 기반 타입(`PluginError`)의 길로 가서 진단과 종료 코드 1이다. 음수는 인자 오류다.

**문서.** 결정을 참조하는 문장을 같이 고치고 잔존을 grep한다(`CLAUDE.md` 작업 규약 4). 알려진 자리는 이렇다.

- `.claude/rules/core.md`: 재개 시그니처, 결정이 묶이는 것, 첫 걸음의 열거, 실패 정책의 판정 순서와 `NotResumable`의 뜻
- `.claude/rules/channel.md`: 결정 본문
- core 포트 모듈의 `NotResumable` 독스트링("일시정지가 아니거나 형식 1 트레이스다"). 뜻을 둘로 닫은 열거다.
- core 실행 모듈
  - 모듈 독스트링의 재개 불가 열거와 하위 타입 열거
  - `resume()` 독스트링의 첫 걸음 열거("트레이스 읽기, 일시정지 확인, 결정 쓰기")
  - 트레이스 판정 독스트링("마지막 일시정지(결정이 묶이는 호출)")과 결정을 묶는 클래스의 독스트링
- 채널 라우터의 409 주석("뜻이 셋")
- CLI `resume`의 독스트링. 열거의 순서가 "형식 1, 일시정지 아님"이다.
- 채널 테스트의 "409 의 뜻 셋" 독스트링과 동시 재개 테스트 독스트링의 첫 걸음 열거

`.claude/rules/http.md`와 `channel.md`의 "재개 불가"는 타입(`NotResumable`)을 가리켜 그대로 참이다(2026-09-28 grep).

**잔존 grep.** 패턴은 아홉이다. 명세 검토가 재 보니 처음의 넷만으로는 위 목록의 절반을 보지 못했다.

- `뜻이 셋`
- `일시정지 아님, 형식 1`
- `형식 1, 일시정지 아님`
- `일시정지가 아니거나 형식 1`
- `마지막 일시정지`
- `마지막 \`run_paused\``
- `resume\(run_id, decision, approver`
- `Approve \| Deny`
- `트레이스 읽기, 일시정지 확인`

plugin-toggle이 쓴 셋째 grep(`재개 불가|NotResumable|재개할 수 없는`)도 같은 제외로 돌린다. 걸린 것마다 뜻을 둘이나 셋으로 닫아 적었는지 본다. 제외는 plugin-toggle 명세와 같다. 일지, ADR, `.scratch/`, `.claude/worktrees/`, `.scratch/retro-queue.md`다.

**원칙 II 아래서 고치는 기존 테스트.** 필드가 required가 되는 순간 빨개지는 것들이다. 목록에 없으면 구현자가 원칙 II 때문에 멈춘다(plugin-toggle 명세 검토의 선례). 단언의 뜻은 그대로 두고 결정에 자리만 싣는다. 명세 검토가 센 자리다.

- `tests/channel/http/test_router.py`
  - 결정 본문 상수 둘(`APPROVE`, `DENY`)과 그것을 쓰는 테스트들
  - 계약 모양 단언 둘. 결정 본문의 필드 집합이 `{"decision"}`과 `{"decision", "reason"}`이라는 단언이다.
  - 결정 본문의 422 매개변수 테스트. `violations`가 정확히 하나라고 단언하는데, 자리가 빠진 본문은 둘을 낸다.
- `tests/core/test_run.py`의 재개 도우미(기본값 `Approve()`)와 그것을 부르는 곳들
- `tests/test_main.py`
  - 안내 줄의 문자열 단언
  - `main(["resume", …])`를 부르는 테스트들

**LLM 테스트.** `-m llm` 가운데 재개를 지나는 둘이 자리를 싣게 고친다.

- CLI로 다른 프로세스가 재개하는 것(`tests/test_main.py`의 `test_멈춘_실행은_그_프로세스가_끝난_뒤_다른_프로세스가_재개해_끝까지_간다`)
- 실제 `serve`에서 HTTP로 승인하는 것(`test_실제_serve_에서_HTTP_로_일으킨_실행이_승인_대상에서_멈추고_HTTP_승인으로_끝까지_간다`)

이 티켓은 `core/run.py`, `channel/`, `main.py`를 건드리므로 `uv run --env-file .env pytest -m llm`을 돌리고 일지에 적는다(`operations.md` LLM 테스트 절).

**프로브.** 이 티켓 뒤에 `probe_stale_decision.py`를 다시 돌리면 결정이 422이고, 422 봉투에는 `type`이 없어 스크립트가 프레임을 읽다가 `KeyError`로 멈춘다. 스크립트는 근거의 기록으로 둔다. 자리를 실은 변형은 더하지 않는다. 409는 이 티켓의 core·채널 테스트가 덮는다.

### 생성 클라이언트 — `packages/api-client` (ADR 0021, ADR 0010 이력)

- **생성은 openapi-typescript의 기본 출력이다.** 열거는 리터럴 유니온이다. `--immutable`은 거뒀다. openapi-fetch 0.17.0이 readonly 배열을 배열로 보지 못해 응답을 순회할 수 없었다(ADR 0021의 2026-09-29 이력).
- **재귀 `Json`은 생성 스크립트가 `unknown`으로 바꾼다.** openapi-typescript는 `Json`이 제 자신을 가리키는 한 자리에서 TS2502를 내고 그것을 `any`로 둔다(설계 세션이 생성물 `ots/v31.d.ts`를 grep했다). 바꾼 뒤 생성물에 `any`가 없다는 것을 판정자가 본다. 변환은 순수 함수이고 그 자리 하나만 바꾼다. 다른 곳에 `any`가 생기면 판정자가 빨개지도록 둔다.
- **생성물을 커밋한다.** 최신성은 다섯째 명령의 한 단계다.
- **클라이언트는 둘이다(이 명세가 정했다).** 토큰은 요청의 경로를 보고 고르지 않고, 클라이언트가 고른다.
  - 관리 클라이언트는 관리 토큰을 싣는다. 그 타입은 생성된 `paths`에서 채널의 경로 둘을 뺀 것이다.
  - 채널 클라이언트는 채널 토큰을 싣는다. 그 타입은 결정 경로 하나만 안다.
  - 둘 다 openapi-fetch이고 생성된 `paths`를 쓴다.

  이렇게 하면 한 토큰이 맡지 않은 경로에 실리는 실수를 타입이 막는다(스토리 10). 서버의 접두사→토큰 규칙(`.claude/rules/http.md`)을 TS가 다시 판정하지는 않는다. TS가 아는 것은 생성된 경로 키 가운데 어느 것이 채널의 것인가뿐이다. 계약에 채널 경로가 늘면 관리 클라이언트의 타입에 새 경로가 보인다. 그래서 그 목록을 고칠 자리가 컴파일러 앞에 선다. 행동은 페이지 테스트의 헤더 단언이 따로 잰다.
- **`baseUrl`은 `location.origin`에서 만든 절대 주소다.** 상대 경로 `/api`는 jsdom에서 `Failed to parse URL`로 선다(`jsdom_sse.sh`, 스크립트로 쟀다). 브라우저에서는 상대 경로도 되지만, 한 모양이어야 테스트가 제품 코드를 본다.
- **SSE는 손으로 받는다(ADR 0021, ADR 0010 이력).**
  - `parseAs: "stream"`으로 받아 `data:` 줄을 파싱한다.
  - 프레임은 빈 줄로 갈린다. 주석 줄(keepalive `:`)은 이벤트가 아니다. 줄 끝은 `\r\n`과 `\n`을 모두 받는다.
  - 항목은 판별자만 보는 타입 술어로 생성 타입 `Event`가 된다. 종류 목록은 `satisfies Record<Event["type"], true>`로 두어 컴파일러가 생성 타입과 대조한다.
- **술어를 지나지 못한 프레임은 버리지 않는다(이 명세가 정했다).** `JSON.parse`에 실패한 것도 같다. 화면은 그 프레임을 원문 그대로 글자로 보이고 스트림을 계속 읽는다. "읽는 쪽이 모르는 것을 지우지 않고 들고 있게 한다"(ADR 0010·0012 이력)를 스트림에도 건다. 같은 저장소에서 생성하므로 정상이면 일어나지 않는다. 그래도 일어나면, 스트림이 끝난 뒤 다시 읽는 트레이스가 기록의 원천이다.
- **에러 응답은 JSON 봉투다.** 스트림 경로에서도 에러는 스트림이 시작되기 전에 JSON으로 나간다(`.claude/rules/http.md`). openapi-fetch는 `parseAs: "stream"`에서도 409 봉투를 `error`에 파싱해 주었다(`jsdom_sse.sh`, 스크립트로 쟀다).

### 관리 화면 — 중계와 시작 래퍼 (ADR 0019, ADR 0011 이력)

- **`rewrites`는 같은 출처의 `/api/*`를 파이썬 서버로 넘기고 `compress: false`다.**
  - 기본 압축은 SSE를 끝에 몰았다. 끄면 500ms 간격 그대로 흘렀다(`next_measure.mjs`, 스크립트로 쟀다).
  - `Authorization`, `OPTIONS`, 클라이언트의 끊김은 그대로 상류로 간다.
- **상류도 루프백이다(이 명세가 정했다).**
  - 호스트가 `127.0.0.1`이나 `::1`이 아니면 설정이 읽힐 때 구성 오류로 끝낸다. 판정은 설정 파일 안이다. `dev`와 `build`와 `start`가 모두 그 파일을 읽으므로 한 자리에서 막힌다.
  - 기본값은 `http://127.0.0.1:8000`(`serve`의 기본 포트, ADR 0010 이력)이다.
  - ADR 0011의 CWE-319 논증이 바인딩과 똑같이 걸린다. 중계가 루프백에 서도, 상류가 다른 호스트면 토큰이 그 사이를 평문으로 지난다.
  - **`rewrites`는 빌드 산출물에 박힌다.** 명세 검토가 Next 16.3.3 설치본의 코드를 읽었다. dev가 아니면 `rewrites`를 빌드 산출물(`routes-manifest.json`)에서 읽고, `start`도 설정 파일을 불러온다. 결론은 셋이다.
    - 상류 입력은 빌드 때의 값이다. README는 "상류 포트를 바꾸면 다시 빌드한다"를 적는다.
    - 보안은 빌드 때의 판정이 지킨다. `start` 때 설정 파일이 다른 값을 판정해도, 실제 목적지는 빌드 때 값이다. 빌드 때 판정이 통과한 값만 박히므로 새 결정은 필요 없다.
    - e2e는 `serve`의 포트를 빌드 전에 정하고 `build` 뒤 `start`로 띄운다(이 명세가 정했다). 운영에 가까운 모드이기 때문이다. `dev`는 `rewrites`를 빌드 산출물이 아니라 설정에서 바로 읽는다(명세 검토가 16.3.3의 코드를 읽었다). 그러면 e2e가 운영과 다른 길을 재게 된다.

    16.3.6에서 같은지는 중계를 세우는 티켓이 다시 본다. 상류 입력의 이름도 그 티켓이 정한다.
- **시작 래퍼.**
  - `dev`와 `start`는 래퍼를 거친다. 래퍼는 바인딩 호스트가 `127.0.0.1`이나 `::1`이 아니면 구성 오류로 끝낸다.
  - 진단은 `serve`처럼 SSH 포트 포워딩을 안내한다(`tests/test_main.py`의 `test_루프백이_아닌_호스트는_서버가_뜨지_않고_진단이_SSH_포트_포워딩을_안내한다`가 선례).
  - 판정은 순수 함수다. 운영자가 `next`를 직접 다른 인자로 띄우는 것은 막지 못한다(ADR 0019).
- **`agentRules: false`.** 블록의 요지는 그 앱의 web 규칙 한 줄로 옮긴다(ADR 0021).
- **Next에 API를 부르는 서버 코드를 두지 않는다.** 판정은 위 "판정자와 검사" 절의 ESLint다.

### 관리 화면 — 토큰 (ADR 0019)

- **토큰 둘은 Zustand 스토어가 들고 persist를 sessionStorage에 건다.** `partialize`로 토큰만 저장한다. 서버 응답은 스토어에 복사하지 않는다(씨앗, 서버 데이터는 SWR).
- **관리 토큰은 필수다.** 넣으면 목록 요청 하나로 확인하고, 401이면 거부됐다고 말하고 저장하지 않는다(이 명세가 정했다). 틀린 토큰이 저장된 뒤 화면마다 401을 되풀이하지 않게 하기 위해서다.
- **채널 토큰은 선택이다.** 확인할 채널의 읽기 경로가 없다(ADR 0014가 거부했다). 그래서 틀린 채널 토큰은 첫 결정의 401로 드러난다.
- **401의 처리(이 명세가 정했다).**
  - 관리 요청의 401: 관리 토큰을 지우고 입력 화면으로 돌아간다. 메시지는 "관리 토큰이 거부됐다"다.
  - 결정의 401: 채널 토큰만 지우고, 결정 자리에 "채널 토큰이 거부됐다"를 보인다. 관리 화면은 그대로 쓴다.

  토큰마다 따로인 이유는 두 토큰이 다른 면을 여는 다른 권한이기 때문이다(ADR 0015). 거부된 토큰을 들고 있으면 모든 요청이 같은 401을 되풀이한다.
- **토큰 지우기 버튼이 있다.** 두 토큰을 모두 지운다.
- **토큰은 헤더에만 실린다.** URL, 화면의 글자, 콘솔 로그, 에러 표시에 싣지 않는다(원칙 V의 정신, 스토리 9). 에러 봉투는 토큰을 싣지 않는다(`.claude/rules/http.md`).

### 관리 화면 — 화면들

화면은 `components/pages/`의 클라이언트 컴포넌트이고 `app/**/page.tsx`는 라우팅과 레이아웃만 한다(ADR 0021). 데이터는 SWR 훅이 가져오고 컴포넌트는 `useSWR`이나 클라이언트를 직접 부르지 않는다(씨앗). API는 organisms 이상만 부른다(`tech.md` 프론트 구성).

- **플러그인 목록**(`GET /plugins`)
  - 행은 겉 셋(`kind`, `name`, `enabled`)에 `manifest`나 `reason` 하나다. 종류별로 묶는다.
  - 표지 행은 이유를 글자로 보이고 스위치를 둔다.
  - 스킬과 모델 행에는 "로더가 생기기 전에는 효과가 없다"를 보인다.
  - 운영자 파일이 깨지면 목록 전체가 500 봉투다(ADR 0017). 화면은 목록 대신 그 메시지를 보인다.
- **플러그인 하나**(`GET /plugins/{kind}/{name}`)
  - 읽히는 행의 매니페스트를 통째로 보인다.
  - 깨진 매니페스트는 500 봉투의 메시지를 보인다. 경로와 이유다.
  - 없는 이름은 404다.
- **켜고 끄기**(`PUT /plugins/{kind}/{name}/enabled`)
  - 스위치를 누르면 PUT을 보내고 204 뒤에 목록과 그 행을 다시 읽는다. 화면이 값을 먼저 뒤집어 두지 않는다(스토리 18). 누른 뒤 응답까지는 스위치를 막아 두 번 보내지 않는다(이 명세가 정했다). PUT은 멱등이라 두 번 가도 틀리지 않지만, 두 응답이 엇갈려 목록을 두 번 다시 읽을 까닭이 없다.
  - 실패하면 메시지를 보이고, 다시 읽은 값이 스위치를 정한다.
- **실행 목록**(`GET /traces`)
  - 상태 넷과 "전부"로 거른다. 커서(`next_cursor`)로 더 본다. 행은 실행 요약이거나 읽을 수 없는 트레이스다.
  - 상태의 이름은 용어집의 말이다. 일시정지, 끝남, 실패, 결말 없음이다(ADR 0021).
  - 멈춘 실행은 목록에서 바로 알아보게 한다.
- **실행 하나**(`GET /traces/{run_id}`)
  - **상세의 응답에는 요약이 없다.** 필드는 `run_id`, `schema_version`, `events` 셋이다. 목록을 거치지 않고 상세로 곧장 들어온 화면도 서야 한다(ADR 0010의 2026-09-24 이력). 그래서 화면은 트레이스에서 읽는다(이 명세가 정했다).
    - 에이전트는 첫 이벤트(`run_started`)의 `agent`다.
    - 일시정지인지는 마지막 이벤트의 `type`이 `run_paused`인지로 본다.

    이것은 core `run_status()`의 한 갈래를 TS가 다시 쓰는 것이다. 서버에 필드를 더하는 안은 계약을 한 번 더 바꾸게 되어 거부했다. 갈래 하나로 좁히는 이유가 있다. 결정 자리를 세울지만 이것으로 정하고, 상태의 이름을 보이는 것은 목록의 요약에 맡긴다. 규칙이 두 언어에 퍼지는 것은 이 한 줄뿐이다.
  - 이벤트를 쓴 순서 그대로 전부 보인다. 종류별 필드를 글자로 보이고, 모르는 종류(`unknown`)는 원문 문자열을 그대로 보인다.
  - 형식 1이면 "읽을 수 있지만 재개할 수 없다"를 보인다.
  - 인자와 도구 결과 같은 JSON 값은 들여쓴 글자로 보인다. HTML이나 마크다운으로 그리지 않는다.
- **결정**(`POST /runs/{run_id}/approval`, 채널 클라이언트)
  - 보이는 조건: 채널 토큰이 있고, 실행 상태가 일시정지이고, 형식 2 트레이스다. 형식 1이면 결정 자리를 두지 않고 이유를 보인다(이 명세가 정했다, 스토리 52). 누르면 어차피 409이고, 형식 버전은 요약과 상세에 이미 있다.
  - 무엇을 결정하는지는 마지막 이벤트(`run_paused`)의 도구와 인자다. **결정의 자리는 트레이스 상세에서 읽은 그 인덱스다**(ADR 0019 이력). 화면이 자리를 짐작하거나 스트림에서 세지 않는다. 결정 뒤에는 트레이스를 다시 읽기 때문이다.
  - **꺼짐을 미리 알린다(ADR 0019).** 실행의 에이전트(`run_started`의 `agent`)와 그 매니페스트의 `mcp`를 `/plugins`의 행과 잇는다. 무엇이 꺼졌는지 보이고 버튼을 막는다. 에이전트 행이 표지이거나 없으면 미리 알 수 없다. 그 경우는 서버의 봉투가 말한다(500).
  - 허가는 버튼 하나다. 거부는 사유를 적어야 보낼 수 있다. 다듬어 비면 보내지 않는다. 서버의 422(`body.deny.reason`)는 그 자리에 보인다.
  - 보내면 결정 버튼을 막는다. 재개 스트림의 이벤트를 받는 대로 트레이스 아래에 붙인다.
  - 스트림이 결말 이벤트로 끝나거나 결말 없이 끊기면 트레이스를 다시 읽는다. **결정을 다시 보내지 않는다**(ADR 0019). 결말 없이 끊겼으면 스트림이 끊겼고 실행은 서버에서 계속된다는 것을 보인다.
  - 다시 읽은 트레이스가 새 일시정지에서 끝나면 새 자리로 결정 자리가 다시 선다.
  - 409를 받으면 봉투의 메시지를 보이고 트레이스와 `/plugins`를 다시 읽는다(이 명세가 정했다). 자리 어긋남, 일시정지 아님, 형식 1, 꺼짐이 모두 같은 처리다. 가르는 것은 메시지다(ADR 0014 이력). `/plugins`도 다시 읽는 이유가 있다. 꺼짐의 409 뒤에 버튼을 막는 미리 알림이 그 목록에 기대기 때문이다.

### 관리 화면 — 새로 고침과 상태 (설계, 일지 06 R2)

- **포커스, 버튼, 쓰기 직후만 다시 읽는다.** 쓰기는 켜고 끄기와 결정이다. 주기 폴링은 없다. SWR의 포커스 재검증을 켜고 주기 재검증을 두지 않는다.
- **처음 불러오는 중(`isLoading`)과 다시 확인하는 중(`isValidating`)을 가른다.** 앞의 것은 자리표시(스켈레톤), 뒤의 것은 작은 표시다. 다시 확인하는 동안 이미 보인 것을 지우지 않는다(씨앗).
- **에러는 봉투의 `message`와 `request_id`를 보인다.** `violations`가 있으면 그 필드 옆에 보인다. 봉투가 아닌 실패(네트워크, 중계가 상류에 닿지 못함)는 "서버에 닿지 못했다"로 보인다.

### 관리 화면 — 문구와 렌더링 (ADR 0019, 0021)

- **화면 문구는 한국어이고 용어집의 말을 쓴다.** 운영자, 관리 화면, 꺼진 플러그인, 일시정지, 결정, 승인자, 재개, 표지다. 각 항목의 _Avoid_에 적힌 말(예: 콘솔, 대시보드, 비활성, 실행 중, 대기)을 쓰지 않는다.
- **트레이스 내용은 텍스트로만 그린다.** React의 기본 이스케이프에 기대고, `dangerouslySetInnerHTML`과 마크다운의 HTML 렌더를 쓰지 않는다. 앞의 것은 ESLint가 판정한다. 뒤의 것은 그런 의존성을 들이지 않는 것으로 지킨다. 들이려면 ADR이 필요하다(`tech.md`).
- **아이콘은 lucide-react를 서브패스로 import한다(ADR 0021).** 판정은 ESLint다.

### 문서 갱신

바뀐 결정을 참조하는 문장을 같이 고치고 잔존을 grep한다(`CLAUDE.md` 작업 규약 4). 첫 티켓과 계약 티켓의 몫은 위 각 절에 있다. 그 밖의 자리는 이렇다.

- **실제 `serve`를 띄우는 것이 하나라고 적은 문장.** `.claude/rules/http.md`는 "uvicorn이 실제로 포트를 열고 소켓으로 스트림을 흘리는 것"을 `-m llm` 테스트 하나가 잰다고 적었다. `tests/test_main.py`의 `serve` 판정 테스트 독스트링도 uvicorn이 포트를 여는 것은 `-m llm`의 실제 serve 테스트가 잰다고 적었다. e2e가 서면 실제 `serve`를 띄우는 것이 둘이 되고, 그중 매 푸시에서 도는 것은 e2e 하나다. e2e를 세우는 티켓이 둘을 고친다. 이 저장소에서 "둘째 구동자"는 이미 같은 앱을 ASGI로 직접 부르는 것의 이름이다(`tech.md`, `.claude/rules/http.md`). 그래서 e2e는 "실제 `serve`의 둘째 구동자"라고 부른다.
- **`README.md`.** 관리 화면을 띄우는 법(파이썬 `serve`와 포트 맞추기, 토큰 둘)이다. 관리 화면을 세우는 티켓이 적는다.
- **`plan.md`.** 기능 상태가 바뀔 때 행을 고친다. web-widget 행에 넘기는 것 하나를 더한다(Out of Scope).
- **`CONTEXT.md`는 바뀌지 않는다.** 이 기능의 용어 둘(운영자, 관리 화면)은 설계에서 들었다. 결정이 일시정지 하나에 대한 답이라는 것은 "결정"의 정의("승인 하나가 내린 답")에 이미 있다.

## Testing Decisions

좋은 테스트는 **바깥 행동만** 본다. 이 기능에서 바깥 행동은 이렇다.

- **화면에 보이는 것.** 역할과 글자, 버튼이 눌리는가, 입력이 받아지는가다.
- **HTTP 경계를 지나는 요청.** 경로, 메서드, 헤더의 토큰, 본문이다.
- **sessionStorage에 남은 것.**
- **CLI의 종료 코드와 진단, 트레이스 파일, 계약 파일.**
- **판정자와 검사의 종료 코드와 보고.**

클래스 이름, 컴포넌트 구조, 훅의 내부 상태, 스토어의 모양은 단언하지 않는다. 테스트 이름은 행동 명세로 쓴다. TS 테스트의 이름도 한국어 문장이다(이 명세가 정했다). `CODING_STANDARDS.md`가 테스트 함수명에 요구하는 것의 연장이다. 그 파일에 적는 것은 사용자가 "규칙으로"라고 말한 뒤다.

원칙 II대로 구현 전에 실패하는 테스트를 쓴다. 테스트가 실패하면 테스트를 고치지 않고 멈춰 보고한다. 환경이 없어 건너뛴 테스트는 초록이 아니다. 브라우저가 없어 e2e가 건너뛰면 실패여야 한다.

### 주 이음매 — 페이지 (Vitest jsdom + Testing Library + MSW)

프리어 아트는 아직 없다. 이 기능이 첫 TS 테스트다. 원칙은 파이썬 쪽의 주 이음매와 같다. 가짜는 바깥 경계(HTTP) 하나에만 두고, 그 안은 진짜다(`tests/test_server.py`, `tests/channel/http/test_router.py`의 `create_app()` + `ASGITransport`).

- **가짜의 모양.** MSW 핸들러의 응답 본문은 생성 타입(`components["schemas"]`)으로 적는다. 계약이 바뀌면 핸들러가 컴파일에서 깨진다(스토리 81). SSE 핸들러는 `ReadableStream`으로 프레임을 시간 간격을 두고 낸다(`jsdom_sse.sh`의 모양).
- **격리.** 테스트마다 SWR 캐시를 새로 두고(`provider`), 스토어와 sessionStorage를 비운다. 처리하지 않은 요청은 에러다(`onUnhandledRequest: "error"`). 화면이 부르지 말아야 할 경로를 부르면 빨개진다.

여기서 판정하는 것:

- **토큰**
  - 관리 토큰 없이는 입력 화면이다.
  - 넣은 토큰이 확인 요청의 `Authorization`에 실린다. 401이면 저장되지 않는다.
  - 저장된 토큰이 sessionStorage에 있고 다른 상태는 없다. localStorage는 비어 있다(스토리 2).
  - 새로 그려도 토큰이 남는다.
  - 토큰이 URL, 화면의 글자, 콘솔 어디에도 없다(스토리 9). 위치의 경로·질의, 문서의 글자를 보고, 콘솔 출력을 가로채 본다. 토큰 입력칸 자체는 가린 입력이라 값이 글자로 보이지 않는다.
  - 관리 요청의 401이 관리 토큰만 지우고 입력으로 돌아간다. 결정의 401이 채널 토큰만 지우고 결정 자리에 알린다.
  - 토큰 지우기가 둘을 지운다.
  - 관리 요청에 채널 토큰이, 결정 요청에 관리 토큰이 실리지 않는다. 핸들러가 헤더를 본다.
- **플러그인**
  - 종류별로 묶인 행과 켜짐이 보인다. 표지 행은 이유를 보인다.
  - 운영자 파일 손상의 500 봉투가 목록 대신 메시지와 `request_id`로 보인다.
  - 하나를 열면 매니페스트가 보인다. 깨진 매니페스트는 메시지가 보인다.
  - 스킬과 모델 행에 효과 없음이 보인다.
- **켜고 끄기**
  - 스위치가 PUT을 보내고(본문 `{"enabled": false}`) 204 뒤에 목록을 다시 읽는다.
  - 응답 전 두 번째 누름은 요청을 더 보내지 않는다.
  - 실패하면 메시지가 보이고 스위치가 다시 읽은 값이다.
  - 표지 행도 끌 수 있다.
- **실행 목록**
  - 행이 서버가 준 순서 그대로다(스토리 23). 화면이 다시 정렬하지 않는다.
  - 상태로 거르면 질의에 `status`가 실린다. 커서로 더 보면 `after`가 실린다.
  - 상태 이름이 용어집의 말이다. "결말 없음"이 보이고 "실행 중"은 어디에도 없다.
  - 읽을 수 없는 트레이스 행이 식별자와 이유를 보인다.
- **실행 하나**
  - 이벤트가 쓴 순서대로 보이고, `unknown`의 원문이 보이고, 형식 1이면 재개할 수 없다는 것이 보인다.
  - **HTML이 든 도구 결과가 글자 그대로 보이고 요소로 그려지지 않는다.** 예는 `<img src=x onerror=…>`다. 문서에 그 요소가 없음을 본다.
- **결정**
  - 채널 토큰이 없으면 결정 자리가 없다.
  - 있으면 도구와 인자가 보인다. 허가가 본문에 판별자와 **트레이스 상세에서 읽은 인덱스**를 싣는다.
  - 거부는 사유가 비면 보내지지 않는다. 사유가 본문에 실린다.
  - 재개 스트림의 이벤트가 받는 대로 붙는다. 스트림이 닫히기 전에 첫 이벤트가 화면에 있다.
  - 스트림이 끝나면 트레이스를 다시 읽는다.
  - 결말 없이 끊기면 결정을 다시 보내지 않는다. 결정 요청은 정확히 한 번이다.
  - 다시 멈춘 트레이스가 새 인덱스로 결정 자리를 다시 세운다.
  - 409면 메시지가 보이고 트레이스를 다시 읽는다.
  - 에이전트나 그 mcp가 꺼졌으면 버튼이 막히고 무엇이 꺼졌는지 보인다.
  - 형식 1이면 결정 자리가 없다.
  - 422의 `violations`가 사유 옆에 보인다.
  - 술어를 지나지 못한 프레임이 원문 그대로 보이고, 뒤의 프레임도 계속 붙는다.
- **새로 고침과 에러**
  - 창 포커스에 목록을 다시 읽는다. 시간이 흘러도 스스로 다시 읽지 않는다(가짜 시계로 민다).
  - 새로 고침 버튼이 다시 읽는다(스토리 34).
  - 다시 확인하는 동안 이미 보인 행이 남아 있다.
  - 네트워크 실패(MSW의 네트워크 에러)가 "서버에 닿지 못했다"로 보인다(스토리 37).

### 좁은 이음매 — 순수 함수

- **SSE 프레임 파서**
  - 조각 경계가 프레임 한가운데서 갈려도 프레임 하나다. 한 조각에 프레임이 여럿이어도 된다.
  - 주석 줄은 이벤트가 아니다. `\r\n`과 `\n`을 모두 받는다.
  - `data:` 뒤의 공백 하나는 값이 아니다. 파이썬 쪽 선례는 `tests/test_main.py`의 `test_스트림을_가를_때_keepalive_주석은_이벤트로_읽지_않는다`다.
- **판별자 술어**
  - 계약의 종류마다 참이고, 모르는 `type`, 객체가 아닌 것, `type`이 없는 것은 거짓이다.
  - 종류 목록이 생성 타입과 어긋나면 컴파일이 실패한다. 이것은 타입 테스트 파일에서 `@ts-expect-error`로 고정한다.
- **생성 스크립트의 `Json` 변환**
  - openapi-typescript가 낸 그 자리만 `unknown`이 되고 다른 바이트는 그대로다.
  - 기대한 자리가 없으면 조용히 지나가지 않고 실패한다. 생성기를 올려 모양이 바뀌면 알아야 한다.
- **루프백 판정**
  - 래퍼의 바인딩 호스트와 설정의 상류 호스트를 본다. `127.0.0.1`과 `::1`은 통과한다.
  - `0.0.0.0`, `::`, `localhost`, LAN 주소, 호스트 이름은 구성 오류이고, 진단이 허용되는 두 주소와 SSH 포트 포워딩을 말한다.
  - `serve`의 규칙과 같다. `main.py`는 허용 목록을 `127.0.0.1`과 `::1` 둘로 두고 문자열 그대로 비교한다. `localhost` 거부는 `tests/test_main.py`의 `test_허용되는_루프백_주소_둘이_진단에_그대로_적혀_있다`가 고정한다(명세 검토가 코드를 읽었다). 이름은 `::1`로도 풀릴 수 있어 루프백이라는 보장이 없다.
- **tsconfig 검사**
  - `strict: true`만 있으면 통과한다.
  - `strict`가 없거나 거짓이면 실패한다. `extends`로 물려받은 설정이 켜고 자식이 끄면 실패한다.
  - `strict: true`에 `strictNullChecks: false`가 있으면 실패한다.

### 판정자와 검사의 변이 테스트 (첫 티켓)

"검사 도구가 내가 생각하는 것을 실제로 봤는지 먼저 확인한다"(`CLAUDE.md` 환경 함정, 세 번 겪었다). 저장소 상태를 보는 검사에는 두 테스트를 하나씩 둔다(`.claude/rules/tests.md`). 이 저장소가 지금 통과함을 재는 테스트와, 위반을 잡는 변이 테스트다.

- **ESLint 판정자**
  - 위반을 담은 코드를 테스트가 만들어 판정자에 넣는다. 커밋한 파일에 위반을 두지 않는다. 두면 그 파일을 빼는 목록이 생긴다(ADR 0013이 경계한 모양).
  - 재는 위반은 이렇다.
    - `.ts`: `any`, `as`, 꺾쇠 단언, `!`, `@ts-ignore`, `@ts-nocheck`, TS `enum`, 전역 `fetch`(생성 클라이언트 패키지 안팎. 패키지의 예외는 티켓 03이 거뒀다)
    - `.tsx`: `dangerouslySetInnerHTML`
    - `.d.ts`: `any`
    - 타입 테스트가 아닌 파일의 `@ts-expect-error`
    - Server Actions 지시문, 그리고 Next 서버가 돌리는 파일(`route`, `middleware`, `proxy`, `instrumentation`)
    - 층 경계: atoms가 organisms를 import하는 것, 앱 사이의 import, barrel을 거르지 않는 import
    - 아이콘 세트를 통째로 import하는 것(서브패스가 아닌 것)
    - **끄기 주석과 그것이 끄려던 위반.** 끄기 주석은 혼자서는 경고라서, 경고 0이 게이트인 `verify`의 린트 명령으로 돌린 결과가 빨강이어야 한다. 그리고 그 주석이 끄려던 위반도 그대로 보고되어야 한다.
  - 각각이 빨강이다. `as const`와 타입 테스트 파일의 설명 붙은 `@ts-expect-error`는 초록이다.
  - 뼈대에는 앱이 없으므로, 타입 기반 규칙을 앱 자리의 파일에 돌릴 수 있는지(프로젝트 서비스가 tsconfig 밖의 파일을 거부할 수 있다)는 이 티켓이 먼저 본다. 명세 검토도 재지 않았다.
- **tsconfig 검사**
  - 워크스페이스의 실제 tsconfig 전부가 통과한다.
  - 하나를 바꾼 사본은 실패한다.
  - `web/` 아래에 새로 둔 tsconfig가 목록을 고치지 않아도 검사에 든다.
- **중첩 지침 파일 검사**
  - 이 저장소가 지금 통과한다.
  - 하위 디렉터리에 `CLAUDE.md`나 `AGENTS.md`를 둔 사본에서 실패한다. `node_modules/` 아래의 것은 무시한다. 스토리 79를 결과로 덮는 테스트다.
  - 검사의 CLI 진입점을 subprocess로 한 번 부르는 테스트가 이 빨강을 출력에서 본다. 저장소 밖 임시 트리를 루트 인자로 준다(`.claude/rules/tests.md`, #94).
- **게이트 훅**
  - `pnpm -C web verify`와 e2e 명령을 파이프 뒤에 둔 입력에서 경고하고, 단독으로 친 입력에서는 조용하다(`tests/tools/test_hook_bash_gate_pipe.py`에 더한다).
  - 같은 두 입력을 `tools/hook_payloads.toml`에 더해 `tools/run_hooks.py`가 실제 훅으로 돌린다.

생성물 최신성과 생성물이 판정 범위에 드는지의 변이 테스트는 이 티켓이 아니라 생성 클라이언트 티켓의 것이다(위 "판정자와 검사" 절). 그 티켓에서의 모양은 이렇다. 최신성은 지금 통과하고, `openapi.json`의 설명 한 줄을 바꾼 사본에서 실패한다. 판정 범위는 판정자가 커밋된 생성물을 무시하지 않는다는 것이다.

앱을 세우는 티켓은 경로에 기대지 않게 쓴 규칙들이 실제 배치에서 빨강인지 다시 본다. 같은 변이를 앱의 실제 자리에 넣는다.
- **실제 실행으로 확인한다**(`CLAUDE.md` 작업 규약 3).
  - pre-commit이 다섯째 명령을 실제로 돈다. 훅의 출력으로 본다.
  - CI의 `verify` 잡 로그에 web 단계가 있다. `gh run view`로 본다.
  - 빨강은 `tools/mutate.py`로 본다(`.claude/rules/tools.md`).

### e2e — Playwright, 실제 `serve`와 실제 중계

실제 `serve`를 서브프로세스로 띄우는 선례는 `tests/test_main.py`의 `test_실제_serve_에서_HTTP_로_일으킨_실행이_승인_대상에서_멈추고_HTTP_승인으로_끝까지_간다`다(`-m llm`).

**e2e는 실제 `serve`의 둘째 구동자이고, 모델을 부르지 않는다.**

- 픽스처 에이전트는 모델 없이 승인 대상 도구를 `ctx.tool()`로 직접 부른다.
- 도구는 기존 MCP 픽스처 서버(`tests/adapters/mcp_fixture_server.py`)가 준다.
- 그래서 결정 뒤의 재개가 모델 없이 끝까지 간다. 승인 뒤 모델을 부르는 경로는 LLM 테스트의 몫이다(일지 06).

**픽스처 플러그인 루트는 테스트 준비가 임시 디렉터리에 쓴다(이 명세가 정했다).** MCP 매니페스트가 그 기계의 파이썬 인터프리터 경로를 들어야 해서 커밋할 수 없다. `tests/test_main.py`가 `sys.executable`로 짓는 것과 같다.

**읽기용 트레이스**(끝남, 실패, 형식 1, 모르는 종류의 줄, 읽을 수 없는 파일)도 준비가 쓴다.

**멈춘 실행은 준비가 채널 토큰으로 `POST /runs`를 보내 만든다.** 화면 밖의 요청이다.

**토큰은 테스트만 아는 값이다.** 준비가 만들어 두 프로세스의 환경에 넘긴다. 화면에는 테스트가 입력한다. 커밋하지 않는다.

흐름은 셋이다.

- **읽기.**
  - 토큰을 넣고, 플러그인 목록과 실행 목록을 본다.
  - 실행 하나를 열어 모르는 종류의 원문과 형식 1의 표시를 본다.
  - 트레이스의 HTML이 요소로 그려지지 않는다. 실제 브라우저에서 한 번 더 본다.
- **켜고 끄기.**
  - 스위치로 에이전트를 끄면 플러그인 루트에 운영자 파일이 생긴다. 목록이 꺼짐을 보이고, 그 에이전트의 멈춘 실행에 결정 버튼이 막힌다.
  - 다시 켜면 풀린다.
- **결정.**
  - 멈춘 실행을 허가하면 재개 스트림이 화면에 붙고, 실행이 끝남으로 바뀌며, 도구가 실제로 불렸다(트레이스의 `tool_called`).
  - **오래된 화면**
    - 한 턴에 승인 대상이 둘인 실행을 화면에 열어 둔다.
    - 테스트 준비가 채널 토큰으로 그 실행의 첫 일시정지를 직접 허가한다. 실행은 둘째에서 다시 멈춘다.
    - 그다음 화면에서 옛 일시정지를 허가한다. 409 메시지가 보이고, 새 일시정지가 보이고, 둘째 도구는 불리지 않았다.

    "다른 곳"을 둘째 탭이 아니라 준비의 요청으로 두는 이유가 있다(이 명세가 정했다). 탭을 바꾸면 포커스 재검증이 먼저 새 일시정지를 읽어, 옛 자리를 보낼 기회가 사라질 수 있다. 헤드리스 브라우저에서 탭 전환이 포커스 사건을 내는지는 명세 검토가 재지 않았다. 준비의 요청은 화면의 포커스를 건드리지 않는다.
  - 재개 스트림이 조각으로 온다. 첫 이벤트가 결말보다 먼저 화면에 있다. `compress: false`의 회귀를 잡는 자리다.

**e2e가 재지 않는 것.**

- 루프백 거부는 순수 함수와 래퍼의 테스트가 잰다. e2e가 LAN 주소에 바인딩을 시도하지 않는다.
- 침묵 30초의 끊김은 설계 측정(`next_measure.mjs`의 `gaplong`)이 근거다. CI에서 수 분을 기다리지 않는다. 대신 간격의 짝은 아래 파이썬 테스트가 고정한다.

**e2e를 세우는 티켓이 함께 두는 파이썬 테스트 둘(이 명세가 정했다).** 둘 다 중계가 기대는 서버의 성질인데 지금 테스트가 없다(명세 검토). 이음매는 새것이 아니다. 채널 테스트와 같은 `create_app()` + `ASGITransport`다.

- **다른 출처의 preflight는 토큰 없이 401이다.** ADR 0011 이력은 "미들웨어는 메서드를 가르지 않는다"고 적었지만, 파이썬 테스트에 `OPTIONS`가 한 번도 없다. `tests/test_server.py`에 관리 경로 하나와 채널 경로 하나의 토큰 없는 `OPTIONS`가 401이라는 테스트를 둔다(스토리 65).
- **keepalive 간격이 중계의 침묵 한도(30초)보다 짧다.** 15초는 FastAPI의 사적 상수라 올림에서 조용히 바뀔 수 있다. 기존 `test_모델이_조용한_동안_keepalive_주석이_나간다`가 줄여 쓰는 바로 그 이름(`fastapi.routing`의 것)을 읽어 30보다 작은지 단언한다(스토리 67).
  - **이것은 이 명세의 "바깥 행동만"의 예외다.** 행동으로 재려면 기본 스위트에서 15초 넘게 기다려야 한다.
  - 기존 테스트가 이미 같은 이름에 기대므로 새로 느는 결합은 없다. 이름이 사라지면 두 테스트가 함께 깨지고, 그것이 올림에서 다시 볼 신호다.

**CI.** e2e는 `verify` 잡의 한 단계다(ADR 0021 이력). 브라우저는 그 잡에서 설치한다. 브라우저가 없어 건너뛰면 실패다. 로컬에서는 중계, 시작 래퍼, api-client, 서버 라우트를 건드렸을 때 친다.

### 파이썬 — 계약 티켓 (기존 이음매)

**core.** 프리어 아트는 `tests/core/test_run.py`의 `test_한_턴에_승인_대상이_둘이면_재개한_뒤_둘째에서_다시_멈춘다`다.

- 자리가 맞으면 지금과 같다.
- 한 턴에 승인 대상이 둘일 때, 첫 일시정지의 자리로 둘째 일시정지에 결정하면 `NotResumable`이다. 메시지가 두 자리를 든다. 트레이스는 이벤트 수와 마지막 이벤트가 그대로다. 도구는 불리지 않는다.
- **같은 도구와 같은 인자로 두 번 멈춘 경우도 자리가 가른다.** 이것이 도구와 인자로 묶는 안을 거부한 근거의 테스트다.
- 일시정지가 아니면 자리와 무관하게 "일시정지 아님"이다(순서).
- 꺼진 에이전트여도 자리 어긋남이 먼저다(순서).
- 음수 자리(`-1`)는 `NotResumable`이다. 파이썬의 음수 인덱스로 마지막 이벤트에 맞지 않는다.
- 동시 재개 불변식의 기존 테스트가 같은 자리를 든 둘로 그대로 초록이다.

**채널.** 프리어 아트는 `tests/channel/http/test_router.py`의 `test_재개가_다시_멈추면_같은_경로로_둘째_결정을_내_끝까지_간다`와 `test_한_루프에서_동시에_온_결정_둘은_하나만_받아들여져_도구가_한_번_불린다`다.

- 자리가 없거나, 음수이거나, 추가 필드가 있으면 422다. **정수가 아닌 것은 JSON 정수로 보이는 것까지 422다.** 문자열 `"2"`, 실수 `2.0`, 불린 `true`, 소수 `2.5`다. 앞의 셋은 lax 검증이면 받아진다(`probe_lax_index.py`). 그래서 이 사례들을 고르지 않은 테스트는 lax로도 초록이다. `violations`가 그 필드를 가리킨다. 이때 포트는 불리지 않는다.
- 자리가 어긋나면 409 봉투이고 트레이스가 바뀌지 않는다.
- 스트림을 모두 본 클라이언트가 센 수로 다음 결정을 낼 수 있다(스토리 61). 본 프레임의 총수에서 1을 뺀 것이 마지막 이벤트, 곧 새 일시정지의 자리다. 예를 들어 첫 스트림이 셋(`run_started`, `llm_called`, `run_paused`)이고 재개 스트림이 넷이면 자리는 6이다. 셀 때 1을 빼지 않으면 409다. 명세 축 리뷰가 스크립트로 쟀다.
- `openapi.json`이 `create_app().openapi()`와 같다. 두 결정 본문에 그 필드가 required이고 `minimum: 0`이다.
- 두 번 멈추는 기존 테스트 안의 결정 본문 둘은 자리를 싣게 고친다.

**CLI.** 프리어 아트는 `tests/test_main.py`의 `test_안내된_재개_명령을_그대로_실행하면_재개된다`, `test_멈추면_거부_명령도_함께_안내된다`, `test_플러그인_루트를_지정했으면_안내된_재개_명령이_그것을_물려받는다`다.

- 안내 줄 둘이 자리를 싣는다. 그대로 실행하면 재개된다.
- 재개가 다시 멈추면 새 안내 줄의 자리가 새 일시정지의 것이다. 재개 스트림만 세면 틀리는 자리다.
- 옛 안내 줄을 그대로 치면 진단과 종료 코드 1이고, 트레이스가 바이트 그대로다.
- 자리를 빼거나 음수를 주면 인자 오류다.

### LLM 테스트

**새로 두지 않는다.**

- 관리 화면은 모델을 부르지 않는다.
- 결정의 자리는 모델 호출보다 앞(`resume()`의 첫 걸음)에서 판정된다.
- 승인 뒤 모델을 부르는 경로는 기존 HTTP LLM 테스트가 이미 잰다.

**계약 티켓이 기존 `-m llm`을 돌린다.** 재개를 지나는 둘이 자리를 싣도록 고친 뒤다. 결과는 그 티켓의 일지에 남긴다(통과 수와 토큰 합계, `operations.md`). CI는 이 마커를 돌리지 않는다.

## Out of Scope

- **실행을 일으키는 화면.** 관리는 실행을 일으키지 않는다(용어집). 요청을 보내는 화면은 채널이고, 위젯(web-widget)의 몫이다.
- **플러그인의 등록, 해제, 편집.** 진실의 원천은 파일시스템이고(ADR 0003) 관리 API에 그 경로가 없다.
- **실시간 관찰(구독, 재접속, 떠난 스트림에 다시 붙기).** ADR 0014가 위젯으로 미뤘다. 관리 화면은 트레이스를 다시 읽어 이어 본다.
- **로그인, 세션, 쿠키.** ADR 0019가 BFF를 거부했다. 쿠키를 들이는 날 Host 검사를 다시 본다.
- **원격 배치와 TLS.** ADR 0011이 원격의 답을 SSH 포트 포워딩으로 두었다.
- **정적 내보내기(`output: "export"`) 서빙.** 일지 2026-09-19가 슬라이스 3으로 넘겼다. 정적 내보내기에는 `rewrites`를 돌릴 Next 서버가 없어, ADR 0019의 중계와 함께 설 수 없다. 이 명세는 따로 재지 않았다.
- **Storybook과 공유 atoms(`packages/ui`).** ADR 0021이 web-widget에서 다시 보기로 했다.
- **ADR 0021 밖의 ESLint 플러그인.** 예는 react-hooks 규칙이다. 들이려면 ADR 0021의 이력으로 제안한다. 훅 규칙 위반은 이 기능에서 페이지 테스트가 행동으로 잡는다.
- **트레이스 내용의 마크다운 렌더링과 문법 강조.** 텍스트로만 그린다(ADR 0019).
- **다국어.** 화면은 한국어만이다(설계 R1).
- **일시정지의 만료, 4-eyes, 자기 승인 금지.** ADR 0009가 미뤘고 설계 인터뷰에서 필요가 생기지 않았다.
- **프로세스 사이의 결정 경합.** 두 프로세스가 같은 자리를 들고 같은 순간에 오면 둘 다 통과한다. 알려진 한계 그대로다(ADR 0014).
- **web-widget에 넘기는 것.** `plan.md`의 web-widget 행에 여섯째로 적는다. 그 행의 Blocked by에 web-admin이 있다.
  - **(6) 결정은 그것이 답하는 일시정지의 자리를 든다**(ADR 0014의 2026-09-28 이력). 위젯이 결정을 내린다면 그 자리를 알아야 한다. 스트림만 보는 클라이언트는 자기가 본 프레임의 총수에서 1을 뺀 값으로 센다. 하나라도 놓치면 409를 받고 트레이스를 읽을 수 없어 다시 맞추지 못한다. 재접속(SSE `id:`)을 만드는 날 그 번호를 같은 자리로 두는 것이 ADR 0014 이력이 열어 둔 길이다.

## Further Notes

- **근거의 종류.** 이 명세가 든 근거는 셋으로 갈린다(대기열 45). 목록은 여기 하나다.
  - **스크립트로 쟀다.**
    - 이 명세: `probe_stale_decision.py`, `jsdom_sse.sh`, `tsc_showconfig.sh`
    - 명세 검토: `probe_lax_index.py`
    - 설계: `next_measure.mjs`, `gen_run.mjs`, `ts7_lint.sh`
  - **코드를 읽었다.**
    - core의 재개 진입점이 마지막 이벤트를 일시정지로 쓰는 것
    - 재개할 수 있는 트레이스에서 core의 인덱스와 상세의 인덱스가 같은 것
    - `serve`의 루프백 판정
    - CLI가 자리를 더해 셀 수 있는 것
    - openapi-typescript 생성물의 `any` 자리(설계 세션)
    - 명세 검토가 옆 저장소의 설치본에서 읽은 넷. 판이 이 명세의 것과 다르다.
      - Next 16.3.3: `rewrites`가 빌드에 박히는 것, 서버 파일 관례, tsconfig를 고쳐 쓰는 것
      - typescript-eslint 8.33.1: `as const` 면제, `ban-ts-comment` 기본값
      - ESLint 9.39.5: `noInlineConfig`일 때 인라인 설정 주석이 경고라는 것
  - **재지 않았다.**
    - 판정자가 비null 단언, `@ts-ignore`, `@ts-nocheck`, 꺾쇠 단언, `.d.ts`, 인라인 설정 주석, 내장 규칙들을 어떻게 다루는지. 첫 티켓의 변이 테스트가 잰다.
    - 타입 기반 규칙을 앱이 없는 뼈대의 앱 자리 파일에 돌릴 수 있는지. 첫 티켓이 잰다.
    - Next 16.3.6에서 `rewrites`와 서버 파일 관례가 16.3.3과 같은지. 중계와 앱을 세우는 티켓이 잰다.
    - ESLint 10.11.0에서 인라인 설정 주석의 심각도. `--max-warnings 0`이 어느 쪽이든 덮는다.
    - 헤드리스 브라우저에서 탭 전환이 포커스 사건을 내는지. e2e의 오래된 화면 흐름이 탭 전환을 쓰지 않게 해서 비켜 갔다.

    넷째까지는 ADR 0020·0021이 정한 것을 확인하는 일이라, 어긋나면 설정을 고치고 새 결정을 낳지 않는다.

  - 게이트 훅의 목록

  - 관리 클라이언트의 타입

  나머지는 목록을 채우고 주장을 좁혔다.
- **설계의 "CI 워크플로는 별도 PR로 먼저"는 고쳐졌다.** 사용자가 이 명세를 쓰며 "web 뼈대와 같은 PR"을 골랐다(ADR 0021의 2026-09-28 첫 이력). `plan.md` 행의 그 문장도 이 커밋에서 고친다.
- **CI 시간이 는다.** Node 설치, pnpm 설치, Next 빌드, Playwright 브라우저 설치가 `verify` 잡에 든다. 필수 검사가 하나라서 잡이 길어지면 모든 PR이 기다린다. 캐시(pnpm 스토어, 브라우저)는 CI를 바꾸는 티켓이 본다.
- **윈도우 개발 기계.** 이 저장소의 개발 기계는 윈도우다(Node 24.19.0, pnpm 11.24.0, 이 세션에서 확인). e2e와 래퍼는 윈도우와 CI의 ubuntu에서 모두 돌아야 한다. `next_measure.mjs`가 윈도우 전용 도구(taskkill, netstat)를 쓴 것과 달리, 테스트는 운영체제별 명령에 기대지 않는다.
- **`probe_stale_decision.py`는 계약 티켓 뒤 `KeyError`로 멈춘다.** 결정이 422이고 봉투에 `type`이 없기 때문이다. README 행이 적었다. 근거의 기록으로 두고 변형을 더하지 않는다(계약 티켓 절의 "프로브").
- **PR 직전 CLI 축은 좌석이 있으면 `coderabbit-review`를 돌리고, 없으면 돌리지 않고 체크리스트에 그 사실을 적는다**(`docs/constitution/operations.md` 리뷰 파이프라인 2항). PR과 병합은 사용자가 말할 때다.
- **환경 규약은 그대로다.** Git Bash에서는 `uv run python`을 쓰고, 커밋 메시지는 heredoc이나 파일로 넘긴다. 검사 도구가 내가 생각하는 것을 실제로 봤는지 먼저 확인한다.
