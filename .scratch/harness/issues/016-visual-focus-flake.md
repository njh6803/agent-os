# 016: 사진 비교가 몇 픽셀 차이로 흔들리는 원인을 재서 고친다

**What to build:** `visual` 잡이 웹 코드를 건드리지 않은 PR에서 사진 한 장의 몇 픽셀 차이로 빨갰다가 다시 돌리면 초록이 되는 일이 세 번 났다. 사진은 셋 다 달랐다(스위치 꺼짐의 다크 포커스 1픽셀, 여러 줄 글 입력의 다크 올림 3픽셀, 알림 보여 주기의 라이트 6픽셀). 실패한 실행의 실제·정답·차이 그림과 같은 이미지에서 되풀이해 찍은 사진으로 어느 픽셀이 왜 갈리는지 재고, 그 원인을 없앤다. 문턱(`maxDiffPixels`, `threshold`)을 넓히지 않는다. 사진 비교를 느슨하게 하는 길이라 대기열 행이 넘겼다.

대기열 행은 원인을 포커스 링 전환의 찍는 시점으로 보고 찍기 전 대기를 처방했다. 재 보니 원인은 크롬의 부분 래스터였고(인자 없이는 같은 코드의 사진이 두 그림 가운데 하나로 찍혔고 알림은 찍는 시점에 따라 갈렸다. 부분 래스터를 끄면 그림이 하나였다), 기다리는 것으로는 고쳐지지 않았다. 그래서 고침은 사진 비교의 브라우저 실행 인자(`--disable-partial-raster`)와, 그 인자로 다시 만든 정답 사진이다. 근거는 아래 Comments와 프로브 `.scratch/harness/probes/visual_flake/`다.

- [x] 그 인자로 정답을 한 번 더 전부 다시 써도 바이트까지 같다
- [x] 고친 뒤 같은 프로브로, 흔들리던 세 사진이 곧바로 찍든 기다려 찍든 정답과 같고 CI가 실패하며 올린 세 실제 그림이 고친 뒤의 사진과 바이트까지 같은 것을 본다
- [x] 문턱(`maxDiffPixels: 0`, `threshold: 0`)이 그대로다
- [x] 검증 명령이 모두 초록이고 `pnpm -C web visual`·`pnpm -C web visual:widget`이 초록이다

## Comments

### 2026-10-26 원인(프로브 `visual_flake/`)

- 실패한 세 실행(`39725276747`, `39786765789`, `39941987396`)의 아티팩트에서 갈린 픽셀은 모두 둥근 모서리에서 테두리와 바탕 사이의 중간색으로 칠한 불투명 픽셀(알파 255)이고 채널마다 1~3씩 부호가 섞여 달랐다(`ci_diff.mjs`). 나머지 픽셀은 같았다. Playwright 기록은 100ms 넘게 떨어진 두 장이 같았다("captured a stable screenshot")고 적어, 전환 도중에 찍힌 것이 아니다.
- 이미지의 크롬은 GPU 없이 소프트웨어로 래스터한다(`SystemInfo.getInfo`의 `rasterization: disabled_software`).
- 결과의 수는 이 PR의 프로브 README 행이 적는다.
