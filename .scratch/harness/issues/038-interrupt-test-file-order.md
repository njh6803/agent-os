# 038: Ctrl+C 시험의 앞뒤 판정을 시계 값 비교가 아니라 자식이 파일에 쓴 순서로 가른다

**What to build:** `tests/channel/cli/test_interrupt.py`의 `test_도구_호출_도중에_한_번_누르면_서버를_닫고_중단으로_끝난다`가 `assert 끝.pressed[0] < 끝.cancelled`에서 이 PC(윈도)의 pre-commit과 시험 파일 단독 실행에서 여러 번 빨갰고, 두 값이 정확히 같았다. 자식 프로세스가 누르기 직전과 취소를 받은 직후에 각각 `time.time()`을 파일에 쓰는데, 두 호출 사이가 짧으면 같은 눈금에 들어 같은 값이 나오는 때가 많고, 그러면 `<`가 거짓이 된다. 이 PC에서 `time.time()`을 연달아 두 번 부른 값이 20000쌍 중 19999쌍에서 같았다(`uv run python -c "import time; print(sum(1 for _ in range(20000) if time.time()==time.time()))"`로 손으로 봤다. 시계의 눈금만 보여 주고 시험의 실제 간격은 재지 않았다). 대기열 531은 부하 없이도 빨갰다고 적었다. 그래서 자식이 표지 파일을 쓸 때 공용 순서 파일 `order.txt`에 이름을 한 줄씩 덧붙이게 하고, 시험은 앞뒤를 그 줄의 순서로 판정한다. 같은 시험 파일의 다른 앞뒤 판정(`cancelled < pressed[1]`, `closing < pressed[0]`, `pressed[0] < closed`)도 같은 종류의 비교라 함께 옮긴다. 순서 파일에는 신호를 올리기 전에 먼저 덧붙이고, 다른 스레드가 기다리는 표지 파일(`cancelled`, `closing`)은 순서 파일에 덧붙인 뒤에 만든다. 그래야 "표지를 본 뒤 한 일"이 순서 파일에서도 뒤에 온다. 끝나기까지의 시간 단언(`ended - pressed[1]`)은 길이를 재는 것이라 시각 파일을 그대로 쓴다. `<`를 `<=`로 바꾸는 길은 판정을 느슨하게 해서 같은 눈금에 든 역순도 통과시키므로 택하지 않는다.
