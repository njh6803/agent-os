# 018: 푸시 훅의 도움말 시험이 git 의 종료 코드에 기대지 않게 한다

**What to build:** CI 러너 이미지 ubuntu-24.04 20261025.353.1(git 2.56.0)에서 `git push -h` 가 사용법을 내고 푸시하지 않은 채 129 가 아니라 0 으로 끝나, `tests/tools/test_hook_push_behind_main.py` 와 `tests/tools/test_hook_push_delete_open_pr.py` 의 `test_도움말_판정이_실제_git_과_같다` 열 갈래가 실패했다(PR #403 의 CI 실행 40497038501, python 잡 로그로 봤다. 앞 이미지 20261012.334.1 의 git 2.55.0 에서는 같은 시험이 통과했다, PR #404 의 실행 40491814684. 그래서 2.55.0 이 129 를 낸 것은 통과에서 미루어 본 것이고, 이 PC 의 git 2.32 가 129 를 내는 것은 손으로 봤다). 셀프 리뷰 명세 축이 태그 원문을 받아 읽은 바로는, v2.55.0 의 `parse-options.c` 는 `PARSE_OPT_HELP` 와 `PARSE_OPT_ERROR` 를 함께 `exit(129)` 로 끝내고 v2.56.0 은 `PARSE_OPT_HELP` 를 `exit(0)` 으로 갈랐다(코드 읽기, `--help-all` 도 같은 길이라 그 갈래의 실패와 맞는다). main 의 필수 검사 verify 가 빨개져 새 이미지에 걸린 PR 은 병합하지 못한다. 두 시험의 129 단언을 사용법 표지(`usage: git push`)와 푸시 여부(지워졌는지)로 가르게 바꾸고, 129 를 사실로 적은 독스트링·주석(`tools/hook_push_behind_main.py` 의 `asks_help`, 두 시험 파일)을 고친다. 훅의 판정 코드는 종료 코드를 보지 않는다(PR #403 세션이 `asks_help` 를 읽었다). 이 길은 사람이 PR #403 세션의 물음에서 골랐다. git 2.56 의 종료 코드 0 은 CI 로그로만 봤고 이 PC(git 2.32)에서는 재현하지 못했다.

**대기열:** 없음

- [x] 이 PC 의 git 2.32 에서 두 시험이 초록이고, git 2.56 쪽은 이 PR 의 CI 로 본다
