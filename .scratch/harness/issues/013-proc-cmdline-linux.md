## Comments

- 범위 밖: `tools/hook_edit_during_commit.py`가 이름이 git 인 프로세스를 훑으며 읽는 리눅스 cmdline 도 막 뜬 git 이면 같은 틈이 있을 것으로 코드를 읽어 어림한다(그 길은 재지 않았다). 훅은 단독 실행이라 이 모듈의 `settled`를 쓰지 못하고, 그 훅은 이 PC(윈도)에서 돈다
- 셀프 리뷰에서 직접 찾아 고쳤다: 윈도의 생존 판정이 조회 권한만으로 열어, 읽기 권한으로 열리지 않는 프로세스(이 PC에서 7개)를 살아 있다고 보고 하나마다 5초를 기다렸다. 읽기와 같은 권한으로 열게 고쳤다(`.scratch/harness/probes/proc_cmdline_alive_gap.py`)
- 윈도의 빈 값 1/1200 은 늦은 진단 읽기로 끊긴 단계를 가르지 못했다. 처방(살아 있으면 다시 읽기)은 단계와 무관하게 덮고, 프로브의 둘째 실행에서 그 1회차를 도구가 메웠다
- PR 직전 `bug-perf-review`가 찾아 고쳤다: 32비트 파이썬의 윈도는 읽기가 늘 None 인데 생존 판정은 참이라, 부를 때마다 기한까지 기다렸다(코드를 읽은 것. 32비트 파이썬은 없어 돌려 보지 않았다). `_readable`이 읽지 못하는 플랫폼을 걸러 기다리지 않는다. 시험이 그 갈래를 가짜로 고정한다
