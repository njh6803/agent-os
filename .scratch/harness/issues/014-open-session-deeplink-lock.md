# 014: open-session 딥링크가 겹쳐 열기가 실패하는지 앱 로그로 가르고, 겹침이면 기계 전체의 잠금으로 막는다

**What to build:** 두 세션의 `tools/open_session.ps1 -Action send`가 몇 초 사이로 딥링크를 쏘면, 뒤의 딥링크가 앞 세션의 새 세션 화면 입력창을 제 글로 덮는다. 그러면 앞 세션은 지시문이 든 입력창을 찾지 못하거나(`입력창 을(를) 찾지 못했다`) 모델을 고르는 사이 지시문이 바뀌었다며(`지시문이 바뀌었다`) 보내지 않고 멈춘다고 세 회차의 일지가 보았지만, 앱 로그로 가르지는 않았다. 가를 진단 프로브 `.scratch/harness/probes/deeplink_timeline.ps1`은 앱이 두 번째 인스턴스의 로그 문구를 바꾸고 로그를 `main1.log`~`main4.log`로 돌리게 된 뒤로 아무 딥링크도 뽑지 못했다. 그래서 먼저 프로브가 지금 판의 로그를 읽게 고치고, 트랜스크립트에 남은 `send`의 출력과 앱 로그를 맞대 실패한 회차와 성공한 회차를 같은 기준(자기 딥링크 뒤 자기 세션이 서기 전에 남의 딥링크가 왔는가)으로 가른다. 겹침이면 `send`가 쏘기 전에 기계 전체의 이름 있는 잠금을 잡고, 보내고 기본값을 되돌린 뒤나 멈춘 뒤 놓는다. 되돌리기도 표지 딥링크를 쏘므로 잠금 안에 든다. 같은 표지 딥링크를 쏘는 `defaults`도 잠근다.

**대기열:** 360

**Status:** done

- [x] 겹침 판정 프로브가 대기열 360의 세 회차를 앱 로그로 가르고, 성공한 열기를 대조군으로 같은 기준에 넣는다. 자기 딥링크의 두 번째 인스턴스를 로그에서 찾지 못한 회차는 측정이 아니라고 센다
- [x] 겹침이면 `tools/open_session.ps1`의 `send`와 `defaults`가 쏘기 전에 기계 전체의 이름 있는 잠금을 잡고, 보낸 뒤 기본값을 되돌리고 나서나 멈춘 뒤 놓는다. 잠금을 기다리다 시간을 넘기면 쏘지 않고 멈춘다
- [x] 잠금의 시험이 셋을 고정한다. 다른 프로세스가 쥐고 있으면 제한 시간에 멈춘다, 놓으면 잡는다, 쥔 프로세스가 놓지 않고 끝나도 잡는다. 변이로 빨강을 본다
