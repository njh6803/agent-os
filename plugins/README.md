# 플러그인 폴더와 커스텀 에이전트 만들기

고객사의 요구에 맞춘 에이전트를 만들려는 개발자가 읽는 안내다. 기본으로 들어 있는 에이전트 `assistant`를 복사해서 이름을 바꾸고, 필요한 만큼만 고치는 길을 순서대로 적었다. 이 파일은 `plugins/` 바로 아래에 있고 플러그인이 아니다. 런타임은 `agents/`, `mcp/`, `skills/`, `models/` 아래에서 `plugin.toml`이 있는 폴더만 플러그인으로 읽으므로 이 파일은 읽히지 않는다.

## 1. 기본 에이전트는 무엇으로 이루어졌나

기본 에이전트 `assistant`는 등록된 문서를 검색해서, 찾은 근거로만 답하고 출처를 다는 도우미다. 에이전트 코드는 일의 이름도 도구의 이름도 모른다. 그 일은 아래 네 자리에 나뉘어 있다.

| 자리 | 위치 | 무엇을 들고 있나 |
| --- | --- | --- |
| 에이전트 | `agents/assistant/` | 코드(`agent.py`)와 매니페스트(`plugin.toml`). 스킬 본문과 앞 대화를 엮어 모델을 한 번 부른다. 어떤 스킬과 연결을 쓰는지, 두 끝이 얼마인지도 매니페스트에 있다 |
| 스킬 | `skills/cite-sources/` | 검색하고 답하는 방법을 적은 글(`SKILL.md`). 근거를 쓴 문장 끝에 번호를 달고, 답 끝에 출처를 적고, 근거가 없으면 정해진 문장으로만 답하라는 지시다 |
| 연결 | `mcp/doc-search/` | 문서 검색 서버의 주소와, 접속할 때 보낼 토큰을 어느 환경 변수에서 읽는지 |
| 규칙 파일의 표 | `rules.toml`의 `[agents.assistant]` | 이 에이전트가 도구를 부를 때의 규칙. 검색은 묻지 않고 부르고, 문서 전문 읽기는 사람이 승인해야 하고, 지식베이스 목록은 아예 막는다 |

규칙 파일의 표는 에이전트 이름으로 붙는다. 그래서 에이전트를 복사하면 표도 새 이름으로 하나 더 만들어야 한다.

## 2. 사본을 만드는 순서

`acme-assistant`라는 이름으로 사본을 만드는 예다. 이름은 소문자로 시작하고 소문자, 숫자, 하이픈만 쓰며 2자에서 63자까지다.

**첫째, 에이전트 폴더를 새 이름으로 복사한다.** 저장소 루트에서 친다.

```bash
cp -r plugins/agents/assistant plugins/agents/acme-assistant
```

PowerShell이면 이렇게 친다.

```powershell
Copy-Item -Recurse plugins/agents/assistant plugins/agents/acme-assistant
```

**둘째, 사본의 매니페스트에서 `name`을 폴더 이름과 같게 바꾼다.** `plugins/agents/acme-assistant/plugin.toml`을 열어 `name = "assistant"` 줄만 고치면 된다. 폴더 이름과 `name`이 다르면 로더가 오류를 낸다. 고친 파일은 이렇게 된다.

```toml
schema_version = "1"
kind = "agent"
name = "acme-assistant"
version = "0.1.0"
entrypoint = "agent:Assistant"
mcp = ["doc-search"]
skills = ["cite-sources"]
max_turns = 6
max_tool_calls = 4
```

**셋째, 규칙 파일에 새 이름의 표를 더한다.** `plugins/rules.toml`의 맨 끝에 아래 표를 붙여 넣는다. 기본 에이전트의 표와 같은 세 줄로 시작하는 것이다. 표가 없으면 사본이 도구를 부를 때마다 기본값에 따라 사람에게 묻게 되어, 검색이 올 때마다 승인 카드가 뜬다.

```toml
[agents.acme-assistant]
allow = ["doc-search:search"]
ask = ["doc-search:get_document"]
deny = ["doc-search:list_knowledge_bases"]
```

이 세 걸음이면 이름만 다른 사본이 선다. 사본을 원본과 똑같이 시험하는 시험이 저장소에 있고(`tests/test_assistant_plugin.py`), 그 시험도 이 순서와 이 표를 그대로 써서 사본을 만든다.

## 3. 무엇을 고치나

사본에서 고치는 것은 다섯 가지 안에서 고르면 된다. 코드(`agent.py`)는 거의 고칠 일이 없다.

- **`mcp`**: 에이전트가 쓸 연결의 이름 목록이다. 비워 두면 도구가 없는 에이전트가 된다. 다른 문서 검색 서버를 쓰려면 `mcp/` 아래에 연결 폴더를 더하고 이름을 여기 적는다. 규칙 표는 `doc-search:search`처럼 연결의 이름을 넣어 도구를 가리키므로, 연결 이름을 바꾸면 규칙 표의 세 줄도 새 이름으로 고쳐야 한다. 고치지 않으면 표가 연결에 없는 서버를 가리키게 되어, 그 실행은 도구 연결 오류로 끝난다.
- **`skills`**: 쓸 스킬의 이름 목록이다. 적은 순서대로 프롬프트에 실린다.
- **`model`**: 이 에이전트만 다른 모델을 쓰게 하려면 `models/` 아래 모델 플러그인의 이름을 적는다. 적지 않으면 기본 모델을 따른다.
- **두 끝**: `max_turns`와 `max_tool_calls`다. 셈은 다음 절에 있다.
- **스킬의 글**: 답하는 방식을 바꾸려면 스킬 본문을 고친다. 이때 기본 스킬을 직접 고치지 않는다. 기본 스킬을 고치면 그것을 쓰는 기본 에이전트도 함께 바뀐다. 스킬 폴더도 새 이름으로 복사해서(`skills/cite-sources`를 `skills/acme-cite-sources`로) 그 복사본을 고치고, 사본의 `skills`가 새 스킬 이름을 가리키게 한다. 스킬 폴더를 복사할 때도 `plugin.toml`의 `name`과 `SKILL.md` 머리말의 `name`을 폴더 이름과 같게 바꾼다.

## 4. 두 끝을 세는 법

두 끝은 모델이 헛돌 때 실행이 끝없이 이어지지 않게 하는 상한이다.

- `max_tool_calls`는 한 번의 실행에서 도구 호출을 시도할 수 있는 횟수다. 그 횟수를 넘은 호출은 도구에 닿지 않고 "도구 호출 횟수를 넘었다"는 실패 결과로 모델에게 돌아간다.
- `max_turns`는 모델과 주고받는 턴의 수다. 한 턴에 모델이 도구 하나를 부르는 때가 가장 느리게 도는 경우이므로 이 경우를 기준으로 센다.

**턴의 끝은 도구 호출의 끝에 2를 더한 값으로 잡는다.** 기본 에이전트가 그 예다. 도구를 4번까지 부르게 하면(`max_tool_calls = 4`) 넷째 호출이 넷째 턴이고, 다섯째 턴에 낸 호출은 끝을 넘어 거부되며, 여섯째 턴에 모델이 답한다. 그래서 `max_turns = max_tool_calls + 2`, 곧 6이다. 1만 더하면 거부된 호출 다음에 답할 턴이 남지 않아, 그때까지 찾은 근거로 답하지 못하고 "루프가 5턴 안에 멈추지 않았다"처럼 걸린 턴의 끝을 든 오류로 실행이 끝난다.

`max_turns`는 10을 넘길 수 없다. 10을 넘게 적으면 그 에이전트의 실행은 시작도 하지 못하고 구성 오류가 난다. 그러므로 `max_tool_calls`의 쓸모 있는 최댓값은 8이다. 두 값을 적지 않으면 턴은 10, 도구 호출은 제한 없음으로 읽힌다.

## 5. 최종 사용자에게 열기

사본을 만들어 두기만 하면 운영자만 부를 수 있다. 사이트의 방문자가 위젯에서 부르게 하려면 두 곳을 고친다.

**첫째, 사이트 파일에서 그 사이트가 열 에이전트 목록에 새 이름을 더한다.** 사이트 파일은 `serve --site-file`로 넘기는 TOML이고, 사이트마다 `[[sites]]` 표 하나에 `agents`가 있다. 사본만 열려면 이렇게 적는다. 발급자, 대상, 공개 키, 허용 출처는 그 사이트의 것을 그대로 둔다. 사이트 파일은 서버가 시작할 때 한 번 읽으므로 고친 뒤에는 `serve`를 다시 시작한다. 파일의 전체 모양은 [tests/fixtures/site_file/README.md](../tests/fixtures/site_file/README.md)의 예에서 볼 수 있다.

```toml
agents = ["acme-assistant"]
```

**둘째, 사이트 페이지의 위젯 요소에 그 이름을 `agent` 속성으로 적는다.**

```html
<agent-os-widget agent="acme-assistant"></agent-os-widget>
```

위젯을 페이지에 넣는 방법과 나머지 속성은 [web/apps/widget/EMBED.md](../web/apps/widget/EMBED.md)에 있다. 사이트가 열지 않은 에이전트의 이름을 속성에 적으면 방문자에게는 없는 에이전트로 보인다.

## 6. 사본은 원본을 따라가지 않는다

사본은 복사한 시점의 `assistant` 폴더를 그대로 가져온 독립된 에이전트다. 그 뒤로 기본 에이전트의 코드(`agent.py`)와 매니페스트, 규칙 표가 고쳐져도 사본은 그 고침을 받지 않는다. 사본이 원본을 따라가지 않는다는 점은 일부러 정한 것이다. 기본 에이전트를 고쳤더니 고객사의 에이전트가 말없이 바뀌는 일이 없게 하려는 것이다.

다만 스킬과 연결은 복사하지 않고 이름으로 가리키므로, 사본이 같은 이름을 가리키는 동안에는 원본과 사본이 그 폴더를 함께 쓴다. 기본 스킬 `cite-sources`나 연결 `doc-search`를 고치면 원본과 사본이 둘 다 바뀐다. 사본만 따로 두려면 3절처럼 그 폴더도 새 이름으로 복사해서 사본이 복사본을 가리키게 한다.

대신 기본 에이전트가 좋아졌을 때 사본에 받아들이는 일은 손으로 한다. 두 폴더의 차이를 보고 필요한 부분만 사본에 옮긴다.

## 7. 스킬의 지시는 보장이 아니다

스킬은 모델에게 주는 지시일 뿐이다. 모델이 그 지시를 거의 지키더라도, 모든 요청에서 반드시 지킨다는 보장은 아니다. 예를 들어 문서에 관한 질문인지 가르는 일을 모델이 잘못하면 검색 없이 답할 수 있다. 앞 대화의 글은 질문한 사람이 넣은 글과 같은 수준으로만 믿을 수 있어서, 앞 질문에 심어 둔 주장이 다듬은 답에 실릴 수도 있다.

"반드시 검색한 뒤 답한다", "정해진 문장을 글자 그대로 낸다"처럼 어겨서는 안 되는 일이 있는 조직은 지시에 기대지 말고 사본의 코드에 고정 단계를 넣는다. 코드가 먼저 검색 도구를 직접 부른 뒤에 그 결과를 프롬프트에 실어 모델을 부르거나(`ctx.tool("search", query=...)`), 근거가 없을 때 코드가 정해진 문장을 직접 내면 된다. 이렇게 코드에 고정 단계를 두는 방식은 도구 호출이 불안정한 모델을 쓸 때의 대비책이기도 하다. 에이전트 코드가 기대하는 모양은 기본 에이전트의 `agents/assistant/agent.py`가 보여 준다.

## 8. 제대로 도는지 확인하기

CLI의 `run`으로 질문 하나를 던져 본다. 모델 이름은 `--model`이나 환경 변수 `AGENT_OS_MODEL`로 주고, 모델 제공자의 키(`ANTHROPIC_API_KEY`)와 문서 검색 서버의 토큰(`DOC_SEARCH_AUTHORIZATION`, 다음 절)이 환경에 있어야 한다.

```bash
uv run agent-os run acme-assistant "육아휴직은 최대 몇 년까지 쓸 수 있어?" --model claude-opus-5 --verbose
```

`--verbose`를 주면 진행 이벤트가 표준 에러로 나온다. 실행의 기록은 `traces/<실행 식별자>.jsonl`에 한 줄에 JSON 하나로 남는다. 아래를 확인한다.

- `tool_called` 줄의 `tool`이 `search`이고 `ok`가 `true`이고 `rule`이 `allow`이면 검색이 묻지 않고 불린 것이다.
- 전문 읽기(`get_document`)를 하려 하면 `run_paused` 줄이 나오고 `rule`이 `ask`이며 실행이 멈춘다. `run`은 종료 코드 3으로 끝나고, 표준 출력에 `승인:` 줄과 `거부:` 줄이 안내된다. 두 줄 모두 `agent-os resume <실행 식별자> --pause-index <자리>`로 시작한다. `승인:` 줄은 끝에 `--approve`가 이미 붙어 있어 그대로 치면 승인이다. `거부:` 줄은 `--deny --reason`에서 끝나므로 그 뒤에 사유를 이어 적어서 친다. 위젯에서는 같은 자리에 승인 카드가 뜬다.
- 지식베이스 목록을 부르려 하면 `rule`이 `deny`인 실패 줄이 남는다.
- 끝을 넘은 호출은 `ok`가 `false`이고 `rule`이 비어 있다.
- 마지막 줄이 `run_finished`면 답으로 끝난 것이고, `run_failed`면 `cause`를 본다.

## 9. 문서 검색 서버에 붙이기

기본 연결 `mcp/doc-search/plugin.toml`은 아래처럼 서비스 이름 `rag-engine`의 8000번 포트에 붙는다.

```toml
[server]
transport = "http"
url = "http://rag-engine:8000/mcp"

[server.headers]
Authorization = "DOC_SEARCH_AUTHORIZATION"
```

- **주소**: 배포의 서비스 이름이나 포트가 다르면 `plugins/mcp/doc-search/plugin.toml`의 `url` 줄을 고친다.
- **토큰**: 매니페스트에는 토큰이 없다. `Authorization` 헤더의 값은 환경 변수 `DOC_SEARCH_AUTHORIZATION`에서 읽는다. 이 변수에는 토큰만이 아니라 헤더 값 전체인 `Bearer <토큰>`을 넣는다. `Bearer ` 접두를 빼면 서버가 토큰을 알아보지 못해 거절한다. 토큰의 역할은 읽기만 되는 `reader`면 충분하다. `run`이나 `serve`를 시작하는 셸에서 먼저 정해 둔다.

```bash
export DOC_SEARCH_AUTHORIZATION='Bearer <토큰>'
```

```powershell
$env:DOC_SEARCH_AUTHORIZATION = 'Bearer <토큰>'
```

  변수가 없으면 연결이 실패하고, 그 실행은 어느 헤더의 어느 변수가 없는지 밝히는 `tool_connection` 오류로 끝난다.
- **문서 검색 서버 쪽 요건**: 그 서버의 환경 변수 `RAG_ALLOWED_HOSTS`에 서비스 이름 `rag-engine`이 들어 있어야 한다. 서버는 적힌 값마다 포트 없는 꼴과 `값:*` 꼴을 모두 받으므로 `rag-engine:8000`으로 오는 요청이 맞는다. 이름이 빠져 있으면 서버가 `/mcp` 요청을 421로 거절한다. 서비스 이름을 바꿨다면 `url`과 `RAG_ALLOWED_HOSTS`를 함께 바꾼다.

### 이 문서에서 돌려 본 것과 돌려 보지 못한 것

돌려 본 것은 2절의 세 걸음이다. 시험이 같은 순서와 같은 표로 사본을 만들어, 가짜 문서 검색 서버와 대본 모델로 원본과 똑같이 지나는 것을 확인한다. 검색은 묻지 않고 불리고, 전문 읽기는 승인에서 멈추고, 지식베이스 목록은 막히고, 두 끝이 듣는다.

돌려 보지 못한 것은 둘이다. 실제 모델로 `run`을 끝까지 돌려 답을 받는 것은 이 문서에서 하지 않았고, 8절의 명령은 그 형식과 확인할 줄의 이름만 코드와 시험으로 맞춰 적었다. 실제 문서 검색 서버에 붙는 것(9절의 토큰과 `RAG_ALLOWED_HOSTS`가 실제 서버와 맞물리는지)도 이 문서에서 하지 않았다. 가짜 서버가 같은 헤더와 도구를 흉내 내어 시험했을 뿐이다. 이 저장소의 가짜 서버는 `RAG_ALLOWED_HOSTS`를 모르고 허용된 `Host`가 루프백뿐이라, 9절에서 `RAG_ALLOWED_HOSTS`의 값을 서버가 받아들이는 꼴과 421로 거절하는 동작은 문서 검색 서버 쪽의 명세를 읽고 적은 것이지 이 저장소에서 잰 것이 아니다. 실제 서버 이미지로 한 번 붙여 보는 일은 따로 남아 있다.
