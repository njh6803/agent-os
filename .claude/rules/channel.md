# HTTP 채널 규칙

채널에만 걸리는 것이다. 봉투와 어휘, 상태 코드 표, 에러 문서, 인증, 스트림의 프레임, 테스트 이음매처럼 관리와 함께 따르는 것은 `http.md`에 있다. 원천은 ADR 0014·0015와 `.scratch/http-channel/spec.md`다. 아래는 확정된 결정이고, 코드와 다르면 코드를 고치거나 ADR을 남긴다.

- **실행은 앱의 수명이 소유한다(`runs.py`의 `Runs`).** 라우트가 `run()`·`resume()`을 제 제너레이터에서 흘리지 않는다. 그러면 끊김에서 제너레이터가 취소되고 실행이 `run_failed`도 없이 도구를 반쯤 부른 채 사라진다(ADR 0014가 거부한 모양). 채널 라우터가 수명을 들고 오고 앱에 붙으면 그것이 앱의 수명에 합쳐진다. 수명이 닫히면 남은 실행은 기다리지 않고 취소되어 결말 없음이다.
- **실행은 받는 쪽을 기다리지 않는다.** 둘 사이는 크기 제한이 없는 흐름이고 실행은 기다리지 않고 넣는다. 상한과 초과 정책은 동시 실행 상한과 함께 본다(명세 Further Notes). 이유는 느린 수신자 하나만이 아니다. **실행을 모는 루프는 이벤트와 이벤트 사이에 await 하지 않는다.** core는 도구 연결의 anyio 취소 범위 안에서 yield하므로, 그 사이의 await에서 취소를 받으면 제너레이터가 취소 범위 안에 멈춘 채 남고 나중에 다른 태스크에서 닫혀 수명의 태스크 그룹이 깨진다. 크기가 제한된 흐름에 기다리며 넣는 구현은 느린 수신자 테스트와, 끊긴 뒤 수명을 닫는 테스트에서 이것으로 빨개진다.
- **실행의 태스크가 예외를 스스로 받는다.** 태스크 그룹은 자식 하나의 예외에 형제 전부를 취소하므로, 그대로 두면 실행 하나의 디스크 오류가 다른 실행들과 앱의 수명을 함께 끝낸다. 첫 이벤트 전의 예외는 요청이 상태 코드로 말하고, 그 뒤의 것(트레이스를 쓰지 못함)은 결말 없이 닫힌 스트림과 서버 기록 한 줄로 남는다.
- **응답은 첫 이벤트를 받은 뒤에 시작한다.** 실행을 일으키고 첫 이벤트를 기다리는 것은 의존성(`Depends`)이다. FastAPI는 의존성을 전부 푼 뒤에 SSE 제너레이터를 부르므로 그 전의 예외가 핸들러를 지나 봉투가 된다. 제너레이터 안에서 첫 yield 전에 던지지 않는다 — 이미 200이 나간 뒤이고 예외 그룹에 감싸져 고정 문구의 500이 된다. 응답 객체를 직접 만들어 돌려주지 않는다 — FastAPI가 제너레이터 라우트에만 붙이는 keepalive를 잃는다.
- **라우터 모듈에는 `from __future__ import annotations`를 두지 않는다.** 라우트가 라우터 안에서 만든 의존성을 주해의 `Depends(...)`로 가리키는데, FastAPI는 문자열 주해를 모듈 전역에서만 풀어 스키마를 만들다 실패한다.
- **주체와 모델은 조립이 넘긴 것이다.** 본문에서 받지 않는다. 본문 모델은 추가 필드를 무시하지 않고 422로 거절하고, 기본값 있는 필드를 두지 않는다 — 요청 본문은 검증 스키마로 실려 기본값이 곧 계약의 "선택"이 된다(ADR 0015, 명세 검토).
- **테스트는 앱의 수명을 테스트 본문의 `async with`로 연다.** `ASGITransport`는 lifespan을 보내지 않고, 수명은 anyio 태스크 그룹이라 픽스처의 setup과 teardown이 다른 태스크면 깨진다(`tests.md`의 MCP 어댑터와 같은 조건). 가짜 도구 포트는 연결을 anyio 취소 범위 안에서 연다. MCP 어댑터가 그렇고, 연결이 연 태스크가 아닌 곳에서 닫히면 그 자리에서 드러난다.
