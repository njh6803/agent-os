# 다음 세션 지시문

PR을 열거나 병합했으면 그 세션의 작업은 끝이다(`docs/constitution/operations.md` 브랜치와 병합). 여기서 멈추고, 다음 세션에 그대로 붙여 넣을 지시문을 낸다. 티켓은 신선한 컨텍스트 하나에 맞게 잘려 있고 티켓 파일 하나가 자족적이라, 앞 작업을 지나온 컨텍스트는 도움이 아니라 잡음이다.

같은 세션에서 이어갈 이유가 있으면 "어디서" 줄에 그 이유를 적는다. 지시문은 그래도 낸다. 사용자가 이어서 지시하면 그대로 따른다.

## 순서

1. **남은 단계를 마친다.** 진행 중인 스킬의 뒷단계(PR을 열었으면 `@coderabbitai review` 코멘트, 병합했으면 main 최신화)와 일지. 단계를 닫는 세션이면 일지의 "다음" 절이 이미 갱신되어 있다. 없으면 여기서 쓴다. 끝: 뒷단계가 남아 있지 않다.
2. **다음 작업을 정한다.** 아래 결정표에서 위에서부터 처음 맞는 줄. 판단은 이 세션이 한다. 다음 세션은 정해진 것을 읽고 시작할 뿐이다. 후보가 여럿이면(프론티어가 열려 있으면) 하나를 고르고 나머지는 "읽을 것"의 `plan.md`로 가리킨다. 끝: 시작 프롬프트 한 줄이 정해졌다.
3. **지시문을 낸다.** 아래 형식 여덟 줄 전부. 저장소·PR에서 읽을 수 있는 것은 위치로 가리키고, 이 세션에서만 알 수 있는 것(브랜치 상태, 보류한 지적, 확인 못 한 전제)을 본문에 적는다. 구현 내용과 결정 과정은 PR·ADR·일지 원문에 있으므로 지시문은 위치만 가리킨다. 끝: 여덟 줄에 빈 칸이 없다.
4. **멈춘다.** 지시문이 이 턴의 마지막 내용이다.

## 다음 작업 결정표

`.scratch/plan.md`의 프론티어와 `.scratch/<slug>/`의 상태로 정한다.

| 지금 | 다음 단계 | 시작 프롬프트 |
|---|---|---|
| PR을 열었고 아직 병합 전 | PR 반영·병합 | `/git-pr-feedback` 뒤 `/git-pr-merge` |
| 병합했고 같은 기능에 `ready-for-agent` 티켓이 남았다 | 구현 | `/implement .scratch/<slug>/issues/<NN>-<slug>.md` |
| 병합했고 그 기능의 마지막 티켓이었다 | 다음 프론티어 기능 | `plan.md`에서 고른 기능으로 아래 줄 중 하나 |
| 기능에 `.scratch/<slug>/`가 없다 | 설계 인터뷰 | `/grill-with-docs` |
| 설계는 끝났고 `spec.md`가 없다 | 명세 | `/to-spec` |
| `spec.md`는 있고 `issues/`가 없다 | 티켓 | 명세 검토(읽기 전용 서브에이전트, `KICKOFF.md` 9단계 3번)가 안 됐으면 그것부터. 그 뒤 `/to-tickets .scratch/<slug>/spec.md` |
| 작업을 마치지 못한 채 끊는다 | 이어서 | 같은 시작 프롬프트. "이어받을 상태"에 어디까지 했는지와 일지의 "다음" |

`/grill-with-docs`, `/to-spec`, `/to-tickets`, `/implement`는 사용자만 부른다. 시작 프롬프트는 사용자가 다음 세션 첫 줄에 칠 것이다.

## 지시문 형식

```
다음 작업: <.scratch/<slug>/issues/<NN>-<slug>.md 또는 기능 <slug>>. <한 줄 요약>
다음 단계: <설계 인터뷰 / 명세 / 티켓 / 구현 / PR 반영·병합>
어디서: 새 세션. <같은 세션에서 이어가면 "이 세션"과 그 이유 한 줄>
시작 프롬프트: <그대로 칠 한 줄>
읽을 것: <일지 파일의 "다음", spec.md, 티켓 파일, 관련 ADR 번호>
이어받을 상태: <브랜치, PR 번호와 병합 여부, main HEAD SHA, 워크트리>
확인할 선행 조건: <Blocked by 티켓의 Status, 리베이스 필요 여부, 이번에 실제로 막힐 수 있는 것>
이번 요청 범위: <티켓까지 / 구현·리뷰·커밋까지 / PR까지. PR 반영 세션이면 병합까지>
```
