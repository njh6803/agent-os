# 다음 세션 지시문

PR을 열거나 병합하면 다음 작업의 지시문을 낸다(`docs/constitution/operations.md` 브랜치와 병합). 그 사건이 세션을 끝내는 것이 아니다. PR을 열었으면 이 세션이 반영과 병합까지 마치고, 지시문은 병합 뒤에 실행된다. 세션을 끝내는 것은 지시문의 "어디서"가 새 세션일 때뿐이고, 그 판단은 결정표가 한다. 티켓은 신선한 컨텍스트 하나에 맞게 잘려 있고 티켓 파일 하나가 자족적이라, 다른 티켓으로 넘어갈 때는 앞 작업을 지나온 컨텍스트가 도움이 아니라 잡음이다.

결정표와 다르게 하려면 "어디서" 줄에 이유를 적는다. 사용자가 이어서 지시하면 그대로 따른다.

## 순서

1. **병합까지 마친다.** PR을 열었으면 `@coderabbitai review` 코멘트를 남기고 `/git-pr-feedback`으로 검사와 코멘트를 반영한 뒤 `/git-pr-merge`로 병합한다. 병합은 PR을 연 세션의 일이다. 병합했으면 main 최신화. 그리고 일지. 단계를 닫는 세션이면 일지의 "다음" 절이 이미 갱신되어 있다. 없으면 여기서 쓴다. 끝: PR이 병합됐고 뒷단계가 남아 있지 않다.
2. **다음 작업을 정한다.** 아래 결정표에서 위에서부터 처음 맞는 줄. 판단은 이 세션이 한다. 다음 세션은 정해진 것을 읽고 시작할 뿐이다. 후보가 여럿이면(프론티어가 열려 있으면) 하나를 고르고 나머지는 "읽을 것"의 `plan.md`로 가리킨다. 끝: 시작 프롬프트 한 줄이 정해졌다.
3. **지시문을 낸다.** 아래 형식 아홉 줄. 본문에는 이 세션에서만 알 수 있는 것(끊은 작업의 진행, 보류한 지적, 확인하지 못한 전제)만 적는다. 구현 내용과 결정 과정은 PR·ADR·일지 원문에 있으므로 위치만 가리킨다. **명령 한 줄로 알 수 있는 것은 적지 않는다** — main SHA, 작업 트리, 지금의 브랜치 목록, 워크트리, 검사 수치, 티켓 상태는 `git`과 파일이 원천이고, 지시문에 옮기면 캐시가 되어 병합 한 번에 썩는다. 티켓 03 세션에서 워크트리 줄이 틀린 채 여러 지시문을 건넜고, main SHA는 쓴 직후 병합으로 틀렸다(일지 `2026-09-23-02`). 지시문은 새 세션에 한 번 실리고, 사람이 슬래시 명령으로 넣으면 두 번 실린다(명령 인자와 스킬의 `ARGUMENTS`). 끝: 아홉 줄이 다 있고, 적을 것이 없는 칸은 `없음`이다.
4. **연다, 또는 이어간다.** "어디서"가 새 세션이면 Skill 도구로 `open-session`을 돌린다. 그 스킬이 지시문을 첫 메시지로 넣은 세션을 연다. 이름은 새 세션이 스스로 붙인다. 이 세션은 거기서 끝난다. "이 세션"이면 지시문을 낸 뒤 그 시작 프롬프트대로 바로 이어간다.

## 다음 작업 결정표

`.scratch/plan.md`의 프론티어와 `.scratch/<slug>/`의 상태로 정한다.

| 지금(병합 뒤) | 다음 단계 | 시작 프롬프트 | 어디서 |
|---|---|---|---|
| 같은 기능에 `ready-for-agent` 티켓이 남았다 | 구현 | `/implement .scratch/<slug>/issues/<NN>-<slug>.md` | 새 세션. 티켓 하나가 컨텍스트 하나다 |
| 그 기능의 마지막 티켓이었다 | 다음 프론티어 기능 | `plan.md`에서 고른 기능으로 아래 줄 중 하나 | 새 세션 |
| 기능에 `.scratch/<slug>/`가 없다 | 설계 인터뷰 | `/grill-with-docs` | 새 세션 |
| 설계는 끝났고 `spec.md`가 없다 | 명세 | `/to-spec` | 새 세션 |
| `spec.md`는 있고 `issues/`가 없다 | 티켓 | 명세 검토(읽기 전용 서브에이전트, `KICKOFF.md` 9단계 3번)가 안 됐으면 그것부터. 그 뒤 `/to-tickets .scratch/<slug>/spec.md` | 새 세션 |
| 하네스·문서만 고친 PR이었고 같은 주제가 남았다 | 이어서 | 남은 것을 한 줄로 | 이 세션. 컨텍스트가 자산이다 |
| 작업을 마치지 못한 채 끊는다 | 이어서 | 같은 시작 프롬프트. "이어받을 상태"에 어디까지 했는지와 일지의 "다음" | 새 세션 |

`/grill-with-docs`, `/to-spec`, `/to-tickets`, `/implement`는 사용자만 부르는 스킬이라 모델이 Skill 도구로 부르지 못한다. 시작 프롬프트는 사람이 칠 수 있는 그 슬래시 명령 그대로 적는다. 새 세션에 어떻게 들어가는지는 `open-session`이 원천이다.

## 지시문 형식

```
다음 작업: <.scratch/<slug>/issues/<NN>-<slug>.md 또는 기능 <slug>>. <한 줄 요약>
다음 단계: <설계 인터뷰 / 명세 / 티켓 / 구현 / PR 반영·병합>
어디서: <새 세션 / 이 세션. 결정표의 "어디서"와 다를 때만 이유 한 줄>
시작 프롬프트: <그대로 칠 한 줄>
브랜치: <다음 작업이 딸 브랜치 이름만. 짓는 규약은 operations.md 브랜치와 병합>
읽을 것: <CLAUDE.md 작업 규약·rules·티켓이 이미 부르는 것 밖의 것. 대개 일지의 "다음" 하나>
이어받을 상태: <저장소로 알 수 없는 것. 병합 뒤 깔끔하면 없음. 끊었으면 어디까지 했는지와 커밋하지 않은 의도>
확인할 선행 조건: <이 세션이 확인하지 못한 전제. 확인한 것은 적지 않는다. 없으면 없음>
이번 요청 범위: <티켓까지 / 구현·리뷰·커밋까지 / PR과 병합까지>
```

줄은 불릿이나 인용 없이 줄 머리에서 시작한다. 새 세션의 `UserPromptSubmit` 훅(`tools/hook_prompt_directive.py`)이 첫 메시지에서만, 줄 머리의 `브랜치:`·`어디서: 새 세션` 두 줄로 지시문을 알아보고 그 세션이 스스로 이름을 붙이게 한다. 라벨을 바꾸면 훅은 예외 없이 침묵하고 `tests/tools/test_hook_prompt_directive.py`가 빨강이 된다.
