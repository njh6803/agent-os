# 작업 보고 (매일 09:45)

먼저 `common.md`를 따른다. 이 보고는 "어제 무엇을 끝냈고, 무엇이 진행 중이고, 어디서 오래 기다렸나"에 답한다.

## 메모

`<보고 폴더>/<어제>.work.notes.json`.

```json
{
 "heads": {"work": {"conclusion": "어제 PR 넷을 병합했고 둘이 리뷰를 기다린다. 커밋 대기가 평소보다 길었다.", "decide": ["열린 PR 둘을 이어 갈 세션을 열까?"]}},
 "blocks": {
  "work.merged": {"conclusion": "어제 PR 넷을 병합했고 셋이 아침 보고 작업이다", "so_what": "아침 보고 분리가 끝나 간다", "todo": "없음"}
 },
 "prs": {"301": {"name": "Ctrl-C 판정 안정화", "content": "부하에서만 빨개지던 시험 둘의 원인을 가른 뒤 시험만 고쳤다", "group": "부하 시험"}},
 "branches": {"feature/02-…": "런타임 실패 원인 기록: 런타임이 쓰는 모든 실패에 원인을 싣는다"}
}
```

- **블록.** 이 보고로 가는 표와 볼 것은 이렇다. 행이 없는 표(어제 병합 0건 등)는 블록 없이 "그 밖의 수"에 `해당 없음`
  한 줄로 적히고 시트의 표 목록에서도 빠지므로, 시트에 없는 표의 블록은 쓰지 않는다.
  - `work.merged` 어제 병합된 PR: 주제끼리 묶은 `group`, 무엇을 끝냈나.
  - `work.open` 열린 PR: 초안·리뷰 결정·CI가 막힌 것, 이어 갈 세션이 필요한 것.
  - `work.worktrees` 최근 기록이 있는 진행 중인 세션: PR이 없는 것. PR이 병합됐는데 남은 워크트리는 표에 없고 "그 밖의 수"에
    수만 적힌다.
  - `work.days` 요즘 하루에 얼마나 돌렸나: 사람이 연 세션과 그 밖의 세션, PR당 비용·시간당 병합의 흐름.
  - `work.expensive` 비싼 작업: 비용·활동 시간·리뷰 왕복이 큰 PR의 공통점.
  - `work.kinds` 작업 종류마다: 종류별 중앙값의 차이.
  - `work.commands` 오래 걸린 명령: 상위 명령과 10분 30초를 넘은 수.
  - `work.agents` 서브에이전트 유형마다: 횟수와 실행 시간 합이 큰 유형.
- **이름.** 시트의 이름을 지을 PR 전부와 PR 없는 브랜치 전부에 쓴다. 어제 병합된 PR에는 `group`을 쓴다(없으면 제목 앞머리
  `chore` 등이 들어간다).
- 수집 JSON의 `journal`(가장 최근 일지의 "다음")은 진행 중인 작업을 읽는 근거로 쓴다. 머리나 블록에 옮겨 적지 않는다.

그리기는 `common.md`의 "그리기와 보고"를 `--report work`로 따른다.
