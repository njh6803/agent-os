# 기초 카드 원본

`foundations/` 아래 넷은 디자인 시스템 아티팩트의 기초 카드 원본이다. 짓기 명령(`assemble`)이 바이트 그대로 산출의
`foundations/` 에 두고, 같은 바이트가 올라간다. 그래서 `web/.prettierignore` 가 넷을 뺀다. 이 글은 그 폴더 밖에 두어
올라가지 않는다.

- 넷이고 폴더마다 HTML 하나다. `colors`(Colors. 쓰임새 토큰의 녹청 라이트·다크, 테마 넷, 녹청의 원색), `type`(Type.
  글자 단계, 굵기, 글꼴 둘), `spacing`(Spacing. 간격, 모서리, 틀), `density`(Density. 밀도 두 벌). 첫 줄이
  `<!-- @dsCard group="…" -->` 다. 짓기 시험이 폴더마다 HTML 하나와 그 표지, 원본과 같은 바이트를 본다.
- 값은 글자로 적지 않는다(ADR 0026 "디자인 토큰의 값은 코드에만"). 색과 길이는 `var(--이름)` 으로 칠하고, 칸에 보이는
  값은 카드 끝의 작은 스크립트가 그 요소의 계산값을 읽어 채운다(`data-value="--이름"`). 밀도를 따르는 글자와 높이는
  별칭(`--text-body`)이 아니라 원천인 밀도 변수(`--body-size`)로 읽는다. 별칭은 `@theme inline` 이라 CSS 변수로 나오지
  않는다. 짓기 시험이 카드가 읽는 변수와 `data-theme`·`data-density` 값을 묶음 CSS 의 선언·선택자와 맞댄다.
- 테마를 단 줄과 칸은 `data-mode` 도 함께 단다. 빼면 그 줄은 시스템 설정을 따라, 다크 설정의 브라우저에서 다크로
  그려진다(2026-10-13 내장 브라우저에서 색 카드의 테마 줄이 그랬다).
- 카드는 손으로 고치는 정적 HTML 이다. 처음 판은 세션 스크래치의 생성 스크립트로 한 번 써 냈고 그 스크립트는 커밋하지
  않았다. 그래서 넷이 머리의 `<style>`(바탕, 제목, 값 글자)과 끝의 값 채우기 스크립트를 똑같이 들고, 고치면 넷을 함께
  고친다.
- 열린 문제: 2026-10-14 단독 Claude Design 의 디자인 시스템 창이 넷을 그룹 `Colors`·`Density`·`Spacing`·`Type` 아래에
  모았고, 카드 이름은 파일 이름을 따라 모두 `index` 로 보였다. 파일 이름을 바꾸면 고쳐질 것으로 보지만 재지 않았고,
  아티팩트 페이지에서 어떻게 보이는지도 보지 않았다. 파일 이름을 바꾸면 이 폴더를 겨누는 변이 표
  (`.scratch/design-card-build/probes/assemble_mutations.toml`)의 경로도 함께 고친다.
