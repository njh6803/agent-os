# Agent OS 헌법

세 파일로 나뉜다. 로드 시점이 다르기 때문이다.

- [principles.md](principles.md): 원칙 다섯과 거버넌스. `CLAUDE.md`가 임포트해 항상 실린다.
- [tech.md](tech.md): 언어, 도구, 의존성. 의존성을 더하거나 스택을 바꿀 때 읽는다.
- [operations.md](operations.md): 검증, LLM 테스트, 가드레일, 브랜치, 리뷰 파이프라인, 이슈, 환경 규약. 커밋·병합·리뷰·트래커를 만질 때 읽는다.

디렉터리별 규칙은 헌법이 아니라 `.claude/rules/*.md`에 있고 해당 파일을 Read 도구로 열 때만 실린다. 현재 트리는 루트 `README.md`, 미래 배치와 첫 슬라이스의 범위는 `.scratch/plan.md`에 있다.

**Version**: 3.0.16 | **Ratified**: 2026-09-19 | **Last Amended**: 2026-10-07 (ADR 0001~0016, 0018, 0020, 0021, 0023~0026). 3.0.16은 운영 가드레일의 문구 하나다. pre-commit에서 파일을 고치지 않는 `always_run` 검사 일곱을 러너 `tools/run_checks.py`가 함께 띄우고, 설정 최상위의 `default_stages: [pre-commit]`이 commit-msg 단계의 재실행을 막는다는 것을 적었다(ADR 0005의 2026-10-07 이력). 게이트 수는 그대로다. 원칙의 내용은 바뀌지 않았다. 3.0.15는 운영 가드레일과 스택 표의 문구다(design-system 티켓 01). web verify의 Vitest가 디자인 시스템의 스토리 테스트를 실제 chromium에서 돌고, chromium은 기계마다 Playwright 판마다 까는 것과 CI `web` 잡이 그 전에 까는 것을 적었다. 스택 표의 웹 행은 Tailwind·lucide-react·Storybook·글꼴을 티켓 01이 들였다는 지난 사실로 고치고 시각 회귀는 티켓 02의 것으로 두었으며, 프론트 구성 행에 앱의 스토리가 앱마다의 Storybook에서 패키지의 미리보기를 나눠 쓴다는 것을 적었다(ADR 0026의 2026-10-07 이력). 게이트 수는 그대로다. 원칙의 내용은 바뀌지 않았다. 3.0.14는 스택 표의 문구 하나다. 웹 행에 시각 회귀의 도구(Storybook 정적 빌드를 Playwright의 `toHaveScreenshot`으로)와 글꼴(Noto Sans KR과 고정폭 둘, 패키지 셋, `@ibm/plex-mono`의 설치 스크립트는 끈다)을 적었다(ADR 0026의 넷째 2026-10-06 이력). 원칙의 내용은 바뀌지 않았다. 3.0.13은 스택 표의 문구 하나다. 웹 행이 테마를 라이트와 다크 둘로 적던 것을, 색과 글꼴의 한 벌인 테마 다섯과 테마마다의 라이트·다크 모드로 고쳤다(ADR 0026의 둘째 2026-10-06 이력). 원칙의 내용은 바뀌지 않았다. 3.0.12는 스택 표의 문구 하나다. 런타임 의존성 행의 core에 `anyio`를 더하고, core의 실행 타임아웃과 채널의 실행 수명이 그 취소 범위에 직접 기대 major 4로 묶는다는 것을 적었다(ADR 0014의 2026-10-06 이력. 락의 판은 그대로다). 원칙의 내용은 바뀌지 않았다. 3.0.11은 스택 표의 문구 둘이다(design-system 설계 인터뷰). 웹 행에 디자인 토큰의 단위와 테마, Storybook과 스토리 테스트, 컨테이너 안의 시각 회귀, 자가 호스팅 글꼴을 적었고, 프론트 구성 행의 "두 앱이 토큰과 컴포넌트를 나누는 자리는 design-system 기능이 정한다"를 `web/packages/ui`와 스토리의 자리로 바꿨다(ADR 0026). 원칙의 내용은 바뀌지 않았다. 3.0.10은 스택 표의 문구 하나다. 런타임 의존성 행의 `pyjwt[crypto]`를 end-user-channel 티켓 01이 직접 의존으로 선언했다는 지난 사실로 고쳤다(락의 패키지와 판은 그대로다). 원칙의 내용은 바뀌지 않았다. 3.0.9는 운영의 문구다(워크트리 감사, 일지 2026-10-05-05). LLM 테스트에 워크트리의 `--env-file`, 가드레일에 pre-commit install은 주 체크아웃에서 한 번이고 `uv sync`·`pnpm -C web install`은 워크트리마다라는 것과 워크트리의 병합 길, 브랜치와 병합에 나란히 여는 세션과 워크트리 병합(ADR 0005의 2026-10-06 이력), 환경 규약 상세에 모드별로 실리는 것의 표와 세션 파일의 폴더 키를 적었다. 원칙의 내용은 바뀌지 않았다. 3.0.8은 스택 표의 문구 넷이다(web-widget 설계 인터뷰). 런타임 의존성 행에 최종 사용자 토큰 검증의 `pyjwt[crypto]`(ADR 0023), 원격·CI 행에 nginx의 원격 노출과 그 판정(ADR 0024), 웹 행에 위젯의 스택과 관리 화면에 아직 스타일이 없다는 것과 디자인 시스템의 원천(ADR 0024, ADR 0021 이력, ADR 0025), 프론트 구성 행에 공유 자리를 design-system이 정한다는 것을 적었다. "위젯 기술은 슬라이스 4에서 결정"과 "위젯과 공유하는 atoms는 `web/packages/ui`"를 거뒀다. 원칙의 내용은 바뀌지 않았다. 3.0.7은 운영 가드레일의 문구 하나다. 두 자동 검사의 차이에 변이 표의 원문 확인(`tools/mutate.py --check`)이 커밋에 든 표만 보는 것이라 pre-commit에만 있다는 것을 더했다(대기열 92). 원칙의 내용은 바뀌지 않았다. 3.0.6은 운영의 문구 셋이다. 리뷰 파이프라인에 리뷰를 부르는 쪽의 PR head 지연과 그것을 막는 훅(대기열 86), 문서 위치에 잔존 grep이 보는 살아 있는 문서와 기록의 가름(대기열 87), 환경 규약 상세에 카나리아 명령의 `--strict-mcp-config`와 stdin 질문(대기열 85)을 적었다. 원칙의 내용은 바뀌지 않았다. 3.0.5는 운영 가드레일의 문구 하나다. 잡을 `verify`의 `needs`에 빠뜨리면 `verify`가 같은 실행의 잡 목록을 API로 읽어 빨강으로 본다(ADR 0021의 둘째 2026-10-01 이력, 대기열 89). 원칙의 내용은 바뀌지 않았다. 3.0.4는 운영 가드레일과 스택 표의 문구다. CI가 파이썬, web, e2e를 잡 셋으로 함께 돌고 필수 검사 `verify`는 그 결과를 모으는 잡이 되었다. 건너뛰거나 취소된 잡도 빨강으로 본다(ADR 0021의 첫째 2026-10-01 이력). 원칙의 내용은 바뀌지 않았다. 3.0.3은 운영 환경 규약 상세의 문구 하나 — 바꾼 rules와 스킬이 실리는지 새 `claude -p` 세션의 카나리아와 대조군으로 보는 법(대기열 63). 원칙의 내용은 바뀌지 않았다. 3.0.2는 운영 가드레일과 스택 표의 문구다(web-admin 티켓 05). CI의 `verify` 잡이 web 검증 뒤에 e2e(`pnpm -C web/apps/admin exec playwright test`)를 돌고 브라우저가 없으면 실패한다(ADR 0021 이력). 훅 러너가 CI에도 들어가 pre-commit에만 먼저 있던 예외가 걷혔다. 두 자동 검사의 차이로 인용 대조와 커밋 메시지 검사(pre-commit에만)와 e2e(CI에만)를 적었다. 스택 표의 원격·CI 행은 e2e가 선 뒤라 미래형 괄호를 거뒀다. 원칙의 내용은 바뀌지 않았다. 3.0.1은 운영 가드레일의 문구 셋 — `.env` deny가 모든 위치와 PowerShell 읽기 모양을 덮는 것(가짜 `.env` 탐침), 에이전트 층 밖의 셋째 층이 키 자체라는 것(사용 한도, 실린 키는 회전), 관리자 우회가 에이전트에게도 열려 있어 병합은 `/git-pr-merge`로만 한다는 것(ADR 0005의 2026-09-29 이력). 원칙의 내용은 바뀌지 않았다. 3.0.0은 원칙 III이 TypeScript로 넓어진 것이다. 금지 목록은 `any`, 타입 단언(`as const` 제외), 비null 단언, `@ts-ignore`·`@ts-nocheck`이고, `@ts-expect-error`는 타입 테스트 파일에서만 쓴다. 판정자는 typescript-eslint이고 tsconfig의 strict 계열도 검사가 본다(ADR 0020). 원칙의 문장이 바뀌어 major다. 같은 올림에서 스택 표의 웹·프론트 구성·원격·CI 행이 ADR 0021의 스택을 적는다. 운영의 머리와 가드레일은 다섯째 검증 명령 `pnpm -C web verify`와 클론 뒤 `pnpm -C web install`을 안다. 운영의 문서 위치는 한 앱의 지침을 중첩 `CLAUDE.md`가 아니라 `paths`를 든 규칙에 두게 했다. 새 중첩 지침 파일 검사와 ADR 0004·0021에 맞춘 것이다(web-admin 티켓 01). 2.5.4는 운영 가드레일의 문구 하나 — 마크다운 표 검사와 줄 구분 문자 검사가 pre-commit에서 스테이지된 파일에, CI에서 pytest의 저장소 상태 테스트로 도는 것(대기열 44·22). 원칙의 내용은 바뀌지 않았다. 2.5.3은 운영의 문구 셋 — 인용 대조 검사가 경고만이라 pre-commit에만 있는 것(대기열 42), `.env` 읽기를 훅이 막는 것(대기열 43), `PYTHONUTF8`이 설정 `env`에서 오는 것(대기열 40). 원칙의 내용은 바뀌지 않았다. 2.5.2는 원칙 IV의 판정자 문장을 사실에 맞춘 것 — 플러그인 경계는 `tests/test_plugins_boundary.py`가, 나머지는 import-linter가 판정한다(ADR 0018. 판정자만 바뀌어 patch). 2.5.1은 patch 여럿을 묶은 것. 스택 표의 테스트 행에 둘째 구동자 문장(#75)과 HTTP 행의 fastapi 하한 0.140.8(#76)은 버전을 올리지 않은 채 들어와 여기서 소급한다. `principles.md`의 형제 상대 경로 셋(`tech.md`·`operations.md`·`adapters.md`)을 전체 경로로 고쳤다 — 임포트된 파일은 루트에서 읽히고(대기열 32), 이제 `tools/check_instructions.py`가 판정한다. 운영에는 LLM 테스트를 돌리는 계기(대기열 1), `fix/` 접두사(대기열 23), 일지 이름 규약, 리뷰 축 이름의 원천, Claude Code Review 건너뛰기 조건의 정정(#43은 반례가 아니었다), skip 판정자와 권한 거부 문장을 더했다. 원칙의 내용은 바뀌지 않았다. 2.5.0은 원칙 IV의 의존 방향에 공용 HTTP 층 `http`를 더하고, core의 금지 열거에 그것을 넣고, 어댑터가 그것을 import하지 않는다고 적은 것(ADR 0016, 열거가 는 것이라 minor). 같은 올림에서 스택 표의 HTTP 행이 fastapi의 하한을 적었다(ADR 0014). 2.4.0은 2.3.3 뒤에 버전을 올리지 않은 채 헌법 파일을 바꾼 PR 열하나(#19·#24·#27·#28·#30·#38·#39·#43·#45·#46·#50)를 한 번에 묶은 것. 가장 큰 것이 운영의 새 규칙 문장과 스택 표의 HTTP 행이라 minor이고, 원칙의 내용은 바뀌지 않았다(원칙 III는 판정자만, ADR 0013). 같은 올림에서 `principles.md`가 이 파일을 전체 경로로 가리키게 했다. 루트 README로 읽혀 PR #43이 버전을 찾지 못했다(ADR 없음, 문구 수정, 경위는 일지 2026-09-25-01). 2.3.3은 CodeRabbit 상한을 공식 문서 기준으로 바로잡은 것. CLI는 청구 주기당 3회가 아니라 개발자당 시간당 3회이고, OSS PR 리뷰는 별 수에 따라 시간당 1~10회다(ADR 없음, 사실 정정). 2.1.0은 원격·CI·PR을 첫날부터로 바꾼 것, 2.2.0은 리뷰 파이프라인 절 추가, 2.2.1은 CodeRabbit PR 리뷰를 빼고 CLI만 남긴 것, 2.3.0은 거버넌스에 "ADR은 결정 단위" 문장을 더하고(절 추가라 minor) 2.1.0~2.2.1을 ADR 0005·0006으로 소급한 것, 2.3.1은 공개 전환 뒤 CodeRabbit PR 리뷰를 다시 켠 것, 2.3.2는 스택 표의 테스트 행에 pytest-asyncio를 더한 것(ADR 0007)

2.0.0은 파일 분할이다. 원칙 I~V의 문구는 1.6.0과 같다. 1.x 이력은 git과 `docs/journal/`에 있다.
