## 한 일

티켓 03을 구현했다. 실행 기한이나 `serve` 종료로 취소된 실행에서도 원격 MCP 서버에 세션 종료 요청(DELETE)이 2초 유예 안에서 닿고, 닫기가 끝까지 간다(`src/agent_os/adapters/mcp.py`).

- 라이브러리의 종료 요청을 끈다(`terminate_on_close=False`). 라이브러리 문맥(세션, 전송)은 보호 없이 `try` 안에서 닫고, 같은 `finally`의 `CancelScope(shield=True)` 안에서 `_end_session`(DELETE를 `move_on_after(CLOSE_GRACE_SECONDS)` 안에서)과 `client.aclose()`를 차례로 한다. 유예는 종료 요청에만 걸려 클라이언트 닫기는 건너뛰어지지 않는다.
- 세션 번호는 응답 훅이 `mcp-session-id` 응답 헤더에서 받아 둔다(`_Attempt.session_id`). 프로토콜 판은 `initialize()` 결과(`_Attempt.protocol_version`)에서 받는다. 라이브러리의 비공개 속성은 읽지 않는다.
- 종료 요청의 리디렉션은 `follow_redirects=False`로 받아(`_delete`), httpx2의 공개 API(`Response.next_request`, `URL`)로 같은 출처(http에서 https로 올리는 것 포함)·메서드 그대로·사용자 정보 없음일 때만 `client.max_redirects` 번까지 따른다(`_stays_in_server`). `HTTPError`와 유예 초과는 삼키고 어댑터는 로그를 쓰지 않는다.
- 픽스처(`tests/mcp_http_server.py`)에 선택 인자 넷을 더했다. `--delete-sleep`, `--delete-drop`, `--delete-redirect`, 그리고 체크박스 밖의 `--stateless`다(아래 "정한 것").
- 시험: 어댑터 시험 여덟에 `--stateless` 하나(`tests/adapters/test_mcp.py`), core 시험 하나(`tests/core/test_run.py`, 도구 호출 도중의 기한은 원인 `timeout`이고 종료 요청이 닿는다), 채널 시험 하나(`tests/channel/http/test_end_user.py`, 앱의 수명을 닫아 취소한 실행도 닿는다).

## 정한 것(티켓 "정한 것"에도 있다)

- `--stateless` 시험을 체크박스 밖으로 더했다. 여는 도중 실패하는 시험만으로는 `if attempt.session_id is None: return` 가드를 뺀 변이가 초록이었다(가드가 없어도 `None` 헤더 값이 낸 오류가 `ConnectionError`에 덮인다). 세션 번호를 주지 않는 서버에서 정상으로 닫는 시험은 그 가드를 뺀 변이가 빨갛다.
- `--delete-drop`은 상태줄과 헤더(`content-length: 10`)만 보낸 뒤 본문 없이 연결을 끊는다. 클라이언트에는 응답이 끝나기 전에 끊긴 `RemoteProtocolError`로 보이고 `httpx2.HTTPError` 갈래다.
- 리디렉션을 따르는 횟수(`client.max_redirects`)를 직접 가르는 시험은 없다. 체크박스가 요구하지 않았고 따르는 길은 307 시험 둘이 지난다.
- `.scratch/mcp-http/probes/canary/adapters_rule_http_close.toml`을 새로 썼다(아래 검증).
- 사용자에게 물은 것은 없다.
