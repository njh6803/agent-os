## 맥락을 대신한 것

to-spec은 지금 대화를 합성하는 스킬인데, 이 세션에는 설계 인터뷰의 대화가 없다. ADR 0022와 그것이 이력을 남긴 ADR
0008·0009·0014, ADR 0023, `plan.md`의 conversation 행, 일지 2026-10-03-03을 읽었다. 코드는 sdk(`AgentContext`, 이벤트,
매니페스트), core(`run.py`, `loop.py`, `replay.py`, `ports.py`), JSONL 어댑터, CLI와 HTTP 채널, 공용 에러 표, 관리 화면의
`EventItem`·`RunDecision`·`RunDetail`, api-client의 스트림 술어를 읽었다.

코드를 읽다 찾은 것이 둘이고 둘 다 명세의 계약 티켓 절에 들었다.

- **관리 화면의 결정 자리가 형식 3에서 조용히 사라진다.** `RunDecision`은 `trace.schema_version === "2"`일 때만 결정 자리를
  세운다. 생성 타입에 `"3"`이 늘어도 비교는 컴파일되므로 타입이 잡지 못하고, 실제 `serve`로 멈춘 실행을 만드는 결정 e2e가
  CI에서야 빨개진다.
- **필드와 헤더 3은 같은 변경이다.** 직렬화는 필드를 언제나 전부 싣기 때문에, `RunStarted`에 필드가 느는 순간 모든 시작
  이벤트의 줄이 그 키를 싣는다. 헤더 2 아래에 쓰면 옛 코드가 손상으로 읽는다.

## 잰 것

ADR 0022가 "그 비용은 명세가 잰다"고 넘긴 것과, 기본 한도의 선택지를 토큰으로 설명하는 데 필요한 것을 쟀다. 판과 다시 돌리는
법은 `.scratch/conversation/probes/README.md`다.

- **거슬러 읽기(`chain_walk.py`).** 실제 `JsonlTrace`로 끝난 실행의 트레이스를 쓰고 `read`로 거슬러 읽었다. 트레이스 하나에
  0.3~1.3ms(프롬프트 한글 2,000~60,000자)였고, 1000개는 286ms와 615ms(2,000자와 20,000자)였다. 처음 판의 대조군은 프롬프트가
  든 셋째 줄까지 파싱해 원인을 가르지 못했다(셀프 리뷰, 아래). 둘로 나눠 다시 재니 머리만 읽어도 트레이스 하나에 약 0.12ms가
  들었고, 가벼운 읽기는 2~4배를 줄일 뿐이었다. 그래서 포트에 가벼운 읽기를 더하지 않았다.
- **글자당 토큰(`token_ratio.py`).** 토큰 세기 API(모델을 부르지 않는다)로 claude-opus-5에서 한국어 1.045, 영어 0.356이었다.

`token_ratio.py`는 `uv run --env-file .env`로 돌렸다. 그 전에 `.env`의 존재를 `ls`로 보려던 명령은 거부됐다(훅). 키 값은
보지 않았다.

## 명세가 스스로 정한 것

열셋이고 명세의 각 절에 표시했다. PR에서 사용자가 본다.

- 판정 순서(앞 실행 → 고리 → 준비, 앞 실행 안에서는 손상 → 주체 → 끝나지 않음). 최종 사용자 경로가 남의 실행을 404로 숨기려면
  주체가 다른 상태보다 먼저여야 한다.
- 이어 갈 수 없음의 하위 타입. `NotResumable`은 이름과 독스트링이 재개를 말한다.
- 형식 1·2·3 모두 이어 간다. 이어 가기는 읽기이지 재개가 아니다.
- 기본 한도는 core가 소유한다. 매니페스트에 숫자 기본값을 두면 계약에 박힌다.
- 한도 값은 1 이상의 엄격한 정수이고 글자 수는 코드 포인트다.
- 요약 이벤트는 `run_started` 바로 뒤에 하나이고 덮는 범위의 끝만 든다.
- 요약 이벤트는 런타임만 낸다. 에이전트가 내면 실행이 실패한다.
- 고정 프롬프트의 문구(시스템 메시지와 JSON 데이터의 가름, 지시를 따르지 않음, 언어)와 목표 길이(한도의 4분의 1).
- 요약 실패는 다시 시도 없이 `run_failed`. 실패한 실행은 고리에 들지 않으므로 같은 앞 실행으로 다시 이어 가는 것이 곧 다시
  시도다.
- 재개는 요약할지를 다시 판정하지 않는다. 멈춘 사이 한도가 바뀌어도 같은 값을 준다.
- 갈래를 막지 않는다. 막으려면 역방향 찾기가 든다.
- CLI는 끝난 실행에 안내를 찍지 않는다. "성공하면 표준 에러는 비어 있다"를 테스트가 고정한다.
- 관리 화면은 새 이벤트를 일반 그리기로, 실행 식별자 필드 둘은 링크로.

넘긴 것은 받는 쪽 행에 적었다. web-widget(최종 사용자 경로의 이어 가기 모양, 요약 실패를 가를지)과 end-user-channel(다른
주체의 하위 타입을 나눠 쓰기, 요약 이벤트의 투영, 손상된 남의 트레이스의 500). end-user-channel은 이 기능에 막혀 있지 않아
먼저 병합될 수 있으므로 조건으로 적었다.
