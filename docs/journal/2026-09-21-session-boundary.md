# 세션 경계 일지 · 2026-09-21

다른 프로젝트의 "작업 하나로 세션 끝내기"와 "다음 세션 시작 지시문" 두 절을 이 저장소에 옮긴 기록. 스킬 하나, 훅 하나, 문서 셋을 고쳤다. 기록 규칙은 [킥오프 일지](2026-09-19-kickoff.md) 머리말과 같다.

> 사용자: "깃 PR을 생성하거나 병합을 하면 이번 세션에서 작업이 끝났다고 보고 다음은 뭐 진행해야할지. 새 세션에서 진행해야할지를 지시문으로 알려줬으면 좋겠어. 예를 들어 /to-spec, /to-ticket 등 뭘 해야하는 지 등을 지시문으로 알려줬으면 좋겠어. 그리고 이 규칙을 강제할 hook을 만드는 건 어떻게 생각해? 아래는 다른 프로젝트 내용이야. 참고해서 우리 프로젝트에 맞게 만들었으면 해."

붙여 준 원문은 다른 프로젝트 `AGENTS.md`의 두 절이다. 결과 보고를 마치면 멈추고 다음 작업은 새 세션에서 한다는 것, 멈출 때 여섯 줄 지시문(다음 작업, 다음 단계, 상세 Plan, 이어받을 상태, 선행 조건, 요청 범위)을 낸다는 것, 미완이면 `handoff` 스킬로 인계 문서를 만든다는 것.

## 결과

- 새 스킬 `next-session`(model-invoked). PR을 열거나 병합하면 그 세션의 작업은 끝이고, 다음 세션에 붙여 넣을 여덟 줄 지시문을 내고 멈춘다. 다음 단계를 고르는 결정표가 스킬 안에 있다.
- 새 훅 `tools/hook_pr_next_session.py`(PostToolUse). `gh pr create|merge`와 GitHub MCP의 PR 도구 뒤에 계기 문장을 넣는다. 막지 않는다. 테스트 여섯.
- 고친 문서 셋. `implement` 스킬의 끝 문단(세션 경계의 원천을 새 스킬로), `operations.md` 브랜치와 병합 절(정책 한 줄), `KICKOFF.md` 7·9·10단계와 체크리스트.
- 검사 넷과 지침 검사 초록(`105 passed`, pyright `0 errors` 49파일, `Contracts: 3 kept`).

**"시작 프롬프트" 줄을 더한 이유.** 지난 세션이 `/to-spec`과 `/to-tickets`를 부르려다 거부당했다(`disable-model-invocation`, 인터럽트 설계 일지). 다음 세션의 첫 줄은 모델이 아니라 사용자가 친다. 그러니 지시문에서 가장 값진 줄은 "무엇을 하라"가 아니라 "무엇을 치라"다. 사용자가 예로 든 것도 정확히 그 줄이었다.

## 훅을 두되 막지 않는다

> 사용자: "이 규칙을 강제할 hook을 만드는 건 어떻게 생각해?"

둔다. 다만 게이트가 아니라 계기 주입이다. 이유 셋.

1. **같은 병을 이미 한 번 겪었다.** retro 계기는 스킬 설명에 지침으로 있었는데 에이전트가 일지를 쓰고도 돌리지 않았고, 그래서 `hook_journal_retro.py`가 생겼다(첫 슬라이스 일지 회고). 단계를 닫는 순간은 긴 작업의 끝이라 주의가 풀리는 자리이고, PR 뒤 지시문도 정확히 그 자리다. 런북 10단계의 사다리("훅은 어겨지는 것이 확인된 뒤에")는 막는 훅의 사다리다. 계기만 넣는 훅은 거짓 양성의 비용이 문장 하나라 사다리를 탈 이유가 없다. 런북에 그렇게 갈라 적었다.
2. **규칙의 절반은 훅이 강제할 대상이 아니다.** "다음 작업은 새 세션에서"는 사용자의 행동이다. 훅이 할 수 있는 것은 모델이 지시문을 내고 멈추게 하는 것까지다.
3. **Stop 훅 하드 게이트는 거짓 양성 기계다.** "지시문 없이 턴을 끝내지 못하게" 하려면 Stop 훅이 트랜스크립트를 파싱해 이번 턴에 PR 명령이 있었는지와 마지막 메시지에 지시문이 있는지를 판정해야 한다. 형식이 내부 것이고 턴 경계가 흐리다. `CLAUDE.md`는 거짓 양성이 많은 규칙을 하드 게이트로 만들지 않는다. 계기 훅이 넣었는데도 지시문 없이 턴이 끝나는 사건이 확인되면 그때 Stop 훅이다.

**훅이 이 세션에서 스스로 실측됐다.** 훅 실행을 시험하려고 페이로드 JSON을 쓰는 파이썬 한 줄을 Bash로 돌렸는데, 그 명령 문자열 안에 `gh pr create`가 데이터로 들어 있었다. `settings.json`을 고친 직후라 재시작 없이 훅이 걸렸고 계기 문장이 컨텍스트에 들어왔다. 테스트 줄을 고치는 heredoc에서 한 번 더 걸렸다. 둘 다 훅 자신을 만드는 명령이 그 문구를 데이터로 품은 경우이고, 평소 작업에서 Bash 명령 문자열이 그 문구를 품을 일은 드물다. 둘을 한 번에 확인했다. 새 훅 항목이 즉시 유효하다는 것, 그리고 거짓 양성의 비용이 정확히 문장 하나라는 것(PR이 없었으므로 무시했다). 페이로드 다섯으로 돌린 결과는 `gh pr create`(Bash)와 `gh pr merge`(PowerShell), MCP `merge_pull_request`에서 계기가 나오고 `gh pr view`와 Write에서는 아무것도 안 나온다.

## 배치

지침의 자리는 로드 시점으로 정했다(ADR 0004).

- 정책 한 줄은 `operations.md` 브랜치와 병합 절. 절차와 형식은 스킬. 지난 세션이 정한 "정책은 헌법, 절차는 스킬"과 같다.
- `CLAUDE.md`에는 넣지 않았다. 스킬 설명과 훅이 계기를 나르므로 "이 줄을 지우면 실수하게 되나"에 아니오다.
- `implement` 스킬의 끝 문단은 이유를 반복하지 않고 새 스킬을 가리킨다. 같은 사실을 두 곳에 두지 않는다.
- 런북 7단계 파일 목록에 스킬과 훅을 더했고, "파일 여섯"이라는 개수 표현을 없앴다. 지난 세션이 일곱째를 더했을 때 이미 낡아 있었다.

## 함정

- **워크트리에는 `.venv`가 없다.** `uv run --no-sync pytest`가 "program not found"로 죽는다. `uv sync` 한 번이면 된다. 훅은 `--no-sync`인데도 돌았다. 표준 라이브러리만 쓰기 때문이다. 훅 스크립트에 프로젝트 의존성을 넣는 날 워크트리에서 조용히 안 걸린다.
- `Path.read_text(newline=...)`는 3.13부터다. 3.12에서는 `open(newline="")`.

둘 다 한 번의 사건이라 기록만 한다.

## 셀프 리뷰 (`/code-review main`)

두 축이 Critical·Major 없이 Minor 다섯(겹침 하나), Nit 여섯을 냈다. 양쪽이 독립적으로 같은 것을 짚었다. 런북 10단계는 계기 훅을 사다리에서 뺐는데 항상 실리는 `CLAUDE.md` 교정 루프는 옛 문장 그대로였다. 작업 규약 4(결정이 바뀌면 참조처를 같이 고친다)를 이 세션이 어겼다.

고친 것 일곱. (1) `CLAUDE.md` 교정 루프 한 문장. (2) 훅의 계기 문장이 정책과 스킬 1단계를 되풀이하던 것을 retro 훅처럼 계기만으로 줄였다. 원천은 스킬 하나다. (3) 지시문에 "어디서" 줄. 사용자가 물은 "새 세션에서 해야 하는지"가 형식에 없이 이유의 부재로만 암시됐다. (4) 결정표의 티켓 줄에 명세 검토(런북 9단계 3번) 선행. (5) "이번 요청 범위"의 "병합까지"를 PR 반영 세션으로 한정. PR을 여는 세션에서는 정책과 모순이었다. (6) 테스트 이름 둘을 반환값이 아니라 행동으로. (7) 훅 docstring을 형제 길이로, 런북 7단계의 항목 열거를 "형식은 스킬"로.

남긴 것 셋. 훅 셋의 `main()`과 TypedDict 중복은 세 번째라 공용 모듈 후보이지만 기존 훅 둘을 건드리므로 이 변경 밖이고 회고 후보로 올렸다. 래퍼 스크립트 사각(`bash x.sh` 안에 PR 명령이 들어가면 명령 문자열에 문구가 없어 계기가 안 들어가고 스킬 설명이 유일한 포인터다)은 실측된 경로가 아니라 기록만 한다. 훅을 승인 없이 넣었다는 지적은 맞고, 위 "갈린 곳"에 그렇게 적었다.

다시 돌린 명령: `ruff check`·`ruff format --check`·`pyright`·`lint-imports`·`pytest`·`check_instructions.py`. 전부 초록. 전체 리뷰는 다시 돌리지 않았다.
