## 이어받은 것

PR #136은 3회차(`8b28517`)에서 CI 여섯이 초록이었고 `009b1d1`로 병합됐다. 3회차 claude-review는 지적이 없었고, CodeRabbit은 2·3회차가 시간당
한도로 리뷰가 아니었으며 1회차 스레드 넷은 봇이 닫았다. 병합 뒤라 그 일지(2026-10-05-04)에 적지 못해 여기 한 줄 남긴다. 그 세션의 회고 승인
하나(대기열 106)는 하네스라 반영하지 않았고 그대로다.

선행 조건: 주 체크아웃이 main이고 깨끗했으며 `git fetch` 뒤 `origin/main`과 같았다(`009b1d1`). 원격 브랜치가 main 하나라 값 기반 마스킹의 ADR
이력 초안 세션은 열리지 않았다. `.env`는 있었다(파일이 있는지만 봤다 — `grep`으로 키 이름을 보려다 훅이 막았다). 세션 제목은 훅의 지시대로 브랜치
이름으로 바꿨다.

## 이 티켓이 정한 열하나

티켓 끝의 "이 티켓이 정할 것"이 PR에서 사용자가 이름을 보라고 넘긴 것이다. 이름과 모양은 티켓의 "이 티켓이 정한 것 (2026-10-06)"에
적었고 여기에는 근거를 적는다.

1. **접두사와 경로와 `operation_id`.** 접두사 `/end-user`는 용어집 "최종 사용자"를 면의 이름으로 쓴 것이다. 경로 셋은 운영자 채널의
   `/runs`·`/{run_id}/approval` 꼴을 따랐고 구독의 접미사 `subscription`은 용어집 "구독"에서 왔다. 구독에 접미사가 있어야 하는 이유는
   운영자 채널과 같다 — `verbatim`이 슬래시까지 잡아 접미사 없는 경로가 결정 경로를 통째로 잡는다. `operation_id`에 `end_user`를 넣은 것은
   생성 클라이언트에서 운영자 채널의 함수와 이름이 갈리게 하려는 것이다.
2. **항목 유니온과 멤버 일곱.** `…Item`으로 지어 본문 `Decision`·`Approve`·`Deny`와 sdk 이벤트(`RunStarted` 따위)와 컴포넌트 이름이 겹치지
   않는다. 판별자 값(`started` 따위)도 이벤트의 것(`run_started` 따위)과 다르다. `UnfinishedItem`에 필드가 없는 것은 근거 이벤트가
   없어서다(용어집의 최종 사용자 항목 정의를 이것에 맞췄다, domain-modeling).
3. **어휘 여섯째 `too_many_requests`.** 기존 다섯(`not_found`, `conflict` 따위)처럼 상태 코드의 뜻을 말하는 낱말이다. 대상의 상태를 말하는
   409와 뜻이 달라 따로 둔다는 것은 ADR 0023이 이미 정했다.
4. **사이트 파일의 키.** 허용 출처와 열 에이전트는 비어 있을 수 있되 빼면 거절한다. 빈 목록에는 뜻이 있어서다(허용 출처가 비면
   브라우저가 아닌 클라이언트만 부른다, 명세). 빠뜨린 키에 기본값을 두면 그 뜻을 적지 않고 고른 셈이 된다. 공개 키는 하나 이상이고
   `kid`만 선택이다. 값은 엄격한 타입이다(TOML 배열은 리스트 필드로 받는다, 아래 "구현에서 정한 것").
5. **접두사 표의 값과 사이트 목록 타입.** `Credential = SharedToken | SiteSigned`. 공유 토큰 둘은 같은 모양이라 한 타입이고, 서명 토큰 줄만
   사이트 목록과 시계를 든다. 기본값(관리 토큰)도 `SharedToken`이라 표 밖의 경로가 틀린 토큰으로 막히는 것은 그대로다.
6. **집합 인자와 자기 실행 읽기.** `visible_agents`는 "호출자가 볼 수 있는 에이전트"이고 `None`이 전부다. 운영자 채널과 CLI는 넘기지 않아
   지금의 호출이 그대로 돈다. `read_own_run`은 재개와 구독이 같은 판정을 같은 순서로 내리게 하는 자리이고, 판정에 쓴 읽기를 `OwnTrace`로
   돌려줘 구독이 트레이스를 다시 읽지 않는다.
7. **면의 열거와 꺼짐의 문구.** 면이 셋인 이유는 하위 타입이 아닌 `PluginError`가 시작 경로에서는 500, 실행을 가리키는 경로에서는 404로
   갈리기 때문이다. 면을 정하는 접두사를 조립이 넘기는 것(`EndUserPaths`)은 원칙 IV 때문이다 — `http`는 `channel`을 import하지 않으므로
   채널이 소유한 접두사 상수를 예외 표가 직접 읽을 수 없다. 꺼짐의 문구가 종류와 이름을 들지 않는 것은 ADR 0017의 2026-10-03 이력이
   정했고, 이 티켓은 그 문구만 지었다.
8. **`serve --site-file PATH`.** 용어집 "사이트 파일" 그대로다. 인자가 없으면 사이트 목록이 비고 최종 사용자 경로는 서되 모든 토큰이
   401이다(명세).
9. **라우터의 나눔.** 채널 라우터 하나가 `Runs` 하나와 수명을 들고 두 하위 라우터를 품는다. 등록부가 둘이면 어느 면에서 일으킨 실행에
   다른 면이 붙지 못하고, 수명도 둘로 갈린다. 본문 모델은 두 면이 같이 쓰므로 `bodies.py`로 옮겼고 계약의 이름은 그대로다.
10. **경로 하나의 설명과 429 헤더.** 시작 경로의 422만 글자 수 상한을 말하므로 공유 설명을 바꾸지 않고 그 라우트 선언에 덮어쓸 설명을
    둔다. `Retry-After`는 상태 코드에 딸린 표에 두어 429를 적는 라우트마다 저절로 붙는다. 스키마에서 `minimum`을 뺀 이유는 아래 "구현에서
    정한 것".
11. **서명 토큰 줄의 시계.** `SiteSigned(sites=, clock=)`. 채널과 같은 `Clock`이라 테스트의 가짜 시계 하나로 만료와 실행 시각을 함께
    재고, 검증은 시간 클레임에 닿을 때만 `now()`를 부른다.

## 구현에서 정한 것

- **서명 보조 모듈 `tests/signing.py`.** 서버·최종 사용자 채널·`serve`의 테스트 셋이 키 만들기와 서명을 같이 쓴다. 테스트 모듈이
  아니라 수집되지 않고 `tests.signing`으로 import한다. `tests/` 루트에 테스트도 `conftest.py`도 아닌 모듈이 선 것은 이것이 처음이다.
  거절 사례를 만드는 토큰(서명 없는 `alg: none`, 공개 키 PEM을 HMAC 비밀로 쓴 HS256)도 여기서 만들고, 라이브러리가 그런 토큰을 만들어
  주지 않으므로 서명 입력을 손으로 조립한다(`_signing_input` 하나).
- **등록부의 이름표 교체.** 멈춘 실행이 도구 연결을 닫는 사이에 그 재개가 오면 새 실황이 이름표를 바꾸고, 앞 실행의 태스크는 뗄 때 자기
  실황일 때만 뗀다. 처음 문서는 실행이 등록부를 떠나는 자리가 하나뿐이라고만 적어 이 반례를 덮었다(셀프 리뷰 표준 축).
- **구독의 의존성은 `async def`다.** 동기 의존성은 FastAPI가 워커 스레드에서 돌려 자기 실행 읽기와 등록부 보기 사이가 이벤트 루프 밖이
  된다. 그 사이에 실행이 이벤트를 쓰면 그 이벤트는 읽은 트레이스에도 나중에 붙은 실황에도 없다.
- **401의 서버 기록.** `토큰이 없거나 틀리다: 서명 토큰 — {reason}`. 원인(형식, 발급자, `kid`, 서명, 시각, `sub`)은 기록에만 가고 토큰
  값은 싣지 않는다. 밖으로는 `UNAUTHORIZED_MESSAGE` 하나다.
- **`pause_index`의 계약 설명을 고쳤다.** 설명이 트레이스 상세의 `events`에서 센 인덱스만 말해 최종 사용자가 볼 수 없는 것을 가리켰다(셀프 리뷰 표준 축).
  "최종 사용자 스트림에서는 일시정지 항목의 id 다"를 더했다. 기존 필드의 설명이 바뀐 것이라 계약 변경이고, 이 티켓의 이름들과 함께
  PR에서 사용자가 본다.
- **공개 키는 SubjectPublicKeyInfo PEM만 받는다.** `load_pem_public_key`는 PKCS#1(`BEGIN RSA PUBLIC KEY`)도 받아 머리글로 거른다. 진단
  문구에는 PEM 머리글을 싣지 않는다 — 형식만 말하면 되고, 파일 내용이 진단에 새는 선례를 만들지 않는다.
- **수명은 정수로 자르지 않은 값으로 센다.** 처음에는 `exp`·`iat`를 정수로 잘라 수명 600.9초짜리 토큰이 지나갔다(셀프 리뷰 명세 축).
  만료와 미래 시각의 비교는 라이브러리처럼 정수로 하고, 수명만 실수 차이로 센다.
- **`Retry-After`의 스키마는 정수 하나다.** `minimum: 1`을 두자 FastAPI가 계약을 pydantic 모델로 다시 읽으며 라우트 하나에서만 `1.0`으로
  바꿔 같은 헤더가 라우트마다 다르게 실렸다. 하한은 설명에 적었다. 헤더 문서는 부를 때마다 새 사전을 만든다.
- **사이트 파일 모델의 배열은 리스트 필드다.** strict 모드의 pydantic은 TOML 배열(파이썬 리스트)을 튜플 필드로 받지 않는다.
- **기존 테스트 셋을 고쳤다.** 결정의 주체 판정이 들어와 다른 주체의 결정은 `DifferentPrincipal`이다. core에서 승인자를 `bob`으로 둔
  두 테스트(트레이스에 승인자가 먼저 기록되는 것, 거부도 그런 것)를 요청한 주체로 바꿨고 "자기 승인 금지는 이번 범위가 아니다"는
  지웠다. 라우터의 `test_채널_밖에서_멈춘_실행을_채널이_재개하고_승인자는_채널의_주체다`는 CLI와 같은 주체로 멈춘 실행을 쓰게 바꾸고, 다른 주체의 결정이 409이고
  결정이 쓰이지 않는다는 테스트를 따로 더했다.

## TDD와 변이

- core(결정의 주체, 열 에이전트, 자기 실행 읽기와 판정 순서)는 테스트를 먼저 쓰고 빨강을 본 뒤 구현했다.
- 공용 층·채널·`serve`의 테스트는 구현과 나란히 또는 뒤에 썼다. 단언 하나하나가 무는지 보지 못했으므로 변이 표
  `.scratch/end-user-channel/probes/contract_mutations.toml`로 31개를 되돌려 봤다. core의 판정 순서 다섯, 서명 토큰의 경계 여덟(만료 경계,
  미래 `iat`의 여유, `nbf`, 수명 600초, `kid`, 벽시계, 빈 `sub`, 수명을 자른 정수), 세 면의 자격, 면별 덮기 넷과 서버 기록, 어휘 표,
  결정 응답의 첫 인덱스, 구독(도는 실행에 붙기, 끝내지 못함의 `id`, `Last-Event-ID`의 범위와 형식, 한 걸음 사이의 await), 투영, OS 사용자
  이름 가드, 사이트 파일(와일드카드 출처, 같은 `kid`, SPKI가 아닌 PEM)이다. 31개 모두 기대대로 빨갰다. 셋(한 걸음 사이의 await, SPKI,
  수명)은 셀프 리뷰 뒤에 더했다.
- 변이 도구가 `-k`로 한국어 parametrize id를 고르지 못해 함수 이름으로 좁혔다. 코드를 옮긴 뒤에는 `--check`로 원문이 그대로인지 봤다.
- 새 접두사를 실제 모델로 지나는 LLM 테스트 하나를 더했다(`tests/test_main.py`, 사이트 파일과 테스트가 서명한 토큰으로 시작 요청 하나를 보내
  시작·끝남 항목과 `id`를 본다).
