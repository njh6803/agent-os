## 결정

- **위젯 요소를 사이트를 고를 때마다 새로 만든다.** 위젯은 요소의 `agent`가 바뀔 때만 새로 띄우므로, 요소를 재사용하면 같은 에이전트(`echo`)의 두 사이트 사이를 바꿔도 앞 대화가 메모리에 남는다. 새 요소는 붙자마자 저장한 대화의 묶음(발급자와 `sub`)을 새 사이트의 토큰과 견주어 다르면 비운다. 변이 9(쓰던 요소를 재사용)가 앞 대화가 남아 빨개지는 것을 보였다.
- **확인이 기록된 뒤에도 위젯 요소를 새로 만든다.** 덮개 뒤에 숨은 위젯이 저장한 대화를 되돌리려고 토큰을 받다 401을 받으면 `unauthorized`에 머문다. 쿠키를 잃은 브라우저가 다시 확인해도 입력창이 막힌다. e2e 사례를 더했고(`쿠키를 잃어 저장한 대화만 남은 브라우저가…`) 변이 11이 그 길을 없애면 빨개지는 것을 보였다.
- **서버가 내린 자리표시 `<agent-os-widget hidden>`은 `mountWidget`이 걷는다.** 처음 구현은 새 요소를 하나 더 붙여 위젯이 둘이 되었고(e2e 8건 빨강, strict mode 위반), 자리표시는 속성이 없어 "위젯 설정이 올바르지 않습니다"를 그렸다. 변이 10이 걷지 않으면 빨개지는 것을 보였다.
- **정보 글은 사람이 위젯을 만진 뒤의 `tokenProvider` 호출에만 거둔다.** 티켓은 "`tokenProvider`가 다음에 불릴 때"라 썼으나 위젯은 붙자마자 저장한 대화를 되돌리려고 사람이 요청을 보내지 않아도 토큰을 부른다. 그 호출만으로 거두면 글이 곧바로 사라진다. 위젯 안의 눌림·키 입력이 먼저 있었던 호출만 거둔다(변이 7·8이 두 갈래를 가른다). 티켓 문구를 그렇게 고쳤다.
- **로그인 사이트는 상태를 묻지 않는다.** 07이 남긴 "상태 묻기 실패 때 덮개" 갈래가 로그인 사이트의 모습과 어떻게 만나는지 정하라는 몫이다. 로그인 사이트는 상태 끝점을 아예 부르지 않고 안내 상자를 보이므로 만나지 않는다. e2e가 상태 끝점 요청이 나가지 않는 것을 본다(변이 12).
- **id 맞댐은 Vitest 시험으로 둔다.** PR 봇이 짚은 `findParts()`의 조용한 실패는 마크업이 늘어난 지금 더 커져서, 스크립트 원문의 `pp-` id 목록과 `pageHtml`의 마크업을 맞대는 시험을 `server/page.test.ts`에 두었다(원문 정규식이므로 `byId("pp-…")` 꼴로 찾는 id만 센다).
- **`choose()`의 `clearSwitched`를 걷었다.** 셀렉트로 바꿀 때는 바로 뒤에 `announceSwitched`가 `replaceChildren`으로 덮고 처음 열 때는 자리가 비어 있어 어떤 시험도 그 줄을 잡지 못했다.
- **스크린샷은 파일로 보내고 PR 본문에는 글로 적는다.** 티켓은 그림을 PR 본문에 싣는다고 했으나 `gh`는 본문에 올릴 그림 주소를 낼 수 없다. 1280px와 375px의 기본·덮개·로그인·둘 다 그림 여덟 장을 이 세션이 사용자에게 파일로 보냈고(커밋하지 않았다), PR 본문에는 디자인 그림과 대 본 배치를 글로 적는다. 첫 판은 라벨을 셀렉트 위에 쌓고 스위치를 가득 늘려 디자인 그림(`pp-page.dc.html` 22~54행: 라벨이 셀렉트 왼쪽 한 줄, 좁은 창에서 셀렉트가 남은 폭을 채우고 스위치는 내용 폭)과 어긋났고, 그림을 본 뒤 고쳤다.
