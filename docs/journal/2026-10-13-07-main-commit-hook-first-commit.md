# 2026-10-13 (07) kickoff-auto-flow 티켓 01: `hook_git_main_commit`이 커밋 없는 저장소의 main에서 첫 커밋을 지나가게 한다

## 계기

일지 2026-10-13-01의 "다음"이 kickoff-auto-flow 티켓을 01부터 차례로 구현하는 것이었다. 지시문의 "어디서"대로 이 세션이 먼저
주 체크아웃에서 `tidy-checkouts`를 돌고 워크트리 `01-main-commit-hook-allows-first-commit`에 들어가 브랜치
`feature/01-main-commit-hook-allows-first-commit`로 바꿨다.

`tidy-checkouts`는 루트를 `5a618af`에서 `f168f73`으로 당겼다. 판정이 지울 후보로 낸 스물하나(병합된 워크트리 열아홉, 등록 없는
폴더 둘)는 모두 종료 1로 남았다. 지우기 직전의 다시 판정에서 다른 세션의 python.exe 넷(pid 37240·38364·40928·10944)과 node·esbuild
프로세스가 각 후보 아래의 모듈을 올려 두었다고 나왔다. 그 밖에 잠금 pid가 살아 있는 것 셋, 작업 디렉터리를 쥔 claude.exe가 있는
것 다섯, 병합된 PR이 없는 것 다섯, 다시 만들 수 없는 무시 항목이 있는 것 셋을 남겼고, prunable 둘과 그 `.tidy-probe` 옆 폴더, 분리
HEAD 둘, 병합 PR 머리와 브랜치 끝이 다른 것 하나를 사람에게 넘겼다. 새 세션의 첫 턴이라 답을 기다리지 않았다.

## 한 것

- **훅.** `tools/hook_git_main_commit.py`에 `head_has_commit(cwd)`(`git rev-parse --verify HEAD`)와 합성 함수
  `reason_at(command, cwd)`를 더했다. 커밋 명령인지, 보호 브랜치인지, `HEAD`에 커밋이 있는지를 차례로 보고, 앞에서 걸러지면 뒤의
  git을 띄우지 않는다. 그래서 커밋의 유무는 보호 브랜치일 때만 읽는다. 브랜치 읽기와 커밋 유무 읽기는 같은 `_git`을 거쳐
  `GIT_DIR`·`GIT_WORK_TREE`·`GIT_COMMON_DIR`을 벗긴 환경으로 돈다. git을 띄우지 못하면 커밋이 없다고 보아 막지 않는다. `main()`은
  `reason_at`을 부르고, 테스트만 쓰던 `reason_for(command, branch)`는 지웠다(아래 셀프 리뷰).
- **독스트링과 막는 이유.** "main 위의 커밋은 언제나 실수다"를 커밋이 있는 저장소로 좁히고, 커밋 없는 저장소를 막지 않는 까닭(킥오프의
  첫 커밋, 옮겨 올 다른 브랜치가 없다)을 적었다. 못 보는 것에 orphan main(다른 브랜치에 커밋이 있어도 `HEAD`가 커밋을 가리키지 않는
  main)을 더하고, fail-open 항목에 커밋의 유무를 읽지 못한 경우를 더했다. 막는 이유의 "이 저장소에서 언제나 실수다"는 "커밋이 있는
  저장소에서 보호 브랜치 위의 커밋은 언제나 실수다"로 바꿨다.
- **훅 러너.** `create_fixtures`의 `${MAIN_REPO}`에 커밋 하나를 두고, 커밋 없는 main을 새 자리표시자 `${EMPTY_MAIN_REPO}`로 따로
  두었다. 작성자 인자는 `_unpushed_repository`와 같이 쓰도록 모듈 상수 `_IDENTITY`로 올렸다. 러너 독스트링의 자리표시자 수(열여섯)와
  목록, `create_fixtures` 독스트링의 임시 저장소 열거, 표 머리의 자리표시자 줄을 고쳤다. 표에는 `${EMPTY_MAIN_REPO}`에서
  `KICKOFF.md` 8단계의 첫 커밋 명령이 침묵하는 사례를 더했다.
- **런북.** `KICKOFF.md` 7단계 훅 목록의 `hook_git_main_commit` 한 항목만 커밋이 있는 저장소의 main 위 커밋 deny와 커밋 없는
  저장소의 첫 커밋 통과(8단계)로 고쳤다.

## TDD와 변이

- 테스트를 먼저 썼다. 첫 조각(커밋 없는 main의 침묵)은 `reason_at`이 없어 수집 오류로 빨갰고, 둘째 조각(커밋 하나 있는 main의 deny)은
  막는 이유의 새 문구가 없어 빨갰다. 러너의 픽스처 테스트(`test_main_저장소_둘은_커밋의_유무로_갈린다`)는 `EMPTY_MAIN_REPO` 키가 없어
  빨갰다.
- 나머지 넷(orphan main, 커밋 유무의 `GIT_DIR`, 작업 브랜치에서 읽지 않기, git이 없을 때)은 구현과 함께 처음부터 초록이었다. git이
  없을 때는 `PATH`를 빈 폴더로 두고 커밋이 있는 저장소를 읽게 했다. git이 있었다면 참이 나올 자리라 거짓을 단언하는 값이 있다.
  셀프 리뷰 뒤에 더한 첫 거름(커밋 명령이 아니면 브랜치도 커밋의 유무도 읽지 않는다)도 처음부터 초록이었다.
- 지키는 동작이 틀려서 빨개진 것을 본 적이 없는 테스트를 모두 `.scratch/kickoff-auto-flow/probes/main_commit_hook_mutations.toml`의
  변이로 겨눴다. 처음에 여덟을 돌려 모두 기대대로 빨강이었고, 셀프 리뷰를 반영한 뒤(이름 바꿈, 테스트 이름, 첫 거름 변이 하나)
  아홉을 다시 돌려 기준선 여덟이 초록, 변이 아홉이 모두 기대대로 빨강이었다. 러너 픽스처의 두 단언(main에 커밋이 있다, 빈 main에
  커밋이 없다)은 변이를 하나씩 따로 겨눴다.

## 확인한 것

- 셀프 리뷰 전에 검증 명령 다섯을 손으로 돌려 모두 초록이었다. pytest는 2287개 통과(`llm` 마커 7개는 선택에서 빠짐, skip 없음),
  web은 테스트 파일 28개와 테스트 357개였다. 리뷰를 반영한 뒤의 다섯은 커밋의 pre-commit 결과로 갈음한다.
- `uv run python tools/run_hooks.py`가 79건 어긋남 0이었다. `${MAIN_REPO}`의 main 위 커밋은 여전히 deny이고, `${EMPTY_MAIN_REPO}`의
  `KICKOFF.md` 8단계 첫 커밋 명령은 침묵이다. 워크트리 세션의 훅은 주 체크아웃의 파일로 돌므로 바뀐 훅의 확인은 이 러너와
  테스트로 했다.
- 잔존. 옛 말("main 위 커밋 deny", "이 저장소에서 언제나 실수", "자리표시자 열다섯")이 살아 있는 문서에 남은 자리는 없다. ADR
  0028 "함께 바뀌는 것"의 "`main` 픽스처는 `git init -b main`만 한 빈 저장소라"는 결정 시점의 근거라 두었다(`.claude/rules/adr.md`의
  달지 않는 것). 명세 "Problem Statement"의 "훅은 브랜치 이름만 보기 때문이다"도 이 기능이 푸는 문제를 적은 문장이라 두었다.
  `CLAUDE.md` 환경 함정과 `operations.md`의 "main 위 커밋은 훅이 막는다"는 커밋이 있는 이 저장소에서 그대로 참이다(티켓).

## 셀프 리뷰

`/code-review`(base `f168f73`, 수정 일곱과 미추적 하나, 커밋 없음). 표준 축은 Critical·Major 없이 Minor 넷과 Nit 여섯, 명세 축은
막을 지적 없이 Nit 다섯이었다. 명세 축은 티켓 체크박스 아홉이 모두 찼다고 봤다.

- 고친 것
  - 변이 표 머리가 러너 픽스처 테스트의 빨강을 수집 오류라고 적었다(둘 다). 실제로는 실행 중의 `KeyError`였다. 까닭마다 갈라 고치고,
    README 줄의 "빨강을 본 적이 없는"도 같은 기준으로 맞췄다.
  - 프로브 README 줄의 "1분이 안 된다"는 재지 않은 시간이었다(표준). 지웠다. README 머리가 명세만 근거로 들어 일지를 더했다(Nit).
  - `main()`이 `reason_at`을 부르게 되자 `reason_for`를 부르는 실제 길이 사라졌고, 그 테스트는 커밋 유무 없이 main을 막는다고 고정해
    실제 판정과 갈렸다(둘 다). `reason_for`를 지우고 테스트를 `deny_reason`만 재게 바꿨다.
  - `has_commits`는 저장소가 아니라 `HEAD`를 잰다(표준 Nit, orphan main이 그 차이다). `head_has_commit`으로 바꿨다.
  - git이 없을 때의 테스트 이름이 "막지 않는다"인데 `head_has_commit`만 단언했다(표준). 단언대로 이름을 바꿨다. 막지 않는 쪽으로
    이어지는 것은 커밋 없는 main 테스트와 그 변이가 본다.
  - `reason_at`의 첫 거름(커밋 명령이 아니면 git을 띄우지 않는다)에 테스트가 없었다(명세). 가짜 두 읽기로 고정하고, 같은 가짜로
    커밋 명령이 둘 다 읽어 막는 대조를 두었다. 변이 하나를 더했다.
  - 훅 독스트링과 테스트 독스트링이 킥오프가 `git init -b main`을 한다고 현재형으로 적어, 지금의 `KICKOFF.md` 1단계(`git init`)보다
    앞섰다(둘 다).
    8단계와 ADR 0028을 드는 문장으로 바꿨다. 1단계의 `-b main`은 02의 몫이다.
  - 러너 독스트링의 `${MAIN_REPO}`·`${WORK_REPO}` 설명이 작업 브랜치에도 커밋이 있는 것처럼 읽혔다(표준 Nit). 둘을 갈라 적었다.

  - 테스트의 `_작성자` 주석이 가리킨 선례가 이제 `_IDENTITY`를 쓴다(표준 Nit). 주석을 고쳤다.
  - 티켓의 상태와 체크박스(명세 Nit). 선례(`design-refresh/issues/01`)대로 `done`과 `[x]`로 바꿨다.
- 남긴 것

  - `_IDENTITY`로 올리며 `_unpushed_repository`도 바뀐 것(명세 Nit, 범위). 중복만 없앴다.
- 다시 돌린 것: 훅·러너 테스트 50개, 변이 아홉(위), `ruff check`. 검증 명령 다섯은 커밋의 pre-commit으로 갈음했다. 커밋

## origin/main 합치기

커밋 뒤 origin/main이 `f168f73`에서 `185fe61`(#208, `hook_webfetch_summary`)로 움직여 합쳤다. `KICKOFF.md` 7단계의 훅 목록 줄에서
충돌이 났다. 그쪽이 같은 줄에 새 훅의 항목과 매처를 더했고 이쪽은 `hook_git_main_commit`의 설명을 바꿨다. 그쪽의 줄을 받고 이쪽의
설명 변경을 다시 얹었다(`git diff origin/main -- KICKOFF.md`가 그 한 항목만 냈다). 병합 커밋 `1d1b3e4`의 pre-commit이 모두
초록이었다. #208이 바꾼 `.claude/rules/tools.md`는 계기 훅의 측정 방법이라 이 변경에 걸리지 않는다.

PR 직전 리뷰 뒤 origin/main이 `68e8786`(#207)으로 다시 움직여 한 번 더 합쳤다. `.scratch/retro-queue.md` 끝에서 충돌이 났다. 그쪽이 더한
217~222 가운데 217이 이 세션이 223으로 적은 항목과 같아, 그쪽 행을 받고 223을 버린 뒤 217에 회차를 더했다(아래 회고). #207이 바꾼
`next-session` 스킬은 병합 전에 다시 읽어 그 판을 따른다.

## PR 직전 리뷰

CodeRabbit CLI는 좌석이 없어(`Seat: not assigned`) 대체 둘을 나란히 돌렸다. 범위는 첫 합치기 뒤의 `git diff origin/main...HEAD`(커밋
`ebdbf78`·`1d1b3e4`·`656eaf3`)다.

- `/security-review`: 발견 없음. 새 git 호출은 인자가 상수 목록이고 셸을 거치지 않으며, `rev-parse --verify HEAD`는 ref만 읽어 저장소
  설정으로 명령이 도는 길을 타지 않는다. orphan main의 우회는 보안 경계가 아니라 독스트링의 못 보는 것이다.
- `bug-perf-review`: 유효·보류 0건, 오탐 여덟. 커밋 명령이 아니거나 보호 브랜치가 아니면 git을 더 띄우지 않는다는 것, `rev-parse`가
  커밋이 있는데 실패해 지나가는 입력을 찾지 못했다는 것, 러너 픽스처의 새 커밋이 옛 `_unpushed_repository`와 같은 모양이라 새로
  깨지는 환경이 없다는 것을 들었다. 선택으로 `-c commit.gpgsign=false`를 픽스처와 테스트의 작성자 인자에 더하는 방어를 들었다. 전역
  서명 설정이 있는 환경에서는 옛 픽스처도 함께 깨지므로 이 PR의 노출이 아니라 두었다.

병합은 워크트리의 길로 한다(`next-session` "워크트리에서 병합할 때"). 주 체크아웃 미갱신: 루트는 main.

## 에이전트가 번복하거나 고친 것

- git이 없을 때의 테스트를 처음에는 없는 작업 폴더로 썼다. 티켓의 상황(git이 없다)과 다르고 커밋이 있는 저장소를 읽지 않아 거짓을
  단언하는 값이 약했다. 변이를 돌리기 전에 `PATH`를 빈 폴더로 두고 커밋이 있는 저장소를 읽게 바꿨다.
- 빈 main 픽스처의 단언을 겨눈 변이를 처음에는 main 픽스처의 커밋을 빈 main으로 옮기는 모양으로 썼다. 그러면 main 픽스처의
  커밋도 사라져 앞의 변이와 같은 단언을 빨갛게 했다. 빈 main 픽스처가 커밋 있는 저장소를 가리키는 모양으로 바꿨다.
- 변이 표 머리에 러너 픽스처 테스트의 빨강을 수집 오류라고 적었다. 그 테스트의 빨강을 다시 보지 않고 첫 조각의 빨강과 같다고
  적은 것이다. 셀프 리뷰가 짚어 고쳤다.

## 추천과 결정이 갈린 곳

이 세션에는 사용자에게 물은 선택 화면이 없다. 지시문 밖의 사용자 메시지도 없다.

  "계기"). 21번의 `remove`가 모두 종료 1이었고, 남긴 이유의 프로세스가 매번 같은 pid였다. 판정 3이 하드링크 이름까지 보는 것은
  대기열 201이 들인 정당한 판정이라 판정을 고치는 것이 아니라 하드링크 공유를 줄이는 설치 방식이 층이다. 그 방식의 비용(설치 시간,
  디스크)을 재지 않아 측정부터 하는 행으로 승인했다. 처음에는 새 행 223으로 적었는데, origin/main을 다시 합치자 형제 세션(일지
  2026-10-13-06)이 같은 항목을 217로 먼저 올려 두었다. 고칠 자리와 측정이 같아 223을 버리고 217에 회차와 이 일지를 더했다.
