## 잰 것

### 카나리아 세션에 git 상태가 실리는지(쟀다)

`.scratch/harness/probes/canary_git_status.py`, claude 2.1.299. 임시 git 저장소(브랜치 `probe/mark-branch`, 커밋
여덟, 고친 파일, 스테이지한 새 파일, 추적하지 않는 파일, 추적하지 않는 폴더 안의 파일)와 같은 파일을 둔 보통
폴더(음성 대조)에서 카나리아 명령으로 띄워 도구 없이 컨텍스트의 git 상태 블록을 옮기게 했다. 셋 모두 도구 0회.
저장소 둘은 지금 브랜치, 주 브랜치, git 사용자 이름, `Status:` 아래 짧은 꼴 네 줄(추적하지 않는 폴더는 `mark-dir/`로만),
`Recent commits:` 아래 커밋 다섯(`mark-c08`~`mark-c04`)을 옮겼고, 보통 폴더는 "없음"이었다. 그래서 확인의 범위를 그
셋(경로, 브랜치, 최근 커밋 다섯의 제목)으로 정했다. 243 행이 "실린 것으로 보인다"고 적은 전제가 섰다.

### 변이

옛 코드(`head_commit`의 subprocess 호출 등)를 가리키던 변이 여섯(68·70·74·95·96·97)의 원문을 지금 코드로 고치고, 새 변이
스물아홉(100~128)을 더했다. git 상태 열넷(카나리아 알림, 읽지 못한 갈래, 사전 확인에 잇기, 경로·브랜치·제목 견주기,
이름 바꾼 옛 경로, 줄 머리 떼기, NUL 가르기, 다섯, 저장소 밖, 브랜치·로그의 제한 시간, 한 번만 읽기, 체크아웃 없는
갈래)과 대조군 커밋 열다섯(인자 알아보기, 깃발 같은 커밋, 사전 확인의 깃발, 자리 쓰기, 실험군을 바꾸지 않기, 찾지 못한
커밋과 그 종료 코드, `--detach`, `core.longpaths`, `--force`, 걷기, 제한 시간의 반쯤 꺼낸 자리, git이 거부한 자리를
지우지 않기, 걷기 실패 알림, 시작 줄)이다. `tools/mutate.py`로 고른 서른일곱(옮겨진 98·99 포함)이 모두 기대대로
빨강이었다. 변이를 고치다 스크립트가 윈도의 `write_text` 기본값으로 `canary_mutations.toml`과 `test_canary.py`를 CRLF로
바꿔 놓은 것을 보고 LF로 되돌렸다.
