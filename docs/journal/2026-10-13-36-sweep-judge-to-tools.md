## 구현

- `tools/model_sweep_judge.py`(새 파일): `sweep.py`에서 판정의 순수 함수를 옮겼다. 입력의 조건(`input_problems`,
  `kind_problems`), 표지 모집단(`marked`, `merged_in_time`), 배정대로 가르기(`split_arms`), 판정하지 않는
  조건(`blocking_reasons`), 주된 판정과 되풀이(`lower_verdict`, `verdicts`), 그리고 그 셋을 묶는 `judge_kind`다. 판정의
  순서는 이 파일의 독스트링으로 옮겼다. `tools/`는 `.scratch/`를 들이지 않으므로(pyright가 풀지 못한다) 부트스트랩·90%
  구간·3사분위를 `analyze.py`와 같은 식으로 옮겨 적었다.
- PR #220 claude-review에서 보류한 셋을 함께 풀었다.
  - 불리언 인자 `stopped`·`markers_ok`: `blocking_reasons`와 `judge_kind`는 이제 `swept`(도구의 `SWEPT`, 빠진 종류를 안에서
    멈춘 것으로 가린다)와 `failed_markers`(소급 측정 표지 넷 가운데 문턱을 넘은 것의 이름)를 받는다. 그래서 사유 줄이 어느
    표지에 걸렸는지 이름을 든다.
  - `BASE`와 `tool.BASE`의 같은 이름: 기록 쪽은 `ARM_RECORD`가 도구로 옮겨 갔고, `sweep.py`의 `population`이 쓰는 값은
    `RECORDED_BASE`(`ARM_RECORD[tool.BASE]`)로 바꿨다.
  - 행마다 `parse_ts(SWEEP_START)`: 모듈 상수 `SWEEP_START_AT`으로 한 번 셈한다.
- 같은 PR 둘째 회차의 다른 리뷰가 낸 둘도 풀었다. `test_빠지는_것_밖의_차이를_잡는다`가 `!= []`만 보던 것은 어긋난 종류의
  이름을 단언하게 했고, `N_K`가 사전 등록과 대 보는 검사 없이 종류가 더해지면 판정 시점에 `KeyError`로 죽는 것은 사전
  등록의 종류가 모두 `N_K`에 있는지 보는 테스트로 막았다.
- `tools/model_sweep.py`: 두 프로브 README의 사전 등록 절을 떼는 `prereg_section`을 더했다. `sweep.py`와
  `test_model_sweep.py`가 저마다 하던 표지 자르기를 이것 하나로 모았고, 새 테스트 파일도 이것을 쓴다.
- `sweep.py`: 파일 읽기, 두 절의 해시 대조, `analyze.markers`로 표지 셈, 표 찍기만 남았다. 판에 `model_sweep_judge.py`의
  해시를 더했다.
- `tests/tools/test_model_sweep_judge.py`(새 파일): 합성 행 픽스처(`_행`, 기본값은 표지 모집단에 들고 기한 안에 병합된 행)로
  조건마다 경계를 단언한다. 고정값(n_k, 판정 시점, 80%, 표지, 기록 모델·레벨)이 사전 등록 절에 있는지, 부트스트랩의 횟수와
  시드가 소급 측정 사전 등록 절에 있는지도 본다.
- `.scratch/harness/probes/model_sweep_judge_mutations.toml`: 판정 조건과 고정값을 하나씩 깬 변이 마흔넷(셀프 리뷰 뒤의 판).
  프로브 README 표에 행을 더했다.
