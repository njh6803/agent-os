# 2026-09-26 (05) 실제 `serve`로 멈추고 HTTP로 승인한다 — http-channel 티켓 05

브랜치 `feature/05-real-serve-pauses-and-approves`, PR #80(`2056e7b`로 squash 병합). `src/`는 한 줄도
바뀌지 않았다. 01~04가 가짜 포트로 닫은 채널 위에 실제 경로 하나를 긋는 `-m llm` 테스트 하나다. 실제
`agent-os serve` 서브프로세스에 실제 모델과 실제 stdio 도구 서버를 붙여, HTTP로 일으킨 실행이 승인 대상에서
멈추고 HTTP로 보낸 승인으로 재개되어 답 `5`로 끝나는 것을 본다. 이것으로 **http-channel이 닫혔다**.

사용자 입력은 인계 지시문 하나, 병합 지시 하나, 선택 둘(PR 감시, 회고 판정 넷)이었다.

## 설계

- **서버가 설 때까지 기다리는 방식(티켓이 정하라고 한 것).** `--port 0`으로 띄우고 uvicorn의 기동 줄
  (`Uvicorn running on …`)에서 고른 포트를 읽는다. uvicorn 0.53은 `port == 0`이면 `getsockname()`으로 실제
  포트를 싣고, 그 줄은 lifespan 시작과 `create_server` **뒤에** 찍힌다. 빈 포트를 미리 골라 `/health`를
  폴링하는 안은 포트를 닫고 넘기는 사이의 경합 때문에 택하지 않았다. `_port`의 독스트링이 "0 은 남겨 둔다"고
  적은 그 0을 처음 쓴다.
- **출력은 파이프가 아니라 파일로 받고 나갈 때 표준 에러로 옮긴다.** 비우는 쪽이 없는 파이프는 차면 서버를
  쓰기에서 세운다. pytest는 실패한 테스트의 캡처만 보여 주므로 서버 쪽 트레이스백이 실패와 함께 보인다.
- **정리는 `terminate` → `wait` → `kill`.** Windows에서 venv의 `python.exe`는 실제 인터프리터를 자식으로
  띄우는 런처이고, 런처를 거두면 자식도 도구 서버도 함께 끝났다(아래 변이).
- **요청마다 전체 상한 120초(`_post_stream`).** 처음엔 읽기 상한(60초)만 두었다. 조각 사이만 재는 값이라
  모델 호출이 멈춰도 keepalive가 15초마다 오는 한 끝나지 않는다는 것을 CodeRabbit이 짚었다(Major). 조각이 올
  때마다 상한을 보고, keepalive가 간격마다 오므로 상한을 넘긴 뒤 늦어도 그만큼 안에 알아챈다.
- **keepalive 건너뛰기는 기본 스위트의 테스트 하나가 잰다.** 실제 모델로는 15초 넘는 침묵을 부를 수 없어서
  FastAPI의 `KEEPALIVE_COMMENT` 바이트로 스트림 파서를 잰다.
- **토큰 둘은 `secrets.token_urlsafe()`.** 실제 소켓이 듣는 동안 같은 기계의 다른 프로세스가 짐작할 수 없다.
- 자식 프로세스의 `PYTHONUTF8` 강제를 `_env()` 한 곳으로 모았다(interrupts 06이 `_cli`를 만들며 한 곳에
  둔 것을 지켰다).

## 밟은 것

- **초록으로 시작했다.** interrupts 06과 같은 자리라 반증으로 이빨을 쟀다.
- **아무것도 재지 않은 변이가 두 번 초록으로 지나갔다.** 읽기 상한 0.5초 변이는 도구 서버가 뜨기 전에
  끝나 "남은 프로세스 0"이 아무것도 말하지 않았다(로그에 `ListToolsRequest`가 없고 트레이스가
  `run_started` 하나). 2.5초로 늘려 도구 서버가 뜬 뒤를 확인했다. 전체 상한 3초 변이는 요청 하나가 3초 안에
  끝나 초록이었고 0.5초로 줄여 빨강을 봤다. 변이의 전제가 성립했는지 로그와 트레이스로 본 뒤에야 판정했다.
- **184줄 heredoc을 훅이 막았다**(환경 함정). Edit로 나눠 반영했다.
- 정리를 뺀 대조군에서 남은 프로세스가 **둘**(venv 런처와 인터프리터)이었다. 런처 구조를 이것으로 알았다.

## 테스트와 변이

기본 스위트 +1(keepalive), `-m llm` +1. 변이는 바이트 단위로 넣고 되돌렸다.

| 변이 | 결과 |
|---|---|
| `main.py`가 트레이스 디렉터리를 엉뚱한 곳으로 넘김 | 빨강 |
| 서버가 선 뒤 테스트가 실패(기동 줄 정규식을 깸) | 빨강, 남은 프로세스 0 |
| 도구 서버가 `ListToolsRequest`를 처리한 뒤 모델 호출 도중 실패 | 빨강, 도구 서버까지 0 |
| 대조군: 정리를 뺌 | 서버가 남음 |
| 스트림 파서의 주석 필터를 지움 | 새 기본 테스트 빨강 |
| 전체 상한 0.5초 | 빨강(모델 호출 뒤 도착한 조각에서), 남은 프로세스 0 |

실물 트레이스는 interrupts 06과 같은 모양이다 — `run_started`, `llm_called`, `run_paused(add)`,
`approval_granted`, `run_resumed`, `tool_called(add, ok)`, `llm_called`, `run_finished("5")`. 두 스트림을
이으면 이 열이다.

## 갈린 곳

- 기동 줄을 읽는 쪽을 택했다(헬스 폴링 거부). 대가는 uvicorn 문구에 기대는 것이다.
- keepalive 가드를 테스트 헬퍼를 재는 기본 스위트 테스트로 두었다. 실제 모델로 부를 수 없는 조건이라서다.
- 수정 커밋의 CodeRabbit 전체 리뷰가 한도에 걸린 채 병합했다. 스레드 답글이 그 수정을 확인했고 수정은
  테스트 파일뿐이다. 한도가 풀리길(약 한 시간) 기다리지 않았다.
- 도구 서버 정리의 독스트링을 메커니즘("표준 입력이 닫히면")이 아니라 관측으로 적었다. job object인지
  EOF인지는 재지 않았다.
