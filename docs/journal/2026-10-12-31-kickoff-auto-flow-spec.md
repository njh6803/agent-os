## 선행 조건의 측정

지시문의 선행 조건은 세션 도중에 만든 사용자 레벨 스킬을 그 세션에서 바로 부를 수 있는지였다(ADR 0028 "첫 시작").

- 공식 skills 문서는 있던 스킬 폴더는 감시해 바로 반영하고, 세션 시작 때 없던 최상위 폴더는 `/reload-skills`가 든다고
  적는다. 처음에는 WebFetch의 요약으로 읽었고, PR #192를 들인 뒤 원문을 받아 그 문장(321행)을 손으로 봤다.
- 프로브 `.scratch/kickoff-auto-flow/probes/skill_live/run.py`(claude 2.1.296)를 세 번 돌렸다. 폴더가 세션 전부터 있으면 도중에
  만든 `disable-model-invocation` 스킬이 사람이 친 `/이름`으로 바로 불렸다. 없던 폴더면 두 번 불러도 불리지 않다가
  `/reload-skills` 뒤에 불렸다. 셋째 판은 CLI의 표지 둘(다시 낸 사용자 메시지의 `<command-name>` 태그, 그 턴 `system/init`의
  `skills`)로 턴을 가르고, 측정이 아닌 턴은 0이었다.
- 사용자 레벨은 직접 재지 못했다. 첫 판에서 `project,local` 설정 출처로는 세션 전에 `~/.claude/skills`에 만든 스킬도 부르지
  못했다. `user` 출처를 켜면 이 기계의 사용자 설정에 있는 Stop 훅(`~/.claude/hooks/stop-hook.sh`)이 턴마다 Slack에 알림을
  보낸다는 것을 그 스크립트를 읽어 알았다. 그래서 프로젝트 레벨로 대신 쟀다.

결과로 첫 시작의 세션 경계를 없앴다. 진행 규율이 시작할 때 사용자 레벨 스킬을 먼저 만들고 같은 세션에서 `/kickoff`로
잇는다. ADR 0028에 이력 초안을 올렸다.

billing usage도 쟀다(`.scratch/kickoff-auto-flow/probes/billing_usage/run.py`, gh 2.98.0). `year`·`month`로 이번 달만 받히고,
`repositoryName`은 주인 없이 오며, 요구 범위는 `user`였다. 조직의 길이 관리자만이라는 것은 GitHub REST 문서의 원문을 받아
손으로 봤다. CodeRabbit CLI(0.7.5)의 `coderabbit auth status` 출력 모양도 손으로 봤다.

## 이음매와 진행 파일

선택 화면으로 두 가지를 물었다. 묻기 전에 테스트 이음매, 진행 파일, `/compact`를 무엇인가와 잡아 주는 것과 치르는 값으로
풀었다.

> 사용자: (이음매 — 킥오프 자동 진행을 어느 이음매에서 시험할까요?) "셋으로 가른다 (Recommended)" — 설명: 훅은 기존 순수 함수 테스트와 훅 러너 표로 봅니다(커밋 있는 main은 막고, 빈 저장소의 첫 커밋은 지나감). 사람 몫 줄은 새 검사를 pytest 저장소 상태 테스트로 봅니다. 진행 규율은 사람이 임시 폴더에서 돌려 봅니다: 런북 머리의 한 줄로 시작 → 0단계가 사용자 레벨 스킬을 실제로 만듦 → 같은 세션에서 /reload-skills·/kickoff → 1단계 뒤 /compact → 2단계 → 새 세션 /kickoff가 3단계에서 이어 가는지 확인.

> 사용자: (진행 파일 — 8단계의 첫 커밋 뒤에는 main 커밋 훅과 브랜치 보호 때문에 진행 파일의 갱신을 main에 커밋할 수 없습니다. 그 갱신을 어떻게 남길까요?) "첫 PR이 싣는다 (Recommended)" — 설명: 8단계의 첫 PR을 chore/ 브랜치로 열어, 첫 커밋 뒤의 진행 파일과 일지 갱신을 싣습니다. 훅과 보호를 그대로 지키고, 병합하면 원격의 진행 파일이 '8단계 끝'이 됩니다. 첫 PR에 넣을 내용을 따로 만들 필요가 없습니다.

  이유를 남겼다(일지 2026-10-12-25의 같은 지적과 같은 처리).
- 프로브의 `gh_json`이 실패를 딕셔너리로 돌려준다(Nit): 그대로 둔다. `CODING_STANDARDS.md`의 "실패는 예외로"는 어댑터 층의
  규칙이고 이 파일은 일회성 프로브다.

## 이 세션의 판단

- 이음매의 질문에 적은 검증 차례는 "0단계가 사용자 레벨 스킬을 만든다"였다. 명세를 쓰며 스킬을 시작 확인에서 먼저 만들도록
  당겼다. 붙여 넣은 한 줄로 도는 구간이 준비 전부를 덮지 않게 하기 위해서다. 검증의 모양(첫 시작의 한 줄, 같은 세션의
  `/kickoff`, `/compact`, 새 세션의 재개)은 그대로다.
- 일지 만들기를 1단계에서 준비로 당겼다. 준비의 결정을 적을 곳이 처음부터 있게 하기 위해서다.
- 사람 몫 줄은 단계 머리에 모으지 않고 그 일이 일어나는 자리에 둔다. 8단계처럼 사람 몫이 여럿인 단계에서 멈출 차례가 줄의
  자리로 정해진다.

## 에이전트가 번복하거나 고친 것

- 스킬 프로브의 첫 판은 사용자 레벨 변형(A·B)을 들었다. A가 `project,local`에서 불리지 않아 `user` 출처가 필요했고, 그
  출처의 Stop 훅이 Slack 알림을 보낸다는 것을 알고 사용자 레벨 변형을 뺐다. 알림은 보내지 않았다(A는 `project,local`로만
  돌았다).
- 첫 판의 C에서 `/reload-skills` 뒤 부르기의 답은 표지 문자열을 담은 거절이었는데, "표지가 답에 있다"로 판정해 실렸다고
  찍혔다. 본문이 실리고 모델이 따르지 않은 것인지 가를 수 없었다. 판정을 답이 표지 그대로인 것으로 좁혔고, PR #192를 들인
  뒤 CLI의 표지 둘로 가르는 셋째 판으로 바꿨다.
- 공식 문서 두 곳(skills, GitHub billing)을 처음에는 WebFetch 요약으로 읽었다. PR #192의 규약대로 원문을 받아 손으로 대
  보고 명세에는 원문으로 적었다.
- 명세 서두의 표시 수를 셀프 리뷰 뒤에는 다시 셌지만 PR 직전 리뷰 반영 뒤에는 세지 않아 claude-review가 짚었다. `to-spec`은
  "리뷰를 반영한 뒤" 다시 세라고 적는데, 이 세션은 그것을 셀프 리뷰 하나로 읽었다.

## 회고

후보 넷을 냈고 대기열로 간 것은 없다. PR을 연 뒤 하나를 더 냈고 그것은 대기열 207로 갔다(이 절 끝).

> 사용자: (회고 — 회고 후보 넷을 어떻게 처리할까요?) "모두 일지에만 (Recommended)" — 설명: 넷 모두 기존 장치(리뷰 파이프라인, 주장 검증, 커밋 전 대조, 기존 프로브의 project,local 관행)가 잡았거나 한 번의 사건이라, 대기열 행 없이 일지 회고 절에만 남깁니다.

- **헤드리스 프로브가 사용자 설정을 켜면 전역 Stop 훅이 Slack 알림을 보낸다(Minor).** 사용자 레벨 스킬을 재려고 `user`
  출처를 켜려다 `~/.claude/hooks/stop-hook.sh`를 읽고 피했다. 보낸 알림은 없다. 기존 프로브(`hook_registration/run.sh`)와
  카나리아 러너가 이미 `--setting-sources project,local`을 쓴다. 한 번의 사건이다.
- **확인이 뒤 단계의 산출물에 기대는 차례 모순을 셀프 리뷰가 놓쳤다(Minor).** CodeRabbit App 확인이 아직 없는 첫 PR에
  기댄 것을 PR 직전 리뷰가 Major로 잡았다. 리뷰 파이프라인이 정한 대로 작동했다.
- **닫힌 수 "아홉 절"의 셈 실수(Minor).** 셀프 리뷰 두 축이 주장 검증 1로 잡았다.
- **측정 도중 main에 근거 규약이 들어와 프로브를 다시 고쳐 돌렸다(관찰).** 커밋 전 대조(`CLAUDE.md` 환경 함정의 커밋 전
  줄)가 잡았다.

PR을 연 뒤 claude-review가 명세 서두의 수를 짚어(위 "PR 리뷰 반영") 후보 하나를 더 냈고 대기열로 갔다.

> 사용자: (추가 후보 — 명세 서두의 수가 본문과 어긋난 것이 세 번째입니다(대기열 105는 셀프 리뷰 뒤에 세라는 지침으로 닫혔고, 이번엔 그 뒤의 PR 직전 리뷰가 본문을 고쳐 어긋났습니다). 이 후보를 어떻게 할까요?) "대기열에 새 행 (Recommended)" — 설명: to-spec 3단계의 '서두의 수 세기'를 셀프 리뷰 하나가 아니라 병합 전에 본문을 고치는 모든 반영(PR 직전 리뷰, PR 봇 회차) 뒤로 넓히는 행을 대기열에 적습니다(3회차, 대상 to-spec, ADR 불필요). 반영은 다음 chore 배치에서 합니다.

- **명세 서두의 수를 PR 직전 리뷰 반영 뒤에 다시 세지 않았다(Minor, 대기열 207).** 105의 지침은 셀프 리뷰 뒤를 가리켜 이번에
  지켰지만, 그 뒤의 반영이 본문을 고쳐 다시 어긋났다. 105의 두 회차에 더해 세 번째다.
