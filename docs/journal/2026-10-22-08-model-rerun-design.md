# 2026-10-22 (08) 지난 티켓을 갈래마다 다시 풀어 모델과 레벨을 재는 측정을 설계한다

## 사용자 프롬프트

아침 보고 재설계 세션(일지 2026-10-20-39, `chore/morning-report-split`)에서 사용자가 다른 AI의 답을 붙여 넣고 물었고, 그 세션이 이
세션을 곁 세션으로 열었다. 붙여 넣은 글의 주장은 기준이 아니라 측정할 가설로 쓴다(설계 문서 1절).

> 사용자: 모델 선택 기준에 아래 내용을 참고해서 선택하게 할 수 있나?

> 사용자: '실제 작업으로 직접 측정해 보시는 것이 가장 정확'하다고 해서 측정해보고 싶어.

이 세션에서 갈래를 보고:

> 사용자: 갈래는 Opus xhigh(지금 기본), Opus medium, Sonnet medium, Sonnet high이거만 있어?
> Opus high이랑 Sonnet xhigh은 왜 없어

- Opus high는 넣고 Sonnet xhigh는 빼자고 답했다(설계 문서 4절). 다시 풀기는 며칠에 끝나 "medium 먼저, high는 다음 스윕"의
  까닭이 약하고, 나중에 따로 돌리면 Claude Code 판과 시기가 달라 짝 비교가 흐려진다. Sonnet xhigh는 결정표 칸을 바꾸는
  경우가 좁다.

> 사용자: 티켓의 난이도에 따라 모델을 선택할 수 있는거야?

- 장치(지시문의 "모델" 줄)는 있고 근거가 없다고 답했다. 열기 전 지표는 비용을 맞히지만(ρ 0.6대) 비싼 티켓에 Opus가 필요한지는
  답하지 않고, 모델이 티켓을 분류하는 길은 단순 지표보다 못했다(ADR 0029 이력 2026-10-13). 크기 층별 결과표와 "싸게 열고
  실패하면 올리기"의 비용 셈을 판정이 아닌 탐색으로 넣자고 했다.

> 사용자: 승인

- 둘을 설계 문서 6절의 탐색에 넣었다. 난이도로 나눌 근거가 보이면 문턱 후보만 정하고 새 티켓의 2차로 확인한다.

## 셀프 리뷰(`/code-review`, base 30949cf, 커밋 0, 바뀐 파일 1, 미추적 2)

대상은 설계 문서, ADR 0029 이력 2026-10-20 초안과 본문 포인터 둘, 이 일지다. 명세는 과제 원문과 위 사용자의 답이다.

표준 축(sonnet·high): Critical 0, Major 3, Minor 4, Nit 1, 냄새 2. 판정은 모두 고친다(냄새는 남긴다).

- Major 1. 사전 등록이 6절만 옮겨, 과제 목록·층·숨은 시험 ID(3절), 갈래(4절), 끝남·측정 아님·상한·오염(5절)이 해시 밖이다
  (`.claude/rules/probes.md`의 "정의 전부를 고정한 절 안에"). 고친다.
- Major 2. 이어 가기에서 러너가 "지시문을 내고 멈춤"과 "지시문 없이 멈춤"을 무엇으로 가르는지, 개입·세션 상한을 넘으면 어떻게
  되는지가 없다. 고친다.
- Major 3. 클론에 pre-commit git 훅이 깔리지 않는다(`hook_session_web_deps`는 클라우드에서만 깐다). 실제 세션은 커밋마다
  pre-commit을 지난다. 고친다.
- Minor 4. 시작 프롬프트를 `/implement`로 넣으면 `open-session`이 실제로 보내는 모양(`Convert-StartLine`이 옮긴 한 줄)과 다르다. 고친다.
- Minor 5. "bug-perf-review가 잡았다"의 대기열 361은 셀프 리뷰 명세 축이 잡은 사건이다. 고친다.
- Minor 6. ADR이 판정 문턱을 옮겨 적었고, 개입 조건이 설계 6절과 뜻이 다르다. 고친다.
- Minor 7. "손으로 봤다"에 명령이 없다(`docs/agents/issue-tracker.md`). 고친다.
- Minor 8. 일지 `2026-10-20-32`(그 세션이 뒤에 39로 옮겼다)는 이 브랜치와 main에 없고 `morning-report-format` 워크트리에만 있다. 고친다.
- Nit 9. 공식 측정의 xhigh는 한 번만 돌렸다는 단서가 없다. ADR 0033의 "보고서를 본 뒤에 정한다"의 범위를 이 이력이 바꾼다. 고친다.
- 냄새: 10절 2차(계획·실행 나누기)는 Speculative Generality로 보일 수 있다. 붙여 넣은 글의 주장을 가설로 다루라는 요구 6의 몫이라
  남긴다. 칸을 바꿀 때 여러 파일을 고치는 Shotgun Surgery는 결정표·스윕·지표 문서가 따로 있는 구조의 값이라 남긴다.

명세 축(메인 모델을 물려받음): 14개. 판정은 모두 고친다.

- 1. 붙여 넣은 글의 "max에서는 Sonnet이 오히려 비싸다"와 Sonnet low가 1절 표에 없다.
- 2. 서브에이전트 쪽에 "이력 초안 → 사용자 승인"이 없고, 10절 판정이 "비싼 쪽이 하나 더"와 "싼 쪽이 더"를 정하지 않았다.
- 3. `SWEPT`에서 구현을 빼면 `test_model_sweep.py`의 feature 사례와 `test_model_sweep_judge.py:251`이 빨개진다. ADR의 "시험이
  이미 그 길을 든다"가 틀렸다(서브에이전트가 스크래치 탐침으로 봤다).
- 4. "판정 전에 고치는 것"이 지표 문서 2절 "내릴지는 이 저장소의 스윕이 정한다(4절)"와 4절 6의 머리를 빠뜨렸다.
- 5. 사용자 결정의 판단 재료가 모자란다. 칸을 내리면 A 갈래가 어떻게 되는지, 상한이 얼마나 넘칠 수 있는지(`--max-budget-usd`는
  호출마다라 세션 넷이면 네 배), 결론이 나는 최소 예산.
- 6. 9절 순서에 파일럿 뒤의 한 줄 보고와, 상한에 여섯 과제가 들지 않을 때 멈추는 갈래가 없다.
- 7. 개입 조건의 뜻이 두 문서에서 다르다(표준 축 6과 같다).
- 8. 2절 "스윕의 기록을 보지 않았고 쓰지 않는다"가 사실이 아니다. 7절의 xhigh 13개는 스윕의 기준 갈래이고, 3절의 원래 세션 비용도
  스윕 브랜치에서 온다. 본 세션이 트랜스크립트에서 다시 보니, 7절 어림의 스크래치 스크립트(`branch_cost.py`)가 10-12 뒤의 구현
  브랜치를 한 줄씩 찍어 medium 갈래 브랜치의 비용도 화면에 나왔다. 갈래끼리 견준 수는 내지 않았다. 문장을 사실대로 고치고, 원래
  세션과 A를 견주는 탐색은 원래 세션이 xhigh인 과제로 좁힌다.
- 9. 1절 표의 세 줄이 주장과 맞지 않는다(분류는 `coderabbit-review` 쪽이다, "Opus medium으로 넘긴다"를 셈이 A로 올린다, 55~60%
  동등은 판정이 아니라 탐색이다).
- 10. "파일럿은 갈래 비교를 본 뒤의 고침이 아니다"가 틀렸다(파일럿이 같은 과제에서 A와 E를 돈다). web 숨은 시험의 판정을 파일럿에서
  정하는데 숨은 시험 ID는 그 앞에 고정한다.
- 11. 2절이 "장부에 들지 않는다"를 사실로 적었는데 5절은 어림이다.
- 12. 대기열 361(표준 축 5와 같다).
- 13. 끊는 줄 갈래: headless 세션이 `open-session`을 부르면 `tools/open_session.ps1`이 사용자의 실제 앱에 세션을 연다. 막는 규칙과
  오염 검사에 이 길이 없다.
- 14. 파일럿의 작은 과제는 20만 토큰에 닿지 않아 인계가 밟히지 않을 수 있다.

고친 것:

- 설계 문서 1절: 가설 표에 max와 Sonnet low를 넣고, Haiku 행을 `coderabbit-review`로, 올리기 행을 D→C 짝으로, 55~60% 행을 탐색으로 고쳤다.
- 2절: 스윕 기록의 문장을 사실대로 고치고(medium 갈래 브랜치의 비용이 스크래치 출력에 실렸다, 갈래 비교는 내지 않았다), 장부 문장을 어림으로 고쳤다.
- 3절: 손으로 본 근거에 스크립트가 한 일을 적고, 과제 고정을 파일럿 뒤로, 파일럿 과제를 셋으로 고쳤다.
- 4절 B 행에 공식 측정의 xhigh가 한 번만 돌았다는 단서를 더했다.
- 5절: 준비에 `uv run pre-commit install`, 막는 규칙과 오염 검사에 `open-session`·`open_session.ps1`·`claude://`, 첫 메시지를
  `Convert-StartLine` 모양으로, "어디서"를 `새 세션`과 모델 줄을 갈래 값으로 바꿨다(본 세션의 판단: 실제 구현 지시문 세션과 첫 턴
  훅의 길을 같게 둔다). 이어 가기를 갈래 셋과 상한 넘김으로, `--max-budget-usd`를 회차의 남은 값으로 고쳤다.
- 6절: 사전 등록의 범위를 3~6절의 정의 전부로 넓히고, 파일럿이 한 과제를 두 갈래로 돌리지 않게 했다. 개입 조건을 "개입 수가 A보다
  많은 과제가 둘 이하"로, 올리기 셈을 (x, y) 짝으로 고치고, 원래 세션과 A의 비는 원래 세션이 xhigh인 과제로 좁혔다.
- 7절: 근거 문장에 명령을 적고, 일지 2026-10-20-39(그때 번호 `2026-10-20-32`)가 main에 없다고 적었다. 파일럿·최소·8과제의 어림 행을 더하고, 멈춤의 과제
  어림을 갈래 비율 위 끝의 합(4.1배)으로, 넘칠 수 있는 폭을 적었다.
- 8절: 파일럿을 과제 셋으로, 장부·pre-commit·open-session 확인과 인계 문턱의 갈음을 더했다.
- 9절: 순서를 파일럿 → 과제 고르기 → 사전 등록 → 한 줄 보고(여섯이 안 들면 멈춤) → 본 측정으로 고쳤다.
- 10절: 사건 목록을 116·229·278·282·318·321로 고치고 출처를 적었다. 서브에이전트 판정의 빈 갈래와 이력 승인 단계, ADR 0033과의
  관계, `coderabbit-review`를 재는 조건을 더했다.
- 11절: 한계에 스윕 medium 갈래의 원래 세션을 더하고, 결정 셋의 판단 재료를 늘렸다.
- ADR 0029 이력: 굵은 결정에 실행 조건과 `model`의 승인 단계를 넣고, ADR 0033과의 관계를 적었다. 판정 문단은 문턱을 옮겨 적지 않고
  원천을 가리키게 했다. 사건 목록, 판정 전에 고칠 지표 문서의 두 문장, `SWEPT`와 함께 고칠 시험, 예산을 고쳤다.
- ADR 0033 본문 35줄 뒤에 `(바뀜: ADR 0029 이력 2026-10-20 "…")` 포인터를 달았다.

반영하며 새로 쓴 사실 문장(PR 직전 리뷰가 겨냥할 주장):

- "셋째는 pre-commit과 commit-msg 두 git 훅을 깐다(`.pre-commit-config.yaml`의 `default_install_hook_types`)."
- "클론에는 저절로 깔리지 않는다(`hook_session_web_deps`는 클라우드 세션에서만 깐다, `.claude/rules/tools.md`)."
- "마지막 것은 `next-session` 4단계가 "어디서"가 새 세션이면 `open-session`을 부르게 해서다."
- "알아보는 법은 첫 턴 훅과 같이 줄 머리의 `브랜치:`와 `어디서: 새 세션` 두 줄이다(`tools/hook_prompt_directive.py`)."
- "첫 턴 훅(`hook_prompt_directive`)이 세션에 스스로 이름을 붙이라고 하는데 headless에는 그 도구가 없다."
- "클론은 main에 깨끗하게 체크아웃되고 묶음이 아니라 3단계의 세 조건이 모두 아니다."
- "`--max-budget-usd`는 `claude -p` 호출마다 걸리므로"
- "규칙 파일과 `code-review` 스킬이 PR 직전 `bug-perf-review`가 잡았다고 적은 사건(대기열 116·229·278·282·318·321 등)"
- "`tests/tools/test_model_sweep_judge.py`가 `SWEPT`로 구현을 판정하는 사례"

남긴 것: 표준 축의 냄새 둘(위 판정의 이유).

다시 돌린 명령: `uv run python tools/check_adr_pointers.py`, `tools/check_md_tables.py`, `tools/check_line_separators.py`,
`tools/check_instructions.py`. 넷 다 출력 없이 종료 0이었다. 코드는 바꾸지 않아 pytest·pyright·경계·web은 돌리지 않았고, 이 세션은 커밋하지 않으므로 pre-commit 갈음도 없다.
