# 2026-10-12 (37) 새 세션의 모델과 추론 레벨을 지시문이 정한다

브랜치 `chore/session-model-select`, 워크트리 `.claude/worktrees/session-model-select`. ADR 0029 초안.

> 사용자: "새 세션을 열 때 작업의 난이도나 복잡도 등을 따져서 모델과 추론레벨을 자동으로 선택해서 시작하고 싶어. 어떤 작업에 어떤 모델을 쓸지는 나랑 정하고."

## 길 찾기

- 딥링크 `claude://code/new`는 모델을 싣지 못한다. 앱 2.19675.0.0의 `app.asar`에서 `code/new` 처리기를 읽었다(`q`·`prompt`·`folder`·`file`과 SSH 인자뿐).
- `set_session_model`·`set_session_effort`는 다음 턴부터다. 새 세션의 첫 턴이 작업 전체라 늦다.
- 새 세션 입력창의 `모델:`·`노력:` 버튼이 접근성 트리에 펼치기 패턴으로 있었다. 스크립트가 보내기 전에 고르는 길로 정했다.
- 세션이 다시 시작되며 `start_session` 도구가 생겼다. 모델과 노력을 받지만 여는 세션과 같거나 싼 것만 연다(도구 설명). Sonnet으로 돈 세션이 다음을 Opus로 열 수 없어 버렸다(ADR 0029).

## 표를 정하는 방식

처음에는 초안 표를 내고 선택 화면으로 물었다.

> 사용자: (판단 기준 — 난이도를 무엇으로 판단할까요?) "난이도나 복잡도 등을 측정하는건 별로인가?"

> 사용자: (Fable — Fable 5.1은 어디에 쓸까요?) "모델(추론레벨) 별로 조사를 해보자. 언제 어떤 모델을 쓸지 우리끼리 정하지 말고."

> 사용자: (Sonnet — Sonnet 5.5로 내릴 범위는 어디까지일까요?) "PR 반영·병합만 (Recommended)" — 설명: 리뷰 지적을 반영하고 병합하는 작업만 Sonnet으로 엽니다. 판단보다 절차가 많은 작업입니다.

> 사용자: (구현 추론 — Opus로 여는 일반 구현의 추론 레벨은 무엇으로 할까요?) "[No preference]"

조사는 서브에이전트 셋으로 갈랐다(공식 모델·레벨 자료, Claude Code 동작, claude-api 스킬 동봉 문서). 결론은 "작업을 열기 전에 난이도를 가르는 공식 기준은 없고 자기 작업으로 재 보라"였다. 보고의 수는 웹 요약이라, ADR에 옮긴 셋(SWE-bench Pro 부분집합의 Opus 5.5 레벨별 차이, Opus 5.5 medium과 Fable 5.1의 92.8%·92.3%와 "실행 간 잡음 안", Sonnet 5.5가 low·medium의 긴 작업에서 확인을 구하며 멈춘다는 문장)은 `curl`로 받은 마크다운 본문에서 `grep`으로 대 봤다. 처음 보고에서 WebFetch로 확인한 것을 "원문 대조"라고 쓴 것은 이 저장소에서는 웹 요약이라 바로잡았다. Haiku의 최신이 5.5(2026-10-07)라는 것도 조사에서 알았다. 환경 정보와 claude-api 스킬 표(2026-09-25)는 4.5를 최신으로 적고 있었다.

> 사용자: (진행 순서 — 어떤 순서로 진행할까요?) "1번으로 하고. 지난 티켓을 소급해서 측정하는 프로브의 설계도 함께 제안하고 앞으로 모델이 업데이트되고 할 수도 있으니까 모델(추론레벨) 별로 어떤 작업이나 난이도, 복잡도, 설계, 디자인 등 선택에 도움이 될 수 있는 지표들을 작성하는 .md 파일을 하나 만드는건 어때? 표로 만들어도 되고? 근거를 만들어도 되고 그건 너가 생각했을 때 필요할만한 것들을 전부 넣어서"

1번은 "장치 먼저, 이어서 소급 측정"이다.

## 소급 측정 설계의 검토

사용자가 설계를 네 번 되물었고, 그때마다 고쳤다.

> 사용자: "소급 측정 프로브 설계 제안 위에 정도면 괜찮은거 확실해? 필요없거나 필요한게 더 있는지 단계적으로 생각해봐."

> 사용자: "좋은데 한번만 더 검토해봐. 난이도나 복잡도는 측정이 어렵겠지?"

> 사용자: "모델에게 티켓만 보여 주고 1~5를 매기게 할 때 1~5는 범위가 너무 좁은거 아니야?"

> 사용자: "이제 진짜 더 고려할 것 없어?"

> 사용자: "그리고 Haiku 5.5는 메뉴 활성 시켰어. 진행해."

고친 것의 줄기: 비용은 출력 토큰이 아니라 API 환산 비용으로, 시간은 빈 구간을 빼는 어림이 아니라 턴 시간의 합으로 잰다. 사전 지표는 완성된 diff가 아니라 merge-base 시점의 티켓 본문에서만 뽑는다(누출). 주된 가설은 돌리기 전에 README에 적는다(사전 등록). 모델 판정 실험은 1~5 눈금 대신 단위가 있는 범위 추정(턴 수·파일 수·시간), 기준 티켓 제시, 축별 채점으로 묻는다. 난이도는 끝난 뒤에만 드러나고 미리 알 수 있는 것은 복잡도와 범위가 닫혔는지 열렸는지라, 프로브는 그것이 드러난 난이도를 맞히는지를 처음으로 재는 일이다. 전체는 "다음" 절에 둔다.

## 구현과 실제 실행

- `tools/open_session.ps1`: `Read-ModelLine`(쏘기 전에 읽고, 못 읽으면 세션을 만들지 않는다), `Set-ComposerModel`(입력창 묶음의 버튼만 고른다. 분할 보기의 다른 패널을 건드리지 않게 입력창에서 위로 올라가 찾는다), `Restore-DraftDefaults`, `-Action defaults`(복구). 테스트 13개를 먼저 빨강으로 보고(`Read-ModelLine 가 스크립트에 없다`) 초록으로 만들었다.
- 슬라이더 칸은 보내지 않은 표지 화면에서 옮기며 읽었다. 0 낮음, 1 중간 (추천), 2 높음, 3 엑스트라, 4 최대, 5 Ultracode.
- 시험 세션 셋을 실제로 열었다. `Haiku 5.5 / low`, `Sonnet 5.5 / medium`, `Haiku 5.5 / high`의 `get_session`이 그대로였다. 넷째는 셀프 리뷰를 반영한 뒤에, 다섯째와 여섯째는 PR 직전 리뷰를 반영한 뒤에 열었다(아래). 일곱째는 분할 보기에서 열었다. 일곱 세션은 사이드바에 남아 있다(사용자가 그대로 두라고 했다).
- 끈적임: 첫 시험 뒤의 표지 화면이 `Opus 5.5 / 낮음`, 2분 뒤가 `Opus 5.5 / 엑스트라`라 갈렸다. 보내지 않은 화면에서 노력을 중간으로 두고 닫자 다음 화면이 중간이었다. 둘째 시험 뒤에는 모델도 `Sonnet 5.5`로 남아 있었다. 첫 시험 뒤에 모델이 원래대로였던 것은 사람이 그 사이 화면을 만진 것이었다.

> 사용자: "미안 내가 중간에 건들였어"

그래서 모델과 노력을 둘 다 되돌린다. 셋째 시험은 `restored=Opus 5.5 / xhigh`로 끝났고 다음 화면이 `Opus 5.5 / 엑스트라`였다. 둘째 시험 뒤 남은 `Sonnet 5.5`는 `-Action defaults`로 되돌렸다.

- 고쳤다

## PR 직전 리뷰

- 카나리아(새 세션에서 스킬 불러 보기): `next_session_model_line.toml`과 `open_session_model_pick.toml` 모두 통과 4(claude 2.1.296). 실험군 세 번이 바뀐 줄을 옮겼고, 대조군(주 체크아웃의 옛 판)은 옛 줄과 "없음"이었다. 뒤에 open-session 문구를 고친 것은 사전 확인으로 갈음했다.
- CodeRabbit CLI는 `Seat: not assigned`라 대체 둘을 돌렸다. 보안(`/security-review`)은 지적 없음. 버그·성능(`bug-perf-review`)은 유효 넷(Major 하나), 보류 둘, 오탐 넷.
- 고쳤다
  - [Major] 고른 뒤 `sent=` 전에 멈추는 길 대부분(보내기 버튼 둘, 지시문 바뀜, 제출 확인 시간 초과)에 복구 안내가 없었다. 고르기부터 제출 확인까지를 한 곳에서 받아 `restore=필요`를 낸다.

  - 메뉴를 연 뒤 멈추면 메뉴를 접는다. 표지 지우기는 던지지 않고, 지웠는지만 돌려준다.
  - 순수 함수 둘(`Get-EffortButtonStep`, `Get-RepairHint`)의 테스트 8개를 더했다.
  - 보류였던 "키 입력 가드"를 고쳤다. 먼저 키를 보내기 전에 Claude 창이 앞에 있는지 보는 가드를 넣었는데, 첫 실행에서 바로 멈췄다. 그때 앞에 있던 창은 Chrome이었고, 입력창에 `SetFocus`를 해도 Claude 창이 앞으로 오지 않았다(`foreground_window.ps1`). 그대로면 사람이 다른 앱을 쓰는 동안 늘 멈추므로, 키를 버리고 패턴(펼치기, `SelectionItem.Select`, `RangeValue.SetValue`, 값으로 지우기)으로 바꿨다(`composer_patterns.ps1`). 그 과정에서 탐침이 메뉴가 닫힌 것을 다른 라디오 버튼(`Claude`, `Code`) 때문에 열린 것으로 읽어 기본 모델을 Haiku 5.5로 남겼다. 고친 스크립트의 `-Action defaults`로 `Opus 5.5 / xhigh`로 되돌렸고, 그것이 패턴 판의 첫 실제 실행이었다.
  - 다섯째 시험(`Haiku 5.5 / medium`)은 메모장을 앞에 둔 채 시작해 `restored=Opus 5.5 / xhigh`로 끝났다. 여섯째(`Opus 5.5 / xhigh`)는 `restored=바뀐 것 없음`이었다. 두 세션의 `get_session`이 줄과 같았다. 같은 시각 다른 세션이 연 티켓 세션 둘(`feature/01`, `feature/02`)은 13:33에 만들어져 겹치지 않았다.
- 분할 보기 지적(보류)은 손으로 돌려 닫았다. 창이 분할 보기(왼쪽 여섯째 시험 세션, 오른쪽 `docs/kickoff-auto-flow-tickets`)일 때 일곱째 시험(`Sonnet 5.5 / high`)을 돌렸다. 새 세션은 `claude-sonnet-5-5`·`high`였고, 오른쪽 세션의 `get_session`은 전후 모두 `claude-opus-5-5`·`xhigh`였다. 자기 입력창 묶음에 버튼이 없는 경우는 새 세션 화면에서 본 적이 없어 가드를 넣지 않았다. 되돌리기 화면이 왼쪽 패널에 남아 이 세션을 `-Action focus`로 불러왔다.

  - 재작업: PR 뒤 커밋 수, 봇 코멘트 수, CI 실패 수, 심각도(뽑히는 것만), 하네스 마찰(훅 거부, 도구 오류), 사람 개입(첫 지시문 뒤의 사용자 메시지, `AskUserQuestion`), 지연된 실패(후속 `fix/` PR, 대기열 행, `diagnosing-bugs` 호출, 되돌리기).
