# 2026-09-30 (03) 플러그인 하나와 켜고 끄기

web-admin 티켓 06. 일지 2026-09-30-02의 "다음"(06이 다음이다)을 이어 새 세션에서 했다. 브랜치는
`feature/06-plugin-detail-and-toggle`, 주 체크아웃이다. 요청 범위는 구현·리뷰·커밋·PR·병합까지다. 지시문이 넘긴 상태 하나는

`rejectAdminTokenIfStillHeld`로 바꾸기로 PR에서 답했고 이 티켓이 실었다.

## 한 것

- **플러그인 하나.** 동적 라우트 `app/plugins/[kind]/[name]/page.tsx`가 주소의 두 조각을 `components/pages/PluginPage`에
  넘긴다. 페이지가 종류를 가리고(`api/plugins`의 `isPluginKind`), `organisms/PluginDetail`이 켜짐과 들여 적은 매니페스트를
  보인다. 실패, 새로 고침, 다시 확인하는 중은 목록과 같다.
- **토큰 문.** 첫 화면의 hydration 가드, 관리 토큰을 넣는 자리, 토큰 지우기를 `components/pages/AdminScreen`으로 옮겼다.
  첫 화면과 플러그인 하나가 지난다.
- **켜고 끄기.** 목록 행마다 이름의 링크와 스위치(`role="switch"`인 제어 체크박스)가 섰다. 요청 함수 `setPluginEnabled`는
  204를 응답의 상태로 가른다. 훅 `useSetPluginEnabled`가 PUT 뒤에 목록을 다시 읽고 그 플러그인 하나의 캐시를 버리며, 그것이
  끝나야 돌아온다. 행은 그동안 스위치를 막고, 실패는 목록의 머리에 보인다.
- **401 처리 한 자리.** fetcher 둘과 쓰기 하나가 `orRejectAdminToken`을 지난다. 지시문의 이름 바꾸기를 실었다.
- **페이지 테스트 21.** 플러그인 하나 10(새 파일), 목록에 링크 1과 켜고 끄기 10. 토큰 넣기 도우미를 `testing/token.ts`로
  옮기고, `renderPage`가 캐시를 받아 화면을 옮겨 다니는 운영자를 잴 수 있게 했다.
- **e2e.** `e2e/plugin-toggle.e2e.ts`가 에이전트 `echo`를 끄고, 운영자 파일의 `agent` 줄을 보고, 열어 보고, 다시 켠다.
  준비가 플러그인 루트를 `AGENT_OS_E2E_PLUGINS_ROOT`로 넘긴다. 두 흐름의 화면 도우미를 `e2e/screen.ts`로 옮겼다.
- **프로브 둘.** `probes/plugin_toggle_mutations.mjs`(변이)와 `probes/switch_after_rejection.mjs`(401 뒤 `finally`의 목록).
  05의 러너 원문 하나를 좁혔다.
- **문서.** 티켓 06의 체크와 "이 티켓이 정한 것", `spec.md`에 이 티켓이 달리 읽은 세 자리의 주석, 07·08의 "06이 남긴
  메모", 05의 옛 함수 이름에 주석 하나, 프로브 README의 두 행.

## 잰 것

- **openapi-fetch 0.17의 204.** 본문 없는 성공에도 `data`가 비어 있다(설치본 `index.mjs` 180행). 목록처럼 `data`로 가르면
  성공이 실패가 된다. 변이("본문 없는 204 를 실패로 읽는다")가 페이지 테스트를 빨갛게 했다.
- **SWR 2.5.1.** 마운트되지 않은 키의 `mutate`는 요청을 보내지 않는다(`config-context`의 `startRevalidate`). 캐시가 있으면
  마운트에서 그것을 먼저 보이고 다시 읽는다. `revalidateIfStale`의 기본값이 true라서다(`use-swr`의 suspense가 아닌 갈래,
  287행). 그래서 스위치 뒤에 플러그인 하나는 `mutate(key, undefined, { revalidate: true })`로 캐시의 값을 버린다. 값만 두는
  변이("그 행을 다시 읽기만 하고 캐시의 값을 버리지 않는다")가 교차 화면 테스트를 빨갛게 했다.
- **next/link와 jsdom.** Vitest에서 `next/link`는 `next/link.js`를 거쳐 `dist/client/link.js`(`RouterContext`)로 풀린다. 라우터
  컨텍스트가 없으면 `<a>`로 그리고 누름을 넘긴다(`if (!router)`). 앱의 빌드는 app 라우터의 링크를 쓴다. 페이지 테스트는
  `href`만 보고, 실제로 여는 것은 e2e가 본다.
- **동적 라우트의 타입.** `next build`가 `.next/types/validator.ts`에서 라우트의 props를 `AppPageConfig<"/plugins/[kind]/[name]">`와
  맞춘다. `next-env.d.ts`는 `.gitignore`에 있고 `.next/types/routes.d.ts`를 import하므로 `PageProps` 전역 대신 props 타입을
  손으로 적었다. CI의 tsc는 빌드 전에 돌아 validator를 보지 않고 e2e의 빌드가 본다.
- **401 뒤의 `finally`(`probes/switch_after_rejection.mjs`).** 훅의 `finally` 첫 줄에 문서의 스위치 수와 넣는 칸의 유무를
  표준 에러로 찍고 켜고 끄기 절을 돌렸다. 넣는 칸이 선 한 줄(401)만 스위치 0이고 나머지 열 줄은 5였다. `console.info`로 찍은
  줄은 Vitest의 출력에 나오지 않아(까닭은 재지 않았다) `process.stderr.write`로 찍었다.

## TDD와 변이

- 플러그인 하나의 첫 테스트는 "모듈이 없다"로, 켜고 끄기 일곱은 "스위치가 없다"로 빨갰다. 그 빨강은 각 테스트가 지키는
  행동의 빨강이 아니고, 실패·401·새로 고침·다시 확인하는 중·다시 읽다 실패·키의 횟수 테스트는 구현 뒤에 썼다. 그래서
  행동마다 변이를 넣었다(`probes/plugin_toggle_mutations.mjs`, e2e 둘 포함).
- **변이 목록을 짜다 공백 하나를 찾았다.** 플러그인 하나의 키에 토큰을 받아들인 횟수를 실었는데 지키는 테스트가 없었다.
  05의 "지운 토큰의 늦은 401"과 같은 테스트를 플러그인 하나에 더했고, 변이(키에서 횟수를 뺀다)가 그것을 빨갛게 했다.
- **처음 돌렸을 때 24 가운데 둘이 초록이었다.**
  - "본문 없는 204 를 실패로 읽는다". 204를 실패로 읽어도 훅이 목록을 다시 읽어 스위치는 꺼짐이 되고, 첫 테스트는 실패가
    보이지 않는다는 것을 보지 않았다. 단언을 더했다.
  - "401 뒤에도 목록을 다시 읽는다". 401을 가르는 분기가 관찰되지 않는 코드였다. 위의 프로브로 까닭을 쟀다. 분기를 걷고
    `finally` 하나로 줄였다.
- 고친 뒤 변이 27(분기가 사라져 하나를 걷고, 셀프 리뷰가 부른 것 넷을 더했다). 묶음 셋(플러그인 하나 10, 목록 15, e2e 2)으로
  나눠 돌려 모두 빨강이다. 한 번에 돌리면 약 10분이라 명령 상한에 걸릴 수 있고, 도중에 죽으면 변이를 되돌리지 못한다.
- **05의 러너 28을 이 티켓의 코드에 다시 돌렸다.** 토큰 문을 옮기고 훅을 고친 것이 05의 테스트를 무디게 하지 않았는지 보려고
  했다. 원문 하나를 좁힌 뒤 28 모두 빨강이다.
