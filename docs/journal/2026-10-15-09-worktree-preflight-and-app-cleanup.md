# 2026-10-15 (09) 워크트리 운영 규칙안을 현재 방식과 견주어 진입 전 확인과 앱 정리 예외를 정한다

## 계기

사용자가 외부에서 가져온 워크트리 운영 규칙안(기본 경로 `.worktrees/<slug>`, 만들기 전 `git worktree list --porcelain`
확인, 세션 소유권 확인, 강제 제거와 `prune` 금지, 앱이 관리하는 워크트리는 앱의 지원 기능으로 정리)을 붙이고 현재 방식과의
차이를 물었다.

> 사용자: 위 내용을 비교했을 때 지금 워크트리 방식이랑 많이 달라?

시작 상태: 등록된 워크트리 17개(주 체크아웃 1, `.claude/worktrees/` 13, 다른 세션의 스크래치패드 3). 비교는 항목마다 한 줄로
냈다. 정리 순서, 소유권 판정, 강제 제거와 `prune` 금지는 `tidy-checkouts`가 이미 같은 방향으로 더 엄격했고, 달랐던 것은
셋이었다. 기본 경로, 진입 전 목록 확인, 앱 정리 기능이다. 사용자가 이어서 정했다.

> 사용자: 제안대로

제안은 경로를 옮기지 않고 목록 확인을 더하며 앱 정리 예외를 명시하는 것이었다. ADR 초안은 셀프 리뷰를 반영한 뒤 보여
드렸고 사용자가 승인했다.

> 사용자: 승인

PR을 연 뒤 두 가지를 더 물었다.

> 사용자: Auto-fix는 항상 키도록하는게 좋을까?

(권하지 않는다고 답했다. 앱에 "항상 켜기" 설정이 없고 PR마다 켜는 스위치이며, 이 저장소는 봇의 Minor·Nit에 둘째 회차부터
응하지 않기로 했기 때문이다. 이 PR은 켜지 않았다.)

## 갈린 곳

- **`locked` 줄 규칙을 처음에 넣었다가 뺐다.** 첫 판은 "그 항목에 `locked` 줄이 있으면 들어가지 않고 사람에게 넘긴다"였다.
  명세 축과 표준 축이 모두 짚었다. `EnterWorktree`가 만든 워크트리는 그 세션의 pid로 잠기고(이 세션의 워크트리도
  `git worktree list --porcelain`에서 `locked claude session … (pid …)`였다), 그러면 이어받는 세션이 자기 잠금에 막힌다.
  `tools/tidy_checkouts.py` 판정 3은 죽은 pid의 잠금을 풀고 지우므로 두 문서가 같은 신호를 다르게 판정하게 된다. 뺐다.
- **앱 정리 예외 문장을 승인된 제안보다 좁게 썼다가 되돌렸다.** 승인된 제안은 "앱 표지가 있는 워크트리만 앱에 맡기고, 이
  저장소의 워크트리는 `tidy-checkouts`로 지운다"였다. 첫 판은 "앱에 기대지 않는다"로 절대형이었고 표지 쪽 몫이 사라졌다.
  명세 축이 요구가 줄었다고 짚었다. 승인된 문장대로 되돌렸다.
- **ADR 번호를 0031에서 0032로 옮겼다.** 커밋 직전의 `tools/sibling_overlap.py`가 PR #245의 0031과 겹침을 알렸다. 이 브랜치가
  들인 참조 여덟 자리만 옮겼다.
- **`.worktrees/`로 옮기지 않았다.** `EnterWorktree`가 새 워크트리를 `.claude/worktrees/` 안에 만들고, 그 경로가 든 줄이
  정리 도구와 시험 등 14개 파일 57줄이다.
