## 라운드

plan 행이 넘긴 물음은 일곱이었다(패키지 모양, rem과 px, 다크 모드, 접근성, 한글 글꼴, Storybook, 디자인 문서). 라운드는
다섯이었고, 사실이 필요한 물음(글꼴, Storybook, 디자인 문서)은 서브에이전트의 보고를 받은 뒤의 라운드로 미뤘다.
라운드가 나아가며 물음이 늘었다. 색 토큰의 구조, 테마를 고르는 손잡이, 컴포넌트 범위, 변형 표현, 상호작용 부품,
`dist`의 자리, 시각 회귀, 동기화 계기, 용어, 스토리 테스트의 자리, 디자인 토큰에 없는 클래스, 사진 비교의 자리다.

추천과 다르게 정해진 것은 하나다. 다크 모드를 나중에 값만 더하는 안을 추천했는데, 사용자는 라이트와 다크를 지금
둘 다 골랐다. 그 답이 색 토큰의 구조(쓰임새 변수가 테마마다 바뀜)와 테마 손잡이(`data-theme`, 없으면 시스템)의
물음을 열었다.

시각 회귀는 두 번 되돌아왔다.

> 사용자(질문에 답): "좀 더 쉽게 설명해줘"

정답 사진과 비교하는 테스트라는 것, 잡는 것(색과 1px 밀림), 치르는 값(Windows와 Linux가 글자를 다르게 그려 정답
사진이 운영체제마다 갈림, 의도한 변경마다 다시 찍음)으로 풀어 다시 올렸다.

> 사용자(질문에 답): "3번을 하나로 쓸수는 없는거야?"

사진을 늘 같은 Linux 컨테이너 안에서만 찍으면 한 벌로 된다고 답했다. 이 기계에 Docker 24.0.7과 Linux 엔진이
떠 있는 것을 `docker info`로 손으로 봤다. 운영체제마다 두 벌을 관리하는 부담이 사라져, 추천을 시각 회귀를 두지 않는 안에서
사진 한 벌을 늘 같은 Linux 컨테이너에서 찍는 안으로 바꿨고 사용자가 골랐다. 측정에 필요한 이미지(약 956MB)를 받는 것도 사용자가
허락했다.

합의를 확인받은 뒤 ADR 0026 초안을 `proposed`로 보였다. 사용자는 승인하면서 범위를 넓혀, 뒤따르는 문서와 검증,
셀프 리뷰, 커밋과 PR까지 가기로 했다.

## 잰 것

넷 모두 서브에이전트가 했고 보고를 근거의 종류로 갈라 받았다. 프로브와 판은 `.scratch/design-system/probes/README.md`다.

- **`/design-sync`의 형식.** 스킬은 디스크의 파일이 아니라 Claude Code 2.1.286 실행 파일에 zstd로 압축된 자원이었다.
  압축을 메모리에서만 풀어 읽었다(손으로 봤다). React만 대상이고, `.storybook/main.*`가 있으면 storybook 모양(스토리를
  컴파일해 참조 화면과 스크린샷 비교)으로, 없으면 package 모양(에이전트가 미리보기를 씀)으로 돈다. 컴파일된 `dist/`를
  묶고 Tailwind는 돌리지 않는다. guidelines는 패키지의 `docs/*.md` 등이 기본이고 `guidelinesGlob`으로 바꾼다.
  `.design-sync/`는 저장소 루트에 커밋한다. 프로브는 없다. 읽은 것이라 ADR에도 그렇게 적었다.
- **글꼴(`font_shadow/`).** Chromium과 Firefox는 shadow root 안의 `@font-face`를 쓰지 않았다. 문서에 고유한 이름으로
  선언하면 사이트에 새지 않았다. 다른 출처 글꼴은 CORS 머리글이 있어야 했다.
- **Storybook(`storybook/`).** Storybook 10.6.1과 addon-vitest, addon-a11y, Vitest 5.0.2 브라우저 모드가 `web/` 사본에서
  판정자 범위를 줄이지 않고 우회 없이 `verify`를 지났다. 조건 셋(`allowBuilds`, `.storybook` include, 앵커한
  gitignore)과 Tailwind의 기본 `@theme` 값을 비웠을 때 익숙한 클래스가 조용히 빠지는 것을 찾았다. 뒤의 것이 디자인 토큰에 없는 클래스를
  막을지 묻는 물음을 열었다.
- **컨테이너 사진(`visual_docker/`).** 같은 이미지로 따로 띄운 컨테이너 둘의 사진 16장이 바이트까지 같았다. Windows와는
  글자가 든 사진만 달랐다.

## 셀프 리뷰

`/code-review`(base `750e488`, 수정 9, 커밋 0, 미추적 29)를 돌렸다. 표준 축은 문서만 바뀌어 sonnet이었다. 명세
축에는 티켓이 없어, 사용자가 확인한 합의 요약과 고른 선택지의 설명을 요구로 넘겼다(대기열 46).

- **고쳤다, 두 축 모두.** ADR 0025의 "코드가 바뀌면 `/design-sync`로 다시 맞춘다"에 포인터가 없었다. 0026이
  동기화를 화면을 그리기 직전으로 좁혔다. 같은 기준으로 ADR 0024의 "단위는 design-system이 정한다"와 ADR 0025의
  "세부는 design-system 기능의 인터뷰가 정한다"에도 달아 포인터가 다섯이 됐고, 0026의 Consequences가 다섯을 센다.
  "51개 중 24개"를 `style.mjs`로 가리켰는데 재는 것은 `build.mjs`였다. 단독 "토큰"이 ADR에 남아 있었고(용어집이
  피하라고 한 말), Tailwind의 `@theme`과 우리의 테마를 같은 "테마"로 써서 둘을 갈랐다. `plan.md` web-widget 행의
  "rem은 사이트를 따라간다"에 px로 닫혔다는 말을 더했다.
- **고쳤다, 명세 축.** ADR 결정 단락에 핵심 컴포넌트 목록이 없었고 `plan.md` 행에는 "(한 줄·여러 줄)"이 빠졌다.
  pnpm 11이 설치를 멈춘 것은 손으로 본 것인데 프로브의 측정처럼 적혀 있었다. 일지의 스킬 인용이 원문과 달랐다.
  PR #137과의 충돌은 둘이 아니라 셋이었다(`plan.md`의 이웃한 행). 게이트 티켓이 고칠 목록에 `tech.md` 원격·CI
  행의 "잡 셋"이 빠졌다. `plan.md`의 목표 배치에 `packages/ui/`가 없었다.
- **고쳤다, 표준 축.** `index.json`을 `/design-sync`가 읽는다는 것과 `guidelinesGlob`의 동작은 실행 파일을 읽은
  것인데 표기가 없거나 프로브에 붙어 있었다. CSP가 막으면 시스템 글꼴로 내려간다는 문장은 재지 않은 설계 의도라
  그렇게 적었다. 상속 문단이 `:host`에 `!important`를 둔 대안(측정에서 사이트를 이겼다)을 빠뜨려 Considered
  Options에 더했고, 잰 속성이 `font-family`뿐임을 밝혔다. "조건은 셋이다"를 설치와 판정의 조건으로 좁혔다.
  `tech.md` 웹 행의 모호한 "셋 다"와 아직 없는 패키지를 "있고"로 적은 것을 고쳤다. 용어집의 디자인 토큰 정의에서
  규칙인 둘째 문장을 지웠다. 대기열 114·115의 "무엇" 칸을 한 문장으로 줄였다. 프로브 README의 근거 자리를
  넓혔다. 화면 디자인 절이 읽힐 계기가 없어, 화면을 그리는 기능의 `plan.md` 행(web-widget, admin-style)이 그 절을
  가리키게 했다.
- **남겼다.** 접근성 선택지의 설명은 `@axe-core/playwright`였지만, Storybook이 정해진 뒤 합의 요약이 addon-a11y로
  바꿨고 사용자가 확인했다. 디자인 탐색을 `.scratch/design-system/design/`에 내보낸다는 것은 요약에 없던 것을
  ADR 0025의 규약을 이 기능에 적용해 더했다. ADR 0021 Considered Options의 "슬라이스 4에서 다시 본다"는 거부한
  안의 근거라 포인터를 달지 않았다(`.claude/rules/adr.md`). 프로브끼리 겹치는 도우미 함수(`remSites` 등)는 프로브가
  하나씩 따로 돌게 둔 것이라 그대로다. 같은 결정이 ADR, `plan.md`, `tech.md`에 겹쳐 적힌 것은 기존 행들의 관례를
  따랐다.

> 사용자(질문에 답): "1. 개념을 쉬운 말로 먼저 푼다,2. 열린 PR과도 번호를 대조한다"

1. **설계 인터뷰의 질문에 처음 나오는 기술 개념은 쉬운 말로 먼저 푼다(대기열 114).** 시각 회귀 질문이 "좀 더 쉽게
   설명해줘"로 되돌아왔다. interrupts 설계(2026-09-21)와 web-widget 설계(2026-10-03-03)에 이은 3회차다. 다시 올릴 때
   쓴 세 토막(무엇인가, 잡아 주는 것, 치르는 값)으로 풀자 사용자가 그 자리에서 대안까지 물었다. 자동 검사로 잡을 수
   없는 판단이라 grilling 스킬의 한 줄로 간다. 하네스를 바꾸면 새 세션에서 실리는지 확인해야 해서 이 PR에 넣지 않았다.
2. **커밋 직전의 번호 대조에 열린 PR의 head도 넣는다(대기열 115).** 이 브랜치와 열린 PR #137이 둘 다 헌법을
   3.0.10으로 올린다. `CLAUDE.md` 환경 함정의 대조는 `origin/main`만 봐서 잡지 못하고, 앞 일지(2026-10-06-03)의
   "다음"이 적어 두어 알았다. 그 일지에서도 #137과 #138·#139가 3.0.9로 부딪혔으니 2회차다. 회고 줄을 올리다 #137이
   대기열 112·113도 먼저 쓴 것을 `git show`로 손으로 봐서, 이 세션의 줄은 114·115다.

일지에만 남기는 것: 첫 라운드에서 질문 여섯 가운데 넷만 올리고 나머지 둘(변형 표현, 상호작용 부품)을 두 라운드
뒤에 물었다. 스킬의 "frontier가 넷을 넘으면 같은 라운드를 호출 여럿으로 잇달아 올린다"를 놓친 1회차이고, 그 둘에 기대는 물음이 없어 손해는 없었다.
