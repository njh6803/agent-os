## 측정이 정한 것

이음매는 PR #107에 이미 서 있었고 사례 36개가 돌았다. 그래서 결정은 그 이음매를 둘지 Pester로 옮길지였다. 수는 프로브
`.scratch/harness/probes/pwsh_test_seam.py`가 다시 낸다.

- **Pester의 판은 이미 갈려 있다.** 이 PC의 pwsh가 보는 Pester는 Windows PowerShell 모듈 폴더의 3.4.0뿐이고, CI가 쓴 러너
  이미지(`ubuntu-24.04` 20261004.327.1)의 README를 받아 grep하니 5.9.0이었다(손으로 봤다). 어느 lock 파일도 이것을 고정하지
  못한다. 거부의 첫 까닭이 됐다. "판을 고정할 자리가 없다"만으로는 pwsh에도 똑같이 걸린다는 것을 셀프 리뷰가 짚었다.
- **비용.** 사례 하나가 0.92초이고 그중 pwsh 기동이 0.40~0.41초다(프로브의 최종 판, 두 회차). 시험 파일 하나는 유휴 상태에서 29.94초, 같은 날 pytest
  전체는 325초였다(둘 다 손으로 봤다). 첫 측정의 48.92초는 워크트리의 `.venv`를 막 만든 직후의 회차라 쓰지 않았다(왜
  느렸는지는 재지 않았다).
- **묶으면.** `Read-ModelLine`의 정상 사례 36개를 pwsh 하나에서 사례마다 새 runspace로 부르면 1.50~1.59초였다. 실패 사례를
  pytest에 사례별로 돌려주는 규약은 재지 않아 이번 결정에 넣지 않았다. 전역 변수는 runspace 사이에 새지 않았지만 환경
  변수는 35개 모두 샜다(PR 직전 리뷰가 짚은 뒤 프로브에 갈래를 더해 쟀다).
- **Mock 없이.** 시험 본문이 cmdlet과 같은 이름의 함수를 정의하면 떼어 낸 함수가 그 가짜를 부르고, 가짜가 받은 인자도
  나온다. Pester의 가장 큰 이점이 이 이음매로 된다.

## PR 직전 보안·버그·성능 축

`coderabbit auth status`가 `Seat: not assigned`라 CLI 축은 돌지 못했다. 그래서 커밋하고 origin/main을 합친 뒤 대체 둘을
나란히 돌렸다. `/security-review`의 커밋 목록(`origin/HEAD...`)은 이 브랜치의 커밋과 병합 커밋 둘뿐이었다.

- **`/security-review`.** 취약점이 없었다. 프로브는 손으로 돌리는 측정 스크립트라 신뢰 경계 밖의 입력이 없고, pwsh에
  넘기는 글은 모두 저장소의 상수이며 값은 JSON 환경 변수나 `AddArgument`로 넘긴다. 걸러 낼 후보가 없어 거짓 양성 필터
  단계는 돌리지 않았다.
- **`bug-perf-review`.** 6건이다(유효 5, 보류 1).
  - **고친 것.**
    - Minor: runspace로 묶을 때 환경 변수가 사례 사이로 샌다. 리뷰어가 손으로 본 것을 프로브의 `env-leaked` 갈래로
      다시 재서 35개 모두 새는 것을 봤고, ADR의 묶는 조건에 더했다.
    - Nit: 묶는 기준이 없었다. 이 파일의 시간이 지금의 두 배를 넘으면 정한다는 기준을 더했다.
    - Nit: pwsh가 없으면 프로브가 트레이스백으로 멈춘다. 시작에서 `shutil.which`로 본다.
  - **보류.** Nit: `_call`에 시간 제한이 없다. 이 PR이 고치는 시험이 없어, 대기 루프 시험을 들일 때 단다고 ADR의

  - 리뷰어가 유효로 낸 다섯 가운데 셋을 고쳤고, 하나(`_call`의 시간 제한)는 보류했고, 하나(두 칸 공백)는 오탐으로 봤다.

## PR

PR [#211](https://github.com/njh6803/agent-os/pull/211)(`fd5b923`까지). 연 직후 `@coderabbitai review`를 남겼다. 이 절과
회고를 더한 커밋은 봇 첫 회차를 반영할 때 함께 푸시한다.

- **CodeRabbit.** "Review rate limited"로 리뷰 없이 `pass`였다. 보안·버그 축은 PR 체크리스트에 적은 PR 직전 대체 둘이 맡는다.
- **claude-review 첫 회차.** Minor 둘과 Nit 하나를 냈고 모두 반영했다. PR 본문이 `_call`의 시간 제한을 "고쳤다"로 셌던
  것을 보류로 바로잡았고(일지도 같이), `test_open_session.py`의 `_call` 옆에 프로브가 그 이름들에 기댄다는 주석을 두었으며,
  ADR Consequences의 조건 셋을 목록으로 나눴다. `tests/` 영역이 늘어 #207의 새 규약대로 푸시 전에 PR 본문부터 고쳤다.
  반영 커밋은 `2fb97f6`이고 pre-commit의 검사가 모두 통과했다.
- **둘째 회차(`2fb97f6`).** CI가 모두 초록이었다. CodeRabbit은 다시 "Review rate limited"였다. claude-review는
  Critical·Major·Minor 0건이고 Nit 하나(ADR 첫 단락에 결정 문장이 늦게 나온다)를 냈다. 둘째 회차라 고치지 않고 PR
  코멘트에 보류 이유를 남겼다.
- **다시 합치기와 일지 번호.** 그 사이 main에 #210과 #205가 병합돼 PR이 `BEHIND`였다. `git merge origin/main`으로 충돌
  없이 합친 뒤의 `sibling_overlap.py`가 1로 끝났다. 이 일지(처음 이름 08)가 main의 최신 일지 10보다 이름순으로 앞서,
  다음 세션이 이름순 최신의 "다음"만 읽으면 이 일지를 지나친다. 출력의 "옮길 번호"대로 12로 옮기고 대기열 17·222 행과
  PR 본문의 옛 번호를 고쳤다. 커밋 메시지(`43467a5`·`fd5b923`·`2fb97f6`)의 옛 번호는 기록이라 두었다.
