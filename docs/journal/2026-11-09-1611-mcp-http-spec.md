## 측정

프로브 둘을 `.scratch/mcp-http/probes/`에 지었다(결과와 돌리는 법은 그 `README.md`). `http_close.py`는 픽스처 서버 `http_fixture_server.py`를 사례마다 새 프로세스로 띄우고 `tools/probe_kit.py`의 `Rounds`로 표지를 센다. Linux는 Docker(`python:3.12.10-slim-bookworm`, `--init`)에서 `linux.sh`로 돌렸다. `manifest_shape.py`는 워크트리에 `web/node_modules`가 없어 주 체크아웃의 것을 `--node-modules`로 줬다. 실행을 네 번 거듭하며 사례와 기록 칸을 더했고, 차례는 아래다.

- ADR 0049의 첫째 안(라이브러리 문맥 닫기를 `CancelScope(shield=True)`로 감싼다)은 `RuntimeError: Attempted to exit a cancel scope that isn't the current tasks's current cancel scope`로 끝났다. ADR이 적어 둔 대안(`terminate_on_close=False`로 라이브러리의 종료 요청을 끄고 프로브가 DELETE)을 같은 자리의 보호로 돌려도 같은 예외였다. 원인은 종료 요청이 아니라 보호의 자리였다.
- 문맥을 보호 없이 닫은 다음 문장에 보호를 두는 갈래(`deadline_shield_after`)는 그 문장이 돌지 않았다. 취소된 범위에서는 닫기의 `await`가 끝나며 취소가 다시 올라간다.
- 문맥 닫기를 `try`에, 보호를 `finally`에 두는 갈래(`deadline_shield_finally`)가 섰다. 종료 요청이 같은 세션 식별자로 닿고(200), `cancelled_caught`가 참이고, 예외가 새지 않는다. 답하지 않는 서버에서는 2초에 끊는다(`deadline_shield_finally_hang`).
- 401은 상태 코드 없는 `MCPError`였다. 응답 훅(`event_hooks`의 `response`)이 `POST 401 Unauthorized`와 `Mcp-Session-Id`를 받는 것을 확인해, 상태를 원인에 덧붙이는 결정과 세션 식별자를 응답 훅으로 받는 결정의 근거가 됐다. 쿼리 문자열은 예외 글에는 없고 `mcp.client.streamable_http`의 DEBUG 줄과 `httpx2`의 INFO 줄에는 실렸다.
- 마지막 실행에서 `httpcore2` 로거를 더해 토큰 값이 세 로거의 DEBUG 줄 어디에도 실리지 않는 것을 두 OS 33회차로 봤다. 두 OS 모두 33회차 측정, 측정 아님 0이었다. 매니페스트 프로브는 14회차 측정, 측정 아님 0이었다(Windows만. 모양은 OS를 가르지 않는다).
- 걸린 자리. 워크트리 가드가 heredoc(`cat > … <<'EOF'`)과 스크래치패드로의 `cd`를 거부해 스크립트는 Write로 쓰고 경로를 인자로 줬다. 프로브 독스트링이 ruff E501에 걸려 `tools/rewrap_comments.py`로 감았다. 측정 낱말 훅이 ADR 이력의 "쟀다" 세 줄을 짚어 같은 줄에 프로브 경로를 넣었다. 첫 로그 캡처에 `httpcore2`가 빠져 있어 더했다. pyright가 `.scratch` 프로브의 Unknown 타입과 닿지 않는 코드를 경고했으나 `.scratch`는 pyright의 범위 밖이라 두었다.

## 명세가 정한 것과 문서

명세는 `.scratch/mcp-http/spec.md`다. 넘겨받은 것 열아홉, 명세가 정한 것 열넷, 이력 하나, 거부한 안 열하나(서두에 센 수. 셀프 리뷰 반영 뒤 다시 센다).

- 닫기 보호의 자리는 `finally`이고 종료 요청은 어댑터가 응답 훅으로 받은 세션 식별자로 직접 보낸다. ADR 0049 결정 "닫기"의 문장("보호의 자리는 라이브러리 바깥이다. … 감쌀 수 있을 뿐이다")이 거짓이 되어 2026-11-09 이력 "닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다"를 쌓고 포인터를 달았다. 이력은 사용자 승인 전이다(작업 규약 5).
- 실패 문구의 주소는 쿼리 문자열과 조각을 뗀 것(원칙 V. 관리 API의 매니페스트 응답은 그대로). 2xx가 아닌 응답으로 실패하면 원인 끝에 ` (HTTP 401 Unauthorized)`처럼 상태를 덧붙인다. 설계가 묻지 않은 자리를 측정이 드러낸 것이라 ADR 이력의 "명세가 정한 것"에 함께 적었다(본문을 거짓으로 만들지 않아 포인터는 없다).
- 매니페스트는 호출 가능 판별자(`transport` 없음을 stdio로), `urlsplit`의 세 검사, 헤더 이름은 RFC 9110 토큰 문자, 변수 이름은 `^[A-Za-z0-9_]+$`, 거부 위치는 pydantic의 태그 경로(`server.http.command`), `command` 없음의 스토리 글은 그대로, `schema_version` `"1"`의 근거는 ADR 0008의 2026-09-21 이력.
- 접속은 변수 없음이 여럿이면 `; `로 잇고 값은 판정하지 않으며(빈 문자열도 그대로), 응답 훅이 세션 식별자와 마지막 오류 응답을 받는다.
- 이어받은 상태 셋. (1) 대기열 0518의 "세 번"은 넷이 맞다는 것은 다음 회고가 바로잡는다(이 일지에 적어 둔다). (2) 보류 넷은 명세의 "실패 문구"(쿼리 문자열과 시험 사례), "매니페스트"(`schema_version` 근거), Testing Decisions(실행 기한 초과의 결말), `CONTEXT.md`의 한 줄로 받았다. (3) 평문 http 허락 표지는 `.scratch/mcp-trust/plan.md`에 안(서버 항목의 `allow_plaintext_http = true` 같은 표지. 표지 없는 http 주소의 서버에 `[server.headers]`가 있으면 접속 전에 거부. 루프백 예외는 그 설계 인터뷰에서 묻는다)으로 적었다.
- 다른 문서. `CONTEXT.md` 원격 MCP 서버 항목에 `transport = "http"`가 streamable HTTP를 뜻한다는 한 줄. `.scratch/diag-bundle/plan.md`의 `**Blocked by:**`에 mcp-http를 더하고 넘긴 것(서버 하나를 여는 함수의 경계, 상태를 든 실패 문구로 토큰 불일치를 가른다)을 적었다. `.scratch/plan.md`는 `tools/plan_table.py`로 다시 만들었다.

이 세션이 스스로 고친 것. 명세 서두의 거부한 안 수를 열다섯에서 열하나로(본문의 "거부한 안:" 표시를 센 값). 명세 "닫기"의 걸리는 시간과 Further Notes의 닫힌 포트 시간, ADR 0049 이력의 시간을 마지막 실행의 값으로. ### 손으로 본 것(헤더 값에 쓸 수 없는 글자)

스크래치패드의 스크립트로 한 번 봤고 저장소 프로브로 남기지 않았다. 닫는 로컬 TCP 서버에 `httpx2.AsyncClient(headers={"Authorization": 값})`로 GET을 보냈다. `Bearer SECRET123\n`·`\r`·`\x00`은 `LocalProtocolError: Illegal header value b'<값 전체>'`로 거부되고 `__cause__`에도 같은 글이 든다. 비ASCII 글자(`é`, `가`)는 `UnicodeEncodeError`가 그 글자 하나와 자리를 싣는다. 탭은 통과한다. 연결이 닫히는 포트로만 보내면 헤더 검사 전에 연결 실패로 끝나 보이지 않는다(첫 시도가 그랬다). 그래서 명세 "접속"에 ASCII 인쇄 가능 글자(0x20~0x7e)와 탭이 아닌 글자가 든 값은 값 없이 거부한다고 적고(서두의 "값의 판정" 몫이라 자기 결정 수 열넷은 그대로다), 구현 티켓의 시험 사례에 끝에 개행이 붙은 값을 더했다. 명세 문장은 "쟀다"가 아니라 "손으로 본 것이다(프로브로 남기지 않았다)"로 적었다.

### 프로브를 다시 돌렸다

`http_close.py`를 Windows(`uv run`)와 Linux(`docker run … linux.sh`)에서 열두 사례 전체로 돌려 둘 다 측정 36회차, 측정 아님 0회차, 종료 코드 0이었다. `manifest_shape.py`는 Windows에서 측정 16회차, 측정 아님 0회차였다. 유예가 지난 `deadline_shield_finally_hang`의 세 회차(두 OS)도 `client_closed` 참, `client_close_seconds` 0.0이었다. README의 시간 범위(`normal_own_delete`, `deadline_shield_finally`, `…_hang`)와 명세의 "걸리는 시간"을 새 값으로 맞췄다.

### 수 다시 세기

명세 본문을 고쳤으므로 서두의 수를 다시 셌다. "거부한 안:" 표시는 12이고 이는 반영 전 HEAD와 같다(서두 문장의 인용 하나를 빼면 11). 이번에 거부한 안을 더하지 않았고 명세가 정한 것도 더하지 않아 19·14·2·11이 그대로다.
