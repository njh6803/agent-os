## 이어받은 것

선행 조건: 주 체크아웃이 main이고 깨끗했으며 `git fetch` 뒤 `origin/main`과 같았다(`b7d1382`). 원격 브랜치는 main 하나라 값 기반
마스킹의 ADR 이력 초안 세션, design-system 인터뷰, web-widget의 첫 티켓은 모두 열리지 않았다(`.scratch/web-widget/`에는
프로브만 있다). 세션 제목은 훅의 지시대로 브랜치 이름으로 바꿨다. PR #134의 claude-review 3회차 Nit 둘은 지시문이 적은 대로다
— 하나는 PR 본문으로 반영했고, `RunList`와 `EventItem`의 `runHref` 공용화는 셋째 자리가 생길 때로 보류.

## 맥락을 대신한 것

to-spec은 지금 대화를 합성하는 스킬인데 이 세션에는 설계 인터뷰의 대화가 없다(대기열 103). ADR 0023과 그것이 이력을 남긴 ADR
0009·0010·0011·0014·0015·0017, `plan.md`의 end-user-channel 행과 web-widget 행, 일지 2026-10-03-03과 2026-10-04-01, conversation
명세와 그 프로브 README를 읽었다. 코드는 공용 층(`auth.py`, `errors.py`, `routes.py`), `server.py`, `main.py`, 채널(`router.py`,
`runs.py`), core(`run.py`의 진입점 둘과 `_read_paused`, `ports.py`, `continuation.py`의 손상 판정), sdk(이벤트, 식별자, 컨텍스트),
관리 화면의 `RunDecision`, api-client의 `clients.ts`, 테스트의 사례 목록을 읽었다. 설치된 `fastapi.sse`와 Starlette CORS와 PyJWT의
원문도 읽었다.

코드를 읽다 찾은 것 셋이 명세에 들었다.

- **FastAPI는 SSE `id`를 실으려면 `ServerSentEvent`를 yield해야 하고 그 타입은 스트림 항목 타입에서 뺀다.** ADR 0023의 두 결정
  (프레임마다 `id`, 항목은 이름 있는 컴포넌트)이 그대로는 함께 서지 않았다. 측정으로 길을 찾았다(아래).
- **Starlette의 CORS 미들웨어는 앱 전체에 걸린다.** ADR 0011 이력은 preflight를 새 접두사에서만 통과시키라 했다. 접두사로 가르는
  ASGI 분기 하나로 풀렸다(아래).
- **요약 호출은 몸통(`_drive`) 밖에서 돈다.** 타임아웃의 자리를 몸통으로 적었다가 셀프 리뷰가 잡아 진입점으로 고쳤다(아래).

## 잰 것

선택지에 넣는 사실을 올리기 전에 확인했다(대기열 101). 다섯이고 판과 다시 돌리는 법은 `.scratch/end-user-channel/probes/README.md`다.

- **SSE `id`와 항목 스키마(`sse_id_frames.py`, `check_types.py`).** `ServerSentEvent`만 주해하면 `data: string`이고, 항목 유니온을
  주해하고 `ServerSentEvent`를 yield하면 pyright strict가 거부한다. pydantic `SkipJsonSchema`로 멤버를 더한 유니온을 주해하면 둘이
  함께 선다(pyright 0, 타입 우회 검사 0). 대가는 FastAPI의 정의 수집이 남기는 고아 컴포넌트 `ServerSentEvent` 하나다(pydantic
  단독은 남기지 않는다). 지금 계약은 37개가 모두 참조된다.
- **접두사 한정 CORS(`cors_scoped.py`).** 접두사 아래 preflight는 토큰 없이 200, 밖은 401, 접두사 아래 인증의 401과 라우트의 429에
  `Allow-Origin`·`Vary`·`Expose-Headers`(`Retry-After`)가 붙고, 허용 밖 출처에는 `Allow-Origin`이 없다.
- **클레임 규칙(`jwt_claims.py`).** PyJWT 2.14.0에서 `require`가 `iat`·`sub` 없음을, 라이브러리가 미래 `iat`를 거부하고, 수명은 소비
  지점이 세며, `kid`로 키를 고르고 없으면 차례로 시도한다. 사례 열넷이 기대와 같았고 RS256 검증 한 번은 약 0.23ms였다.
- **실행 타임아웃(`run_timeout.py`).** core 몸통 모양의 제너레이터 안에서 `anyio.fail_after`를 열면 실제 MCP 연결이 열린 채 yield를
  건넌 뒤에도 `TimeoutError`가 `run_failed`로 바뀌고 태스크 그룹이 깨지지 않는다. 소비자가 바깥에서 자르는 대조군은 결말이 없다.
  처음 1초로 돌렸을 때는 서버가 뜨기 전에 끊겨 연결 중의 취소를 잰 것이었고, 6초로 다시 쟀다.

## 물은 것

명세에 확정하기 전에 여덟을 두 묶음으로 물었다. 여섯은 추천안이었고 둘은 달랐다.

> 사용자(질문에 답): "기존 이음매만 넓힌다 (Recommended)", "필수 다섯, 최대 수명 10분, 여유 30초, kid 목록 (Recommended)",
> "발급자|sub, 구분자를 양쪽에서 금지 (Recommended)", "없음 → 손상 → 주체 → 열 에이전트 → 형식 1 → … (Recommended)"

> 사용자(질문에 답): "중간 (Recommended)", "실행 타임아웃을 들인다", "건너뛴다 (Recommended)", "최종 사용자 면에서 500도 404로 덮는다"

- 이음매는 새로 만들지 않고 여섯을 넓힌다. 토큰은 필수 클레임 다섯·수명 600초·여유 30초·`kid` 목록. 주체는 `발급자|sub`이고
  구분자를 사이트 파일 발급자와 OS 사용자 이름 양쪽에서 금지한다. 재개의 판정 순서는 주체가 형식 1 앞이다(형식 1이 손상 뒤로 간다).
  상한 기본값은 중간 묶음(요청 20,000자, 주체별 동시 2·시간당 60, 사이트별 20·1,000, 전역 50, 구독 4, 백로그 1,000 프레임).
- **추천과 달랐던 둘.** 걸린 실행이 동시 실행 칸을 붙잡는 열린 문제의 답으로 실행 타임아웃을 들인다 — ADR 0014가 범위 밖에 둔 것이라
  선택지에 "범위를 넘는다"고 적었는데 사용자가 골랐으므로 설계를 명세에 넣고 ADR 0014 이력 초안을 올렸다(기본 600초, `serve` 인자,
  core 진입점의 `fail_after`). 손상된 남의 트레이스는 최종 사용자 면에서 500도 404로 덮는다 — 자기 손상도 404가 되는 대가를 적고
  ADR 0023 이력 초안을 올렸다.

## 명세가 스스로 정한 것

스물셋이고 명세 서두에 모았다. PR에서 사용자가 본다. 가장 큰 넷: 프레임을 `SkipJsonSchema` 유니온으로 짓고 고아 컴포넌트 하나를
두는 것(지우는 후처리는 ADR 0014 이력의 논증으로 거부), CORS를 Starlette 미들웨어로 접두사 분기 뒤에 두는 것, 열 에이전트 목록의
판정을 core가 하는 것(`run()`·`resume()`의 집합 인자, 구독도 쓰는 자기 실행 읽기 함수), 면별 번역을 공용 표가 면의 열거를 받아 하고
최종 사용자 면의 404는 고정 문구 하나인 것.
