지시문의 "이어받을 상태"가 일지 39에 적히지 않은 것을 넘겼다. PR #226의 첫 회차는 CI가 모두 초록, claude-review는 지적
없음, CodeRabbit은 한도(Review rate limited)라 리뷰가 없었고, 그 PR의 보안·버그 축은 PR 체크리스트에 적은 PR 직전 대체
리뷰 둘이 대신했다. 그 뒤 병합(`65685b2`)했다. 프로브의 `mutate`·`time` 값은 PR 직전 리뷰를 반영하기 전의 판이고, 반영한
판으로는 `contract`와 시험 파일 전체만 다시 돌렸다.

## 한 일

- **규약 시험 먼저.** `test_open_session.py`에 서버의 규약을 재는 시험 아홉을 더했다. 서버의 수명은 본문의 `$PID`로 봐서
  시험이 서버의 비공개 이름에 기대지 않는다. 앞의 `_call`로 돌리니 셋이 기대한 까닭으로 빨갰다(PID가 매번 다름, 서버
  종료를 실패로 보지 않음, 경고에 `경고:` 머리가 붙고 정보 스트림이 숨음).
- **서버판.** `_LOAD`를 `_SERVER_SCRIPT`로, `_call`의 몸통을 모듈에 하나인 `_PwshServer`로 바꿨다. 프로브의 `ServerCall`에서
  주로 달라진 것은 pwsh가 없을 때의 `pytest.fail`을 기동에 옮긴 것, stdin 쓰기가 `OSError`면 서버를 한 번 새로 띄워 다시
  쓰는 것, 서버를 끝낼 때 stdin을 닫고 읽는 스레드가 EOF 뒤에 stdout을 닫는 것, 세션 범위 autouse 픽스처가 서버를 닫는
  것이다. 프로브에만 있던 계수기와 되돌림 스위치는 뺐다.
- **변이.** 새 표 `open_session_case_server_mutations.toml`의 여덟과 기존 표 셋의 38개가 모두 빨갰다. 기존 표의 "시간 제한
  없이 pwsh 를 기다린다"는 서버의 대기 줄을 가리키게 고쳤다.
- **프로브와 문서.** `pwsh_test_seam.py`의 독스트링과 README 행(per_call이 이제 서버 요청 하나를 잰다), `pwsh_case_server.py`의
  독스트링과 README 행(바꿔칠 사례마다 pwsh가 없다), ADR 0030 이력 "사례를 pwsh 서버 하나에 묶었다"를 썼다.
- **시간.** 셀프 리뷰를 반영한 뒤 시험 파일 전체 78개가 `-W error`로 15.11초였다(CPU는 재지 않았다). 앞의 판은 일지
  39의 프로브 `time` 회차(CPU 평균 48.3%)에서 67개에 62~75초였다. 부하가 같은지는 모른다.

## 판단

- 넘겨받은 셋 가운데 정보 스트림, 콘솔의 오류 쓰기, 네이티브 명령의 종료 코드는 앞의 이음매에 맞추지 않았다. 스크립트가
  쓰지 않고, 정보 스트림은 합쳐야 `Write-Host`의 차례가 지켜진다. 서버판의 규약으로 두고 시험 파일의 주석과 시험에 적었다.
- 서버의 정리는 처음에 모듈 범위 픽스처로 썼다. 두 축 리뷰가 명세(서버의 수명은 pytest 세션 하나)와 갈린다고 짚어 세션
  범위로 바꿨다. 프로브가 모듈을 pytest 밖에서 불러도 프로세스가 끝나면 stdin이 닫혀 서버가 끝난다.
- 셀프 리뷰의 나머지 반영: 깨진 stdin 닫기(Major), 시험 파일 주석에서 지웠던 `pwsh_case_server.py`의 이름 의존을 되살림,
  갈림을 셋이 아니라 다섯으로 셈, 서버의 기존 환경 변수를 바꾸거나 지운 갈래의 시험과 변이, `_pid`가 빈 글을 받지 않게,
  프로브 독스트링의 "지금의" 범위와 README 행의 결과. 남긴 것은 둘이다. `_server_stderr`가 서버의 stderr 꼬리 전체를 내
  앞 사례의 글이 섞일 수 있는 것은 실패 메시지의 정보가 늘 뿐이라 두었다. 시험 파일과 프로브의 서버가 두 벌인 것은
  프로브가 기록이라 두었다(ADR 이력에 적었다).

## 회고

후보 셋, 승인 0·기각 3·넘김 0. 대기열에 더한 행은 없다.

- **변수가 든 `for` 루프를 워크트리 가드가 거부했다.** 기각. `CLAUDE.md` 환경 함정이 이미 긴 입력을 파일로 써서 경로로
  넘기라고 적고, 그대로 스크립트 파일로 옮겨 한 번에 지나갔다.
- **스크래치패드로 `cd`하려던 것을 훅이 막았다.** 기각. 막는 훅(`hook_bash_cd_outside`)이 이미 잡았고 비용은 호출 하나였다.
- **실행 중인 세션 하나("CI 완료 자동 알림")의 제목이 브랜치와 맞지 않아 병합된 워크트리 열여덟이 정리되지 않았다.**
  기각. 판정 3이 의도한 동작이고, 풀려면 그 세션의 제목을 브랜치로 바꾸거나 사람이 승인하면 된다. 환경을 고칠 사건이
  아니다. 일지에만 남긴다.
