## 찾은 사실

- Design System 형식의 페이지 스크립트(아티팩트에 실린 `app.js`)를 Artifact 도구로 받아 읽었다. `tokens.json`은 계열마다 `{"tokens":[{name,value,usage}]}`이고 색에만 `themes`가 붙으며 별칭은 `"{other}"`다. 테마 8개, 색 600개까지다. 저장할 때 페이지가 `tokens.css`(첫 주석이 생성물 표시일 때만 덮어쓴다), `api/*.md`, `manifest.json`을 짓는다. 선택자는 `:root, [data-theme="<첫 테마>"]`와 나머지 `[data-theme="<id>"]`다.
- 같은 스크립트에서, 색인의 `"editing": "off"`는 페이지를 읽기 전용으로 하고 README 밖의 절을 숨긴다. 키를 지우면 켜지고, `source`는 남아도 배너(플래그 `design_system_clean_up_button`)를 띄울 뿐이다. 정리 버튼("Finish the migration")은 파일을 옮기지 않고 에이전트에게 요청만 보낸다. 웹 편집기는 토큰의 값·설명·더하기·지우기·이름 바꾸기(별칭과 README의 이름도 고친다)와 README, 다른 마크다운, 컴포넌트 README, 에셋·글꼴을 고친다. 테마를 더하는 화면은 없다. 저장은 약 800ms 디바운스의 자동 저장이고 `tokens.json`을 통째로 다시 쓰며, 충돌은 `ifMatch`와 토큰 단위의 3-way merge로 푼다. 파일 트리 모드에서 사람이 저장해도 색인의 `lastChange`는 바뀌지 않는다.
- 미리보기 프레임은 메모리에서 지은 토큰 CSS와 `bundle.css`를 싣고 `<html>`에 `data-theme`/`data-mode`를 건다. 우리 `_ds_bundle.css`가 토큰을 다시 선언하므로 웹 편집이 컴포넌트 카드에 보이지 않을 가능성이 크다(어림).
- 우리 아티팩트 색인은 `editing:"off"`, `source.app:"claude-design"`, `lastChange.via:"agent-os 부분 main@c41adad"`이고 `tokens.json`이 없다(Artifact 도구로 받아 봤다).
- `theme.css`(654줄)는 테마 넷(녹청 기본, 군청, 자초, 쪽빛) × 모드 둘, 밀도 둘, 미디어 사본 블록을 갖고, 토큰마다의 주석은 없고 블록 주석만 있다(읽었다). 낼 토큰은 112개다. 한 벌마다 색 98(원색 68 = gray 13 + 다섯 색 × 11, 반투명 7, 쓰임새 23)과 모든 벌이 같은 글자 크기 3, 간격 7, 모서리 4다(읽어 셌다). 인터뷰의 선택지에는 "약 120개(어림)"로 적었고 합의 요약에서 바로잡았다.
- 판정 스토리 Matrix는 여덟 벌 × 짝 43개의 명암비를 hex 형식으로만 받아 잰다. 사진 비교는 Docker에서 기본 테마만, 오차 0으로 찍고 정답은 422장이다(`.claude/rules/web-design.md`와 스토리를 읽었다).
- `/design-sync`는 Claude Code의 번들 스킬(Claude Design용)이고, 2026-10-16부터 스킬은 부르지 않고 빌드만 빌려 쓰며 올리기는 Claude Code가 Artifact 도구로 한다(`.design-sync/NOTES.md` 36~63줄, `docs/agents/issue-tracker.md` 37~44줄을 읽었다).
- 아티팩트의 판 id는 사람이 고치지 않아도 오른다. 형식 쪽 파일이 바뀌며 `1792491791-94a2`에서 `1792564314-af13`으로 올랐고 `project/` 파일은 크기가 그대로였다. 파일 목록에는 경로, MIME, 바이트만 있고, 읽기 결과의 머리에 판, 바이트, MIME, sha256이 나온다(서브에이전트가 Artifact 도구로 손으로 봤다, 2026-10-21 06:32~06:37Z).
- 웹 저장은 지켜보는 세션에 턴도 알림도 일으키지 않는다. 댓글에서 Claude를 부르면 자동 응답이 켜진 지켜보는 세션이 깨어난다(ArtifactComments 도구 설명을 읽었다).
- 아침 보고 예약 세션 다섯 회차는 회차마다 $1.18~1.82였고, 첫 호출만으로 opus 약 $0.32가 들었다. 예약 세션의 도구 목록에 Artifact가 있지만 부른 회차는 없고, PushNotification은 원격 제어가 꺼져 휴대폰에 가지 않았다. 그 주의 사용 한도는 81%를 썼다(서브에이전트가 세션 스크래치패드의 스크립트로 손으로 셌다, 커밋하지 않았다).
- 예약 작업은 앱 폴더(`~/.claude/scheduled-tasks/`)에 얇은 껍데기만 두고 지시문은 저장소의 `tools/morning_tasks/`에서 읽는다(`daily-morning-report/SKILL.md`를 읽었다). 앞 라운드의 선택지 설명("예약 작업의 절차 파일은 저장소 밖이라 PR로 리뷰되지 않고")은 틀렸고, 다음 라운드의 본문에서 바로잡았다.
- `/ui-design` 스킬은 아직 없다(`.claude/skills/`를 봤다). ADR 0033의 2026-10-20 이력이 다음 PR에서 짓기로 했다. `implement` 스킬은 `disable-model-invocation: true`다(읽었다). 쓰는 순간 한 번 알리는 계기 훅의 선례는 `tools/hook_scratch_probe_rule.py`다(읽었다).
- `theme.css`는 design-system이 처음 만들었고(#156), 지금의 테마·색·밀도는 design-refresh의 티켓 03·04가 바꿨다(#216, #221. `git log`와 `git show --name-only`로 봤다).

### 합의 요약

확인받은 요약(에이전트가 쓴 글, 글자 그대로):

**1. 아티팩트에 내는 것** (`tokens.json`)
- `web/tools`에 TypeScript 스크립트를 두고, 이 스크립트가 `theme.css`를 읽어 `tokens.json`을 씁니다. 거꾸로 방향을 비교할 때도 같은 스크립트를 쓰고, 테스트는 `pnpm -C web verify`에 들어갑니다. 컴포넌트 카드는 지금처럼 Claude Design용 번들 스킬의 빌드를 빌려 짓습니다. 그 빌드를 걷어 낼지는 plan.md에 따로 행을 엽니다.
- 테마는 테마 넷 × 라이트·다크로 여덟 벌이고, 녹청 라이트가 첫째입니다.
- 범위는 원색 68개(테마마다), 반투명 7개, 쓰임새 23개(원색의 별칭), 글자 크기 3개, 간격 7개, 모서리 4개입니다. **바로잡기: 앞에서 "약 120개(어림)"라고 적었는데, 세어 보니 112개입니다.** 밀도와 이름 있는 치수는 넣지 않습니다.
- 토큰마다의 설명은 `theme.css`의 그 줄 주석에 둡니다. 원색은 녹청 블록에, 쓰임새는 라이트 대응 블록에 둡니다.

**2. 웹에서 고친 것을 코드로 옮기는 규칙**
- 값만 바꾼 고침(원색, 반투명, 글자 크기, 간격, 모서리)은 스크립트가 `theme.css`의 해당 줄로 자동으로 옮깁니다. 사본 블록도 함께 고칩니다. hex가 아닌 값은 hex로 바꾸고, 바꾼 값을 보고에 적습니다. 크기를 바꾸면 스토리의 단언과 사진도 같은 PR에서 고칩니다.
- 별칭 바꾸기, 토큰 더하기·지우기, 이름 바꾸기는 자동으로 옮기지 않고 멈춰서 묻습니다. 명암비 검사에 걸리면 걸린 토큰 짝과 실제 명암비, 통과하는 가장 가까운 값을 보여 주고 멈춥니다. 사람은 "제안 값으로 들인다", "그 토큰만 코드 값으로 되돌린다", "웹에서 다시 고친다" 가운데 고릅니다.
- 마지막으로 올린 뒤에 코드와 웹이 같은 토큰을 둘 다 바꿨으면 멈추고 묻습니다. 이 항목은 위 규칙에서 이어지는 것으로 보고 제가 더했습니다.
- 토큰이 아닌 파일(README, 다른 문서, 에셋)을 고친 것은 찾아서 보여 주고, "저장소 파일에 옮긴다"와 "버린다" 가운데 고르게 합니다.

**3. 웹에서 고친 것을 찾는 때**
- 올리기의 마지막 호출이, 보낸 파일마다의 sha256을 아티팩트의 `project/` 아래 기록 파일에 적어 둡니다. 확인할 때는 편집될 수 있는 파일을 읽습니다. 읽은 결과 머리에 sha256이 나오므로, 그 값을 기록과 맞대 보기만 하면 됩니다.
- **기본은 사람이 알리는 것입니다.** "디자인 시스템을 고쳤다"고 말하거나 `/sync-design-system`을 치면, 그 세션이 `.scratch/design-reverse-sync/issues/`에 티켓을 쓰고 들인 뒤 PR, 병합, 다시 올리기까지 합니다. 브랜치는 `feature/NN-…`입니다.
- **안전망은 셋입니다.** ① 세션이 `web/packages/ui`나 `web/apps/*` 아래 파일을 처음 고치려 할 때, 계기 훅이 그 세션에 한 번 확인하라고 알립니다. ② `/ui-design`은 그리기 전에 확인합니다. ③ 올리기 직전에 확인합니다. 화면 작업 중에 고친 것을 찾으면 멈추고 묻습니다. 먼저 들이기로 하면 그 일은 자기 티켓과 PR로 따로 병합하고, 화면 작업은 병합 뒤 main을 합쳐서 이어 갑니다.
- 예약 작업이나 감시 세션은 두지 않습니다.

**4. 절차와 편집 켜기**
- 흩어져 있던 올리기 절차를 새 프로젝트 스킬 `/sync-design-system`으로 묶습니다. 첫 단계에서 웹 고침을 확인합니다.
- `/ui-design`은 아직 없고 다음 PR이 만듭니다. 그래서 "그리기 전 확인"은 두 PR 가운데 나중에 들어가는 쪽이 넣습니다.
- 편집은 색인의 `editing` 키만 지워서 켭니다. `source`는 남기고, 정리 배너는 누르지 않습니다. 키를 지우는 것은 `tokens.json` 올리기, 확인 단계, 계기 훅, 스킬이 모두 들어온 뒤의 마지막 단계입니다.

**바로잡기: 티켓 폴더의 근거.** 앞 화면에서 `.scratch/design-reverse-sync/issues/`가 "ADR 0037의 '그 동작을 만든 기능 폴더' 규칙과 맞다"고 적었는데, 이는 정확하지 않았습니다. ## 인계 (커밋 뒤)

- 커밋을 친 뒤 `hook_handoff`가 세션 컨텍스트 271,658 토큰, 경계 `커밋 뒤`로 인계를 지시했다. `next-session` "인계할 때" 1의 인계하지 않는 때 다섯에 들지 않는다. 커밋이 성공했고, 요청 범위는 PR과 병합까지이고, 이 세션의 지시문의 이어받을 상태는 `인계: 셀프 리뷰 직전`이라 경계가 다르고, 이 일지에 `인계 못함` 줄이 없고, `get_session`의 `self`에 `parentSessionId`가 없다.

## 이어받은 세션 (커밋 뒤, 푸시 전)

지시문(이어받을 상태: 인계: 커밋 뒤)으로 연 새 세션이 제목을 `docs/design-reverse-sync`로 바꾸고 `EnterWorktree(path)`로 이 워크트리에 들어왔다. 시작 프롬프트는 `/grill-with-docs`이지만 설계 인터뷰는 끝났고 "다음 단계"가 PR 반영·병합이라, 스킬을 따르되 인터뷰는 다시 열지 않고 푸시와 `next-session` 순서 1의 2(봇 회차)부터 이었다. 사용자 프롬프트는 지시문 하나뿐이다.

- 시작할 때 `git fetch origin` 뒤 `HEAD..origin/main`이 비어 있어 main이 더 앞서지 않았다. 푸시하지 않은 커밋은 병합 커밋 `d497e28b`와 일지 이동 `f61852d1`이고, PR #341은 원격 브랜치가 병합 커밋을 몰라 `BEHIND`였다. 이 절과 앞 "인계 (커밋 뒤)" 절은 한 커밋에 실어 푸시한다(일지만 따로 푸시하면 claude-review가 한 번 더 돈다).

## 다음

기능 design-reverse-sync는 설계가 끝났고 `.scratch/design-reverse-sync/`에 `spec.md`가 없는 단계다. 결정표대로 다음은 명세(`/to-spec`)이고, 명세가 정할 것은 ADR 0025 2026-10-21 이력의 "명세가 정할 것" (1)~(6)과 "재지 못한 것"이다. PR 직전 리뷰가 넘긴 밀 주장 가운데 저장소 밖 원문이라 대 보지 못한 셋(형식 설명의 테마·색 한도와 "kept, no UI", CronCreate의 7일 만료)은 명세가 아티팩트 형식 설명을 다시 읽을 때 대 본다. 또 ADR 0025 2026-10-21 이력의 한 글머리표가 천 자를 넘는 항목("옮기는 규칙", "명세가 정할 것")은 명세로 옮기며 항목 하나씩 나눠 쓴다(PR 봇의 Nit을 보류한 일이고 이력의 글은 바꾸지 않는다). 둘째 회차에서 보류한 둘도 명세 단계의 일이다. 명세가 정할 것 (1)~(6)의 확정 결과는 ADR 0025에 되쓰지 않고 `spec.md`에만 두며, ADR 0036 본문에 계기 훅이 문턱을 거치지 않는다는 예외를 한 줄로 옮기는 것은 훅이 실제로 들어오는 구현 때 본다.
