(1) 동기와 수치. 동기는 컨텍스트가 아니라 나란히 도는 브랜치의 병합 충돌과 번호 충돌이다. 2026-10-01 이후 main 커밋 355개 가운데 대기열을 고친 것이 298개, plan.md가 89개, 헌법 README가 62개다(git log --since로 셌다). 10~11월 토큰 장부에서 대기열은 Read 글자의 1.1%(1회 평균 2,101자)뿐이었다. 대기열 550행 가운데 417행(283,414자)이 닫힌 행이다. (2) 범위. 일지·harness 티켓·ADR은 이미 항목마다 파일 하나라 글자 충돌은 없고 번호 겹침만 남는다(지금은 tools/sibling_overlap.py가 잡는다). 대기열을 항목 파일로 나누면 대기열도 같은 상태가 되므로, 번호 정책은 넷에 공통인 결정 하나다. plan.md의 기능 행 상태 칸은 티켓 Status에서 나오는 값이라(tests/test_plan_status.py가 대조한다, harness 044) 손으로 고치지 않고 만들어 내는 안도 본다. 헌법 README의 판 번호와 이력도 같은 모양의 문제인지 본다. (3) 번호 대신 제목. 문제는 번호 자체가 아니라 나란히 도는 브랜치가 순번 하나를 함께 나눠 쓰는 것이다. 앞 세션의 추천은 대기열 항목과 harness 티켓은 제목(slug), 일지는 날짜+제목(순번 NN 빼기), ADR은 번호 유지다. 파일 이름에는 이미 제목이 있다(2026-11-05-04-mutate-check-marker-quality.md, 044-plan-status-matches-tickets-test.md). 견줄 값은 넷이다. 인용이 길어진다("대기열 NNN" 인용이 저장소에 적어도 5,111개, 살아 있는 문서에 662개). 한번 정한 제목은 바꾸지 않는 규칙이 필요하다. 옛 항목은 번호로 남아 섞인다. sibling_overlap, 커밋 검사(브랜치 = 티켓 파일 이름), queue_open_rows, 커밋 메시지의 "(harness NNN)" 꼴을 고쳐야 한다. 같은 제목이 겹치면 git이 병합 때 "양쪽에서 더함" 충돌로 알린다. (4) 노션. 원천을 노션으로 옮기는 안은 추천하지 않았다. 검사(pre-commit의 check_ticket, CI의 티켓 done 확인, pytest의 test_plan_status, sibling_overlap, queue_open_rows, 일지 훅)는 Claude 세션 밖에서 돌아 MCP를 쓸 수 없고 노션 API 토큰을 요구하게 된다. 노션이 응답하지 않으면 시험이 돌지 못한다(원칙 II). 검사를 스킬로 옮기면 강제력이 없다(plan.md 상태 규약이 문서에만 있어 세 번 어겨졌다, harness 044). 항목 닫기와 티켓 done이 PR과 함께 반영되지 않는다. 대신 선택지 둘을 넣는다. 하나는 원천을 git에 두고 열린 대기열 항목과 기능 상태를 노션 읽기 전용 보기로 만들어 내는 것이다. 토큰을 두지 않고 앱 세션(아침 보고 예약 작업 등)이 노션 MCP로 쓰게 한다. 갱신 때는 병합 직후(merge.md 단계에서 노션 MCP 호출)와 예약 작업의 전체 재생성을 함께 두는 것이 앞 세션의 추천이고, 보기는 origin/main 기준으로 만들며 작업 중인 브랜치의 티켓 상태는 반영하지 않는다. 다른 하나는 "지금 어느 세션이 어느 항목을 맡았나"만 브랜치 밖의 라이브 저장소(노션, 또는 이 PC의 git 밖 공유 파일)에 두는 것이다. 지금은 next-session이 세션 기록 검색으로 이것을 우회하고, 두 세션이 27초 사이에 같은 항목을 맡은 일이 있었다(대기열 283). (5) 고르지 않은 안. 외부 저장소를 원천으로 두는 안(위 4)과 git의 merge=union이다. merge=union은 기존 행을 고치면(취소선, 회차) 옛 판과 새 판이 함께 남고 GitHub 병합에는 적용되지 않는다. 그보다 앞서 사용자는 닫힌 행만 별도 파일로 옮기는 안에 "지금은 두기"라고 답했다. 위의 추천은 모두 앞 세션의 것이고 사용자가 정한 것이 아니다. (6) 이 지시문은 같은 기능으로 먼저 연 세션(docs/retro-queue-per-item)의 범위를 넓힌 판이다. 그 세션에 붙여 넣었으면 하던 인터뷰를 이어 가며 넓힌 범위를 다음 라운드에 더한다
> 확인할 선행 조건: 회차 3 기준을 쓰는 자리(CLAUDE.md 교정 루프, ADR 0036, retro 4단계, next-session 결정표, tools/queue_open_rows.py 등)와, 대기열·번호·plan.md를 읽거나 쓰는 도구·훅·스킬을 저장소 전체에서 다 세지 않았다. 옛 번호 인용이 새 구조에서 어떻게 풀리는지 보지 않았다. 아침 보고 예약 작업 세션에 노션 연결이 있는지 확인하지 않았다
