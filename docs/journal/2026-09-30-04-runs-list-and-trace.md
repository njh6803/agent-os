## 잰 것

- **SWR 2.5.1의 무한 목록(설치본 `swr/dist/infinite/index.mjs`를 읽었다).** 한 fetcher가 쪽을 차례로 돌며 쪽마다
  `getKey(i, 앞 쪽)`으로 키를 짓는다. 인자 없는 `mutate()`는 `_i: true`를 두어 본 쪽을 모두 다시 읽는다. 값을 넘긴
  `mutate(data)`와 `setSize`는 `_i: false`라 첫 쪽(`revalidateFirstPage`)과 캐시가 없거나 바뀐 쪽만 읽는다. 포커스도
  `_i`가 없어 같다. 첫 쪽의 커서가 바뀌면 둘째 쪽의 키도 바뀌어 캐시가 없으니 읽힌다. 그래서 커서가 바뀌는 테스트는
  본 쪽을 모두 읽는 것과 첫 쪽과 바뀐 쪽만 읽는 것을 가르지 못한다. 커서가 그대로인 둘째 쪽의 상태가 바뀌는 테스트를 새로 고침과
  포커스에 하나씩 두어 갈랐다. `revalidateAll`은 쪽마다 읽을지를 가르는 식의 첫 항이라 켜면 모든 다시 읽기가 본 쪽을 모두
  읽는다.
- **더 보기는 첫 쪽도 다시 읽는다.** 처음 쓴 테스트가 요청의 열을 `[첫 쪽, 둘째 쪽]`으로 적었다가 설치본을 읽고 "커서를 실은
  요청은 하나"로 고쳤다. `revalidateAll`을 켠 뒤로는 본 쪽을 모두 다시 읽는다. 명세의 새로 고침 절에 주석을 달았다.
- **openapi-fetch 0.17의 질의.** 값이 `null`이나 `undefined`인 질의는 싣지 않는다(설치본 `index.mjs` 405행, 질의
  직렬화의 `continue`). 그래서 "전부"는 `status`를 null로 넘긴다. 페이지 테스트가 질의에 `status`가 없는 것을 본다.
- **`Object.entries`와 이벤트 유니온.** `RunDetail`이 이벤트 유니온에 `Object.entries`를 부르는데 `strictTypeChecked`의
  `no-unsafe-*`가 조용했다. 까닭(어느 오버로드가 골라지는지)은 재지 않았다. ESLint가 새 파일을 실제로 봤는지는 JSON 출력의
  파일 목록으로 확인했다.
