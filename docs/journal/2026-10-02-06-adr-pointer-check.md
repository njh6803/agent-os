답했다. 주 체크아웃은 워크트리 가드가 `git -C`를 거부해 이 세션이 당기지 못했다.

## 자리를 정한 것

- **검사의 자리.** 판정은 `tools/check_adr_pointers.py`, 테스트는 `tests/tools/test_check_adr_pointers.py`다. 사례 테스트,
  CLI를 subprocess로 부르는 테스트(`.claude/rules/tests.md`), 이 저장소가 지금 통과하는지 재는 저장소 상태 테스트를
  둔다. pre-commit 훅과 CI 단계는 더하지 않았다. pytest가 이미 게이트라 새 게이트가 아니다(행이 "ADR 불필요"로 적은
  이유).
- **프로브와 달라진 판정.** 같은 판정을 옮긴 것이 아니다.
  - 이력 절을 줄마다 추적하는 도우미(`_lines_with_section`) 하나로 묶었다. 프로브는 이력 제목을 모으는 곳과 포인터
    위치를 보는 곳이 따로 절을 추적했고, 포인터 위치는 `## 이력` 줄부터 파일 끝까지를 이력으로 봤다. 새 검사의 이력
    절은 제목이 정확히 `## 이력`인 절이고 다음 `##` 제목에서 끝난다. 지금 ADR은 모두 `## 이력`이 마지막 절이라 결과가
    같다.
  - 수를 세지 않는다. 대신 ADR 파일이 하나도 없으면 실패한다(빈 범위의 초록을 막는다).
  - 번호가 겹친 ADR을 모두 판정하고 겹침을 알린다. 프로브는 파일마다 돌았고, 옮긴 첫 판은 번호를 키로 덮어써 한쪽을
    건너뛰었다(셀프 리뷰가 잡았다).
  - 펜스 안의 줄과 바로 앞이 백틱인 `(바뀜:`(코드 스팬으로 적은 모양의 예시)은 코드로 본다. 빈 포인터 `(바뀜: )`는
    모양이 틀린 것으로 센다.
- **지운 것.** 프로브 `.scratch/harness/probes/adr_pointers.py`를 지웠다. 일지 05가 그 프로브로 낸 수를 근거로 드므로
  프로브 README 행은 지웠다는 표시와 병합 커밋의 마지막 판(`git show 43f7148:…`), 위의 차이로 남겼다.
- **함께 고친 것.** `.claude/rules/adr.md`의 안내 줄을 검사로 바꾸고 포인터의 낱말 사이 공백이 하나라는 것을 적었다.
  KICKOFF의 복사 목록에 ADR 규약과 검사를 더했다. 같은 문단의 "검사 여섯"은 이 검사로 일곱이 되므로 대기열 96의
  교훈대로 수를 지웠다.

## 잰 것

- **원칙 II.** 테스트를 먼저 썼고 모듈이 없어 수집 오류(`ModuleNotFoundError`)로 빨갰다. 구현 뒤 하나가 빨갰는데,
  이력 절 안의 포인터를 붙인 픽스처의 줄 번호를 내가 12로 잘못 셌다(실제 11). 구현이 아니라 방금 쓴 기대값의 셈이
  틀려 기대값을 고쳤다. 셀프 리뷰 뒤에 더한 동작(번호 겹침, 빈 디렉터리, 펜스, 코드 스팬)도 테스트를 먼저 더해 넷이
  빨간 것을 보고 고쳤다.
- **변이**(`.scratch/harness/probes/adr_pointer_check_mutations.toml`). 스물하나가 모두 기대대로 빨갰다. 첫 판(열하나)의
  "개정 이력 절은 이력이 아니다" 변이 하나는 초록이었다. 절 단위로 추적하면 0006의 Consequences는 어느 쪽이든 다시
  본문이라 그 구분이 결과를 바꾸지 않았다. 프로브 독스트링의 0006 단서는 내 첫 스크래치 판이 `## 개정 이력`도 이력으로
  보던 때의 것이다. 이력 절의 경계를 둘(제목이 정확히 `## 이력`, 다음 `##`에서 끝남)로 나눠 한 테스트가 둘을 재게 했다.
  셀프 리뷰 뒤에 프로브 첫 판의 버그 모양(`(바뀜: ADR NNNN)`)과 한 줄의 여러 포인터, 새 동작 넷의 변이를 더했다.
- **저장소 상태.** `uv run python tools/check_adr_pointers.py`는 출력 없이 0으로 끝났다. 검사는 수를 세지 않는다.
