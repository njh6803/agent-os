## 이 티켓이 정한 다섯

일지 02의 "다음"이 01에 넘긴 것이다. 전부 티켓 파일 끝에도 적었다.

1. **포트 메서드 둘의 이름과 반환 타입.** `read_disabled() -> frozenset[PluginKey]`, `write_enabled(kind, name, enabled) -> WriteOutcome`.
   `PluginKey(kind, name)`은 켜고 끄는 키다 — 매니페스트가 아니라 이것이 키인 이유는 매니페스트가 읽히지 않는 플러그인도 끌 수
   있어야 해서다. `WriteOutcome = Literal["applied", "absent"]`는 부재를 값으로 말한다(ADR 0012 이력). `applied`는 요청한 켜짐이
   지금 상태라는 뜻이지 파일을 건드렸다는 뜻이 아니다. `bool`은 `if not write_enabled(...)`가 실패로 읽혀서, `Absent`를 던지는
   것은 포트의 약속과 어긋나서 택하지 않았다.
2. **계약 이름(domain-modeling).** 읽히는 행 `Plugin`, 표지 행 `PluginPlaceholder`, 유니온 `PluginRow`(기존 이름), 본문 `SetEnabled`,
   `operation_id` `set_plugin_enabled`. HTTP의 `UnreadableManifest`는 사라진다. 판정은 이렇다 — 표지 행이 `enabled`를 얻으면 그
   이름은 "매니페스트가 켜짐을 가진다"고 읽혀 용어집의 "읽을 수 없는 매니페스트"(종류·이름·이유)와 스토리 10(켜짐이 매니페스트의
   필드처럼 보이지 않기를)에 어긋난다. 용어집의 표지(Placeholder)로 이름 짓고, "깨진 플러그인"을 피하라는 항목 때문에
   `UnreadablePlugin`은 쓰지 않았다. core의 `UnreadableManifest`와 용어집은 그대로다.
3. **재시도 상한.** 1·2·4·8·16ms 그대로. 실제 어댑터로 다시 쟀다 — 읽기 스레드와 쓰기 스레드가 3초 동안 쉬지 않고 부딪혀 읽기
   9736번 실패 0(재시도 한 번 426, 두 번 24), 쓰기 670번 실패 1(다섯 단계를 다 쓴 것 7). 재시도를 끄면 읽기 406/9643, 쓰기
   750/2147 실패. ADR 0017의 2026-09-27 첫 이력에 한 줄 더했다. 프로브는 스크래치패드다(대기열 29의 8회차).
4. **PUT `.../calc/enabled%0A`.** 실제 변환기로 재니 이름 `calc`로 맞아 204다. 포트에 닿는 이름이 패턴을 지나 루트를 벗어나지 않으므로
   테스트로 고정하고 두었다.
5. **ADR 0014 이력의 "네 자리".** 여덟이었다는 한 줄을 더했다. 글자 그대로 여섯, 같은 뜻의 다른 말 둘.

## 어댑터와 윈도우 경합

- 운영자 파일의 손상은 TOML을 읽은 느슨한 값을 pydantic 모델(`_OperatorFile`, `extra="forbid"`, `Literal["1"]`, 패턴 `Annotated`)이
  좁힌다. 원칙 III의 첫 선례가 되지 않게 손으로 좁히는 자리가 없다.
- 실핸들 테스트 넷(스레드·프로세스 × 교체·읽기)은 skip하지 않는다. 윈도우에서는 재시도를 실제로 지나고(재시도를 끄면 넷 다 빨강),
  리눅스 러너에서는 같은 단언이 "열린 채 읽는 쪽이 있어도 교체가 막히지 않는다"와 "교체 도중에도 읽기는 완전한 집합 하나를 본다"를
  잰다.
- **커밋 직전 한 번 빨개졌다.** 스레드 교체 중 읽기 테스트다. 원인은 테스트의 교체 스레드가 쉬지 않고 `os.replace`만 돌아 읽기
  여섯 시도가 전부 교체 창에 걸릴 만큼 잦았던 것이다. ADR의 실측과 내 프로브는 둘 다 쓰기 쪽이 실제 어댑터(읽고 렌더링하고 교체)였다.
  교체 쪽을 실제 어댑터로 바꿔 측정 조건과 맞추자 15회 연속 초록이었고, 재시도를 끄면 여전히 빨갛다. 상한을 넘긴 쓰기는 세기만
  하고 단언하지 않는다 — ADR 0017이 받아들인 것이다. 교훈은 "경합 테스트의 상대편은 측정 조건과 같은 것"인데 1회차라 그 테스트
  위의 주석과 여기에만 둔다.
- PUT을 `def`로 바꾸면 동시 PUT 테스트가 빨개진다. 가짜의 쓰기가 디스크 시간을 들이는 이유다(채널의 `disk_seconds` 선례).
