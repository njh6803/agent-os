## 출력 스타일의 한자어 조항을 좁혔다 (저장소 밖)

사용자의 답 "3. 흔히 쓰는 한자어로"에 따라 사용자 폴더의 출력 스타일 파일(`fluent-korean-explanatory.md`) "구 단위" 2번의 한 문장을 고쳤다. 저장소 밖의 파일이라 이 PR의 변경에는 들지 않는다.

- 전: "따라서 맥락에 적합한 한자어를 적극적으로 활용하고, …"
- 후: "따라서 맥락에 적합하면서 사람이 흔히 쓰는 한자어를 적극적으로 활용하고, …"

새 세션부터 실린다(이 세션의 시스템 프롬프트에는 옛 문장이 그대로 있는 것을 손으로 봤다). 고친 조항이 새 세션에서 그대로 지켜지는지는 재지 않았다. 앞 일지의 "출력 스타일의 그 조항을 … 좁힐지는 사용자가 정할 일이다"와 "다음"의 같은 줄은 이 답으로 닫혔다. 앞 일지는 기록이라 고치지 않는다.

**rag-engine.** 사용자가 이 변경을 rag-engine에도 전해야 하는지 물었다. 파일은 옮길 것이 없다. rag-engine(`C:\project\rag-engine\.claude`)에는 프로젝트 출력 스타일 사본이 없고(Glob 0건) 프로젝트 설정에 `outputStyle` 줄도 없어서(Grep 0건), 이 PC에서 여는 rag-engine 세션은 같은 사용자 파일을 읽는다고 본다(사용자 설정 파일은 열어 보지 않았다. 다른 PC는 보지 못했다). 낡은 것은 앞 일지에 실은 rag-engine용 지시문의 1-4절("그 조항을 좁힐지는 사용자가 정할 일이라 …")이라, 그 절을 갈아 끼울 문단과 이미 넘겼을 때 덧붙일 글을 사용자에게 코드 블록으로 냈다. 둘 다 rag-engine에서 돌려 보지 않았다고 함께 적었다.

## 마무리 보고의 잘못과 승인된 새 이름 둘의 겹침

앞 마무리 보고의 "정하실 것 1"은 두 가지를 한 항목으로 섞어 적었다. 여덟 이름(주체, 고지, 보증 모드, 교환, 제품 판, 저자, 상한, 표지)은 사용자가 2026-11-17에 새 이름을 골라 승인한 일이고(대기열 `glossary-plain-names-left`), 마흔아홉 후보는 사용자가 고른 적이 없는 후보다(앞 일지 "넷째 선택 화면"의 끝). 선택 화면의 질문 문장에서 이를 바로잡았다.

여덟의 첫 이름을 바꾸기 전에 새 이름이 저장소에서 이미 쓰이는지 훑었고(세션 스크래치 `new_name_clash.py`, 손으로 읽었다) 둘이 겹쳤다.

- **로그인 방식**(보증 모드의 새 이름). 이미 "로그인하는 방법"의 뜻으로 쓰인다. ADR 0059(8·12·45·58행. 12행은 결정 제목 "로그인 방식"이다), ADR 0046(181행), ADR 0064(8·68행), 기능 계획 넷(`portal-ldap-login` 1·5행, `portal-login-admin` 5행, `portal-admin` 32행, `portal-login` 6행), 그 제목에서 만들어지는 `.scratch/plan.md` 87행, 프로브 `portal-login/probes/README.md` 24행이다(Grep으로 줄마다 앞뒤 70자를 읽었다).
- **요청자**(주체의 새 이름). 용어집의 다른 용어 "요청한 계정"이 피할 말로 들고 있다(`CONTEXT.md` 431행). "요청한 계정"은 "결정한 계정"(599행)과 짝이고, 값은 로그인한 운영자 계정이 일으키거나 이어 간 실행의 시작 이벤트에 남는다(ADR 0063 8·17행을 읽었다).
- 나머지 새 이름. 이용 안내, 문답, 플러그인 개발자는 일지 밖에서 쓰인 곳이 없었다. 릴리스와 자리 표시는 이미 같은 뜻으로 쓰인다. 제한(상한의 새 이름)은 훑지 않았다.

## 후보 마흔아홉을 다듬었다

앞 일지 "넷째 선택 화면" 끝의 후보 마흔아홉(이름으로 쉰하나)을 다시 봤다. 이름마다 용어집의 풀이와 피할 말을 읽고(세션 스크래치 `cand49.py`가 작업 폴더의 `CONTEXT.md`에서 뽑았다), 2차 검토 노트(공유 노트 `plain-words-glossary-review.md`, 서브에이전트의 판단)의 후보를 견줘 새 이름을 정했다. 가름은 본 세션의 판단이다.

- **바꾸기를 권한 것(열여덟).** 노트 조각 → 릴리스 노트 원고, 서버 파일 → MCP 서버 파일, 규칙 파일 → 승인 규칙 파일, 전송 → 연결 방식, 관리 → 관리 창구, 컨텍스트 → 에이전트 컨텍스트, 인터럽트 → 결정 대기, 서빙 엔진 → 모델 서버 프로그램, 고아 실행 → 담당이 사라진 실행, 운영자 쪽 실행 → 운영자가 시작한 실행, 토큰 합 상한 → 토큰 합 제한, 기본 에이전트 → 기본 제공 에이전트, 되돌려 합치기 → 운영에서 개발로 합치기, 원색 토큰 → 색 단계 토큰, 거꾸로 동기화 → 웹 편집 반영, 루트 브랜치 → 주 체크아웃이 따르는 브랜치, 정해 둔 조회 → 미리 적어 둔 조회, 재생 평가 → 지난 실행 비교 평가.
- **그대로 두기를 권한 것(후보는 있다, 열여섯).** 조건부 이어쓰기, 구독, 채널, 트레이스, 하네스, 대기열 항목, 회차, 계기, 살아 있는 문서, 비워 둔 판, worker, 시스템 관리자·관리자, 넘김·넘김 메모, 설치, 운영자 파일, 사이트 파일.
- **더 쉬운 이름을 찾지 못한 것(열다섯).** 단독 배포, 로그인 서버 항목, 머리말, 모델, 내보내기, 최종 사용자 항목, 대화 넘겨받기, 앞 실행, 헌법 판, 재생, 슬러그, 쓰임새 토큰, 사용량 장부, 세션 카드, 인계.

올리기 전에 대 본 것.

### 사용자가 되물은 셋에 대해 본 것

- **넘김 → 위임.** "위임"은 앞 PR에서 사용자가 "맡기기"의 새 이름으로 고른 말이고(`CONTEXT.md` 549행, 위임하는 쪽이 실행 도중에 다른 에이전트를 불러 일을 시키고 그 출력을 받는 것), 넘김의 피할 말에도 "위임(실행 도중에 다른 에이전트를 부르는 것이다)"이 있다. 넘김까지 위임이라 부르면 서로 다른 두 가지가 한 이름이 된다. 다른 후보로 "이관"(일지 밖에서 쓰인 곳 없음), "교대"(쓰인 곳 없음), "담당 넘기기"(쓰인 곳 없음)를 봤다(세션 스크래치 `pan_count.py`와 Grep).

### 정해진 이름 바꾸기 (처음 화면과 그 뒤의 다섯 화면을 합친 것)

- 넷째와 다섯째 화면에서 정한 것: 관리자 → 일반 관리자, 헌법 판 → 헌법 버전, 비워 둔 판 → 비워 둔 버전(판 번호 → 버전 번호와 홀로 쓰인 "판"도 함께), 운영자 파일 → 운영자 설정 파일, 사이트 파일 → 허용 사이트 설정 파일, 넘김 → 이관(넘김 메모, 연속 넘김도 함께).

- 묶는 법: 널리 쓰인 이름은 이름 하나에 PR 하나, 작은 이름은 주제가 가까운 것끼리 PR 하나. "판"은 다른 이름을 다 바꾼 뒤 영역별로 나눈다.

## 2. 그대로 두기로 한 이름

사용자가 agent-os에서 그대로 두기로 한 이름이다. 이 저장소에서도 바꾸지 않는다.

- 하네스, 회차, 계기, 대기열 항목, 살아 있는 문서, worker, 설치, 관리.
- "표지"가 "확인용 흔적"의 뜻으로 쓰인 곳. agent-os가 "자리 표시"로 바꾸는 것은 용어집의 "표지"(목록에 읽을 수 없는 항목이 있을 때 그 자리에 대신 넣는 항목) 하나뿐이고, 이 저장소에는 그 뜻의 "표지"가 보이지 않았다(73개 파일 557곳을 다 열어 보지는 않았다).

## 3. 이 저장소에만 있어 사용자에게 물을 것

agent-os의 결정이 이 말들까지 정한 것은 아니다. 이름마다 "지금 이름 → 후보 이름", 가리키는 것 한 줄, 바뀌는 파일 수(어림이면 어림이라고)를 선택 화면으로 보이고 고른 것만 한다. 사용자가 자기 후보를 적으면 그대로 받지 않고, 조사가 붙는 실제 문장에 넣어 본 것과 다른 낱말과 겹치는지를 적어 다시 보인다.

### 3-1. 색인 판 계열

- 대상: 색인 판(지식베이스의 색인이 어떤 스키마, 임베딩 모델, 청킹 설정으로 만들어졌는지 적은 레코드), 현재 판, 건설 중인 판, 물러난 판, 살아 있는 판, 판 전환.
- agent-os에서 사용자는 "앞말 없이 쓰인 '판'도 모두 바꾼다"를 골랐다. 그 뜻을 따르면 색인 버전, 현재 버전, 만드는 중인 버전, 물러난 버전, 살아 있는 버전, 버전 전환이 된다. 이 후보는 이 글을 쓴 세션이 지은 것이고 사용자가 고른 것이 아니다. 첫 선택지로 두되 아래의 치를 값을 함께 보인다.
- 치를 값 셋. 용어집이 "인덱스 버전"과 "스키마 버전"을 피할 말로 적어 둔 줄을 고쳐야 한다. 계약의 "버전"과 색인의 "버전"이 같은 낱말이 되므로, 지금 "판" 하나로 갈라 읽히던 둘을 "계약 버전"과 "색인 버전"처럼 앞말을 붙여 가르는 규칙이 필요하다. 그리고 코드와 시험의 독스트링에 가장 널리 쓰인 이름이라 바뀌는 곳이 많다(`src/rag_engine/domain/ports.py`, `tests/app/test_reindex.py`, `src/rag_engine/app/index_document.py`에 많다. 이 계열만 따로 센 수는 없다).

### 3-2. 뜻이 가까워 맞출지 물을 것

| 지금 이름 | agent-os의 결정 | 이 저장소의 쓰임 | 물을 것 |

### 3-3. 글자는 같지만 다른 뜻이라 바꾸지 않는 것

2026-11-18에 쓰인 자리를 읽어 본 것이다. 바꾸지 않는다고 일지에 한 줄씩 남긴다.

- 관리자(24개 파일 55곳). agent-os는 운영자 계정의 두 단계 가운데 "관리자"를 "일반 관리자"로 바꾼다. 이 저장소의 "관리자 페이지", "세션 관리자", "작업 관리자"는 다른 것이다. 이 서버에 운영자 계정의 단계가 생기면 "시스템 관리자"와 "일반 관리자"로 부른다.
- 컨텍스트(24개 파일 52곳). agent-os는 런타임이 에이전트에게 넘겨주는 통로를 "에이전트 컨텍스트"로 바꾼다. 이 저장소의 "세션 컨텍스트", "컨텍스트 압축", 도메인 문서의 "단일 컨텍스트"는 다른 것이다.
- 규칙 파일(2개 파일 3곳). agent-os는 승인 규칙을 적은 파일을 "승인 규칙 파일"로 바꾼다. 이 저장소에서는 `.claude/rules/`의 파일을 가리킨다.
- 넘김(13개 파일 22곳). agent-os는 에이전트가 자기 실행을 끝내며 다른 에이전트에게 넘기는 것을 "이관"으로 바꾼다. 이 저장소에서는 회고의 판정 "넘김", "시간 넘김", PR 코멘트의 `사용자에게 넘김:`이다.
- 교환(1곳, 토큰 교환), 인터럽트(1곳, agent-os의 옛 대화를 가리킨 스킬 주석), 위임(1곳, 보통 동사).

## 4. agent-os에만 있는 이름

이 저장소에는 쓰인 곳이 없어 옮길 것이 없다. 이 저장소의 글이 agent-os의 것을 가리킬 일이 생기면 새 이름으로 쓴다.

- 2026-11-17에 바꾼 것: 덮는 끝 → 요약에 든 마지막 실행, 실황 → 실시간 전달, 등록부 → 실행 중 목록, 값 기반 마스킹 → 비밀 값 가리기, 참조 배포 → 통합 배포, 참조 클라이언트 → 본보기 앱, 조회문 직접 작성 → 모델의 조회문 직접 작성, 맡기기 → 위임, 리드 → 위임하는 쪽, 맡긴 이벤트 → 위임 이벤트, 넘김 고리 → 연속 넘김(아래에서 다시 "연속 이관"이 된다).
- 새 이름을 정했고 아직 바꾸지 않은 것(보증 모드 하나만 PR로 올리는 중이다): 보증 모드 → 신원 확인 방식, 고지 → 이용 안내, 교환 → 문답, 저자 → 플러그인 개발자, 서버 파일 → MCP 서버 파일, 규칙 파일 → 승인 규칙 파일, 컨텍스트 → 에이전트 컨텍스트, 인터럽트 → 결정 대기, 고아 실행 → 담당이 사라진 실행, 운영자 쪽 실행 → 운영자가 시작한 실행, 토큰 합 상한 → 토큰 합 제한, 원색 토큰 → 색 단계 토큰, 거꾸로 동기화 → 웹 편집 반영, 정해 둔 조회 → 미리 적어 둔 조회, 재생 평가 → 지난 실행 비교 평가, 관리자 → 일반 관리자, 운영자 파일 → 운영자 설정 파일, 사이트 파일 → 허용 사이트 설정 파일, 넘김 → 이관(넘김 메모 → 이관 메모, 연속 넘김 → 연속 이관), 표지 → 자리 표시.
- 그대로 두기로 한 것: 서빙 엔진, 기본 에이전트, 조건부 이어쓰기, 채널, 트레이스, 구독, 시스템 관리자, 위임.

## 5. 바꾸는 길

### 5-1. agent-os에서 겪은 것 (열일곱 이름을 바꾸며 돌려 보거나 리뷰가 잡은 것이다)

- 이름 뒤의 조사를 함께 바꾼다. 새 이름의 받침이 달라지면 은/는, 이/가, 을/를, 과/와, 으로/로가 바뀐다. 다 바꾼 뒤 받침에 맞지 않는 조사("버전는", "요청자을" 같은 꼴)를 정규식으로 한 번 훑는다.
- 바꾸는 곳은 용어집, 살아 있는 문서(규칙, 스킬, 기능 계획, 진행 중인 기능의 명세, 열린 개선 항목, README), 코드의 주석과 독스트링, 오류 문구와 그것을 맞대는 시험, 시험 이름이다.
- 용어집에서는 이름을 바꾸고 피할 말에 옛 이름을 "옛 이름. 바꾼 날짜"와 함께 넣는다. 풀이의 사실은 그대로 둔다. 새 이름이 그동안 피할 말에 적혀 있었으면 그 줄을 뒤집는다.
- ADR은 본문과 색인을 고치지 않는다. 옛 이름이 본문에 든 ADR마다 이력에 "용어집의 이름을 바꿨다. 본문의 옛 이름은 새 이름으로 읽는다"는 한 항목을 단다.
- ADR 결정의 제목을 글자 그대로 든 곳은 옛 이름 그대로 둔다. 제목이 바뀌면 그 이름으로 ADR에서 결정을 찾지 못한다. 제목을 풀어 쓴 문장은 새 이름으로 바꾸고, 그 문장이 결정을 가리키는 자리이면 옛 제목을 괄호로 덧붙인다.
- 디자인 폴더처럼 바깥 도구와 주고받는 사본은 손으로 고치지 않는다. 그래서 명세의 이름과 사본의 이름이 어긋나면, 그 화면을 지을 기능의 계획에 "새 이름으로 짓는다"는 한 줄을 적는다.
- 남은 옛 이름을 찾을 때는 낱말 사이의 공백, 줄바꿈, 주석 머리표, 밑줄을 허용하는 정규식으로 추적 파일과 미추적 파일을 모두 훑는다. 그래도 낱말 사이에 조사가 끼거나 줄여 부른 꼴은 잡히지 않는다. 옛 이름의 핵심 낱말 하나로도 한 번 훑어 눈으로 가린다. agent-os에서는 시험 이름이 "보증"이라고만 줄여 쓴 한 곳이 처음 셈에서 빠졌다.
- 시험 이름을 바꾸면 시험을 이름으로 골라 돌리는 설정(시험을 일부러 깨 보는 검사의 표, pytest `-k`, vitest `-t`)이 옛 이름을 가리키게 된다. agent-os에서는 여섯 곳이 그랬고 검사는 알리지 않았다. 바꾼 시험 이름을 가리키는 설정이 있는지 따로 훑는다.
- 새 이름이 길어지면 파이썬 줄 폭(한글은 두 칸으로 센다)을 넘는 줄이 난다. 주석의 가름줄처럼 폭을 맞춘 줄도 다시 맞춘다.
- 규칙 파일과 스킬을 고쳤으면 그 파일을 원천으로 든 확인 절차를 이 저장소의 방식으로 다시 돌린다.
- 사용자에게 보인 바뀌는 파일 수와 실제로 바뀐 파일 수가 달라지면 마무리 보고에 알린다. agent-os에서는 18개로 보였다가 14개가 됐다(디자인 폴더와 제목 인용만 든 파일이 빠졌다).

### 5-2. 묶는 법과 차례

사용자가 agent-os에서 고른 묶는 법이다. 널리 쓰인 이름은 이름 하나에 PR 하나로 하고, 작은 이름은 주제가 가까운 것끼리 PR 하나로 묶는다. "판"은 가장 큰 일이라 다른 이름을 다 바꾼 뒤 영역별로 나눠 한다. 모두 용어집 파일을 고치므로 나란히 하지 않고 차례로 한다.

이 저장소에 맞춘 차례(이 글을 쓴 세션의 어림이다. 다시 센 수를 보고 고친다).

1. 작은 하네스 이름 묶음: 끝이 열린 결함 종류, 이은 항목, 더하는 문턱(줄인 꼴).
2. 주체 → 요청자.
3. 루트 브랜치, 되돌려 합치기(도구가 글자를 찾는지 먼저 본다).
4. 3절의 답을 받는다. 색인 판 계열의 답이 "판"을 나누는 방법을 정한다.
5. "판": 헌법 판과 비워 둔 판과 판 번호(도구와 시험과 스킬을 함께), 릴리스를 가리키는 판, 용어집의 "판"과 홀로 쓰인 판, 색인 판 계열(고른 경우) 순서로 영역별 PR.

### 5-3. 돈이 드는 시험

이름 바꾸기가 실제 모델을 부르는 시험의 범위에 닿으면 이 저장소의 규약대로 예상 비용을 사용자에게 보이고 묻는다. 사용자가 agent-os에서 준 "묻지 않고 돌린다"는 답은 agent-os의 일부 PR에만 닿는 답이라 이 저장소로 옮겨 오지 않는다.
