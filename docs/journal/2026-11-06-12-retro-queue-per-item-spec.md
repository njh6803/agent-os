## 명세가 사람에게 물은 것

명세를 쓰기 전에 ADR 0045가 정하지 않은 틈 셋과 시험 이음매 하나를 선택 화면 하나로 물었다. 앞의 화면은 설명에 든 사실(전체 계획 142,072바이트, 가장 긴 줄 17,899바이트, 대기열 523, 설계 PR b77f158f가 기능 폴더를 만들지 않았다)을 대 보라는 훅에 막혀, 대 본 뒤 같은 질문을 다시 올렸다. 받은 답(고른 라벨과 그 설명, 글자 그대로):

- **시험 자리.** "임시 폴더 시험과 저장소 대조 (Recommended)" — "임시 폴더에 기능 계획과 티켓을 깔고 도구를 돌려 나온 표(상태, 순서, 프론티어)를 봅니다. 그리고 이 저장소에서는 디스크의 기능 계획으로 만든 표가 커밋한 plan.md와 글자 그대로 같은지 봅니다. 상태를 정하는 규칙(끝 줄, done 티켓)마다 사례가 하나씩 생깁니다."
- **끝 줄.** "그 기능을 고친 브랜치만 막기 (Recommended)" — "제안입니다. 커밋 검사(tools/check_ticket.py, 지금도 브랜치의 변경만 보는 검사)가 그 기능의 티켓을 고친 브랜치만 봅니다. 마지막 티켓의 PR은 끝 줄이 없으면 커밋이 막혀 그 PR에서 적습니다. 나란히 돌다 빠진 채 들어가면 전체 계획 표에 '끝 줄 없음'이 뜨고, 그 기능에 고침 티켓을 더하는 브랜치가 끝 줄부터 적어야 커밋됩니다. 다른 세션의 커밋은 막히지 않습니다. ADR 0045 결정 3의 '시험이 빨개진다'를 이력으로 바꿉니다."
- **설계 표지.** "기능 계획에 설계 줄 (Recommended)" — "제안입니다. 설계 인터뷰를 마친 세션이 기능 계획에 그 결정의 ADR 번호를 적습니다(예: 승인 규칙 기능이면 `**설계:** ADR 0044`). 명세도 설계 줄도 없으면 설계 인터뷰, 설계 줄만 있으면 명세입니다. next-session 결정표의 두 줄(설계 인터뷰, 명세)이 같은 조건이 되지 않습니다. ADR 0045 결정 4를 이력으로 넓힙니다."
- **표의 내용.** "한 줄 요약과 링크 (Recommended)" — "칸에는 기능 계획 머리의 한 줄 요약과 그 파일(.scratch/<slug>/plan.md)로 가는 링크만 둡니다. 표가 수 KB로 줄어 한눈에 읽히고(기능 51개에 한 줄씩이라는 어림), 긴 내용은 기능 계획을 열어 봅니다."

이 화면으로 확인받은 요약: 전체 계획 도구는 임시 폴더 시험과 저장소 대조로 보고, `끝` 줄이 빠진 것은 그 기능의 티켓을 고친 브랜치만 커밋 검사가 막으며, 설계가 끝난 것은 기능 계획의 `**설계:**` 줄로 알고, 전체 계획 표의 내용 칸은 한 줄 요약과 링크다. 끝 줄과 설계 줄은 ADR 0045의 결정 3·4를 이력으로 바꾸고 넓힌다.

## 명세

`.scratch/retro-queue-per-item/spec.md`를 썼다(`Status: ready-for-agent`). 설계 일지 2026-11-06-04 "다음"의 명세가 정할 것 열세 줄과 ADR 0045 "단계"를 넘겨받은 것 열네 행으로 받고, 그 자리마다 명세의 절을 대었다. 사용자 답 넷은 서두 밖 다섯 자리에 표시했고, 명세가 스스로 정한 것은 서두 밖 서른 자리, 거부한 안은 열다섯이다.

명세가 정한 것 가운데 ADR 본문과 다른 것:

- **차례.** ADR Consequences는 회차 다섯, 전체 계획 생성, 헌법 README를 나란히 열 수 있다고 했지만, 바뀌는 자리를 전수로 보니 셋 다 다른 조각과 파일이 겹쳐(회차 다섯은 `queue_open_rows`와 그 시험, 전체 계획 생성은 `check_ticket`과 `docs/constitution/operations.md`, 헌법 README는 `sibling_overlap`과 `check_ticket`) 모두 차례로 연다. 회차 다섯 → 대기열 분할 → 리뷰 봇 경로 거르기 → 일지 이름 → 전체 계획 생성 → 헌법 README → 티켓 이름. 리뷰 봇 경로 거르기만 분할 뒤 다음 티켓과 나란히 열 수 있다.
- **비워 둔 판의 신호.** 이력 문단이 헌법 README에서 빠지므로, 형제 몫으로 비워 둔 판을 가져간 신호를 "X의 판 줄은 main의 판 줄과 같고, main에 있던 X 몫의 비워 둔 문장을 X가 지웠다"로 정했다(ADR 결정 5의 문장 그대로는 main의 판을 낮추는 결함이 있었다). 번호 대조 도구와 판 검사가 이 신호를 쓴다.
- **워크플로 가드.** 그 PR은 커밋 검사 때문에 티켓 파일을 싣는데 지금 패턴은 티켓 파일을 받지 않아 그 PR 자신이 실패한다. 그래서 패턴에 대기열 폴더와 함께 `.scratch/<폴더>/issues/` 바로 아래의 `.md`를 더한다. 대기열 분할 뒤에 낸다.
- **실패 문장.** ADR 결정 10은 폴더 README만 가리켰는데, 시험마다 제 원천(그 폴더의 README, 기능 계획, 헌법 README)을 가리키게 넓혔다.

이것과 사용자가 고른 끝 줄·설계 줄로 ADR 0045에 이력 `2026-11-06 명세가 끝 줄을 막는 자리, 설계 줄, 비워 둔 판의 신호, 실패 문장의 범위, 조각의 차례를 정한다`를 더하고 본문 문장 일곱에 포인터를 달았다. 이력은 **아직 사용자 승인을 받지 않았다**(작업 규약 5, 셀프 리뷰를 반영한 뒤에 보인다). `CONTEXT.md`의 "기능 계획" 정의는 상태 칸이 없고 설계 결정과 끝난 날짜만 적는다는 것과 하네스 기능의 기능 계획은 전체 계획에 들지 않는다는 것으로 바꿨다.
