## 이어받은 것

워크트리는 origin/main(`57efd62`)에서 섰다. `.design-sync/`가 저장소에 없어 첫 `/design-sync`는 아직 돌지 않았다. 그래서
지시문의 선행 조건(첫 `/design-sync`가 `build`의 글꼴을 판정한다)은 이 세션이 아니라 그리는 단계의 일이고, 프롬프트의
하는 법 1에 적었다.

## 찾은 사실

모두 이 세션이 손으로 봤다.

- 관리 화면의 화면은 다섯이다(관리 토큰 넣기, 플러그인 목록, 플러그인 하나, 실행 목록, 실행 하나와 결정 자리). 머리에
  탐색 링크 둘, 채널 토큰 입력, "토큰 지우기"가 있다(`components/pages/AdminScreen.tsx`).
- 디자인 파일 v3의 04.3(실행 목록)은 "768 이상은 옆 탐색과 표, 미만은 위 막대와 카드 목록"이다. 표의 "요청" 열은 계약의
  `RunSummary`에 없고(그 설명이 "프롬프트와 토큰 수는 싣지 않는다"), 옆 탐색의 운영자 이름은 관리 화면이 알 길이 없다.
  파일을 내장 브라우저로 열어 글자를 읽었다. 정적 그림이라 스크립트가 채우는 값은 보이지 않았다.
- 관리 화면에는 CSP가 없다(앱의 `.ts`·`.tsx`·`.mjs`를 grep했다). `dangerouslySetInnerHTML`은 ESLint의
  `no-restricted-syntax`가 막는다(`web/eslint.config.mjs`). 이것은 테마를 그리기 전에 다는 스크립트의 흔한 모양을 막아,
  사용자가 고른 뒤에 알았다. 결정은 그대로 두고 모양을 명세가 재게 ADR에 적었다.
- 용어집에서 승인은 허가와 거부를 아우르는 행위이고 결정의 값은 허가와 거부인데, design-system 명세는 결정 버튼의 글자를
  "승인"으로 정했다. 용어집은 매니페스트를 "설정"이라 부르지 않는다.
- Claude Design의 템플릿이 양식을 띄우는지 보려고 내장 브라우저로 `claude.ai/design`을 열었으나 로그인 화면이었다. 로그인하지
  않았고, 프롬프트에 긴 글과 양식의 짧은 답을 함께 두었다.

## 라운드

라운드는 셋이었고 질문은 열셋이었다. 모두 추천안으로 정해졌고, 합의를 확인받은 뒤 한 가지가 바뀌었다.

1. 범위(겉모습과 배치만, 계약 그대로), 틀과 설정(설정 화면을 더한다), 테마 저장(localStorage와 그리기 전 스크립트), 버튼
   글자("승인"을 두고 용어집에 한 줄).
2. 테마 고르는 모양(미리보기 카드 다섯), 화면 이름("설정"과 범위를 밝힌 한 줄), 채널 토큰이 없을 때(안내 한 줄과 설정 링크),
   이벤트 열(모두 펼친 카드), 아이콘(패키지의 `IconName`), 폭(그림 375·1280, 테스트 320·1280), 그리는 차례(UI mockups로 바로).
3. 실행 목록의 시간 열(시작과 마지막). 1라운드의 범위 질문이 선택지 설명에 "걸린 시간"으로 적었는데, 일시정지한 실행에서는 뜻이
   "멈출 때까지"로 갈려 다시 물었다. 시각 표기(목록만 운영자의 시간대로, 이벤트 필드는 글자 그대로).

묻지 않고 가정으로 밝힌 것은 테마의 즉시 적용, 긴 글자의 줄바꿈(리플로), 상태 화면은 패턴 03.2~03.4를 가리키기만 함,
설정 화면이 관리 토큰 뒤에 열림, 탐색 차례(플러그인·실행·설정), 다크는 실행 목록 하나, 진행 표시를 쓰는 자리가 없음이다.

합의를 확인받고 프롬프트를 쓰는 도중에 사용자가 그리는 차례를 바꿨다.

> 사용자: "UI mockups로 바로 그리는 거 와이어프레임도 그리는걸로 수정해줘"

프롬프트를 둘로 나눴다. 나누는 자리는 사람이 고르는 자리(와이어프레임의 안)다. 배치가 열린 화면 셋(플러그인 목록, 실행
하나, 설정)에만 데스크톱 A·B 두 안을 그리게 했다. 같은 프로젝트에 두면 Project archive 하나에 둘이 담기므로 두 파일 모두
`design/`에 옮기고 README 표에 줄을 둔다.

## 셀프 리뷰

`/code-review`의 두 축(표준은 sonnet, 명세는 지시문을 명세로)을 base `57efd62`에서 돌렸다. 지적은 표준 축 열넷, 명세 축
열다섯쯤이었고 겹치는 것이 많았다. 근거를 먼저 보고 고친 것은 다음과 같다.

- 프롬프트의 관리 토큰 화면에 채널 토큰이 남았을 때의 "토큰 지우기"가 빠져 있었다(`AdminScreen.tsx`, web-admin 스토리 8).
- 묻지 않은 가정(즉시 적용, 다크는 실행 목록 하나, 설정 화면이 관리 토큰 뒤)이 프롬프트와 ADR의 굵은 결정에 결정처럼
  들어 있었다. 프롬프트의 "탐색용 가정"과 ADR의 가정 문단으로 옮겼다.
- ADR이 카드의 `data-theme` 미리보기를 "측정에 기댄다"고 적었으나, 프로브(`tokens/measure.mjs`의 switch)가 잰 것은 뿌리와
  shadow 호스트의 속성과 뿌리에서 물려받은 요소였다. 카드 모양은 CSS 선택자를 읽은 것이라 명세가 재는 것으로 고쳤다.
- "이 브라우저에만 남는다"는 sessionStorage의 채널 토큰에 틀렸다. "테마는 이 브라우저에, 토큰은 이 탭에만"으로 고쳤다.
- "기존 화면에 더하는 동작은 이것 하나다"는 적게 셌다. 토큰 조작의 이동과 목록 시각의 표기도 테스트를 바꾼다. 셋으로 적었다.
- 패턴 03.2~03.4(v3)에 관리 화면에 없는 동작("다시 실행", "위젯 넣는 법", "거르기 지우기")과 뺀 열("요청", "플러그인")이
  있었다(디자인 파일을 내장 브라우저로 열어 글자를 읽었다). 프롬프트가 그것들을 빼고, 읽기 실패는 이미 보인 것을 지운다는
  규칙(`.claude/rules/web-admin.md`)을 적게 했다.
- 채널 토큰이 없고 최종 사용자의 실행일 때 어느 줄이 서는지 정해져 있지 않았다. 토큰을 넣어도 결정할 수 없으므로 최종
  사용자의 줄이 이기게 적었다. 사용자에게 묻지 않은 논리적 귀결이다.
- localStorage가 비었다고 단언하는 테스트 둘(`HomePage.test.tsx`, `admin-token.e2e.ts`)과 `public/`의 스크립트가 테마 목록을
  import하지 못하는 것을 명세가 다룰 것으로 ADR에 적었다.
- 포인터와 잔존: ADR 0026의 "관리 화면의 테마 토글은 들이지 않았다", ADR 0021의 "persist를 sessionStorage에 걸고 토큰만"에
  포인터를 달았다. `tech.md`의 웹 행에 테마의 자리를 더하고 헌법을 3.0.22로 올렸다.
- "설정"이 매니페스트의 _Avoid_와 부딪혀 `CONTEXT.md`에 설정 화면을 세웠다. 결정 항목은 두 문장으로 줄였다.
- ADR의 아이콘 결정을 관리 화면으로 좁혔다. 위젯의 아이콘은 web-widget 행대로 그 기능이 정한다.
- 프롬프트가 README 표를 "디자인 파일마다"로 적어 화면 디자인 절의 "화면마다"와 달랐다. 고른 안은 디자인 파일에 적게 했다
  (`kickoff/prompting.md`: 대화에만 남은 결과는 내보낸 파일에 실리지 않을 수 있다). 첫 `/design-sync`가 글꼴을 고쳐야 하면
  그 세션이 따로 PR을 내고 그리기는 그것을 기다린다고 적었다.

남긴 것: 결정 항목의 버튼 글자 한 줄은 용어집에 화면 글자를 담는다는 지적을 받았지만, 사용자가 그 자리를 골랐다. 같은
사실이 ADR, plan 행, 프롬프트, 일지에 되풀이된다는 지적에는 plan 행을 ADR과 프롬프트를 가리키게 줄이는 것으로 답했다.

반영 뒤 검증 명령을 모두 다시 돌렸다. pytest 1875 통과, ruff·format·pyright·lint-imports 초록, `pnpm -C web verify` 초록(테스트
356)이다. 사용자가 ADR 초안을 승인했다.

> 사용자(질문에 답): "승인, 커밋·PR·병합 (Recommended)"
