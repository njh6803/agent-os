## 사용자 프롬프트

> 사용자: 설계 인터뷰할 거 있어?

`.scratch/*/plan.md`에서 명세도 `**설계:**` 줄도 `**끝:**` 줄도 없는 기능을 셌고, 프론티어와 겹치는 것은 `portal-admin`과 `widget-appearance`라고 답했다. 직전 일지(`2026-11-13-1625-rename-portal-to-widget-preview.md`)의 "다음"이 가리킨 위젯 로그인 상태의 설계 인터뷰는 `ListAgents`에서 `docs/widget-login-state-design` 세션이 사용자의 답을 기다리고 있어서, 그 세션에서 잇는 것이 맞다고 답했다.

> 사용자: 릴리즈 노트 관련해서는 끝났었나?

기본 꼴은 ADR 0056에서 정해졌고, 요약 단락 안은 `.scratch/release-image/plan.md`에 명세가 검토할 안으로 적혀 있다(일지 `2026-11-12-0108-release-notes-summary.md`). 하지만 `release-image`에는 명세도 티켓도 없고 판 내기 워크플로도 아직 없다고 답했다.

> 사용자: 그럼 reg-engine 저장소 관련해서는?

dev 전환은 rag-engine으로 옮겨졌다(agent-os의 `dev-branch-create`·`dev-branch-transition`이 done이고, rag-engine에 `origin/dev`가 있으며 최근 PR #34~#37이 그 브랜치에 들어갔다). 판 내기 워크플로를 옮기는 일은 `release-image` 뒤라고 답했다. 점검 도구(대기열 `rag-engine-harness-drift`)는 시작 조건이 찼는데 티켓이 없다고 답했다. 새 세션 카드를 내려 했으나 훅이 모델이 스스로 내는 세션 카드를 막아(ADR 0037 "세션 카드") 말로만 알렸다.

> 사용자: 근데 2번은 꼭 맞출필요가 있어?

여기서 "2번"은 점검 도구다. 답하기 전에 두 저장소의 같은 이름 파일을 바이트로 대 봤다. 세션 스크래치패드의 셸 스크립트가 `cmp -s`로 비교했고, 저장소에 남기는 프로브가 아니다. 댄 것은 agent-os 주 체크아웃(`1117a170f`)과 rag-engine 작업 트리(HEAD `11f91c9`, `main`)다. 스킬(`.claude/skills/*/SKILL.md`)은 같은 이름 16개 가운데 14개가 달랐고(차이는 `diff`가 낸 `<`·`>` 줄을 합친 수로 2~35줄), 훅(`tools/hook_*.py`)은 같은 이름 25개 가운데 6개가 달랐다. 꼭 맞출 필요는 없다고 답했다. 근거는 셋이다. 첫 실행부터 경고가 스물이고, 일부러 다르게 둔 곳의 목록을 하네스 PR마다 고쳐야 한다. 사용자가 직접 겪는 규약은 이미 지시문으로 옮기는 길이 있다. 차이의 상당수는 agent-os의 ADR 번호나 경로를 가리키는 것일 수 있다(차이를 줄마다 읽지는 않았으므로 어림이다). 대신 훅의 버그 수정은 지시문에 싣자고 했다.

## 판단한 것

- **옛 결정을 인용한 글은 고치지 않았다.** `점검 도구`와 `harness-drift`를 Grep으로 찾았을 때, 이 일을 가리키는 곳은 지난 일지 둘(`2026-11-11-1532`, `2026-11-11-2250`)과 done인 harness 티켓 `dev-branch-create`였다. 같은 Grep에 걸린 ADR 0056과 일지 `2026-11-11-1110`은 판 내기의 취약점 점검 도구라 다른 이야기다. 지난 일지와 done 티켓은 기록이라 그대로 둔다(`docs/constitution/operations.md` 문서 위치 절이 done 티켓을 기록으로 정한다).
- **ADR은 쓰지 않았다.** 원래 결정이 대기열 항목의 승인 줄에 "ADR 불필요"로 적힌 하네스 일이었고, 접는 것도 같은 무게라고 봤다.

## 회고

후보는 셋이고 모두 기각했다. 승인 0, 넘김 0, 기각 3이다.
