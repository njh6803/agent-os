## 설계

> 사용자: "주 체크아웃 갱신이랑 병합된 워크트리 정리도 필요할 때 할 수 있도록 기존 스킬 절차에 포함 시킬 수 없어? 아니면 새로운 스킬로?"

새 스킬을 권했다. 근거는 셋이다.

- next-session은 지시문을 내고 세션을 여는 스킬이라, 정리만 하려고 부르면 지시문까지 나온다.
- 두 작업은 주 체크아웃 세션만 할 수 있다. 워크트리 세션에서는 앱의 가드가 주 체크아웃 당기기를 거부한다.
- 정리 절차가 이미 next-session 안에 있으니 옮기면 원천이 하나다.

빼는 것도 둘 정했다. 앱의 `clean_up_worktrees`는 오래 쓰지 않은 세션의 워크트리만 지운다. 새 세션이 첫 턴에
정리하는 방식은 나란히 연 세션들이 다툰다.

> 사용자: "진행해줘"

  "워크트리에서 병합할 때" 4의 미갱신 한 줄은 `주 체크아웃 세션에서 /tidy-checkouts`로 끝난다.

## 셀프 리뷰

`/code-review`(base `e9aa574`, 파일 4, 커밋 0, 미추적 1)의 두 축에 더해, 지우는 절차라 반박 검증 워크플로를 따로
돌렸다. 데이터 손실, 돌고 있는 세션과의 간섭, git·윈도 동작의 세 관점이 임시 저장소에서 재현하며 반박했다.

- **Critical, 고쳤다.** 처음 판에는 `remove`가 `Filename too long`으로 실패하면 PowerShell `Remove-Item`으로
  지우는 대체 절차가 있었다. `core.longpaths`가 꺼진 채로는 `git status`가 긴 경로 안의 추적하지 않는 파일을
  stderr 경고만 내고 빠뜨려 판정 2를 지나고, 대체 절차가 그 파일을 지웠다(반박 검증이 손으로 재현했다). 모든
  git을 `-c core.longpaths=true`로 치고, 판정 2는 stderr까지 비어야 하며, `remove`가 실패하면 멈춘다.
- **Major, 고쳤다.** 같은 워크트리에서 브랜치를 바꿔 가며 일하는 세션은 제목이 브랜치와 다르고 워크트리도
  잠그지 않는다. 이 세션이 그렇다(제목 "병렬 작업 가능 시점"). 판정 3이 그 세션을 주인으로 알아보지 못해, 병합
  뒤 다음 브랜치를 따기 전의 이 워크트리를 지울 수 있었다. 제목이 체크아웃된 어느 브랜치와도 맞지 않는 세션이
  돌고 있으면 어느 워크트리도 지우지 않고 사람에게 넘긴다. 지우기 직전에 브랜치와 HEAD도 다시 본다.
- **Major, 고쳤다.** git 2.32는 `remove`가 실패해도 등록과 `.git` 파일을 먼저 지운다(프로브가 등록을, 반박 검증이
  `.git` 파일을 봤다). 처음 판의 "git은 등록을 남긴다"와 `git worktree prune`은 틀렸다. `prune`은 폴더가 옮겨진
  다른 워크트리의 등록까지 걷었다. 지웠다.
- **Minor, 고쳤다.** `pull`과 `switch`는 무시된 파일을 묻지 않고 덮어쓴다(기본값 `--overwrite-ignore`). 당기기는
  `git merge --ff-only --no-overwrite-ignore origin/main`, 옮기기는 `git switch --no-overwrite-ignore main`이다.
  `switch` 쪽이 덮어쓰기를 거부하는 것은 이 세션이 임시 저장소에서 손으로 봤다. 루트의 "깨끗하다"는 판정 2와
  next-session 3단계처럼 추적하지 않는 파일까지 센다. 원격에 없는 로컬 main 커밋은 `rev-list`로 먼저 본다.
- **그 밖에 고친 것.** 처음 판에 "서브에이전트에는 `list_sessions`가 없다"를 넣었다. 두 축과 반박 검증이 모두
  서브에이전트에서 그 도구를 불러 거짓임을 보였다. 그 문장은 open-session에서 옮긴 것이고 지웠다. `KICKOFF.md`가
  병합된 워크트리 열여섯을 2026-10-06의 수로 적은 것은 2026-10-05 감사의 수라 날짜를 고쳤다. 세션 목록 도구가
  없으면 판정 3을 잠금 pid만으로 하라던 안내는 스킬이 막으려는 위험을 되살려, 사람에게 확인받기로 바꿨다. `list_sessions`의 `limit`을 50으로 적었다. 단계를 1부터 세고, 판정 1의 HEAD를
  브랜치 끝으로, 1의 자리 판정에 `--show-prefix`를 더했다. next-session 4가 스킬의 규칙을 다시 적던 문장은
  가리키기만 한다.
- **남긴 것.** open-session의 같은 거짓 문장은 이 PR의 범위 밖이라 두었다. 워크트리 경계 문장이 여러 파일에 있는
  것(표준 축의 Shotgun Surgery)은 새 스킬에서만 next-session을 가리키게 줄였다.

   파일을 지우는 사슬로 재현했다. 두 리뷰 축은 그 사슬을 잡지 못했다. 지우거나 덮어쓰는 하네스 절차는 커밋 전에

2. **워크트리에 든 세션이 자기 워크트리를 잠근다(ADR 감).** 판정 3은 세션 제목으로 주인을 찾는데, 같은
   워크트리에서 브랜치를 바꿔 가며 일하는 세션은 찾지 못해 이번에는 지우기를 통째로 멈추게 했다. 들어간 세션이
   `git worktree lock --reason "claude session <sessionId>"`를 걸면 git이 지우기를 막고 판정 3이 정확해진다.
   next-session의 워크트리 문장과 implement에 닿는 결정이라 ADR이 먼저다.
