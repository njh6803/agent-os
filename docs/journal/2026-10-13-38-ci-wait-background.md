## 계기

## 길을 고르다

- **앱의 감시.** `set_monitor` 도구 설명은 auto_fix가 깨우는 계기로 CI 실패, 충돌, 리뷰 코멘트를 들고 초록 완료는 들지
  않는다. PR 구독은 연 지 5~9분 뒤에 생긴다(대기열 37의 4회차). 푸시 한 번의 CI는 2.5~3.5분이라(아래 측정) 첫 푸시의
  완료는 대개 구독 전이다.
- **GitHub 쪽 코멘트.** CI 끝에 PR 코멘트를 남겨 구독 알림으로 깨우는 길도 같은 까닭(구독 전에 끝난다)으로 첫 푸시를 놓친다.
- **로컬 백그라운드 대기.** Bash 도구의 `run_in_background`는 띄운 명령이 끝나면 세션을 다시 부른다(같은 날 데스크톱 앱
  세션에 실린 도구 설명). 기다리는 동안 모델은 돌지 않는다. 앱 지침은 세션이 CI를 스케줄하거나 `gh`로 폴링하지 말라고
  하는데, 사용자가 자동을 요청했고 앱에는 초록 완료로 깨우는 길이 없어 이 길을 골랐다. `tools/wait_ci.py` 독스트링에 그
  어긋남과 걷어 낼 조건을 적었다.

> 사용자: "그리고 CI 를 돌리기 전에 충돌을 해결하게 하는건 어때? 매번 CI를 여러번 돌리게 되는 것 같은데 아니면 더 좋은 방법이 있으면 알려줘."

`.scratch/retro-queue.md`였고**, 손으로 연 하나(#217)는 두 쪽이 표 끝에 행을 더한 자리였다. 충돌 없는 합치기는
`tools/protection.json`의 strict(최신 main 위에서 돈 CI만 병합)가 부른 것으로 어림했다(합친 까닭은 재지 않았다).

strict가 켜져 있으면 합치기 횟수는 충돌이 아니라 PR이 열린 동안 main이 몇 번 움직였느냐가 정한다. 그래서 CI 전에 충돌을
먼저 푸는 것만으로는 줄지 않고, 줄이는 모양은 푸시할 때마다 main보다 뒤처졌으면 먼저 합치고 푸시하는 것(리뷰 반영 푸시와
합치기를 CI 한 번으로 묶는다)이라고 답했다. GitHub merge queue는 내려받은 문서(merging-a-pull-request-with-a-merge-queue)가 조직
소유 저장소에서만 쓸 수 있다고 적어, 개인 계정 저장소인 이곳에서는 저장소를 옮겨야 한다. 자동 대기도 초록에서 병합까지의
틈을 줄여 뒤처짐 합치기를 줄이는 쪽이다.

## PR 직전 보안·버그·성능 축

CodeRabbit CLI는 `Seat: not assigned`라 돌지 못해 대체 둘을 돌렸다.

- **보안(`/security-review`).** 발견 없음. GitHub의 상태 설명이 에이전트가 읽는 출력에 닿는 길은 상태를 쓸 수 있는 주체가
  저장소 쓰기 권한을 가진 쪽뿐이고, 같은 세션이 이미 봇 리뷰 전문을 읽으므로 새 신뢰 경계가 아니라고 봤다.
- **버그·성능(`bug-perf-review`).** Major 하나와 Minor 넷, Nit 둘, 보류 하나. 모두 유효로 보고 고쳤다.
  - gh 호출에 시간 제한이 없어 멈춘 gh가 대기를 끝나지 않게 했다(Major). 호출마다 60초 제한을 두고, 넘기거나 띄우지 못하면
    조회 실패로 센다. `tools/sibling_overlap.py`가 같은 모양이다.
  - 리뷰를 요청하고 곧바로 다시 띄운 대기가 첫 조회의 건너뜀을 보고 "요청되지 않았다"로 끝났다. 요청 유예(90초)를 두었다.

  - 실패가 있어도 건너뜀이 남으면 리뷰 요청 안내로 끝났다. 실패를 먼저 본다.

## merge queue를 직접 할 수 있나

> 사용자: "merge queue를 직접 할 수는 없을까?"

길은 둘이라고 답했다. 저장소를 무료 조직으로 옮겨 GitHub merge queue를 쓰거나(내려받은 문서가 조직 소유 공개 저장소에서
쓸 수 있다고 적는다), auto-merge(이 저장소는 이미 켜져 있다)와 맨 앞의 뒤처진 PR 하나만 `update-branch`하는 워크플로로
병합 기차를 만드는 것이다. 뒤의 것은 `GITHUB_TOKEN`이 일으킨 이벤트가 새 워크플로 실행을 만들지 않아(내려받은 문서)
사람이 만든 토큰이 필요하다. 어느 쪽도 `retro-queue.md` 충돌은 풀지 못한다. 앞의 것을 추천했고, 비용을 원문으로 확인하는
ADR 초안을 별도 세션 카드로 제안했다.
