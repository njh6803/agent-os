## 이 티켓이 정한 것

원천은 티켓 끝의 같은 이름의 절이다. 여기에는 줄기만 둔다.

- 필드 이름은 `pause_index`이고 CLI 옵션은 `--pause-index`다. `…_at`은 시각으로 읽혀 버렸다.
- core는 자리를 결정 값의 필드가 아니라 따로 된 인자로 받는다. `resume(run_id, pause_index, decision, approver, …)`.
  자리는 결정의 내용이 아니라 결정이 답하는 일시정지의 주소이고 게이트는 그것을 쓰지 않는다.
- 판정은 `_read_paused`의 끝, 일시정지 아님 바로 뒤이고 같은지만 본다.
- CLI 안내 줄의 자리는 센다. `run`은 0부터, `resume`은 받은 자리 다음부터다. 트레이스 포트로 다시 읽으면 그 사이에 낀
  다른 결정이 이 스트림이 보이지 않은 일시정지를 안내하게 한다.
- 계약의 최솟값이 `0.0`으로 찍힌다. pydantic은 `0`을 내고 FastAPI의 `OpenAPI` 모델(`Schema.minimum: float | None`)이
  바꾼다. 스크래치 프로브 둘로 쟀다(pydantic 단독의 네 모양은 모두 `0`, 라우터의 실제 모델도 `model_json_schema`는
  `0`). 손으로 고치지 않는다.

## TDD와 변이

core → 채널 → CLI 순으로 테스트를 먼저 고쳐 빨강을 보고 구현했다. core는 시그니처 부재(`TypeError`), 채널은 추가
필드 422, CLI는 모르는 인자와 시그니처 부재로 빨갰다. 그런데 이 빨강은 대부분 판정의 이유가 아니라 모양의 부재에서
왔다. 채널의 형식 오류 사례는 구현 전에도 초록이었다(자리 필드 자체가 추가 필드라 같은 경로의 422였다). CLI의 음수·실수
사례도 "모르는 인자"로 초록이었다. 그래서 변이를 넣었다. 셀프 리뷰 반영 뒤의 판은 11이고 모두 기대대로 빨강이다.

| 변이 | 빨개진 것 |
|---|---|
| core: 자리 판정을 일시정지 아님 앞에 | core 순서 테스트 "다른 자리" 하나 |
| 같은 변이, 채널의 동시 재개 테스트로 | 동시 재개(둘째의 메시지가 "일시정지 상태가 아니"가 아니다) |
| core: 자리 판정을 트레이스 판정 맨 앞에 | 형식 1 하나, 손상 둘(모르는 종류, 다른 실행이 섞임) |
| core: 준비를 트레이스 판정 앞에 | 꺼진 에이전트여도 자리 어긋남이 먼저 |
| core: 자리로 이벤트를 꺼낸다 | 음수 자리 |
| 채널: `strict` 없음 | 문자열·실수·불린 × 승인·거부 여섯 |
| 채널: `ge=0` 없음 | 음수 × 승인·거부 둘 |
| 채널: 승인의 자리에 기본값 | 자리 없는 승인 |
| CLI: 자리를 `int()`로 읽는다 | 인자 오류의 음수·밑줄·전각 |
| CLI: 음수만 따로 막지 않는다 | 인자 오류의 음수 |
| CLI: 재개 스트림을 0부터 센다 | 재개가 다시 멈추면 새 안내 줄의 자리 |

변이 파일의 `-k`에 매개변수 id(`음수`)를 넣었다가 선택이 비어 도구가 기준선 오류로 멈췄다. pytest가 한국어 id를
`음수`로 이스케이프한다. 테스트 이름으로만 고르고 어느 사례가 빨간지는 출력으로 봤다.

## 셀프 리뷰

`/code-review main`, base `acb3868`, 수정 15파일과 미추적 1, 커밋 0. 명세 축은 누락 0이었고 요청 밖 둘과 구현
의심 셋을, 표준 축은 확정 셋과 판단 여덟을 냈다. 고친 것은 이렇다.

- 티켓에 적은 lax 주장(티켓이 든 네 값이 lax에서 409로 끝난다)은 넷 가운데 둘만 참이었다. `true`는 1로 읽혀 자리
  1의 실행이면 200이고 `2.5`는 lax에서도 422다. 고쳐 적었다.
- `.claude/rules/core.md`가 트레이스 판정의 순서 전체를 "결정의 자리" 절이 고정한다고 적었는데 실제보다 넓었다. 그
  절은 일시정지 아님 → 자리 → 준비만 고정했다. 문장을 좁히지 않고 테스트 둘(형식 1 → 자리, 손상 → 자리)을 더해 참으로
  만들었다.
- `tests/core/test_run.py`의 실행 전 실패 절 머리가 재개 불가를 실행의 상태 하나로 닫았다. 자리 어긋남은 실행의
  상태가 아니라 결정 쪽이 낡은 것이다.
- 라우터의 409 주석은 자리가 지나가면 트레이스를 다시 읽어 맞는 자리로 보내면 된다고 했고, CLI `resume` 독스트링은
  마지막 안내 줄로 이어 가면 된다고 했다. 채널 토큰만 든 클라이언트와 HTTP로 멈춘 실행에는 거짓이다. web-widget 행
  (6)이 적은, 트레이스를 읽지 못해 다시 맞추지 못하는 그 경우다. 둘 다 같은 결정은 다시 보내도 받아들여지지 않는다는
  데까지로 좁혔다.
- CLI `_pause_index`가 `int()`라 `1_0`, 공백, 전각 숫자를 받았다(두 축 모두). ASCII 숫자만 받게 했다. 전각 `１`은
  자리 1의 실행을 그대로 재개했었다.
- 변이 이름 하나("채널: …"인데 core를 고친다)와 프로브 README 행이 변이를 다 세지 않은 것. 모듈 독스트링의 짧은 줄.

남긴 것과 이유는 이렇다.

- **Data Clumps `(run_id, pause_index)`, Primitive Obsession(맨 `int`).** 판단 호출이다. 묶는 타입은 core `resume()`의
  시그니처와 채널 둘의 모양을 다시 바꾸는 설계이고, 0 이상 규칙은 채널 둘이 자기 형식으로 막는 것이라 core의 타입이
  대신하지 않는다(core는 같은지만 본다). 지금 넓히지 않는다.
- **판정 순서 열거의 반복**(`core.md`, 실행 모듈 둘, CLI 독스트링). 기존 관행이다. 이번에도 넷을 같이 고쳤다.
- **`DENY`가 `_approve`와 짝인 도우미 없이 리터럴이다.** Minor. 쓰는 곳이 둘뿐이다.
- **`plan.md` web-admin 행에서 티켓 01의 열거를 지운 것**(명세 축의 요청 밖). 이어받은 PR #97 Minor의 처방이고 지운 내용은
  티켓 01에 모두 있다. PR 설명에 적는다.
