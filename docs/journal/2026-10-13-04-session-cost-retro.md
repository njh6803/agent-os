- 응답 하나는 내용 블록마다 기록이 나뉘고 같은 `message.id`를 든다. 출력 토큰은 뒤 조각이 크다(같은 id 안에서 줄어든 일 0).
- 서브에이전트 기록은 응답의 약 7할이 스트림 시작의 usage만 남아 출력 토큰이 빠진다. 입력과 캐시는 맞다.
- 세션마다 `cost-state` 기록(Claude Code가 모델마다 셈한 토큰과 `costUSD`, 서브에이전트 포함)이 프로세스가 끝날 때 남는다.
  단가표의 양성 대조로 썼다.

- `turn_duration` 기록은 다섯뿐이라 턴 시간은 기록의 시각으로 셌다.

## 모델 판정 실험

`judge.py plan`의 어림을 보고하고 물었다.

> 사용자: (판정 실험 — 모델 판정 실험을 돌릴까요? … 대상 34개 × 3회 = 호출 102번, 노력 high, 캐시 5분, 대체 모델(fallbacks)은 켜지 않습니다 … 글자 수로 어림한 금액은 가운데 약 $6.75, 위 끝 약 $16.24입니다 …) "승인 (Recommended)" — 설명: 102번 호출(약 $7~16)로 사전 등록한 실험을 끝까지 돌립니다. 결과가 '쓸모 있다고 볼 수 없다'여도 ④에서 모델 분류 단계를 넣을지 정하는 근거가 됩니다.

호출 하나로 요청 모양을 본 뒤(`--limit 1`) 나머지를 돌렸다. 102번 모두 측정이었고 단가표로 셈한 금액은 $4.44였다. 결과는 "쓸모
있다고 볼 수 없다"다. 시간 가운데 값과 실제 턴 시간의 ρ가 0.416 [0.10, 0.66]이었고, 단순 지표(백틱 경로 수 0.518)보다 0.1 이상
커야 했다. 보정은 파일 수(0.79)와 턴 시간(0.68)은 됐고 턴 수(0.59)는 아니었다. 설계의 "`llm` 마커"는 pytest 테스트가 아니라
`run --yes` 없이는 API를 부르지 않는 하위 명령으로 두었다. 통과·실패를 단언하는 테스트가 아니라 결과를 내는 측정이라서다.
