## 시작 프롬프트

`.scratch/widget-login-state/design/screens-prompt.md`를 `.scratch/answer-markdown/design/screens-prompt.md`의 모양으로 썼다. 고를 갈래는 넷이다. 로그인 상태 줄과 다크 모드 스위치의 자리(세 안), 로그인 모드 사이트의 로그인 전 화면(세 안), 고지 전문의 펼침(세 안), 만료 알림의 모양(후보 셋, 위젯 설정에 둘 모양과 기본 모양을 따로 묻는다). 완성 화면은 열넷이다. 와이어프레임 차례는 두지 않았다.

쓰며 대 본 사실. 디자인 시스템의 아이콘 집합에 해·달, 사람, 로그인·로그아웃 화살표가 없어(`web/packages/ui/src/components/atoms/Icon.tsx`의 import 열여덟) 다크 모드 스위치는 아이콘 버튼이 아니라 스위치 부품(라벨 "다크 모드"와 상태 글)으로 두었다. 버튼 변형은 주·보조·위험 셋뿐이라(`Button.tsx`의 `ButtonVariant`) "고지 전문"은 브라우저 기본 button으로 짓는 글자 단추로 적고 명세에 넘겼다. 새 창 로그인은 위젯이 다시 뜨지 않으므로, 만료 알림의 본문을 앞선 탐색의 "보내려던 질문은 남지 않으니 다시 적어 주세요."에서 "적어 둔 질문은 입력창에 남아 있습니다."로 바꿨다(제안). 버튼 차례는 승인 묻기와 같은 "보조가 먼저, 주가 나중"으로 두었다.

고른 것을 모으면 이렇다.

- 갈래 1: 안 4. 위쪽 띠는 이름, 설정 단추(톱니, 테두리 없는 아이콘 단추), "새 대화"이고, 설정 메뉴에는 다크 모드 스위치만 든다. 로그인 줄은 로그인 주소가 있는 사이트에만 위쪽 띠 아래에 선다.
- 갈래 2: 세 모양(대화 안의 안내 카드, 입력 자리를 단추로, 첫 화면 안내 안의 단추)을 위젯 설정에 두고 기본은 대화 안의 안내 카드다.
- 갈래 3: 세 모양(고지 줄 안에서 펼침, 덮개로 보이기, 대화 안의 카드로)을 위젯 설정에 두고 기본은 고지 줄 안에서 펼침이다.
- 갈래 4: 세 모양(대화 안의 카드, 위젯을 덮는 상자, 입력창 위 띠)을 위젯 설정에 두고 기본은 대화 안의 카드다.

명세에 넘길 것이 셋 생겼다. 첫째, 위젯 설정에 화면 모양의 칸이 셋 든다(로그인 전, 고지 전문, 만료). ADR 0061은 만료 알림의 다른 모양을 화면 작업이 그린다고만 적었고 칸의 목록을 정하지 않아, 칸 셋은 명세가 정한다(셀프 리뷰에서 틀린 것으로 고쳤다. 만료 칸은 ADR 0061이 이미 넣었고 목록의 주인은 '위젯 설정 관리' 행이다. 아래 "셀프 리뷰"). 둘째, 설정 메뉴는 위젯 창 다음의 두 번째 떠 있는 것이다. `.claude/rules/web-design.md`는 그림자를 떠 있는 것(위젯 창, 메뉴)에 쓴다고 해 규칙과 어긋나지 않지만, 시작 프롬프트의 "떠 있는 것은 위젯 창 하나다"는 고쳤다. ADR 0061의 "스위치는 모든 위젯에 보인다"는 사이트가 밝기를 정해도 스위치를 빼지 않는다는 뜻으로 읽었고, 메뉴 안에 두어도 모든 위젯에 들어 그 결정과 어긋나지 않는다고 본다. 명세가 이 읽기를 확인한다. 셋째, 고지 전문을 덮개로 보이는 값을 두면 위젯의 덮개가 고지 확인, 만료(덮는 상자를 고른 사이트), 고지 전문의 셋이 될 수 있다.

## 완성 화면

둘째 라운드의 결정을 시작 프롬프트에 반영했다. 고를 갈래 블록의 "떠 있는 것은 위젯 창 하나다"에는 설정 메뉴만 예외라고 덧붙였고, 그리지 않을 것의 "펼치는 사용자 메뉴"는 로그아웃을 숨기는 메뉴라고 좁혀 설정 메뉴와 가렸다. 캔버스 "1. 고를 갈래"의 "갈래 1 다시" 줄 오른쪽에는 둘째 라운드에서 고른 것을 녹색 메모로 남겼다.

완성 화면은 스크래치패드의 생성 스크립트 하나로 열네 장을 지었다. 위쪽 띠, 로그인 상태 줄, 대화 안의 카드, 덮개, 고지 줄을 함수 하나씩으로 두고, 고를 갈래에서 고른 아트보드(ch-status-4, ch-gate-1, ch-notice-1, ch-expiry-1~3)의 마크업을 그대로 옮겼다. 시작 프롬프트의 그릴 화면 열넷 가운데 6(로그인 창을 연 뒤)은 4와 5 안에 한 장씩 그렸고, 11(URL 방식의 창)은 좁은 창과 넓은 탭의 두 장으로 나눴다. Design 아티팩트 판 17로 올렸고, 아티팩트를 열면 "2. 완성 화면" 쪽이 먼저 보이게 바꿨다.

그리면서 시작 프롬프트가 정하지 않은 자리를 넷 정했다. 명세가 결정으로 바꾸거나 다시 묻는다.

- 로그인 창을 연 뒤의 안내 글은 로그인 상태 줄의 왼쪽 글 칸이 아니라 줄 아래에 폭을 채워 선다. 320px에서 왼쪽 칸은 단추에 밀려 좁아 안내가 세 줄로 꺾이기 때문이다. 카드에서는 본문 바로 아래에 선다.
- 로그인 모드 사이트의 고지 줄 글은 익명 사이트의 글을 그대로 썼다.
- URL 방식의 창을 주소로 직접 열었을 때 로그인 상태 줄은 "로그인하지 않음"과 쓸 수 없는 "로그인하고 질문하기"로 그렸다(어림). 창을 연 페이지가 없으면 로그인할 길도 없다고 봤다.
- 넓은 탭의 폭 480px 열은 떠 있지 않으므로 그림자와 모서리 없이 양옆에 경계선 한 줄씩을 둔다.

고지 확인 덮개의 안쪽 여백은 시작 프롬프트대로 16px로 그렸다(고를 갈래의 덮개 안은 위 24px이었다). 예시 전문 세 문단은 320px에서도 덮개 안에서 넘치지 않아, 스크롤은 그림 대신 아트보드 설명에 적었다.

확정을 묻는 질문 화면은 훅이 두 번 막았다. 처음에는 첫 등장이라 막았고, 질문 안의 목록에 "고지 확인 뒤"가 빠진 것을 찾아 질문 문장을 고치자 새 문장이라 한 번 더 막았다. 대 본 사실은 둘이다. 생성 스크립트가 낸 아트보드는 열네 개(mk-01~05, mk-07~10, mk-11a, mk-11b, mk-12~14)이고, 옮길 폴더 `.scratch/widget-login-state/design/`는 이미 있다.

> 질문: Design 아티팩트의 '2. 완성 화면' 쪽에 그린 아트보드 열네 장을 이대로 확정할까요?
>
> 사용자: "이대로 확정 (추천)" — 설명: 열네 장(기본, 고지 확인 덮개, 고지 확인 뒤, 둘 다인 사이트, 로그인 모드 사이트, 이름의 대체와 긴 이름, 만료, 거절, 로그아웃, URL 방식의 좁은 창과 넓은 탭, 다크, 형광 점의 테마 넷, 키보드 포커스)을 완성 화면으로 확정합니다. 이어서 고른 갈래의 안과 완성 화면, 캔버스 배치를 저장소의 .scratch/widget-login-state/design/ 폴더로 옮기고, 화면마다 한 줄인 README 표를 만듭니다.

스킬 6단계는 확정 질문의 문장에 아티팩트에만 남을 것(고르지 않은 안)도 적으라고 하는데, 이 질문은 옮길 것만 적었다. 그래서 확정 메모(`mk-confirmed`)에 옮길 것과 아티팩트에만 남을 것(갈래 1의 안 1, 2, 3, 5, 6)을 함께 적어 판 18로 올리고, 끝 보고에서 사용자에게 알린다.

## 인계

셀프 리뷰(`/code-review origin/dev`)를 부르자 인계 계기(`hook_handoff`)가 왔다. 세션 컨텍스트 321,465 토큰이 문턱 200,000을 넘은 채 단계 경계 `셀프 리뷰 직전`에 왔다. `next-session/handoff.md` 1의 인계하지 않는 때 다섯에 들지 않는다. 계기를 낸 명령이 실패하지 않았고, 요청 범위(PR과 병합까지)가 이 경계에서 끝나지 않으며, 지시문의 "이어받을 상태"는 "없음"이고, 이 일지에 `인계 못함` 줄이 없으며, `get_session`의 `self`에 `parentSessionId`가 없다. 그래서 셀프 리뷰의 단계를 밟지 않고 넘긴다. 바꾸기 전 제목은 `docs/widget-login-state-screens`다. 넘길 때 커밋하지 않은 변경은 `.scratch/widget-login-state/design/`(시작 프롬프트, README, 화면 스물넷, `canvas.json`), `.scratch/design-system/design/frontend-design-conflicts.md`의 넷째 줄까지, 이 일지다.
