# open-session 일지 · 2026-09-21

`next-session`이 낸 지시문으로 새 세션을 클릭 없이 여는 스킬을 만든 기록. 앞서 같은 제목의 세션 하나가 워크트리 칩으로 열려 `/open-session`(사용자 호출, 워크트리, `claude --bg`, 열렸다/끝 손잡이)을 만들었다가 "없던 걸로" 되돌린 뒤의 두 번째 시도다. 기록 규칙은 [킥오프 일지](2026-09-19-kickoff.md) 머리말과 같다.

> 사용자: "새 세션을 열어주는 스킬을 만들어줘. (kickoff-harness 프로젝트 참고) 새 세션으로 열어야 하는 경우에 발동 되는 스킬로 만들어줘. 워크트리로 열지 말고 새 세션으로 열어야 해. 새 세션이 열리면 옆 패널로 띄우고 새 세션으로 포커스가 되도록 해줘. 새 세션을 열어주는 세션이랑 메시지를 주고 받을 필요 없어. 새 세션을 열 때 다음에 해야 할 지시문도 같이 입력되도록 만들어줘. 새 세션의 이름은 지시문으로 생성된 브랜치명으로 만들어질 수 있도록 해줘."

## 결과

- 새 스킬 `.claude/skills/open-session/SKILL.md`(model-invoked). `next-session` 지시문의 "어디서"가 새 세션이면 돈다. 같은 체크아웃에서 열고, 워크트리는 새 세션이 필요할 때 자기 브랜치에서 판다.
- 새 스크립트 `tools/open_session.ps1`. `send`는 앱 딥링크 `claude://code/new?q=<지시문>`을 쏘고 접근성 트리(UI Automation)에서 "보내기"를 호출한다. `split`은 사이드바 행 메뉴 "다음에서 열기 → 분할 보기"를 누른다. 그 사이에 스킬이 `list_sessions`로 새 세션을 찾아 `set_session_title`로 브랜치명을 붙인다.
- `next-session` 지시문에 "브랜치" 줄을 더해 아홉 줄. 4단계가 "멈춘다"에서 "열고 멈춘다"로. 새 세션의 제목과 그 세션이 딸 브랜치의 원천이 이 한 줄이다.
- 포인터 셋. `operations.md` 브랜치와 병합 절 한 문장, `KICKOFF.md` 7단계 항목 하나("여덟 줄"이라는 개수 표현도 뺐다).
- 실측 열한 번. 끝 상태: 여는 세션이 왼쪽, 새 세션이 오른쪽 옆 패널에 `focused: true`, 폴더 `C:\project\agent`, 아홉 줄 지시문 전문 도착, 제목 `feature/02-read-the-trace`, 사용자 클릭 0회. 검사 넷과 지침 검사 초록(143 passed, pyright 0, Contracts 3 kept). 파이썬은 안 바뀌었다.

## 어떻게 찾았나

앱은 스토어 설치본(`WindowsApps\Claude_2.2553…\app\resources\app.asar`)이고 번들이 읽힌다. 딥링크 라우트(`claude://code/new`, `/continue`, `/needs-input`)와 핸들러가 읽는 파라미터(`q`·`prompt`, `folder`, `file`)를 문자열로 찾았다. 앱 자신도 폴더를 `code/new?folder=`로 정규화한다("ccd alias launch"). 자동 제출 파라미터는 없고, `folder`가 있으면 `src=external`을 붙인다. 바깥에서 온 프롬프트는 사람이 보고 보낸다는 설계다. 그래서 이 스킬은 그 설계를 우회하지 않고 사용자를 대신해 보내기를 누른다. 지시문은 사용자가 이미 본 것(`next-session` 출력)이어야 한다.

접근성 트리는 Chromium이 낸다. 세션 행의 옵션 버튼과 메뉴 항목은 `InvokePattern`을 지원하지 않아 경계 상자 가운데를 클릭하고, "보내기"와 "작업 공간 신뢰"는 `Invoke`가 된다. 메뉴 이름은 로케일(한국어)이고 스크립트에 영어 대안을 같이 적었다.

## 함정

- **PowerShell은 한글을 변수 이름 문자로 읽는다.** `"$Title에 대한"`은 `$Title에`라는 빈 변수다. `${Title}`. `split`이 20초를 두 번 헛돈 원인이었다.
- **`open_session_in`의 거부문 둘은 다르다.** "not started from this session"(부모-자식)과 "cursor is in a text field"(포커스). 후자는 사용자가 메시지를 친 직후엔 항상 나온다. 실측은 백그라운드 대기로 깨어나 사람 손이 입력란 밖일 때 했다.
- **칩 세션은 기록에 `spawnedFrom.sessionId`가, 스케줄 세션은 `scheduledTaskId`만 박힌다.** 앱의 배치 도구는 앞의 것만 받는다.
- **딥링크 페이지가 열려 있을 때 다시 쏘면 같은 자리에서 바뀐다.** 스크립트를 두 번 돌리면 세션이 둘 생기는 것은 제출 뒤 얘기다.
- **`list_sessions`의 새 세션 식별은 `lastActivityAt`으로.** 앱이 지은 제목은 프롬프트에서 따오므로 제목으로 찾으면 안 된다.
- **앱 번들(30MB `app.asar`)은 고정 문자열로 바이트 오프셋을 잡고 그 주변만 잘라 읽는다.** 정규식 문맥 검색(`.{0,200}패턴.{0,200}`)은 두 번 타임아웃했고, `grep -a -b -o -F` 뒤 `tail -c +오프셋 | head -c 800`은 즉시였다. "앱이 무엇을 지원하나"는 처음부터 이 길로.
- 앞선 세션의 함정 둘을 확인했다. `cd`가 앱 세션의 기본 작업 디렉터리를 바꾼다(다른 워크트리는 `git -C`), `uv run --no-sync`는 새 워크트리에 ruff가 없다.

## 추천과 결정이 갈린 곳

- 무클릭과 네이티브 패널이 동시에 안 된다고 두 번 단정하고 선택을 물었다. 사용자가 "제대로 다시 확인해봐"로 밀었고, 번들과 접근성 트리를 뒤진 끝에 둘 다 됐다. 도구가 거부하는 것과 앱이 못 하는 것을 같은 것으로 읽은 실수다.
- 신뢰 대화상자 자동 수락은 사용자 승인으로 넣었다. 루트 폴더와 정확히 같을 때만이고, `folder`를 빼면 대화상자가 안 뜨므로 지금은 예비다.
