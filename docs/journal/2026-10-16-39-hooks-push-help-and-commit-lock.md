## 잰 것

- `commit_lock/probe.py`(git 2.32.0.windows.2, 측정 6/6): `git add` 뒤의 보통 커밋은 pre-commit·commit-msg 훅이 도는 동안 그
  git 디렉터리에 `index.lock`이 없었다(주 체크아웃과 워크트리 모두). `-a`는 `index.lock`이, 경로를 준 커밋은 `index.lock`과
  `next-index-<pid>.lock`이 있었다. 워크트리의 git 디렉터리는 `<주 체크아웃>/.git/worktrees/<이름>`이었다. 행이 든 신호로는
  이 저장소의 커밋 꼴을 거의 못 본다.
- `slash_prompt_payload/probe.py`(claude 2.1.300의 `claude -p`, 측정 3/3): 반각 `/probe-slash 인자` 첫 줄은 스킬이 실렸는데도
  훅의 `prompt`가 보낸 글 그대로였다. 전각 `／`와 슬래시 없는 줄도 그대로였다. 훅 입력에는 세션을 어떻게 열었는지 알리는
  키가 없었다. 데스크톱 앱의 입력창은 재지 않았다.
- git의 도움말 꼴(임시 저장소에서 손으로 봤다, git 2.32): `-h`는 위치와 관계없이(`origin main -h`, `-fh`, `-hf`, `--dry-run
  -h`, `-dh`) 사용법을 내고 129로 끝났다. `-oh`·`-o -h`·`--push-option -h`·`--push-opt -h`는 `-h`를 푸시 옵션 값으로 먹었다.
  `git push --help`는 `GIT_TRACE`에 `built-in: git help --exclude-guides push`가 찍혔다. 이 가운데 줄임(`--push-opt`)을 뺀
  것은 두 훅의 실제 git 시험이 고정한다.
- pre-commit 4.6.2의 `staged_files_only.py`를 읽었다. 스테이지하지 않은 변경이 있으면 패치로 저장하고 `git checkout -- .`으로
  치운 뒤 훅을 돌고, 끝에 패치를 되돌리다 충돌하면 다시 치우고 패치만 얹는다.

## 정한 것

- 293의 신호를 `index.lock`에서 도는 `git commit` 프로세스로 바꿨다. 다른 길로 pre-commit 설정에 처음과 끝 훅을 더해 표지
  파일을 쓰는 길이 있었지만, 게이트 설정을 바꾸고 끊긴 커밋이 남긴 표지를 가려야 해 버렸다.
- 293을 PostToolUse로 지었다. PreToolUse의 계기도 편집이 돈 뒤에 읽히고(`.claude/rules/tools.md`), PostToolUse면 성공한
  편집에만 낸다.
- 72에 행의 판정(반각 `/<스킬>`) 밖에 "첫 줄이 지시문의 라벨 줄"을 더했다. 행을 쓴 뒤 하네스 chore의 시작 프롬프트가 슬래시
  명령이 아닌 글이 되어(이 세션의 시작 프롬프트가 그렇다) 행의 판정만으로는 그 꼴을 놓친다. open-session은 시작 프롬프트를
  늘 첫 줄에 두므로 라벨 줄로 시작하는 프롬프트는 그 스크립트가 보낸 것이 아니다.
- 행이 반영 때 정하라고 한 `held=` 뒤의 가름은 스킬 파일로 했다. open-session은 스킬 파일이 있는 슬래시 명령을 늘 옮기므로
  반각 `/<스킬>`로 남은 첫 줄은 스킬 파일이 없을 때만 `held=` 뒤에 나온다.
