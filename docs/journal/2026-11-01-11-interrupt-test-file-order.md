## 한 것

- 새 워크트리에 들어가 브랜치를 `chore/038-interrupt-test-file-order`로 바꿨다. 티켓을 쓰고(`in-progress`) 번호 겹침을 `tools/sibling_overlap.py`로 다시 쳐 보았다(겹침 없음, 이 브랜치의 새 번호는 티켓 038).
- 고침: `tests/channel/cli/test_interrupt.py`의 MCP 사례 자식이 표지(`pressed-N`, `cancelled`, `closing`, `closed`)를 쓸 때 `order.txt`에 이름을 먼저 덧붙인 뒤 표지 파일을 만든다. 시험은 `_끝.앞선다`로 순서 파일의 줄 순서를 견준다. 시계 값끼리의 `<` 비교 넷(`pressed[0] < cancelled`, `cancelled < pressed[1]`, `closing < pressed[0]`, `pressed[0] < closed`)을 모두 옮겼다. 끝나기까지의 길이 단언은 시각 파일을 그대로 쓴다. 쓰이지 않게 된 `_끝.closed` 필드는 걷었다.

## 손으로 본 것

- `uv run python -c "import time; print(sum(1 for _ in range(20000) if time.time()==time.time()))"` 꼴로 이 PC에서 `time.time()`을 연달아 두 번 부른 값이 20000쌍 중 19999쌍에서 같았다(손으로 봤다. 시계의 눈금만 보이고 시험의 실제 간격은 재지 않았다). 명세 축 서브에이전트도 같은 방식으로 19999를 얻었다고 보고했다.
- 순서를 쓰는 시험 셋 가운데 둘(도구 호출 도중, 닫는 도중에 한 번 더)을 한 묶음으로 20번, 셋째(닫기 시작 뒤)를 따로 20번 `uv run pytest`로 쳐서 모두 통과했다(손으로 봤다). 시험 파일 전체는 한 번 6 passed.
- `앞선다`에 순서가 맞은 목록·뒤집힌 목록·한쪽이 빠진 목록을 손으로 넣어 True·False·False를 봤다. 커밋한 변이 시험은 없다.
- 전체 러너(`tools/run_checks.py`)에서 별개 시험 `tests/adapters/test_filesystem.py::test_다른_프로세스가_운영자_파일을_연_채여도_교체가_재시도_안에서_성공한다`가 한 번 빨갰다(`PermissionError`, 한 바퀴 909초로 형제 세션들의 부하가 컸다). 그 시험만 홀로 돌리면 통과했다(67초). 이 변경이 건드리지 않은 시험이다.

## 셀프 리뷰 (`/code-review`, base `544381ea`, 파일 1개, 커밋 0, 미추적 1)

표준 축 지적: 독스트링 전칭 단정 둘, 쓰이지 않는 필드 하나, 사소한 것 몇. 명세 축: 티켓 문구 정확성 둘.

- 고친 것: ① 시험 파일 독스트링의 "눈금보다 짧은 간격이면 같다"는 눈금 경계에서 거짓이고 윈도우 한정이라는 범위가 없었다. 이 PC에서 20000쌍 중 19999쌍이라고 손으로 본 값으로 바꾸고 범위를 적었다. ② 같은 독스트링의 "자식이 표지를 쓸 때마다 덧붙인다"는 `_SLEEPING_CHILD`와 서버가 쓰는 `slow`가 반례라 "MCP 사례의 자식은"으로 좁혔다. ③ 쓰이지 않는 `_끝.closed`를 걷었다. ④ 티켓 수용 기준의 "시각 비교는 길이를 재는 것뿐"은 `time.monotonic()`의 기한 루프가 남아 거짓이라 `time.time()` 값끼리의 `<`로 좁히고 남은 `<`의 종류를 적었다. ⑤ 반복 증거가 "두 시험"이라고만 적혀 있어 어느 시험인지 적고, 셋째 시험을 따로 20번 돌려 증거를 채웠다. ⑥ 티켓에 손으로 본 명령을 적었다.
- 남긴 것: `_SLEEPING_CHILD`의 `pressed-0`을 직접 쓰는 한 줄은 순서를 견주지 않는 사례라 `record`로 바꾸지 않았다. `앞선다`의 `and (…)` 괄호는 ruff format이 정한 모양이다. `cancelled`→`pressed-1`, `closing`→`pressed-0` 단언은 자식 코드의 구조가 보장해 구현이 틀려도 빨개지지 않는다는 명세 축의 말은 변경 전에도 같았고, 이 티켓의 범위(흔들림 제거) 밖이다.
- 다시 돌린 것: 린트 둘과 pyright를 반영 뒤에 쳤고(통과), 시험은 셋째 20회를 반영 뒤에 쳤다. 나머지는 pre-commit이 갈음한다.

## 번복·결정

- `<`를 `<=`로 바꾸는 길은 같은 눈금에 든 역순도 통과시켜 판정을 느슨하게 하므로 택하지 않았다(대기열 531의 처방).
- 순서 파일은 줄 번호를 따로 매기지 않고 이름을 한 줄씩 덧붙인다. 같은 프로세스 안에서 `open("a")`로 덧붙이는 순서가 곧 일어난 순서이고, 덧붙인 뒤에 표지 파일을 만들어 기다리는 스레드가 "표지를 본 뒤 한 일"을 순서에서도 뒤에 둔다.
