## 찾은 사실

사실 조사는 서브에이전트 하나에 맡기고, 선택지 설명에 넣은 사실은 이 세션이 코드를 직접 읽어 대 봤다.

- **프론티어(손으로 봤다).** `.scratch/plan.md`의 기능 행 18개가 모두 `done`이다. 프론티어 문단 끝은 "model-plugin 이 2026-11-01 에
  닫혔다 … 프론티어에 남은 기능이 없다"이다. 지난 인터뷰(일지 2026-10-31-06, ADR 0040)가 같은 자리에서 PRD 범위의 model-plugin을
  골랐다.
- **PRD에서 남은 것(읽었다).** PRD "무엇을 만드나"는 플러그인 네 종류(agent, mcp, skill, model)를 읽어 실행하는 런타임, 채널(CLI →
  HTTP → 위젯), 관리(API → 화면)다. 채널과 관리는 닫혔고 플러그인은 skill만 남았다. "누구의 어떤 문제"의 최종 사용자 줄이
  "위젯이나 Slack 같은 채널"을, 개발자 줄이 "트레이스, 가드레일"과 "비용 라우팅"을 든다. 성공의 정의는 네 줄이고 넷째가 지난
  인터뷰가 더한 모델 플러그인 줄이다.
- **스킬(코드를 읽었다).** `plugins/skills/`는 `.gitkeep` 하나다(`ls`). `src/`에 `SKILL.md`를 읽는 코드가 없고 `skill`은
  `sdk/manifest.py:19`의 예약 주석("skill은 첫 슬라이스에서 디렉터리와 값만 예약한다"), `adapters/filesystem.py:54`의 디렉터리
  이름, `:79`·`:87`의 운영자 파일 칸뿐이다(서브에이전트가 Grep으로 봤고 이 세션이 그 줄을 읽었다). kind가 skill인 매니페스트는
  공통 넷만 가질 수 있다(`manifest.py:107-136`). `AgentContext`의 멤버는 `run_id`, `conversation`, `now()`, `llm(prompt)`,
  `tool(name, **args)` 다섯이다(`sdk/agent.py:49-59`). 관리 화면의 `WITHOUT_LOADER`는 `["skill"]` 하나이고 그 행에 "로더가 생기기
  전에는 효과가 없다"가 붙는다(`PluginList.tsx:22-23`). 용어집 `CONTEXT.md:91-93`은 "스킬(Skill): 에이전트의 컨텍스트에 주입되는
  절차 지식의 폴더. 도구가 아니다"다. `.claude/rules/sdk.md`는 "스킬은 절차 지식이다. `SKILL.md`와 부속 파일의 폴더이고 에이전트의
  컨텍스트에 주입된다. 함수가 아니다"라고 적는다.
- **토큰 수(코드를 읽었다).** `LlmCalled`는 `model`, `input_tokens`, `output_tokens`, `prompt`, `text`, `tool_calls`를 든다
  (`sdk/events.py:82-91`). 실행 요약 `RunSummary`는 일곱 칸이고 독스트링이 "프롬프트, 토큰 수, 출력, 이벤트는 여기 없다"고 적는다
  (`core/ports.py:174-187`). 관리 화면 트레이스 상세는 토큰 칸을 그대로 보이고(`EventItem.tsx:38-39`), 실행 단위 합계나 비용은
  `src/`에도 `web/apps/`에도 없다(서브에이전트가 Grep으로 봤다).
- **마스킹(코드를 읽었다).** 키 기반 하나다. mcp 매니페스트의 `server.secret_args`가 가리킨 인자 값만 core가 이벤트를 만들 때
  `MASKED = "***"`로 바꾼다(`core/run.py:178`, `sdk/manifest.py:61`). ADR 0009의 48·84·154행이 값 기반 치환을 "지금의 키 기반
  마스킹과 다른 메커니즘"이라며 미뤘다(Grep `값 기반`). `.scratch/plan.md`의 conversation 행이 PR #130 리뷰가 낸 값 기반 마스킹을
  "ADR 0009·0022의 이력 초안으로 따로 본다(사용자 결정 2026-10-04)"로 적는다.
- **채널(손으로 봤다).** `src/agent_os/channel/`은 `cli/`, `http/` 둘이다. `src/`에 `slack`·`webhook`·`schedul`·`cron`은 대소문자를
  무시해도 0건이다(서브에이전트의 Grep).
- **후보 목록(서브에이전트가 읽었다).** 킥오프 일지 `2026-09-19-kickoff.md:170-172`의 "확신 높음" 가운데 아직 없는 것은 스케줄러·
  웹훅 트리거, 토큰 스트리밍, 에이전트가 에이전트 호출, 병렬 도구, 스킬 로더, 멀티 프로바이더, 모델 라우팅, 비용 계량, RAG, 트레이스
  DB·OTel, PII·가드레일, Docker이고, 미정은 WASM, 빌더 UI, LangGraph Studio, Slack, 카카오톡이다. 토큰 스트리밍은 ADR 0014:31이
  범위 밖으로 두었고 용어집의 이벤트 스트림 항목이 "단위는 이벤트이고 모델의 토큰이 아니다"다. 둘째 제공사는 ADR 0040이 "목록에
  값을 더하는 가산 변경"으로 두었다. `.scratch/retro-queue.md`에 다음 기능 후보 행은 없다.

  시작하거나 64자인 것은 거부되고, 표준이 거부하는 끝 하이픈과 연속 하이픈은 통과한다.

   모델`로 `src/`를 훑어 이 둘뿐이었다). `_prepare` 독스트링의 "깨짐과 꺼짐이 같은 순서(에이전트 → mcp → 모델)"도 같은 셈이라 함께 "고칠 곳"에 더했다.
5. **YAML 예외가 `PluginError`로 바뀌는 자리, 유효.** `yaml.YAMLError`는 `Exception` 직계이고 `ValueError`가 아니다(설치된 6.0.3의 `yaml/error.py`
   45행을 읽었다). 어댑터의 `_parse`가 잡는 `(OSError, ValidationError, ValueError)` 모양을 그대로 따라 쓰면 머리말 거부가 날것으로 올라간다. ADR이 정한 머리말
   거부의 `PluginError`가 그 모양으로는 서지 않는다는 것을 적고, 바꾸는 층은 명세가 시그니처와 함께 정한다고 두었다.
6. **오류 문구의 되울림 금지, 유효.** `MarkedYAMLError.__str__`이 `Mark.get_snippet`(기본 75자)의 원문 조각을 싣는다(`yaml/error.py` 14·37·58행을
   읽었다). 매니페스트 문구와 같은 규칙(경로·줄·칸 위치·오류 종류만)을 ADR에 적고, `name` 어긋남 문구가 드는 값은 패턴을 지난 이름뿐이라고 했다
   (매니페스트의 어긋남 문구 `filesystem.py:134`가 패턴을 지난 `manifest.name`을 든다).
7. **준비 순서 요약의 "운영자 파일의 손상" 누락, 유효.** `_prepare`는 `_reject_disabled(plugins.read_disabled(), …)`로 그 손상을 꺼진 집합을 읽는
   자리에서 보고 독스트링은 깨짐에 센다. ADR의 순서 요약에 그 자리를 넣고, 스킬의 깨짐이 모델 뒤·운영자 파일 앞이라고 못 박았으며 순서를 고정하는
   시험 절을 적었다.
