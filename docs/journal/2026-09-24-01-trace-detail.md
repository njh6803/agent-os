# 2026-09-24 (01) 한 실행의 이벤트를 쓴 순서 그대로 본다 — admin-api 티켓 06

브랜치 `feature/06-trace-detail`, PR #63(`19bcc2f`로 squash 병합). `GET /traces/{run_id}`가 한 실행의
트레이스를 본문 객체 `Trace {run_id, schema_version, events}`로 돌려준다. 이 런타임이 모르는 종류의
이벤트는 `{"type": "unknown", "raw": "<원문 한 줄>"}`로 실린다. admin-api의 마지막 티켓이라 이 기능이
닫혔다(티켓 01~06).

사용자 입력은 인계 지시문 하나, 계약 결정 둘, ADR 승인 하나, 보고 언어 교정 하나, PR·병합 지시 하나,
회고 판정이었다.

## PR #60 훅의 첫 실측

지시문이 "확인할 선행 조건"으로 적은 것이다. 첫 메시지에 UserPromptSubmit 훅의 계기("이 세션의 제목을
지시문의 브랜치 이름으로 바꾼다")가 붙어 왔다. `set_session_title self`로 앱이 지은 제목("Trace detail
엔드포인트")이 묻지 않고 `feature/06-trace-detail`로 바뀌었다. 첫 줄은 전각 `／`인 채로 왔고 훅이 그것을
알아보고 스킬 파일을 읽으라고 했다. 06 일지 "다음"의 셋 중 반각 `/`로 고쳐 보낸 경로는 이번에도 재지
못했다. 사람이 고쳐 보내지 않았다.

## 결정 둘 — 프로브를 먼저 돌렸다

후보 모양이 `openapi.json`에 어떻게 찍히는지 스크래치 앱으로 먼저 봤다. 셋이 나왔다.

- 같은 판별자(`type`)를 쓰는 판별 유니온을 겹치면 pydantic이 평평한 `oneOf` 하나로 펼치고 mapping도
  하나다. `sdk`의 `Event`를 다시 나열하지 않아도 된다.
- 판별자 값이 실제 종류와 겹치면 `TypeError: Value 'run_started' for discriminator 'type' mapped to
  multiple choices`다. 앱이 서지 않는다.
- 이벤트의 `type`은 기본값이 있어서 직렬화 스키마의 required에서 빠진다. 매니페스트가 켠 설정이
  이벤트에도 필요했다.

> 사용자: (응답 모양) "객체 Trace (Recommended)"
> 사용자: (판별자 값) '"unknown" (Recommended)'

이벤트를 `sdk`의 모델 그대로 싣는 것은 매니페스트의 선례(ADR 0010의 2026-09-23 이력)를 따랐다. 그
대가(`BaseEvent`의 설정, `LlmCalled` 독스트링 한 줄화)와 함께 ADR 0010의 2026-09-24 이력으로 적었다.

> 사용자: (ADR 0010 이력 초안) "승인한다 (Recommended)"

## 테스트 먼저, 그리고 변이

빨강 열셋을 먼저 봤다. 그중 하나(없는 실행은 404)는 구현 전에도 초록이었는데, 라우트가 없어서 난
라우팅 404였다. 포트가 실제로 불렸는지(`traces.reads`)를 단언에 더해 "포트가 None이라고 답한 404"를
재게 했다. 초록 뒤 변이 일곱을 하나씩 넣었고 전부 잡혔다(직렬화 required 설정 제거, 모르는 종류 누락,
순서 뒤집기, 경로 패턴 제거, `verbatim` 제거, 부재를 500으로, 형식 버전 고정).

HTTP 이음매는 명세대로 가짜 포트로만 밀었다(스토리 54). 티켓의 "500 테스트의 손상 파일은 개행으로
끝나야 한다"는 파일로 미는 테스트를 전제한 문장인데, 그 성질(개행으로 끝나는 손상 → `PluginError`,
끝나지 않은 꼬리 → 앞 줄까지)은 `tests/adapters/test_jsonl.py`가 이미 잰다. 명세 축이 Minor로 짚었고
받아들였다.

## 셀프 리뷰

표준 축 Minor 1·Nit 3, 명세 축 Minor 3, Critical·Major 없음. 두 축이 같은 것을 짚었다. `secret_args`
불변식 테스트가 가짜 포트 이음매 파일(`tests/test_server.py`)에서 디스크를 읽는다는 것이다. 라우트
옆이라 찾기 쉬울 거라고 거기 뒀는데, `.claude/rules/admin.md`가 그 파일에 "디스크를 타지 않는다"를
걸어 두었다. 그래서 `tests/sdk/test_manifest.py`로 옮겼다. 어댑터 대신 `parse_manifest`로 저장소 파일을
읽고, mcp 매니페스트에 `secret_args`를 잠깐 넣어 빨강을 봤다.

표준 축 브리프에 "주석과 독스트링의 사실 주장이 코드와 어긋나는지 본다"를 손으로 넣었다. 리뷰어가
주장 넷을 프로브로 쟀다(import 순간의 `TypeError`, 평평한 `oneOf`, required, 한 줄 독스트링). 대기열
20이 제안한 한 줄이 효과가 있다는 근거다.

## 줄 끝 문자

리뷰 반영 중 파이썬 heredoc 스크립트가 `Path.write_text`로 테스트 파일 둘을 고쳤다. 윈도의 텍스트 모드라
작업 트리에 CRLF가 들어갔다. 커밋 때 git이 경고했고, `.gitattributes`의 `eol=lf`가 인덱스를 LF로 정규화해
커밋은 깨끗했다. 두 파일을 지우고 체크아웃해 작업 트리를 LF로 되돌렸고, 그 뒤로는 바이트로 썼다.

## 갈린 곳

- 응답 모양, 판별자 값, ADR 초안은 전부 추천대로 갔다.
- 불변식 테스트의 자리는 라우트 옆에서 매니페스트 코드 옆으로 옮겼다. 재는 것이 앱이 아니라 저장소다.
- 쓰는 중인 트레이스가 200이라는 것을 HTTP 층에서 직접 재는 테스트는 두지 않았다(스토리 54).
- `spec.md`의 "예외는 셋이고 전부 ADR 이력으로 들어갔다"(115행)는 낡았지만 두었다. 그 절은 당시 상태의
  기록이고 앞 티켓들도 고치지 않았다.
- `1ac5f85`에 CodeRabbit 리뷰를 다시 요청하지 않았다. 한도가 0이었고 바뀐 것이 독스트링과 테스트뿐이다.

- `admin/traces.py` 주석 "테스트가 그 전에 무엇이 겹쳤는지 말한다" → 틀렸다. 겹치면 모듈을 import하는
  순간 `TypeError`라 테스트 본문까지 가지 못한다. 리뷰 전에 스스로 바로잡았다.
- 없는 실행 404 테스트가 구현 전에 초록이었다 → 포트 호출 단언을 더했다.
- 불변식 테스트의 자리 → sdk 테스트로.
- 기대값 헬퍼 이름 `_wire` → `_expected_json`.
- 이벤트 셋의 독스트링 누락 → 한 줄 독스트링과 검사.

## 회고

> 사용자: (회고 판정) "2. 대기열 20에 근거 (Recommended)"

1. **보고 언어가 영어로 샜다(1회차).** 한글 비율을 보는 Stop 훅(경고만)으로 잡을 수는 있지만 코드
   식별자 때문에 거짓 양성이 나기 쉽고 1회차다. 기록만.
2. **대기열 20에 효과의 근거.** 브리프에 사실 주장을 검증하라는 한 줄을 넣으니 리뷰어가 주장 넷을
   프로브로 쟀다. 20에 적었다. 새 줄이 아니다.
3. **규칙을 적은 날 기존 멤버에 대보지 않았다.** `sdk.md`의 "이벤트 독스트링은 한 줄"을 적고 독스트링
   없는 이벤트 셋을 못 봤다. 이 세션에서 테스트로 닫았다. 교정 루프가 이미 요구하는 것이라 기록만.
4. **인계 문장이 이음매를 전제했다(1회차).** "500 테스트의 손상 파일"은 파일로 미는 테스트를 전제했는데
   명세는 HTTP 이음매를 가짜로 정했다. 기록만.
5. **윈도 `write_text`의 CRLF(1회차).** 커밋에는 피해가 없었다. 기록만.
