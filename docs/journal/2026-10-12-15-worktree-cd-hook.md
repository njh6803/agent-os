next-session 지시문으로 연 새 세션이다. 대기열 123(워크트리 밖 `cd`, 3회차)을 `chore/worktree-cd-hook` 한 PR로 반영한다.

> 사용자: (지시문의 시작 프롬프트) "대기열 123(워크트리 밖 cd 훅, 3회차)을 chore/worktree-cd-hook 한 PR로 반영한다. 184·185(카나리아 사전 확인 모드, 프로브 README canary/ 셀)를 묶을지는 이 세션이 정한다"

## 체크아웃 정리

`tidy-checkouts` 판정에서 지울 후보는 없었다. 남긴 것은 잠금 pid가 살아 있는 여섯, 병합된 PR이 없는 넷, 다시 만들 수 없는
무시된 항목(`grep.exe.stackdump`)이 든 `canary-spec-pipeline-followup`, 병합된 PR이 없는 로컬 브랜치 스물둘이다. 넘긴 것은
제목이 어느 브랜치와도 맞지 않는 실행 중 세션(`docs/admin-style-spec`) 때문에 넘긴 병합된 워크트리 셋(`review-workflow-guards`,
`rewrap-and-separator-hook`, `spec-pipeline-and-pytest-ids`), 분리 HEAD 셋, `prunable` 하나, 병합된 PR의 머리와 브랜치 끝이
다른 것 하나, 등록 없는 워크트리 폴더 여섯이다. 지시문대로 답을 기다리지 않았다.

## 184·185를 묶지 않았다

둘은 카나리아라는 같은 주제(러너 `tools/canary.py`와 그 프로브 README의 `canary/` 셀)를 공유하고, 이 PR과는 겹치는 파일이
없다. 묶으면 이 PR의 리뷰가 셸 파싱·경로 판정과 카나리아 러너의 새 모드로 갈린다. 둘을 다음 chore PR 하나로 함께 낸다.
형제 세션 둘(`chore/cwd-owner-and-review-turns`는 186·169, `chore/sibling-overlap-next-numbers`는 157·175·182)도 이 파일들을
건드리지 않는다(각 일지의 "다음"을 읽었다).

## 바꾼 것

- **새 훅 `tools/hook_bash_cd_outside.py`(PreToolUse Bash, 막는 훅).** 명령 위치의 `cd`·`pushd`·`popd`를 차례로 따라가며
  페이로드의 `cwd`에서 대상을 풀고, 풀린 자리 하나라도 `cwd`가 든 체크아웃 밖이면 막는다. 체크아웃은 `.git`이 있는 가장
  가까운 조상이거나 `.claude/worktrees/<이름>`이다. 뒤의 것은 `.git`이 없어도 따로 센다. git을 부르지 않는 것은 그런
  폴더에서 부른 git이 주 체크아웃을 루트로 읽기 때문이다. `CLAUDE_PROJECT_DIR`은 워크트리 세션에서 주 체크아웃을 가리켜
  쓰지 않았다. 서브셸·명령 치환·파이프의 한 단·`&`로 끝나는 목록의 `cd`는 작업 폴더를 남기지 않아 세지 않는다. 인용은
  같은 길이의 `_`로 가려, 구조는 가린 문자열에서 보고 인자는 같은 자리의 원문에서 꺼낸다.
- **막기를 고른 까닭.** 같은 모양이 워크트리 세션의 일지에 여섯 번 있다(2026-09-28-02, 2026-10-06-11, 2026-10-07-01,
  2026-10-07-15, 2026-10-12-06, 2026-10-12-09). 주 체크아웃으로 간 셋은 원래 저장소 루트로 cd 하지 말라는 앱의 환경 안내를
  어겼다. 스크래치패드로 간 둘은 그 안내 밖이지만 사용자가 같은 행으로 세기를 승인했다(일지 09 회고 4). 경로를 인자로 주는
  대안이 있어 막는 값은 다시 치는 한 번이다.
- **주 체크아웃 세션에도 건다.** 그 세션의 사건은 없지만 같은 cd이고, 가드가 없어 잘못 옮긴 뒤의 git이 다른 체크아웃에,
  `.git` 없는 폴더에서는 루트에 조용히 닿는다. `.claude/rules/tools.md`의 "실패가 조용하고 패턴이 고정된 것"의 예외를
  가드 없는 쪽에 넓힌 판단이다.
- **넷을 함께.** `.claude/settings.json`의 PreToolUse Bash 묶음에 래퍼 모양으로 등록했다. 테스트
  `tests/tools/test_hook_bash_cd_outside.py`(27개), `tools/hook_payloads.toml`의 사례 넷(막기 둘은 06-11·12-09의 모양,
  침묵 둘은 이 세션이 tidy-checkouts 3에서 친 명령의 모양과 서브셸 안의 cd), 변이 표
  `.scratch/harness/probes/cd_outside_hook_mutations.toml`(열넷), 시간 프로브 `cd_outside_hook_time.sh`와 그 README 행이다.
- `KICKOFF.md`의 훅 목록에 한 줄을 더했고, 대기열 123을 닫았다.

훅 시간은 등록 모양으로 첫 판 234~299ms, 셀프 리뷰 반영 뒤 244~319ms였다(시간 프로브, 이 PC, 워크트리). 같은 날 다른 훅의
시간 프로브 값(`line_separators_hook_time.sh` 233~305ms, 프로브 README)과 같은 크기다. Bash 호출마다 이만큼 붙는다.

이 세션이 받는 모양으로도 손으로 돌려 봤다. 역슬래시 `cwd`에서 `cd /c/project/agent`(주 체크아웃), 스크래치패드, 형제
워크트리, 인자 없는 `cd`, 주 체크아웃 세션에서 `.claude/worktrees/ci-parallel-jobs`(등록 없는 남은 폴더)는 막혔고, 제
워크트리의 `/c/…` 표기와 `cd web`, 주 체크아웃 세션의 루트 `cd`, cd 없는 `git -C`는 지나갔다(스크래치 스크립트,
`payloads.py`).

## 셀프 리뷰

`/code-review`(base `bd72bae`, 수정 5·미추적 4·커밋 0). `.py`가 있어 두 축 모두 기본 모델이었다. 명세는 사용자 요청, 대기열 123
행, 일지 09의 회고 4와 "다음", `.claude/rules/tools.md`의 새 훅 의무를 요구로, 184·185를 묶지 않은 결정과 막기를 고른
까닭을 참고로 붙였다. 브리프를 쓰다가 내 문장 셋을 먼저 고쳤다(사건 수 "세 번", 영어 안내를 번역해 넣은 따옴표, 테스트
독스트링의 "tidy-checkouts 판정 4 앞"). 표준 축은 Minor 4·Nit 1과 smell 하나, 명세 축은 Minor 4·Nit 1이었다. Critical·Major는
없었다.

- **고친 것.**
  - [표준 Minor 1, 명세 Minor] 독스트링의 "세지 않는 것"·"못 보는 것"이 코드와 달랐다. `cd /c/x && ls &`를 셌고(bash는 목록
    전체를 백그라운드로 돌린다), here-string `<<<`을 heredoc으로 읽어 뒤 줄을 지웠고, `2>/dev/null cd …`와 인용 없는
    `eval cd …`를 놓쳤다. 넷을 코드로 고치고 테스트와 변이를 더했다. 함수 정의(한 줄 정의는 세지 않아 부르면 놓친다),
    `case` 갈래, `$'…'` 안의 이스케이프된 따옴표, `{ cd …; } &`(거짓 양성)는 실제 동작대로 "못 보는 것"에 적었다. "드라이브
    글자의 대소문자"는 코드가 경로 전체를 가리지 않아 "대소문자"로 고쳤다.
  - [표준 Minor 2] 사건이 넷이 아니라 여섯이었다(09-28-02와 10-07-01은 대기열 122로 셌다). tidy-checkouts의 줄은 남은 워크트리
    폴더만 다뤄 12-06·09의 스크래치패드는 그 줄을 어기지 않았다. 근거를 앱의 환경 안내(주 체크아웃 셋)와 사용자 승인(스크래치패드
    둘)으로 다시 적었다.
  - [표준 Minor 3] 일지 번호 11을 main에 병합된 PR #183이 먼저 가져갔다. 12로 옮겼다가, 커밋 직전의 `tools/sibling_overlap.py`가
    형제 워크트리(`sibling-overlap-next-numbers`)의 일지 12를 알려 그 옮길 번호대로 15로 두었다. 프로브 README 두 행과 대기열
    닫힘 문구의 인용도 고쳤다.
  - [표준 Minor 5] 막기를 기대하는 테스트가 `is not None`만 봤다. 이유가 그 자리(`다른 체크아웃(<경로>)`, 체크아웃 밖의
    경로)를 대는지 단언하게 했다.
  - [명세 Minor] 이유 문장이 대안으로 `git -C <경로>`를 안내했다. 워크트리 가드가 다른 체크아웃을 겨눈 git을 거부한다(일지
    2026-10-06-12 회고 2). 안내에서 빼고 Read 도구를 넣었고, 테스트가 그 부재를 본다.
  - [명세 Minor] 훅이 보지 못한 길로 이미 다른 체크아웃에 와 있는 세션은 돌아오는 cd도 막힌다. 훅은 그 세션의 체크아웃을 알 길이
    없어 동작은 두었다. 이유 문장이 워크트리 세션의 복귀 길(`EnterWorktree(path)`)을 안내하게 하고 "이 체크아웃"을 "지금 작업
    폴더가 든 체크아웃"으로 고쳤으며, 테스트로 고정했다. 주 체크아웃 세션이 워크트리로 밀려난 경우에는 cd로 돌아올 길이 없다는
    것을 "못 보는 것"에 적었다.
  - [명세 Minor] 주 체크아웃 세션에도 거는 것이 요구 밖이라는 지적. 범위는 두고 까닭을 독스트링·`KICKOFF.md`·대기열 닫힘
    문구와 위 절에 적었다.
  - [Nit 둘] 테스트 독스트링의 사건 인용(07-15는 워크트리 세션이다, 12-06에는 grep이 없다)을 고치고 워크트리에서 남은 폴더로
    가는 테스트를 더했다. 페이로드 note는 "친 명령"을 "친 명령의 모양"으로 고쳤다.
  - [smell] `_step`이 `_verb()`를 네 번 부르던 것을 한 번으로 줄였다.
- **남긴 것.**
  - [smell Primitive Obsession] `Step`의 대상에 `~`·`-`·None 표지가 섞인 것. 단독 실행 훅 하나 안의 표지이고, 타입을 따로
