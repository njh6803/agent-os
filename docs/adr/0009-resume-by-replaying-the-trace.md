# 일시정지한 실행은 트레이스를 재생해 재개한다

사람 승인 인터럽트는 승인이 필요한 도구 호출 직전에 실행을 **끝내고**, 승인 뒤 같은 `run_id`로 에이전트를 처음부터 다시 돌리되 이미 한 모델 호출과 도구 호출은 트레이스에 기록된 값으로 대신해 그 지점까지 되돌아간 뒤 이어 간다. 승인이 필요한 도구는 에이전트 매니페스트의 `requires_approval`이 정하고, 멈추는 자리는 런타임이 소유한 루프 안이다. 프로세스 안에서 `await`로 기다리지 않는 이유는 기능의 이름이 "사람 승인"이기 때문이다. 사람이 프로세스 수명 안에 답해야 한다면 그것은 승인 게이트가 아니라 확인 프롬프트다. 재생을 고른 이유는 에이전트가 async generator라 파이썬 스택을 직렬화할 수 없고, ADR 0008이 `ctx.now()`와 `ctx.run_id`를 넣으며 "run()이 재실행 가능하려면 시각과 난수가 컨텍스트를 통해서만 들어와야 한다"고 적어 둔 결정성이 정확히 이것을 위한 활주로이기 때문이다. 저장할 곳을 새로 만들지 않는 이유는 원칙 V가 "트레이스는 이벤트를 저장한 것이지 별도 수집 층이 아니다"라고 못 박았기 때문이다.

## Considered Options

- **프로세스 안에서 `await`로 기다린다.** 체크포인터도 재개 명령도 새 포트도 필요 없고 이번 주에 끝난다. 그러나 프로세스가 죽으면 실행도 죽어 "사람 승인"이 "지금 앞에 앉아 있는 사람의 확인"으로 줄어든다. 거부했다.
- **루프의 메시지 목록만 저장하고 루프만 이어 돈다(상태 기반).** 에이전트 코드를 다시 안 돌려도 된다. 그러나 `RunFinished`를 낼 사람이 없다. 그것은 에이전트가 `ctx.llm()` 뒤에 yield하는 것이고, 런타임이 대신 지어내면 "에이전트가 `run_finished` 하나를 마지막에 낸다"는 규칙(`.claude/rules/core.md`)이 깨진다. 거부했다.
- **재생하지 않고 재개 시 모델을 실제로 다시 부른다.** 저장할 것이 없어 가장 싸다. 그러나 모델이 이번엔 다른 도구 호출을 낼 수 있어 사람이 승인한 것과 실제로 실행되는 것이 달라진다. 승인 게이트에 구멍이 나므로 기능의 목적을 잃는다. 거부했다.
- **재개 스냅샷을 별도 포트(`Checkpointer`)에 둔다.** 트레이스를 얇게 유지할 수 있다. 그러나 같은 사실이 두 곳에 남고 원칙 V와 어긋난다. 비밀 노출 문제는 스냅샷에도 도구 인자가 들어가므로 이쪽을 골라도 똑같이 존재해서 이점이 되지 않는다. 거부했다.
- **LangGraph의 `interrupt`와 체크포인터를 쓴다.** ADR 0001이 "슬라이스 2에 다시 연다"고 예약한 길이다. 2026-09-21에 같은 프로브로 재측정했고 결과가 같았다. ADR 0001의 이력에 적었다. 거부했다.

## Consequences

- **디스크 형식이 바뀐다. 트레이스 헤더 버전을 2로 올리고 버전 1 파일은 재개를 거부한다.** `LlmCalled`가 모델이 낸 텍스트와 도구 호출을, `ToolCalled`가 인자와 결과 내용을 담는다. 관찰에만 쓰이던 트레이스가 재개의 입력이 된다. 이벤트 종류 넷이 는다: `RunPaused`, `ApprovalGranted`, `ApprovalDenied`, `RunResumed`. 승인과 거부를 별도 클래스로 쪼갠 것은 거부만 사유를 갖는 비대칭이 실제로 있고 `events.py`가 "종류별 클래스, 타입 검사가 지켜 주는 쪽"을 이미 골랐기 때문이다.
- **재개는 같은 `run_id`이고 트레이스 파일 하나다.** 용어집이 실행을 "요청 하나를 처리하는 한 번"으로 정의했고 재개는 새 요청이 아니다. `run_started`는 다시 내지 않는다. 재생 구간과 실제 실행 구간의 경계가 `RunResumed`다. 재생 구간에서 **재생된 사실**은 트레이스에 다시 쓰지 않는다 — 이미 거기 있기 때문이다. 그 구간에서 **처음 생긴** 사실은 쓴다. 대조 불일치로 인한 `run_failed`가 그것이고, 그 실행은 `RunResumed` 없이 끝난다. 쓰지 않는 기준은 "재생 구간인가"가 아니라 "이미 트레이스에 있는가"다.
- **재생은 순서로 대응시키고 대조로 검증한다.** N번째 호출에 N번째 기록을 쓰되, 모델 호출의 입력 메시지와 도구 호출의 이름·인자가 기록과 다르면 `run_failed`로 끝내고 그 실행은 재개 불가가 된다. 승인을 기다리는 사이 에이전트 코드가 바뀌는 일은 개발 중에 늘 일어나고, 그때 조용히 다른 실행의 기록을 먹이는 것보다 시끄럽게 죽는 쪽이 낫다. 원칙 II의 "테스트가 실패하면 테스트를 고치지 않고 멈춰 보고한다"와 같은 판단이다.
- **`ctx.now()`는 재생 구간에서 실행의 시작 시각(`run_started.ts`)을, 그 뒤로는 실제 시각을 돌려준다.** 시계 읽기를 따로 기록하지 않고도 결정적이다. 이것이 없으면 프롬프트에 날짜를 넣는 평범한 에이전트가 대조 검증에 걸려 전부 재개 불가가 된다. `sdk/agent.py`에 명시한다.
- **포트는 다섯 그대로이고 `TraceSink`가 `TraceStore`로 바뀐다.** `read(run_id)`가 는다. 닿는 바깥 지점은 "트레이스 저장소" 하나이지 새 지점이 아니므로 포트를 더하지 않는다. `Sink`라는 이름이 쓰기 전용을 뜻해 개명한다. 쓰는 곳과 읽는 곳이 항상 같다는 사실을 타입이 강제한다. 같은 필요가 `admin-api`의 `/traces`에서도 곧 생긴다.
- **core에 `resume(run_id, decision, approver, *, 포트들)`이 는다.** `run()`의 인자로 넣지 않는 이유는 입력이 실제로 다르기 때문이다. 재개는 `agent`, `request`, `principal`을 받지 않고 트레이스의 `run_started`에서 읽는다. 내부는 `run()`과 공유한다.
- **매니페스트에 필드 둘이 는다(ADR 0008 이력).** 에이전트에 `requires_approval`, mcp `[server]`에 `secret_args`. `secret_args`를 가진 도구는 `requires_approval`에 들어갈 수 없고 매니페스트 단계에서 거부한다. 마스킹된 인자는 복원할 수 없어 승인받아 실제로 실행되는 그 호출에 `***`를 보내게 되기 때문이다. 둘 다 매니페스트에 있어 정적으로 판정된다. `requires_approval`이 실재하지 않는 도구를 가리키면 도구 연결 직후 `run_failed`로 끝낸다. 오타가 가드레일을 조용히 끄는 fail-open을 막는다.
- **원칙 V의 "이벤트에 API 키, 토큰, 비밀번호를 싣지 않는다"는 그대로 지킨다.** `secret_args`로 선언된 필드는 마스킹해 쓰고, 대조 검증에서 제외한다. 재생 구간에서 도구 인자는 쓰이지 않고 결과만 필요하므로 마스킹이 재생을 깨지 않는다. **마스킹하는 자리는 `core`가 이벤트를 만드는 지점이지 트레이스 어댑터가 아니다.** 원칙 V가 금하는 것은 이벤트에 비밀을 싣는 것이지 파일이 아니고, `secret_args`를 아는 것도 `core`다. 어댑터는 받은 것을 쓴다.
- **승인 게이트는 루프와 `ctx.tool()` 둘 다 덮는다.** 정책은 도구에 붙는 것이지 경로에 붙는 것이 아니다. 에이전트 코드는 플러그인이라 신뢰 경계 밖이고, 경로를 바꿔 빠져나갈 수 있는 가드레일은 가드레일이 아니다. `ctx.tool()`이 거부당하면 사유를 담은 `ToolError`가 난다.
- **거부는 실행을 끝내지 않는다.** `tool_called(ok=false)`로 사유를 모델에 되돌려 루프가 계속한다. 이미 있는 도구 실패 경로 그대로이고, 모델이 사용자에게 "허락을 못 받아 못 보냈습니다"라고 답할 수 있다. 모델이 다른 도구로 우회하는 위험은 거부가 아니라 정책이 막는다. 같은 일을 할 수 있는 도구는 전부 `requires_approval`에 들어가야 한다.
- **한 턴에 승인 대상이 여럿이면 첫 것에서 멈춘다.** `RunPaused`가 도구 하나만 담아 승인과 실행이 1:1이 된다. 사람을 여러 번 찾는 대가를 치른다.
- **`MAX_TURNS = 10`은 실행 전체 기준이고 재생된 턴도 센다.** 상한의 목적이 비용이 무한정 늘지 않게 하는 것인데 재개로 리셋되면 멈추고-재개를 반복해 무한히 돌 수 있다. 승인이 여러 번 끼는 긴 작업은 상한에 닿을 수 있고, 그때는 상한을 올리는 별도 결정을 한다.
- **승인자는 필수로 기록하고 자기 승인은 허용한다.** ADR 0008이 `principal`을 필수로 만든 논증 그대로다. 선택으로 두면 승인자 없는 승인이 기본값으로 굳어 fail-open이 된다. 자기 승인 금지는 지금 혼자 쓰는 CLI에서 기능 자체를 못 쓰게 하므로 정책으로 나중에 더한다.
- **이번 슬라이스의 승인 표면은 CLI뿐이다.** `agent-os resume <run_id> --approve | --deny`. 멈춘 실행의 **목록** 조회는 만들지 않는다. 용어집이 관찰을 관리(admin)의 일로 정했고 `admin-api`가 병렬 프론티어다. CLI는 멈출 때 `run_id`와 승인 요청 내용을 찍고 `run_failed`와 구분되는 전용 종료 코드로 끝낸다. 일시정지에 만료 시간은 두지 않는다.
