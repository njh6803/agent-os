# HTTP 표면은 FastAPI로 서고 `server.py` 하나가 조립한다

관리 API가 슬라이스 2의 첫 HTTP 표면이고 곧 HTTP 채널이 같은 프로세스에 붙으므로, 앱을 조립하는 자리를 지금 정한다. **FastAPI와 uvicorn을 런타임 의존성으로 더하고, `server.py`가 `create_app(*, plugins, trace, token, ...)` 하나만 내보낸다. 전역 `app` 객체를 두지 않는다.** FastAPI를 고른 이유는 `openapi.json`이 이 저장소에서 계약이기 때문이다 — 슬라이스 3의 `packages/api-client`가 그 파일에서 생성되고, `sdk`의 디스크 형식이 이미 pydantic이라 이름 있는 `$defs`가 공짜로 나온다(ADR 0008이 `StrEnum`을 고른 이유가 그것이다). 전역 `app`을 두지 않는 이유는 어댑터 주입이다. 어댑터를 만들어 넘기는 자리는 `main.py`와 `server.py`뿐이고(원칙 IV의 의존 방향), 어댑터는 자기를 스스로 조립하지 않는다(`.claude/rules/adapters.md`). 모듈 수준에서 앱을 만들면 import 시점에 `plugins/` 경로와 트레이스 디렉터리가 고정되어, 테스트가 가짜 포트 대신 진짜 파일시스템을 쓰게 된다.

## Considered Options

- **Starlette만 쓴다.** 의존성이 가볍고 FastAPI의 마법이 없다. 그러나 OpenAPI 문서를 손으로 조립해야 하고, 그 문서가 계약이라 손으로 쓴 스키마와 실제 응답이 어긋날 자리가 생긴다. 생성 클라이언트가 기대는 이름 있는 `$defs`도 직접 만들어야 한다. 거부했다.
- **모듈 수준 전역 `app`을 둔다.** `uvicorn agent_os.server:app`으로 바로 뜨고 배포가 단순하다. 그러나 어댑터를 넘길 자리가 없어져 조립 층이 둘로 갈리고, import 시점에 경로가 고정된다. 거부했다.
- **성공 응답도 봉투로 감싼다.** 모든 응답에 추적 식별자가 본문에 실린다. 그러나 생성 클라이언트가 매번 `.data`를 벗겨야 하고 OpenAPI 스키마가 두 겹이 된다. 프론트 규칙이 이미 "공용 apiClient만 쓰고 data만 반환"이라 벗기기를 클라이언트 쪽에 두라고 말한다(일지 2026-09-19의 프론트 규칙 분석). 거부했다.
- **설정 파일(`agent-os.toml`)로 서버 설정을 모은다.** 값이 늘어도 명령줄이 길어지지 않는다. 그러나 새 디스크 형식이라 `schema_version`과 ADR이 또 필요하고, 지금 값이 넷뿐이다. 거부했다.

## Consequences

- **`tech.md` 스택 표에 웹 프레임워크 행이 는다.** 런타임 의존성이 넷에서 여섯이 된다(`fastapi`, `uvicorn`). 의존성 추가는 ADR을 남긴다는 규약을 이 문서가 만족한다.
- **import-linter 계약의 `(agent_os.server)` 층이 실물이 된다.** 지금은 선택 층으로 선언만 돼 있고 파일이 없다. `server.py`가 생기는 순간 `main → server → {channel | admin | adapters} → core → sdk`가 실제로 판정된다. 채널과 관리는 서로를 import하지 않고 `server.py`가 라우터 둘을 마운트한다. 이번에는 관리 라우터만 있고 `http-channel`이 `/runs`를 더한다.
- **에러만 봉투로 감싼다.** `{code, message, violations, request_id}`. 성공 응답은 생값이고 추적 식별자는 `X-Request-Id` 헤더로 나간다. 예외를 HTTP 상태 코드로 옮기는 표는 `admin/http` 한 곳에 둔다 — 부재(포트가 `None`을 돌려준 것)는 404, `PluginError`는 **500**. 부재가 이미 404로 갈리므로 `PluginError`에 남는 것은 "서버 디스크의 매니페스트가 깨졌거나 읽을 수 없다"뿐이고, 그것은 클라이언트가 재요청으로 고칠 수 있는 일이 아니다. 4xx를 돌려주면 관리 화면이 "잘못 요청했다"고 표시해 운영자가 깨진 파일을 못 찾는다. 경로와 질의 파라미터의 형식 오류(없는 `kind` 등)는 그대로 FastAPI가 422로 내며 그것이 422의 제자리다. `core`의 예외는 상태 코드를 모른다.
- **`main.py`에 `agent-os serve`가 는다.** `--host`(기본 `127.0.0.1`) `--port` `--traces` `--plugins-root`. 비밀만 환경변수이고, 루프백이 아닌 주소는 받지 않는다. 둘 다 ADR 0011. `--plugins-root`가 생기면서 지금 `main.py`에 `PLUGINS_ROOT = Path("plugins")`로 하드코딩된 것이 `run`·`resume`에서도 풀린다.
- **`openapi.json`이 저장소 루트에 커밋된다.** 생성기는 `tools/export_openapi.py`, 최신성은 pytest 하나가 `create_app().openapi()`와 파일을 비교한다. 검사 명령 넷이 그대로 게이트이므로 새 훅을 만들지 않는다. 계약 파일이 하나 더 생기는 것이라 이후 `sdk`와 같은 무게로 다룬다.

## 이력

### 2026-09-22 테스트 클라이언트는 httpx이고 dev 의존성으로 선언한다

`admin-api` 명세를 쓰며 열렸다. 이 문서는 런타임 의존성 둘(`fastapi`, `uvicorn`)만 셌는데,
`create_app()`이 만든 앱에 요청을 넣어 보는 지점이 그 기능의 주 이음매라 그것을 미는 클라이언트가
함께 필요하다. **`httpx`의 `AsyncClient`와 `ASGITransport`를 쓰고 dev 의존성으로 선언한다.**

`fastapi.testclient.TestClient`도 같은 `httpx`를 요구하는데 동기 API라 내부에 포털을 띄운다. 이
저장소의 비동기 테스트는 `asyncio_mode = "auto"`에서 `async def`로 쓰므로(ADR 0007) 관리 쪽에만
다른 모양의 테스트가 생긴다. 클라이언트를 손으로 짜는 안은 거부했다 — HTTP 왕복을 짜는 그 코드가
곧 자기는 테스트되지 않는 두 번째 클라이언트가 된다.

`httpx`는 이미 `mcp` 뒤에서 락파일에 있다. 그래도 선언하는 이유는 전이 의존성에 기댄 테스트가 그
전이 경로가 바뀌는 날 조용히 깨지기 때문이다. 선언 자체가 결정인 자리는 ADR 0007이 dev 전용
`pytest-asyncio` 하나를 위해 문서를 남긴 것과 같다. `tech.md`가 "의존성을 추가하려면 ADR을
남긴다"고 적었고 dev 의존성도 예외가 아니다. 스택 표의 테스트 행에 같이 적는다. **런타임 의존성은
여섯 그대로다.**

### 2026-09-22 모르는 이벤트는 판별자를 달고 트레이스 상세에 실린다

`admin-api`의 티켓을 쪼개며 열렸다. 이 문서는 에러 봉투와 상태 코드까지 정했지만 `GET /traces/{run_id}`의
본문이 무엇인가는 열어 두었다. `Trace.events`의 타입이 이미 `tuple[Event | UnknownEvent, ...]`이므로 그
열을 그대로 내보내느냐 걸러 내보내느냐가 응답 배열의 항목 스키마를 정하고, 그것이 `openapi.json`에 박힌다.

**원문을 들고 있는 그대로 싣는다.** ADR 0012의 표지 이력이 `UnknownEvent`를 선례로 들며 쓴 문장이 그대로
근거다 — "읽는 쪽이 모르는 것을 지우지 않고 들고 있게 한다". HTTP도 읽는 쪽이다. 빼면 화면이 "이벤트를
쓴 순서 그대로 전부"에 대해 거짓말을 하고, `core`의 재개 진입점이 모르는 이벤트가 하나라도 있으면 재개를
거부하므로 화면이 보지 못한 그 줄이 곧 재개 불가의 원인이 된다.

**이 결정의 내용은 표지에 판별자 값을 붙이는 것이다.** `Event`는 `type`으로 갈리는 판별 유니온인데
`UnknownEvent`는 판별자 없이 원문 하나를 드는 타입이다. 판별자 없이 합치면 생성 클라이언트가 그 항목을
갈라낼 수 없다. 그 값은 실제 이벤트 종류와 충돌하지 않아야 한다. **원문은 문자열 그대로 둔다** —
`raw`는 JSON 줄 하나를 담은 문자열이지 파싱된 값이 아니므로, 그것을 펼쳐 최상위에 판별자를 얹지
않는다. 원문이 이미 그 이름의 필드를 들고 있으면 덮어쓰게 되고, 배열이나 스칼라에는 얹을 자리가
없다. 표지는 판별자와 원문 문자열을 나란히 든 봉투다. **디스크 형식은 바뀌지 않는다.**
`UnknownEvent`는 쓰이는 타입이 아니라 읽기 결과이고 트레이스에는 언제나 원래의 그 줄이 있다. 바뀌는
것은 API 표현뿐이다.

노출은 새로 늘지 않는다. 그 줄의 원문은 같은 응답이 이미 마스킹 없이 내보내는 트레이스의 일부이고,
경계는 ADR 0011의 인증이다.

### 2026-09-23 `--port`의 기본값은 8000이다

티켓 03을 구현하며 열렸다. 이 문서의 `serve` 인자 줄이 `--host`의 기본만 적고 `--port`는 이름만
적었는데, "운영자가 `agent-os serve`를 치면 관리 API가 루프백에 선다"가 그 티켓의 문장이라
기본값이 없으면 그 문장이 성립하지 않는다. **uvicorn 자신의 기본값인 8000을 쓴다.** 지어낸 숫자를
하나 더 문서화하지 않아도 되고, `uvicorn`으로 직접 띄울 때와 같은 포트라 운영자가 두 경로에서
다른 숫자를 외우지 않는다.

8000이 dev 서버가 가장 많이 다투는 포트라는 것이 비용이고, 그때 답은 `--port`다. 슬라이스 3의
관리 화면(Next.js 3000)과는 겹치지 않는다.

기본값을 두지 않고 `--port`를 필수로 만드는 안은 거부했다. 결정 자체는 없어지지만 `agent-os serve`
만 친 운영자가 인자 오류(종료 코드 2)를 받게 되어, 구성 오류를 시작 자리에서 사람 말로 끝낸다는
이 명령의 성격과 어긋난다.

### 2026-09-23 플러그인 응답은 `sdk`의 매니페스트 그대로다

티켓 04를 구현하며 열렸다. 이 문서는 성공 응답을 봉투로 감싸지 않는다는 것까지 정했고, `GET /plugins`와
`GET /plugins/{kind}/{name}`이 내보내는 매니페스트가 `sdk`의 타입 그대로인지 API 쪽 별도 타입인지는 열어
두었다.

**`sdk`의 `PluginManifest`를 그대로 응답 타입으로 쓴다.** 운영자 스토리가 요구하는 것이 "매니페스트를
통째로"이고, 별도 타입은 같은 필드 목록을 두 곳에 두어 매니페스트에 필드가 느는 날 API 쪽이 조용히
뒤처진다. 그 대가로 매니페스트의 `schema_version`과 이름 패턴이 `openapi.json`에 박히고, `plugin-toggle`이
매니페스트 계약을 바꾸는 날 계약 파일이 같은 PR에서 함께 바뀐다. 그것이 조용히 지나가지 않는 것은
최신성 테스트가 보장한다. 둘이 같은 것을 말하므로 함께 바뀌는 것이 맞다.

**직렬화 스키마에서는 기본값 있는 필드도 required다.** 서버는 매니페스트의 필드를 언제나 전부 싣는데
pydantic은 기본값이 있는 필드를 JSON 스키마의 required에서 빼므로, 그대로 두면 생성 클라이언트가
`requires_approval`을 선택 필드로 받는다. 이 티켓이 보이려는 바로 그 필드다. `PluginManifest`와
`McpServer`에 `json_schema_serialization_defaults_required`를 켠다. 디스크 형식도 검증도 바뀌지 않고
바뀌는 것은 직렬화 쪽 JSON 스키마뿐이다. 에러 봉투의 `violations`에 기본값을 두지 않은 것과 같은
이유다.

**목록의 항목은 매니페스트와 표지의 유니온 `PluginRow`이고 판별자가 없다.** 매니페스트에는 행을 가를
필드가 없고 붙이려면 디스크 형식을 바꿔야 한다. 둘은 required 필드로 갈린다 — 표지만 `reason`을,
매니페스트만 `schema_version`과 `version`을 들고 둘 다 `additionalProperties: false`다. 유니온에 이름을
붙여 생성 클라이언트가 익명 타입을 받지 않게 한다. 트레이스 상세의 모르는 이벤트에 판별자를 단 위의
이력과 다른 것은, 거기서는 합쳐질 쪽이 이미 `type` 판별 유니온이라 판별자 없는 멤버가 끼면 갈라낼 수
없었기 때문이다. 표지는 core의 `UnreadableManifest`를 관리 쪽 모델로 옮긴 것이다. core의 독스트링은
논증이라 그대로 계약의 설명이 되면 주석을 다듬는 것이 계약 변경으로 보인다.

API 쪽 별도 타입은 거부했다. 계약이 디스크 형식에서 풀리고 판별자를 달 수 있지만, 필드 목록이 두 곳이
되어 "통째로"가 손으로 지키는 약속이 되고 그 약속을 지키려면 두 타입의 필드를 대조하는 테스트가 또
필요하다. `plugin-toggle`이 켜짐 여부를 매니페스트에 더하면 운영자는 그것을 여기서 봐야 하므로 어차피
계약이 바뀐다.

### 2026-09-24 트레이스 상세는 객체이고 이벤트는 `sdk`의 것 그대로다

티켓 06을 구현하며 열렸다. 위의 2026-09-22 이력은 모르는 이벤트에 판별자를 달아 싣는다는 것까지
정했다. 응답 본문이 배열인지 객체인지, 이벤트가 `sdk`의 타입 그대로인지, 판별자 값이 무엇인지는 열어
두었다.

**본문은 `Trace {run_id, schema_version, events}` 객체다.** core의 `Trace`와 필드가 같고 대조 테스트가
둘을 맞춘다. 배열을 거부한 이유는 둘이다. 하나는 필드를 더하는 날 배열을 객체로 바꾸는 것이 파괴적
변경이라는 것이다. 슬라이스 3의 클라이언트가 여기서 생성되므로 ADR 0012가 페이지네이션을 미루지 않은
논증이 그대로 적용된다. 다른 하나는 배열에는 형식 버전을 실을 자리가 없다는 것이다. 그러면 목록을
거치지 않고 상세로 곧장 들어온 화면이 "이 실행은 재개할 수 없다"를 말하지 못한다. 목록의 `TracePage`와
같이 이것은 봉투가 아니라 이 자원의 모양이다. 이 문서가 거부한 봉투는 모든 응답에 같은 겉을 씌우는
것이다.

**이벤트는 `sdk`의 모델 그대로 싣는다.** 매니페스트를 그대로 쓴 위 이력과 논증이 같다. 별도 타입을
두면 필드 목록이 두 곳이 되어, 이벤트에 필드가 느는 날 API 쪽이 조용히 뒤처진다. 대가도 같다. 이벤트의
독스트링이 `openapi.json`의 설명이 되므로 한 줄로 쓰고 논증은 `#` 주석에 둔다. 기본값 있는 필드가
스키마의 required에서 빠지지 않게 `BaseEvent`에 `json_schema_serialization_defaults_required`를 켠다.
판별자 `type`도 기본값이 있어서, 켜지 않으면 생성 클라이언트가 갈라낼 그 필드를 선택으로 받는다. 디스크
형식도 검증도 바뀌지 않는다. 이제 이벤트의 종류나 필드를 바꾸는 PR은 `openapi.json`도 함께 바꾼다.

**모르는 종류의 판별자 값은 `unknown`이다.** 이벤트 종류의 이름은 전부 `run_started`처럼 명사와
과거분사를 이은 꼴이라 이 값은 그 꼴에 들지 않는다. 상세의 유니온은 `sdk`의 `Event`에 표지 하나를
더한 것이다. 판별자가 같으므로 pydantic이 평평한 `oneOf` 하나로 펼치고, 종류가 늘면 상세도 저절로 는다.
값이 겹치면 모듈을 import하는 순간 pydantic이 `TypeError`를 내 앱이 서지 않는다. 테스트는 두 가지를
요구로 적는다. 판별자 값이 실제 종류와 겹치지 않는다는 것, 그리고 상세의 유니온이 `sdk`의 종류를 하나도
빠뜨리지 않는다는 것이다.

### 2026-09-24 채널이 붙으며 앱의 인자와 에러 어휘가 는다

`http-channel` 설계 인터뷰에서 정했다. 채널의 모양은 ADR 0014, 인증은 0015, 공용 배관의 자리는 0016이다.
여기에는 이 문서가 정한 것 가운데 바뀌는 것만 적는다.

**에러 코드 어휘가 다섯이 된다. `conflict`가 409다.** 재개할 수 없는 실행(일시정지 아님, 형식 1)에 결정을
보낸 것이다. 부재가 아니라 상태가 요청과 맞지 않는 것이고, 422는 경로와 질의와 본문의 형식 오류라는 제자리가
있다. 관리 라우트는 이 코드를 내지 않는다. 어휘를 늘리는 것은 계약 변경이라 여기 적는다.

**표가 core의 `PluginError` 하위 타입을 MRO로 옮긴다.** 부재는 404, 재개 불가는 409, `PluginError` 자체는
여전히 500이다. 관리 쪽 부재는 그대로 포트의 `None`을 라우트가 404로 말한다. core가 상태 코드를 모른다는
문장은 그대로다 — 타입만 갈리고 번역은 표 한 곳이다.

**`create_app`이 모델과 도구와 시계 포트, 채널 토큰을 받는다.** "`create_app`은 도구 포트를 받지 않는다"는
"관리 라우터는 도구 포트를 받지 않는다"로 좁아진다. 조회 하나가 MCP 서버를 띄우는 길을 닫던 것은 앱이 아니라
관리 라우터의 시그니처였고, 그 성질은 그대로다.

**`serve`에 `--model`이 는다.** CLI와 같은 규칙(`--model` > `AGENT_OS_MODEL` > 기본값)으로 시작 때 한 번 푼다.
`main.py`가 적은 "serve 를 먼저 가르는 이유는 관리 API 가 읽기 전용이라 모델이 필요 없기 때문이다"는 더 이상
사실이 아니다.

**앱의 제목과 설명이 관리 API에서 관리와 채널을 함께 말하는 것으로 바뀐다.** 지금의 제목과 설명은 "읽기
전용이고 실행을 일으키지 않는다"고 말해서 채널이 붙는 순간 거짓이 된다. 계약 파일의 머리가 바뀌므로 같은 PR에서
`openapi.json`이 함께 바뀐다.

**스트림의 항목은 `sdk`의 `Event`이고 트레이스 상세의 `TraceEvent`가 아니다.** 스트림은 이 런타임이 방금 낸
이벤트라 모르는 종류의 표지(`unknown`)가 들 자리가 없다. 계약에는 지금 이름 있는 `Event`가 없고(멤버 아홉과
`TraceEvent`만 있다) 항목 스키마를 어떤 이름으로 싣는지는 명세가 정한다. 멤버는 두 유니온이 같은 컴포넌트를
가리킨다.

### 2026-09-26 관리가 첫 쓰기 경로를 갖고 플러그인 응답은 감싼 행이 된다

`plugin-toggle` 설계 인터뷰에서 정했다. 켜짐의 자리는 ADR 0017이다.

**`PUT /plugins/{kind}/{name}/enabled`가 관리의 첫 쓰기 경로다.** 본문은 `{"enabled": bool}`이고 답은 204다.

- 멱등이라 이미 꺼진 것을 꺼도 204다.
- 본문을 불린 하나가 아니라 객체로 둔다. 필드를 더하는 날 가산 변경으로 남기 위해서다.
- `plugin.toml`이 없는 (kind, name)은 404, 경로 형식 오류는 422, 운영자 파일 손상은 500이다.
- 매니페스트가 깨진 플러그인도 끌 수 있다. 키는 이름이지 매니페스트가 아니다.

204인 이유는 마지막 줄에서 나온다. 갱신된 행을 돌려주면, 깨진 매니페스트를 끈 직후의 응답이 표지가 되어
단건 GET(500)과 모양이 갈린다.

거부한 모양은 둘이다. `PATCH /plugins/{kind}/{name}`은 매니페스트 필드도 고칠 수 있는 것처럼 읽혀서
거부했다. 동사 경로 둘(`/disable`, `/enable`)은 멱등성이 메서드에 드러나지 않아서 거부했다.

`{name:verbatim}`은 슬래시까지 잡는다. 그래서 GET 쪽에서 `.../calc/enabled`는 이름 `calc/enabled`로 맞은 뒤
패턴 검사가 422로 거른다. 이름 패턴에 슬래시가 없으므로 모호함은 없다.

인증은 바뀌지 않는다. 미들웨어의 기본값이 관리 토큰이라 새 경로는 저절로 그 뒤에 선다(ADR 0011 이력).

**플러그인 응답은 감싼 행이 된다.** 위의 2026-09-23 이력("플러그인 응답은 `sdk`의 매니페스트 그대로다")을
이만큼 개정한다.

- 행의 겉은 `kind`, `name`, `enabled`다.
- 읽히는 행은 `manifest`에 sdk의 `PluginManifest`를 그대로 담고, 표지 행은 `reason`을 든다.
- 두 행은 여전히 required 필드(`manifest`와 `reason`)로 갈린다.
- 단건 `GET /plugins/{kind}/{name}`도 읽히는 행을 돌려준다.

위 이력의 논증은 `manifest` 안에서 그대로 선다. 매니페스트를 sdk 타입 그대로 실으므로 필드 목록이 두 곳이
되지 않는다. 바뀌는 것은 매니페스트가 응답의 전부가 아니게 된다는 점 하나다.

거부한 안은 둘이다.

- **`PluginManifest`를 상속해 `enabled`를 더한 평평한 타입.** 필드는 물려받으므로 두 곳이 되지 않는다.
  그러나 계약을 읽는 사람에게 `enabled`가 `plugin.toml`의 필드처럼 보인다. ADR 0017이 파일을 가른 이유가
  계약에서 되살아난다.
- **꺼진 목록을 따로 내는 경로.** ADR 0012가 `/traces/paused`를 거부한 이유("상태는 요약의 한 필드이지 다른
  자원이 아니다")가 그대로 걸린다.

계약을 쓰는 소비자(web-admin)가 아직 없으므로, 모양을 바꾸는 비용은 지금이 가장 싸다.

**표에 `Disabled` 행이 409로 는다.** 어휘는 다섯 그대로다. 지금은 승인 경로만 409를 문서화하는데, 이제
`POST /runs`의 문서화된 에러에도 409가 는다.
