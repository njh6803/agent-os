# 플러그인의 진실의 원천은 파일시스템이다

관리 화면이 생기면 "등록"이 어디에 기록되느냐가 문제가 된다. `plugins/` 디렉터리와 매니페스트를 유일한 원천으로 두고, 관리 API와 화면은 그 파일을 읽고 쓰는 클라이언트로 만든다. DB는 색인과 권한에만 쓴다. (바뀜: ADR 0042) 선행 저장소 둘은 DB 레지스트리부터 시작해 화면과 마이그레이션이 실행 루프보다 먼저 자랐다. 파일이 원천이면 화면이 없어도 시스템이 돌고 git이 이력을 가진다. 멀티테넌시는 테넌트별 `plugins/` 루트로 시작한다.

## 이력

### 2026-11-04 트레이스·운영 설정·평가 표는 DB로 가고, 다중 인스턴스의 플러그인 디렉터리는 공유 볼륨이다

ADR 0042가 정했다. 묶음 ② 18이 트레이스 저장소를 PostgreSQL 어댑터로 바꾸고, 묶음 ② 12의 운영 설정 표와 묶음 ④ 14의 평가
표도 PostgreSQL이다. 그래서 위 본문의 "DB는 색인과 권한에만 쓴다"는 거짓이 되어 포인터를 달았다. 플러그인 디렉터리와 매니페스트가
원천인 것은 그대로다. 묶음 ⑤ 5의 다중 인스턴스에서 플러그인 디렉터리와 운영자 파일은 배포의 몫(공유 볼륨이나 같은 이미지)이고,
쓰는 기능(관리 화면 CRUD, 마켓플레이스 설치, 업로드)은 공유 볼륨이 전제다. 테넌트별 `plugins/` 루트는 그대로이고 멀티테넌시는
미룬 것이다(PRD).
