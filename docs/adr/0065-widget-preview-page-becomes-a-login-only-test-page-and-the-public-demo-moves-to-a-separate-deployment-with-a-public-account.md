# 위젯 미리보기 페이지는 로그인해야 여는 위젯 테스트 페이지가 되고, 공개 데모는 공개 계정을 둔 따로 띄운 배포로 옮기며, 위젯 관리 화면은 양식 옆에 저장 전 위젯을 그린다

ADR 0064 결정 "'테스트' 메뉴와 공개 주소"는 위젯 관리 화면의 "테스트" 메뉴가 위젯 미리보기 페이지를 새 탭으로 열고, 그 페이지는 주소를 아는 누구나 여는 페이지로 남는다고 정했다. 대가로 저장하기 전의 설정을 운영자만 미리 볼 수는 없다고 적었다. portal-admin의 화면 그리기(일지 2026-11-16-0025)에서 사용자가 그 결정을 다시 열었다. 위젯 설정 화면 사례 다섯의 공개 도움말 문서를 세션이 맡긴 서브에이전트가 읽은 결과(화면은 보지 않았다. 다섯 가운데 Intercom, Crisp, Chatbase 셋의 문서가 설정 화면에서 저장 전 모양을 보인다고 적는다)를 보고, "양식 옆에 저장 전 위젯 그림 두기로 하고 이걸 미리보기 페이지로 하자. 테스트는 말 그대로 테스트 해보는 곳으로. 공개된 미리보기 페이지는 없고. 공개 계정을 하나 주는건 어때"라고 답했다. 그 답이 공개 데모와 사내 로그인 두 계획에 닿는다는 것을 풀어 보인 뒤 다시 묻자 "로그인 없이 쓰는 페이지를 없애고 공개 계정을 줄껀데. 실제 운영할 서버랑 공개용 서버랑 따로 올릴꺼야. 그래서 공개 계정으로 전부 사용해 볼 수 있게."라고 했고, 이 세션에서 정하기를 골랐다. 후속 질문에서는 직원이 질문하는 자리로 "테스트 페이지에 회사 로그인 문도 둠"을, 공개 계정을 막는 방법으로 "따로 막지 않음"을 골랐다. **위젯 관리 화면의 사이트 화면은 양식 옆에 저장하지 않은 값으로 그린 위젯(미리보기)을 둔다. 위젯 미리보기 페이지는 위젯 테스트 페이지로 이름을 바꾸고 로그인해야 연다. 들어오는 문은 운영자 계정과 회사 로그인 둘이다. 로그인하지 않은 사람에게는 사이트 목록도 사이트 토큰도 내지 않는다. 공개 데모는 실제 운영할 배포와 따로 띄운 공개용 배포에서, 이름과 비밀번호를 공개한 운영자 계정 하나(공개 계정)로 제품 전부를 써 보게 한다. 공개 계정은 관리자 단계이고 따로 막지 않는다.** Agent OS의 계약(`sdk`, `openapi.json`, 사이트 파일의 형식, 사이트 토큰의 주장)은 바뀌지 않는다.

이 ADR의 "미리보기"는 사용자가 "미리보기 페이지"라고 부른, 양식 옆의 저장 전 위젯 그림이다. 질문의 답과 고른 안의 설명은 일지 2026-11-16-0025의 "방향", "위젯 미리보기 페이지를 다시 묻기", "후속 질문 둘"에 글자 그대로 있다.

## 결정

- **미리보기.** 위젯 관리 화면에서 사이트 하나를 고치는 화면은 양식 옆에 지금 고친 값으로 그린 위젯을 둔다. 저장하지 않은 값으로 그리고, 질문을 보내지 않으며, Agent OS에도 위젯 관리 서버에도 묻지 않는다. 운영자는 로그인 전 모양, 고지 전문, 만료 알림, 밝기처럼 위젯이 그리는 상태를 바꿔 가며 본다. 그리는 방법은 위젯 앱의 화면 부품을 `web/packages/` 아래의 공유 패키지로 옮겨, 위젯 앱과 위젯 관리 화면이 같은 부품을 쓰는 것이다. 앱 사이의 import는 판정자가 막는다(`web/eslint.config.mjs`의 "앱 사이에서 import 하지 않는다. 함께 쓸 것은 packages/ 로 옮긴다"를 읽었다). 실제 위젯 페이지를 품어 저장 전 값을 창 사이의 메시지로 넘기는 안은 고르지 않았다(Considered Options). 추천은 "두지 않고 저장 뒤 '테스트'로 보기"였고, 사용자는 선택지를 누르지 않고 'Other'에 직접 써서 "양식 옆에 저장 전 위젯 그림 두기"로 하자고 답했다(머리의 인용). 부품을 옮기는 일은 portal-admin이 맡는다. 그 행은 이미 widget-login-state를 기다리므로, 위젯이 로그인 상태와 고지와 밝기 스위치의 화면을 지은 뒤에 옮긴다. 대가는 셋이다. 위젯 앱의 코드가 패키지로 움직인다. 미리보기와 실제 위젯이 다른 것이 입력(저장 전 값, 미리 정한 예시 대화)뿐이도록 지켜야 한다. 그리고 미리보기는 실제로 답이 오는지, 로그인이 되는지는 보여 주지 못해 그것은 위젯 테스트 페이지에서 본다. 옮기는 데 얼마나 드는지는 어림이고 재 보지 않았다. (바뀜: 이력 2026-11-16 "위젯 테스트 페이지의 서버도 화면이 부른 갱신만 전하고, 미리보기는 옮긴 부품을 고치지 않고 감싼 요소로 가린다")
- **위젯 테스트 페이지.** 위젯 미리보기 페이지(ADR 0050)를 위젯 테스트 페이지로 부르고, 로그인해야 연다. 위젯 관리 화면의 메뉴 글자 "테스트"와 새 탭으로 여는 것은 ADR 0064 그대로다. 들어오는 문은 둘이다.
  - 운영자 계정. 관리 화면에 로그인한 그대로 들어온다. 위젯 테스트 페이지의 서버가 받은 운영자 로그인 쿠키를 Agent OS의 "지금 누구인지"와 "갱신" 경로에 전해 확인한다. 위젯 관리 서버가 하는 방식(ADR 0064 결정 "로그인")과 같고, 부르는 경로도 그 둘뿐이며, 쿠키를 저장하거나 기록하지 않는다. (바뀜: 이력 2026-11-16 "위젯 테스트 페이지의 서버도 화면이 부른 갱신만 전하고, 미리보기는 옮긴 부품을 고치지 않고 감싼 요소로 가린다") 운영자는 모든 사이트를 시험한다. 익명 사이트에서는 지금처럼 고지를 확인한 뒤 익명 식별자로 토큰을 받고, 로그인 사이트에서는 회사 로그인을 거친다.
  - 회사 로그인. 로그인 서버 항목(ADR 0059)으로 로그인한 사람이다. 로그인 모드 사이트에서 질문한다(고른 선택지의 설명).

  어느 문으로도 들어오지 않은 브라우저에는 사이트 목록도 사이트 토큰도 내지 않고 들어오는 문만 보인다. 사용자가 "테스트 페이지에 회사 로그인 문도 둠"을 골랐다. 운영자의 문은 portal-admin이, 회사 로그인의 문은 portal-login이 짓는다. 로그인하지 않은 사람을 막는 것은 운영자의 문과 함께 portal-admin이 들인다. 그 전에 운영자를 막으면 운영자가 시험할 길이 없기 때문이다. 그때까지 그 페이지는 지금처럼 열린다. 회사 로그인으로 들어온 사람에게 어느 사이트를 보일지(둘 다 사이트도 보일지를 포함한다), 들어오는 문의 화면, 로그인 서버 항목이 여럿일 때 문에 무엇을 둘지는 두 행 가운데 뒤에 끝나는 행의 명세가 정한다. 대가는 셋이다. "테스트"라 부르는 페이지가 직원이 질문하는 자리이기도 하다. 운영자의 로그인 쿠키를 Agent OS에 전하는 프로그램이 Agent OS 밖에 둘(위젯 관리 서버, 위젯 테스트 페이지의 서버)이 된다. 그리고 그 둘째는 방문자용 포트의 서버다(Consequences "신뢰와 노출").
- **익명 모드는 남는다.** 위젯을 자기 페이지에 붙인 사이트는 지금처럼 익명 모드를 고른다. 바뀌는 것은 위젯 테스트 페이지가 로그인하지 않은 사람에게 토큰을 내지 않는다는 것뿐이고, 사이트의 보증 모드 셋(익명, 로그인, 둘 다)은 그대로다.
- **공개 데모.** 로그인 없이 묻는 공개 페이지를 없앤다. 공개 데모는 실제 운영할 배포와 따로 띄운 공개용 배포다. 이름과 비밀번호를 공개한 운영자 계정 하나(공개 계정)로 관리 화면, 위젯 관리 화면, 위젯 테스트 페이지를 모두 써 보게 한다. 처음 설명한 안("질문만 하고 설정은 못 고친다")과 달리 사용자가 'Other'에 "공개 계정으로 전부 사용해 볼 수 있게"라고 답했다. 공개 계정은 관리자 단계(ADR 0062)이고 따로 막지 않는다. 추천은 "비밀번호는 못 바꾸게, 정해진 때 처음 상태로"였고 사용자가 "따로 막지 않음"을 골랐다. 그래서 ADR 0062의 단계와 권한과 비밀번호의 결정은 바뀌지 않는다. 바뀌는 것은 "계정은 사람마다 하나다"에 공개용 배포의 공개 계정이라는 예외가 하나 생기는 것이다(Consequences "다른 ADR").

  대가는 공개 계정을 아는 누구나 관리자의 일을 모두 한다는 것이다. 질문은 그 계정이 플러그인을 끄거나 위젯 설정을 바꾸거나 자기 비밀번호를 바꿀 수 있고, 비밀번호를 바꾸면 다른 사람의 로그인이 모두 끊긴다고 적었다. 고른 선택지의 설명은 "누가 비밀번호를 바꾸면 다른 방문자는 로그인하지 못하고, 시스템 관리자가 비밀번호 링크를 만들어 계정을 되찾습니다. 바꿀 것이 없지만 데모가 자주 막힐 수 있습니다."였다. 바꾼 설정은 다음 방문자도 그대로 본다. 사용자가 고를 때 질문에 없던 대가가 다섯 더 있고, 이 초안을 쓰며 찾았다.
  1. 틀린 비밀번호를 일부러 거듭 넣어 그 계정을 잠근다. 연속 다섯 번이면 1분이고, 그 뒤 틀릴 때마다 두 배가 되어 최대 1시간이다(ADR 0062 결정 "잠금과 실패 문구"). 계정이 하나라 잠긴 동안 아무도 공개 데모에 로그인하지 못한다.
  2. 트레이스(`GET /traces`)에서 다른 방문자가 한 질문과 받은 답을 모두 본다.
  3. 관리 화면의 대화로 운영자 쪽 실행을 일으키고, 그 실행이 묻는 승인도 스스로 내린다. 최종 사용자 경로의 상한은 운영자 쪽 실행에 걸리지 않는다(ADR 0063 결정 "쓰는 경로").
  4. 꺼 둔 플러그인을 켠다(`PUT /plugins/{kind}/{name}/enabled`). 규칙 파일의 deny에 적지 않은 도구는 묻는 것이 기본이라(ADR 0046 이력 2026-11-06의 "공개 인터넷에 먼저 선다"), 켠 플러그인의 도구를 대화에서 스스로 승인해 쓸 수 있다. 이것은 문서를 읽고 이은 어림이고 재 보지 않았다.
  5. 위젯 테스트 페이지 설정(사이트의 발급자와 보증 모드)도 바꾼다. 발급자를 사이트 파일에 없는 값으로 고치면 그 사이트가 닫힌다(ADR 0064 결정 "시작 검사가 가는 자리").

  이 가운데 셋째와 넷째, 그리고 공개 계정이 관리 화면을 쓴다는 것 자체가 공개 데모가 지금 적어 둔 약속과 부딪친다(Consequences "공개 데모의 비용과 도구").
- **이름.** 용어집(`CONTEXT.md`)의 "위젯 미리보기 페이지"를 "위젯 테스트 페이지"로, "위젯 미리보기 페이지 설정"을 "위젯 테스트 페이지 설정"으로 바꾸고, "미리보기", "공개 계정"을 더하며, "공개 데모"의 뜻을 고친다. 메뉴 글자 "테스트"만으로는 이 저장소의 자동 시험(테스트)과 섞이므로(ADR 0064 결정 "'테스트' 메뉴와 공개 주소"가 적은 대가) 용어는 "위젯"을 앞에 붙인다. 코드 이름 `portal`과 경로 `/portal/`은 그대로다. 용어집 밖의 살아 있는 문서(규약 문서, 스킬, 규칙, 기능 계획, 하네스 지침)의 옛 이름은 이름 바꾸기 chore가 따로 고친다. 앞선 이름 바꾸기(ADR 0050 이력 2026-11-13, "질문 페이지"를 "위젯 미리보기 페이지"로)와 같은 방식이다. `.scratch/widget-login-state/`를 고치는 세션(`docs/widget-login-state-screens-2`)이 아직 병합되지 않아, 그 파일은 그 세션이 병합된 뒤에 고친다.
- **승인 때 함께 확인받는 세부.** 질문의 답에 없었고 이 초안을 쓰며 정한 것이 있다.
  - 이 결정을 ADR 0064의 이력이 아니라 새 ADR로 쓴 것. "이 세션에서 정하고 그리기"의 설명은 "이 세션이 ADR 0064의 이력 초안을 씁니다"였다. ADR 0050·0059·0064와 PRD를 함께 바꾸는 새 결정이라 ADR 하나로 묶었다.
  - 미리보기가 질문을 보내지 않고 위젯 부품을 공유 패키지로 옮겨 그리는 것(위 "미리보기").
  - 운영자의 문이 위젯 관리 서버와 같은 두 경로로 확인하는 것과 각 문을 짓는 행, 운영자가 로그인 사이트를 시험할 때 회사 로그인을 거치는 것, 운영자의 문이 서기 전까지 그 페이지가 지금처럼 열리는 것, 회사 로그인으로 들어온 사람에게 보일 사이트를 명세에 넘긴 것(위 "위젯 테스트 페이지").
  - 공개 계정의 대가 가운데 사용자가 고를 때 질문에 없던 다섯(위 "공개 데모").
  - 이름에 "위젯"을 앞에 붙이는 것(위 "이름").
  - 아래 Consequences의 PRD 고침과 public-demo의 Blocked by.

  승인 화면(일지 2026-11-16-0025 "승인")에서 사용자가 이름은 "위젯 테스트 페이지 (추천)"를, 공개 계정의 대가 다섯과 부딪치는 약속을 다룰 자리는 "public-demo 인터뷰에 넘김 (추천)"을, 위 세부를 포함한 이 ADR과 ADR 0064 이력 2026-11-16은 "이대로 확정 (추천)"을 골랐다.

## Considered Options

- **양식 옆에 그리지 않고, 저장한 뒤 "테스트"로 본다.** 추천이었다. 짓는 것과 고칠 ADR이 가장 적지만, 고친 값을 보려면 먼저 저장해야 하고 저장하면 다음에 위젯을 여는 그 사이트의 최종 사용자도 바뀐 값을 본다.
- **실제 위젯 페이지를 품고 저장 전 값을 창 사이의 메시지로 넘긴다.** 부품을 옮기지 않아도 되지만, 위젯 페이지가 부모 창에서 설정을 받는 길이 새로 생긴다. 위젯을 품는 다른 사이트의 페이지도 그 길로 값을 넣을 수 있어, 받는 쪽이 출처를 가려야 하고 위젯의 공개 표면이 는다.
- **"테스트"는 운영자만 쓰고, 지금 페이지는 이름을 바꿔 공개 데모와 사내 질문 자리로 남긴다.** 다시 물은 화면의 추천이었다. PRD의 공개 데모 문장과 portal-login 행이 그대로지만, 운영자용 시험 자리를 새로 짓고 그 자리가 토큰을 어디서 받을지 정해야 한다.
- **"테스트"는 지금 페이지 그대로 두고 저장 전 그림만 더한다.** 바뀌는 것이 가장 적지만, 운영자의 시험과 최종 사용자의 질문이 로그인 없이 같은 페이지에서 일어난다.
- **직원이 질문하는 자리를 없앤다.** 위젯 테스트 페이지는 운영자 계정으로만 들어오고 직원은 조직이 자기 사내 사이트에 붙인 위젯으로 묻는 안이다. portal-login 행을 다시 써야 하고, 위젯을 붙일 사내 사이트가 없는 조직은 질문할 자리가 없으며, 기준선의 배포(PRD 성공의 정의 "안내 문서만 보고 1시간 안에")에 조직이 자기 사이트에서 토큰을 서명하는 일이 더해진다.
- **공개 계정의 비밀번호를 바꾸지 못하게 하고 정해진 때 처음 상태로 되돌린다, 또는 비밀번호만 바꾸지 못하게 한다.** 앞의 것은 추천이었다. 둘 다 계정에 새 표시를 달아 ADR 0062에 이력이 들고, 앞의 것은 공개용 배포에 데이터베이스를 되돌리는 설정이 더 든다.
- **공개 계정을 질문만 하는 계정으로 둔다.** 처음 설명한 안이다. 0.1 판에는 그런 단계가 없고(역할은 admin-roles, 0.1 판 뒤) 사용자가 제품 전부를 써 보게 하기를 골랐다.

## Consequences

- **신뢰와 노출.** 위젯 테스트 페이지의 서버가 운영자의 로그인 쿠키를 Agent OS의 두 경로에 전한다. 그 서버는 방문자용 포트에 서므로, 그 포트의 서버가 운영자의 쿠키를 받는다는 ADR 0062 Consequences "한계"의 성질을 위젯 관리 서버(ADR 0064 Consequences "신뢰와 노출")에 이어 이 서버도 로그인을 확인하는 길로 쓴다. 그 서버가 뚫리면 운영자의 로그인 상태가 드러나는 것은 지금도 같고, 바뀌는 것은 그 서버가 쿠키를 Agent OS에 전하는 코드를 갖게 된다는 것이다. 그래서 부르는 경로를 둘로 고정하고 시험으로 지키며, 쿠키를 저장하거나 기록하지 않는다. 그 서버의 로그(ADR 0050 결정 "기록")에도 쿠키 값을 싣지 않는다. 공개용 배포에서는 공개 계정을 아는 누구나 운영자이므로, 그 배포에 둔 문서와 대화 기록과 설정은 모두 공개된 것으로 다룬다.
- **공개 데모의 비용과 도구.** 공개 데모가 지금 적어 둔 약속 셋이 공개 계정과 부딪친다.
  - 비용. PRD 성공의 정의는 "시간당 비용에는 계산한 최댓값이 있고"를 적고, ADR 0046 이력 2026-11-06 "기준선 열 안에서 공개 데모를 먼저 연다"는 그 최댓값을 사이트 파일의 사이트별 시간당 실행 수 상한으로 묶었다(그 이력의 "공개 데모의 비용"). 공개 계정은 그 상한이 걸리지 않는 운영자 쪽 실행을 일으킨다.
  - 도구. 같은 이력의 "공개 인터넷에 먼저 선다"는 도구를 읽기 전용 검색 하나만 연다고 적었다. 공개 계정은 꺼 둔 플러그인을 켜고 묻는 도구를 스스로 승인한다(위 결정 "공개 데모"의 넷째, 어림).
  - 관리 화면. ADR 0053 결정 "기능 둘과 차례"와 public-demo의 기능 계획은 공개 데모가 관리 화면을 밖에 내놓지 않는다고 적었다. 공개 계정은 관리 화면을 쓴다.

  약속은 아니지만 새로 드러나는 것도 하나 있다. 로그인 없이 묻던 방문자는 남의 질문을 보지 못했지만, 공개 계정은 트레이스에서 모든 방문자의 질문과 답을 본다. 이것들을 어떻게 다룰지(운영자 쪽 실행에도 상한을 둘지, 공개용 배포의 모델 API에 지출 한도를 걸지, 켤 수 있는 플러그인을 어떻게 둘지, 관리 화면의 답을 마크다운으로 그리는 admin-answer-preview를 기다릴지, 고지에 무엇을 적을지)는 public-demo 행의 설계 인터뷰가 정한다. 그 행에는 아직 설계 줄이 없다.
- **PRD.** 공개 데모 줄의 "공개 주소에서 누구나 로그인 없이 공개 정부 문서에 대해 묻고"를 "실제 운영할 배포와 따로 띄운 공개용 배포에서 누구나 공개 계정으로 로그인해 제품을 써 보고, 공개 정부 문서에 대해 묻고"로 고치고, 그 줄의 출처에 이 ADR을 더한다. 기한(2027-01-08)과 비용과 보고서 문장은 그대로이고, public-demo의 설계 인터뷰가 위 셋과 함께 다시 본다.
- **다른 행.** public-demo는 admin-login과 portal-admin을 더 기다린다. 공개 계정은 운영자 계정이고(admin-login), 로그인 없이 묻는 자리가 없으려면 위젯 테스트 페이지의 운영자 문이 서야 한다(portal-admin). 두 행은 0.1 판의 조건이라, 공개 데모의 기한이 0.1 판의 기한(2027-03-05)보다 앞서는 지금의 차례가 서지 않을 수 있다(어림). public-demo의 슬라이스는 8 그대로 두고, 그 행의 설계 인터뷰가 기한과 함께 다시 본다. public-demo의 기능 계획 머리와 설명, portal-admin의 기능 계획(미리보기와 공유 패키지, 운영자의 문), portal-login의 기능 계획(회사 로그인의 문)을 고치고 `.scratch/plan.md`를 다시 짓는다. pilot-portal은 끝난 행이라 그 계획은 고치지 않는다. widget-login-state의 기능 계획은 그 세션이 병합된 뒤 이름 바꾸기 chore가 고친다. 이 ADR은 그 행에 일을 더하지 않는다. ADR 0064 이력 2026-11-16이 그 행에 더한 일(위젯이 짓고 시험할 모양 넷)도 같은 chore가 그 계획에 함께 적는다.
- **용어.** `CONTEXT.md`의 이름을 위 결정 "이름"대로 바꿨다. 옛 이름 "위젯 미리보기 페이지"는 _Avoid_에 "옛 이름. 2026-11-16에 바꿨다"로 남긴다. 공개 계정은 운영자 계정의 뜻("운영자 한 사람이 … 사람마다 하나")에 맞지 않는 예외라 그 항목에 적었다.
- **다른 ADR.** 이 ADR이 본문의 문장을 바꾸는 ADR에 포인터 `(바뀜: ADR 0065)`를 단다. 달린 자리는 그 ADR마다 `(바뀜: ADR 0065)`로 찾는다.
  - ADR 0064: 요약과 결정 "위젯 미리보기 페이지 설정"의 그 페이지의 서버가 지금의 일을 그대로 한다는 문장, 결정 "'테스트' 메뉴와 공개 주소"의 용어집 이름이 그대로라는 문장과 공개 주소를 남기고 저장 전 설정을 미리 볼 수 없다는 문장들, Consequences "신뢰와 노출"의 로그인 사이트를 익명으로 돌리면 로그인하지 않은 사람이 질문한다는 문장.
  - ADR 0050: 처음 온 브라우저가 고지를 확인한 뒤 익명 식별자 쿠키를 받는다는 요약 문장, 결정 "페이지"의 사이트 목록을 페이지에 싣는다는 문장, 토큰 끝점이 쿠키만 보고 거절한다는 문장.
  - ADR 0059: 둘 다 사이트가 익명으로 바로 질문할 수 있다는 문장.
  - ADR 0062: 운영자용 경로가 사람마다 하나씩인 계정으로 열린다는 요약 문장과 결정 "계정"의 "계정은 사람마다 하나다"(공개 계정이 예외다), Consequences "한계"의 쿠키가 다른 포트에 실리는 것이 방문자용 서버가 뚫렸을 때의 일이라는 문장(위젯 테스트 페이지의 서버가 그 쿠키를 일부러 전한다).
  - ADR 0053: 결정 "기능 둘과 차례"의 공개 데모가 answer-markdown만 기다리고 관리 화면을 밖에 내놓지 않는다는 문장.

  그 ADR들에는 이력을 쌓지 않는다. 포인터를 달지 않는 것도 있다. ADR 0046 이력 2026-11-06의 공개 데모 문장들은 지난 이력이라 달지 않고, 위 "공개 데모의 비용과 도구"가 그 문장을 든다. ADR 0050의 "public-demo는 사이트 하나라 셀렉트 박스가 숨는다"와 ADR 0054 결정 "익명 주체"의 "공개 데모에는 기억 부품을 붙이지 않고"는 글자 그대로 여전히 참이라 달지 않는다. 뒤의 것은 모르는 여러 사람이 공개 계정 하나를 쓰므로 더 지켜야 한다.
- **화면.** 이번 화면 그리기(`/ui-design portal-admin`)에 미리보기를 둔 사이트 화면과, 위젯 테스트 페이지의 들어오는 문을 더한다. 위젯 테스트 페이지의 사이트 화면 자체는 pilot-portal이 그린 그대로다(`.scratch/pilot-portal/design/`).
- **재지 않은 것.** 아래는 어림이고 적힌 행이 확인한다. 위젯 테스트 페이지의 서버(Node)가 운영자 쿠키를 Agent OS의 두 경로에 전해 로그인을 이어 주는 흐름은 위젯 관리 서버의 것과 같이 돌려 보지 않았고 portal-admin의 명세가 확인한다. 위젯의 화면 부품을 공유 패키지로 옮기는 데 드는 일과, 옮긴 부품이 위젯 앱의 사진 비교를 그대로 통과하는지는 portal-admin의 명세가 본다. (바뀜: 이력 2026-11-16 "위젯 테스트 페이지의 서버도 화면이 부른 갱신만 전하고, 미리보기는 옮긴 부품을 고치지 않고 감싼 요소로 가린다")

## 이력

### 2026-11-16 위젯 테스트 페이지의 서버도 화면이 부른 갱신만 전하고, 미리보기는 옮긴 부품을 고치지 않고 감싼 요소로 가린다

Consequences "재지 않은 것"이 portal-admin의 명세에 넘긴 둘을 그 명세(`.scratch/portal-admin/spec.md`의 "로그인 확인"과 "미리보기를 그리는 부품")가 확인했고, 그 결과로 본문의 문장 셋의 뜻을 정했다. 셋 다 명세가 스스로 정했다. 본문이 명세에 확인을 맡긴 자리이기 때문이다(일지 2026-11-16-1705 "명세가 먼저 확인한 것 셋"). 사용자에게 따로 물은 것은 하나이고, 셋째의 끝이 적는 미리보기의 높이를 넘는 글을 다루는 법이다.

첫째, 결정 "위젯 테스트 페이지"의 운영자 문이 쓰는 로그인 흐름이다. `.scratch/portal-admin/probes/login_relay/`가 쟀다. Agent OS의 로그인 경로(admin-login)가 아직 없어 Agent OS와 위젯 테스트 페이지의 서버는 대역이고 브라우저는 Chromium 153이다. 그 서버 대역이 Agent OS 대역을 Node의 `fetch`와 `node:http`로 부른 두 길에서, 로그인한 브라우저가 그 포트의 요청으로 답을 받고 짧은 JWT의 수명이 끝난 뒤 갱신을 거쳐 다시 답을 받는 흐름이 섰다(쟀다). 화면이 갱신을 부르는 꼴에서 동시에 보낸 요청 넷이 유예 없이 로그인을 지켰다(쟀다. 길마다 유예가 없는 회차 하나씩이다). 그 서버가 지켜야 하는 것은 위젯 관리 서버와 같고, ADR 0064 이력 2026-11-16 "로그인 시간이 끝났을 때의 갱신은 화면이 부르고, 위젯 테스트 페이지의 서버는 설정을 요청마다 받아 와 기억하지 않는다"가 적었다. 갱신은 페이지의 스크립트가 부르고 서버는 스스로 갱신하지 않으며, 서버는 로그인 쿠키 둘을 담은 `Cookie` 머리만 전하고 `Set-Cookie`를 줄마다 되돌리며 응답의 쿠키를 기억하지 않는다. 그 서버는 `web/` 아래의 코드라 전역 `fetch`를 직접 부르지 않고 생성 클라이언트(`openapi-fetch`)로 부른다(ADR 0021). 그 클라이언트로 부른 길에서도 `Cookie`만 실은 요청이 요청 출처 검사를 지났고, `Set-Cookie` 두 줄이 글자 그대로 닿았으며, 받은 쿠키를 다음 요청에 싣지 않았고, 제한 시간의 신호를 넘긴 호출이 제한 시간에 끊겼다(쟀다). 그 길로는 흐름 전체와 동시 요청을 재지 않았다. 그 페이지는 문서를 내는 요청에서 로그인을 보지 않는다. 페이지와 정적 파일은 누구에게나 같고, 페이지의 스크립트가 "들어온 사람"을 물을 때 서버가 로그인을 확인한다(그 명세의 "위젯 테스트 페이지의 운영자 문"). 그래서 화면이 갱신을 부를 수 없는 문서 요청에서 서버가 스스로 갱신해야 하는 경우가 생기지 않는다. 재지 못한 것은 ADR 0064의 그 이력이 적은 것과 같다.

둘째, 결정 "미리보기"가 "옮기는 데 얼마나 드는지는 어림이고 재 보지 않았다"고 적은 것과 Consequences "재지 않은 것"의 둘째다. `.scratch/portal-admin/probes/shared_widget_parts/`가 기준 커밋 `02dcfe97d`의 위젯 앱에서 화면 부품 20파일을 새 패키지 `@agent-os/widget-ui`로 실제로 옮겨 보았다. 패치를 붙이고 검사를 한 번씩 돌려 본 실험이라 아래는 "손으로 봤다"다. 옮긴 20파일 가운데 17파일이 한 글자도 바뀌지 않았고, 변경 전체는 34파일에 더한 줄 137과 뺀 줄 31이었다. `pnpm -C web verify`가 옮기기 전과 뒤에 같은 수로 통과했고, 위젯의 사진 비교 44건이 정답 사진 77장을 한 장도 고치지 않고 통과했으며, 위젯 e2e 19건이 통과했다(손으로 봤다). 명세는 옮기는 티켓이 파일을 옮기고 import와 설정을 맞추는 일만 하게 했다. 부품의 모양과 동작을 함께 고치면 "정답 사진이 그대로다"가 옮기기의 판정이 되지 못하기 때문이다. 실제로 옮기는 때는 widget-login-state가 화면을 더 지은 뒤라 파일과 줄의 수는 달라진다. 본 것은 옮기는 방식이 서는지다.

셋째, 같은 결정이 대가로 적은 "미리보기와 실제 위젯이 다른 것이 입력(저장 전 값, 미리 정한 예시 대화)뿐이도록 지켜야 한다"를 지키는 방법이다. 위젯의 틀은 대화 자리를 `<main>`으로 그려, 옮긴 부품을 관리 화면 앱의 틀 안에 그대로 두자 접근성 검사(axe)가 위반 셋(`landmark-main-is-top-level`, `landmark-no-duplicate-main`, `landmark-unique`)을 냈다(손으로 봤다). 명세는 부품을 고치지 않고 미리보기 칸이 감싼 요소로 가리게 했다. 바깥 요소에 그림의 역할과 이름 "미리보기, 저장하지 않은 값으로 그린 위젯"을 주고, 위젯을 감싼 안쪽 요소에 `inert`와 `aria-hidden="true"`를 함께 준다. 그렇게 가린 갈래에서 위반 셋이 사라지고 새 위반이 없었으며, 실제 Tab이 위젯 안에 서지 않고 다음 단추에 닿았고, Chromium의 접근성 트리에 그 이름의 그림 하나만 남았다(손으로 봤다). `aria-hidden`만 준 갈래는 포커스가 위젯 안에 들고 새 위반 둘이 나서 쓰지 않는다(손으로 봤다). 부품이 `<main>`을 그리는 자리를 입력으로 바꾸는 안은 고르지 않았다. 그 안이면 미리보기와 실제 위젯이 다른 것이 입력만이 아니게 되고, 옮기는 티켓이 부품을 고치게 된다. 대가는 둘이다. 하나는 미리보기가 화면 읽기 프로그램에 그림 한 줄로만 읽혀, 화면을 보지 못하는 운영자는 미리보기로 위젯의 글을 확인하지 못한다는 것이다. 그 운영자는 양식의 칸에서 같은 글을 읽고, 저장한 뒤 위젯 테스트 페이지에서 실제 위젯을 쓴다. 다른 하나는 운영자가 미리보기 안을 굴려 볼 수 없다는 것이다. 그렇게 가린 갈래에서 위젯의 단추 자리를 실제 마우스로 눌러도 처리기가 불리지 않았고, 넘친 자리 위에서 휠을 굴려도 그 자리는 그대로인 채 위젯 관리 화면이 굴렀다(손으로 봤다. 가리지 않은 갈래에서는 처리기가 불리고 위젯 안이 굴렀다). 그래서 미리보기의 높이를 넘는 글은 한쪽 끝만 보이고, 나머지는 저장한 뒤 위젯 테스트 페이지에서 본다. 명세는 미리보기 아래에 그것을 알리는 도움말 한 줄을 두었다(그 명세의 "미리보기"). 미리보기의 높이를 글에 맞춰 늘리는 안과 가린 요소 밖에 스크롤하는 조작을 따로 두는 안은 해 보지 않았고 고르지 않았다. 이 셋은 명세의 셀프 리뷰 뒤에 사용자에게 물었고, 사용자가 지금의 안인 "넘친 글은 테스트 페이지에서 보기 (Recommended)"를 골랐다(일지 2026-11-16-1705 "셀프 리뷰 뒤에 물은 것과 답"). Chromium 밖의 브라우저와 실제 화면 읽기 프로그램, 휠 밖의 스크롤(터치로 밀기, 키보드)은 보지 않았다.
