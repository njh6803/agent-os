# 다음은 설치형 문서 질의응답의 기준선과 제품 1.0이고, ADR 0042의 나머지 열셋은 그 뒤에 선다

skill-plugin이 2026-11-05에 닫혀 ADR 0042의 열일곱 가운데 첫 행 approval-rules가 프론티어가 되었고, 같은 날 그 설계(ADR 0044)와 명세(`.scratch/approval-rules/spec.md`)가 섰다. 나머지 열여섯은 ADR 0042의 다섯 묶음(신뢰·강제, 비용·기록, 바깥 연결, 여러 에이전트, 확장·채널)에 걸친 런타임 기능이고, `plan.md`에서 행마다 바로 앞 행에 막혀 한 줄로 이어져 있다. 이것을 실제 사용처 없이 차례대로 만들면 넉 달 넘게(어림) 런타임 기능만 쌓이고, 그 기능이 어떤 요구에 답하는지 시험할 자리가 없다. PRD가 적은 앞선 두 시도의 교훈(실행 없이 문서와 관리 화면만 남았다)과 같은 모양의 위험이다.

2026-11-05의 계획 제안서(저장소 밖의 파일, 일지 2026-11-06-02)는 이 런타임 위에 설치형 문서 질의응답을 먼저 세우자고 했고, 사용자가 2026-11-06 PRD 개정으로 그 방향을 승인했다. 이 사용처는 agent-os에 셋을 요구한다. 바깥 API 없이 도는 모델, 실행마다 띄우지 않고 상주하는 MCP 서버, 최종 사용자를 확인하는 길이다. 여러 부서가 한 배포 환경을 나눠 쓰려면 묶음 ①의 주체 전파와 묶음 ②의 값 기반 마스킹도 먼저 필요하다.

## 결정

- **다음 기능은 기준선(슬라이스 7~9)이다.** 기준선은 PRD 성공의 정의의 "기준선, 제품 0.1" 줄이 적은 상태다. 폐쇄망 서버 한 대에 안내 문서만 보고 1시간 안에 배포되고(밖으로 여는 포트는 하나다), 바깥 API 없이 배포 환경의 모델로 문서에 근거한 답을 출처와 함께 내며, 검색 적중률과 사람이 판정한 정답률을 보고서로 낸다. 이 상태의 제품 판을 0.1이라 부르고 기한은 2027-02-19다. (바뀜: 이력 2026-11-06 "기준선 열 안에서 공개 데모를 먼저 연다")
- **approval-rules는 지금 자리(슬라이스 7)에 남아 기준선 행과 나란히 간다.** 설계와 명세가 섰고 티켓을 쓰는 중이라서다(사용자가 골랐다, 일지 2026-11-06-02). 그래서 기준선 판의 강제에는 운영자의 규칙 파일이 든다.
- **기준선 다음은 제품 1.0의 agent-os 몫(슬라이스 10)이다.** 묶음 ①의 나머지 둘(mcp-trust, principal-propagation)이 차례 그대로 들어가고, 묶음 ②에서는 value-masking 하나만 앞으로 당겨 그 둘 바로 뒤에 두며, 새 행 io-guardrail, audit-export, run-feedback, stale-warning, usage-report를 더한다. 1.0은 여러 부서가 한 배포 환경을 나눠 쓸 때 사용자가 자기가 볼 수 있는 문서로만 답을 받고, 입출력에서 민감한 값의 패턴을 막으며, 운영자가 누가 무엇을 물었고 어떤 근거로 답을 받았는지 조회하고 내보내며, 최종 사용자가 틀린 답을 신고할 수 있는 상태다.
- **ADR 0042의 나머지 열셋은 버리지 않고 차례만 뒤로 민다(슬라이스 11~14).** 보장(중재, 강제, 기록)은 그대로이고, 묶음 안의 차례도 value-masking이 빠진 것 말고는 그대로다.
- **원격 MCP 서버를 claude-code-compat에서 mcp-http로 떼어 기준선에 넣는다.** core는 실행마다 MCP 서버에 연결하고 stdio 서버는 그때마다 새 프로세스로 뜬다(`core/run.py`의 `self._tools.connect`, `adapters/mcp.py`의 `stdio_client`, main 83a66cd의 코드를 읽었다). 그래서 임베딩 모델과 색인을 올리는 문서 검색 서버는 상주해야 한다. 모양은 ADR 0042 묶음 ③의 "원격 MCP"(`[server]`의 http 모양은 url과 헤더의 환경 변수 이름이고 streamable HTTP만 받는다)에서 출발한다. 주소가 배포 환경마다 달라지는 문제 때문에 그 모양을 바꿔야 하면, mcp-http의 설계 인터뷰가 ADR 0042의 이력으로 바꾼다.
- **두 전송의 역할을 나눈다.** 시작할 때 무거운 것을 올리거나 여러 실행이 같은 데이터를 함께 보는 서버는 원격 MCP 서버(상주)가 기본이다. 가볍고 상태가 없는 도구, 바깥에서 받아 온 공개 MCP 서버, 사용자별 비밀 값이 필요한 도구는 stdio(실행마다 띄움)를 쓴다. stdio는 실행 사이의 격리를 프로세스로 보장하고, 공개 MCP 서버의 다수가 이 모양으로 배포되므로(어림, 세지 않았다) 지우지 않는다. 기준선 동안 stdio 전송에만 걸리는 것(런처, ADR 0034의 프로세스 정리)은 지금 상태로 두고 더하지 않는다. 전송과 무관한 것은 두 모양에 똑같이 건다. approval-rules가 도구마다 싣는 서버 이름(`.scratch/approval-rules/spec.md`의 `ToolSpec.server`)과, mcp-trust의 신뢰 수준·해시·주체 전파(ADR 0042 "원격 MCP")가 그것이다.

  | 서버의 성격 | 모양 | 예 |
  |---|---|---|
  | 시작할 때 무거운 것을 올리는 서버 | 원격 MCP 서버(상주) | 문서 검색 서버(임베딩 모델, 색인) |
  | 여러 실행이 같은 데이터를 함께 보는 서버 | 원격 MCP 서버(상주) | 사내 문서 색인, 사내 시스템 연동 게이트웨이 |
  | 가볍고 상태가 없는 도구 | stdio | 형식 변환, 날짜 계산 |
  | 바깥에서 받아 온 공개 MCP 서버 | 배포된 모양 그대로(대부분 stdio, 어림) | 파일 시스템, git |
  | 사용자별 비밀 값이 필요한 도구 | stdio(실행마다 격리) | 개인 계정으로 접속하는 도구 |

- **문서 검색 서버는 다른 저장소다(ADR 0048).** `.scratch/plan.md`는 그 저장소의 행을 `rag-server:<slug>`로 가리킨다. (바뀜: ADR 0048 이력 2026-11-06 "문서 검색 서버의 저장소 이름을 rag-engine으로 정한다")

## 앞당김

배포 환경이 나머지 열셋 가운데 하나를 요구하면, 그 행과 그 행이 기술적으로 기대는 행의 Blocked by를 풀어 제품 1.0 뒤 첫 프론티어로 올리고 이 ADR의 이력에 적는다. 예를 들어 사용자가 많아 파일 트레이스로는 목록과 보존 관리가 버거우면 trace-postgres를 당기고, 배포 환경이 이미 쓰는 관측 도구로 실행을 보려 하면 otel-export를 당긴다.

## Considered Options

- **열일곱을 먼저 끝내고 사용처를 세운다.** 거부했다. 넉 달 넘게(어림) 런타임 기능만 쌓이고, 그 기능을 시험할 사용처가 없다.
- **기준선 뒤에 열일곱을 원래 차례대로 둔다.** 거부했다. value-masking이 trace-postgres, run-cost, token-limit 뒤에 있어서, 최종 사용자의 글과 문서 조각이 쌓이는 트레이스에 값 가림 없이 기능만 늘어난다.
- **approval-rules까지 기준선 뒤(슬라이스 10)로 미룬다.** 제안서의 안이었다. 거부했다. 설계와 명세가 섰고 티켓을 쓰는 중이라, 미루면 명세가 석 달 넘게 기다리는 사이 mcp-http가 같은 MCP 어댑터를 바꿔 명세를 다시 맞춰야 할 수 있다(어림). 사용자가 "지금 자리에서 계속"을 골랐다(일지 2026-11-06-02).
- **상주 검색 서비스와 실행마다 뜨는 얇은 stdio 서버로 나눈다.** 거부했다. agent-os를 바꾸지 않지만, 두 구성 요소 사이에 자체 API를 하나 더 두어야 하고 얇은 서버의 시작 비용은 여전히 질문마다 남는다.
- **stdio 서버를 `serve`가 켜질 때 한 번 띄워 두고 여러 실행이 다시 쓴다.** 거부했다. 실행 사이의 격리가 사라지고, 죽은 서버를 다시 띄우는 감시를 core가 떠안아 원격 MCP 서버가 표준으로 주는 것을 다시 만들게 된다.
- **stdio 모양을 지우고 http 모양만 남긴다.** 거부했다. `command` 모양을 지우는 계약 변경이고, 공개 MCP 서버와의 호환과 실행 사이의 격리를 잃는다.

## Consequences

- **기준선 판의 강제.** 저자의 `requires_approval`, 꺼진 플러그인, 운영자의 규칙 파일까지다. MCP 서버의 신뢰 수준과 값 기반 마스킹이 없으므로, 제품 0.1의 지원 범위 문서(pilot-release)에 알려진 한계로 적는다.
- **규칙 파일의 기본값.** 규칙 파일에 적지 않은 도구는 묻는 것이 기본이고, 최종 사용자가 주체인 실행에서 그 물음은 운영자의 검토가 아니라 최종 사용자 자신의 확인이다(ADR 0044). 그래서 doc-qa와 참조 배포는 검색 도구를 허락하는 규칙 파일을 함께 낸다. (바뀜: 이력 2026-11-10 "기본 에이전트 assistant가 참조 에이전트 doc-qa를 대신하고 공개 데모가 answer-markdown을 기다린다") 그러지 않으면 질문마다 검색 도구를 부르기 전에 실행이 멈추고, 위젯에서 질문한 사람이 그 호출을 직접 승인해야 답이 나온다.
- **같은 파일을 고치는 두 행.** approval-rules와 mcp-http가 둘 다 `adapters/mcp.py`를 고친다. 나중에 병합하는 쪽이 충돌을 풀고, approval-rules가 도구마다 싣는 서버 이름이 원격 MCP 서버의 도구에도 실리는지를 시험으로 본다.
- **단일 인스턴스와 JSONL.** 기준선과 제품 1.0은 `serve` 한 프로세스와 파일 트레이스다. 1.0에 드는 value-masking은 프로세스를 늘리지 않는다. PRD의 프로세스 넷은 trace-postgres가 PostgreSQL과 Redis를 더하고 retention-worker가 worker를 더해 선다(ADR 0042 묶음 ②의 표). 그래서 audit-export의 조회는 JSONL 위에서 먼저 돌고, 트레이스 저장소 포트의 읽기로 지어 trace-postgres 뒤에도 남게 한다.
- **원격 MCP 서버의 수명.** agent-os 밖(배포)이 관리한다. 서버가 꺼져 있으면 실행이 원인 `tool_connection`으로 끝난다. 실행마다 따로 뜨던 stdio 서버와 달리 여러 실행의 요청을 한 프로세스가 받으므로, 서버가 동시 요청을 안전하게 다뤄야 한다.
- **문서 속 지시.** mcp-trust 전에는 런타임이 검색 결과를 바깥 글로 감싸지 않는다. 그때까지는 doc-qa의 프롬프트가 검색 결과를 데이터로 엮는 것에 기댄다. (바뀜: 이력 2026-11-10 "기본 에이전트 assistant가 참조 에이전트 doc-qa를 대신하고 공개 데모가 answer-markdown을 기다린다")
- **늦어지는 것.** 나머지 열셋의 차례가 기준선과 1.0만큼(어림 대여섯 달) 늦어진다.
- **`.scratch/plan.md`.** mcp-trust, principal-propagation, value-masking은 슬라이스 10으로, 나머지 열셋은 11~14로 옮긴다. 슬라이스는 더 이상 ADR 0042의 묶음과 같지 않다. 기록(일지, 닫힌 harness 티켓)의 옛 번호는 고치지 않는다. 행마다 설계 인터뷰가 먼저 볼 것은 그 행의 내용 칸에 적고 (바뀜: ADR 0045), 여러 행이 함께 쓰는 자료(GPU 환경과 요금, 모델 배치 구성, 남은 확인)는 일지 2026-11-06-02의 "설계 인터뷰 입력" 절에 두어 행에서 가리킨다. (바뀜: 이력 2026-11-06 "기준선 열 안에서 공개 데모를 먼저 연다") 요금은 조사한 시점의 기록이라 그 행의 설계 인터뷰가 쓰기 전에 다시 확인한다.
- **같은 PR에 드는 것.** PRD 개정(2026-11-06 사용자 승인), `CONTEXT.md`의 용어(배포 환경, 참조 배포, 참조 에이전트, 참조 클라이언트, 문서 검색 서버)와 값 기반 마스킹의 `_Avoid_`, ADR 0042의 이력과 포인터, ADR 0044의 포인터다.

## 이력

### 2026-11-06 기준선 열 안에서 공개 데모를 먼저 연다

같은 날 고친 계획 제안서의 셋째 판(저장소 밖의 파일. 이 저장소에는 2026-11-07에 반영했다, 일지 2026-11-07-2053)이 기준선 열 안에 공개 데모(`CONTEXT.md`)를 먼저 세웠다. 공개 데모는 클라우드 VM 한 대에 공개 정부 문서를 넣고, 공개 주소에서 누구나 로그인 없이 묻게 하는 배치다. 모델은 Anthropic API이고 기한은 2027-01-08이다. 폐쇄망 배포보다 두 달쯤(어림) 앞서 같은 구성 요소(doc-qa, 문서 검색 서버 이미지, 질문 페이지)를 실제 최종 사용자의 질문 앞에서 끝까지 돌려 보고, 검색 적중률과 정답률을 그 문서 묶음으로 재기 위해서다. 공개 데모는 제품 0.1의 조건이 아니므로 pilot-release를 막지 않는다. 사용자가 PRD 개정(2026-11-07 사용자 승인)으로 이 방향을 승인했다.

- **기한.** 기준선(제품 0.1)의 기한은 2027-02-19에서 2027-03-05로 2주 늦어진다. 본문 결정 첫 항목의 기한이 이것으로 바뀐다.
- **차례.** pilot-portal을 익명 모드(`CONTEXT.md`)와 사내 로그인 모드로 나누고, 사내 로그인 모드는 새 행 portal-login이 맡는다. 공개 데모로 가는 mcp-http와 pilot-portal을 먼저 하고, 공개 데모에 필요 없는 local-model과 portal-login은 그 뒤에 한다. local-model은 막는 기능이 없어 프론티어에 남으므로, 이 차례는 Blocked by가 아니라 기능 계획의 내용 칸에 적는다. 2026-11-07부터 `.scratch/plan.md`는 도구가 기능 계획에서 만들고 손으로 쓰는 프론티어 문단이 없기 때문이다(ADR 0045 결정 3).
- **기준선 표.** 본문 "agent-os의 기준선" 표에서 pilot-portal 줄이 바뀌고 두 줄이 는다.

  | 기능 | 한 줄 |
  |---|---|
  | pilot-portal | 위젯을 담는 독립 질문 페이지와 익명 모드의 사이트 토큰 발급 |
  | public-demo | 공개 정부 문서를 넣은 클라우드 VM 한 대의 공개 배치, 시간당 비용의 최댓값, 고지 |
  | portal-login | 질문 페이지의 사내 로그인 모드 |

- **`.scratch/plan.md`의 Blocked by.** public-demo(슬라이스 8)는 doc-qa-agent, release-image, answer-eval, `rag-engine:release-image`, `rag-engine:search-eval`을 기다리고, portal-login(슬라이스 9)은 pilot-portal을 기다린다. 문서 검색 서버 저장소의 계획이 그 저장소의 release-image를 core 바로 뒤로 당겨 admin을 기다리지 않게 했으므로, ADR 0048 이력 2026-11-06 "문서 검색 서버의 저장소 이름을 rag-engine으로 정한다"가 적은 두 행이 기다리는 것도 바뀐다. answer-eval은 `rag-engine:core` 대신 `rag-engine:release-image`를 기다린다. 수락 문장이 실제 문서 검색 서버 이미지를 요구하기 때문이다(일지 2026-11-06-11이 보류한 Minor). deploy-package는 portal-login과 `rag-engine:admin`을 더 기다린다. 그 이력은 기록이라 고치지 않고 이 이력에 적는다.
- **설계 인터뷰 입력.** 여러 행이 함께 쓰는 자료는 일지 2026-11-06-02의 "설계 인터뷰 입력" 절에 더해, 이번에 더해진 것(공개 데모는 GPU를 쓰지 않는다, 공개 데모는 모델 배치 구성의 셋째다, 넣을 문서의 저작권 확인)이 일지 2026-11-07-2053의 같은 이름의 절에 있다. 행은 그 자료를 쓰는 쪽에서 가리킨다. 본문 Consequences의 `.scratch/plan.md` 항목에서 자료의 자리를 적은 문장이 이것으로 바뀐다.
- **공개 데모의 비용.** 새 런타임 기능 없이 묶는다. `serve`가 다시 시작하지 않는 동안 시간당 비용의 최댓값은 사이트 파일의 사이트별 시간당 실행 수 상한에, doc-qa의 구조(실행 하나의 모델 호출 수의 끝, 모델 매니페스트의 `max_tokens`, 요청 글자 수 상한, 검색 조각 수)가 정하는 실행 하나의 토큰 최댓값을 곱한 값이다. 시간당 실행 수 상한에는 전역 범위가 없으므로(주체별과 사이트별뿐이다, `channel/http/limits.py`), 공개 데모의 사이트 파일에는 사이트를 질문 페이지 하나만 둔다. 그 셈은 프로세스 메모리라 `serve`가 다시 시작하면 비워진다(같은 모듈). 다시 시작한 시간에는 이 값을 넘을 수 있고, 그 초과분은 모델 API 계정의 사용 한도가 받는다(public-demo 기능 계획). 제안서는 전역 범위의 시간당 상한을 들었고, 사용자가 전역 상한을 새로 만들지 않고 사이트별 상한으로 고쳐 쓰는 안을 골랐다(일지 2026-11-07-2053).
- **이미지 판을 아는 자리.** ADR 0048 결정의 저장소 표는 agent-os에서 doc-qa 플러그인과 참조 배포만 문서 검색 서버의 검색 도구 형식과 이미지 판을 안다고 적는다. 공개 데모의 배치도 판을 고정한 문서 검색 서버 이미지를 띄우므로 그 판을 안다. 공개 데모는 참조 배포가 아니다(`CONTEXT.md`). 런타임(`src/`)이 그 서버를 모른다는 것은 그대로다.
- **사이트의 의무.** ADR 0023 Consequences의 "사이트의 의무"는 `sub`를 사이트가 인증한, 오래 가는 사용자 식별자로 정한다. 익명 모드의 질문 페이지(pilot-portal)는 사람을 확인하지 않고 처음 들어온 브라우저마다 새 식별자를 `sub`로 내므로, 이 저장소가 함께 내는 사이트가 그 의무를 일부러 지키지 않는다. 그 경우를 위해 ADR 0023이 둔 사이트별 합계(사이트별 시간당 실행 수 상한)로 비용을 묶는 것이 위의 "공개 데모의 비용"이다. 실행의 주체를 가르는 검사는 브라우저마다 따로 선다. ADR 0023이 거부한 익명 최종 사용자는 주체가 위젯 배치 하나의 이름이 되는 안이었다.

Consequences.

- **공개 인터넷에 먼저 선다.** 공개 데모는 mcp-trust와 io-guardrail보다 먼저 공개 인터넷에 선다. 문서 속 지시를 런타임이 감싸지 않고, 입력에 든 민감한 값도 막지 않는다. 그래서 문서는 출처가 분명한 공개 정부 문서로 한정하고, 도구는 읽기 전용 검색 하나만 열며, 최종 사용자에게 개인정보를 넣지 말라고 알린다. 검색 도구 밖의 도구는 규칙 파일의 deny에 이름이나 접두 패턴으로 적는다. deny가 allow보다 먼저 집행되므로 맨 `*`는 검색 도구까지 막고, 적지 않은 도구는 묻는 것이 기본이라 질문한 최종 사용자가 스스로 승인할 수 있기 때문이다(ADR 0044와 그 이력 2026-11-06 "도구 이름의 별표는 패턴이다", 일지 2026-11-07-2053에서 사용자가 골랐다). 토큰 합 상한(token-limit)도 아직 없으므로, 실행 하나의 토큰은 doc-qa의 구조로 묶는다.
- **기준선이 늦어진다.** 기준선의 기한이 공개 데모만큼 늦어진다(2027-02-19에서 2027-03-05로).

Considered Options.

- **폐쇄망 기준선을 먼저 끝내고 공개 데모를 그 뒤에 둔다.** 거부했다. 실제 최종 사용자의 질문으로 검색과 답을 시험하는 시점이 두 달쯤(어림) 늦어지고, 그동안 숫자는 평가 세트에서만 나온다.

### 2026-11-10 기본 에이전트 assistant가 참조 에이전트 doc-qa를 대신하고 공개 데모가 answer-markdown을 기다린다

doc-qa-agent의 설계 인터뷰(일지 2026-11-10-1345)에서 사용자가 이 에이전트를 사용처 하나의 본보기가 아니라 커스텀 에이전트의 바탕인 기본 에이전트로 바꾸고 이름을 `assistant`로 정했다(ADR 0051). 같은 인터뷰에서 위젯이 답을 마크다운으로 그리게 해 달라고 요구했다(ADR 0053). 기준선의 기한과 차례는 바뀌지 않는다.

- **기준선 표.** 본문 "agent-os의 기준선" 표에서 doc-qa-agent 줄이 바뀌고 한 줄이 는다.

  | 기능 | 한 줄 |
  |---|---|
  | base-agent | 문서 검색 서버에서 근거를 찾아 출처를 달아 답하고 근거가 없으면 모른다고 답하는 기본 에이전트와 스킬, 커스텀 에이전트를 만드는 안내 |
  | answer-markdown | 모델이 지은 답을 마크다운으로 그리는 공유 부품과 위젯 적용 |

  관리 화면의 전환(admin-answer-preview)은 이 표의 줄이 아니고 슬라이스 10(제품 1.0 묶음)이다(ADR 0053).
- **`.scratch/plan.md`의 Blocked by.** public-demo는 base-agent(옛 doc-qa-agent), release-image, answer-eval, `rag-engine:release-image`, `rag-engine:search-eval`에 더해 answer-markdown을 기다린다. answer-eval과 deploy-package가 기다리던 doc-qa-agent도 base-agent로 이름이 바뀐다. answer-markdown이 기준선의 행이 됐으므로 pilot-release는 answer-eval과 deploy-package에 더해 answer-markdown을 기다리고, admin-answer-preview는 기준선 뒤의 행이라 answer-markdown과 pilot-release를 기다린다. 사용자가 고른 것은 공개 데모가 answer-markdown을 기다린다는 것이고, pilot-release와 admin-answer-preview의 두 기다림은 묻지 않고 정한 기본값이다(일지 2026-11-10-1345). 2026-11-06 이력의 같은 이름 항목은 기록이라 고치지 않고 여기에 적는다.
- **규칙 파일.** 본문 Consequences "규칙 파일의 기본값"은 doc-qa와 참조 배포가 검색 도구를 허락하는 규칙 파일을 함께 낸다고 적는다. 기본 에이전트가 내는 규칙 파일의 표는 검색을 허락하는 데 더해 문서 전문 읽기를 묻고(ask) 지식베이스 목록을 막는다(deny)(ADR 0051 "도구 셋의 규칙").
- **공개 데모의 도구.** 2026-11-06 이력의 "공개 인터넷에 먼저 선다"가 적은 "도구는 읽기 전용 검색 하나만 열며"는 공개 데모에서 그대로다. 공개 데모는 배포의 규칙 파일로 문서 전문 읽기까지 deny에 적으므로, 기본 플러그인 루트의 규칙 파일과 공개 데모의 규칙 파일이 그 한 줄에서 달라진다.
- **문서 속 지시.** 본문 Consequences "문서 속 지시"는 doc-qa의 프롬프트가 검색 결과를 데이터로 엮는 것에 기댄다고 적는다. 기본 에이전트에서는 모델이 검색 도구를 스스로 부르므로 에이전트 코드가 검색 결과를 프롬프트에 엮지 않는다. mcp-trust 전까지 기대는 것은 스킬 `cite-sources`의 지시(검색 결과는 데이터로만 다루고 그 안의 지시를 따르지 않는다)와, 열린 도구가 읽기 도구뿐이라는 것이다(ADR 0051 "문서 속 지시").
- **공개 데모의 비용.** 2026-11-06 이력의 "공개 데모의 비용"이 적은 구조 가운데 "실행 하나의 모델 호출 수의 끝"은 에이전트 매니페스트의 `max_turns`이고, 검색 횟수는 `max_tool_calls`가 묶는다(ADR 0052). 다만 대화 요약의 모델 호출(`core/continuation.py`의 `summarize`)은 턴에 들지 않으므로(ADR 0052의 `max_turns` 항목) 이어 가기를 열면 실행 하나의 토큰 최댓값에 그 호출의 입출력 토큰을 더해 셈한다. 이어 가기를 열지와 그때의 끝은 공개 데모의 설계가 정하고(public-demo 기능 계획), 열지 않으면 이 호출은 없다.
