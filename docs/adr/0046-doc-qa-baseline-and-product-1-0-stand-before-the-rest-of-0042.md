# 다음은 설치형 문서 질의응답의 기준선과 제품 1.0이고, ADR 0042의 나머지 열셋은 그 뒤에 선다

skill-plugin이 2026-11-05에 닫혀 ADR 0042의 열일곱 가운데 첫 행 approval-rules가 프론티어가 되었고, 같은 날 그 설계(ADR 0044)와 명세(`.scratch/approval-rules/spec.md`)가 섰다. 나머지 열여섯은 ADR 0042의 다섯 묶음(신뢰·강제, 비용·기록, 바깥 연결, 여러 에이전트, 확장·채널)에 걸친 런타임 기능이고, `plan.md`에서 행마다 바로 앞 행에 막혀 한 줄로 이어져 있다. 이것을 실제 사용처 없이 차례대로 만들면 넉 달 넘게(어림) 런타임 기능만 쌓이고, 그 기능이 어떤 요구에 답하는지 시험할 자리가 없다. PRD가 적은 앞선 두 시도의 교훈(실행 없이 문서와 관리 화면만 남았다)과 같은 모양의 위험이다.

2026-11-05의 계획 제안서(저장소 밖의 파일, 일지 2026-11-06-02)는 이 런타임 위에 설치형 문서 질의응답을 먼저 세우자고 했고, 사용자가 2026-11-06 PRD 개정으로 그 방향을 승인했다. 이 사용처는 agent-os에 셋을 요구한다. 바깥 API 없이 도는 모델, 실행마다 띄우지 않고 상주하는 MCP 서버, 최종 사용자를 확인하는 길이다. 여러 부서가 한 배포 환경을 나눠 쓰려면 묶음 ①의 주체 전파와 묶음 ②의 값 기반 마스킹도 먼저 필요하다.

## 결정

- **다음 기능은 기준선(슬라이스 7~9)이다.** 기준선은 PRD 성공의 정의의 "기준선, 제품 0.1" 줄이 적은 상태다. 폐쇄망 서버 한 대에 안내 문서만 보고 1시간 안에 배포되고(밖으로 여는 포트는 하나다), 바깥 API 없이 배포 환경의 모델로 문서에 근거한 답을 출처와 함께 내며, 검색 적중률과 사람이 판정한 정답률을 보고서로 낸다. 이 상태의 제품 판을 0.1이라 부르고 기한은 2027-02-19다.
- **approval-rules는 지금 자리(슬라이스 7)에 남아 기준선 행과 나란히 간다.** 설계와 명세가 섰고 티켓을 쓰는 중이라서다(사용자가 골랐다, 일지 2026-11-06-02). 그래서 기준선 판의 강제에는 운영자의 규칙 파일이 든다.
- **기준선 다음은 제품 1.0의 agent-os 몫(슬라이스 10)이다.** 묶음 ①의 나머지 둘(mcp-trust, principal-propagation)이 차례 그대로 들어가고, 묶음 ②에서는 value-masking 하나만 앞으로 당겨 그 둘 바로 뒤에 두며, 새 행 io-guardrail, audit-export, run-feedback, stale-warning, usage-report를 더한다. 1.0은 여러 부서가 한 배포 환경을 나눠 쓸 때 사용자가 자기가 볼 수 있는 문서로만 답을 받고, 입출력에서 민감한 값의 패턴을 막으며, 운영자가 누가 무엇을 물었고 어떤 근거로 답을 받았는지 조회하고 내보내며, 최종 사용자가 틀린 답을 신고할 수 있는 상태다.
- **ADR 0042의 나머지 열셋은 버리지 않고 차례만 뒤로 민다(슬라이스 11~14).** 보장(중재, 강제, 기록)은 그대로이고, 묶음 안의 차례도 value-masking이 빠진 것 말고는 그대로다.
- **원격 MCP 서버를 claude-code-compat에서 mcp-http로 떼어 기준선에 넣는다.** core는 실행마다 MCP 서버에 연결하고 stdio 서버는 그때마다 새 프로세스로 뜬다(`core/run.py`의 `self._tools.connect`, `adapters/mcp.py`의 `stdio_client`, main 83a66cd의 코드를 읽었다). 그래서 임베딩 모델과 색인을 올리는 문서 검색 서버는 상주해야 한다. 모양은 ADR 0042 묶음 ③의 "원격 MCP"(`[server]`의 http 모양은 url과 헤더의 환경 변수 이름이고 streamable HTTP만 받는다)에서 출발한다. 주소가 배포 환경마다 달라지는 문제 때문에 그 모양을 바꿔야 하면, mcp-http의 설계 인터뷰가 ADR 0042의 이력으로 바꾼다.
- **두 전송의 역할을 나눈다.** 시작할 때 무거운 것을 올리거나 여러 실행이 같은 데이터를 함께 보는 서버는 원격 MCP 서버(상주)가 기본이다. 가볍고 상태가 없는 도구, 바깥에서 받아 온 공개 MCP 서버, 사용자별 비밀 값이 필요한 도구는 stdio(실행마다 띄움)를 쓴다. stdio는 실행 사이의 격리를 프로세스로 보장하고, 공개 MCP 서버의 다수가 이 모양으로 배포되므로(어림, 세지 않았다) 지우지 않는다. 기준선 동안 stdio 전송에만 걸리는 것(런처, ADR 0034의 프로세스 정리)은 지금 상태로 두고 더하지 않는다. 전송과 무관한 것은 두 모양에 똑같이 건다. approval-rules가 도구마다 싣는 서버 이름(`.scratch/approval-rules/spec.md`의 `ToolSpec.server`)과, mcp-trust의 신뢰 수준·해시·주체 전파(ADR 0042 "원격 MCP")가 그것이다.

  | 서버의 성격 | 모양 | 예 |
  |---|---|---|
  | 시작할 때 무거운 것을 올리는 서버 | 원격 MCP 서버(상주) | 문서 검색 서버(임베딩 모델, 색인) |
  | 여러 실행이 같은 데이터를 함께 보는 서버 | 원격 MCP 서버(상주) | 사내 문서 색인, 사내 시스템 연동 게이트웨이 |
  | 가볍고 상태가 없는 도구 | stdio | 형식 변환, 날짜 계산 |
  | 바깥에서 받아 온 공개 MCP 서버 | 배포된 모양 그대로(대부분 stdio, 어림) | 파일 시스템, git |
  | 사용자별 비밀 값이 필요한 도구 | stdio(실행마다 격리) | 개인 계정으로 접속하는 도구 |

- **문서 검색 서버는 다른 저장소다(ADR 0048).** `.scratch/plan.md`는 그 저장소의 행을 `rag-server:<slug>`로 가리킨다.

## agent-os의 기준선

| 기능 | 한 줄 |
|---|---|
| approval-rules | 운영자의 규칙 파일(ADR 0044). 자리를 옮기지 않는다 |
| local-model | 모델 공급자에 OpenAI 호환 엔드포인트를 더한다(sdk 계약) |
| mcp-http | `[server]`에 http 모양을 더해 원격 MCP 서버에 접속한다(sdk 계약) |
| pilot-portal | 위젯을 담는 독립 질문 페이지와 사이트 토큰 발급 |
| doc-qa-agent | 출처를 달아 답하고 근거가 없으면 모른다고 답하는 참조 에이전트와 스킬 |
| release-image | 판마다의 이미지, 단독 compose와 배포 안내 |
| answer-eval | 트레이스를 읽어 검색 적중, 출처 적중, 사람 판정을 합친 보고서와 모델 비교 |
| ops-backup-upgrade | agent-os 데이터의 백업, 복원, 판 올림 |
| diag-bundle | 비밀과 최종 사용자 글을 기본으로 싣지 않는 진단 묶음 |
| deploy-package | 참조 배포: 문서 검색 서버와 함께 띄우는 compose, 밖으로 여는 포트 하나, 관리 명령 |
| pilot-release | 판 0.1.0, 릴리스 노트, 지원 범위 문서 |

문서 검색 서버의 행(bootstrap, rag-mcp, rag-admin, search-eval, rag-ops)은 그 저장소의 계획에 둔다. 그 저장소는 아직 없다.

## 앞당김

배포 환경이 나머지 열셋 가운데 하나를 요구하면, 그 행과 그 행이 기술적으로 기대는 행의 Blocked by를 풀어 제품 1.0 뒤 첫 프론티어로 올리고 이 ADR의 이력에 적는다. 예를 들어 사용자가 많아 파일 트레이스로는 목록과 보존 관리가 버거우면 trace-postgres를 당기고, 배포 환경이 이미 쓰는 관측 도구로 실행을 보려 하면 otel-export를 당긴다.

## Considered Options

- **열일곱을 먼저 끝내고 사용처를 세운다.** 거부했다. 넉 달 넘게(어림) 런타임 기능만 쌓이고, 그 기능을 시험할 사용처가 없다.
- **기준선 뒤에 열일곱을 원래 차례대로 둔다.** 거부했다. value-masking이 trace-postgres, run-cost, token-limit 뒤에 있어서, 최종 사용자의 글과 문서 조각이 쌓이는 트레이스에 값 가림 없이 기능만 늘어난다.
- **approval-rules까지 기준선 뒤(슬라이스 10)로 미룬다.** 제안서의 안이었다. 거부했다. 설계와 명세가 섰고 티켓을 쓰는 중이라, 미루면 명세가 석 달 넘게 기다리는 사이 mcp-http가 같은 MCP 어댑터를 바꿔 명세를 다시 맞춰야 할 수 있다(어림). 사용자가 "지금 자리에서 계속"을 골랐다(일지 2026-11-06-02).
- **상주 검색 서비스와 실행마다 뜨는 얇은 stdio 서버로 나눈다.** 거부했다. agent-os를 바꾸지 않지만, 두 구성 요소 사이에 자체 API를 하나 더 두어야 하고 얇은 서버의 시작 비용은 여전히 질문마다 남는다.
- **stdio 서버를 `serve`가 켜질 때 한 번 띄워 두고 여러 실행이 다시 쓴다.** 거부했다. 실행 사이의 격리가 사라지고, 죽은 서버를 다시 띄우는 감시를 core가 떠안아 원격 MCP 서버가 표준으로 주는 것을 다시 만들게 된다.
- **stdio 모양을 지우고 http 모양만 남긴다.** 거부했다. `command` 모양을 지우는 계약 변경이고, 공개 MCP 서버와의 호환과 실행 사이의 격리를 잃는다.

## Consequences

- **기준선 판의 강제.** 저자의 `requires_approval`, 꺼진 플러그인, 운영자의 규칙 파일까지다. MCP 서버의 신뢰 수준과 값 기반 마스킹이 없으므로, 제품 0.1의 지원 범위 문서(pilot-release)에 알려진 한계로 적는다.
- **규칙 파일의 기본값.** 규칙 파일에 적지 않은 도구는 묻는 것이 기본이고, 최종 사용자가 주체인 실행에서 그 물음은 운영자의 검토가 아니라 최종 사용자 자신의 확인이다(ADR 0044). 그래서 doc-qa와 참조 배포는 검색 도구를 허락하는 규칙 파일을 함께 낸다. 그러지 않으면 질문마다 검색 도구를 부르기 전에 실행이 멈추고, 위젯에서 질문한 사람이 그 호출을 직접 승인해야 답이 나온다.
- **같은 파일을 고치는 두 행.** approval-rules와 mcp-http가 둘 다 `adapters/mcp.py`를 고친다. 나중에 병합하는 쪽이 충돌을 풀고, approval-rules가 도구마다 싣는 서버 이름이 원격 MCP 서버의 도구에도 실리는지를 시험으로 본다.
- **단일 인스턴스와 JSONL.** 기준선과 제품 1.0은 `serve` 한 프로세스와 파일 트레이스다. 1.0에 드는 value-masking은 프로세스를 늘리지 않는다. PRD의 프로세스 넷은 trace-postgres가 PostgreSQL과 Redis를 더하고 retention-worker가 worker를 더해 선다(ADR 0042 묶음 ②의 표). 그래서 audit-export의 조회는 JSONL 위에서 먼저 돌고, 트레이스 저장소 포트의 읽기로 지어 trace-postgres 뒤에도 남게 한다.
- **원격 MCP 서버의 수명.** agent-os 밖(배포)이 관리한다. 서버가 꺼져 있으면 실행이 원인 `tool_connection`으로 끝난다. 실행마다 따로 뜨던 stdio 서버와 달리 여러 실행의 요청을 한 프로세스가 받으므로, 서버가 동시 요청을 안전하게 다뤄야 한다.
- **문서 속 지시.** mcp-trust 전에는 런타임이 검색 결과를 바깥 글로 감싸지 않는다. 그때까지는 doc-qa의 프롬프트가 검색 결과를 데이터로 엮는 것에 기댄다.
- **늦어지는 것.** 나머지 열셋의 차례가 기준선과 1.0만큼(어림 대여섯 달) 늦어진다.
- **`.scratch/plan.md`.** mcp-trust, principal-propagation, value-masking은 슬라이스 10으로, 나머지 열셋은 11~14로 옮긴다. 슬라이스는 더 이상 ADR 0042의 묶음과 같지 않다. 기록(일지, 닫힌 harness 티켓)의 옛 번호는 고치지 않는다. 행마다 설계 인터뷰가 먼저 볼 것은 그 행의 내용 칸에 적고, 여러 행이 함께 쓰는 자료(GPU 환경과 요금, 모델 배치 구성, 남은 확인)는 일지 2026-11-06-02의 "설계 인터뷰 입력" 절에 두어 행에서 가리킨다. 요금은 조사한 시점의 기록이라 그 행의 설계 인터뷰가 쓰기 전에 다시 확인한다.
- **같은 PR에 드는 것.** PRD 개정(2026-11-06 사용자 승인), `CONTEXT.md`의 배포 환경·참조 배포·문서 검색 서버, ADR 0042의 이력과 포인터, ADR 0044의 포인터다.
