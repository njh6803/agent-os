# 관리 화면은 브라우저가 토큰을 들고 Next는 무상태 중계다

슬라이스 3의 관리 화면(`web/apps/admin`, Next.js)이 관리 API와 채널의 승인 경로를 부른다. 파이썬 서버는 루프백에만 서고, `/health` 밖 전부에 베어러 토큰을 요구하며, CORS가 없다(ADR 0011·0015). 브라우저와 그 서버 사이에서 누가 토큰을 드는지가 새 앱의 노출 경계를 정한다. **운영자가 화면에 토큰을 넣고 브라우저가 매 요청의 헤더에 싣는다. 토큰은 sessionStorage에 두어 탭이 닫히면 사라진다. Next는 같은 출처의 `/api/*`를 파이썬으로 넘기는 `rewrites`일 뿐이고, 비밀도 API를 부르는 서버 코드도 없다. Next도 루프백에만 선다.** 이렇게 하면 "노출 경계는 인증이 맡는다"(ADR 0011)가 파이썬 서버 한 자리에 그대로 남는다. 헤더에 싣는 토큰은 쿠키처럼 저절로 실리지 않아 CSRF와 DNS rebinding이 토큰에 닿지 않고, 파이썬은 한 줄도 바뀌지 않는다. 채널 토큰을 넣으면 승인 콘솔이 되고 넣지 않으면 읽기 전용이다. ADR 0015가 "운영자가 고른다"고 적은 선택이 탭마다의 입력이 된다.

## Considered Options

- **Next 서버가 두 토큰을 든다(BFF).** 브라우저가 토큰을 모르므로 XSS가 토큰에 닿지 않는다. 그러나 Next가 토큰 없이 관리와 채널 권한을 쓰는 새 면이 된다. fail-closed를 지키려면 Next에 로그인과 세션, CSRF 방어, Host 검사를 새로 세워야 한다. Next 16.3.6은 어느 모드에서도 Host를 검사하지 않고, Server Actions의 CSRF 검사는 Host와 Origin이 같은 이름인 DNS rebinding 모양을 통과시킨다(`.scratch/web-admin/probes/next_measure.mjs`). ADR 0011의 "지금 비용이 0일 때 필수로 만들지 않으면 나중에 기본값이 fail-open으로 굳는다"가 새 앱에 그대로 걸린다. 거부했다.
- **브라우저가 파이썬을 직접 부른다(CORS).** Next가 서버로 설 필요가 없다. 그러나 파이썬에 CORS 미들웨어가 들고, 토큰 없는 preflight를 fail-closed 미들웨어 앞에서 통과시켜야 해 allowlist가 는다. `plan.md`는 CORS를 위젯(슬라이스 4)의 몫으로 넘겼다. 거부했다.
- **라우트 핸들러(`app/api/[...path]`)로 중계한다.** 압축 설정과 무관하게 SSE가 흐르고 경로 허용 목록을 둘 수 있다. 그러나 중계가 코드가 되고 그 코드가 경계에 선다. 잰 함정이 셋이다. 요청 헤더를 그대로 넘기면 chunked POST가 500이다. `request.signal`을 넘기지 않으면 GET의 끊김이 상류에 닿지 않는다. `OPTIONS`를 내보내지 않으면 Next가 상류에 묻지 않고 204로 답한다. 거부했다.
- **토큰을 localStorage에 둔다.** 한 번 넣으면 남는다. 그러나 디스크에 평문으로 남고 모든 탭이 공유한다. 거부했다. 메모리에만 두는 안은 새로 고침마다 다시 넣게 해서 거부했다.

## Consequences

- **`rewrites`는 `compress: false`와 함께다.** 기본 압축은 브라우저가 늘 보내는 gzip 요청에 SSE를 압축해, 이벤트 열 개가 끝에 한꺼번에 도착했다. 끄면 500ms 간격 그대로 흐른다. `Authorization`, `OPTIONS`, 클라이언트의 끊김은 그대로 상류로 간다. 미들웨어 `RequireToken`은 메서드를 가르지 않으므로(`http/auth.py`) 다른 출처의 preflight는 토큰 없는 `OPTIONS`로 401에서 끝난다. CORS가 없는 것이 곧 차단이다.
- **중계는 침묵 30초에서 끊긴다.** `rewrites`의 프록시 타임아웃 기본값이다. 채널 스트림에서는 `EventSourceResponse`의 keepalive 주석이 이것을 덮는다(ADR 0014, 15초 간격이면 310초 침묵도 버텼다). keepalive를 끄거나 간격을 30초 넘게 늘리면, 모델 호출이 조용한 동안 관리 화면의 재개 스트림이 끊긴다. 둘은 짝이다.
- **Next는 루프백에만 선다.** 인자 없이 띄우면 dev든 start든 `0.0.0.0`과 `[::]`에서 듣는다(LISTEN 소켓으로 쟀다). 중계가 LAN에 열리면 토큰이 LAN 위를 평문으로 지난다(ADR 0011의 CWE-319). 관리 화면의 `dev`와 `start`는 시작 래퍼를 거치고, 래퍼는 호스트가 `127.0.0.1`이나 `::1`이 아니면 구성 오류로 끝낸다. `serve`와 같은 모양이고 ADR 0011의 2026-09-28 이력이 받는다. 운영자가 `next`를 직접 다른 인자로 띄우는 것은 막지 못한다. `uvicorn`을 직접 띄우는 것과 같은 자리다.
- **Next에 API를 부르는 서버 코드를 두지 않는다.** Server Actions, 라우트 핸들러, 서버 컴포넌트의 데이터 가져오기가 없다. 있으면 그 코드가 토큰 없이 서버 쪽에서 도는 길이 되어, BFF가 거부된 이유가 뒷문으로 돌아온다. 화면은 클라이언트 컴포넌트이고 데이터는 브라우저가 가져온다(ADR 0021).
- **XSS가 곧 토큰 유출이다.** 트레이스는 도구 결과와 프롬프트, 곧 바깥에서 온 텍스트를 싣는다(ADR 0009의 열린 문제). 화면은 그것을 텍스트로만 그리고 HTML로 렌더하지 않는다. React가 기본으로 이스케이프하므로 이 약속은 `dangerouslySetInnerHTML`과 마크다운의 HTML 렌더를 쓰지 않는 것으로 지켜진다.
- **Host 검사를 두지 않는다.** DNS rebinding으로 들어온 페이지는 출처가 달라 이 탭의 sessionStorage를 읽지 못하고, 토큰 없이는 중계를 지나도 401이다. 방어는 토큰이 저절로 실리지 않는다는 사실 하나에 기댄다. 쿠키를 들이는 날 이 줄을 다시 본다.
- **승인 뒤 재개 스트림은 받는 대로 화면에 붙는다.** 결정은 채널의 `POST /runs/{run_id}/approval`로 가고 응답은 SSE다. 창을 닫거나 떠나면 연결만 끊기고 실행은 끝까지 간다(ADR 0014).
- **꺼진 에이전트나 그 mcp 때문에 재개할 수 없는 실행은 미리 알린다.** 멈춘 실행의 에이전트와 그 매니페스트의 mcp를 `/plugins` 행과 이어 결정 버튼을 막는다. 화면을 연 뒤에 꺼진 경합은 409 봉투가 말한다(ADR 0017).
- **위젯(슬라이스 4)은 이 결정을 물려받지 않는다.** 최종 사용자의 브라우저는 운영자의 토큰을 들 수 없다. CORS와 최종 사용자 인증은 그 기능이 정한다(ADR 0015).
