# 세션 컨텍스트는 단계 경계의 인계와 40만 자동 압축 창으로 묶고, 토큰 사용은 사용량 장부에서 만든 일간 보고서로 지켜본다

사용 한도가 빨리 찬다는 문제로 세션 기록을 쟀다(`.scratch/harness/probes/token_usage/`, 결과는 그 README의
2026-10-15 실행). 지난 24시간 환산 비용의 87.0%가 메인 세션이었고 서브에이전트는 13.0%였다. 모델 호출은 그때의
세션 컨텍스트 전체를 다시 읽으므로 비용은 호출 수와 세션 컨텍스트 크기의 곱을 따른다. 메인 세션은 티켓 하나를
하는 동안 압축 없이 커졌다. 1M 토큰 모델은 약 96.7만 토큰에서야 자동 압축한다(웹 요약,
https://code.claude.com/docs/en/model-config.md). 기록에 남은 자동 압축도 모두 96.7만~100.2만 토큰에서 일어났다.
시작 컨텍스트는 중앙값 3만 토큰이었고, 이 저장소에서 쓰지 않는 플러그인의 스킬 목록이 그 일부를 차지했다. 설계
인터뷰(일지 2026-10-15-18)에서 아래를 정했다. 용어는 `CONTEXT.md`의 하네스 절이다.

**세션 컨텍스트를 묶는다.**
- 사용자 설정(`~/.claude/settings.json`)의 `autoCompactWindow`를 40만 토큰으로 둔다. 한도는 계정 단위라 모든
  프로젝트에 건다. 기본 1M 창에서 압축이 약 96.7만에 일어나는 것으로 보아 압축은 창보다 조금 앞에서 일어날 것으로
  보고(어림), 실제 지점은 적용할 때 확인한다.
- 세션 컨텍스트가 20만 토큰을 넘은 뒤 첫 단계 경계(구현을 커밋한 뒤, PR을 연 뒤)가 오면 훅이 모델에게 인계를
  지시한다. 인계는 `next-session`과 `open-session`으로 하고, 새 세션은 같은 티켓·브랜치·워크트리에서 남은 일을
  잇는다. 사람이 `/compact`를 치지 않는다. 같은 문턱에서 사람에게는 알림만 보이고 막지 않는다.
- 레벨 스윕 기간에 스윕하는 브랜치의 인계 세션은 그 브랜치의 갈래(`tools/model_sweep.py`가 내는 값)로 연다.
  `next-session` 결정표의 "남은 것이 PR 반영·병합뿐이면 `Sonnet 5.5 / high`"는 스윕 밖의 브랜치에만 쓴다.
- Read나 Bash의 결과가 문턱(값은 명세에서 정한다)을 넘으면 훅이 모델에게 Grep으로 위치를 찾고 범위를 주어
  읽으라고 알린다. 막지 않는다.

**시작 컨텍스트를 줄인다.** 이 저장소에서 쓰지 않는 플러그인 가운데 넷(`document-skills`, `example-skills`,
`skill-creator`, `code-review` 플러그인판)을 프로젝트 설정(`.claude/settings.json`의 `enabledPlugins`)에서 끈다.
`frontend-design`, `claude-security`, `coderabbit`, `slack`은 앞으로 쓸 것으로 보고 둔다. `claude-hud`는 상태줄이 쓰고,
스킬 목록에 보인 `cowork-plugin-management`는 사용자 설정의 `enabledPlugins`에 없어 이번에 다루지 않았다.
Playwright MCP는 두 벌이 실리므로 사용자 범위의 서버를 지우고 플러그인판만 남긴다.

**셀프 리뷰의 표준 축은 변경 종류와 상관없이 `sonnet`·`high`로 돈다.** 명세 축은 지금처럼 메인 세션의 모델과 노력을
물려받는다. 다른 서브에이전트(`bug-perf-review`, `spec-reviewer`, 조사 위임)의 모델과 노력은 보고서를 본 뒤에 정한다.

**토큰 사용은 사용량 장부에서 다시 계산한 보고서로 지켜본다.** 작업 스케줄러가 매일 모델 없이 세션 기록을 읽어 주
체크아웃의 `.scratch/token-report/`(커밋하지 않는다)에 달마다 하나인 사용량 장부를 쌓는다. 일간 보고서(최근 7개),
주간 보고서(최근 4개), 4주 요약(모두 보존)은 장부에서 다시 계산해 만든다. 그날 첫 세션이 시작될 때 훅이 요약 몇
줄을 사람에게만 보인다. 세션이 시작될 때 훅이 그 세션의 계정 ID를 장부에 남겨, 보고서는 합계와 계정별 내역을
함께 낸다. 지표는 계정별·전체 환산 비용, 메인 세션과 서브에이전트, 모델·노력, 서브에이전트 유형, 상위 세션,
40만을 넘은 세션, 쉰 뒤의 캐시 재작성, 시작 컨텍스트(중앙값과 구성), 티켓(브랜치)별 비용과 PR 전후의 몫, 캐시
효율, 큰 도구 결과와 반복 Read다. 반복 Read에는 같은 세션에서 바뀌지 않은 파일을 다시 읽은 "다시 읽기 후보" 한
줄을 둔다. 하루 비용이 지난 7일 중앙값의 1.5배를 넘는 것 같은 이상치는 경보 줄로 맨 위에 올린다. 레벨 스윕의
갈래별 비교는 넣지 않는다.

**훅과 보고서 도구는 저장소 `tools/`에 두고 프로젝트 설정에 저장소의 훅 규약대로 등록한다.** 지난 24시간
비용이 모두 이 저장소의 것이었다. 다른 프로젝트의 세션은 경고를 받지 않고, 보고서에는 "계정 모름"으로 합계에만
든다.

**묶음 티켓을 줄이는 규칙은 지금 두지 않는다.** 보고서의 티켓별 비용으로 큰 티켓이 되풀이되는지 지켜보고, 되풀이되면
retro가 규칙 후보로 올린다(`CLAUDE.md` 교정 루프).

**레벨 스윕(ADR 0029 이력 2026-10-13)은 그대로 둔다.** 이 방침은 두 갈래에 함께 들어가고, 들인 시각을 스윕
프로브 README의 결과 절에 적는다.

## 근거

- **압축 창.** 지난 72시간에 시작한 메인 세션 522개로 어림하면, 압축 뒤 컨텍스트를 시작 컨텍스트에 요약 2만과 다시
  읽기 3만을 더한 값으로 둘 때 읽는 컨텍스트가 압축 지점 20만에서 60%, 30만에서 50%, 40만에서 41% 준다. 세션당 압축은
  각각 0.6회, 0.2회, 0.1회다. 15만으로 내려도 절감은 61%로 거의 같고 압축만 3.3회로 는다. 40만은 20만·30만보다 작업
  도중의 압축이 드문 안전망이고, 그보다 앞의 정리는 인계가 맡는다.
- **압축이 작업을 끊는지.** 기록 전체의 압축 17건(포크한 세션에 복사된 같은 압축과 시험 세션을 뺐다) 가운데 12건
  뒤에 세션은 117~341번 더 호출했다. 압축 뒤 첫 사람 입력(도구 결과와 시스템 알림은 건너뛴다)의 출처는 사람 7건, 스킬
  재주입 4건, 앱 알림 2건, 세션 간 메시지 1건, 없음 3건이었고, 사람 7건 가운데 다섯은 다음 단계 지시, 둘은 질문·새
  요청이었다. 압축 전의 맥락을 다시 설명한
  글은 없었다(입력 글을 읽은 판단이다). 압축 뒤 30호출 안에 압축 전에 읽은 파일을 다시 읽은 것은 0~8회였다. 품질에
  준 영향은 재지 않았다.
- **인계를 고른 까닭.** `/compact`는 내장 명령이라 모델이 Skill 도구로 부르지 못한다(Skill 도구 설명). 훅이 그것을
  실행하는 방법은 공식 문서에서 찾지 못했다(웹 요약, https://code.claude.com/docs/en/hooks.md, 앞 200K자만 읽었다).
  그래서 찾은 길 가운데 "단계 경계에서 사람 손 없이"를 이루는 것은 인계뿐이다. 새 세션은 시작 컨텍스트(중앙값
  3만)에서 다시 시작한다. 비용 상위 세션 열 가운데 아홉은 브랜치 하나, PR 하나였다(인터뷰 중 스크래치 스크립트로
  셌고 프로브에는 없다). 크기는 티켓 수가 아니라 티켓 하나 안에서 커졌다.
- **CI 대기와 쉬는 시간.** `tools/wait_ci.py`를 백그라운드로 띄운 대기(중앙값 4.3분) 뒤 깨어난 호출은 65회에 비용의
  0.92%였고, 컨텍스트를 다시 쓴 것은 2회였다. 메인 세션의 캐시 쓰기는 대부분 1시간 TTL이었고, 60분 넘게 쉰 뒤 깨어난
  호출 30회는 모두 컨텍스트를 다시 썼다(비용의 7.8%). 대기 자체는 싸고, 비싼 것은 한 시간을 넘긴 휴지다. 그래서 CI
  대기는 바꾸지 않는다.
- **리뷰 축.** 지난 24시간 서브에이전트 비용의 대부분이 general-purpose(전체의 11.5%)였고, 그 대부분이 셀프 리뷰
  두 축이었다(인터뷰 중 스크래치 스크립트로 셌고 프로브에는 유형까지만 있다). 서브에이전트 비용은 Opus 5.5 `xhigh`가
  7.7%로 가장 컸다. 노력을 지정받지 않은 서브에이전트가 메인 세션의 노력으로 도는
  것으로 본다(어림, 부모 세션과 짝지어 보지 않았고 문서 문장도 찾지 못했다). 결정표(`docs/model-selection.md` 87행)는 Sonnet 5.5를
  명세가 분명한 여러 단계의 도구 사용에는 `medium`, 어렵거나 긴 일과 그 밖의 일에는 `high`로 둔다. 표준 축은 diff
  전체를 표준 문서와 대 보는 긴 일로 보고 사용자가 `high`를 골랐다.
- **플러그인.** 최근 2주 이 저장소의 스킬 호출 1,556회 가운데 플러그인 스킬은 `anthropic-skills` 4회였고, MCP 가운데
  Playwright 두 벌은 0회였다. 가장 큰 첫 스킬 목록 29,218자 가운데 끄는 넷이 7,260자였다. 프로젝트 설정의 `false`는
  그 프로젝트에서만 사용자 설정의 `true`를 이긴다(웹 요약, https://code.claude.com/docs/en/plugins/loading.md).
- **세션 컨텍스트의 구성.** 지난 48시간 메인 세션에 들어온 항목을 "글자 수 × 그 뒤 실려 간 호출 수"로 매긴 무게는
  Bash 결과 17.1%, Read 결과 13.7%, 스킬 목록 첨부 12.4%였다. 같은 세션에서 바뀌지 않은 파일을 다시 읽은 후보는
  Read 글자의 3.3%이고 그 가운데 `tools/tidy_checkouts.py` 하나가 47%였다. 두 수를 곱하면 무게 전체의 약 0.5%다
  (기간과 창의 뜻이 다른 두 측정을 손으로 곱한 어림이다).

## Considered Options

사용자에게 선택지로 올렸지만 고르지 않은 것들이다.

- **사람이 단계 경계에서 `/compact`를 친다(경고 20만 + 자동 40만, 추천).** 거부했다. 사용자가 사람 손 없이 되기를
  골랐다.
- **크기로 압축하고 단계 경계에서는 진행 상태만 기록한다(추천).** 거부했다. 사용자가 단계마다 새 세션으로 인계하기를
  골랐다. 인계는 세션 컨텍스트를 시작 컨텍스트로 되돌리고, 상태 기록은 압축을 견디게 할 뿐 줄이지는 않는다.
- **크기로만 자동 압축한다.** 거부했다. 디버깅 도중에 압축될 수 있다.
- **자동 압축을 20만에 둔다(경고 15만).** 거부했다. 절감은 크지만 세션당 0.6회 압축되어 40만(0.1회)보다 작업 도중에
  요약될 일이 여섯 배쯤 잦다. 압축이 작업 품질에 주는 영향을 재지 않은 채 그 위험을 늘리지 않는다.
- **경고 문턱을 넘으면 프롬프트 제출을 막는다.** 거부했다. 막는 훅은 지침을 둔 뒤에도 어겨진 것이 확인된 다음에
  더한다(`CLAUDE.md` 교정 루프, `.claude/rules/tools.md`). 큰 파일 읽기를 막는 훅도 같은 까닭으로 알림에 그친다.
  전체가 필요한 읽기도 막히고, 부분만 읽은 파일을 Edit·Write할 수 있는지는 확인하지 않았다.
- **레벨 스윕을 멈추고 구현·하네스를 `medium`으로 연다.** 거부했다. 판정이 "결론 없음"이 되어 결정표의 모델 칸을
  바꿀 근거를 잃는다. 판정이 `medium`의 손을 들면 그 뒤의 세션이 모두 싸진다.
- **리뷰 두 축을 모두 `sonnet`으로 돌리거나, 표준 축을 `xhigh`로 돌린다.** 거부했다. 명세 축은 명세가 요구한 것과
  맞는지 판단하는 일이라 품질 위험이 크다. `xhigh`는 평가에서 품질 이득이 보일 때만 쓰라는 것이 결정표의 기준이다.
- **주간 보고서(추천)와 `~/.claude/token-report/`(추천).** 거부했다. 한도가 하루 안에 차서 사용자가 일간을 골랐고,
  보고서는 저장소에서 열기 쉬운 주 체크아웃의 `.scratch/`에 둔다.
- **보고서 파일끼리 합쳐 쌓는다.** 거부했다. 세션 기록이 지워지면 합칠 때 빠진 수를 되살릴 수 없고, 반올림이
  겹친다. 장부에서 다시 계산하면 오래된 보고서를 지워도 잃는 것이 없다.
- **PC 합계만 내거나, 보고서에 생성 때의 계정만 적는다.** 거부했다. 한도는 계정마다 차므로 계정별 내역이 든다. 계정
  ID는 세션에 붙인 이름표라 합계도 함께 낼 수 있다.
- **사용자 설정이 훅과 보고서 도구를 불러 모든 프로젝트에 건다(추천).** 거부했다. 저장소의 등록 대조
  (`tools/run_hooks.py`)와 시험을 받지 못하고, 비용의 거의 전부가 이 저장소에서 났다. 자동 압축 창만은 설정 하나라
  사용자 설정에 둔다.
- **2주간 쓰지 않은 플러그인을 모두 끈다(추천).** 거부했다. 사용자가 앞으로 쓸 넷을 남겼다.
- **모델이 세션마다 필요 없던 읽기를 판정한다.** 거부했다. 필요했는지는 작업의 의도를 알아야 가를 수 있어 기록만으로는
  판정하지 못하고, 모델에게 판정시키면 그 자체가 토큰을 쓰며 탐색하다 관계없다고 확인한 읽기를 낭비로 잘못 읽는다.
  기계로 셀 수 있는 다시 읽기 후보 한 줄로 충분하다.

## Consequences

- **바뀌는 자리.** 명세와 티켓이 맡는다. 저장소 밖에서는 사용자 설정의 `autoCompactWindow`, `~/.claude.json`의 사용자
  범위 Playwright 서버, 작업 스케줄러 등록이 바뀐다. 이 셋은 저장소의 검사와 리뷰를 받지 않으므로 명세가 적용 뒤
  확인을 단계로 둔다. 저장소 안에서는 프로젝트 설정의 `enabledPlugins`와 새 훅 등록, `.gitignore`의
  `/.scratch/token-report/`, `code-review` 스킬(표준 축의 모델과 노력), `docs/model-selection.md`의 표준 축 행과 "PR을 연
  세션은 반영과 병합까지 한다"는 186행의 문단, `docs/constitution/operations.md` 브랜치와 병합의 "PR을 연 세션이 반영과
  병합까지 한다"(20행), `next-session`의 같은 문장(8행)과 결정표의 PR 반영·병합 칸, 새 훅(문턱 알림과 인계, 큰 결과
  알림, 계정 기록과 보고서 요약), 보고서 도구가 바뀐다.
- **인계와 워크트리 확인.** 새 세션은 같은 워크트리로 들어가고, ADR 0032의 확인은 같은 브랜치를 제목으로 한 실행
  중 세션이 있으면 사람에게 넘긴다. ADR 0032가 드물다고 본 이 길(연 세션이 아직 돈다)이 인계에서는 늘 지나는 길이
  된다. 그래서 인계하는 세션은 새 세션을 열고 바로 끝낸다.
- **인계와 레벨 스윕.** 갈래는 브랜치 이름만으로 정해진다(`tools/model_sweep.py`의 `arm`). 지금의 `next-session`은 칸이
  `Opus 5.5 / xhigh`일 때만 그 도구를 부르므로, 인계 지시문은 결정표 칸과 상관없이 스윕 브랜치이면 도구를 불러야
  한다(위 결정). 소급 측정의 비용은 브랜치마다 모으므로(`session_cost/README.md`) 세션이 둘로 나뉘어도 한 행이다.
  판정 전에 두 갈래의 조건이 함께 바뀌므로 그 시각을 결과 절에 적는다.
- **용어집.** `CONTEXT.md`의 범위를 하네스까지 넓히고 하네스 절을 들였다. 지시문, 대기열 같은 앞선 하네스 용어는
  소급해 넣지 않았다.
- **`tidy-checkouts`의 다시 읽기.** 다시 읽기 후보의 47%가 `tools/tidy_checkouts.py`였다. 보고서가 아니라 그 스킬을
  고칠 몫이라 회고 후보로 둔다. 대기열에 올릴지는 retro가 판정한다.
- **헌법 판.** `operations.md` 브랜치와 병합의 문장을 바꾸므로 patch다. 원칙과 게이트, 손으로 치는 검증 명령은 그대로다.
  이 ADR은 2026-10-15에 사용자가 승인했다. 스윕 브랜치의 인계 세션을 그 갈래로 여는 것도 그때 따로 확인받았다.
- **못 보는 것.** 압축과 인계가 작업 품질에 주는 영향은 재지 않았다. 환산 비용은 청구액도 한도의 남은 양도 아니다.
  `autoCompactWindow`가 압축이 일어나는 지점과 얼마나 다른지, 계정을 바꾸면 `~/.claude.json`의 계정 정보가 바로
  바뀌는지, 세션 시작 훅의 `systemMessage`가 모델 컨텍스트에 들어가지 않는지(웹 요약)는 구현 때 확인한다. 압축
  지점의 절감률은 압축 뒤의 증가가 압축 전과 같다는 가정 위의 어림이다. 근거의 웹 요약은 서브에이전트가 WebFetch로
  받은 것이고 원문과 바이트로 대 보지 않았다.
