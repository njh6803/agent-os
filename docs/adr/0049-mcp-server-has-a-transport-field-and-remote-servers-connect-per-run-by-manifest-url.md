# MCP 매니페스트의 `[server]`는 `transport` 칸으로 stdio와 http를 가르고, 원격 MCP 서버에는 매니페스트에 적은 주소로 실행마다 붙되 헤더 값은 환경에서 읽고 닫기는 취소에서 보호한다

core는 실행마다 도구 연결을 열고(`core/run.py`의 `self._tools.connect`), MCP 어댑터는 서버마다 stdio 클라이언트로 새 프로세스를 띄운다(`adapters/mcp.py`의 `stdio_client`. main `24fdbe9a`의 코드를 읽었다). 임베딩 모델과 색인을 올리는 문서 검색 서버는 그래서 상주해야 하고, ADR 0046이 원격 MCP 서버를 claude-code-compat에서 mcp-http로 떼어 기준선에 넣으며 그 모양은 ADR 0042 묶음 ③의 "원격 MCP" 줄(`[server]`의 http 모양은 url과 헤더의 환경 변수 이름이고 streamable HTTP만 받는다)에서 출발한다고 정했다. 그 줄은 뼈대만 적었다. 주소를 어디에 둘지, 두 전송을 어떻게 가를지, 서버가 꺼졌을 때 무엇이 보일지, 취소된 실행이 연결을 어떻게 닫을지는 비어 있었고, mcp-http 설계 인터뷰(일지 2026-11-09-1229)가 그것을 정했다. 결정의 원문은 그 일지의 `> 사용자:` 인용과 사용자가 확인한 합의 요약 여덟이고, 아래가 요약과 다르게 읽히면 일지가 원천이다.

인터뷰 전에 라이브러리를 읽었다. mcp 2.3.0의 `streamable_http_client(url, *, http_client=None, terminate_on_close=True, max_sse_event_size=1MB)`에는 헤더 인자가 없어 토큰을 실으려면 `httpx2.AsyncClient`를 만들어 넘겨야 하고, 넘기지 않을 때 라이브러리가 만드는 기본 클라이언트의 기한은 접속·쓰기·풀 30초, 읽기 300초다. 연결을 닫을 때의 세션 종료 요청(DELETE, `terminate_session`)은 `finally`에서 보내되 취소 보호(`CancelScope(shield=True)`)가 없고, 서버 쪽 세션은 mcp의 서버 구현이 기본 1800초 유휴 뒤 닫는다(`mcp/client/streamable_http.py` 695~794줄, `mcp/shared/_httpx_utils.py` 32~64줄, `mcp/server/streamable_http_manager.py` 39~111줄을 읽었다). httpx2 2.13.0 `AsyncClient`의 `trust_env` 기본값은 True다(`httpx2/_client.py` 192·622줄을 읽었다). 닫힌 포트(루프백에서 바인드했다 놓은 포트)에 붙으면 이 PC(윈도우)에서 2.2초 뒤 `ConnectError`로 끝났다(세션 스크래치 스크립트로 한 번 손으로 봤다. 리눅스에서는 재지 않았고, 명세의 프로브가 다시 잰다). `core/`와 `sdk/`에는 환경을 읽는 코드가 없다(grep).

**`[server]`는 `transport` 칸으로 두 전송을 가른다. 칸이 없거나 `"stdio"`면 지금의 `command`·`args`이고, `"http"`면 매니페스트에 글자 그대로 적은 `url`과 헤더 이름마다 환경 변수 이름을 적는 선택 표 `[server.headers]`다. 원격 MCP 서버에는 실행마다 붙어 세션을 열고 도구 목록을 읽으며, 헤더 값은 어댑터가 접속 직전에 환경에서 읽고 어디에도 싣지 않는다. 서버가 꺼졌거나 주소가 틀렸거나 헤더의 환경 변수가 없거나 인증이 거부되면 여는 단계의 `ConnectionError`이고 실행은 `run_failed` 원인 `tool_connection`으로 끝난다. 재시도와 미리 확인은 없다. 연결을 닫을 때는 세션 종료 요청과 클라이언트 닫기를 취소에서 보호하되 2초 안에 끝내고, `httpx2`를 런타임 직접 의존으로 선언한다.**

## 결정

- **매니페스트.** `transport`는 `"stdio"`·`"http"`의 닫힌 값이고 없으면 `"stdio"`다. 그래서 지금 있는 매니페스트는 고치지 않는다. stdio 모양은 `command`·`args`, http 모양은 `url`과 선택 표 `[server.headers]`(헤더 이름 → 환경 변수 이름)이고, `secret_args`는 두 모양이 같이 쓴다. `url`은 `http`·`https`만 받고 `사용자:비밀번호@`(사용자 정보)가 들면 매니페스트를 읽는 단계에서 거부한다. 환경 변수 이름은 글자·숫자·밑줄 꼴만 받는다. 한 모양의 칸을 다른 모양에 적으면(http에 `command`) 그 모양의 모르는 칸으로 거부된다. Claude Code의 `.mcp.json`도 `type` 칸으로 전송을 가르는 선례다(ADR 0042 "원격 MCP" 줄의 `type http` 항목). sdk에는 모양마다 모델이 하나씩 서고(`StdioServer`, `HttpServer`) `transport`로 가르는 합이 `McpServer`다. 그래서 `openapi.json`의 매니페스트 응답에는 두 모양이 oneOf로 따로 서고 생성한 TS 타입도 둘로 갈린다. 두 모양 모두 비어 있던 선택 칸이 늘거나 새 모양이 더해지는 것이라 옛 매니페스트의 뜻은 바뀌지 않고, ADR 0008의 2026-09-21 이력이 적은 기준(기존 필드의 뜻이나 필수 여부가 바뀔 때 올린다)대로 `schema_version`은 `"1"` 그대로다.
- **주소는 매니페스트에 그대로 적는다.** 플러그인 디렉터리는 배포의 몫이라(ADR 0042 전제) 배포마다 그 파일을 두고, compose에서는 서비스 이름이 곧 주소라 공개 데모와 참조 배포가 같은 주소를 쓴다. 주소는 비밀이 아닌 것으로 보아 관리 API의 매니페스트 응답과 실패 문구에 그대로 실린다. 사용자 정보가 든 주소를 거부하는 까닭이 이것이다.
- **접속.** 실행마다 어댑터가 접속 직전에 `[server.headers]`의 환경 변수를 읽어 `httpx2.AsyncClient`를 만들고(헤더는 그 값 전체를 그대로 싣고, 기한은 mcp의 기본값, `trust_env`는 기본값 True) mcp의 `streamable_http_client`에 넘겨 세션을 열고 도구 목록을 읽는다(쪽 나눔의 상한은 stdio와 같다). 그 뒤의 호출은 stdio와 같은 `McpConnection`이고 도구마다 `ToolSpec.server`에 그 플러그인의 이름이 실린다. 환경을 읽는 코드는 어댑터에만 있다(`.claude/rules/adapters.md`의 "파일, DB, 외부 서비스, 시계에 닿는 코드는 여기에만 산다". core와 sdk에는 환경을 읽는 코드가 없다, grep).
- **실패.** 여는 동안(접속, 세션 열기, `initialize()`, 도구 목록 읽기)의 실패는 지금 stdio와 같은 자리(`_connecting`)에서 `ConnectionError`가 되고 문구는 `MCP 서버 <이름>(<주소>)에 붙지 못했다: <원인>`이다. 헤더의 환경 변수가 없으면 붙지 않고 같은 예외로 끝내며 원인은 `헤더 <헤더 이름>의 환경 변수 <변수 이름>이 없다`다. 변수 없음은 실행 식별자가 생긴 뒤에 드러나 트레이스에 실패 하나가 남는다. 실행 전 거부를 두지 않은 대가다. 헤더 값은 문구에도 원인(`__cause__`)에도 트레이스에도 싣지 않는다(헌법 원칙 V). core는 지금처럼 그 예외를 원인 `tool_connection`의 `run_failed`로 쓴다(`.claude/rules/core.md` 실패 정책). 재시도는 하지 않고 접속 기한의 칸도 두지 않는다. 기한은 mcp 기본값(접속 30초, 읽기 300초) 위에 실행 전체의 기한(기본 600초)이 있다.
- **닫기.** 연결을 닫을 때 세션 종료 요청(DELETE)과 클라이언트 닫기를 `CancelScope(shield=True)`와 기한 2초로 감싸, 실행 기한이나 `serve` 종료로 취소된 실행에서도 종료 요청이 서버에 가게 한다. 2초는 stdio 상류가 서버가 스스로 끝나기를 기다리는 유예와 같은 값이다(ADR 0034). 2초를 넘기면 그만둔다. 어댑터가 만들어 넘긴 클라이언트는 라이브러리가 닫지 않으므로(`client_provided`, `mcp/client/streamable_http.py` 746~761줄을 읽었다) 닫기도 어댑터의 몫이다. 보호의 자리는 라이브러리 바깥이다. 종료 요청은 라이브러리 문맥의 `finally`(789~791줄)에서 나가고 어댑터는 그 문맥을 닫는 호출을 감쌀 수 있을 뿐이다. ADR 0034는 stdio에서 같은 모양(어댑터가 라이브러리 바깥에서 닫기를 보호한다)을 재 보고 안쪽 task group이 취소를 삼켜 서지 않는다고 거부했다. 그 까닭이 streamable HTTP 클라이언트(태스크 그룹 하나와 `finally`, 766~792줄)에도 걸리는지는 재지 않았다(어림). 명세의 프로브가 먼저 잰다. 프로브는 종료 요청이 서버에 닿았는지만이 아니라 기한이 걸린 실행이 지금처럼 시간 초과의 `run_failed`로 끝나는지도 본다. ADR 0034에서 서지 않았던 양상은 가려진 취소를 안쪽 task group이 삼켜 호출자에게 취소가 전해지지 않은 것이고, 지금 core는 범위가 취소를 받았는지(`cancelled_caught`)로 기한을 보므로 그것이 거짓이 되면 결말이 바뀐다(`.claude/rules/core.md`의 실행 타임아웃 항목). 서지 않으면 `terminate_on_close=False`로 라이브러리의 종료 요청을 끄고 어댑터가 자기 클라이언트의 응답 훅으로 받아 둔 세션 식별자(`Mcp-Session-Id` 헤더)로 직접 보낸다(2.3.0은 세션 식별자를 yield하지 않는다, 788줄을 읽었다. httpx2에 httpx와 같은 응답 훅이 있는지는 대 보지 않았다, 어림). 어느 길이든 결정(취소된 실행에서도 2초 안에 종료 요청을 보낸다)은 같고 자리만 명세가 정한다. 런처와 프로세스 그룹 정리(ADR 0034)는 이 전송에 걸리지 않는다.
- **의존.** `httpx2`를 런타임 직접 의존으로 선언하고 major 2로 묶는다(`httpx2>=2.13,<3`). 잠금 파일의 2.13.0은 `mcp` 2 뒤에서 이미 오던 것이라 락의 패키지와 판은 바뀌지 않는다(어림. 구현 티켓이 `uv lock`으로 확인한다). 직접 import하는 의존은 선언하는 관행을 따른 것이다(`pyproject.toml`의 `[dependency-groups]` 주석, ADR 0023의 pyjwt, ADR 0034의 mcp).
- **시험.** 테스트 픽스처는 지금의 stdio 픽스처와 같은 `MCPServer`를 streamable HTTP로 루프백의 빈 포트에 띄운 서버다(mcp 2.3.0 `MCPServer.run(transport="streamable-http", host, port, …)`, `mcp/server/mcpserver/server.py` 387~395줄을 읽었다). 사례는 도구 목록·호출·`ToolSpec.server`, 헤더 변수 없음, 꺼진 서버에 붙은 실행이 `tool_connection`으로 끝남(기능 계획의 수락), 취소된 실행에서 종료 요청이 서버에 닿음, calc 예시가 http 모양의 플러그인으로 도구를 써 트레이스가 남음(수락)이다. `plugins/mcp/`에 http 모양의 예시는 두지 않는다. 실제 플러그인은 doc-qa-agent가 가져온다.
- **범위 밖.** 접속을 미리 확인하는 길(diag-bundle), 운영자의 서버 파일과 신뢰 수준·도구 정의 해시(mcp-trust), SSE 전송, OAuth, 재시도, 접속 기한의 칸.

## Considered Options

- **주소를 환경 변수 이름으로 적는다(`url_env`).** 같은 매니페스트를 여러 배포가 쓴다. 그러나 실패 문구와 관리 API에 주소 대신 변수 이름만 보여 운영자가 어디에 붙으려 했는지 바로 알 수 없고, 변수가 비면 접속 실패가 하나 더 는다. 거부했다.
- **주소를 운영자의 서버 파일에 둔다.** mcp-trust가 계획한 운영자 파일을 이 기능이 먼저 만든다. mcp-trust의 설계(신뢰 수준, 해시)를 보기 전에 그 파일의 형식을 정하게 되고 범위가 는다. 거부했다. 배포마다 주소를 바꿔야 하는 요구가 서면 그 파일에서 다시 본다.
- **칸 유무로 가른다(`command`면 stdio, `url`이면 http).** 칸이 늘지 않지만, 둘 다 적거나 둘 다 없는 파일의 거부 문구가 두 모양의 오류를 함께 실어 길어지고 계약에 두 모양을 가르는 표지가 없다. 거부했다.
- **한 모양에 선택 칸을 더한다(`command`를 선택으로, `url`을 추가).** 계약에서 `command`가 필수에서 선택으로 바뀌는 변경이고, TS 타입이 `command?: string`이 되어 어느 모양인지 읽는 쪽이 좁혀야 하며 모양에 맞지 않는 칸을 거부하기 어렵다. 거부했다.
- **접속을 짧게 재시도한 뒤 실패한다.** 서버가 다시 뜨는 짧은 틈을 넘기지만, 꺼진 서버에서는 실패가 그만큼 늦고 재시도 수와 간격이 새 설정이 된다. 거부했다.
- **접속 기한을 매니페스트 칸으로 둔다.** 방화벽 뒤 주소의 30초 기다림을 줄일 수 있으나 칸이 계약에 들고, 잘못 적으면 느린 서버가 실패로 보인다. 거부했다.
- **꺼진 서버를 미리 아는 길을 지금 둔다.** CLI 명령(`agent-os mcp check`)은 CLI 표면과 테스트가 늘고 diag-bundle과 같은 일을 두 자리가 하게 된다. `/health`가 서버들을 함께 보는 것은 상태 확인마다 모든 서버에 요청이 가고 `/health`의 뜻(`serve`가 살아 있다)이 바뀌는 계약 변경이다. 둘 다 거부했다.
- **헤더의 환경 변수가 없으면 실행 전에 거부한다(`PluginError`).** 준비 단계는 core의 일이라 환경을 미리 보려면 포트에 메서드를 더해 어댑터가 대신 보게 해야 하고, 확인과 실제 읽기 사이에 환경이 바뀔 틈도 남는다. 거부했다.
- **닫기의 취소 보호 없이 서버의 유휴 만료에 맡긴다.** 상류가 그대로 주는 동작이고 서버 쪽 세션은 기본 1800초 뒤 닫히므로 남는 것은 프로세스가 아니라 서버 안의 세션 하나다. 추천이었으나 사용자가 취소가 잦을 때 서버에 세션이 최대 30분 쌓이는 것보다 보호 코드와 그 테스트를 골랐다(일지 2026-11-09-1229 라운드 1 둘째 호출).
- **bearer 토큰 전용 칸 하나(`bearer_token_env`), 또는 표와 전용 칸 둘 다.** 전용 칸만 두면 토큰 밖의 헤더(API 키 헤더 등)가 필요한 서버에 붙지 못하고, 둘 다 두면 `Authorization`을 두 자리에 적은 충돌을 거부해야 한다. 거부했다. 치르는 값은 운영자가 `Bearer ` 접두까지 환경 변수 값에 직접 적는 것이다.
- **프록시 환경 변수를 따르지 않는다(`trust_env=False`).** 프록시를 거쳐야만 닿는 서버에 붙을 수 없고, 인증서 저장소 같은 다른 환경 설정도 함께 꺼질 수 있다(어림). 거부했다.
- **https를 강제한다(루프백 주소만 http 예외).** http 주소로는 헤더 값(토큰)이 평문으로 간다. 그러나 이 기능의 첫 쓰임이 참조 배포의 compose 네트워크 안에서 문서 검색 서버에 서비스 이름으로 붙는 주소(인터뷰의 예 `http://rag-engine:8000/mcp`, 일지 2026-11-09-1229 라운드 1. 함께 띄우는 compose는 ADR 0046의 deploy-package 행, 저장소 이름은 ADR 0048의 2026-11-06 이력)라 루프백만 예외로 두면 그 배포가 깨지고, 내부 네트워크마다 인증서를 두어야 한다. 거부했다. 대신 Consequences의 배포 항목이 평문 경고를 적는다(PR 직전 리뷰가 짚었다).

## Consequences

- **계약 변경이 첫 티켓이다.** sdk의 `McpServer`, `openapi.json`, 생성한 TS 타입(`web/packages/api-client`)이 함께 바뀐다. 관리 화면의 컴포넌트는 `server.command`를 읽지 않아(`web/apps/admin`을 grep했다) 화면은 바뀌지 않는다. 그러나 생성 타입은 기본값이 있는 칸도 필수로 내므로(`args`가 `@default []`인데 `args: string[]`이다. `sdk/manifest.py`의 매니페스트 공통 설정 `_MANIFEST_CONFIG`가 켠 `json_schema_serialization_defaults_required`, ADR 0010) `transport`도 필수가 되고, `server` 값을 생성 타입으로 적은 테스트 픽스처와 스토리 넷(`components/pages/HomePage.test.tsx`, `components/pages/RunPage.decision.test.tsx`, `components/organisms/RunDetail.stories.tsx`, `components/organisms/PluginDetail.stories.tsx`)이 `transport`를 더해야 한다(코드를 읽었다. `tsc`는 돌리지 않았다). `[server]`에 `command`가 없는 매니페스트의 거부 문구를 든 스토리(`components/organisms/PluginList.stories.tsx`)는 문구가 바뀌면 함께 고친다. e2e가 쓰는 stdio 매니페스트(`e2e/stack.ts`)는 `transport`가 없어도 stdio라 그대로다. 그 티켓이 다른 티켓을 막는다(`docs/agents/issue-tracker.md`).
- **구현 티켓이 함께 고칠 자리.** `pyproject.toml`의 의존성 선언과 주석 둘(`[project]` 머리 주석의 mcp 대목 뒤에 httpx2가 직접 의존인 까닭을, `[dependency-groups]` 머리 주석의 mcp 2가 httpx 대신 httpx2를 쓴다는 대목에 httpx2가 직접 의존이 된 사실을 잇는다), `adapters/mcp.py`의 모듈 독스트링과 `_connecting` 문구(`server.command`를 모양에 따라 명령이나 주소로), `.claude/rules/sdk.md`의 `[server]` 문장(`command`·`args`만 든다), `.claude/rules/adapters.md`의 MCP 항목 셋(어댑터 목록의 "mcp 2의 stdio 클라이언트와 세션", 런처 항목의 범위(stdio 모양에만 걸린다), 예외 항목의 `<명령>`), `.claude/rules/core.md` 포트 표 `ToolSource` 행의 첫 어댑터 칸(stdio 클라이언트만 든다)과 실패 정책의 "MCP 서버 시작 실패", import-linter의 금지 목록 둘("core knows no provider", "sdk knows no engine")에 `httpx2`를 더해 core와 sdk가 import하지 못하게 하는 것. `docs/constitution/tech.md`의 런타임 의존성 행은 이 ADR과 같은 PR이 고친다(헌법 판 3.0.73, 스택 표의 문구 하나).
- **문구에 실리는 것과 실리지 않는 것.** 주소는 실패 문구와 관리 API에 실리고 헤더 값은 어디에도 실리지 않는다. 운영자가 주소의 쿼리 문자열에 비밀을 적는 것은 막지 않는다. 알려진 한계이고, 매니페스트가 비밀을 들지 않는다는 ADR 0009의 2026-09-22 이력의 방향 그대로다.
- **로그.** mcp의 streamable HTTP 클라이언트는 로거 `mcp.client.streamable_http`(`logging.getLogger(__name__)`, 47줄)에 DEBUG 수준으로 보내는 메시지 전체(`Sending client message: {message}`, 635줄)와 SSE로 받은 메시지 전체(`SSE message: {message}`, 191줄)를, INFO 수준으로 서버가 준 세션 식별자(172줄)를 찍는다(`mcp/client/streamable_http.py`를 읽었다. stdio 클라이언트 `mcp/client/stdio/`에는 메시지를 찍는 로그가 없다. `mcp/client/`를 `logger.`로 grep했다). 도구 호출 본문에는 `secret_args`의 실제 값이 실리므로(가리는 자리는 이벤트다. `core/run.py`의 `secret_args_by_tool`, ADR 0009) 그 로거가 DEBUG로 켜지면 비밀이 로그에 남는다(원칙 V). 이 저장소는 로깅을 설정하지 않아(`src/agent_os`에 `logging`의 설정 호출이 없다. grep) 기본 WARNING에서는 나오지 않고, 운영자가 루트 로거나 그 로거를 DEBUG로 켤 때의 조건부 위험이다. 구현 티켓의 수락에 "`secret_args`가 있는 도구를 http 모양의 서버에 부르며 루트 로거를 DEBUG로 켠 테스트에서 그 값이 로그에 나타나지 않는다"를 넣고, 막는 자리(어댑터가 그 로거에 필터를 거는 것 등)는 구현 티켓이 정한다(PR 직전 리뷰가 짚었다).
- **닫는 데 시간이 든다.** 취소된 실행의 끝이 종료 요청만큼, 최대 2초 늦는다. stdio 서버와 함께 쓰는 에이전트는 서버를 차례로 닫으므로 그 시간이 더해지고(ADR 0034), `serve` 종료도 그만큼 기다린다. 정상 종료에서는 종료 요청이 바로 돌아오므로 늦지 않는다(어림. 명세의 프로브가 잰다).
- **배포가 알아야 할 것 넷.** http 주소에서는 헤더 값(토큰)이 평문으로 가므로, http 주소는 신뢰하는 내부 네트워크(compose 네트워크의 서비스 이름 주소)에서만 쓰고 인터넷을 지나는 주소는 https로 적는다. 프록시 뒤의 배포에서는 내부 주소(compose 서비스 이름)를 `NO_PROXY`에 적어야 하고, 빠뜨리면 내부 서버 요청이 프록시로 가서 접속 실패로 보인다(httpx2는 `trust_env`가 참이면 urllib의 `getproxies()`로 프록시 환경 변수를 읽고 `no_proxy`의 항목을 프록시를 거치지 않는 주소로 옮긴다. `httpx2/_utils.py` 30~76줄을 읽었다). mcp의 HTTP 클라이언트는 같은 출처(같은 scheme·host·port, 또는 기본 포트를 쓰는 같은 호스트의 http에서 https로) 안에서 메서드를 지키는 리다이렉트만 따르고 클라이언트의 `follow_redirects` 설정은 보지 않는다(`streamable_http_client` 독스트링, `mcp/client/streamable_http.py` 727~733줄을 읽었다). SSE로 오는 이벤트 하나의 상한이 1MB라(`max_sse_event_size` 기본값) 도구 결과가 SSE로 오는 서버에서 1MB를 넘는 결과는 실패하고, JSON 응답으로 답하는 서버는 걸리지 않는다(같은 독스트링). 앞의 둘은 deploy-package의 배포 안내에, 뒤의 둘은 문서 검색 서버 저장소에 넘긴다.
- **서버의 몫.** 여러 실행의 요청을 한 프로세스가 받으므로 서버가 동시 요청을 안전하게 다뤄야 하고 수명은 배포가 관리한다(ADR 0046 Consequences). 실행마다 세션을 새로 열므로 서버 쪽 세션은 실행 수만큼 생겼다 닫힌다.
- **approval-rules와의 접점.** 두 행이 `adapters/mcp.py`를 고치므로 나중에 병합하는 쪽이 충돌을 풀고, 원격 MCP 서버의 도구에도 `ToolSpec.server`가 실리는지를 시험으로 본다(ADR 0046). 이 ADR의 시험 항목이 그 사례를 든다.
- **뒤 기능이 기대는 것.** doc-qa-agent는 이 모양으로 문서 검색 서버를 가리키는 플러그인을 가져오고, diag-bundle은 어댑터의 서버 하나를 여는 함수(`_opened`)를 접속 확인에 다시 쓸 수 있도록 그 함수의 경계를 지킨다. mcp-trust의 신뢰 수준·해시·주체 전파는 두 전송에 똑같이 건다(ADR 0042 "원격 MCP", ADR 0046).
- **바꾸지 않는 것.** 두 전송의 역할 분담(ADR 0046)과 stdio 모양은 그대로다. 최종 사용자 경로와 위젯에는 지금의 실패 항목이 그대로 보인다.
- **다른 ADR의 본문.** ADR 0034의 두 문장(결정의 "닫기는 상류의 보호된 절차를 그대로 받아 …", Consequences의 "서버마다 `stdio_client`와 `ClientSession`을 열고 …")은 http 전송이 더해지면 stdio에만 참이라 `(바뀜: ADR 0049)` 포인터를 단다. ADR 0034가 거부한 안 "어댑터가 라이브러리 바깥에서 닫기를 보호한다"는 stdio에 대한 그때의 측정이라 포인터가 없고, 이 결정이 http에 그 모양을 쓰는 것과 그 위험은 위 닫기 항목이 적는다. ADR 0012의 "실제 도구 목록은 `ToolSource.connect`가 stdio 프로세스를 띄워야 나오는데"는 `/plugins`가 서버에 붙지 않는다는 결정의 그때 근거이고 결정은 이 ADR과 같은 방향(미리 확인 없음)이라 달지 않는다. ADR 0042의 "원격 MCP" 줄(url·헤더의 환경 변수 이름, streamable HTTP만)은 글자 그대로 참이다. 같은 ADR의 업로드 변환 줄(`.mcp.json`의 `headers`의 `${VAR}` 이름을 서버 파일의 "넘길 환경 변수 이름"에 적는다)은 변환이 매니페스트의 `[server.headers]`에도 적을지를 claude-code-compat의 인터뷰가 정할 접점이라 그대로 둔다. ADR 0009의 2026-09-22 이력이 "`McpServer`에는 `command`와 `args`만 있고 환경변수 필드가 없으므로"라고 적은 문장은 지난 이력의 기록이라 고치지 않는다. 같은 이력이 "다시 볼 때"의 둘째로 적은 날(매니페스트에 환경변수 필드가 생기는 날)이 이 ADR이고, 그때 함께 정하라던 담는 규칙은 결정의 매니페스트 항목(`[server.headers]`는 환경 변수 이름만 담고 값은 어댑터가 환경에서 읽는다)이다. 그 ADR의 2026-10-03 이력이 첫째 날을 적은 선례대로 둘째 날의 이력을 ADR 0009에 더하고, 포인터는 달지 않는다(지난 이력 항목은 기록이다, `.claude/rules/adr.md`. PR 직전 리뷰가 짚었다).
- **용어.** `CONTEXT.md`에 전송을 더하고, MCP 서버의 정의를 프로세스만이 아니라 두 전송을 품게 고쳤다. 원격 MCP 서버의 항목은 그대로다.
- **로컬 개발.** 주소가 다른 자리에서는 매니페스트를 고쳐야 한다. 배포마다 주소를 바꾸는 길이 필요해지면 mcp-trust의 서버 파일에서 다시 본다(위 거부한 안).
