# MCP 매니페스트의 `[server]`는 `transport` 칸으로 stdio와 http를 가르고, 원격 MCP 서버에는 매니페스트에 적은 주소로 실행마다 붙되 헤더 값은 환경에서 읽고 닫기는 취소에서 보호한다

core는 실행마다 도구 연결을 열고(`core/run.py`의 `self._tools.connect`), MCP 어댑터는 서버마다 stdio 클라이언트로 새 프로세스를 띄운다(`adapters/mcp.py`의 `stdio_client`. main `24fdbe9a`의 코드를 읽었다). 임베딩 모델과 색인을 올리는 문서 검색 서버는 그래서 상주해야 하고, ADR 0046이 원격 MCP 서버를 claude-code-compat에서 mcp-http로 떼어 기준선에 넣으며 그 모양은 ADR 0042 묶음 ③의 "원격 MCP" 줄(`[server]`의 http 모양은 url과 헤더의 환경 변수 이름이고 streamable HTTP만 받는다)에서 출발한다고 정했다. 그 줄은 뼈대만 적었다. 주소를 어디에 둘지, 두 전송을 어떻게 가를지, 서버가 꺼졌을 때 무엇이 보일지, 취소된 실행이 연결을 어떻게 닫을지는 비어 있었고, mcp-http 설계 인터뷰(일지 2026-11-09-1229)가 그것을 정했다. 결정의 원문은 그 일지의 `> 사용자:` 인용과 사용자가 확인한 합의 요약 여덟이고, 아래가 요약과 다르게 읽히면 일지가 원천이다.

인터뷰 전에 라이브러리를 읽었다. mcp 2.3.0의 `streamable_http_client(url, *, http_client=None, terminate_on_close=True, max_sse_event_size=1MB)`에는 헤더 인자가 없어 토큰을 실으려면 `httpx2.AsyncClient`를 만들어 넘겨야 하고, 넘기지 않을 때 라이브러리가 만드는 기본 클라이언트의 기한은 접속·쓰기·풀 30초, 읽기 300초다. 연결을 닫을 때의 세션 종료 요청(DELETE, `terminate_session`)은 `finally`에서 보내되 취소 보호(`CancelScope(shield=True)`)가 없고, 서버 쪽 세션은 mcp의 서버 구현이 기본 1800초 유휴 뒤 닫는다(`mcp/client/streamable_http.py` 695~794줄, `mcp/shared/_httpx_utils.py` 32~64줄, `mcp/server/streamable_http_manager.py` 39~111줄을 읽었다). httpx2 2.13.0 `AsyncClient`의 `trust_env` 기본값은 True다(`httpx2/_client.py` 192·622줄을 읽었다). 닫힌 포트(루프백에서 바인드했다 놓은 포트)에 붙으면 이 PC(윈도우)에서 2.2초 뒤 `ConnectError`로 끝났다(세션 스크래치 스크립트로 한 번 손으로 봤다. 리눅스에서는 재지 않았고, 명세의 프로브가 다시 잰다). `core/`와 `sdk/`에는 환경을 읽는 코드가 없다(grep).

**`[server]`는 `transport` 칸으로 두 전송을 가른다. 칸이 없거나 `"stdio"`면 지금의 `command`·`args`이고, `"http"`면 매니페스트에 글자 그대로 적은 `url`과 헤더 이름마다 환경 변수 이름을 적는 선택 표 `[server.headers]`다. 원격 MCP 서버에는 실행마다 붙어 세션을 열고 도구 목록을 읽으며, 헤더 값은 어댑터가 접속 직전에 환경에서 읽고 어디에도 싣지 않는다(바뀜: 이력 2026-11-09 "서버가 되울린 헤더 값을 실패 문구에서 가린다"). 서버가 꺼졌거나 주소가 틀렸거나 헤더의 환경 변수가 없거나 인증이 거부되면 여는 단계의 `ConnectionError`이고 실행은 `run_failed` 원인 `tool_connection`으로 끝난다. 재시도와 미리 확인은 없다. 연결을 닫을 때는 세션 종료 요청과 클라이언트 닫기를 취소에서 보호하되 2초 안에 끝내고, `httpx2`를 런타임 직접 의존으로 선언한다(바뀜: 이력 2026-11-09 "닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다").**

## 결정

- **매니페스트.** `transport`는 `"stdio"`·`"http"`의 닫힌 값이고 없으면 `"stdio"`다. 그래서 지금 있는 매니페스트는 고치지 않는다. stdio 모양은 `command`·`args`, http 모양은 `url`과 선택 표 `[server.headers]`(헤더 이름 → 환경 변수 이름)이고, `secret_args`는 두 모양이 같이 쓴다. `url`은 `http`·`https`만 받고 `사용자:비밀번호@`(사용자 정보)가 들면 매니페스트를 읽는 단계에서 거부한다. 환경 변수 이름은 글자·숫자·밑줄 꼴만 받는다. 한 모양의 칸을 다른 모양에 적으면(http에 `command`) 그 모양의 모르는 칸으로 거부된다. Claude Code의 `.mcp.json`도 `type` 칸으로 전송을 가르는 선례다(ADR 0042 "원격 MCP" 줄의 `type http` 항목). sdk에는 모양마다 모델이 하나씩 서고(`StdioServer`, `HttpServer`) `transport`로 가르는 합이 `McpServer`다. 그래서 `openapi.json`의 매니페스트 응답에는 두 모양이 oneOf로 따로 서고 생성한 TS 타입도 둘로 갈린다. 두 모양 모두 비어 있던 선택 칸이 늘거나 새 모양이 더해지는 것이라 옛 매니페스트의 뜻은 바뀌지 않고, ADR 0008의 2026-09-21 이력이 적은 기준(기존 필드의 뜻이나 필수 여부가 바뀔 때 올린다)대로 `schema_version`은 `"1"` 그대로다.
- **주소는 매니페스트에 그대로 적는다.** 플러그인 디렉터리는 배포의 몫이라(ADR 0042 전제) 배포마다 그 파일을 두고, compose에서는 서비스 이름이 곧 주소라 공개 데모와 참조 배포가 같은 주소를 쓴다. 주소는 비밀이 아닌 것으로 보아 관리 API의 매니페스트 응답과 실패 문구에 그대로 실린다. 사용자 정보가 든 주소를 거부하는 까닭이 이것이다.
- **접속.** 실행마다 어댑터가 접속 직전에 `[server.headers]`의 환경 변수를 읽어 `httpx2.AsyncClient`를 만들고(헤더는 그 값 전체를 그대로 싣고, 기한은 mcp의 기본값, `trust_env`는 기본값 True) mcp의 `streamable_http_client`에 넘겨 세션을 열고 도구 목록을 읽는다(쪽 나눔의 상한은 stdio와 같다). 그 뒤의 호출은 stdio와 같은 `McpConnection`이고 도구마다 `ToolSpec.server`에 그 플러그인의 이름이 실린다. 환경을 읽는 코드는 어댑터에만 있다(`.claude/rules/adapters.md`의 "파일, DB, 외부 서비스, 시계에 닿는 코드는 여기에만 산다". core와 sdk에는 환경을 읽는 코드가 없다, grep).
- **실패.** 여는 동안(접속, 세션 열기, `initialize()`, 도구 목록 읽기)의 실패는 지금 stdio와 같은 자리(`_connecting`)에서 `ConnectionError`가 되고 문구는 `MCP 서버 <이름>(<주소>)에 붙지 못했다: <원인>`이다. 헤더의 환경 변수가 없으면 붙지 않고 같은 예외로 끝내며 원인은 `헤더 <헤더 이름>의 환경 변수 <변수 이름>이 없다`다. 변수 없음은 실행 식별자가 생긴 뒤에 드러나 트레이스에 실패 하나가 남는다. 실행 전 거부를 두지 않은 대가다. 헤더 값은 문구에도 원인(`__cause__`)에도 트레이스에도 싣지 않는다(헌법 원칙 V)(바뀜: 이력 2026-11-09 "서버가 되울린 헤더 값을 실패 문구에서 가린다"). core는 지금처럼 그 예외를 원인 `tool_connection`의 `run_failed`로 쓴다(`.claude/rules/core.md` 실패 정책). 재시도는 하지 않고 접속 기한의 칸도 두지 않는다. 기한은 mcp 기본값(접속 30초, 읽기 300초) 위에 실행 전체의 기한(기본 600초)이 있다.
- **닫기.** 연결을 닫을 때 세션 종료 요청(DELETE)과 클라이언트 닫기를 `CancelScope(shield=True)`와 기한 2초로 감싸, 실행 기한이나 `serve` 종료로 취소된 실행에서도 종료 요청이 서버에 가게 한다(바뀜: 이력 2026-11-09 "닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다"). 2초는 stdio 상류가 서버가 스스로 끝나기를 기다리는 유예와 같은 값이다(ADR 0034). 2초를 넘기면 그만둔다. 어댑터가 만들어 넘긴 클라이언트는 라이브러리가 닫지 않으므로(`client_provided`, `mcp/client/streamable_http.py` 746~761줄을 읽었다) 닫기도 어댑터의 몫이다. 보호의 자리는 라이브러리 바깥이다. 종료 요청은 라이브러리 문맥의 `finally`(789~791줄)에서 나가고 어댑터는 그 문맥을 닫는 호출을 감쌀 수 있을 뿐이다(바뀜: 이력 2026-11-09 "닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다"). ADR 0034는 stdio에서 같은 모양(어댑터가 라이브러리 바깥에서 닫기를 보호한다)을 재 보고 안쪽 task group이 취소를 삼켜 서지 않는다고 거부했다. 그 까닭이 streamable HTTP 클라이언트(태스크 그룹 하나와 `finally`, 766~792줄)에도 걸리는지는 재지 않았다(어림). 명세의 프로브가 먼저 잰다(바뀜: 이력 2026-11-09 "닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다"). 프로브는 종료 요청이 서버에 닿았는지만이 아니라 기한이 걸린 실행이 지금처럼 시간 초과의 `run_failed`로 끝나는지도 본다. ADR 0034에서 서지 않았던 양상은 가려진 취소를 안쪽 task group이 삼켜 호출자에게 취소가 전해지지 않은 것이고, 지금 core는 범위가 취소를 받았는지(`cancelled_caught`)로 기한을 보므로 그것이 거짓이 되면 결말이 바뀐다(`.claude/rules/core.md`의 실행 타임아웃 항목). 서지 않으면 `terminate_on_close=False`로 라이브러리의 종료 요청을 끄고 어댑터가 자기 클라이언트의 응답 훅으로 받아 둔 세션 식별자(`Mcp-Session-Id` 헤더)로 직접 보낸다(2.3.0은 세션 식별자를 yield하지 않는다, 788줄을 읽었다. httpx2에 httpx와 같은 응답 훅이 있는지는 대 보지 않았다, 어림)(바뀜: 이력 2026-11-09 "닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다"). 어느 길이든 결정(취소된 실행에서도 2초 안에 종료 요청을 보낸다)은 같고 자리만 명세가 정한다. 프로브가 서지 않는 쪽으로 나와 대안으로 가면 이 항목의 "보호의 자리는 라이브러리 바깥이다"가 거짓이 되므로, 명세를 쓰는 같은 작업에서 무엇이 바뀌었는지와 명세의 경로를 이 ADR의 이력에 쌓고 그 문장에 포인터를 단다(`.claude/rules/adr.md`. PR #499의 claude-review가 짚었다). 런처와 프로세스 그룹 정리(ADR 0034)는 이 전송에 걸리지 않는다.
- **의존.** `httpx2`를 런타임 직접 의존으로 선언하고 major 2로 묶는다(`httpx2>=2.13,<3`). 잠금 파일의 2.13.0은 `mcp` 2 뒤에서 이미 오던 것이라 락의 패키지와 판은 바뀌지 않는다(어림. 구현 티켓이 `uv lock`으로 확인한다). 직접 import하는 의존은 선언하는 관행을 따른 것이다(`pyproject.toml`의 `[dependency-groups]` 주석, ADR 0023의 pyjwt, ADR 0034의 mcp).
- **시험.** 테스트 픽스처는 지금의 stdio 픽스처와 같은 `MCPServer`를 streamable HTTP로 루프백의 빈 포트에 띄운 서버다(mcp 2.3.0 `MCPServer.run(transport="streamable-http", host, port, …)`, `mcp/server/mcpserver/server.py` 387~395줄을 읽었다). 사례는 도구 목록·호출·`ToolSpec.server`, 헤더 변수가 있을 때 그 값이 요청 헤더로 서버에 닿음(픽스처가 받은 헤더를 본다. PR #499의 CodeRabbit이 짚었다), 헤더 변수 없음, 꺼진 서버에 붙은 실행이 `tool_connection`으로 끝남(기능 계획의 수락), 취소된 실행에서 종료 요청이 서버에 닿음, calc 예시가 http 모양의 플러그인으로 도구를 써 트레이스가 남음(수락)이다. `plugins/mcp/`에 http 모양의 예시는 두지 않는다. 실제 플러그인은 doc-qa-agent가 가져온다. (바뀜: ADR 0051)
- **범위 밖.** 접속을 미리 확인하는 길(diag-bundle), 운영자의 서버 파일과 신뢰 수준·도구 정의 해시(mcp-trust), SSE 전송, OAuth, 재시도, 접속 기한의 칸.

## Considered Options

- **주소를 환경 변수 이름으로 적는다(`url_env`).** 같은 매니페스트를 여러 배포가 쓴다. 그러나 실패 문구와 관리 API에 주소 대신 변수 이름만 보여 운영자가 어디에 붙으려 했는지 바로 알 수 없고, 변수가 비면 접속 실패가 하나 더 는다. 거부했다.
- **주소를 운영자의 서버 파일에 둔다.** mcp-trust가 계획한 운영자 파일을 이 기능이 먼저 만든다. mcp-trust의 설계(신뢰 수준, 해시)를 보기 전에 그 파일의 형식을 정하게 되고 범위가 는다. 거부했다. 배포마다 주소를 바꿔야 하는 요구가 서면 그 파일에서 다시 본다.
- **칸 유무로 가른다(`command`면 stdio, `url`이면 http).** 칸이 늘지 않지만, 둘 다 적거나 둘 다 없는 파일의 거부 문구가 두 모양의 오류를 함께 실어 길어지고 계약에 두 모양을 가르는 표지가 없다. 거부했다.
- **한 모양에 선택 칸을 더한다(`command`를 선택으로, `url`을 추가).** 계약에서 `command`가 필수에서 선택으로 바뀌는 변경이고, TS 타입이 `command?: string`이 되어 어느 모양인지 읽는 쪽이 좁혀야 하며 모양에 맞지 않는 칸을 거부하기 어렵다. 거부했다.
- **접속을 짧게 재시도한 뒤 실패한다.** 서버가 다시 뜨는 짧은 틈을 넘기지만, 꺼진 서버에서는 실패가 그만큼 늦고 재시도 수와 간격이 새 설정이 된다. 거부했다.
- **접속 기한을 매니페스트 칸으로 둔다.** 방화벽 뒤 주소의 30초 기다림을 줄일 수 있으나 칸이 계약에 들고, 잘못 적으면 느린 서버가 실패로 보인다. 거부했다.
- **꺼진 서버를 미리 아는 길을 지금 둔다.** CLI 명령(`agent-os mcp check`)은 CLI 표면과 테스트가 늘고 diag-bundle과 같은 일을 두 자리가 하게 된다. `/health`가 서버들을 함께 보는 것은 상태 확인마다 모든 서버에 요청이 가고 `/health`의 뜻(`serve`가 살아 있다)이 바뀌는 계약 변경이다. 둘 다 거부했다.
- **헤더의 환경 변수가 없으면 실행 전에 거부한다(`PluginError`).** 준비 단계는 core의 일이라 환경을 미리 보려면 포트에 메서드를 더해 어댑터가 대신 보게 해야 하고, 확인과 실제 읽기 사이에 환경이 바뀔 틈도 남는다. 거부했다.
- **닫기의 취소 보호 없이 서버의 유휴 만료에 맡긴다.** 상류가 그대로 주는 동작이고 서버 쪽 세션은 기본 1800초 뒤 닫히므로 남는 것은 프로세스가 아니라 서버 안의 세션 하나다. 추천이었으나 사용자가 취소가 잦을 때 서버에 세션이 최대 30분 쌓이는 것보다 보호 코드와 그 테스트를 골랐다(일지 2026-11-09-1229 라운드 1 둘째 호출).
- **bearer 토큰 전용 칸 하나(`bearer_token_env`), 또는 표와 전용 칸 둘 다.** 전용 칸만 두면 토큰 밖의 헤더(API 키 헤더 등)가 필요한 서버에 붙지 못하고, 둘 다 두면 `Authorization`을 두 자리에 적은 충돌을 거부해야 한다. 거부했다. 치르는 값은 운영자가 `Bearer ` 접두까지 환경 변수 값에 직접 적는 것이다.
- **프록시 환경 변수를 따르지 않는다(`trust_env=False`).** 프록시를 거쳐야만 닿는 서버에 붙을 수 없고, 인증서 저장소 같은 다른 환경 설정도 함께 꺼질 수 있다(어림). 거부했다.
- **https를 강제한다(루프백 주소만 http 예외).** http 주소로는 헤더 값(토큰)이 평문으로 간다. 그러나 이 기능의 첫 쓰임이 참조 배포의 compose 네트워크 안에서 문서 검색 서버에 서비스 이름으로 붙는 주소(인터뷰의 예 `http://rag-engine:8000/mcp`, 일지 2026-11-09-1229 라운드 1. 함께 띄우는 compose는 ADR 0046의 deploy-package 행, 저장소 이름은 ADR 0048의 2026-11-06 이력)라 루프백만 예외로 두면 그 배포가 깨지고, 내부 네트워크마다 인증서를 두어야 한다. 거부했다. 대신 Consequences의 배포 항목이 평문 경고를 적는다(PR 직전 리뷰가 짚었다).

## Consequences

- **계약 변경이 첫 티켓이다.** sdk의 `McpServer`, `openapi.json`, 생성한 TS 타입(`web/packages/api-client`)이 함께 바뀐다. 관리 화면의 컴포넌트는 `server.command`를 읽지 않아(`web/apps/admin`을 grep했다) 화면은 바뀌지 않는다(바뀜: 이력 2026-11-10 "관리 화면의 매니페스트 JSON에 transport 줄이 늘어 사진 정답이 바뀐다"). 그러나 생성 타입은 기본값이 있는 칸도 필수로 내므로(`args`가 `@default []`인데 `args: string[]`이다. `sdk/manifest.py`의 매니페스트 공통 설정 `_MANIFEST_CONFIG`가 켠 `json_schema_serialization_defaults_required`, ADR 0010) `transport`도 필수가 되고, `server` 값을 생성 타입으로 적은 테스트 픽스처와 스토리 넷(`components/pages/HomePage.test.tsx`, `components/pages/RunPage.decision.test.tsx`, `components/organisms/RunDetail.stories.tsx`, `components/organisms/PluginDetail.stories.tsx`)이 `transport`를 더해야 한다(코드를 읽었다. `tsc`는 돌리지 않았다). `[server]`에 `command`가 없는 매니페스트의 거부 문구를 든 스토리(`components/organisms/PluginList.stories.tsx`)는 문구가 바뀌면 함께 고친다(바뀜: 이력 2026-11-10 "거부 문구를 든 관리 화면 스토리의 글은 그대로 둔다"). e2e가 쓰는 stdio 매니페스트(`e2e/stack.ts`)는 `transport`가 없어도 stdio라 그대로다. 그 티켓이 다른 티켓을 막는다(`docs/agents/issue-tracker.md`).
- **구현 티켓이 함께 고칠 자리.** `pyproject.toml`의 의존성 선언과 주석 둘(`[project]` 머리 주석의 mcp 대목 뒤에 httpx2가 직접 의존인 까닭을, `[dependency-groups]` 머리 주석의 mcp 2가 httpx 대신 httpx2를 쓴다는 대목에 httpx2가 직접 의존이 된 사실을 잇는다), `adapters/mcp.py`의 모듈 독스트링과 `_connecting` 문구(`server.command`를 모양에 따라 명령이나 주소로), `.claude/rules/sdk.md`의 `[server]` 문장(`command`·`args`만 든다), `.claude/rules/adapters.md`의 MCP 항목 셋(어댑터 목록의 "mcp 2의 stdio 클라이언트와 세션", 런처 항목의 범위(stdio 모양에만 걸린다), 예외 항목의 `<명령>`), `.claude/rules/core.md` 포트 표 `ToolSource` 행의 첫 어댑터 칸(stdio 클라이언트만 든다)과 실패 정책의 "MCP 서버 시작 실패", import-linter의 금지 목록 둘("core knows no provider", "sdk knows no engine")에 `httpx2`를 더해 core와 sdk가 import하지 못하게 하는 것. `docs/constitution/tech.md`의 런타임 의존성 행은 이 ADR과 같은 PR이 고친다(헌법 판 3.0.73, 스택 표의 문구 하나).
- **문구에 실리는 것과 실리지 않는 것.** 주소는 실패 문구와 관리 API에 실리고 헤더 값은 어디에도 실리지 않는다(바뀜: 이력 2026-11-09 "서버가 되울린 헤더 값을 실패 문구에서 가린다"). 운영자가 주소의 쿼리 문자열에 비밀을 적는 것은 막지 않는다. 알려진 한계이고, 매니페스트가 비밀을 들지 않는다는 ADR 0009의 2026-09-22 이력의 방향 그대로다. 관리 API의 매니페스트 응답은 파일 그대로다(운영자가 자기 파일시스템의 파일을 보는 자리라는 같은 이력의 논증). 다만 실패 문구는 `run_failed`로 트레이스에 남으므로, 그 문구의 주소를 원점과 경로만 싣고 쿼리 문자열을 뺄지는 명세가 정한다(PR #499의 CodeRabbit이 Critical로 짚었다. 결정의 주소 항목은 바뀌지 않고 문구의 모양만 명세의 몫이다).
- **매니페스트 저자와 운영자.** http 모양의 매니페스트는 `url`과 `[server.headers]`의 환경 변수 이름을 함께 들어, 저자가 운영자의 환경 변수(예: `AGENT_OS_ADMIN_TOKEN`)를 제 주소로 보내게 쓸 수 있다. 이 ADR은 그것을 막는 승인을 두지 않는다. 플러그인 디렉터리는 배포의 몫이고(ADR 0042 전제. 켜짐은 운영자 파일이 든다, ADR 0017) stdio 모양의 `command`·`args`는 이미 임의의 프로세스를 띄울 수 있어, 매니페스트를 그 디렉터리에 두는 운영자가 지금의 신뢰 경계다. 서버마다 넘길 환경 변수 이름을 운영자가 허락하는 자리는 mcp-trust의 서버 파일이고(그 기능 계획의 "넘길 환경 변수 이름"), 그 기능이 `[server.headers]`의 이름을 그 목록으로 좁히고 목록 밖의 이름을 접속 전에 거부하는 요구를 받는다(`.scratch/mcp-trust/plan.md`에 적었다. PR #499의 CodeRabbit이 Major로 짚었다).
- **로그.** mcp의 streamable HTTP 클라이언트는 로거 `mcp.client.streamable_http`(`logging.getLogger(__name__)`, 47줄)에 DEBUG 수준으로 보내는 메시지 전체(`Sending client message: {message}`, 635줄)와 SSE로 받은 메시지 전체(`SSE message: {message}`, 191줄)를, INFO 수준으로 서버가 준 세션 식별자(172줄)를 찍는다(`mcp/client/streamable_http.py`를 읽었다. stdio 클라이언트 `mcp/client/stdio/`에는 메시지를 찍는 로그가 없다. `mcp/client/`를 `logger.`로 grep했다). 도구 호출 본문에는 `secret_args`의 실제 값이 실리므로(가리는 자리는 이벤트다. `core/run.py`의 `secret_args_by_tool`, ADR 0009) 그 로거가 DEBUG로 켜지면 비밀이 로그에 남는다(원칙 V). 이 저장소는 로깅을 설정하지 않아(`src/agent_os`에 `logging`의 설정 호출이 없다. grep) 기본 WARNING에서는 나오지 않고, 운영자가 루트 로거나 그 로거를 DEBUG로 켤 때의 조건부 위험이다. 구현 티켓의 수락에 "`secret_args`가 있는 도구를 http 모양의 서버에 부르며 루트 로거를 DEBUG로 켠 테스트에서 그 값이 로그에 나타나지 않는다"를 넣고, 막는 자리(어댑터가 그 로거에 필터를 거는 것 등)는 구현 티켓이 정한다(PR 직전 리뷰가 짚었다).
- **닫는 데 시간이 든다.** 취소된 실행의 끝이 종료 요청만큼, 최대 2초 늦는다. stdio 서버와 함께 쓰는 에이전트는 서버를 차례로 닫으므로 그 시간이 더해지고(ADR 0034), `serve` 종료도 그만큼 기다린다. 정상 종료에서는 종료 요청이 바로 돌아오므로 늦지 않는다(어림. 명세의 프로브가 잰다).
- **배포가 알아야 할 것 넷.** 앞의 둘은 deploy-package의 배포 안내에 넘긴다(`.scratch/deploy-package/plan.md`에 적었다). 뒤의 둘은 문서 검색 서버 저장소에 넘긴다. 그 저장소는 이 저장소의 세션이 고치지 않으므로(ADR 0048) 넘길 글은 여기에 둔다. 항목으로 나눈 것은 PR #499의 claude-review가 짚었다.
  - **평문.** http 주소에서는 헤더 값(토큰)이 평문으로 가므로, http 주소는 신뢰하는 내부 네트워크(compose 네트워크의 서비스 이름 주소)에서만 쓰고 인터넷을 지나는 주소는 https로 적는다.
  - **프록시.** 프록시 뒤의 배포에서는 내부 주소(compose 서비스 이름)를 `NO_PROXY`에 적어야 하고, 빠뜨리면 내부 서버 요청이 프록시로 가서 접속 실패로 보인다(httpx2는 `trust_env`가 참이면 urllib의 `getproxies()`로 프록시 환경 변수를 읽고 `no_proxy`의 항목을 프록시를 거치지 않는 주소로 옮긴다. `httpx2/_utils.py` 30~76줄을 읽었다). 빠뜨린 요청은 헤더 값(토큰)을 그 프록시에 넘기므로, 프록시가 서버에 닿지 못해도 토큰은 프록시에 남는다. 프록시를 믿을 수 있는지도 함께 본다(PR #499의 CodeRabbit이 짚었다).
  - **리다이렉트.** mcp의 HTTP 클라이언트는 같은 출처(같은 scheme·host·port, 또는 기본 포트를 쓰는 같은 호스트의 http에서 https로) 안에서 메서드를 지키는 리다이렉트만 따르고 클라이언트의 `follow_redirects` 설정은 보지 않는다(`streamable_http_client` 독스트링, `mcp/client/streamable_http.py` 727~733줄을 읽었다).
  - **SSE 상한.** SSE로 오는 이벤트 하나의 상한이 1MB라(`max_sse_event_size` 기본값) 도구 결과가 SSE로 오는 서버에서 1MB를 넘는 결과는 실패하고, JSON 응답으로 답하는 서버는 걸리지 않는다(같은 독스트링).
- **서버의 몫.** 여러 실행의 요청을 한 프로세스가 받으므로 서버가 동시 요청을 안전하게 다뤄야 하고 수명은 배포가 관리한다(ADR 0046 Consequences). 실행마다 세션을 새로 열므로 서버 쪽 세션은 실행 수만큼 생겼다 닫힌다.
- **approval-rules와의 접점.** 두 행이 `adapters/mcp.py`를 고치므로 나중에 병합하는 쪽이 충돌을 풀고, 원격 MCP 서버의 도구에도 `ToolSpec.server`가 실리는지를 시험으로 본다(ADR 0046). 이 ADR의 시험 항목이 그 사례를 든다.
- **뒤 기능이 기대는 것.** doc-qa-agent는 이 모양으로 문서 검색 서버를 가리키는 플러그인을 가져오고 (바뀜: ADR 0051), diag-bundle은 어댑터의 서버 하나를 여는 함수(`_opened`)를 접속 확인에 다시 쓸 수 있도록 그 함수의 경계를 지킨다. mcp-trust의 신뢰 수준·해시·주체 전파는 두 전송에 똑같이 건다(ADR 0042 "원격 MCP", ADR 0046).
- **바꾸지 않는 것.** 두 전송의 역할 분담(ADR 0046)과 stdio 모양은 그대로다. 최종 사용자 경로와 위젯에는 지금의 실패 항목이 그대로 보인다.
- **다른 ADR의 본문.** 포인터를 단 것과 달지 않은 것을 ADR마다 가른다(`.claude/rules/adr.md`. 항목으로 나눈 것은 PR #499의 claude-review가 짚었다).
  - **ADR 0034.** 세 문장(결정의 "`mcp`(`>=2.3,<3`)의 `stdio_client`와 `ClientSession`을 직접 써서 …"와 "닫기는 상류의 보호된 절차를 그대로 받아 …", Consequences의 "서버마다 `stdio_client`와 `ClientSession`을 열고 …")은 http 전송이 더해지면 stdio에만 참이라 `(바뀜: ADR 0049)` 포인터를 단다(첫 문장의 포인터는 PR #499의 CodeRabbit이 짚었다). 거부한 안 "어댑터가 라이브러리 바깥에서 닫기를 보호한다"는 stdio에 대한 그때의 측정이라 포인터가 없고, 이 결정이 http에 그 모양을 쓰는 것과 그 위험은 위 닫기 항목이 적는다.
  - **ADR 0012.** "실제 도구 목록은 `ToolSource.connect`가 stdio 프로세스를 띄워야 나오는데"는 `/plugins`가 서버에 붙지 않는다는 결정의 그때 근거이고 결정은 이 ADR과 같은 방향(미리 확인 없음)이라 달지 않는다.
  - **ADR 0042.** "원격 MCP" 줄(url·헤더의 환경 변수 이름, streamable HTTP만)은 글자 그대로 참이다. 같은 ADR의 업로드 변환 줄(`.mcp.json`의 `headers`의 `${VAR}` 이름을 서버 파일의 "넘길 환경 변수 이름"에 적는다)은 변환이 매니페스트의 `[server.headers]`에도 적을지를 claude-code-compat의 인터뷰가 정할 접점이라 그대로 둔다.
  - **ADR 0009.** 2026-09-22 이력이 "`McpServer`에는 `command`와 `args`만 있고 환경변수 필드가 없으므로"라고 적은 문장은 지난 이력의 기록이라 고치지 않는다. 같은 이력이 "다시 볼 때"의 둘째로 적은 날(매니페스트에 환경변수 필드가 생기는 날)이 이 ADR이고, 그때 함께 정하라던 담는 규칙은 결정의 매니페스트 항목(`[server.headers]`는 환경 변수 이름만 담고 값은 어댑터가 환경에서 읽는다)이다. 그 ADR의 2026-10-03 이력이 첫째 날을 적은 선례대로 둘째 날의 이력을 ADR 0009에 더하고, 포인터는 달지 않는다(지난 이력 항목은 기록이다, `.claude/rules/adr.md`. PR 직전 리뷰가 짚었다).
- **용어.** `CONTEXT.md`에 전송을 더하고, MCP 서버의 정의를 프로세스만이 아니라 두 전송을 품게 고쳤다. 원격 MCP 서버의 항목은 그대로다.
- **로컬 개발.** 주소가 다른 자리에서는 매니페스트를 고쳐야 한다. 배포마다 주소를 바꾸는 길이 필요해지면 mcp-trust의 서버 파일에서 다시 본다(위 거부한 안).

## 이력

### 2026-11-09 닫기 보호는 라이브러리 문맥을 닫은 뒤의 finally에 두고 종료 요청은 어댑터가 직접 보낸다

mcp-http 명세(`.scratch/mcp-http/spec.md`)를 쓰며 정했다. 결정 "닫기"가 명세의 프로브에 넘긴 자리를 채우고, 그 항목의 어림 둘(첫째 안의 보호 모양이 streamable HTTP 클라이언트에도 서지 않는지, httpx2에 응답 훅이 있는지)과 Consequences "닫는 데 시간이 든다"가 프로브에 넘긴 어림(정상 종료는 늦지 않는다)을 잰 값으로 바꾸며, 거짓이 된 본문의 문장에 포인터를 단다. 측정은 `.scratch/mcp-http/probes/`(결과는 그 `README.md`)다.

**보호의 자리.** 라이브러리 문맥(`streamable_http_client`와 `ClientSession`)을 닫는 호출을 `CancelScope(shield=True)`로 감싸는 첫째 안은 서지 않는다. 쟀다(`.scratch/mcp-http/probes/http_close.py`, Windows와 Linux 각 3회차, 두 OS 같음). anyio 4.15.1이 `RuntimeError: Attempted to exit a cancel scope that isn't the current tasks's current cancel scope`를 내고 그 예외가 실행 밖으로 샌다. 라이브러리가 안에서 연 취소 범위(태스크 그룹)를 그 뒤에 연 보호 범위가 현재 범위인 채로 닫게 되어 중첩이 어긋나는 것으로 본다(해석. anyio의 문구). 라이브러리의 종료 요청을 끄고 같은 자리에서 보호해도 같은 예외라 원인은 종료 요청이 아니라 보호의 자리다(같은 프로브의 갈래). ADR 0034가 stdio에서 본 양상(안쪽 task group이 취소를 삼켜 `cancelled_caught`가 거짓이 된다)과는 다른 실패이고, 그 양상은 `cancelled_caught`를 기록한 네 갈래 어디에서도 나지 않았다(예외로 끝난 세 갈래는 기록이 없다). 그래서 결정 "닫기"가 적어 둔 대안으로 간다. `terminate_on_close=False`로 라이브러리의 종료 요청을 끄고, 라이브러리 문맥을 보호 없이 닫은 뒤 같은 `finally`에서 `CancelScope(shield=True)`와 2초 유예 안에서 어댑터가 응답 훅으로 받아 둔 세션 식별자로 DELETE를 보내고, 클라이언트는 유예가 지났어도 같은 보호 안에서 닫는다(유예는 종료 요청에만 걸린다. 명세의 "닫기"). 이 모양에서 종료 요청이 같은 세션 식별자로 서버에 닿고(응답 200) 기한의 표지(`cancelled_caught`)는 참이며 예외가 새지 않는다. 종료 요청에 답하지 않는 서버에서는 2초에 끊고 결말이 그대로다. 보호를 `finally` 밖의 다음 문장에 두면 취소된 범위에서는 그 문장이 돌지 않는다(같은 프로브의 갈래). 결정(취소된 실행에서도 2초 안에 종료 요청을 보낸다)은 그대로이고 바뀐 것은 자리와 보내는 주체다. 본문 "종료 요청은 라이브러리 문맥의 `finally`(789~791줄)에서 나가고 어댑터는 그 문맥을 닫는 호출을 감쌀 수 있을 뿐이다"는 거짓이 되어 포인터를 달았다. 종료 요청은 어댑터가 보내고 보호는 그 호출을 감싸지 않는다. 그 앞 문장 "보호의 자리는 라이브러리 바깥이다"는 이 모양에서도 참이다(보호는 어댑터의 `finally`에 있다). 본문이 거짓이 되리라 미리 적은 자리는 앞 문장이었으나 실제로 거짓이 된 것은 뒤 문장이다. 종료 요청의 모양(주소, 헤더 넷, 세션 식별자가 없으면 보내지 않음, 응답과 실패를 보지 않음)은 명세의 "닫기"다.

**잰 값으로 바뀐 어림.** httpx2 2.13.0의 `AsyncClient`에는 `event_hooks`의 `response` 훅이 있고, 그 훅이 `Mcp-Session-Id` 헤더와 2xx가 아닌 응답의 메서드·상태 코드·이유 구절을 받는다(쟀다, `.scratch/mcp-http/probes/http_close.py`의 `normal`과 `unauthorized`). Consequences "닫는 데 시간이 든다"의 어림(정상 종료는 늦지 않는다)은 쟀다(같은 프로브의 `normal_own_delete`. 정상 종료를 이 이력이 고른 길로 닫아 같은 실행의 `normal`과 견줬다). Windows 0.0~0.015초 대 `normal` 0.015초, Linux 0.003~0.005초 대 `normal` 0.003~0.004초로 같은 범위다. 참고로 라이브러리가 종료 요청을 보내는 정상 닫기는 앞선 실행에서 Windows 0.0~0.016초, Linux 0.002~0.003초였고, 어댑터가 보내는 길은 취소된 실행에서 종료 요청의 왕복까지 Windows 0.0초, Linux 0.002~0.008초, 기한부터 돌아오기까지 두 OS 모두 0.03초 안이다(쟀다, 같은 프로브의 `normal`과 `deadline_shield_finally`). 종료 요청의 모양과 명세의 자리는 그 명세의 "닫기"다.

### 2026-11-09 오류 응답의 상태를 원인에 덧붙인다

mcp-http 명세(`.scratch/mcp-http/spec.md`의 "실패 문구")를 쓰며 정했다. 설계가 묻지 않은 자리를 명세가 재어 찾은 것 하나다. Consequences "문구에 실리는 것과 실리지 않는 것"이 명세에 넘긴 자리(실패 문구의 주소에서 쿼리 문자열을 뺄지)는 명세의 초안이 원칙 V를 들어 떼는 쪽을 제안했으나 사용자가 승인에서 주소 전체를 골라(일지 2026-11-09-1611의 "승인") 결정 "주소"가 글자 그대로 참으로 남는다. 그래서 그 자리는 이 이력에 쌓지 않고 명세의 "실패 문구"가 거부한 안으로 적는다.

**상태.** 2xx가 아닌 응답으로 여는 동안 실패하면 어댑터가 응답 훅으로 받아 둔 마지막 오류 응답의 상태 코드와 이유 구절을 원인 끝에 ` (HTTP <상태 코드> <이유 구절>)`로 덧붙인다. 결정 "실패"에 더하는 것이다. mcp 2.3.0이 본문이 JSON-RPC 오류가 아닌 오류 응답(401처럼 글만 든 것)을 404 밖에서는 상태 코드 없이 `Server returned an error response` 하나로 바꿔(쟀다, `.scratch/mcp-http/probes/http_close.py`의 `unauthorized`. 본문이 JSON-RPC 오류인 오류 응답은 그 오류를 그대로 올리고 404는 세션 유무에 따라 두 문구다, mcp 2.3.0의 `client/streamable_http.py`를 읽었다) 꺼진 서버와 틀린 토큰이 문구에서 갈리지 않기 때문이고, diag-bundle의 수락(토큰 불일치를 가른다)이 그 구분에 기댄다. 이것은 본문의 문장을 거짓으로 만들지 않아 포인터가 없다.

`CONTEXT.md`의 원격 MCP 서버 항목에는 `transport = "http"`가 그 전송을 뜻한다는 한 줄을 더했다(PR #499 둘째 회차의 보류).

### 2026-11-09 서버가 되울린 헤더 값을 실패 문구에서 가린다

mcp-http 티켓을 쪼개기 전의 명세 검토(`spec-reviewer`)가 찾았고 사용자가 골랐다(일지 2026-11-09-2138의 "결정"). 세부와 시험은 `.scratch/mcp-http/spec.md`의 "실패 문구"에 단 주석이다. 결정 "실패"의 "헤더 값은 문구에도 원인(`__cause__`)에도 트레이스에도 싣지 않는다"는 라이브러리가 지은 예외 글을 두고 한 말이었고, 명세의 프로브가 잰 것도 그 글이다. 그런데 mcp 2.3.0은 400 이상의 오류 응답이 `content-type: application/json`이고 본문이 JSON-RPC 오류면 그 오류의 글을 그대로 예외로 올린다(`client/streamable_http.py` 398~416줄을 읽었다). 그래서 서버가 받은 `Authorization` 값을 그 글에 되울리면 값이 실패 문구에 실려 트레이스에 남는다. 검토가 httpx2의 `MockTransport`로 그런 서버를 지은 임시 스크립트에서 원인이 `MCPError: bad credentials: Bearer echo-secret-9f3a token=echo-secret-9f3a`로 나오는 것을 손으로 봤다(Windows에서 한 번. 커밋한 프로브가 아니고, 구현 티켓의 되울림 모드 시험이 이 사례를 고정한다).

**가리기.** 어댑터가 짓는 두 문구(여는 동안의 `ConnectionError`, 도구 호출이 실패할 때의 `RuntimeError`)에서, 헤더마다 환경에서 읽은 값 전체와 값이 `<낱말> <나머지>` 꼴이면 그 나머지(`Bearer <토큰>`의 토큰)를 긴 글부터 글자 그대로 찾아 `[가림: 헤더 <헤더 이름>]`으로 바꾼다. 8자보다 짧은 글은 상관없는 글자까지 바꾸지 않게 가리지 않는다. 가린 것이 있으면 그 예외는 원인을 잇지 않고(`from None`) 던진다. 이때 `__context__`는 남는데, core가 닫기의 정리 코드가 덮은 취소를 그것으로 찾기 때문이다(`core/run.py`의 `_cancellation_under`를 읽었다. core의 문구 `_describe`는 예외의 종류와 글만 쓴다). 그래서 `PluginError`를 `except` 밖에서 던져 문맥까지 끊는 모양(ADR 0041, `.claude/rules/adapters.md`의 `read_skill` 항목)은 이 자리에 쓰지 않는다. 가린 것이 없으면 지금처럼 원인을 잇는다.

**남는 한계.** 서버가 값을 바꿔(인코딩, 일부, 대소문자) 되울리면 놓친다. 8자보다 짧은 값은 가리지 않는다. 도구가 오류로 돌려준 결과(`isError`)의 본문은 예외가 아니라 도구 결과로 모델과 트레이스에 가므로 가리지 않는다. 그래서 요약의 "어디에도 싣지 않는다", 결정 "실패"의 "트레이스에도 싣지 않는다", Consequences "문구에 실리는 것과 실리지 않는 것"의 "어디에도 실리지 않는다"는 이 범위 안에서만 참이라 포인터를 달았다.

**거부한 안.** 서버가 쓴 오류 글을 싣지 않는다. 어떤 꼴로 되울려도 막지만, 라이브러리가 지은 안내(따르지 않은 리디렉션, 끝난 세션)도 같은 `MCPError`로 와서 함께 사라지고 운영자가 원인을 가르기 어려워진다. 지금대로 두고 한계로 적는다. 헌법 원칙 V와 글자 그대로 어긋난다.

**같은 검토가 함께 바꾼 것.** 앞 이력 "오류 응답의 상태를 원인에 덧붙인다"의 "마지막 오류 응답"은 마지막 POST 응답이 2xx가 아닐 때의 그 상태로 좁혔다. GET 알림 흐름의 405나 라이브러리가 따른 307을 뒤의 다른 실패에 붙이지 않기 위해서다(명세 "실패 문구"의 주석). 어댑터가 보내는 종료 요청은 라이브러리가 자기 요청에 쓰는 규칙대로, 같은 출처(scheme·호스트·포트가 같거나, 기본 포트를 쓰는 같은 호스트의 http에서 https로)이고 메서드를 지키며 위치에 사용자 정보가 없는 리디렉션만 따른다(사용자가 골랐다). 종료 요청의 모양은 명세의 몫이라 본문을 거짓으로 만들지 않고, 명세 "닫기"의 주석이 적는다. 그리고 첫째 이력이 거짓으로 만든 결정 "닫기"의 첫 문장(종료 요청과 클라이언트 닫기를 함께 2초 기한으로 감싼다)과 요약의 같은 문장에 그 이력의 포인터를 더했다. 첫째 이력은 유예를 종료 요청에만 걸었으므로, 같은 문단의 "2초를 넘기면 그만둔다"도 첫 문장의 포인터가 덮는다(PR #501의 claude-review 셋째 회차가 짚었고 사용자가 골랐다).

**티켓 분할이 바꾼 것.** 티켓을 네 장으로 나누며(일지 2026-11-09-2138의 "분할") `httpx2`의 선언이 첫 티켓(계약)이 아니라 둘째 티켓(접속)으로 갔다. 그래서 `docs/constitution/tech.md` 런타임 의존성 행의 "mcp-http의 첫 티켓이 선언한다"를 "mcp-http의 접속 티켓(02)이 선언한다"로 고치고 헌법 판을 3.0.75로 올렸다. 선언한 뒤의 문장(선언했다는 것과 `uv lock`의 결과)은 그 접속 티켓이 쓴다.

### 2026-11-10 거부 문구를 든 관리 화면 스토리의 글은 그대로 둔다

mcp-http 명세(`.scratch/mcp-http/spec.md`의 "거부 문구의 위치")가 이미 정한 것을 본문의 거짓 문장에 맞춰 쌓는다. PR #503의 CodeRabbit 첫 회차가 Consequences의 해당 문장이 명세와 어긋난다고 짚었고(일지 2026-11-09-2138의 "봇 회차"), 이 세션이 사용자에게 물어 이 PR에서 고치기로 승인을 받았다.

**결정.** `[server]`에 `command`가 없는 매니페스트의 거부 문구를 든 관리 화면 스토리(`web/apps/admin/components/organisms/PluginList.stories.tsx`)의 글은 고치지 않는다. 그 글은 운영자 파일의 문구를 흉내 낸 임의의 글이지 런타임이 내는 문구가 아니고, 스토리는 문구의 자리를 보는 것이지 문구를 대 보는 것이 아니다. 런타임의 위치는 stdio 모양에서 `command`가 없을 때 `server.command`에서 `server.stdio.command`로 바뀌지만(명세, 종류는 `missing`) 스토리의 글은 그대로 둔다. 본문 Consequences의 "문구가 바뀌면 함께 고친다"는 이 결정으로 거짓이 되어 포인터를 달았다. 같은 문장을 되풀이한 명세 서두의 요약(7줄)도 "그대로 두며"로 맞췄고, 티켓 01의 수락 기준(`.scratch/mcp-http/issues/01-contract-mcp-server-transport-stdio-or-http.md`)은 처음부터 "그대로 둔다"를 적었다.

**거부한 안.** 스토리의 글을 새 위치로 고친다. 명세의 근거는 스토리가 문구의 자리를 보는 것이지 문구를 대 보는 것이 아니라는 것이다.

### 2026-11-10 관리 화면의 매니페스트 JSON에 transport 줄이 늘어 사진 정답이 바뀐다

티켓 01(`.scratch/mcp-http/issues/01-contract-mcp-server-transport-stdio-or-http.md`)을 구현하며 사진 비교 `pnpm -C web visual:admin`을 돌리자 본문 Consequences의 "화면은 바뀌지 않는다"가 사실과 어긋났다. 본문의 근거인 grep은 맞다. 관리 화면의 컴포넌트는 `server.command`를 읽지 않는다. 그러나 `PluginDetail`(`web/apps/admin/components/organisms/PluginDetail.tsx`)이 `formatJson(plugin.manifest)`로 매니페스트 전체를 JSON으로 그려, `server`의 칸을 읽지 않아도 칸이 늘면 그림이 바뀐다.

**바뀐 것.** 스토리 픽스처에 더한 `"transport": "stdio"` 한 줄이 `PluginDetail`의 `Disabled` 스토리 그림에 나타나 사진 정답 네 장(너비 둘, 모드 둘)을 `pnpm -C web visual:admin:update`로 갱신했다. 다른 스토리의 사진은 바뀌지 않았다. 실제 관리 API 응답에도 `transport`가 실리므로 운영자가 보는 매니페스트 화면도 줄이 하나 늘어난다.

**결정은 그대로다.** 컴포넌트를 고치지 않는다. 화면이 매니페스트를 있는 그대로 보이는 것이 이 컴포넌트의 일이다(운영자가 자기 파일의 모양을 보는 자리). 앞으로 `[server]` 칸을 더하는 기능은 이 사진 넷이 바뀐다는 것을 미리 안다. 같은 문장을 되풀이한 명세(`.scratch/mcp-http/spec.md`의 "계약과 관리 화면")에는 주석을 달았다.
