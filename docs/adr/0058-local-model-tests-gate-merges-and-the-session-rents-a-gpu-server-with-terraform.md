# 로컬 모델 시험은 실행 코드를 고친 변경의 병합 조건이고, 그 시험의 모델 서버는 세션이 Runpod에 Terraform으로 띄웠다 지운다

ADR 0057이 모델 서버에 붙는 제공사 `openai-compatible`을 더했고, 평소의 pytest와 CI는 루프백의 가짜 호환 서버로 그 어댑터를 본다. 가짜 서버는 실제 모델이 도구 호출 형식을 지키는지와 서빙 엔진의 파서가 그것을 풀어내는지를 보지 못한다. local-model의 수락은 계열이 다른 모델 둘을 모델 파일만 바꿔 같은 시험으로 통과시키는 것이고(`.scratch/local-model/plan.md`의 수락. 이 기능을 기준선에 넣은 것은 ADR 0046이다), 그 시험은 GPU가 달린 모델 서버가 떠 있어야 돈다. 이 저장소의 실제 모델 시험은 지금 셋(`-m llm`, `-m llm_widget`, `-m llm_portal`)이고 모두 손으로 돌리며 CI는 돌리지 않는다. local-model 설계 인터뷰(일지 2026-11-11-1534)가 로컬 모델로 도는 시험을 언제 누가 돌리는지, 그 통과가 병합의 조건인지, 모델 서버를 누가 어떻게 띄우는지를 정했다. 결정의 원문은 그 일지의 `> 사용자:` 인용과 라운드 7에서 확인받은 합의 요약이고, 아래가 그것과 다르게 읽히면 일지가 원천이다. 제공사와 모델 파일과 런타임의 동작은 ADR 0057이다.

인터뷰 전과 도중에 본 것은 다음과 같다. 근거의 종류는 문장마다 밝힌다. 문서의 원문은 세션 스크래치패드에 받아 대 본 것이라 커밋하지 않았고, 클라우드는 한 번도 부르지 않았다. 아래의 명령과 구성은 돌려 보지 않은 것이다.

- **지금의 규약(읽었다).** `docs/constitution/operations.md`의 LLM 테스트 절은 `-m llm`이 키가 없으면 skip이 아니라 실패한다고 적고, 손으로 돌리는 계기를 "그 테스트가 지나는 코드(`core/run.py`·`core/loop.py`, 어댑터, `channel/`, `main.py`)를 건드렸을 때"로 적는다. 다시 돌려 통과하면 통과로 치는 규칙은 없다. 그 시험을 지키게 하는 것은 지침(`CLAUDE.md` 검증 명령, 위 절)과 PR 체크리스트 한 줄(`.github/PULL_REQUEST_TEMPLATE.md`)이고 자동으로 막는 검사는 없다. 병합 절차(`.claude/skills/next-session/merge.md`의 "병합 전" 4)는 "병합할지는 사용자에게 묻지 않는다"고 적는다. CI의 잡은 모두 GitHub이 제공하는 ubuntu 러너에서 돈다(`.github/workflows/ci.yml`의 `runs-on`. 그 러너에 GPU가 없다는 것은 어림이다).
- **범위의 변경 빈도(손으로 봤다, `git rev-list --count 57efd620..33dc5cd9 -- <경로>`).** 2026-10-12 0시(+09:00) 앞의 마지막 커밋 `57efd620`부터 2026-11-11의 `33dc5cd9`까지 30일의 커밋 354건 가운데 `core/run.py`, `core/loop.py`, `core/model.py`, `adapters/`, `channel/`, `main.py`를 건드린 것은 30건이다. `core/loop.py`와 `core/model.py`만 세면 1건이다.
- **Runpod(문서와 Terraform 레지스트리의 원문을 읽었다, 2026-11-11에 받았다).** 48GB GPU A40 한 장이 시간당 $0.59다(가격 페이지. Community와 Secure 가운데 어느 값인지는 가르지 못했다). 선불 크레딧이고 잔액이 0이면 파드가 멈추며, 잔액이 문턱 아래로 내려가면 저장된 카드로 다시 채우는 자동 충전(auto-pay)이 따로 있다. API 키의 권한은 All·Restricted·Read Only이고 Restricted는 API 종류로만 나뉘어, 서버 종류나 금액으로 좁히는 수단은 문서에서 찾지 못했다. 파드의 프록시 주소는 공개 주소이고 인증은 직접 넣어야 한다. Terraform 프로바이더 `runpod/runpod`의 최신 판은 2.0.0(2026-10-27 발행, 레지스트리 등급 community, 소스는 Runpod 조직의 저장소)이고 Terraform 1.6 이상을 요구하며, 키를 환경 변수 `RUNPOD_API_KEY`에서 읽고, `runpod_pod` 자원으로 파드를 만들고 `terraform destroy`로 지운다. `runpod_pod`의 인자에 `image`, `gpu_type_id`, `ports`, `args`, `env`가 있다. 문서는 파드마다 `runpodctl`과 그 파드에만 듣는 API 키가 미리 들어 있다고 적고, 파드 안에서 일정 시간 뒤 스스로 멈추는 예시를 싣는다. 멈춘 파드는 계산 요금이 없고 볼륨 디스크 요금(GB당 월 $0.20)만 나간다.
- **vLLM 0.33.0(문서 원문).** `--api-key`는 `/v1` 아래 등 일부 경로만 인증하고 `/invocations` 같은 다른 경로는 인증 없이 남으며, 문서가 그것 하나에 기대지 말라고 적는다. `--gpu-memory-utilization`은 인스턴스마다의 한도라 한 GPU에 인스턴스 둘을 띄울 수 있다고 적는다.
- **모델 후보(모델 카드와 LICENSE, Hugging Face 파일 목록의 원문).** `skt/A.X-4.0-Light`(Apache-2.0, vLLM 파서 `hermes`, 가중치 14.52GB)와 `openai/gpt-oss-20b`(Apache-2.0, 파서 `openai`, 사고를 내는 모델, 가중치 13.76GB)다. 같은 기준의 다른 후보는 `skt/A.X-3.1-Light`(`hermes`)와 `mistralai/Ministral-3-8B-Instruct-2512`(`mistral`)다. EXAONE 3.5·4.0·4.5는 비상용 라이선스다.
- **이 PC(손으로 봤다, `command -v`와 `--version`).** Terraform은 1.5.5이고 `runpodctl`은 없다.
- **돌려 보지 않은 것.** vLLM 이미지를 Runpod 파드로 띄워 두 모델이 실제로 뜨는지, 48GB 한 장에 둘이 함께 올라가는지(가중치의 합으로 본 어림이다), vLLM 0.33.0에서 두 모델의 도구 호출이 실제로 되는지, 파드 안의 스스로 멈추는 명령이 vLLM 이미지에서 듣는지, 띄우기부터 준비까지 걸리는 시간(10~20분은 어림이다), `temperature` 0이 모델의 흔들림을 얼마나 줄이는지, 워크트리 세션에서 주 체크아웃의 `.env`를 읽어 넘기는 명령과 워크트리 밖의 상태 파일을 쓰는 명령이 데스크톱 앱의 가드와 `.env` 읽기 훅(`tools/hook_env_read.py`)을 지나는지.

**실제 모델 서버로 도는 로컬 모델 시험(새 마커 `llm_local`)을 둔다. 손으로만 돌리고, 환경이 없으면 건너뛰지 않고 실패한다. 어댑터 폴더 전체와 실행 코드(`core/run.py`, `core/loop.py`, `core/model.py`, `channel/`, `main.py`), 로컬 모델 시험 자신, 호환 서버 라이브러리의 판을 고친 변경은 이 시험을 두 모델 모두로 통과해야 병합한다. 한 번 실패하면 실패다. 시험의 모델 서버는 세션이 병합 직전에 Runpod 파드를 Terraform으로 띄워 두 모델로 시험한 뒤 지우고, 띄울 때마다 예상 비용을 보여 주고 사용자의 확인을 받는다.**

## 결정

- **시험은 두 층이다.** 평소의 pytest와 CI는 가짜 호환 서버로 돌고(ADR 0057 "평소의 시험"), 로컬 모델 시험은 마커 `llm_local`을 붙여 `-m llm_local`로만 돈다. 기본 실행과 CI는 이 마커를 뺀다. 모델 서버의 주소 같은 환경이 없으면 skip이 아니라 실패한다(헌법 원칙 II, `-m llm`과 같다).
- **로컬 모델 시험이 보는 것.** calc 예시가 MCP 도구를 써서 답하고 트레이스가 남는 것을, 모델 파일만 바꿔 두 모델로 본다(기능 계획의 수락). 트레이스에 도구 호출이 실제로 남아야 통과한다. 그래야 도구 호출이 글로 샌 조합(ADR 0057)이 통과로 읽히지 않는다.
- **두 모델.** 둘 다 상용 이용이 가능한 라이선스이고, 24GB GPU 한 장에 올라가며, vLLM에 든 파서로 도구 호출이 되는 모델이다. 하나는 한국 회사의 한국어 모델이고 하나는 해외 모델이며 둘의 파서가 달라야 한다. 첫 후보는 SKT A.X 4.0 Light(`hermes`)와 OpenAI gpt-oss-20b(`openai`)다. 띄워 보니 도구 호출이 되지 않으면 같은 기준의 다음 후보(한국어는 A.X 3.1 Light, 해외는 Ministral 3 8B)로 바꾸고 까닭을 일지에 적는다. 치르는 값은 모델마다 서버를 다른 옵션으로 띄워 봐야 해서 GPU를 빌리는 시간이 늘고, 사고를 내는 모델(gpt-oss-20b)이 시험을 더 까다롭게 만들 수 있다는 것이다.
- **병합 조건의 범위.** `src/agent_os/adapters/` 전체, `core/loop.py`, `core/model.py`, `core/run.py`, `channel/`, `main.py`, 로컬 모델 시험 자신(시험 파일, 서버를 띄우는 Terraform 파일과 스크립트), `langchain-openai`와 `openai`의 판을 바꾼 변경이다. `-m llm`의 계기를 모두 품는 범위라 "`-m llm`을 돌려야 하는 변경은 `-m llm_local`도 돌린다"로 기억할 수 있다(`core/model.py`와 로컬 모델 시험 자신, 라이브러리 판만 더 든다). 문서와 하네스만 바꾼 변경은 해당하지 않는다. 다만 서버를 띄우는 Terraform 파일과 스크립트는 저장소의 어디에 두든(하네스의 자리인 `tools/`에 두더라도) 로컬 모델 시험 자신으로 세어 해당한다.
- **두 모델 모두 통과해야 병합한다.** 한쪽 파서에서만 깨지는 변경이 main에 들어오지 않게 한다.
- **한 번 실패하면 실패다.** 다시 돌려 통과하면 통과로 치는 규칙을 두지 않는다. 다른 실제 모델 시험과 같은 판정이다. 실패하면 세션이 멈춰 원인을 보고하고, 고친 뒤 서버를 다시 띄워 처음부터 돌린다. 모델의 흔들림은 시험을 짜는 쪽에서 줄인다(시험용 모델 파일의 `temperature`를 0으로 두는 것 등).
- **언제 돌리고 무엇을 남기는가.** 마지막 리뷰 반영 뒤 병합 직전에 한 번 돌린다. 시험한 커밋, 두 모델, 모델 서버의 판과 옵션, 통과 수와 토큰 합계를 PR 코멘트와 일지에 적는다. 그 커밋 뒤로 위 범위가 바뀌지 않았으면 기록이 유효하고, 바뀌었으면 다시 돌린다. 유효한지는 시험한 커밋과 병합하려는 브랜치 끝 사이의 차이를 위 범위의 경로로 봐서 가리고, main을 합쳐 들어온 범위의 변경도 바뀐 것으로 센다. 기록을 일지에 적는 커밋은 범위를 바꾸지 않으므로 기록을 무효로 만들지 않는다. 다만 그 푸시로 PR 봇이 한 번 더 돌 수 있고(병합 절차의 봇 회차), 그 회차의 지적으로 범위의 파일을 고치면 다시 돌린다. 브랜치를 갱신하지 않은 채 병합될 때 main에 먼저 들어간 범위의 변경과의 조합은 시험되지 않으며, 이 ADR은 그 틈을 막지 않는다. 제품 판을 내기 전에도 한 번 돌린다(라운드 1의 설명에 있던 계기이고 범위를 넓힌 뒤에도 거두지 않았다. 판을 내는 절차는 pilot-release와 deploy-package가 정한다).
- **첫 적용.** 호환 서버 어댑터를 처음 넣는 PR부터다. 어댑터와 로컬 모델 시험을 같은 PR에 넣고 그 PR이 시험을 통과해야 병합한다. 그 PR보다 먼저 병합되는 변경(ADR 0057의 계약 티켓, 서버를 띄우는 파일을 따로 먼저 들이는 경우의 그 PR)에는 돌릴 시험이 아직 없어 이 조건이 붙지 않는다.
- **지키게 하는 수단.** 다른 실제 모델 시험과 같이 지침과 PR 체크리스트다. 자동으로 막는 검사는 두지 않는다.
- **모델 서버는 세션이 띄웠다 지운다.** 병합하려는 세션이 Runpod 파드를 Terraform(프로바이더 `runpod/runpod`)으로 띄우고, 두 모델로 시험한 뒤 지운다. 띄우기, 준비 기다리기, 시험, 지우기를 명령 하나가 이어서 한다. 그 명령이 서버 키를 만들어 시험에 환경 변수로 넘기고 화면에 찍지 않으므로 세션은 서버 키를 보지 않는다.
- **서버를 막는 것.** 띄울 때마다 새로 만든 무작위 키를 vLLM의 `--api-key`로 준다. 인증 없이 남는 경로의 틈은 받아들인다. 서버는 일정 시간 뒤 스스로 꺼지게 걸린 채로 떠서, 명령이나 세션이 중간에 죽어도 계속 돌지 않게 한다. 타이머가 멈춤까지만 가면 멈춘 파드가 남아 디스크 요금이 나가므로(위 "Runpod"), 삭제까지 가게 할지와 남은 파드를 누가 언제 지우는지는 명세가 정한다(아래 "명세로 넘기는 것"). 파드 안에서 스스로 멈추는 명령이 vLLM 이미지에서 듣는지는 돌려 보지 않았다.
- **비용 확인.** 세션은 띄울 때마다 예상 비용을 보여 주고 사용자의 확인을 받는다. 그래서 위 범위의 PR은 병합 직전에 한 번 멈춰 묻는다. 병합 절차의 "병합할지는 사용자에게 묻지 않는다"에 예외가 생긴다. 묻는 것은 병합이 아니라 과금이다.
- **사용자가 한 번 준비하는 것.** Runpod 계정과 크레딧 충전, API 키를 주 체크아웃의 `.env`에 `RUNPOD_API_KEY`로 넣기, Terraform을 1.6 이상으로 올리기, 자동 충전(auto-pay)을 켜지 않기다. 세션은 계정을 만들거나 키를 입력하지 않는다.
- **상태 파일.** Terraform이 무엇을 지울지 적어 두는 상태 파일은 워크트리 밖에 브랜치마다 따로 둔다. 병합 뒤 워크트리가 지워져도 남은 서버를 지울 기록이 남고, 나란히 도는 두 세션이 서로의 서버를 지우지 않는다.
- **띄우지 못할 때.** 재고가 없거나, 잔액이 모자라거나, 키와 Terraform이 없는 자리(클라우드 세션)면 이 PC의 세션에 넘기거나 병합을 기다린다. 시험은 모델 서버의 주소와 키만 받으므로, 사용자가 다른 곳에 띄운 서버의 주소와 키로도 같은 시험을 돌릴 수 있다.
- **기본 에이전트의 사례.** base-agent가 끝난 뒤 그 실제 모델 시험의 사례(요청을 셋으로 가르기, 검색한 뒤 답하기, 정해진 문장을 글자 그대로 내기)를 두 모델로 돌려 사례별 통과와 실패를 기록하는 티켓이 이 기능의 마지막 티켓이다. 통과를 요구하지 않는다. 실패한 사례는 스킬 문구(base-agent)나 모델 고르기(answer-eval)의 입력이 된다. 다른 티켓은 base-agent를 기다리지 않고 calc 예시로 먼저 끝난다.
- **명세로 넘기는 것.** GPU의 종류와 두 모델을 한 파드에 올릴지 차례로 올릴지, 타이머의 값과 그것이 멈춤이 아니라 삭제까지 가는지, 스크립트와 Terraform 파일의 자리, 시험이 주소와 키를 받는 환경 변수의 이름, 명령이 시작할 때 같은 상태 파일에 남은 서버를 먼저 지우는지와 그때 앞 세션의 명령이 아직 쓰고 있는 서버를 어떻게 가르는지, 세션이 죽거나 PR이 버려져 남은 파드와 상태 파일을 누가 언제 지우는지, 서버 쪽 사정(타이머가 먼저 껐다, 프록시가 끊겼다)으로 시험이 끝까지 돌지 못한 회차를 "한 번 실패하면 실패"로 셀지다. vLLM 이미지를 파드로 띄워 두 모델이 실제로 뜨는지는 서버를 띄우는 파일을 들이는 티켓이 띄워 확인한다(합의 요약의 "구현의 첫 티켓"이다. ADR 0057의 계약 티켓과의 순서와 그 파일이 어느 PR에 드는지는 티켓을 나눌 때 정하고, 어댑터를 처음 넣는 PR보다 늦지 않아야 한다).

## Considered Options

- **지금의 실제 모델 테스트(`-m llm`)에 합친다.** `-m llm`은 원칙 I의 판정이라, 합치면 GPU 서버가 떠 있지 않은 동안 그 판정이 초록이 될 수 없다. 위젯 e2e를 `llm_widget`으로 가른 것과 같은 까닭이다(`operations.md` LLM 테스트 절). 거부했다.
- **CI가 GPU를 빌려 정기적으로 돈다.** Runpod 키가 CI의 시크릿이 되고, 실패가 어느 변경에서 났는지를 뒤늦게 안다. 거부했다.
- **병합하고, 돌리지 못했다고 남긴다.** 이 세션이 추천했고 사용자가 고르지 않았다. 서버가 없을 때 작은 수정이 멈추지 않지만, 실제 모델과 어긋난 변경이 main에 들어온다. 거부했다.
- **제품 판을 내기 전에만 돌린다.** 어긋남이 여러 변경에 쌓인 뒤에야 드러나 어느 변경 때문인지 가르기 어렵다. 거부했다.
- **범위를 모델과 주고받는 코드만으로 둔다(호환 서버 어댑터, `core/loop.py`, `core/model.py`, 시험 자신, 라이브러리 판).** 이 세션이 추천했고 사용자가 고르지 않았다. 최근 30일에 1건이라 서버를 거의 띄우지 않지만, 실행을 감싸는 코드(`core/run.py`)를 고쳐 실제 모델과 어긋난 경우를 이 규칙이 잡지 못한다. 거부했다. 치르는 값은 아래 Consequences의 빈도다.
- **범위의 어댑터를 호환 서버 어댑터 하나로 읽는다.** 고른 설명 안에서 말이 갈려 라운드 7에서 다시 물었다. MCP 어댑터는 모델에 넘길 도구 설명(`ToolSpec`의 `input_schema`)을 만들어(`adapters/mcp.py`를 읽었다) 모델이 받는 요청의 모양에 닿고, 폴더 전체로 읽어야 `-m llm`의 계기와 한 줄로 맞는다. 거부했다.
- **한 모델만 통과하면 병합하고 둘은 판을 내기 전에 본다.** 서버를 띄우는 시간이 줄지만 다른 파서에서만 깨지는 변경이 main에 들어온다. 거부했다.
- **규칙을 로컬 모델 시험이 main에 들어온 뒤부터 적용한다.** 실제 모델로 확인되지 않은 어댑터가 main에 먼저 들어온다. 거부했다. 치르는 값은 첫 PR이 커지고 그 PR부터 GPU 서버가 필요하다는 것이다.
- **사람이 서버를 띄운다(병합 직전에 묻고 그 세션이 기다린다, 작업을 시작할 때 먼저 묻는다, 묻지 않고 PR을 열어 둔 채 끝낸다).** 처음 올린 선택지 셋이 모두 이 전제였고, 그 가운데 "병합 직전에 묻고 그 세션이 기다린다"가 이 세션의 추천이었다. 사용자가 세션이 직접 띄우고 내릴 수 없는지를 되물었고, 넓힌 범위의 변경이 하루에 한 번꼴이라 사람이 그때마다 서버를 띄우는 길은 성립하기 어렵다. 거부했다.
- **AWS EC2에 띄운다.** 라운드 5에서 이 세션이 추천했고, 사용자는 고르는 대신 Runpod을 Terraform으로 다룰 수 있는지를 되물었다. 그것을 찾아본 뒤 라운드 6에서 Runpod을 추천했고 사용자가 골랐다. GPU 인스턴스의 할당량 기본값이 0이라(원문) 신청이 먼저이고, 처리 시간의 공식 수치는 받아 둔 문서에서 찾지 못했다(사례가 30분에서 한 주 넘게까지 퍼져 있다는 것은 웹 요약이다). 48GB 한 장(g6e.xlarge)이 us-east-1에서 시간당 $1.861이다(2026-11-10 가격표 원문). 포트를 열지 않고 붙는 관리 통로(SSM)에는 이 PC의 플러그인과 인스턴스 역할이 따로 필요하다. 거부했다. 라운드 5에서 AWS를 전제로 올린 붙는 방법 셋(포트를 열지 않는 관리 통로, 내 IP에만 열고 키로 막는다, SSH 터널)은 사용자가 고른 관리 통로를 포함해 모두 쓰이지 않는다.
- **Modal에 띄운다.** 요청이 없으면 0으로 줄고 Modal이 내는 주소가 기본으로 인증을 요구하지만, 공식 예시의 vLLM 판이 0.21.0이고, 권한을 좁힌 서비스 사용자는 Team 요금제부터이며(원문), Windows에서의 CLI 동작을 확인하지 못했다. 거부했다.
- **CloudFormation 템플릿이나 AWS CLI 스크립트로 띄운다.** CloudFormation 템플릿은 AWS를 전제로 한 질문에서 이 세션이 추천했고 사용자가 고르지 않았다. 둘 다 AWS에만 쓰이는 수단이다. 사용자가 다른 클라우드로 옮겨도 같은 도구를 쓰는 Terraform을 골랐다. 거부했다. 치르는 값은 무엇을 지울지의 기록이 PC의 파일(상태 파일)이라 그 파일을 잃으면 남은 서버를 손으로 찾아 지워야 한다는 것이다.
- **파드 안에 인증 프록시를 둔다.** 인증 없이 남는 경로까지 막지만, 이미지에 프록시를 얹어 설치하고 지켜야 할 것이 는다. 거부했다.
- **SSH로 포트를 잇는다.** 서버를 공개 주소에 열지 않지만, Runpod의 기본 SSH는 Runpod을 거치는 제한된 연결이고 온전한 SSH는 공인 IP가 있는 파드와 파드 안에서 도는 SSH 서버가 필요하다(원문). vLLM 이미지에 SSH 서버가 없다는 것은 어림이다. 거부했다.
- **같은 서버에서 한 번 더 돌려 통과하면 통과로 본다, 또는 세 번 돌려 두 번 이상 통과하면 통과로 본다.** 모델의 흔들림으로 병합이 멈추는 일이 줄지만, 가끔만 깨지는 변경이 통과로 읽히고 다른 실제 모델 시험과 판정이 갈린다. 거부했다. 치르는 값은 코드가 맞아도 모델이 한 번 도구 호출을 빠뜨리면 병합이 멈추고 서버를 한 번 더 띄우는 비용과 확인이 든다는 것이다.
- **두 모델을 만든 곳만 다르게 고른다, 또는 기준만 정하고 모델은 티켓이 고른다.** 앞의 것은 두 모델이 같은 파서를 쓰면 한 형식만 보게 된다. 뒤의 것은 수락의 대상이 설계에서 정해지지 않는다. 거부했다.
- **기본 에이전트의 사례를 평가 보고서(answer-eval) 쪽에 넘긴다, 또는 그 사례의 통과를 이 기능의 끝 조건으로 한다.** 앞의 것은 base-agent 명세가 이 기능에 넘긴 일을 다시 미룬다. 뒤의 것은 스킬 문구와 모델 고르기에 달린 결과가 이 기능을 막는다. 거부했다.

## Consequences

- **빈도와 비용.** 위 범위를 건드린 커밋이 최근 30일에 30건이라 하루에 한 번꼴로 서버를 띄운다. 한 번을 30분으로 어림하면 A40 한 장에 약 $0.30이고 한 달 30번이면 약 $9다(단가는 원문, 시간과 횟수는 어림이다). 이 범위를 고치는 다른 기능의 세션도 병합 직전에 멈춰 비용을 확인받는다. 문서와 하네스만 바꾼 PR은 지금처럼 묻지 않고 병합한다(서버를 띄우는 파일을 고친 PR은 위 범위대로 해당한다).
- **규약이 서는 때.** 이 ADR은 결정이고, 규약 문서는 어댑터와 로컬 모델 시험을 넣는 PR이 고친다. 그때까지 `llm_local` 마커도 병합 조건도 없다. 그 PR이 고칠 자리는 실제 모델 시험의 마커를 이름으로 드는 살아 있는 문서와 코드 전부와, 병합 절차다. 앞의 것은 가장 늦게 든 마커 `llm_portal`로 저장소를 grep해 다시 찾는다. 2026-11-11에 그 grep이 낸 것은(일지와 `.scratch/`의 기록, 시험 파일 자신을 빼고) `pyproject.toml`의 마커 선언과 `addopts`, `tests/conftest.py`의 마커 목록과 그 시험(`tests/test_conftest.py`), `CLAUDE.md`의 검증 명령, `docs/constitution/operations.md`의 LLM 테스트 절(헌법 개정이라 판을 올린다), `.claude/rules/tests.md`와 `.claude/rules/http.md`, `.github/PULL_REQUEST_TEMPLATE.md`의 체크리스트, `.github/workflows/ci.yml`의 주석, `.coderabbit.yaml`, `tools/llm_tokens.py`(토큰 합계를 내는 도구)와 그 시험, `tools/hook_env_read.py`의 문구, `tools/mutate.py`의 독스트링이다(Grep으로 봤고 파일마다 무엇을 고칠지는 열어 보지 않았다). 뒤의 것은 `.claude/skills/next-session/merge.md`의 "병합 전"이다(시험과 비용 확인의 단계, 기록이 유효한지의 판정, "병합할지는 사용자에게 묻지 않는다"의 예외). `docs/constitution/tech.md`에는 이 ADR과 같은 PR이 시험용 모델 서버의 행을 더한다(헌법 판 3.0.85).
- **브랜치 전략과의 관계.** ADR 0043이 정한 전환(티켓 PR은 dev로, 기능이 끝나면 dev를 main으로)이 서면 이 조건은 위 범위의 변경을 싣는 PR의 병합에 붙는다. dev로 가는 티켓 PR과, main에서 따 main으로 바로 가는 hotfix PR이 그것이다(ADR 0043의 "CI 분담"이 main PR을 dev→main과 hotfix→main으로 적는다). ADR 0043이 main PR의 CI에 더하기로 한 LLM 테스트에 `llm_local`은 들지 않는다. CI 러너에 GPU가 없고 이 ADR이 자동 검사를 두지 않기 때문이다. 전환을 하는 harness 티켓이 병합 절차를 고칠 때 이 조건을 함께 옮긴다.
- **비밀.** `RUNPOD_API_KEY`는 주 체크아웃의 `.env`에만 있고 세션은 그 값을 읽지 않는다. 서버 키는 명령이 만들어 넘기며 일지와 PR 코멘트에 적지 않는다. Terraform의 상태 파일에는 서버 키가 평문으로 남을 수 있는데(어림, 일반 지식), 그 파일은 저장소 밖에 있고 키는 서버와 함께 죽는다.
- **받아들인 틈.** 서버가 떠 있는 동안 무작위 파드 ID가 든 주소를 알아낸 사람은 인증 없이 남는 경로로 그 GPU를 쓸 수 있다. 서버에는 공개 모델과 시험용 글만 있고 타이머가 서버를 끈다. 요금이 선불 잔액을 넘지 않는 것은 자동 충전을 켜지 않았을 때만이다. API 키의 권한을 서버 종류나 금액으로 좁히지 못하므로 그 키가 새면 잔액만큼의 서버를 띄울 수 있다. 프로바이더 2.0.0은 나온 지 두 주 된 판이다.
- **서버를 띄우는 파일을 들이는 티켓이 띄워 확인하는 것.** 위 "돌려 보지 않은 것" 전부다. vLLM 이미지가 파드로 뜨지 않거나 두 모델이 한 파드에 오르지 않으면 명세가 GPU의 종류와 올리는 방식을 다시 정하고, 그래도 되지 않으면 이 ADR의 이력에 무엇이 바뀌었는지를 적는다. 첫 PR이 병합되기 전에 사용자의 준비(계정, 크레딧, 키, Terraform 올리기)가 끝나 있어야 하고, 늦으면 그 PR이 기다리거나 사용자가 다른 곳에 띄운 서버로 시험한다.
- **기능이 닫히는 때.** 마지막 티켓이 base-agent를 기다리므로 이 기능은 base-agent가 끝날 때까지 닫히지 않는다. 둘을 모두 기다리는 deploy-package의 차례는 그대로다(`.scratch/plan.md`).
- **용어.** "로컬 모델 시험"은 용어집에 두지 않는다. 용어집에 실제 모델 시험 계열의 항목이 없고, 이 말은 마커 `llm_local`이 붙은 시험을 가리키는 규약의 말이다. 모델 서버와 서빙 엔진은 ADR 0057이 용어집에 더했다.
