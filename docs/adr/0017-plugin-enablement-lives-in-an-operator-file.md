# 플러그인의 켜짐은 플러그인 루트의 운영자 파일이 든다

PRD의 운영자는 등록된 에이전트, 도구, 모델을 켜고 끄고 싶어 한다. 그러려면 켜짐을 어디에 적을지부터 정해야 한다. ADR 0003에 따라 자리는 파일시스템이다. `plan.md`와 ADR 0010 이력은 매니페스트 필드를 가정했다. **켜짐은 매니페스트가 아니라 플러그인 루트의 `disabled.toml` 하나가 든다. 기본은 켜짐이고 파일에는 끈 것만 적는다. 꺼짐은 새 실행과 재개를 막고, 도는 실행은 끝까지 둔다. 꺼진 것을 부른 요청은 core의 `Disabled`이고 409다.** 매니페스트에 두지 않는 이유는 두 역할이 쓰는 파일이 다르기 때문이다. 매니페스트는 플러그인이 무엇인지 개발자가 손으로 적은 것이다. 켜짐은 운영자가 이 배치에서 고른 것이다. 둘을 섞으면 두 가지 문제가 생긴다. 하나는 개발자가 새 버전을 디렉터리째 갈아 끼울 때 운영자가 끈 것이 조용히 다시 켜진다는 것이다. 다른 하나는 관리 API가 사람이 쓴 TOML을 기계로 다시 써야 한다는 것이다. 표준 라이브러리 `tomllib`은 읽기만 하므로 쓰기 의존성이 새로 들고, 주석을 지키느냐 버리느냐를 또 골라야 한다. sdk 계약이 바뀌지 않는다는 것도 PRD의 우선순위(계약의 안정성)에 맞는다.

## Considered Options

- **매니페스트의 선택 필드 `enabled`.** 장점이 있다. `/plugins` 응답에 저절로 실리고, 손상 처리가 기존 경로 그대로이며, 선택 필드라 형식 버전도 "1" 그대로다(ADR 0008 이력의 규칙). 그러나 위의 이유로 거부했다.
- **플러그인 디렉터리 안의 표시 파일(`DISABLED`).** 형식이 없어 깨질 수 없고 만들고 지우기가 원자적이다. 그러나 디렉터리를 갈아 끼우면 사라진다는 점은 매니페스트 필드와 같다. 무엇이 꺼져 있는지 한 곳에서 보이지도 않는다. 거부했다.
- **꺼짐 기본(켠 것만 적는 허용 목록).** 이 저장소의 fail-closed 계보(ADR 0002·0008·0011)와 같은 모양이다. 그러나 그 계보가 막은 것은 기본값이 남에게 노출되는 자리였다. 인증, 주체, 에이전트별 도구 범위가 그렇다. 플러그인 루트에 디렉터리를 두는 것은 이미 파일시스템 권한을 가진 사람만 할 수 있는 일이다. 그 뒤에 게이트를 하나 더 둘 신뢰 경계가 없다. 새 에이전트의 첫 실행과 테스트의 임시 루트마다 켜는 단계가 든다는 대가도 있다. ADR 0003이 파일을 원천으로 둔 이유("화면이 없어도 시스템이 돌고 git이 이력을 가진다")와도 어긋난다. 거부했다.
- **재개는 허용한다(드레인).** 새 실행만 막는 안이다. 그러나 승인을 기다리는 것이 바로 그 도구 호출이다. 위험해서 끈 에이전트를 승인 하나가 통과시키게 된다. 거부했다.
- **꺼짐을 404나 500으로 옮긴다.** 404는 운영자가 있다고 아는 이름을 틀렸다고 말한다. 500은 "서버의 파일이 깨졌다"는 신호(ADR 0010)를 거짓으로 만든다. 꺼짐은 깨짐이 아니라 운영자가 고른 상태다. 거부했다.
- **켜진 에이전트가 가리키는 mcp는 끌 수 없게 한다.** 손편집으로 우회되므로 실행 시점 검사가 어차피 필요하고, 그러면 같은 규칙이 두 곳에 산다. 거부했다. 꺼진 mcp를 빼고 도는 안도 거부했다. 조용한 기능 저하이고, `requires_approval`이 가리키는 도구가 사라져 어차피 `run_failed`다(ADR 0008 이력).

## Consequences

- **파일의 모양.**
  - `schema_version = "1"`(필수)과, 종류 키 넷(`agent`, `mcp`, `skill`, `model`)의 이름 배열로 이뤄진다.
  - 빠진 키는 빈 목록이고 중복은 합친다. 둘 다 뜻이 하나로만 읽히기 때문이다.
  - 파일이 없으면 꺼진 것이 없다. 빈 파일은 형식 버전이 없으므로 손상이다. ADR 0008이 "없으면 1"을 거부한 것과 같은 이유다.
  - 파일 이름이 내용 하나만 말하게 해서 설정 파일로 자라지 않게 한다. ADR 0010이 `agent-os.toml`을 거부한 것과 같은 방향이다.
- **런타임이 파일을 쓰는 법.**
  - 종류 넷을 모두, 이름순으로, 중복 없이 임시 파일에 쓴 뒤 이름을 바꿔 통째로 교체한다.
  - 모양이 닫혀 있고 이름이 패턴에 묶여 있으므로 쓰기 코드는 직접 짠다. 맞게 쓰는지는 `tomllib`과의 왕복 테스트가 판정한다.
  - 손으로 단 주석은 API로 쓸 때 사라진다.
  - 파일은 git 추적 대상이다. 누가 언제 껐는지는 git이 들고 있으므로 감사 필드를 두지 않는다.
- **깨지면 전부 거부한다.** 손상은 문법 오류, 모르는 형식 버전, 모르는 키, 패턴을 어긴 이름이다. 그러면 새 실행, 재개, `GET /plugins`, 켜고 끄기가 모두 `PluginError`(500)이고, 메시지가 파일 경로와 이유를 든다.
  - 무엇이 꺼져 있는지 알 수 없으니 돌리지 않는다.
  - 덮어쓰지도 않는다. 덮어쓰면 끈 것이 조용히 켜질 수 있다.
  - 무시하고 전부 켜는 안은 fail-open이라 거부했다.
  - 목록이 행마다 "알 수 없음"을 싣는 안은 행의 타입이 약해져 거부했다. ADR 0012 이력이 부분 요약을 거부한 것과 같은 이유다.
- **고아 항목은 남는다.** 디렉터리가 없는 이름은 손상이 아니고, 쓸 때도 지우지 않는다. 같은 이름이 다시 들어오면 꺼진 채로 오는데, 그것이 안전한 쪽이다. `/plugins`는 디렉터리를 훑으므로 고아 항목은 보이지 않는다.
- **런타임은 준비 단계에서 꺼짐을 본다.** 보는 대상은 셋이다: 요청한 에이전트, 트레이스가 가리키는 에이전트, 에이전트가 가리키는 mcp.
  - 부재 판정이 먼저다. 없는 것은 여전히 `Absent`(404)이거나 `PluginError`(500)다(ADR 0014 이력).
  - 재개에서는 결정 이벤트를 쓰기 전에 거부된다. 그래서 거부된 실행은 트레이스에 아무것도 남기지 않고 일시정지 그대로다. 다시 켜면 이어서 승인할 수 있다.
  - 캐시가 없으므로 `serve`를 다시 띄우지 않아도 바로 효력이 난다.
  - 도는 실행을 취소하지 않는 이유는 ADR 0014가 취소를 목표에서 뺀 이유와 같다.
- **`Disabled`는 `PluginError`의 하위 타입이고, 공용 표가 409 `conflict`로 옮긴다.**
  - 이것은 하위 타입을 가르는 기준을 "요청을 고쳐서 풀리나"에서 "깨졌나"로 바꾼다. 그 개정과 옛 문구를 고칠 자리는 ADR 0014의 2026-09-26 이력에 있다.
  - 에러 어휘는 다섯 그대로다.
  - 메시지는 꺼진 플러그인의 종류와 이름을 든다. 켜진 에이전트가 꺼진 mcp 때문에 거부되면 그 mcp의 이름이다.
  - 승인 경로에서 409는 재개 불가(일시정지 아님, 형식 1)와 꺼짐으로 갈린다. 그 구분은 `message`가 말한다.
  - CLI는 기반 타입을 잡으므로 바뀌지 않는다.
  - 최종 사용자 앞에서 꺼진 에이전트의 존재를 숨길지는 web-widget이 에러 노출과 함께 다시 본다.
- **넷 종류 모두 켜고 끈다.** skill과 model은 로더가 생길 때 그 로더가 켜짐을 본다. 지금은 효과가 없다.
- **켜고 끄는 면은 관리 API와 손편집이다.** CLI 명령은 두지 않는다. PRD 우선순위에서 마지막인 편의에 해당하기 때문이다. 관리 API의 모양은 ADR 0010 이력에, 포트의 모양은 ADR 0012 이력에 있다.
- **프로세스 사이의 경합은 알려진 한계다.**
  - 한 프로세스 안의 쓰기 둘은 이벤트 루프가 줄세운다. 읽고 고치고 쓰는 사이에 `await`가 없기 때문이다.
  - 손편집과 API 쓰기가 같은 순간에 오면 나중에 쓴 쪽이 이긴다.
  - 이름 바꾸기로 통째로 교체하므로 반쯤 쓰인 파일은 보이지 않는다.
  - 윈도우에서 다른 프로세스가 파일을 연 순간 이름 바꾸기가 실패하는지는 구현 티켓이 잰다.
