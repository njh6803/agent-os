# Agent OS는 플러그인으로 실은 실행의 모델·도구 호출을 중재·강제·기록하는 런타임이고, 다음 기능은 다섯 묶음 열일곱이다

PRD(2026-09-21 승인)의 성공의 정의 다섯 줄은 skill-plugin(슬라이스 6, 아직 todo)까지로 기능이 모두 섰고, 그것이 닫히면 `.scratch/plan.md`의 프론티어에 남는 기능이 없었다(이 ADR의 행 열일곱이 서기 전). 그래서 업계 조사 보고서(`C:\project\reports\Agent OS 업계 동향과 방향 점검.md`, 저장소 밖. 조사 노트 다섯은 `C:\project\research_notes\Agent OS 업계 동향과 방향 점검\`)와 PRD를 대조해, 우리가 "an agent OS"라는 이름으로 무엇을 보장할지와 다음 기능을 정하는 설계 인터뷰를 했다(일지 2026-11-03-04의 방향 라운드, 2026-11-04-01의 묶음 라운드 여섯). 결정의 원문은 그 두 일지의 `> 사용자:` 인용이고, 묶음마다 사용자가 확인한 합의 요약이 있다(묶음 ①은 라운드 2 4호출과 라운드 3 1호출의 바로잡기, 묶음 ②는 라운드 3 10호출, 묶음 ③은 라운드 4 5호출, 묶음 ④는 라운드 5 4호출, 묶음 ⑤와 전체는 라운드 6 4호출). 이 ADR은 그 요약을 용어집(`CONTEXT.md`)의 말로 옮긴 것이고 조건은 하나도 빼지 않았다. 세부가 요약과 다르게 읽히면 일지의 인용이 원천이다. **Agent OS가 보장하는 것은 에이전트 코드가 건너뛸 수 없는 셋이다. 중재: 실행의 모델 호출과 도구 호출은 런타임을 지난다. 강제: 운영자가 바깥에서 건 정책(승인 규칙, 서버의 신뢰 수준, 상한, 승인 만료, 보존 기간)을 런타임이 집행하고 저자의 코드가 풀지 못한다. 기록: 그 호출과 판정이 트레이스에 남아 되짚을 수 있다. 에이전트 코드 안의 일(저자가 손으로 엮는 글, 코드가 런타임을 거치지 않고 부르는 것)은 보장 밖이다. 다음 기능은 다섯 묶음 열일곱이고 순서는 ① 신뢰·강제(6 → 7 → 11), ② 비용·기록(18 → 9 → 8 → 15 → 12 → 20), ③ 바깥 연결(1 → 3 → 13), ④ 여러 에이전트(4 → 2 → 14), ⑤ 확장·채널(21 → 5)이다.** 번호는 일지의 후보 번호이고 아래 표가 이름으로 푼다. 후보는 열여덟으로 시작해 10이 빠지고 19·20·21이 더해져 번호가 1~21이고(자리는 일지), 그 가운데 열일곱이 `plan.md` 행이 되며 넷(10 모델의 기밀 등급·능력 선언, 19 분류기 승인, 17 승인 알림, 16 웹훅·스케줄러)은 미룬 것이다. 인터뷰 깊이는 "열여덟 전부 설계"였으므로(추천과 다른 답, 일지 2026-11-03-04) 뒤 묶음의 결정은 앞 묶음의 구현을 보지 못한 채 섰다. 그 기능의 차례가 오면 그 설계 인터뷰가 여기 적힌 조건 위에서 세부를 정하고, 조건을 바꾸면 이 ADR의 이력에 쌓는다.

## 보장과 전제

- **중재.** 모델 호출은 `ctx.llm()`, 도구 호출은 `ctx.tool()`과 루프의 도구 호출뿐이다. 묶음 ④의 맡기기(`ctx.delegate()`)도 같은 길이다. 런타임이 모르는 호출은 보장 밖이다.
- **강제.** 운영자가 운영자 파일(플러그인 루트의 규칙 파일·서버 파일·꺼짐 파일과 `serve`가 인자로 받는 사이트 파일)과 운영 설정(PostgreSQL 표)으로 건 것을 런타임이 실행을 준비할 때와 호출마다 집행한다. 운영자는 저자의 `requires_approval`을 풀지 못하고(일지 2026-11-03-04의 라운드 밖 결정), 저자는 운영자의 deny를 넘지 못한다.
- **기록.** 호출과 판정은 트레이스의 이벤트이고(원칙 V) 트레이스가 원천이다. 묶음 ⑤의 실황(Redis 채널)은 트레이스에 쓴 뒤의 흘림이라 받는 쪽이 없으면 버려도 기록은 남는다.
- **전제.** 배포는 프로세스 넷(`serve`, `worker`, PostgreSQL, Redis)이다. PRD는 배포의 모양을 적지 않았고 인터뷰는 PRD와 보고서를 "작은 자체 호스팅 프로세스 하나"로 읽었다(일지 2026-11-03-04의 다중 인스턴스 대목). 이번 개정이 프로세스 넷을 PRD의 전제로 적는다(PRD 개정은 사용자 승인). 다중 인스턴스(묶음 ⑤의 5)는 같은 트레이스 저장소·Redis를 보고 플러그인 디렉터리와 운영자 파일은 배포의 몫(공유 볼륨이나 같은 이미지)이며, 쓰는 기능(관리 화면 CRUD, 마켓플레이스 설치, 업로드)은 공유 볼륨이 전제다.
- **용어.** `CONTEXT.md`의 Agent OS 정의는 "에이전트, MCP 서버, 스킬, 모델을 플러그인으로 로드해 실행하고, 그 실행의 모델·도구 호출을 중재·강제·기록하는 런타임"이다. 지금 정의는 모델이 빠져 있고(ADR 0040 뒤에도) 보장이 없다. 멀티 에이전트는 셋째 뜻(리드가 맡기고 병렬로 받는다)이고 한 턴의 도구 호출 병렬이 전제다.

## 묶음 ① 신뢰·강제(6 → 7 → 11)

- **운영자 파일은 둘이 는다.** 규칙 파일과 서버 파일이고, 플러그인 루트에 `disabled.toml` 옆에 두며 그 파일과 같은 규칙(실행을 준비할 때마다 읽고, 깨지면 전부 거부하고, git 추적)을 따른다(ADR 0017). 파일 이름은 명세가 짓는다.
- **규칙 파일.** 공통 표와 에이전트별 표를 합쳐 본다. 규칙은 "도구 이름"이나 "서버:\*"이고 인자 패턴은 내장 도구가 생길 때 더한다. 판정은 deny(운영자) → `requires_approval`(저자) → ask(운영자) → allow(운영자) → 어느 것에도 맞지 않으면 묻는다. "묻는다"는 지금처럼 `run_paused`로 멈추고 그 실행의 채널(CLI의 운영자, 운영자 채널, 최종 사용자 위젯)이 결정한다. deny는 모델의 도구 목록에서 빼고 직접 호출은 거부로 기록한다. 저자의 `requires_approval`이 가리키는 도구가 실재하는지 보는 지금의 검사는 deny로 빼기 전의 목록에 대 본다. 치르는 값: 기본이 "묻는다"라 기존 예시 에이전트와 e2e가 allow 규칙 없이는 첫 도구 호출에서 멈춘다. 구현 티켓이 규칙 파일의 예시를 함께 둔다.
- **서버 파일.** 서버마다 넷을 든다. 믿는다(불린 하나. 켜면 운영자 수준으로 스킬 본문·에이전트 코드와 같고, 적지 않으면 최종 사용자 입력 수준으로 `conversation`의 요약·교환과 같다. ADR 0041의 컨텍스트 멤버 항목. 중간 단계는 없고 서버가 스스로 신고하는 MCP 도구 애노테이션은 쓰지 않는다), 확인한 도구 정의 해시(첫 연결에서 런타임이 적는다), 넘길 환경 변수 이름(적지 않으면 지금처럼 mcp의 기본 허용 목록만, `adapters/mcp.py`), 주체 전파(기본 끔, 켜면 `_meta`에). 도구 단위 신뢰는 적지 못하고 그 서버를 둘로 나눈다. 해시가 다르면 연결 직후의 `run_failed`(원인 `tool_connection`)이고 409가 아니다. 해시는 서버에 붙어 도구 목록을 받은 뒤에야 알 수 있고 그 연결은 `run_started` 뒤의 몸통 안이기 때문이다(`core/run.py`의 `self._tools.connect`. 코드를 읽었다, 라운드 3 1호출). 연결 이벤트가 적어 둔 해시와 받은 해시를 함께 들어 운영자가 그 트레이스에서 새 값을 보고 관리 API의 해시 승인으로 받아들인다.
- **효과.** 믿지 않는 서버의 결과는 루프가 모델에 넣을 때 바깥 글로 감싸고 `tool_called`에 수준을 적는다. `tool()`의 반환은 맨 문자열 그대로이고, 저자 코드가 손으로 엮는 글은 보장 밖이라고 sdk 독스트링에 적는다. 연결 이벤트가 새 종류로 늘어 서버 이름, 도구 정의 해시, 처음 기록인지, 판 고정 없음 경고, 주체 전파 여부를 든다.
- **관리 API.** 쓰기 경로가 는다. 해시를 새 값으로 받아들이는 요청과 "믿는다" 토글의 PUT이다. 동시 쓰기 규칙(ADR 0017의 줄세우기)을 파일 둘에 넓히고 관리 화면도 바뀐다.
- **계약.** 이벤트 종류와 `tool_called`의 필드가 늘어 `openapi.json`이 같은 PR에서 바뀐다. 포트는 다섯 그대로이고 `ToolSource`의 `connect`·`call`에 인자가 는다(ADR 0012가 허용하는 모양).

## 묶음 ② 비용·기록(18 → 9 → 8 → 15 → 12 → 20)

- **18 저장소 교체.** 트레이스 저장소는 PostgreSQL 어댑터 하나다. JSONL 어댑터와 그 테스트는 코드에서 지우고 CLI run·테스트·개발도 DB를 쓴다. 포트의 `write`에 기대 자리를 더한 조건부 이어쓰기와, 실행 식별자 키를 TTL과 함께 잡는 Redis 분산 잠금(재개와 주기 작업 앞)을 함께 들인다. 테스트는 pytest가 testcontainers로 PostgreSQL·Redis를 스스로 띄우고 없으면 실패한다(skip 아님. 원칙 II). 제품 판과 드라이버는 그 기능의 인터뷰가 정한다. 치르는 값: Docker 없이는 테스트도 첫 실행도 없고, JSONL 이름을 든 테스트 파일 28개(인터뷰 때의 셈)를 다시 쓴다.
- **9 비용·소요시간.** `llm_called`·`tool_called`에 밀리초 칸(기본값 없음의 선택 필드, 형식 번호 그대로)을 더한다. 단가는 모델 매니페스트의 선택 칸(입력·출력 토큰 100만 개당 달러)이고 비용은 읽을 때 셈한다(트레이스에 쓰지 않음). 단가 없는 모델은 비용이 없음이다. 단가를 받는 자동 경로는 찾지 못했다. Models API의 목록 첫 항목과 그 id의 단건 응답에는 단가 칸이 없다(`.scratch/agent-os-direction/probes/probe_models_price.py`가 anthropic SDK 1.7.0으로 쟀다. 그 두 호출에서만이고, 판정은 응답의 모든 키(중첩 포함)에서 price·pricing·cost·usd·dollar 낱말을 찾은 것과 사람이 본 최상위 키 열하나라, 중첩 안의 다른 이름 칸은 가르지 못한다). 가격 페이지와 Usage and Cost API 문서는 curl로 받은 원문을 읽은 것이고, 앞의 것은 사람이 읽는 표이며 뒤의 것은 조직 단위의 쓴 금액이라 단가가 아니다(라운드 3 1호출). 집계는 런타임 밖이다(13).
- **8 토큰 합 상한.** core 기본값과 에이전트 매니페스트의 선택 칸이고 넘으면 `run_failed` 원인 `token_limit`이다. 비용 상한은 두지 않는다.
- **15 값 기반 마스킹.** 런타임이 아는 비밀 값(최소 길이는 어림 8자)을 core의 이벤트 쓰기 직전 한 자리에서 모든 글 칸에 가린다. PII 처리는 미룬 것이고, 트레이스에 최종 사용자의 글이 그대로 남고 보존 기간이 수명을 정한다는 사실은 PRD에 적는다.
- **12 보존 기간·승인 만료·worker.** 별도 명령 `agent-os worker` 프로세스가 주기 작업을 돌리고 `serve`는 돌리지 않는다. 승인 만료는 재개 시점 판정(`NotResumable`, 409)에 더해 worker가 만료된 일시정지에 `run_failed` 원인 `approval_expired`를 쓴다. 새 상태도 새 칸도 없다. 보존 기간 지우기는 worker가 하고 CLI 명령도 남기며, 남는 실행이 거슬러 읽는 범위의 트레이스는 지우지 않고(기준은 마지막 이벤트 시각) 멈춘 실행은 만료 길이가 지난 뒤에만 지운다. 설정(보존 기간, 만료 기본 길이, 주기 간격)의 원천은 PostgreSQL의 운영 설정 표 하나이고 관리 API GET·PUT으로 바꾸며 인자는 없다. 에이전트 매니페스트의 만료 칸은 그 에이전트에서만 기본 길이를 덮어쓴다. ADR 0009의 "일시정지에 만료 시간은 두지 않는다"와 승인자 스토리 20("답이 늦어도 일시정지가 만료되지 않기를", `.scratch/interrupts/spec.md`)을 뒤집는다.
- **20 고아 실행 회수.** 공유 저장소 위의 임대(쥔 인스턴스와 만료 시각, 도는 동안 갱신)로 가리고, 임대가 지난 결말 없는 실행에 worker가 `run_failed` 원인 `interrupted`를 쓴다. 임대 길이와 갱신 주기, 인스턴스 식별은 그 기능의 인터뷰가 정한다.
- **그 밖.** 지표 집계는 9·13이, 장기 기억은 MCP 서버 플러그인이 덮고, 평가 배치(LLM 채점)는 미룬 것이다.

## 묶음 ③ 바깥 연결(1 → 3 → 13)

- **1 선언형 에이전트.** `plugins/agents/<이름>/`에 entrypoint 없는 `plugin.toml`과 `AGENT.md`(Claude Code 서브에이전트와 같은 YAML 머리말 + 본문 프롬프트)를 둔다. 머리말의 name·description·model·tools를 읽고 모르는 칸은 무시한다. 몸통은 sdk의 공개 클래스(예: `DeclarativeAgent`)이고 로더가 entrypoint 없는 에이전트에 그것을 쓴다. 도구 루프는 지금처럼 core의 `ctx.llm()`이 돈다. 매니페스트 판정(agent에 entrypoint 필수, `.claude/rules/sdk.md`)과 로더가 바뀌므로 sdk 계약 변경이고 그 티켓이 다른 티켓을 막는다. 머리말 tools와 mcp 목록의 대응은 그 기능의 명세가 정한다. 스킬을 컨텍스트로 넘기는 것(ADR 0041)은 그대로이고, 코드가 없어 skill-plugin이 먼저이거나 같이 선다.
- **3 Claude Code 호환 = 등록, 길은 둘.** (a) 마켓플레이스는 우리 형식이다. 우리 플러그인 폴더 모양을 든 git 저장소나 폴더이고 목록 파일은 루트에 우리 이름으로 둔다. 관리 화면에서 주소(owner/repo·URL·로컬 경로)로 등록·관리하고, 플러그인을 골라 설치하면 그 폴더를 우리 `plugins/` 아래로 복사한다(변환 없음, 원본 참조 없음, 업데이트는 다시 받기). 설치하는 종류는 코드 없는 넷(선언형 에이전트·스킬·MCP 서버 매니페스트·모델)이고 코드 에이전트는 배포로만 간다. 목록 파일의 이름·칸, 설치 기록과 목록의 저장 자리, 업데이트 동작은 그 기능의 인터뷰가 정한다. (b) 업로드는 Claude Code의 것 넷(스킬 폴더 zip, 서브에이전트 .md, `.mcp.json`의 mcpServers 조각, 플러그인 zip)을 관리 화면에서 올리면 서버가 우리 `plugin.toml`로 바꿔 저장한다(zip 안의 `.claude-plugin/plugin.json`은 읽을 때만 보고 우리 디스크에 남지 않는다). skills/는 스킬(SKILL.md 그대로), agents/\*.md는 선언형 에이전트, `.mcp.json` 항목은 mcp 플러그인이 된다. hooks·commands·lsp·bin·output-styles·settings와 type이 sse·ws인 서버는 건너뛰고 결과에 항목별로 알리며, 같은 이름이 있으면 그 요소만 거절한다(덮어쓰기 없음). `env`·`headers`의 `${VAR}`는 변수 이름을 서버 파일의 "넘길 환경 변수 이름"에 적고(신뢰 수준은 적지 않아 믿지 않음으로 시작) 글자 그대로의 값은 거절한다. 관리 API에 multipart 업로드 길이 새로 선다.
- **원격 MCP(3의 한 가지).** `[server]`는 stdio(command·args)와 http(url·헤더의 환경 변수 이름) 두 모양이고 streamable HTTP만 받는다(SSE 없음). 신뢰 수준·해시·주체 전파는 전송과 무관하게 같고, Claude Code `.mcp.json`의 type http 항목이 이 모양으로 등록된다.
- **13 OTel 내보내기.** 프로세스 안의 OTel SDK다. main이 트레이스 저장소를 감싸는 어댑터를 조립해 쓰기마다 span을 SDK에 넘기고, SDK의 배치 프로세서가 배경에서 OTLP로 보낸다(최선 노력, 큐가 넘치면 버림). core와 포트는 그대로다. 설정은 OTel 표준 환경 변수(`OTEL_EXPORTER_OTLP_ENDPOINT`·`OTEL_EXPORTER_OTLP_HEADERS`)를 프로세스(`serve`·`worker`)마다 읽고 없으면 보내지 않으며 관리 화면에서 켜고 끄지 않는다. 매핑은 실행 = trace(trace_id는 run_id에서), 이벤트 = span, 속성은 GenAI 시맨틱 컨벤션, span 길이는 9의 밀리초 칸이다. 본문(프롬프트·응답·도구 인자·결과)은 값 기반 마스킹을 지난 글을 늘 싣는다. 컨벤션의 Opt-In 권고와 다른 선택이고(컨벤션은 인터뷰가 웹 요약으로 읽었다) PRD에 "기본 설정에서 최종 사용자의 글이 OTLP 끝점으로 나간다"를 적는다. 수락 기준은 로컬 Langfuse에 run_id·모델·도구·토큰과 함께 뜨는 것이고 Langfuse SDK는 들이지 않는다.
- **치르는 값.** sdk 계약이 두 번 바뀌고(선언형 agent 판정, `[server]`의 http 모양), 서버가 git을 실행하며, Claude Code 마켓플레이스는 주소로 등록하지 못하고, 프로세스가 죽으면 큐의 span을 잃는다.

## 묶음 ④ 여러 에이전트(4 → 2 → 14)

- **4 실행 경계 넘김.** 앞 에이전트가 `run_finished`에 선택 칸 둘(`next_agent`, `handoff_note`)을 낸다. 런타임이 같은 주체의 이어 가기(`previous_run`은 앞 실행)로 다음 에이전트의 실행을 바로 시작한다(위젯 개입 없음. 추천과 다른 답, 라운드 5 1호출). 다음 실행의 요청은 사용자의 원래 요청 그대로이고, 넘김 메모는 `ctx.conversation`의 넘김 교환으로 받는다(선언형은 몸통이 프롬프트에 넣고 코드 에이전트는 conversation에서 읽는다). 채널의 한 스트림이 넘김 고리의 실행들을 이어 보내고(새 run_id의 `run_started`부터) 넘김이 없는 결말 뒤에 닫히며, 승인 멈춤이면 거기서 닫고 결정 스트림이 이어 간다(ADR 0014 "결말 이벤트를 보낸 뒤 닫힌다"의 이력). 검사 넷(다음 에이전트가 사이트의 열 에이전트 목록 안인가, 켜져 있는가, 한 요청의 고리 길이가 core가 든 값 안인가(어림 3), 같은 에이전트가 고리에 두 번 나오는가)에 걸리면 앞 실행은 `run_finished`로 끝나고(출력 보존) 둘째 실행이 `run_started` 뒤 바로 `run_failed`(새 원인 `handoff`)로 끝난다. 둘째 실행도 시간당 실행 수에 든다(어림).
- **2 맡기기.** 리드가 `ctx.delegate(에이전트 이름, 요청)`으로 부른다. 하위 실행은 같은 주체의 별개 실행(자기 run_id·트레이스)이고 리드 트레이스에 맡긴 이벤트(하위 run_id)가 남는다. 부를 수 있는 에이전트는 매니페스트의 목록 칸(mcp 칸과 같은 모양)이다. 하위의 도구 호출은 하위 에이전트의 승인 정책과 규칙 파일을 타고, 리드에게 `delegate()`는 도구 호출처럼 기록되어 재생 구간에서는 기록된 결과를 돌려준다. 하위가 승인으로 멈추면 리드도 그 자리에서 멈춘 것으로 기록되고 결정은 하위 실행에 내리며 하위가 끝나면 리드를 재개한다(어림, 세부는 그 기능의 인터뷰). 운영자의 규칙 파일이 맡기기도 deny·ask할 수 있다(어림). 한 턴의 도구 호출 병렬은 전제라 2의 첫 티켓이 `core/loop.py`의 차례 호출을 병렬로 바꾸고, 재생 대조는 순서가 아니라 호출 집합으로 맞춘다(어림). 깊이 상한과 고리(리드가 자기를 부름)를 막는다.
- **14 재생 평가.** 운영자가 고른 지난 실행(원본 실행)들을 같은 요청·같은 앞 고리로 바뀐 에이전트·모델·스킬에 다시 돌린다(평가 실행). 모델은 실제로 부르고, 도구 호출(맡기기 포함, 어림)은 원본 기록에서 이름·인자가 같은 결과를 찾아 돌려주며, 못 찾으면 평가 실행은 `run_failed`(새 원인 `evaluation`)로 끝난다. 실제 도구는 부르지 않고 승인 게이트도 걸지 않는다. 원래 출력과 평가 출력을 나란히 보여 주고 사람이 좋음·나쁨을 적는다. 판정은 평가 표(PostgreSQL)에 평가 실행의 run_id와 함께 적고 트레이스에는 쓰지 않으며, LLM 채점은 런타임이 하지 않는다(OTel로 내보낸 뒤 바깥 도구가 한다). 평가 실행은 트레이스 저장소에 남되 `run_started`에 평가 꼬리표(원본 run_id, 선택 칸)가 붙고, 대화 고리·최종 사용자 경로·시간당 실행 수 밖이며 보존 기간을 따른다. 평가 실행의 `run_finished`에 `next_agent`가 있어도 넘김을 시작하지 않는다(어림). 관리 API·관리 화면에 평가 경로를 두고 CLI 명령도 둔다. 주체는 돌린 운영자다.
- **치르는 값.** sdk 계약이 다섯 자리에서 바뀐다(`ctx.delegate`, 맡긴 이벤트, 매니페스트의 목록 칸, `run_finished`의 칸 둘, `run_started`의 평가 꼬리표). CLI·위젯·관리 화면의 "실행 하나 = 응답 하나" 전제가 고리로 바뀐다. 다음 에이전트는 메모에 적힌 것만 안다. 거절마다 실행 하나가 트레이스에 남는다. 평가는 새 도구를 쓰는 에이전트를 평가하지 못하고 모델 비용이 실제로 든다. 표가 하나 는다.

## 묶음 ⑤ 확장·채널(21 → 5)

- **21 관리 화면 CRUD.** 파일 원문을 경로별 PUT으로 받는다. 매니페스트(`plugin.toml`), 본문 파일(`AGENT.md`·`SKILL.md`), 운영자 파일(규칙·서버·사이트)이다. 서버가 sdk의 매니페스트 판정(`parse_manifest`)과 운영자 파일 판정을 지나면 꺼짐 파일과 같은 원자 교체(`adapters/filesystem.py`의 임시 파일 쓰기 뒤 이름 바꾸기. 코드를 읽었다)로 쓰고, 어긋나면 422 봉투다. 새 플러그인은 종류·이름과 원문의 POST다. 관리 화면은 원문 편집기와 판정 메시지이고 칸별 폼은 없다. 에이전트 코드(entrypoint의 `.py`)는 받지 않고 배포로 간다. DELETE는 꺼진 플러그인의 폴더를 지우고 켜진 것은 409다. 도는 실행은 끝까지 가고(코드 에이전트는 실행마다 import하므로, 코드를 읽었다), 지운 뒤의 시작·재개·이어 가기는 없는 플러그인과 같은 실패이며 복구는 없다. 사이트 파일은 `serve`가 요청마다 변경 시각으로 보고 바뀌었을 때만 다시 읽으며, 깨진 판은 버리고 마지막 좋은 판을 쓴다(ADR 0023 "바꾸면 다시 시작한다"의 이력. 그 ADR이 요청마다 읽기를 거부한 까닭 "파일이 깨지는 순간부터 최종 사용자 경로가 모두 500"은 마지막 좋은 판으로 닫힌다). 공유 볼륨의 다른 인스턴스도 같은 길로 따라간다. 허용 출처로 만드는 CORS 미들웨어는 다시 읽기가 닿는 모양으로 바뀐다(어림). 묶음 ①의 관리 API 쓰기(해시 승인, 믿기 토글)와 묶음 ②의 운영 설정 PUT은 그대로이고 21이 그 위에 선다.
- **5 다중 인스턴스.** "도는 실행인가"는 트레이스 저장소의 임대(20)가 답하고, 동시 실행 칸·시간당 창·구독 수의 셈은 Redis의 원자 연산으로 옮기며, 상한의 뜻은 배치 전체의 합이다. 운영자 채널과 관리에 상한이 없는 것은 그대로다. 인스턴스는 자기 실행의 이벤트를 트레이스에 쓴 뒤 Redis 채널(run_id)에도 내고, 구독은 트레이스의 나머지를 보낸 뒤 그 채널을 받는다(사이의 틈은 인덱스로 거른다). 결정은 어느 인스턴스에서나 받고 재개 스트림은 그 인스턴스가 낸다. 넘김 고리(묶음 ④)는 한 인스턴스 안에서 이어진다. 플러그인 디렉터리와 운영자 파일은 배포의 몫(공유 볼륨이나 같은 이미지)이고 런타임은 인스턴스마다 자기 디스크를 지금처럼 읽는다(매니페스트와 꺼짐 파일은 부를 때마다 읽고 캐시가 없다. 코드를 읽었다). 쓰는 기능(21 CRUD, 마켓플레이스 설치, 업로드)은 다중 인스턴스에서 공유 볼륨이 전제이고 PRD가 적는다. 인스턴스 식별은 20의 인터뷰가 정한다.
- **치르는 값.** Redis가 실행을 시작하는 경로에 서서 죽으면 최종 사용자 경로가 실행을 시작하지 못하고(fail-closed), 셈이 네트워크를 타며, 이벤트마다 Redis에 한 번 더 쓴다. 공유 볼륨 없이 띄우면 쓴 인스턴스에만 플러그인이 보이고 런타임은 그것을 확인하지 못한다. 운영자가 TOML·마크다운 형식을 화면에서 직접 쓴다. 멈춘 실행이 가리키는 플러그인을 지우면 그 실행은 재개하지 못한다. 사이트의 발급자를 바꾸면 지난 실행은 남의 것이 된다. `channel/http/limits.py` 독스트링의 "워커가 하나라 충분하고"와 ADR 0023의 등록부·셈·구독·사이트 파일 규칙이 이력으로 간다.

## Considered Options

- **보장을 적지 않고 보고서의 순위대로 기능만 더한다.** 이름이 무엇을 뜻하는지 PRD가 답하지 못하고, 기능마다 런타임이 할 일인지 에이전트가 할 일인지를 다시 묻게 된다. 인터뷰에 올린 선택지가 아니라 이 ADR이 견준 안이고, 방향 라운드가 고른 것은 "건너뛸 수 없는 중재·강제·기록"이다(일지 2026-11-03-04).
- **묶음 ①만 설계하고 나머지는 차례가 올 때 연다.** 추천이었으나 사용자가 "열여덟 전부 설계"를 골랐다. 치르는 값은 위에 적었다.
- **범용 오케스트레이션.** 그래프 상태 공유, 그룹 챗, goto 핸드오프, 엔진의 그래프 상태 객체, 실행 안의 제어권 넘김. 만들지 않는다(PRD의 "만들지 않는 것"에 더한다). 공유 작업물은 도구(MCP 서버)를 지난다.
- **분류기 승인(19), 모델의 기밀 등급·능력 선언(10), 승인 알림(17), 웹훅·스케줄러(16).** 미룬 것이다. 16의 세 질문(채널의 모양과 주체, 정의의 자리와 한 번만 발화, 본문·응답·상한)은 그 기능이 돌아올 때 그 인터뷰가 처음부터 묻는다(라운드 6 3호출). 보고서도 웹훅·스케줄러를 "실행이 연결에 묶이지 않는 지금 구조 위에 나중에 얹을 수 있다"로 두었다.
- **LLM 채점을 런타임이 한다.** 거부했다. OTel로 내보낸 뒤 바깥 도구의 몫이다.
- **다중 인스턴스를 프록시의 스티키 라우팅으로 푼다, 구독이 트레이스를 주기적으로 다시 읽는다, 매니페스트와 운영자 파일을 PostgreSQL로 옮긴다, 쓰기는 관리 인스턴스 하나만 한다.** 모두 거부했다(라운드 6 1호출의 고르지 않은 선택지). 파일이 원천(ADR 0003)이고 트레이스가 원천(원칙 V)인 채로 임대와 Redis 채널이 "도는가"와 "지금 나오는가"를 답한다.
- **그 밖의 거부한 안.** 묶음마다 라운드의 "고르지 않은 선택지(라벨만)" 줄에 있다. 이 ADR은 그것을 되풀이하지 않는다.

## Consequences

- **sdk 계약이 묶음마다 바뀐다.** ① 연결 이벤트의 새 종류, `tool_called`의 수준 칸, `ToolSource.connect`·`call`의 인자. ② `llm_called`·`tool_called`의 밀리초 칸, 모델 매니페스트의 단가 칸, 에이전트 매니페스트의 토큰 합 상한 칸과 만료 칸, `run_started`의 `previous_run` 위의 변화 없음, 실패 원인 셋(`token_limit`, `approval_expired`, `interrupted`), `TraceStore.write`의 기대 자리. ③ 매니페스트 판정(agent의 entrypoint 선택화), `[server]`의 http 모양, 선언형 몸통의 공개 클래스. ④ `ctx.delegate`, 맡긴 이벤트, 매니페스트의 목록 칸, `run_finished`의 칸 둘, `run_started`의 평가 꼬리표, 실패 원인 둘(`handoff`, `evaluation`). ⑤ `PluginSource`의 쓰기·지우기 메서드. 계약에 닿는 티켓은 그 기능의 다른 티켓을 막는다(작업 규약 2). 실패 원인은 아홉에서 열넷이 되고 ADR 0031의 이력에 쌓는다.
- **이력으로 가는 ADR과 포인터.** 이 ADR의 커밋이 단다(`.claude/rules/adr.md`). 포인터 `(바뀜: ADR 0042)`를 단 본문 문장은 ADR 0003 "DB는 색인과 권한에만 쓴다"(트레이스·운영 설정·평가 표가 DB로 간다), ADR 0009 "트레이스 헤더 버전을 2로 올리고 버전 1 파일은 재개를 거부한다"(18의 JSONL 삭제)와 "일시정지에 만료 시간은 두지 않는다"(12), ADR 0014 "스트림은 결말 이벤트(`run_finished`, `run_failed`, `run_paused`)를 보낸 뒤 닫힌다"(4의 넘김 고리)와 "프로세스 사이의 경합은 알려진 한계다"(18의 Redis 잠금), ADR 0022 "형식 2도 그대로 읽고 재개한다. 형식 1은 지금처럼 읽기만 된다"(18), ADR 0023의 사이트 파일 "바꾸면 다시 시작한다"(21), 등록부 "그래서 앱이 지금 도는 실행을 run_id로 든 등록부를 둔다"(5의 임대), 구독의 "등록부에 없고 결말도 없는 실행은 … 끝내지 못했다는 항목으로 닫는다"(5), 상한의 "셈은 프로세스 메모리에서 한다"(5의 Redis)다. 이력 2026-11-04를 쌓는 ADR은 0003(공유 볼륨과 DB), 0009(만료), 0012(포트는 다섯 그대로, `TraceStore.write` 기대 자리, `PluginSource` 쓰기·지우기, `ToolSource` 인자, JSONL 어댑터 삭제), 0014(넘김 고리와 Redis), 0017(삭제는 꺼짐 뒤에만 선다, 운영자 파일 둘), 0022(JSONL과 형식), 0023(사이트 파일 다시 읽기, 임대와 Redis), 0031(원인 다섯), 0041(선언형 에이전트와 업로드·설치. 선언형 몸통도 스킬을 프롬프트에 엮는 쪽이고 런타임은 `llm()`에 붙이지 않으므로 거짓이 되는 문장이 없어 포인터는 없다)이다.
- **`docs/constitution/tech.md`.** 의존성은 그것을 들이는 기능의 계약 티켓이 ADR 뒤에 적는다(PostgreSQL 드라이버와 Redis 클라이언트와 testcontainers는 18, `opentelemetry-sdk`·`opentelemetry-exporter-otlp`는 13, 서버의 git 실행은 3). 지금 tech.md의 런타임 의존성 줄에는 이 가운데 어느 것도 없다(grep).
- **PRD 개정(사용자 승인).** "보장하는 것" 절(중재·강제·기록 세 문장과 전제 둘), 성공의 정의에 줄 하나(운영자가 바깥에서 건 정책을 에이전트 코드가 건너뛸 수 없고 트레이스로 되짚을 수 있다), "만들지 않는 것"에 셋(실행 안의 제어권 넘김, 엔진의 그래프 상태 객체, 범용 오케스트레이션 프레임워크), 미룬 것 아홉(10, 19, 17, 16, Slack 입력 채널, A2A, 멀티테넌시, PII 처리, LLM 채점), 사실 둘(최종 사용자의 글이 트레이스에 남고 보존 기간이 수명을 정한다, 기본 설정에서 OTLP 끝점으로 나간다).
- **`CONTEXT.md`.** Agent OS 정의에 모델과 보장이 든다. 묶음의 용어(운영자 파일·규칙 파일·서버 파일·신뢰 수준·도구 정의 해시·주체 전파, 토큰 합 상한·승인 만료·보존 기간·worker·임대·조건부 이어쓰기·고아 실행·운영 설정, 선언형 에이전트·마켓플레이스·설치·업로드·원격 MCP 서버·내보내기, 넘김·넘김 메모·넘김 고리·맡기기·리드·하위 실행·맡긴 이벤트·재생 평가·원본 실행·평가 실행·평가 꼬리표·판정, 인스턴스·마지막 좋은 판·삭제·실황)는 인터뷰가 묶음 경계마다 올렸다. 인터뷰의 "평가 표지"는 용어집에서 "평가 꼬리표"다(표지는 읽을 수 없는 매니페스트의 자리라 겹친다).
- **`.scratch/plan.md`.** 행 열일곱이 위 표의 순서로 서고 슬라이스는 묶음이다. 10·16·17·19는 행이 없다. 각 기능은 `.scratch/<slug>/`가 없으니 차례가 오면 설계 인터뷰부터 하고(작업 규약 1), 이 ADR의 조건이 그 인터뷰의 전제다. (바뀜: ADR 0045)
- **브랜치 전략.** 같은 인터뷰에서 정한 Git Flow의 release 없는 판은 별도 ADR 0043이다. 그 전환이 서기 전에 열린 PR(이 PR 포함)은 main으로 끝낸다.
- **근거의 종류.** 이 ADR이 "코드를 읽었다"로 적은 것은 인터뷰가 올리기 전에 대 본 것이고 자리는 일지의 "올리기 전에 대 본 사실"에 있다. "어림"은 대 보지 못한 것이다. 웹 요약(GenAI 시맨틱 컨벤션, MCP 도구 애노테이션, Agent Skills 표준, Claude Code의 디스크 형식)은 원문과 대 보지 않았고 주소는 일지에 있다. 프로브는 `.scratch/agent-os-direction/probes/`다.
