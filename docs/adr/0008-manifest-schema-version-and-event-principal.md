# 매니페스트는 형식 버전을, 시작 이벤트는 주체를 필수로 가진다

매니페스트와 이벤트는 디스크에 남는 형식이라 나중에 바꿀 때 옛 파일을 어떻게 읽을지가 문제가 된다. 첫 슬라이스의 계약 티켓(03)에서 `plugin.toml`에 `schema_version = "1"`을 필수로 넣고 모르는 값은 거부하며, `run_started` 이벤트에 `principal`을 필수로 넣는다. 둘 다 선택 필드로 미룰 수 있었지만 미루지 않았다. 버전을 선택으로 두면 "없으면 1"이라는 암묵 규칙이 생겨 형식이 바뀐 뒤 옛 플러그인이 조용히 다르게 해석되고, 주체를 선택으로 두면 멀티테넌시가 올 때 주체 없는 실행이 기본값으로 굳어 fail-open이 된다. 지금 매니페스트와 트레이스가 저장소 밖에 하나도 없어서 필수로 넣는 비용이 0인 유일한 시점이다.

## Considered Options

- **`schema_version`을 선택 필드로 두고 기본 `"1"`.** 기존 파일이 그대로 읽힌다. 그러나 형식 2가 나온 뒤 버전을 안 적은 파일이 1인지 실수인지 구분할 수 없다. 거부했다.
- **`principal`을 선택 필드로 두고 CLI만 채운다.** 지금 채널이 CLI 하나라 당장은 같다. 그러나 HTTP 채널이 올 때 빈 주체로도 실행이 되는 코드가 이미 있게 되고, 그것을 막는 쪽이 예외가 된다. 거부했다.
- **이벤트 스키마에도 파일 단위 버전을 둔다.** 트레이스 파일 첫 줄 헤더가 그 역할을 하므로 이벤트마다 버전을 붙이지 않는다(05).

## Consequences

- 같은 티켓에서 함께 들어가는 계약 변경. `PluginKind`가 `model`을 포함한 `StrEnum`이 된다(OpenAPI가 이름 있는 정의로 내보내야 슬라이스 3의 생성 클라이언트가 재사용한다). 에이전트 매니페스트에 `mcp = [...]`, mcp 매니페스트에 `[server]`(`command`, `args`). 컨텍스트에 `run_id`와 `now()`. 식별자 넷(`RunId`, `AgentName`, `PluginName`, `Principal`)은 `NewType`이고 JSON은 문자열 그대로다.
- 판별자(`type`)와 `schema_version`만 `Literal`로 남는다. 나머지 고정 값 집합은 `StrEnum`이다.
- 같은 슬라이스의 티켓 07이 sdk 표면에 둘을 더했다. `Json`(컨텍스트 메서드가 주고받는 값의 타입. `llm()`과 `tool()`이 JSON으로 직렬화 가능한 것만 다룬다는 규칙을 타입으로 옮긴 것)과 `ToolError`(`ctx.tool()`로 직접 부른 도구가 실패했을 때 에이전트가 이름으로 잡을 수 있는 예외. sdk만 import하는 플러그인이 core의 예외를 알 수 없어서 sdk에 둔다). 디스크 형식은 아니다.
- `schema_version`을 올리면 이 ADR의 이력에 쌓는다. 새 ADR을 만들지 않는다.
