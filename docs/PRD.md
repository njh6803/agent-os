# Agent OS 제품 의도

status: accepted (2026-09-21 사용자 승인, 2026-11-04 개정 사용자 승인, 2026-11-06 개정 두 번 사용자 승인, 2026-11-07 개정 사용자 승인, 2026-11-10 개정 두 번 사용자 승인, 2026-11-11 개정 사용자 승인. 개정의 근거는 ADR 0042와 ADR 0046과 ADR 0051과 ADR 0054와 ADR 0055, 일지 2026-11-06-11과 2026-11-07-2053과 2026-11-10-1345와 2026-11-10-1845). 바꾸려면 사용자 승인으로. 설계 문서는 "어떻게"를 담고 이 한 장은 "누구의 어떤 문제를 왜"를 담는다. 스펙끼리 충돌할 때 무엇을 기준으로 고를지 이 문서가 답한다.

## 누구의 어떤 문제

- **문서를 밖으로 보낼 수 없는 조직의 현업과 보안 담당.** 사내 문서에서 근거 있는 답을 찾고 싶지만 문서를 밖으로 보낼 수 없고, 누가 무엇을 물었고 어떤 근거로 답을 받았는지 되짚을 수 있어야 한다. 기준선과 제품 1.0이 이 문제를 다룬다.
- **에이전트를 만드는 개발자.** 서비스마다 LLM 호출, 세션, 도구 연결, 트레이스, 가드레일을 다시 만든다. 빌더는 PoC에는 좋지만 프로덕션에서 필요한 상태 제어, 예외 처리, 비용 라우팅이 안 된다.
- **운영자.** 어떤 에이전트, 도구, 모델이 등록돼 돌아가는지 한 곳에서 보고 켜고 끄고 싶다.
- **최종 사용자.** 위젯 같은 앱으로 최종 사용자 채널을 써서 에이전트에게 묻는다. 공개 데모에서는 누구나 공개 정부 문서에 대해 묻고, 기준선에서는 조직의 직원이 사내 문서에 대해 묻는다.

## 왜 지금, 왜 우리

- 같은 주제로 두 번 시도했고 둘 다 실행 루프 없이 문서와 관리 화면만 남겼다. 세 번째는 실행부터 만든다(원칙 I).
- MCP와 Agent Skills가 표준이 되어 플러그인 경계를 우리가 발명할 필요가 없다. 런타임이 할 일은 그것들을 싣고 실행하고 기록하는 것이다.
- 설치형 문서 질의응답이 요구하는 승인 통제와 감사 기록은 이 런타임이 보장하는 강제와 기록 그 자체다. 기준선은 그 보장을 실제 사용처 하나 위에서 끝까지 시험하는 자리다.

## 무엇을 만드나

- 플러그인(agent, mcp, skill, model)을 디렉터리에서 로드해 실행하는 런타임. 실행은 이벤트 스트림이고 트레이스로 남는다.
- 실행을 일으키는 채널(CLI → HTTP)과 구성을 다루는 관리(API → 화면). 위젯은 채널이 아니라 최종 사용자 채널의 참조 클라이언트이고, Agent OS는 위젯을 모른다(ADR 0047).
- 기본 에이전트 assistant와 그 참조 배포(설치형 문서 질의응답)를 이 저장소에 두지만, 런타임은 그것을 모른다. 기본 에이전트는 커스텀 에이전트의 바탕이고, 특별한 요구가 없으면 그대로 쓴다(ADR 0051). 기본 에이전트가 쓰는 문서 검색 서버는 다른 저장소에 있고, 런타임은 그 서버도 모른다(ADR 0048).
- 커스텀 에이전트가 골라 붙이는 부품: 최종 사용자마다의 기억(ADR 0054), 데이터베이스 조회, 사내 시스템을 조회하는 본보기(둘은 ADR 0055), 여러 단계를 밟는 에이전트의 계획표. 기본 에이전트에는 붙이지 않고, 런타임은 그것들도 모른다. 데이터베이스 조회는 매출이나 재고처럼 숫자가 바뀌고 합계를 내야 하는 데이터를 묻는 것이고, 운영자가 조회문을 미리 적어 두는 정해 둔 조회와 모델이 조회문을 스스로 쓰는 조회문 직접 작성(Text-to-SQL)을 둘 다 낸다. 문서 검색 서버는 그런 데이터를 색인하지 않는다.
- 만들지 않는 것: 그래프를 그리는 빌더, 범용 챗 제품, 우리만의 툴 프로토콜, 실행 안의 제어권 넘김(goto 핸드오프, 그룹 챗), 엔진의 그래프 상태 객체, 범용 오케스트레이션 프레임워크. 여러 에이전트는 리드가 맡기고 병렬로 받는 모양과 실행 경계의 넘김(앞 실행이 끝나며 다음 에이전트가 잇는다)뿐이고 공유 작업물은 도구(MCP 서버)를 지난다.
- 미룬 것(이번 방향에서 설계하지 않는다): 모델의 기밀 등급·능력 선언, 분류기 승인, 승인 알림, 웹훅·스케줄러, Slack 입력 채널, A2A, 멀티테넌시, LLM 채점. 돌아오면 그 기능의 설계 인터뷰가 처음부터 묻는다. PII 처리는 제품 1.0의 입출력 가드레일(패턴으로 막거나 가린다)로 당기고, 이름과 주소처럼 패턴으로 잡히지 않는 개인정보의 탐지는 계속 미룬다. 제품 1.0에서 여러 부서가 한 배포 환경을 나눠 쓰는 것은 한 조직 안에서 문서 권한을 나누는 것이고, 테넌트를 분리하는 것(멀티테넌시)이 아니다.

## 보장하는 것

an agent OS가 보장하는 것은 에이전트 코드가 건너뛸 수 없는 셋이다.

- 중재: 실행의 모델 호출과 도구 호출은 런타임을 지난다.
- 강제: 운영자가 바깥에서 건 정책(승인 규칙, MCP 서버의 신뢰 수준, 상한, 승인 만료, 보존 기간)을 런타임이 집행하고 저자의 코드가 풀지 못한다. 운영자도 저자가 매니페스트에 적은 승인 대상을 풀지 못한다.
- 기록: 그 호출과 판정이 트레이스에 남아 되짚을 수 있다.
- 전제 셋. 배포의 프로세스는 trace-postgres부터 PostgreSQL과 Redis가, retention-worker부터 worker가 더해져 넷(serve, worker, PostgreSQL, Redis)이 되고, 다중 인스턴스는 공유 볼륨 위다. 그 전의 판(기준선과 제품 1.0)은 `serve` 한 프로세스와 파일 트레이스(JSONL)이고 단일 인스턴스다. 원격 MCP 서버(상주 서버)의 수명은 배포가 관리한다. 에이전트 코드 안의 일(저자가 손으로 엮는 글, 런타임을 거치지 않는 호출)은 보장 밖이다.
- 알아 둘 사실 둘. 최종 사용자의 글은 트레이스에 그대로 남고 보존 기간이 수명을 정한다. OTel 내보내기를 켠 기본 설정에서는 그 글이 OTLP 끝점으로 나간다.

## 성공의 정의

- 2026-09-22까지 LLM을 실제로 호출하는 테스트가 통과한다.
- 2주 안에 CLI로 에이전트 하나가 MCP 도구를 써서 답하고 트레이스가 남는다.
- 그다음 슬라이스 셋: HTTP 채널, 관리 API와 화면, 위젯. 순서와 의존은 `.scratch/plan.md`.
- 그다음: 모델 플러그인. 에이전트가 매니페스트로 고른 모델로 돌고, 모델 파일을 고치거나 켜고 끈 것이 서버를 다시 띄우지 않아도 다음 실행부터 듣는다.
- 그다음: 스킬 플러그인. 에이전트가 매니페스트로 고른 스킬의 이름·설명·본문을 컨텍스트로 받아 프롬프트에 엮고, 스킬 파일을 고치거나 켜고 끈 것이 서버를 다시 띄우지 않아도 다음 실행부터 듣는다.
- 그다음(공개 데모, ADR 0046의 2026-11-06 이력): 2027-01-08까지 공개 주소에서 누구나 로그인 없이 공개 정부 문서에 대해 묻고 출처와 갱신일이 붙은 답을 받는다. 시간당 비용에는 계산한 최댓값이 있고, 같은 문서 묶음으로 잰 검색 적중률과 정답률 보고서를 함께 공개한다. 공개 데모는 제품 0.1의 조건이 아니다.
- 그다음(기준선, 제품 0.1, ADR 0046): 2027-03-05까지 폐쇄망 서버 한 대에 안내 문서만 보고 1시간 안에 배포되고(밖으로 여는 포트는 하나다), 외부 API 없이 배포 환경의 모델로 문서에 근거한 답을 출처와 함께 내며, 검색 적중률과 사람이 판정한 정답률을 보고서로 낸다. 문서 검색은 다른 저장소의 문서 검색 서버가 맡는다. 운영자의 승인 규칙은 기준선과 나란히 간다.
- 그다음(제품 1.0): 2027년 상반기(어림)에 묶음 ①의 나머지(MCP 서버의 신뢰 수준, 주체 전파)와 값 가림, 입출력 가드레일, 감사 조회와 내보내기, 오류 신고, 오래된 근거의 경고, 지식베이스 고르기를 더한다. 여러 부서가 한 배포 환경을 나눠 쓸 때 사용자는 자기가 볼 수 있는 문서로만 답을 받고, 기본 에이전트는 질문에 맞는 지식베이스를 골라 검색하며, 운영자는 누가 무엇을 물었고 어떤 근거로 답을 받았는지 조회하고 내보낸다.
- 제품 1.0과 나란히(커스텀 에이전트의 부품, ADR 0054와 ADR 0055. 제품 1.0의 조건이 아니다): MCP 서버의 신뢰 수준과 주체 전파가 선 뒤에 기억, 정해 둔 조회와 사내 시스템을 조회하는 본보기(둘은 나란히), 조회문 직접 작성, 계획표를 차례로 낸다. 기본 설정에서는 로그인한 최종 사용자가 승인한 것만 기억에 남아 다음 대화에서 쓰이고, 본인이 보고 고치고 지운다. 조직이 데이터베이스에 권한과 행 수준 보안을 설정해 두면, 데이터베이스의 숫자를 묻는 사람은 자기가 볼 수 있는 데이터로만 답을 받는다(그 설정을 했는지는 이 제품이 확인하지 못한다. ADR 0055). 기한은 정하지 않았다.
- 그다음(다섯 묶음 열일곱의 나머지, ADR 0042와 ADR 0046): 운영자가 바깥에서 건 정책을 에이전트 코드가 건너뛸 수 없고, 그 집행을 트레이스로 되짚을 수 있다. 순서와 의존은 `.scratch/plan.md`.

## 스펙이 충돌하면

실행 가능성 > 계약의 안정성(sdk, 디스크 형식) > 확장성 > 편의. 앞이 뒤를 이긴다.
