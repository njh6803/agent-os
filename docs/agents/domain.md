# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색하기 전에 이 저장소의 도메인 문서를 어떻게 읽어야 하는지 정한다.

## 탐색 전에 읽을 것

- 루트 `CONTEXT.md`: 용어집
- `docs/adr/`: 지금 다룰 영역에 걸리는 ADR

이 파일들이 없으면 조용히 진행한다. 없다고 지적하거나 미리 만들자고 제안하지 않는다. `/domain-modeling`(`/grill-with-docs`가 호출)이 용어나 결정이 실제로 확정될 때 그때 만든다.

## 배치 (단일 컨텍스트)

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-<slug>.md
│   └── 0002-<slug>.md
└── src/
```

멀티 컨텍스트(`CONTEXT-MAP.md`)는 쓰지 않는다. 모노레포로 바뀌면 setup 스킬을 다시 돌린다.

## 용어집의 어휘를 쓴다

출력물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에 도메인 개념이 들어가면 `CONTEXT.md`에 정의된 용어를 쓴다. 용어집이 피하기로 한 동의어로 흘러가지 않는다.

필요한 개념이 용어집에 없으면 신호다. 프로젝트가 쓰지 않는 말을 만들어 내고 있거나(재고), 진짜 빈틈이 있는 것이다(`/domain-modeling`용으로 메모).

## ADR 충돌은 드러낸다

출력물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시한다.
